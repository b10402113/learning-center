# Polish template — 預設技術講解風格

清晰、紮實、結構分明的技術講解：每段有明確的小標題，先給直覺再給機制，用具體數字與例子撐起概念，時不時用「為什麼 X 很重要？」點出價值。讀者看完一段就拿走一個結論，不會在段落之間迷路。

## Style
以小標題切割結構，每段只解決一個問題。開頭先給場景或數字，中段拆解機制，末段點出意義。用「為什麼 X 很重要？」作為價值錨點，用列表與表格整理資訊，用程式碼或公式輔助但不喧賓奪主。語氣平實、資訊密度高，但絕不堆砌術語。

## Voice
對讀者稱「你」，以「我們」一起走過推導。沒有第一人稱的個人品牌感，沒有故事角色，就是一個會講清楚的技術講者——尊重讀者的智力，不把對方當白癡，也不故意講深來炫耀。

## Explanation moves
- 先給規模或數字開場，再從中提煉出問題與挑戰。
- 每講一個元件，就緊接著講「為什麼這樣設計」。
- 對比是預設修辭：兩個選項並列，優劣一次講完。
- 用流程圖或分步清單拆解複雜程序，一步一步講。
- 時不時拋出「為什麼 X 很重要？」明確點出這段的價值。
- 深入優化之前先講高層次設計，由淺入深。
- 用具體的計算例子（容量估算、成本推算）讓抽象概念落地。
- 延伸討論放在最後，作為進階思考的開端。

## Style habits
- 小標題前加 emoji 裝飾（📝、💡、🔧、⚡️ 等），幫助掃讀。
- 每個大概念下再拆幾個子小標題，層級清楚。
- 愛用「四大核心原因」「三個主要部分」這類明確計數。
- 列表與表格是常備工具，能列表就不寫長句。
- 程式碼與公式用區塊呈現，前後有文字解讀。
- 段落不會太長，一兩段就有一個小標題轉換。
- 價值詞直白：核心、關鍵、重要、優化、挑戰。

## Rhetorical devices
- 對比預設：before vs after、好 vs 壞、成本 vs 品質。
- 數字開場：用規模數據營造分量，再從中提煉問題。
- 「為什麼 X 很重要？」——標準的價值點題句式。
- 分步驟講解：編號清單，一步一步推進。
- 表格歸納：把幾個選項的優缺點一次攤開。
- 類比輔助：把抽象系統比作日常生活中的東西（水管、倉庫、餐廳）。
- 長尾分佈、80/20 這類經驗法則作為常備論據。

## Exemplars
- 「在開始設計前，我們先看看 YouTube 2020 年的驚人數據」——數字開場。
- 「為什麼這些數據很重要？這告訴我們系統必須處理……」——價值點題。
- 「為什麼要分離 API Servers 和視頻串流？因為……」——因果提問。
- 「四大核心原因：1. 儲存空間優化……」——明確計數的列點。
- 「聽起來很複雜？其實核心思想很簡單：……」——拆解難點。

## Negative list
- 不寫空泛的開場白（「隨著科技的進步……」）。
- 不丟術語不解釋；每個新詞第一次出現都有白話翻譯。
- 不長篇大論講一個點；能用列表就用列表。
- 不講與主題無關的個人軼事；例子必須服務於概念。
- 不用營銷腔或喊口號；結論來自數據與推理。
- 不戛然而止；每節有明確的收束句。
- 不堆砌代碼；代碼是輔助，主角是解釋。
