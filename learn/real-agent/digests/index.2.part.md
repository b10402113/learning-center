# L1 overview

- The Limits Of One Session — Once agents can build, the bottleneck moves from doing to planning, but grilling collapses at 200–300K tokens and splitting across sessions breaks when questions interlock. Fix: plan at the right fidelity, using Shape Up's ladder from discussion to working code. Takeaway: Wayfinder exists to plan arbitrarily large work over many sessions.
- Charting The Way — Wayfinder is a map (a GitHub issue labeled `wayfinder:map`) plus child decision tickets, one per session; tickets block each other, and the unblocked set is the frontier. Four ticket types: grilling, prototype, research (AFK sub-agent), task (checklist). Takeaway: the map is a low-res index of decisions and fog, and resolving tickets clears the fog toward a named destination.
- Chart The Map — Practice: run `/wayfinder` with a prompt on the in-app notifications feature, answer the grilling, and pick a spec as the destination. Skill drilled: charting scope, tolerating "I don't know", noticing research tickets firing.
- Chart The Map Solution — Solution shows the charting session: destination, scope, vendor, then glossary terms written during grilling, a seven-ticket map with all four ticket types, and two background research agents that return Knock as the vendor and email as the default out-of-app channel.
- Grilling Ticket — Practice: clear context, run `/wayfinder` on a single grilling ticket URL, answer until the ticket's question is resolved and the issue is closed. Skill drilled: one decision per session, no carry-over from the charting session.
- Grilling Ticket Solution — Solution demonstrates the session: claim ticket, read glossary and blocking graph, ten questions then five follow-ups, override two recommendations, write glossary terms, post the catalogue as the resolution and close. Takeaway: staying in the smart zone beats extending the session into implementation.
- Grilling Ticket 2 — Practice: a second grilling ticket, "Pick the notification vendor", resting on two closed research tickets. Skill drilled: reading a ticket's blockers before deciding, and closing with a recorded decision rather than new structure.
- Grilling Ticket 2 Solution — Solution shows the map growing as decisions reveal more: commit to Knock but keep the door open, postpone extra sign-ups (Firebase/FCM, email provider), accept the pricing cliff, split into two prototype tickets, name Courier as fallback. Takeaway: the graph extends as learning happens; decisions can be provisional.
- Task Ticket — Practice: identify a `wayfinder:task` ticket (sign up for Knock, provision dev keys), add the wizard skill, and get the agent to author an interactive bash wizard to run in a second terminal. Skill drilled: delegating fiddly external setup without handing secrets to the agent.
- Task Ticket Solution — Solution shows the model-invoked wizard firing from its description, guiding account, channel, API keys, signing key and enhanced security mode, writing four values to `.env`. Takeaway: verification caught a truncated signing key; secrets stay local, and the agent validates without reading them.
- Prototype Ticket — Practice: build the "Does Knock hold up against Cadence?" spike on a throwaway branch, iterate until all four checks are visible in running code, and only then close the ticket. Skill drilled: high-fidelity, token-expensive feedback.
- Prototype Ticket Solution — Solution runs the spike: check one passes, a wizard handles Knock workflow setup, stage three confuses the author badly, and the agent works around it by having Cadence write the default preference. Takeaway: friction is evidence about the product, and prototype code may take shortcuts; the resolution records pitfalls for implementers.
- Finish The Map — Practice: close the final three tickets (channels grilling, feed prototype, preferences grilling), remove throwaway prototype code, and verify the "Not yet specified" section is empty. Skill drilled: driving a whole map to completion on your own.
- Finish The Map Solution — Solution shows four more sessions: cut email and web push from v1, fold refund emails into notifications, prototype three feed variants and drill into pagination to land on bell popover plus infinite scroll, keep Knock behind an interface, then a mop-up grilling clears the last fog. Takeaway: a finished map is a complete decision index ready for `/to-spec`.
