生產硬化：託管沙箱與 eval

Step 5/5 · 從課程專案走到可維運的生產系統

學習目標

能判斷何時該把工具執行從本機 node:vm 移到託管沙箱、用 eval 驗證每一次改進，並用「多用戶、非寫程式的產品」這條線決定該自建 programmatic agent 還是用現成 harness。

沙箱：從 node:vm 走向託管服務

課程裡我們用本機的 node:vm 做 code mode，也學過一個關鍵限制：vm 不是真正的安全邊界。它適合示範「用一段程式取代多次工具往返」的概念，但如果你把它當成跑不可信程式碼的防線，那就是在賭。

生產環境的做法是把工具執行搬到託管沙箱（hosted sandbox）：由專門的服務負責隔離、資源限制與生命週期。這個領域已經有幾個成熟的選項，各自提供不同的隔離層級與 API，把它們接進 harness 的方式，跟你當初接 runInSandbox 幾乎一樣——換掉實作，保留介面。

介面是你自己定的（runInSandbox(code)），實作是可以換的。先寫對介面，之後搬家就不痛。

什麼時候該換掉本機沙箱

訊號為什麼本機沙箱不夠
多租戶 / 多使用者別人的程式碼不該跟你的 process 共享同一個世界
執行的是不可信輸入vm 逃逸後果等同直接執行任意程式
需要嚴格資源上限CPU、記憶體、網路都要能硬性隔離與計量
要對外承諾 SLA隔離、審計、可觀測性得由專門服務承擔

Eval：驗證「改動真的變好」的唯一方法

harness 的每一層都能調——prompt 的措辭、工具的描述、壓縮的門檻、supervisor 的計畫。問題是：你憑什麼知道你改對了？沒有 eval，你只能靠感覺，而感覺在這種系統裡幾乎一定會騙你。

Eval 的做法不只是跑分，而是先把「好」定義清楚，再建立可重複的評測集，讓每次改動都有前後可比的訊號。它回答的是那個唯一重要的問題：這次改動到底讓系統變好，還是只是變了？

知道系統該長什麼樣，才看得出幻覺

另一個只有真的動手建過才有的能力，是「看得出模型在胡說」。如果你清楚一個正確的 harness 應該產生哪些事件——工具呼叫的順序、handoff 的理由、審批的觸發點——那麼當模型編造出一個不存在的流程時，你一眼就能察覺。這不是直覺，而是你把系統建起來後長出的刻度尺。

也因此，這個領域的學習方式不是讀完就好：多建幾個 agent，讓每個都真的跑起來；讀研究論文找靈感，就算數學看不懂，裡面的架構想法常常可以直接借；然後用 eval 把「靈感」變成可驗證的改進。

自建還是用現成：多用戶產品那條線

走到生產，最後會撞上一個決策：我該自己寫 programmatic agent，還是直接用 Claude Code 這類現成 harness？答案取決於任務與規模：

情境建議理由
任務是寫程式、需要電腦用現成 coding harnessBash、檔案、終端機、repo 它都幫你處理好了
任務是資料分析或原型用現成 coding harness它能直接動手，你不用自己造輪子
多用戶、非寫程式的產品自建 programmatic agent現成 harness 太通用、prompt 難 eval、無法強制決定性流程

關鍵在那句「無法強制決定性流程」。前面幾堂課你不斷看到的模式——審批由 harness 決定、handoff 由 runtime 攔截——都建立在你能控制流程的前提上。現成 harness 把這些控制權收走了，你只剩 prompt、skills 與 MCP（本質上都只是 context）。對一個要對使用者負責的多用戶產品，這樣是不夠的。

這個領域還很前沿

這些內容不是業界共識，而是相對前沿的做法：多數人會說「Claude 會做」，卻說不出內部怎麼做、也無法驗證做得對不對。好消息是，因為你現在知道系統該長什麼樣，你具備了驗證的能力——這正是這門課想留給你的東西。

把這套帶回你自己的 runtime

最後把整條路線收起來。你走過的每一個能力，都是可遷移的模式，而不是某個函式庫的用法：

  • durable execution：把 side effect 包成可重放、可 checkpoint 的 step。
  • sandbox boundary：自訂介面、可換實作，本機到託管只是換引擎。
  • compaction：歷史要能估算、摘要、以輪為單位滑動。
  • handoff 與 supervisor：agent 是資料，控制權轉移由 runtime 攔截。
  • approval gate：決定性的暫停與恢復，是 inbox 世界的互動基礎。

把這些模式在你自己的 Agent OS 上重新推導一次，你會發現你學會的不是「怎麼用 TypeScript 寫一個 harness」，而是「一個 harness 為什麼要長這樣」——那才是能帶得走的部分。
