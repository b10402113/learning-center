裸迴圈的失敗模式

Step 3/5 · 把 harness 拆掉，看 agent 在哪裡壞掉

學習目標

能描述一個沒有 harness 的裸 LLM 迴圈會在哪幾種情境下失敗——只有一次性交易推論、無記憶、無持久化、無法自癒——並指出每種失敗對應缺失的哪一層。

最快的理解方式：先讓它壞

與其從定義背誦「harness 有什麼」，不如反過來：假裝 harness 不存在，直接呼叫模型，然後看哪裡壞。壞掉的地方，就是 harness 存在的理由。課程正是用這個節奏教的——先做一個壞掉的最小 agent，再一層一層補。

裸迴圈的失敗，可以歸成四種。每一種都能對應回上一節的某個設計面。

失敗一：只會「一問一答」

裸的模型呼叫是一來一回的 transactional（交易式）：你給一段 prompt，它回一段文字，然後這段關係就結束了。它沒有「對話」的概念，不會記得前一句你說過什麼，也無法追問、澄清、改口。你要的是一個能來回討論、把任務拆開逐步推進的 agent；它給你的是一次又一次互不相干的問答。

缺的是哪一層：對話迴圈與上下文記憶。

失敗二：金魚般的失憶

就算你硬把它接成迴圈，每一輪它都像剛醒來。上一輪查到的事、用戶提過的偏好、中途寫下的草稿——全都不見了。它沒有短期記憶（這輪聊到哪）、長期記憶（這個用戶是誰）、也沒有暫存空間（正在算的東西）。

缺的是哪一層：記憶子系統的四種記憶。

失敗三：一關窗就死

你丟了個「查十個網站、彙整成報告」的任務讓它跑。跑到一半，你關掉 app 或 server 重啟，於是：進度全沒、得從頭重跑；更糟的是，如果它在中途做過「寄出退款」這類不可逆的副作用，重跑就會做成兩次。裸迴圈既不能斷點續跑，也保證不了「只做一次」。

缺的是哪一層：持久化執行（checkpoint + 冪等）。

失敗四：壞了不會自己站起來

模型答錯、工具呼叫失敗、遇到沒遇過的輸入——裸迴圈沒有一層機制去「偵測錯誤 → 修正 → 重試」，也沒有自我評估。它不會自癒，壞了就壞了。一個真正可靠的 agent，要能察覺自己出錯並試著補救。

缺的是哪一層：自癒與 guardrail（護欄）機制。

四種失敗對照表

失敗症狀缺的那層 harness
一問一答不記得上下文，無法來回討論對話迴圈 + 記憶
金魚失憶每輪都像剛醒來短／長／暫存／事實記憶
一關窗就死進度蒸發、副作用重複持久化執行
壞了不會自癒出錯就停、不修正自癒 + 護欄

這張表是整門課的地圖。之後每遇到一個新能力，你都能問：「它是來補哪一種失敗的？」看到別人的 agent 產品出包，也照樣套：「這故障屬於哪一欄？」——這就是長出判斷力的方式。
