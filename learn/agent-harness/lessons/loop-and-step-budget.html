Agent Loop 與 Step 上限

Step 2/5 · 迴圈骨架，與防止失控的保險絲

學習目標

能寫出 while 迴圈的 step 記數與 maxSteps 上限，並解釋為什麼 harness 要自己擁有這個迴圈、而不是用 SDK 內建的 loop。

把原料擺上桌

上一課組出了訊息陣列，現在要把它接進一顆會重複轉的迴圈。先看 runtime 檔開頭該拉進哪些東西：streamText（來自 ai）、幾個 TypeScript 型別、model、tools、以及 system prompt。這些都是前面幾課準備好的零件，這裡只是把它們搬到位。

其中 streamText 的工作就一句話：帶著這些訊息去 LLM provider 一趟，然後把回覆串流回來。它正是這顆迴圈的心跳。

Step 是什麼

在寫迴圈前，先定義一個詞。課程裡所謂的一個 step，就是一次「想 → 做 → 再想」的完整往返：你叫模型做一件事，它做了，接著它再想一想下一步。一圈就是一個 step。

這個詞後來會反覆出現——往後講到 durable execution 時，每個 step 會被包成一個可檢查點（checkpoint）的單位。現在你只要記住：step = 迴圈的一次迭代。

maxSteps：那條保險絲

模型可能陷入無限迴圈：它不斷呼叫工具、拿結果、再呼叫、再拿結果……永遠不喊停。放著不管，它會一直燒你的帳單。所以我們在迴圈外面立一個上限：

const maxSteps = 10;

「做最多十次就給我停」——這是防失控 AI 的保險。具體數字是個人選擇，課程用 10；重點不是數字，而是要有一個人為設下的終點。迴圈本身長這樣：

let step = 0;
while (step < maxSteps) {
  // 呼叫模型、處理串流、執行工具……（後面幾課會填進來）
  step++;
}

只要 step 追上 maxSteps，迴圈就強制結束。後面會看到，正常完成與被上限踢出去，兩者會被賦予不同的結局。

為什麼不直接用 SDK 內建的 loop

你可能會問：AI SDK 自己就有 maxRetries 之類的內建 loop，功能跟這顆一樣，幹嘛重造輪子？答案是控制權。

用了 SDK 的內建 loop，就等於「選擇進入」它的 hooks（掛鉤）體系——你被迫用它的回呼、受它的實現方式綁定。一旦哪天要換 SDK、換語言，這些掛鉤全得重寫，你就被釘死在 AI SDK 的世界裡。反過來，這門課的策略是：AI SDK 只用來做「呼叫模型」這一件事，其餘——迴圈、事件、執行——都是你自己的。這樣換 SDK、換語言，動的只有最外面那一層，核心迴圈一字不改。

這條界線（boundary）是整個 harness 的可攜性基礎。每一課你都會看到它：能放給 SDK 的，只有那一趟 LLM 呼叫。
