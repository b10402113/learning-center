一個 agent 是怎麼呼叫工具的

Step 1/4 · 工具與 Agent 的契約

學習目標

能說出一個沒有 harness 的 agent 是怎麼用工具完成一件事的——工具呼叫 → 拿到結果 → 迴圈直到有信心回答——並列出三種讓這個裸迴圈在生產環境失敗的原因。

先想：模型本身動不了外面任何東西

一個大型語言模型（LLM，Large Language Model）本質上只會做一件事：吃一串文字，吐一串文字。它無法自己查資料庫、無法寄信、無法花錢。要讓它真的對世界動手，你得給它工具（tool），並讓它自己決定「現在該不該叫工具、叫哪一個、帶什麼參數」。

這一節只講最小、最直覺的版本——先不談任何 harness。這就叫裸迴圈（naive loop）：模型的推論能力和幾個工具的執行，直接串在一起，中間沒有任何保護、沒有限制、沒有失敗處理。它跑給別人的示範（demo）非常漂亮，卻完全不能上生產。

工具呼叫迴圈的解剖

把這個裸迴圈一步步拆開，它長這樣：

  1. 給工具加描述。你把每一支工具、以及它是做什麼用的描述，一起放進模型能看到的地方。模型看不到工具底下的程式碼，它只透過這些描述文字來「認識」工具。
  2. 呼叫模型。模型讀完使用者問題和工具描述，決定下一步：是直接回答，還是要叫一支工具。
  3. 模型要求工具呼叫。當模型決定叫工具，它的回應裡會指名是哪一支工具、以及要傳給它的參數（arguments）。
  4. 執行工具。你的程式拿到那份參數，真正去跑這支工具。
  5. 把結果餵回去。工具的執行結果被當成新訊息，塞回模型。
  6. 重複。模型看了結果，可能再叫一支工具、或者覺得夠了，給出最終回答。迴圈一直轉到模型有信心回答為止。

這個「叫工具 → 拿結果 → 再判斷」的迴圈，就是所有 agent 執行的底層心跳。值得一提的是，像 AI SDK 這類函式庫現在已經把這段迴圈直接內建了——你呼叫高層 API，它自己會在背後跑完這整輪。

裸迴圈的三種失敗模式

問題是，這個迴圈是一匹沒有韁繩的野馬。具體來看，它至少在三件事上會砸鍋：

失敗模式出了什麼事舉例
無限迴圈沒有停止條件、沒有失敗處理，可能一直轉或一遇錯誤就死模型永遠「覺得還差一點」，狂叫工具停不下來
危險工具無把關會造成真實後果的工具沒有審批層，模型說叫就叫一支「花錢」的退款工具，迴圈毫不猶豫就執行
可靠性靠機率LLM 輸出是機率的，好的示範可能只是好的、沒被量測的 prompt換句話說 prompt 後，同一個 agent 表現天差地別

前兩項是「結構」問題，可以用程式硬性補上（限制步數、加審批）。第三項是「機率」問題，光靠程式補不齊：你得有評估（evals）去量測它到底行不行。evals 是修好可靠性的其中一半，基礎設施（infrastructure）是另一半——這門課專注做的，就是基礎設施那一半。

把這個心智模型立好之後，下一節就要動手：一支工具的定義到底長什麼樣、那些「描述文字」和「參數」是怎麼被寫死下來變成可執行的契約。
