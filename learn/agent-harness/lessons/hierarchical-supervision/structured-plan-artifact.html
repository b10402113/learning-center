把 plan 做成一級結構化產物

Step 3/5 · generateObject、zod schema、z.infer 與 deprecation 提醒

學習目標

能說明 generateObject 相對 generateText 的差異，用 zod 定義 plan schema（steps 內含 id / agent / objective）並以 z.infer 取型別，實作 makePlan；同時知道 generateObject 已被標記 deprecated 的替代寫法。

問題：計畫不能只是散文

如果 supervisor 產出的計畫只是一段自由文字，會有兩個麻煩：程式沒辦法可靠地迭代它（哪一步對應哪個 agent？），也沒辦法驗證它（少了一個欄位誰知道？）。所以第一步是讓計畫變成一份有結構、可驗證的物件。

這正是 結構化輸出（structured outputs）要解決的事。

generateObject vs generateText

兩者都呼叫模型，差別在回傳的東西：

回傳保證適合
generateText純文字無結構保證摘要、對話、需要自然語言的地方
generateObjectJSON 物件保證符合你給的 schema計畫、分類、任何要被程式消費的資料

結構化輸出之所以強大，是因為它由 schema 背書：你宣告形狀，模型就必須吐出符合形狀的 JSON。這解鎖了比如「用元件 schema 生成 React 元件」這種即時生成 UI 的用例。

它也讓「舊做法」顯得多餘。以前要拿結構化資料，得在 prompt 裡拜託模型用 markdown 的 JSON 區塊回答，再自己 parse、比對 schema、不合法就重試——一個 loop-parse-retry 的迴圈。現在的模型在模型層就被調校過 JSON 輸出，schema 遵循變成模型本身的能力，而不是你外掛的補救措施。

定義 plan schema

計畫的形狀是：一個 steps 陣列，每個元素回答「哪個 agent、做什麼」。用 zod 宣告，並在欄位上寫 describe 當給模型的指示：

const PlanSchema = z.object({
  steps: z.array(
    z.object({
      id: z.string().describe("short id, e.g. 'billing'"),
      agent: z.enum(["billing", "technical", "sales"]),
      objective: z.string().describe("what this investigator should find out"),
    }),
  ),
});
type Plan = z.infer<typeof PlanSchema>;

三個細節：agent 用 z.enum 限制成三個已知的調查員名稱——這讓模型不可能編出一個不存在的工人（正好對上 runInvestigator 的防呆）；id 與 objective 的 describe 直接變成對模型的欄位說明；而 z.infer 從同一份 schema 推導出 TypeScript 型別，之後的程式碼就能拿到完整的型別檢查，不必手動維護兩份定義。

makePlan(task)

async function makePlan(task: string): Promise<Plan> {
  const { object } = await generateObject({
    model,
    schema: PlanSchema,
    system:
      "Decompose a customer escalation into independent sub-tasks — one per area the message actually raises (billing / technical / sales). Only include relevant areas.",
    prompt: task,
  });
  return object;
}

system prompt 是計畫品質的關鍵。它做兩件事：把客訴拆成彼此獨立的子任務，以及「只包含訊息真的提到的領域」——如果客訴沒談技術問題，就不該硬派一個 technical 調查員出去浪費一次呼叫。

supervisor 的角色定位

到這裡可以清楚劃分職責了：supervisor 的工作是判斷需不需要調查員、以及計畫是什麼；它本身不是調查員，不碰工具、不查資料。它是規劃者與指揮者，計畫是它的產出。這也是為什麼 supervisor 是整段程式裡最複雜的檔案——它要同時接上 DBOS、事件、模型與 workflow。

一個當前的 API 提醒：generateObject 已 deprecated

寫這段程式時會遇到一個 deprecation 警告：generateObject 被標記為已棄用。

官方建議的替代寫法是改用 generateText 搭配 output 設定（要做串流則有 streamObject 等變體）。這裡刻意保留目前的 generateObject 程式碼，因為它把結構化輸出的概念表達得最直接；但你在自己的專案或之後重構時，應該採用新的 API。記住這個落差就好，不必現在改。

計畫有了型別與 schema，下一步是把它放進一條持久化的 workflow，讓它只被計算一次、崩潰也不重來。
