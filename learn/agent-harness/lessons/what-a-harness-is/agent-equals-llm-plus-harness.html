Agent = LLM + Harness

Step 1/5 · 那層讓 agent 可靠起來的基礎設施

學習目標

能說出「agent = LLM + harness」這個等式，並解釋為什麼 harness 是讓 agent 可靠、可依賴的那一層基礎設施，而不是可有可無的包裝。

先看一個「沒被包起來」的模型呼叫

你寫過或看過這種程式：把整段 prompt 丟給 LLM，拿到一段回覆，印出來，結束。這一趟呼叫就是所謂的 transactional inference（一次性交易推論）——輸入進去、輸出出來，中間沒有任何狀態留下來。下一次呼叫，模型完全不記得剛剛聊到哪裡。

這種東西能叫 agent 嗎？不行。它沒有對話、沒有記憶、跑不長、也無法在出錯時自己站起來。把「一次模型呼叫」放大成「一個能交付工作的 agent」，中間缺的那一大塊，就是本節的主角：harness（護具／框架）。

核心等式

整個課程建立在一條等式上：

agent = LLM + harness

把它拆成兩半來看：

那一半負責什麼類比
LLM「想」——推理、判斷、生成文字、決定下一步引擎（大腦）
harness「讓想的結果在真實世界可靠落地」——記憶、工具、持久化、自癒、對話車體（底盤、油路、方向盤、安全帶）

一顆再強的引擎，沒有底盤、油路、方向盤，也開不出停車場。同樣地，「最好的模型」若被一個爛 harness 包著，也交不出可靠的成果。這正是後面第四步要講的：harness 的品質，比模型選擇更能決定勝負。

Harness 是「基礎設施」，而且跟 agent 無關

Harness 有兩個關鍵性質，要牢牢記住：

第一，它是基礎設施，不是某個 agent 的私有配件。課程裡用的 agent 故意做得很無聊，工具都是 mock（假的）——因為重點不是這個 agent 多聰明，而是包著它的那層環境。沒有 harness，你有的只是一次性交易推論；有了 harness，它才長出對話、記憶、持久化、自癒能力，才有資格被叫成一個能上生產環境的 agent。

第二，它 agent-agnostic（跟具體 agent 無關）。同一套 harness 可以包住不同模型、不同任務的 agent。單獨看它常常很沒意義——一個只有 bash、檔案系統權限、auto-compaction 的框架，擺在那裡什麼都不是；但一包在某個 agent 外面，就立刻變得意義重大、決定成敗。

心智模型放對位置

把這個等式立在腦子裡，後面每一步都是在「補這段右邊的 harness」。當你在日常用 Claude Code 或 opencode 時，你其實已經是一個重度 harness 使用者：自動壓縮對話、開 sub-agent、要求你批准高風險操作——這些都是 harness 提供的，不是模型本身會做的。

所以下次再聽到「我們做了一個 agent」時，先問一句：那個 agent 外面的 harness 長什麼樣？這才是能看出門道的地方。
