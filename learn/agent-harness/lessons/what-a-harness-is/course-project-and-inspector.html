課程專案與 Inspector 的驗證面

Step 5/5 · 看懂 repo 結構、把 event stream 拿來當驗證面

學習目標

能說出課程專案的結構（harness／runtime／server／shared／web）、`npm run dev` 起動的 inspector 兩欄各顯示什麼，以及 event stream 為何成為每個能力的驗證面。

這門課的成品長什麼樣

課名原文是 "Stop building scripts. Start building durable multi-agent systems."——別再寫一次性腳本，開始打造能活過生產環境的系統。它不靠一個越堆越大的專案，而是每個 lesson 教一個新的架構 pattern：看到它被引入、被 live-coding、然後過關。

開箱之後，你看到的是一個叫 Harness Inspector 的偵測工具：左邊是聊天／任務欄，右邊是即時的 event-stream（事件串流）面板。一個 triage（分診）agent 會在左邊完成任務、規劃、升級、呼叫工具；右邊同步滾出它做的每一件事。

Repo 結構：只有這幾個資料夾重要

資料夾角色你要不要碰
harness/核心：runtime、model、memory、sandbox、agents、tools、bus、db大部分課程都在這裡
shared/定義所有事件型別（runtime 發出、client 消費）讀懂即可
server/WebSocket event bus + Express少量改動
web/Inspector UI（Vite + React）幾乎不用做
lessons/每課 markdown 筆記（VitePress）閱讀即可

其他如 notes、OpenSpec、.dev.vars 分別是講師用途、追蹤工具、放 API key 的地方。

整個課程的核心是 harness/runtime.ts——agent 的環境、它執行的迴圈，類似遊戲的 game loop。開箱時它幾乎全是 stub（佔位），只會 emit 出一些事件。

為什麼是 WebSocket，不是普通的 HTTP？

一個分散式、持久化的 agent，需要雙向、fire-and-forget（發了就忘）的事件，而不是一問一答的 request/response。所以傳輸層用 WebSocket：事件能推到任何已連線的 client。你不需要懂 WebSocket——只要知道 emit 就是「廣播一件事發生了」。

開箱第一跑：先看到「no agent yet」

跑 npm run dev 會起動 harness server（:8787）＋ inspector UI（:5173）。丟一個任務進去，你看到的不是結果，而是事件流：

workflow.started  →  "no agent yet"  →  workflow.completed

這是刻意的：runtime 只會 emit，還沒有真的 agent 迴圈。接下來的每一步——做一個極脆弱的 agent 迴圈、再包上 harness——都由你來填。很多 UI 按鈕先是 no-op，所以你不必回頭碰 UI。

為什麼事件串流是「驗證面」

仔細看，這門課反覆強調一件事：event log 就是這個系統的真相。瀏覽器那張 UI，不過是把 server 發來的事件串流「投射」成畫面；server 本身，也只是把 durable 的事件歷史重播給你。

這代表：持久化、handoff、sandbox、memory、supervision、approval——每個能力完成後，你都能在同一條事件串流上看到一個新的事件型別滾出來。課程要教的七個能力，分別是：

  1. The Agent Harness——包住 LLM 的 middleware
  2. Durable Execution——crash 或 rate limit 時從斷點續跑
  3. Secure Sandboxing——用 timeout 隔離跑不受信任的程式碼
  4. Advanced Memory——狀態儲存、滑動視窗、總結
  5. Orchestration——triage 與 specialist 之間的意圖路由與交接
  6. Hierarchical Supervision——supervisor 規劃、平行開子 agent、合併結果
  7. Human-in-the-Loop——可無限期暫停／恢復的審批

後面每一課，你都會回到這條事件串流，看著新事件型別一個一個出現。先記住這件事：你能觀察到的，才敢信任它是持久的——這就是 inspector 存在的理由。
