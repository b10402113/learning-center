system prompt：agent 的底層契約

Step 4/4 · 工具與 Agent 的契約

學習目標

能區分 system prompt 與使用者訊息，說明它承載什麼（背景、人設、背景脈絡）與它的代價（吃 context window），並說出為什麼把其他產品的 system prompt 挖出來其實不是大事。

給模型的一份「底層設定」

工具定義是「動作的契約」，這一節要講另一張契約：system prompt（系統提示）。如果說工具告訴模型「你能做什麼」，system prompt 就是告訴模型「你是誰、你該怎麼表現」。

system prompt 是 agent 作者寫下的那一份基礎指令與人設：背景知識、角色定位、語氣、以及關於使用者的脈絡。它跟「每一則使用者訊息」是分開的——使用者訊息是每回合都會變的那句問話，system prompt 則是每次對話開始前就固定貼在位置上、貫穿全程的那份底層設定。你在聊天產品裡看到的「語氣／人格」選項，本質上就是在改 system prompt。

它跟使用者訊息差在哪

那一份文字多久變一次裝的是什麼
system prompt固定，整段對話同一份背景、人設、語氣、使用者脈絡
user message每回合都變這一刻具體的那句要求

一個最陽春的 system prompt 可以長這樣——它描述課程裡的 triage agent、並交代它的工作節奏：

export const systemPrompt = `
你是一個支援團隊的 triage agent。
請逐一處理每個工作項目：先判斷類型，再簡短摘要你的處理結果。
`;

它的代價：吃 context window

system prompt 不是免費的。它每一回合都會被送進模型，所以它佔掉的是脈絡視窗（context window）的寶貴空間。一個 system prompt 動輒數千 token，而且不同模型的每個 token 對應大致四到六個英文字元——換算成中文字數會更少。這意味著你把 system prompt 寫得越肥大，留給真正工作的空間就越少。這是後面「記憶」那一大主題會直接接手的問題：該塞多少、塞哪些、怎麼在塞不下的時候壓縮。

被挖出來，其實不是大事

你可能看過一種新聞：有人把某個產品的 system prompt 抽出來公開，講得像資安事故。實際上，供應商（例如 Anthropic）普遍不把 system prompt 外洩當成大事。原因在上一節已經講透：system prompt 和其他文字一樣，只是「軟性建議」，不是「安全邊界」。真正的安全不靠「把 prompt 藏起來」，而是靠 harness 層的硬性把關。prompt 就算被看光，也挖不走你真正值錢的東西——那些寫在程式裡的強制邏輯。

到此，這個節點的另一半拼圖就齊了：agent 跟外面的世界訂的是兩張文字契約——工具（能做什麼）與system prompt（該怎麼表現）——而這兩張契約都有同一個邊界：它們只能「建議」模型，不能「約束」模型。真正有約束力的，永遠是包在模型外頭的那層 harness。
