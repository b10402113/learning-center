run_code 工具：把沙箱接進 harness

Step 3/4 · 把沙箱變成 agent 的一支工具

學習目標

能定義 runCode 工具（description + code schema）、建出只開放 getCharges 與 searchKnowledgeBase 的 sandbox API，並在 runTool switch 裡接上它，體會「定義工具、處理工具」的固定節奏。

先有 sandbox API：白名單長什麼樣

上一步的 runInSandbox(code, api) 要一個 api。這一課要決定「這個 sandbox 到底允許 agent 的程式做什麼」。課程用一個 billing（帳單／退款）情境，白名單刻意縮到只剩兩支函式：

const sandboxApi: SandboxApi = {
  getCharges: (customerId: string) =>
    CHARGES.filter((c) => c.customerId === customerId),
  searchKnowledgeBase: (query: string) =>
    searchKB(query),
};
  • getCharges(customerId) —— 查出某個客戶的所有帳單（過濾假資料 CHARGES）。
  • searchKnowledgeBase(query) —— 去知識庫檢索（例如退款政策）。

兩支都是唯讀。沙箱裡的程式能讀取、能計算，但不能改狀態、不能寄信、不能退款——那些有副作用的能力，留在外面的 durable tools 裡，走完全不同的安全路徑。這就是「safe / dangerous 工具的界線」：跑在沙箱裡的只配拿到唯讀能力。

另外注意 searchKB 被抽成了獨立 helper：原本的工具程式碼和現在的 sandbox，兩邊共用同一支函式，避免同一份檢索邏輯寫兩次。這是個小卻重要的重構——能力要能複用，才不會各寫各的。

定義工具：description 就是給模型的說明書

工具定義跟前幾課學的 tool() 完全一樣，只是這次 tool 的動作是「讓模型寫程式」：

runCode: tool({
  description:
    "Run a JavaScript async function body inside a sandbox. " +
    "Use `await tools.getCharges(customerId)` and " +
    "`await tools.searchKnowledgeBase(query)`. " +
    "Write results with `console.log(...)`, and `return` any JSON value.",
  inputSchema: z.object({ code: z.string() }),
  execute: () => { throw new Error("handled by runTool"); },
}),

看清楚這裡的契約，它跟前面的工具節點是同一套道理：

  • description —— 告訴模型「這支工具讓你寫一段 JavaScript async 函式主體，你可以 await 哪些東西、可以 console.log、可以 return JSON」。模型依賴這段文字來決定何時用它、怎麼寫。
  • inputSchema —— 輸入就一個欄位：code: string。模型把整段程式碼塞進這個字串。

一句話記法：工具的 description 是護欄。你只有在說明書裡寫清楚「能 await 白名單那兩支函式」，模型的程式才不會妄想呼叫 process 或 require。

處理工具：runTool switch 接上沙箱

定義了工具，還得在 harness 自己的 executor runTool 裡「處理」它。這是整門課一直重複的節奏——定義工具、處理工具：

switch (toolName) {
  case "getCharges": { ... }
  case "searchKnowledgeBase": { ... }
  case "runCode": {
    const { code } = args as { code: string };
    return runInSandbox(code, sandboxApi);   // options 可省略，兩個參數就夠
  }
}

重點在 runCode 這個 case：解析出 code 字串，直接丟給 runInSandbox(code, sandboxApi)。注意 options 是選填——只用預設的 2 秒 timeout，所以傳兩個參數就合法。沙箱回傳的 { ok, ... } 原封不動地當成 tool 結果，交回給模型。

至此整條路就通了：模型遇到要算的事情 → 呼叫 runCode → 寫一段程式 → runTool 把它送進沙箱 → 沙箱在只有兩支唯讀函式的環境裡執行、綁 timeout → 回傳 { ok, result, logs }。下次想再加一種沙箱能力，節奏不變：在 sandbox API 加一支函式、在工具 description 裡提它、在 switch 加一個 case。
