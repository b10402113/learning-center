# 沙箱與 Code Mode

## Learning goal

用 `node:vm` 實作 `runInSandbox`（注入 API/console、async IIFE、timeout race）並接上 `run_code` 工具，讓 agent 以一段程式取代多次工具往返；同時指出 `vm` 不是真正的安全邊界。

## Steps

1. [[learn/agent-harness/nodes/sandboxed-code-mode/code-mode-why|Code Mode：一段程式取代多次往返]] — 為什麼沙箱 agent 產生的程式碼、code mode 如何省下多次工具往返
2. [[learn/agent-harness/nodes/sandboxed-code-mode/run-in-sandbox|實作 runInSandbox：node:vm 的沙箱邊界]] — context、注入 tools/console、async IIFE、timeout race、ok/error 結果（after step 1）
3. [[learn/agent-harness/nodes/sandboxed-code-mode/run-code-tool|run_code 工具：把沙箱接進 harness]] — sandbox API、runCode 工具定義與 runTool switch（after step 2）
4. [[learn/agent-harness/nodes/sandboxed-code-mode/code-beats-inference|為何 code 勝 inference，與 vm 不是真正的邊界]] — $49 退款 demo、算術幻覺、timeout 設定、test-sandbox 的三大護欄（after step 3）

## Lesson

這節課回答一個敏感的信任問題：agent 會自己寫程式，那這份程式該在哪裡跑、跑壞了會不會弄壞你的伺服器？答案是兩件事一起做——先讓模型在**一段程式裡**把多次工具呼叫串起來（code mode），再用一個**逃不出去的沙箱**框住這段程式。

四步拆成兩半。前半（第一步、第二步）先講清楚「為什麼」與「沙箱本身」：code mode 的價值是把十幾次「呼叫─等待─推理─回傳」的往返壓成一次「寫程式、跑、拿結果」，而 `node:vm` 的 `runInSandbox` 就是那個只在最小 context 裡執行、注入白名單 API、綁 timeout 的邊界。後半（第三步、第四步）把沙箱接進 harness 並驗證：定義 `runCode` 工具、在 `runTool` switch 接上它，用一個真的算出 49 美元退款的 demo 證明「寫程式比推論可靠」——因為推論做算術、認日期是會幻覺的。

但整節最重要的一課留在最後：`node:vm` 只是個**中介點**，不是真正的安全邊界（它殺不掉外洩的 async 工作）。課堂上用它學得又快又好，但真要部署，答案是託管沙箱（e2b、Cloudflare Sandbox SDK 這一類）。學完這節，你能把同一層沙箱邊界推回自己的 runtime（OryxOS / Java）。
