# 訊息序列完整性與端到端示範

<LearningGoal>
能解釋 toolResultsMessage 為何要立刻回填同 ID 的結果以維持 message 陣列有效，並看懂 triage → billing 的端到端 handoff 事件流。
</LearningGoal>

## Lesson

tool call 之後必須立刻接上同一 tool call ID 的結果，而 handoff 沒有 execute，所以 runtime 用 toolResultsMessage 手動合成那則回應；這條鐵律正是「以 turn 為壓縮單位」的理由，也讓 triage → billing 的端到端流程能靠 durable 事件與 agent 交換走完，而不必要求模型零失誤。
