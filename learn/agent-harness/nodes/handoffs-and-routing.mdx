# Handoff 與 Agent 路由

## Learning goal

判斷何時該拆 agent（避開 swarm 陷阱），把 agent 變成資料（name + systemPrompt + toolSet），用 runtime 攔截 handoff 做控制權橫向轉移，示範 triage → billing 與最小權限。

## Steps

1. [[learn/agent-harness/nodes/handoffs-and-routing/when-to-split|判斷：何時拆 agent，handoff 到底是什麼]] — 權限邊界、handoff vs subagent、避開 swarm 陷阱
2. [[learn/agent-harness/nodes/handoffs-and-routing/agent-as-data|把 agent 變成資料：三個欄位]] — name + systemPrompt + toolSet，triage 與 billing，最小權限（after step 1）
3. [[learn/agent-harness/nodes/handoffs-and-routing/runtime-intercepts-handoff|runtime 攔截 handoff：橫向控制權轉移]] — handoff 工具、currentAgent、攔截、交換與 durable event（after step 2）
4. [[learn/agent-harness/nodes/handoffs-and-routing/turn-integrity-and-demo|訊息序列完整性與端到端示範]] — toolResultsMessage 與 triage → billing 端到端（after step 3）

## Lesson

一個 agent 塞滿所有工具通常就能跑，但當某些工具不可逆、破壞力大，或分屬不同團隊、需要不同護欄時，把 agent 拆成多個、讓控制權「橫向轉移」就比讓一個全能 agent 承擔一切更安全、更清楚。

這節課做的就是把「agent」從一顆寫死的迴圈，降格成三個欄位就能描述的一筆資料：名字、system prompt、工具集。剩下的 runtime、記憶、持久化全部共用。分工之後，每個 agent 只拿它職責範圍內的工具——triage 不會退款工具，billing 才有——這正是最小權限，而不是把危險工具發給每個人。

真正讓它動起來的是 runtime 那一層：handoff 不是 agent 自己能完成的動作（它無法把自己換掉），所以 runtime 在武器呼叫迴圈裡攔截 handoff 呼叫，切換 currentAgent、發出 durable 的 agent_handoff event，並立刻回填一筆同 tool call ID 的工具結果以維持訊息陣列有效。學會這四步，你就掌握了 control-flow 原語該住在 harness 而非 LLM 裡的這條核心原則。
