# Messages 陣列就是 agent 的狀態

你在聊天介面問了 AI 一個問題，接著補充「那如果換成下週呢？」你可能會以為 AI 自然記得上一句。但對常見的 messages 陣列呼叫方式來說，模型不會自動保留剛才的對話；要讓它接得上，應用程式得把對話內容再次送過去。

## 先組出 system 和 user 訊息

每則訊息通常有 `role` 和 `content`。`role` 說明訊息是誰提供的；`content` 則是訊息內容。

`system` 用來交代模型要遵守的指示，`user` 放使用者這一輪送來的文字。以下是概念範例：

<!-- derived -->
```js
const messages = [
  {
    role: "system",
    content: "請用簡潔的繁體中文回答。"
  },
  {
    role: "user",
    content: "幫我整理這段文字的重點。"
  }
];
```

把這個陣列送給模型時，模型就能根據 system 指示來回應 user 的問題。`system` 和 `user` 是訊息的角色，不是兩種不同的對話記憶。

## 為什麼每一輪都要重送對話？

模型回覆後，應用程式需要把回覆也加入對話紀錄。下一輪提問時，再把先前的訊息一併送出：

<!-- derived -->
```js
const messages = [
  {
    role: "system",
    content: "請用簡潔的繁體中文回答。"
  },
  {
    role: "user",
    content: "幫我整理這段文字的重點。"
  },
  {
    role: "assistant",
    content: "重點是……"
  },
  {
    role: "user",
    content: "那可以再縮短成一句話嗎？"
  }
];
```

這裡的 `assistant` 訊息是模型上一輪的回答。若只送出最後一句「那可以再縮短成一句話嗎？」，模型就沒有前文可參照，也不知道「縮短」指的是哪段文字。

換句話說，模型不會因為剛才回答過，就自動記得自己說了什麼。每次呼叫都要提供它需要的對話脈絡；在這種設計裡，應用程式管理並重送的 messages 陣列，就是 agent 對話狀態的一部分。

## 對話越長，送出的內容也越多

每一輪都帶上先前對話，代表陣列會隨著聊天變長，送出的文字量也會增加。對話越長，模型要處理的內容通常越多，因此回應可能變慢，使用成本也可能上升。

所以，實作時不能只記得把新問題放進陣列，也要把模型回覆加入紀錄。下一輪再連同 system 指示與先前對話一起送出，模型才能延續上下文。
