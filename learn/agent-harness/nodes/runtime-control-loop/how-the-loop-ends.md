# 迴圈怎麼結束：回答、maxSteps、失敗

使用者送出問題後，工作流程可能要讓模型呼叫工具、讀取結果，再繼續處理。這個迴圈會在什麼時候結束？可以先分清楚兩條路：模型準備好回答時正常收尾；如果步數用完或發生錯誤，就以失敗事件結束。

## 沒有工具呼叫：送出回答並完成

每一輪收到模型結果後，先看它是否還需要呼叫工具。如果沒有工具呼叫，代表模型已經可以回答。

這時先取出回答文字，送出 `model completed` 事件，再送出 `workflow completed` 事件，並把回答文字作為最終輸出。這就是正常收尾：工作流程交付答案，然後結束。

## 迴圈走到底：以 maxSteps 收尾

如果流程沒有在迴圈內正常結束，代表它可能已經跑到允許的步數上限，也就是 `maxSteps`。這時不能把它當成已完成，也不應送出正常完成事件，而是改送 `workflow failed`，並附上適合使用者閱讀的訊息，例如「max steps」。

換句話說，離開迴圈本身不等於完成。正常完成應該在迴圈內明確發生；如果跑出迴圈卻沒有走到正常完成，就要以失敗狀態收尾。

## 發生例外：把錯誤交代清楚

另一條異常路徑是呼叫模型時出錯，例如遇到速率限制或系統故障。收到錯誤後，可以送出 `workflow failed`，附上工作流程 ID 和錯誤訊息，並把錯誤轉成字串，方便傳遞或顯示給使用者，接著結束流程。

這樣一來，兩種收尾方式就很清楚：有答案時送出 `workflow completed`；步數用盡或發生錯誤時，送出 `workflow failed`，並附上原因。
