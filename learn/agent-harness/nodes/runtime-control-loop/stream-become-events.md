# 把 stream part 翻成 UI 事件

使用者送出問題後，模型可能一邊產生文字、一邊呼叫工具。若等到全部完成才更新畫面，使用者就看不到過程。做法是逐一讀取串流中的 part，辨認它的類型，再轉成前端能處理的 UI 事件。

可以用 `switch` 依 part 類型分流。每種 part 對應一種事件：

| stream part | 對應的 UI 事件 | 畫面可以怎麼呈現 |
|---|---|---|
| `text delta` | 文字更新事件 | 把新收到的文字接到回答中，讓內容逐步出現。 |
| `tool call` | 工具呼叫事件 | 顯示模型正在呼叫工具，或更新相關的處理狀態。 |
| `tool result` | 工具結果事件 | 顯示工具回傳的結果，或更新工具處理狀態。 |
| `error` | 錯誤事件 | 告知使用者發生錯誤，並呈現適當的錯誤訊息。 |

例如收到 `text delta` 時，可以把這段文字連同工作識別碼送給前端。前端收到事件後，就能把文字加到目前的回答裡。這裡重要的是讓關心這段工作的用戶端持續收到更新；事件要透過 WebSocket、輪詢或其他方式傳送，則取決於系統架構。

串流中的更新是逐步發生的，但對話紀錄通常要等串流結束後，再加入完整訊息。這樣可以讓畫面即時更新，同時避免把尚未完成的部分當成完整結果保存。
