# Tool call 是請求，不是執行

你問模型「這個城市現在下雨嗎？」它可能不會直接回答，而是回傳一個工具呼叫，表示想使用天氣查詢工具。這不代表模型已經連上工具、查到資料；它只是提出請求。

在一般由應用程式執行工具的流程裡，模型會回傳工具名稱和參數，例如要查詢哪個城市。模型負責選擇要用哪個工具、提供所需參數；真正執行工具的，是你的應用程式或伺服器。

流程可以想成：

1. 你把可用工具及其用途提供給模型。
2. 模型回傳工具名稱與參數，提出執行請求。
3. 你的程式依照名稱找到對應工具，並用那些參數執行。
4. 工具完成後，你把結果交回模型，讓它接著回應使用者。

因此，收到 tool call 時，不能只把它當成答案顯示給使用者。程式還要判斷是否需要執行、找到正確的工具，並把結果送回模型。

## 用 toolCallID 配對請求與結果

模型提出工具呼叫時，也會提供一個 `toolCallID`。這個 ID 用來標記「這一筆工具請求」。工具執行完成後，回傳結果時要附上同一個 ID，模型才能知道結果對應的是哪一筆請求。

例如，模型提出查詢天氣的請求，ID 是 `call_123`。你的程式執行查詢後，送回結果時也要帶著 `call_123`。如果省略或換成別的 ID，模型可能無法把結果和原本的工具呼叫配對。

如果同時有多筆工具呼叫，這個配對方式尤其重要：每個結果都要回到正確的請求，而不是只把一串結果交給模型，期待它自行猜出各自的用途。

簡單來說，模型說的是「請用這個工具，帶上這些參數」，不是「我已經替你執行完了」。你的程式負責執行，再用相同的 `toolCallID` 把結果交還模型。
