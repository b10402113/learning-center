# 觀察壓縮：清空事件日誌，在 inspector 看 memory_compacted

<LearningGoal>
用 `clearEventLog` 與 `POST /api/clear`（含 CORS）清空 durable 日誌，在 inspector 上看到 `memory_compacted` 事件的 summarized turns 與 token 數，並解釋為何壓縮總發生在門檻略下方。
</LearningGoal>

## Lesson

用 `clearEventLog` 與含 CORS 的 `POST /api/clear` 把 durable 日誌清空後重跑，在 inspector 上看到反覆出現的 `memory_compacted` 事件（summarizedTurns 與 tokens），並理解壓縮因「呼叫模型前先檢查」而總落在門檻略下方；上限決定何時觸發，保留門檻決定壓完的落點。
