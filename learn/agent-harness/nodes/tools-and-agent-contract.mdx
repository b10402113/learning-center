# 工具與 Agent 的契約

## Learning goal

用 AI SDK 的 `tool()` 定義工具（description + Zod schema + execute），做出 KB 檢索與 classify/draft/send 工具與 system prompt，並解釋為何護欄不能只寫在 prompt 裡。

## Steps

1. [[learn/agent-harness/nodes/tools-and-agent-contract/how-agents-use-tools|一個 agent 是怎麼呼叫工具的]] — 認識工具呼叫迴圈，以及裸迴圈在生產環境的三種失敗模式
2. [[learn/agent-harness/nodes/tools-and-agent-contract/defining-tools-with-tool|用 tool() 定義工具：description、schema、execute]] — 寫出 `search_knowledge_base` 與 `classify_item`，掌握工具的三段式結構（after step 1）
3. [[learn/agent-harness/nodes/tools-and-agent-contract/unguarded-actions-need-the-harness|送出的工具：護欄不能只寫在 prompt]] — 用 `send_reply` 說明文字護欄為何必然失效，強制要落在 harness 層（after step 2）
4. [[learn/agent-harness/nodes/tools-and-agent-contract/system-prompt-as-contract|system prompt：agent 的底層契約]] — 認識 system prompt 承載什麼、代價是什麼（after step 1）

## Lesson

這節課把「agent 能呼叫工具」這件事拆成兩半：先是模型那一半——它如何決定要叫哪個工具、拿回結果、再一次次迭代；再來是工程那一半——工具長什麼樣、怎麼定義、邊界在哪。關鍵轉折在於：工具描述與 system prompt 都是「給模型的契約文字」，但契約文字的約束力是有限的，真正危險的動作必須由 harness 硬性把關。

走完這四步，你會一手寫得出 AI SDK 的 `tool()`（description、Zod schema、execute），一手分得清什麼該寫給模型看、什麼必須寫進 harness。後續節點要做的 durable execution、sandbox、human-in-the-loop 審批，全都是為了把這一節認出的那道「文字護欄擋不住」的缺口補起來。
