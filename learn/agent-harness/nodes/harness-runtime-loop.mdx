# Harness Runtime 迴圈

## Learning goal

寫出 harness 自己擁有的 agent loop——messages 陣列、maxSteps、`streamText`、stream part 轉事件、工具呼叫語意與串流必要性——並用 dry run 看見裸迴圈的缺口。

## Steps

1. [[learn/agent-harness/nodes/harness-runtime-loop/message-array|訊息陣列：模型的對話契約]] — ModelMessage 的四種 role，與為什麼每一輪都得把整段對話重新送給模型
2. [[learn/agent-harness/nodes/harness-runtime-loop/loop-and-step-budget|Agent Loop 與 Step 上限]] — while 迴圈的 step 記數與 maxSteps，以及為什麼 harness 要自己擁有這個迴圈（after step 1）
3. [[learn/agent-harness/nodes/harness-runtime-loop/streaming-loop|streamText 與串流迴圈]] — streamText 為何不 await、for-await 如何迭代 fullStream、串流為何不可讓步（after step 2）
4. [[learn/agent-harness/nodes/harness-runtime-loop/parts-to-events|Stream Part 轉成 Harness 事件]] — 把 part 類型對應到 modelDelta / toolRequest / toolCompleted / workflowFailed（after step 3）
5. [[learn/agent-harness/nodes/harness-runtime-loop/tool-calling-and-dry-run|工具呼叫語意與 Dry Run]] — LLM 只請求工具不執行、append 回應、終態與 dry run 看見的缺口（after steps 1、4）

## Lesson

這節課要做的是把前面定義好的工具與 system prompt 接上一顆「會自己轉」的心臟：harness 自己的 agent loop。模型本身只會做無狀態的一次性推論；要讓它多輪推進，就得由你——harness——去維護一串 messages、設一個 maxSteps 上限、呼叫一次會串流的模型、再把每一個 chunk 轉成對應的事件。這四件事合起來，就是整門課往後每一層（durable、sandbox、memory、handoff、supervision）都長在上面的那根脊柱。

走完這五步，你手上會有一個跑得動、但**故意還缺東缺西**的裸迴圈。它會在 dry run 裡露餡：重複寄出回覆、送出前不問你——這些缺口不是 bug，是接下來每一課要補的那一層的提示。
