冗餘與複製基礎

system-design · proxy-redundancy · Step 3/4

學習目標

解釋冗餘（Redundancy）與複製（Replication）的概念，說明它們如何透過消除單點故障來提升系統可靠度。

從備份講起：為什麼需要冗餘？

想像你把所有重要文件都存在一台筆電裡。某天筆電壞了，所有資料全沒了。如果你同時把文件備份到外接硬碟，即使筆電壞了，你還有備份可以用。

這就是冗餘（Redundancy）的核心思想：把關鍵元件多準備一份，這樣即使其中一個壞了，另一個能接手。在系統設計中，冗餘是消除單點故障（Single Point of Failure，SPOF）最直接的手段。

什麼是單點故障？

單點故障是指系統中只有一個的元件——它掛了，整個系統就跟著掛。

用戶端 ──→ 反向代理（只有一台！）──→ 伺服器

上面這個架構，如果反向代理掛了，所有用戶都連不上來。不管後面有幾台伺服器都沒用，因為流量根本過不去。

冗餘的做法很直覺：多加一台反向代理。

用戶端 ──→ 反向代理 A ──→ 伺服器群
       ──→ 反向代理 B ──→ 伺服器群

現在任何一台代理掛了，另一台能接手。單點故障消除了。

冗餘 vs 複製：有什麼不同？

這兩個詞經常被混用，但它們有不同的側重：

概念 定義 重點
冗餘（Redundancy） 重複部署關鍵元件，提供備援 可靠性——壞了一個還有另一個
複製（Replication） 將一份資料同步到多個位置 資料可用性——多個地方有同一份資料

冗餘是概念，複製是實作。你可以冗餘一台伺服器（硬體層面），也可以複製資料庫裡的資料（資料層面）。兩者通常一起使用。

資料庫複製

資料庫複製是分散式系統中最常見的複製形式。基本做法：有一台主資料庫（Primary）負責寫入，一台或多台副本資料庫（Replica）同步資料，負責讀取。

寫入 → 主資料庫 → 複製到 → 副本 A
                        → 副本 B
讀取 ← 用戶端 ← 從副本讀取

好處：

  • 讀取擴展：多個副本分擔讀取壓力
  • 故障轉移：主資料庫掛了，可以從副本中選一個升格為新主庫
  • 地理就近：在不同地區部署副本，讓用戶就近讀取，減少延遲

但複製也帶來新的挑戰：

  • 一致性：副本之間的資料什麼時候同步？有延遲怎麼辦？
  • 衝突處理：如果兩個地方同時修改同一筆資料怎麼辦？

這些挑戰會在後續的共識定理（CAP/PACELC）和一致性模型課程中深入討論。

冗餘的層次

冗餘不只存在於伺服器層。在一個完整的系統中，冗餘幾乎出現在每一層：

層次 冗餘方式 保護什麼
硬體 多台伺服器、 RAID 磁碟陣列 伺服器故障、磁碟故障
服務 多個服務實例 + 負載均衡 單一服務實例故障
資料 資料庫複製、跨區域備份 資料遺失、資料庫故障
網路 多條網路路徑、多個 DNS 記錄 網路中斷
電力 UPS、備用發電機、多供電商 停電

系統設計的原則是：任何只有一份的東西，都可能成為單點故障。

面試中的關鍵點

在系統設計面試中，冗餘與複製是討論「可靠性」時必提的工具。面試官期望你能：

  • 定義單點故障，並舉例說明
  • 區分冗餘和複製（概念 vs 實作）
  • 解釋資料庫複製的基本模式（主從複製）及其好處與挑戰
  • 知道冗餘存在於多個層次（硬體、服務、資料、網路、電力）

冗餘和複製是「讓系統不會因為一個元件壞掉就全倒」的基礎手段。下一課會把这些概念應用到 Proxy 架構上——怎麼設計一個不會因為一台代理掛掉就中斷的架構。

小結

冗餘是重複部署關鍵元件以消除單點故障；複製是將資料同步到多個位置以確保可用性。兩者通常一起使用。資料庫複製是分散式系統中最常見的複製形式，它帶來讀取擴展、故障轉移和地理就近的好處，但也引入一致性和衝突處理的挑戰。系統設計的原則是：任何只有一份的東西，都可能成為單點故障。
