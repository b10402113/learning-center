網路爬蟲基礎與需求分析

Step 2/4 · Twitter Search & Web Crawler

學習目標

理解網路爬蟲（Web Crawler）的定義、用途、核心需求與設計考量，掌握大規模爬蟲的容量估算方法。

什麼是網路爬蟲？

網路爬蟲是一個自動化程式，它以系統化的方式瀏覽萬維網（World Wide Web），透過遞迴地跟隨連結來收集文件。搜尋引擎靠爬蟲下載網頁來建立索引，才能提供快速搜尋。

爬蟲不只是 Google 在用。它還用於：

  • 搜尋引擎索引：下載網頁建立倒排索引
  • 資料採集：收集價格、評論、新聞等公開資料
  • 網站監控：偵測網頁是否被竄改或下線
  • 學術研究：分析網路結構、社群圖譜

核心需求

需求說明
可擴展性（Scalability）能爬取整個網路的數百億網頁，橫向擴展 worker 數量
可擴充性（Extensibility）模組化設計，能處理新的文件類型（圖片、影片、PDF）
健壯性（Robustness）面對惡意網頁、爬蟲陷阱、異常格式仍能正常運作
效率（Efficiency）在有限的頻寬和儲存下，最大化爬取量

設計考量

在動手設計之前，必須先回答幾個問題：

爬什麼？

  • 只爬 HTML 頁面，還是也要抓圖片、影片、PDF？
  • 不同媒體類型需要不同的下載器和處理管線
  • 一般目的爬蟲（general-purpose）需要處理多種文件類型

怎麼爬？

  • BFS（廣度優先搜尋）：最常用，從種子 URL 開始逐層向外擴散
  • DFS（深度優先搜尋）：適合爬取單個網站內部的所有頁面，減少 TCP 握手開銷
  • 路徑上升爬取（Path-ascending crawling）：沿 URL 路徑向上爬，能發現被孤立的資源

爬行策略

網路的兩個特性使爬取變得極其困難：

  1. 網頁數量龐大：爬蟲在任何時刻只能下載網路的一小部分，必須聰明地排定優先順序
  2. 網頁不斷變化：今天爬的頁面明天可能就改了，需要決定何時重新爬取

容量估算

假設要在 4 週內爬取 150 億個網頁：

爬取速率

150 億 ÷ (4 週 × 7 天 × 86400 秒) ≈ 6,200 頁/秒

這意味著你需要數百台爬蟲伺服器同時工作。每台伺服器大約處理 10-20 頁/秒（考量網路延遲和解析時間）。

儲存需求

假設只存 HTML 文字，平均頁面大小 100KB，加上 500 bytes 的 metadata（URL、爬取時間、HTTP header 等）：

150 億 × (100 KB + 500 B) ≈ 1.5 PB

這是原始 HTML 的儲存量。如果還要存截圖、解析後的結構化資料，儲存量會再倍增。

頻寬需求

6,200 頁/秒 × 100 KB ≈ 620 MB/秒 ≈ 5 Gbps

這是所有爬蟲伺服器的總頻寬。分散到 100 台伺服器，每台約 50 Mbps，完全在合理範圍內。

與搜尋的關係

網路爬蟲是搜尋引擎的上游——它負責收集原始網頁資料，後續的索引建立和搜尋查詢都建立在爬蟲收集的資料之上。上一課的 Twitter Search 是對使用者產生內容的搜尋，而 Web Crawler 是對公開網路內容的收集。

面試要點

在面試中討論 Web Crawler 時，先釐清需求（爬什麼、爬多快、存什麼），再討論架構。不要一開始就跳進去談去重或陷阱——先讓面試官知道你在做正確的需求分析。
