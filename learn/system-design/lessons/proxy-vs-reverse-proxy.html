Proxy vs Reverse Proxy 比較

system-design · arch-patterns · Step 2/5

學習目標

理解 Forward Proxy 與 Reverse Proxy 的角色差異，以及各自的使用場景。

同一個中介，兩種立場

Proxy（代理）和 Reverse Proxy（反向代理）本質上都是中介——擋在用戶端和伺服器之間，轉發請求。差別在於：它們是代表誰說話。

用生活來比喻：Forward Proxy 像是你的私人助理，替你去外面辦事；Reverse Proxy 像是公司的前台接待，替公司過濾訪客。

Forward Proxy（正向代理）

Forward Proxy 代表用戶端向伺服器發出請求。伺服器不知道真正發請求的人是誰，只看到 Proxy 的身份。

用戶端 A ──┐
用戶端 B ──┼──→ Forward Proxy ──→ 伺服器
用戶端 C ──┘
功能 做什麼 實際例子
隱私保護 隱藏用戶端的真實 IP，伺服器只看到 Proxy 的 IP 公司員工上外網，外部網站看到的是公司出口 IP
存取控制 過濾允許或封鎖的網站 學校封鎖社群媒體、企業封鎖娛樂網站
快取 儲存常用資源，減少重複請求 公司 Proxy 快取員工常看的新聞網站
記錄審計 記錄所有對外請求 企業追蹤員工的上網行為

Reverse Proxy（反向代理）

Reverse Proxy 代表伺服器端接收來自客戶端的請求，再轉發給後端伺服器。客戶端不知道真正處理請求的是哪台伺服器——它只看到 Reverse Proxy。

客戶端 ──→ Reverse Proxy ──┬──→ 伺服器 A
                           ├──→ 伺服器 B
                           └──→ 伺服器 C
功能 做什麼 實際例子
負載均衡 把請求分散到多台後端伺服器 Nginx 把流量分給 3 台 Web 伺服器
安全防護 隱藏後端伺服器的真實 IP，提供 DDoS 防護 後端伺服器完全不暴露在公網上
SSL 終止 在 Proxy 層處理 HTTPS 解密，後端用 HTTP 通訊 減少每台後端伺服器的 CPU 負擔
快取 快取靜態資源（圖片、CSS、JS） CDN 本質上就是一種 Reverse Proxy
壓縮 壓縮回應內容再傳給客戶端 減少傳輸大小，加速載入

核心差異對照

面向 Forward Proxy Reverse Proxy
代表誰 代表用戶端 代表伺服器端
流量方向 管理用戶端的出站請求（outbound） 管理進站請求（inbound）
用戶端知道嗎？ 知道（要手動設定 Proxy） 不知道（對用戶端完全透明）
伺服器知道嗎？ 不知道（只看到 Proxy） 不知道（只看到 Proxy）
主要用途 隱私、存取控制、快取、審計 負載均衡、安全、SSL 終止、快取
常見實現 Squid、公司 VPN Nginx、HAProxy、Cloudflare

面試中的關鍵點

  • 一句話區分：Forward Proxy 代表用戶端，Reverse Proxy 代表伺服器端
  • 兩者的「反轉」是代理的對象不同，不是方向的反轉
  • Reverse Proxy 常見功能：負載均衡、安全防護、SSL 終止、快取
  • Reverse Proxy 在系統設計面試中出現頻率極高——幾乎所有架構圖都有一個

小結

Forward Proxy 和 Reverse Proxy 都是中介，但代理的對象完全相反：Forward Proxy 代表用戶端（隱藏用戶身份、控制存取），Reverse Proxy 代表伺服器端（隱藏後端、負載均衡、安全防護）。Reverse Proxy 在現代架構中更常見，幾乎所有系統設計都離不開它。下一課會看看 API Gateway 和 Reverse Proxy 有什麼不同。
