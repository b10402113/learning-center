常見系統組件全覽

系統設計面試入門 · Step 3/4

學習目標

認識 DNS、Load Balancer、API Gateway、CDN、Proxy、Cache、Partitioning、Replication、Messaging、Microservices、NoSQL、Index、Distributed FS、Notification 等常見組件，在步驟 5-6 中能靈活選用。

為什麼要先認識這些「積木」？

系統設計面試步驟 5-6 要你畫架構圖、選組件。你需要認識這些「積木」才能組合出方案。這一步是工具箱——不需要精通每一個，但要在被問到時能說出用途、優缺點和適用場景。

工具箱思維：面試時不要想「我要用 Redis」，而要想「這裡需要快取層，Redis 是好選擇，但 Memcached 也可以，取捨是……」。先想需求，再選工具。

網路層組件

DNS（Domain Name System，域名系統）是所有流量的起點，把人類可讀的網址翻譯成 IP 地址。面試中你不需要深入 DNS 實作，但要知道它是第一跳。

Load Balancer（負載均衡器）把流量分配到多台伺服器，是從單機走向分散式的分水嶺。常見演算法有 Round Robin、Least Connections、IP Hash。多個 LB 可以做冗餘，避免單點故障。

API Gateway是微服務的前門，所有外部請求的第一站。具備七大功能：路由（根據 URL 分發到不同服務）、認證（統一驗 token）、限流（防止被打爆）、熔斷（下遊掛了快速失敗）、快取（熱門請求直接返回）、轉碼（外部 HTTPS 轉內部 gRPC）、日誌監控。跟 LB 的區別：LB 只管流量分到哪台機器（網路層），Gateway 還管業務邏輯（應用層）。

快取與分發

CDN（Content Delivery Network，內容分發網路）把靜態資源緩存到全球邊緣節點，適合讀多寫少的場景。用戶就近取得資源，延遲大幅降低。典型產品：Cloudflare、AWS CloudFront。

Cache（快取）用 Redis 或 Memcached 在應用和資料庫之間加一層高速存取。關鍵問題是失效策略（什麼時候過期）和三大陷阱：穿透（查不存在的資料打爆 DB）、雪崩（大量 key 同時過期）、擊穿（熱點 key 過期瞬間被打爆）。

資料層組件

Data Partitioning（資料分片）把資料水平切分到多台機器，提升寫入效能。代價是跨分片查詢變複雜。水平分片（sharding）切行，垂直分片切欄位。

Database Replication（資料庫複製）一主多從，提升可用性和讀取效能。取捨是一致性——從節點可能有延遲。

NoSQL 四大類型對應不同查詢模式：Key-Value（Redis）、Column-Family（Cassandra）、Document（MongoDB）、Graph（Neo4j）。

Database Index（資料庫索引）B-tree 適合範圍查詢，Hash 適合等值查詢。索引加速讀取但拖慢寫入。

通訊與架構

分散式訊息系統（Kafka、RabbitMQ）解耦服務通訊，讓生產者和消費者獨立擴展。

Microservices（微服務）把單體拆成獨立部署的小服務，好處是獨立擴展和部署，代價是引入分散式複雜性（網路延遲、資料一致性、服務發現）。

Notification System（通知系統）用佇列解耦發送——.email、push、SMS 各走獨立通道。

Proxy：正向 vs 反向

Forward Proxy（正向代理）= 朋友幫你代寄信。你寫了一封信，不想讓對方知道是誰寄的，就請朋友幫你寄出去。典型場景：翻牆 VPN、公司內網閘道器、爬蟲 Proxy Pool。

Reverse Proxy（反向代理）= 公司前台收信。你寄信到「台積電」，信先到公司前台，前台看了信封決定轉給哪個部門。還做限流、快取、擋災。典型產品：Nginx、Cloudflare。

關鍵詞：Forward Proxy 你要藏身、繞限制的時候用；Reverse Proxy 你的伺服器要擋流量、分發的時候用。
