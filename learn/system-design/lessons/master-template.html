為什麼要認識這些組件？

上一步學了 7 步驟框架，步驟 5-6 要你畫架構圖、選組件。如果你不認識這些「積木」，就沒辦法組合出方案。這一步是你的工具箱——不需要精通每一個，但要在被問到時能說出它的用途、優缺點和適用場景。

網路層

DNS（Domain Name System）

網際網路的電話簿。把人類可讀的域名（google.com）翻譯成 IP 地址。在系統設計中，DNS 是所有流量的起點，也是實施流量路由和地理分散的第一層。

Load Balancer（負載均衡器）

把進來的流量分配到多台伺服器，避免某台被打爆。常見演算法：Round Robin、Least Connections、IP Hash。

面試中怎麼用：任何需要水平擴展的系統，第一件事就是加 LB。它是從「單機」走向「分散式」的分水嶺。

API Gateway

微服務架構的前門。所有外部請求先到 Gateway，由它做認證、限流、路由、協議轉換，再轉發到內部服務。

七大功能：

  • 路由 — 根據 URL 分發到不同服務（/users → 用戶服務，/orders → 訂單服務）
  • 認證 — 統一驗 token，下游服務不用各自驗（JWT 驗證在 Gateway 做一次就好）
  • 限流 — 防止某用戶/服務被打爆（每秒最多 100 次請求）
  • 熔斷 — 下遊服務掛了，快速失敗不卡住（訂單服務掛了，返回 503 而不是等 30 秒）
  • 快取 — 熱門請求直接返回，不打到後端
  • 轉碼 — 協議轉換（外部 HTTPS → 內部 gRPC）
  • 日誌/監控 — 統一記錄所有請求（哪個 API 最慢、哪個用戶流量最大）

跟 LB 的區別：LB 管的是「流量分到哪台機器」（網路層），Gateway 管的是「業務邏輯」（應用層）。典型產品：Kong、AWS API Gateway、Nginx。

面試怎麼講：「外部流量先過 API Gateway 做認證、限流、路由，再分發到各微服務。Gateway 前面再放 LB 分流量到多個 Gateway 實例，避免單點。」

快取與分發

CDN（Content Delivery Network）

把靜態資源（圖片、CSS、JS、影片）緩存到全球邊緣節點，用戶從最近的節點取資料，減少延遲。

適用場景：讀多寫少、內容不常變的系統（部落格、電商商品頁、影片平台）。

Cache（快取）

在應用和資料庫之間加一層高速存儲（通常是 Redis 或 Memcached）。資料在快取中就直接返回，不打資料庫。

面試中的關鍵問題：快取失效策略（TTL）、快取穿透/雪崩/擊穿、Write-through vs Write-behind。

資料層

Data Partitioning（資料分片）

把一張大表拆成多份，分散到不同機器上。水平分片（按 row 拆）是常見做法，例如按 user_id 哈希分片。

取捨：分片提升寫入效能，但跨分片查詢變複雜。

Database Replication（資料庫複製）

維護多份資料副本。一個 Primary 負責寫，多個 Replica 負責讀。

面試中的關鍵問題：主從同步 vs 異步同步的一致性取捨。

NoSQL Database

非關聯式資料庫，適合非結構化資料和大規模水平擴展。四大類型：Key-Value（Redis）、Document（MongoDB）、Column-family（Cassandra）、Graph（Neo4j）。

跟你經驗的連結：你用過 Redis 和 MongoDB，知道它們「好用」。面試中要能說出「因為我的查詢模式是 X，所以選 Y 類型的 NoSQL」。

Database Index

書的目錄。讓資料庫不用掃全表就能找到資料。B-tree index 最常見，適合範圍查詢；Hash index 適合等值查詢。

通訊與架構

Distributed Messaging System（分散式訊息系統）

Kafka、RabbitMQ 這類工具。用來解耦服務間通訊：一個服務產生事件，多個服務消費事件，彼此不知道對方的存在。

適用場景：訂閱系統、事件驅動架構、異步任務處理。

Microservices（微服務）

把一個大系統拆成多個小服務，每個服務負責一個業務領域，透過 API 溝通。

取捨：提升獨立部署和擴展的靈活性，但引入分散式系統的複雜性（網路故障、資料一致性）。

Notification System

發送 Email、Push、SMS 的統一服務。通常用訊息佇列解耦，確保發送失敗可以重試。

Proxy

Proxy 就是「中間人」。客戶端不直接跟伺服器講話，中間有個人幫忙傳話。用寄信比喻最好懂：

Forward Proxy（正向代理）= 朋友幫你代寄信

你寫了一封信，不想讓對方知道是誰寄的，就請朋友幫你寄出去。對方看到的寄件人是你朋友，不是你。

你 → 朋友幫寄 → 對方（對方不知道是你寄的）

什麼時候用：你要藏身、繞限制、換身份的時候。

場景App為什麼需要
翻牆ExpressVPN、Clash政府封了某個網站，透過境外 Proxy 繞過去
公司內網企業閘道器公司不讓員工直接上外網，所有流量先過 Proxy 審查
爬蟲Scrapy + Proxy Pool大量抓資料怕被封 IP，輪流用不同 Proxy 出去
隱私Tor Browser想完全匿名上網，流量經過多層 Proxy 層層加密

Reverse Proxy（反向代理）= 公司前台收信

你寄信到「台積電」，信先到公司前台。前台看了信封，決定轉給哪個部門。

你寄信到台積電 → 前台收 → 轉給有空的部門

前台做了什麼？路由：技術問題轉研發部，人事問題轉人資部。限流：同時來 500 封信，「請排隊」。快取：上次問過的問題，答案直接給。擋災：某部門放假，先把信收著。

什麼時候用：你的伺服器要擋流量、分發、保護後面東西的時候。

場景App為什麼需要
電商網站Shopify、淘寶流量太大，Nginx 幫忙分到 50 台伺服器
API 服務你自己的後端前端只打一個網址，Nginx 轉發到微服務 A/B/C
靜態資源Netflix、YouTube影片封裝從 CDN（一種 Reverse Proxy）出，不打到應用伺服器
防火牆CloudflareDDoS 攻擊先到 Cloudflare，過濾惡意流量再放行

翻牆看 Netflix 的完整流程

你 → Forward Proxy（翻牆）→ Netflix Reverse Proxy（Nginx）→ 影片伺服器
 （幫你藏身）              （幫 Netflix 擋流量、分發）
工具箱思維：面試時不要想「我要用 Redis」，而要想「這裡需要快取層，Redis 是一個好選擇，但 Memcached 也可以，取捨是……」。先想需求，再選工具。
