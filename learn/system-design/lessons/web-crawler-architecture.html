網路爬蟲架構設計

Step 3/4 · Twitter Search & Web Crawler

學習目標

掌握大規模網路爬蟲的高層次架構、URL Frontier 的設計，以及各核心元件的職責與互動方式。

基本演算法

任何爬蟲的核心迴圈都是：

  1. 從未訪問 URL 佇列中取一個 URL
  2. 解析域名，取得 IP 位址
  3. 建立 TCP 連線，下載網頁文件
  4. 解析文件內容，提取新的 URL
  5. 將新 URL 加入未訪問佇列
  6. 處理已下載的文件（儲存、建立索引）

看起來很簡單對吧？但當你要把這個迴圈分散到數百台機器上，同時爬取數百億網頁時，每個步驟都變成了一個獨立的挑戰。

高層次架構

種子 URLs → URL Frontier（優先佇列）
                ↓
          DNS Resolver → 網頁下載器
                ↓
          HTML Parser → URL Extractor
                ↓
          URL Filter → URL Storage → 回到 Frontier

整個系統可以拆成以下核心元件：

1. URL Frontier（URL 前線）

URL Frontier 是整個爬蟲的排程中心。它不是簡單的 FIFO 佇列，而是一個優先佇列，負責決定下一個要爬取的 URL。

Frontier 的設計考量：

  • 優先級：重要網站（如知名新聞站）優先爬取
  • politeness：對同一個網站的請求間隔至少 N 秒，避免把對方伺服器當 DDoS
  • 分散式：多台機器共享同一個 Frontier，需要用一致性雜湊（Consistent Hashing）分配 URL

Frontier 通常分兩層：

  • Priority Queues（優先佇列層）：根據 URL 的來源、網頁變化頻率等決定優先級
  • Politeness Queues（禮貌佇列層）：確保對同一個主機的請求保持間隔

2. DNS Resolver

每個 URL 都需要 DNS 解析才能拿到 IP 位址。在大規模爬蟲中，DNS 解析是主要瓶頸之一：

  • DNS 查詢本身有延遲（數十到數百毫秒）
  • 數百億次 DNS 查詢會對 DNS 伺服器造成壓力
  • 解決方案：本地 DNS 快取、預解析、批量 DNS 查詢

3. 網頁下載器（Document Fetcher）

負責實際下載網頁。使用非同步 I/O（如 Node.js 的 event loop 或 Go 的 goroutine）來同時處理數千個連線。

下載器需要處理：

  • HTTP/HTTPS 連線管理
  • 遵循 robots.txt 規範
  • 處理 HTTP 錯誤（404、500、429 限流）
  • 設定合理的逾時和重試策略
  • 尊重 Crawl-Delay 指令

4. HTML Parser 與 URL Extractor

下載的 HTML 文件需要解析，提取出：

  • 頁面中的所有超連結（<a href="...">）
  • 頁面的 metadata（title、description、modified time）
  • 頁面的純文字內容（用於後續建立索引）

URL Extractor 還需要處理相對路徑轉絕對路徑、URL 正規化（去 fragment、統一大小寫）等瑣碎但重要的工作。

5. URL Filter

不是所有提取出的 URL 都值得爬取。Filter 會過濾掉：

  • 不支援的協議（如 ftp://、mailto:）
  • 已被封鎖的域名
  • 已爬過的 URL（去重）
  • 超出爬取範圍的 URL（如只爬 .com 不爬 .gov）

分散式架構

當爬蟲分散到多台機器時，需要解決：

URL 分配

使用一致性雜湊（Consistent Hashing）將 URL 分配到不同的爬蟲機器。以 hostname 為 key 做 hash，確保同一個網站的 URL 分配到同一台機器——這樣 politeness 策略在單台機器上就能實現。

狀態同步

每台機器獨立運作，但需要共享「已爬過的 URL」狀態。通常用分散式的 KV 儲存（如 DynamoDB、Cassandra）來記錄 URL 的 checksum，避免不同機器重複爬取。

容錯

如果一台爬蟲機器故障：

  • 一致性雜湊自動將其負責的 URL 重新分配到其他機器
  • 故障機器的 FIFO 佇列需要定期 checkpoint 到磁碟
  • 恢復後從 checkpoint 重建狀態

面試要點

在面試中，不要只描述爬蟲的「基本迴圈」——那是教科書的起點。真正的設計功力體現在你如何討論 URL Frontier 的優先級和禮貌機制、如何處理分散式狀態同步、以及如何應對單點故障。
