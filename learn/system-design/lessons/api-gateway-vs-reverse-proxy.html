API Gateway vs Reverse Proxy 比較

system-design · arch-patterns · Step 3/5

學習目標

理解 API Gateway 與傳統 Reverse Proxy 的功能差異，以及在現代微服務架構中的角色分工。

從兩張名片說起

想像你去一棟大樓拜訪客戶。大樓門口有兩個角色：

  • 保全（Reverse Proxy）：站在大門口，負責檢查你的證件、控制誰能進出、把你導到正確的樓層。他不管你找的是哪個部門的哪個人——他只管「你能不能進來」和「你要去幾樓」。
  • 秘書（API Gateway）：坐在辦公室裡，聽你說「我要找技術部門討論 API 接入」，然後幫你安排會議室、通知相關人員、準備資料、甚至把幾個部門的報告合併給你看。她理解你的具體需求，並做更多事情。

Reverse Proxy 是網路層級的守門人；API Gateway 是應用層級的管家。兩者都在管理流量，但做的事情深淺不同。

Reverse Proxy 回顧

上一課已經詳細介紹過 Reverse Proxy。它的核心能力是：

  • 負載均衡（把請求分散到多台後端伺服器）
  • SSL 終止（在 Proxy 層解密 HTTPS）
  • 安全防護（隱藏後端 IP、過濾惡意流量）
  • 快取（快取靜態資源）
  • 壓縮（減少傳輸大小）

這些功能都在網路層或傳輸層操作。Reverse Proxy 不理解 API 的語意——它不知道這個請求是要查詢訂單還是新增用戶。

API Gateway 的額外能力

API Gateway 繼承了 Reverse Proxy 的所有能力，再加上一層應用層級的功能：

功能 Reverse Proxy API Gateway
負載均衡 ✅ ✅
SSL 終止 ✅ ✅
快取 ✅ ✅
安全防護 ✅（網路層） ✅（應用層 + 網路層）
API 路由 ❌ ✅ 根據 API 路徑導到正確微服務
身份驗證 ❌ ✅ 統一驗證 JWT / OAuth token
授權控制 ❌ ✅ 根據用戶角色限制 API 存取
限流 ❌ ✅ 按用戶/ API 限制請求頻率
API 聚合 ❌ ✅ 一次請求合併多個微服務的結果
協議轉換 ❌ ✅ REST → gRPC、HTTP → WebSocket
API 版本管理 ❌ ✅ /v1/users → v1 服務，/v2/users → v2 服務
請求/回應轉換 ❌ ✅ 修改 header、body 格式

關鍵差異：關注點不同

面向 Reverse Proxy API Gateway
主要關注 網路層效率和安全 應用層 API 管理
感知層級 L4 / L7（不理解 API 語意） L7（理解 API 路徑、header、body）
典型部署 任何需要反向代理的場景 微服務架構的統一入口
複雜度 較低，配置簡單 較高，需要定義路由規則、驗證策略
面試重點 「如何保護後端伺服器？」 「如何統一管理微服務的 API？」

兩者可以搭配使用嗎？

可以，而且這是現代微服務架構的標準做法：

用戶端 → Reverse Proxy（網路層防護 + LB）→ API Gateway（API 路由 + 驗證）→ 微服務

Reverse Proxy 處理所有網路層的事情（SSL 終止、DDoS 防護、靜態資源快取），API Gateway 處理所有應用層的事情（路由、驗證、限流、聚合）。兩者各司其職，互不衝突。

有些 API Gateway（如 Kong、AWS API Gateway）本身內建了 Reverse Proxy 的能力，可以一個工具搞定兩件事。但在大規模系統中，分開部署更靈活——Reverse Proxy 可以用 Nginx（高效、穩定），API Gateway 可以用 Kong 或自建（功能豐富）。

面試中的關鍵點

  • API Gateway 是 Reverse Proxy 的超集——它包含了 Reverse Proxy 的所有能力，再加上應用層的 API 管理
  • 兩者的核心差異在於是否理解 API 語意（路由、驗證、限流、聚合）
  • 微服務架構中，API Gateway 是統一入口，Reverse Proxy 是網路層防護
  • 面試時被問「該用哪個」，先確認是純網路層防護（Reverse Proxy）還是需要 API 管理（API Gateway）

小結

API Gateway 繼承了 Reverse Proxy 的所有能力（負載均衡、SSL 終止、快取、安全防護），再加上應用層級的 API 管理（路由、驗證、限流、聚合、協議轉換）。兩者在微服務架構中常常搭配使用：Reverse Proxy 處理網路層防護，API Gateway 處理應用層邏輯。下一課會從 API 設計風格的角度，看看 REST 和 RPC 的差異。
