進階擴展與優化

這個步驟的目標

你能解釋資料分片、複製、快取、負載均衡和清理機制，並說明它們如何讓系統從「能用」成長到「能撐住大流量」。

1. 資料分片（Partitioning）

當單台資料庫無法承受所有資料時，就需要把資料分散到多台機器上。

按金鑰範圍分片

把金鑰按字母順序分成若干範圍，每個範圍存到不同的節點。例如 A-F 在節點 1，G-M 在節點 2。優點是範圍查詢效率高；缺點是某些範圍可能特別熱（熱點問題）。

按金鑰雜湊分片

對金鑰做雜湊運算，根據雜湊值分配到不同節點。分佈均勻，避免熱點。短網址只根據單一金鑰查詢，雜湊分片更合適。

選擇建議：短網址用雜湊分片（均勻分佈、避免熱點）；Pastebin 的元資料用雜湊分片，內容由 S3 自己管理分片。

2. 資料複製（Replication）

主從複製（Primary-Replica）

一台主節點負責寫入，多台從節點負責讀取。主節點把寫入同步或非同步複製到從節點。讀寫分離，讀取效能大幅提升。

多主複製（Multi-Primary）

多台主節點都能寫入，互相複製。適合地理分散場景，但引入衝突解決的複雜性。

短網址和 Pastebin 的選擇：讀多寫少的場景，主從複製是最佳選擇。讀取分散到多台從節點，大幅降低單台壓力。

3. 快取（Caching）

根據 80/20 法則，80% 的請求集中在 20% 的資料上。把熱門資料放進記憶體快取（如 Redis），大部分請求就不經過資料庫。

策略做法優點缺點
Write-Through寫入時同時寫快取和 DB一致性好寫入延遲增加
Write-Behind先寫快取，非同步寫 DB寫入快一致性風險
Read-Through先查快取，miss 再查 DB 回填透明首次查詢慢
Cache-Aside應用程式自己管理最靈活最複雜
短網址快取：新短網址先不進快取，存取量超過閾值（如 1000 次/小時）再放進快取（hot key detection）。
Pastebin 快取：熱門 paste 內容不變，非常適合快取元資料和內容本身。

4. 負載均衡（Load Balancer）

策略說明適用場景
輪詢（Round Robin）依序分配給每台伺服器伺服器規格相同
最少連接分配給連接數最少的伺服器伺服器負載差異大
IP Hash根據客戶端 IP 雜湊需要 session 粘性

短網址完全無狀態，輪詢就夠了。

5. 資料清理（DB Cleanup）

過期資料不能一直佔儲存空間。兩種策略結合使用效果最好：

  • 被動清理：讀取時檢查過期，過期就回傳 404 並刪除。第一道防線。
  • 主動清理：背景工作定期掃描，刪除過期記錄。處理沒人存取的過期資料。

6. 速率限制（Rate Limiting）

防止濫用的最後一道防線。常見策略：

  • 令牌桶（Token Bucket）：允許突發流量，桶內有令牌就能發
  • 漏桶（Leaky Bucket）：嚴格限制速率，突發流量會被排隊

短網址可限制單個 IP 或 API Key 每分鐘的建立次數，防止惡意大量建立。
