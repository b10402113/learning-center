7 步驟回答框架

系統設計面試入門 · Step 2/4

學習目標

掌握系統設計面試的 7 步驟回答流程：需求澄清 → 估算 → API 定義 → 資料模型 → 高階設計 → 詳細設計 → 瓶頸分析，並理解每一步的目標與時間分配。

為什麼需要一套框架？

系統設計面試是開放式的，但不代表你可以隨便講。你需要一套可複用的流程，讓你在任何題目下都能有序推進。這套 7 步驟框架是業界最常見的做法，從需求澄清一路走到瓶頸分析。

核心邏輯：前四步定義「做什麼」，後三步定義「怎麼做」。

前四步：定義「做什麼」

步驟 1 需求澄清。拿到題目先問問題——核心功能是什麼、規模多大、需要支援哪些裝置。需求決定設計，clarify 的過程本身就在展示經驗。

步驟 2 粗估。花 2-3 分鐘估算日活、峰值 QPS、資料量、讀寫比，數字幫你做後續決策。

步驟 3 API 定義。定義系統對外暴露的 API，清楚輸入輸出和協議選擇。

步驟 4 資料模型。決定用 SQL 還是 NoSQL、核心實體有哪些、索引怎麼建。

後三步：定義「怎麼做」

步驟 5 高階設計。畫 5-6 個方塊的架構圖作為骨架，不急著深入任何方塊內部。

步驟 6 詳細設計。面試官會指定 2-3 個組件深入討論，每深入一層都要說明取捨。

步驟 7 瓶頸分析。回頭審視單點故障、資料備份、擴展性瓶頸，這一步最容易被忽略但面試官很看重，它展示你能自我批判。

時間分配建議

步驟建議時間
步驟 1-2（需求 + 估算）5 分鐘
步驟 3-4（API + 資料模型）5 分鐘
步驟 5（高階設計）10 分鐘
步驟 6（詳細設計）15 分鐘
步驟 7（瓶頸分析）5 分鐘

45 分鐘面試中，詳細設計佔最多時間——這正是面試官最想看到的深度討論。

實例走讀：Netflix 的步驟 1

拿到「設計 Netflix」這道題，需求釐清分三層問：

功能性需求：核心功能有哪些——播放影片、搜尋、推薦、下載離線觀看？支援哪些裝置——手機、平板、電視、瀏覽器、遊戲機？

非功能性需求：什麼最重要——可用性（99.99%）優先於一致性（推薦可以延遲）；影片開始播放要在 2 秒內；需要用戶登入和付費驗證。

規模：DAU 多少——2 億和 2000 萬的設計完全不同；讀寫比大約 200:1（看的人遠多於上傳的人）；峰值在哪——週五晚高峰還是世足賽直播？

問 3-4 個最關鍵的問題後，就說「我先假設 X、Y、Z，如果不對再調整」——用最少的問題收斂最多不確定性，才是面試官想看到的。

口訣記憶

七步驟順序：需A資，高詳瓶。諧音「需要 A 紙，高級詳評」——想像一個人拿著 A 紙到高級廁所做詳細評估，蹲太久遇到瓶頸。越荒謬越好記。

前四步（需、A、資）定義「做什麼」，後三步（高、詳、瓶）定義「怎麼做」。
