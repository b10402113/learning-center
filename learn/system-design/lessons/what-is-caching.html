什麼是快取

system-design · caching · Step 1/4

學習目標

理解快取的基本定義、核心術語，以及快取為什麼能提升系統效能。

從生活開始：書店陳列架的比喻

想像你是一家書店的店員。每天有很多客人來問同一本書在哪裡。如果每次都走到後面的倉庫去找，效率很低。解決方案是：把最常被問到的書放在門口的陳列架上。客人一問，你轉身就能拿到——這就是快取的基本邏輯。

快取（Cache）是位於應用程式與原始數據源之間的一個高速儲存層。原始數據源可能是資料庫、檔案系統，或是遠端的網路服務。當應用程式需要數據時，第一步不是去原始數據源找，而是先查快取。

快取的運作流程

應用程式 → 查快取 → 命中？ → 是 → 直接返回（快速）
                         ↓ 否
                    去數據源取 → 存入快取 → 返回

兩種結果：

術語 發生什麼 速度
快取命中（Cache Hit） 數據在快取中找到了，直接返回 極快（微秒級）
快取未命中（Cache Miss） 快取中沒有，需要去原始數據源取回 較慢（毫秒到秒級）

快取為什麼有效？

核心原理是利用「不同存儲介質的速度差異」。記憶體的訪問速度比硬碟快幾個數量級，硬碟又比跨網路的資料庫查詢快得多。把常用數據存在更快的介質上，就能大幅減少應用對底層緩慢數據源的訪問次數，降低延遲、提升吞吐量，同時減輕底層系統的負載。

另外兩個關鍵術語

除了命中和未命中，還有兩個必須知道的術語：

術語 意思 比喻
快取驅逐（Eviction） 快取空間滿了，必須移除舊數據騰出空間 陳列架滿了，把最久沒人翻的書放回倉庫
快取失效（Invalidation） 底層數據變了，快取中的舊版本要作廢 作者出了修訂版，舊版要從陳列架上撤下

常見的驅逐策略包括 LRU（最近最少使用）和 LFU（最不經常使用），後面會在快取失效和策略的課程中深入討論。

面試中的關鍵點

在系統設計面試中，快取幾乎是必考的技術。面試官期望你能：

  • 用精準的術語（Cache Hit、Cache Miss、Eviction、Invalidation）描述快取行為
  • 解釋為什麼快取能提升效能（存儲介質的速度差異）
  • 討論快取的代價（一致性問題、記憶體成本、失效複雜度）

先把這些基礎概念搞清楚，後面的「有哪些類型」和「怎麼失效」才會有根基。

小結

快取是位於應用程式與數據源之間的高速儲存層，利用存儲介質的速度差異來提升效能。核心術語包括 Cache Hit、Cache Miss、Eviction 和 Invalidation，這些是後續所有快取策略的基礎語言。
