什麼是負載均衡

system-design · load-balancing · Step 1/4

學習目標

理解負載均衡的基本概念、核心角色，以及它在分散式系統中扮演的關鍵位置。

從生活開始：餐廳領班的比喻

想像一家生意很好的餐廳。如果只有一個服務生，他同時要端菜、倒水、結帳，很快就忙不過來。客人等太久會走掉，服務生也可能出錯。老闆的解法是：多請幾個服務生，然後安排一個領班來分配客人——新客人進來時，領班觀察哪個服務生比較閒，就把客人帶過去。

負載均衡器（Load Balancer，簡稱 LB）就是這個領班。在電腦世界裡，它坐在用戶端（client）和伺服器（server）之間，負責把進來的網路請求分配給多個後端伺服器。

負載均衡器的核心角色

負載均衡器不只是「把請求分一分」這麼簡單，它同時承擔了三個核心角色：

角色 做什麼 為什麼重要
流量分配 把用戶請求依規則分散到多台後端伺服器 避免單一伺服器過載，整體回應更快
健康檢查 定期探測後端伺服器是否正常運作 自動排除故障節點，用戶無感知
統一入口 對外只暴露一個 IP 或域名 隱藏內部架構，方便擴展和維護

沒有負載均衡會怎樣？

假設你只有一台伺服器處理所有請求。當流量成長時，你會遇到三個問題：

  1. 效能瓶頸：單一伺服器的 CPU、記憶體、頻寬有上限，超過就變慢甚至當機。
  2. 單點故障：這台伺服器掛了，整個服務就中斷。
  3. 無法擴展：想加伺服器？沒有負載均衡器，你根本沒辦法把流量導到新伺服器。

負載均衡器解決了這三個問題：把工作分散出去、自動繞過故障節點、讓你隨時加減伺服器。

負載均衡器在哪裡？

負載均衡器通常出現在系統的邊界——用戶端的請求第一個碰到的就是它。在典型的三層架構中：

用戶端 → 負載均衡器 → Web 伺服器叢集 → 應用伺服器 → 資料庫

負載均衡器就像一道門，決定每個請求要走進哪扇門。後面的伺服器叢集可以有幾台、幾十台、甚至幾百台，但對用戶來說，它們看起來就像一台——因為負載均衡器統一處理了所有的分配邏輯。

面試中的關鍵點

在系統設計面試中，負載均衡幾乎是必考的題目。面試官想聽到的是：

  • 你能解釋為什麼需要負載均衡（不只是「分散流量」）
  • 你知道負載均衡器可以放在不同層級（DNS、L4、L7、服務層）
  • 你能討論演算法選擇（Round Robin、Least Connections、IP Hash 等）
  • 你能指出負載均衡器本身也是單點故障，需要冗餘設計

這四個面向分別對應後續的課程內容。先把「它是什麼」搞清楚，後面的「怎麼選」和「怎麼設計」才會有基礎。

小結

負載均衡器是分散式系統的流量入口，它讓多台伺服器對外看起來像一台，同時提供流量分配、健康檢查和統一入口三個核心功能。理解這個概念後，下一步是看看它具體帶來哪些好處。
