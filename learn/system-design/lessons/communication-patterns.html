即時通訊模式比較

系統設計面試 · 通訊與可靠度 · 步驟 1/3

學習目標：理解並比較 Polling、Long Polling、Server-Sent Events (SSE) 與 WebSocket 這幾種常見即時通訊模式的運作原理、優缺點與適用場景。

問題背景

你做了一個聊天 App，使用者 A 發了一條訊息給使用者 B。問題是：B 的手機怎麼「即時」收到這條訊息？最直覺的做法是 B 的手機每隔幾秒問一次伺服器「有新訊息嗎？」——這就是 Polling。但這真的好嗎？

在分散式系統中，客戶端與伺服器之間的通訊模式選擇，直接影響延遲、資源消耗和使用者體驗。面試中，當你被問到「怎麼設計一個即時通知系統」或「怎麼讓多個客戶端同步更新」，你需要在幾種通訊模式之間做出正確的取捨。

四種通訊模式

1. Ajax Polling（輪詢）

最基本的方式。客戶端每隔一段固定時間就向伺服器發一次 HTTP 請求，問「有新資料嗎？」伺服器如果有新資料就回傳，沒有就回傳空的響應。

特點說明
運作方式客戶端定期發送 HTTP 請求，伺服器立即回應
優點實現簡單，所有瀏覽器都支援
缺點大量空請求造成 HTTP 開銷；延遲等於輪詢間隔
適用場景對即時性要求不高的場景，如定期刷新的儀表板

類比：像是每 5 分鐘打電話到快遞站問「我的包裹到了嗎？」——大部分時候答案是「還沒有」，但你不得不打。

2. HTTP Long Polling（長輪詢）

Polling 的改良版。客戶端發出請求後，如果伺服器沒有新資料，不會立即回應空的，而是hold 住這個連線，等到有新資料時才回應。回應後，客戶端再發一個新請求，重複這個過程。

特點說明
運作方式伺服器 hold 住請求直到有新資料才回應，客戶端收到後立即發新請求
優點比 Polling 減少空請求；伺服器主動推送資料
缺點每個客戶端都佔用一個持久連線；伺服器資源消耗大
適用場景中等即時性需求，如通知系統、Facebook 即時留言

類比：打電話到快遞站，「你先別掛，我幫你查」——一直hold著線，直到包裹到了才告訴你。掛掉後你再打一次，重複這個過程。

3. Server-Sent Events (SSE，伺服器推送事件)

SSE 是一種伺服器單向推送的機制。客戶端與伺服器建立一個持久的 HTTP 連線，伺服器可以主動把新資料推給客戶端，但客戶端不能透過這條連線向伺服器發資料（如果需要上傳，要用另一條連線）。

特點說明
運作方式客戶端建立持久 HTTP 連線，伺服器主動推送資料
優點伺服器主動推送，延遲低；基於 HTTP，易於穿越防火牆；自動重連
缺點只能伺服器→客戶端單向；連線數量受限（HTTP/1.1 下瀏覽器限制）
適用場景單向即時推送，如股票行情、新聞推送、活動日誌

類比：訂閱了新聞推送服務——有新消息時記者會主動寄給你，但你不能透過這條通道回覆記者。

4. WebSocket

WebSocket 提供全雙工（Full Duplex）通訊。客戶端透過一個「握手」過程將 HTTP 連線升級為 WebSocket 連線，之後雙方都可以隨時主動發送資料，不受「誰先請求」的限制。

特點說明
運作方式透過 HTTP 握手升級為 WebSocket 連線，之後全雙工通訊
優點雙向即時通訊；延遲最低；連線 overhead 低（無重複 HTTP header）
缺點實現複雜度高；需要處理連線管理、斷線重連；某些代理/防火牆可能阻擋
適用場景雙向即時通訊，如聊天室、多人遊戲、協作編輯

類比：兩人之間拉了一條專屬電話線——隨時可以互相打過去，不用等對方先打來。

比較總覽

模式方向即時性資源消耗實現難度
Polling客戶端→伺服器低（等於輪詢間隔）高（大量空請求）低
Long Polling伺服器→客戶端中中（每客戶端一條持久連線）中
SSE伺服器→客戶端高低中
WebSocket雙向最高低高

如何選擇？

選擇哪種模式取決於三個問題：

  1. 需要雙向通訊嗎？ 如果只需要伺服器推資料給客戶端，SSE 就夠了；如果需要雙向，選 WebSocket。
  2. 對延遲的容忍度？ 延遲敏感（如遊戲、聊天）用 WebSocket；延遲不敏感可以用 Long Polling。
  3. 客戶端數量和伺服器資源？ 大量客戶端用 SSE 或 WebSocket（連線數少）；少量客戶端 Long Polling 也可以接受。

在面試中怎麼用？

當你被問到即時通訊相關的系統設計題（如設計 Facebook Messenger、設計即時通知系統），你可以按照這個思路：

  1. 先確認需求：是單向推送還是雙向通訊？即時性要求多高？
  2. 選擇模式：根據上面的比較表做出選擇，並解釋取捨。
  3. 考慮退化：WebSocket 不支援的客戶端退化為 Long Polling；SSE 不支援時退化為 Polling。
