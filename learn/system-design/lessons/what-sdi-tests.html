系統設計面試在考什麼？

系統設計面試入門 · Step 1/4

學習目標

理解系統設計面試在考什麼（問題解決、溝通、取捨判斷），以及它不是什麼（不是背答案、不是追求完美方案）。

面試官到底在評什麼？

系統設計面試跟演算法面試最大的不同：演算法有對錯，系統設計沒有。面試官給你一個開放式問題——「設計一個短網址服務」「設計一個聊天系統」——你不可能給出一個「完美」的答案，因為根本不存在。面試官評的不是結果，而是你的思考過程。

三個核心評估維度：

第一，問題解決能力。拿到模糊問題後，能不能自己拆解成具體的、可設計的子問題。面試官在乎的是你從哪裡開始、為什麼這樣拆、每一步的推理邏輯。

第二，溝通能力。系統設計面試是一場對話，不是獨白。你需要一邊思考一邊講，讓面試官跟上你的思路——先問對問題、解釋每一步的「為什麼」、主動詢問面試官的偏好和反饋。

第三，取捨判斷。每個設計決策都有代價，選 SQL 犧牲水平擴展的便利，選 NoSQL 犧牲強一致性。面試官想看到你能意識到這些取捨，並根據場景做出合理選擇，而不是死記硬背。

面試不是什麼

不是背誦測驗。背熟 CAP theorem 不會幫你通過面試，理解它在什麼場景下影響你的設計才會。

不是追求完美。面試官期待你在討論中不斷改進方案。一開始畫出粗糙的架構圖沒關係，重要的是你能根據反饋迭代。

不是只考技術。取捨判斷、溝通、適應性在評分中佔比很高。

你的經驗怎麼用？

你做過 REST API、用過 Postgres 和 Redis，這些經驗不是用來「炫耀」的，而是用來建立連結的。當被問到快取設計時，你可以說「我之前在專案中用 Redis 做 session cache，但那個場景是 X，這裡是 Y，所以我選 Z」。這就是把個人經驗轉化為設計能力。

關鍵心法：每個概念都要能回答「這跟我之前做的 X 有什麼關係？」面試官聽到這種連結，會覺得你不是在背書，而是在真正理解。
