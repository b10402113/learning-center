快取的常見類型

system-design · caching · Step 2/4

學習目標

認識不同部署位置與使用場景的快取類型，理解每種類型的適用時機。

為什麼要了解快取類型？

快取不是只有一種——它可以部署在系統的不同層級，從用戶的瀏覽器到全球分散的 CDN 節點。選錯快取類型，可能花了成本卻沒有效果；選對了，效能提升可以是數量級的。

七種常見快取類型

類型 存儲位置 速度 容量 典型用途
記憶體內快取 主記憶體（RAM） 極快（微秒） 受限於 RAM API 回應、session、熱數據
磁碟快取 硬碟 / SSD 中等（毫秒） 較大 資料庫查詢、大檔案
資料庫快取 資料庫內部 快 由資料庫管理 頻繁查詢的結果集
客戶端快取 用戶設備 最快（本地） 受限於設備 圖片、CSS、JS、本地儲存
服務端快取 後端伺服器 快 伺服器記憶體 全頁快取、片段快取、對象快取
CDN 快取 全球邊緣節點 快（就近存取） 分散式大容量 圖片、影片、靜態資源
DNS 快取 瀏覽器/OS/路由器 極快 小 域名解析結果（domain → IP）

深入每一種

記憶體內快取（In-memory Cache）

數據存在主記憶體中，訪問速度極快（微秒級），但容量受限於可用記憶體。適合存放 frequently accessed 的熱數據。分散式場景常用 Redis 或 Memcached，單機應用常用 Guava Cache 或 lru-cache。這是系統設計面試中最常被討論的快取類型。

磁碟快取（Disk Cache）

數據存在硬碟或 SSD 上，速度比記憶體慢但比遠端訪問快。適合兩種場景：數據太大放不進記憶體，或是重啟後需要保留的數據。資料庫的查詢結果快取常採用這種方式。

資料庫快取（Database Cache）

由資料庫自身管理，自動快取頻繁查詢的結果集。MySQL 的 Query Cache、PostgreSQL 的 shared buffers 都是例子。應用程式不需額外設定就能受益，但可控性較低。

客戶端快取（Client-side Cache）

在用戶設備上運作。瀏覽器快取圖片、CSS、JavaScript 檔案（透過 HTTP Cache Headers 控制），App 的本地儲存（localStorage、SQLite）。減少重複請求，提升二次訪問速度。

服務端快取（Server-side Cache）

部署在後端伺服器。常見形式有全頁快取（整個 HTML）、片段快取（頁面中的某個區塊）、對象快取（某筆資料的序列化結果）。例如 Redis 存儲用戶 session、热门商品資料。

CDN 快取（CDN Cache）

在全球邊緣節點分散存儲靜態資源，讓用戶從地理位置最近的節點獲取數據。Cloudflare、AWS CloudFront、Akamai 都是常見的 CDN 服務。圖片、影片、JS/CSS 檔案是典型對象。

DNS 快取（DNS Cache）

快取域名解析結果（domain → IP 的對應）。瀏覽器有自己的 DNS 快取，作業系統也有，路由器也有。TTL 通常設為幾分鐘到幾小時。

如何選擇？

考量 建議方向
數據太大放不進記憶體 磁碟快取或 CDN
重啟後需要保留 磁碟快取
極高頻訪問 記憶體快取（Redis）
多台伺服器共享 分散式快取（Redis / Memcached）
全球多地域用戶 CDN

面試中的關鍵點

Redis 和分散式記憶體快取是最常被討論的快取類型。面試官期望你能解釋：

  • 為什麼選擇某種快取類型（而不只是「用 Redis」）
  • 快取在整體架構中的位置（客戶端？服務端？CDN？）
  • 不同快取類型如何組合使用

小結

快取按部署位置分為七種主要類型，從最快但最小的記憶體快取，到全球分發的 CDN。選擇的關鍵在於數據大小、生命週期、訪問頻率和分散式需求。Redis 是後端分散式場景最常用的快取技術。
