反向代理（Reverse Proxy）

system-design · proxy-redundancy · Step 2/4

學習目標

比較反向代理與正向代理的差異，並理解反向代理在系統設計中的常見使用場景。

鏡像翻轉：從用戶端到伺服器

上一課介紹了正向代理——它站在用戶端這邊，代表用戶端向伺服器發請求。現在把鏡子翻過來：如果有一個代理站在伺服器這邊，代表伺服器接收用戶端的請求，那就是反向代理（Reverse Proxy）。

兩者的核心差異一句話說完：

正向代理隱藏用戶端的身份；反向代理隱藏伺服器的身份。

反向代理長什麼樣？

用戶端 ──→ 反向代理 ──→ 伺服器 A
                     ├→ 伺服器 B
                     └→ 伺服器 C

用戶端以為自己在跟「一台伺服器」溝通，但其實反向代理背後可能有好幾台伺服器。所有請求都先到反向代理，由它決定轉發給哪台後端伺服器。

對用戶端來說，它只需要知道反向代理的 IP 或域名。後面有幾台伺服器、每台跑什麼服務，用戶端完全不需要知道。

反向代理的核心功能

功能 做什麼 為什麼重要
負載均衡 把進來的請求分配到多台後端伺服器 避免單一伺服器過載，提升整體吞吐
SSL 終止 在反向代理處理 HTTPS 加解密，後端只需處理明文 減輕後端伺服器的加密負擔，統一管理憑證
快取 把靜態資源（圖片、CSS、JS）存在反向代理 減少後端伺服器的壓力，加速回應
壓縮 自動壓縮回應內容 減少傳輸量，提升用戶體驗
隱藏後端 用戶端只看到反向代理，不知道後端伺服器的存在 安全：攻擊者無法直接瞄準後端伺服器

為什麼需要反向代理？

假設你經營一個電商網站。如果沒有反向代理，所有用戶請求直接打到你的 Web 伺服器。當流量暴增（比如雙 11），你會遇到：

  1. 單點過載：一台伺服器處理不了所有請求
  2. 安全暴露：後端伺服器的 IP 和架構直接暴露在公網
  3. 憑證管理混亂：每台伺服器都要各自管理 SSL 憑證

加了反向代理後，這些問題一次性解決：流量分散到多台後端、後端 IP 隱藏在代理後面、SSL 憑證統一在代理上管理。

正向代理 vs 反向代理：完整對比

面向 正向代理 反向代理
代表誰 用戶端 伺服器
隱藏誰 用戶端的身份 伺服器的身份
誰設定 用戶端（或用戶端的管理員） 伺服器端（或網站管理員）
常見場景 企業上網管控、翻牆 負載均衡、SSL 終止、快取、安全
用戶端是否感知 通常需要手動設定 Proxy 透明，用戶端無感知

面試中的關鍵點

反向代理在系統設計面試中幾乎是必提的概念。面試官期望你能：

  • 一句話區分正向代理和反向代理（隱藏的對象不同）
  • 說出反向代理的至少三個功能（負載均衡、SSL 終止、快取、壓縮、安全）
  • 理解反向代理是透明的——用戶端不需要做任何設定
  • 知道反向代理可以是軟體（Nginx、HAProxy）或硬體（F5）

反向代理是系統架構的「前門」，它擋在後端伺服器前面，既做交通指揮（負載均衡），又做安全閘門（隱藏後端）。下一課會介紹冗餘和複製——如何讓這個「前門」本身也不會成為單點故障。

小結

反向代理是站在伺服器這邊的代理，代表伺服器接收請求。它的核心功能包括負載均衡、SSL 終止、快取、壓縮和隱藏後端。與正向代理的關鍵差異在於：正向代理隱藏用戶端，反向代理隱藏伺服器。反向代理對用戶端透明，是現代 Web 架構中不可或缺的元件。
