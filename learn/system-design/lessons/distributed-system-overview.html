學習目標

理解什麼是分散式系統，認識五大核心特性的整體框架，為深入學習每個特性打好基礎。

什麼是分散式系統？

想像一下你在用一個網站——電商、社群媒體、或是雲端儲存。你感覺它就是「一個東西」，但背後其實是數百萬台伺服器分散在全球各地的資料中心，通過網絡通信來協同工作。這就是分散式系統。

簡單定義：分散式系統是由多個獨立節點組成，通過網絡通信來協同完成共同目標的系統。

為什麼不直接用一台超級電腦？因為：

  • 規模限制：單台機器的 CPU、記憶體、儲存都有物理極限，無法承載數億用戶的請求
  • 單點故障：一台機器壞了，整個服務就掛了
  • 延遲問題：使用者在亞洲，伺服器在美洲，光速傳輸就要 200ms+
  • 成本：一台超級電腦比一百台普通伺服器貴得多

分散式系統透過「分而治之」來解決這些問題：把工作分散到多台機器上，讓它們各自處理一部分，最後匯總結果。

為什麼需要分散式系統？

現實中的大規模服務都面臨同樣的挑戰：

挑戰單機的困境分散式系統的解法
流量增長單台伺服器很快就扛不住增加更多伺服器分擔流量
硬體故障壞了就全掛冗餘部署，壞了還有備份
地理延遲使用者離伺服器太遠把伺服器部署在使用者附近
成本控制超級電腦非常昂貴大量廉價普通機器即可

五大核心特性

設計分散式系統時，我們主要圍繞五個核心特性來做取捨和決策。這五個特性就像五個不同的「維度」，每個都影響著系統設計的方向：

1. 可擴展性（Scalability）
系統應對增長需求的能力。當流量、數據量增加時，系統能不能透過增加資源來維持性能？
2. 可靠性（Reliability）
系統在故障環境下持續正確運行的能力。部分節點故障時，系統能不能依然正確完成請求？
3. 可用性（Availability）
系統在正常條件下保持可操作的時間百分比。使用者需要使用服務時，能不能正常訪問？
4. 效率（Efficiency）
衡量系統響應速度和吞吐量。一般用延遲（Latency）和吞吐量（Throughput）來衡量。
5. 可管理性（Manageability）
系統維護與運營的難易程度。部署、監控、排查問題、升級是否方便？

這五個特性之間往往存在權衡取捨。例如，追求極高可用性可能需要更多冗餘，增加成本；追求極低延遲可能需要在多地部署，增加複雜度。沒有完美的系統，只有最適合場景的取捨。

在面試中怎麼用？

系統設計面試中，面試官會問你如何設計一個系統。掌握了這五個特性，你就有了一個思考框架：

  1. 先問清楚需求：需要多大的規模？（可擴展性）
  2. 問清楚可用性要求：能容忍多少 downtime？（可用性）
  3. 問清楚數據一致性要求：能接受多少數據丟失？（可靠性）
  4. 問清楚延遲要求：使用者能忍受多慢？（效率）
  5. 問清楚運維團隊規模：有多少人維護這個系統？（可管理性）

每個問題都會引導你做出不同的設計決策。後續步驟會逐一深入每個特性。
