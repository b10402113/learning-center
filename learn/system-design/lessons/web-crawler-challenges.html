網路爬蟲關鍵挑戰與解決方案

Step 4/4 · Twitter Search & Web Crawler

學習目標

掌握大規模爬蟲面臨的重複 URL 移除、爬蟲陷阱、容錯處理與資料分區四大核心挑戰，並理解對應的解決方案。

挑戰一：URL 去重

同一個網頁可能從不同的連結被發現多次。如果不做去重，爬蟲會浪費大量資源重複爬取相同的頁面。

雙重 checksum 策略

大規模爬蟲通常用兩種 checksum 來去重：

  • URL Checksum：對 URL 本身做 hash（如 MD5）。用來判斷「這個 URL 有沒有爬過」
  • 文件 Checksum：對下載的文件內容做 hash。用來判斷「這個頁面的內容有沒有變過」

為什麼需要兩個？因為 URL 不變但內容可能變（網頁更新了），URL 變了但內容可能不變（同一個頁面有不同 URL 指向）。

儲存空間的估算：假設 150 億個 URL，每個 checksum 16 bytes（MD5），加上 document checksum 16 bytes：

150 億 × 32 bytes ≈ 480 GB

這在現代分散式儲存系統（如 Bigtable、DynamoDB）中是完全可行的。

Bloom Filter

Bloom Filter 是一種空間效率極高的概率資料結構，用來快速判斷「某個 URL 是否已爬過」。它的特點是：

  • 可能誤報（false positive）：說「有爬過」但實際沒有——這只是多爬一次，不影響正確性
  • 不會漏報（false negative）：說「沒爬過」就一定沒爬過
  • 空間效率遠優於 Hash Set：150 億個 URL 只需約 18 GB（1% 誤報率）
Bloom Filter 非常適合爬蟲場景：偶爾多爬一次沒關係，但絕不能漏爬。它的空間效率比 Hash Set 好一個數量級，是大規模爬蟲的標配。

挑戰二：爬蟲陷阱

爬蟲陷阱（Crawler Trap）是一組會讓爬蟲無限迴圈的 URL。陷阱有兩種：

無意的陷阱

  • 檔案系統中的符號連結形成迴圈（A → B → A）
  • 動態生成的 URL 帶有遞迴參數（如 /page?page=1&ref=2&page=2）

有意的陷阱

  • 垃圾網站故意生成無限頁面來消耗爬蟲資源
  • 動態產生無限文件的爬蟲陷阱（crawler trap pages）

解決方案

  • 設定最大深度：限制從種子 URL 開始的爬取深度（如最多 15 層）
  • 設定最大頁數：對每個域名設定爬取頁面上限
  • URL 正規化：移除重複參數、統一排序查詢參數
  • 模式偵測：偵測 URL 中的遞迴模式（如重複的路徑片段）
  • 設定逾時：對單個域名設定整體爬取時間上限

挑戰三：容錯處理

大規模爬蟲系統中，機器故障是常態而非例外。容錯設計需要覆蓋：

Checkpoint 機制

每台爬蟲機器定期將 FIFO 佇列的狀態 checkpoint 到磁碟：

  • 記錄目前爬到哪個 URL
  • 記錄已爬 URL 的 checksum 狀態
  • 故障後從最近的 checkpoint 恢復，而非從頭開始

一致性雜湊 Failover

使用一致性雜湊（Consistent Hashing）分配 URL 到爬蟲機器。當一台機器故障：

  1. 一致性雜湊自動將故障機器的 key 範圍重新分配到其他機器
  2. 其他機器接管後，從 checkpoint 恢復狀態繼續爬取
  3. 不需要中央協調器手動介入

Index Server 重建

如果存儲索引的伺服器故障且無副本：

  • 回放所有推文/網頁的寫入日誌（write-ahead log）重建索引
  • 這就是為什麼原始資料（raw content）不能丟——它是索引重建的唯一來源

挑戰四：資料分區

爬蟲系統處理三種主要資料：

  1. URLs to visit：待爬取的 URL 佇列
  2. URL checksums：已爬 URL 的 checksum（用於去重）
  3. Document checksums：已下載文件的 checksum（用於內容去重）

關鍵洞察：因為我們按 hostname 做一致性雜湊來分配 URL，所以這三種資料可以存放在同一台機器上。每台機器負責一組 hostname，並同時存放這些 hostname 對應的 URL 佇列、URL checksum 和 document checksum。

這樣做的好處：

  • URL 去重查詢不需要跨機器通訊
  • Politeness 策略在同一台機器上就能實現
  • Checkpoint 和恢復邏輯更簡單

面試總結

爬蟲設計的面試重點是「你知不知道大規模下的 trick」：用 Bloom Filter 做高效去重、用一致性雜湊做分散式分配和 failover、用 checkpoint 做容錯恢復。這些不是教科書知識，而是生產環境的實務經驗。
