效率：系統跑得快，還要能撐得住

系統設計 · 分散式系統基礎 · Step 4/5

學習目標

理解分散式系統如何衡量效率，分清楚延遲（Latency）與吞吐量（Throughput），並知道兩者在什麼情境下需要取捨。

什麼是效率？

在分散式系統裡，效率不是單純看「快不快」，而是看系統完成工作的表現。

想像你送出一個請求，系統要到好幾台機器收集資料，整理完後再把結果傳回來。這段過程可以從兩個角度觀察：

  • 延遲（Latency）：送出請求後，要等多久才收到結果。
  • 吞吐量（Throughput）：在一段時間內，系統總共能處理多少工作。

這很像衡量一條公路：延遲是在問「一輛車從 A 點開到 B 點要多久」；吞吐量則是在問「一小時內，這條路能讓多少輛車通過」。一條路可能讓單輛車很快抵達，卻因為車道太少而塞車；也可能一次容納很多車，但每輛車都要排隊。

延遲：使用者等多久？

延遲是使用者感受到的回應時間。例如使用者點擊按鈕後，直到畫面更新，中間等待的時間就是延遲。

一次請求的延遲，通常不是只有一個環節造成的，而像一段接力賽：

  • 網路傳輸：資料在網路上往返所需的時間。受到光速限制，跨洲傳輸的延遲通常約為 100–300ms。
  • 處理時間：CPU 計算、資料庫查詢等工作所花的時間。
  • 排隊等待：請求已經抵達，卻還要在佇列中等候處理。
  • 序列化：把資料轉換成可傳輸或儲存格式所需的時間。

如果你之前做過 API 或資料庫查詢，可以把延遲想成「從送出請求到拿到回應」的完整等待時間。即使程式本身只花了幾毫秒，若請求卡在網路或佇列裡，使用者仍然會覺得系統很慢。

為什麼不只看平均值？

分散式系統通常用 P50、P95、P99 這類百分位數衡量延遲，而不是只看平均值。

平均值容易被少數極端慢的請求拉偏；百分位數則能回答更實際的問題：「大多數使用者到底要等多久？」例如：

如果 P99 延遲是 200ms，代表 99% 的請求會在 200ms 內完成，只有 1% 的請求超過 200ms。

因此，當你設計系統或分析效能時，不能只說「平均延遲是 50ms」，還要確認 P95 或 P99 是否出現異常。平均表現漂亮，不代表每位使用者都順利。

吞吐量：系統一次能處理多少？

吞吐量是系統在單位時間內完成的工作量。例如：

  • 每秒處理 10,000 個請求，也就是 10,000 RPS。
  • 每秒傳輸 1GB 資料。

如果延遲像是「單輛車的行車時間」，吞吐量就是「這條道路每小時能通過多少車」。當你面對大量請求，例如日誌持續寫入、資料流持續進來，吞吐量就會變得特別重要。

影響吞吐量的因素包括：

  • 硬體限制：CPU 核心數、記憶體頻寬與網路頻寬，都會限制系統能處理的量。
  • 並發處理能力：系統能否同時處理多個請求。
  • 鎖與同步：鎖太多時，請求必須輪流等待，並發度就會下降。
  • 資源共享：多個服務同時搶用同一項資源，也會降低整體吞吐量。

所以，當你之前在設計服務時考慮「要不要平行處理」，其實就是在思考吞吐量。不過並發不是越高越好；如果所有請求都擠向同一個資料庫或共享資源，反而可能因為排隊而讓延遲變高。

延遲與吞吐量：為什麼常常要取捨？

延遲和吞吐量關心的是不同問題，因此最佳策略也可能不同：

策略對延遲的影響對吞吐量的影響
批次處理（Batch）延遲增加吞吐量提高
快取（Cache）延遲降低吞吐量可能提高
增加並發延遲可能增加（排隊）吞吐量提高
同步 vs 非同步同步延遲高非同步吞吐量高

以日誌系統為例，如果每一筆日誌都立刻寫入，單筆日誌的等待時間可能較短，但每次寫入都要付出一次操作成本，整體吞吐量較低。

另一種做法是先累積多筆日誌，再一次打包寫入。這就像把零散包裹集中成一車配送：每筆日誌要多等一下，但系統可以更有效率地處理大量資料，吞吐量也會提高。

因此，設計前要先問清楚需求：

  • 是使用者正在等回應，必須優先降低延遲？
  • 還是系統要持續處理大量資料，必須優先提高吞吐量？

這個問題在面試中特別重要。你選擇快取、批次處理、同步或非同步，不應該只是背設計模式，而要能說明：這個系統最在意的是單次回應速度，還是單位時間的處理量。

效率不只有延遲和吞吐量

當你設計分散式資料結構或演算法時，還要留意其他效率指標：

  • 節點間的訊息數量：不論每則訊息大小，訊息越多，網路往返與處理開銷通常越大。
  • 資料交換量：傳輸的資料越多，占用的網路頻寬就越多。
  • 操作複雜度：例如在分散式索引中搜尋某個 key，需要花多少時間。

這些指標可以幫你看見系統的「隱形成本」。有時候單次操作的延遲看起來不高，但如果每個節點都要互相傳送大量訊息，整個系統仍可能被網路頻寬或通訊成本拖慢。

所以，當你下次分析一個分散式設計時，可以依序問三個問題：單次請求要等多久？每秒能處理多少工作？為了完成這些工作，節點之間需要交換多少訊息與資料？
