資料庫選擇：SQL vs NoSQL

system-design · data-strategies · Step 5/5

學習目標

全面比較 SQL 與 NoSQL 資料庫，能依系統需求選擇合適的資料庫類型。

兩種完全不同的資料櫃

想像你要整理家裡的東西。一種方式是買一個大型收納櫃，每個抽屜有固定的標籤和格子——襪子放 A 抽屜、内衣放 B 抽屜、T恤放 C 抽屜。你必須在買櫃子之前就決定每個格子放什麼。另一種方式是買一組透明收納箱，裡面的東西隨便放，今天放衣服明天放書，格式由你決定。

收納櫃就是 SQL 資料庫，透明收納箱就是 NoSQL 資料庫。兩者都在存資料，但組織方式完全不同。

SQL 資料庫

SQL（Structured Query Language）資料庫是關聯式資料庫，資料存在結構化的表格（table）中，表格之間透過關聯（relation）連接。

核心特點：

特點 說明
結構化 Schema 資料必須符合預先定義的表格結構，欄位類型固定
ACID 事務 Atomicity、Consistency、Isolation、Durability——保證事務的可靠性和一致性
SQL 查詢 使用標準 SQL 語法，支援複雜的 JOIN、GROUP BY、子查詢
垂直擴展 擴展方式是升級單台機器的硬體（更多 CPU、RAM）

你在用過的 Postgres 和 MySQL 就是 SQL 資料庫。例如一個電商系統，你會定義 Users 表、Orders 表、Products 表，它們之間有外鍵關聯。要查「某個用戶的所有訂單及商品明細」，一個 SQL JOIN 就能搞定。

NoSQL 資料庫

NoSQL（Not Only SQL）資料庫是非關聯式或分散式資料庫，支援多種資料模型：文件（Document）、鍵值（Key-Value）、寬列（Wide-Column）、圖（Graph）。

模型 資料結構 代表產品 適用場景
文件 JSON/BSON 文档 MongoDB、CouchDB 內容管理、使用者資料
鍵值 Key → Value 對 Redis、DynamoDB 快取、 Session、配置
寬列 列族（Column Family） Cassandra、HBase 時間序列、日誌、IoT
圖 節點 + 邊 Neo4j、Amazon Neptune 社交網路、推薦系統

NoSQL 的核心特點：

  • 彈性 Schema：不需要預先定義結構，不同文件可以有不同的欄位
  • 水平擴展：擴展方式是加更多機器（scale out），而不是升級單台
  • 最終一致性：通常不保證即時一致性，但能提供更高的可用性
  • 高吞吐量：針對特定資料模型優化，讀寫速度通常比 SQL 快

SQL vs NoSQL：全面比較

維度 SQL NoSQL
資料結構 預先定義的表格結構 彈性，不同文件可有不同欄位
擴展方式 垂直（升級硬體） 水平（加機器）
事務 強 ACID 保證 通常最終一致性，部分支援 ACID
查詢能力 強大的 SQL，支援複雜 JOIN 查詢能力因產品而異，JOIN 通常有限
適合的資料量 中等規模、結構清晰 大規模、結構多變
Schema 變更 需要遷移（migration），成本高 直接加欄位，成本低
典型場景 金融系統、ERP、電商訂單 社交網路、即時通訊、IoT、快取

選擇的判斷框架

問自己三個問題：

  1. 資料結構是否明確且穩定？ 如果你的資料結構清晰、未來不會頻繁變動，SQL 的結構化 Schema 是優勢。如果資料結構多變（例如不同用戶有不同欄位），NoSQL 的彈性 Schema 更合適。
  2. 你需要強一致性嗎？ 金融交易、庫存管理這類不能容忍不一致的場景，SQL 的 ACID 事務是必要的。社交媒體的按讚數、瀏覽量這類能容忍短暫不一致的場景，NoSQL 的最終一致性就夠了。
  3. 你的資料量和擴展需求？ 中等規模、讀取為主的系統，SQL 綽綽有餘。超大規模（數十億筆記錄）、需要水平擴展的系統，NoSQL 的分散式架構更容易擴展。

很多生產系統會混合使用——用 SQL 處理核心事務（訂單、支付），用 NoSQL 處理非結構化資料（用戶行為日誌、快取）。這不是「SQL 比較好」或「NoSQL 比較好」的問題，而是「什麼場景用什麼工具」。

面試中的關鍵點

  • 能清楚解釋 SQL 和 NoSQL 在資料結構、擴展方式、事務保證上的差異
  • 能根據三個判斷問題（結構穩定性、一致性需求、資料量）選擇資料庫
  • 能說明為什麼很多系統混合使用兩種資料庫
  • 能列出 NoSQL 的四種資料模型及其適用場景

小結

SQL 適合結構清晰、需要強一致性的場景；NoSQL 適合結構多變、需要水平擴展的場景。選擇時要看資料結構穩定性、一致性需求、資料量三個維度。生產系統常常混合使用，用 SQL 處理事務、用 NoSQL 處理非結構化資料。
