Proxy 基礎概念

system-design · proxy-redundancy · Step 1/4

學習目標

理解什麼是 Proxy 伺服器，以及正向代理（Forward Proxy）在系統設計中的核心角色與常見用途。

從快遞站開始：Proxy 的比喻

想像你要寄一封信給某個朋友，但你不希望對方知道你的真實地址。你可以把信交給一個快遞站，由快遞站代為寄出。收件人看到的寄件地址是快遞站的，不是你的。

Proxy（代理）伺服器就是這個快遞站。它是介於用戶端（client）和伺服器（server）之間的一段軟體或硬體，代替用戶端向伺服器發出請求，再把結果回傳給用戶端。

什麼是 Proxy 伺服器？

用一句話說：Proxy 伺服器是一個中介（intermediary），用戶端不直接跟目標伺服器溝通，而是先把請求交給 Proxy，由 Proxy 轉發。

這個「轉發」的動作可以做很多事：

功能 做什麼 實際例子
快取 把常用資源存在 Proxy，下次有人要同樣的東西直接給，不用再去原始伺服器拿 公司網路的 Proxy 快取員工常看的新聞網站
過濾 擋掉不符合規則的請求 學校網路封鎖社群媒體
記錄 記下所有經過的請求，方便审计和分析 企業追蹤員工上網行為
轉換 修改請求或回應的內容（加 header、加密、壓縮等） 自動壓縮圖片以節省頻寬
隱藏身份 代替用戶端發請求，伺服器看到的是 Proxy 的 IP 翻牆工具、隱私瀏覽

正向代理（Forward Proxy）

Proxy 有兩大類：正向代理和反向代理。這一課先聚焦在正向代理。

正向代理（Forward Proxy）是站在用戶端這邊的代理。它代表用戶端去跟伺服器打交道。關鍵特徵：伺服器不知道真正發請求的人是誰——它只看到 Proxy 的身份。

用戶端 A ──┐
用戶端 B ──┼──→ 正向代理 ──→ 伺服器
用戶端 C ──┘

想想這個場景：你公司有 500 個員工要上外網。如果不設正向代理，每個人直接對外發請求，公司無法控制也無法審計。設了正向代理後，所有流量都經過同一個出口，公司可以：

  • 快取常見資源，減少外部頻寬消耗
  • 過濾不當內容
  • 記錄所有對外請求
  • 統一管理出口 IP

正向代理 vs 直接連接

比較一下有沒有正向代理的差異：

面向 直接連接 經過正向代理
伺服器看到的 用戶端的真實 IP Proxy 的 IP
公司可否審計 難以集中審計 所有請求都有記錄
能否快取 瀏覽器快取為主，效率有限 Proxy 級快取，全公司共用
能否過濾 每台機器各自設定 集中規則，一次生效

面試中的關鍵點

在系統設計面試中，Proxy 是一個基礎但高頻的概念。面試官想聽到的是：

  • 你能一句話定義 Proxy（中介，轉發請求）
  • 你能分辨正向代理和反向代理的核心差異（代理的對象不同）
  • 你能列舉正向代理的實際用途（快取、過濾、記錄、隱藏身份）
  • 你理解 Proxy 不只是「轉發」，它可以修改、快取、過濾、記錄請求

正向代理是站在用戶端這邊的；下一課會介紹站在伺服器那邊的反向代理，兩者的角色完全相反。

小結

Proxy 伺服器是介於用戶端和伺服器之間的中介。正向代理代表用戶端發請求，伺服器看到的是 Proxy 而非真實用戶。它的核心價值在於：快取加速、集中管控、隱藏身份。理解正向代理後，下一課會看到它的鏡像——反向代理。
