可擴展性（Scalability）

系統設計 · 分散式系統基礎 · Step 2/5

學習目標

掌握可擴展性的定義，區分垂直擴展與水平擴展，理解各自的優缺點與適用場景。

什麼是可擴展性？

可擴展性是系統持續增長並應對越來越大需求的能力。當你的使用者越來越多、數據量越來越大、請求量越來越高時，系統能不能透過調整資源來維持甚至提升性能？

一個具有良好可擴展性的系統，能夠在需求增長時，透過增加資源來匹配需求，不會讓性能隨著規模增長而快速下降。

舉個實際的例子：你的網站一開始只有 1000 個使用者，用一台伺服器就夠了。後來使用者增長到 100 萬，你能不能只透過增加伺服器數量來承載更多流量，而不需要完全重寫整個系統？如果可以，那你的系統就是可擴展的。

垂直擴展（Scale Up）

垂直擴展就是給現有單台伺服器增加更多資源——換上更強大的 CPU、增加更多記憶體、換上更大更快的硬碟。

優點

  • 簡單：不需要改變程式架構
  • 無分散式複雜度：不需要處理分散式一致性等問題

缺點

  • 硬體極限：單台機器能增加的資源始終有限
  • 停機升級：升級通常需要停機，影響可用性
  • 成本高：單位成本比水平擴展高
  • 單點故障：一台壞了全部掛掉

垂直擴展常見於中小型應用，或者數據庫這種比較難做水平擴展的場景。例如 MySQL 一開始通常都是垂直擴展，換更大的機器。

水平擴展（Scale Out）

水平擴展就是增加更多伺服器節點，把流量和數據分散到多台機器上。

優點

  • 理論上無限擴展：需要更多容量就加更多機器
  • 動態增減：不需要停機就能增減機器
  • 成本低：使用普通廉價機器
  • 高可用：單一機器故障不影響整體服務

缺點

  • 架構複雜：需要重新設計架構，把應用改成可以分散執行的模式
  • 分散式問題：需要處理負載均衡、數據分區、一致性等問題
  • 運維成本：需要管理大量機器

水平擴展常見於大規模網際網路服務。例如 Cassandra、MongoDB 這類分散式數據庫天生就支援水平擴展。大型網站的 Web 伺服器通常也是水平擴展，根據流量增減機器數量。

垂直 vs 水平：怎麼選？

維度垂直擴展水平擴展
操作方式升級單台機器的硬體增加更多機器
架構改變不需要需要重新設計
擴展上限有硬體極限理論上無限
成本單位成本高單位成本低
故障影響單點故障故障隔離
適用場景中小型、數據庫初期大規模網際網路服務

很多系統一開始都是垂直擴展，等到規模夠大了再逐漸改成水平擴展。這是一個務實的策略——過早優化是萬惡之源。
