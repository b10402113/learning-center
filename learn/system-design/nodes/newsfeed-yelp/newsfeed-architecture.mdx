# Facebook Newsfeed 架構設計
## Learning goal
掌握 Newsfeed 系統的整體架構，了解推播 (push) 與拉播 (pull) 模式的取捨，以及動態消息生成、排名和資料分片的設計。
## Lesson

Facebook Newsfeed 的核心挑戰是：如何在數百萬來源中快速聚合最新內容，並以低延遲遞送給數億使用者？資料模型涉及三個實體——User、Entity（粉專、社團等）和 FeedItem（貼文），關鍵關係是每個使用者的追蹤清單（UserFollow）記錄他追蹤了哪些對象。

架構設計的核心取捨是推播（Push）與拉播（Pull）模式的選擇。拉播模型在使用者查詢時才即時拉取追蹤者的最新貼文，資料永遠最新但延遲高。推播模型在貼文發布時就預先將 FeedItem ID 寫入追蹤者的 feed 快取（sorted set，以時間或排名分數為 score），查詢時直接從快取取出前 N 條再批量查詢貼文詳細資料，讀取延遲極低但寫入成本高。實際的 Facebook 使用混合模型：大部分使用者走推播，追蹤者極多的帳號（如名人）改為查詢時即時拉取，與預計算 feed 合併後排序。

Feed 排名不只是按時間順序。現代排名演算法先選出影響貼文重要性的訊號——親密度（使用者與發布者的互動程度）、內容類型（影片圖片通常比純文字獲得更多互動）、時間衰減和互動率——再透過模型或加權公式組合成最終分數。面試中要能解釋排名的取捨：精準排名需要更多計算資源和延遲。

資料分片方面，貼文按 UserID 進行 hash partitioning，同一使用者的貼文在同一分片上。Feed 快取也按 UserID 分片。主要挑戰是熱點使用者（名人有數千萬追蹤者，一篇貼文的 fan-out 寫入量巨大）、快取大小和推播模型中寫入快取與資料庫的時間差導致的短暫不一致。
