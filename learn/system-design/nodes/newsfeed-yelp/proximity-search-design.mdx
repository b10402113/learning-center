# Yelp 鄰近搜尋設計
## Learning goal
掌握地理位置鄰近搜尋的核心演算法，包括 SQL 查詢、網格分割、QuadTree 與動態網格等方法，以及如何進行資料分片。
## Lesson

Yelp 的核心功能是根據使用者的經緯度搜尋指定半徑內的地點。這是經典的地理空間鄰近搜尋問題，關鍵約束是地點位置幾乎不變（靜態資料），適合建立高效靜態索引。每個地點約 800 bytes（LocationID、Name、Latitude、Longitude、Description、Category），5 億個地點的純地點資料約 400GB。

最直覺的做法是用 SQL 查詢：在經緯度欄位上建立索引，以 BETWEEN 查詢一個方形範圍內的地點，再過濾掉超出實際圓形搜尋半徑的結果。但 5 億個地點在 100K QPS 下，單一資料庫無法承受。

網格分割（Grid）將地圖分成固定大小的格子，每個格子存儲範圍內的地點。搜尋時只查詢相鄰的 1-4 個格子，查詢範圍從全球縮小到數千個地點。但固定大小的網格有「分佈不均」問題：市中心的格子可能包含數千個地點，郊區可能只有幾個。

QuadTree（四元樹）透過動態分割解決分佈不均：當一個格子的地點超過閾值（如 500 個）時，分割成四個等大的子格子。市中心會有大量小網格，郊區會有少量大網格，查詢效率自動適應密度。搜尋時從根節點遞迴進入包含搜尋範圍的子節點。

當 QuadTree 太大無法放單機記憶體時，需要分片。水平分片使用一致性雜湊將葉節點分散到多台機器；地理分片按區域分割（如美國西岸和東岸各由不同伺服器負責）。QuadTree 伺服器使用主從複製：從伺服器只處理讀取，寫入先到主伺服器再同步，從伺服器可能有輕微延遲但搜尋場景可接受。熱門地點可用 Memcache 的 LRU 快取加速。
