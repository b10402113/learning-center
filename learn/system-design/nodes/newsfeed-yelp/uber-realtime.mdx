# Uber 即時位置與配對設計
## Learning goal
了解如何修改 Yelp 的靜態鄰近搜尋架構來支援 Uber 場景中駕駛位置的頻繁更新，以及如何實現即時乘客-駕駛配對。
## Lesson

Yelp 的 QuadTree 建立在地點位置幾乎不變的假設上，但 Uber 的駕駛位置每 3 秒更新一次——50 萬名活躍駕駛每秒產生約 167K 次位置更新。這帶來兩個核心問題：QuadTree 更新成本高（每次都需要找到舊節點、刪除、計算新節點、插入，時間複雜度 O(log n)，但每秒 167K 次成為瓶頸），以及需要在駕駛進入乘客搜尋半徑時即時通知。

解決方案是將 QuadTree 放在記憶體中以減少 I/O 成本，駕駛最新位置存儲在 QuadTree 葉節點中，同時同步寫入 SSD 作為持久化存儲以防止伺服器宕機導致資料遺失。更新採用增量方式：每次位置更新只需從 QuadTree 的舊位置中刪除該駕駛，再插入到新位置的節點中，不需要重建整個結構。

叫車流程為：乘客發出請求後，系統以乘客位置為中心搜尋半徑內的所有可用駕駛，按距離、評分、歷史表現和預估到達時間等多因素排名，選擇最佳匹配並發送請求。若選中的駕駛未在一定時間內回應，自動嘗試下一個最佳匹配。配對成功後，駕駛位置即時推送到乘客 App 中。

進階問題包括：網路斷線時的同步與計費處理、推播與拉取混合模式的選擇、以及地理圍欄（Geofence）——當駕駛位置跨越圍欄邊界時觸發「附近有新訂單」等事件通知。
