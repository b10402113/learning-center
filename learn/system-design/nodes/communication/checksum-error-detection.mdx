# Checksum 錯誤偵測
## Learning goal
理解 Checksum 如何檢測資料傳輸過程中的錯誤，認識其原理與常見應用場景
## Lesson

在分散式系統中，資料在節點之間傳輸時，可能因為儲存設備故障、網路干扰、軟體 bug 等原因而損壞。你從一台伺服器下載了一個 1GB 的檔案，但下載過程中網路線被干擾了一下，某個位元從 0 翻轉成了 1。你怎麼知道檔案有沒有被損壞？你不可能逐位元比對原始檔案。

**Checksum（校驗和）** 是對原始資料做一次數學運算後得到的固定長度的字串（包含字母和數字）。它的核心特性是：相同的資料 always 產生相同的 checksum，不同的資料（哪怕只差一個位元）會產生不同的 checksum（機率極高），運算速度很快。類比：Checksum 就像資料的「指紋」，每份資料有獨一無二的指紋，只要比對指紋就能判斷兩份資料是否相同。

Checksum 的運作流程分三個階段。儲存時，伺服器計算資料的 checksum，把 checksum 與資料一起儲存。傳輸時，發送方計算資料的 checksum 與資料一起傳輸，接收方收到後獨立計算一次 checksum，比對兩個 checksum：相同則資料正確，不同則資料已損壞。讀取時，從儲存設備讀取資料和它對應的 checksum，獨立計算一次 checksum 並比對。

Checksum 通常使用加密雜湊函數（Cryptographic Hash Function）來計算。常見的有 MD5（128 bits，已發現碰撞，不建議用於安全性）、SHA-1（160 bits，已不建議用於安全性）、SHA-256（256 bits，目前的標準選擇）和 SHA-512（512 bits，高安全性需求）。在系統設計面試中，SHA-256 是首選，MD5 和 SHA-1 適用於非安全性場景。

Checksum 的局限包括：碰撞（兩份不同資料可能產生相同 checksum，但 SHA-256 的碰撞機率約 2<sup>-128</sup>，可忽略不計）；無法修正錯誤（只能偵測，修正需要重新傳輸或從備份恢復）；計算成本（對超大檔案計算 SHA-256 需要時間，但現代 CPU 每秒可計算數 GB）。Checksum 是最低成本的防線，通常與 RAID、副本等機制配合使用。
