# 效率（Efficiency）

## Learning goal
理解分散式系統中效率的衡量指標，認識延遲（Latency）與吞吐量（Throughput）之間的差異與取捨。

## Lesson

在分散式系統中，效率衡量的是**系統完成工作的表現**。想像一個分散式操作：系統從多台機器上收集資料，最終返回結果給使用者。衡量這個過程的效率，主要有兩個指標——延遲（Latency）和吞吐量（Throughput）。

這兩個指標就像是衡量一條公路的兩種方式：延遲是「從 A 點到 B 點要多久」，吞吐量是「每小時能通過多少輛車」。它們從不同角度描述系統的效率，而且往往存在取捨關係。

### 延遲（Latency）

延遲是**使用者感知到的響應時間**。當使用者點擊一個按鈕，到畫面更新，中間的等待時間就是延遲。延遲的來源有很多：網路傳輸（光速限制，跨洲延遲通常 100-300ms）、處理時間（CPU 計算、資料庫查詢）、排隊等待（請求在佇列中等待處理）、序列化（資料轉換格式）。

在分散式系統中，延遲通常用 **P50、P95、P99** 等百分位數來衡量，而不是平均值。因為平均值會被極端值拉偏，而百分位數能告訴你「99% 的請求在多久內完成」。例如 P99 延遲是 200ms，意味著 99% 的請求在 200ms 內完成。

### 吞吐量（Throughput）

吞吐量是**系統在單位時間內能處理的工作量**。例如每秒處理 10,000 個請求（10,000 RPS），或每秒傳輸 1GB 數據。影響吞吐量的因素包括硬體限制（CPU 核心數、記憶體頻寬、網路頻寬）、並發處理能力、鎖與同步機制、資源共享競爭等。

### 延遲 vs 吞吐量：取捨

延遲和吞吐量之間常常存在取捨。例如批次處理（Batch）把多個操作打包處理，吞吐量提高了，但每個操作的等待時間也增加了。快取（Cache）能降低延遲，但增加了系統複雜度。在面試中，問清楚需求是「低延遲優先」還是「高吞吐量優先」，會直接影響你的設計方向。

除了延遲和吞吐量，效率還可以用節點間發送的訊息數量、資料交換量、操作複雜度等方式衡量。這些指標在設計分散式資料結構和演算法時尤其重要。
