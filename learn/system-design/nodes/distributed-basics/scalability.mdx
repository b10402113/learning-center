# 可擴展性（Scalability）

## Learning goal
掌握可擴展性的定義，理解為什麼它是分散式系統的核心目標，區分垂直擴展與水平擴展。

## Lesson

可擴展性是<strong>系統持續增長並應對越來越大需求的能力</strong>。當你的服務使用者越來越多，數據量越來越大，請求量越來越高，系統能不能透過調整資源來維持甚至提升性能，這就是可擴展性要解決的問題。

一個具有良好可擴展性的系統，能夠在需求增長時，透過增加資源來匹配需求，不會讓性能隨著規模增長而快速下降。舉例來說，當你的網站從1000個使用者增長到100萬個使用者，能不能只透過增加伺服器數量來承載更多流量，而不需要完全重寫整個系統？如果可以，那你的系統就是可擴展的。

擴展系統主要有兩種方式，分別是垂直擴展和水平擴展：

### 垂直擴展（Scale Up）
垂直擴展就是<strong>給現有單台伺服器增加更多資源</strong>，比如換上更強大的CPU、增加更多記憶體、換上更大更快的硬碟。優點是簡單，不需要改變程式架構，也不需要處理分散式一致性等複雜問題；缺點是有硬體極限，單台機器能增加的資源始終有限，而且升級通常需要停機，會影響服務可用性，另外單位成本比水平擴展高，還有單點故障風險。

垂直擴展常見於中小型應用，或者數據庫這種比較難做水平擴展的場景。例如MySQL一開始通常都是垂直擴展，換更大的機器。

### 水平擴展（Scale Out）
水平擴展就是<strong>增加更多伺服器節點</strong>，把流量和數據分散到多台機器上。優點是理論上可以無限擴展，需要更多容量就加更多機器，可以動態增減機器不需要停機，使用普通廉價機器整體成本更低，還能提高可用性，單一機器故障不影響整體服務。缺點是需要重新設計架構，把應用改成可以分散執行的模式，增加了系統複雜度，需要處理負載均衡、數據分區、一致性等問題，也需要更多的運維工作來管理大量機器。

水平擴展常見於大規模網際網路服務，例如Cassandra、MongoDB這類分散式數據庫天生就支援水平擴展。大型網站的Web伺服器通常也是水平擴展，根據流量增減機器數量。

## 總結
可擴展性是分散式系統最核心的目標之一，大多數時候我們偏好水平擴展，因為它更適合大規模增長。但垂直擴展也不是完全不用，在系統規模還小的時候，垂直擴展通常是更簡單便宜的選擇。很多系統一開始都是垂直擴展，等到規模夠大了再逐漸改成水平擴展。
