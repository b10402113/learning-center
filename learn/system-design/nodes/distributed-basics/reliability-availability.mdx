# 可靠性與可用性（Reliability & Availability）

## Learning goal
區分可靠性、容錯與可用性的概念，理解它們在系統設計中的不同含義與重要性。

## Lesson

### 可靠性（Reliability）
可靠性指的是<strong>系統在故障環境下，持續正確運行的能力</strong>。簡單來說，就算部分組件故障了，系統還是能正確完成工作，不丟失數據，也不出錯，那這個系統就是可靠的。

舉例來說，電商網站中，使用者加入購物車後，就算存放這筆資料的伺服器壞了，使用者還是能在結帳時看到購物車裡的商品，那這個系統就是可靠的。達成可靠性主要依靠<strong>冗餘（Redundancy）</strong>，也就是多保存幾份數據，多部署幾份服務，這樣一個壞了還有其他備份可以用。

### 容錯（Fault Tolerance）
容錯和可靠性高度相關，但概念不太一樣。容錯是<strong>系統在組件故障時，繼續運行的能力</strong>，就算性能降低，至少不會整個掛掉。

兩者的差異可以總結為：
- **範疇不同**：可靠性關注整個系統端到端的正確性和一致性；容錯關注個別組件故障時系統能不能繼續跑。
- **觀點不同**：可靠性是使用者導向的概念，關心系統能不能一直符合使用者預期；容錯是系統導向的概念，關心系統怎麼處理內部故障。
- **衡量方式不同**：可靠性常用上線時間、錯誤率、平均故障間隔（MTBF）來衡量；容錯常用故障偵測、隔離、恢復的速度來衡量。

### 可用性（Availability）
可用性是<strong>在特定時間段內，系統能夠正常工作的時間百分比</strong>。簡單來說就是，當使用者需要使用服務時，服務能不能正常訪問。

可用性通常用「幾個9」來衡量，例如：
- 99%可用性 = 一年 downtime 約 3.65 天
- 99.9%（三個9）可用性 = 一年 downtime 約 8.76 小時
- 99.99%（四個9）可用性 = 一年 downtime 約 52.5 分鐘
- 99.999%（五個9）可用性 = 一年 downtime 約 5.25 分鐘

要達到越高的可用性，需要的成本也指數上升，所以要根據服務需求選擇適當的可用性等級，不需要盲目追求越多個9越好。例如一般部落格網站99.9%就夠了，但金融交易系統可能需要99.999%。

### 可靠性 vs 可用性：差異與關係
很多人會搞混這兩個概念，簡單來說：**可靠的系統一定可用，但可用的系統不一定可靠**。

高可靠性有助於達成高可用性，但你也可以透過快速修復來達成高可用性，就算系統本質上不是那麼可靠。舉例來說，一家電商網站開張前兩年可用性達到99.99%，但一開始沒有做資安測試，系統其實有很多漏洞，可靠性不高。第三年發生大規模資安事件，導致長時間不可用，還損失了大量用戶數據，這就是高可用性但低可靠性的例子。
