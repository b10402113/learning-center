# 分散式系統概述

## Learning goal
理解什麼是分散式系統，認識核心特性的整體框架，為深入學習每個特性打好基礎。

## Lesson

分散式系統是由**多個獨立節點**組成的系統，這些節點通過網絡進行通信，協同完成一個共同的目標。在現代網際網路中，絕大多數大規模服務背後都是分散式系統，因為單機很難承載越來越大的規模，也無法滿足可靠性、可用性等需求。

舉例來說，你常用的電商網站、社群媒體、雲端服務，都是由數百萬台伺服器組成的分散式系統，分散在全球各地的資料中心，卻能提供一個統一的服務體驗。

為什麼需要分散式系統？主要有這幾個原因：

- **可擴展性**：可以根據需求增減節點，應對越來越大的流量和數據量
- **可靠性／容錯**：單個節點故障不影響整體服務，提升整體可用性
- **低延遲**：可以把服務部署在靠近使用者的位置，降低訪問延遲
- **成本效益**：可以使用大量廉價的普通伺服器替代超級電腦，降低整體成本

設計分散式系統時，我們主要圍繞五個核心特性來做取捨和決策：

1. **可擴展性**：系統應對增長需求的能力。當流量、數據量、請求數增加時，系統能不能透過增加資源來維持性能？
2. **可靠性**：系統在故障環境下持續正確運行的能力。當部分節點故障時，系統能不能依然正確地完成請求，不丟失數據？
3. **可用性**：系統在正常條件下保持可操作的時間百分比。使用者在需要使用服務時，能不能正常訪問？
4. **效率**：衡量系統響應速度和吞吐量，一般用延遲和吞吐量來衡量。
5. **可管理性**：系統維護與運營的難易程度。包括部署、監控、排查問題、升級等操作是否方便。

每個特性都會影響設計決策，也彼此有權衡取捨，在接下來的步驟我們會逐一深入。
