# 什麼是索引

## Learning goal

理解索引的核心概念、類比以及它為什麼能加速查詢。

## Course

[↗ 課程頁面](../../lessons/what-is-an-index.html)

## Lesson

資料庫查詢慢的時候，最先想到的優化手段就是索引。索引的核心思想很簡單：**用額外的空間換取更快的查詢速度**，就像圖書館的目錄卡片讓你不用逛遍所有書架就能找到書。

### 全表掃描的問題

假設你有一張包含 1 億筆使用者記錄的資料表，要找「名字叫 Alice 的使用者」。最直覺的做法是從第一筆開始，一行一行往下找——這就是**全表掃描（Full Table Scan）**。1 億筆記錄，就算每筆只要 1 微秒，掃完也要將近 2 分鐘。在掃描結束之前，你不知道 Alice 到底存不存在。更糟的是，如果你經常做這樣的查詢，整個系統會被拖垮。

### 圖書館的啟發

圖書館怎麼解決同樣的問題？它有兩套**目錄卡片**：一套按書名排序，一套按作者排序。你想找某本書的時候，不用把所有書架逛一遍——翻一下目錄卡片，就能直接定位到正確的書架位置。索引（Index）就是資料庫的目錄卡片。

### 索引的本質

索引是一種資料結構，它把資料表中某一欄（或某幾欄）的值和對應的資料位置，以特定方式組織起來。查詢時，資料庫先在索引中快速找到目標值的位置，然後直接跳到那一筆記錄。沒有索引的查詢是 O(n)，有索引的查詢可以達到 O(log n) 甚至 O(1)。

具體來說，假設你有一張 `users` 表，執行 `SELECT * FROM users WHERE name = 'Alice'`：

- **沒有索引**：資料庫逐行比較 `name` 欄位，找到 Alice 才停。資料越多越慢。
- **有索引**：資料庫在預先建好的索引結構中查找 "Alice"，直接得到它的位置，一步到位。

索引可以用在一個欄位上（單欄索引），也可以用在多個欄位的組合上（複合索引），取決於你的查詢模式。

### 索引的代價

索引不是免費的午餐。每多一個索引，就多佔一份磁碟空間（索引本身也是一張表），而且每次插入、更新、刪除資料時，索引也要同步更新，拖慢寫入效能。就像圖書館的目錄卡片：書越多、目錄越完整，維護成本就越高。所以索引的關鍵不是「越多越好」，而是「在對的地方建對的索引」。
