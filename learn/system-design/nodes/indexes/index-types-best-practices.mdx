# 索引類型與最佳實踐

## Learning goal

認識常見索引類型（主索引/次要索引、叢集/非叢集索引）以及在系統設計中如何正確使用索引。

## Course

[↗ 課程頁面](../../lessons/index-types-best-practices.html)

## Lesson

前三課講了索引的概念、資料結構和讀寫取捨。這課把索引的「工具箱」攤開來看——有哪些類型的索引，以及在系統設計中怎麼正確使用它們。

### 主索引 vs 次要索引

主索引建立在**主鍵（Primary Key）**上，每張表只能有一個。在 MySQL InnoDB 中，主索引就是叢集索引——資料表的物理排序就是按照主鍵來的。次要索引建立在非主鍵欄位上，一張表可以有多個。次要索引的葉子節點存的是主鍵值，而不是資料的物理位置。這意味著透過次要索引找到主鍵後，還需要**一次額外的查找**才能拿到完整資料——這就是所謂的**回表查找（Lookup）**。

類比：主索引就像書的正文頁碼——直接翻到那一頁就有內容。次要索引就像書的索引——先找到頁碼，再翻到那一頁看內容。

### 叢集索引 vs 非叢集索引

叢集索引決定了資料在磁碟上的**物理排列順序**。一張表只能有一個叢集索引（物理順序只有一種）。優點是範圍查詢極快（相鄰資料在磁碟上也相鄰，順序讀取），缺點是插入時可能導致頁分裂（page split），因為要維持物理順序。

非叢集索引是獨立於資料物理儲存的索引結構，葉子節點存的是指向資料的指針（或主鍵值）。可以建多個，不影響資料的物理儲存，但範圍查詢不如叢集索引快（資料在磁碟上可能不連續）。

### 覆蓋索引

覆蓋索引是一種優化技巧：當索引包含了查詢所需的所有欄位時，資料庫**不需要回表查找**，直接從索引就能返回結果。例如查詢 `SELECT name, email FROM users WHERE age > 25`，如果建了 `(age, name, email)` 的複合索引，這個查詢只需要掃描索引就能拿到所有需要的資料。

### 複合索引的欄位順序

複合索引的**欄位順序非常重要**。規則是：把等值條件（`WHERE x = 1`）的欄位放在前面，範圍條件（`WHERE y > 10`）的欄位放在後面。例如查詢 `WHERE status = 'active' AND created_at > '2024-01-01'`，最佳索引順序是 `(status, created_at)`。因為 B+ 樹先用第一個欄位定位範圍，再用第二個欄位進一步篩選。順序反了，第二個欄位的範圍條件就無法有效利用索引。

### 最佳實踐

1. 只為高頻查詢建索引，不為低頻或一次性查詢建。
2. 優先建複合索引，一個複合索引可以服務多個查詢。
3. 注意複合索引的欄位順序：等值在前，範圍在後。
4. 利用覆蓋索引避免回表查找。
5. 避免過多索引，每多一個就多一份寫入和維護成本。
6. 定期監控索引使用情況，移除長期未使用的索引。
