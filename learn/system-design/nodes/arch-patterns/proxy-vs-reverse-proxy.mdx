# Proxy vs Reverse Proxy 比較

## Learning goal
理解 Forward Proxy 與 Reverse Proxy 的角色差異，以及各自的使用場景

## Lesson

Proxy 和 Reverse Proxy 本質上都是中介——擋在用戶端和伺服器之間轉發請求。差別在於它們代表誰說話。

**Forward Proxy（正向代理）** 代表用戶端向伺服器發出請求。伺服器不知道真正發請求的人是誰，只看到 Proxy 的身份。它的核心價值是隱私保護（隱藏用戶 IP）、存取控制（過濾不當網站）、快取（儲存常用資源）和記錄審計。常見於公司網路、學校防火牆、VPN 等場景。

**Reverse Proxy（反向代理）** 代表伺服器端接收來自客戶端的請求，再轉發給後端伺服器。客戶端完全不知道 Reverse Proxy 的存在。它的核心功能是負載均衡（把請求分散到多台伺服器）、安全防護（隱藏後端 IP、DDoS 防護）、SSL 終止（在 Proxy 層處理 HTTPS 解密，減輕後端 CPU 負擔）和快取。Nginx、HAProxy、Cloudflare 都是常見的 Reverse Proxy 實現。

核心差異在於代理的對象：Forward Proxy 代理用戶端（管理出站請求），Reverse Proxy 代理伺服器端（管理進站請求）。Reverse Proxy 在現代架構中幾乎無處不在，幾乎所有系統設計圖都會畫一個。

面試時一句話區分：Forward Proxy 代表用戶端，Reverse Proxy 代表伺服器端。
