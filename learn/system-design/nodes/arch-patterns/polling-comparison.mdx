# 通訊模式比較：Polling vs LongPolling vs WebSockets vs Webhooks

## Learning goal
比較不同的客户端-服務器通訊模式，理解各自的延遲、資源消耗和適用場景

## Lesson

客户端和伺服器之間的通訊有四種主要模式，核心差異在於：誰主動問、多久問一次、能不能即時收到。

**Polling（輪詢）** 是最簡單的方式：客戶端定期向伺服器發送 HTTP 請求問「有新資料嗎？」，伺服器立即回覆。缺點是即使沒有新資料也要不斷發送請求，資源消耗高。適合更新不頻繁的場景（如天氣查詢）。

**Long-Polling（長輪詢）** 是 Polling 的改良：客戶端發送請求後，如果伺服器沒有新資料就 hold 住連線，有新資料才回覆。減少了無意義的請求，但每次收到資料後要重新建立連線。適合更新較頻繁但不需要完全即時的場景。

**WebSockets** 完全不同：在客戶端和伺服器之間建立一條持久的雙向連線，連線建立後雙方可以隨時互相傳送資料。延遲極低、資源消耗低，適合即時聊天、遊戲、股票行情等場景。

**Webhooks** 是伺服器對伺服器的事件驅動通訊：一個系統定義 URL，當事件發生時另一個系統主動 POST 到這個 URL。不需要輪詢，有事件就通知，適合支付完成、訂單狀態更新等伺服器間事件通知。

面試時被問「該用哪個」，先問清楚是哪種場景：用戶端即時（WebSockets）、伺服器間通知（Webhooks）、還是低頻更新（Polling/Long-Polling）。
