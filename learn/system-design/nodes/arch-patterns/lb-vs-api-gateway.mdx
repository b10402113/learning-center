# Load Balancer vs API Gateway 比較

## Learning goal
理解 Load Balancer 與 API Gateway 的核心差異，以及何時該選擇哪一種架構

## Lesson

Load Balancer（負載均衡器）和 API Gateway（API 閘道）都在管理流量，但關注的層級完全不同。

**Load Balancer** 的核心任務是把進來的網路請求分配到多台後端伺服器，避免任何一台過載。它工作在網路層（L4）或應用層（L7），但不管請求的「語意」——不在乎這個請求是查詢訂單還是新增商品，只管分發。它的三大價值是高可用（high availability）、高效能（performance）和可擴展（scalability）。

**API Gateway** 則是一個 API 管理工具，坐在客戶端和一組後端微服務之間。它不只是分發，還會理解請求的語意，提供路由、身份驗證、限流、API 聚合、協議轉換等功能。例如客戶端要「我的訂單 + 用戶資料」，Gateway 可以同時叫兩個微服務再合併結果回傳。

兩者的核心差異在於：LB 專注於分散流量（不分語意），Gateway 則處理 API 級別的跨領域關注點。兩者不互斥——最常見的架構是把 Load Balancer 放在 API Gateway 前面，LB 分散流量到多個 Gateway 實例，Gateway 處理所有 API 邏輯。

面試時被問「該用哪個」，先確認需求是純流量分散（LB）還是需要 API 管理能力（Gateway），很多時候兩者都要。
