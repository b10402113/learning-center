# API Gateway vs Reverse Proxy 比較

## Learning goal
理解 API Gateway 與傳統 Reverse Proxy 的功能差異，以及在現代微服務架構中的角色分工

## Lesson

API Gateway 繼承了 Reverse Proxy 的所有能力，再加上一層應用層級的功能，是 Reverse Proxy 的超集。

**Reverse Proxy** 的核心能力都在網路層：負載均衡、SSL 終止、安全防護、快取、壓縮。它不理解 API 的語意——不知道這個請求是要查詢訂單還是新增用戶。

**API Gateway** 繼承了上述所有能力，再加上：API 路由（根據路徑導到正確微服務）、身份驗證（統一驗證 JWT/OAuth）、授權控制（按角色限制存取）、限流（按用戶/API 限制頻率）、API 聚合（一次請求合併多個微服務結果）、協議轉換（REST → gRPC）和版本管理（/v1 → v1 服務，/v2 → v2 服務）。

兩者在微服務架構中常常搭配使用：Reverse Proxy 處理網路層防護（SSL 終止、DDoS 防護），API Gateway 處理應用層邏輯（路由、驗證、限流）。有些工具（如 Kong、AWS API Gateway）內建了 Reverse Proxy 能力，一個工具搞定兩件事，但在大規模系統中分開部署更靈活。

面試時的關鍵：Reverse Proxy 是網路層守門人，API Gateway 是應用層管家。兩者互補，不衝突。
