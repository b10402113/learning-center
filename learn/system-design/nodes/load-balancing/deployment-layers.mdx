## Lesson

負載均衡可以部署在系統的不同層級，從外到內最常見的有 DNS 層級、第 4 層（傳輸層）、第 7 層（應用層）、容器/服務層級四種，不同層級有不同的作用，大型生產環境通常會結合多層級使用，發揮每個層級的優點。

DNS 層級最常用於異地多活，把使用者分配到最近的資料中心。當用戶端查詢域名時，DNS 伺服器回傳多個 IP 位址，用戶端從中選一個連線。但 DNS 快取會讓流量分配不夠即時，你沒辦法精確控制每一個請求的分配。

第 4 層（L4）負載均衡工作在 TCP/UDP 傳輸層，只看 IP 位址和連接埠號碼，不解析應用層內容。因為不解析 HTTP 內容，處理速度非常快、開銷很低，適合遊戲伺服器、資料庫叢集、影片串流等大流量低延遲的場景。

第 7 層（L7）負載均衡工作在 HTTP 應用層，可以解析完整的 HTTP 請求，包括 URL 路徑、Header、Cookie 等，據此做更細緻的流量分配。例如基於路徑的路由把 /api/* 導到 API 伺服器、基於 Header 的路由根據 User-Agent 把行動裝置導到行動版伺服器、基於 Cookie 的路由實現會話親和性（Session Affinity）。L7 的代價是處理速度比 L4 慢，所以通常在 L4 之上再加一層 L7。

容器/服務層級處理微服務之間的流量分配，常見實作包括 Kubernetes 內建的 Service 負載均衡、服務網格（Service Mesh）如 Istio 的 sidecar 代理、客戶端負載均衡（Client-Side Load Balancing）如 gRPC 內建的 LB。

實際生產環境通常從外到內一層一層分配流量：DNS 負責跨地域分流，L4 負責快速分流，L7 負責精緻路由，服務層級負責微服務間的流量分配。每層專注於自己最擅長的事，整體系統既高效又靈活。面試中要能解釋為什麼選這個層級以及各層級的取捨。
