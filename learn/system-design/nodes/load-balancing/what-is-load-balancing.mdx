## Lesson

負載均衡（Load Balancing）是分散式系統中負責將進來的用戶請求流量，依據特定規則分配到多個後端伺服器的核心元件。它扮演著餐廳領班的角色：當客人很多時，領班安排每個服務生接待適量的客人，讓整個店的運作維持順暢，不會讓某個服務生工作量過載而其他服務生卻很閒。

在分散式系統中，負載均衡是使用者進入系統的第一個接觸點，它同時承擔了流量分配、後端健康檢查、統一入口這三個核心角色：流量分配把工作分散給多台後端，健康檢查自動排除故障的後端伺服器，統一入口則對外隱藏了內部架構的細節。

沒有負載均衡時，單一伺服器會面臨三個致命問題：效能瓶頸（CPU/記憶體有上限，超過就變慢）、單點故障（掛了整個服務中斷）、無法擴展（想加伺服器卻沒辦法把流量導過去）。負載均衡器一次性解決了這三個問題。

負載均衡器通常部署在用戶端和伺服器叢集之間，是用戶請求的第一個接觸點。在典型的三層架構中，它的位置是：用戶端 → 負載均衡器 → Web 伺服器叢集 → 應用伺服器 → 資料庫。後面的伺服器叢集可以有幾台到幾百台，但對用戶來說它們看起來就像一台——因為負載均衡器統一處理了所有的分配邏輯。

在系統設計面試中，負載均衡幾乎是必考題目。面試官期望你討論四個面向：為什麼需要負載均衡、可以放在哪些系統層級、選擇什麼演算法、以及負載均衡器本身的冗餘設計。
