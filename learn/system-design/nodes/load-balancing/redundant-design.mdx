## Lesson

單一負載均衡本身就是單點故障，一旦故障整個系統就會對外中斷，所以高可用系統必須設計冗餘架構來避免這個問題。常見的冗餘設計有三種：主-備架構簡單容易實現，但資源利用率低；主-主架構資源利用率高，但架構複雜；Anycast 路由適合大型廠商，能自動容錯還能就近服務使用者。

主-備架構（Active-Standby）準備兩台 LB，主 LB 處理所有流量，備 LB 平時待命但持續監控主 LB 健康狀態。一旦主 LB 掛了，備 LB 自動接管。優點是實現簡單、故障轉移邏輯清晰；缺點是備 LB 資源利用率低（50% 硬體在睡覺），故障轉移時可能有短暫中斷。

主-主架構（Active-Active）讓兩台 LB 同時處理流量，各自分擔一半。每台都監控對方健康狀態，一旦某台掛了另一台接管全部流量。優點是資源利用率高、故障轉移更無縫；缺點是需要處理兩台 LB 之間的會話同步（Session Synchronization），否則故障轉移時用戶會被登出，还需要同步路由規則和健康狀態。

Anycast 路由讓多台 LB 宣告同一個 IP 位址，BGP 路由協定自動把用戶端導到網路距離最近的 LB。故障時 BGP 自動重新路由到下一個最近的 LB。優點是自動容錯、就近服務、不需要額外故障偵測機制；缺點是需要大型網路基礎設施，通常只有 Google、Cloudflare 等大型廠商才用得起。

設計冗餘架構時需要注意三個關鍵問題：會話一致性（用戶的 session 資料在多台 LB 之間同步，可透過 Session affinity 或外部 Session Store 如 Redis 解決）、節點健康檢查（LB 之間透過 Heartbeat 心跳機制互相偵測健康狀態）、配置同步（多台 LB 的路由規則必須保持一致，可透過共享配置儲存或自動同步機制實現）。只要做好冗餘設計，負載均衡層就能做到非常高的可用性，不會成為系統的可用性瓶頸。
