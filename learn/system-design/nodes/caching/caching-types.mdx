# 快取的常見類型

## Learning goal
認識不同部署位置與使用場景的快取類型，理解每種類型的適用時機。

## Lesson

快取不是只有一種——它可以部署在系統的不同層級，每種類型適合不同的場景。理解這些類型的差異，才能在系統設計中做出正確的選擇。

**記憶體內快取（In-memory Cache）** 把數據存在主記憶體中，訪問速度極快（微秒級），但容量受限於可用記憶體。適合存放 frequently accessed 的熱數據，例如 API 回應、使用者 session、計算結果。分散式場景常用 Redis 或 Memcached，單機應用常用 Guava Cache 或 lru-cache。

**磁碟快取（Disk Cache）** 把數據存在硬碟或 SSD 上，速度比記憶體慢但比遠端訪問快。適合兩種場景：數據太大放不進記憶體，或是重啟後需要保留的數據。資料庫的查詢結果快取常採用這種方式。

**資料庫快取（Database Cache）** 由資料庫自身管理，自動快取頻繁查詢的結果集。大部分關聯式資料庫（MySQL、PostgreSQL）都內建此機制，應用程式不需額外設定就能受益。

**客戶端快取（Client-side Cache）** 在用戶設備上運作，例如瀏覽器快取圖片、CSS、JavaScript 檔案，或是 App 的本地儲存。減少重複請求，提升二次訪問速度。這是前端效能優化的基礎手段。

**服務端快取（Server-side Cache）** 部署在後端伺服器，儲存預計算結果或熱門對象。常見的形式有全頁快取（整個 HTML 頁面）、片段快取（頁面中的某個區塊）、對象快取（某筆資料的序列化結果）。

**CDN 快取（CDN Cache）** 在全球邊緣節點分散存儲靜態資源，讓用戶從地理位置最近的節點獲取數據，大幅降低延遲。圖片、影片、JS/CSS 檔案是 CDN 快取的典型對象。

**DNS 快取（DNS Cache）** 快取域名解析結果（domain → IP 的對應），省去重複的 DNS 查詢。瀏覽器、作業系統、路由器都有自己的 DNS 快取層。

選擇快取類型的關鍵考量：

| 考量 | 影響 |
| --- | --- |
| 數據大小 | 太大放不進記憶體 → 磁碟快取或 CDN |
| 生命週期 | 需要重啟後保留 → 磁碟快取 |
| 訪問頻率 | 極高頻 → 記憶體快取 |
| 分散式需求 | 多台伺服器共享 → 分散式快取（Redis） |
| 全球分發 | 多地域用戶 → CDN |

在系統設計面試中，Redis 和分散式記憶體快取是最常被討論的快取類型。面試官期望你能解釋為什麼選擇某種快取類型，以及它在整體架構中的位置。
