# 什麼是快取

## Learning goal
理解快取的基本定義、核心術語，以及快取為什麼能提升系統效能。

## Lesson

想像你是一家書店的店員。每天有很多客人來問同一本書在哪裡。如果每次都走到後面的倉庫去找，效率很低。解決方案是：把最常被問到的書放在門口的陳列架上。客人一問，你轉身就能拿到——這就是快取的基本邏輯。

**快取（Cache）** 是位於應用程式與原始數據源之間的一個高速儲存層。原始數據源可能是資料庫、檔案系統，或是遠端的網路服務。當應用程式需要數據時，第一步不是去原始數據源找，而是先查快取：

- **快取命中（Cache Hit）**：數據在快取中找到了，直接返回，速度快。
- **快取未命中（Cache Miss）**：快取中沒有這筆數據，需要去原始數據源取回來，取回後通常會存入快取，下次就能直接命中。

快取之所以能提升效能，核心原理是利用「不同存儲介質的速度差異」。記憶體的訪問速度比硬碟快幾個數量級，硬碟又比跨網路的資料庫查詢快得多。把常用數據存在更快的介質上，就能大幅減少應用對底層緩慢數據源的訪問次數，降低延遲、提升吞吐量，同時減輕底層系統的負載。

除了命中和未命中，還有兩個關鍵術語：

- **快取驅逐（Cache Eviction）**：當快取空間滿了，必須決定移除哪些舊數據來騰出空間。常見的驅逐策略包括 LRU（最近最少使用）和 LFU（最不經常使用）。
- **快取失效（Cache Invalidation）**：當底層數據發生變化，快取中的舊數據就變成「髒數據」，需要讓它失效或更新。這是快取設計中最困難的問題之一，後面會專門討論。

用書店的比喻來說：陳列架滿了，要把最久沒人翻的書放回倉庫（驅逐）；作者出了修訂版，舊版要從陳列架上撤下來（失效）。

這些術語是後續所有快取策略的基礎語言。在系統設計面試中，能正確使用這些術語（Cache Hit、Cache Miss、Eviction、Invalidation）會讓你的回答更精準，面試官也會注意到你對快取有系統性的理解。
