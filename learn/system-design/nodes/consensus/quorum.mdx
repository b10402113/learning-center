# Quorum 共識

## Learning goal
理解 Quorum 機制如何在多副本分散式系統中保證一致性與容錯

## Lesson

### 多副本的煩惱

當你把同一筆資料存在 5 台伺服器上，問題就來了：使用者讀到的資料一定是最新版本嗎？如果其中 2 台伺服器掛了，剩下的 3 台能正常運作嗎？

這就是 Quorum（法定人數）要解決的問題：**在多副本環境中，最少需要多少台伺服器達成共識，才能宣告操作成功？**

### Quorum 的基本規則

Quorum 的核心公式是 **Q = N/2 + 1**（多數派 Quorum），其中 N 是伺服器總數。例如 3 台伺服器需要 2 台達成共識、5 台需要 3 台、7 台需要 4 台。關鍵洞察是：**任何兩個 Quorum 一定有交集**。這意味著如果一個寫操作被 3 台伺服器確認，那麼讀取 3 台伺服器時，至少會讀到 1 台有最新資料的伺服器。

### 讀取與寫入 Quorum

更細緻的設計可以為讀取和寫入分別設定 Quorum：寫入 Quorum (W) 是寫操作需要多少台伺服器確認才算成功，讀取 Quorum (R) 是讀取操作需要從多少台伺服器讀取才算成功。要保證一致性，需要滿足 **W + R > N**。例如 N=5，W=3，R=3，則 3+3=6 > 5，保證讀取一定會包含最新寫入。

三種常見配置：強一致性（W=N, R=1，寫慢讀快）、均衡（W=N/2+1, R=N/2+1，讀寫速度均衡）、寫入優化（W=1, R=N，寫快讀慢）。

### Quorum 的優勢與挑戰

優勢包括：容錯（容忍一定數量的節點故障）、一致性（W + R > N 保證讀取總能得到最新資料）、可用性（只要 Quorum 數量的節點存活，系統就能服務）。挑戰包括：網路分區時可能無法形成 Quorum、每次操作都需要等待多台伺服器回應增加延遲、節點頻繁加入退出時 N 的值需要動態調整。

### 面試中的應用

Quorum 概念出現在幾乎所有分散式儲存系統的設計中：DynamoDB、Cassandra、CouchDB、ZooKeeper、etcd。在面試中，當你談到「多副本的一致性」時，必須提到 Quorum。
