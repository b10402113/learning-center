# 一致性與效能

## Learning goal
理解強/最終一致性、延遲vs吞吐量、ACID vs BASE 這些核心系統設計取捨，能根據不同場景選擇適合的一致性與效能模型。

## Steps

1. **[[learn/system-design/nodes/consistency-perf/tradeoffs-importance|為什麼系統設計需要討論取捨]]** — 認識為什麼取捨是系統設計的核心，以及這在面試中為何重要
2. **[[learn/system-design/nodes/consistency-perf/consistency-models|強一致性 vs 最終一致性]]** — 比較兩種一致性模型的保證與適用場景
3. **[[learn/system-design/nodes/consistency-perf/latency-vs-throughput|延遲 vs 吞吐量]]** — 理解兩個關鍵效能指標的差異與取捨
4. **[[learn/system-design/nodes/consistency-perf/acid-vs-base|ACID vs BASE]]** — 比較兩種資料庫一致性設計哲學

## Lesson

系統設計本質上就是在各種限制條件下做出取捨，沒有放諸四海皆準的「最佳」設計，只有最適合當前需求的選擇。本節點介紹四個最常見的取捨議題，從觀念到具體模型，幫助你在設計時清楚思考每個決策的代價與收益。

所有實際系統都需要在一致性和效能之間找到平衡：強一致性保證正確性但犧牲了延遲和可用性，而放寬一致性可以帶來更好的效能和擴展性，但需要應用程式處理暫時的不一致。理解這些取捨能幫助你根據業務需求做出正確的設計決策。
