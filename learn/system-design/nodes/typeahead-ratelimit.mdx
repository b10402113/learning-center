# Typeahead & Rate Limiter

這個節點包含兩個經典系統設計問題：設計搜尋框的自動完成（Typeahead）建議功能，以及設計一個分散式 API 限流器來保護服務免受濫用。我們會分別從需求分析開始，逐步深入核心演算法與擴展架構。

## Learning goal
能夠從零開始設計一個低延遲的 Typeahead 搜尋建議系統，以及一個可擴展的分散式 API 限流器，理解每個設計選擇的取捨。

## Lesson

Typeahead 搜尋建議是互動搜尋體驗的核心元件，要求使用者輸入每個字元後數百毫秒內返回熱門搜尋建議。解決這個問題的關鍵是使用 Trie 字典樹來有效儲存和查詢前綴匹配，再透過資料分片、多層快取和客戶端最佳化來達到低延遲要求。

API 限流是保護服務穩定性的基礎機制，用於防止濫用和控制成本。不同的限流演算法（固定窗口、滑動窗口、令牌桶、漏桶）有不同的取捨，在分散式環境下需要考慮跨節點同步、資料分片和一致性議題。

兩個問題都體現了系統設計中「需求分析 → 核心演算法 → 分佈式擴展 → 優化」的標準思考流程。
