# 網路爬蟲基礎與需求分析

## Learning goal
理解網路爬蟲的作用、核心需求與設計考量，掌握容量估算方法

## Lesson

### 什麼是網路爬蟲

網路爬蟲（Web Crawler）是一個自動化程式，以系統化的方式瀏覽萬維網，透過遞迴跟隨連結來收集文件。搜尋引擎靠爬蟲下載網頁建立索引，才能提供快速搜尋。除了搜尋引擎，爬蟲還用於資料採集（價格、評論）、網站監控（偵測竄改）和學術研究（分析網路結構）。

### 核心需求

大規模爬蟲需要四大能力：可擴展性（能橫向擴展 worker 爬取數百億網頁）、可擴充性（模組化設計處理多種文件類型）、健壯性（面對惡意網頁和異常格式仍能運作）、效率（在有限頻寬和儲存下最大化爬取量）。

### 設計考量

動手設計前必須先釐清：爬什麼（只爬 HTML 還是包含圖片影片？）、怎麼爬（BFS 廣度優先逐層擴散最常用，DFS 適合單站內部爬取以減少握手開銷，路徑上升爬取能發現孤立資源）、爬行策略（網頁數量龐大需要排定優先順序，網頁不斷變化需要決定何時重新爬取）。

### 容量估算

假設 4 週內爬取 150 億個網頁：爬取速率 150 億 ÷ (4 × 7 × 86400) ≈ 6,200 頁/秒，需要數百台伺服器分散處理。儲存方面，假設平均 100KB/頁加 500 bytes metadata，總共約 1.5 PB。頻寬需求約 5 Gbps，分散到 100 台伺服器每台約 50 Mbps，在合理範圍內。

### 與搜尋的關係

網路爬蟲是搜尋引擎的上游——收集原始網頁資料，後續的索引建立和搜尋查詢都建立在爬蟲收集的資料之上。Twitter Search 是對使用者產生內容的搜尋，Web Crawler 是對公開網路內容的收集。
