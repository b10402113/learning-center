# 網路爬蟲架構設計

## Learning goal
掌握大規模網路爬蟲的高層次架構與細部元件設計

## Lesson

### 基本演算法

任何爬蟲的核心迴圈是：從未訪問 URL 佇列取一個 URL → DNS 解析取得 IP → 建立連線下載網頁 → 解析 HTML 提取新 URL → 將新 URL 加入佇列 → 處理已下載文件。看起來簡單，但分散到數百台機器、爬取數百億網頁時，每個步驟都變成獨立的系統設計挑戰。

### URL Frontier

URL Frontier 是整個爬蟲的排程中心，不是簡單的 FIFO 佇列而是優先佇列。它分兩層：Priority Queues 根據 URL 來源和網頁變化頻率決定優先級，Politeness Queues 確保對同一主機的請求保持間隔避免類似 DDoS 的壓力。多台機器共享 Frontier 時用一致性雜湊分配 URL。

### 核心元件

DNS Resolver 負責域名解析，在大規模場景下是主要瓶頸——DNS 查詢本身有延遲且量大，解決方案包括本地快取和預解析。網頁下載器使用非同步 I/O 同時處理數千個連線，需遵循 robots.txt、處理 HTTP 錯誤和合理逾時。HTML Parser 與 URL Extractor 提取超連結和 metadata，並做 URL 正規化（相對轉絕對、去 fragment、統一大小寫）。URL Filter 過濾不支援的協議、已封鎖域名和已爬過的 URL。

### 分散式架構

使用一致性雜湊以 hostname 為 key 分配 URL，確保同一網站分到同一台機器以實現 politeness。已爬 URL 狀態用分散式 KV 儲存（如 DynamoDB）記錄 checksum 避免重複。機器故障時一致性雜湊自動重新分配，佇列定期 checkpoint 到磁碟以便恢復。
