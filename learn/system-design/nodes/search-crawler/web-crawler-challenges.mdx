# 網路爬蟲關鍵挑戰與解決方案

## Learning goal
理解大規模爬蟲面臨的主要挑戰，包括重複移除、爬蟲陷阱、容錯與資料分區，並掌握對應解決方案

## Lesson

### URL 去重

同一個網頁可能從不同連結被發現多次，不去重會浪費大量資源。大規模爬蟲用雙重 checksum 策略：URL Checksum（對 URL 做 hash）判斷「這個 URL 有沒有爬過」，文件 Checksum（對內容做 hash）判斷「頁面內容有沒有變」。兩者缺一不可——URL 不變但內容可能變（網頁更新），URL 變了但內容可能不變（不同 URL 指向同一頁面）。150 億個 URL 的 checksum 約 480 GB，在分散式儲存中完全可行。

Bloom Filter 是更高效的去重方案：空間效率遠優於 Hash Set（150 億個 URL 只需約 18 GB），可能誤報但不會漏報——偶爾多爬一次沒關係，但絕不能漏爬。

### 爬蟲陷阱

爬蟲陷阱是讓爬蟲無限迴圈的 URL 集合。無意的陷阱如符號連結迴圈或遞迴參數的動態 URL，有意的陷阱如垃圾網站故意生成無限頁面。解決方案包括設定最大爬取深度和頁數上限、URL 正規化（移除重複參數、統一排序）、偵測 URL 中的遞迴模式、對單個域名設定整體爬取時間上限。

### 容錯處理

Checkpoint 機制讓每台機器定期將 FIFO 佇列狀態存到磁碟，故障後從最近 checkpoint 恢復而非從頭開始。一致性雜湊（Consistent Hashing）在機器故障時自動將 key 範圍重新分配到其他機器，無需中央協調。若索引伺服器故障且無副本，需回放寫入日誌重建索引——這就是原始資料不能丟的原因。

### 資料分區

爬蟲處理三種資料：待爬 URL 佇列、URL checksum（去重用）、文件 checksum（內容去重用）。關鍵洞察：因為按 hostname 做一致性雜湊分配，三種資料可以存放在同一台機器上。好處是 URL 去重查詢不需要跨機器通訊、politeness 策略在單機上實現、checkpoint 和恢復邏輯更簡單。
