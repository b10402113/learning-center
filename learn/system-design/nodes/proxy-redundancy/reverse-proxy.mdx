## Lesson

反向代理（Reverse Proxy）是正向代理的鏡像。正向代理站在用戶端這邊，代表用戶端發請求；反向代理站在伺服器這邊，代表伺服器接收請求。兩者的核心差異一句話說完：正向代理隱藏用戶端的身份，反向代理隱藏伺服器的身份。

反向代理對用戶端完全透明。用戶端以為自己在跟「一台伺服器」溝通，但其實反向代理背後可能有好幾台伺服器。所有請求都先到反向代理，由它決定轉發給哪台後端。用戶端只需要知道反向代理的 IP 或域名，後面有幾台伺服器、每台跑什麼，完全不需要知道。

反向代理的功能比正向代理更貼近伺服器端的需求。最核心的幾個：負載均衡（把請求分配到多台後端，避免單一伺服器過載）、SSL 終止（在代理層處理 HTTPS 加解密，後端只需處理明文，減輕加密負擔並統一管理憑證）、快取靜態資源（圖片、CSS、JS 存在代理層，減少後端壓力）、壓縮回應內容（減少傳輸量）、以及隱藏後端架構（攻擊者無法直接瞄準後端伺服器的 IP）。

在面試中，反向代理幾乎是必提的概念。你需要能一句話區分正向和反向代理、說出至少三個功能、理解它的透明性，並知道常見的實作工具（Nginx、HAProxy 等）。反向代理是系統架構的「前門」，擋在後端伺服器前面，既做交通指揮又做安全閘門。但這個「前門」本身也可能成為單點故障——下一課會介紹冗餘與複製，讓這個前門不會一倒就全倒。
