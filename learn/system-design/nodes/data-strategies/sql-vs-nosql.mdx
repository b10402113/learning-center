## Lesson

SQL 和 NoSQL 是兩種根本不同的資料庫組織方式。SQL 資料庫像一個大型收納櫃——每個抽屜有固定的標籤和格子，你必須在買櫃子之前就決定每個格子放什麼。NoSQL 資料庫像一組透明收納箱——裡面的東西隨便放，今天放衣服明天放書，格式由你決定。

**SQL（Structured Query Language）資料庫** 是關聯式資料庫，資料存在結構化的表格中，表格之間透過關聯連接。核心優勢是 ACID 事務（Atomicity 原子性、Consistency 一致性、Isolation 隔離性、Durability 持久性）——保證事務的可靠性和一致性。你用過的 Postgres 和 MySQL 就是 SQL 資料庫。例如電商系統定義 Users 表、Orders 表、Products 表，用外鍵關聯，查「某個用戶的所有訂單及商品明細」一個 SQL JOIN 就搞定。SQL 的擴展方式是垂直擴展（升級單台機器的硬體），Schema 變更需要遷移，成本較高。

**NoSQL（Not Only SQL）資料庫** 是非關聯式資料庫，支援四種資料模型：文件模型（MongoDB，適合內容管理）、鍵值模型（Redis，適合快取）、寬列模型（Cassandra，適合時間序列和日誌）、圖模型（Neo4j，適合社交網路）。核心優勢是彈性 Schema（不同文件可有不同欄位，變更成本低）和水平擴展（加更多機器而非升級單台）。代價通常是最終一致性——不保證即時同步，但能提供更高的可用性和吞吐量。

選擇時問三個問題：資料結構是否明確且穩定？你需要強一致性嗎？你的資料量和擴展需求如何？結構清晰、需要強一致性、中等規模選 SQL；結構多變、能容忍短暫不一致、超大規模選 NoSQL。很多生產系統混合使用——SQL 處理事務（訂單、支付），NoSQL 處理非結構化資料（用戶行為、快取）。面試中要能根據三個維度做出選擇，並說明為什麼混合使用是常見的設計決策。
