<LearningGoal>
比較資料壓縮與重複數據刪除的差異，理解兩種技術各自適用的場景與優缺點。
</LearningGoal>

## Lesson

壓縮和去重是兩種減少儲存空間的技術，但它們解決的問題完全不同。壓縮關注的是「單一檔案內部有什麼冗餘可以消除」，去重關注的是「跨多份資料之間有什麼重複可以消除」。理解這個根本區別，就能判斷什麼場景該用哪種。

**資料壓縮（Data Compression）** 用更少的位元表示同樣的資訊，核心是找出資料中的冗餘模式並重新編碼。壓縮分兩種：無損壓縮（Lossless）可以完全還原原始資料，例如 ZIP、Gzip、Brotli，適合文字、程式碼、資料庫備份等不能丟失任何資訊的場景。有損壓縮（Lossy）會丟棄人眼/人耳不易察覺的資訊來換取更高的壓縮比，例如 JPEG、MP3、H.264，適合圖片、音訊、影片。壓縮的作用範圍是單一檔案或資料流，計算開銷在壓縮和解壓縮時即時發生。你在 REST API 中用 Gzip 壓縮 response body，就是無損壓縮的典型應用——文字的壓縮比很高，壓縮後體積大幅縮小，解壓縮後和原始資料完全一樣。

**資料去重（Data Deduplication）** 找出系統中重複的資料區塊，只保留一份，其他用指標替代。系統先把資料切成固定大小的區塊（chunk），為每個區塊計算 hash 指紋，如果兩個區塊的 hash 相同就只保留一份。去重的作用範圍是整個儲存系統，特別適合備份系統——例如你有 52 個週備份，每週只有不到 1% 的資料變化，去重後實際儲存空間可能只需要 15-20 GB 而非 520 GB。Git 的 packfile 也是一種去重機制。

兩者互補：壓縮減少單一檔案大小、加速傳輸；去重消除跨檔案重複、優化大規模儲存空間。很多系統會並用——先壓縮每個檔案，再去重跨檔案的重複區塊，這在備份和災難恢復系統中很常見。面試中要能區分兩者的作用範圍和適用場景，並解釋為什麼它們常常一起使用。
