## Lesson

上一課介紹了水平分片、垂直分片和混合分片三種分片方法。但「怎麼切」只是第一步，接下來要回答一個更關鍵的問題：**依照什麼規則把資料分配到不同分片？**這就是分片標準（Partitioning Criteria）。

你可以把分片標準想像成圖書館的分類規則：你可以按書名的字母順序排（雜湊分片），按出版年份排（範圍分片），按語言分類排（列表分片），或者一本一本輪流放（輪詢分片）。不同的分類規則對資料分布、擴展難易度、查詢性能都有很大影響。選錯標準，可能導致某些書架爆滿而其他書架空蕩蕩（hotspot），查詢效率反而下降。選對標準，資料均勻分布，系統自然高效。

**雜湊分片（Hash-based Partitioning）** 是最常用的分片標準之一。它的原理很簡單：對分片鍵（例如使用者 ID）計算一個雜湊值，然後對分片數量取模，得到的結果就是資料應該去的分片編號。

舉個具體的例子：假設你有 4 個分片，使用者 ID 為 12345。計算 `hash(12345) % 4 = 2`，所以這筆資料存到分片 2。因為雜湊函數的特性，不同 ID 會被均勻地分配到各分片，不容易出現某些分片特別多、某些特別少的情況。這就是雜湊分片最大的優點：**資料均勻分布**。在你不知道查詢模式，或者查詢模式很分散的情況下，雜湊分片是最安全的選擇。

但雜湊分片有一個嚴重的限制：**擴展困難**。如果你把分片數從 4 增加到 5，大部分資料的 `hash % 5` 結果都會改變，意味著需要重新搬移大量資料。在實務中，這可能導致長時間的停機。想像一下：你有 1000 萬筆使用者資料，分在 4 個分片裡。現在要擴展到 5 個分片，幾乎所有使用者的 `hash % 5` 結果都跟 `hash % 4` 不同，你需要把大部分資料從舊分片搬到新分片。這個過程可能需要幾小時甚至幾天，期間系統的性能會嚴重下降。更糟糕的是，搬移過程中你還需要確保資料一致性——如果使用者在搬移過程中修改了資料，你需要確保修改不會丟失。如果系統需要頻繁擴展，可以改用**一致性雜湊**（Consistent Hashing）來改善這個問題——它在新增或移除分片時，只需要搬移少量相鄰分片的資料，而不是全部重新分配。一致性雜湊的原理是把分片鍵空間組織成一個環，每個分片負責環上的一段區間，新增或移除分片時只需要調整相鄰的區間。

雜湊分片還有一個常見的問題：**不支持範圍查詢**。因為資料的分片位置是由雜湊值決定的，而不是由分片鍵的自然順序決定的。例如，你無法輕易地「查詢 ID 1000 到 2000 的所有使用者」，因為這些 ID 可能被雜湊分散到所有分片上。如果你的應用需要頻繁的範圍查詢，雜湊分片可能不是最佳選擇。在實務中，你經常會看到系統同時使用兩種分片標準：用雜湊分片做主分片（均勻分布），同時建立一個額外的索引或快取來支持範圍查詢。這就是複合分片的思路——用不同的分片標準服務不同的查詢模式。

**範圍分片（Range-based Partitioning）** 依照分片鍵的連續範圍來切分。例如，ID 1~10000 放分片 A，ID 10001~20000 放分片 B，以此類推。這種方式特別適合像時間戳、連續 ID 這種有自然順序的鍵。

範圍分片的優點是**擴展容易**：新增範圍只需要加新分片，不需要搬移舊資料。例如，你原本有 4 個分片，每個分片負責 250 萬筆資料。現在新增第 5 個分片，只需要把第 4 個分片的後半段資料搬過去，其他分片完全不受影響。而且範圍查詢（例如「查詢 2024 年 1 月的所有訂單」）非常高效，因為相關資料都在同一個分片，不需要跨分片掃描。

但範圍分片容易出現**熱分片**（hotspot）問題。例如按照時間分片，最新的分片會不斷接收新資料的讀寫，而舊分片幾乎沒有流量。這會導致單一節點過載，其他節點閒置。在社群平台中，如果按使用者 ID 範圍分片，新註冊的使用者都在同一個分片上，這個分片的寫入負載會遠高於其他分片。熱分片問題是範圍分片最大的挑戰，需要透過合理的分片鍵設計或結合其他技術（如快取）來緩解。

**列表分片（List-based Partitioning）** 類似範圍分片，但用離散的值來劃分，每個分片分配一組值。例如，你可以按地理區域分片：台灣的資料放分片 A，日本的資料放分片 B，美國的資料放分片 C。

列表分片的優點是**按業務分類靈活度很高**。如果查詢也常常按照這個分類（例如「查詢所有台灣使用者」），性能會很好，因為相關資料都在同一個分片。而且你可以根據業務需求自定義分類規則，不需要受限於連續範圍或雜湊值。例如，你可以按語言分片（中文、英文、日文），按業務線分片（電商、社群、金融），或者按資料等級分片（VIP 使用者、一般使用者）。

但列表分片的缺點是你需要**預先知道所有值**，新增值需要修改分片規則。例如，如果你按地理區域分片，現在要新增「韓國」，你需要修改分片配置，把韓國的資料從原來的分片搬到新分片。而且如果不同列表的資料量差異大（例如台灣資料 100 萬筆，美國資料 10 萬筆），容易分布不均。在這種情況下，你可能需要對資料量大的列表再做一次水平分片。

**輪詢分片（Round-robin Partitioning）** 是最簡單的：按順序一筆筆輪流分配到分片。第一筆放分片 A，第二筆放分片 B，第三筆放分片 C，第四筆放分片 D，第五筆又回到分片 A。因為是輪流分配，一定能均勻分布。

但輪詢分片的致命缺點是**查詢特定資料很難找到分片**。你不知道某筆資料在哪個分片，必須掃描所有分片才能找到。例如，你想查詢使用者 ID 為 12345 的資料，你不知道它在分片 A 還是分片 B，只能兩個都查一遍。這在實務中幾乎是不可接受的，因為查詢性能會隨著分片數量線性下降。實務上幾乎不會使用這種方法，但在某些場景下（例如日誌儲存，寫入為主、查詢很少），輪詢分片可以用來確保寫入均勻分布。

在實務中，**複合分片**（Composite Partitioning）會結合多種標準。例如先按地理區域做列表分片，再對每個區域做雜湊分片。這種方式能取各自的優點：列表分片讓同一區域的資料在同一個分片（優化區域查詢），雜湊分片確保區域內的資料均勻分布（避免熱分片）。但架構複雜度也更高，需要管理多層分片邏輯。

選擇哪種分片標準，取決於你的查詢模式。如果你的查詢主要是精確查詢（查單筆資料），雜湊分片是最佳選擇。如果你的查詢主要是範圍查詢（查一段時間或一個區間的資料），範圍分片更合適。如果你的查詢有明顯的業務分類（按地區、語言、業務線），列表分片最靈活。在面試中，能根據具體的查詢模式來選擇分片標準，而不是死記硬背某種方法，才是得分關鍵。

值得注意的是，分片標準的選擇不是一成不變的。隨著業務成長，你的查詢模式可能會改變。例如，早期你的使用者量不大，雜湊分片足以應付。但當使用者量成長到數千萬，你可能需要範圍分片來支持按時間查詢。或者早期你的業務只在台灣，列表分片按地區分就夠了。但當業務拓展到多個國家，你可能需要結合雜湊分片來避免某個地區的分片過載。所以分片標準的選擇是一個動態的過程，需要根據業務的發展不斷調整。
