# 進階擴展與優化
## Learning goal
學習如何對短網址與 Pastebin 服務進行資料分片、複製、快取與清理，以應對不斷增長的流量與儲存需求。
## Lesson

基礎架構搞定之後，系統已經能用了。但面試中考的不只是「能不能用」，而是「能不能應付大流量」。這一步會討論資料分片、複製、快取、負載均衡和清理機制——這些都是從「能用」到「能撐住百萬級 QPS」的關鍵技術。

## 資料分片（Partitioning）

當單台資料庫無法承受所有資料時，就需要把資料分散到多台機器上。常見的分片策略有兩種：

**按金鑰範圍分片（Range-Based Partitioning）：** 把金鑰按字母順序分成若干範圍，每個範圍存到不同的資料庫節點。例如 A-F 的金鑰在節點 1，G-M 在節點 2，以此類推。優點是範圍查詢效率高；缺點是某些範圍可能特別熱（熱點問題），導致負載不均。

**按金鑰雜湊分片（Hash-Based Partitioning）：** 對金鑰做雜湊運算，根據雜湊值分配到不同節點。優點是分佈均勻，避免熱點；缺點是範圍查詢變得困難。對於短網址這種「只根據單一金鑰查詢」的場景，雜湊分片更合適。

Pastebin 的資料分片則更複雜一些。元資料可以用雜湊分片，但大內容（存在 S3 中）則由物件儲存自己管理分片，不需要你操心。

## 資料複製（Replication）

為了提高可用性和讀效能，資料通常會複製到多個節點。

**主從複製（Primary-Replica）：** 一台主節點負責寫入，多台從節點負責讀取。主節點把寫入操作同步或非同步地複製到從節點。優點是讀寫分離，讀取效能大幅提升；缺點是主節點掛了需要切換，有一定風險。

**多主複製（Multi-Primary）：** 多台主節點都能寫入，互相複製。適合地理分散的場景，但引入了衝突解決的複雜性。

對於短網址和 Pastebin 這種讀多寫少的場景，主從複製是最佳選擇。讀取請求量遠大於寫入，把讀取分散到多台從節點，可以大幅降低單台資料庫的壓力。

## 快取（Caching）

快取是提升讀取效能的殺手鐧。根據 80/20 法則，80% 的請求可能集中在 20% 的資料上。把這些熱門資料放進記憶體快取（如 Redis 或 Memcached），可以讓大部分請求不經過資料庫。

**快取策略：**

- **Write-Through：** 寫入時同時寫快取和資料庫，保證一致性，但寫入延遲增加
- **Write-Behind：** 先寫快取，再非同步寫資料庫，寫入快但有一致性風險
- **Read-Through：** 查詢時先查快取，miss 再查資料庫並回填快取
- **Cache-Aside：** 應用程式自己管理快取邏輯，最靈活但也最複雜

短網址的快取策略：新產生的短網址不一定馬上被大量存取，可以先不進快取；一旦某個短網址的存取量超過閾值（如 1000 次/小時），就放進快取。這叫「快取預熱」或「hot key detection」。

Pastebin 的快取更有價值：一篇熱門 paste 的讀取量可能很大，且內容不變，非常適合快取。可以同時快取元資料和內容本身。

## 負載均衡（Load Balancer）

負載均衡器把流量均勻分發到多台伺服器。常見的分配策略包括：

- **輪詢（Round Robin）：** 依序分配給每台伺服器，簡單但不考慮伺服器負載差異
- **最少連接（Least Connections）：** 分配給當前連接數最少的伺服器，更公平
- **IP 位址散列（IP Hash）：** 根據客戶端 IP 做雜湊，確保同一客戶端 always 打到同一台伺服器（有狀態場景）

短網址的讀取是完全無狀態的，輪詢就夠了。如果要做 IP Hash 以支援某些有狀態的功能（如 session），也可以考慮。

## 資料清理（DB Cleanup）

過期的資料不能一直佔著儲存空間。兩種清理策略：

**主動清理（Active Cleanup）：** 部署背景工作（Background Worker），定期掃描資料庫，刪除過期記錄。例如每小時掃描一次，刪除 `expireAt` 已過期的 paste。優點是及時釋放空間；缺點是掃描操作本身會消耗資源。

**被動清理（Lazy Cleanup）：** 在讀取時檢查是否過期，過期就回傳 404 並刪除。優點是不需要額外的掃描資源；缺點是過期資料可能在資料庫中残留很久，浪費儲存。

最佳實踐是兩者結合：用被動清理作為第一道防線（使用者存取到過期資料時立即刪除），同時用主動清理定期掃描，處理那些從來沒人存取的過期資料。

## 速率限制（Rate Limiting）

防止濫用的最後一道防線。常見策略包括令牌桶（Token Bucket）和漏桶（Leaky Bucket）。令牌桶允許突發流量（桶內有令牌就能發），漏桶則嚴格限制速率。對於短網址，可以限制單個 IP 或 API Key 每分鐘的建立次數，防止惡意大量建立短網址。
