# 共識與容錯

## Learning goal
掌握分散式系統中達成共識與容錯的核心機制：從基礎的 CAP 理論出發，理解不同 trade-off 模型，然後學習實務上常用的一致性雜湊、Quorum 以及 Leader-Follower 選舉模式。

## Steps

這個節點分解為以下步驟，依序閱讀：

1. **[[learn/system-design/nodes/consensus/cap-theorem|CAP 定理]]** — 理解分散式系統不可能同時滿足一致性、可用性、分區容錯，學會辨識三個屬性的意義與取捨
2. **[[learn/system-design/nodes/consensus/pacelc-theorem|PACELC 定理]]** — 擴展 CAP 定理，理解在沒有分區時系統仍然需要面對延遲與一致性的取捨，認識不同資料庫的設計選擇
3. **[[learn/system-design/nodes/consensus/consistent-hashing|一致性雜湊]]** — 學習如何有效率地在動態節點環境中分佈資料，最小化增減節點時的資料移動
4. **[[learn/system-design/nodes/consensus/quorum|Quorum 共識]]** — 理解 Quorum 機制如何在多副本環境中平衡一致性、可用性與容錯
5. **[[learn/system-design/nodes/consensus/leader-follower|Leader-Follower 選舉模式]]** — 學習透過單一領導者簡化副本協調，以及故障轉移的處理方式

## Lesson
共識與容錯是分散式系統設計的核心挑戰。當系統擴展到多個節點，網路分區與節點故障是不可避免的，系統必須設計機制來保證所有節點最終能對資料狀態達成一致，同時維持足夠的可用性。

本節點從理論基礎開始，先認識 CAP 定理告訴我們的根本限制，再延伸到 PACELC 定理對現代分散式系統的更精細描述。接著學習實務上常用的幾個共識與容錯機制：一致性雜湊解決了資料分佈的問題，Quorum 解決了多副本一致性問題，Leader-Follower 則是常見的協調模式。這些概念是進一步學習分散式資料庫、共識演算法（如 Paxos/Raft）的基礎。
