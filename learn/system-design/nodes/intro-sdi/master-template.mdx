# 常見系統組件全覽

## Learning goal

認識 DNS、Load Balancer、API Gateway、CDN、Proxy、Cache、Partitioning、Replication、Messaging、Microservices、NoSQL、Index、Distributed FS、Notification 等常見組件，在步驟 5-6 中能靈活選用。

## Lesson

系統設計面試步驟 5-6 要你畫架構圖、選組件。你需要認識這些「積木」才能組合出方案。這一步是工具箱——不需要精通每一個，但要在被問到時能說出用途、優缺點和適用場景。

網路層包括 DNS（域名翻譯，所有流量的起點）、Load Balancer（流量分配到多台伺服器，是從單機走向分散式的分水嶺）、API Gateway（微服務的前門）。API Gateway 是所有外部請求的第一站，具備七大功能：路由（根據 URL 分發到不同服務）、認證（統一驗 token，下游不用各自驗）、限流（防止某用戶被打爆）、熔斷（下遊服務掛了快速失敗不卡住）、快取（熱門請求直接返回）、轉碼（外部 HTTPS 轉內部 gRPC）、日誌監控（統一記錄所有請求）。跟 LB 的區別在於：LB 只管流量分到哪台機器（網路層），Gateway 還管業務邏輯（應用層）。典型產品是 Kong、AWS API Gateway、Nginx。快取與分發包括 CDN（靜態資源緩存到全球邊緣節點，適合讀多寫少的場景）和 Cache（Redis/Memcached，關鍵問題是失效策略和穿透/雪崩/擊穿）。資料層包括 Data Partitioning（水平分片提升寫入效能但跨分片查詢變複雜）、Database Replication（一主多從提升可用性和讀取效能，取捨是一致性）、NoSQL（四大類型對應不同查詢模式）、Database Index（B-tree 適合範圍查詢，Hash 適合等值查詢）。通訊與架構包括分散式訊息系統（解耦服務通訊）、Microservices（獨立部署但引入分散式複雜性）、Notification System（用佇列解耦發送）。Proxy 用寄信比喻最好懂。Forward Proxy（正向代理）= 朋友幫你代寄信：你寫了一封信，不想讓對方知道是誰寄的，就請朋友幫你寄出去，對方看到的寄件人是你朋友。典型 App：翻牆用的 VPN（ExpressVPN、Clash）——政府封了某個網站，透過境外 Proxy 繞過去；公司內網閘道器——公司不讓員工直接上外網，所有流量先過公司 Proxy 審查；爬蟲的 Proxy Pool——大量抓資料怕被封 IP，輪流用不同 Proxy 出去；Tor Browser——想完全匿名上網，流量經過多層 Proxy 層層加密。Reverse Proxy（反向代理）= 公司前台收信：你寄信到「台積電」，信先到公司前台，前台看了信封決定轉給哪個部門——技術問題轉研發部，人事問題轉人資部。前台還做限流（同時來 500 封信請排隊）、快取（上次問過的問題答案直接給）、擋災（某部門放假先把信收著）。典型 App：電商平台（Shopify、淘寶）——Nginx 幫忙分流量到 50 台伺服器；API 後端——前端只打一個網址，Nginx 轉發到微服務 A/B/C；影片平台（Netflix、YouTube）——影片封裝從 CDN（一種 Reverse Proxy）出，不打到應用伺服器；防 DDoS（Cloudflare）——攻擊先到 Cloudflare，過濾惡意流量再放行。關鍵詞：Forward Proxy 你要藏身、繞限制、換身份的時候用；Reverse Proxy 你的伺服器要擋流量、分發、保護後面東西的時候用。

工具箱思維：面試時不要想「我要用 Redis」，而要想「這裡需要快取層，Redis 是好選擇，但 Memcached 也可以，取捨是……」。先想需求，再選工具。
