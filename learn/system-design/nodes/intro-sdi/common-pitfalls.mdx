# 避開面試中的 7 大陷阱

## Learning goal

識別並避開系統設計面試中的 7 大常見陷阱：忽略需求、太早深入細節、固守單一想法、忽略取捨、忽略非功能需求、溝通不足、過度自信。

## Lesson

知道「該做什麼」不夠——大多數人掛在面試，不是因為不知道答案，而是踩了坑。提前避開這些坑比多學一個技術組件更有價值。

七個常見陷阱。第一，忽略需求：拿到題目直接畫圖不問清楚，結果設計了支援一億用戶的系統但面試官只想討論一萬用戶的場景。避開方式是花前 3-5 分鐘認真問功能性需求、非功能性需求和規模預估。第二，太早深入細節：一開始就討論 PostgreSQL 還是 MySQL，卻沒先畫高階架構。堅持 7 步驟順序，步驟 5 之前不深入任何組件的內部實現。第三，固守單一想法：面試官暗示方案有問題但你堅持不改，展示的是固執不是自信。把面試官當 teammate，他給反饋是想幫你。第四，忽略取捨：只說「我選 Redis」但不解釋為什麼不選 Memcached。每個決策都加上「我選 X 是因為 Y，代價是 Z」。第五，忽略非功能需求：設計了功能完整但沒有考慮可用性、擴展性、容錯性的系統。在步驟 7 系統性地檢查單點故障、資料備份、擴展瓶頸。第六，溝通不足：默默畫圖五分鐘不解釋，或單向輸出不問面試官意見。每畫一個方塊就解釋作用，每做一個決策就問面試官「這個方向 OK 嗎？」。第七，過度自信：對所有問題都斬釘截鐵即使不確定。坦承不確定是加分的，可以說「這部分我不確定，但直覺是 X，因為 Y」。

把這 7 個陷阱當成面試後的 checklist，每次模擬面試後回頭逐項檢視。
