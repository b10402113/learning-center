# 為什麼系統設計需要討論取捨

## Learning goal

理解在系統設計中討論取捨（Tradeoffs）的重要性，以及為什麼這是面試中關鍵的考察點。

## Lesson

系統設計本質上就是在各種限制條件下做出取捨。沒有一個方案能同時最大化所有指標——你想要更快的延遲，就得接受更高的成本；你想要更高的可用性，就得容忍暫時的不一致。每一個技術決策都是在多個好處之間做選擇，而你的工作就是根據業務需求判斷哪個好處最重要。

在面試中，討論取捨不只是展示你知道有哪些選項，更重要的是展現你的決策能力。面試官想看到的不是一個「正確答案」，而是你的思考過程：你列出了哪些可行方案？每個方案的代價是什麼？你為什麼根據當前需求選擇了這個方案？能清楚表達「我選 A 而不是 B，因為……」的候選人，比只給出一個答案的候選人更能展現工程深度。

能討論取捨也代表你有真實的工程經驗。現實世界中幾乎不存在完美方案——預算有限、時間緊迫、團隊技術棧固定，每個決策都要在這些限制下做權衡。能在面試中提到這些非技術因素（營運成本、開發效率、維護複雜度），會讓面試官覺得你有全局觀而不只是會寫程式碼。

一個實用的面試框架是「先列選項，再說取捨，最後做選擇」。先列出至少兩個可行方案展現知識面，然後每個方案說清楚它的代價，最後根據面試中給出的具體業務需求做選擇。這個順序展現了完整的分析過程，比直接給出結論更有說服力。

本節點接下來會深入探討三個最核心的取捨議題：一致性模型（強一致性 vs 最終一致性）、效能指標（延遲 vs 吞吐量）、以及資料庫設計哲學（ACID vs BASE）。掌握這些取捨，你就能在任何系統設計題中展現出深度和判斷力。
