# Newsfeed & Yelp/Uber

本節點結合三個經典系統設計題目：Facebook 動態消息、Yelp 鄰近地點搜尋與 Uber 叫車後端設計，涵蓋動態內容推送、地理位置搜尋與即時位置更新三種核心場景。

## Learning goal
能夠獨立設計可擴展的動態消息推送系統與地理位置服務，比較不同場景下的設計取捨，並結合之前學到的分片、快取、容錯等技術來優化系統。

## Steps

以下是本節點的學習步驟，依序閱讀：

1. **[[learn/system-design/nodes/newsfeed-yelp/requirements-capacity|需求分析與容量估算]]** — 釐清三個系統的功能與非功能需求，學習如何針對不同場景進行容量估算
2. **[[learn/system-design/nodes/newsfeed-yelp/newsfeed-architecture|Facebook Newsfeed 架構設計]]** — 深入探討動態消息的推播/拉播架構、生成、排名與分片設計
3. **[[learn/system-design/nodes/newsfeed-yelp/proximity-search-design|Yelp 鄰近搜尋設計]]** — 學習地理位置搜尋的核心演算法，包括網格分割與 QuadTree
4. **[[learn/system-design/nodes/newsfeed-yelp/uber-realtime|Uber 即時位置與配對設計]]** — 調整靜態鄰近搜尋來支援頻繁位置更新與即時配對
5. **[[learn/system-design/nodes/newsfeed-yelp/reliability-optimization|快取、複製與容錯設計]]** — 整合快取、複製與容錯策略，確保系統高可用性

## Lesson

本節點整合三個真實世界的系統設計案例，分別處理三種不同挑戰：
- **高讀取吞吐量的動態聚合**：Facebook Newsfeed 需要從數百個來源聚合最新內容，並快速遞送給數億用戶，關鍵挑戰在於平衡讀取延遲與寫入開銷，以及如何排名重要內容。
- **靜態地理位置的高效查詢**：Yelp 需要快速找到使用者周圍的地點，關鍵挑戰在於如何對二維地理空間進行索引，平衡查詢速度與空間利用。
- **動態位置的即時更新與搜尋**：Uber 需要處理駕駛位置的頻繁更新，並即時配對乘客與附近駕駛，關鍵挑戰在於修改靜態地理索引來支援高頻更新。

所有三個案例都展示了如何從需求開始，一步步分解問題，選擇合適的架構與演算法，並討論各種設計的取捨，這正是系統設計面試中需要展現的能力。
