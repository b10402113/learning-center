# 混合雲 vs 全雲端儲存

## Learning goal

比較混合雲儲存與全雲端儲存架構的差異，理解各自的設計考量、安全性取捨與適用場景。

## Lesson

儲存架構的選擇直接影響資料的安全性、可用性、和成本。在系統設計面試中，面試官可能會問：「你的資料要放在哪裡？」或「如何滿足合規要求？」理解混合雲和全雲端的取捨，你才能給出一個既安全又可擴展的答案。

**混合雲儲存（Hybrid Cloud Storage）** 結合了本地儲存（私有雲）和公有雲儲存。資料和應用程式可以在私有雲和公有雲之間移動，提供更大的靈活性。想像你有一個保險箱放在家裡（私有雲），同時也在銀行租了一個保險箱（公有雲）。重要文件放在家裡的保險箱，一般文件放在銀行——這就是混合雲。

混合雲的核心特性包括：結合本地、私有雲、公有雲服務（Integration）；敏感資料放在私有雲，一般資料放在公有雲（Flexibility）；可以滿足資料主權和法規要求（Compliance）；需要管理兩套基礎設施和它們之間的整合（Complexity）；混合成本模型：私有雲固定成本 + 公有雲按量計費（Cost Model）。典型的範例是一家金融公司將客戶的敏感交易資料放在本地伺服器（符合金融法規），同時將行銷資料和分析數據放在 AWS 或 Azure 上（利用雲端的擴展性）。

**全雲端儲存（All-Cloud Storage）** 是指使用雲端服務來處理所有資料儲存需求，沒有本地基礎設施。通常使用 AWS、Azure 或 Google Cloud Platform 等公有雲服務。全雲端就像把所有文件都放在銀行的保險箱裡：你不用管理保險箱、不用擔心火災或盜竊，一切都交給銀行專業管理——但你完全依賴銀行。

全雲端的核心特性包括：所有資料都儲存在雲端（Cloud-dependent）；基礎設施由雲端供應商維護（Vendor Management）；幾乎無限的儲存和計算資源（Scalability）；只為實際使用的資源付費（Cost）；遷移到其他供應商可能有困難（Vendor Lock-in）。典型的範例是一家新創公司從第一天就把所有服務部署在 AWS 上，使用 S3 儲存、RDS 資料庫、Lambda 函數。不用買伺服器、不用租機房，快速上線。

| 維度 | 混合雲 | 全雲端 |
| --- | --- | --- |
| 基礎設施 | 混合：本地 + 私有雲 + 公有雲 | 完全使用公有雲 |
| 靈活性 vs 簡單性 | 靈活但複雜 | 簡單但受限 |
| 安全性 | 敏感資料可留在本地 | 依賴雲端供應商的安全機制 |
| 合規性 | 容易滿足資料主權要求 | 需確認雲端供應商符合法規 |
| 擴展性 | 公有雲部分可擴展 | 整體可擴展 |
| 成本模型 | 混合：固定 + 按量 | 主要是按量計費 |
| 適用場景 | 有嚴格合規要求的企業 | 需要快速擴展、無合規限制 |

選擇混合雲還是全雲端，取決於幾個關鍵因素：資料的敏感性——如果資料高度敏感且有法規限制如金融、醫療，混合雲更安全；合規要求——如果法規要求資料不能離開特定地理位置，混合雲更靈活；預算——全雲端通常前期成本較低，但大規模使用後成本可能上升；團隊能力——混合雲需要更強的基礎設施管理能力；擴展需求——如果需要快速擴展到全球，全雲端更簡單。

混合雲和全雲端各有優劣。選擇的關鍵在於：資料敏感性、合規要求、預算、和團隊能力。在面試中展示你能權衡這些因素，比單純選一個方案更重要。
