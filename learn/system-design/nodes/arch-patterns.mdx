# 架構模式

本節點彙整了系統設計中常見架構選項的直接比較，幫助你在面試時快速判斷「該選 A 還是 B」，並清晰解釋為什麼。這些比較題是系統設計面試的常見考點，也直接影響架構決策的品質。

## Learning goal
理解常見架構元件和風格的比較與選擇，包括 LB vs API Gateway、Proxy vs Reverse Proxy、REST vs RPC 等核心對比，能依場景做出合理的取捨

## Steps

以下是逐步學習的步驟-DAG：

1. **[[learn/system-design/nodes/arch-patterns/lb-vs-api-gateway|Load Balancer vs API Gateway 比較]]** — 基礎比較，瞭解兩者的分工差異
2. **[[learn/system-design/nodes/arch-patterns/proxy-vs-reverse-proxy|Proxy vs Reverse Proxy 比較]]** — 理清 Proxy 的兩種角色
3. **[[learn/system-design/nodes/arch-patterns/api-gateway-vs-reverse-proxy|API Gateway vs Reverse Proxy 比較]]** — 整合前面兩個比較，進一步區分現代微服務閘道與傳統反向代理
4. **[[learn/system-design/nodes/arch-patterns/rest-vs-rpc|REST vs RPC 比較]]** — API 設計風格的核心取捨
5. **[[learn/system-design/nodes/arch-patterns/polling-comparison|通訊模式比較：Polling vs LongPolling vs WebSockets vs Webhooks]]** — 客户端-服務器通訊模式的選擇

閱讀順序按照編號依序進行。

## Lesson
架構模式與比較是系統設計面試中最常被要求「比較 A 和 B 的差異」的考點。本節點透過直接對比，幫助你快速掌握每種選項的設計本質與適用場景，避免混淆相似名詞，並能清晰表達取捨理由。

每個步驟聚焦一組核心比較，深入淺出解釋差異、使用時機、實際案例。
