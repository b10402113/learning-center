# Ticketmaster

## Learning goal
設計高併發訂票系統（座位鎖定、公平性），解決熱門電影同時搶票時的一致性與公平性問題。

## Steps

1. **[[learn/system-design/nodes/ticketmaster/requirements-and-goals|需求分析與系統目標]]** — 理解功能與非功能需求
2. **[[learn/system-design/nodes/ticketmaster/capacity-estimation|容量估算]]** — 估算流量與存儲需求
3. **[[learn/system-design/nodes/ticketmaster/database-design|資料庫設計]]** — 設計關聯式資料庫結構
4. **[[learn/system-design/nodes/ticketmaster/high-level-architecture|高層架構設計]]** — 整體架構與系統 API 設計
5. **[[learn/system-design/nodes/ticketmaster/detailed-component-design|核心元件詳細設計]]** — ActiveReservationsService 與 WaitingUsersService
6. **[[learn/system-design/nodes/ticketmaster/concurrency-fault-tolerance|併發控制與容錯]]** — 解決座位衝突與服務崩潰恢復

## Lesson

本節點實現從零開始設計一個高併發線上訂票系統，這是系統設計面試中常見的真實場景，重點考察設計者如何在極端高併發下保證一致性與公平性：不會有人買到同一個座位，先到先得，且系統能容錯恢復。

我們將按照標準系統設計流程逐步推進：從需求分析開始，到容量估算、資料庫設計，再到高層架構和核心元件設計，最後解決併發和容錯問題。每個步驟都會深入討論關鍵取捨。
