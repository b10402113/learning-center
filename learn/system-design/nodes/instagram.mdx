# Instagram

## Learning goal
從零開始設計一個可擴展的 Instagram 圖片分享平台，能夠處理大量照片上傳與儲存，並快速生成用戶的動態消息。

## Steps

1. [[learn/system-design/nodes/instagram/requirements-consideration|需求分析與設計考量]] — 列出功能性與非功能性需求，分析系統讀寫特性
2. [[learn/system-design/nodes/instagram/capacity-estimation|容量估算與限制約束]] — 估算總存儲需求與日常流量，明確系統限制
3. [[learn/system-design/nodes/instagram/high-level-architecture|高階系統架構設計]] — 區分上傳與讀取流程，定義核心元件分工
4. [[learn/system-design/nodes/instagram/data-modeling|資料庫建模與 Schema 設計]] — 設計使用者、照片、追蹤關係的資料模型，估算儲存大小
5. [[learn/system-design/nodes/instagram/component-data-sharding|元件設計與資料分片]] — 處理讀寫並發問題，選擇合適的元數據分片策略
6. [[learn/system-design/nodes/instagram/newsfeed-design|動態消息生成設計]] — 在分片資料上高效生成按時間排序的動態消息
7. [[learn/system-design/nodes/instagram/reliability-redundancy|可靠性與冗餘設計]] — 透過多副本確保資料不遺失，實現高可用性

## Lesson

本節點將帶你從零開始完整設計 Instagram 這款圖片分享平台，這是系統設計面試中非常經典的「大型社交平台」題目。你將會練習從需求分析開始，逐步推演到容量估算、架構設計、資料分片，最後解決動態消息生成這個核心挑戰。

不同於簡單的短網址服務，Instagram 的核心挑戰在於**處理讀取密集的工作負載**、**管理大量非结构化照片儲存**，以及**在分片架構下維持動態消息的高效生成**。每一個步驟都會牽涉到明確的取捨，這些取捨正是系統設計面試中重點考察的能力。

完成本節點後，你將能夠獨立從零開始設計一個可擴展的圖片分享平台，並清楚解釋每一個設計決策背後的理由。
