# 系統設計面試入門

## Learning goal

理解系統設計面試在考什麼、回答步驟框架、避開常見陷阱

## Steps

1. [[learn/system-design/nodes/intro-sdi/what-sdi-tests|系統設計面試在考什麼？]] — 理解面試考的是問題解決、溝通與取捨判斷，不是背答案
2. [[learn/system-design/nodes/intro-sdi/answering-framework|7 步驟回答框架]] — 掌握從需求澄清到瓶頸分析的完整回答流程（after step 1）
3. [[learn/system-design/nodes/intro-sdi/master-template|常見系統組件全覽]] — 認識 DNS、LB、CDN、Cache 等常見元件，在設計中靈活選用（after step 2）
4. [[learn/system-design/nodes/intro-sdi/common-pitfalls|避開面試中的 7 大陷阱]] — 識別並避開忽略需求、太早深入細節、忽略取捨等常見錯誤（after step 2）

## Lesson

系統設計面試是一場「從零設計可擴展系統」的開放式對話。它不考你背了多少技術名詞，而是看你能不能在壓力下拆解問題、做合理的取捨、並把思路講清楚。面試官想看到的是你的思考過程——你如何從模糊的需求出發，一步步收斂成一個可落地的方案。

準備這場面試有三根支柱：先搞清楚面試在考什麼（以及不考什麼），再學會一套可複用的回答框架，最後避開大多數人都會踩的坑。這個節點會帶你走完這三步，為後續的技術主題打下基礎。
