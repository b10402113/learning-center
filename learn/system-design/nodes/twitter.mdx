# Twitter

## Learning goal
設計一個支援推文、追蹤、我的最愛與動態時間軸的可擴展短影音社群平台，能夠處理每日上億級的推文與讀取流量。

## Steps

1. **[[learn/system-design/nodes/twitter/requirements-capacity|需求分析與容量估算]]**
   - 釐清功能與非功能需求，完成系統容量估算
   - Deps: 無

2. **[[learn/system-design/nodes/twitter/core-design|核心系統設計與資料庫綱要]]**
   - 定義系統 API、繪製高層架構、設計資料庫綱要
   - Deps: requirements-capacity

3. **[[learn/system-design/nodes/twitter/data-scaling|資料擴展：分片與快取]]**
   - 設計資料分片策略與快取機制來應對海量讀寫流量
   - Deps: core-design

4. **[[learn/system-design/nodes/twitter/timeline-optimization|動態時間軸生成優化]]**
   - 優化時間軸生成的延遲與吞吐量，處理延伸需求
   - Deps: data-scaling

5. **[[learn/system-design/nodes/twitter/production-readiness|生產環境就緒：複製、容錯、負載均衡與監控]]**
   - 確保生產環境的可靠性、可擴展性與可觀測性
   - Deps: timeline-optimization

## Lesson

本節點將一步步帶你設計 Twitter 這類型的社群媒體平台。不同於單純的訊息服務，Twitter 的核心挑戰在於**讀取量大於寫入**——每日有數十億次的推文讀取，但只有數億次的推文寫入。我們從需求開始，一步步推導出架構：先估算容量，定義 API，設計高層架構，再解決資料擴展、時間軸生成優化，最後加上生產環境需要的可靠性與監控。

每個步驟都聚焦一個核心問題，並討論不同設計決策的取捨。學完本節點，你將能在面試中從容回答「設計 Twitter」這道經典題目。
