# MEMORY — system-design

## Goal
通過系統設計面試，並能將所學應用於生產環境的系統設計。具體目標：能在白板上從零開始設計一個可擴展的系統，清楚解釋每個決策的取捨。

## Why
半年內有系統設計面試。這是晋升或換工作的關鍵關卡。面試不只考「知不知道」，更考「能不能在壓力下從零設計並講清楚為什麼」。

## Prior experience
- 有個人專案的 REST API 開發經驗（非生產環境大規模使用）
- 用過關聯式資料庫（Postgres/MySQL），但未深入思考過 OLTP vs 分析的取捨
- 用過 NoSQL（Redis/MongoDB 等），但使用場景有限，未理解背後的設計哲學
- 沒有負載均衡、快取、訊息佇列、架構圖設計、分散式系統正式學習的經驗

## Anchors
- 個人專案中的 REST API：可以連結 API 設計、REST vs RPC 的討論
- 資料庫使用經驗：可以連結 SQL vs NoSQL、索引、ACID vs BASE 的討論
- 「用過但沒想過為什麼」的經驗：每個概念都可以從「你之前用 X，其實背後是 Y 原理」切入

## Habits & constraints
- 每週5小時，時段不固定
- 獨自學習，無白板或繪圖工具
- 時間充裕（半年），可以深入學習但需要保持節奏

## Knowledge type
混合型（mixed），程式化（procedural）為主。概念記憶不是瓶頸，瓶頸在於「拿到題目後如何一步步拆解、設計、並講清楚取捨」。每個節點都應包含：概念解釋 → 為什麼重要 → 如何在面試中應用。

## How to teach me
- 閱讀 + 做筆記是主要學習方式
- 希望有「老師講解」的感覺：先解釋概念，再舉例，最後連結到我的經驗
- 不要只列事實，要講「為什麼」和「什麼時候用」
- 每個概念都要能回答：「這跟我之前做的 X 有什麼關係？」
- 避免無聊：不要長篇大論的定義，用實際案例和對比來教學
