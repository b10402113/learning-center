# issue 佇列驅動

## Learning goal

把 GitHub issue 變成 agent 的任務佇列：gh CLI + 最小權限 PAT、task selection prompt、修完自動 close/comment。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/issue-queue/task-queue-shift|為什麼讓 agent 自己挑任務]] — 從「指定計畫」到「自己挑任務」，以及五級任務優先序
2. [[learn/ai-coding-for-real-engineer/nodes/issue-queue/private-issue-repo|準備一個只有你能動的 issue repo]] — 複製目錄、清 git 歷史、建一個屬於自己的 GitHub repo（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/issue-queue/wire-agent-to-github|用 gh CLI 把 agent 接上 GitHub]] — 抓 issue JSON、挑任務、做完 commit 後 close/comment、注入 PAT（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/issue-queue/least-privilege-token|只給 agent 剛好夠用的 token]] — 最小權限的取捨，與一次完整修復的可觀測性（after step 3）

## Lesson

前一個節點把 AFK 迴圈接上了 PRD 與 plan，但那個迴圈還不夠「放手」：每次開跑前，你仍得親自指定這次要做哪一份計畫，它做完就淡出，不會自己接著找下一件事。這一節把迴圈的輸入換成一個**任務佇列**——讓 agent 除了「做任務」，還要「自己挑下一個任務」。

四步沿著一條線走。先講**為什麼**要換（觀念：固定計畫 vs. 佇列，以及那個決定先後的五級優先序）；再講怎麼在 GitHub 上**準備**一個只有你能動的私有 issue repo；接著用 gh CLI 把 agent 真正**接上**這個佇列，讓它抓開放 issue、挑一件、做完後 close 或留言；最後處理整件事最敏感的一環——**token 權限**，用最小權限原則決定 agent 到底該拿到多少存取權。

走完之後，你會有能力在自己的 side project 上跑起「agent 產 code → 人 review → 開 issue → agent 再產 code」的良性循環：plan 不再是你每次手動餵給它的東西，而是一條 agent 自己會去拉的待辦佇列。
