# issue 佇列驅動

## Learning goal

把 GitHub issue 變成 agent 的任務佇列：gh CLI + 最小權限 PAT、task selection prompt、修完自動 close/comment。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/issue-queue/task-selection-prompt|讓 agent 自己挑任務：task selection prompt]] — 設計讓 agent 從 issue 佇列自行挑選下一個任務的優先順序 prompt
2. [[learn/ai-coding-for-real-engineer/nodes/issue-queue/own-repo-isolation|為什麼每個 AFK 設定要配自己的 repo]] — 為何不能 fork，以及建立獨立 repo + issue tracker 的三步驟（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/issue-queue/gh-cli-wiring|用 gh CLI 把 GitHub 接進 AFK prompt]] — 用 `!gh issue list` 拉 open issues，comment 當工作紀錄，修完自動 close（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/issue-queue/least-privilege-token|最小權限 token 與端到端收尾]] — 最小權限 PAT，以及一個 bug 從 issue 到修完 close 的完整自走迴圈（after step 3）

## Lesson

上一章的 AFK agent 還是指著一份 PRD + plan 跑。這一章讓它從 GitHub issue 佇列自己挑任務，變成一個可以連續消化 backlog 的自走迴圈：你用 task selection prompt 教它按優先序選題，用自己的 repo 隔離 issue 佇列，用 gh CLI 把 open issues 灌進 prompt、用 comment 留下 append-only 工作紀錄，再給它最小權限的 token，讓它在修完後自己 close issue 並留下理由。人退到 review 的位置：agent 產出程式碼、人審查、回饋變成新 issue、agent 繼續產出——這就是 issue 佇列驅動的核心迴圈。
