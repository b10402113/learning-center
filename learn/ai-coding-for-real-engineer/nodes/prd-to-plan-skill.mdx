# 只寫耐久決策的計畫

## Learning goal

用 PRD-to-plan skill 產出引用 user story、只含 durable decisions 的垂直切片計畫。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/prd-to-plan-skill/fair-test-setup|公平比較的實驗設置（跑一次 PRD-to-plan）]] — 用乾淨的實驗環境呼叫 skill，先讓比較成立
2. [[learn/ai-coding-for-real-engineer/nodes/prd-to-plan-skill/skill-workflow|PRD-to-plan 怎麼運作（探索、提案、確認、寫檔）]] — skill 的四段工作流，以及寫前先問為什麼值得（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/prd-to-plan-skill/durable-decisions|只寫耐久決策（別規劃你無法規劃的事）]] — 先找耐久架構決策再切 slice，細節留到實作（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/prd-to-plan-skill/vertical-slice-plan|產出的計畫長什麼樣（tracer bullet、user story 引用、更少的實作洩漏）]] — 對照天真計畫看結果，垂直切片加上 user story 引用（after step 3）

## Lesson

PRD 寫好之後，下一步是把 destination 切成一段一段的 journey，這份 journey 就是計畫。天真計畫有一組穩定的失敗訊號，水平切層、劇透實作、不引用 user story，skill 產出的計畫逐一對著修。要確認它真的修對了，先學會把比較建立在乾淨的實驗環境上，全新 session、刪掉舊計畫檔、只帶 PRD。接著看懂 skill 自己的流程，先探索、先提案、先問人，才寫檔。真正讓計畫跨 phase 存活的是耐久決策，只寫那些到 phase 3 還不會變的架構軌道，細節一律留給實作。最後看產出的樣貌，phase 1 是一條用最簡單資料打通全棧的 tracer bullet，每個 phase 都引用對應的 PRD user story。四步走完，你手上就有判斷標準，任何一份計畫拿來，用切法、內容、引用三件事過一遍，就知道它陪不陪得到最後一站。
