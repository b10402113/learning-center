# 為什麼探索是第一個動作

<LearningGoal>
說明 LLM 的 statelessness 為何讓「每次開新 session 都從零探索 codebase」成為與 agent 合作的第一個基本功。
</LearningGoal>

## Lesson

在所有 LLM 的限制裡，最棘手、最奇怪、而且你必須第一個去想的那個，是 **statelessness**：LLM 沒有跨 session 的記憶，每次被丟進你的 codebase 都是「第一次」——它完全不記得上次 session 看過哪些檔案、得出過什麼結論。這不是偷懶，而是模型本質：context window 是一次性的，session 結束就清空。所以探索不是加分題，而是與 agent 合作的起點：你給它的第一份「資料」不是 spec，而是「這個 repo 長什麼樣、程式碼怎麼組織、哪些 pattern 是慣例」，這份資料決定後面每一步的判斷品質。

課程把 exploration 稱為 foundational skill——在 coding agent 上變強之前必須先理解它。它回答三個樸素問題：這個 codebase 在做什麼（purpose）、它是怎麼被佈置的（layout / patterns）、慣例是什麼該怎麼遵循。「新 session 一開先探索」不是流程上的儀式，而是 statelessness 直接推導出來的必然動作：你不餵它 context，它就沒有 context。
