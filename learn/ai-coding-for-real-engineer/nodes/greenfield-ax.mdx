# 從零開始的專案

## Learning goal

知道 Greenfield vs Brownfield 的差別，理解 AX（agent experience）先於 UX 的概念，並能用 ADR + glossary 支撐 agent。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/greenfield-ax/greenfield-vs-brownfield|Greenfield 與 Brownfield：從空白頁開始]] — 分辨全新 repo 與既有 constraints 的 codebase，看出 Greenfield 的難處在設定 agent experience
2. [[learn/ai-coding-for-real-engineer/nodes/greenfield-ax/ax-before-ux|AX 先於 UX：第一份 PRD 通常是一份 AX PRD]] — 說出 AX 為何與 UX 綁在一起，並列舉第一份 PRD 要先定的四件事（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/greenfield-ax/adr-and-glossary|用 ADR + Glossary 補上 agent 答不出來的兩個問題]] — 用 ADR 答「why did you do it this way」、用 context.md glossary 答「what is an X」（after step 1）
4. [[learn/ai-coding-for-real-engineer/nodes/greenfield-ax/greenfield-start-sequence|Greenfield 起手式：grill → research → prototype → PRD]] — 串起完整起手式，AX 排定後 codebase 變 Brownfield、接回正常七階段 loop（after steps 2–3）

## Lesson

這個 node 處理「從零開始」的時刻：面前是一塊白板，沒有 codebase、沒有約束，你要讓 agent 幫你蓋出第一棟房子。課程之前所有的練習都是 Brownfield——既有 repo、既有 constraints——所以 Greenfield 是全新的課題，而它的難處幾乎全部落在同一件事：設定 agent experience（AX）。

關鍵心法是把 AX 擺在 UX 前面，不是忽略 UX，而是「你無法為了 UX 犧牲 AX」。在 Greenfield 裡，第一份 PRD 常常根本就是一份 AX PRD：feedback loops（typecheck、tests、pre-commit hooks、formatting）、technology choices、module shape（deep modules）、testing strategy 全部要在 UX 目標之前或與其並行定下來，因為這些決定會塑造 agent 之後每一次閱讀和修改的體驗。與此同時，要建立兩份 agent 答不出來的文件：ADR 回答「為什麼這樣做」（trade-off、tech choice），repo root 的 `context.md` glossary 回答「什麼是 X」（業務黑話），都在 grilling 期間、PRD 之前建立。

最後把起手式串起來：grill → 把輸出寫成 research markdown → prototype → PRD。一旦 AX 排定，這塊 codebase 行為上就跟 Brownfield 一樣，正常七階段 loop 直接接手。整件事的動力正如課程總結所說：「AI coding 給你 permission to build」——把從空白頁到可交付的距離縮短到一個 agent 能自己走完的程度，人只需要在開頭把 taste 與 AX 灌進去。
