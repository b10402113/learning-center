# 自動化迴圈

## Learning goal

用 main.ts 的 maxIterations + completion signal 迴圈，跑出完整的多階段實作。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/afk-loop/main-ts-loop|main.ts：把互動式 agent 變成自動迴圈]] — 認識 run mode、positional PRD/plan 參數與迴圈結構
2. [[learn/ai-coding-for-real-engineer/nodes/afk-loop/termination-signals|兩種停止機制：maxIterations 與 completion signal]] — 迭代上限與「no more tasks」完成訊號（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/afk-loop/resume-from-commits|每輪從上次 commit 續跑]] — 多輪 iteration 如何逐 phase 推進、typecheck/test、commit（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/afk-loop/afk-result|人走開，回來拿到程式碼]] — 讀懂一次完整 AFK loop 的成果與人機平行作業（after step 3）

## Lesson

互動式 AFK 還有一個缺點：每次 agent 停下來等你批准，你都得回到螢幕前。自動化迴圈把這個最後的互動也拔掉——`sandcastle/main.ts` 用 `run` mode 反覆執行同一份 prompt，直到 agent 自己說「沒任務了」或撞上迭代上限。上一課的 permission 問題由 Docker 沙盒解決（sandboxing node），於是迴圈可以真的放手跑完多個 phase。

關鍵的洞察是「do phase N 是 for loop」：把「檢查哪些 phase 已 commit、挑下一個做、跑回饋迴圈、commit」這套流程塞進一個重複執行的腳本，agent 每輪都從上次的 commit 續跑，直到 completion signal 出現。這個 node 從腳本結構、停止機制、續跑行為到一次完整實跑，帶你把 AFK loop 從「知道概念」走到「看得懂 log、知道結果長什麼樣」。
