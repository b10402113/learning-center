# 自動化迴圈：main.ts

## Learning goal

用 main.ts 的 maxIterations + completion signal 迴圈，跑出完整的多階段實作。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/afk-loop/main-runner|從 interactive 到 main.ts：無人值守的 runner]] — 認出 main.ts 與 interactive 的三個差異，並用位置引數呼叫（entry point）
2. [[learn/ai-coding-for-real-engineer/nodes/afk-loop/loop-termination|迴圈怎麼停：maxIterations 與 completion signal]] — 兩個終止條件與成本取捨（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/afk-loop/multi-phase-run|跑一次完整多階段實作（並讀懂日誌）]] — 逐階段實作、commit、context window 判讀（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/afk-loop/parallelize-yourself|放手之後：規劃前提與平行化自己]] — 人該做什麼、規劃為何是前提（after step 3）

## Lesson

`interactive.ts` 把「一次跑一個 phase」這件事自動化，但要真的無人值守地把整份多階段計畫做完，還需要一個會**重複執行**的 runner。`sandcastle/main.ts` 就是這個 runner：它沿用同一個 prompt，卻把單次互動換成一個會自己轉的迴圈。

節點的核心是一個「跑—停」機制。每一次迭代都是一輪完整的 探索 → 實作 → typecheck／test → commit，跑完再由 completion signal 決定要不要再來一輪，maxIterations 則是最後一道保險。理解這個迴圈的終止條件，才能拿捏「放多大膽、燒多少 token」。這條線的另外一端，是把已完成的工作辨識出來、只往下一個 phase 走——這是多階段計畫能一氣呵成、而不是每輪重來的關鍵。

四步走完之後，你不只知道 main.ts 怎麼呼叫，還能讀懂它的日誌：哪一輪在做什麼、上下文漲到哪裡、什麼時候它會說「沒事了」。最後一步把鏡頭拉回自己身上——agent 在跑的時候，你應該去做什麼。
