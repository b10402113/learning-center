# 訪談取代 plan mode

## Learning goal

用 GrillMe 一題一題把模糊需求釘成 shared design concept，再直接進實作，不靠 plan mode 的牆式計畫。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/interview-not-plan/plan-mode-wall|plan mode 的牆式計畫：它做對了什麼、錯在哪]] — 走一遍 plan mode 的完整流程，看出它把訪談壓短、直接吐一面計畫牆的失敗模式
2. [[learn/ai-coding-for-real-engineer/nodes/interview-not-plan/shared-design-concept|shared design concept：為什麼訪談才是核心]] — 設計概念是短暫共享而非資產，explore → interview → implement 才是該走的順序（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/interview-not-plan/grillme-mechanics|GrillMe 的運作原理：一次一題、先探索、給推薦]] — GrillMe 檔案的設計原則，以及每一條如何守住 shared design concept（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/interview-not-plan/grill-to-implement|實跑 GrillMe：從訪談到直上實作]] — lesson comments 完整實跑：用 reversibility 挑設計、用「Correct」加速，訪談完直接實作、零 steering（after step 3）

## Lesson

這個 node 回答一個具體困擾：給 agent 一個模糊需求時，它的計畫往往是一面牆——長、完整、但跟你心中想的對不上。plan mode 的牆式計畫把訪談壓成一兩個問題就急著輸出，於是參與者之間的共識根本沒建立起來。四步安排是一條從「看出問題」到「實作驗證」的鏈：先看 plan mode 到底做對了什麼、錯在哪；再理解它跳過的 shared design concept 是什麼、為什麼非建立不可；接著認識 GrillMe 這份把訪談變成技能的檔案；最後跟著一次完整實跑，確認「訪談釘對 → 實作零 steering」真的成立。
