# 超出一個 context window 怎麼辦

## Learning goal

對放不進單一 context 的任務，用 grill→to-PRD 產出 destination（PRD）+ journey（plan）兩份文件。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/two-documents/big-build-breaks-context-window|為什麼大任務會爆掉 context window]] — 認出任務大到塞不進一個 window 的 smart zone，理解拆小任務、各用乾淨 window 的解法方向
2. [[learn/ai-coding-for-real-engineer/nodes/two-documents/destination-and-journey|兩份文件：destination 與 journey]] — PRD（destination）裝 taste、plan（journey）切成 phase，呼叫方式是「do phase N + PRD + 整個 plan」（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/two-documents/grill-then-to-prd|先用 grill 釘 scope，再用 to-PRD 落地]] — grill-me 訪談先釘住目的地，太大就呼叫 to-PRD 把 context 就地寫成 PRD 骨架（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/two-documents/analytics-dashboard-worked-run|實跑：把 taste 釘成一份受限的 PRD]] — analytics dashboard 完整實跑：scope 逐步釘死、領域細節、to-PRD 產出的完整結構（after step 3）

## Lesson

這個 node 是「大任務放手給 agent」的第一塊地基：單一小功能或修 bug 塞進一個 context window 就夠，但一次大建置（大型 refactor、整面新功能）會一路爆進 dumb zone，越做越笨。解法不是換更大的 window，而是跟工程一直以來做的事一樣——把大任務拆成小任務，每個小任務各用一個乾淨的 context window 跑。但拆的前提是得有跨 window 還能用的計畫，於是有了兩份文件：destination（PRD，裝你要什麼、你的 taste）與 journey（plan，把 PRD 切成 phase 怎麼走）。四步安排是一條「看懂問題 → 認識工具 → 學會產出 → 看完整實跑」的鏈：先認出任務何時會爆掉 window；再認識這兩份文件與「do phase N + PRD + plan」的呼叫方式；接著學會用 grill→to-PRD 把開放式需求變成 durable 的 PRD；最後跟完一次 analytics dashboard 實跑，確認 taste 是怎麼被一步步釘成一份受限、可交接的規格的。
