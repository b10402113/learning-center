# 指令太長怎麼辦

## Learning goal

把肥胖的 CLAUDE.md 重構成 skill + reference files 的 progressive disclosure 結構，並寫出自己的 skill。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/progressive-disclosure/bloated-claude-md|肥胖 CLAUDE.md 的病：指令全擠在全局作用域]] — 看懂每條指令都在佔 context、跟 prompt 搶位置，並認識 progressive disclosure 原則
2. [[learn/ai-coding-for-real-engineer/nodes/progressive-disclosure/agent-skills-format|Agent Skills：按需揭露指令的開放格式]] — 認識 skill 資料夾結構與「預設只看 name + description」的按需揭露機制（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/progressive-disclosure/refactor-to-skill|動手重構：用 skill 把 coding standards 從 CLAUDE.md 搬走]] — 實作一次重構，留下極簡 context pointer，看懂 double-linkage（after steps 1–2）

## Lesson

當 CLAUDE.md 越寫越長，每一條指令都會進入每次 request 的 context，跟你的 prompt 競爭注意力——哪怕這條指令只對少數 session 有用。解法不是「寫更短的 CLAUDE.md」，而是換一種組織方式：progressive disclosure。把可能一起用到的指令放進同一個檔案，讓 CLAUDE.md 只留一張連結地圖，agent 需要時再往下讀。Agent Skills 就是這件事的標準落地格式：一個資料夾，預設只把 name 和 description 餵給 agent，內容等你調用才載入。把這三步走完，你手上會有一套「skill 化的 coding standards」：肥胖的 CLAUDE.md 縮成一行 pointer，細節收在按需載入的 reference files 裡，未來加規矩也不再讓每個 request 變肥。
