# SQLite 與 Drizzle：資料庫如何與 code 同步

<LearningGoal>
解釋為什麼 schema 改了不會自動生效，用 generate → migrate 讓 migration 檔案與資料庫跟上 schema，並用刪 data.db + reseed 重置資料庫。
</LearningGoal>

## Lesson

Playground 用 SQLite + Drizzle，而 SQLite 是「一個檔案就是一個資料庫」——整個資料庫存在本地 <code>data.db</code>（外加 <code>data.db-shm</code>、<code>data.db-wal</code> 配套檔）。這代表重置超級容易：刪掉 <code>data.db</code> 再跑一次 <code>pnpm db:seed</code> 就好，因為全部都是假資料，刪掉重來零損失。

真正的反直覺陷阱在 Drizzle：<code>schema.ts</code> 是 source of truth，但**改了不會自動生效**。你得親手推兩步——<code>db generate</code> 從 schema 產出 migration 檔案（程式碼世界），<code>db migrate</code> 把 pending migration 套進資料庫（資料庫世界）。跳過 migrate，schema 和資料庫就不同步。課程的實戰觀察是 agent 通常自己會想到 generate，但常常漏掉 migrate，於是你會看到「agent 以為自己動了資料庫其實沒有」的假象——這是你在 HITL 模式要盯的第一個點。搞砸了就刪 <code>data.db</code> + reseed，不需要逆向資料庫。
