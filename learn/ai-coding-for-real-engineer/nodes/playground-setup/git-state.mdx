# 用 reset / cherry-pick / pull 控制 git 狀態

<LearningGoal>
用 pnpm reset（配對錄影的程式碼狀態）、pnpm cherry-pick（保留自己的改動）、pnpm pull（同步上游修復）控制 playground 的 git 狀態，並把 merge conflict 交給 Claude。
</LearningGoal>

## Lesson

每一支錄影練習都對應一顆特定 commit，你必須能把 repo 對齊到那顆 commit。但「對齊」有三種不同意圖，課程用三支 pnpm 命令分別包裝：<code>pnpm reset</code>（配對錄影的程式碼狀態）、<code>pnpm cherry-pick</code>（保留自己的改動）、<code>pnpm pull</code>（同步上游修復）。<code>pnpm reset</code> 是唯一會真的抹掉你工作的地方——它破壞性重置到選定的錄影 commit、刪掉無關的工作（例如你加的 npm script），而且不能直接 reset main，得先開新 branch。

<code>pnpm cherry-pick</code> 保留現有工作、把目標 commit 疊過來，代價是可能產生 merge conflict——但衝突不是麻煩，Claude 很會解，你只要說「Claude fix this merge conflict for me」，卡死時 <code>git cherry-pick --abort</code> 退回原狀。當講師修了課程 repo 的 bug、你想把上游修復帶進目前 branch 時用 <code>pnpm pull</code>——它 fetch 並合併，不會 reset 你的狀態。這三支的決策樹：要完全對齊且不在乎改動 → reset；要對齊又要保改動 → cherry-pick；只想拿修復 → pull；遇到衝突一律交給 Claude。
