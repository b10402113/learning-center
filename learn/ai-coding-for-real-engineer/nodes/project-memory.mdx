# CLAUDE.md 專案記憶

## Learning goal

寫/修 CLAUDE.md 讓 agent 跨 session 記住規矩；理解它 global、燒 token、可能被忽略的特性，並懂得審查自動記憶與用全局偏好壓制不需要的行為。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/project-memory/claude-md-basics|CLAUDE.md 是什麼：global、燒 token、可能被忽略]] — 認識 CLAUDE.md 三特性與 `/init` 風險
2. [[learn/ai-coding-for-real-engineer/nodes/project-memory/writing-rules-that-steer|寫出真的會生效的規矩]] — 用實驗證明規矩能壓過慣例，並學會耐久規則與 re-review 技巧（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/project-memory/auto-memory-review|審查自動記憶]] — 分辨三層記憶並定期清理失效內容（after step 1）
4. [[learn/ai-coding-for-real-engineer/nodes/project-memory/global-preferences|用全局偏好壓制行為]] — 用 user 層 CLAUDE.md 壓制不想要的 agent 行為（after step 3）

## Lesson

agent 是無狀態的，每個 session 都是從零開始。CLAUDE.md 就是補上這塊的「專案記憶」：把規矩寫進 repo 根目錄的檔案，讓 agent 每次對話都自動讀到。但這個記憶有代價——它 global（每個 request 都會帶上）、燒 token（每句內容都佔 context）、而且可能被忽略（模型不保證照做）。看懂這三個特性，你才知道 CLAUDE.md 該放什麼、不該放什麼。

寫規矩不只是「寫進去」，要寫到真的會生效。用實驗驗證：一條和 codebase 慣例衝突的規矩，agent 會乖乖照 CLAUDE.md 走；而「服務必須有測試」這種指名慣例、不指名檔案的規則，才不會因為檔案改名就腐壞。除了你手寫的記憶，Claude 也會自動寫自己的記憶檔，而且可能過時——需要定期審查。最後，除了 repo 層，還有 user 層的全局 CLAUDE.md，可以用來壓制你不想要的跨 session 行為。
