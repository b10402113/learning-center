# 先做 prototype

## Learning goal

對不確定的設計先做 throwaway prototype 沖出 unknown unknowns，把 taste 先灌進去，再讓 AFK loop 接手。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/prototyping/prototype-rationale|為什麼先做 prototype：把 unknown unknowns 沖出來]] — 認出 prototype 解決的問題、何時該做與不該做
2. [[learn/ai-coding-for-real-engineer/nodes/prototyping/prototype-prompt|跑一輪 prototype：從 do-work skill 到 throwaway route]] — 用「do-work skill → 引用 research → throwaway route → 可重用 asset」的 prompt 模板跑一輪（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/prototyping/prototype-feedback-loop|prototype 的 feedback loop：為什麼人要在場]] — 看懂 prototype 產出的 production-ready 程式碼，以及 HITL 早投入對 AFK 實作的價值（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/prototyping/prototype-skill-branches|prototype 的兩種 archetype：UI 變體與邏輯時間步進]] — 用 UI 變體與終端機時間步進兩個 archetype 覆蓋多數 prototype 需求（after step 3）

## Lesson

有的設計光在文字裡談不準：plan mode 用文字把事情「說」清楚，但 taste 要看到、摸到才定得下來。這個 node 在七階段流程的 research 與 PRD 之間插進一個 prototype 階段——在 throwaway 的 route 上把不確定的部分真的做出一版，把 unknown unknowns 沖出來，人趁早把 taste 灌進去。prototype 不只是研究的一種形式，它還簡化實作：用 do-work skill 跑出來的是 production-ready 的程式碼，之後 AFK loop 只是把現成 asset 複製進真 app。node 走完你手上就有「為什麼做、怎麼 prompt、feedback loop 為什麼要在場、用哪種 archetype」的完整判斷，可以決定自己的 prototype 該長什麼樣。
