# 用 permissions 設定管住風險

## Learning goal

理解 risk/reward 權衡，用 `.claude/settings.local.json` 的 `permissions.allow`/`deny`（含 wildcard）與 `settings.json` 預授權命令，並管控 web 存取等風險，避免 agent 造成災難性動作。

## Lesson

跟 agent 合作的第一個問題是**你願意讓它有多大權力**。權力越大、能交付越多，但出事的後果也越大（例如不小心刪掉整個檔案系統）。Claude Code 的解法是一套詳細的 permissions 模型，預設非常嚴格。當 Claude 想跑一個命令（例如 typecheck），它會先請求核准，畫面上顯示**確切命令 + 原因**，然後你有幾個選項：允許這次、以後都允許（這個專案內不用再問）、否決、或按 Tab 建議**另一個命令**（例如叫它用 `npx tsc` 代替 `pnpm typecheck`）。極度安全的命令（如 `echo hello`）則直接跑不問。

你的核准會被記錄到 `.claude/settings.local.json` 的 `permissions.allow` / `permissions.deny` 陣列，也可以自己手動編輯預先授權。規則支援 wildcard：`"allow": ["Bash(pnpm:*)"]` 一次允許所有 pnpm 命令，`"deny": ["Bash(git push:*)"]` 則永久封鎖 git push。不只 bash，**web search / web fetch 也一樣受控**——agent 上網也是要管的風險面。

預設的 `settings.local.json` 在 .gitignore 裡只對你個人有效；改名成 `settings.json` 就能讓整個 repo 的 Claude 實例共用這套規則，新人第一次進 repo 就跑得起來。這就是 repo 層級 agent 配置的種子：預授權一套已知安全的命令，省去每次 session 都跟安全提示搏鬥。
