# 用 IDE 檢視與核准 diff

## Learning goal

用 `/ide` 啟動 IDE 整合，在 VS Code 檢視 rich diff，並用「Accept Proposed Changes」或直接存檔核准 agent 的編輯，把 review 變成上線前的 HITL 閘門。

## Lesson

Claude Code 預設在終端機裡顯示 diff，純文字、難捲、難比較——對「review agent 改了什麼」是致命的，因為看不清楚就等於沒有 review。解法是把 Claude Code 接上你日常用的 IDE：執行 `/ide` 會顯示連線狀態並教你安裝對應的 extension（VS Code、Cursor、Windsurf 都行），裝好後 agent 的 diff 就出現在 IDE 介面中。整合的核心不是「讓 Claude 幫你在 IDE 寫程式」，而是**diff 管理**——一個可捲動、可逐行檢查的 rich diff。

核准的流程很簡單：看完 diff 後，按 IDE 介面的 **Accept Proposed Changes** 按鈕，或直接儲存檔案（Ctrl-S / Cmd-S）——存檔就等於同意這份 diff。沒核准就不算數。這就是一個**人類在迴路中的閘門（HITL gate）**：agent 可以提議任何改動，但只有你按下核准的那一瞬間它才生效。課程示範都在 VS Code 的整合終端跑 Claude Code，正因為偶爾要「潛進去」微調 agent 的輸出，而 review diff 這種事在真正的 IDE 裡做遠比終端舒服。

這是本 node 的第一課，也是之後所有信任的前提：**看得清楚，才敢放手**。後面的 rewind（改壞了倒帶）、bash 模式（控制它看得到什麼）、permissions（管住它能跑什麼），全都建立在「你能夠清楚地 review agent 做了什麼」這塊地基上。
