# 用 bash 模式控制 agent 看得到的輸出

## Learning goal

用 `!` 進入 bash mode、Ctrl-B 背景化長命令、Ctrl-Z 掛起 Claude 執行隱藏命令、`fg` 恢復，並依決策樹決定該讓 agent 看到哪些輸出，讓它有能力閉合與專案的 feedback loop。

## Lesson

bash 命令把 agent 從「被動的碼農」變成「能跟專案互動的夥伴」：它可以跑 typecheck、跑測試、起 dev server、curl API，然後看到結果、自己修問題——這就是閉合 feedback loop 的能力。例如跑一次 `npm run typecheck`，錯誤訊息進入 Claude 的 context，它就能診斷出「Zod 在 package.json 裡但沒裝」並幫你 `npm install`，不必你逐字複製錯誤給它。

跑命令有三種方式，差別在「誰看得到輸出」。**Bash mode（`!`）**：輸入列開頭打 `!`，接下來的命令輸出直接進 Claude 的 context，適合 typecheck/test/build 這類「有開始有結束」的命令。**背景化（Ctrl-B）**：dev server 這類永遠不會結束的命令，在執行中按 Ctrl-B 丟到背景，輸出寫入本機檔案、狀態列可打開查看——對除錯 dev server 特別有用，Claude 能看 log、去 UI 試、發 curl，再回來看 server 印了什麼。**掛起（Ctrl-Z / `fg`）**：按 Ctrl-Z 掛起 Claude Code 回到一般 shell，跑的任意命令都不會進 Claude 的 context，跑完 `fg` 恢復原狀。注意課程用的是 Windows 快捷鍵，Mac 上可能不同。

決策樹很簡單：想讓 Claude 看到輸出 → `!`（長命令再加 Ctrl-B 背景化）；不想讓它看到 → Ctrl-Z 掛起。背後的深層意義是**你控制 context 裡裝什麼**——你想讓它「看到問題並自己修」，就把輸出餵給它；你想私下確認，就掛起。這預告了下一課 permissions 的邏輯：你知道它在看什麼、跑什麼，才談得上放權。
