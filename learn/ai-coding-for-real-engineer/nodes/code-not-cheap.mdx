# code 不 cheap

## Learning goal

用 easy-to-change 與 entropy 論證，說明為何 agent 時代程式品質比人寫時更關鍵，而 feedback loop 是解藥。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/code-not-cheap/code-is-cheap-myth|「code 很便宜」的說法]] — 說出這個說法在講什麼、為何聽起來合理
2. [[learn/ai-coding-for-real-engineer/nodes/code-not-cheap/quality-is-easy-to-change|品質＝好不好改]] — 用 Ousterhout 的定義拆解「codebase 好不好改」（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/code-not-cheap/entropy-and-cludge-meter|entropy 與 cludge meter]] — 用 entropy 與 cludge meter 解釋 code 為何變糟、AI 為何加速它（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/code-not-cheap/agents-copy-your-codebase|agent 以 codebase 為師]] — 從三個輸入與 statelessness 看 agent 為何比人更受壞 codebase 影響（after steps 1–2）
5. [[learn/ai-coding-for-real-engineer/nodes/code-not-cheap/feedback-loops-are-the-defense|feedback loop 才是解藥]] — 收束成「code 不 cheap」，並說明 feedback loop 為何是關鍵防禦（after steps 3–4）

## Lesson

這一個 node 先拆穿一個反直覺的命題：有人說 agent 時代 code 很便宜，bug 無所謂、品質無所謂，反正壞了再叫 agent 重寫。課程用一連串論證反過來——正因為 agent 能大量產出 code，品質反而比人類時代更關鍵。

論證順序是：先定義品質不是風格、不是整齊，而是 Ousterhout 說的「codebase 好不好改」；接著用 software entropy 與 cludge meter 說明 code 天生傾向變糟，而 AI 加速了這個過程；然後是關鍵一擊——agent 每次 session 的三個輸入裡，codebase 是最重要那個，而 stateless 的 agent 沒有記憶和工作區去繞過爛 codebase。把這三塊疊起來，結論就出來了：code 不 cheap，便宜 code 只是加速衝向 cludge meter 爆表；feedback loop 才是把品質守住的手段。
