# AFK agents 與互動模式

## Learning goal
說明「do phase N 是 for loop」，並用 Sandcastle interactive 模式 + prompt.md，在可觀察環境下跑第一次單一任務。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/afk-concept-interactive/afk-concept|認識 AFK agents：「do phase N 是 for loop」]] — 看懂 do phase N 是條 for-loop，說出多 phase 計畫的三樣輸入，以及 AFK 把人的角色換成什麼
2. [[learn/ai-coding-for-real-engineer/nodes/afk-concept-interactive/interactive-first|先互動後 AFK，Sandcastle 與兩種執行模式]] — 解釋為什麼放手前要先互動，拆解 Sandcastle 三件式配方與 interactive.ts / main.ts 的分工（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/afk-concept-interactive/interactive-run|第一次互動式單一任務實跑]] — 用 prompt.md 的 shell 展開與單任務原則，跑通第一次互動式單一 phase 實作（after steps 1–2）

## Lesson

這一節把「放手」這件事從概念落到第一次執行。核心判斷只有一句，`do phase N` 是一條 for-loop，人要做的就是確認迴圈每一圈跑完再給下一道指令。認出這是迴圈，才談得上自動化，AFK agents 就是把這條迴圈交出去，人從迴圈主體執行者變成佇列管理者。但放手之前要先證明行為可靠，所以執行順序是先用 Sandcastle 的互動模式，人留在迴圈裡觀察、修改 prompt，確認行為穩定後，同一份設定才交給無人監督的執行。第一次互動實跑只做一個 phase，靠 prompt.md 的 shell 展開抓取 repo 當下狀態、內聯 PRD 與 plan，並用單任務原則把每一圈限制在聰明區內。跑完一圈，人對 AFK 的把握就從「理解概念」變成「親眼看過一次」。
