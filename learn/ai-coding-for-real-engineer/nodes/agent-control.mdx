# review diff、bash、風險控管

## Learning goal

用 IDE 整合 review diff、用 rewind/resume 回放 session、用 bash 模式控制 agent 看得到的輸出、用 permissions 設定管住風險。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/agent-control/ide-diff-review|用 IDE 檢視與核准 diff]] — 用 `/ide` 啟動 IDE 整合，在 VS Code 檢視 rich diff，並用 Accept Proposed Changes 或存檔核准 agent 的編輯
2. [[learn/ai-coding-for-real-engineer/nodes/agent-control/rewind-and-resume|用 rewind / resume 回放 session]] — 用 escape 兩次回退還原 code/對話，並用 `/resume`、`claude --continue` 續開持久化的 session（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/agent-control/bash-mode|用 bash 模式控制 agent 看得到的輸出]] — 用 `!` bash mode、Ctrl-B 背景化、Ctrl-Z 掛起、`fg` 恢復，依決策樹決定該讓 agent 看到什麼（after step 1）
4. [[learn/ai-coding-for-real-engineer/nodes/agent-control/permissions-model|用 permissions 設定管住風險]] — 用 `.claude/settings.local.json` 的 allow/deny 與 `settings.json` 預授權命令、管控 web 存取（after step 3）

## Lesson

這個 node 是「怎麼把車開得安全」：上一課學會在終端握住方向盤，這一課教你三件控制 agent 的事——怎麼看它改動了什麼、怎麼在改壞時倒帶回去、怎麼管住它能不能跑命令。全部圍繞同一個核心：**把控制權留在人手上**。

四步的安排先學 review：`/ide` 把 diff 從難看的終端搬進 IDE，讓你在存檔核准前先看清 agent 的編輯，這是上線前的 HITL 閘門。接著是出錯時的回放機制（rewind/resume），因為 LLM 無狀態，session 持久化是你唯一能倒帶的工具。第三步學會用 bash 模式控制「agent 看得到哪些輸出」——這是閉合 feedback loop 的關鍵，也是下一步權限管理的伏筆：只有當你知道它會跑什麼命令、看到什麼結果，你才有資格決定放權給它。最後用 permissions 設定把風險管住，預授權一套已知安全的命令，免得每次 session 都跟安全提示搏鬥。

學會這四招，你就能在放手與把關之間找到平衡——這正是「離線交付」（AFK）能成立的前提：你之所以敢走開，是因為你知道回來能 review、能倒帶、能限制它。
