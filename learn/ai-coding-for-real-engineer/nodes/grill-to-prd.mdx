# 兩文件模型與 PRD

## Learning goal

對放不進單一 context 的任務，用 grill→to-PRD 產出 destination（PRD）+ journey（plan）兩份文件。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/grill-to-prd/why-two-documents|為什麼大任務要塞不進一個 context window]] — 說出為什麼大 build 爆掉 smart zone，答案是拆小 + 跨視窗規劃
2. [[learn/ai-coding-for-real-engineer/nodes/grill-to-prd/destination-and-journey|destination（PRD）與 journey（plan）兩份文件]] — 兩份文件各裝什麼，以及「do phase N」prompt 為何要帶整份（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/grill-to-prd/grill-then-capture|grill 完，把它變成一份 PRD（to-PRD 流程）]] — grill-me → to-PRD 流程與 PRD 骨架（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/grill-to-prd/taste-into-prd|一場真實的 grill，把 taste 釘進 PRD]] — 用 analytics dashboard walked run 看 taste 怎麼被逐題釘進 PRD（after step 3）

## Lesson

這節課處理放不進單一 context window 的大任務。起點是「為什麼不能硬塞」：context 有 smart zone 上限，任務一大就掉進 dumb zone，於是把任務拆成多個 phase、每個 phase 在新視窗執行。拆解之後靠兩份文件把碎片接回一體：destination（PRD）編碼人類的 taste、journey（plan）拆成 phase，每個 phase 用「do phase N + PRD + 整份 plan」的 prompt 執行。兩份文件不會憑空出現，由 grill-me 訪談逐題釘下 scope 與領域細節，再經 to-PRD 固化成一顆可跨 session 交接的 PRD。整條鏈路的核心是：人類留在 taste 的位置，agent 對抗式 grill 並把共識變成文件。
