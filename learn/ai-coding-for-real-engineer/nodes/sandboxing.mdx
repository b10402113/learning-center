# 安全的沙盒

## Learning goal

用 Docker/Podman sandbox 隔離 agent（避開 YOLO 風險）。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/sandboxing/yolo-risks|為什麼不能開 YOLO：放手前先看風險]] — 為什麼 permission prompts 阻擋真 AFK、YOLO 為何危險、官方要求把它關在隔離容器/VM 裡
2. [[learn/ai-coding-for-real-engineer/nodes/sandboxing/sandbox-model|容器沙盒的隔離模型]] — Docker 容器只給 agent repo 存取權、不給主機存取權（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/sandboxing/sandbox-setup|把沙盒建起來：Docker/Podman 與 image]] — 裝 Docker Desktop/Podman、填 .env 的 API key、build image（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/sandboxing/sandbox-smoke-test|煙霧測試：hello world 確認沙盒就緒]] — 用 test.ts 的 hello world 跑一遍並看 live logs，確認隔離生效再上 AFK（after step 3）

## Lesson

走到 AFK 的最後一哩是「敢不敢放手」。上一課的互動模式還卡在 permission prompts——每個 bash 動作都要你按同意，這在沒人盯著的 AFK 迴圈裡行不通。最省事的做法是開 YOLO 模式繞過所有權限，但那等於把家目錄、公司代碼和主機本身都交給一個可能被 prompt injection 劫持的 agent。這一個 node 用容器沙盒回答「怎麼放手又不翻車」：讓 agent 只在一個裝了 Claude Code 的 Docker 容器裡工作，repo 綁定掛載進去，bash 全部在容器內執行，agent 接觸不到容器外的世界。

四個步驟從「為什麼」到「怎麼驗證」：先看懂 YOLO 的具體風險和官方限制，再理解容器沙盒的隔離模型為什麼給 repo 存取但不給主機存取，然後在本機把 Docker/Podman sandbox 建起來，最後用 hello-world 煙霧測試確認一切就緒。走完這裡，AFK 迴圈才真正能無人值守地跑起來。
