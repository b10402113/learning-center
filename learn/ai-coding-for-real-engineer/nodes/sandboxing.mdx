# 安全的沙盒

## Learning goal

用 Docker/Podman sandbox 隔離 agent（避開 YOLO 風險）。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/sandboxing/why-not-yolo|別在主機上開 YOLO]] — 認出 YOLO 在未隔離主機上的兩種代價，以及內建 sandbox 為何不足
2. [[learn/ai-coding-for-real-engineer/nodes/sandboxing/what-isolation-means|隔離到底隔離了什麼]] — bind mount、容器內 bash、憑證注入如何把可及範圍縮到最小（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/sandboxing/build-the-sandbox|建起沙盒：Dockerfile、.env 與 build image]] — 安裝 Docker/Podman、設定 API key、build 映像（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/sandboxing/verify-the-sandbox|驗證沙盒：用 test.ts 跑一次 Hello]] — 從 logs 判讀沙盒是否真的在運作（after step 3）

## Lesson

放手讓 agent 自走之後，下一個問題不是「它夠不夠聰明」，而是「它做錯事時能錯到多大」。要完全無人看管，就得讓它不必每次停下來問權限；可是把權限全部打開（Claude Code 的 `--dangerously-skip-permissions`，俗稱 YOLO），等於把整台電腦交給一個不受監督、又可能被 prompt injection 帶偏的程式。官方文件只允許在隔離的容器或 VM 裡這麼做，就是這個道理。

這條節點要蓋的是那道邊界。真正有用的隔離不是把 agent 關起來不做事，而是把它能碰到的東西收到最小：只 bind mount 你要給它的 repo、所有 bash 指令都在容器裡跑、認證用的金鑰用環境變數注入。這樣它照樣能在專案裡自由行動，卻碰不到你的家目錄和系統的其他角落。

四個步驟先講清楚「為什麼不能在主機上放飛」，再拆解「隔離到底隔離了什麼」，接著實際把 Sandcastle 的 Docker 映像建起來，最後用一支 hello-world 測試確認沙盒真的能跑。走完之後，你手上會有一個可以安全承載後續 AFK 迴圈的環境。
