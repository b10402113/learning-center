# Context Window 與二次方擴張

<LearningGoal>
說出 context window 是什麼、token 之間注意力怎麼二次方成長，並理解為什麼把越多的內容塞進 context 會讓模型越吃力。
</LearningGoal>

## Lesson

Context window 是模型在單一次 request 內看得到的所有內容：你的 prompt、被 `@` 參照讀進來的檔案、工具（跑測試、讀檔）的回傳輸出、整段對話歷史，全部擠在同一個窗口裡。它是模型的工作記憶，不是長期記憶——窗口外的一切對模型而言不存在。這解釋了為什麼 `@` 參照要花成本：每個被讀進來的檔案都佔掉窗口空間，而 agent 做的事（讀檔、跑指令、看日誌）幾乎都會把結果寫回 context。

LLM 的核心機制是 attention：讓每個 token 去「看」其他每個 token，找出彼此關係。成本不是線性成長，而是兩兩配對——有 n 個 token，就要處理約 n×(n−1)/2 組關係：4 個 token 產生 6 組、8 個產生 28 組、100 個約 5,000 組。token 數翻倍，關係數暴增四倍左右；你每多塞一個 token，它要跟所有既有 token 建立關係，既有 token 也要跟它建立關係。這就是為什麼「再加一行說明」比你想的貴得多。

實務上這帶來第一條鐵律：只放必要內容進 context。`/context` 顯示你燒了多少 token，每次 `@` 參照和工具輸出都在往這個二次方成本裡加燃料。把 context 保持在精簡狀態，不但是省錢，更是保住品質的前提——下一課會看到，當 context 被塞到某個量級，模型的推理品質會開始崩壞。
