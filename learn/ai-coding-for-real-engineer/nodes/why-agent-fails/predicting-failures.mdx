# 用這些約束預測 agent 何時會出錯

<LearningGoal>
綜合二次方擴張、dumb zone、不可靠記憶與非決定性四項約束，預測 agent 在哪些情況下容易出錯，並說出對應的防範方式。
</LearningGoal>

## Lesson

四條約束各指向一種失敗模式：二次方擴張與 dumb zone 讓 context 越塞越滿時推理退化、幻覺、召回失敗；不可靠記憶讓憑參數回想的專案事實（檔名、設定、舊知識）被編造；無狀態讓新 session 的 agent 對專案一無所知、重做或提出衝突方案；非決定性讓同一指令每次結果不同，跟示範對不上是常態。

合起來是一張出錯預測表：token 逼近 80k–100k 就該 `clear`/compact、探索丟 sub-agent；需要精確事實就用 `@` 參照與文件讓它讀，別靠參數記憶；長任務用 handoff/`/resume` 延續，知識放進 codebase 與 AGENTS.md；結果用測試與 typecheck 驗證，不期待逐字相同，讓不同軌跡收斂到同一個正確終點。

四條約束最終指向同一組好習慣：保持 context 精簡、把事實放進 context 與文件、用測試驗證而不是對照範本。agent 出錯時先問是哪條約束在背後起作用——診斷對了，防範就順理成章。這正是後續 context economy、exploration、feedback loops 每一招的出發點。
