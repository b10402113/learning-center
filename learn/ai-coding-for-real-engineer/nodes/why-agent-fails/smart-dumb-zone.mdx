# Smart Zone 與 Dumb Zone

<LearningGoal>
說出 context 被填滿後會發生什麼（推理變差、幻覺、召回失敗），並用 token 門檻（約 80k–100k token）判斷 agent 何時開始進入 dumb zone。
</LearningGoal>

## Lesson

Context 越大，attention 被稀釋，模型愈難同時顧好所有內容，於是產生漸進式退化：推理從清晰變成答非所問，開始編造事實（幻覺），也抓不回早前看過的細節（召回失敗）。課程把窗口切成兩段——smart zone（推理清晰、幾乎沒有幻覺）與 dumb zone（三個症狀齊發）；開頭很聰明的 agent 聊到後來變笨，多半就是從 smart zone 滑進 dumb zone。

可操作的判斷線是 token 門檻：教練的原話是「約 40% 開始緊張」——他錄課用 200k 窗口，40% 就是約 80k token；後來主流窗口長到 1M，但 smart zone 大約在 80k–100k 個原始 token 這條線仍然適用。所以要用 token 數、別用百分比：同一百分比在 200k 與 1M 窗口代表完全不同的絕對量，看比例會誤判。

手上要有儀表板——Claude Code 用 `/context` 或常駐 status-line、Cursor/OpenCode 預設就顯示用量——逼近門檻就清 context（`/clear`）或 compact 回到精簡。這條門檻是所有「context 經濟學」技巧的根：sub-agent 燒探索的 token、compact 壓縮對話、handoff 換乾淨窗口接手，目的都是把主窗口留在 smart zone 內。
