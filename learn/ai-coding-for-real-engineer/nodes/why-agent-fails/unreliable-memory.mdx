# 參數記憶不可靠與無狀態

<LearningGoal>
說出為什麼 LLM 不是可靠的資料庫（fuzzy JPEG 式壓縮記憶、知識 cutoff），以及完全無狀態意味著什麼，並推導出「靠 context 與文件、別靠模型記憶」。
</LearningGoal>

## Lesson

模型有兩種「記住」：參數記憶（訓練時把資料壓縮進權重，之後憑權重回想）與 context 記憶（當下窗口裡實際看到的文字）。課程把參數記憶比喻成「全人類知識的一張模糊 JPEG」——壓縮會掉細節、模糊邊緣、偶爾重建錯，幻覺就是壓縮重建時的失真。對比可靠的資料庫，LLM 不儲存原始資料，只儲存近似，所以憑參數記憶回答專案的確切事實，它可能在合理的地方編出一個聽起來對的答案；而 context 記憶可靠得多，只要事實寫在窗口裡，模型直接讀而不是回想。

由此得到第一個反轉：knowledge cutoff 沒那麼重要了——既然本來就不該信任參數召回，需要最新或精確的事實就放進 context 讓它讀，而不是期待參數記得。第二個關鍵事實是模型完全無狀態：你在對話中建立的所有「部落知識」都存在 context 裡，一旦 `/clear` 或換 session 全部蒸發，每次 session 都從零開始。

兩件事合起來推出一條鐵律：事實要進 context，不要進想像。需要精確的資料就用 `@` 參照檔案、把 spec 與慣例寫進文件（含 AGENTS.md）讓它直接讀；凡是只能靠模型「回想」的都假設它會錯。這也解釋了為什麼 codebase 品質與文件是關鍵資產——知識放不進模型腦子，只能放進它每次都能重新讀到的地方。
