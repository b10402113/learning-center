# 從源頭避免壞架構

## Learning goal

在 PRD 階段就 sketch major modules、找 deep module 機會，避免 shallow modules 被生出來。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/prevent-bad-arch/prevent-vs-cure|預防 vs 補救：為什麼架構思考要搬進 PRD 階段]] — 用「預防 vs 補救」配對定位這個 node，理解為什麼架構思考要在設計當下就做
2. [[learn/ai-coding-for-real-engineer/nodes/prevent-bad-arch/sketch-major-modules|寫 PRD 模板前，先畫出 major modules]] — 動筆寫模板前，先列出要新建/修改的 major modules（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/prevent-bad-arch/hunt-deep-modules|主動找 deep modules，並跟使用者對齊模組切分]] — 找出可獨立測試的 deep modules、確認切分符合預期，逼出對的 seams 和 TDD loop（after step 2）

## Lesson

improve-codebase-architecture skill 是「補救」：等 shallow modules 被生出來、摩擦浮現，再回頭重設計、提出 RFC。這個 node 講的是同一枚硬幣的另一面——「預防」。更新後的 PRD skill 把架構思考搬進最關鍵的時刻：設計新實作的那一刻。就在動筆寫 PRD 模板之前，它先畫出這次要建或要改的 major modules、主動找可以獨立測試的 deep modules、並跟使用者確認模組切分符合預期。壞模組根本不會被生出來，對的 seams 在第一輪就被測到，TDD loop 也在設計階段就被逼出來。對於跨越多次 session 的 AFK 功能，這一步尤其重要——模組邊界先講清楚，agent 放手執行時才不會各自為政。
