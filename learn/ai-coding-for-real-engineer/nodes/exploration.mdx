# 怎麼探索陌生 codebase

## Learning goal

在陌生 repo 開新 session 時，用「Explore」關鍵字觸發深層 sub-agent 探索，把程式碼轉成自己的 mental model。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/exploration/why-explore-first|為什麼探索是第一個動作]] — 用 statelessness 說明為何每次開 session 都要從零探索 codebase
2. [[learn/ai-coding-for-real-engineer/nodes/exploration/baseline-explore-prompt|天真 prompt：先看看它給多少]] — 用「告訴我 tech stack 和用途」開場，觀察它淺層覆蓋、不 spawn sub-agent（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/exploration/explore-keyword|用「Explore」叫出深層 sub-agent]] — 用動詞「Explore」觸發帶自訂 system prompt 的深層探索，並看懂它的成本（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/exploration/build-mental-model|把發現長成自己的 mental model]] — 用 follow-up 問題追問，把片段發現轉成可操作的 repo 認知（after step 3）

## Lesson

agent 每次被丟進一個新 repo 時，對裡面的程式碼一無所知——LLM 完全沒有跨 session 的記憶。所以與其說探索是「加分題」，不如說它是跟 agent 合作的第一個基本功：session 一開就先把 codebase 讀進去，讀得越深，後面每一步的判斷越可靠。這一節的關鍵不是「問什麼」的措辭技巧，而是詞彙的選擇：一個隨口的「告訴我 tech stack」只會讓 agent 掃幾份檔案就交差，而「Explore」這個動詞會把它引到一條完全不同的深層路徑上。看懂這兩種 prompt 的差距、學會用 follow-up 問題把結果轉成自己的 mental model，你才真正「擁有」這個 repo，而不是只得到一份摘要。
