# 為什麼 agent 的計畫會失敗

## Learning goal

認出 agent 天真計畫的三個失敗訊號（水平切層、過度指定、失去 traceability），並理解為什麼需要另一種切法。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/naive-plan-failure/naive-plan-prompt|一條未指定的「做個 plan」指令會產出什麼]] — 重現未指定時 plan 的產出，並看懂 task sizing 是關鍵判斷
2. [[learn/ai-coding-for-real-engineer/nodes/naive-plan-failure/horizontal-slicing|失敗訊號一：水平切層，feedback 遲到]] — 認出每 phase 只覆蓋一整個 layer 的切法，以及它為什麼把回饋拖到後期（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/naive-plan-failure/over-specification|失敗訊號二：過度指定，函式名會過期]] — 認出寫死實作細節的計畫，以及它為什麼在後續 phase 執行前就過期（after step 1）
4. [[learn/ai-coding-for-real-engineer/nodes/naive-plan-failure/lost-traceability|失敗訊號三：失去 traceability，計畫不接回需求]] — 認出從不引用 user stories 的計畫，以及它為什麼丟掉「為什麼」（after step 1）
5. [[learn/ai-coding-for-real-engineer/nodes/naive-plan-failure/why-vertical-slices|為什麼需要另一種切法：垂直切片]] — 理解垂直切片如何一次修好三個訊號，並接上下一節 tracer-bullets（after steps 2–4）

## Lesson

把一份規格交給 agent 之前，plan 這一步是最容易翻車的地方。你不指定任何東西，只丟一句「把這個變成多階段計畫」，agent 會用自己的預設直覺來切——而那套直覺幾乎必然是水平的、過度指定的、而且不接回需求的。這節課就是教你認出這三個訊號：先看清楚未指定的指令會產出什麼（step 1），再逐一認識三個失敗訊號（step 2–4），最後才明白「另一種切法」為什麼值得——垂直切片讓每個 phase 貫穿所有 layer，早回饋、能驗證、也把計畫釘回 PRD。認病是這一節的任務，藥方（把垂直切片變成可執行的流程）在下一節 tracer-bullets。
