# 紅綠重構

## Learning goal

把 TDD 織進 do-work skill，用 failing-test-first 逼 agent 寫出可測試、可變動的程式碼。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/tdd-agents/red-green-refactor-basics|紅綠重構三拍]] — 說出 red → green → refactor 每一拍在做什麼，以及 CI（types + tests）的角色
2. [[learn/ai-coding-for-real-engineer/nodes/tdd-agents/tdd-for-agents|為什麼 TDD 特別適合 AI agent]] — 用「強迫可測試」「紅轉綠難造假」「阻止水平層假測試」三點說明 TDD 對 agent 的價值（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/tdd-agents/weaving-tdd-into-do-work|把 TDD 織進 do-work skill]] — 修改 implementation 步驟：後端 Red Green Refactor、前端直接實作，用更模糊的指引喚起模型已知知識（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/tdd-agents/tdd-end-to-end-run|用 coupon redemption PRD 端到端跑一遍]] — 觀察 agent 的紅綠迴圈、pre-commit hook 二次把關與 QA 結果（after step 3）

## Lesson

do-work skill 保證「每次變更都跑 feedback loop」，但沒有規定實作該怎麼長。這個 node 把 TDD 的紅綠重構織進 implementation 步驟：先寫一個會失敗的測試（red），再寫最小實作讓它變綠，最後在保持 CI 綠的前提下重構。failing-test-first 對 agent 有兩個特別的效果——強迫它寫出可測試、因而可變動的程式碼，以及給人一個「LLM 難造假」的信任訊號：測試由紅轉綠，agent 無法假裝。

把這個概念與 tracer bullets 合流，一次只推一個垂直切片的失敗測試，就能阻止 agent 噴灑一整層「大多是假的」水平測試。實際做法是把 skill 的後端指令改成「use Red Green Refactor」、前端直接實作，且不點名外部文件——模型早已知道 TDD，模糊的指引反而喚醒它既有的知識。最後用 coupon redemption PRD 端到端跑一遍，看 agent 的紅綠迴圈是否真的執行、pre-commit hook 是否在 commit 前再把關一次，並認識到那個留下來的大測試網絡本身就是品質資產。
