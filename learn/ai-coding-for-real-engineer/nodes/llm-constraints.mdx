# LLM 的天性決定一切

## Learning goal

解釋 context window 二次方擴張、smart/dumb zone、statelessness、非決定性，並用這些約束預測 agent 什麼時候會出錯。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/llm-constraints/quadratic-context|為什麼 context 塞得越滿，agent 越笨]] — 從 token 與窗口講起，用二次方擴張的帳算出聰明區與愚蠢區，建立「塞滿會變笨」的判斷框架
2. [[learn/ai-coding-for-real-engineer/nodes/llm-constraints/fuzzy-jpeg-memory|LLM 不是資料庫]] — 參數記憶是壓縮的模糊 JPEG、by design 不可靠，窗口內資訊才可靠（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/llm-constraints/statelessness|完全無狀態的 agent，clear 一次記憶就歸零]] — 模型本身沒有記憶，tribal knowledge 只活在窗口裡，文件與 codebase 品質變成關鍵（after step 1）
4. [[learn/ai-coding-for-real-engineer/nodes/llm-constraints/nondeterminism|同一句話，agent 兩次給你不一樣的答案]] — next-token 抽樣機器、輸出落在機率分佈上、靠回饋迴圈收斂但殘留變異要接受（after step 1）
5. [[learn/ai-coding-for-real-engineer/nodes/llm-constraints/predicting-agent-failure|用四條天性預測 agent 何時會出錯]] — 綜合四條約束，把「塞滿窗口、依賴參數記憶、期待跨 session 記憶、期待可重現」變成可預測的失敗情境（after steps 2–4）

## Lesson

這節課要把 coding agent 拆成一台有四條先天限制的機器來理解。它的工作記憶只有一個上下文窗口，而這個窗口的消耗是二次方成長的，塞得越滿，推理越差，於是分出聰明區與愚蠢區。它對世界知識的持有方式是壓縮過的參數記憶，可靠度天生存疑，真正能信的只有窗口裡看得到的內容。它沒有任何跨 session 的記憶，每次清空窗口就像失憶症患者醒來，一切歸零。最後，它每次生成都是從機率分佈裡抽樣，同樣的輸入會得出不同的輸出。

四條限制單獨看都是怪癖，合起來就變成一套預測工具。agent 什麼時候會出錯，多半能從這四條推出來：窗口塞進愚蠢區會幻覺，靠參數記憶講事實會張冠李戴，期待新 session 記得舊對話會失望，要求同樣輸入同樣輸出會落空。知道這些之後，與其怪模型不夠強，不如把可靠資訊放進窗口、把規矩寫進文件、把成功標準交給測試，讓 agent 在它擅長的條件下工作。
