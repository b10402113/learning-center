# 審查 agent 的成果

## Learning goal

建立 automated review pipeline，把 coding standards 編碼進 review agent，並在 PR 級別做 UX/DX/AX 三維審查。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/review-pipeline/implement-vs-review|把實作與審查拆成兩個 agent]] — 為何 implement 與 review 分開才能讓 agent 寫出符合標準的 code
2. [[learn/ai-coding-for-real-engineer/nodes/review-pipeline/standards-encoding|coding standards 從哪來]] — shared repo/RFC 複利與 review comment 歷史萃取（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/review-pipeline/ux-dx-ax-review|三軸審查：UX / DX / AX]] — 審查 agent 成果的第三個軸與 QA-plan issue（after step 1）
4. [[learn/ai-coding-for-real-engineer/nodes/review-pipeline/label-triggered-review|label 觸發的自動審查管線]] — GitHub Actions 上 agent-implement → draft PR → agent-review → ready（after steps 2–3）

## Lesson

人走開之後，agent 交回來的 code 怎麼把關？前幾個 node 把「寫」變成了迴圈，這個 node 把「審」也變成迴圈。核心洞察只有一個：想讓 agent 寫出符合 coding standards 的 code，不要把標準塞進實作 agent——實作只要基本可用、通過測試就好，清空 context 後換一個 review agent 專門套用 standards。分開之後，標準從哪裡來、審查看哪幾個軸、怎麼自動觸發，成為可以各自拆解的三個問題：標準靠 shared repo/RFC 複利、靠 review comment 歷史萃取；審查按 UX／DX／AX 三軸；最後用 GitHub Actions 的 label 把「開 draft PR → 審查 → mark ready」串成自動管線。
