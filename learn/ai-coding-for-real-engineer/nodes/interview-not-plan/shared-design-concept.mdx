# shared design concept：為什麼訪談才是核心

## Learning goal

能說出設計概念是參與者之間短暫共享、而非可以交付的資產，並解釋為何 explore → interview → implement 能取代「計畫先行」的工作流。

## Lesson

設計概念（design concept）不是可以交付的資產。Brooks 在《The Design of Design》裡指出它是「所有參與者之間短暫共享的那個東西」——你腦中的畫面、agent 腦中的畫面對不上，後面所有文件都建立在沙上；它活在對話裡，寫不進單一份文件。plan mode 的真正失敗不是計畫本身，而是跳過建立共享設計概念這一步：訪談被壓成一兩個問題，牆式計畫替換了參與者各自不同的畫面，還讓大家誤以為已經對齊。

先記住 default / implement 模式下 agent 有四種能力：寫檔案、讀檔案、跑 bash、呼叫 MCP server。plan mode 關掉寫檔案、鼓勵不要主動變更，讓 agent 變成只會輸出文字的顧問。課程推薦的工作流是 explore → interview → implement：explore 讓 agent 先查清「自己查得到的事」，interview 是核心、可以花很久——一題一題把模糊需求釘成 shared design concept，把 context 填滿「你要什麼」；訪談產出可以變成 spec，也可以直接進實作，因為文件只是手段、對齊才是目的。概念一致後，實作階段反而零 steering——花在訪談上的時間，省回的是實作中段「方向錯了重做」的時間。
