# 實跑 GrillMe：從訪談到直上實作

## Learning goal

能跟著 lesson comments 的完整實跑，走過 GrillMe 訪談 → 直接實作的流程，並用 reversibility（可否回退）思維挑選設計，理解為何對齊來自訪談、實作階段零 steering。

## Lesson

lesson 25 的完整實跑從一個故意模糊的需求起手：「做一個 lesson comments 功能」，用 V1-first prompt 丟給 default mode 的 agent。訪談由「Correct」加速——講師最常做的只是接受 GrillMe 附上的推薦答案，把注意力省下來想真正重要的問題；想比較方案時再自己追問，例如「哪一個版本之後會很難回退？」，把挑設計的鏡頭換成 reversibility：純 flat 最可回退（每則留言是獨立資料），巢狀 thread 最難逃脫（資料意義依賴於深度），所以 V1 選純 flat——不是最好的體驗，但是最安全的地基。

被釘出來的 V1 scope：已註冊學生＋講師可發文/閱讀、留言綁定單一 lesson、純 flat list、純文字＋自動連結、只能 soft delete 不能編輯、討論區放在 lesson 內容/測驗下方、thread-like 排序、一次載入全部、不做通知、2000 字元上限、admin 可刪除。一次一題之所以重要，是因為問題太多時人會不自覺地把傷筋骨的決策「延後略過」——一次一題逼你對 threading、編輯權限這些決定現在就做。訪談結束約 40k tokens、還在 smart zone，且沒有產生任何計畫資產，agent 直接進 implement：schema、migration、comment service、tests、UI 一路做完、測試全過，到 UI 階段約 78k tokens，實作階段零 steering。QA 驗證的就是訪談決定的照實落地：James Park 看不到留言、Olivia 刪不了、soft-delete 占位正常——對齊完全來自訪談。
