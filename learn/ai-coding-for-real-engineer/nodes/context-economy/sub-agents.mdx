# 用 sub-agent 把探索成本外包

<LearningGoal>
說明 orchestrator 為何把任務委派給帶全新 context window 的 sub-agent，並指出它如何保住主 agent 的 smart zone。
</LearningGoal>

## Lesson

agent 每次進到 repo 都是零記憶，得先探索再實作，而兩件事搶同一個 context window：探索花的 token 越多，留在 smart zone 給實作的越少；但探索偷工減料也不行，context 少實作就爛。Claude Code 的解法是**委派**——跟你對話的 orchestrator 會 spawn 一個 sub-agent，本質上**新建一個全新的 context window**，讓它在自己的 smart zone 裡盡情燒 token 做任務，做完只回傳摘要。這就像主開發把「把 repo 摸清楚」丟給實習生，回來只聽報告，自己的桌面保持乾淨。

sub-agent 還能平行（多個同時跑、各自回報）、還能換 system prompt 跟模型——探索這種相對簡單的任務，常見用便宜又快的 Haiku。Claude Code 對這招用得極其積極，你在它的 UI 會隨處看到 sub-agent。課程稍早的實戰證實了觸發方式：加「Explore」這個動詞才會 spawn 出 Explore sub-agent——它燒了 ~64k token、25 次 tool call，換回深度好幾倍的探索。上一步裝好 status-line 後，sub-agent 就是保持你主 agent token 數字低的第一招。
