# 用 handoff 換一個乾淨的 context

<LearningGoal>
當 session 中途冒出需要獨立處理的支線任務時，用 handoff skill 把任務寫進暫存 markdown，在一個全新 session 裡繼續，不 clear 也不撐大原 session。
</LearningGoal>

## Lesson

主線進行到一半冒出支線任務（發現一個 bug 或壞掉的 test）時，直接順手修不行——不知道會花多久，可能燒光主線預算；clear 也不行——主線還需要完整脈絡。而支線任務其實不需要主線的脈絡，它自己的 context window 就夠用了。handoff skill 的答案：把<strong>目前對話濃縮成一張暫存 markdown</strong>，讓一個全新 session 去接。文件存到 `make temp -t handoff` 的暫存路徑、建議下一步要用的 skill、不重複複製其他文件已有的內容（只放連結）、並依你的指令對準新 session 的焦點。

兩個典型用法：實作中發現壞掉的 test，handoff 到獨立 session 修，主線不受影響；長 GrillMe 走到一半想深挖某個分支，handoff 到新 session 專門 grill／prototype／research，燒完 context 再濃縮成文件 handoff 回來。這就是講師說的 **expand-then-contract** 流程——文件在 session 之間遞來遞去，每個 session 用完即可拋棄。相對於 compact 的 sediment 跟 clear 的失憶，handoff 是第三條路：不縮小、不刪除，把支線整個搬到一個新 window。
