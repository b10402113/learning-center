# 把環境跑起來

## Learning goal

在本機跑起課程的 20k 行 TS/React playground：pnpm install/seed/dev、理解 SQLite + Drizzle migration 怎麼與 code 同步、用 reset/cherry-pick/pull 控制 git 狀態。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/playground-setup/setup-playground|把 playground 跑起來]] — clone、Node LTS + corepack/pnpm、install、db:seed、dev（localhost:5175）、裝好 agent，並遵守「先別探索 codebase」的紀律
2. [[learn/ai-coding-for-real-engineer/nodes/playground-setup/db-sync|SQLite 與 Drizzle：資料庫如何與 code 同步]] — schema 不會自動同步，用 generate → migrate 跟上、刪 data.db + reseed 重置（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/playground-setup/git-state|用 reset / cherry-pick / pull 控制 git 狀態]] — 用三個 pnpm 命令把 git 狀態對齊錄影、保留自己的改動、同步上游修復（after step 1）

## Lesson

這個 node 是整門課的「落地前哨」：先讓 20k 行的 playground 在你的機器上真正跑起來，否則後面所有跟 agent 一起改 code 的練習都沒有著陸點。步驟很機械——clone、裝依賴、seed 資料庫、起 dev server——但背後有兩個反直覺的紀律值得先建立。

第一個是**資料庫與 code 不同步**：playground 用 SQLite + Drizzle，schema 是 source of truth，但改了不會自動生效，你得先 `generate` 再 `migrate`，否則 agent 會以為自己動了資料庫其實沒有。第二個是**git 狀態要能隨意對齊**：每個錄影練習對應某個 commit，`reset`、`cherry-pick`、`pull` 三支命令決定你是要拋棄、保留還是吸收別人的改動。這兩件事學會，之後的每一課才不會卡在環境或資料庫層面。
