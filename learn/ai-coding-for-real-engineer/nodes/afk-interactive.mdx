# 互動式 AFK：第一次放手

## Learning goal

說明「do phase N 是 for loop」，並用 Sandcastle interactive 模式 + prompt.md，在可觀察環境下跑第一次單一任務。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/afk-interactive/do-phase-n-is-a-loop|「do phase N」是一個 for 迴圈]] — 看懂 HITL 的「do phase N」其實是可以自動化的迴圈
2. [[learn/ai-coding-for-real-engineer/nodes/afk-interactive/sandcastle-runners|Sandcastle：先從 interactive 模式開始]] — 分辨 interactive.ts 與 main.ts，以及為何先不掛沙箱（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/afk-interactive/first-interactive-run|跑第一次：prompt.md 與單一任務]] — 設定並執行 interactive.ts，讀懂 prompt expansion 與單一任務的結果（after steps 1–2）

## Lesson

到目前為止，你都是坐在 agent 旁邊，一階段一階段下指令：讀 PRD、看 plan、說「do phase one」，等它做完，再決定要不要往下。這套流程之所以需要你，是因為選哪一階段、什麼時候放手，看起來像需要判斷的決策。但這一節要拆穿它：那句話只是一次迴圈迭代的觸發，而迴圈本身可以被寫成程式。

當你接受這個觀點，剩下的問題就只剩「用什麼跑」和「怎麼跑才安全」。Sandcastle 把 agent、沙箱、prompt 三個變數拆開，讓同一份 prompt 可以先在 interactive 模式、掛在你自己看得見的環境裡跑一次；等你確定它理解任務、只做一個切片、會跑回饋迴圈、會 commit，而且沒有做出你沒預期的事，才換成無人看管的自走迴圈。先把 prompt 調對、把單一任務跑順，是這一節的目標；真正長時間無人值守的版本留到後面的節點。
