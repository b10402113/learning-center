# 先分清楚：工具與流程

<LearningGoal>
能說出「agent 工具（harness）」與「七階段流程」的區別，並理解 Claude Code 只是示範用的 CLI agent、真正可轉移的是流程本身。
</LearningGoal>

## Lesson

先立一個心智框架：把「agent 工具（harness）」和「七階段流程」分開。課程用 Claude Code 做示範，只是因為它夠流行、是講師的日常工具，不是因為它有什麼獨門絕活——整套七階段流程（grill → research → prototype → PRD + plan → issues → implement → review）包得住任何跑在 CLI 裡的 coding agent。工具會換、會改版，流程才是跟著你走、真正可轉移的方法論。

很多人學 AI coding 的方式是「學某個工具的操作」。今天學 Claude Code 的 slash commands，明天學 Cursor 的 panel，後天學 Codex 的 terminal mode——每次換工具都要重學一遍。但工具的操作只是手指的事，真正決定你能不能把功能交付出去的是背後的判斷：什麼時候該清 context、該參照哪個檔、什麼時候該打斷 agent、什麼時候該放手讓它跑。這些判斷不綁定任何工具，它們跟著你走。

你可以把 AI coding 想成兩層。工具層是特定產品的操作方式——Claude Code 的 `/clear`、`@` 參照、escape 中斷，這些是 Claude Code 專屬的按鍵。流程層是怎麼把需求變成交付——grill → research → prototype → PRD/plan → issues → implement → review，這是一套方法論，跟你用哪個工具無關。接下來幾課你會學很多工具層的動作，動作本身學得很快。但每個動作背後都有一個流程層的判斷。動作是手指的事，判斷才是腦袋的事。

開車的比喻最能說明這件事：方向盤、油門、煞車是工具層——任何車都差不多。但「什麼時候超車」「什麼時候該減速」是流程層——這是駕駛的判斷，跟你開的是豐田還是特斯拉無關。這門課教你的是「判斷」，不是「按鍵」。就算你天天用 Claude Code，這章也值得重看，因為它是 basics 加 advanced tips 的混合，重點是為什麼，不是按鍵。

把「工具 vs 流程」這件事想清楚，還能避開另一個誤區：把「換了一個更好的工具」當成「變更強了」。工具只是手段，流程才是能力。你用 Claude Code 能交付一個功能，換成另一個 agent 一樣能交付——因為你知道要做什麼，只是工具不同。反過來，如果你只會操作 Claude Code 的按鍵但不懂流程，換工具你就報銷了。
