# 暫存 prompt 與貼圖

<LearningGoal>
用 Ctrl-S 暫存目前寫到一半的 prompt、Ctrl-C 丟棄它，並把圖片直接貼進 prompt（WSL 不支援），讓 prompt 可以中途抽離再恢復。
</LearningGoal>

## Lesson

開車基本功的最後兩個工具，讓 prompt 可以中途抽離再恢復。你正在打一個很長的 prompt，解釋你要 agent 做什麼——忽然你想起要先查一個東西。傳統做法是把 prompt 複製到某個地方、做完事再貼回來。但 Claude Code 有內建機制：**Ctrl-S 暫存**。按下 Ctrl-S，你目前打到一半的 prompt 會被暫存起來，輸入框清空。你可以跑別的指令、做別的事。想恢復的時候，暫存的 prompt 會自動回來。不想恢復了？按 **Ctrl-C 丟棄**暫存的 prompt，輸入框保持乾淨。這不是手動複製貼上——是 Claude Code 內建的 prompt 管理機制，把「打 prompt」從一次性動作變成可暫停、可反悔的流程。

暫存的價值在於它讓你的思緒不斷裂。打 prompt 時你正在把腦袋裡的想法組織成文字，如果中途被打斷（要查東西、要跑指令），沒有暫存就只能放棄這段思路。Ctrl-S 保存了你的組織過程，做完別的事回來，不需要重新想一遍「我剛才要寫什麼」。這是小事，但在長 session 裡累積起來差很多。

除此之外，你還能直接把**圖片貼進 prompt**：UI 長歪、報錯畫面、設計稿，一張圖勝過描述半天。做法很簡單——把圖片直接貼進 prompt 輸入框，Claude Code 會把圖片一併送進 context window。這是給 agent 視覺資訊最直接的方式。想想看：「按鈕跑到右邊去了，應該在左邊」跟一張截圖，哪個更精確？截圖讓 agent 直接看到問題，不需要你用文字描述半天還描述不準。唯一例外是 WSL（Windows Subsystem for Linux）不支援貼圖功能，原生 Windows 和 macOS 都可以。

回頭看這個 node 的整套動作——`/clear`、`@` 參照、Ctrl-S/Ctrl-C、貼圖——其實全部在管理同一件事：**你要給 agent 的輸入**。`/clear` 清掉舊的 context；`@` 參照指到對的檔案；Ctrl-S/Ctrl-C 暫存沒打完的 prompt；貼圖貼上說不清的視覺資訊。四招，四種輸入管理。把它們練熟，之後學大流程時就不必分心想「怎麼打字」——打字變成反射，判斷才是主軸。你已經有了駕駛的基本功，接下來要學的是「什麼時候該往哪個方向開」。
