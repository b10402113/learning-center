# 用 @ 精準參照檔案

<LearningGoal>
用 @ 加上下鍵與 tab 參照特定檔案，並理解被參照的檔案會自動被讀進 context window，用小成本換取 agent 需要的精確資訊。
</LearningGoal>

## Lesson

讓 agent 的 prompt 精準，第一招是 `@` 檔參照。在輸入框打 `@` 跳出檔名補全，上下鍵移動、tab 接受；被參照的檔案會被自動讀進 context window——你不是給它一個檔名提示，而是把整份檔案內容直接放進它眼前。這點重要，因為 LLM 是不可靠的記憶體：你省略「這個檔是哪個」，它就靠探索去補，而探索燒的是你最珍貴的資源。

一個具體場景最能說明這件事。你想讓 agent 修改 `src/services/user.ts` 裡的某個函數。不參照的話，它可能先讀 `src/models/user.ts`（猜錯），然後讀 `src/routes/user.ts`（又猜錯），最後才讀對的——這三次探索全部燒進 context window，每次燒幾千 token。直接 `@src/services/user.ts`，一次搞定，token 花在正確的地方。冤枉路省下的 token，就是你在 smart zone 裡多出來的空間。

為什麼「小成本換精確」划算：參照會花一點前置時間（agent 讀檔、燒一點 token），但換來的是它手上握著剛好正確的那份內容；不參照的版本是它自己翻目錄、猜檔名、讀錯檔再回頭，冤枉路燒的往往更多、結果更不可靠。LLM 的 parametric memory（參數式記憶）是模糊的——訓練資料被壓縮進參數裡，像一張模糊的 JPEG。你問它「user.ts 裡有什麼」，它可能根據壓縮後的模糊印象回答，而不是精確地列出每一行。直接把檔案內容放進 context window，才是可靠的資訊來源。

`@` 參照和「Explore」探索的邊界值得記住。`@` 參照是你告訴它讀哪個檔——精準、省 token，用在你知道答案的時候。Explore 是讓它自己找出相關檔——深、貴，用在你不確定的時候（之後 exploration 那一課會深入講 Explore sub-agent 的機制）。先養成「知道就 @ 給它」的習慣，探索是備用方案，不是預設選項。養成這個習慣之後，你會發現 prompt 的品質明顯提升——agent 讀到的是精確的檔案，而不是靠猜。
