# 怎麼把 context 當貨幣花

## Learning goal

用 sub-agent、status-line 監控、compact/clear、handoff 四招把 context 保持在 smart zone。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/context-economy/monitor-context|把 context 用量放在眼前]] — 安裝 status-line，用 raw token 數隨時盯住 smart zone
2. [[learn/ai-coding-for-real-engineer/nodes/context-economy/sub-agents|用 sub-agent 把探索成本外包]] — 把會燒 token 的探索委派給帶全新 context window 的 child agent，保住主 agent 的 smart zone（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/context-economy/compact-vs-clear|compact 與 clear：sediment 問題]] — 看懂 auto-compact buffer，知道重複 compact 為何是 anti-pattern（after step 1）
4. [[learn/ai-coding-for-real-engineer/nodes/context-economy/handoff|用 handoff 換一個乾淨的 context]] — 支線任務寫進暫存文件、換新 session 繼續，不 clear 也不撐大原 session（after step 3）

## Lesson

上一節解釋了「為什麼」：context 是二次方擴張的，裝越多，模型越接近 dumb zone。這一節把「為什麼」變成四招「怎麼做」。第一招是監控——先裝 status-line 讓 token 用量隨時可見，這是所有節約的前提，看不見就管不住。第二招是外包——把探索類工作交給帶全新 context window 的 sub-agent，讓它燒 token、只回傳摘要，你自己面前留著乾淨的 smart zone 給真正的實作。第三招是重置——真到了 context 邊緣，與其反覆 compact 讓「沉澱層」堆在 context 裡，不如 clear 後重來，寧可花一次重新探索的錢。第四招是換手——如果還有一條主線任務不能清掉，就把支線寫進暫存文件，換一個全新的 session 去接。四招合起來是一套紀律：context 是貨幣，只花在該花的地方。
