# PRD 變成 Kanban

## Learning goal

用 PRD-to-issues skill 把 PRD 切成帶 dependency 的垂直切片 issues，標出 HITL/AFK，並留下 QA checklist issue 收尾。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/kanban-backlog/prd-as-issue|把 PRD 搬進 GitHub issue]] — 把 PRD 和 plan 存成 issue，讓 agent 看到整個 backlog，人規劃與 agent 實作並行
2. [[learn/ai-coding-for-real-engineer/nodes/kanban-backlog/taste-divide|用 taste 分出留給人的部分]] — 用「taste」判斷哪些工作必須 HITL、哪些放手 AFK（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/kanban-backlog/kanban-over-plan|Kanban 勝過線性 plan]] — 解釋帶 blocked-by 的 issue 圖為何比線性 plan 更好擴充、更好 QA（after step 1）
4. [[learn/ai-coding-for-real-engineer/nodes/kanban-backlog/prd-to-issues-skill|PRD-to-issues：把 PRD 切成 issue]] — skill 的完整切法：垂直切片、標 HITL/AFK、串 dependency、留 QA issue（after steps 2–3）
5. [[learn/ai-coding-for-real-engineer/nodes/kanban-backlog/kanban-loop-run|實跑 Kanban loop 與手動 QA]] — 審查切片、讓 Ralph loop 只吃 AFK issues、用手動 QA 收尾（after step 4）

## Lesson

前一節的 issue 佇列解決了「agent 自己挑下一件工作」，這一節補上「工作從哪裡來」。關鍵動作是把手邊的 PRD 變成 GitHub 上的 Kanban board：把 PRD 當成一個 issue，再用 PRD-to-issues skill 把它切成一張帶 dependency（blocked-by）關係的 issue 圖。每個 issue 都是一個垂直切片（tracer bullet），並標明是 human-in-the-loop（需要人的 taste，例如架構決策、設計審查）還是 AFK（agent 可自行實作並 commit）；最後永遠留下一張 QA checklist issue，讓你能走開之後回來照著手動驗證。切割的判斷力來自「taste」這個框架——規劃與 QA 是人的工作，實作的苦工交給 agent。跑起來之後，AFK loop 只吃標成 AFK 的 issues，HITL 的部分留給人，形成「人規劃、agent 出貨」的並行迴圈。
