# Sandbox 與 AFK loop

## Learning goal
用 Docker/Podman sandbox 隔離 agent（避開 YOLO 風險），跑 main.ts 的 maxIterations + completion signal 迴圈。

## Steps

1. [[learn/ai-coding-for-real-engineer/nodes/afk-loop-sandbox/yolo-risk|為什麼放手前要先上 sandbox（權限、YOLO 與風險）]] — 說出權限請求為何擋住放手，拆開 YOLO 模式的三種危險，並排除 Claude 內建 sandbox
2. [[learn/ai-coding-for-real-engineer/nodes/afk-loop-sandbox/docker-sandbox-setup|Docker 沙盒（設定與冒煙測試）]] — 看懂容器隔離機制，照四步設定 Docker/Podman 沙盒並用 test.ts 冒煙測試（after step 1）
3. [[learn/ai-coding-for-real-engineer/nodes/afk-loop-sandbox/afk-loop-mechanics|main.ts（maxIterations 與完成訊號的迴圈）]] — 拆解 main.ts 與互動版的三個差異，說出兩個終止條件如何分工（after step 2）
4. [[learn/ai-coding-for-real-engineer/nodes/afk-loop-sandbox/afk-loop-run|AFK 迴圈實跑（兩圈迭代交付完整功能）]] — 走完兩圈迭代實跑，看懂完成訊號收尾與並行規劃的吞吐量意義（after step 3）

## Lesson

這一節把放手執行補齊最後兩塊，隔離與自動收尾。互動模式證明行為可靠以後，剩下的關卡是權限請求與執行節奏。權限請求讓人留在迴圈裡按鍵，直接拿掉又踩進 YOLO 模式的危險，解法是用 Docker 容器把 agent 關進與主機隔開的環境，讓它看得見 repo、碰不到主機。環境就緒後，main.ts 靠 maxIterations 與完成訊號兩個條件自己決定跑幾圈、何時停。四步走完，你手上有一套可以真正走開的執行方式，回來時拿到可以跑、有測試、已 commit 的成果。下一節把這套迴圈接到 GitHub issue 佇列，讓 agent 自己挑下一件工作。
