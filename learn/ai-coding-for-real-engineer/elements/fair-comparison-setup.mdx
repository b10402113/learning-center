# 公平比較的實驗設置（Fair Comparison Setup）

## Problem Statement

你剛拿到一個新 skill，想確認它是不是真的比之前的方式好。問題是 agent 的輸出高度受 context 影響，舊檔案、舊對話、舊計畫都留在裡面的話，你看到的結果可能是那些殘留物造成的，而不是 skill 本身造成的。要怎麼分辨「skill 變好了」和「剛好這次運氣好」？

## Why it matters

評估 agent 工具最怕的是先射箭再畫靶。context 裡躺著一份舊的 naive plan，agent 會讀它、改它、參考它，最後的輸出根本不是你測的那個 skill 的產出。乾淨的實驗環境是唯一能讓比較成立的前提，沒有這個前提，所有結論都是猜。

## How it works

測 PRD-to-plan 時，課程的設置是這樣：

1. 開一個全新的、零 context 的 session，不留任何舊對話。
2. 先把上一份 naive plan 檔案刪掉，讓 agent 無從讀取、也無從動手改它。
3. 把 PRD 用 `@` 帶進 prompt，呼叫「PRD to plan」。
4. 觀察產出的計畫，和之前的 naive plan 對比，看好在哪、還能不能更好。

刪掉舊檔這一手是關鍵。留著它，agent 會去讀去抄去改，你測到的是「會複製貼上的 agent」，不是你要測的 skill。

## In plain terms

換新釣竿之前，先把舊魚餌從池子裡撈乾淨。不然你分不出魚是吃新餌上鉤的，還是吃剩餌上鉤的。

## Practical use

往後每次要評估任何新的 skill、prompt 或工具，都用同一套姿勢，乾淨 session、清掉舊產物、只帶必要的輸入。把比較的條件寫進自己的檢查清單，讓「這次真的贏了」變成可重複的結論。

## Questions

### Q1. 為什麼比較兩個 skill 之前，一定要刪掉舊的計畫檔案？
A1. 因為 agent 的輸出受 context 影響，舊計畫留在視窗裡會被讀取、參考甚至修改，你測到的結果被殘留物污染，無法歸因給新 skill。

### Q2. 什麼樣的情況下，你對「某個 skill 有效」的結論不能信？
A2. 測試環境不乾淨的時候，舊檔案沒刪、對話沒清、輸入不只一樣東西。判斷的關鍵是結論能不能重現，不能重現的比較只是運氣。
