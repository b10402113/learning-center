# Phase Prompt（do phase N）

## Problem Statement

兩文件模型把大任務拆成 PRD + plan（見 [[learn/ai-coding-for-real-engineer/elements/two-document-model|兩文件模型 (Two-Document Model)]]），每個 phase 在一個新 context window 執行。但光有文件還不夠——新 session 的 agent 拿到文件後，怎麼知道「這次只做第 N 段，不是全部一次做完」？如果只是把 PRD 丟給它，它可能又想一次做完整個 build，又爆回 dumb zone。

## Why it matters

phase prompt 是把「拆解」和「執行」接起來的那個鉤子。沒有它，PRD + plan 只是擺著好看的文件，phase 之間照樣各自為政、踩來踩去。理解 phase prompt 的形態，才知道兩文件在實作階段是如何被實際消費的，也才接得上後面的 phased implementation 章節。

## How it works

執行每個 phase 時，prompt 的標準形態是：

```
we're going to do phase N
+ PRD（整份 destination）
+ 整份 plan（整個 journey）
```

關鍵有三點：

1. **明確指出現在做 phase N**：告訴 agent 這次的範圍是第 N 段，不是整個 build。
2. **帶上整份 PRD**：讓 agent 知道全局目標與 taste，避免偏離。
3. **帶上整份 plan**：讓 agent 知道自己這一段跟前後段怎麼接，phase 之間不會踩到彼此的腳。

之所以要帶「整份」而不只是「第 N 段」，是因為 agent 需要全局脈絡才能做出對的取捨，也才知道哪些東西已經被前一 phase 做過、哪些留給後一 phase。

## In plain terms

把 phase prompt 想成施工指揮。你有一張總藍圖（PRD）和一張工序表（plan），每天只做工序表上第 N 步。但你不會只把第 N 步那張紙給工頭，而是給他總藍圖加工序表，再告訴他「今天做第 N 步」，這樣他知道這一步為什麼存在、跟前後怎麼接。

## Practical use

在實作階段，你每完成一個 phase 就 clear context、commit，然後開新 session，丟「do phase N + PRD + 整份 plan」。這樣每個 phase 都從乾淨的 smart zone 開始，同時靠文件保持對全局的掌握。這正是 [[learn/ai-coding-for-real-engineer/elements/prd-structure|PRD 結構 (PRD Structure)]] 那兩份文件被實際消費的方式。

## Questions

### Q1. phase prompt 的三個組成是什麼？
A1. 明確指出做 phase N、帶上整份 PRD、帶上整份 plan，讓新視窗的 agent 知道範圍、目標與前後銜接。

### Q2. 為什麼要帶「整份」而不是只帶第 N 段？
A2. 因為 agent 需要全局脈絡才能做對的取捨，才知道哪些已被前一 phase 做過、哪些留給後一 phase，避免 phase 之間踩腳。
