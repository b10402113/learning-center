# Tracer Bullets（垂直切片）

## Problem Statement

LLM 天生橫著寫程式，先整個 database 層、再整個 service 層、再整個 UI 層。這種水平切法讓每一個 phase 都碰不到其他層，於是沒有任何東西能被驗證，直到很晚的 phase 才第一次見到整條鏈路動起來。feedback 來得越晚，錯誤越難定位，整套 build 走完才知道方向對不對。

## Why it matters

寫程式的人要的是盡早看到「整條鏈路能不能通」。垂直切片讓每個 phase 都穿過所有層，一開頭就能看到完整的功能在跑，架構對不對、整合點通不通，一次驗證完。這個概念本身很有名，短講就夠，LLM 一聽到就懂。

## How it works

「Tracer Bullets」出自 The Pragmatic Programmer。二戰防空砲兵裝上曳光彈，打一發看得到彈道，砲手能立刻調整。寫程式也一樣，每個 phase 都做一條穿過所有層的切片，用最簡單的資料打通全棧，先確認整條路走得通，再回頭補厚度。

在 analytics dashboard 的例子上，phase 1 就是一條貨真價實的 tracer bullet，把 analytics service、instructor route、summary cards 全部接起來，只用三個彙總數字當資料。做完這一 phase，你就知道整件事能動，unknown unknowns 也一併被沖出來。

## In plain terms

與其先蓋一層樓的地基再蓋一整面牆，不如先蓋一棟一樓高的小房子，每一層都有一間，走進去確定房子立得住，再往上加樓。

## Practical use

規劃 prompt 裡加一句「use tracer bullets / vertical slices」，配上短解釋就夠，agent 會直接照辦。驗收一個 phase 時，問自己這條切片是不是真的打通了所有層，還是只是某一個層的一整塊。

## Questions

### Q1. 水平切層和垂直切片，給 feedback 的時機差在哪裡？
A1. 水平切層要等到很晚的 phase 才第一次看到整條鏈路整合，垂直切片每個 phase 都穿過所有層，一開頭就有端到端的結果可以驗證。

### Q2. 為什麼「用最簡單的資料」也能算一條完整的 tracer bullet？
A2. 切片的目的不是做出成品，而是證明整條鏈路走得通、把 unknown unknowns 沖出來，用三個彙總數字就能做到，判斷的重點在路通了沒，不在資料有多豐富。
