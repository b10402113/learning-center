# 上下文窗口 vs 參數記憶，該信哪一個

## The relationship

模型能給你的答案來自兩個地方，一個是上下文窗口（context window，一次對話裡模型看得到的全部 token，也是它唯一的工作記憶；token 是模型處理文字的最小單位），另一個是參數記憶（parametric memory，把海量訓練資料壓縮成參數後留下的世界知識）。窗口裡的內容是原始、完整的，參數記憶是壓縮過的模糊 JPEG，所以前者可靠，後者 by design（刻意如此）不可靠。

## Why it matters

這兩者的可靠度差距，決定了你給 agent 餵資訊的方式。把重要的規格、API 簽名、業務規則交給參數記憶去扛，等於押在它最容易糊的地方；把這些東西放進窗口，才押在它唯一讀得準的地方。分不清這兩個來源，你就無法解釋為什麼 agent 有時背得出整段文件、有時卻把函式簽名講錯，也無法決定哪些資訊必須自己放進 prompt。

## When each applies

要拿「事實」時，優先從窗口要。把原始碼、文件、輸出用 @（在提示詞中參照檔案，讓模型讀進窗口）帶進對話，讓答案改由窗口內的原始資訊支撐，這是可靠路線。參數記憶適合拿「常識和模式」，生成樣板程式、判斷哪種寫法更符合慣例、補一句不影響正確性的語句，這些靠統計規律就夠。判斷的界線是，這個答案如果講錯會造成什麼後果。會影響決策的，放窗口；只是順手填空的，才交給參數記憶。兩條路線都受聰明區（smart zone，窗口前段推理還清楚的區間）限制，窗口本身塞太滿也會把可靠打折。

## Interleave

同一個問題，你分別「只靠參數記憶問」和「把原始碼放進窗口後問」各得到一個答案。兩者矛盾時，你憑什麼判斷該信哪個？反過來，什麼樣的問題連窗口都救不了，只能降低期望？
