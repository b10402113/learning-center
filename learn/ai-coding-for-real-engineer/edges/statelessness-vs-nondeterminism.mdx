# 失憶 vs 隨機，agent 不連續的兩種原因

## The relationship

模型有兩條不同的天性會讓你的工作經驗「接不上」，一條是無狀態性（statelessness，模型完全不保留跨 session 記憶，清空 context 一切歸零），另一條是非決定性（nondeterminism，每次生成都是從機率分佈裡抽樣，同樣輸入會得到不同輸出）。一個切斷的是時間上的記憶，一個切斷的是同一時刻的可重現性。

## Why it matters

這兩種現象都會讓 agent 看起來「壞了」，但修法完全不同。搞混它們，你會把「新 session 不記得昨天的決定」當成隨機故障重跑一遍，或者把「兩次跑出不同結果」當成記憶問題去餵更多資訊。先分辨是哪一種，才能選對手段。

## When each applies

判斷的方法是看變數。把 session 換掉（新開、/clear（清空上下文）之後重開），agent 不知道昨天講過的事，這幾乎都是失憶，是無狀態性。session 一樣、context 一樣、提示詞一字不差，跑兩次結果不同，這是非決定性。實務上兩者常常疊在一起，跨 session 的差異同時含兩者。補救各有各的去處。失憶要靠把知識寫進文件、CLAUDE.md（專案記憶檔）、handoff 備忘（把當前對話的關鍵摘要寫成文件，交給下一個 session），讓新 session 從看得見的地方重建；隨機要靠測試、型別檢查這類可驗證的成功標準把抽樣往好的一端收斂。見失憶補文件，見隨機補驗證。

## Interleave

你覺得 agent「變了」，一次是換了 session，一次是沒換。分別說明你該往哪條天性去想，各自的第一步動作是什麼。為什麼「重跑一遍」只對其中一種有效？
