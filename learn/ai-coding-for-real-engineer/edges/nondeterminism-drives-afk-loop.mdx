# 非決定性催生了 AFK 迴圈

## The relationship

非決定性（nondeterminism，agent 每次生成都是從機率分佈抽樣、同樣輸入會有不同輸出）是問題，AFK 迴圈（afk-loop，讓 agent 無人監督地一輪一輪重跑直到完成訊號的執行模式）是它的解法之一。既然單次輸出不保證對，解法就是把「一次做對」改成「循環檢查到對」，用明確的成功標準把抽樣往好的一端收斂。

## Why it matters

沒有這條關係，你會把 AFK 迴圈看成單純的自動化，覺得它只是把 agent 放著跑而已。看清它是為非決定性設計的，你才理解為什麼迴圈裡必須有測試、有型別檢查、有可驗證的完成定義，也才明白為什麼就算迴圈跑得很順，偶爾還是會出現一次怪異輸出。非決定性決定了解法的形狀。

## When each applies

任務結果能用自動檢查的標準判斷時，AFK 迴圈就有著力點，測試過不過、typecheck 過不過、檔案有沒有長出來、完成訊號有沒有觸發。這類任務適合放手讓迴圈收斂。任務結果只有人看得出對錯、或一次性的決策型工作，迴圈幫不上忙，得靠 HITL（human-in-the-loop，人在迴圈裡）盯緊，或靠更精準的規格壓低變異。兩者的分界在於，錯誤能不能被自動偵測。能自動偵測，放手；不能，留人。

## Interleave

同一個功能，一個版本你在場盯著 agent 一次做完，另一個版本你把任務丟進 AFK 迴圈讓它重跑到過測（測試全過才停）。用非決定性解釋為什麼後者對「殘留的怪異輸出」容忍度更高。如果這個任務的結果沒有可驗證的標準，AFK 迴圈會怎麼壞掉？
