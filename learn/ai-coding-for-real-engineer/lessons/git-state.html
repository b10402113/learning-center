用 reset / cherry-pick / pull 控制 git 狀態

Step 3/3 · 把環境跑起來

學習目標：用 pnpm reset（配對錄影的程式碼狀態）、pnpm cherry-pick（保留自己的改動）、pnpm pull（同步上游修復）控制 playground 的 git 狀態，並把 merge conflict 交給 Claude。

為什麼需要控制 git 狀態

每一支錄影練習都對應一顆特定 commit。你必須能把 repo 對齊到那顆 commit，才能跟著錄影一起做。但「對齊」有三種不同意圖：

意圖 做法
完全配對錄影，不在乎自己之前的改動 pnpm reset
配對錄影，但保留自己的改動 pnpm cherry-pick
只想拿上游修復，不動其他東西 pnpm pull

課程用三支 pnpm 命令分別包裝這三種意圖，底下都是 git 操作。

pnpm reset——配對錄影

pnpm reset

這是最暴力的選項。它會破壞性重置到選定的錄影 commit，把你的 branch 拉回那個時間點。你在那個 commit 之後加的任何東西——npm script、額外檔案、實驗性改動——全部會被刪掉。

注意：pnpm reset 不能直接 reset main 分支。你得先開一個新 branch，再在那個 branch 上 reset。這是 git 的安全機制——main 是保護分支。

什麼時候用？當你想完全從錄影的起點開始，不在乎自己之前做過什麼。最常見的場景是你改壞了想從頭來。

pnpm cherry-pick——保留自己的改動

pnpm cherry-pick

這個選項更溫和：它保留你現有的工作，把目標 commit 的改動疊過來。你的改動不會消失，但代價是可能產生 merge conflict（合併衝突）。

Merge conflict 聽起來可怕，但它是完全正常的 git 行為：兩邊改了同一個檔案的同一行，git 不知道要用誰的版本。你有三個選擇：

  1. 交給 Claude——說「Claude fix this merge conflict for me」，它很會處理這個
  2. 手動解決——打開衝突檔案，看你想要哪個版本
  3. 放棄——git cherry-pick --abort 退回原狀，什麼都沒發生
類比：想像你在翻譯一本書。有人同時在改同一章的同一段。Cherry-pick 就是把他的版本疊在你的版本上面，然後你得決定「這段到底用誰的」。衝突就是兩邊都改了同一句話。

pnpm pull——同步上游修復

pnpm pull

當講師修了課程 repo 的 bug、或加了新的練習素材，你想把這些上游修復帶進你目前的 branch 時，用 pnpm pull。它會 fetch 並合併上游的改動，但不會 reset 你的狀態。

跟 cherry-pick 一樣，pull 也可能產生 merge conflict。處理方式一樣：交給 Claude 或手動解決。

決策樹

你要什麼？ 用哪個？ 注意事項
完全配對錄影 pnpm reset 會刪掉你的改動；不能 reset main
配對錄影 + 保留改動 pnpm cherry-pick 可能有 conflict；交給 Claude 解
只拿上游修復 pnpm pull 可能有 conflict；交給 Claude 解

遇到衝突一律交給 Claude

這是一個重要的模式：merge conflict 不是麻煩，它是 git 的正常行為。而 Claude 非常擅長處理衝突——它能讀懂兩邊的改動，理解意圖，做出合理的選擇。你只需要在遇到衝突時說一句「Claude fix this merge conflict for me」。

這也是為什麼課程不教你自己解衝突——在 AI coding agent 的工作流裡，解衝突是 agent 的活。

小結

三支命令：reset（完全對齊，刪改動）、cherry-pick（對齊 + 保改動）、pull（只拿修復）。遇到衝突一律交給 Claude。這三支讓你能自由切換到任何錄影練習的起點。
