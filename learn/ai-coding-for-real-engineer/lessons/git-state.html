用 reset / cherry-pick / pull 控制 git 狀態

Node 1 · git-state · 讓 repo 對齊錄影，同時保住你的改動

Learning goal

用 pnpm reset（配對錄影的程式碼狀態）、pnpm cherry-pick（保留自己的改動）、pnpm pull（同步上游修復）控制 playground 的 git 狀態，並把 merge conflict 交給 Claude。

為什麼需要三個命令

每一支錄影練習都對應一個特定的 commit。你必須能把 repo 對齊到那顆 commit 才能跟著做。但「對齊」有三種不同意圖，課程用三支 pnpm 命令分別包裝：

命令意圖對你的改動風險
pnpm reset配對錄影的程式碼狀態刪掉無關的工作破壞性，無法挽回
pnpm cherry-pick保留自己的改動保留可能產生 merge conflict
pnpm pull同步上游修復保留（不 reset）可能產生 conflict

pnpm reset：破壞性對齊

pnpm reset 把你的 branch 破壞性重置到選定的錄影 commit——它會刪掉無關的工作（例如你自己加的一個 npm script 就沒了）。兩個重點：

  • 它不能直接 reset main——你得先開一條新 branch 再重置。
  • 用之前想清楚：這是唯一真的會抹掉你工作的地方。

pnpm cherry-pick：保留自己的改動

如果你已經在 branch 上做了自己的改動、又想對齊到錄影的 commit，用 pnpm cherry-pick——它保留現有工作，把目標 commit 疊過來。代價是可能產生 merge conflict。

衝突不是麻煩，是機會：Claude 很會解衝突。你只要說「Claude fix this merge conflict for me」，或卡死時 git cherry-pick --abort 退回原狀。

pnpm pull：同步上游修復

當講師修了課程 repo 的 bug、你希望把上游修復帶進你目前的 branch 時用 pnpm pull——它 fetch 上游變更並合併，不會 reset 你的狀態。萬一衝突，一樣交給 Claude。

決策樹

想對齊錄影的程式碼狀態？
├─ 不在乎自己的改動 → pnpm reset（開新 branch，破壞性）
├─ 想保住自己的改動 → pnpm cherry-pick（衝突交給 Claude）
└─ 只想拿上游修復   → pnpm pull（不動自己狀態）

遇到 merge conflict → 交給 Claude，或 git cherry-pick --abort
