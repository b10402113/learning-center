選好你的 agent 與訂閱

Step 3/3 · 七階段流程是什麼、為什麼有效

學習目標：用 tiering 原則幫自己的訂閱選出課程要用的 model：用訂閱的預設模型、選 medium effort、避開 Haiku，並理解頂/中/入門三級在各 provider 都成立。

不要記名字，記 tiering 原則

模型名稱會一直換（課程錄完後教練就發過補充），但每個 provider 都有三級：

等級 Claude 其他 Provider 特點
Opus 級（頂） Opus 4.6 GPT-4o、Gemini 1.5 Pro 等 最聰明、最貴
中階級 Sonnet 4.6 GPT-4o mini、Gemini 1.5 Flash 等 夠用、平衡
Haiku 級（入門） Haiku GPT-3.5、Gemini Flash Lite 等 便宜、但不夠力

所以做法是：用你訂閱方案的預設模型，在 Claude Code 用 /model 確認即可。不要手動去換名字，預設就是你的方案能給的最好平衡。

三個決策清單

  1. 看你的訂閱 → Max 5x 的預設是 Opus 級，Pro 的預設是 Sonnet 級
  2. 用它的預設 → 不要手動換模型名稱
  3. 確認 effort 是 medium → 跟著 harness 的預設走

教練觀察到 harness 把 Opus 的預設從 high 調回 medium，因為內部評估發現 medium 對大部分工作就夠了。所以 effort 你只要不動它就好。

避開 Haiku

課程三令五申避開 Haiku：它快但不夠力，扛不住課程要丟給它的一些工作流。Haiku 級的模型在 Grill、research、implement 等需要深度推理的階段會明顯吃力。如果你的訂閱預設是 Haiku 級，你需要升級方案。

為什麼不用最低階的？因為七階段流程裡，grill 需要深度理解你的需求、research 需要正確的技術判斷、implement 需要寫出能跑的代碼——這些都不是 Haiku 級模型能穩定做到的。用 Haiku 跑，你會花更多時間在修 agent 的錯誤上，反而更慢。

課程用什麼、你用什麼

情境 推薦方案 說明
課程打造環境 Max 5x + Opus 課程是用這個打造的，最完整的體驗
預算有限 Pro + Sonnet 「Pro 應該過得去」，可能偶爾撞 usage limit
其他 harness harness-agnostic 任何跑在 CLI 裡的 coding agent 都能套用

課程 demo 用 Claude Code 只是因為它流行、教練每天在用。任何跑在 CLI 裡的 coding agent 都能套用同一套七階段流程——這才是可遷移的東西。

小結

選 model 的核心原則：用訂閱的預設模型、effort 選 medium、避開 Haiku。三級（Opus 級/中階/入門）在所有 provider 都成立。模型名稱會變，tiering 原則不會。
