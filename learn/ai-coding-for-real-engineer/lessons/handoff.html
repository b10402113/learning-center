用 handoff 換一個乾淨的 context

Node 6 · context-economy · Step 4/4 · 支線任務寫進暫存檔，換新 session 接

Learning goal

當 session 中途冒出需要獨立處理的支線任務時，用 handoff skill 把任務寫進暫存 markdown，在一個全新 session 裡繼續，不 clear 也不撐大原 session。

情境：主線進行到一半，支線冒出來

你在做一件大事（藍色任務），中途發現一個 bug 或一個壞掉的 test（黃色任務）。這下兩難：

  • 在目前 session 順手修？你根本不知道要花多久，可能把主線的預算燒光。
  • clear 清掉重來？不行——藍色任務還要做完，你不能把主線脈絡丟掉。

而且黃色任務其實根本不需要藍色任務的完整脈絡——它只是碰巧在藍色 session 裡被發現而已，它自己的 context window 就夠用了。

handoff：寫一張交接單，開新 session 去接

這正是 handoff skill 存在的理由。它把目前的對話濃縮成一張暫存 markdown，讓一個全新的 agent session 可以接著做。做法是：

  1. 寫一份 handoff 文件，摘要目前的對話——這樣新 agent 能接手。
  2. 存到 make temp -t handoff 產生的暫存路徑（在暫存目錄裡，不弄髒 repo）。
  3. 如果下一步要用 skill，在文件裡建議該用的 skill（例如「繼續 GrillMe」）。
  4. 不重複複製其他文件裡已有的內容——只放連結。
  5. 如果你傳了指令，就把文件對準新 session 的焦點量身訂做。

核心洞察：藍色任務留在自己的 context window 自由成長，黃色任務在全新的 context window 裡完成——兩個都不必 clear、都不必硬塞同一個 window。

兩個典型用法

用法一：修壞掉的 test。實作別的功能時發現某個 test 是壞的，對 agent 說「handoff，開個獨立 session 去修那個 test」，它生成一份文件，你把它丟進新 session 就搞定，主線完全不受影響。

用法二：grilling 卡在 dumb zone。長 GrillMe session 走到一半發現某個小分支需要深挖——handoff 到新 session 去專門 grill／做 prototype／做 research，燒掉大量 context 之後，再把學到的濃縮成一張文件 handoff 回主 session。

這就開啟了講師所說的 expand-then-contract（擴張再收縮）流程：文件在 session 之間遞來遞去，每個 session 用完即可拋棄。handoff 就是「grilling session 進到 dumb zone 該怎麼辦」的標準答案。

跟 compact/clear 的取捨

compact 會堆 sediment、clear 會丟主線脈絡——handoff 是第三條路：不縮小、不刪除，而是把支線整個搬到一個新 window。主線原封不動，支線自己成長。session 變成可壓縮、可拋棄的工作單位。
