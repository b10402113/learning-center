Smart Zone 與 Dumb Zone

學習目標：說出 context 被填滿後會發生什麼（推理變差、幻覺、召回失敗），並用 token 門檻（約 80k–100k token）判斷 agent 何時開始進入 dumb zone。

上一步的延伸：填滿不是免費的

上一課看到注意力成本隨 token 二次方成長。如果代價只是「變貴」，那大不了多付錢；但真正的殺手是——塞太滿之後，模型會變笨。填進 context 的內容超過某個量級，輸出的品質會開始崩壞。這就是本課的主角：smart zone 與 dumb zone。

Smart Zone 與 Dumb Zone

課程把 context window 的狀態切成兩段：

Smart ZoneDumb Zone
推理清晰、有條理退化、答非所問
事實幾乎沒有幻覺開始編造
召回抓得到早前細節召回失敗、忘了前面講過什麼

關鍵不是「塞滿那一刻突然壞掉」，而是漸進式的退化：context 越多，attention 被稀釋，模型愈難同時顧好所有內容，於是愈容易顧此失彼。開頭很聰明的 agent，聊到後來變笨——多半就是從 smart zone 滑進了 dumb zone。

核心概念 Dumb zone 的三個症狀：推理變差、幻覺、召回失敗。 這不是模型壞掉，而是把 context 塞太滿的正常後果。

門檻在哪：80k–100k token

課程給了一個可操作的判斷線。教練的原話是「大約在 40% 的時候開始緊張」——他錄課時用的是 200k 的窗口，40% 就是約 80k token。後來主流窗口已經長到 1M token，但「smart zone 大概在 80k–100k 個原始 token 左右」這條線仍然適用。

一句話記法 用 token 數、別用百分比。 窗口越大，「40%」代表的絕對量越驚人；直接盯 80k–100k 這個絕對門檻最可靠。

為什麼不看百分比？因為窗口從 200k 長到 1M，同一百分比（例如 40%）代表 80k 或 400k token，品質的意義完全不同。1M 窗口裡 30% 早就超過 dumb zone 門檻了，還覺得「才三成很安全」就會踩雷。

怎麼知道自己逼近門檻

手上要有儀表板：Claude Code 用 /context 看目前消耗，或裝 status-line 套件讓百分比常駐顯示；Cursor、OpenCode 這類工具預設就把 context 用量畫在介面上。看到逼近 80k–100k，就該清 context（/clear）或 compact，讓它回到精簡、回到 smart zone。

這條門檻也是整個課程後面所有「context 經濟學」技巧的根：sub-agent 幫你燒探索的 token、compact 壓縮對話、handoff 換一個乾淨窗口接手——全都是為了把主窗口留在 smart zone 內。
