用 IDE 檢視與核准 diff

Step 1/4 · review diff、bash、風險控管

學習目標：用 /ide 啟動 IDE 整合，在 VS Code 檢視 rich diff，並用「Accept Proposed Changes」或直接存檔核准 agent 的編輯，把 review 變成上線前的 HITL 閘門。

終端 diff 的痛點

Claude Code 預設在終端機裡顯示 diff。想像一下：白底黑字、沒有對齊、長行跑出畫面、改了十個檔案要一行一行捲——對「review agent 改了什麼」是致命的。因為看不清楚就等於沒有 review。如果你看不清 agent 做了什麼，你要嘛全部接受（等於盲信），要嘛全部拒絕（等於沒用 agent）。兩個都不對。

所以你需要把 diff 搬進一個真正的 IDE——VS Code、Cursor、Windsurf 都行——在那裡 diff 是可捲動、可逐行對照、有顏色標記的 rich diff。

用 /ide 啟動整合

啟動方式很簡單：在 Claude Code 裡打 /ide。它會顯示連線狀態，如果還沒裝 extension，會引導你安裝對應的 VS Code 擴充套件。裝好之後，agent 每次產生 diff，就會直接出現在 IDE 的 diff 視窗裡。

步驟 做什麼
1 在 Claude Code 輸入 /ide
2 如果還沒裝 extension，按指示安裝
3 Agent 產生 diff 時，IDE 自動跳出 rich diff 視窗
4 逐行檢查 → 按 Accept Proposed Changes 或 Ctrl-S / Cmd-S 存檔

關鍵概念：存檔就等於同意這份 diff。沒核准就不算數。這就是一個人類在迴路中的閘門（HITL gate）：agent 可以提議任何改動，但只有你按下核准的那一瞬間它才生效。

類比：你請了一個裝修工人（agent）幫你改房間。他改完之後不是直接走——他把修改清單（diff）攤在你面前，你逐項看過，同意的打勾，不同意的退回。存檔 = 打勾，沒打勾的改動不算數。

為什麼在 VS Code 裡跑 Claude Code？

課程 demo 都在 VS Code 的整合終端跑 Claude Code。原因不是「VS Code 比較好」，而是：偶爾你會想潛進去微調 agent 的輸出——改一個變數名、調整格式、手動修一個 import——這些事在真正的 IDE 裡做遠比在終端舒服。review diff 這種事尤其如此：IDE 的 diff 視窗是為了這件事設計的，終端不是。

Review 是所有信任的地基

這是本 node 的第一步，也是之後所有控制機制的地基。後面你會學到：改壞了怎麼倒帶（rewind）、怎麼控制 agent 看得到什麼輸出（bash mode）、怎麼管住它能跑什麼命令（permissions）。但這一切的前提都是——你能夠清楚地 review agent 做了什麼。看不清楚，其他控制都沒意義。

口訣：看得清楚，才敢放手。用 /ide 把 diff 搬進 IDE，存檔 = 核准，沒核准 = 沒生效。這是 HITL 閘門的第一道。
