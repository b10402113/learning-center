非決定性：同一個 prompt 每次不同

學習目標：說出 agent 是從機率分布抽樣選下一個 token 的非決定性機器，因此同樣的指令每次可能給出不同結果，並據此調整期待。

前兩課講記憶，這一課講機器本身

前兩課的約束都跟「記住什麼」有關。這一課換一個軸：即使你完全不管記憶問題，agent 本身也不是一台確定的機器。同一個 prompt、同一個檔案、同一天，它可能給你不同的結果——這不是 bug，是它的設計。

Next-token 抽樣機

LLM 產生文字的方式是逐 token 生成：在每一個時間點，它算出整個詞表裡每個 token 的機率分布（哪個字最可能接在後面），然後從這個分布抽樣選出一個。抽樣帶有隨機性——一個機率 30% 的 token，十次裡大致會被抽中三次。

核心概念 Agent 不是「算答案」，是「抽答案」。 它從下一個 token 的機率分布裡抽樣，所以同樣的指令跑兩次，走的軌跡可以完全不同，最後的結果也不同。

證據：整班人跑同一個作業

課程第一次開跑時，約 2,500 位學生跑完全相同的練習。結果是：有些人手上的 agent 行為和教練的示範天差地遠——有人一次到位，有人繞了好大一圈，有人做出不同的實作取捨。這不是學生操作錯，而是非決定性內建在每個 agent 裡，規模越大越明顯。

所以當你照著課程做，agent 卻沒有複製出教練的示範時，先別慌：差很多是常態。重點不是「為什麼它不聽話」，而是「結果有沒有對」。

但也不是完全沒救

非決定性不代表無序。後面的課程（尤其 AFK 階段）會用 feedback loops 把它拉向一致：讓 agent 跑測試、過 typecheck，對的就留下，錯的再修——驗證的是結果，不是逐字輸出。有了這層回饋，不同軌跡會收斂到同一個正確終點。

一句話記法 期待結果正確，不要期待結果每次都一樣。 用測試當裁判，而不是用「對照示範逐字比對」。

調整你的期待

把這條約束接回你的工作方式：

  • agent 第一次給的答案不代表「唯一答案」，也別當成「標準答案」。
  • 結果不如預期時，先驗證（跑測試、看實際檔案），不要直接質疑「它是不是壞了」。
  • 想要更穩定，就多給它可靠的 feedback loop，而不是祈禱它這次別發神經。
