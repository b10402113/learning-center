天真 prompt：先看看它給多少

Node 7 · exploration · Step 2/4

Learning goal

用「告訴我這 repo 的 tech stack 和用途」當開場 prompt，並用 Ctrl-O 觀察它只讀幾份檔案、不會 spawn sub-agent 的淺層覆蓋。

練習：用最直覺的問法開場

上一課我們知道探索是第一個動作。那實際怎麼問？課程的練習從一個最天真、最直覺的 prompt 開始：

Tell me what the tech stack of this repo is and what its intended purpose is.

「告訴我這個 repo 的 tech stack 和它的用途」——沒有任何花俏詞彙，就是你會隨口問出來的那種問法。先別改措辭，先看看它給多少。

用 Ctrl-O 進入 verbose 模式

答案不只是看它回你什麼，還要看它做了什麼。在 Claude Code 的 UI 按 Ctrl-O 可以展開成 verbose 模式，顯示這個 agent 跑過的每一條 bash command、讀過的每一個檔案。

展開後你會看到它的整個動作軌跡：搜了哪幾個 pattern、讀了哪些檔、跑了什麼指令。這是觀察 agent 行為的第一個工具——不看它做了什麼，你就不知道它到底「懂」了多少。

觀察結果：淺層覆蓋

用這個天真 prompt 跑一次課程 repo，agent 的表現是：

  • 搜尋了 2 個 pattern
  • 讀了 6 個檔案
  • 給出一份簡短 summary，包含 tech stack 清單
  • 沒有 spawn 任何 sub-agent

「它只讀了六個檔案，這不會給我這個 repo 在發生什麼事的完整 breakdown。」——課程原文。讀 6 個檔案可以交差，但離「擁有這個 repo 的 mental model」還很遠。

關鍵觀察點：這個 prompt 沒有觸發子代理。agent 用自己（orchestrator）的 context 淺淺掃過幾份檔案就回答——它給了你一份「看起來合理」的摘要，但沒有真的把整個 repo 讀進去。這正是淺層探索（shallow coverage）的長相。

為什麼這個結果很重要

你要養成的習慣是：把探索當成一個可觀察的過程，而不是一個答案。第一次問，記住它讀了幾個檔案、有沒有 spawn sub-agent；然後在下一課用一個字眼徹底改變這個結果。現在你知道基準線長什麼樣了。
