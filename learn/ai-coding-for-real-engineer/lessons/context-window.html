Context Window 與二次方擴張

學習目標：說出 context window 是什麼、token 之間注意力怎麼二次方成長，並理解為什麼把越多內容塞進 context 會讓模型越吃力。

「agent 為什麼變笨」的第一塊拼圖

你可能遇過這種情況：agent 開頭很聰明，愈聊愈笨；或者你把整份 repo 丟給它，它反而開始答非所問。這不是它偷懶，而是它被四條硬性約束綁住——而第一條、也是最根本的一條，就是 context window。這一課先把這條約束講清楚，後面的課再補上另外三條。

Context Window 是什麼

Context window（上下文窗口）是模型在單一次 request 裡看得到的所有內容：你的 prompt、系統提示、被 @ 參照讀進來的檔案、agent 執行工具（跑測試、讀檔）的回傳結果、整段對話歷史。這些全部擠在同一個窗口裡，模型只能憑這個窗口裡的東西作答。

核心概念 Context window 是工作記憶，不是長期記憶。 窗口外的一切對模型而言不存在；它不像你有硬碟或記憶庫，可以「回想」上一次 session 聊過什麼。

這也解釋了為什麼 @ 參照檔案要「花成本」：每個被參照的檔案都會被讀進 context window，佔掉珍貴的空間。工具輸出、bash 回傳的日誌也一樣，全部落進同一個窗口。

注意力為什麼二次方成長

現代 LLM 的核心機制是 attention（注意力）：讓每個 token 都去「看」其他每個 token，找出彼此的關係。注意力的成本不是線性成長，而是兩兩配對——有 n 個 token，就要處理大約 n×(n−1)/2 組關係。

看清楚這個成長的形狀：token 數翻倍，關係數暴增四倍左右。你多塞一個 token，它要跟所有既有的 token建立關係；而既有每個 token 也要跟它建立關係。所以「再加一行說明」的成本，遠比你想的貴。

一句話記法 Context 越大，注意力越貴。 關係數約是 token 數的二次方，塞越多越吃力——這不是玄學，是數學。

這對實務代表什麼

把這個機制接回你手上的工具：/context 顯示的就是你現在塞了多少 token、燒掉了窗口多少空間。每個被 @ 參照的檔案、每次工具輸出，都是往這個二次方成本裡加燃料。

所以第一條實務鐵律是：只把必要的東西放進 context。 不需要的檔案別 @、跑完的長日誌該清就清、無關的對話歷史該斷就斷。因為下一課會看到：當你把它塞到某個量級，模型的推理品質會開始崩壞——那就是「dumb zone」。

下一步：context 塞滿後會發生什麼——進入「Smart Zone 與 Dumb Zone」。
