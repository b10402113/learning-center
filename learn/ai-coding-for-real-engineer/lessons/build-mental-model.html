把發現長成自己的 mental model

Node 7 · exploration · Step 4/4

Learning goal

用準備好的 follow-up 問題追問 agent，把探索回傳的片段發現轉成自己對 repo 完整且可操作的 mental model。

summary 是 sub-agent 的，mental model 才是你的

Explore sub-agent 回傳的是一份濃縮的 summary——它燒了 64k token 換來的洞察濃縮成幾段文字回到 orchestrator。這份 summary 不是你的 mental model。它是別人的（一個子代理的）理解壓縮，而你對 repo 的理解，還是一張白紙。

課程的練習指令講得很清楚：當 agent 回傳一段回應，query it and ask it some more questions——繼續問它、看接下來發生什麼。探索不是問一次就結束的單次動作，而是一段追問的對話。

follow-up 問題：把片段發現接成完整認知

怎麼問？課程給了一批預先準備好的問題（exercise 下方的 question list），方向大致是：

  • 這個 repo 的核心功能流程是怎麼串的（purpose 的具體化）？
  • 資料模型長什麼樣、source of truth 在哪？
  • 程式碼是怎麼分層的（routes / services / data access）？
  • 慣例有哪些（命名、測試、狀態管理）？
  • 如果我要加一個 feature，會動到哪些檔案？

每一個 follow-up 都在把上一份 summary 的「片段發現」焊進你的腦海——不只是「知道 repo 有這些東西」，而是「我理解它怎麼拼在一起、下一步改哪裡」。這才是可操作的（actionable）認知。

課程的收尾提醒：繼續跑任何你想跑的 exploration commands 來加深理解，因為「soon we're going to be getting to building features」。探索不是為了炫耀知道 tech stack——是為了接下來的實作有個可靠的落點。

一個可重用的節奏

把整個 node 串成一個可重用的節奏：

  1. 開場：天真 prompt（Tell me tech stack）看基準線
  2. 換字眼：用「Explore + 具體主題」叫出 deep sub-agent
  3. 追問：用 follow-up 問題把 summary 展開成自己的 mental model
  4. 收尾：確認「我理解它怎麼拼在一起、feature 會動到哪」

到這一步，你才真正「擁有」這個 repo——而不是收到一份摘要。
