用 @ 精準參照檔案

ai-coding-for-real-engineer › agent-basics › file-references

學習目標：用 @ 加上下鍵與 tab 參照特定檔案，並理解被參照的檔案會自動被讀進 context window，用小成本換取 agent 需要的精確資訊。

問題：不要讓 agent 用猜的

你給 agent 一個任務：「改這個檔的登入邏輯」。它要做的第一件事就是去找「這個檔」是哪個——是 auth.ts？services/auth.ts？還是 utils/login.ts？你省略掉的資訊，它就用探索去補，而探索燒的正是你最珍貴的資源：context window。

更糟的是，LLM 是不可靠的記憶體。與其讓它猜你在講哪個檔、然後讀錯檔案，不如直接把它指到正確的檔。

動作：@ 加上下鍵 + tab

在輸入框打一個 @，就會跳出檔名補全清單：

  • 上下鍵——在候選檔名之間移動
  • tab——接受選中的檔名

被參照的檔案會自動被讀進 context window。這就是關鍵：你不是給 agent 一個「檔名提示」，你是把整份檔案內容直接放進它眼前。

@services/auth.ts 幫我把這個檔的登入邏輯改成支援 email 登入

為什麼「小成本換精確」是划算的

參照檔案會花掉一點前置時間（agent 讀檔、token 燒掉一些），但換來的是 agent 手上握著「剛好正確的那份內容」。對比另一種世界：不參照，agent 自己去翻目錄、猜檔名、讀錯檔、再回頭……這些冤枉路燒的 token 往往比直接讀對檔多得多，而且結果更不可靠。

這背後的原理就是課程反覆強調的：context 要精準，不要靠模型猜。你自己知道哪個檔最關鍵，就讓它只裝那一個。

參照不等於探索

注意一個邊界：@ 參照是「我告訴你讀這個檔」，探索是「你去找出相關的檔」。兩者都是把內容裝進 context，但意圖不同——前者精準、省 token、用在你知道答案時；後者深、貴、用在你不確定時（那是另一課的「Explore」sub-agent）。先養成「知道就 @ 給它」的習慣，再學什麼時候該放手讓它探索。
