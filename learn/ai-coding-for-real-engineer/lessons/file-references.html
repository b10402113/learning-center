用 @ 精準參照檔案

Step 3/4 · 怎麼開車

學習目標：用 @ 加上下鍵與 tab 參照特定檔案，並理解被參照的檔案會自動被讀進 context window，用小成本換取 agent 需要的精確資訊。

問題：agent 不知道你要它看哪個檔

當你給 agent 一個 prompt，例如「幫我修 UserService 裡的 bug」，agent 會怎麼做？它會自己去翻目錄、猜檔名、讀錯檔、再回頭——冤枉路燒的是你最珍貴的資源：context window 裡的 token。

更好的做法是你直接告訴它讀哪個檔。這就是 @ 檔參照的用途。

@ 參照的操作方式

  1. 在輸入框打 @——跳出檔名補全選單
  2. 用上下鍵移動選取
  3. 按 tab 接受——被參照的檔案會被自動讀進 context window

你不是給它一個「檔名提示」——你是把整份檔案內容直接放進它眼前。這很重要，因為 LLM 是不可靠的記憶體（parametric memory 是模糊的），你省略「這個檔是哪個」，它就靠探索去補，而探索燒的 token 往往更多、結果更不可靠。

為什麼「小成本換精確」划算

方式 成本 結果
@ 參照 一點前置時間（讀檔、燒 token） agent 手上握著剛好正確的那份內容
不參照 agent 自己探索（猜、讀錯、回頭） 冤枉路更多、結果更不可靠

一個具體場景：你想讓 agent 修改 src/services/user.ts 裡的某個函數。不參照的話，它可能先讀 src/models/user.ts（猜錯），然後讀 src/routes/user.ts（又猜錯），最後才讀對的——這三次探索全部燒進 context。直接 @src/services/user.ts，一次搞定。

@ 參照 vs Explore 探索

你可能聽過「Explore」關鍵字（之後 exploration 那一課會深入講）。兩者的邊界：

  • @ 參照：你知道答案時用——精準、省 token，「我知道要讀這個檔」
  • Explore：你不確定時用——深、貴，「幫我找出相關的檔案」

先養成「知道就 @ 給它」的習慣。探索是備用方案，不是預設選項。

小結

@ 檔參照：打 @ → 上下鍵選 → tab 接受。被參照的檔案自動讀進 context window。用小成本換精確資訊，比讓 agent 自己探索可靠得多。
