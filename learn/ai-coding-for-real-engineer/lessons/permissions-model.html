用 permissions 設定管住風險

學習目標：理解 risk/reward 權衡，用 .claude/settings.local.json 的 permissions.allow/deny（含 wildcard）與 settings.json 預授權命令，並管控 web 存取等風險，避免 agent 造成災難性動作。

風險 vs 報酬：給 agent 多少權力？

跟 agent 合作的第一個問題不是「它多聰明」，而是你願意讓它有多大權力。如果你把無限權力交給 Claude（很多人真的這麼做），你就會合理地緊張——怕它不小心把整個檔案系統刪掉。這是 risk/reward 的權衡：權力越大、能交付的越多，但出事的後果也越大。

Claude Code 的解法是一套很詳細的 permissions 模型，預設對自己非常嚴格，避免災難性動作。

核准流程長什麼樣

當 Claude 想跑一個命令（例如 typecheck），它不會直接跑，而是先請求核准。請求裡會顯示：

  • 要執行的確切命令（例如 pnpm typecheck）
  • 它想跑的原因

然後你有幾個選項：

  1. 允許這次（yes，只允許一次）
  2. 以後都允許（yes，這個專案內以後跑同樣命令不用再問）
  3. 否決，或按 Tab 建議另一個命令（例如叫它用 npx tsc 代替 pnpm typecheck）

注意有些命令（例如 echo hello）被認定極度安全，會直接跑，連問都不問。

你的選擇被記在哪裡

你的核准會被記錄到一個檔案：

.claude/settings.local.json

裡面有 permissions.allow（允許的清單）和 permissions.deny（禁止的清單）兩個陣列。你也可以自己手動編輯這個檔，預先授權：

{
  "permissions": {
    "allow": ["Bash(pnpm typecheck)"],
    "deny": ["Bash(git push:*)"]
  }
}

Wildcard：一次授權一整類

如果你想允許「所有 pnpm 命令」，不必逐條列出，用 wildcard：

"allow": ["Bash(pnpm:*)"]

同理，deny 也可以加 wildcard——例如絕對不讓它 git push，就寫 Bash(git push:*)。

語法關鍵 allow / deny 陣列裡的規則用「命令 + wildcard」描述，自己編輯檔案就能提前放行或封鎖整個類別。

不只是 bash：web 存取也被管控

Claude Code 不只跑命令要權限，搜尋網路、抓取網頁也一樣受控。例如要它上網查 react-router-typegen 的文件，它會先請求做一次 web search；你核准後，它才真的去抓文件、回報摘要。

這代表「agent 上網」也是你該管的風險面——不是只有刪檔才算危險。

個人設定 vs 團隊共用

預設的 settings.local.json 通常在 .gitignore 裡，只對你個人有效。如果你想讓團隊共用一套「這個 repo 固定允許的命令」，只要把它改名成 settings.json：

  • 任何在這個 repo 上跑的 Claude 實例都會自動吃到這套規則
  • 新人第一次進 repo 就跑得起來，不用每次手動核准

這就是 repo 層級的 agent 設定種子——預授權一套已知安全的命令，省去每次跟安全提示搏鬥。

小結

  • 風險 vs 報酬：給 agent 的權力越大，能交付越多但風險越大
  • Claude Code 預設嚴格，跑命令前請求核准（顯示命令 + 原因）
  • 核准記錄在 .claude/settings.local.json 的 allow/deny，支援 wildcard
  • Web search/fetch 同樣受控
  • 改名 settings.json 即可讓團隊共用規則
