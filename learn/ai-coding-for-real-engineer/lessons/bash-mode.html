用 bash 模式控制 agent 看得到的輸出

Step 3/4 · review diff、bash、風險控管

學習目標：用 ! 進入 bash mode、Ctrl-B 背景化長命令、Ctrl-Z 掛起 Claude 執行隱藏命令、fg 恢復，並依決策樹決定該讓 agent 看到哪些輸出。

從被動碼農到能互動的夥伴

如果 agent 只能寫代碼不能跑命令，它就像一個只會畫藍圖但不能試裝的建築師。Bash 模式讓 agent 從「被動的碼農」變成「能跟專案互動的夥伴」——它可以跑 typecheck、跑測試、起 dev server、curl API，然後看到結果、自己修問題。

實際場景：跑一次 npm run typecheck，錯誤訊息進入 Claude 的 context，它就能診斷出「Zod 在 package.json 裡但沒裝」並幫你 npm install，不必你逐字複製錯誤給它。這就是閉合 feedback loop——agent 看到自己的輸出，自己修正，不需要人做中間人。

三種跑命令的方式

差別在「誰看得到輸出」：

方式 操作 輸出去向 適合場景
Bash mode（!） 輸入列開頭打 !，接命令 直接進 Claude 的 context typecheck / test / build（有開始有結束）
背景化（Ctrl-B） 執行中按 Ctrl-B 寫入本機檔案，狀態列可查看 dev server（永遠不會結束的命令）
掛起（Ctrl-Z / fg） 按 Ctrl-Z 掛起，跑完 fg 恢復 不進 Claude 的 context 你想私下確認的事

Bash mode（!）是最常用的：打 ! 接 npm run typecheck，typecheck 的輸出直接進入 Claude 的 context。它看到錯誤就能自己修。這是讓 agent 閉合 feedback loop 的核心工具。

背景化（Ctrl-B）是給「永遠不會結束的命令」用的，最典型的就是 dev server。執行中按 Ctrl-B，命令丟到背景，輸出寫入本機檔案——你從狀態列打開就能看 log。Claude 能看 log、去 UI 試、發 curl，再回來看 server 印了什麼。對除錯 dev server 特別有用。

掛起（Ctrl-Z）是「不想讓它看到」的答案。按 Ctrl-Z 掛起 Claude Code 回到一般 shell，你在這裡跑的任何命令都不會進 Claude 的 context。跑完 fg 恢復原狀。注意課程用的是 Windows 快捷鍵，Mac 上可能不同。

決策樹

決策樹：
想讓 Claude 看到輸出？ → ! bash mode（長命令再加 Ctrl-B 背景化）
不想讓它看到？ → Ctrl-Z 掛起

背後的深層意義是你控制 context 裡裝什麼。你想讓它「看到問題並自己修」，就把輸出餵給它；你想私下確認，就掛起。Context 不是垃圾桶——你餵什麼進去，它就會用什麼來推理。

閉合 Feedback Loop 的意義

Bash 模式真正的價值不是「能在終端跑命令」，而是讓 agent 閉合 feedback loop：寫代碼 → 跑 typecheck → 看到錯誤 → 自己修 → 再跑 → 通過。沒有 bash mode，agent 每次寫完代碼都得等你手動跑命令、手動複製錯誤訊息、手動貼給它——feedback loop 是斷裂的，效率低落。

這也預告了下一課 permissions 的邏輯：你知道它在看什麼、跑什麼，才談得上放權。Bash mode 讓你控制「它看得到什麼」，permissions 讓你控制「它能跑什麼」——兩者加起來，才是完整的 agent 控制。

口訣：! 跑給它看，Ctrl-Z 掛起不給看。Context 是 agent 的推理素材——你決定裝什麼，它就用什麼來思考。
