用 bash 模式控制 agent 看得到的輸出

學習目標：用 ! 進入 bash mode、Ctrl-B 背景化長命令、Ctrl-Z 掛起 Claude 執行隱藏命令、fg 恢復，並依決策樹決定該讓 agent 看到哪些輸出，讓它有能力閉合與專案的 feedback loop。

bash 命令 = 讓 agent 閉合 feedback loop

只會寫程式的 agent 是「被動的碼農」：你叫它改、它改完就停。但 bash 命令讓它變成能跟專案互動的夥伴——它可以跑 typecheck、跑測試、起 dev server、curl 一下 API，然後看到結果、自己修問題。這就是閉合 feedback loop 的能力。

舉例：跑一次 npm run typecheck，錯誤訊息進入 Claude 的 context，它就能診斷「Zod 在 package.json 裡但沒裝」並幫你 npm install。你不必逐字複製錯誤給它看——它自己看到了。

三種跑命令的方式

1. Bash mode：輸出給 agent 看（!）

在輸入列開頭打一個 !，就進入 bash mode。接下來輸入的命令會被執行，輸出直接進到 Claude 的 context。

! npm run typecheck

適合「有開始有結束」的命令：typecheck、test、build、git status 這類一次跑完、輸出有意義的。

2. 背景化：長命令掛在背景（Ctrl-B）

dev server 這種永遠不會結束的命令，直接跑會卡住對話。解法是在命令執行中按 Ctrl-B 把它丟到背景：

  • 輸出會寫到一個本機檔案，狀態列上會出現一個背景任務
  • 用方向鍵往下捲、Enter，就能打開這個 shell 看它目前的輸出
  • 不需要時可以按 X 停止

這對除錯 dev server 特別有用：Claude 可以看到 server 的 log、去 UI 試一下、發個 curl，再回來看 server 印了什麼。整個循環在它眼前閉合。

3. 掛起：完全不讓 agent 看到（Ctrl-Z / fg）

有些命令你不想讓 Claude 看到輸出（或純粹想自己跑一下）。按 Ctrl-Z 會掛起 Claude Code，回到一般 shell；你在這裡跑任何命令都不會進 Claude 的 context。跑完輸入 fg，Claude 就恢復，狀態完好。

注意 課程用的是 Windows 快捷鍵（Ctrl-B / Ctrl-Z）。在 Mac 上快捷鍵可能不同——用之前先查一下你平台的對應按鍵。

決策樹：該讓 agent 看到什麼？

情境做法
想讓 Claude 看到命令輸出! bash mode
同上，但命令很長、不想卡住! 之後按 Ctrl-B 背景化
不想讓 Claude 看到輸出Ctrl-Z 掛起 → 跑命令 → fg

這個決策樹的深層意義是你控制 context 裡裝什麼。agent 看到的輸出就是它 context 的一部分——你想讓它「看到問題並自己修」，就把輸出餵給它；你想自己私下確認，就掛起。這預告了後面「context 是稀缺資源」的整個管理哲學。

小結

  • bash 讓 agent 從被動寫碼變成能閉合 feedback loop 的夥伴
  • ! 進入 bash mode，輸出進 Claude context（適合 typecheck/test）
  • Ctrl-B 背景化長命令（dev server），log 可隨時查看
  • Ctrl-Z 掛起跑隱藏命令，fg 恢復；Mac 快捷鍵可能不同
  • 核心：你決定 agent 的 context 裡看得到什麼
