參數記憶不可靠與無狀態

學習目標：說出為什麼 LLM 不是可靠的資料庫（fuzzy JPEG 式壓縮記憶、知識 cutoff），以及完全無狀態意味著什麼，並推導出「靠 context 與文件、別靠模型記憶」。

模型有兩種「記住」

要理解 agent 為什麼會說錯話，先分清它記住的兩種方式：

  • 參數記憶（parametric memory）：訓練時把資料壓縮進模型的權重裡，之後憑這些權重「回想」。這是你問它「React 是什麼」時它答得上來的原因。
  • Context 記憶：當下窗口裡實際看到的文字。你 @ 參照的那份檔、對話裡貼的需求，都屬於這種。

兩種記憶的可靠度天差地遠——這正是本課要拆穿的重點。

參數記憶是一張模糊的 JPEG

核心概念 LLM 的參數記憶是「全人類知識的一張模糊 JPEG」。 訓練資料被壓縮進參數裡，壓縮會掉細節、模糊邊緣、偶爾把細節重建錯——幻覺就是壓縮重建時的失真。

對比一下可靠的資料庫：你查一行，它回你精確的那一行，一字不差。LLM 不同——它不儲存原始資料，只儲存壓縮後的近似。所以憑參數記憶回答「我們專案的某個設定是什麼」，它可能在合理的地方重建出一個聽起來對、其實是編的答案。參數答案不可靠是設計使然，不是 bug。

反過來，context 記憶可靠得多：只要事實真的寫在窗口裡（前提是別把它塞進 dumb zone），模型可以直接「讀」而不是「回想」。這就是為什麼課程說「靠 context 與文件、別靠模型記憶」。

知識 cutoff 的真相

每個模型都有訓練資料的截止日期（knowledge cutoff）。直覺上你會擔心「它不知道最新的事」。但課程給了一個反轉觀點：既然你本來就不該信任參數召回，cutoff 日期就沒那麼重要了——需要最新或精確的事實，就放進 context 讓它讀，而不是期待它的參數記得。

完全無狀態：每次從零開始

第二個關鍵事實：LLM 完全無狀態。你在對話中建立起的所有「部落知識」——專案的來龍去脈、剛決定的架構、踩過的雷——都存在 context 裡，一旦 /clear 或換 session，全部蒸發。模型不會記得上次 session 聊過什麼，也不會有任何「習慣了你」的默契。

這解釋了兩件事：第一，為什麼每次開新 session 都要重新探索 codebase（下一節課會講）；第二，為什麼codebase 品質與文件變成關鍵資產——你的知識放不進模型腦子，就只能放進程式碼、文件、AGENTS.md 這些它每次都能重新讀到的地方。

一句話記法 模型沒有硬碟，只有一張隨取隨丟的工作桌。 想讓它「記得」，就把東西放在桌上（context）或牆上（文件），而不是指望它的腦袋。

推導出實務原則

把兩件事合起來，得到一條鐵律：事實要進 context，不要進想像。 需要精確的資料，用 @ 參照檔案、把 spec/慣例寫進文件，讓它直接讀；凡是只能靠它「回想」的，都該假設它會錯。
