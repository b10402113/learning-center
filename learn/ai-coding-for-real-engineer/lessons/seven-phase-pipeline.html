七階段流程總覽

Node 1 · process-overview · 七階段流水線的每一站做什麼、產出什麼

學習目標：按順序說出七階段流程——grill（訪談）→ research → prototype → PRD/plan → issues → implement → review——並說出每個階段各自產出什麼。

先講立場：這門課不賣框架，教你擁有流程

近年 AI coding agent 能力暴漲，很多人開始建「大型框架」來包裝 agent——像是 GSD、spec kits、be mad 這些。但這門課的立場相反：你應該擁有自己的流程，而不是套用別人的框架。課程教你的是一套可以迭代、改造成自己的七階段流程，底下靠的是三十年的工程直覺與實務經驗，不是魔法。

七階段一覽

整條流水線長這樣，每個階段都在把「模糊」往「可執行」推一格：

階段做什麼產出
1. Grill（訪談）一題一題把模糊需求問清楚釘清楚的需求輪廓
2. Research（研究）補齊我們不知道的未知研究筆記與判斷
3. Prototype（原型）用小代碼沖掉設計上的未知數可丟的實驗、驗證過的方案
4. PRD / plan把方向寫成兩份文件PRD + plan
5. Issues（任務）把文件切成可執行的任務一份 issue 清單
6. Implement（實作）整段放手讓 agent 跑能跑、有測試、已 commit 的代碼
7. Review（審查）回頭守住品質修正與品質回饋

關鍵支柱：Implement 要全程 AFK

整套系統最重要的一根柱子，是讓 implement 這一段徹底 away from keyboard——人不在鍵盤前，讓 agent 自己跑完。你常會聽到一句抱怨：「好煩，我得坐在那邊看 agent 做事。」AFK 模式就是為了解決這個：不用盯。

原理很樸素：當前面五個階段已經把該決定的都決定了，implement 就不需要你逐行指揮——你放手讓 agent 寫，然後用同一段時間去做別的事，這就是課程反覆強調的 「plan while the AI ships」（趁 AI 交貨時規劃下一批工作）。一人做超過一人的事，靠的就是這條。

課程怎麼練：一個 20k 行 playground

這不是講座課。課程附一個約 20,000 行的 TypeScript / React playground repo，所有練習都是「在真實 app 上跟 agent 一起蓋功能」。你也可以不用課程 repo、把練習套在自己的 repo 上——但跟練課程 repo 會得到更多支援。

另一個隱藏的因果：agent 在好的 codebase 裡才會表現好。這條流程（先釘規格、放手實作、最後審查）本身就在把你推向一個更健康的 codebase——而健康的 codebase 又反過來讓 agent 更可靠，形成正循環。

小結

七階段是一條「模糊 → 可執行」的流水線：grill、research、prototype 處理需求與設計上的不確定；PRD/plan 和 issues 把決定固化成文件與任務；implement 在一切都決定好之後放手 AFK；review 在最後守住品質。先記住順序和各自的產出，下一課再解釋為什麼非得這樣排。
