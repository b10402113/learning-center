GrillMe 的運作原理：一次一題、先探索、給推薦

Node interview-not-plan · grillme-mechanics · 一份把訪談變成技能的 markdown 檔案

Learning goal

能說出 GrillMe 這份 skill 檔案的設計原則（一次一題、可探索的就不問、每個問題附推薦答案），並解釋每一條如何把模糊需求釘成 shared design concept。

GrillMe 就只是一份 markdown 檔

先破除「skill 很高級」的印象：GrillMe 是**一個單一 markdown 檔案**，內容就是給 agent 的指令。Agent Skills 的格式讓它「平常只露出名稱＋描述，agent 自己決定要不要載入」——但它本質上仍是一份指令文件。它的五條設計原則，每一條都直接對應「把模糊需求釘成 shared design concept」的某個環節。

五條設計原則

  1. 訪談直到共享理解成立：不設題數上限，relentlessly 地問，直到雙方腦中的設計概念一致——這是上一課 shared design concept 的直接執行。
  2. 一次只問一題：不一次丟十個問題讓你想都不想就「都行都行」。一次一題逼你逐個做決定，也防止你把真正重要的決策「順手略過」。
  3. 可探索的就不問：任何用讀 codebase 就能回答的事（「留言存在哪張表？」），agent 該自己去 explore，不要拿這些問題浪費你的注意力。skill 裡有「Explore」這個字，所以它真的會去 explore——字會連結到模型潛在空間裡的 Explore sub-agent。
  4. 沿設計樹逐條分支、逐一解決依賴：把需求想成一棵設計樹，每個分支（誰能發文、能不能編輯、要不要通知）有依賴關係，一次沿一條分支走完，不跳來跳去。
  5. 每個問題附推薦答案：不把決策丟回給你乾想——它先給一個它建議的答案，你可以直接接受、或追問、或推翻。

一次一題 ＋ 給推薦 ＝ 把「訪談」變成一個低摩擦的流程。你花的心力是「判斷」，不是「憑空設計」；判斷比設計省力得多，於是你願意把每個決策都認真做完，而不是草率略過。

練習怎麼跑（lesson 24 的設定）

開一個全新的 Claude Code session，用 default mode（不進 plan mode、不開 auto-accept edits），把模糊需求丟給它，讓 GrillMe 接手訪談。當作沙盒：邊跑邊記筆記，記錄你對這份 skill 的改進想法。它的設計原則（一次一題、先探索、給推薦）是完全可複用的——你不一定要用 GrillMe，任何「把訪談當技能」的寫法都長這樣。
