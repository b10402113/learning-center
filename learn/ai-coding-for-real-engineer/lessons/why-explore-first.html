為什麼探索是第一個動作

Node 7 · exploration · Step 1/4

Learning goal

理解 LLM 的 statelessness 為何讓「每次開新 session 都從零探索 codebase」成為與 agent 合作的第一個基本功。

LLM 是完全無狀態的

在所有 LLM 的限制裡，最棘手、最奇怪、而且你必須第一個去想的那個，是 LLM 沒有跨 session 的記憶。課程稱它為 statelessness：agent 每次被丟進你的 codebase，都是「第一次」——它完全不知道上一次 session 曾經看過哪些檔案、得出過什麼結論。

Statelessness 的意思是：LLM 每一次都被丟進你的 codebase，卻完全不記得之前探索過它。而每次它要「追上進度」、搞懂 codebase 的 pattern、layout，甚至搞清楚這個 codebase 到底在做什麼，都必須重新探索一遍。

這不是「偷懶」或「省事」的產物，而是模型的本質：context window 是一次性的，session 結束就清空。你在上一課（lesson 15）已經看過這個論點——LLM 是一個 stateless 的 fuzzy-JPEG 資料庫，不是一個可靠記憶體。

為什麼「探索」因此變成第一個基本功

既然 agent 每一次都是從零開始，探索就不是加分題，而是合作的起點。你給它的第一份「資料」不是 spec，不是 commit message——而是「這個 repo 長什麼樣、程式碼怎麼組織、哪些 pattern 是慣例」。這份資料決定後面每一步的判斷品質。

用課程的句子說：exploration 是你在 coding agent 上變強之前，必須先理解的基礎技能（foundational skill）。它回答的問題很樸素：

  • 這個 codebase 在做什麼（purpose）？
  • 它是怎麼被佈置的（layout / patterns）？
  • 慣例是什麼，我該怎麼遵循它？

所以「新 session 一開先探索」不是流程上的儀式，而是 statelessness 直接推導出來的必然動作：你不餵它 context，它就沒有 context。越早把 repo 讀進去，後面每一步（寫 code、改 bug、加 feature）的判斷就越可靠。
