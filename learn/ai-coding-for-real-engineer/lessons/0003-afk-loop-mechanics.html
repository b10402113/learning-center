Lesson 003 · Sandbox 與 AFK Loop

main.ts 的迴圈結構

maxIterations 作為安全網，完成訊號作為主要終止條件。

從互動到迴圈的跳躍

上一課你在 Docker 沒盒裡跑了冒煙測試，確認 agent 能在容器中執行。現在要知道 main.ts 的結構——它是 AFK 迴圈的心臟。

互動模式的 interactive.ts 是一次性執行：跑一個 prompt，等結果。AFK 迴圈的 main.ts 是重複執行：同一個 prompt 跑很多圈，直到 agent 說「沒事做了」或達到次數上限。

核心差異 互動模式跑一次，AFK 迴圈跑很多次。互動模式等人按鍵，AFK 迴圈自己決定什麼時候停。

指令格式

互動模式用 shell 展開注入 PRD 和 plan。AFK 迴圈用 CLI 位置參數：

# 互動模式（上一個節點）
npx tsx sandcastle/interactive.ts

# AFK 迴圈（本節）
npx tsx sandcastle/main.ts plans/prd.md plans/plan.md

兩個參數：

  • 第一個：PRD 檔案路徑（目的地）
  • 第二個：plan 檔案路徑（旅程）

agent 的 prompt 會讀入這兩個檔案，然後開始執行。

迴圈的三個組件

AFK 迴圈結構 ┌─ while (iterations < maxIterations) ─────────┐ │ │ │ ① 啟動 sandbox + agent │ │ 讀入 PRD + plan │ │ 執行 prompt.md 的指令 │ │ │ │ ② Agent 完成一個 phase │ │ 跑 typecheck + test │ │ commit │ │ │ │ ③ 檢查終止條件 │ │ ┌─────────────────────────┐ │ │ │ Agent 輸出 │ │ │ │ "no more tasks" ? │──→ break │ │ └─────────────────────────┘ │ │ │ │ iterations += 1 │ └───────────────────────────────────────────────┘

1 maxIterations — 安全上限

你在執行時設定一個數字，迴圈最多跑這麼多圈。實務上設 10–50。

# 設定 3 圈（測試用）
npx tsx sandcastle/main.ts plans/prd.md plans/plan.md --max-iterations 3

# 設定 50 圈（實戰用，信任完成訊號）
npx tsx sandcastle/main.ts plans/prd.md plans/plan.md --max-iterations 50

為什麼設很高？因為完成訊號才是主要終止條件。maxIterations 只是防止完成訊號失效的最後防線——像保險絲，不是開關。

2 完成訊號 — Agent 說「沒事做了」

你的 prompt.md 裡有一條指令，告訴 agent：

當沒有更多任務時，輸出 "no more tasks" 這串文字。

當 agent 完成所有 phase（或判斷沒有可做的工作），它會輸出這串文字。main.ts 偵測到這個字串就跳出迴圈。

這比 maxIterations 更精準——agent 自己知道什麼時候做完了。

3 每圈全新 Context

這是最關鍵的差異。每一圈迭代都是一個全新的 Claude Code session，全新的 context window。

Context window 每圈重置 迭代 1: context ████████░░░░░░░░ (64k) → commit → 關閉 迭代 2: context ██████████░░░░░░ (80k) → commit → 關閉 迭代 3: context ████████░░░░░░░░ (64k) → "no more tasks" → 停

為什麼每圈要重置？

  • 永遠在 smart zone——不會塞到 dumb zone（~120k tokens）
  • 重新探索 repo——每一圈都讀最新的 commit 狀態，接續上一圈的成果
  • 壞掉的 context 不會汙染下一圈——前一圈有 bug 的推理不影響後面

跟互動模式的完整比較

面向 互動模式 (interactive.ts) AFK 迴圈 (main.ts)
執行模式 interactive（等人批准） run（自動執行）
PRD/plan 注入 prompt.md 內的 !cat 展開 CLI 位置參數
終止條件 單一 phase 完成即停 maxIterations 或完成訊號
Context window 持續一條（會長大） 每圈全新（固定大小）
人在場 是（觀察 + 批准） 否（走開）
沙盒 不需要（人盯著） 需要（Docker/Podman）
用途 驗證行為、調 prompt 批量交付、放手執行

迭代時的偵測邏輯

迴圈怎麼知道「phase one 已經做完了」？答案是 git commit。

每一圈 agent 都會：

  1. 探索 repo（讀檔案、看 git log）
  2. 發現上一圈已經 commit 過某個 phase
  3. 跳過已完成的 phase，開始下一個

這就是為什麼每一圈都要 commit——commit 是 agent 之間傳遞狀態的方式。沒有 commit，下一圈就不知道上一圈做了什麼。

# Agent 的內部推理（概念）
git log --oneline
# 看到: "feat: add analytics service with tests"
# → Phase 1 已完成
# → 開始 Phase 2: revenue line chart
