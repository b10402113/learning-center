先分清楚：工具與流程

ai-coding-for-real-engineer › agent-basics › harness-vs-process

學習目標：能說出「agent 工具（harness）」與「七階段流程」的區別，並理解 Claude Code 只是示範用的 CLI agent、真正可轉移的是流程本身。

這一課要建立的心智框架

整個課程用 Claude Code 做示範——不是因為它有什麼獨門絕活，而是因為它夠流行、是講師的日常工具。課程的立場從第一課就很明確：這套七階段流程（grill → research → prototype → PRD + plan → issues → implement → review）包得住任何 coding agent，只要它跑在 CLI 裡就行。

所以在你學任何按鍵、任何 slash command 之前，先把兩件事分開：

工具（harness）流程（process）
Claude Code、Codex、Gemini CLI、Cursor……七階段流程、AFK 執行、feedback loop、context 管理
會換、會改版、是商品是你自己的方法論，跟著你走
這一課之後的按鍵細節都算這類整個課程反覆回來的主題都算這類

為什麼這個分離很重要

如果你把「用 Claude Code」當成學習目標，那換工具那天你就得全部重學。但如果你把「七階段流程 + 讓 agent 放手跑」當成目標，Claude Code 就只是你暫時借來開的那台車——學會開車的人換車不需要重學。

課程給了一個很實際的提醒：只要 harness 是 CLI-based，這套流程就搬得過去。你今天在這裡學的 `/context`、`@` 參照、permissions，換到 Codex 或 Gemini CLI 上可能鍵位不同，但背後的意圖（掌控 context、給精準資訊、管住風險）完全一樣。

連老手都值得重看這一節

講師自己說：這一段不只是新手教學，就算是每天用 Claude Code 的人，接下來幾課（bash 模式、rewind、permissions……）也大概率會撿到新東西。課程的 Claude Code 章節是「basics 加 advanced tips」的混合——所以不要因為你「用過 agent」就跳過，重點不是按鍵，是為什麼。

把注意力放在哪

接下來的每一課都有一個隱藏的節奏：動作是工具的，判斷是流程的。`/clear` 是動作，但「什麼時候該清 context」是判斷；`@` 是動作，但「該參照哪個檔」是判斷；escape 是動作，但「什麼時候該打斷 agent」是判斷。學動作很快，學判斷才是一整門課的事。
