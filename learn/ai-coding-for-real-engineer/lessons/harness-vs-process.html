先分清楚：工具與流程

Step 1/4 · 怎麼開車

學習目標：能說出「agent 工具（harness）」與「七階段流程」的區別，並理解 Claude Code 只是示範用的 CLI agent、真正可轉移的是流程本身。

工具會換，流程跟你走

這門課用 Claude Code 做示範。但 Claude Code 不是重點——它只是一個跑在 CLI 裡的 coding agent，夠流行、是講師的日常工具，所以被拿來當教材。換成 Codex、OpenCode、Cursor 的 terminal mode，甚至任何能讀寫檔案、跑 shell 的 CLI agent，整套七階段流程都一樣適用。

把這件事想清楚很重要，因為很多人學 AI coding 的方式是「學某個工具的操作」。工具的操作會過時、會改版、會被更好的產品取代。但七階段流程——grill → research → prototype → PRD/plan → issues → implement → review——是一套方法論，它解決的是「怎麼把模糊需求變成可交付的程式碼」，這件事不管工具怎麼換都不會變。

心智框架：兩層分離

你可以把 AI coding 想成兩層：

層級 內容 例子
工具層（harness） 特定產品的操作方式 Claude Code 的 `/clear`、`@` 參照、escape 中斷
流程層（process） 怎麼把需求變成交付 grill → research → prototype → PRD/plan → issues → implement → review

接下來幾課你會學很多工具層的動作——slash commands、`@` 參照、prompt stash、貼圖。動作本身學得很快。但每個動作背後都有一個流程層的判斷：「什麼時候該清 context？」「該參照哪個檔？」「什麼時候該打斷 agent？」動作是手指的事，判斷才是腦袋的事。

類比：開車。方向盤、油門、煞車是工具層——任何車都差不多。但「什麼時候超車」「什麼時候該減速」是流程層——這是你作為駕駛的判斷，跟你開的是豐田還是特斯拉無關。這門課教你的是「判斷」，不是「按鍵」。

為什麼這件事值得第一課就講

因為如果你把「學 AI coding」等同於「學 Claude Code 的按鍵」，你會遇到兩個問題：

  1. 工具一換你就慌。Anthropic 改了介面、你換到另一個 agent、團隊用不同的 harness——你的知識就報銷了。
  2. 你只會操作，不會判斷。知道 `/clear` 怎麼按是一回事，知道「什麼時候該 clear」是另一回事。後者才是這門課的主軸。

反過來，如果你先建立了「流程才是可轉移的」這個心智框架，工具層的動作就變成了手段——你知道為什麼要用它，而不是只是記得怎麼用。就算你天天用 Claude Code，這章也值得重看，因為它是 basics 加 advanced tips 的混合，重點是為什麼，不是按鍵。

小結

工具 vs 流程：Claude Code 是示範用的 harness，不是唯一的答案。七階段流程才是可轉移的方法論。接下來學的每個動作，都帶著「它在流程裡解決什麼問題」的判斷一起學。
