# 軟體工廠的三層審查：從成本看代碼品質的煞車機制

學會和 AI Agent 對齊目標、規劃大區塊工作後，下一步就是搭建自己的「軟體工廠」（software factory）。

經營軟體工廠就像學開車，第一件該學會的事是怎麼踩煞車讓車停下來。

如果只一味衝刺、把進度往前推，工廠最後只會變成狂噴劣質代碼的「廢話加農砲」（slop cannon）。

為了避免精疲力竭、被爛代碼淹沒，必須懂得減速，在交付成品時拉高品質。

軟體工廠裡有三道減速的煞車機制，分為三層層層遞進的審查：

### 第一層：自動化檢查（Automated checks）

這是最底層、確定性的檢查（deterministic checks），用來驗證程式碼的基本品質。

常見形式包含單元測試（unit tests）、型別檢查（type checking）以及 Linter。

這些檢查可以依需求一層層疊加在應用程式上。

<!--image:1-->

從成本來看，自動化檢查效益極高。

它只消耗 CPU 運算週期，不花費任何模型 token。

建立大量且密集的自動化檢查，能用極低成本守住底線，確保 Agent 的產出不脫軌。

### 第二層：自動化審查（Automated review）

架構在自動化檢查之上的是第二層自動化審查。

這一層由 AI Agent 親自驅動，與確定性檢查不同。

例如實作規格技能（implement spec skill）或程式碼審查技能（code review skill），都是由 Agent 讀取程式碼並提供審查建議。

自動化審查需要消耗 token，成本高於單純跑測試。

但它能處理更靈活的語意與邏輯問題，具備很大的發揮空間。

### 第三層：人工審查（Human review）

最後一道防線是人工審查，由真人工程師親自檢視程式碼。

人工審查的成本最高，消耗的是工程師最寶貴的時間與專注力。

因此必須最佳化人工審查流程，釐清到底該審核多少程式碼，以及哪些關鍵情境才需要人工介入。

### 審查層級的協同運作

掌握這三層的順序與成本結構後，策略上會優先聚焦在自動化審查與人工審查的搭配：

我們先釐清人工審查的標準與界線，再利用人工審查的經驗來優化自動化審查的 Agent。

在理想循環下，自動化審查能承接的範圍會越來越廣，人工審查需要負擔的比例就會逐步減少。

完整掌握這三層煞車機制，就能在全力交付產品的同時穩穩守住品質，避免軟體工廠失控翻車。
