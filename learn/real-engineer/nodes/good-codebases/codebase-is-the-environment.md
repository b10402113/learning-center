# 你的程式庫就是 Agent 的環境：戰術與戰略的重新分工

想像你剛剛體驗了一陣子「憑感覺寫程式」（vibe coding），或者從別人手上接下一個完全靠 vibe coding 堆出來的程式庫（codebase）。裡面的功能大致上能動，甚至已經部署上線、有真實使用者在用了，但你每次想改動它，心裡都會隱隱發毛。

vibe coding 的本質，就是完全不看程式碼在寫程式。這是一種順著感覺走、徹底忘記程式碼存在的開發型態。開發時甚至不再去看變更紀錄（diff），只拿來做做週末隨手丟掉的玩具專案還算合適。

許多團隊已經悄悄把 vibe coding 當成正式開發軟體的方式。大家擁抱技術的指數級成長，完全放手交給直覺，相信只要 agent 夠聰明就能搞定一切。但在這種程式庫裡工作的實際經驗往往是一場災難。程式庫不但沒有變好維護，反而迅速腐爛到難以收拾。

## 程式庫是 Agent 運作的環境

要理解為什麼會變成災難，得先看清楚 agent 的基本架構。

模型（model）與控制框架（harness）結合在一起，構成了能夠行動的 agent，而這個 agent 必須在特定的環境（environment）中運作。根據框架部署的方式，環境可能是一個相對乾淨的線上沙盒，也可能是電腦上的整個檔案系統。在寫程式的情境裡，程式庫本身就是 agent 的運作環境。

<!--image:1-->

Agent 在專案裡看到的程式碼、能存取的資料、能隨時執行的測試、型別檢查與各類自動化工具，全部都是這個環境的一部分。如果這個環境建立時毫無章法、缺乏維護，agent 在裡面工作自然會處處碰壁。

想要改善 agent 的表現，關鍵在於改善它所在的環境。程式庫的複雜度（complexity），指的是軟體系統結構中任何讓人難以理解與修改的因素。

糟糕的程式庫就是高度複雜的程式庫。好的程式庫則是「容易修改」的程式庫。當程式庫難以改動，agent 在 A 處做了一個調整，就很可能在其他地方引發無法預測的連鎖反應。只有結構清楚、容易預測、好懂又好改的程式庫，agent 才能在裡面穩定運作。

## 戰術與戰略：兩種完全不同的程式設計視角

要讓程式庫保持容易理解與變更，必須釐清寫程式時的兩種核心活動：戰術性程式設計（tactical programming）與戰略性程式設計（strategic programming）。

戰術性程式設計著眼於短期目標。它就像在前線泥濘中作戰的士官，唯一的目標是打贏眼前的戰鬥：把 bug 修掉、把功能做出來、讓測試亮綠燈。戰術工作的重心就是把程式碼敲出來、確認它能跑、功能符合需求。

<!--image:2-->

戰略性程式設計著眼的則是長遠未來。它像是綜觀全局、在乎整場戰爭輸贏的將軍，而不是前線衝鋒的士官。戰略工作關心的是程式庫長期的健康度，確保系統不會因為眼前的改動而在幾個月後寸步難行。

過去由人類自己寫程式時，每一次送出變更通常都會揉合這兩種思考。一邊想著戰術上如何把眼前的功能接起來，一邊盡量兼顧戰略，為下一次修改留下好走的底子。

不過，並非所有工程師都願意花心力做戰略思考。有一種開發者被稱為「戰術龍捲風」（tactical tornado）。他們的產出速度極快，寫 code 的量遠遠超過身邊所有人，但做事方式百分之百是戰術導向。戰術龍捲風所到之處，只會留下滿目瘡痍的廢墟。

這個早在 2018 年就出現的描述，拿來形容今天的 coding agent 完全吻合。

## Agent 是不知疲倦的戰術龍捲風

現今所有的 coding agent，本質上都是不折不扣的戰術龍捲風。它們不知疲倦，能瞬間產出無窮無盡的程式碼，但完全沒有戰略思考的能力。

Agent 之所以只會戰術思考，是因為它眼裡永遠只有當下被指派的任務。它不會停下腳步退後一步想：「我這樣寫，這個程式庫整體會不會變差？」目前的架構與提示詞根本不是為了這種長遠考量而設計的。

<!--image:3-->

就算看各大模型在 Deep SWE benchmark 這類評測上的排行榜，大家比拚的也純粹是戰術性程式設計的能力。評測只問一件事：agent 有沒有把那個 issue 解決、功能有沒有過。從來沒有評測去衡量，在 agent 交付改動之後，整個程式庫的結構到底更健康了，還是變得更難以維護。

## 認出你該負責的那一半

如果希望 agent 運作的環境能隨時間越來越乾淨、好改，而不是逐漸崩塌，這份戰略思考的重擔就必須有人扛起來。

那個人就是你。

<!--image:4-->

在 AI 時代，你等於瞬間擁有了上百位能隨時差遣、產出飛快的前線戰術工程師。但這批戰術大軍極度需要有人替他們做戰略規劃、劃定邊界、維持架構的一致與簡潔。要是連你也放棄戰略思考、跟著一起「完全看感覺」，最後換來的只會是一個連 agent 自己都動彈不得、誰碰誰害怕的程式庫包袱。

要扛起這份責任，先得有一套能跟 agent 共用的診斷語言；下一個 step 就來建立它。
