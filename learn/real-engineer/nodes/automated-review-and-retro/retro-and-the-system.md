# 為什麼需要 Retro：把人類審查變成 Agent 環境的升級機制

審查 AI 寫的程式碼時，多數人最先關注兩件事：如何加快審查速度，以及如何決定優先看哪些變更。

但人類審查還有第三個關鍵面向，也是讓這些努力成立的核心：不能只確認程式碼是否符合需求，更要想辦法改善產出程式碼的系統。

## 人類審查的核心：同一條建議不該留第二次

翻閱程式碼 diff 時，可以一邊留意哪些模式能事先提醒 Agent。例如哪些做法很好、哪些不妥，或是 Agent 當時應該怎麼做、不該怎麼做。

人類審查的核心理論是：你永遠不該針對同一件事留兩次相同的審查留言。

<!--image:1-->

code review 修的是眼前這則 PR；retro 修的則是下一次不會再犯同樣的錯。

與其每次都在後面替 Agent 抓同樣的錯誤、反覆審查品質不佳的程式碼，不如將留下的每條審查意見反饋給系統，讓系統持續進化。人類審查的價值不只是修正眼前的程式碼，更是為了回過頭改進自動化審查與檢查機制。

執行這項工作可以使用專門的技能：retro（回顧）。

## 安裝 retro 技能：為什麼選擇 cherry-pick

安裝這個技能需要執行以下指令：

<!-- derived -->

```bash
npm run cherry-pick add-retro-skill
```

專案中雖然也有 `npm run reset add-retro-skill` 這類指令，但這裡必須用 `cherry-pick` 而不是 `reset`。因為這能避免覆蓋目前 Pull Request 裡寫好的變更。

執行完成後，專案中會出現 `retro` 目錄以及對應的 `SKILL.md`。這項技能用來回顧 coding session，在提出需求時主動針對 Agent 的工作環境給出改善建議，提升未來的執行成效。

## Retro 會檢查哪些項目？

Retro 本質上就是去檢視任何一次 Agent 的執行歷程，從中找出改善空間。它主要會掃描以下幾個面向：

<!--image:2-->

1. **程式碼規範（Coding Standards）**：檢視目前對話中出現的問題，評估哪些內容適合定成規範，並對 `coding-standards.md` 這類檔案提出新增或修改建議。
2. **全域 AGENTS.md**：檢視全域 `AGENTS.md` 這類引導檔案，找出是否能進一步精簡或修剪（prune），避免指令過於肥大。
3. **工具經濟性（Tool Economy）**：檢查 Agent 是否使用了自訂基礎架構或外部工具，評估這些流程是否能精簡流暢（streamlined）。
4. **其他自動化項目**：包含自動化檢查與專案導覽路徑等機制。

## Agent 總是默默受苦：如何善用 Retro

多數 Agent 執行框架（harness）都會把對話紀錄存成你本機上的檔案。Retro 技能會讀取這些原始歷史紀錄，分析 Agent 當時接收到哪些資訊、遇到了什麼阻礙，進而提出改進方向。

<!--image:3-->

可以針對剛完成的單次對話執行 retro，也可以直接回顧最近 25 次對話，從更大的樣本中尋找改善機會。

Agent 遇到不好的環境配置時通常只會默默承受，不會主動反映提示詞難懂或工具難用。實際查看紀錄往往會發現，原本以為順暢的環境其實有不少破綻與盲點。定期透過 retro 檢視並調整這些設定，能大幅提升 Agent 的工作效率。
