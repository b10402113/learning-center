# L1 overview

- `app/routes/admin.categories.tsx` — 分類 CRUD 後台：`loader`/`action`、`CategoryRow`、`CreateCategoryRow`、`getAllCategoriesWithCourseCounts` 一次 leftJoin 算出每個分類的課程數。刪除前會數 `courses` 以免孤兒資料，這個規則就寫在 `deleteCategory()` 裡。它是這批檔案裡最「乾淨」的一個，剛好可以當對照組：一樣是 route 直呼 `db`，但邏輯份量還塞得進一個檔案。
- `app/routes/admin.courses.tsx` — 平台課程總表與 `update-status` action。`loader` 用 `getAllCourses()` 之後對每門課各跑 `getLessonCountForCourse`、`getEnrollmentCountForCourse`，是教科書級的 N+1。`statusBadge` 在這裡實作了一份，`instructor.tsx` 與 `instructor.$courseId.tsx` 又各自再寫一份。
- `app/routes/admin.users.tsx` — 使用者管理：`update-user` / `update-role` 兩個 intent、`EditableUserRow` 行內編輯、`roleBadge`。`updateUser()` 強迫呼叫端傳 `bio`，所以 action 得先 `getUserById` 再原值傳回，形成 read-modify-write。這裡用原生 `<input>`，`admin.categories.tsx` 卻用 `<Input>` 元件，同一個 admin 介面兩套寫法。
- `app/routes/instructor.$courseId.lessons.$lessonId.quiz.tsx` — 四步 wizard（Settings → Questions → Answers → Review）建構 quiz。`action` 的 `save-quiz` 策略是「先 `deleteQuiz` 再重建」，`deleteQuiz()` 用手寫迴圈逐一刪 answers/attempts/options/questions，是應用層 cascade。驗證散在三處：`wizardDataSchema`、render 內的 `renderStep4()`、`canGoNext()`。`renderStep4` 中的 toast + `navigate()` 寫在 component 主體（render 期間）而非 `useEffect`，是明確的副作用錯置。
- `app/routes/instructor.$courseId.lessons.$lessonId.tsx` — 單一 lesson 編輯器：Monaco Markdown 內容、YouTube `videoUrl`、`durationMinutes`、`githubRepoUrl`，加上 `useBlocker` 未存檔攔截。`updateLesson()` 接受一堆 `null` 代表「不改」，呼叫端一律傳 `null` 給 title，這是典型 shallow interface：參數多、語意靠 null 編碼。
- `app/routes/instructor.$courseId.modules.$moduleId.tsx` — 模組預覽（講師視角看學生會看到什麼）。整個 `getCourseWithDetails()`（約 55 行、含兩次 join 與 modules/lessons 組裝）是從 `instructor.$courseId.tsx` 原封不動複製過來的。這個 route 根本沒用到 `course.modules`，只為了拿 `instructorName`/`instructorBio` 就付了整包查詢。
- `app/routes/instructor.$courseId.students.tsx` — 學生名冊頁。`loader` 從 `getCourseEnrolledStudents` 到「每人進度 + 每人每題最佳成績」的建構流程，和 `instructor.$courseId.tsx` 的 Students tab 幾乎逐行相同；`calculateProgress()`、`getCourseLessonIds()`、`getQuizByLessonId()`、`getBestAttempt()` 也都是複製貼上。也就是同一份商業邏輯在 repo 裡有兩份會各自漂移的實作。
- `app/routes/instructor.$courseId.tsx` — 全批最大的檔案（2264 行），課程編輯器＋課程後台。它同時是：約 30 個 `db` helper、zod schema、`loader`（含 N+1 的學生名冊）、只有一個 `intent` 標籤的 14 路 action 分派、4 個 `InlineEditable*` 元件、拖曳排序（模組與課程跨模組搬移）、Pricing/Status/Sales Copy/Students 四個 tab。這是最典型的 shallow module：一個入口很淺（一個檔案一個 route），裡面什麼責任都混在一起。
- `app/routes/instructor.analytics.tsx` — 收益與課程分析，1944 行。前半是十多個聚合函式（`getStudentRevenue`、`getTopBuyers`、`getRevenueOverTime`、`getCourseDropOff`、`getCourseQuizPassRates`、`getCourseRevenueByCountry`），後半是十二個展示元件與一整頁 tabs。註解品質極高（說明為何毛收益/平台費/淨額要拆三個數字、為何 seat 要另開查詢避免 join 放大金額），但知識全部鎖在 route 檔裡，無法被別的 route 重用。
- `app/routes/instructor.new.tsx` — 開課表單。`generateSlug()` 與 `admin.categories.tsx` 的 `slugify()` 是同一段程式碼、兩個名字。`newCourseSchema` 把 `categoryId` 宣告成 `z.string()`，於是在 `createCourse()` 呼叫處才 `parseInt`。唯一在 action 內正確 `throw redirect` 的檔案，其餘多數用 fetcher 留在原頁。
- `app/routes/instructor.questions.tsx` — 未回覆問題佇列與回覆框。`getUnansweredQuestions()` 用 `alias(users)` + `notExists(staffReply)` 判斷「沒有任何講師或 admin 回覆過」。這段完全相同的查詢（連註解都一樣）也內嵌在 `instructor.analytics.tsx` 的 `loader` 裡算「未回覆問題數」。這是本批最明顯的業務規則重複。
- `app/routes/instructor.tsx` — 講師首頁（我的課程卡片牆）。`loader` 只允許 `UserRole.Instructor`，但底下所有 `instructor.$courseId*` 子 route 都允許 admin，權限模型在這裡就不一致。`getLessonCountForCourse` / `getEnrollmentCountForCourse` 又各複製一份，`loader` 對每門課再跑一次，形成第二處 N+1。
