# L1 overview

- `request-logger/README.md` — 使用說明與設計理由。說明它如何用「base URL 環境變數或設定檔」把 agent 的流量導到 `http://localhost:8787`、哪些 agent 可以記錄（Cursor／Amp 因為 system prompt 在廠商伺服器組裝而做不到）、以及 Observer Effect（Claude Code 換 host 會關掉 tool search，所以要 `ENABLE_TOOL_SEARCH=true`）。對學習者而言，這是「資料來源」這一課的主文：先能擷取真實流量，才有東西可以診斷。
- `request-logger/model-discovery.ts` — 只有兩個 export：`parseModelIds`（從 OpenAI 相容的 `/v1/models` 回應取 `data[].id`，去重、跳過空字串）與 `discoverModelIds`（對 base URL 的 origin 打一次無認證的 `/v1/models`，3 秒 timeout，任何失敗都回空陣列）。意義是：自訂伺服器要先知道有哪些 model ID，但探索失敗不能變成致命錯誤。
- `request-logger/model-discovery.test.ts` — 用注入的 `fetchImpl` 與 fake timers 釘住探索行為：只打一次、URL 取 origin、不帶 headers、失敗與超時都回 `[]`。是「把網路呼叫當純函式測」的乾淨示範。
- `request-logger/config.ts` — wizard 的 glue 層：`loadChoice`／`saveChoice`／`clearChoice` 讀寫 `.agent-choice.json`，`askChoice` 依序問 agent、provider（或 custom base URL + wire format）、是否記住。註解反覆強調「只存選擇，host／renderer／command 每次重算」，所以 catalogue 更新會自動生效。
- `request-logger/config.test.ts` — 測 `.agent-choice.json` 的讀寫與毀損容錯（半寫入的 JSON 回 `null` 而不是丟錯），以及「一般答案只存 agent/provider」這個唯一例外規則。
- `request-logger/config-wizard.test.ts` — 用 `vi.mock` 換掉 `@clack/prompts` 與 `model-discovery`，測 wizard 的分支順序：只有一個模型時不問、探索失敗才手動輸入、OpenCode 只在 OpenAI 相容路線才探索模型、Pi 每種 wire format 都探索。
- `request-logger/agents.ts` — 整個工具的 single source of truth：一份 `AGENTS` catalogue（每個 agent 的 upstream host、renderer、base URL suffix、env、command、setup 檔）加上 `resolveChoice` 這個純函式，把「學生的選擇 + port + platform」轉成可路由的 target 或明確的 error/refusal/request。`shouldLogRequest` 也在此，決定哪些請求值得寫檔。
- `request-logger/agents.test.ts` — 最大的測試檔，逐 agent 釘住 upstream host、renderer、base URL suffix、指令字串（含 win32 PowerShell 語法）、setup 檔內容、notes/warnings、refusal 理由，以及 custom target 的模板借用規則。它讓 README 的表格不可能是錯的。
- `request-logger/proxy.ts` — 零依賴的 HTTP proxy 本體：`handle()` 緩衝請求 body、組 upstream path、轉發並把回應 stream 回 agent，結束後呼叫 `writeCapture()` 寫三個檔；另有 `upstreamConnection`／`upstreamPathPrefix`（custom base URL 的 scheme/port/path prefix）、`rejectUpgrade`（WebSocket → 426）、`trackBurst`（重試風暴節流）。
- `request-logger/proxy.test.ts` — 測 proxy 的純邏輯與一個真的 socket：`upstreamConnection` 的 https/443 與 http/自訂 port 推導、`upstreamPathPrefix` 的 `/zen/go` 保留、`rejectUpgrade` 回 426 不掛住、`trackBurst` 的門檻與視窗重置。
- `request-logger/render.ts` — 把擷取到的 request/response 變成可讀 Markdown：`decodeRequestBody` 解 zstd/gzip/br/deflate（失敗要大聲警告而不是顯示亂碼），`renderMarkdown` 依 renderer 分派到 Anthropic／OpenAI／Gemini／raw 四條路徑，並把 streamed SSE 重組成助手文字與 tool calls；secret headers 一律 `[REDACTED]`。
- `request-logger/render.test.ts` — 每個 wire format 各一組測試，外加 `raw` renderer 必須「不要」掉進 OpenAI parser 的反向斷言、壓縮 body 的解碼、header redaction。等於把「renderer 不亂猜」這個設計規則寫成可執行規格。
- `request-logger/logs/.gitkeep` — logs 目錄的佔位檔（內容只有一行註解），captures 本身被 gitignore。單次擷取的檔名形如 `2026-07-07T14-32-05-123_claude-code.md`，並伴隨同名的 `.request.txt` 與 `.response.txt`。

# L2 detail

- `#L1-L393` — `request-logger/README.md` — 使用文件與設計理由。說明啟動流程（`npm run request-logger`，第一次問 agent 與 provider，`--force` 重問，`PORT=9000` 換埠）、每個 agent 需要的設定（Claude Code 一條指令、Codex 一個 `-c` flag、Pi／OMP／Junie 要寫設定檔），以及 Cursor／Amp 為何原理上做不到：它們在本機只送訊息，system prompt 與 tool schema 在廠商伺服器才組裝，proxy 讀不到本機從未送出的東西。Observer Effect 段落給出實測數字（63,596 bytes → 39,013 bytes，小 39%），說明為何 Claude Code 的指令要帶 `ENABLE_TOOL_SEARCH=true`。核心資料流描述在「What you get」與「How it works」：每個請求寫三個檔案到 `logs/`（`.md` 可讀渲染、`.request.txt` 原始 bytes、`.response.txt` 原始 stream），`.md` 用 XML 標籤（`<request>`、`<system-prompt>`、`<tools>`、`<messages>`、`<response>`）而不是 Markdown 標題分段，因為被擷取的內容自己就充滿 `#`；secret headers 隱藏、壓縮 body 只有 `.md` 解碼。另有 housekeeping 呼叫（token 計數）「轉發但不寫檔」的規則、重試風暴節流、空 logs 的五種安靜失敗原因、以及誠實的測試範圍說明。本目錄沒有另外的 HTML viewer 檔案，這份 `.md` 就是 viewer。
- `#L1-L59` — `request-logger/model-discovery.ts` — 模型探索。`parseModelIds` 對 `{data: [{id}]}` 做防禦性解析：非物件、缺 `data`、非陣列都回 `[]`，逐筆要求 `id` 是非空字串，最後用 `new Set` 去重。`discoverModelIds` 只取 `new URL(baseUrl).origin` 再拼 `/v1/models`，刻意丟掉使用者輸入的 path（探索端點固定在 origin 上），用 `AbortSignal.timeout` 包 3 秒上限，`!response.ok` 或任何例外都吞成 `[]`。設計點：探索是錦上添花，永不該讓 wizard 卡死，所以呼叫端一定保留手動輸入的退路。
- `#L1-L81` — `request-logger/model-discovery.test.ts` — 釘住介面契約。`parseModelIds` 測標準回應、壞資料過濾，並用 `it.each` 覆蓋 `null`／`{}`／`data:{}`；`discoverModelIds` 用 `vi.fn()` 假 fetch 斷言「只呼叫一次」「URL 是 origin + `/v1/models`」「init 沒有 headers」（證明是無認證請求），再用三種失敗（網路錯誤、500、非 JSON）與 fake timer 超時證明一律回 `[]`。
- `#L1-L322` — `request-logger/config.ts` — 設定與 wizard。`loadChoice` 從 JSON 讀 `agent`，並把非字串的 `provider`／`customBaseUrl`／`customRenderer`／`customModel` 一律視為 undefined，手改壞的檔案不會炸。`clearChoice` 特意在 `--force` 提問前先刪檔，否則「選了一個不能記錄的 agent」會留下舊答案。`askCustomTarget()` 問 base URL（驗證必須是 http/https）與 wire format；`askDiscoveredModel()` 串起探索：0 個就警告並要求手動輸入、1 個直接採用（並印出訊息，因為沒得選就不該問）、2 個以上才開選單並保留手動選項。`askChoice` 是主流程：先列 agent（不支援的標 `cannot be logged`），`alwaysCustom` 的 agent 跳過 provider 問題，其餘都給 `Custom base URL`，最後才問是否記住。`stopIfCancelled` 讓 Ctrl+C 在任何一步都能乾淨退出。
- `#L1-L115` — `request-logger/config.test.ts` — 用 `fs.mkdtempSync` 建臨時目錄測三個函式。重點在「記住的答案」語意：寫什麼讀什麼、只有一個 provider 的 agent 讀回 `provider: undefined`、檔案不存在或壞掉都回 `null`（半寫入的檔案不該讓工具停下，重問就好）；另有四條測 custom base URL 這個唯一例外確實落盤，且一般答案的 key 只有 `agent`／`provider`。`clearChoice` 對不存在的檔案不拋錯。
- `#L1-L238` — `request-logger/config-wizard.test.ts` — wizard 分支的規格書，測的是「問問題的順序」而不是畫面。`vi.hoisted` + `vi.mock` 換掉 prompts 與探索模組，再用「第 N 次 select 回什麼」控制流程。關鍵斷言：OpenCode 只保留一個 `Custom base URL` 選項、discovered models 後面一定接「Enter a model ID manually」、只有一個模型時 select 只被呼叫三次（第四次就代表多問了）、探索失敗先 `console.warn` 再進手動輸入、OpenCode 的 anthropic/raw 與其他 agent 的 openai custom target 都不探索；Pi 則三種 wire format 都探索，非 custom 路線不探索。
- `#L1-L1400` — `request-logger/agents.ts` — catalogue 與解析，是整個工具的事實來源。型別面：`AgentChoice`（存檔內容）、`ResolvedTarget`（catalogue 目標，`upstreamHost` 固定走 HTTPS 443）、`CustomTarget`（學生輸入的 `upstreamBaseUrl`，可帶 path prefix）、`AgentRefusal`／`ResolveError`／`SetupRequest` 三種非目標結果。資料面：`AGENTS` 按人氣排序，每筆 provider 帶 `upstreamHost`、`renderer`、`suffix`、`env`、`bin`／`args`、`setup`、`notes`／`warnings`，以及 `customTemplateFor`（哪些 wire format 可借用這個 provider 的指令模板）；`alwaysCustom` 的 OMP 與 Junie 沒有固定 host，直接走 custom 問題。行為面：`shouldLogRequest` 只放行 POST，Gemini 只留 `generateContent`，其餘排除 `count_tokens`／`countTokens`；`listAgents` 把不支援的排到最後；`withEnv` 在 win32 改用 `$env:KEY = 'value';`，`powerShellQuote` 把單引號加倍。核心 `resolveChoice` 依序處理 Other（回 issue tracker 的 `request`）、未知 agent（`error`）、不能記錄（`refusal`），再分流到 `resolveCustomTarget` 或 catalogue provider，最後 `buildCommand` 把 base URL 填進 env／args 並組出 setup 檔內容。`resolveCustomTarget` 最精巧：借用模板（單一 provider 無條件借用、多 provider 只按 `customTemplateFor` 精準匹配）、OpenCode 的 OpenAI 路線用一次性的 `OPENCODE_CONFIG_CONTENT`、Pi 每條路線都要求 model 並改寫 `models.json`。
- `#L1-L1596` — `request-logger/agents.test.ts` — catalogue 的執行期契約，也是整個資料流的規格。`listAgents` 測完整順序與「不支援的全部排在支援的後面」；`listProviders` vs `agentProviders` 測兩者差異（後者連單一 provider 與 alwaysCustom 的內部模板都回）；upstream host、renderer、base URL suffix 逐 agent 斷言（OpenCode 的 `/v1`、Claude Code 不加 suffix、Pi codex 的 `/backend-api`）。指令測試精確到字串相等，含 win32 的 `$env:...;` 形式與「绝不出現 POSIX 形式」的反向斷言；OpenCode 的 `OPENCODE_CONFIG_CONTENT` 甚至用 `execFileSync` 讓 `/bin/sh` 真的展開再 `JSON.parse`，並測含引號與 shell metachar 的 model ID 不會注入。setup 檔測到 Pi 的 `baseUrl` 拼字、transport 必須放 settings.json 而非 models.json。其餘是 notes/warnings 關鍵字、refusal 理由、`shouldLogRequest` 十多種路徑、bad input 訊息含 `--force`，以及 custom base URL 的大量分支。它是很好的 feedback loop 範例：每條註解都寫著「為什麼會有這個測試」（issue #74 的 path prefix、Claude Code 換 host 會關 tool search、Codex 0.133.0 移除 `OPENAI_BASE_URL`），所以 README 那句「Claude Code／OMP 端到端測過、其餘只驗證文件」才站得住腳。
- `#L1-L587` — `request-logger/proxy.ts` — proxy 主體，也是「資料來源」的實際管線。啟動：`main()` 讀 `--force`、載入或詢問 choice、呼叫 `resolveChoice`，若 catalogue 已不認識存下的答案就重問；成功後印 banner（agent、`http://localhost:8787`、forward 目標、logs 路徑、要貼的設定檔內容、可直接複製的指令）並 `server.listen`。請求進來後：`handle()` 先把 body 收成 Buffer，算 `upstreamPath = upstreamPathPrefix(target) + req.url`（custom base URL 的 `/zen/go` 因此不會被丟掉），`forwardHeaders` 複製表頭（刪 host／connection／accept-encoding／transfer-encoding／content-length 並重算長度，但保留 `content-encoding`，因為上游必須收到原始壓縮 bytes），再依 `upstreamConnection` 選 `http` 或 `https` 送出。回應：`onUpstreamResponse` 把 status 與 headers 寫回 agent，邊收邊 `res.write(chunk)` 即時串流，`end` 時才 `writeCapture`。寫檔：`writeCapture` 先問 `shouldLogRequest`（housekeeping 只印一行），再用 `trackBurst`／`burstKey`（同 method+path+status、20 次／2 秒）擋重試風暴——超過門檻仍轉發，只是每 500 次印一行摘要；最後 `mkdirSync` 後寫 `${base}.request.txt`（原始 bytes，可重放）、`.response.txt`、`.md`（呼叫 `renderMarkdown`），`baseName` 產生 `2026-07-07T14-32-05-123_claude-code` 這種檔名。`rejectUpgrade` 對 WebSocket attempt 立刻回 426，因為若不回應，Node 會靜默關 socket，agent 永遠等不到回覆。檔尾的 `isMain` 判斷讓測試可以 import 純函式而不觸發 wizard。
- `#L1-L314` — `request-logger/proxy.test.ts` — 先經 `resolveChoice` 拿真 target 再測 proxy 的純函式。`upstreamConnection`：catalogue 一律 https:443，custom 則依 scheme 推 443/80 並尊重顯式 port。`upstreamPathPrefix`：針對 issue #74 的迴歸（`https://opencode.ai/zen/go` 不能被縮成 origin，否則每個請求 404），並驗證與 `/v1/chat/completions` 串接後是 `/zen/go/v1/chat/completions`。`rejectUpgrade` 那條不只呼叫函式，而是真的 `net.connect` 送 upgrade handshake，要求 1 秒內收到 `HTTP/1.1 426`，註解說明「hang 就代表退回舊的靜默丟棄行為」。`trackBurst` 測五種情境：分散的重複不壓制、同視窗超過門檻才壓制（剛好等於門檻還不算）、`justDetected` 只發一次、不同 signature 不受影響、超過視窗就重置。
- `#L1-L903` — `request-logger/render.ts` — 可讀渲染，也就是 viewer 的實作。`decodeRequestBody` 先看 `content-encoding`：空或 identity 直接 utf8；zstd 在 Node 沒有 `zstdDecompressSync` 時回一句明確的「需要 Node >=22.15」警告；gzip/br/deflate 各走 zlib；任何解不開或未知編碼都走 `decodeFailureWarning`，把原因與原始 bytes 一起印出——寧可大聲壞掉，也不要讓 binary 假裝是文字。`renderMarkdown` 依序組 `<meta>`（timestamp、agent、wire format、model、endpoint、status）、`<headers>`（`REDACT` 集合裡的 authorization／x-api-key／api-key／x-goog-api-key 換成 `[REDACTED]`）、`<request>`、`<response>`。`findModel` 先看 body 的 `model`，沒有才從 URL 的 `models/{x}` 取（Gemini 就是這條）。request 端三條 renderer：Anthropic 讀 `system`／`tools`／`messages` 並標 cache_control 斷點；OpenAI 同時處理 `messages`（chat）與 `instructions` + `input`（responses）；Gemini 先把 Google 登入的外層 `request` 拆掉，再讀 `systemInstruction`／`contents`／`tools`。`raw` 在三個地方都被最先檢查，直接傾倒 pretty JSON，避免悄悄落進 OpenAI parser。response 端把 SSE 的 `data:` 行抽出後重組：Anthropic 依 `content_block_start/delta` 累積並依 index 排序、OpenAI 分辨 `response.` 串流與 chat chunk、Gemini 合併 candidates 並把 thought 分開。任何 renderer 例外都退回註解加原始文字。
- `#L1-L484` — `request-logger/render.test.ts` — 把 renderer 當規格測。`decodeRequestBody` 覆蓋未壓縮／identity／zstd／gzip／大小寫，以及三種「必須大聲失敗」的情況（解不開、未知編碼、runtime 無 zstd——後者用 delete 掉 `zstdDecompressSync` 再還原）。`renderMarkdown` 對 Anthropic、OpenAI、Gemini（API key 與 Google 登入兩種信封）、raw 各寫一組斷言，最有價值的是 raw 那組負向斷言：`not.toContain("<system-prompt>")`、`not.toContain("<messages>")`，證明它沒有偷偷用 OpenAI 模板。另有 tool call/result、`role="model"` 而非 assistant、thinking 分離、NDJSON 退回原文、以及兩個 secret header 不得出現在輸出中。
