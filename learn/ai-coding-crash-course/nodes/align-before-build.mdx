# 先對齊再動手：Grilling、壓縮與交接

## Learning goal

能在代理寫任何程式前先跟它把設計談清楚，並讓工作跨 session 繼續而不掉出聰明區——plan mode 的盲點、grilling、compaction、handoff。

## Steps

1. [[learn/ai-coding-crash-course/nodes/align-before-build/plan-mode-blindspot|「先想清楚」還不夠，plan mode 為什麼還是會衝]] — 看出「先想清楚」為什麼還是不夠：代理衝太快、plan mode 產出的是資產不是共識、設計概念才是實作前缺的拼圖
2. [[learn/ai-coding-crash-course/nodes/align-before-build/grilling|動手前把設計談清楚，grilling 對齊法]] — 用 what+why 的輪問在動手前把設計談清楚，把主導權放回人手上（after step 1）
3. [[learn/ai-coding-crash-course/nodes/align-before-build/compaction|把長 session 壓進新 session，compaction 壓縮機制]] — 在長 session 逼近聰明區邊緣時，把知識壓成摘要種子進新 session，並看懂它「用資訊換效率」的代價（after step 2）
4. [[learn/ai-coding-crash-course/nodes/align-before-build/handoff|把上下文帶去別處，handoff 跨代理交接]] — 用可攜的 markdown 把上下文帶去別的代理、目錄或同事，並在 compact 與 handoff 之間依情境選擇（after step 3）

## Lesson

這個節點回答兩個問題。第一個是「動手之前怎麼把設計談清楚」。代理的預設是急著交差，你叫它蓋什麼它就蓋什麼，所以無論是直接實作還是開了 plan mode，它都可能蓋出你不要的東西。解法是 grilling，把對齊變成一個實作之前的明確階段，靠一整輪「做什麼＋為什麼」的問答把設計概念磨出來。對齊做得越好，實作就越像照著走。

第二個是「工作跨 session 怎麼不掉出聰明區」。對齊、實作、QA 疊在同一個 session 裡，上下文很快就逼近聰明區邊緣。繼續硬撐品質退化，清空上下文連「為什麼」一起丟掉。compaction 把整個 session 壓成摘要種子進新 session，保留決策、丟掉噪音；handoff 把同樣的知識寫成可攜的 markdown 檔案，讓它能跨代理、跨目錄、跨人。

串起四步的主線，是把代理留在聰明區，把主導權留在人手裡。對齊用對話省下重做的代價，壓縮與交接用「用資訊換效率」的交易省下品質與金錢的代價。四步走完，你面對的不是一台會猜的機器，而是一個先跟你確認、再帶著你一路做完的搭檔。
