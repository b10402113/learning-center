# 操作代理：Bash、權限與自動模式

## Learning goal

能控制代理能碰什麼、不能碰什麼，並安全地放手——bash 管理、permissions / settings、auto mode 與安全分類器。

## Steps

1. [[learn/ai-coding-crash-course/nodes/operating-the-agent/bash-visibility|控制 Bash 命令的可見性]] — 用 `!` bash 模式、Ctrl+B 背景執行、Ctrl+Z 掛起三種方式，決定代理能看見哪些命令與輸出。
2. [[learn/ai-coding-crash-course/nodes/operating-the-agent/permissions-settings|權限模型：代理能碰什麼]] — 用 allow once / forever、deny、wildcards 與 `settings.local.json` vs `settings.json`，控制代理可執行的命令。（after step 1）
3. [[learn/ai-coding-crash-course/nodes/operating-the-agent/auto-mode|自動模式：讓安全分類器把關]] — 理解 auto mode 的 LLM 分類器如何取捨安全與手動把關，並知道何時適合放手。（after steps 1–2）

## Lesson

要讓代理成為可靠的協作者，先要能控制它。這個 node 的立場是：控制從「看得見」開始，再到「碰得到」，最後才是「放手讓它跑」。三個步驟剛好對應這三段。

第一步處理可見性。代理透過 harness 執行 bash 命令，但你能決定它看到哪些命令與輸出——`!` 模式讓它連同 live log 一起看，Ctrl+B 把長時間命令丟到背景，Ctrl+Z 掛起整個代理讓你在它看不見的地方跑命令。看得見與看不見，直接決定代理拿什麼資訊做判斷。

第二步處理權限。代理想自己跑命令時，harness 用嚴格預設的權限模型把關：允許一次、永遠允許、拒絕，還能按 tab 換成更安全的命令。規則寫在 `.claude/settings.local.json`（個人、被 git 忽略）或 `settings.json`（提交、團隊共用），支援萬用字元與 deny 清單。這是「代理能碰什麼」的正式閘門。

第三步處理放手。auto mode 把每條命令交給 LLM 分類器，由它從對話脈絡判斷安全性，代價是每條命令多花 token 與時間，換來幾乎不用介入的運作。分類器不完美，會漏放也會誤擋，但擋得住大方向上的災難。知道它怎麼判斷、`settings.json` 的 allow-list 怎麼優先於它，你才能在「放手」與「把關」之間選對位置。

三步合起來是一條完整的安全弧線：先控制代理看得見什麼，再控制它能做什麼，最後在有規則、有分類器、有 allow-list 的前提下安全地放手。
