# 把上下文帶去別處：handoff 跨代理交接

## Learning goal

能用 /handoff 產出可攜的交接文件、用 @temp/... 把它帶進新 session，並在 compaction 與 handoff 之間依情境做出正確選擇。

## Lesson

### 🔒 壓縮有一道出不去的高牆

上一課我們學會了壓縮（compaction）。工作階段（session）逼近聰明區（smart zone）邊緣時，你用 `/compact` 把整個 session 濃縮成一張摘要，種進一個全新的 session，就能一直待在聰明區裡繼續工作。但壓縮有一道牆，而且是一道很硬的牆。它只能在同一個目錄、同一個代理（agent）內部運作。

把這句話拆開看。「同一個目錄」指的是你啟動代理的那個工作資料夾。壓縮出來的摘要，只能在這個資料夾裡的新 session 中被種子化（seed），它離不開這個資料夾。「同一個代理」指的是壓縮只能在同一個代理工具（harness）裡自我循環，摘要留的是那個工具的記憶體、那套規則、那個 session 的延續。

這道牆在實務上非常具體。假設你用 Claude Code 做完了一個功能的實作，程式碼寫好、測試跑過，但你想換個角度讓 Codex 來做審查（review）。用壓縮辦不到。壓縮的摘要出不了 Claude Code 的目錄，也進不了 Codex 的世界，因為那是不同的代理、不同的工作目錄，兩者之間沒有通道。同樣地，你想把工作帶去另一個儲藏庫（repo），或是交給一位同事接手，壓縮全都幫不上忙。它生來就是一個「在原地、在同一個代理身上」運作的機制。

### 📄 交接的理論：把壓縮搬到代理工具之外

於是有了 [[learn/ai-coding-crash-course/elements/handoff|Handoff 跨代理交接 (Handoff)]]。它的理論很簡單，把壓縮的整個流程，從代理工具的內部搬到外面去。

壓縮是怎麼運作的？它在 harness 內部、在代理工具的記憶體裡，就地把你目前的工作階段濃縮成一張摘要。交接則反過來做。它把摘要寫成一份標記文件（markdown file），叫做 `handoff.md`。這份檔案的內容是「總結目前的對話，讓一個全新的代理可以接著做下去」。摘要就從代理工具的記憶體裡，搬到了檔案裡。

**為什麼「它是一份檔案」很重要？** 只要脈絡以檔案的形式存在，它就完全可攜帶（portable）了。你可以對它做任何事：

- **餵給另一個代理工具**：把 `handoff.md` 讀進 Codex，Codex 就等於接過了 Claude Code 的全部脈絡。
- **交給另一個目錄裡的代理**：在同一個 repo 的另一個資料夾，或是完全另一個 repo，開一個代理，把檔案帶進去。
- **寄給一位同事**：它只是一份普通的 markdown 文字檔，直接轉寄給人就行，對方用自己的代理接手。
- **先把不相干的 bug「停車」起來**：你正在做某個功能（feature），途中瞥見一個跟這個功能完全不相干的 bug，你不想現在分心。那就先寫一份交接文件把它記錄下來，之後再開一個獨立的 session 回來修。功能的進度一點都不受影響，那個 bug 也不會被忘掉。

最後這個「停車」場景，是交接最漂亮的用法之一。你找到了一個不會讓任何事情失落的暫停方式，功能可以繼續，bug 也不會丟。壓縮做不到這件事，它只能在原地、在當下的代理身上運作。交接因為產出的是檔案，脈絡就可以被自由地攜帶、擱置、再撿起來。

### 🗑️ 刻意存進暫時目錄：生來就是暫時性的

交接文件會被存到哪裡？答案是作業系統（operating system, OS）的暫時目錄（temp directory）。

這個位置是刻意的設計。存進暫時目錄，意思是這些交接文件生來就是暫時性的（ephemeral）。它們不會被存進本機的一般檔案系統，也不會被存進任何記憶體（memory）。它們只會活到「你的電腦下一次重開機」或是「作業系統哪天決定清空暫時目錄」的那一刻。在那之後，它們就被刪掉。

**為什麼要這樣設計？** 因為交接文件的本質是中轉站。它的用途是把脈絡從一個 session 搬到另一個 session、從一個代理搬到另一個代理。搬完了，這份文件就完成了任務，不需要長期保存。把它放在暫時目錄裡，等於告訴自己和作業系統，這是用完即棄的東西，不必當成資產看待。你真的想長期保留某段脈絡時，正確的做法是把重要的東西寫回 repo，寫成文件、註解或規格，而不要指望一張交接單。

這個設計對使用者的實際影響是，交接文件是易逝的。產生了就趕快用，開新 session 把它讀進去、寄給同事，或是確認它已經完成使命。不要產生完就放著不管，指望隔天還在。它就像寫在便利貼上的留言，寫完就要貼到該貼的地方，不然打掃阿姨一來就沒了。

### 🔧 操作：`/handoff <purpose>`

實際操作跟壓縮很像，只有一個關鍵差異。在 Claude Code 裡，你執行：

```
/handoff pass to codex to review
```

就像 `/compact` 可以帶一句總結指示（summarization instruction）一樣，`/handoff` 也要帶上你交接的目的（purpose），也就是你要把工作交給誰、讓對方做什麼。這裡的例子是「交給 codex 去 review」。你把交接的原因講清楚，交接文件就會往那個方向寫。

**為什麼要給目的？** 因為負責寫交接文件的也是一個大型語言模型（large language model），它需要方向才知道這份文件該把重點放在哪裡。要讓接手者做審查、修 bug，還是接著寫某個功能，模型都靠你給的這句目的來判斷。

執行之後，代理會請求寫入暫時目錄，然後你就得到了一份 `handoff.md`。打開來讀，你會發現它讀起來像一份非常詳細的壓縮文件（compacted document），跟你之前看到的 `/compact` 產物長得很像，但它更細、更完整。它包含大量的檔案引用（file references），把該看的檔案、該知道的決策，還有該注意的約定，全部列得清清楚楚。它是一份「接手者照著做就能繼續工作」的完整交接單，比一張摘要式的重點提示詳細得多。

用歷史學家的詞彙來說，這份文件是一份次要史料（secondary source）。它跟你壓縮出來的摘要一樣，都是主要史料（primary source，也就是原始 session 的紀錄）的有損壓縮。它同樣有遺失細節的代價。但因為它是為「交接」這個明確目的而寫、而且寫得詳細，它在「讓一個陌生代理接手」這件事上，比壓縮摘要更靠得住。

### 🚀 使用：開新 session，用 @temp/... 帶進上下文

拿到 `handoff.md` 之後，怎麼讓新代理接手？步驟很簡單，只有兩步。

第一步，開一個全新的、已清空的 session。如果你正待在舊 session 裡，就清空上下文（clear the context）。按下清除、回到一張白紙，或者直接在一個新的視窗、新的代理裡打開。

第二步，用 `@` 符號指向暫時目錄裡的檔案，把它帶進上下文視窗（context window）。在 Claude Code 裡，輸入框打 `@` 會跳出檔案引用選單。你輸入 `temp` 就會看到暫時目錄，找到那份 `handoff course star ratings review` 之類的檔案，選它。一選中，這份文件就會立刻被讀進上下文視窗。它直接把內容放進當下的上下文裡，就像你用 `@` 帶任何檔案進 prompt 一樣，不會只留下一個檔案指標讓代理之後再去讀。

一旦被種子化（seeded），新 session 就不再是一張白紙。它知道自己接下來要做什麼（例如 review star rating 系統）、該看哪些檔案、該遵守哪些決策。新代理等於接過了舊 session 的脈絡，可以馬上開始工作，不需要重新探索、不需要你重新解釋一遍。整個過程跟壓縮的「摘要種子進新 session」幾乎一樣。差別只在於這份種子的來源，壓縮從舊 session 就地濃縮，交接從一份檔案讀進來。

### 📊 比較：compaction vs handoff

到這裡，兩種機制的輪廓已經清楚了。把它們攤開來對比：

| 面向 | 壓縮（compaction） | 交接（handoff） |
| --- | --- | --- |
| 產物 | 留在代理工具記憶體裡的摘要 | 一份可攜帶的 markdown 檔案 `handoff.md` |
| 作用範圍 | 同一個目錄、同一個代理 | 跨代理、跨目錄、跨 repo、跨人 |
| 儲存位置 | 代理工具的 session 記憶體 | 作業系統的暫時目錄（temp directory） |
| 暫時性 | 摘要隨新 session 活著 | 暫時性（ephemeral），OS 一清就沒了 |
| 使用方式 | `/compact` 就地種子化新 session | `/handoff <purpose>` 產檔，再用 `@temp/...` 帶進新 session |
| 接續下一段對話 | 順，壓縮完可排入訊息（queue a message）自動接上 | 瑣碎（fiddly），要自己開新 session、手動把檔案帶進去 |
| 靈活度 | 較低 | 較高，檔案可寄、可帶、可擱置 |
| 最適合的場景 | 留在同一個目錄繼續工作、只想保留上一段對話的脈絡 | 跨越代理、目錄、repo 或人際邊界 |

讀這張表，一句話就能抓到結論。壓縮順手但封閉，交接靈活但瑣碎。

### 🤔 何時選誰：依情境下判斷

既然兩者之間沒有「一個取代另一個」的關係，真正的工作就是把「什麼時候用哪個」的判斷練成直覺。決策可以濃縮成兩條主線。

**選壓縮（compaction）**，當你留在同一個目錄、同一個代理裡繼續工作的時候。這是最常見的情況。你剛做完實作，準備在同一個專案資料夾裡接著做 QA，你不需要把工作搬去任何地方，只需要把上一段對話的脈絡保留下來、把噪音清掉。這種時候壓縮幾乎總是更好的選擇，尤其因為壓縮完可以排入訊息（queue a message）。你把「壓縮完之後要做的下一件事」先打進去排隊，壓縮一完成代理就自動接手，你完全不用自己接線。這是壓縮獨有的順暢。交接做不到這件事，因為它要求你手動開新 session、手動帶檔案。

**選交接（handoff）**，當你要跨越某道邊界的時候。要不要跨代理（Claude Code 交給 Codex）、要不要跨目錄或跨 repo（在另一個專案裡修 bug）、要不要跨人（寄給同事）、或要不要「把一個不相干的發現先停車起來」。這些場景壓縮全都辦不到，因為摘要出不了原目錄、原代理。只要你正在把工作帶去一個壓縮到不了的地方，交接就是那個時候的答案。

[[learn/ai-coding-crash-course/elements/compaction|Compaction 壓縮機制 (Compaction)]] 是你在原地、在熟人圈裡的預設選項。[[learn/ai-coding-crash-course/elements/handoff|Handoff 跨代理交接 (Handoff)]] 是你在要出門的時候才拿出來用的工具。兩者共用同一個核心心智模型，把 session 的知識濃縮成一份次要史料帶走，也都付出「遺失細膩度」的代價。差別只在於這份史料留在原地，還是寫成一份可以帶走的檔案。

### ✅ 實戰清單：在真實工作裡用交接

把上面的機制收斂成幾個可以立即套用的動作：

1. **認得該交接的那一刻**：當你想把工作交給另一個代理工具、帶去另一個目錄、交給同事，或想把一個不相關的 bug 先「停車」起來，這就是 `/handoff` 的時機。
2. **執行 `/handoff <purpose>`，把目的講清楚**：例如 `/handoff pass to codex to review`。寫交接文件的也是一個模型，它需要方向才知道重點放哪。
3. **趕快用，不要囤**：文件存在作業系統的暫時目錄，生來是暫時性的。電腦重開或 OS 清暫時目錄就沒了。產生了就開新 session 帶進去，或立刻寄出。
4. **開一個全新、清空的 session，用 `@temp/...` 把檔案帶進上下文**：選中檔案後它立刻被讀進上下文視窗，新代理直接接手，不必重新探索。
5. **留在原地時，別忘了壓縮**：只要不跨代理、不跨目錄，壓縮依然更好，尤其壓縮完能排入訊息自動接續。交接的「接線到下一段對話」比較瑣碎，只有在真的跨了邊界、得到好處時才划算。

交接和壓縮沒有高下之分，它們是兩種適用不同場合的工具。壓縮把話留在同一間會議室裡繼續開會。交接則把會議記錄寫成一張紙，讓你帶去另一間會議室、交給另一個人，甚至隔天再拿出來處理。想清楚自己是要「留在原地」還是「把話帶到別處」，你就能在兩種機制之間，每一次都做出正確的選擇。
