# Claude Code 進階提示：@ 引用、暫存與圖片貼入技巧

## Learning goal
能用 @ 引用檔案、Ctrl+S 暫存草稿、貼上圖片來豐富提示

## Lesson

### 三個操作，解決三個摩擦點

[[learn/ai-coding-crash-course/elements/advanced-prompting|進階提示技巧 (Advanced Prompting)]] 是 Claude Code 為真實專案場景設計的三種操作：用 `@` 引用檔案、用 `Ctrl+S` 暫存草稿、從剪貼簿貼入圖片。我們逐一拆解它們的運作機制和價值。

---

### 📝 @ 引用檔案：把檔案內容直接塞進上下文

**場景：** 你正在重構一個模組，需要同時參考三個檔案。沒有 `@` 的話，你要手動複製路徑、等模型用工具讀取、再等它回來，每多一個檔案就多一輪來回。

**怎麼操作：** 在輸入框打 `@`，系統立刻啟動模糊搜尋（Fuzzy Search），根據你輸入的關鍵字自動過濾專案中所有檔案。不需要記住完整路徑，輸入部分檔名，用 Tab 或 Enter 選取即可。

```
請根據以下三個檔案的現有實作進行重構：
@src/services/user-service.ts
@src/models/user.ts
@tests/user-service.test.ts
```

三個檔案的完整內容會在第一次模型請求中一併送出，模型從第一次回應就擁有全部參考資訊。相較之下，不使用 `@` 時模型需要額外工具呼叫才能讀取檔案，每多一個檔案就多消耗一輪 token。

**模糊搜尋的額外好處：** 記得某個檔案叫 `config` 開頭？輸入 `@config` 就會列出所有匹配結果，從中挑選即可。大型專案中不必反覆切換到檔案總管確認路徑。

**為什麼 `@` 很重要？**
它改變了上下文的傳遞方式——從「模型主動去讀」變成「你直接塞給它」。第一輪互動就拿到完整資訊，省掉工具呼叫的來回成本，回應品質也更穩定。

---

### ⚡️ Ctrl+S 暫存草稿：沒寫完不急著送出

**場景：** 你在撰寫複雜提示，寫到一半發現需要先貼入一段程式碼、修正路徑、或補充新的要求。你已經輸入了大量文字，不想從頭再寫，但現在送出又不完整。

**怎麼操作：**

1. 按下 `Ctrl+S`，當前輸入框的草稿被暫存，輸入框清空
2. 你自由執行其他操作：貼入程式碼、執行命令、做任何需要的事
3. 按回復快捷鍵，先前暫存的草稿重新出現
4. 繼續編輯、精煉，最後才正式送出

**沒有暫存功能時會怎樣？** 你可能先把不完整的提示送出去，等模型回應後再補充說明；或者在心裡記住「等等要加上那段程式碼」，結果忘了。暫存功能讓你不需要在「沒準備好」和「強行送出」之間二選一。

**為什麼暫存很重要？**
提示的品質直接決定回應的品質。暫存讓你從容地打磨每一個提示，確保模型拿到的是完整且正確的資訊，而不是半成品。對 Agent 給回饋時尤其關鍵——你可能需要先加入一段程式碼範例、修正一個路徑、或補充一個要求，暫存讓你隨時抽離再回來，最後才正式送出。

---

### 📷 圖片貼入：終端機裡的視覺輸入

**場景：** 你遇到一個 UI 錯誤，想讓模型看問題長什麼樣。沒有的話，你得用文字描述「那個按鈕偏右了大約 5 像素」，模型還不一定能理解。

**怎麼操作：** 在任何圖片查看器中複製一張圖片（截圖、設計稿照片皆可），切回 Claude Code 輸入框，貼上。即使你在終端機（Terminal）環境中也能直接從剪貼簿（Clipboard）貼入圖片。

貼入的圖片會被納入多模態輸入（Multodal Input），模型同時處理文字和圖片的資訊。實際演示中，有人貼入了一張斯洛維尼亞布萊德湖（Lake Bled）的照片，模型正確辨識並描述了照片中的景點，證明視覺資訊的傳遞在終端機中是完整且可靠的。

**日常開發的三個主要應用場景：**

| 場景 | 怎麼用 | 為什麼有效 |
|------|--------|-----------|
| 錯誤排查 | 貼入錯誤訊息截圖 | 模型同時看到錯誤畫面和文字描述，診斷更精準 |
| 設計稿比對 | 貼入 UI 設計稿截圖 | 直接比較目前實作與設計稿的差異 |
| 介面問題回報 | 截取異常畫面貼入 | 讓模型直接看到問題，省去文字描述的理解偏差 |

**為什麼圖片貼入很重要？**
一張截圖可以傳達的資訊，用文字可能需要幾百字才能表達清楚，而且還容易產生理解偏差。圖片貼入讓你直接把「看到的」交到模型手上，省去翻譯成文字的中間環節。

---

### 為什麼這三個功能值得記住

三個功能，一個核心問題：**如何在有限的互動輪次中，把最完整的上下文交到模型手上。**

| 功能 | 解決的問題 | 效果 |
|------|-----------|------|
| `@` 引用檔案 | 模型需要多輪工具呼叫才能讀取檔案 | 第一次請求就拿到完整檔案內容 |
| `Ctrl+S` 暫存 | 沒準備好的提示被迫送出 | 從容打磨，確保模型拿到完整資訊 |
| 圖片貼入 | 視覺問題難用文字描述 | 直接傳遞視覺資訊，省去描述成本 |

掌握這三招，不只是操作更快，更重要的是模型拿到的上下文更完整，回應品質自然也會更好。
