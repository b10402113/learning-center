# Claude Code 5 大核心指令：/usage /context /clear /terminal-setup / escape

## Learning goal
能啟動 Claude Code、完成終端設定、使用 /usage /context /clear 等核心指令，並在需要時中斷代理

## Lesson

[[learn/ai-coding-crash-course/elements/cli-core-commands|CLI 核心指令 (Core CLI Commands)]] 是你操控 AI coding agent 的基礎。這一篇文章用 5 個具體指令，帶你從「只能等它回覆」變成「能隨時觀察、打斷、重置」的主動操控者。我們會先搞清楚你跟 agent 之間的操控介面是什麼，再一個一個拆解每個指令的用途與實務技巧。

---

### 📝 什麼是 CLI harness？為什麼所有 AI coding 工具都需要它？

AI coding agent 不能自己跑——它需要一個操控介面來接收你的指令、讀取檔案、執行操作。這個介面叫做 **harness**（操控環境）。你跟 agent 之間的每一次互動：送出指令、觀察回覆、中斷執行，全都透過 harness 完成。

當這個介面運作在終端機裡，它就是 **CLI harness**（命令列操控環境）。

市面上的 AI coding 工具——Cursor、Aider、Windsurf、Claude Code——底層做的事大同小異：

| 功能 | 說明 |
|------|------|
| 把你的輸入送到模型 | 接收你的指令 |
| 把模型的輸出顯示回來 | 顯示回覆 |
| 檔案讀寫 | 讀取、修改專案檔案 |
| 終端執行 | 執行 shell 指令 |

這門課程用 **Claude Code** 做示範，因為它廣泛使用且功能完整。但所有原則適用於任何 CLI harness——你可以用自己熟悉的工具跟著學。

---

### 💡 50/50 心智模型：一半靠模型，一半靠環境

在深入指令之前，先建立一個關鍵心智模型：

> AI coding 的整體效果 = **模型（50%）** + **harness 環境設定（50%）**

用一個類比：模型是員工，harness 是公司基礎設施。再優秀的員工，如果工具缺失、流程混亂，也無法高效產出。反之，一個良好的環境設定能讓任何合理的模型都表現出色。

**effort level（推理 effort 等級）** 是另一個旋鈕。effort 越高，輸出 token 越多，回覆越慢，成本越高——但品質並非線性提升。

**為什麼這個心智模型很重要？** 因為實務上的最佳策略是：**固定模型和 effort level，把心力花在優化 harness 與環境設定上**，而不是每次任務都換模型。

此外，harness 能把任務 **委派（delegate）給子代理（sub-agents）**。主代理（orchestrator）同時派生多個子代理，各自用不同模型或 effort level。子代理做完後把摘要傳回主代理，就像資深工程師派 junior 做研究再回報。這是 context management（上下文管理）的關鍵技巧，後續會大量使用。

---

### 🔧 啟動 Claude Code：從 `claude` 指令開始

**第一步：在終端機中執行 `claude`。**

在 VS Code 裡，最佳做法是用 **整合式終端機（integrated terminal）**——它繼承了 VS Code 的工作目錄與環境變數，確保你跟 agent 看到的環境一致。這可以避免終端環境不一致的問題。

執行後你會看到一個提示符號（prompt），代表 agent 已經準備好接收指令。這時候你可以直接用自然語言跟它對話。但真正的操控能力來自接下來要介紹的核心指令。

---

### ⚡️ `/terminal-setup`：第一步的必要設定

啟動後，第一件事是執行 `/terminal-setup`。它會安裝按鍵綁定（key bindings），最關鍵的是 **shift+enter**。

**為什麼需要 shift+enter？**

在預設狀態下，按 enter 會直接送出訊息。但你撰寫多行指令時，經常需要在中間插入換行而不送出。shift+enter 讓你在不送出的情況下插入換行，是撰寫多行指令的基礎操作。

**實務建議：** 執行 `/terminal-setup` 後立刻測試：
1. 按 **shift+enter** → 確認能正常換行
2. 按 **enter** → 確認能正常送出

這兩個按鍵的分工，是你跟 Claude Code 互動的基本節奏。聽起來是小事，但在實務中你會頻繁依賴它。

---

### 📊 `/usage`：追蹤你的 token 配額

`/usage` 顯示當前 session 與 **每週配額（weekly limit）** 的剩餘量。

AI coding agent 的使用通常有兩層限制：

| 限制類型 | 說明 |
|---------|------|
| 每週上限 | 一週內能使用的總 token 數 |
| Session 上限 | 單次對話的 token 額度 |

**當你覺得回覆變慢或成本上升時，第一件事就是執行 `/usage`。**

它會告訴你本週還剩多少 token 額度、本 session 已經用了多少。如果你接近週配額上限，即使 session 正常也可能無法繼續使用，因此需要提前規劃。

**為什麼 effort level 也會反映在 usage 上？** 因為高 effort 會產生更多輸出 token，更快耗盡配額。這是你在調整 effort 時需要意識到的代價。

---

### 🔍 `/context`：看見 agent 的視野

`/context` 是除錯你目前設定的首選指令。它把 **context window（上下文窗口）** 的內容拆解為幾個類別：

| 類別 | 說明 |
|------|------|
| System prompt | 系統級指令，佔據空間 |
| Tools | 工具定義 |
| Skills | 已安裝的技能 |
| Messages | 對話歷史 |
| 總容量 | context window 的上限 |

context window 是模型一次能「看到」的全部資訊。如果 system prompt 已經佔掉大量空間——例如你裝了很多 skill，每個都往 system prompt 裡塞定義——你的可用空間會比預期小。

**為什麼先看 context 是調整與優化的前提？** 因為你必須知道空間被什麼佔據了，才能決定下一步怎麼調。建議每次開始新工作前，先執行 `/context` 確認佔用比例，確保 system prompt 沒有佔掉不成比例的空間。這就像飛行員起飛前檢查儀表板——你不希望飛到一半才發現油量不足。

---

### 🔄 `/clear`：重置 session 狀態

`/clear` 把整個 context 歸零。另一個等效操作是 **連按兩次 Ctrl+C**，效果相同：清空所有脈絡，從零開始。

為什麼這可行？因為模型本身是 **無狀態的（stateless）**——它沒有「記憶」，只有每一次 request 裡送入的 context。`/clear` 就是把這個 session 的所有累積內容清空，讓你從全新的狀態開始。

**什麼時候該用 `/clear`？**

- agent 的回覆品質明顯下降
- context 已累積太多無關的對話紀錄
- 你完成了一個任務，要開始全新的任務

**⚠️ 注意事項：** `/clear` 會丟棄所有脈絡，包括之前討論過的決定和上下文。在 clear 之前，確認你已經把重要資訊記在其他地方。

---

### ⛔ escape 鍵：執行中的即時中斷

escape 鍵的功能是 **中斷（interrupt）正在執行的代理**。

假設 agent 正在跑一個計畫，結果它開始刪除你不該刪除的檔案——你可以在任何時候按 escape 打斷它。代理會在這裡插入一段「interrupted」的訊息，然後問你接下來想怎麼做。

**escape vs /clear：一次對比**

| 操作 | 用途 | 脈絡 |
|------|------|------|
| **escape** | 執行中打斷 | 保留脈絡，由你決定下一步 |
| **/clear** | 重置 session | 丟棄脈絡，從零開始 |

escape 保留脈絡，clear 丟棄脈絡。這是你在操控 agent 時最重要的區別。

**為什麼 escape 這麼重要？** 因為養成隨時準備按 escape 的習慣，特別是當 agent 開始進行你沒預期到的操作時，能讓你避免災難性的後果。這就像飛機上的緊急中止按鈕——你希望它永遠不需要被按下，但你必須知道它在哪裡、怎麼用。

---

### ⚡️ 從被動等待到主動操控

掌握這 5 個核心指令，你從「只能等它回覆」的被動角色，轉變為「能隨時觀察、打斷、重置」的主動操控者。

**五大指令速查：**

| 指令 | 功能 | 使用時機 |
|------|------|---------|
| `/terminal-setup` | 安裝按鍵綁定 | 第一次啟動時 |
| `/usage` | 查看配額剩餘量 | 回覆變慢或成本上升時 |
| `/context` | 觀察 context window 組成 | 開始新工作前 |
| `/clear` | 重置 session 狀態 | 回覆品質下降或開始新任務時 |
| **escape** | 執行中即時中斷 | Agent 做出預期外的操作時 |

這 5 個指令加上基本的自然語言對話，構成了你跟 AI coding agent 互動的完整基礎。掌握了這些，你已經有能力開始真正的 AI coding 實戰。
