# Claude Code Rewind Resume Fork：會話回退、恢復與分岔

## Learning goal
能回退代碼與對話到檢查點、恢復或分叉過去的 session

## Lesson

### ⚡️ 為什麼你需要會話導航

你和 Claude Code 寫了一小時的程式碼，結果代理做了一個你不想看到的改動——刪錯檔案、實作方向搞反、或者連續改了五個檔案但結果完全不對。你想回到五分鐘前的狀態。但這不是按一個「撤銷」就能解決的事：對話歷史是單向累積的，而檔案系統的變更是多個步驟穿插的結果，你沒辦法光靠嘴說就讓一切復原。

這就需要 [[learn/ai-coding-crash-course/elements/rewind-resume-fork|會話導航：Rewind、Resume 與 Fork (Session Navigation)]]。它的核心價值是讓你**精確地選擇回到哪個時間點、復原哪些東西**，從而解決 AI coding agent 最根本的信任問題——如果你不能回退，你就不會敢讓代理做太多事。

### 📝 Rewind：回到過去的時間點

Rewind 是會話導航的核心操作，有兩種進入方式：

| 方式 | 操作 | 精確度 |
|------|------|--------|
| 口頭指令 | 對代理說 `revert that` | 只能撤銷最近一次動作 |
| 快捷鍵 | 連按兩次 Escape | 可選擇任意歷史 checkpoint |

兩次 Escape 會打開 rewind 選單，列出對話歷史中所有 checkpoint（檢查點），每個 checkpoint 代表一個你可以回到的時間點。選一個就能決定要復原到哪裡。

#### 三種復原選項

選擇 checkpoint 後，你會面對三個選項：

1. **Restore code and conversation**（還原程式碼與對話）：程式碼和對話都回到那個時間點，彷彿後面的事沒發生過。大多數情況下你會選這個——最安全、最徹底。

2. **Restore conversation only**（僅還原對話）：程式碼維持不動，對話歷史回到那個時間點。適用於程式碼沒問題、但對話太冗長想清理的場景。

3. **Restore code only**（僅還原程式碼）：對話歷史保留，程式碼回到那個時間點。適用於代理在錯誤方向上改了多個檔案、但你在對話中已經確認正確設計方向的場景。

三者的差異在於**你要回溯的範圍**——純程式碼、純對話、還是兩者。

#### Summarize from here：壓縮後重新出發

Rewind 模式還有第四個選項：**「summarize from here」**（從這裡摘要）。它把你選的 checkpoint 到目前為止的對話壓縮成一份摘要，再用摘要建立一個全新 session。

這結合了 rewind 的回溯能力和 compaction 的壓縮能力，讓你從某個歷史脈絡繼續工作，而不必帶著整段冗長的對話歷史。

### 💡 Session 持久化：你的工作不會消失

Claude Code 會把每次 session 持久化（persist）到本地磁碟。你關掉終端機、甚至重開電腦，session 資料都還在。

每個 session 都有一個 UUID（唯一識別碼），用來精確找到並恢復特定的 session。UUID 通常在上一次 session 結束時顯示在輸出中。但你就算沒記下 UUID，也有其他方式找到過去的 session——這就是 Resume 機制。

### 🔧 Resume：三種恢復已結束 session 的方式

| 指令 | 用法 | 適合場景 |
|------|------|----------|
| `claude --continue` | 直接執行，不需參數 | 剛關掉終端機，想無縫接軌上次的工作 |
| `claude resume <UUID>` | 提供特定 session 的 UUID | 跳過多個 session，直接回到某個歷史狀態 |
| `/resume` 指令 | 在新 session 裡輸入 | 不知道 UUID，或需要從大量歷史中搜尋 |

這三種方式從「無腦恢復最近」到「精確恢復特定」覆蓋完整粒度。核心概念只有一個：**session 不會因為你關了終端機就消失**。

### ⚡️ Fork：從某個時間點分岔

Fork 是從一個既有 checkpoint 建立一個全新的 session。它複製那個時間點的完整狀態（對話歷史 + 程式碼），從該點開始獨立發展。

**使用場景：**你在某個方向上工作了一段時間，想嘗試另一個方向，但不想放棄已有的脈絡。Fork 之後，原始 session 仍然存在；新 session 從 fork 的那個時間點開始，兩個分支互不影響。

操作方式是在 rewind 模式中選一個 checkpoint，再選 fork。你可以把這想像成 `git branch`——從某個 commit 分岔出新分支，原始分支不受影響。

### 💡 為什麼非確定性讓你特別需要這些工具

AI coding agent 的輸出具有**非確定性**（non-determinism）：即使你給了相同的 prompt，模型在不同時間可能改不同的檔案、用不同的實作方式、甚至走完全不同的方向。這不是 bug，而是這類工具的本質特性。

非確定性意味著你無法預測代理下一步會做什麼。它可能做出驚人的改進，也可能做出災難性的破壞。如果你不能回退，你就會本能地限制代理的操作範圍——只讓它改小檔案、只做簡單任務——從而失去 AI coding agent 最大的價值。

Rewind、Resume 和 Fork 一起解決了這個問題：

- **Rewind**：你不必害怕犯錯
- **Resume**：你不必害怕中斷
- **Fork**：你不必害怕探索

它們讓你敢於讓代理做更多事情，因為你知道每一步都是可以回退的。

如果說 context 管理是「桌上有什麼文件」，那會話導航就是「知道你可以把時鐘轉回哪一個時刻，以及轉回去之後桌上的文件會變成什麼樣子」。
