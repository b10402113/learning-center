# 上下文衛生：讓代理保持在聰明區

## Learning goal

能透過管理代理的上下文把它留在 smart zone——重置 harness、刪掉 system prompt 的贅肉、在狀態列接上 token 計數器、探索全新 session 對 repo 知道多少。

## Steps

1. [[learn/ai-coding-crash-course/nodes/context-hygiene/reset-the-harness|重置代理外殼]] — 備份並重置代理設定，建立乾淨的 context 基線。
2. [[learn/ai-coding-crash-course/nodes/context-hygiene/strip-system-prompt-bloat|清除 System Prompt 贅肉]] — 找出並移除會污染每次請求的無用工具、技能與連接器。（after step 1）
3. [[learn/ai-coding-crash-course/nodes/context-hygiene/measure-context-continuously|持續測量上下文]] — 用 `/context` 與 status line 追蹤 token 消耗，維持 smart zone。（after step 2）
4. [[learn/ai-coding-crash-course/nodes/context-hygiene/explore-from-zero|從零探索全新 Session]] — 理解全新 session 實際知道什麼，並建立可靠的 repo exploration 方法。（after step 1）
5. [[learn/ai-coding-crash-course/nodes/context-hygiene/use-files-as-memory|以檔案作為跨 Session 記憶]] — 以檔案與探索紀錄跨 session 保存狀態，完成第一次有意識的 context 管理。（after step 4）

## Lesson

代理的能力不只取決於模型本身，也取決於每次請求帶進上下文的內容。上下文越大，成本越高，注意力越容易分散，長 session 越可能慢慢離開 smart zone。這個 node 先建立乾淨基線，再把測量、探索與檔案記憶串成一套可重複的工作習慣。

第一條主線是清理固定負載。先備份並暫時移開外殼設定，再逐項檢查 system prompt 裡的工具、技能與連接器。第二條主線是觀察與保存。用 token 計數器看見上下文如何增長，從全新 session 的實際視角重新探索 repo，最後把需要跨 session 保留的知識寫進檔案系統。這樣的管理方式讓你知道代理目前知道什麼、還缺什麼，以及什麼時候應該清理或重開。
