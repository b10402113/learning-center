# 代理如何思考與燒錢

## Learning goal

能解釋代理何時聰明何時笨、以及錢花在哪——attention 退化、smart/dumb zone、statelessness、token 計費與快取、幻覺類型、effort 旋鈕。

## Steps

1. [[learn/ai-coding-crash-course/nodes/agent-thinking-and-cost/attention-and-smart-zone|注意力退化與 Smart Zone]] — 從 token 關係數量理解 context 變長如何降低代理品質，並辨識 smart zone 與 dumb zone。
2. [[learn/ai-coding-crash-course/nodes/agent-thinking-and-cost/state-and-context-cost|Stateless 模型、Session 與 Token 成本]] — 追蹤 state 在 model、harness 與 environment 的位置，讀懂 session 累積與 token 成本。（after step 1）
3. [[learn/ai-coding-crash-course/nodes/agent-thinking-and-cost/hallucination-diagnosis|兩種幻覺與診斷決策樹]] — 分辨 factuality 與 faithfulness hallucination，並選擇載入資訊或重建 context。（after steps 1–2）
4. [[learn/ai-coding-crash-course/nodes/agent-thinking-and-cost/effort-and-model-tradeoffs|Effort 旋鈕、Reasoning Tokens 與模型選擇]] — 在品質、延遲、成本與 smart zone 壓力之間選擇 effort 和模型。（after steps 1–2）

## Lesson

代理的表現會同時受到兩種限制影響。第一種是它能否在越來越長的 context 中維持注意力，第二種是你是否理解 state、token billing 與 reasoning effort 的代價。context 太長，代理可能仍然能回答，卻已不適合做複雜工作；effort 太高，單次任務可能更可靠，卻也會更慢、更貴，並更快消耗 session 的工作空間。

這個 node 先用 Smart Zone 建立品質邊界，再拆解 state 如何累積與 token 如何計費，接著用 factuality 和 faithfulness 的決策樹診斷錯誤，最後把 effort 與模型選擇放回真實工作流。你最後要能根據任務風險和 session 狀態做取捨，而不是只追求最大 context、最高 effort 或排行榜上的最強模型。
