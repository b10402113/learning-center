# 跨階段引導：指標、文件與技能

## Learning goal

能在 session 之間引導代理，讓它持續照你的意圖做事——phase boundary 的五個選項、auto-compaction 的危險、push-vs-point 引導、agents.md、doc+pointer、skills 的放置與修剪。

## Steps

閱讀順序依賴 phase boundary 先建立轉場判斷，再處理跨 session 的引導與封裝。

1. [[learn/ai-coding-crash-course/nodes/steering-across-sessions/choose-phase-boundary|轉場時怎麼選：五種 phase boundary 策略]] — 看懂五種轉場選擇與決策樹，避免讓 auto-compaction 代替你做判斷。
2. [[learn/ai-coding-crash-course/nodes/steering-across-sessions/steer-with-pointers|別把整本手冊塞進上下文：Push、Point 與 doc + pointer]] — 學會用最小固定負載保存專案規則，並把條件式流程改成 doc + pointer。
3. [[learn/ai-coding-crash-course/nodes/steering-across-sessions/package-and-prune-skills|把流程做成 skill，並修掉沒用的 steering]] — 把可分享程序封裝成 skill，並用 pruning 測試維持 steering 的精簡與有效。
4. [[learn/ai-coding-crash-course/nodes/steering-across-sessions/navigate-and-handoff|找得到路，也交得好班：navigation pointer 與 handoff]] — 把穩定導航和一次性交接分開設計，讓工作能跨 session、跨代理延續。

## Lesson

這個 node 談的不是單一技巧，而是一整套讓代理跨 session 仍然沿著你的意圖前進的基礎設施。第一步是先把 phase boundary 看成一個需要人判斷的轉場點，而不是讓工具在上下文快滿時自動替你收尾。你要知道何時該繼續、何時該清空、何時該壓縮、何時該交接、何時該派子代理。這一步處理的是工作狀態怎麼過關。

第二步是把跨 session 的穩定知識從一次性的對話脈絡中抽出來。不是每一條規則都值得固定 push 進 `agents.md`。真正成熟的做法，是把最小但高價值的全域規則留在常駐引導裡，把只在特定任務才需要的詳細程序放進文件，然後用 pointer 在需要時把代理送到正確位置。再往前一步，當某套程序值得跨 repo、跨 harness、跨人分享時，就把它封裝成 skill。最後持續修剪 steering，清掉重複、沉積物和 no-op，避免路標比路本身還多。

第三步是把穩定導航和暫時交班分開。pointer 解決的是找路，handoff 解決的是接班。把這兩者混在一起，會讓 steering 檔案堆滿事故史，或讓交接文件承擔本來應該由專案文件長期保存的規則。分清楚這個界線後，代理即使換了 session、換了目錄、換了 harness，也能用很小的固定上下文成本，重新找到穩定知識，再從具體交接文件接手眼前的工作。
