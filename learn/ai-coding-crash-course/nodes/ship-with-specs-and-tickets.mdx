# 用 Specs 與 Tickets 交付大型工作

## Learning goal

能把大型功能拆成 agent 大小的區塊，並用五步流程交付——spec/tickets、implement 迴圈、code review 與 QA、存檔 spec、改道重談（re-grill）、coding-standards。

## Steps

1. [[learn/ai-coding-crash-course/nodes/ship-with-specs-and-tickets/when-specs-and-tickets|五步交付流程：Spec、Tickets 與 Context Window 的正確用法]] — 理解大型任務的五步流程與兩份核心文件的角色
2. [[learn/ai-coding-crash-course/nodes/ship-with-specs-and-tickets/write-spec-and-split-tickets|撰寫 Spec 與拆分 Tickets 實戰指南]] — 撰寫 spec 並拆分為垂直切片的 tickets（after step 1）
3. [[learn/ai-coding-crash-course/nodes/ship-with-specs-and-tickets/run-implement-loop|Implement 迴圈：五步完成 Ticket 實作]] — 逐張 ticket 實作、auto mode、驗證迴圈（after step 2）
4. [[learn/ai-coding-crash-course/nodes/ship-with-specs-and-tickets/code-review-and-qa|三層 Code Review 流程]] — 三層 review 機制與 coding-standards 維護（after step 3）
5. [[learn/ai-coding-crash-course/nodes/ship-with-specs-and-tickets/re-grill-and-archive|中途改道與存檔 Spec]] — re-grill 流程與 spec 存檔策略（after step 2）

## Lesson

當一個功能大到無法在單一 context window 內完成時，你需要的不是更聰明的模型，而是一套把大任務切成 agent 大小區塊的流程。這套流程的核心是兩份文件：spec（目的地）和 tickets（路線圖上的每一站）。Spec 定義你要去哪裡，ticket 定義每一次出發要完成什麼。

五步流程從 grilling（對齊需求）開始，產出 spec，再把 spec 拆成 tickets，逐張 implement，最後 code review 加 QA。每一步都在自己的 context window 內完成，確保代理始終待在 smart zone 裡工作。當中途發現方向不對，你可以 re-grill spec 並替換 tickets，而不必丟掉已完成的工作；完成後把 spec 存檔在 issue tracker 而非 repo 裡，避免 stale secondary source 誤導代理。
