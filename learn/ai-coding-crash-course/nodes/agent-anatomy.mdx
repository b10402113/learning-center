# 代理的構成：模型、外殼與環境

## Lesson

一個 AI coding agent 看起來像一個會讀程式、改檔案和跑測試的單一工具，實際上是幾個邊界不同的部件合作而成。模型負責根據文字上下文逐步產生下一個 token，外殼把模型接上工具和工作流程，環境提供檔案系統、命令、依賴與測試結果，代理則是模型與外殼在環境中的整體運作。只有把這些層次拆開，才能知道問題究竟出在推理能力、工具編排、權限設定，還是專案本身。

代理的輸出也不是一次想完整答案後直接交付。模型會在每個生成位置面對候選 token，依照機率分布取樣，逐步形成自然語言、工具呼叫與後續策略。這種非決定性讓相同任務可能走出不同路徑，也代表教學示範不應被視為唯一腳本。可靠性要靠測試、檢查、權限與清楚的環境邊界補足，而不是只追求每次都逐字重現。

當代理開始工作時，使用者看到的一次回合其實可能包含很多次模型供應商請求。模型先提出工具呼叫，外殼執行讀檔、搜尋、寫檔或命令，再把工具結果送回模型。模型根據新結果繼續工作，直到它判斷可以停止並回報。Context 包含系統提示、工具定義、目前訊息、歷史訊息與環境回饋；context window 是單次請求可容納的上限；session 則是跨多個 turn 累積起來的工作脈絡。脈絡越長，成本與注意力負擔越高，因此工程師需要知道什麼資訊值得保留、何時清空、何時壓縮，以及哪些狀態應該寫進檔案讓環境承擔。

四個步驟合在一起，提供一套實用的觀察方法。先拆部件，再理解模型如何生成，接著沿著工具迴圈查看代理真的做了什麼，最後檢查 context 與 session 是否已經累積過多。遇到代理行為異常時，沿著這條鏈逐層排查，比直接更換模型更容易找到可重現、可修正的原因。
