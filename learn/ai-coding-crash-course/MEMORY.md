# MEMORY — ai-coding-crash-course

## Goal

Ship a real, non-trivial feature on a real codebase end-to-end using an AI coding agent (Claude Code or similar), running the full grilling → spec → tickets → implement → review loop without babysitting it.

## Why

Already uses AI in day-to-day dev work and keeps hitting its limits — wants it to become a dependable teammate, not a smart autocomplete. The course gets hard (agents do something dumb, token bills climb, config fights back); the driver is "stop fighting it, make it dependable."

## Prior experience

- Working engineer, fully terminal-comfortable (cd, ls, git, bash, running dev servers).
- At home in at least one language/stack; treat TypeScript/Node-era conventions as native turf (the course's own stack).
- Already studying AI agents in a separate subject (geek-ai-agent, cognition/essence/value angle) — conceptual overlap to cross-link.
- Comfortable in VS Code with a built-in terminal; normal git/PR review habits.

## Anchors

- TypeScript/Node-era stack as home turf; the course's Cadence playground maps onto the learner's own codebase.
- The course's 5-step system (grilling → spec → tickets → implement → review) is itself the reusable mental model.
- Personal learning-notes repo + existing AI-agent learning subject (geek-ai-agent) for cross-linking concepts like context, agents, and cognition.
- Paid AI subscription assumed (~$100/mo) — free tiers don't survive agentic work.

## Habits & constraints

- ~3–6 hours per week, evening sessions on a laptop.
- Learn in the same environment they build in; needs a paid AI subscription budgeted if not already held.

## Knowledge type

Procedural-dominant, mixed — the goal is doing (run a grilling, ship a ticket, review a diff), but the concepts are needed to understand why the doing works (context window, token billing, smart/dumb zone, hallucinations).

## How to teach me

- Lessons the learner can act on, anchored to their own stack; elements short and pointed, like dictionary entries.
- Verified by probing and interrogation rather than lecturing — being quizzed is what sticks.
- Bored by theory with no payoff, vague "understand X" goals, and repetitive demos.
- Relating material back to the learner's own code is what makes it durable.
