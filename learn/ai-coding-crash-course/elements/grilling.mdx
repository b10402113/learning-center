# Grilling 對齊法 (Grilling)

## 問題陳述 (Problem Statement)

代理（agent）的預設行為是「你說什麼它做什麼」：你叫它蓋一個功能，它就探索程式碼庫、然後埋頭實作，中間沒有任何確認。結果常常是「蓋錯了東西」——它做出來的不是你想要的。就算你有計劃模式（plan mode），它也只是讓代理把「急著寫程式」換成「急著寫計劃」，計劃讀起來跟實作一模一樣，仍然沒有停下來問你「這真的是你要的嗎」。問題的根源是：實作前的對齊（alignment）——確認彼此對「要蓋什麼」有共同理解——這一段完全缺席。

Grilling 對齊法就是補上這一段的技術。它把「先對齊、後動工」變成一個明確的階段：在寫任何程式之前，先跟代理進行一整輪設計問答，把需求、取捨、甚至「為什麼要做」都逼出來。

## 為什麼重要 (Why it matters)

有三個理由讓 grilling 值得做。

第一，對齊發生在工作開始之前，而不是之後。一旦代理開始實作，方向就很難回頭；在動手前把分歧磨平，等於用對話的廉價代價，避開實作後重做的昂貴代價。功能越複雜，這個前置成本越划算。

第二，把控制權放回人（human）手上。市面上很多技術框架傾向「降低人的參與、把權力交給代理」，結果人變成旁觀者。Grilling 相反：它刻意要求你動腦回答、拍板決定、反駁建議——這不是偷懶的藉口，而是它的目的。最後你會覺得自己更像主導者，更理解整個進行的過程，而不是被代理牽著走。

第三，它對上下文（context）非常節省。整場問答只需要約 2 萬到 3.3 萬個 token，把數十萬 token 的「聰明區」（smart zone）空間留給後續實作。對齊花了很少的代價，卻讓真正的工程階段擁有充足的思考餘裕。

## 運作方式 (How it works)

Grilling 的核心機制是「探索與提問並行」：代理先啟動一個探索器（explorer）子代理，在背景（background）掃描整個程式碼庫——這一步是非阻塞（non-blocking）的，探索不會擋住提問。與此同時，代理一輪又一輪地把問題丟回來，前後總共約 40 題，涵蓋「做什麼（what）」也涵蓋「為什麼（why）」：這個功能到底是幹嘛的、為什麼要建它、誰會用它、資料該怎麼存。

人（human）的工作是「口述答案」：逐題把回答打進輸入框，多數時候同意代理的建議，但該推翻時就明確推翻。就這個課程留言功能的案例來說，代理每丟回一輪（round），人就逐題回答，幾輪下來累積成一份完整的 V1 設計。

過程中人的確推翻了好幾個代理的建議，也接受了幾個代理自己想的點子：

- 代理建議「每個課程先不開放留言，直到流量能支撐為止」——被否決，改成設計一個好看、鼓勵留言的空狀態（empty state），不要讓學生一進來就被澆冷水。
- 代理建議「未登入或未註冊的使用者也可以看到既有留言」——被強烈否決，留言只在課程內部保密，這是付費權益的一部分。
- 代理建議「學生的存取權到期後，留言與身份一併移除」——被否決，留言應保留並繼續標示原作者。
- 代理主動指出一個矛盾：人選了「扁平列表（flat list）＋不設明確已解決狀態」又要求「未回答問題佇列」——扁平列表裡沒有討論串概念，每則留言都是頂層、誰也不指向誰，根本湊不出「未回答的討論串」。於是接受代理建議，改成**一層回覆（one-level replies）**，也因此需要軟刪除（soft delete）。
- 講師與學生的留言共用一張表、同一個功能，講師掛一個徽章（badge）做視覺區分，不需要分成兩個功能。
- 存取以「已註冊（enrolment）」判定，而不是「已購買」；第二道閘門（PPP 地區定價）不存在，看不到課程就等同未註冊。
- 講師／管理員有一個獨立的佇列頁（queue page），列出所有未回答的討論串，最新在前（newest first）——這樣萬一誤標了不需要回答的回覆，它會自然沉下去。
- 軟刪除，且作者可以無限編輯自己的留言；擁有課程的講師和管理員可以刪除任何人的留言。
- 探索時還抓到一個既有程式的安全漏洞：原本的 Markdown 渲染器完全沒有消毒（sanitization），原始 HTML 直接穿透。於是採用代理的建議，用一個受限渲染器（restricted renderer）只對學生留言消毒。
- 其他拍板的細節：留言支援語法高亮；V1 設長度上限但不做濫用控管；管理員也掛徽章；管理員回覆算已回答；佇列頁可以內嵌回覆；學生的「收到回覆」通知先延後不做；程式碼裡到處複製的內聯權限檢查抽成共享 helper，但重構只限留言會碰到的路由。

等問答收尾，代理會吐出一小段摘要，但通常連讀都不用讀——因為透過剛才的對答，雙方已經建立了一個共享的設計概念（design concept），那段摘要只是把你已經做過的決定重述一遍。

接著進入實作階段。最漂亮的是：整場 grilling 只用掉約 2 萬到 3.3 萬個 token，上下文視窗（context window）還剩約 12 萬個 token 的聰明區給實作。實作跑了 14 分 28 秒，衝到約 15.5 萬個 token，剛好壓在聰明區邊緣。之後對結果做 QA：貼文、回覆、編輯、刪除都正常，軟刪除掉的父留言其回覆仍然顯示，講師的「未回答問題佇列」能列出問題並內嵌回覆——只有幾個小視覺瑕疵（兩個導覽連結同時亮著、空狀態不夠漂亮）。最後，作者覺得自己是「對齊了，而不是被坑了」（aligned, not cheated）——成品和他腦中的想法一致，不是代理擅自造出來的東西。

一個很值得記住的觀察：每個人的 grilling 結果會不同。因為代理的行為是非確定性（non-deterministic）的，它問你的問題可能完全不一樣，你做出的決定自然也不一樣。這不是缺點，正是這技術「把主導權還給人」的證明。

## 白話解釋 (In plain terms)

Grilling 就是「動手之前，先讓代理狠狠盤問你一輪」。代理在背景把程式碼庫翻過一遍，然後像面試官一樣一題一題問你：這個功能到底是做什麼的、為什麼要做、誰用得到、資料要怎麼存。你逐題口述答案，多數同意它、該駁回就駁回。幾輪下來，你發現自己腦中的畫面越來越清楚，代理也一樣，雙方就「要蓋什麼」達成共識——之後的實作只是照著這份共識走，順得像在抄答案。

## 類比 (Analogy)

想像你要蓋一棟房子。做法 A：你對包商說「我要一棟房子」，他二話不說直接開工，三個月後你看到一棟醜得離譜、格局全錯的房子——這就是沒有對齊的代理。做法 B（grilling）：包商先派測量員把地看完，然後坐下來一題一題問你——這房子給誰住、為什麼要搬、預算多少、玄關要不要、樓梯朝哪邊——你逐題回答、推翻他幾個建議（「不要車庫，改成書房」）。聊到一半你發現，他描述的房子正是你腦中想的那一棟，你們的畫面合而為一了。這時候才開工。後面的施工快而且順，因為最難的決定——「到底要蓋什麼」——已經在對話桌上解決了。

## 實際應用 (Practical use)

想在自己真實的代理工作裡跑一次 grilling，記住以下幾件事。

第一，主動把「對齊」變成實作前的一個階段。不要一開口就說「幫我建 X」，而是先要求代理探索、然後逐題問你。市面上有現成的 skill（例如 grill me）可以做這件事，你也可以自己來：讓代理讀完程式碼庫，然後向你提問。

第二，對每一題，明確說出「是什麼」和「為什麼」。代理問的不只是功能規格，還包括動機、對象、取捨。你回答得越具體，後面實作越不會走偏。看到代理附帶的建議，別照單全收——同意是合法的選擇，「我不同意，改成這樣」更常見，偶爾「我不在乎，你決定」也是合法的答案。

第三，該推翻就推翻，這正是 grilling 的價值所在。案例裡幾個最重要的決定——留言只限課程內部、門控（gate）在已註冊學生、一張表加講師徽章——都是人推翻代理建議換來的。如果全程只會說「同意」，等於把主導權又還給了代理。

第四，用「實作前我是不是覺得很順」來驗收 grilling。對齊成功的徵兆是：你覺得「接下來蓋起來很簡單」，因為難的決定都做完了。如果進入實作前你還有模糊感、還在想「它大概會幫我決定吧」，那代表還沒對齊夠。

## 前置知識 (Prerequisites)

- 了解代理的預設行為是「急著生產資產」的過早完成（premature completion），以及計劃模式（plan mode）只是一道「生產資產的緩衝」、不是真正的對齊。
- 知道什麼是設計概念（design concept）——不是文件或資產，而是靠對話逐步磨清楚、雙方共享的那份理解。
- 大致了解上下文視窗（context window）與聰明區（smart zone）的概念，才能體會 grilling 為什麼如此節省上下文。

## 自檢問題 (Questions)

### Q1. 代理探索程式碼庫的同時在做什麼？為什麼這樣設計？

A1. 探索與提問並行：代理啟動探索器子代理在背景掃描程式碼庫，是非阻塞的，不會擋住它向你丟問題。這樣人回答問題的同時，探索持續進行，等探索完成後代理又能帶回新一輪問題，讓整個對齊過程又快又不浪費等待時間。

### Q2. 為什麼「扁平列表」和「未回答問題佇列」這兩個決定互相矛盾？最後怎麼解？

A2. 扁平列表裡沒有討論串的概念，每則留言都是頂層、誰也不指向誰，根本湊不出「某個討論串還沒被回答」。代理主動指出這個矛盾後，人接受了建議，改成「一層回覆」——也因此需要軟刪除（因為要能在保留回覆的情況下移除父留言）。

### Q3. Grilling 和設計概念有什麼關係？（關係題）

A3. 設計概念不是文件或資產，而是靠對話磨出來的共享理解。Grilling 正是那場對話：一整輪「做什麼＋為什麼」的問答，讓人和代理對「要蓋什麼」的理解逐步收斂一致。案例裡最明顯的證據是，問答結束後代理產出的摘要「連讀都不用讀」——因為雙方腦中已經有同一個畫面，摘要只是把既定的決定重述一遍。

### Q4. 案例裡最重要的幾個決定都是推翻代理建議得來的。為什麼「該推翻就推翻」如此關鍵？（價值判斷題）

A4. 因為 grilling 的意義就在於把主導權放回人手上。留言只限課程內部、門控在已註冊學生、一張表加講師徽章，這些決定全是人否決代理建議的結果；如果全程只會說「同意」，就等於又把控制權還給代理。Grilling 刻意要求你動腦、拍板、反駁——這正是它和「讓代理替你決定」的技術最根本的區別。
