# 進階提示技巧 (Advanced Prompting)

## Problem Statement

在使用 AI 編碼助手（AI Coding Assistant）時，隨著任務複雜度提升，單純在輸入框打字已經不夠——你需要在提示中引用特定檔案、在送出前反覆修改草稿、甚至貼入圖片讓模型理解視覺資訊。如果不懂得這些內建的進階提示技巧，每次都要手動複製貼上路徑、重新撰寫相同指令，效率會大幅下降。

## Why it matters

進階提示技巧直接決定你能多快把正確的上下文交到模型手上。掌握這些功能後，你可以在一次對話中精準引用多個檔案、在送出前隨時修改草稿不浪費 token、甚至用圖片描述需求。這些能力讓你在處理大型專案、設計稿審查或跨模態任務時，不再被提示的輸入方式卡住。

## How it works

### 檔案引用：@ 語法（File Referencing with @）

Claude Code 允許你在提示中使用 `@` 符號來引用專案中的檔案。輸入 `@` 後，系統會啟動模糊搜尋（Fuzzy Search），根據你輸入的關鍵字自動過濾專案中的檔案。你可以用 Tab 鍵或 Enter 鍵將搜尋結果中的檔案直接拉入提示文字。

被引用的檔案內容會被**直接讀入模型的上下文窗口（Context Window）**，不需要額外的工具呼叫（Tool Call）。這代表什麼？當你在提示中寫 `@README.md`，該檔案的完整內容會在第一個模型提供者請求（Model Provider Request）中一併送出，模型立刻就能看到全部內容。這對於需要將規格書（Spec）、設計文件或範例檔案作為參考輸入的場景特別有用——你不需要讓模型花一次來回才去讀取檔案，而是從一開始就把所有必要資訊打包進去。

模糊搜尋的機制讓你不需要記住精確的檔案路徑。例如你只記得某個檔案叫 `config` 開頭，輸入 `@config` 就會列出所有匹配的檔案，從中挑選即可。這種方式大幅降低了檔案引用的認知負擔。

### 草稿暫存：Ctrl+S 暫存與回復（Prompt Stashing）

當你在撰寫一段複雜的提示時，可能寫到一半發現需要先做其他事情，或者想先貼入一些內容再回來修改。Claude Code 提供了暫存草稿（Stashing）功能：按下 Ctrl+S，當前正在輸入的提示文字會被暫存起來，輸入框清空，你可以繼續做其他事。

當你準備好繼續時，按下對應的回復快捷鍵，先前暫存的草稿會重新出現，你可以繼續編輯。這個機制的核心價值在於：**你不需要在還沒準備好的情況下強行送出提示**。當你在給予代理（Agent）回饋時，可能需要先加入一段程式碼範例、修正一個路徑、或補充一個要求——暫存功能讓你可以隨時抽離、插入新內容、再回來精煉，最後才正式送出。

這種「延遲送出」的工作模式避免了來回修改的低效循環。你不再需要把不完整的提示先送出去、等模型回應、再補充說明，而是在送出前就把提示打磨完整。

### 圖片貼入：剪貼簿圖片輸入（Image Pasting）

Claude Code 支援從剪貼簿（Clipboard）直接貼入圖片到提示中，即使你在終端機（Terminal）環境中也是如此。你可以在任何圖片查看器中複製一張圖片，然後在 Claude Code 的輸入框中貼上，圖片就會被納入當次提示的多模態輸入（Multodal Input）中。

例如，你截取了一段錯誤訊息的截圖、拍了一張介面設計的照片、或複製了一張風景圖片——貼入後，模型會同時處理文字和圖片的資訊，並根據兩者給出回應。在實際演示中，有人貼入了一張斯洛維尼亞布萊德湖（Lake Bled）的照片，模型正確辨識並描述了照片中的景點，證明了即使在終端機環境中，視覺資訊的傳遞也是完整且可靠的。

## In plain terms

簡單來說，進階提示技巧就是三個讓你更有效率地跟 AI 溝通的功能：用 `@` 引用檔案讓模型一次看到所有內容、用 Ctrl+S 暫存草稿讓你在送出前反覆修改、用剪貼簿貼入圖片讓模型理解視覺資訊。掌握這三招，你跟 AI 的互動品質會明顯提升。

## Analogy

想像你在跟一位顧問開會。如果每次你都要把一疊文件影印後親手遞給他，他才開始看——這就是沒有用 `@` 的情況。用了 `@`，等於你在會議開始前就把所有相關文件直接放在他桌上，他一坐下來就能開始分析。

暫存功能就像你在白板上寫到一半的想法，你不需要把它擦掉或急著講完，可以先放下來，去做別的事，回來再繼續補充。

圖片貼入則像是你帶了一張實體照片或設計草圖去會議室，直接攤在桌上說「就是這種感覺」——有些東西用文字描述半天都說不清，一張圖就解決了。

## Practical use

- **規格驅動開發（Spec-Driven Development）**：在開始實作前，用 `@spec.md` 把需求規格書完整送入上下文，讓模型從一開始就理解所有需求，而不是分段描述導致遺漏。
- **Code Review 輔助**：在給予模型回饋時，先暫存草稿，貼入需要檢視的程式碼片段後再送出，確保模型拿到的是完整且正確的上下文。
- **設計稿比對**：將 UI 設計稿截圖貼入提示，請模型比較目前實作與設計稿的差異，快速找出視覺偏差。
- **多檔案重構**：連續使用 `@` 引用多個需要重構的檔案，讓模型在一次回應中同時處理所有相關檔案，避免逐個檔案處理導致的上下文遺失。
- **錯誤排查**：貼入錯誤訊息截圖，讓模型同時看到錯誤畫面和相關程式碼，提供更精準的診斷建議。

## Questions

1. **@ 引用的檔案是以什麼方式送入模型？**
   答：檔案內容會被直接讀入上下文窗口（Context Window），在第一個模型提供者請求（Model Provider Request）中一併送出，不需要額外的工具呼叫（Tool Call）。

2. **Ctrl+S 暫存草稿的功能解決了什麼問題？**
   答：它解決了「提示還沒準備好就必須送出」的問題，讓使用者可以在送出前隨時暫存、修改、補充提示內容，避免不完整的提示導致低效的來回對話。

3. **在終端機環境中貼入圖片，模型能看到什麼？**
   答：模型會同時處理文字和圖片的多模態輸入（Multodal Input），完整理解圖片中的視覺資訊並據此回應。

4. **使用 @ 語法時，你需要輸入精確的檔案路徑嗎？**
   答：不需要，@ 觸發模糊搜尋（Fuzzy Search），你只需輸入關鍵字，系統會自動過濾匹配的檔案供你選擇。

5. **暫存草稿後，如何重新取回之前輸入的內容？**
   答：按下對應的回復快捷鍵，先前暫存的草稿會重新出現在輸入框中，你可以繼續編輯。
