# 全新 Session 探索 (Fresh Session Exploration)

## Problem Statement

代理在全新 session 開始時，看起來像是已經「進到專案裡」，但它其實幾乎不知道這個專案是什麼。根據課程示範，代理一開始只會拿到平台資訊、主要工作目錄、是否為 git repo、shell、知識截止時間、目前與主要 branch、git 使用者，以及最近的 commit 名稱。最重要的是，它不會自動拿到檔案系統清單，也不知道專案裡有哪些檔案、哪些目錄、哪些框架或功能。

這代表每一個 fresh session 都必須重新探索。若沒有先探索就直接要求代理規劃、實作或評論，它就只能根據目錄名稱、commit 訊息和零碎環境資訊猜測專案性質。這種猜測很容易讓後續工作建立在錯誤前提上。

## Why it matters

探索品質會定義後面所有工作的上限。因為模型本身是無狀態的，上一個 session 的理解不會自動延續到下一個 session；即使你覺得「這個 repo 我們昨天才聊過」，對代理來說仍然是第一次見面。若不把這件事當作工作流程的基本前提，使用者就會誤把代理的自信當成理解。

把 fresh session 視為必須探索的起點，也能改變你對上下文管理的看法。清空上下文、開新 session，並不只是「把雜訊拿掉」，也等於放棄了先前 session 中對專案形成的暫時理解。因此重新開始後，第一步不應該是催代理輸出成果，而是讓它重新建立地圖。這點和 [[learn/ai-coding-crash-course/elements/harness-reset|代理外殼重置 (Harness Reset)]] 與 [[learn/ai-coding-crash-course/elements/context-counter|上下文計數器 (Context Counter)]] 一起構成上下文衛生的實作面：先減少無關負載，再看見成本，最後承認理解必須靠探索重新建起來。

## How it works

在課程示範中，Matt 用 request logger 檢查 fresh session 的起始內容，發現代理拿到的是環境與 git 中繼資料，而不是專案內容本身。這些資訊足以讓代理知道自己位於哪裡、是否在 repo 中、最近做過哪些提交，但不足以回答「技術棧是什麼」或「這個產品打算做什麼」。因此合理的第一個問題，不是直接叫它修改功能，而是先問它：這個專案的技術棧和預期用途是什麼。

這種問題的價值不只在答案本身，也在觀察探索路徑。代理可能自己讀 `README`、`package.json` 和其他關鍵檔案，也可能呼叫 sub-agent 去做初步探勘。課程示範中的那次沒有生成 sub-agent，而是直接讀取 `README` 和 `package.json`。接著代理啟動 teach skill，建立一組持久化的學習檔案，例如 `mission.md`、學習筆記、主要資源、共用樣式資產、詞彙表，以及第一篇教學文章，開始把陌生 repo 轉成可學習的材料。

teach skill 的關鍵不只是「說明專案」，而是把探索結果寫進環境。這使它成為一種有狀態的學習工作區：即使你之後清空上下文，skill 仍可以從已寫下的檔案繼續，而不是每次都從零開始口頭重建。這也說明探索不一定只是一輪讀檔；更好的做法是把探索沉澱成可重用的外部記錄，讓環境而非模型承擔持久記憶。這一點與 [[learn/ai-coding-crash-course/elements/compaction|Compaction 壓縮機制 (Compaction)]] 和 [[learn/ai-coding-crash-course/elements/handoff|Handoff 跨代理交接 (Handoff)]] 形成對照：探索是 fresh session 的起手式，compaction 與 handoff 則是在 session 結束或跨越邊界時搬運理解。

## In plain terms

開一個全新 session，就像把一位很能幹的新同事帶進辦公室。你知道桌上有很多文件，也知道昨天團隊已經討論過很多事，但新同事眼前只看到房間名字、門牌和最近的會議標題，卻還沒打開任何抽屜。這時若直接要他做決策，他只能猜。探索就是先讓他把抽屜打開、把地圖看懂，再開始工作。

## Analogy

fresh session exploration 很像初到一座城市的偵察。你一下車時只知道城市名稱、所在國家和最近新聞標題，卻不知道街道怎麼分布、哪裡是市場、哪裡是港口。真正有用的認識不是來自站牌，而是來自走訪街區、閱讀地圖、詢問在地資料。代理一開始拿到的是站牌資訊；探索才是走進城市本身。

## Practical use

- **把探索當成新 session 的預設第一步**：一開場先要求代理判斷技術棧、產品目的與主要結構，而不是直接進入實作。
- **用問題測試理解深度**：像「這個專案的 tech stack 與 intended purpose 是什麼」這類問題，能迫使代理先找證據再回答。
- **觀察探索策略**：留意代理是自己讀關鍵檔案，還是委派 sub-agent；這能幫你理解該 harness 的預設工作方式。
- **把探索結果寫成外部記錄**：若有 teach 這類技能，就讓它把 mission、資源、術語與教學文章落盤，減少下次重新摸索的成本。
- **清空後不要假設代理還記得**：只要換了 fresh session，就把先前理解視為消失，必要時重新探索或用可攜摘要重新載入。
- **先成為讀者，再成為實作者**：對陌生 repo 先建立結構理解，再要求變更功能，通常比直接開工更穩。

## Questions

### Q1. 為什麼每個 fresh session 都必須重新探索 repo？

A1. 因為模型本身是無狀態的。fresh session 起始時，代理只拿到環境與 git 中繼資料，並不知道檔案系統中有哪些內容，所以若不重新探索，就只能靠猜測理解專案。

### Q2. fresh session 一開始通常知道哪些事，又不知道哪些事？

A2. 它通常知道平台、工作目錄、shell、是否為 git repo、目前 branch、最近 commit 等中繼資料；但它不知道檔案列表、實際技術棧、產品目標與程式碼結構，因為這些都還沒有被讀進來。

### Q3. 問代理「這個專案的 tech stack 和 intended purpose 是什麼」有什麼用？

A3. 這個問題會逼代理先蒐集證據，再形成高層判斷，同時也讓你觀察它如何探索：是自己讀關鍵檔案，還是委派 sub-agent。答案與探索過程同樣重要。

### Q4. teach skill 在探索陌生 repo 時提供了什麼額外價值？

A4. 它不只是即時解說，而是把 mission、筆記、資源、詞彙表與教學文章寫進檔案系統，形成可延續的學習工作區。這樣即使清空上下文，也能從已落盤的材料繼續，而不必每次從零重新講解。

### Q5. fresh session exploration 和 compaction、handoff 之間的差別是什麼？

A5. fresh session exploration 是在沒有既有脈絡時重新理解 repo；compaction 是把同一代理、同一目錄中的舊 session 濃縮後帶進新 session；handoff 則把理解包成可攜文件，交給其他代理、其他目錄或其他人。三者都處理理解的延續，但發生在不同邊界。
