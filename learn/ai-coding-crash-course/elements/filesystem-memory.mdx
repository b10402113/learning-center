# 檔案系統作為記憶 (Filesystem as Memory)

## Problem Statement

模型本身沒有持久記憶。每個全新 session 開始時，模型不會保留上一段對話、上一次探索結果，甚至連目前專案裡有哪些檔案都不知道。session 內看起來像「記得」的東西，其實只是 harness 把先前訊息重新整包送回去而已；一旦清空 session，這份暫時狀態就消失。

這帶來一個實際問題：如果你想讓代理跨 session 保留知識，記憶到底該放在哪裡？課程給出的答案不是替代理外掛一套神祕記憶體，而是回到最穩定的地方：環境本身，尤其是檔案系統。只要資訊被寫進 repo、文件或其他可重讀的檔案，它就能在未來的 fresh session 中再次被探索、讀取與使用。

## Why it matters

把檔案系統當成記憶，會直接改變你和代理協作的方式。你不再期待代理「自己記住」，而是期待重要脈絡被落成檔案，讓任何新 session 都能重新取得。這比依賴 session 內的暫時上下文更穩，因為清空 context 並不會刪掉已經寫到磁碟上的東西。

這也解釋了為什麼 fresh session 一定要探索。課程用 request logger 展示：session 起點只會拿到平台、工作目錄、git 狀態、branch、git user、最近 commits 等環境與版本控制資訊，但不會拿到檔案系統清單。代理知道自己站在哪個資料夾，卻不知道資料夾裡有什麼。因此，真正可持久保留的知識不是「代理腦中的記憶」，而是之後能被重新探索到的檔案與結構。

## How it works

這個模型可以分成三層狀態。

- **模型（model）**：完全無狀態。它不會把任何知識從這次呼叫帶到下一次呼叫。
- **harness**：有狀態，但只在當前 session 內有效。它靠重送整段對話來製造「記得」的效果。
- **環境（environment）**：真正持久，尤其是檔案系統。你存下來的檔案，在清空 session 之後仍然存在。

因此，跨 session 記憶的核心策略不是要求模型記住，而是把未來還需要的知識寫進環境。像是教學記錄、任務說明、專案規則、探索結果與共享資產，只要保存成檔案，就能在下一個 session 重新成為可讀取的事實來源。

課程中的 `teach` skill 就示範了這個思路。它不是只在對話裡解釋專案，而是把理解工作區寫成一組實體檔案：`mission.md`、`notes.md`、`resources.md`、glossary，以及第一課的 HTML lesson。因為這些學習紀錄留在檔案系統中，所以你隨時可以 clear context，再回來接著學；skill 不是憑空記得你學到哪，而是重新讀取它先前寫下的檔案。

## In plain terms

不要把代理想成會自己長期記住事情的同事，比較接近每次上班都失憶、但很會讀文件的同事。你如果把重要事情只講在嘴上，它下次就忘了；你如果把事情寫進 repo，它下次雖然還是失憶，卻能把文件再讀一遍，很快恢復狀態。

## Analogy

這像是一間公司裡的新同事每天早上都會被洗掉短期記憶。主管不能期待他憑腦袋記住流程，只能把流程寫進 wiki、手冊與專案資料夾。隔天他雖然不記得昨天聊過什麼，但只要文件還在，就能靠重新查閱恢復工作能力。檔案系統就是那座公司文件庫。

## Practical use

- **把重要脈絡落檔**：需求、設計決策、探索筆記、教學紀錄與共用資產，能寫成檔案就不要只留在對話裡。
- **預期 fresh session 需要探索**：新 session 只知道環境與 git metadata，不知道 repo 內容；讓代理重新讀取關鍵檔案是正常流程，不是失誤。
- **把 repo 視為主要記憶庫**：跨 session 要延續工作時，優先依賴程式碼、文件與保存下來的工作產物，而不是外掛式記憶幻想。
- **為未來重讀而寫**：既然知識要靠之後的代理再讀回來，檔案應有清楚命名、穩定位置與足夠可理解性。
- **用 stateful skill 寫持久痕跡**：像 `teach` 這種能力之所以能在清空 context 後接續，是因為它把狀態寫到檔案系統，而不是因為模型保留了內在記憶。

## Questions

### Q1. 為什麼說模型本身沒有記憶？

A1. 因為每次呼叫模型時，它都不會保留前一次呼叫的內容；session 內看似記得，只是 harness 把先前上下文重新送進去。

### Q2. 清空 session 後，什麼會留下來？

A2. 留在檔案系統裡的東西會留下來，例如程式碼、文件、筆記與 skill 產生的工作檔案；session 對話本身帶來的暫時狀態則不會。

### Q3. fresh session 一開始知道哪些資訊，不知道哪些資訊？

A3. 它知道平台、工作目錄、git 狀態、branch、git user 與最近 commits 等環境資訊，但不知道 repo 裡有哪些檔案，因此必須探索。

### Q4. 為什麼 `teach` skill 能在 clear context 後接著教？

A4. 因為它把 mission、筆記、資源、glossary 與 lesson 寫成檔案，之後可以重新讀回；不是因為模型保留了內在記憶。

### Q5. 「my code base is my memory system」在實作上代表什麼？

A5. 代表跨 session 要保留的重要知識，應優先寫進程式碼庫與相關文件，讓任何新 session 都能透過探索與讀檔重新取得，而不是依賴外掛記憶或期待模型自己記住。
