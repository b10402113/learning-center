# 可攜式技能 (Portable Skills)

## Problem Statement

代理（agent）需要遵守的流程與專案慣例，不能只靠當下 session 的對話記憶。把完整規則放進 repo 的 `agents.md`，雖然每次都能看見，卻會在每個 model provider request 中持續消耗 token 與注意力；只放一份 repo-local 文件加 pointer，又會遇到可發現性與可攜性的問題。當這套程序需要分享給同事、帶到另一個 repo，或在不同 harness 中重用時，單純的文件與指標不夠方便。

## Why it matters

技能（skill）把可重用的工作程序包裝成標準化、可分享的文件結構。它保留 doc + pointer 的低固定負載優點，又能把整個資料夾帶到另一個 harness 或工作環境。這讓引導不必在每個專案重寫，也讓團隊可以共享一套逐步成長的工作方式。

但技能並非免費。若技能可由模型自動呼叫，名稱與 description 會出現在 parent context，增加固定的 context load；若技能只允許使用者呼叫，則幾乎不增加上下文負載，卻把「何時呼叫」的記憶責任交給人。設計技能時，必須在代理的自動發現能力與上下文成本之間取捨。

## How it works

技能是封裝在 self-contained folder 裡的 doc + pointer 模式。核心是 `skill.md`，其中的名稱與 description 就是 context pointer；預設先放進 parent context 的是名稱與 description，完整程序則在技能被呼叫時才載入。技能也可以附帶多個檔案，讓 `skill.md` 再指向更詳細的參考資料，例如 `writing-for-agents` skill 內的 mechanics reference。

技能可透過兩種方式呼叫：

- **Model-invoked（模型呼叫）**：技能的名稱與 description 可被模型看到，模型依任務判斷是否載入。這降低使用者記憶負擔，但每個可自動呼叫的技能都會增加 context load。
- **User-invoked（使用者呼叫）**：技能不讓模型自動載入，由使用者明確指定，例如設定 `disable model invocation: true` 的 `handoff`。這幾乎不增加固定上下文成本，但使用者必須記得技能名稱與適用時機。

技能遵循 agentskills.io 所描述的開放標準，因此不只綁定單一 harness。技能可以在個人層級或專案層級放置：user-level skill 位於 `.claude` 或 `.agents` 的 skills 資料夾，跟著同一台機器上的使用者跨專案；project-level skill 則提交在 repo 中，限定於該專案，並自動分享給 clone repo 的每位協作者。

## In plain terms

技能像一個附有索引卡的工具箱。索引卡只說明工具箱叫什麼、什麼時候該拿出來；真正的工具與使用說明留在箱子裡，需要時才打開。整個工具箱可以搬給另一個人或另一個工作環境，不必把工具內容永久攤在每次會議的桌面上。

## Analogy

`agents.md` 的 push 像每天把整本操作手冊背在身上；doc + pointer 像帶著寫有書架位置的紙條；portable skill 則像把那本手冊連同目錄、附件與索引裝進一個可攜式工具箱。工具箱不必每天打開，但需要執行該程序時，代理或使用者可以依索引把它取出來。

## Practical use

- **把可重用程序封裝起來**：將原本由 pointer 指向的文件轉成一個 self-contained skill folder，讓程序可被分享給同事或帶到其他 harness。
- **用名稱與 description 設計發現入口**：description 應清楚說明技能處理的任務，因為它是模型判斷是否載入完整文件的主要 pointer。
- **先做基準，再驗證呼叫時機**：加入技能前先送出 dummy request 建立基準，加入後再執行會觸發該流程的變更，確認技能是在正確時機被載入，而不是無關任務也增加負載。
- **個人規則放 user-level**：個人便利工具與生活品質規則適合放在 `.claude` 或 `.agents` 的 user-level skills 資料夾，讓它跟著使用者跨專案。
- **團隊規則放 project-level**：團隊依賴的流程，以及表達專案工作方式的規則，適合提交在 repo 中；專案層級通常是團隊協作時較強的預設，因為每個人都能使用並一起維護。
- **控制自動呼叫數量**：不需要模型每輪考慮的技能可以改成 user-invoked，避免大量 model-invoked skills 把 context load 推高。

## Questions

### Q1. 什麼是 portable skill？

A1. Portable skill 是把 doc + pointer 模式封裝成 self-contained folder 的可重用技能。`skill.md` 的名稱與 description 提供 pointer，完整程序與相關檔案在呼叫時才載入，整個資料夾也能分享給其他 harness 或工作環境。

### Q2. Model-invoked 與 user-invoked skill 的差別是什麼？

A2. Model-invoked skill 讓模型依名稱與 description 自動判斷是否載入，降低使用者記憶負擔但增加 context load；user-invoked skill 只在使用者明確呼叫時載入，幾乎不增加固定 context load，但使用者必須記得何時使用。

### Q3. 為什麼不把完整 skill 內容直接放進 `agents.md`？

A3. 因為 `agents.md` 會在每次 session 或請求中固定 push 完整內容，即使當前任務不需要，也會消耗 token 與注意力。Skill 只把名稱與 description 作為 pointer，完整內容等需要時才載入，並且更容易跨環境分享。

### Q4. 什麼時候應該使用 user-level skill，什麼時候使用 project-level skill？

A4. 個人便利規則與只服務自己的 shortcut 適合放 user-level；團隊依賴的流程或代表專案工作方式的規則適合放 project-level，因為它會隨 repo 分享給所有協作者並能共同成長。

### Q5. portable skill 和 handoff 的核心差異是什麼？

A5. Portable skill 保存可重複執行的工作程序，供未來不同任務與環境重用；handoff 保存一次 session 的工作脈絡，目的是把目前進度交給另一個代理、目錄或人。前者是程序的可攜性，後者是狀態的可攜性。
