# Effort、Reasoning Tokens 與成本品質取捨

## Problem Statement

AI coding agent 不只是產生最後的文字或程式碼。它還會花 token 探索檔案、呼叫工具、比較方案，以及產生中間的 reasoning tokens。當你把 effort 調高，模型通常會投入更多推理，可能更深入地找出文件漂移或實作中的問題，但也會讓請求變慢、成本上升，並更快消耗上下文的聰明區。

問題在於，低 effort 可能省下時間與費用，卻不足以支撐複雜任務；高 effort 可能提高成功率，卻把資源用在一個簡單任務上。使用者需要的是一個依任務風險調整的判斷方法，而不是把 effort 永遠固定在最高或最低。

## Why it matters

Effort 是品質、成本與延遲三者之間的控制桿。課程示範中，同一個 prompt 使用 max effort 約消耗 41k token、花 2 分 15 秒；low effort 約消耗 11k token、花 1 分 11 秒。max effort 進行更深的探索，也抓到文件漂移，但差異同時反映在 token 數與等待時間上。

Reasoning tokens 會以輸出 token 的方式計費，因此「模型想得更多」並不是免費的內部活動。更高 effort 在 DeepSWE 的示範基準中能提高部分任務的成功率，例如 Fable 約從 low 的 60% 提升到 max 的 70%，但每項任務的平均成本也隨之增加。基準測試不能直接代替你的實際工作，因為真實任務、程式碼庫與 harness 都不同。

## How it works

模型在一次工作中可能產生三類可觀察的活動：一般輸出文字、工具呼叫，以及 reasoning tokens。Reasoning tokens 是模型用來拆解問題、檢查假設與規劃下一步的中間推理；有些介面會隱藏它們，有些工具則會顯示它們。Claude Code 的 effort 旋鈕，主要就是控制模型願意投入多少這類推理。

這個設計建立在 chain-of-thought prompting 的想法上。與其直接回答蘋果數學題，模型先寫出中間步驟，通常更能處理複雜推理。對 coding agent 而言，中間步驟可能表現為更完整的程式碼探索、更多次驗證，或對方案取捨的檢查。

Effort 越高，通常意味著更多輸出 token。更多 token 會增加費用與延遲，也會讓上下文更快變長，因而更早接近 dumb zone。Effort 並非單純的「能力開關」：它是用額外資源換取較高成功機率的選擇，而且回報不一定與成本成正比。

## In plain terms

把 effort 想成請一位工程師處理任務時，允許他花多少時間調查與複查。改成 low，適合先快速完成簡單工作；改成 high，適合需要深入探索、詳細規劃或嚴格 code review 的工作。工作越複雜、失敗代價越高，額外推理越可能值得；工作越簡單，額外推理越可能只是浪費。

## Analogy

Effort 像汽車的油門與檢查時間。你可以用低速直接把短途工作做完，也可以放慢速度，多繞幾個路口確認地圖、檢查車況。後者較不容易迷路，但會消耗更多油、花更多時間；如果只是去街角買東西，這種保守駕駛就不划算。

## Practical use

- **簡單任務用低 effort**：格式調整、短摘要、已知範圍內的小修改，先選 cheap、fast 的設定。
- **探索與規劃分開判斷**：研究或摘要可能只需要 low；詳細規劃、複雜實作與 code review，才考慮 medium 或 high。
- **不要把 max 當預設**：extra-high 或 max 主要是為了基準測試中最後幾個百分點，日常任務很少值得支付完整代價。
- **用同一份真實工作做 A/B 測試**：讓兩種模型或 effort 處理相同任務，記錄成功率、修改量、耗時與 token 成本，再重複幾次比較。
- **優先看每 token 的產出**：便宜的 token 不一定代表便宜的任務；真正要比較的是完成工作所付出的總成本，以及得到的品質。
- **先維持一致，再微調**：與其每個任務都反覆 min-max effort，不如先選一個穩定的模型與 effort，將精力投入 harness、環境和上下文管理。
- **留意上下文代價**：高 effort 產生更多 token，可能令 session 更快膨脹；若品質開始下降，應先處理上下文，而不是只繼續提高 effort。

## Questions

### Q1. Effort 旋鈕主要改變了什麼？

A1. 它主要改變模型投入的 reasoning tokens 數量與推理深度。較高 effort 可能進行更多探索和檢查，但也通常產生更多輸出 token，增加成本與延遲。

### Q2. 為什麼 reasoning tokens 會影響費用？

A2. Reasoning tokens 屬於模型輸出的 token，會按照輸出 token 的方式計費。模型即使沒有把完整思路顯示在介面上，這些推理活動仍可能消耗請求資源。

### Q3. 什麼任務適合提高 effort？

A3. 複雜探索、詳細規劃、深度實作與 code review 通常比較值得提高 effort，尤其是錯誤代價高、需要多次驗證的任務。簡單修改、摘要或已知範圍內的工作則可先用 low。

### Q4. 為什麼不直接永遠使用 max effort？

A4. 因為 max 會增加 token 成本與等待時間，還可能令上下文更快進入 dumb zone；基準測試裡多出的品質百分點，也不一定會在你的真實任務中出現。應以實際工作測試額外 effort 帶來的收益。

### Q5. 如何判斷某個 effort 設定是否划算？

A5. 用相同的真實任務比較不同設定，記錄是否完成、結果品質、返工量、耗時與總 token 成本，並重複幾次。最後比較的是每單位成本帶來多少可用成果，不是單看 token 價格或基準分數。
