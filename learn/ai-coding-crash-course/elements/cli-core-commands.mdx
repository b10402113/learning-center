# CLI 核心指令 (Core CLI Commands)

## Problem Statement

AI coding agent 的操控介面通常是一個命令列介面（command-line interface, CLI）。你必須知道怎麼啟動它、怎麼設定環境、怎麼用斜線指令（slash commands）觀察它的內部狀態、以及怎麼在它做出錯事時即時中斷。然而多數人在進入 AI coding 之前，從未認真學過 CLI 的操作層面：他們不知道 `/context` 可以拆解 context window 的組成、不知道 `/clear` 會把 session 歸零、也不知道 escape 鍵能在 agent 執行中途打斷它。

## Why it matters

CLI 是你跟 AI coding agent 之間唯一的操控通道。如果你不知道核心指令，你就無法回答最基本的問題：代理的 context 裡現在到底有什麼？這週的使用配額（quota）還剩多少？你剛才花了太多 token 是因為哪裡設定不對？更關鍵的是，當代理在執行一個明顯錯誤的計畫時，你需要能在它造成破壞之前即時中斷（interrupt），而這也需要你知道 escape 鍵的功能。

掌握核心指令的意義在於：你從「只能等它回覆」的被動角色，轉變為「能隨時觀察、打斷、重置」的主動操控者。這跟 understanding context、managing session、budgeting token 這三個主題直接掛鉤。

## How it works

啟動 CLI agent 的方式是在終端機（terminal）中執行 `claude` 指令。在 VS Code 裡，最佳做法是使用整合式終端機（integrated terminal），因為這樣可以避免終端環境不一致的問題。

啟動後，第一步是執行 `/terminal-setup`。這個指令會安裝按鍵綁定（key bindings），最常用的是 shift+enter：在預設狀態下，按 enter 會直接送出訊息，但加上 shift 後才能插入換行（newline）。這聽起來是小事，但在撰寫多行指令時，你會需要頻繁使用 shift+enter。

接下來是最常用的三個斜線指令：

**`/usage`** 顯示當前 session 與每週配額的剩餘量。AI coding agent 的使用通常有兩層限制：每週上限（weekly limit）和每次 session 的上限（session limit）。當你開始覺得回覆變慢或成本上升時，第一件事就是檢查 usage。

**`/context`** 把 context window 的內容拆解為幾個類別：system prompt 佔了多少 token、工具定義（tools）佔了多少、技能（skills）佔了多少、訊息歷史（messages）佔了多少，以及 context window 的總容量。這是除錯（debugging）你目前設定的首選指令——如果你的 system prompt 超過一萬 token、你根本不知道 harness 往裡面塞了什麼，那其他所有調整都是盲人摸象。

**`/clear`** 把整個 context 歸零。模型本身是無狀態的（stateless），它沒有「記憶」的概念，只有每一次 request 裡送入的 context。`/clear` 就是把這個 session 的所有累積內容清空，讓你從一個全新的狀態開始。另一個等效操作是連按兩次 Ctrl+C，它會結束當前 session 並開一個全新的。

escape 鍵（Escape key）的功能是中斷（interrupt）正在執行的代理。當 agent 正在跑一個計畫——例如它開始刪除你不該刪除的檔案——你可以在任何時候按 escape 打斷它。代理會在這裡插入一段「interrupted」的訊息，然後問你接下來想怎麼做。這跟 clear 不同：escape 是在執行中打斷，clear 是在打斷後清空；escape 保留你剛才的脈絡，clear 則把脈絡一起丟掉。

這些指令的背後，是一個關於模型與 harness 的心智模型。模型本身大約佔整體效果的一半（50/50），另一半來自 harness 的環境設定。effort level（低/中/高）同時影響成本與品質：effort 越高，產生的輸出 token 越多，回覆越慢，成本越高；但 effort 越高，品質並不一定線性提升。實務上的建議是固定使用一個模型和 effort level，把心力花在優化 harness 與環境設定上，而不是每次任務都換模型。

此外，harness 可以把任務委派（delegate）給子代理（sub-agents）。主代理（orchestrator）可以同時派生多個子代理去做不同任務，各自使用不同的模型或 effort level。子代理做完後會把摘要傳回主代理，就像資深工程師派 junior 去做研究再回報。

## In plain terms

CLI 核心指令就是你操控 AI coding agent 的幾個最基本按鈕：`/usage` 看你還有多少額度、`/context` 看你桌上有多少東西、`/clear` 把桌子清乾淨、escape 在 agent 跑偏時立刻打斷它。學會這四個，你就能從被動等待變成主動管理。

## Analogy

把 CLI 想成飛機的駕駛艙儀表板。`/usage` 是油量表，讓你知道還能飛多久；`/context` 是雷達螢幕，顯示飛機此刻看到的所有地形與障礙物；`/clear` 是重置導航，把你帶回起點；escape 則是緊急中止按鈕（abort button），讓你在autopilot 做出危險決定時立刻打斷它。一個不看儀表板的飛行員，就像一個不知道這些指令的 AI coding 用戶。

## Practical use

- 每次開始新工作前，先執行 `/context` 確認 context window 的佔用比例，確保 system prompt 沒有佔掉不成比例的空間。
- 當 agent 的回覆品質明顯下降時，先執行 `/usage` 檢查是否接近週配額上限，再決定是否要 `/clear` 開始新 session。
- 在 agent 執行計畫的過程中，養成隨時準備按 escape 的習慣，特別是當它開始進行你沒預期到的操作時。
- 完成 `/terminal-setup` 後，確認 shift+enter 能正常換行；這是撰寫多行指令的基礎。
- 在 VS Code 整合式終端機中使用 CLI，確保環境一致性，避免終端差異造成的問題。

## Questions

### Q1. `/clear` 跟按 escape 有什麼差別？

A1. Escape 是在 agent 執行中途打斷（interrupt），打斷後會保留當前脈絡，由你決定下一步怎麼做；`/clear` 則是把整個 session 的 context 歸零，從全新狀態開始。Escape 保留脈絡，clear 丟棄脈絡。

### Q2. 為什麼要先執行 `/context` 而不是直接開始寫 code？

A2. `/context` 能讓你看到 system prompt、工具定義、技能與訊息歷史各自佔了多少 token。如果 system prompt 已經佔掉大量空間，你的可用空間會比預期小，後續操作的效率與品質會受影響。先看 context，是調整與優化的前提。

### Q3. `/usage` 顯示的週配額和 session 配額有什麼不同？

A3. 週配額（weekly limit）是整個星期的使用上限，session 配額是單次 session 的使用上限。兩者是不同的限制層級；接近週配額時，即使 session 正常也可能無法繼續使用，因此需要提前規劃。

### Q4. 為什麼說 effort level 是成本與品質的雙重權衡？

A4. Effort level 同時影響輸出 token 數量（成本）與回覆品質：effort 越高，產生的 token 越多，回覆越慢，成本越高；但品質並非線性提升，max effort 通常只比 medium 多出很小的百分比提升，實務上反而是在浪費 token。

### Q5. `/terminal-setup` 裝的 shift+enter 綁定為什麼重要？

A5. 在預設狀態下，按 enter 會直接送出訊息，但多數人撰寫指令時需要插入換行。shift+enter 讓你能在不送出訊息的情況下插入換行，是撰寫多行指令的基礎操作。
