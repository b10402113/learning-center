# 代理、模型、外殼與環境 (Agent, Model, Harness, Environment)

## Problem Statement

談到 AI coding agent 時，人們常把許多不同層次的東西混在一起說，好像「Claude Code」、「Codex」、「GPT」、「Opus」和「檔案系統」都屬於同一種東西。這會讓討論變得模糊：當代理表現不好時，你不知道問題來自模型、來自工具外殼，還是來自它所處的工作環境。

課程在這裡先切開四個核心部件：model、harness、environment，以及 agent。這不是純術語整理，而是為了建立一個能真正指向改善方向的心智模型。若不先分清楚這四者，後面談上下文、工具呼叫、session、探索或配置調整時，很容易把可調的部分和不可調的部分混為一談。

## Why it matters

這個區分最重要的價值，是幫你把注意力放在真正能優化的地方。課程明確指出，許多人過度執著於換模型，但訓練一個新模型的成本極高，對一般使用者來說幾乎不是可操作選項。真正比較有槓桿的，是改善 harness 和 environment，也就是代理如何接觸世界、能用哪些工具、工作在哪個環境中。

它也能幫你更精準地描述 setup。當你說「我在用某個 agent」時，實際上你通常是在說一個模型，被某個 harness 綁定在某個 environment 裡運作。這樣的描述方式，能讓你比較不同產品時不只停留在品牌名稱，而是看清它們的結構差異。

## How it works

課程的定義可以拆成四層。

- **Model**：模型是產生文字輸出的核心引擎。它本身是 text-in, text-out 的東西。課程把它比喻成車子的引擎，例如 Opus、Sonnet、GLM 5.2、Fable 都屬於這一層。
- **Environment**：環境是模型以外、實際工作的世界。這可能是本機檔案系統，也可能是某個產品內建的虛擬環境。環境決定代理可以接觸哪些外部對象。
- **Harness**：外殼是把模型接到環境上的那一層。它負責提供工具、轉接互動、讓模型不是只停留在純文字輸入輸出。像 Claude Code 和 Codex 這類工具，會透過 tool calls 讓模型操作檔案系統；ChatGPT 與 Claude.ai 也各自有自己的虛擬環境與包裝方式。
- **Agent**：agent 不是額外神祕的新東西，而是 model + harness 的組合，被放進某個 environment 裡工作。課程用一句話總結：an agent is a model harnessed in an environment。

課程也提醒，harness 和 environment 的邊界有時會滲開，不總是能畫得非常乾淨。像一個 `npm` script，到底算 harness 提供的操作方式，還是 environment 原本就存在的一部分，未必永遠有唯一答案。這不是定義失敗，而是現實系統本來就有灰區。

## In plain terms

最簡單的理解方式是：模型負責「想字」，外殼負責「接工具」，環境負責「提供世界」，而代理就是這三者組起來後實際替你做事的那個系統。

如果只剩模型，它只是個會吐文字的引擎；一旦有了 harness，它就能呼叫工具；一旦再放進 environment，它才真的能對檔案、專案或平台做事。

## Analogy

課程把模型比喻成車子的引擎，這個比喻可以再往前走一步。引擎本身決定了車子的動力基礎，但你能不能真正上路，還需要車身與操控系統把引擎接起來，也需要道路這個外部世界。對應過來：model 是引擎，harness 像車身與傳動操控系統，environment 則像道路與交通環境。agent 不是只有引擎，而是整台已經能上路的車。

## Practical use

- **描述 setup 時要拆層**：不要只說「我用 Claude」或「我用 GPT」，改成描述是哪個 model、哪個 harness、在哪個 environment 中工作。
- **排錯時先判斷問題層級**：若代理不能操作檔案，常常不是 model 不夠強，而是 harness 沒有提供對應工具，或 environment 不允許存取。
- **優化時優先看外殼與環境**：比起執著換模型，更常見也更可控的做法是改善工具配置、工作流程與環境設計。
- **比較代理時不要只比品牌**：兩個產品即使底層模型接近，只要 harness 和 environment 不同，實際工作能力也可能差很多。
- **接受邊界灰區**：遇到像 script、內建工具、虛擬工作區這類混合部件時，不必強求絕對分類，重點是理解它在整個代理結構裡扮演什麼角色。

## Questions

### Q1. 課程怎麼定義 agent？

A1. agent 不是單獨的一個新元件，而是被 harness 接到某個 environment 中運作的 model。課程的核心句子是：an agent is a model harnessed in an environment。

### Q2. model、harness、environment 各自負責什麼？

A2. model 負責文字輸入輸出；harness 負責把模型接到工具與外部世界；environment 則是代理實際工作的世界，例如檔案系統或產品內建的虛擬環境。

### Q3. 為什麼課程說不要過度執著於換模型？

A3. 因為訓練新模型極度昂貴，對一般使用者來說不是現實槓桿；更可操作、也更值得花力氣優化的，是 harness 與 environment。

### Q4. Claude Code 和 ChatGPT 的差別，依這個心智模型怎麼看？

A4. 它們都可以視為 harness，但接法不同。Claude Code、Codex 這類 harness 會透過工具呼叫接上檔案系統；ChatGPT、Claude.ai 則有自己的虛擬 environment。

### Q5. 為什麼 harness 和 environment 的邊界不一定清楚？

A5. 因為現實中的系統部件常同時帶有包裝層與工作環境的特性。課程舉 `npm` script 為例：它有時很難精確說到底屬於 harness 還是 environment，所以重點不是硬分，而是理解它在代理結構中的作用。
