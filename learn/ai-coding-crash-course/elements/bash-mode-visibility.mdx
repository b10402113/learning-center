# Bash 模式與可見性控制 (Bash Mode & Visibility Control)

## Problem Statement

代理（agent）要跑命令，但你得決定哪些命令和輸出該被它看見。同一條 `npm run dev`，你可能想讓代理看到 server 的即時 log，也可能想偷偷跑一次 `git` 操作不讓它知道。bash 模式（bash mode）負責解決的正是這個問題，讓你把「跑命令」和「給代理看什麼」分開控制。

## Why it matters

不知道怎麼控制可見性，你就只剩兩種極端。讓代理看見一切，它會被無關輸出干擾，也看得到你不打算給它看的東西。完全藏起來，你又看不到 server log，無法判斷程式跑起來沒有。bash 模式給你三個檔位，讓你能按任務挑選，代理該看到什麼由你決定，而不是碰運氣。

## How it works

有三種方式跑 bash，差別在誰看得到命令和輸出。

`!` 前綴（bash mode）。在提示列直接輸入 `!` 再接命令，它會在你眼前的互動 shell 裡執行。命令和輸出都顯示在畫面上，同時進入代理的 context，代理能據此行動。適合想讓代理看到 server log、並拿它當除錯線索的場景。

Ctrl+B（background）。把長時間執行的命令（例如 dev server）丟到背景。輸出寫進本機檔案，狀態列下方出現背景任務指示器。命令還在跑，畫面清空，代理保有看到輸出的路徑，但不需要一直佔著你的終端。

Ctrl+Z（suspend）+ `fg`。完全暫停 Claude Code 整個程式，回到普通 shell。你在這裡跑的命令和輸出，代理一律看不到，但代理的狀態原封不動。想回來就輸入 `fg`，狀態完好接續。適合不想讓代理看到某個命令的場合，例如先自己查一下 git 狀態。

| 模式 | 誰看到輸出 | 命令怎麼跑 | 典型用途 |
| --- | --- | --- | --- |
| `!` 前綴 | 你 + 代理 | 前景互動 shell | 看 dev server log，讓代理一起診斷 |
| Ctrl+B | 你（本地檔案） | 背景執行 | 長時間命令不佔終端，輸出仍給代理 |
| Ctrl+Z + `fg` | 只有你 | 完全隱藏，代理暫停 | 不想讓代理看到的命令 |

注意快捷鍵有平台差異。來源給的是 Windows 快捷鍵，Mac 和 Linux 使用者要對應到自己平台的等價按鍵。

## In plain terms

bash 模式就是「誰看得見」的開關。`!` 是大家看，Ctrl+B 是慢慢跑、需要時再看，Ctrl+Z 是背著代理偷跑、跑完再回來。

## Analogy

想像一個助手站在你桌邊。你可以當著它面做事（`!`），讓它隨時知道你在幹嘛。也可以把一件不急的活放進另一個房間慢慢做，結果留著給它看（Ctrl+B）。或者請它先背過身去，你處理完再叫它轉回來（Ctrl+Z + `fg`），它轉回來時不曉得你剛才動了什麼，狀態卻跟暫停前一模一樣。

## Practical use

- 想邊看 server 邊讓代理診斷，用 `! npm run dev`，再把 shell 畫面留著，代理能看到即時 log。
- `npm run dev` 這類長期命令，用 Ctrl+B 丟到背景，輸出進本地檔案，狀態列下有任務指示器可管。
- 不想讓代理看到的命令，先 Ctrl+Z 暫停代理，跑完再 `fg` 回來，狀態完好。
- 除錯 dev server 或長時間命令的問題，主要靠 bash 模式加背景（`!` + Ctrl+B）。
- 快捷鍵看平台，來源是 Windows 的按法，Mac/Linux 要查對應等價鍵。

## Questions

### Q1.
`!` 前綴跑的命令，誰看得到輸出？

A1. 你眼前的 shell 看得到，輸出也會進入代理的 context，代理能拿它當線索行動。

### Q2.
`npm run dev` 不想一直佔著終端，該用哪個模式？

A2. Ctrl+B 丟到背景。輸出寫進本地檔案，狀態列下方會出現背景任務指示器。

### Q3.
想偷偷跑一個不讓代理看到的 git 命令，怎麼做？

A3. 先 Ctrl+Z 暫停代理，在普通 shell 跑命令，再 `fg` 恢復。代理看不到這段命令和輸出，但狀態完好。

### Q4.
三種模式分別適合什麼場景？

A4. `!` 適合想讓代理一起看即時 log、一起診斷的場景，Ctrl+B 適合長時間執行、不需要佔終端的命令，Ctrl+Z + `fg` 適合完全不想讓代理看到的命令。
