# 代理權限模型 (Agent Permissions Model)

## Problem Statement

代理外殼（harness）的權限模型（Permissions Model）回答一個根本問題，代理在什麼條件下可以真的動手。代理能讀寫整個檔案系統、執行任何命令、呼叫各種工具，如果每一次行動都直接放行，一次錯誤的判斷就可能刪掉資料或弄髒共用分支。介於「問」與「做」之間需要一道閘門，讓危險動作在執行前被攔下來。難處在於這道閘門不能太囉嗦，否則每個普通操作都要打斷你，代理反而難用。

## Why it matters

權限模型是風險與報酬之間的取捨。嚴格預設代表代理不能自動執行任何東西，每次要跑命令都要你批准，安全但繁瑣；全放行代表代理跑得順，但一次誤判的破壞力沒有上限。日常使用需要一個平衡點，常用的安全命令只問一次，真正危險的動作永遠被擋下。權限設定一旦寫錯，它直接決定代理有沒有能力做出不可挽回的事情，例如推上共用分支或刪除檔案。

## How it works

當代理想執行命令，例如 `pnpm typecheck`，它會顯示確切的命令與理由，並給你三個選項。允許一次（allow once）只放行當下這次；永遠允許（allow forever）表示「不要再問了」，把這條規則寫進專案；拒絕（deny）則擋下這次。你也可以按 tab 提出不同的命令，用比較安全的替代指令取代代理原本想跑的內容。

你的偏好會被記錄成 `.claude/settings.local.json` 中的 `permissions` 陣列，這個檔案可以手動編輯。語法支援精確命令與萬用字元，也支援 `deny` 清單。萬用字元讓一條規則覆蓋一類命令，例如 `deny git push *` 可以永久擋下所有分支的推入。網頁搜尋與抓取（web search/fetch）同樣需要權限。

| 型態 | 例子 | 效果 |
| --- | --- | --- |
| 精確命令 | `pnpm typecheck` | 只放行這條確切命令 |
| 萬用字元 | `npm run *` | 放行符合樣式的整類命令 |
| 拒絕清單 | `deny git push *` | 永久擋下所有 git push |

權限檔案分兩層。`settings.local.json` 是個人設定，會被 git 忽略，只影響你這台機器上的代理；`settings.json` 會被提交、跟團隊共用，儲存庫上的任何代理實例都會讀取。授予「不要再問了」會寫入一條專案規則，之後符合的命令自動放行；拒絕某個工具則會把它從系統提示詞中移除。

## In plain terms

權限模型是代理與你之間的一道檢查哨。代理提出要做的動作，你決定放行、記住以後都放行，還是攔下來。記錄下來的規則就是你的「通行證清單」，可以隨時手改。

## Analogy

想像代理是你的助理，權限模型就是助理的刷卡權限。助理每次想花錢都要問你一次，你可以說這次可以、以後這類都行，或者永遠不行。你會把「固定採買」設成永久授權，但把「刷我的卡付大額」永久禁止。手改設定檔就像調整助理胸前的卡片權限等級，而不是每次都要攔住他問。

## Practical use

- **手動編輯權限 JSON** 預先授權常用命令，例如 `pnpm typecheck` 或 `npm run dev`，省下每次都問的麻煩。
- **永久拒絕危險命令** 用 `deny git push *` 擋下所有推入，讓代理永遠沒有能力弄髒共用分支。
- **按 tab 提出替代命令** 代理想跑的動作不合意時，直接取代成更安全的版本，而不是單純拒絕。
- **區分個人與團隊設定** `settings.local.json` 留給自己、會被 git 忽略；`settings.json` 提交共用，讓整個團隊享受同一組安全規則。
- **把常用清單放進團隊設定** 讓每個人在同一個儲存庫上都自動通過這些檢查，不用各自手動授權。
- **理解權限與上下文互相影響** 拒絕某個工具會同時把它從系統提示詞移除，權限設定也順帶縮小了每次請求攜帶的上下文。

## Questions

### Q1. 當代理想執行 `pnpm typecheck` 時，權限提示會提供哪三種選項？

A1. 允許一次、永遠允許（不要再問了）、拒絕。永遠允許會把規則寫進專案的權限設定，之後同樣的命令自動放行。

### Q2. `settings.local.json` 和 `settings.json` 有什麼差別？

A2. `settings.local.json` 是個人設定，會被 git 忽略，只影響本機；`settings.json` 會被提交、跟團隊共用，儲存庫上的任何代理實例都會讀取。

### Q3. 如何永久禁止代理執行 git push？

A3. 在權限設定中加入 `deny git push *`，用萬用字元擋下所有分支的推入。

### Q4. 按 tab 在權限提示中有什麼作用？

A4. 可以用你自己的命令取代代理原本想執行的命令，提出一個比較安全的替代方案，而不是只能全盤接受或拒絕。

### Q5. 拒絕一個工具會對上下文產生什麼影響？

A5. 拒絕工具會把它的定義從系統提示詞中移除，所以權限設定不只控管執行，也同時縮小了每次請求攜帶的上下文。
