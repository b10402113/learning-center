零依賴單檔輸出的設計哲學

ai-html · Step 2/3

一句話回顧

上一步我們理解了 HTML 是 AI 的原生輸出語言。這一步看看 AI 生成 HTML 時採用的架構模式：一個 .html 檔案，內聯所有 CSS 和 JS，打開就能用。

核心問題

知道 AI 擅長生成 HTML 之後，下一個問題是：AI 產出的 HTML 應該長什麼樣？答案是：零依賴單檔。

什麼是零依賴單檔

零依賴單檔的意思是：整個應用——結構、樣式、行為——全部塞進一個 .html 檔案。不需要 npm install，不需要 build tools，不需要任何外部依賴。雙擊檔案，瀏覽器打開，就能用。

這聽起來像是倒退——現代前端不是都在講模組化、講打包嗎？沒錯。但 AI 工作流的約束條件不同：

場景 模組化開發 零依賴單檔
開發者維護的長期專案 ✓ 適合 ✗ 不適合
AI 一次產出的交付物 ✗ 太複雜 ✓ 適合
需要立即預覽 ✗ 需要啟動伺服器 ✓ 雙擊即可
分享給非技術人員 ✗ 需要說明如何運行 ✓ 直接打開

AI 工作流的核心需求是：快速產出、立即預覽、輕鬆分享。零依賴單檔完美滿足這三點。

架構解剖：一個典型的 HTML 投影片

一個零依賴的 HTML 投影片檔案通常包含三個部分：

1. 內聯 CSS（樣式）

所有 CSS 直接寫在 <style> 標籤裡。這包括：

  • 基礎佈局：鎖定 1920×1080 的固定舞台（stage），用 CSS transform 縮放到瀏覽器視窗大小
  • 投影片切換：用 visibility 和 opacity 控制哪張投影片可見，不用 display: none（因為 display: none 會被後來的 CSS 覆蓋）
  • 列印樣式：@media print 讓每張投影片佔一頁
  • 無障礙支援：prefers-reduced-motion 為不想看動畫的使用者關閉效果

2. HTML 結構（內容）

每張投影片是一個 <div class="slide">，堆疊在同一個容器裡。只有當前可見的投影片有 .active 類別。

3. 內聯 JavaScript（行為）

一個小型控制器類別處理所有互動：

  • 鍵盤導航：左右方向鍵切換投影片
  • 觸控導航：手機上的滑動手勢
  • 滾輪導航：滑鼠滾輪切換
  • 自動縮放：1920×1080 的舞台根據瀏覽器視窗大小自動縮放，保持 16:9 比例

固定舞台模型

零依賴 HTML 投影片的一個關鍵設計決策是固定舞台（fixed stage）。每張投影片都設計為 1920×1080 像素，整個舞台用 CSS transform 縮放到瀏覽器視窗大小。

Every deck uses a 1920×1080 slide canvas scaled as a whole to the viewport. Slides must stay 16:9 on every screen, including phones. Do not reflow slide content to fit the device.

這意味著：

  • 投影片內容不會因為螢幕大小而重新排版
  • 在手機上看投影片，效果跟在電腦上一樣（只是整體縮小）
  • 設計師可以在 1920×1080 的固定畫布上精確控制每個元素的位置

這跟響應式設計（responsive design）完全相反。響應式設計會根據螢幕大小重新排版內容；固定舞台則是把整個畫布當成一張圖片來縮放。對於投影片來說，固定舞台是正確的選擇——因為投影片的排版是刻意的，不是彈性的。

為什麼不能用 display: none

一個常見的陷阱是用 display: none / display: block 來切換投影片。這看起來直覺，但有問題：

如果你後來加了一條 CSS 規則 .slide-content { display: flex; }，它會覆蓋 display: none，導致所有投影片同時可見。用 visibility 和 opacity 控制可見性就不會有這個問題，因為這些屬性不會被佈局相關的 CSS 規則覆蓋。

無障礙與列印

零依賴不等於忽略無障礙。一个好的零依賴 HTML 投影片會包含：

  • prefers-reduced-motion 媒體查詢：偵測到使用者偏好減少動畫時，關閉所有過渡效果
  • @media print：讓每張投影片在列印時佔一頁，方便產生 PDF

這些都是幾行 CSS 的事情，但它們讓你的 HTML 投影片從「能用」變成「好用」。
