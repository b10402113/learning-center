什麼是 Agent Skill？

ai-html · Agent Skill 架構 · Step 1/4

你可能已經用過 AI 助手：給它一段 prompt，它回一段文字。但當任務變複雜——比如「把一份 PDF 轉成有動畫的知識影片」——一段 prompt 就不夠了。你需要的不只是一句指令，而是一套完整的工作流程。

從 Prompt 到 Skill

一段 prompt 告訴 AI「做什麼」，但它不會告訴 AI「按什麼步驟做」「遇到特殊情況怎麼辦」「做完之後怎麼驗證品質」。這就像給廚師一張寫著「做一道菜」的紙條——他知道要做菜，但不知道今天要做什麼菜、食材在哪裡、客人有沒有過敏。

Agent Skill（代理技能）就是把「做什麼」擴展成「怎麼做」的結構化工作說明。它不只是一段文字，而是一個完整的資料夾，裡面包含：

組成作用類比
SKILL.md主工作流文件——定義階段劃分、非妥協規則、品質門檻食譜的步驟說明
references/參考文件——按需載入的深度參考資料食材百科全書
templates/範本——預設的輸出格式和 scaffold碗盤和烹飪工具
scripts/腳本——確定性操作（scaffold、匯出、轉換）烤箱和計時器
themes/主題——可替換的設計系統餐廳的裝潢風格
manifest.json版本號與發佈資訊菜單上的菜名和價格

Skill 的核心特徵

一個 agent skill 和一段 prompt 的根本差異在三個地方：

1. 多階段工作流（Multi-phase Workflow）

Skill 把任務拆成多個階段，每個階段有明確的完成標準。比如 beautiful-article skill 的工作流是：來源提取 → 計畫撰寫 → 雙重確認 → 建構 → 最終審查 → 修復——每個階段都有「硬門檻」（hard checkpoint），代理必須通過才能進入下一個階段。

2. 非妥協規則（Non-negotiable Rules）

Skill 裡有些規則是不能違反的。比如 frontend-slides skill 規定：舞台必須是固定的 1920×1080、不能用 CDN 連結、必須是零依賴單檔輸出。這些規則確保每次產出的結果都符合品質標準，不會因為代理的「創意」而偏離。

3. 按需載入（On-demand Loading）

Skill 不會一次把所有參考文件塞進上下文。它只在需要的時候才載入對應的 reference 文件。這就像你在做菜的時候不會把整本食譜百科背下來，而是在需要的時候翻到對應的那一頁。

三個真實的 Skill 範例

beautiful-article

把任何來源材料（URL、PDF、DOCX、Markdown、截圖）轉成一篇精緻的、可分享的單檔 HTML 文章。它使用 reacticle 元件協議，支援 10 種文章類型（長文、教程、解說、簡報等）和 11 種編輯主題。工作流有 3 個硬門檻。

frontend-slides

生成零依賴、帶動畫的 HTML 投影片。6 階段流程：偵測模式 → 內容探索 → 風格探索 → 生成 → 交付 → 分享/匯出。內建 34 個模板和 12 個視覺預設。舞台固定 1920×1080，單檔輸出。

boring-video

把素材轉成帶動畫的知識影片。四階段規劃管線：beats → narration → scenes → storyboard，然後交給 HyperFrames 做最終產出。每個階段產出一份持久的、可獨立審查的文件。

為什麼需要 Skill 這種結構？

核心問題是：怎麼把「人類腦中的設計方法論」打包成代理可以穩定複製執行的工作單元。

傳統的 prompt 只是一段指令。Agent 執行完就忘了。但 Skill 把工作流、品質門檻、設計約束、參考資料全部組織在一起。代理不用每次從零開始想怎麼做，而是按照 skill 定義好的階段走完流程。

這就像從「口頭傳授做菜方法」進化到「有一本完整的食譜書」——任何人都能按步驟做出穩定的結果。
