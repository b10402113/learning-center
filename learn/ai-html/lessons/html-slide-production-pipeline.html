從素材到投影片：6 階段 Pipeline

前幾步你學了舞台模型、導航機制、模板系統。這一步把它們串成一個完整的工作流——從你手上的素材（PDF、筆記、PPT、文章）到一組可播放的 HTML 投影片。

frontend-slides 這個 skill 定義了 6 個階段：

階段名稱做什麼
0偵測模式（Detect Mode）判斷使用者要做什麼類型的投影片
1內容發現（Content Discovery）從素材中提取內容
2風格發現（Style Discovery）選定設計模板和視覺風格
3生成（Generate）組裝 HTML 投影片
4交付（Delivery）品質檢查、調整、確認
5分享/匯出（Share/Export）部署、PDF 匯出、分享連結

階段 0：偵測模式

第一步不是開始排版，而是搞清楚「使用者想做什麼」。常見模式：

  • 從零開始——給我一個主題，幫我做投影片
  • 從 PPT 轉換——我有一個 .pptx 檔，幫我轉成 HTML
  • 從文章生成——我有一篇文章，幫我做成投影片
  • 從筆記生成——我有一些零散筆記，幫我整理成投影片

不同的模式決定後續的 pipeline 走法。例如 PPT 轉換會先用 extract-pptx.py 抓出文字和圖片，然後用提取的內容填充模板。

階段 1：內容發現

內容發現的任務是把素材轉換成結構化的內容。如果是從零開始，agent 會用 LLM 根據主題生成大綱和內容。如果是從現有素材來，就需要提取和重組。

關鍵原則：投影片的內容密度遠低於文章。一張投影片不該塞進一段完整的段落。好的投影片內容是：一個標題、2-3 個要點、一個視覺元素。如果發現內容太密，就拆成更多張。

階段 2：風格發現

這一步對應上一步學到的模板系統。流程是：

  1. 讀取 selection-index.json，根據主題和受眾篩選候選
  2. 讀取候選模板的 preview.md，做三選一（Safe/Bold/Wildcard）
  3. 確認後讀取 design.md，獲得完整的設計規範

如果你用的是 guizang 的雙系統，這一步就是選 Style A 還是 Style B，然後選主題色。選定後，所有後續生成的投影片都會嚴格遵循這套設計語言。

階段 3：生成

這是 pipeline 的核心——把結構化內容和設計規範組合成一個完整的 HTML 檔案。

生成過程：

  1. 載入 viewport-base.css（固定舞台 + slide 堆疊）
  2. 載入選定模板的 CSS（顏色 token + 字型 + 元件樣式）
  3. 為每一張 slide 生成 HTML 結構（使用模板定義的佈局 class）
  4. 加入動畫效果（CSS 進入動畫或 canvas FX）
  5. 加入導航 JS（SlidePresentation 或 <deck-stage>）
  6. 如果有講者備註，加入 SPEAKER_NOTES 陣列和簡報模式

最終產出是一個單一 HTML 檔案——所有 CSS、JS、字型設定都內聯。這是「零依賴單檔輸出」的實現。

階段 4：交付（品質檢查）

生成後不能直接交付，需要過品質關。guizang 的品質清單分 P0-P3 四級：

等級檢查項目嚴重程度
P0簡報模式可控制、Swiss locked mode 合規阻斷性
P1視覺節奏、圖片對齊、標題尺寸高
P2動畫克制、手機預覽中
P3邊界情況處理低

frontend-slides 也有自己的自我檢查機制——agent 生成後會自動驗證 class 名稱是否存在於模板中、圖片比例是否正確、佈局是否溢位。

自動化驗證腳本：

  • validate-swiss-deck.mjs——靜態檢查 + 可選的 Playwright 視覺測量
  • validate-presenter-mode.mjs——頁面 ID 唯一性、備註對齊、時間估算

階段 5：分享/匯出

品質通過後，有幾種分享方式：

方式工具適合場景
直接分享 HTML傳檔案離線演示、最簡單
部署到網路deploy.sh（Vercel）需要連結分享
匯出 PDFexport-pdf.sh（Playwright）需要印刷或離線閱讀
匯出 PPT保持 HTML（PPT 轉入，HTML 轉出）與 PowerPoint 生態整合

HTML 投影片的匯出特別有趣：用 Playwright（無頭瀏覽器）逐一截圖每一張 slide，然後組合成 PDF。這比 PowerPoint 的 PDF 匯出更精確，因為你控制了渲染環境。

Guizang 的 10 步工作流

guizang-ppt-skill 把 pipeline 規劃得更細，分 10 步：

  1. 更新檢查——確認 skill 版本最新
  2. 需求釐清——7 問 intake（風格 A/B、受眾、時長、素材、圖片、主題、限制）
  3. 複製模板——從 template.html 或 template-swiss.html 出發
  4. 填充內容——套用佈局、填入文字、計算主題節奏
  5. （可選）Codex 圖片生成——用 AI 生成插圖
  6. 講者備註——生成 SPEAKER_NOTES 和 data-slide-id
  7. 自我檢查——用品質清單和驗證腳本
  8. 預覽——在瀏覽器中播放確認
  9. 排練——開啟簡報模式測試
  10. 迭代——根據反饋修改

注意第 2 步的 7 問 intake——這是在開始任何排版之前必須回答的問題。這確保你不會做出來之後才發現「風格不對」或「受眾不合」。

三層方法論

RoboNuggets 的教程提出了 HTML 投影片的三層進階路徑：

層級做什麼能力要求
Level 1安裝 HTML slides skill，直接使用零——開箱即用
Level 2用品牌設計系統定制理解 CSS custom properties
Level 3構建自己的動畫組件庫HTML/CSS/JS 開發能力

你的學習路徑大致對應 Level 1 → Level 2 的過渡。目前你已經理解了固定舞台、導航、模板的原理，正在走向能夠修改和客製設計系統的階段。
