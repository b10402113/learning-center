導航與互動控制

投影片基礎 · Step 2/4

學習目標

掌握投影片的導航機制：鍵盤方向鍵、觸控滑動、滾輪切換如何驅動 slide 切換，以及 <deck-stage> Web Component 的自動縮放。

導覽器的誕生

上一步你學到，所有投影片堆疊在同一位置，靠 CSS class 切換可見性。但「切換」這個動作本身需要一個控制者——偵測使用者的操作、判斷方向、更新 class。這個控制者就是 SlidePresentation class，或它的現代替代品 <deck-stage> Web Component。

它的職責只有一件事：把使用者的輸入轉換成 slide 切換。鍵盤按了什麼、手指滑了多遠、滾輪轉了多少——全部匯聚到同一個出口：showSlide(index)。

鍵盤導航

鍵盤是最可靠的導覽方式。基本規則：

按鍵動作備註
→ 或 空格下一張最直覺的操作
←上一張回顧用
Home跳到第一張快速回開頭
End跳到最後一張快速到結尾

實作上，SlidePresentation 在建構函式裡註冊一個全域的 keydown 事件監聽器。偵測到方向鍵或空格時，計算目標 index（不超過 0 和總數 -1 的邊界），然後呼叫 showSlide()：

document.addEventListener('keydown', (e) => {
  if (e.key === 'ArrowRight' || e.key === ' ') {
    e.preventDefault();
    this.showSlide(this.current + 1);
  } else if (e.key === 'ArrowLeft') {
    e.preventDefault();
    this.showSlide(this.current - 1);
  }
});

注意 e.preventDefault()——它阻止瀏覽器的預設行為（例如空格鍵向下捲動頁面）。這在投影片播放時至關重要，因為任何非預期的滾動都會破壞體驗。

觸控導航

在手機或平板上，使用者用手指滑動來切換投影片。觸控導航的核心是水平滑動偵測：

  1. 手指觸碰時記錄起始 X 坐標（touchstart）
  2. 手指離開時記錄結束 X 坐標（touchend）
  3. 計算水平位移：結束 X − 起始 X
  4. 如果位移 > 閾值（通常是 50px），判定為有效滑動
  5. 向左滑 → 下一張；向右滑 → 上一張

為什麼只看水平位移？因為垂直滑動可能是使用者在捲動頁面內容，不該被誤判為切換投影片。實作時會同時檢查水平和垂直位移的比例，只有水平位移明顯大於垂直位移時才觸發切換。

手機的 tap zones

除了滑動，手機上還有一個便捷操作：點擊螢幕左右兩側。左半邊 = 上一張，右半邊 = 下一張。這是鍵盤左右鍵的觸控版等價物，在投影片演示時特別實用——你不需要精準地滑動，只要輕觸一下就行。

滾輪導航

桌面瀏覽器的滾輪（mouse wheel）也能切換投影片：

document.addEventListener('wheel', (e) => {
  e.preventDefault();
  if (e.deltaY > 0) this.showSlide(this.current + 1);
  else this.showSlide(this.current - 1);
}, { passive: false });

注意 { passive: false }——這告訴瀏覽器這個事件處理器會呼叫 preventDefault()，所以不要最佳化它。在 Chrome 裡，如果你忘了這個選項，控制台會出現警告，而且預設行為（頁面捲動）不會被阻止。

Web Component：<deck-stage>

上面的鍵盤、觸控、滾輪三種導航方式，在傳統做法中需要你自己手動綁定事件。但在更現代的架構中，這些全部被封裝成一個 Web Component：<deck-stage>。

Web Component 是瀏覽器原生的元件化機制，不需要 React 或 Vue。它用 Shadow DOM 把自己的 CSS 和 JS 封裝起來，不會污染外部頁面的樣式。

使用方式極其簡單：

<deck-stage width="1920" height="1080">
  <section class="slide">第一張投影片</section>
  <section class="slide">第二張投影片</section>
  <section class="slide">第三張投影片</section>
</deck-stage>

Web Component 內部自動處理：鍵盤導航、觸控滑動、滾輪切換、視窗縮放、投影片計數器、重置按鈕。你只需要負責排版每一張 slide 的內容。

公開 API

方法 / 屬性說明
.next()前進到下一張
.prev()後退到上一張
.goTo(i)跳到第 i 張（0-indexed）
.reset()回到第一張
.index當前投影片的索引（唯讀）
.length總投影片數（唯讀）

事件：slidechange

每次切換投影片時，<deck-stage> 會發出一個 slidechange 自訂事件（CustomEvent）：

stage.addEventListener('slidechange', (e) => {
  console.log(e.detail.index);        // 當前索引
  console.log(e.detail.previousIndex); // 切換前的索引
  console.log(e.detail.total);        // 總投影片數
  console.log(e.detail.reason);       // 'keyboard' | 'touch' | 'wheel' | 'api'
});

reason 欄位特別有用——它讓你知道是什麼觸發了切換，可以用來做差異化處理（例如：鍵盤切換時播放音效，API 切換時不播放）。

屬性驅動的縮放

<deck-stage> 的 width 和 height 屬性定義了畫布尺寸，預設是 1920×1080。加上 noscale 屬性可以關閉自動縮放——在你需要把投影片嵌入到一個已經有自己佈局的頁面時很有用。

列印模式

<deck-stage> 會自動注入列印樣式。當使用者按 Ctrl+P 時，每一張 slide 會自動成為獨立的列印頁面，導航 UI 隱藏。整個過程不需要額外的 PDF 匯出工具——瀏覽器內建的列印功能就是你的 PDF 產生器。

Speaker Notes（講者備註）

導航系統還支援講者備註的同步。透過 postMessage API，主投影片視窗可以把當前投影片的備註發送到另一個視窗（演示者視圖）。這讓你在演示時能同時看到投影片和備註，而觀眾只看到投影片。

投影片切換時，slidechange 事件的 detail 裡包含當前投影片的 index，演示者視窗據此從 SPEAKER_NOTES 陣列中取出對應的備註內容。
