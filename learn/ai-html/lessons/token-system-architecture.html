Token 分層架構

Token 主題系統 · Step 2/4 · 約 15 分鐘

從變數到設計系統

上一課我們知道 CSS Custom Properties 可以宣告變數、覆蓋、切換。但如果你只是把所有顏色和字型塞進一個 :root 區塊，那只是「一堆變數」，不是一套設計系統。設計系統需要組織邏輯——變數之間有什麼關係、誰引用誰、命名怎麼分層。

三層 Token 架構

一套成熟的 token-driven 設計系統把變數分成三層：

層級 作用 例子 誰改它
Base tokens 原始值——顏色色票、字型家族、尺寸數值 --blue-500: #3b82f6 設計師
Semantic tokens 語意命名——描述用途而非顏色 --accent: var(--blue-500) 主題檔案
Component tokens 綁定到特定元件 --card-bg: var(--bg) 元件 CSS

Base tokens：原始調色盤

Base tokens 是設計的原子單位。它們不帶任何語意——只是一個色票或一個數值：

:root {
  --blue-500: #3b82f6;
  --gray-100: #f3f4f6;
  --gray-800: #1f2937;
  --font-sans: "Noto Sans SC", sans-serif;
  --font-mono: "JetBrains Mono", monospace;
  --size-4: 1rem;
  --size-8: 2rem;
}

Base tokens 幾乎不直接被元件引用。它們的價值在於：當你想換色系時，只需改 base tokens 的值，所有語意 token 跟著變。

Semantic tokens：語意橋接層

Semantic tokens 是主題系統的核心。它們用用途命名，引用 base tokens：

:root {
  /* 語意顏色 */
  --bg: var(--gray-100);
  --text-1: var(--gray-800);
  --accent: var(--blue-500);

  /* 語意字型 */
  --font-heading: var(--font-sans);
  --font-code: var(--font-mono);
}

元件 CSS 只引用 semantic tokens。當你換主題時，覆蓋 semantic tokens 就夠了——base tokens 不動：

/* 深色主題：只改 semantic 層 */
.dark {
  --bg: var(--gray-800);
  --text-1: var(--gray-100);
  --accent: #60a5fa;
}
原則：元件不直接引用 base tokens，主題不直接修改元件 CSS。Semantic tokens 是兩者之間的橋接層。

Component tokens：元件內部變數

Component tokens 把 semantic tokens 綁定到特定元件的屬性：

.card {
  --card-bg: var(--bg);
  --card-border: var(--border);
  background: var(--card-bg);
  border: 1px solid var(--card-border);
  border-radius: var(--radius-md);
}

Component tokens 讓元件可以有自己的微調空間，同時保持與主題的一致性。如果你的元件不需要微調，可以直接用 semantic tokens——component tokens 是可選的。

一份真實的 base.css：30+ 變數

在投影片的設計系統中，base.css 的 :root 區塊定義了 30+ 個變數。以下是按類別組織的完整清單：

類別 變數名 用途
背景與文字--bg頁面主背景
--text-1主要文字（標題、段落）
--text-2次要文字（副標題、說明）
--text-3弱化文字（腳註、時間戳）
--muted靜音文字色
強調色--accent主強調色（連結、按鈕）
--accent-2第二強調色
--accent-3第三強調色
--grad漸層色（通常由 accent 派生）
邊框與陰影--border通用邊框色
--shadow-sm / --shadow-md / --shadow-lg三級陰影
--radius-sm / --radius-md / --radius-lg三級圓角
字型--font-sans無襯線字型家族
--font-serif襯線字型家族
--font-mono等寬字型家族
--font-display展示用字型（大標題）

這個清單看起來很多，但其實只需要記住四個類別：背景文字、強調色、邊框陰影、字型。每個類別有 2–5 個變數，形成一個完整但不臃腫的設計空間。

主題檔案的角色

知道了三層架構，主題檔案的角色就很清楚了：它只覆蓋 semantic tokens。一個典型的主題檔案不超過 200 行，內容就是一組 :root 覆蓋：

/* Catppuccin Mocha 主題 */
:root {
  --bg: #1e1e2e;
  --text-1: #cdd6f4;
  --text-2: #a6adc8;
  --text-3: #6c7086;
  --accent: #cba6f7;
  --accent-2: #f38ba8;
  --accent-3: #a6e3a1;
  --border: #313244;
  --shadow-sm: 0 1px 2px rgba(0,0,0,0.3);
  --shadow-md: 0 4px 12px rgba(0,0,0,0.4);
}

這就是主題切換的全貌：base.css 定義變數結構，主題檔案覆蓋值，元件 CSS 引用語意變數。三層各司其職。
