投影片模板 · Step 3/3

Learning goal

能說明 locked layout 如何透過註冊機制保障設計完整性，以及違反規則時會發生什麼。

什麼是 Locked Layout？

大多數投影片工具讓你自由排列內容——標題放哪裡、圖片放哪裡、文字放哪裡，全部由你決定。這聽起來很自由，但問題是：當 AI 代理自由發揮時，它很容易「看起來像 Swiss，但已經脫離原始模板」。

Locked layout 的核心思想是：先註冊，再使用。把所有允許的頁面結構登記在一個清單上，代理只能從這個清單中選擇，不能自己發明新的。

Guizang-ppt-skill 的 Swiss 風格有 22 個已登記的版面（S01-S22），每一個都對應原始參考 PPT 的一頁。這個清單就是 golden source——版式的唯一權威來源。

註冊機制如何運作

每個 Swiss 版面在 HTML 中用 data-layout="Sxx" 屬性標記：

<section class="slide" data-layout="S04">
  <!-- Six Cells 版面的骨架 -->
</section>

代理在生成每一頁時，必須先從清單中選一個版面，然後在 section 上加上對應的 data-layout 屬性。驗證腳本（validate-swiss-deck.mjs）會檢查：

  1. 每個 <section class="slide"> 是否有 data-layout 屬性
  2. data-layout 的值是否在 S01-S22 的已登記清單中
  3. 是否有未登記的正文頁（如臨時發明的 P23/P24）
  4. SVG 中是否出現了可見文字（違反 Swiss 規則）

違反規則會怎樣？

如果你試圖發明一個不在清單中的版面，或者在 SVG 中寫了可見文字，驗證腳本會報錯。更嚴重的是，即使腳本沒抓到，視覺上也會出問題——因為你的新版面沒有對應的 CSS 規則，字型、間距、對齊全部會跑掉。

这就是 locked layout 的設計完整性保障：

  • 註冊 = 保證：已登記的版面有完整的 CSS 支援，視覺效果是可預測的
  • 未登記 = 風險：自己發明的版面沒有 CSS 支援，效果不可預測
  • 驗證 = 閘門：validate-swiss-deck.mjs 在生成後自動檢查，攔截違規

Style A 的版面對比

Style A（電子雜誌）的 10 個版面也是 registered layouts，但它們是「可選」的而非「locked」的。你可以在 10 個中自由選擇、混搭，不需要像 Swiss 那樣嚴格遵守 S01-S22 的限制。

兩者的差異在於：
