# Digest — fem-kubernetes-main

## Overview (L1)

- `app/` — A minimal Bun/TypeScript HTTP API with two endpoints (`/healthz` for probes, `/counter` for a Postgres-backed visit counter). Includes a single-stage Dockerfile (`oven/bun:1.3.10-slim`), a Makefile for multi-arch image builds, and a CI workflow. The app is deliberately trivial — its only job is to make Kubernetes orchestration concepts real (probes, DB durability, CPU-bound load for HPA).

- `manifests/day-one/` — Kubernetes manifests for the Day-1 workshop sequence (Foundations → POC → Stable). Contains a `kind` cluster config (1 control-plane + 2 workers), a POC-era Deployment (no probes, plaintext DB env), and a `k8s/base/` Kustomize base with the matured Stable form: probed Deployment, ClusterIP Service, ConfigMap, CloudNativePG `Cluster`, Gateway API `Gateway` + `HTTPRoute`, and a `kustomization.yaml`.

- `manifests/day-two/` — Kubernetes manifests for the Day-2 Production stage and EKS capstone. Contains an `eksctl` cluster config, Kustomize overlays (`kind` and `eks`) that patch the day-one base with environment-specific values (gateway class, storage class, replica count), Argo CD `Application` manifests, cluster-setup resources (ALB GatewayClass, gp3 StorageClass), and a SealedSecret for the EKS overlay.

- `docs/workshop/` — Comprehensive instructor guides and slide source for the two-day Frontend Masters Kubernetes workshop. Contains the master OUTLINE (32 segments mapped to three maturity stages: POC, Stable, Production), per-stage instructor guides (FOUNDATIONS.md, POC.md, STABLE.md, PRODUCTION.md), an AGENDA, Marp slide source (slides.md), Mermaid diagrams, and a CSS theme.

- `dist/` — Built artifacts: rendered Mermaid SVG diagrams and a Marp-generated HTML slide deck. Generated by the root Makefile from `docs/workshop/` sources.

- `.github/workflows/` — A single CI workflow (`build-image.yml`) that builds and pushes the multi-arch sample-app Docker image to Docker Hub (`docker.io/altf4llc/fem-kubernetes:v1` + `:<git-sha>`) on pushes to `main`/`workshop` or version tags. All `uses:` are digest-pinned to commit SHAs.

## Structure (L2)

### app/server.ts

- Locator: `[[sources/kubernetes/20260910/fem-kubernetes-main/app/server.ts]]`
- Purpose: The sample application — a Bun HTTP server with two endpoints. `/healthz` returns `{"status":"ok"}` (or 500 when toggled unhealthy via `SIGUSR1`). `/counter` inserts a row into Postgres and returns the visit count; accepts a `?work=N` query param to burn CPU for HPA demos.
- Key exports: `Bun.serve` handler with `handleHealthz()` and `handleCounter()`. Internal: `ensureSchema()` (creates `visits` table), `burn()` (CPU work), `rebuildClient()` (reconnects SQL on failure).
- Dependencies: `bun:sql` (Bun's built-in SQL client for Postgres). Reads `PORT`, `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` from environment.
- Learner-relevant: Demonstrates why health probes matter (the `SIGUSR1` toggle lets instructors break `/healthz` on-stage to trigger liveness restarts). The CPU-burn path gives the HPA something to react to. The Postgres connection proves database durability (or lack thereof in POC).

### app/Dockerfile

- Locator: `[[sources/kubernetes/20260910/fem-kubernetes-main/app/Dockerfile]]`
- Purpose: Single-stage Dockerfile based on `oven/bun:1.3.10-slim`. Bun runs TypeScript natively so there is no build step. Layer-cached dependency install, non-root `bun` user, exposes port 8080.
- Key exports: Image entrypoint `bun run server.ts`.
- Dependencies: `oven/bun:1.3.10-slim` base image, `package.json`, `bun.lock`, `server.ts`.
- Learner-relevant: Example of a minimal container image for a Kubernetes workload — single-stage, non-root, layer caching for fast rebuilds. The image coordinate `docker.io/altf4llc/fem-kubernetes:v1` is referenced by every Deployment manifest.

### app/Makefile

- Locator: `[[sources/kubernetes/20260910/fem-kubernetes-main/app/Makefile]]`
- Purpose: Build and push the workshop sample-app image. Mirrors the CI workflow: same image coordinate, same two tags (`$(TAG)` + git SHA), same platforms (`linux/amd64,linux/arm64`). Provides `push` (multi-arch via buildx), `build` (single-arch local), `ensure-builder` (docker-container driver), and `login`.
- Key exports: Make targets `push`, `build`, `ensure-builder`, `login`.
- Dependencies: Docker Buildx, Docker Hub registry.
- Learner-relevant: Shows how container images are built and versioned for Kubernetes deployments — multi-arch builds, immutable per-commit tags as escape hatches.

### app/package.json

- Learner-relevant: Minimal dependency surface — the app uses only Bun built-ins, keeping the container image small.

### manifests/day-one/kind-cluster.yaml

- Locator: `[[sources/kubernetes/20260910/fem-kubernetes-main/manifests/day-one/kind-cluster.yaml]]`

- Dependencies: `kind` CLI, Docker/Podman runtime.

### manifests/day-one/deployment.yaml

- Locator: `[[sources/kubernetes/20260910/fem-kubernetes-main/manifests/day-one/deployment.yaml]]`
- Purpose: POC-era Deployment manifest — the deliberately simple "before" form. No probes, plaintext DB env vars (`DB_HOST=postgres`, `DB_PASSWORD=demo-not-a-real-password`), namespace `default`, 1 replica.
- Key exports: `Deployment/sample-app` (image `docker.io/altf4llc/fem-kubernetes:v1`).
- Dependencies: The sample-app container image.
- Learner-relevant: The contrast between this file and `k8s/base/deployment.yaml` **is the workshop's thesis** — the diff shows what maturing from POC to Stable means (probes, secret refs, namespace, resource limits).

### manifests/day-one/k8s/base/deployment.yaml

- Locator: `[[sources/kubernetes/20260910/fem-kubernetes-main/manifests/day-one/k8s/base/deployment.yaml]]`
- Purpose: The matured Stable-form Deployment. Adds startup/readiness/liveness probes on `/healthz`, resource requests (100m CPU, 128Mi mem) and limits (500m CPU, 256Mi mem), reads config from ConfigMap (`envFrom: db-config`), reads credentials from CNPG-generated Secret (`secretKeyRef: postgres-app`), points at `postgres-rw` Service, lives in namespace `app`.
- Key exports: `Deployment/sample-app` in namespace `app`.
- Dependencies: ConfigMap `db-config`, Secret `postgres-app` (auto-created by CloudNativePG), Service `postgres-rw`.
- Learner-relevant: Reference example of a production-ready Deployment — probes, resource bounds, externalized config, secret references. The probes target `/healthz` which the app's `SIGUSR1` toggle can break for live demos.

### manifests/day-one/k8s/base/postgres-cluster.yaml

- Locator: `[[sources/kubernetes/20260910/fem-kubernetes-main/manifests/day-one/k8s/base/postgres-cluster.yaml]]`
- Purpose: CloudNativePG `Cluster` custom resource — 1 instance, 1Gi storage, initdb bootstrap with database `appdb` and owner `appuser`. The CNPG operator provisions Pods, PVCs, Services (`-rw`/`-ro`), and auto-generated credentials (`-app` Secret).
- Key exports: `Cluster/postgres` (apiVersion `postgresql.cnpg.io/v1`).
- Dependencies: CloudNativePG operator (installed separately).
- Learner-relevant: Teaches the operator pattern — CRDs, control loops, reconciliation. Demonstrates durable storage (PVC-backed) replacing ephemeral Postgres. The operator pattern is a defining Kubernetes concept.

### manifests/day-one/k8s/base/gateway.yaml

- Locator: `[[sources/kubernetes/20260910/fem-kubernetes-main/manifests/day-one/k8s/base/gateway.yaml]]`
- Purpose: Gateway API `Gateway` resource — listener on port 80, HTTP protocol, `gatewayClassName: nginx` (fulfilled by NGINX Gateway Fabric on kind, or patched to `alb` on EKS).
- Key exports: `Gateway/sample-app` in namespace `app`.
- Dependencies: A Gateway API controller (NGF on kind, AWS LBC on EKS).
- Learner-relevant: The "route is a contract, controller is environmental" theme. The same `Gateway` YAML runs on both kind and EKS — only `gatewayClassName` changes.

### manifests/day-one/k8s/base/httproute.yaml

- Locator: `[[sources/kubernetes/20260910/fem-kubernetes-main/manifests/day-one/k8s/base/httproute.yaml]]`
- Purpose: Gateway API `HTTPRoute` — routes `sample-app.local` hostname, path prefix `/`, to backend `sample-app:8080`. Attached to the `sample-app` Gateway via `parentRefs`.
- Key exports: `HTTPRoute/sample-app` in namespace `app`.
- Dependencies: `Gateway/sample-app`, `Service/sample-app`.
- Learner-relevant: The portable routing contract. On EKS the hostname is dropped (path-only through ALB) — the overlay handles this.

### manifests/day-one/k8s/base/kustomization.yaml
