# Kubernetes 是標準，不是地方

## Learning goal

<LearningGoal>
能說出為什麼 Kubernetes 是一個 API 標準而非特定基礎設施，並解釋同一份 manifest 如何跨環境部署。
</LearningGoal>

## Lesson

Kubernetes 是一個容器編排的 API 標準，不是某一台伺服器或某一個雲端平台。它定義了一套完整的規格——怎麼宣告 desired state、怎麼管理容器生命週期、怎麼做服務發現——這套規格跟「跑在哪裡」完全無關。同一份 Deployment manifest 可以用 `kubectl apply` 套用到筆電上的 Kind 集群、公司機房的 on-premise 集群、或 AWS EKS 的雲端集群，指令和操作流程完全一樣。這就是「定義留下，位置改變」——Kubernetes 把基礎設施的差異抽象掉了，讓多雲部署變成一件微不足道的事。
