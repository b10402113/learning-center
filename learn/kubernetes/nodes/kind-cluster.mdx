# 建立本地開發環境

## Learning goal

能用 Kind 建立多節點集群，理解 control-plane 和 worker 的差異

## Steps

1. [[learn/kubernetes/nodes/kind-cluster/local-vs-cloud|Kubernetes 是標準，不是地方]] — 理解為什麼同一份 manifest 能在筆電和雲端跑
2. [[learn/kubernetes/nodes/kind-cluster/getting-started-kind|用 Kind 建立第一個集群]] — 安裝、建集群、驗證 kube-system 核心元件（after step 1）
3. [[learn/kubernetes/nodes/kind-cluster/kind-multi-node-config|用 Config 建立多節點集群]] — 用 YAML config 建出 control-plane + worker 架構（after step 2）

## Lesson

Kubernetes 是一個 API 標準，不是某一台伺服器或某一個雲端平台。你在筆電上跑的 `kubectl apply`，和在 AWS EKS 上跑的，是同一個指令、同一份 manifest。Kind（Kubernetes in Docker）把這個概念落實：它在 Docker 容器裡跑一整個 Kubernetes 集群，讓你在本地就能擁有和雲端相同的操作體驗。先理解 K8s 的跨環境本質，再動手建集群，最後用 config 建出多節點架構——這就是你本地開發環境的起點。
