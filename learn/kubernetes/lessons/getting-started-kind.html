用 Kind 建立第一個集群

建立本地開發環境 · 第 2 步

學習目標

能用 Kind 建立一個預設的本地 Kubernetes 集群，並用 kubectl 驗證 kube-system 命名空間中的核心元件。

安裝 Kind

Kind 是一個用 Docker 容器來跑 Kubernetes 的工具。它的名字就是 Kubernetes in Docker 的縮寫。安裝方式取決於你的作業系統：

# macOS（用 Homebrew）
brew install kind

# Linux（用 curl）
curl -Lo ./kind https://kind.sigs.k8s.io/dl/latest/kind-linux-amd64
chmod +x ./kind
sudo mv ./kind /usr/local/bin/kind

# Windows（用 PowerShell）
curl.exe -Lo kind-windows-amd64.exe https://kind.sigs.k8s.io/dl/latest/kind-windows-amd64.exe
Move-Item kind-windows-amd64.exe kind.exe

安裝完成後，確認版本：

kind version

建立第一個集群

一行指令就能建立一個完整的 Kubernetes 集群：

kind create cluster --name my-cluster

這行指令做了什麼？它在 Docker 裡跑了一個容器，這個容器裡面跑著一整套 Kubernetes 控制平面（control plane）——包括 API server、etcd、controller manager、scheduler。整個過程大約需要 30 秒到 1 分鐘。

建立完成後，你的 kubectl 已經自動指向這個本地集群了。驗證一下：

kubectl cluster-info --context kind-my-cluster

探索 kube-system 命名空間

預設建立的集群不會在 default 命名空間跑任何東西。但如果你用 `--all-namespaces` 看，會發現一堆系統 Pod 在背後運作：

kubectl get pods --all-namespaces

你會看到類似這樣的輸出：

命名空間Pod 名稱前綴功能
kube-systemcoredns-DNS 服務，讓 Pod 可以用名稱互相找到
kube-systemetcd-叢集狀態的 key-value 儲存
kube-systemkindnet-Kind 的 CNI（容器網路介面），負責 Pod 網路
kube-systemkube-apiserver-Kubernetes API 入口，所有 kubectl 指令都經過它
kube-systemkube-controller-控制循環，負責 reconciliation
kube-systemkube-proxy-Service 網路的 iptables 規則管理
kube-systemkube-scheduler-決定 Pod 該跑在哪个節點上

這些就是 Kubernetes 的核心——你的應用程式以後就是跟這些元件互動。注意 default 命名空間是空的，因為你還沒有部署任何東西。

刪除集群

Kind 的一大優勢是集群可以隨建隨銷。當你不需要了：

kind delete cluster --name my-cluster

整個集群就消失了——所有 Pod、Service、Deployment 都沒了，Docker 容器也被移除。這讓你可以反覆練習建集群的流程，不用擔心留下殘留資源。
