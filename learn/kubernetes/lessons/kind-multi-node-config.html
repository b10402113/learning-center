用 Config 建立多節點集群

建立本地開發環境 · 第 3 步

學習目標

能撰寫 Kind cluster config 建立含 1 個 control-plane 和 2 個 worker 的多節點集群，理解節點角色的差異與 port mapping。

預設集群的限制

上一步建立的 `kind create cluster` 是一個預設的單節點集群——所有東西都跑在同一個 control-plane 節點上。這對學習已經夠用，但真實的 Kubernetes 集群幾乎都是多節點的：有專門的 control-plane 負責管理和決策，有 worker 節點負責跑你的應用程式。

要建立多節點集群，你需要一個 config 檔案。

撰寫 cluster config

建立一個名為 `kind-cluster.yaml` 的檔案：

# kind-cluster.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
    extraPortMappings:
      - containerPort: 30080
        hostPort: 30080
        protocol: TCP
  - role: worker
  - role: worker

這份 config 說了什麼？

  • kind: Cluster — 這是 Kind 的 cluster 資源類型
  • role: control-plane — 建立一個控制平面節點，跑 API server、etcd、scheduler 等
  • role: worker × 2 — 建立兩個 worker 節點，負責跑你的應用 Pod
  • extraPortMappings — 把容器的 30080 port 映射到主機，方便未來做 Ingress 測試

Control-plane vs Worker

Kubernetes 的節點分為兩種角色，這是理解集群架構的關鍵：

Control-planeWorker
跑什麼 API server、etcd、controller manager、scheduler kubelet、kube-proxy、你的應用 Pod
功能 管理集群狀態、做決策、接受指令 執行工作負載、跑容器
類比 公司的管理層和 IT 控制台 實際做事的員工
數量 通常 1 個或 3 個（奇數，為了 etcd 共識） 根據工作負載需求決定

在你的日常操作中，你會透過 kubectl 向 control-plane 下指令，但你的應用 Pod 實際跑在 worker 節點上。control-plane 決定 Pod 該跑在哪個 worker，worker 執行它。

建立多節點集群

# 先刪除之前的集群
kind delete cluster --name my-cluster

# 用 config 建立新集群
kind create cluster --config kind-cluster.yaml --name my-cluster

建立完成後，驗證所有節點都就緒：

kubectl get nodes

你應該看到三個節點，角色分別是 control-plane 和 worker：

NAME                            STATUS   ROLES           AGE   VERSION
my-cluster-control-plane        Ready    control-plane   30s   v1.xx.x
my-cluster-worker               Ready    <none>          25s   v1.xx.x
my-cluster-worker2              Ready    <none>          25s   v1.xx.x

注意 worker 節點的 ROLES 欄位是 ``，這是 Kind 的一個已知行為——它不會自動幫 worker 設定 label。這不影響功能，只是顯示上的差異。

Port mapping 的意義

config 中的 `extraPortMappings` 把容器內的 30080 port 映射到你的主機。為什麼要預先設定這個？

在 Kubernetes 中，NodePort Service 可以把你的服務暴露到 30000–32767 的範圍。選擇 30080 是為了將來建 Ingress 時，你可以在瀏覽器中用 `localhost:30080` 測試流量。這是本地開發的常見模式——先把 port 留好，後面再用。

如果你現在建立一個 NodePort Service 並指定 port 30080，就可以用 `http://localhost:30080` 從主機訪問你的服務。

驗證集群

確認系統 Pod 全部正常：

kubectl get pods -n kube-system

所有 Pod 都應該是 Running 或 Completed 狀態。如果看到 Pending 或 CrashLoopBackOff，等一下再檢查——有些 Pod 需要依賴其他 Pod 先啟動完成。
