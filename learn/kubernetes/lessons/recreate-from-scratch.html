從零重建集群

Kubernetes · Tier 1 · 第一個應用部署（POC）

學習目標

能刪除並重建整個集群與所有部署，建立 CLI 操作的肌肉記憶，理解 Kind 集群的建立與銷毀是低成本操作。

為什麼要從零重建？

你已經學會了跑 Pod 和建立 Deployment。現在要做一件聽起來很瘋狂的事：把整個集群砍掉，從零開始重建。

這不是在浪費時間。恰恰相反——這是建立肌肉記憶最有效的方式。Kubernetes 的 CLI 工作流有一個特點：你越是熟悉「建立→部署→刪除→重建」的循環，你在除錯時就越不容易慌。

而且，Kind 集群就是一個 Docker 容器。建立和銷毀的成本極低——幾秒鐘的事情。你不需要害怕「搞壞集群」，因為重建它比修復它快得多。

Kind 集群是 disposable（可丟棄的）——就像一個臨時的工作區，用完就丟，重建一個新的比清理舊的更乾淨。

第一步：刪除現有集群

刪除 Kind 集群只需要一行命令：

kind delete cluster

這會刪除集群中的所有資源：Pod、Deployment、Service、Namespace——一切歸零。你的本機上不會留下任何殘留。

確認集群已經不存在：

kubectl cluster-info

如果看到錯誤訊息，表示集群已經成功刪除。

第二步：重新建立集群

如果你之前用了自定義的 config 檔案來建立多節點集群，現在可以用同樣的檔案重建：

kind create cluster --config kind-config.yaml

如果只是要快速跑起來，用預設配置就好：

kind create cluster

等幾秒鐘，確認集群已經就緒：

kubectl get nodes

你會看到你的節點（如果是預設配置就是一個 control-plane 節點）狀態為 Ready。

第三步：重新部署應用

現在集群是全新的——什麼都沒有。你需要重新建立 Deployment：

kubectl create deployment nginx --image=nginx --port=80

確認它在跑了：

kubectl get pods
kubectl get deployments

整個過程從刪除到重建，通常不超過一分鐘。你已經擁有了一個全新的 Kubernetes 環境，裡面跑著你剛部署的應用。

肌肉記憶：完整的循環

把整個流程串起來，你剛完成了一個完整的循環：

步驟命令效果
1. 刪除集群kind delete cluster一切歸零
2. 建立集群kind create cluster全新環境
3. 部署應用kubectl create deployment ...Pod 在新集群裡跑起來
4. 確認狀態kubectl get podsPod 狀態為 Running

建議你多做幾次這個循環。每次重建，你對 CLI 的熟悉度就會增加一層。當你在後面遇到需要除錯的場景時，這種肌肉記憶會讓你更快找到問題。

POC 階段的反思

到目前為止，你已經完成了 POC（概念驗證）階段的核心操作。回顧一下你做過的事：

  • 用 kubectl run 跑了一個裸 Pod
  • 用 kubectl create deployment 建立了有自我修復能力的 Deployment
  • 刪除並重建了整個集群

這些都是「命令式」操作——你親手一條一條地輸入命令。這在 POC 和除錯時很方便，但不適合實際部署。實際部署需要「宣告式」操作：把所有設定寫在 YAML 檔案裡，用 kubectl apply 一次性套用。

這是下一個階段的起點：從命令式過渡到宣告式。但在此之前，先確保你對 CLI 工作流有足夠的信心——多做幾次從零重建的練習。

POC 階段的目的是「讓東西跑起來」，不是「讓東西穩定運行」。你做的一切在生產環境中都是不對的——但你現在知道什麼是不對的，才能理解為什麼需要改進。

小結

你現在能：

  • 刪除 Kind 集群（kind delete cluster）
  • 重建 Kind 集群（kind create cluster）
  • 在新集群中重新部署應用
  • 理解 Kind 集群的建立和銷毀是低成本操作
