什麼是 Reconciliation Loop？

Kubernetes 核心：Reconciliation Loop · Step 1/3

學習目標

用日常類比（定速巡航、烤箱恆溫）解釋 desired state → actual state → reconcile 的核心概念，能不看筆記向別人說明。

你每天都在用 Loop

開車上高速公路，你設定定速巡航（cruise control）在 100 km/h。車子的速度感知器持續量測實際速度，和你設定的期望速度做比較。遇到上坡，速度掉了 2 km/h，電腦偵測到差距，自動加大油門，把速度補回來。下坡時反過來，收油門。這個「量測 → 比較 → 調整」的過程，不會因為回到 100 km/h 就停止——它會永遠跑下去。

這就是Reconciliation Loop（協調循環）。

三個名字，一個概念

術語意思是什麼定速巡航的例子
Desired State
期望狀態		你聲明想要的狀態速度 = 100 km/h
Actual State
實際狀態		系統此刻的真實狀態當前車速 98 km/h
Reconcile
協調		偵測差距並採取行動，直到兩者一致加大油門，讓車速回到 100

循環跑完一輪，不會停下來。它持續檢查：期望和實際之間還有沒有差距？有就繼續調，沒有就待命——但隨時準備好下一次介入。

另一個例子：烤箱恆溫

你把烤箱溫度設定在 220°C（期望狀態）。烤箱內部的溫度計持續量測（實際狀態）。打開烤箱門放東西進去，溫度掉了 30°C，溫控器偵測到差距，啟動加熱元件，把溫度補回來。關上門後，溫度回升到 220°C，加熱器關閉。循環持續待命。

這個「恆溫器循環」是所有控制系統的原型——你家的冷暖氣、冰箱的壓縮機，都是同一個模式。

廚房裡的 Loop

想像一間餐廳的出餐流程：

  • 菜單（tickets on the rail）= 期望狀態，也就是你「宣告」想要出什麼菜
  • 主廚= Control Plane（控制平面），負責讀取菜單、分配任務
  • 各站厨师= Worker Nodes（工作節點），負責實際烹調
  • 每道菜= Container（容器），是最小的交付單位

主廚不斷巡視：這道菜好了沒？那道菜差什麼配料？某個站沒出菜——是缺人還是卡住了？他持續比對「菜單上要求的」和「出餐口實際有的」，然後調度資源把差距關閉。

這三種場景——車子、烤箱、廚房——說的都是同一件事：你聲明你想要什麼，系統持續檢查實際狀況，然後把兩者之間的差距關閉。

為什麼這很重要

這不是某個 Kubernetes 功能，這是整個 Kubernetes 的核心機制。不管你是管理容器、儲存空間、IP 位址、負載均衡器，底層都在跑同一個循環。你之後學到的所有 Kubernetes 概念——Pod 自動重啟、Deployment 滾動更新、Service 發現——全部建立在這個循環之上。

理解這一點，你就拿到了理解整個 Kubernetes 的鑰匙。
