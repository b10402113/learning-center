Loop vs 指令式工具

Kubernetes 核心：Reconciliation Loop · Step 3/3

學習目標

比較 loop-based 架構與 Ansible 等指令式工具在規模化上的差異，理解 Kubernetes 為什麼更容易除錯。

兩種思維：「去做」vs「讓它成為」

在認識 Kubernetes 之前，你可能用過 Ansible、SSH 腳本、或其他工具來管理伺服器。這些工具有一個共同模式：

  • 指令式（Imperative）：你一步一步告訴系統「做 A → 做 B → 做 C」。每一步是一個命令，跑完就結束了。

Kubernetes 走的是完全相反的路：

  • 宣告式（Declarative）：你聲明「我想要這個狀態」，系統自己想辦法達成，然後永遠維持這個狀態。

用一個比喻：指令式像是叫外送——你打電話說「我要一份炒飯、一碗酸辣湯」，店家照做一次就結束了。宣告式像是在自動販賣機前放了一枚硬幣——你聲明「我要這個」，機器自己出貨，然後持續待命等下一次需求。

Ansible vs Kubernetes：規模化的分水嶺

假設你要管理 100 台伺服器，確保上面都裝了 nginx：

Ansible（指令式）Kubernetes（Loop）
做法SSH 到每台機器，逐一執行安裝命令聲明「我想要 nginx 在跑」，每個節點自己協調
新機器加入要手動跑一次 playbook自動偵測、自動達成期望狀態
機器壞掉要手動偵測、手動修復loop 自動偵測，自動在其他地方補回來
規模到 1000 台Ansible 要逐一連線，效能瓶頸每個節點自我協調，無需中央逐一派送

Ansible 的問題不是它不好——它在小規模、一次性任務上非常方便。但當你管理的機器數量增加，逐一 SSH 連線的模式會遇到兩大瓶頸：

  1. 速度：Ansible 要逐一連線到每台機器執行命令，1000 台就是 1000 次 SSH
  2. 自我修復：Ansible 跑完 playbook 後就結束了——如果某台機器過了十分鐘又壞了，Ansible 不會自動再跑一次

Kubernetes 的 loop 解決了這兩個問題：每個節點自己檢查、自己調整，不需要中央逐一派送；loop 永不停止，任何偏離都會被持續偵測並修正。

可除錯性的來源

Kubernetes 雖然學起來很重，但學會之後非常好除錯。為什麼？因為所有的問題都可以用同一個框架拆解：

期望狀態是什麼？實際狀態是什麼？差距在哪？

舉個具體例子：你部署了一個 Deployment，聲明要 3 個 Pod，但 kubectl get pods 只看到 1 個。你可以立即回答：

  • 期望狀態：3 個 Pod（manifest 裡 replicas: 3）
  • 實際狀態：1 個 Pod（kubectl get 告訴你的）
  • 差距：少了 2 個 Pod
  • 下一步：kubectl describe 看看那 2 個 Pod 為什麼起不來——是映像拉不下來？端口衝突？資源不足？

    • 這種「聲明 → 觀察 → 差距分析」的思維，是你在 Kubernetes 裡除錯的核心武器。不管問題出在容器、網路、儲存、還是負載均衡，都可以用這個框架來拆解。

    Loop 的代價：你必須提供信號

    loop 會永遠重試——這既是優點也是陷阱。如果某個 Pod 一直起不來，loop 會一直重試、一直重試，但它不會主動通知你。

    這就像一個永遠不放棄的員工——他會一直嘗試修好問題，但如果你沒有設定告警（Slack 通知、Discord webhook、監控儀表板），你可能根本不知道他在那邊白忙。

    所以 Kubernetes 的最佳實踐是：loop 負責自動修復，你負責建立信號連線。把 Kubernetes 的事件和指標接上你的告警系統（例如 Prometheus + Alertmanager），這樣 loop 在白忙的時候你至少會收到通知。

    總結：Reconciliation Loop 三步走

    在這個節點裡，你學到了三件事：

    1. Reconciliation Loop 是什麼：「聲明期望 → 觀察實際 → 關閉差距」的永不停止的循環。定速巡航、烤箱恆溫、餐廳出餐都是它的日常原型。
    2. Kubernetes 如何套用它：每一種資源——容器、Volume、IP、Load Balancer——都有各自的 Controller 在跑同一個 loop。loop 是整個平台唯一一致的機制。
    3. Loop vs 指令式：loop 天然適合規模化（每個節點自我協調，無需中央逐一派送），也天然適合除錯（所有問題都可用「期望 vs 實際」框架拆解）。但 loop 不會主動通知你——你必須建立信號連線。

    這個心智模型會貫穿你之後學到的每一個 Kubernetes 概念。現在你知道了「為什麼」，接下來的節點會教你「怎麼做」。
