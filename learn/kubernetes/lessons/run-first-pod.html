用 kubectl run 部署第一個 Pod

Kubernetes · Tier 1 · 第一個應用部署（POC）

學習目標

能用 kubectl run 部署一個 Pod，理解 Pod 是 Kubernetes 最小的部署單位，以及裸 Pod 與受控 Pod 的差異。

Pod 是什麼？

在 Kubernetes 的世界裡，Pod 是你能部署的最小單位。一個 Pod 代表集群中一個正在運行的進程——它是一個或多個容器的包裝。大多數時候，一個 Pod 裡面只有一個容器。

你可以把 Pod 想像成一個「膠囊」：裡面裝著你的應用容器、網路位址、儲存資源的設定。Kubernetes 不會直接管理容器，它管理的是 Pod。你跟 Kubernetes 說「我要跑一個 Nginx」，Kubernetes 創建的不是一個容器，而是一個包裝了 Nginx 容器的 Pod。

Pod 是 Kubernetes 調度的原子單位。Kubernetes 的调度器（scheduler）決定的不是「哪個容器跑在哪個節點」，而是「哪個 Pod 跑在哪個節點」。

用 kubectl run 跑第一個 Pod

最命令式（imperative）的方式是用 kubectl run。打開你的終端，確認你已經有一個運行中的 Kind 集群，然後輸入：

kubectl run nginx --image=nginx --port=80

這條命令做了什麼？

部分意義
kubectl run告訴 Kubernetes 創建一個 Pod
nginxPod 的名稱
--image=nginx使用官方 Nginx Docker 映像
--port=80聲明這個 Pod 監聽 80 端口

執行後，Kubernetes 會在集群裡創建一個 Pod。用以下命令確認：

kubectl get pods

你會看到類似這樣的輸出：

NAME    READY   STATUS    RESTARTS   AGE
nginx   1/1     Running   0          10s

READY 1/1 表示 Pod 裡的一個容器已經準備好。如果看到 0/1，表示容器還在啟動中。

Pod 背後的 Secret：kubectl 幫你寫了 YAML

雖然你只輸入了一行命令，但 Kubernetes 其實在背後生成了一個 YAML manifest（宣告式配置檔）。你可以用這個命令看到它：

kubectl get pod nginx -o yaml

你會看到一大段 YAML，描述了 Pod 的所有設定：使用什麼映像、端口、環境變數、節點選擇器等等。這很重要——命令式操作背後永遠是宣告式狀態。每一條 kubectl 命令都在生成一個 manifest，只是你選擇了不親手寫它。

這個認知會在後面的章節反覆出現：當你開始用 YAML 寫 manifest 時，你只是把背後發生的事情直接寫出來。

裸 Pod 的致命缺陷

你剛才跑的 kubectl run nginx 創建的是一個裸 Pod（bare pod）——沒有任何控制器（controller）管理它。這是 POC 階段的典型做法，但有嚴重的問題：

kubectl delete pod nginx

執行這條命令後，Pod 就消失了。不會有任何東西把它帶回來。因為沒有控制器在監督這個 Pod，Kubernetes 不知道「我應該保持有一個 Nginx 在跑」。它只知道你要求刪除，於是就刪了。

對比一下：

特性裸 Pod受控制器管理的 Pod
生命週期管理手動自動（控制器負責）
刪除後會重建？不會會（幾毫秒內）
適合生產環境？不適合適合
用途除錯、快速測試實際部署
裸 Pod 是你 Kubernetes 旅程的第一步，但請記住它只適合除錯。真正的應用永遠需要一個控制器來管理。

Namespace：組織單位，不是安全邊界

你可能注意到 kubectl run 預設會把 Pod 放在 default namespace（命名空間）裡。Namespace 是 Kubernetes 的組織單位，讓你可以把不同的資源分組管理：

kubectl get pods --all-namespaces

你會看到除了你的 default namespace，還有 kube-system 等系統 namespace——裡面跑著 CoreDNS、etcd、API server 等核心組件。

但要小心一個常見誤解：Namespace 預設不提供安全或網路隔離。不同 namespace 裡的 Pod 理論上可以互相通訊。真正的隔離需要 NetworkPolicy 和 RBAC（角色權限控制），這些是後面才會接觸到的主題。

小結

你已經完成了一件重要的事：在 Kubernetes 集群裡跑起了第一個 Pod。你現在知道：

  • Pod 是 Kubernetes 最小的部署單位
  • kubectl run 創建的是裸 Pod——適合除錯，不適合生產
  • 命令式操作背後永遠是宣告式 manifest
  • 裸 Pod 被刪除後不會自動重建
  • Namespace 是組織單位，不是安全邊界
