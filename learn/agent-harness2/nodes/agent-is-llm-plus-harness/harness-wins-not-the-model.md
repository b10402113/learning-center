# 模型不是差異來源，harness 才是

上一篇文章以一個問題作結：如果差異在於 harness，那麼 harness 是由什麼組成的？Scott Moss 用一個你可能用過的例子來回答：Claude Code。

## 先把模型拿掉

Claude Code 使用 Anthropic 的模型。Moss 從這裡談起。他說，先不考慮選用哪個 LLM，剩下的就是 harness。

你可以用這個方法檢視任何 agent 產品：找出它使用哪個模型，先把模型因素排除，再看看介面和程式碼裡還剩下什麼。

把模型拿掉，剩下的就是 harness。

<!--image:1-->

## Claude Code 裡還剩下什麼

Moss 一項一項列出其中的組成部分。

第一部分是你正在使用的終端機 UI。第二部分是支援 skills 的實作，以及透過 @ 提及檔案的使用體驗。第三部分是自動壓縮：當對話歷史過長時，harness 會將其壓縮。第四部分是 sub-agents：harness 可以自行啟動它們，無須你下達指令。

這四個部分都不在模型裡。每一項都是人們對產品運作方式所做的設計決定。

## 讓 agent 正常運作、不出錯並持續執行所需的一切

Moss 用一句話概括這份清單：harness 包含 agent 要能正常運作、不出錯並持續執行所需的一切。

這項工作涵蓋的範圍比聽起來更廣。終端機 UI、skills、壓縮和 sub-agents 看起來彼此無關，但目的相同：讓工作階段得以持續，並維持可用。

## 同一個模型，不同的 harness

Claude Code 不是唯一的例子。Moss 還列出 Open Code、OpenClaw、Hermes 和 Pi。它們都是 harness。

他用來描述這些產品的說法很重要：它們是建構在相同模型之上的 harness 實作。底層模型可以相同，上層的 harness 卻各不相同。

## 為什麼更好的 harness 會勝出

接下來，論點開始轉向。Moss 說，至少對他來說，模型其實沒那麼重要。每當有新的 LLM 推出，他的反應都是：「好吧，沒差。」

他的理由很簡單：誰做出最好的 harness，誰就會勝出。他不是把這當成預測，而是說自己已經親眼看過這種情況發生。

我看過使用較差模型的 harness，做出比使用較好模型的 harness 更好的成果。

<!--image:3-->

## 現在的模型都很好

他論點的另一半談的是模型本身。他說，現在所有模型都很不錯，就連開源模型也非常好。

如果各家模型都已經夠好，模型就不再是各家實驗室拉開差距的關鍵。真正帶來效率和效能提升的是 harness。這也就是為什麼他說，新模型推出並不會改變他的答案。

他也從職涯選擇的角度表達同樣的看法。他認為，現在 AI 領域最重要的兩件事是 harness engineering 和 evals；依他的估計，兩者占了工作內容的 90%。如果他加入一家開發 AI 產品的公司，就會全力投入其中一個領域。

## 留下的問題

現在我們知道 harness 可以由哪些部分組成，也知道更好的 harness 能勝過更好的模型。這回答了 harness 是由什麼組成的。

但更難的問題還沒有答案：為什麼一個 demo 在 notebook 裡能正常運作，到了正式環境卻可能失敗？下一篇文章會透過兩個案例——deep research 任務和交易 agent——說明 durable execution、guardrails 和 approval 何時不再是可有可無的選項。
