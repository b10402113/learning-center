# 為什麼不停在聊天視窗

你把點子丟給 Claude，叫了 hook 跟 tone skill。幾秒後，一份為 Instagram 或 TikTok 調整過的腳本回來。讀一遍，還真的能用。你複製、關掉分頁，往下一個點子去。

問題在兩週後才出現。那支腳本在哪個對話裡？上一個版本跟這個版本差在哪？當時如果留了一句「這裡短一點」，那句話現在還在嗎？

## 大部分腳本會消失

腳本全留在聊天視窗裡，最常見的結局不是被刪掉，而是慢慢找不到。對話一直往上長。新的對話一直開。舊的那串就沉下去。

這不是模型寫得差。問題是沒有地方放。你要比較兩份腳本，得開兩個分頁往上滑。你要回頭改一句話，得先找到它。你想知道上個月那個 hook 為什麼有效，只能靠記憶。

## 把內容集中到一個地方

Rubric 是 RoboNuggets 社群自己開發、自己維護的一整套客製化軟體與系統。裡面每個工具，包括 Rubric Scripts，都設計成 agent-ready，可以跟 AI agent 一起用，而不是只能自己手動點。

Rubric Scripts 做的第一件事很單純：把你所有的內容集中到一個地方。

它是一套瀏覽器端軟體，在你自己的機器上跑。你餵給 agent 的點子，會在那裡變成一張張可讀的腳本，左邊是點子、右邊是成品，不用在對話串裡撈。

集中之後，腳本才開始有「地址」。你能比較版本、能搜尋、能依最後編輯時間或閱讀時間排序，也能切換卡片式或清單式。這些在聊天視窗裡都做不到。

## 這是一個會自己變強的迴圈

集中管理只是第一層好處。第二層更有價值：你留在腳本上的意見，可以回頭改你的 skill。

Rubric Scripts 預設會去找你的 hooks 跟 tone skill。如果你還沒建，它會教你怎麼建。所以你可以只用一個指令，就拿到一份像你說話的腳本。

關鍵是：tone of voice skill 愈改愈好，Rubric Scripts 也會跟著變強。

這個迴圈的形狀是：產出腳本、你審、留下意見、skill 更新、下一批腳本更貼近你。你留在句子旁邊的每一句「這裡短一點」，都不會是一次性的修稿，而是變成下一批腳本的規則。再往下一層，連介面本身都能改：hook 要幾個、caption 要多長、哪個視窗不需要，都可以直接叫 agent 動。

這才是「作業系統」跟「一個好用的工具」的差別：工具幫你做一次，系統會記住你怎麼做，下一次已經站在你的位置上。

至於安裝、載入 shortlist、留評論的實際操作，下一步會一步一步走。

## 今天可以做的動作

打開你的點子清單，挑三個這一週真的要產出的，用 `slash rubric scripts` 一次載進去。讀完三份，至少留一句意見。然後打開 teach my slash tone，按 copy comments for all scripts，送出。

你要發出的不是三份被稱讚的腳本。是三份兩週後還找得到、而且下一批會更好的腳本。
