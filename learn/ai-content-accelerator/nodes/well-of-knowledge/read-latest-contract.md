# Universal rules：/latest 的九條規則

你按了 `/latest`。瀏覽器開出一個頁面，十張卡片排在那裡。每張都有工作標題、angle、why、平台，還有一個可以點開的連結。看起來像一份選單。

然後你開始拍。拍到第三張你停下來，因為有幾張根本不能拍。有一張是某家公司說自己要推出新功能。有一張是兩年前的舊功能，這禮拜被人重新貼了一次。有一張的連結點進去是一篇別人的推測。

這三張都通過了「有標題、有連結、有數字」的檢查，但它們都不是點子。九條 universal rules 就是拿來擋這類東西的。它們不問你喜不喜歡那個主題，只問這個 item 有沒有資格被叫做點子。

## 先看合格的點子長什麼樣

一個 idea 的形狀很固定：

- 一個工作標題，100 個字元以內。
- 一個 angle，280 個字元以內，寫你會說什麼、會秀什麼。
- 一個 why，160 個字元以內，寫為什麼現在重要。
- 一個平台和作者。
- 一個真的能點開的連結。

這些長度不是排版偏好。卡片會被重複使用，也會被貼進表格，太長的字會被切掉。

寫頁面的腳本對格式分兩級處理。缺標題、或連結不是 `http(s)`，它直接停下，一個字都不寫。標題太長、沒有 angle、沒有 why，它只印 warning，頁面照樣產出。也就是說，一份「過得了腳本」的結果，離「可以拍」還很遠。

## 這幾種內容不算點子

<!--image:2-->

第一種是公司自己的發布公告。沒有人能 copy 一份公告。公告是「我們做了什麼」，不是「你能做什麼」。看到公告，正確的做法是把它留著當來源，把點子改成對這個東西的動手測試或 build。

第二種是「在窗口內被貼出，但不是在窗口內才出現的」。舊功能被當成 breaking news 再宣布一次，這種事一直在發生。貼文的日期落在這七天裡，不代表東西本身是新的。叫它 news 之前，先去查它自己的 release date。

第三種是沒有被證實的說法。洩漏的 benchmark、別人的收入故事，經常是錯的。這種東西不能變成你會複述的事實，只能變成你自己可以跑的測試。你要講的是「我測了，結果是這樣」，不是「據說它很強」。

第四種是找不到出處的連結。一個發明的連結，是使用者唯一看不出來的錯誤。可用的連結池只有三個。第一個是這次存的 raw file，它才是完整清單，引擎印在畫面上的只有前幾個 cluster。第二個是這次網頁搜尋的結果。第三個是你在跑的過程中打開的來源頁。來源頁上的連結，要頁面真的有顯示才算，否則就連那個頁面本身。

<!--image:3-->

還有一種不是點子的東西：一個主題。「AI agent 的未來」不是點子，因為它沒辦法被查核。一個主題不能查，一個連結可以。所以每個 idea 只能錨在一個真實 item 上。

同樣地，一個沒有東西可秀的 angle，也不算點子。angle 要同時說出你會講什麼、你會讓觀眾看到什麼。只有論點、沒有畫面的，是文章大綱，不是短片。

## 被直接跳過的三類 item

把 raw file 整份讀完之後，有三類東西不用進候選名單：

- 偏離 niche 的。不管它來自哪個來源，都跳過。GitHub 和 Hacker News 對非技術的 niche 常常回傳很接近、但不相關的東西。
- 八卦和 drama。它燒得快，但不會讓觀眾多會一件事。
- 規則已經擋掉的。公告、舊瓶新裝、無法查核的說法，直接出局。

## 九條規則其實分三組

第 1 到第 4 條管的是「怎麼跑」。窗口預設是七天，使用者講了就以他講的為準；研究引擎照它原本的寫法跑，不改、不即興；使用者自己的 well of knowledge 要併進來，那是新聞還沒變成影片之前先落地的地方；引擎自己那份報告不要印，這裡的輸出是點子清單。

第 5 到第 8 條管的是「這個 item 算不算」。連結要真實，公告要改成動手做，舊東西要查發布日，未證實的說法要降級成 claim。

第 9 條管的是排序。有 taste file 就先讀。fit 會讓一個點子往前排，也會把 angle 拉向使用者喜歡的形式。它不會擠掉這週最大的真新聞，也不會無中生有生一個 item。

## 拿你上一次的輸出來檢查

打開上一次跑出來的頁面，挑一張你最想拍的卡片，問三個問題。這是別人的發布公告嗎？這是早就存在的東西嗎？這是一個沒有人驗證過的說法嗎？

任何一題答「是」，就改寫它。把「他們推出了 X」改成「我用 X 做了 Y」，把「據說 X 很快」改成「我測 X，跑了三個情境」。原本的連結留著，放進來源，不要丟掉。

改完之後，那張卡片才有資格進到你的拍攝清單。這一步花不到十分鐘，但它決定你這個禮拜拍的是點子，還是別人的新聞稿。
