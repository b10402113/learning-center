# Digest — aws-v3

## Overview (L1)

- CloudFront caching and invalidation — Cache invalidation is one of the hard problems in distributed systems. This section covers how CloudFront caching works via TTL (Time To Live), how invalidation removes cached content from edge locations globally, the cost of invalidations, and behavior settings that control cache control headers.

## Sections (L2)

### Cache invalidation

- Locator: `[[sources/aws-v3/cloudfront-caching#cache-invalidation]]`
- Summary: Explains what cache invalidation is — forcing CloudFront to discard cached content at edge locations so fresh content is fetched from the origin.
- Key claims: Invalidation removes cached objects from edge locations; invalidation requests propagate globally across all edge locations; stale content is replaced on next request.
- Learner-relevant: Critical for deployments — without invalidation, users see old versions of cached files.

### TTL

- Locator: `[[sources/aws-v3/cloudfront-caching#ttl]]`
- Summary: Covers Time To Live settings — how long CloudFront caches an object before checking the origin for a newer version.
- Key claims: TTL determines cache duration at edge locations; default TTL is set by CloudFront behavior settings; origin headers can override TTL per response.
- Learner-relevant: Understanding TTL helps balance freshness vs performance — shorter TTL means more origin hits, longer TTL means faster responses.

### Invalidation costs

- Locator: `[[sources/aws-v3/cloudfront-caching#invalidation-costs]]`
- Summary: AWS charges per invalidation request, so invalidating too frequently or too broadly has cost implications.
- Key claims: AWS charges per invalidation path; the first 1,000 invalidations per month are free; wildcard invalidations count as multiple requests.
- Learner-relevant: Cost awareness prevents surprise bills — design deployments to minimize unnecessary invalidations.

### Behavior settings

- Locator: `[[sources/aws-v3/cloudfront-caching#behavior-settings]]`
- Summary: Covers CloudFront behavior settings that control cache control — TTL defaults, allowed HTTP methods, and forwarded headers/cookies.
- Key claims: Behavior settings are configured per path pattern; cache control headers from the origin override behavior TTL; forwarded headers/cookies increase cache key variety and reduce hit rates.
- Learner-relevant: Behavior settings are the tuning knobs for caching — understanding them lets you optimize for different content types (static assets vs dynamic pages).
