# Digest — 05

## Overview (L1)

- IAM concept — Identity and Access Management answers two questions: who are you (authentication) and what can you do (authorization).
- Least privilege — Give every user or service the minimum permissions they need. A CI/CD bot only needs to put files in one bucket, not full admin access.
- AI coding assistants — They can be creative with permissions; limiting their blast radius with tight IAM policies is essential.
- Policies — JSON documents that define exactly what actions are allowed or denied on which resources.

## Sections (L2)

### iam-concept

- Locator: `[[sources/aws-v3/05#iam-concept]]`
- Summary: IAM is the AWS service that controls identity (authentication) and permissions (authorization) across all other AWS services.
- Key claims: IAM covers both authentication and authorization; it is the central access control layer for AWS.
- Learner-relevant: Every AWS interaction passes through IAM — understanding it early prevents security headaches later.

### least-privilege

- Locator: `[[sources/aws-v3/05#least-privilege]]`
- Summary: The principle of least privilege means granting only the minimum permissions required for a task. Example: a CI/CD deployment bot needs `s3:PutObject` on one bucket, not `AdministratorAccess`.
- Key claims: Least privilege minimizes damage from compromised credentials; CI/CD bots are a common example of narrow-permission entities.
- Learner-relevant: Gives the learner a concrete mental model for scoping permissions — especially relevant when setting up deployment pipelines.

### ai-coding-assistants

- Locator: `[[sources/aws-v3/05#ai-coding-assistants]]`
- Summary: AI coding tools (Copilot, Cursor, etc.) can generate IAM policies or SDK calls that are overly permissive. Restrict their access to limit potential blast radius.
- Key claims: AI assistants can be "creative" with permissions; blast radius reduction is a security strategy.
- Learner-relevant: Directly relevant to the target audience — developers using AI tools need to be aware of the security implications.

### policies

- Locator: `[[sources/aws-v3/05#policies]]`
- Summary: IAM policies are JSON documents structured around Effect (Allow/Deny), Action (the API call), and Resource (the target). They can be attached to users, groups, or roles.
- Key claims: Policies are JSON; they have Effect, Action, and Resource fields; they attach to principals (users, groups, roles).
- Learner-relevant: Reading and writing IAM policies is a core skill — the learner will encounter them whenever they restrict or grant access.
