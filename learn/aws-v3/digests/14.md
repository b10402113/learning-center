# Digest — aws-v3

## Overview (L1)

- CloudFront settings and custom domains — Walks through creating a CloudFront distribution with an S3 origin, setting up custom domain names via alternate domain names (CNAMEs), configuring SSL/TLS certificates for HTTPS, and notes that everything achievable in the console is also scriptable via CLI or infrastructure-as-code.

## Sections (L2)

### Distribution creation

- Locator: `[[sources/aws-v3/cloudfront-settings#distribution-creation]]`
- Summary: Covers the steps to create a CloudFront distribution, including pointing the origin settings to an S3 bucket.
- Key claims: A CloudFront distribution requires an origin (typically an S3 bucket); origin settings configure how CloudFront fetches content from S3; distribution creation is the entry point for all CloudFront features.
- Learner-relevant: Hands-on step for getting a static site onto CloudFront — the first deployment milestone.

### Custom domains

- Locator: `[[sources/aws-v3/cloudfront-settings#custom-domains]]`
- Summary: Explains how to use alternate domain names (CNAMEs) to map a custom domain to a CloudFront distribution instead of using the default `*.cloudfront.net` domain.
- Key claims: Alternate domain names (CNAMEs) let you use your own domain; CloudFront's default domain works without configuration; custom domains require DNS configuration.
- Learner-relevant: Makes deployments production-ready by serving content under a real domain name.

### SSL/TLS

- Locator: `[[sources/aws-v3/cloudfront-settings#ssl-tls]]`
- Summary: Covers SSL/TLS certificate setup for HTTPS, including ACM (AWS Certificate Manager) integration for custom domains.
- Key claims: HTTPS requires an SSL/TLS certificate; ACM provides free certificates for use with CloudFront; certificates must be in us-east-1 for CloudFront.
- Learner-relevant: HTTPS is a production requirement — this section covers the certificate plumbing.

### Console vs CLI

- Locator: `[[sources/aws-v3/cloudfront-settings#console-vs-cli]]`
- Summary: Notes that every console operation has a CLI or script equivalent, and the console is used primarily for demonstration.
- Key claims: Console operations are scriptable; CLI and infrastructure-as-code enable repeatable deployments; console is convenient for learning but not for production workflows.
- Learner-relevant: Encourages thinking in terms of automation from the start rather than relying on manual console clicks.
