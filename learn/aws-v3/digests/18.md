# Digest — aws-v3

## Overview (L1)

- Course wrap-up and future topics — The course goal has been achieved: a programmable CDN for web app deployment. AWS offers much more beyond S3 and CloudFront — databases like Aurora (SQL) and DynamoDB (NoSQL), Lambda@Edge for edge computing, and Lambda functions that can read from Redis, databases, check banned users, and rewrite URLs. Environment variables provide configuration without code changes. This section seeds future exploration.

## Sections (L2)

### Goal achieved

- Locator: `[[sources/aws-v3/course-wrapup#goal-achieved]]`
- Summary: Reflects on what has been built — a programmable CDN using S3 and CloudFront that serves a web application globally.
- Key claims: The deployment pipeline (S3 + CloudFront) is now functional; the CDN is programmable via behavior settings, invalidation, and error-page configuration; the learner has a working production-grade static site deployment.
- Learner-relevant: Marks a milestone — the learner can now deploy and serve web applications globally on AWS infrastructure.

### Future topics

- Locator: `[[sources/aws-v3/course-wrapup#future-topics]]`
- Summary: Introduces what comes next in the AWS ecosystem — databases (Aurora for relational, DynamoDB for NoSQL) and Lambda@Edge for edge computing.
- Key claims: Aurora is AWS's SQL database offering; DynamoDB is the NoSQL option; Lambda@Edge extends compute to edge locations; these are natural next steps after mastering static hosting.
- Learner-relevant: Provides a roadmap for continuing AWS learning beyond static site deployment.

### Lambda capabilities

- Locator: `[[sources/aws-v3/course-wrapup#lambda-capabilities]]`
- Summary: Describes what Lambda functions can do at the edge — read from Redis or databases, check banned users, rewrite URLs, and perform arbitrary computation.
- Key claims: Lambda functions can connect to Redis and databases at the edge; they can implement authentication checks (e.g., banned user lists); URL rewriting enables dynamic routing; Lambda@Edge brings serverless compute to CDN edge locations.
- Learner-relevant: Shows the power ceiling of CloudFront + Lambda@Edge — from static hosting to dynamic, programmable edge computing.

### Configuration

- Locator: `[[sources/aws-v3/course-wrapup#configuration]]`
- Summary: Covers environment variables as the mechanism for configuring Lambda functions without hardcoding values in function code.
- Key claims: Environment variables let you change Lambda behavior without redeployment; they are set in the AWS console or via CLI; sensitive values (API keys, database URLs) should be stored as environment variables, not in code.
- Learner-relevant: A practical pattern for keeping Lambda functions configurable and secure across environments.
