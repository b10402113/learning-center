# Digest — 01

## Overview (L1)

- Introduction — Why front-end developers need AWS: static files (HTML, JS, CSS) are just text that must live on the internet. The journey from FTP-ing files to a server toward putting them in an S3 bucket.
- The physics problem — Distance creates latency; a server in Chicago is slow from Mumbai. Content must be distributed globally, which introduces the CDN concept.
- Workshop format — The course uses browser + CLI hands-on exercises throughout.

## Sections (L2)

### introduction

- Locator: `[[sources/aws-v3/01#introduction]]`
- Summary: Steve Kinney explains that front-end developers build static files which ultimately need to be placed on the internet. Historically this meant FTP-ing files to a server; the modern approach is S3 buckets.
- Key claims: Static files are text files that go on the internet; FTP to servers was the old way; S3 buckets are the modern approach.
- Learner-relevant: Connects existing front-end skills (HTML/JS/CSS) to AWS deployment — the learner already has what it takes, they just need the hosting layer.

### the-physics-problem

- Locator: `[[sources/aws-v3/01#the-physics-problem]]`
- Summary: Physical distance introduces latency. A server in one city is slow for users far away, so content needs global distribution — introducing the CDN concept.
- Key claims: Distance matters for performance; global distribution solves latency; CDNs are the mechanism.
- Learner-relevant: Motivates why AWS isn't just "a server in the cloud" but a global infrastructure — the learner needs to understand the why before the what.

### workshop-format

- Locator: `[[sources/aws-v3/01#workshop-format]]`
- Summary: The course follows a hands-on workshop format using both the AWS browser console and the CLI.
- Key claims: Browser and CLI are both used; the course is hands-on throughout.
- Learner-relevant: Sets expectations — the learner should have a terminal and a browser ready.
