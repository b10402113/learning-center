# Digest — 03

## Overview (L1)

- User groups — Create a group to share permissions across users. Groups simplify management — adding a co-founder or teammate means just adding them to the group.
- AdministratorAccess policy — Attach this managed policy to the group to grant nearly full access. The root user can always revoke it, so safety is preserved.
- The daily driver — Use the IAM admin user for all future work in the course. Never log in as root again after this.

## Sections (L2)

### user-groups

- Locator: `[[sources/aws-v3/03#user-groups]]`
- Summary: Create a user group in IAM. Groups let you assign the same set of permissions to multiple users without duplicating policy attachments.
- Key claims: Groups share permissions across users; adding new members is straightforward.
- Learner-relevant: Foundational IAM concept — groups are the primary way to manage team access.

### administratoraccess-policy

- Locator: `[[sources/aws-v3/03#administratoraccess-policy]]`
- Summary: Attach the AWS-managed `AdministratorAccess` policy to the group. This grants almost every permission, but the root user retains the ability to revoke it.
- Key claims: `AdministratorAccess` is "almost all keys to the castle"; root can always revoke policies.
- Learner-relevant: Gives the learner enough power to follow along with any service in the course while keeping a safety net.

### the-daily-driver

- Locator: `[[sources/aws-v3/03#the-daily-driver]]`
- Summary: Create an admin user in the group, log in as that user, and use it for the rest of the course. Stop using the root user for daily work.
- Key claims: The IAM admin user should replace root for day-to-day use.
- Learner-relevant: Establishes the security habit that carries forward — root is for account-level emergencies only.
