# Digest — 12

## Overview (L1)

- S3 hosting limitations — S3 static website hosting works for getting started but has hard limits: no HTTPS on custom domains, no cache control headers, no edge-location distribution.
- Transition to CloudFront — Production deployments need a CDN for HTTPS, caching, and global edge distribution. CloudFront is the AWS service that fills this gap.
- Disabling S3 website hosting — Before setting up CloudFront, the S3 static website hosting feature is disabled to avoid conflicts.

## Sections (L2)

### s3-hosting-limitations

- Locator: `[[sources/aws-v3/12#s3-hosting-limitations]]`
- Summary: S3's static website hosting does not support HTTPS on custom domains, does not let you set cache-control headers, and serves content from a single region with no edge distribution. These are hard limitations, not configuration options.
- Key claims: S3 website endpoints are HTTP-only on custom domains; no cache-control means browsers re-fetch every time; single-region serving reintroduces the latency problem CDNs solve.
- Learner-relevant: Explains why the learner's "it works" deployment from step 9 is not production-ready — the learner understands the gap before filling it.

### transition-to-cloudfront

- Locator: `[[sources/aws-v3/12#transition-to-cloudfront]]`
- Summary: CloudFront provides HTTPS, cache-control, and global edge distribution — solving all three S3 limitations. It sits in front of S3 as a CDN layer.
- Key claims: CloudFront enables HTTPS on custom domains; cache-control headers are configurable at the distribution level; edge locations serve content from the nearest point to the user.
- Learner-relevant: Motivates the next phase of the course — the learner sees that CloudFront is not an optional add-on but the necessary next step for a real deployment.

### disabling-s3-website-hosting

- Locator: `[[sources/aws-v3/12#disabling-s3-website-hosting]]`
- Summary: When transitioning to CloudFront, the S3 static website hosting feature should be disabled to prevent conflicting access patterns. CloudFront uses the S3 REST API endpoint, not the website endpoint.
- Key claims: S3 website hosting and CloudFront use different access methods; enabling both can cause confusion; disabling S3 hosting is a prerequisite for a clean CloudFront setup.
- Learner-relevant: A practical cleanup step — the learner disables the feature they just learned about, understanding why it served as a stepping stone but is no longer the right tool.
