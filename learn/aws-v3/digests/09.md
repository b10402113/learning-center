# Digest — 09

## Overview (L1)

- Public access — The S3 bucket must have public access enabled and a bucket policy granting public read permissions for the website to be reachable.
- Static website hosting — S3 has a built-in static website hosting feature, enabled in bucket properties, that provides a dedicated hosting URL.
- Initial deployment — After uploading assets and enabling hosting, the app loads at the S3 website endpoint.

## Sections (L2)

### public-access

- Locator: `[[sources/aws-v3/09#public-access]]`
- Summary: S3 buckets are private by default. To serve a public website, the learner must disable the public access block and attach a bucket policy that allows public reads (s3:GetObject).
- Key claims: Buckets block all public access by default; a separate bucket policy is required to grant public read access to objects.
- Learner-relevant: This is the most common stumbling point — the learner uploads files but gets 403 errors because public access was not explicitly enabled and policy-granted.

### static-website-hosting

- Locator: `[[sources/aws-v3/09#static-website-hosting]]`
- Summary: S3's static website hosting feature is enabled in the bucket's Properties tab. It produces a website endpoint URL (http://bucket-name.s3-website-region.amazonaws.com).
- Key claims: Static website hosting is a property toggle on the bucket; the resulting URL uses a specific format; this is separate from the regular S3 object URL.
- Learner-relevant: The learner needs to distinguish between the S3 object URL and the website endpoint URL — only the latter serves index.html as the default document.

### initial-deployment

- Locator: `[[sources/aws-v3/09#initial-deployment]]`
- Summary: After uploading the build output and configuring hosting, the learner opens the website URL and verifies the React app loads correctly in the browser.
- Key claims: Uploading assets and enabling hosting is sufficient for a basic deployment; the app is now live on the internet.
- Learner-relevant: The first "it works" moment — the learner sees their local React app running on a real AWS URL, validating the entire workflow so far.
