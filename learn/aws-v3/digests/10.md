# Digest — 10

## Overview (L1)

- Bucket policies — S3 bucket policies are JSON documents that control who can access the bucket and what actions they can perform. The principle of least privilege applies: grant only what is needed.
- Policy structure — A policy has four core fields: Effect (Allow/Deny), Principal (who), Action (what), and Resource (which bucket/object).
- ARNs — Amazon Resource Names uniquely identify AWS resources. Bucket ARNs and object ARNs appear in policy documents to scope permissions precisely.

## Sections (L2)

### bucket-policies

- Locator: `[[sources/aws-v3/10#bucket-policies]]`
- Summary: Instead of granting full S3 access, bucket policies should restrict permissions to the specific bucket and specific actions (e.g., only s3:GetObject and s3:PutObject). This follows the principle of least privilege.
- Key claims: Full access is overly permissive; policies should target specific buckets and specific actions; least privilege reduces blast radius if credentials leak.
- Learner-relevant: The learner replaces the overly broad public access policy from the previous step with a tighter, least-privilege policy — understanding why is more important than copying the JSON.

### policy-structure

- Locator: `[[sources/aws-v3/10#policy-structure]]`
- Summary: Every S3 policy document has four essential fields: Effect (Allow or Deny), Principal (the AWS user, role, or account), Action (the S3 operation), and Resource (the bucket or object ARN).
- Key claims: Effect is Allow or Deny; Principal specifies who the policy applies to; Action maps to specific S3 API operations; Resource uses ARNs to target specific resources.
- Learner-relevant: Reading and writing IAM policies is a core AWS skill — this section breaks down the JSON structure so the learner can reason about policies rather than copy-pasting blindly.

### arns

- Locator: `[[sources/aws-v3/10#arns]]`
- Summary: Amazon Resource Names (ARNs) follow the format arn:aws:s3:::bucket-name and arn:aws:s3:::bucket-name/* to identify buckets and all objects within them.
- Key claims: ARNs uniquely identify every AWS resource; bucket ARN targets the bucket itself; bucket-name/* targets all objects inside the bucket.
- Learner-relevant: ARNs appear in every policy the learner will write — understanding the format lets them construct policies for any bucket without looking up documentation each time.
