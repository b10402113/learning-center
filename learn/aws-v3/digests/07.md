# Digest — 07

## Overview (L1)

- S3 basics — Simple Storage Service is one of the oldest and most widely used AWS services. It is object storage, not a file system, using key/value pairs.
- Bucket naming — Bucket names must be globally unique. Slashes in names create a folder-like illusion. General purpose buckets replaced the older legacy format.
- Regional vs global — The bucket namespace is global (no two buckets anywhere share a name), but buckets live in a specific AWS region.

## Sections (L2)

### s3-concept

- Locator: `[[sources/aws-v3/07#s3-concept]]`
- Summary: S3 is object storage built on key/value pairs, not a hierarchical file system. Objects are stored and retrieved by a unique key within a bucket.
- Key claims: S3 stores objects, not files; each object is a key-value pair; S3 is one of the first and most used AWS services.
- Learner-relevant: The object-vs-file mental model is foundational — misinterpreting it causes confusion about path behavior, permissions, and what S3 can and cannot do.

### bucket-creation

- Locator: `[[sources/aws-v3/07#bucket-creation]]`
- Summary: Creating a bucket requires a globally unique name. The console offers general purpose buckets (the standard choice) and shows where to set the region. Bucket names with slashes simulate folders.
- Key claims: Bucket names are globally unique across all AWS accounts; general purpose is the default bucket type; the namespace is global but the bucket itself is regional.
- Learner-relevant: The learner will create a bucket for their React app — this section walks through the exact console steps and the naming constraint they will hit.

### object-storage-vs-file-system

- Locator: `[[sources/aws-v3/07#object-storage-vs-file-system]]`
- Summary: S3 is object storage, not a file system. When a real file system is needed, AWS offers EFS (Elastic File System). The distinction matters for what operations are possible.
- Key claims: S3 does not support file system semantics (no in-place edits, no file locks); EFS provides actual file system access for use cases that need it.
- Learner-relevant: Clarifies a common misconception — learners familiar with local file systems may expect familiar behaviors from S3, which leads to wrong architectural choices.
