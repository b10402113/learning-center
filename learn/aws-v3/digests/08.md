# Digest — 08

## Overview (L1)

- Sample app — Steve provides a sample React single-page application repo with a client-side router, index.html, and stylesheets ready for deployment.
- Build process — The React build step compiles and bundles assets into a static output folder suitable for S3 upload.
- Configuration — The repo includes policy files and configuration needed for AWS setup.

## Sections (L2)

### sample-app

- Locator: `[[sources/aws-v3/08#sample-app]]`
- Summary: The sample repo contains a React app with client-side routing, a single index.html entry point, and stylesheets. It is a minimal but realistic single-page application.
- Key claims: The app uses client-side routing (no server-side rendering); it is a standard React SPA with index.html as the shell.
- Learner-relevant: The learner deploys this exact app to S3 — understanding its structure (one HTML file, many JS/CSS bundles) explains why S3 static hosting works for SPAs.

### build-process

- Locator: `[[sources/aws-v3/08#build-process]]`
- Summary: Running the build command produces a static output directory. This folder contains the compiled assets (HTML, JS, CSS) ready for upload to S3.
- Key claims: The build step is required before deployment; the output is a flat static folder, not a running server.
- Learner-relevant: Connects the local development workflow (npm build) to the deployment workflow (upload output to S3) — the learner sees the same build artifacts they are used to, just hosted differently.

### configuration

- Locator: `[[sources/aws-v3/08#configuration]]`
- Summary: The repo includes configuration files and policies needed to set up S3 bucket access and static hosting. These files define what permissions the bucket requires.
- Key claims: Configuration files are provided to simplify setup; they define bucket policies for public read access.
- Learner-relevant: The learner will reference these files when configuring the S3 bucket — they are the bridge between the app and the AWS permissions model.
