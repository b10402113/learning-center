# Digest — aws-v3

## Overview (L1)

- CloudFront CDN introduction — CloudFront is AWS's Content Delivery Network. Instead of serving everything from one S3 bucket in one location, CloudFront distributes small pieces of infrastructure globally. Edge locations, regional edge caches, and origin servers form a multi-tier caching hierarchy. The first user to request content pays the latency cost; everyone after gets the cached version. Cache warming with services like Pingdom can pre-populate. There is a cost vs complexity tradeoff — more infrastructure means more things that can break.

## Sections (L2)

### CDN concept

- Locator: `[[sources/aws-v3/cloudfront-cdn-intro#cdn-concept]]`
- Summary: Explains what a CDN is and why global distribution matters — moving content closer to users rather than serving everything from a single origin.
- Key claims: CloudFront distributes infrastructure globally across edge locations; a single S3 bucket serves as the origin; global distribution reduces latency for distant users.
- Learner-relevant: Foundation for understanding why CloudFront exists and the problem it solves compared to plain S3 hosting.

### Caching tiers

- Locator: `[[sources/aws-v3/cloudfront-cdn-intro#caching-tiers]]`
- Summary: Describes the multi-layer caching architecture — edge locations at the front, regional edge caches in the middle, and the origin server at the back.
- Key claims: Edge locations are the closest cache tier to users; regional edge caches aggregate across a geographic area; origin servers hold the authoritative content.
- Learner-relevant: Understanding cache tiers explains latency differences and why first requests are slower than subsequent ones.

### Cache warming

- Locator: `[[sources/aws-v3/cloudfront-cdn-intro#cache-warming]]`
- Summary: Covers how to pre-populate CloudFront caches using services like Pingdom so the first real user does not pay the cold-cache penalty.
- Key claims: Services like Pingdom can trigger cache warming; warming eliminates the first-user latency cost; warming is optional but useful for latency-sensitive deployments.
- Learner-relevant: Practical technique to reduce cold-start latency in production deployments.

### Cost/complexity

- Locator: `[[sources/aws-v3/cloudfront-cdn-intro#cost-complexity]]`
- Summary: Discusses the tradeoff between adding infrastructure (CDN, edge caches) and the increased operational complexity and cost that comes with it.
- Key claims: More infrastructure means more things that can break; CloudFront adds cost on top of S3; simplicity should be weighed against performance gains.
- Learner-relevant: Helps learners decide when a CDN is worth it versus when plain S3 hosting is sufficient.
