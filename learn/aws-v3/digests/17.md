# Digest — aws-v3

## Overview (L1)

- Client-side routing with CloudFront — Single-page applications (SPAs) use client-side routing where the browser handles routes like `/about` or `/notes/123`. CloudFront returns 404 for these paths because no matching object exists in S3. The fix is configuring custom error pages to map 404 and 403 responses to `index.html` with a 200 status code. Lambda@Edge can add more sophisticated routing logic at edge locations.

## Sections (L2)

### Client-side routing problem

- Locator: `[[sources/aws-v3/client-side-routing#client-side-routing-problem]]`
- Summary: Explains why CloudFront returns 404 for SPA routes — the paths (`/about`, `/notes/123`) do not correspond to actual files in S3.
- Key claims: SPA routes are virtual paths managed by the client-side router, not real files; CloudFront looks for a matching object in S3 and returns 404 when none exists; this breaks deep linking and page refreshes.
- Learner-relevant: Identifies the core problem that every SPA deployment on CloudFront must solve — without the fix, direct navigation to deep links fails.

### Custom error pages

- Locator: `[[sources/aws-v3/client-side-routing#custom-error-pages]]`
- Summary: Covers the CloudFront configuration that maps 404 and 403 error responses to `index.html` with a 200 status code, enabling the SPA router to handle the route.
- Key claims: Map 404 → `/index.html` with 200 response code; map 403 → `/index.html` with 200 response code; this lets the SPA router take over and render the correct page.
- Learner-relevant: The standard fix for SPA routing on CloudFront — a configuration change, not a code change.

### Lambda@Edge

- Locator: `[[sources/aws-v3/client-side-routing#lambda-at-edge]]`
- Summary: Introduces Lambda@Edge as a way to run custom logic at CloudFront edge locations for more sophisticated routing than error-page mapping provides.
- Key claims: Lambda@Edge runs Lambda functions at edge locations; enables request/response manipulation before content is served; can handle complex routing, A/B testing, authentication, and URL rewriting.
- Learner-relevant: Positions Lambda@Edge as the advanced alternative when custom error pages are not sufficient — opens the door to edge computing concepts.
