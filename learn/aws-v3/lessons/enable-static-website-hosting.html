開啟靜態網站託管

學習目標：在 bucket 的 Properties 開啟靜態網站託管，並分辨 object URL 與 website endpoint URL 的差別。

S3 給你兩個 URL

當你把檔案上傳到 S3 之後，S3 會為每個物件提供一個 URL。但問題是：S3 其實給了你兩種不同的 URL，它們看起來很像，行為卻完全不同。

Object URL（物件 URL）

https://你的-bucket名稱.s3.ap-northeast-1.amazonaws.com/index.html

這是 S3 的原始存取方式。你可以用它來下載單一檔案，但對於網站託管來說：它不會把 index.html 當成預設文件。你打開 bucket 根目錄的 URL，看到的是 XML 清單而不是你的首頁。

Website endpoint URL（網站端點 URL）

http://你的-bucket名稱.s3-website-ap-northeast-1.amazonaws.com

這是 S3 靜態網站託管功能提供的 URL。它會把 index.html 當成預設文件，也能處理自訂的 error page。這才是你該用來訪問網站的 URL。

Object URLWebsite endpoint URL
格式.s3.region.amazonaws.com.s3-website-region.amazonaws.com
index.html 為首頁❌ 顯示 XML 目錄✅ 自動 serve index.html
支援 error page❌✅ 可自訂 404 頁面
協定HTTPSHTTP（免費，HTTPS 需 CloudFront）
核心概念 Object URL 是「S3 儲存系統的入口」，website endpoint URL 是「S3 網站託管的入口」。兩者對同一個 bucket，但行為不同。對靜態網站來說，你只會用到 website endpoint。

如何開啟靜態網站託管

  1. 進入 S3 console → 你的 bucket → Properties 標籤
  2. 捲到底部找到 Static website hosting
  3. 按 Edit
  4. 選擇 Enable
  5. 設定：
    • Index document：填 index.html
    • Error document（選填）：填 index.html（SPA 需要讓所有路由都回到 index.html）
  6. 按 Save changes

為什麼 Error document 也要填 index.html？

你的 React app 使用 client-side routing（React Router）。當訪客直接訪問 /about 這類路由時，S3 會在 bucket 裡找不到 about.html 這個檔案——因為所有路由都是由 index.html 裡的 JavaScript 處理的。

如果不設定 error document，S3 會回傳預設的 403/404 XML。但如果你把 error document 設成 index.html，S3 就會在找不到檔案時返回 index.html，讓 React Router 在前端接管路由——使用者體驗完全正常。

面試要點 「S3 靜態網站託管提供兩種 URL：object URL 用於原始物件存取，website endpoint URL 用於網站託管。對 SPA 來說，我把 index.html 設為 Index document 和 Error document，讓 React Router 能正確處理所有前端路由。」
