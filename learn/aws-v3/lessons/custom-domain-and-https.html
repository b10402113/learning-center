自訂網域與 HTTPS

學習目標：用 Alternate domain name (CNAME) 綁定自有網域，並用 ACM 憑證開啟 HTTPS。

兩件事要解決

distribution 預設給你的網址是 xxxxx.cloudfront.net——能用，但你想要自己的網域。這需要兩個設定：

  1. Alternate domain name（CNAME）——告訴 CloudFront「這個自有網域歸我管」
  2. ACM 憑證——讓 CloudFront 用你自己的網域提供 HTTPS

Step 1：設定 Alternate domain name + Default root object

進 CloudFront → 你的 distribution → Settings → Edit：

  1. Alternate domain name (CNAME)：填入你的網域，例如 www.example.com。這讓 CloudFront 接受來自這個網域的請求。
  2. Default root object：填 index.html。這樣訪客直接打根網址（/）就能看到首頁，不用自己輸入 index.html——這正是上一步「根路徑看到錯誤」的解藥（custom-domains）。
  3. 其他可以順手設定的：Price class（全部 edge locations 或只限某些區域）、HTTP/3 支援。對靜態網站，Steve 建議用全部 edge locations。
CNAME 是什麼 CNAME（Canonical Name）是一條 DNS 記錄，把 www.example.com 指向 CloudFront 的 xxxxx.cloudfront.net。訪問者打你的網域 → DNS 導到 CloudFront → CloudFront 看 Alternate domain name 認出這是他管的網域 → 服務內容。

Step 2：用 ACM 發免費憑證

HTTPS 需要 SSL/TLS 憑證。AWS Certificate Manager（ACM）可以免費發——對 CloudFront 來說，憑證必須在 us-east-1 區域，這是 AWS 的慣例：全域服務的資源放在 us-east-1（ssl-tls）。

  1. 切到 us-east-1 → ACM → Request certificate
  2. 輸入你的網域（www.example.com，可加 example.com 一起發）
  3. 選 DNS validation，ACM 會給你一組 CNAME 驗證記錄
  4. 把驗證記錄加到你的 DNS（Route 53 或任何 DNS 服務商）
  5. 等驗證通過（狀態變 Issued），把憑證 ARN 掛到 distribution 的 Custom SSL certificate
不用買網域的替代方案 如果你用預設的 *.cloudfront.net 網域，SSL/TLS 憑證是 自動的——CloudFront 免費送。只有用自訂網域時才需要自己向 ACM 申請。

Step 3：把網域指到 CloudFront

在你的 DNS 服務商（Route 53 或其他）加一條 CNAME：

www.example.com  →  xxxxx.cloudfront.net

如果想讓 apex 網域（example.com，不帶 www）也工作，需要 Route 53 的 Alias record（用 aws:cloudfront:distribution 當目標）。

Console vs CLI

這份配置實際上是一份 JSON——distribution 的完整設定。Console 的每一顆按鈕都有 CLI 對應（例如 aws cloudfront get-distribution 查狀態、aws cloudfront update-distribution 改設定）。你以後可以把它寫成 infrastructure-as-code，部署變成可重複的指令，不用手點（console-vs-cli）。

面試要點 「我綁定自有網域時做三件事：在 distribution 的 Alternate domain name 填 CNAME、設定 Default root object 為 index.html、用 ACM（憑證需在 us-east-1）申請免費憑證並掛到 Custom SSL certificate。最後在 DNS 加 CNAME 記錄指向 cloudfront.net 網址。如果只是用預設網域，SSL 是自動的。」
