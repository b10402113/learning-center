ARN 的格式與用途

學習目標：理解 Amazon Resource Name (ARN) 的格式，能自行建構 bucket 和 object 的 ARN。

ARN 是什麼？

在 AWS 裡，每一個資源——bucket、物件、IAM user、Lambda function——都有一個唯一的「地址」，叫做 ARN (Amazon Resource Name)。就像每棟房子有門牌號碼，每個 AWS 資源也有一個 ARN，讓 AWS 能精確地找到它。

在你寫 bucket policy 的時候，policy 裡的 Resource 欄位就是要填 ARN。如果你不知道 ARN 的格式，就没法正確地指定「這個 policy 要作用在哪些資源上」。

ARN 的通用格式

arn:aws:<service>:<region>:<account-id>:<resource>
欄位說明例子
arn固定前綴arn
awsPartition（aws = 公有雲, aws-cn = 中國, aws-gov = 政府雲）aws
serviceAWS 服務名稱s3, iam, lambda
region區域（S3 是全域服務，所以留空）（空）
account-id12 位數字的帳號 ID（S3 bucket 級別也留空）（空）
resource具體資源識別碼my-bucket, my-bucket/*

S3 的兩種 ARN

S3 有兩種常用的 ARN，分別對應「bucket 本身」和「bucket 裡的物件」：

1. Bucket ARN

arn:aws:s3:::my-bucket-name

注意 s3 後面有三個冒號——因為 S3 是全域服務，region 和 account-id 都省略了，所以連續出現兩個空欄位。

這個 ARN 代表 bucket 本身。在 policy 裡，它通常用來控制 bucket 級別的操作，比如列出物件 (s3:ListBucket)。

2. Object ARN

arn:aws:s3:::my-bucket-name/*

尾端的 /* 代表「這個 bucket 裡的所有物件」。在 policy 裡，它用來控制物件級別的操作，比如讀取 (s3:GetObject) 或寫入 (s3:PutObject)。

核心概念 Bucket ARN 沒有 /*，控制 bucket 級別操作；Object ARN 有 /*，控制物件級別操作。兩者在 policy 裡的用途完全不同。

從 console 找到 ARN

你不需要背下 ARN 格式——在 S3 console 裡，點進任何一個 bucket，在右上角就能看到它的 ARN：

arn:aws:s3:::your-bucket-name

或者用 AWS CLI：

aws s3api head-bucket --bucket your-bucket-name

實戰練習

試著為以下情境建構 ARN：

情境ARN
名為 portfolio-site 的 bucketarn:aws:s3:::portfolio-site
portfolio-site 裡的所有物件arn:aws:s3:::portfolio-site/*
portfolio-site 裡的某個檔案 images/photo.jpgarn:aws:s3:::portfolio-site/images/photo.jpg
面試要點 「ARN 是 AWS 資源的唯一識別碼，格式是 arn:partition:service:region:account:resource。S3 是全域服務，所以 region 和 account 欄位留空，用三個冒號代替。Bucket ARN 不帶尾碼，object ARN 帶 /* 表示所有物件。」
