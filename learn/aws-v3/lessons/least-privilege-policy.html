aws-v3 · S3 policies and security · Step 3/4

實作最小權限 Policy

學習目標：寫出一個只開放必要操作的 bucket policy，理解為什麼最小權限原則能降低爆炸半徑。

為什麼不要用 "*": "*"？

最省事的 policy 長這樣：

{
  "Effect": "Allow",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": "arn:aws:s3:::my-bucket/*"
}

「允許所有人對我的 bucket 做任何事。」這能用，但有嚴重問題：

  • 任何人可以上傳任意檔案（包括惡意軟體）
  • 任何人可以刪除你的檔案
  • 任何人可以列出你的 bucket 內容（洩漏目錄結構）

如果你的 API key 洩漏了，攻擊者能用它做什麼？——任何事。這就是「爆炸半徑」。

最小權限原則

最小權限原則（Principle of Least Privilege）的核心想法很簡單：只給必要權限，不多給。

對於一個公開靜態網站，訪客只需要做一件事：讀取檔案。他們不需要上傳、刪除或列出。所以 policy 應該只開 s3:GetObject。

逐步建構 Policy

場景：公開靜態網站

需求：任何人都能讀取網站的所有檔案，但不能寫入、刪除或列出。

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::my-portfolio-site/*"
        }
    ]
}

逐欄位拆解：

欄位值為什麼是這個值？
EffectAllow授予讀取權限
Principal*任何訪客都能讀取
Actions3:GetObject只開放「讀取」，不給 PutObject、DeleteObject
Resourcearn:aws:s3:::my-portfolio-site/*只作用在 bucket 裡的物件，不作用在 bucket 本身

場景：只允許特定 IAM user 上傳

需求：只有你的部署帳號能上傳檔案，其他人不能。

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowDeployUserUpload",
            "Effect": "Allow",
            "Principal": {
                "AWS": "arn:aws:iam::123456789012:user/deploy-user"
            },
            "Action": "s3:PutObject",
            "Resource": "arn:aws:s3:::my-portfolio-site/*"
        }
    ]
}

注意 Principal 不再是 *，而是特定的 IAM user ARN。只有這個 user 能上傳，其他人連寫入的資格都沒有。

爆炸半徑是什麼？

爆炸半徑（blast radius）是一個安全概念：當你的系統被入侵時，損害的範圍有多大。

Policy爆炸半徑
s3:* 給所有人整個 bucket 的所有操作——任何檔案都能被讀、寫、刪
s3:GetObject 給所有人只有讀取——檔案被看到，但不會被改或刪
s3:GetObject 只給 CloudFront只有 CloudFront 能讀——連 anonymous 使用者都不行
核心概念 最小權限不只是「比較安全」——它限制了意外和入侵的影響範圍。即使 API key 洩漏，攻擊者也只能做你授權的那件事，而不是所有事。

實戰建議

  1. 先想需求，再寫 policy——誰需要做什麼操作？不需要的就不開。
  2. 用具體的 ARN，不用 * 萬用字元——除非你真的需要涵蓋所有資源。
  3. 先 Deny 再 Allow——在大型組織裡，用 Deny 關掉高風險操作，再用 Allow 開放必要的。
  4. 定期審計——用 AWS IAM Access Analyzer 檢查哪些權限從未被使用。
面試要點 「最小權限原則是安全設計的基礎——只授予完成任務所需的最低權限。在 S3 裡，這意味著只開必要操作（如 s3:GetObject），限制 Resource 到特定 bucket，而不是用 s3:* 給所有人。這樣即使憑證洩漏，爆炸半徑也最小。」
