S3 是什麼？物件儲存與 key/value 心智模型

學習目標：建立「S3 = 物件儲存 + key/value」的心智模型，能解釋 bucket 與 object 的關係。

先從一個問題開始

你想把網站檔案放到雲端，讓全世界都能存取。你知道要去「S3」，但 S3 到底是什麼？很多人以為它只是一個「超大雲端硬碟」——把檔案丟進去、開個資料夾、就完事了。

這個直覺幫你入門，但也會害你踩坑。因為 S3 不是檔案系統，是物件儲存（object storage）。這兩個概念差在哪，決定了你接下來所有操作能不能想通。

三個名詞就夠了

要理解 S3，你只需要記住三層關係：

  • Bucket（儲存桶）——裝物件的容器，就像一個倉庫。
  • Object（物件）——S3 儲存的單位，就是你把倉庫裡的那個「箱子」。
  • Key（鍵）——每個物件在 bucket 裡唯一的名字，就像倉庫裡的架號，用 key 就能找到箱子。
核心概念 S3 把每一個物件當成一組 key/value（鍵／值）配對：key 是物件的名字，value 是物件的內容（資料本身）。你「放」一個物件 = 把資料和它的 key 一起丟進 bucket；你要取資料，就給 S3 一個 key，它把對應的 value 還給你。

S3 是 AWS 最早推出、也最常用的服務之一（Simple Storage Service，簡單儲存服務）。它不做任何「檔案」的複雜管理——它只負責一件事：依 key 儲存和取回物件。

為什麼這個心智模型重要

如果你一直用「資料夾、路徑、檔案」的檔案系統思維去想 S3，後面會一路卡關：看不懂權限為什麼這樣設、搞不懂為什麼「刪掉一個檔案」其實是別的操作、甚至選錯服務。把 S3 想成「一個扁平的大倉庫，每個箱子都有唯一標籤」，才是正確的起點。

面試要點 「S3 是 AWS 的物件儲存服務。資料以物件（object）為單位，放在 bucket 裡，每個物件用唯一的 key 來存取——本質上是 key/value 儲存，不是檔案系統。」
