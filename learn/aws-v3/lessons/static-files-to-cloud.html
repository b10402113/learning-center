從 FTP 到 S3 — 靜態檔案的部署演進

學習目標：理解靜態檔案如何從 FTP 伺服器遷移到 S3 雲端儲存，以及前端技能如何直接對接 AWS。

你的技能已經夠了

你會寫 HTML、JavaScript、CSS。你用 npm run build 產生 dist/ 資料夾。這些產出——那些 .html、.js、.css 檔案——就是靜態檔案。它們是純文字，不需要編譯器或執行環境就能被瀏覽器讀取。

問題是：這些檔案現在只存在你的電腦上。要讓全世界的人都能訪問你的網站，你必須把它們放到網路上。

古老的方式：FTP

在雲端出現之前，做法很直接：

  1. 租一台伺服器（通常在某个機房）
  2. 用 FTP（檔案傳輸協定）把 build 出來的檔案上傳到那台伺服器
  3. 伺服器收到檔案後，透過 HTTP 把它們 serve 給訪客

這能運作，但有幾個痛點：

  • 你必須管理伺服器——作業系統更新、安全性修補、流量配置，都是你的事
  • 單點故障——伺服器壞了，網站就掛了
  • 擴展困難——流量暴增時，你得手動升級伺服器規格

現代的方式：S3

AWS S3（Simple Storage Service）本質上是一個檔案櫃——你把檔案丟進去，它就幫你保管，並透過 URL 讓任何人都能存取。

核心概念 S3 Bucket（儲存桶）就像一個超大資料夾。你把 dist/ 裡的所有檔案丟進去，S3 就把它們放到網路上。

跟 FTP 伺服器相比：

FTP 伺服器S3
管理伺服器你要管AWS 管
擴展手動升級自動
可靠性單點故障99.999999999% durability
費用固定月費用多少付多少

這跟你的工作流程有什麼關係？

你在本地執行 npm run build，得到一個 dist/ 資料夾。接下來你要做的事情，本質上就是把那個資料夾「搬」到 S3 上。

# 你的工作流程
npm run build          → 產生 dist/ 資料夾
# 接下來要做的：
aws s3 sync dist/ s3://my-bucket  → 把檔案同步到 S3

就是這麼簡單。你的前端技能——寫出好的 HTML/JS/CSS——就是你需要的一切。AWS 只是提供了一個更好的「放檔案的地方」。

面試要點 「S3 是一個物件儲存服務。對於靜態網站部署，我把 build 產出的檔案同步到 S3 Bucket，設定為公開讀取，就能透過 S3 的網站端點訪問。不需要管理伺服器。」
