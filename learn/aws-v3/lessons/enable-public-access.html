開啟 S3 公開存取

學習目標：關閉 S3 的公開存取封鎖，並用 bucket policy 授予公開讀取權限，避開「上傳後 403」的常見陷阱。

上傳了卻看到 403？

你已經把 dist/ 的檔案上傳到 S3 了，但在瀏覽器打開 URL 卻看到 403 Forbidden。這幾乎是每個新手都會遇到的第一個坑。原因很簡單：S3 bucket 預設是完全私有的。

AWS 這樣的設計是有道理的——預設封鎖公開存取可以防止你不小心把敏感檔案暴露出去。但這也意味著，要讓網站公開可見，你需要做兩件事：

  1. 關閉公開存取封鎖（Public access block）
  2. 加上 bucket policy，授予公開讀取權限

第一步：關閉公開存取封鎖

進入 S3 console → 你的 bucket → Permissions → Block public access (bucket settings) → 按 Edit：

Block all public access:  Uncheck ✗
  ├─ Block public access to buckets and objects granted through new ACLs
  ├─ Block public access to buckets and objects granted through any ACLs
  ├─ Block public access to buckets and objects granted through new public bucket policies
  └─ Block public access to buckets and objects granted through any public bucket policies

全部取消勾選，然後按 Save changes。AWS 會要求你輸入 bucket 名稱來確認——這是一個安全機制，確保你真的知道自己在做什麼。

核心概念 「Public access block」是 S3 的一層安全閘門。即使你的 bucket policy 說了「公開讀取」，如果這個封鎖還開著，S3 會無視那個 policy——檔案照樣 403。

第二步：加上 Bucket Policy

關掉封鎖只是第一步。你還需要一個 policy 明確說：「這個 bucket 裡的所有物件，允許任何人讀取。」

在 Permissions → Bucket policy → Edit，貼上：

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::你的-bucket名稱/*"
        }
    ]
}

逐行解釋：

欄位意思是
Principal: "*"「任何人」——不設限
Action: s3:GetObject允許「讀取物件」這個動作
Resource: .../*適用範圍：這個 bucket 裡的所有物件

兩步的順序很重要

如果你只加了 bucket policy 但沒關掉 public access block——S3 會無視你的 policy，檔案照樣 403。如果你關了 block 但沒加 policy——bucket 還是「沒有明確允許公開」，一樣 403。

兩步都要做，缺一不可：

❌ 只加 policy，沒關 block  → 403（policy 被 block 覆蓋）
❌ 只關 block，沒加 policy  → 403（沒有允許公開的 rule）
✅ 關 block + 加 policy      → 公開可讀 ✓
面試要點 「S3 bucket 預設完全封鎖公開存取。要託管公開網站，我需要先關閉 Public access block，然後附上 bucket policy 允許 s3:GetObject 給 Principal *。兩步缺一不可——只做一步不會生效。」
