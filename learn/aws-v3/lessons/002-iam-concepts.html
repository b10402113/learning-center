IAM 概念與最小權限原則

Node: aws-account-and-iam · Step 2/3

學習目標

理解 IAM 的身份驗證與授權機制，讀懂一份 IAM policy 的 JSON 結構，並說出最小權限原則的實作意義。

IAM 是什麼？

IAM（Identity and Access Management）是 AWS 的中央門禁系統。它回答兩個問題：

你是誰？

身份驗證（Authentication）—— 確認使用者的身分。root user、IAM 使用者、API Key 都是身份。

你能做什麼？

授權（Authorization）—— 決定這個身份能執行哪些操作、存取哪些資源。由 policy 定義。

每一個 AWS 請求都會經過 IAM。你在 Console 按一個按鈕、用 CLI 執行一個指令、用 SDK 呼叫一個 API——全部都要先通過 IAM 的檢查。它是最底層的基礎設施，也是你最重要的安全防線。

類比：IAM 就像一棟辦公大樓的門禁系統。身份驗證是你刷的那張感應卡（確認你是誰），授權是你卡片上的權限等級（能進哪些樓層、哪些房間）。Policy 就是那張卡片上寫的權限清單。

IAM 的核心實體

IAM 裡有三種主要的「身份」：

實體 說明
User 一個長期存在的身份，對應到一個人或一個服務。有登入憑證（密碼、Access Key）。
Group 一群使用者的集合。把 policy 掛在 Group 上，裡面所有人都自動繼承那些權限。
Role 臨時身份，給 AWS 服務或外部程式用。不長期持有憑證，用 STS 拿臨時 Token。
你會最先用到的是 User 和 Group。Role 在後面部署 S3 + CloudFront 時會用到——IAM 角色讓 CloudFront 能安全地讀取 S3 裡的檔案，而不必把 Access Key 寫在設定檔裡。

Policy：權限的 JSON 語言

Policy 是一份 JSON 文件，定義了「允許或拒絕」哪些操作（Action）作用在哪些資源（Resource）上。

policy.json — 允許在特定 S3 bucket 上傳檔案
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::my-portfolio-bucket/*"
    }
  ]
}

逐行拆解：

  • Version — policy 語言版本，固定寫 2012-10-17
  • Statement — 一組規則的陣列，可以有多條
  • Effect — Allow 或 Deny（只能二選一）
  • Action — 允許的 API 操作，格式是 服務:操作
  • Resource — 操作的目標，用 ARN（Amazon Resource Name）指定
deny 永遠優先。如果有一條 deny 規則和一條 allow 規則同時存在，deny 會贏。這讓你可以用一條 deny 來擋住不該發生的操作，即使其他 policy 允許了它。

最小權限原則

最小權限原則（Least Privilege）說的是：給每一個使用者或服務恰好足夠的權限，不要多給。

正確做法

一個 CI/CD 部署機器人只需要 s3:PutObject 來把靜態檔案放進一個特定的 bucket。它不需要讀 DynamoDB、不需要開 EC2、不需要管理 IAM。所以你只給它那一條權限。

常見錯誤

因為「怕以後會用到」，就給所有使用者 AdministratorAccess。這樣一來，只要任何一個帳號被盜用，攻擊者就擁有整個帳號的完整控制權——包括刪除你的資料、開高價實例、修改帳單設定。

最小權限原則不只是一個安全建議，它是一種降低爆炸半徑的策略。如果 AI 編程助手（Copilot、Cursor 等）幫你生成的 IAM policy 給了過多權限，你的系統就多了一個不必要的攻擊面。限制權限就是在限制潛在損失。

Policy 的三種掛載方式

Policy 可以附加在三個地方：

掛載對象 適用情境
User 只給一個人的特殊權限
Group 一群人的共同權限（推薦做法）
Role AWS 服務或外部程式的臨時權限
最佳實踐：盡量把 policy 掛在 Group 上，而不是直接掛在 User 上。這樣新增使用者時只需要加入 Group，不用重複設定權限。

自我檢測

Q1. IAM 回答的兩個核心問題是？

  • 花了多少錢、用多少服務
  • 你是誰、你在哪裡
  • 你是誰、你能做什麼
  • 你的密碼是什麼、你的 email 是什麼

Q2. 一份 IAM policy 的 JSON 裡，Effect 欄位可以填什麼？

  • True 或 False
  • Allow 或 Deny
  • Read 或 Write
  • Grant 或 Revoke

Q3. 如果一條 deny 規則和一條 allow 規則同時作用在同一個操作上，誰會贏？

  • Allow 贏
  • 先建立的贏
  • Deny 永遠優先
  • 看資源的設定

Q4. 最小權限原則的核心是？

  • 所有使用者都應該有 admin 權限
  • 權限越少越好，最好沒有
  • 只用 Role，不用 User
  • 只給恰好足夠的權限，不多給
