aws-v3 · S3 static hosting · Step 4/4

上傳並驗證首次部署

學習目標：把 build 產物上傳進 bucket，打開 website endpoint URL，確認 React app 在 AWS 上正常載入。

終於要上線了

前三步你已經準備好了一切：

  • ✅ build 出了靜態產物（dist/）
  • ✅ 關閉了公開存取封鎖 + 加了 bucket policy
  • ✅ 開啟了靜態網站託管

現在只剩一件事：把檔案搬上去。

上傳方式一：AWS Console（手動）

  1. 進入 S3 console → 你的 bucket
  2. 按 Upload
  3. 把整個 dist/ 資料夾拖曳上去（或按 Add files 選擇）
  4. 按 Upload 等待完成

這種方式對小專案夠用，但每次部署都要手動拖檔案，不夠自動化。

上傳方式二：AWS CLI（推薦）

# 同步整個 dist/ 資料夾到 bucket
aws s3 sync dist/ s3://你的-bucket名稱

s3 sync 會比較本地和遠端的差異，只上傳有變更的檔案。這意味著：

  • 第二次部署會比第一次快很多（只上傳改過的檔案）
  • 你不需要每次都重新上傳所有東西
# 如果要清除舊檔案（例如刪掉的路由對應的 HTML）
aws s3 sync dist/ s3://你的-bucket名稱 --delete

--delete 會移除 bucket 裡有但本地沒有的檔案，保持兩邊同步。

驗證部署

上傳完成後，去 bucket 的 Properties → Static website hosting 底部，找到你的 website endpoint URL。把它貼到瀏覽器。

你應該會看到你的 React app 正常載入。幾個可以檢查的點：

  • 首頁正常顯示——確認 index.html 和 JS/CSS 都有正確載入
  • CSS 樣式正確——如果樣式全失，可能是 build 產物裡的路徑問題
  • 路由切換正常——在 app 裡點導航，確認 React Router 能正確切換頁面
  • 直接訪問子路由——例如在網址列輸入 /about，確認 error document 設定有作用（頁面不會 403/404）

症狀可能原因解法

面試要點 「部署靜態網站到 S3 的流程是：npm run build 產生靜態產物 → 開啟公開存取 + bucket policy → 開啟靜態網站託管 → 用 aws s3 sync 上傳。驗證時用 website endpoint URL 而非 object URL。整個過程不需要管理任何伺服器。」
