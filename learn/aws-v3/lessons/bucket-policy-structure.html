Bucket Policy 的四個欄位

學習目標：能讀寫 S3 bucket policy，掌握 Effect / Principal / Action / Resource 四欄位的意義與互動方式。

Policy 是什麼？

上一步你學了 ARN——AWS 資源的「地址」。這一步要學的是怎麼用 ARN 寫出一份 bucket policy，告訴 S3：「誰能做什麼、作用在哪些資源上。」

Bucket policy 就是一份 JSON 文件，貼在 S3 bucket 的 Permissions → Bucket policy 裡。它的核心結構只有四個欄位。

四個核心欄位

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "示範聲明",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-bucket/*"
    }
  ]
}

1. Effect — 允許還是拒絕？

Effect 只有兩個值：Allow 或 Deny。它決定這個 statement 是「放行」還是「拒絕」。

值意思例子
Allow授予權限允許任何人讀取物件
Deny明確拒絕（即使其他 rule 說了 Allow）拒絕特定 IP 的存取
核心概念 在 AWS 裡，Deny 永遠優先於 Allow。如果你有一條 Allow 說「允許讀取」，又有一條 Deny 說「拒絕讀取」，結果是拒絕。這是 S3 安全模型的基石。

2. Principal — 誰？

Principal 指定「這個 rule 適用在誰身上」。

值意思
"*"所有人（anonymous 使用者也包含在內）
"AWS": "arn:aws:iam::123456789012:root"特定 AWS 帳號下的所有人
"Service": "cloudfront.amazonaws.com"特定 AWS 服務（如 CloudFront）

要託管公開網站，你會設 "*"——讓任何人都能讀取。但如果是 private bucket，你會指定特定的 IAM user 或 role。

3. Action — 做什麼？

Action 指定「允許或拒絕哪個 S3 操作」。S3 的 action 都以 s3: 開頭。

Action用途
s3:GetObject讀取物件（下載檔案）
s3:PutObject寫入物件（上傳檔案）
s3:DeleteObject刪除物件
s3:ListBucket列出 bucket 裡的物件

公開網站只需要 s3:GetObject——訪客只能讀，不能寫、不能刪。

4. Resource — 作用在哪些資源上？

Resource 用 ARN 指定「這個 rule 作用在哪些資源上」。

"Resource": "arn:aws:s3:::my-bucket/*"    ← 所有物件
"Resource": "arn:aws:s3:::my-bucket"      ← bucket 本身
"Resource": "arn:aws:s3:::my-bucket/img/*" ← 特定路徑下的物件

大多數 policy 都用 /* 萬用字元來涵蓋所有物件。

四個欄位的組合邏輯

把四個欄位串起來，一句話就能描述 policy 的意思：

Effect (Allow/Deny) + Principal (誰) + Action (做什麼) + Resource (在哪裡)
= 一句完整的權限聲明

例如：

"Allow" + "*" + "s3:GetObject" + "arn:aws:s3:::my-bucket/*"
= 「允許所有人讀取 my-bucket 裡的所有物件」
面試要點 「S3 bucket policy 有四個核心欄位：Effect（Allow 或 Deny）、Principal（誰）、Action（做什麼操作）、Resource（作用在哪個 ARN 上）。Deny 永遠優先於 Allow，這是 AWS 安全模型的基本原則。」
