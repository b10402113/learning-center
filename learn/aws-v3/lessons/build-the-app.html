Build 出可部署的靜態產物

學習目標：跑 npm run build，理解輸出資料夾裡的內容，以及為什麼這個靜態產物可以直接被 S3 託管。

你的 React app 目前住在哪裡？

你每天用 npm run dev 啟動的開發伺服器，跑在你自己的電腦上。只有你自己能訪問。要讓全世界的人都看到你的網站，你需要把那些檔案從你的電腦搬出去。

但在搬之前，你得先搞清楚一件事：S3 只會存檔案，不會跑程式。它不是 Node.js 伺服器，不會執行你的 React 程式碼。它只會把檔案原封不動地交給訪客的瀏覽器。

好消息是：React 的 build 產物恰好就是純靜態檔案。

執行 build

npm run build

這行指令做了什麼？它把你所有的 React 程式碼、JSX、TypeScript、CSS 預處理器，全部編譯、壓縮、打包成瀏覽器可以直接讀取的格式。完成後，你會看到一個輸出資料夾（通常是 dist/ 或 build/）。

看看裡面有什麼

dist/
├── index.html          ← 唯一的 HTML 入口
├── assets/
│   ├── index-[hash].js ← 打包後的 JavaScript
│   ├── index-[hash].css← 打包後的 CSS
│   └── ...             ← 其他 chunks、圖片等
└── favicon.ico

注意幾個重點：

  • 只有一個 index.html——React 是單頁應用（SPA），所有頁面都由這一個 HTML 檔案和 JavaScript 運算產生
  • JS 和 CSS 都已經打包過了——檔名帶 hash（例如 index-a1b2c3.js），這是為了快取策略
  • 沒有 node_modules——所有依賴都已經被打包進那幾個 JS 檔案裡
核心概念 整個 dist/ 資料夾就是你的「可部署產物」。裡面沒有需要伺服器才能執行的東西——沒有 Express、沒有 API route、沒有伺服器端渲染。純靜態，瀏覽器直接就能跑。

為什麼 S3 能託管這些檔案？

S3（Simple Storage Service）本質上是一個檔案櫃——你把檔案放進去，它給你一個 URL，任何人都能透過那個 URL 存取。

對於靜態網站，流程是：

  1. 你把 dist/ 裡的檔案上傳到 S3 Bucket
  2. S3 把每個檔案當成一個 object（物件）
  3. 每個 object 都有一個 URL，訪客打開那個 URL 就能看到你的網站

你的 index.html 就是整個網站的入口。瀏覽器載入它，它再透過裡面的 JS 檔案渲染出完整的頁面。整個過程不需要任何伺服器端的處理。

面試要點 「我把 React app 用 npm run build 編譯成靜態產物——一個 HTML 入口加上打包後的 JS/CSS。這些純靜態檔案可以直接上傳到 S3，由 S3 託管成網站，不需要任何伺服器端處理。」
