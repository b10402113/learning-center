Lesson 003 · AWS 基礎

建立 IAM 管理員群組與日常帳號

Node: aws-account-and-iam · Step 3/3

學習目標

在 AWS Console 建立一個帶有 AdministratorAccess 權限的 IAM 群組，建立一個日常使用的 IAM 使用者，並設定帳號別名讓登入更方便。

為什麼需要一個日常帳號？

在前兩個 lesson 裡，你已經建立了一個 AWS 帳號並理解了 IAM 的核心概念。現在是時候把它們串起來：建立一個你每天登入用的 IAM 使用者，而不是繼續用 root user。

完成這個 lesson 之後，你會有一個安全的日常登入帳號。你不再需要碰 root——root 只留著應付帳號層級的 emergencies（例如更改帳單資訊、刪除整個帳號）。

建立步驟

以下是完整流程，建議你在 AWS Console 上同步跟著做：

第一步：建立 IAM 群組

  1. 用 root user 登入 AWS Console
  2. 搜尋「IAM」並進入 IAM Dashboard
  3. 左側選單點「Groups」→「Create group」
  4. 群組名稱輸入 Admins（或你喜歡的名字）
  5. 在權限設定中搜尋 AdministratorAccess，勾選這條 AWS Managed Policy
  6. 點「Create group」完成

為什麼用 AdministratorAccess？

這條 policy 給了幾乎所有權限——就像「城堡的幾乎所有鑰匙」。它讓你在後續課程中能自由地操作任何 AWS 服務。root user 始終保留 revoke 這些權限的能力，所以安全網還在。

第二步：建立 IAM 使用者

  1. 在 IAM Dashboard 點「Users」→「Create user」
  2. 使用者名稱輸入 daily-admin（或你喜歡的名字）
  3. 勾選「Provide user access to the AWS Management Console」
  4. 選擇「I want to create an IAM user」
  5. 設定一個強密碼
  6. 在「Set permissions」步驟，選擇「Add user to group」
  7. 勾選你剛建立的 Admins 群組
  8. 點「Create user」完成

第三步：測試日常帳號

  1. 登出 root user
  2. 用 daily-admin 的使用者名稱和密碼登入 Console
  3. 確認你能正常存取 IAM、S3 等服務
  4. 在 IAM Dashboard 確認你的身份是 daily-admin，不是 root
如果你能用 daily-admin 正常登入並操作服務，恭喜——你已經完成了最重要的安全設定。

第四步：設定帳號別名

AWS 預設的登入 URL 是一串難記的帳號 ID。設定一個自訂別名，讓登入 URL 變成一個容易記住的地址：

  1. 以 daily-admin 登入 Console
  2. 進入 IAM Dashboard
  3. 在「IAM-dashboard sign-in link」區域點「Customize」
  4. 輸入一個全球唯一的別名（例如 andy-portfolio）
  5. 儲存

設定完成後，你的登入 URL 變成：

https://andy-portfolio.signin.aws.amazon.com/console

類比：帳號別名就像你的辦公室門牌號。本來是「123456789012」（帳號 ID），現在是「Andy 的工作室」。別人要來拜訪你，不用記那串數字，只要記你的名字就好。

完成後的狀態

  • root user — 收好，不再日常使用。只用於帳號層級的紧急操作。
  • daily-admin — 你的日常登入帳號，有 AdministratorAccess 權限。
  • Admins 群組 — 你未來可以繼續往裡面加使用者。
  • 帳號別名 — 方便記憶的登入 URL。
從現在開始，這就是你登入 AWS 的方式。整個課程後續的所有操作，都以 daily-admin 身分進行。你已經有了一个安全、方便的日常帳號。

自我檢測

Q1. 建立 IAM 群組時，你應該附加哪種類型的 policy？

  • 自訂 policy，只給 s3:ListBucket
  • ReadOnlyAccess
  • AdministratorAccess
  • 不需要附加任何 policy

Q2. 帳號別名的作用是？

  • 更改 root user 的密碼
  • 建立一個容易記憶的登入 URL
  • 限制 IAM 使用者的權限
  • 啟用 MFA 多因素驗證

Q3. 完成設定後，你日常登入 AWS 應該用哪個身份？

  • daily-admin（IAM 使用者）
  • root user
  • Account Owner
  • 都可以，沒有差別

Q4. 為什麼 root user 仍然有 revoke IAM policy 的能力？

  • 因為 IAM 有 bug
  • 因為 AdministratorAccess 不完整
  • 因為 AWS 不信任 IAM
  • 因為 root 是帳號的最終控制者，必須保留最终权限
