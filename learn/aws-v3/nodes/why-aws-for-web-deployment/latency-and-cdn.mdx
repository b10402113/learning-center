# 距離的代价 — 延遲問題與 CDN 概念

## Learning goal

理解距離造成的延遲問題，以及 CDN 如何透過全球分散解決它。

## Lesson

距離造成延遲——這是一個物理學問題。光速有限，一個在台北的使用者訪問美東的伺服器，光來回的傳輸就需要約 150 毫秒。再加上 DNS 解析、TCP/TLS 握手、伺服器處理時間，一個請求的總延遲很容易超過 300 毫秒。人類感知的延遲門檻大約是 100 毫秒，超過這個數字使用者就會明顯感覺「慢」。

解決方案是把內容搬到使用者身邊。CDN（Content Delivery Network，內容傳遞網路）在全球各地部署伺服器節點（Edge Location），把你的檔案複製到這些節點上。當使用者請求檔案時，CDN 從離他最近的節點回傳，大幅縮短物理距離。本質上，CDN 是一個全球分佈的檔案複製系統。

你已經用過 CDN 了——<code>npm install</code> 和 <code>pip install</code> 的套件下載幾乎瞬間完成，就是因為套件檔案被放在全球 CDN 上。Vercel 和 Netlify 本質上也是 CDN——你 push 程式碼，它們 build 完就把靜態檔案放到全球邊緣節點。AWS 的 CloudFront 就是 CDN 服務，接下來你會直接用它搭配 S3 實現同樣的效果。
