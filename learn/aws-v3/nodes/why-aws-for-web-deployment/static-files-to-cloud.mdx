# 從 FTP 到 S3 — 靜態檔案的部署演進

## Learning goal

從 FTP 到 S3 — 理解靜態檔案的部署演進，以及前端技能如何直接對接 AWS。

## Lesson

前端開發者的核心技能——HTML、JavaScript、CSS——最終產出的是靜態檔案。這些文字檔需要被放到網路上，讓任何人透過瀏覽器存取。早期的做法是用 FTP 把檔案上傳到一台伺服器，再由那台伺服器透過 HTTP serve 給訪客。這能運作，但你必須自己管理伺服器——作業系統更新、安全性修補、流量配置都是你的事。伺服器壞了網站就掛了，流量暴增時你得手動升級。

現代的做法是用 S3（Simple Storage Service）。S3 本質上是一個物件儲存服務——你把 <code>dist/</code> 資料夾裡的靜態檔案同步到一個 S3 Bucket（儲存桶），S3 就幫你保管這些檔案，並透過 URL 讓任何人都能存取。你不需要管理伺服器、不需要擔心單點故障、不需要手動擴展。AWS 負責基礎設施，你只需要專注在寫好的 HTML/JS/CSS。

對於前端開發者來說，從 FTP 伺服器遷移到 S3 的核心改變是：你從「管理一台伺服器」變成「把檔案放到一個物件儲存服務」。你的 <code>npm run build → dist/</code> 工作流程完全不變，只是把「放檔案的地方」從自建伺服器換成了 S3。S3 的 durability 達到 99.999999999%（11 個 9），遠超任何自建方案。
