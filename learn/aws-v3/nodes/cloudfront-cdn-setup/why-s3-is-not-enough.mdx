# 為什麼 S3 單獨不夠：三個硬限制

<LearningGoal>
解釋 S3 靜態網站託管的三個硬限制（無自訂網域 HTTPS、無 cache-control、單一區域延遲），以及為何正式上線需要 CDN。
</LearningGoal>

## Lesson

S3 靜態網站託管的唯一賣點是「簡單」——一顆按鈕就能把網站放到網路上，不需要伺服器、不需要 CDN。但除了簡單之外，它是所有託管選項裡最弱的那個。這三個限制不是設定問題，而是功能根本不提供，對正式上線是硬傷：

1. **自訂網域沒有 HTTPS**。S3 的 website endpoint 只支援 HTTP。瀏覽器對非 HTTPS 的警告越來越嚴，而且像 `navigator.clipboard`、geolocation 這類現代瀏覽器 API 只在 HTTPS 下才能用。對正式產品這是不可接受的。
2. **不能設定 cache-control 標頭**。S3 靜態託管沒有讓你設定快取標頭的介面，瀏覽器每次都要重新抓取檔案，每一次請求都打到 origin，既慢又貴。
3. **內容只從單一區域送出**。bucket 放在哪個區域，所有使用者就要連到那個區域。從美東 ping 到澳洲就要 253ms，這還只是 ping——使用者被迫跨越長距離，延遲隨距離增加。

這三個限制剛好對應 CDN 要解決的三件事：HTTPS、可設定的快取、全球邊緣分發。CloudFront 是 AWS 的 CDN，坐在 S3 前面補齊這三項。所以 CloudFront 不是選配，而是正式上線的必要下一步；把 bucket 放到離使用者最近的區域也無法真正解決問題，因為使用者分佈在全球，不可能每個區域都放一份——CDN 用「一份 origin + 全球快取副本」來解決。
