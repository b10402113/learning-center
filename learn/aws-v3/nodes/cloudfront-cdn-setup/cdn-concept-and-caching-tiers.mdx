# CDN 是什麼：邊緣節點與快取階層

<LearningGoal>
說明 CDN 是什麼、邊緣節點 / 區域邊緣快取 / origin 的分層架構，以及首次請求 vs 後續請求的延遲差異。
</LearningGoal>

## Lesson

CDN 的核心做法是把內容保持一份在 origin，但在全球各地放快取副本——不要只有一個 bucket、一個地方，而是在全世界放很小的基礎設施。使用者永遠從離自己最近的節點取資料。CloudFront 用三層快取階層實現這件事：**邊緣節點**最靠近使用者，是第一線快取；**區域邊緣快取**彙整一個地理區域的請求，減少打回 origin 的次數；**origin**（通常就是你的 S3 bucket）是唯一的權威內容來源。

請求流程：使用者連到最近的邊緣節點 → 有快取就回傳 → 沒有就往區域邊緣快取找 → 再沒有才打到 origin。這解釋了首次請求與後續請求的延遲差異：**第一個使用者付冷啟動成本**。澳洲東岸有人先訪問過，區域邊緣快取就填滿了，西岸使用者只要到東岸拿快取即可——差距是幾毫秒對上約 200ms 的打回 origin 成本。CDN Perf 的真實數據證明了這點：掛上 CDN 後，從墨爾本訪問的延遲大幅下降。

CDN 還帶來額外的可靠性紅利：就算 S3 出了狀況，仍有快取的區域節點能繼續服務，那一刻根本沒在讀 bucket。但代價是複雜度——多一層基礎設施就多一點可能壞掉的東西。緩解冷啟動的手段（例如用 Pingdom 定期 ping 自己的 CDN 做 warm up cache）也是額外基礎設施。Steve 的建議是：先測量、再決定，如果你的使用者就在 origin 附近，這層優化未必值得。
