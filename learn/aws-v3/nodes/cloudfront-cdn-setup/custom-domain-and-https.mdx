# 自訂網域與 HTTPS

<LearningGoal>
用 alternate domain name (CNAME) 綁定自有網域，並用 ACM 憑證開啟 HTTPS。
</LearningGoal>

## Lesson

綁定自有網域需要兩個設定。第一是 **Alternate domain name (CNAME)**：在 distribution 的 Settings 填上你的網域（例如 `www.example.com`），讓 CloudFront 接受來自這個網域的請求；同時把 **Default root object** 設為 `index.html`，訪客直接打根網址 `/` 就能看到首頁，不用自己輸入檔名——這也解掉了上一步「根路徑看到錯誤」的問題。其他可順手設定的有 Price class（Steve 對靜態網站建議用全部 edge locations）與 HTTP/3 支援。第二是 **ACM 憑證**：HTTPS 需要 SSL/TLS 憑證，AWS Certificate Manager 可免費發，但對 CloudFront 來說憑證必須在 **us-east-1** 申請——全域服務的資源放在 us-east-1 是 AWS 的慣例。

申請流程：切到 us-east-1 → ACM → Request certificate → 輸入網域（可連 apex 一起發）→ 選 DNS validation → 把 ACM 給的 CNAME 驗證記錄加到你的 DNS（Route 53 或任何服務商）→ 等狀態變成 Issued → 把憑證 ARN 掛到 distribution 的 Custom SSL certificate。最後在你的 DNS 加一條 CNAME：`www.example.com → xxxxx.cloudfront.net`；apex 網域則用 Route 53 的 Alias record。如果你用預設的 `*.cloudfront.net` 網域，SSL/TLS 憑證是自動的，只有自訂網域才需要自己申請。

這份 distribution 配置本質上是一份 JSON。Console 的每個設定都有 CLI 對應（例如 `aws cloudfront get-distribution` 查狀態、`update-distribution` 改設定），之後可以寫成 infrastructure-as-code，讓部署變成可重複的指令而不是手點。到這裡，S3 + CloudFront + 自訂網域 + HTTPS 的四步拼圖完成：你的網站可以正式上線，也足以在面試中解釋每個服務扮演的角色、快取階層為何存在，以及自訂網域與 HTTPS 的設定流程。
