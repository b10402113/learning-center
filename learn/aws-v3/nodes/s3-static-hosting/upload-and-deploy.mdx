# 上傳並驗證首次部署

<LearningGoal>
把 build 產物上傳進 bucket，打開 website endpoint URL，確認 React app 在 AWS 上正常載入。
</LearningGoal>

## Lesson

上傳有兩種方式：AWS Console 手動拖曳（適合小專案），或 AWS CLI 的 `aws s3 sync dist/ s3://bucket-name`（推薦）。`s3 sync` 會比較本地和遠端差異，只上傳有變更的檔案，大幅減少重複上傳；加 `--delete` 可以移除 bucket 裡有但本地沒有的檔案，保持兩邊完全同步。

部署後的驗證重點：確認用的是 website endpoint URL 而非 object URL（後者會顯示 XML 目錄或空白頁面）；確認 CSS/JS 都有正確載入（樣式全失通常是路徑問題）；確認直接訪問子路由時 error document 有作用（React Router 能正確接管）。常見的 403 問題回到 Step 2 檢查公開存取設定，刷新 404 回到 Step 3 檢查 error document。

四步走完：`npm run build` → 關公開封鎖 + 加 policy → 開啟靜態託管 → sync 上傳。這是一套可重複的「build → 公開 → 託管 → 上傳」部署流程，也是後續接 CloudFront 和自訂域名的基礎。
