# Bucket 命名與 Region 的關係

## Learning goal

能說出 bucket 名稱為何必須全域唯一、斜線為什麼造成資料夾錯覺，以及 namespace 全域 vs 儲存區域性的差別。

## Lesson

上一課你建立了一個 bucket，學到名稱必須「全域唯一」，同時又選了 region——資料存在某個地區。這裡有個乍看矛盾的地方：**名稱是全世界的命名空間，資料卻只存在一個地區**。這兩個事實同時成立，正是理解 S3 的關鍵。

**命名空間（namespace）是全域的**：整個 AWS、所有帳號、全世界，只有一個 bucket 能叫某個名字。這跟一般資料夾不同——你的電腦裡可以有 `report.pdf`，別人的電腦裡也可以有，互不衝突；但在 S3，名字就是身分證字號，全球唯一。這也解釋了為什麼名字容易撞：因為命名空間是全世界共用的，任何一個名字只能用一次。再看 `my-app/images/logo.png` 這種 key，Console 會把它顯示得像巢狀資料夾，你甚至可以「點進」資料夾瀏覽——但這是視覺輔助。S3 的儲存是扁平的，整個 bucket 就一個 key 命名空間，斜線只是 key 字串的一部分，不是真的目錄結構。所以「搬移資料夾」在 S3 裡其實是「把每個物件的 key 改掉」，而不是真的移動目錄，這是檔案系統思維的人最常做錯的一件事。

既然名字是全域的，region 的意義在哪？region 決定的是**資料實際儲存的位置**——你的物件躺在哪個地區的資料中心，這影響三件事：延遲（離使用者越近越快）、法規合規（某些資料必須留在特定地區）、成本與可用性。把這兩個層次分開看，你就能向面試官講清楚：bucket 名稱在全域命名空間中唯一，但資料實際儲存在你指定的 region；名稱是全域的，儲存是區域的，兩者不能混為一談。
