# S3 是什麼？物件儲存與 key/value 心智模型

## Learning goal

建立「S3 = 物件儲存 + key/value」的心智模型，能解釋 bucket 與 object 的關係。

## Lesson

你想把網站檔案放到雲端，讓全世界都能存取。你聽說要用 S3，但很多人以為它只是一個「超大雲端硬碟」——把檔案丟進去、開個資料夾就完事。這個直覺能幫你入門，卻也會讓你一路踩坑，因為 **S3 不是檔案系統，而是物件儲存（object storage）**。

理解 S3 只需要記住三層關係。**Bucket（儲存桶）** 是裝物件的容器，就像一個倉庫；**Object（物件）** 是 S3 的儲存單位，就是倉庫裡的那個箱子；**Key（鍵）** 是每個物件在 bucket 裡唯一的名字，就像倉庫的架號。S3 把每個物件當成一組 **key/value（鍵／值）配對**：key 是物件的名字，value 是物件的內容。你「放」一個物件，等於把資料和它的 key 一起丟進 bucket；你要取資料，就給 S3 一個 key，它把對應的 value 還給你。

這個心智模型決定你後面的每一步。如果你一直用「資料夾、路徑、檔案」的檔案系統思維去想 S3，就會搞不懂權限為什麼這樣設、為什麼「刪掉一個檔案」是別的操作、甚至選錯服務。S3 是 AWS 最早推出、也最常用的服務之一（Simple Storage Service，簡單儲存服務），它只做一件事：依 key 儲存與取回物件。把 S3 想成一個扁平的大倉庫、每個箱子都有唯一標籤，才是正確的起點。下一步，我們把物件儲存和檔案系統攤開比較，看看 S3 到底做不到哪些事。
