# 物件儲存 vs 檔案系統：差異與 EFS

## Learning goal

能分辨物件儲存與檔案系統的差異，並說出什麼時候需要改用 EFS。

## Lesson

你在自己電腦上整理檔案，習慣了這些操作：雙擊改一個檔案、存檔、鎖定某個檔案讓別人不能動、在資料夾之間搬來搬去。現在開始用 S3，第一個困惑就來了——「我怎麼不能像平常那樣改檔案？」不是你不會操作，而是 S3 從設計上就**不做檔案系統做的事**。它不是「比較弱的硬碟」，而是另一種東西：物件儲存（object storage）。

傳統檔案系統會做、S3 做不到的有三件事。第一，**就地編輯**：檔案系統可以直接在原檔案上修改；S3 不行，你只能上傳一份新版本去取代舊的。第二，**檔案鎖定**：檔案系統可以鎖住檔案；S3 沒有鎖定機制。第三，**資料夾與路徑**：檔案系統有真正的目錄結構；S3 是扁平的 key 命名空間，沒有資料夾。理解這三點，你就不會再用「檔案開啟、修改、儲存」的流程去想 S3——更新物件，本質上就是「上傳新的，取代舊的」。

那如果某個專案就是需要真正的檔案系統語意呢？比如很多台伺服器要共用同一份檔案、要鎖定檔案、要就地修改。AWS 為這個場景準備了 **EFS（Elastic File System，彈性檔案系統）**：有目錄、有路徑，可以被多台機器當成一般磁碟掛載使用，解決 S3 天生做不到的需求。搞錯這兩個概念，架構選擇就會出錯——使用者上傳頭像、改版本，用 S3 就好；多台實例要即時共享並鎖定同一份設定檔，那是 EFS 的領域。先問自己「我要的到底是不是檔案系統行為」，再決定用哪個服務。
