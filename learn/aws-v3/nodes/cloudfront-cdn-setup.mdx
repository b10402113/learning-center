# CloudFront CDN setup

## Learning goal

Explain why S3 alone isn't enough, create a CloudFront distribution with custom domain and HTTPS.

## Steps

1. [[learn/aws-v3/nodes/cloudfront-cdn-setup/why-s3-is-not-enough|為什麼 S3 單獨不夠：三個硬限制]] — 看出 S3 靜態託管的限制，理解為何正式上線需要 CDN
2. [[learn/aws-v3/nodes/cloudfront-cdn-setup/cdn-concept-and-caching-tiers|CDN 是什麼：邊緣節點與快取階層]] — 建立 CDN 與快取階層的心智模型（after step 1）
3. [[learn/aws-v3/nodes/cloudfront-cdn-setup/create-cloudfront-distribution|建立 CloudFront Distribution]] — 動手建立 distribution，把 S3 bucket 設為 origin（after step 1）
4. [[learn/aws-v3/nodes/cloudfront-cdn-setup/custom-domain-and-https|自訂網域與 HTTPS]] — 綁定自有網域並用 ACM 憑證開啟 HTTPS（after step 3）

## Lesson

上一節的 S3 部署能讓網站「能看」，但還不到「能上線」。S3 靜態網站託管有三個硬限制：自訂網域沒有 HTTPS、無法設定 cache-control 標頭、內容只從單一區域送出。這三個限制剛好對應 CDN 要解決的問題——全球邊緣分發、可設定的快取、以及終端到終端的 HTTPS。

CloudFront 是 AWS 的 CDN，坐在 S3 前面當作一層分發與快取。這個節點從「為什麼需要它」開始，接著建立 CDN 的分層快取心智模型（邊緣節點 → 區域邊緣快取 → origin），然後動手建立 distribution 並把 S3 bucket 接為 origin，最後用 alternate domain name 綁定自有網域、用 ACM 憑證開啟 HTTPS。四步走完，你就能把自己的網站正式上線，也能向面試官解釋 S3 與 CloudFront 各自扮演的角色、快取階層為何存在，以及自訂網域與 HTTPS 的設定流程。
