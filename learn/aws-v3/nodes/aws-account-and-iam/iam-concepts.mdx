# IAM 概念與最小權限原則

## Learning goal

理解 IAM 的身份驗證與授權機制，讀懂一份 IAM policy 的 JSON 結構，並說出最小權限原則的實作意義。

## Lesson

IAM（Identity and Access Management）是 AWS 的中央門禁系統，回答兩個問題：你是誰（身份驗證）和你能做什麼（授權）。每一個 AWS 請求——無論是 Console 操作、CLI 指令還是 SDK 呼叫——都會先通過 IAM 的檢查。

IAM 有三種核心實體：User（長期身份，對應一個人或服務）、Group（使用者集合，共享權限）、Role（臨時身份，給 AWS 服務或外部程式用）。最佳實踐是把 policy 掛在 Group 上，讓新增使用者只需加入 Group 即可繼承權限。

Policy 是一份 JSON 文件，用 Effect（Allow/Deny）、Action（操作）和 Resource（目標資源）定義權限。最小權限原則要求只給每一個身份恰好足夠的權限——不多給。例如 CI/CD 機器人只需要 s3:PutObject 來放檔案進特定 bucket，不需要完整的 admin 權限。deny 規則永遠優先於 allow，這讓你可以建立一道安全網，即使其他 policy 允許了不該發生的操作。
