# MEMORY — agent-as-service

## Goal

把已有的 agent 工程能力變成收入：照這門課的 8 週路徑走完「定位 → 上線 → warm/cold outreach → 成交 → 交付 → 增長」，實際成交第一個付費客戶。

判準不是「讀完課程」，而是手上有真實痕跡：一個說得出 who/what 的一句話定位、一個真的上線的網站與公開貼文、發出去有回覆紀錄的 outreach 訊息、一份報價或提案，最後一份簽約或收款的證據。技術面（怎麼 build agent）不在本課範圍——那部分已由 agent-harness2、background-agents、agentic-engineer、claude-code-master、real-agent 覆蓋。

## Why

工程能力已經足夠，缺的是「賣」這一半：把 agent 從自己的工具變成別人付費的服務。這門課是驗證「賣服務」這條路是否適合自己的實驗——驗證通了，它就是離開純領薪工作的一條退路；沒通，也知道卡在哪一環。

## Prior experience

- TypeScript／Node.js 工程師，agent 工程已走過完整一輪：agent-harness2（durable loop、context 管理）、background-agents（durable runtime）、agentic-engineer（scope／ADR／verify）、claude-code-master（skills／routines／apps）、real-agent（跨 session 協作流程）、agent-harness（心智模型）。
- 每天用 Claude Code 與自寫 skill；能自己 build 出課程要交付的任何 agent demo，技術交付不是瓶頸。
- 沒有賣過服務：沒做過定位、報價、提案、合約、收款的實戰；cold outreach 完全沒碰過。
- 沒有經營過對外內容（社群貼文、inbound funnel），網路上沒有現成的個人品牌。

## Anchors

- warm 名單裡有具體人選：現任／前任同事、客戶、朋友中有人有業務痛點或本身是小型業主——Wk3 warm outreach 直接綁這份名單。
- 利基選內容／電商／行銷類業務：省時間的自動化對他們最直接可買。
- 「我會 build agent，但從來沒人為此付過錢」→ Wk1 的定位練習（who you help + what you do）就是第一次把工程能力翻譯成客戶語言。
- 課程的 milestone 貼文模板（#week1…#week8）→ 當成強制交付物：每個 tier 走完要有對應的真實產出，不是筆記。
- 課程資源裡的 skill kit（warm-outreach、Apollo、Instantly）和 YouTube Summarizer extension → 可以直接餵給自己的 agent 用，把「用 agent 跑業務」變成自己的場景。
- 課程反覆出現的數字（$10K MRR、freedom number、50% 預付、$3,000 productized offer）→ 每個都拿自己的數字重算一遍。

## Habits & constraints

- 每次 45–60 分鐘，一週 2–3 次（沿用既有節奏）；課程原設計 8 週，拉長成幾個月走，不追課程時程。
- macOS；網站、網域、社群帳號都願意真的開，但免費或低成本方案優先。
- 一次一小段，能跑起來比讀完更重要：一週的內容可以拆兩三篇文章，每篇對應一個真的要做的動作。

## Knowledge type

mixed，但**程序性主導**。市場事實（MSP 對照、YC 數據、定價行情）只學到能用；重心是動作——一句話定位怎麼講、50 個聯絡人名單怎麼建、訊息怎麼寫才像人、發現通話怎麼問、報價怎麼錨定、合約要抓哪六個點、交付後報告怎麼寫成續約的引子。

## How to teach me

- 先看失敗長相，再學機制：沒人回的 outreach 長怎樣、被嫌貴的報價長怎樣、範圍蔓延（scope creep）的合約長怎樣。
- 每個框架立刻綁到要發出的真實產物：DOTS 綁下一次發現通話的問題清單，定價課綁給 warm 名單裡某個人的報價。
- 名詞保留英文（AaaS、MSP、retainer、warm/cold、BIT、hypercare、MRR），不要硬翻；不要名詞堆疊。
- 業務教材容易雞湯——保留課程的腳本與數字，砍掉重複的激勵段落，每篇文章以「讀完你要做的那個動作」收尾。
- 已經會的技術內容一句話帶過；篇幅留給從沒做過的商業動作。
