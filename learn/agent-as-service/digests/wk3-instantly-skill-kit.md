# L1 overview

- RoboLabs knowledge file for AI agents covering Instantly.ai for cold email at scale: campaign creation, lead imports from Apollo/CSV/API, warmup management, deliverability monitoring, automated follow-ups, and pausing underperforming campaigns.
- Core thesis: deliverability is everything — domain setup (separate sending domains, SPF/DKIM/DMARC, custom tracking domain) and warmup (minimum 2 weeks, ideally 4) matter more than copy.
- Includes the 3-step campaign structure (value-first opener → 3–5 day bump → 7–10 day break-up), recommended settings (30–50/inbox/day, text only, stop on reply), metric targets and pause triggers, spam triggers, 2025+ Gmail/Yahoo bulk-sender rules, agent prompt library, webhooks/Zapier integrations, and a full V2 API reference.

# L2 detail

- `#L78-L148` — Domain & email setup (flagged as the most important section): Rule #1 never send from your primary business domain — buy tryyourbrand.com-style variants; domain counts (2–3 starting, 5–10 scaling, 20–40 aggressive) and the math that each domain holds 3 accounts × ~40 emails/day, so 3 domains ≈ 360 emails/day; real-sounding mailbox names (john@, sarah@ — not sales@, info@, noreply@); the non-negotiable DNS records table (SPF, DKIM, DMARC) plus a custom tracking domain CNAME; warmup schedule table (Week 1: 5–10/day, Week 2: 20–40, Week 3–4: 40–50), minimum 2 weeks and 4 safer, never disable warmup, 70/30 warmup-to-cold split for new accounts, and 80%+ primary-inbox placement before launching.
- `#L149-L197` — Importing leads: the Apollo→Instantly field-mapping table; CSV import columns (email required, extra columns become custom variables); API bulk add of up to 1,000 leads per call to `POST /api/v2/leads/bulk` needing `campaign_id` or `list_id`; list hygiene — verify emails, dedupe, remove catch-all domains, check the block list, target near-zero bounces and pause above 2%.
- `#L198-L298` — Creating campaigns: the recommended 3-step structure (Email 1 value-first opener, Email 2 follow-up bump at 3–5 days, Email 3 break-up at 7–10 days; more than 3–4 steps rarely helps); settings table (daily_limit 30–50/inbox, stop_on_reply true, text_only true, link_tracking false, open_tracking true, schedule 9am–5pm Mon–Fri); verbatim example copy for all three emails; personalization variables (`{{firstName}}`, `{{companyName}}`, custom `{{title}}`/`{{city}}`) — even adding companyName lifts response rates; A/B testing guidance (subject lines drive opens, opening lines drive replies, CTAs drive conversion; ≥100 sends per variant).
- `#L299-L380` — Monitoring and sending best practices: metric table (open 50%+/below 30%, reply 5%+/below 1%, bounce under 2%/above 5%, spam complaints under 0.1%/above 0.3%) with actions; pause immediately on >2% bounce, >0.1% complaints, sudden open-rate drop, or a flagged account; API analytics endpoints (campaign/daily/step/account level); volume rules — cap 30–50 emails/inbox/day, scale by adding inboxes not pushing harder, Instantly rotates accounts automatically, business-hours sending, no spikes; spam trigger table (HTML, multiple links, images, bit.ly shorteners, shared tracking domain, spikes, hype words, missing unsubscribe); compliance — 2025+ Gmail/Yahoo bulk-sender rules (5,000+/day to Gmail: <0.3% complaints, <2% bounces, 2-day unsubscribe honoring, RFC 8058 one-click headers) and CAN-SPAM/GDPR/Spam Act summaries.
- `#L381-L472` — Account management and integrations: account actions table (list, enable/disable warmup, pause, check vitals) with agent prompts; block list uses (competitors, existing clients, opt-outs, irrelevant domains); five ready-to-use agent prompts (from-scratch setup, campaign creation, Apollo import, performance check, deliverability troubleshooting, scaling 100→500 emails/day); webhooks on Hypergrowth+ (email_sent, email_opened, reply_received, email_bounced, lead_unsubscribed, campaign_completed) and native Zapier/Make/n8n integrations with common automation recipes.
