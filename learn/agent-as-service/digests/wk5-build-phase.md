# L1 overview

- Jay teaches the first phase of the Build-Integrate-Tune (BIT) delivery framework: building the MVP. The goal is speed — get something working, demo it on a client call, and collect feedback before investing deeper.
- Recommended workflow: feed the signed proposal PDF into an agentic platform (anti-gravity or Claude Code), let it break down requirements, suggest an approach, and start building; always build the one core functionality first (the "80% of intended impact" feature).
- A worked example shows a lead-generation website-redesign pipeline (Texas salon/spa leads, Gemini 2.5 Pro redesigns, free Vercel deploys, automated cold-email with live link) built in anti-gravity.
- Demos deliver three things: early feedback, client involvement (the "money's worth" psychology, illustrated by the $50 book anecdote), and clarity for clients who only know ChatGPT. Close with under-promising/over-delivering: under-commit (e.g. commit to 70 customers when you can get 100) to build reputation and leverage.

# L2 detail

- `#L1-L140` — Module intro and why speed matters: the BIT framework recap (Build, Integrate, Tune), the MVP definition ("not perfect, but working"), and the warning that finishing 100% without client involvement usually misses spec because clients themselves don't yet know what they want in the emerging AI-agent space.
- `#L141-L276` — The recommended starting move: open an agentic platform (anti-gravity or Claude Code, the ones taught in the community's technical courses), feed it the proposal PDF, and have it walk through possible build approaches; AI models know the latest automation stacks, so let them break down requirements, suggest an approach, and start building. Core-first rule: ask "what's the one thing this needs to do?", build that first, work backwards — simplicity is your friend, and bells-and-whistles-first risks not fitting client requirements.
- `#L277-L396` — Concrete example: a partner pipeline finding Texas salon/spa leads with unoptimized websites, using Gemini (called "Geminitary.1 Pro" in the transcript) to programmatically improve the sites, showing before/after. The pipeline was built in anti-gravity: crawl web for leads → Gemini redesigns the site → deploy to Vercel free → automated cold-email sequence with the live link, which feeds the partner (a website redesign firm) new leads. MVP focus = a clear graphic illustrating the process to the client, not extensions like broader geography, full websites, or real-domain deploys.
- `#L397-L500` — Anti-feature discipline (don't extend beyond Texas, don't build whole sites, don't deploy to actual domains — Vercel's free program is the trick), then the demo method: share your screen, walk through what it does with a visual diagram of what the AI agent does, before any integration with the client's system.
- `#L501-L632` — The three things a demo achieves. (1) Early feedback: better to learn something's wrong now than after full integration. (2) Client involvement: turnkey handovers make clients feel they didn't get their money's worth — illustrated with the publishing rule that one simple idea gets padded to 200–300 pages with anecdotes so people will pay $50 for the book. (3) Clarity: most clients aren't tech-savvy; the only AI they've seen is ChatGPT, so a demo clarifies intent. Includes the three demo questions: "Does this solve the problem we discussed?", "Is there anything missing?", "What would make this more useful?" — plus document everything (notes, recorded calls, Fathom or Fireflies for AI notes).
- `#L633-L872` — Simplicity philosophy ("if you can't explain something simply, you don't understand it deeply"; simple solutions are better appreciated, foster the relationship, and win more projects from the client and their network) and the over-engineering warning for technical backgrounds: in the MVP phase it's better to ship and show, iterate later. Then expectation management: under-promise/over-deliver is a game of expectation — deliver a two-week commitment in one week and it builds reputation, leverage, and the relationship; anchoring (from the pricing module) matters; when choosing, always under-commit (commit to 70 customers if you can get 100, then deliver 100 — the over-delivery will be remembered).
- `#L873-L901` — Module summary: create the MVP using agentic tools (the strongest leverage available now), show a demo, get feedback, document everything, keep it simple. Teaser for module two: the integrate phase, moving the solution from your staging environment into the client's systems.
