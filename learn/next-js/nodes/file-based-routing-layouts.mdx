# 檔案式路由、layout 與 route groups

## Learning goal

能由 URL 反推檔案樹，正確使用 nested / dynamic / route groups / layout，並判斷 AI 給的路由結構是否會產生錯誤的 URL 或重複的 layout。

## Steps

閱讀順序（deps 決定誰必須先出現）：

1. [[learn/next-js/nodes/file-based-routing-layouts/folders-are-routes|資料夾就是路由：page.tsx 與巢狀路由]] — 由 app/ 的資料夾與 page.tsx 反推 URL，理解為什麼不需要 router 套件。
2. [[learn/next-js/nodes/file-based-routing-layouts/dynamic-segments-and-params|動態路由：用 [id] 吃下不確定的 URL]] — 建立 `[id]` 動態段、從 `params` 取得變動值，取代複製貼上的多個頁面（需先完成 step 1）。
3. [[learn/next-js/nodes/file-based-routing-layouts/nested-layouts|layout.tsx 疊層：root layout 與區塊外框]] — children 插槽、root layout 的必要性、巢狀 layout 由外到內套疊（需先完成 step 1）。
4. [[learn/next-js/nodes/file-based-routing-layouts/route-groups|route group：何時該分組、何時不該]] — 判斷用一般巢狀資料夾還是 `(group)`，以及它為什麼能不進 URL 卻擁有自己的 layout（需先完成 step 3）。
5. [[learn/next-js/nodes/file-based-routing-layouts/reading-a-route-tree|由 URL 反推檔案樹：抓出 AI 路由結構的錯]] — 把前四步變成驗收動作，互相反推 URL 與檔案樹、抓出錯誤路徑與重複 layout（需先完成 steps 2、4）。

## Lesson

App Router 的路由表不是另外寫在設定檔裡，而是直接長在資料夾樹上：`app/` 底下的一個資料夾代表一段 URL，裡面的 `page.tsx` 代表那段網址要顯示的畫面。資料夾可以一層一層疊，於是 `/dashboard/users` 就對應 `app/dashboard/users/page.tsx`；資料夾名稱換成 `[id]` 時，它就變成吃任意值的動態段，實際值從 `params` 讀進來。這一套規則讓 Next.js 不必安裝 router 套件，也讓「改網址結構」和「改檔案路徑」變成同一件事。

畫面外框則由 `layout.tsx` 負責。root layout 是唯一必要的 layout，它用 `children` 插槽把所有頁面接進 `<html>`／`<body>` 之間，於是字型、provider 這種全站關注點只寫一次。往下一層，任何資料夾都能再放一個 `layout.tsx`，替那個子樹加上自己的外框；它們是層層套疊，不是互相取代——最外層管全站，中層管區塊，最內層才是頁面。

真正的判斷力出現在 route group。把資料夾名稱包進括號，例如 `(auth)`、`(root)`，它就只做檔案分組、不進 URL。這個小心機讓你可以把「檔案怎麼分堆」和「網址長怎樣」拆開：登入註冊放進 `(auth)`，網址仍是乾淨的 `/sign-in`，而 `(auth)` 可以擁有和 `(root)` 完全不同的 layout。反之，如果只是想要 `/auth/sign-in` 這個網址，就該用普通巢狀資料夾，不該用括號。

五步走完之後，你應該能看著一串 URL 畫出 `app/` 的檔案樹，也能反過來看著 AI 給的檔案樹講出每個頁面的網址，並一眼抓出兩類常見錯誤：括號用錯導致網址多一段或不見了，以及兩個路由解析到同一條路徑、或 layout 被重複套了兩層。
