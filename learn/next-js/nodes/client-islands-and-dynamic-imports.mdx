# Client 邊界陷阱與 client-only 套件

## Learning goal

能判斷 `"use client"` 是否被濫用、哪些第三方套件（MDX editor、next-themes）必須隔離成 client island 或 dynamic import（ssr:false），以及會不會把 server component 拉進 client bundle。

## Steps

閱讀順序（deps 決定誰必須先出現）：

1. [[learn/next-js/nodes/client-islands-and-dynamic-imports/use-client-boundary-contagion|"use client" 的傳染性：邊界是怎麼擴散的？]] — 看懂 `"use client"` 是「整棵子樹」的標記，被它引入的模組（含 server component）都會被打包進 client bundle。先建立「邊界會擴散」的心智模型。
2. [[learn/next-js/nodes/client-islands-and-dynamic-imports/client-only-packages|client-only 套件：為什麼 MDX editor 與 next-themes 不能直接在 server 跑？]] — 辨認哪些第三方套件是 browser-only，說明它們為何在 server render 出錯，以及為什麼正解是隔離成 client island（需先完成 step 1）。
3. [[learn/next-js/nodes/client-islands-and-dynamic-imports/dynamic-import-ssr-false|用 `next/dynamic` + `ssr:false` 隔離 browser-only 元件]] — 把 step 2 的診斷化為手法：用 `next/dynamic` + `ssr:false` 載入 MDX editor，並接上 react-hook-form（需先完成 step 2）。
4. [[learn/next-js/nodes/client-islands-and-dynamic-imports/audit-client-boundaries|驗收 AI 的 client 邊界：一張檢查表]] — 把前三步變成可操作的判別問句與反例，拿到任何 AI 元件樹都能驗收邊界（需先完成 steps 1–3）。

## Lesson

上一課建立了「一大片 server shell、點綴幾座 client island」的畫面。這一課要看的是這個模型最會出錯的地方：邊界。React Server Components 把 server 與 client 分開，但這條線不是畫在元件上而已——它會沿著 import 往外擴散。一行 `"use client"` 代表「從這個檔案開始的整棵子樹都算 client code」，凡是從這裡被 import 進來的模組，包括你以為還在 server 的元件與第三方套件，都會一起被打包進瀏覽器。多數「AI 寫的架構看不出問題、跑起來卻變慢」的案例，根因就藏在這條線畫錯位置。

這個節點分四步走。第一步先把「傳染」的機制講清楚：為什麼 `"use client"` 掛太高會把整棵樹拖進 client，以及為什麼你不能在 client component 裡 import 一個 server component。第二步換個角度看：有些套件（像瀏覽器限定的 MDX editor、靠瀏覽器存主題的 next-themes）本身就不可能在 server 上跑，一出現在 server 樹裡就會出事——但錯的不是套件，而是你把它放在了不該放的位置。第三步給出標準手法：用 `next/dynamic` 搭配 `ssr:false` 把這種 browser-only 元件隔離成一座真正的 client island。最後一步把前三步收斂成一張驗收表，讓你拿起任何一份 AI 產出的元件樹，都能當場回答「這行 `"use client"` 該不該在、這個套件有沒有漏掉 dynamic import、有沒有 server component 被偷偷拉進 client bundle」。

學完之後，你看待 AI 產出的眼光會多一層：不只問「功能對不對」，而是問「這條邊界畫在哪、代價是什麼」。這正是本門課要培養的判斷力。
