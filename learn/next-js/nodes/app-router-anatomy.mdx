# App Router Anatomy

## Learning goal

看懂一個 Next.js 專案的每個檔案在做什麼（`app/`、`layout`/`page`、`children`、config），並知道新程式碼該放哪。

## Steps

1. [[learn/next-js/nodes/app-router-anatomy/scaffold-and-top-level-map|create-next-app 產出什麼？專案頂層地圖]] — 認識 scaffold 與每個頂層檔案、資料夾的用途
2. [[learn/next-js/nodes/app-router-anatomy/layout-page-and-children|app/ 的核心：layout、page 與 children]] — 看懂 `layout` 包住 `page`、`children` 注入內容的渲染樹（after step 1）
3. [[learn/next-js/nodes/app-router-anatomy/run-and-fast-refresh|把專案跑起來：dev server 與 Fast Refresh]] — 啟動 dev server，邊改檔案邊看到畫面更新（after step 1）
4. [[learn/next-js/nodes/app-router-anatomy/where-new-code-goes|新程式碼該放哪？檔案配置的抉擇]] — 拿到需求時判斷它該進哪個檔案或資料夾（after steps 1–3）

## Lesson

這一節的目標很具體：把一個 `create-next-app` 生出來的專案攤開，讓你指著每個檔案說得出「它是幹嘛的、為什麼在這裡」。這件事之所以重要，是因為 AI 生成專案時最常被忽略的，往往不是語法錯誤，而是東西放錯位置——把該全域的導覽列寫進某個 `page`、把靜態圖片塞進元件資料夾、把 provider 掛在錯誤的層級。只要你能在腦中畫出「哪個檔案影響哪些路由」的樹狀圖，就有能力在幾秒內判斷一份陌生專案的結構對不對。

課程分四步。先建立頂層地圖，認得 scaffold 產出的設定檔、`public/`、`node_modules/` 與最重要的 `app/`。接著鑽進 `app/`，把三個核心檔案的角色分清楚：`layout.tsx` 是包住整棵子樹的外框、`page.tsx` 是某一條路由的內容、`globals.css` 放跨頁面的樣式，而 `children` 就是把這些拼起來的那條線。第三步親手把專案跑起來，用 dev server 與 Fast Refresh 驗證「改哪裡、畫面哪裡變」。最後用一個配置決策步驟收尾：面對一個新需求，先問「它會出現在幾條路由上、屬於誰」，再決定檔案該放哪。

走完這一節，你應該能在任何一個 App Router 專案裡自在走動，並且在下一次看 AI 產出的資料夾結構時，一眼指出東西放錯位置的地方。
