# 事件發生就更新：revalidatePath 與 revalidateTag

<LearningGoal>
能在 server action 裡寫出 `revalidatePath` 與 `revalidateTag`，從 `next/cache` 匯入，並依「改的是哪個路徑」或「改的是哪類資料」正確選用路徑或標籤來作廢快取。
</LearningGoal>

## Lesson

on-demand revalidation 是在資料變動的那一刻主動作廢快取：`revalidatePath` 點名一個路徑、`revalidateTag` 作廢一個標籤，兩者都從 `next/cache` 匯入，且只放在寫入成功之後、每條改資料的分支都要放；它們只是標記要重做，不是立刻重算。
