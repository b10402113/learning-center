# 資料不更新，到底卡在哪一層？

<LearningGoal>
拿到「資料不更新」「改了資料頁面沒反應」「同一份資料被重複抓」的程式碼時，能逐層判斷它卡在哪一層快取，並選出對的修正。
</LearningGoal>

## Lesson

「資料不更新」是一組散在四層快取任一層的症狀，診斷時先問「這是同一輪 render 的重複，還是跨請求的舊資料」，再看伺服器端或瀏覽器端、來源是 fetch 還是 DB，最後檢查寫入後有沒有作廢、以及 API GET 是否被預設快取，而不是逢舊就加 `no-store`。
