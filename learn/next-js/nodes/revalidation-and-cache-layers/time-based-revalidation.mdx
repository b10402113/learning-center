# 時間到了才更新：time-based revalidation

<LearningGoal>
能解釋 `revalidate` 的數值、`false`、`0` 各代表什麼，並分辨 page-level route segment config 與 per-fetch `next.revalidate` 的範圍差別。
</LearningGoal>

## Lesson

time-based revalidation 用 `revalidate` 設定「資料最多放多久」：數字代表秒數、`0` 等同不快取、`false` 等同盡量永久保留；寫在頁面最上層管整個 route，寫在單支 fetch 裡只管那一筆資料，實際運作是「先給舊的、背景再重算」，所以新資料會慢一步。
