# 元件組合模式：server shell + client island

## Learning goal

能用 server shell + client island 組裝畫面，辨認哪些元件該維持 server、哪些 leaf 才需要 client，並看出 props-in / JSX-out 的純元件。

## Steps

閱讀順序（deps 決定誰必須先出現）：

1. [[learn/next-js/nodes/component-composition-patterns/server-shell-client-island|server shell + client island：一個畫面是怎麼拼起來的]] — 建立「整頁 server 外框、局部 client 小島」的心智模型，知道為什麼不是整頁掛 client。
2. [[learn/next-js/nodes/component-composition-patterns/presentational-components|props-in / JSX-out：不需要 "use client" 的純展示元件]] — 用 `QuestionCard` 看懂只吃 props、吐 JSX 的純元件，以及它為什麼能留在 server（需先完成 step 1）。
3. [[learn/next-js/nodes/component-composition-patterns/generic-renderer-composition|用一個泛型 renderer 收斂列表畫面：DataRenderer 的 render prop]] — 把 success / error / empty / 有資料四種狀態收進一個泛型元件，再在 server shell 裡組出整個列表（需先完成 steps 1–2）。
4. [[learn/next-js/nodes/component-composition-patterns/boundary-placement-decision|邊界該畫在哪裡：哪些元件留 server、哪些下沉成 client island]] — 把前三步變成可操作的判別問句與反例，拿到任何元件都能決定邊界（需先完成 steps 1–3）。

## Lesson

React Server Components 改寫了「畫面怎麼組」這件事。過去整頁都是一個 client bundle，現在預設所有元件都住在 server，只有真正需要互動的那幾塊才被標記成 client。於是組裝一個畫面的方式，從「一頁一個大元件」變成「一大片 server 外框，點綴幾座 client 小島」。

外框（shell）通常是 async 的 server component：它負責抓資料、跑邏輯、決定版型，把結果一路往下傳。它底下大多數是所謂的純展示元件——吃進 props、吐出 JSX，沒有 state、沒有事件、不碰瀏覽器 API，因此完全不需要 `"use client"`，也不會把 JavaScript 送進瀏覽器。真正需要互動的葉節點（投票按鈕、篩選器、編輯器）才被下沉成 client island，範圍越小越好。

把這個模式講清楚，靠的是三種能力。第一是看整體：理解 server shell 與 client island 的分工與理由。第二是認純元件：看到一個 `props-in / JSX-out` 的元件，就知道它可以安全地留在 server。第三是做判斷：拿到任何一個元件，能用判別問句決定它該不該跨過邊界，並認出把 `"use client"` 掛太高、或把 server component 硬塞進 client 這兩種常見錯誤。這個節點教的不是背 API，而是看懂 AI 產出的元件樹裡，哪一塊該是 server、哪一塊該是 client。
