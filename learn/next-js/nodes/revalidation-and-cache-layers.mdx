# Revalidation 與多層快取

## Learning goal

能區分 time-based 與 on-demand revalidation（revalidatePath / revalidateTag）、React cache 與 unstable_cache，並指出「快取放錯」導致資料不更新的根因。

## Steps

1. [[learn/next-js/nodes/revalidation-and-cache-layers/cache-layers-overview|多層快取：四層快取各自的壽命與範圍]] — 分清楚 Request Memoization、Data Cache、Full Route Cache、Router Cache 各活多久、管什麼，以及 revalidation 到底在刷哪一層
2. [[learn/next-js/nodes/revalidation-and-cache-layers/time-based-revalidation|時間到了才更新：time-based revalidation]] — 讀懂 `revalidate` 的數值、`false`、`0`，並分辨 page-level 與 fetch-level 的範圍差別（after step 1）
3. [[learn/next-js/nodes/revalidation-and-cache-layers/on-demand-revalidation|事件發生就更新：revalidatePath 與 revalidateTag]] — 在 server action 裡用 `revalidatePath` / `revalidateTag` 精準作廢快取，而不是等時間到（after step 1）
4. [[learn/next-js/nodes/revalidation-and-cache-layers/unstable-cache-and-react-cache|非 fetch 的資料要自己包：unstable_cache 與 React cache]] — 看懂 `unstable_cache` 跨請求持久、`React.cache()` 只管單輪 render，以及 tag 如何把兩者接上 `revalidateTag`（after steps 1、3）
5. [[learn/next-js/nodes/revalidation-and-cache-layers/diagnose-stale-data|資料不更新，到底卡在哪一層？]] — 用判別問句從症狀反推是哪一層快取的錯，選出正確修正（after steps 1–4）

## Lesson

「快取」在 Next.js 裡不是一個開關，而是一疊各自獨立運作的層。同一個頁面從請求進來到畫面出來，中間可能穿過四層快取：只管單輪 render 的 Request Memoization、跨請求存資料的 Data Cache、把整個 page 結果存下來的 Full Route Cache，以及在使用者瀏覽器裡管換頁的 Router Cache。每一層的壽命、範圍、由誰驅動都不一樣，而「資料不更新」的根因，十之八九是把某一層的職責記到另一層頭上。

這一疊層最容易被搞混的是「快取」和「更新快取」是兩件事。有了快取，資料就會舊；要讓它變新，得靠 revalidation。revalidation 有兩條路：一條是 time-based，也就是設定 `revalidate`，時間到了才去重算；另一條是 on-demand，也就是在資料真的變動的那一刻，主動呼叫 `revalidatePath` 或 `revalidateTag` 把對應的快取作廢。前者不需要你盯著事件，代價是資料可能舊一段時間；後者即時，代價是你得在每個寫入點自己想清楚要作廢哪個路徑或哪個標籤。

還有一層常被忽略的差異：`fetch` 之外的資料沒有自動快取。當資料來自直接查資料庫、呼叫 ORM 或 server action 時，Next.js 不會幫你存，你得自己用 `unstable_cache` 把它包成跨請求的快取，或至少用 React 的 `cache()` 把同一次 render 裡的重複呼叫收斂掉。`unstable_cache` 能存活到跨請求、能用 tag 接上 `revalidateTag`；`React.cache()` 則只活在單輪 render。把這兩者的壽命分清楚，才不會寫出「以為它會跨頁快取、結果每次都重查」的程式。

走完這五步，你要練的是反向診斷：看到「資料幾分鐘後還是舊的」「改了資料頁面沒反應」「同一份資料被打了兩次」這類症狀，能一層一層問下去，指出它卡在哪一層，然後選對修正——而不是逢快取就加 `no-store`，或逢舊資料就亂加 `revalidate`。
