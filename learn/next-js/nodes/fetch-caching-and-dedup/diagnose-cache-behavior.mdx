# 這段 fetch 的快取行為符合預期嗎？

<LearningGoal>
拿到一段「資料不更新」或「同一份資料被重複抓」的程式碼時，能逐層判斷它卡在哪一層快取，選出對的修正（`no-store`、`revalidate`、`force-dynamic`、`React.cache`），並判斷症狀是不是預期行為。
</LearningGoal>

## Lesson

判斷快取問題的順序是先看壽命（跨請求或單輪 render）、再看來源（fetch 或非 fetch）、最後才看新鮮度需求，據此選出 revalidate、no-store、force-dynamic 或 React.cache 等對應修正。
