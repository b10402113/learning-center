# Server vs Client Components

## Learning goal

對任一元件判斷它該是 Server 還是 Client Component，並說出 `"use client"` 邊界對 bundle、SEO、安全與依賴的後果。

## Steps

1. [[learn/next-js/nodes/client-server-components/why-component-level-rendering|為什麼選擇要落到元件層級？]] — 從 Next.js 13 之前「SSR 只能做在整個路由頁面」的限制，看見 app directory 為什麼要把選擇權下放到單一元件
2. [[learn/next-js/nodes/client-server-components/server-vs-client-anatomy|Server Component 與 Client Component 到底是什麼？]] — 說出兩種元件各自在哪裡執行、預設是哪一種，並用 console.log 實驗當場分辨（after step 1）
3. [[learn/next-js/nodes/client-server-components/the-use-client-boundary|「use client」這條線劃在哪裡？]] — 解釋 `"use client"` 如何把整個模組連同它 import 的東西標成 client 程式碼，以及為什麼不能在 Client Component 裡塞 Server Component（after step 2）
4. [[learn/next-js/nodes/client-server-components/choosing-component-type|這個元件該放 Server 還是 Client？]] — 用「需不需要瀏覽器互動？」一個問題，對任一元件做出可辯護的判斷（after steps 2–3）
5. [[learn/next-js/nodes/client-server-components/boundary-consequences|邊界畫在哪，會付出什麼代價？]] — 從 bundle、SEO、安全與依賴四個角度，檢查 `"use client"` 邊界劃得對不對（after steps 3–4）

## Lesson

這一節要回答的，是 Next.js 裡最常被 AI 寫錯、也最值錢的一個判斷：手上這個元件，該在伺服器跑還是在瀏覽器跑？很多人把它背成一句「需要互動就加 `"use client"`」，結果專案照樣出問題——bundle 無聲膨脹、密鑰被推進瀏覽器、本來能靜態化的頁面被拖成純客戶端渲染。要避免這些，不能只背口訣，得先弄清楚這條線為什麼存在、它把什麼東西切開、切錯會發生什麼事。

課程沿著五步推進。第一步先回到 Next.js 13 之前，看「伺服器渲染只能做在整個路由頁面」的限制如何造成 prop drilling 與重複抓資料，理解 app directory 為什麼要把選擇權下放到單一元件。第二步定義兩種元件：Server Component 與 Client Component 各在哪裡執行、預設是哪一種，並用 console.log 出現在終端機還是瀏覽器，讓你親眼分辨。第三步拆解 `"use client"` 這條邊界最容易被誤解的地方——它不是標記一個元件，而是標記整個模組，凡是 import 進來的東西都會被一起拉進 client bundle。有了機制，第四步才談應用：用「它需不需要瀏覽器互動？」這一個問題做出判斷。最後一步把代價攤開，從 bundle、SEO、安全與依賴四個角度，給出一條能當場用的邊界檢查規則。

走完這一節，你手上會有一條判斷準則：先問這個元件「在哪裡执行才對」，再決定 `"use client"` 該不該加、加在哪一層。
