# after()：把副作用延到回應之後

<LearningGoal>
能判斷一個副作用該用 `after()`、直接 await、`Promise.all` 還是 client 端執行，並說出以 view counter 為例時每種選擇的取捨。
</LearningGoal>

## Lesson

把副作用放哪裡取決於它該不該擋住回應：會改變當下畫面或需要修改回應的必須留在渲染路徑上，獨立的請求可用 `Promise.all` 平行化但仍然擋路，只有不改變畫面、不改回應、使用者也不等它的副作用才適合交給 `after()` 排到回應之後——以 view counter 來說，要最快選 `after()`，要即時數字選直接 await。
