# Routing as a Filesystem

## Learning goal

由資料夾結構推導出完整路由樹（static/nested/dynamic/route groups/nested layouts），並解釋 params 的來源。

## Steps

1. [[learn/next-js/nodes/file-based-routing/folders-are-routes|資料夾就是路由：檔案路由的第一條規則]] — 資料夾定義 URL 區段、page 檔定義 UI，取代 React Router 的設定
2. [[learn/next-js/nodes/file-based-routing/nested-routes-and-layouts|巢狀路由與巢狀 layout]] — 巢狀資料夾產生巢狀 URL，每層 layout 用 children 串成外框鏈（after step 1）
3. [[learn/next-js/nodes/file-based-routing/dynamic-segments-and-params|動態區段與 params]] — 用 `[param]` 讓一個 page 服務無限 URL，並讀出 params（after step 2）
4. [[learn/next-js/nodes/file-based-routing/route-groups|Route Groups：組織檔案，但不進 URL]] — 用 `(name)` 分組與套用群組 layout，同時保持 URL 不被污染（after step 2）
5. [[learn/next-js/nodes/file-based-routing/reading-the-route-tree|實戰：從資料夾樹推導完整路由樹]] — 拿真實專案的 app/ 樹，走一遍推導流程（after steps 3–4）

## Lesson

Next.js 的 App Router 把「路由表」這件事從程式碼裡拿掉，改成由資料夾結構本身承載。資料夾階層決定 URL 的區段，`page.tsx` 決定那個區段的介面，`layout.tsx` 則提供包住一段子樹的共用外框。這個節點帶你建立一套可以反覆套用的推導方法：看到任何一棵 `app/` 資料夾樹，都能在腦中還原出完整的路由樹、每個 URL 由哪些資料夾疊出來、以及哪裡會套上哪一層 layout。先掌握最基本的「資料夾即路由」，再往上疊巢狀路由與巢狀 layout，接著學會動態區段與 `params` 的來源，最後用 route group 把「檔案怎麼分類」和「URL 長什麼樣」這兩件事拆開。
