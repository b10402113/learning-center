# Why Next.js

## Learning goal

說得出 Next.js 相對純 React/vanilla 解決了什麼問題，以及它的代價。

## Steps

1. [[learn/next-js/nodes/why-nextjs/before-nextjs-evolution|Next.js 之前：Web 工具鏈怎麼一路演進]] — 認識 vanilla → jQuery → Angular → Node → React 的演進，以及每一代為了解決什麼問題而出現
2. [[learn/next-js/nodes/why-nextjs/framework-vs-library|什麼是 Framework？React 留下的坑與 Next.js 的角色]] — 分辨 framework 與 library，看懂 Next.js 蓋在 React 之上補了什麼（after step 1）
3. [[learn/next-js/nodes/why-nextjs/what-nextjs-buys-you|Next.js 到底幫你買到什麼]] — 省工具、全端、效能、SEO 四類回報各自對應什麼問題（after step 2）
4. [[learn/next-js/nodes/why-nextjs/when-not-to-use-nextjs|代價與時機：什麼時候不該用 Next.js]] — 在「用它」與「不用它」之間做出可辯護的選擇（after steps 1–3）

## Lesson

這一節要回答的問題很直白：都已經有 React 了，為什麼還要多學一個 Next.js？如果只背下「Next.js 比較好」，你日後會無法判斷 AI 生成的架構哪裡對、哪裡多餘；唯有先看清楚它「從哪裡來、替誰補洞、要付什麼代價」，才有本事對架構做取捨。

課程沿著四個步驟推進。先回到 Next.js 出現之前的時間線，看每一代工具如何為了解決上一代的痛點而誕生。接著把「框架」與「函式庫」分開，理解 Next.js 其實是蓋在 React 之上的一層框架。然後具體拆解它替你買到的四類回報：省下工具配置、把前後端收進同一個專案、改善效能、解決 SEO。最後一步刻意唱反調，把代價與不適用的情境攤開——小專案、只想練 React、不想被框架慣例綁住的時候，答案可能是不用。

走完這一節，你手上會有一條判斷準則：先問「這個專案痛在哪」，再決定 Next.js 是不是那帖藥。
