# Next.js 作為 framework：加在 React 上的那一層

## Learning goal

能說出 Next.js 相對 React 多加了哪幾層（routing、rendering、data、backend、metadata），以及 framework vs library 的差別，判斷一個 Next.js 專案在哪些地方比純 React「多做了事」。

## Steps

這條 DAG 先分清楚 library 與 framework 的角色，再問 React 獨自使用時漏掉了什麼，接著把 Next.js 補上的那幾層一層一層攤開，最後把這些認識變成可以對著真實專案用的判斷力。

1. [[learn/next-js/nodes/framework-mental-model/framework-vs-library|Library 還是 framework？Next.js 加在 React 上的那一層]] — 說出 library 與 framework 的差別（誰呼叫誰、控制反轉），以及 Next.js 如何加在 React 上而不是取代它。
2. [[learn/next-js/nodes/framework-mental-model/why-nextjs-exists|React 不夠用在哪？Next.js 為什麼會出現]] — 說出 React 單獨用時留下的缺口，以及 Next.js 為什麼出現、補了什麼（after step 1）。
3. [[learn/next-js/nodes/framework-mental-model/layers-nextjs-adds|Next.js 多出來的五層：routing、rendering、data、backend、metadata]] — 列出 Next.js 相對 React 多出來的每一層，並指出對應的檔案或 API（after steps 1–2）。
4. [[learn/next-js/nodes/framework-mental-model/judging-nextjs-value|怎麼看一個專案「多做了事」：Next.js vs 純 React 的判斷]] — 對著一段 code 或檔案樹，判斷哪些是 Next.js 多做的事、哪些只是一般 React（after steps 1–3）。

## Lesson

React 本身只負責一件事：把元件描述的 UI 畫出來、並在狀態改變時更新畫面。它不管你的網址怎麼對應到頁面、資料要在哪裡抓、後端 API 放哪裡、搜尋引擎看不看得到首屏。這些「專案一定會碰到、但 React 故意不碰」的問題，純 React 專案得自己一個一個拼裝工具來解決。

Next.js 就是為了填這個洞而出現的框架。它不是新的語言、也不是取代 React 的函式庫，而是把 React 包在中間，額外規定了一整套慣例與內建功能：檔案即路由、多種渲染策略、伺服器端抓資料與快取、同一份專案裡的後端端點，以及中繼資料管理。所謂「framework」，關鍵在於它掌控了流程的主導權——不是你去呼叫它，而是它呼叫你寫的元件與函式，並決定什麼時候、在哪一層執行。

這個節點要建立的是最上層的心智模型：先看清楚 library 與 framework 的角色差異，再理解 React 的缺口如何催生 Next.js，然後把 Next.js 多出來的層數一數、記住各自對應的檔案與 API，最後練習對著真實專案判斷「這件事是 Next.js 幫我做的，還是我自己得處理的」。有了這張地圖，後面每一層的細節才有地方掛靠。
