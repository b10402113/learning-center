用 next/dynamic 與 ssr:false 隔離 browser-only 元件

Step 3/4 · Client 邊界陷阱與 client-only 套件

這一節要完成什麼

如果表單裡放了需要 DOM 的 MDX editor，光在檔案頂端加上 "use client" 還不夠。你還需要避免它在伺服器端被預先渲染，否則 build 時可能遇到 window is not defined。

這一節會把編輯器隔離到瀏覽器端，並完成它與 react-hook-form 的接線。做完後，你應該能確認三件事：編輯器只在瀏覽器裡載入、next build 不再因為 browser-only 模組報錯，而且編輯器輸入的內容能正確寫回表單欄位。

開始前，請先準備好一個已經標示 "use client" 的表單元件、一個確認需要瀏覽器環境的元件，以及它的 props 介面。以下會直接沿著 DevFlow 的實際程式碼操作。

先看整體接線方式

這次的修改可以拆成幾個互相接上的步驟：

  1. 確認表單本身是 client component。
  2. 用 next/dynamic 取代 editor 的靜態 import。
  3. 在 dynamic import 上設定 ssr: false。
  4. 確認 editor 模組本身也標示 "use client"。
  5. 準備 MDXEditorMethods 型別的 ref。
  6. 把表單的 value 與變更函式傳進 editor。

可以把這條資料流想成一條接線：表單把目前值交給編輯器顯示，編輯器在內容變更時，再把新值送回表單。至於編輯器什麼時候進場，則交給 dynamic 和 ssr: false 管理。

步驟一：確認表單是在 client 端元件裡

next/dynamic 的 ssr: false 只能用在 client component。這是第一個要檢查的地方：如果表單檔案還不是 client component，後面的設定就無法成立。

DevFlow 的 QuestionForm.tsx 第一行就是 "use client"：

"use client";

import { zodResolver } from "@hookform/resolvers/zod";
import { MDXEditorMethods } from "@mdxeditor/editor";
import { ReloadIcon } from "@radix-ui/react-icons";
import dynamic from "next/dynamic";
import { useRouter } from "next/navigation";
import React, { useRef, useTransition } from "react";
import { useForm } from "react-hook-form";
import { z } from "zod";

這段 import 裡有兩個角色。dynamic 來自 next/dynamic，負責稍後載入 editor；MDXEditorMethods 來自 @mdxeditor/editor，只是用來描述 ref 的型別，不會因此把整個編輯器直接靜態載入。

步驟二：用 dynamic 取代靜態 import

接著找到原本直接載入 editor 的地方，將它改成模組頂層的動態載入。這裡最容易出現的問題，是只把元件改成動態 import，卻忘了關掉伺服器端渲染。

AI 常犯版：直接靜態 import。這樣模組可能在伺服器環境被求值，而 browser-only 套件通常會在這個階段碰到不存在的 window 或 DOM。

// 常犯版：靜態 import，模組會在伺服器上被求值
import Editor from "@/components/editor";

正解版：用 dynamic 載入模組，並明確設定 ssr: false：

const Editor = dynamic(() => import("@/components/editor"), {
  ssr: false,
});

第一行建立一個仍然可以放進 JSX 的 Editor 元件。import("@/components/editor") 則把實際載入延後，讓 Next.js 將它切成獨立的 chunk。

第二行的 ssr: false 是關鍵。它告訴 Next.js：這個元件不要在伺服器端渲染。如此一來，@mdxeditor/editor 就不會在沒有 window 的環境中被求值。

如果希望使用者等待 chunk 載入時看到提示，也可以提供 loading：

const Editor = dynamic(() => import("@/components/editor"), {
  ssr: false,
  loading: () => <p>載入編輯器中…</p>,
});

步驟三：確認 editor 自己也標示為 client component

動態載入只處理載入時機，不會替被載入的模組宣告 client 身分。因此，components/editor/index.tsx 自己仍然要在第一行標示 "use client"。

接著確認它提供給外部使用的 props。DevFlow 的介面如下：

interface Props {
  value: string;
  editorRef: Ref<MDXEditorMethods> | null;
  fieldChange: (value: string) => void;
}

這三個 props 各自負責一件事：

  • value：目前表單欄位的內容，交給編輯器顯示。
  • fieldChange：編輯器內容改變時呼叫的函式，負責把新內容寫回表單。
  • editorRef：讓外部表單取得 editor 的 ref，必要時可以操作編輯器實例。

ssr: false 和 "use client" 是兩道不同的門。前者阻止元件在伺服器端渲染，後者宣告模組必須在 client 邊界中執行；使用 browser-only 元件時，兩者都要確認。

步驟四：準備 editor ref

如果表單需要控制 editor，就在 QuestionForm 裡建立一個 ref，並使用 MDXEditorMethods 作為型別：

const editorRef = useRef<MDXEditorMethods>(null);

初始值是 null，因為 editor 還沒載入時，實例尚不存在。等 editor 在瀏覽器端建立完成後，這個 ref 就能指向它。之後若需要在送出前讀取最新內容，或重設編輯器內容，就可以透過這個 ref 操作。

步驟五：把 editor 接上 react-hook-form

現在開始接線。表單欄位的目前值來自 field.value，內容變更則交給 field.onChange。這兩者要分別對應到 editor 的 value 與 fieldChange：

              <FormControl>
                <Editor
                  value={field.value}
                  editorRef={editorRef}
                  fieldChange={field.onChange}
                />
              </FormControl>

這段 JSX 的資料方向很清楚：

  1. field.value 傳進 Editor，讓 editor 顯示表單目前的值。
  2. 使用者修改內容時，Editor 呼叫 fieldChange。
  3. fieldChange 實際上就是 field.onChange，因此新內容會寫回 react-hook-form。
  4. editorRef 同時傳入 editor，保留從表單操作 editor 實例的能力。

editor 需要等瀏覽器端的 chunk 載入完成後才會開始運作，但表單值仍由 react-hook-form 管理。這樣 editor 只是表單欄位的顯示與輸入介面，不會取代表單本身的狀態管理。

步驟六：驗證結果

完成修改後，請逐項確認以下結果。

  1. 執行 next build，或進行首次請求時，不再出現 window is not defined。這表示 browser-only 模組沒有在伺服器上被求值。
  2. 開啟瀏覽器的 Network 面板，確認 editor 的程式碼以獨立 chunk 載入，而不是直接併入首屏 bundle。
  3. 在 editor 中輸入內容，確認表單欄位的值會跟著更新。
  4. 切換主題，確認 editor 會跟著重新繪製。DevFlow 使用 key={resolvedTheme}，讓主題變更時重新 mount editor；而 useTheme 本身也要求這段邏輯留在 client。
警告：ssr: false 代表這個元件不會有伺服器產生的 HTML。對本來就要等待使用者操作的 editor 來說，通常可以接受；但如果把它套在主要內容或需要 SEO 的區塊上，首屏會少掉那部分內容，也可能造成版面跳動。請只對真正 browser-only、而且不靠首屏 HTML 撐起內容的元件使用 ssr: false。

完成後應該長什麼樣子

你最後會得到一個在 client component 中動態載入的 editor：

  • 表單檔案使用 "use client"。
  • editor 透過 dynamic(() => import(...), { ssr: false }) 載入。
  • editor 模組自己也標示 "use client"。
  • editorRef 使用 MDXEditorMethods 型別。
  • value 與 fieldChange 分別接到 field.value 與 field.onChange。
隔離 browser-only 元件的標準手法是：在 client component 裡用 const Comp = dynamic(() => import(...), { ssr: false }) 取代靜態 import，讓該模組完全不經過伺服器渲染；被載入的模組自己仍要標示 "use client"；再用 ref 與 value / onChange 把它接上表單。完成後，build 不再因為 browser-only 模組爆錯，首屏 bundle 也不會直接包含這段程式碼，而 editor 的值仍能正確寫回 react-hook-form。

到這裡，你已經完成三種處理方式中的最後一種：除了讓元件留在 server、或隔離成 client island，也可以用 dynamic import 加上 ssr: false，把真正 browser-only 的元件延後到瀏覽器載入。下一節會把這些判斷整理成檢查表，方便你驗收 AI 產出的元件樹。
