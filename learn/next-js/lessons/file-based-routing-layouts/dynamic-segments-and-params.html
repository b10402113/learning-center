動態路由：用 [id] 吃下不確定的 URL

Step 2/5 · 檔案式路由、layout 與 route groups

學習目標

能建立 [id] 形式的動態路由、從 params 取得 URL 中的變動值，並說明為什麼動態路由能取代複製貼上的多個頁面。

前言：一萬個標籤，難不成要建一萬個資料夾？

上一節學會了「資料夾就是路由」。但那個規則馬上撞到一面牆：假設你的網站有標籤（tag）功能，每個標籤都有自己的頁面，像是 /tags/react、/tags/nextjs、/tags/typescript。標籤會隨著使用者新增，數量沒有上限。如果照上一節的做法，每個標籤都要建一個資料夾、再放一份幾乎一樣的 page.tsx，這顯然行不通。

這正是動態路由（dynamic route）要解決的問題。它讓一個資料夾吃下一整類網址，內容隨網址裡的值而改變。學會之後，你只要寫一次頁面，就能服務無限多個 /tags/xxx。

把會變的那一段用中括號包起來

做法只有一個動作：把資料夾名稱用一對方括號包住，代表「這一段是變數」。原本每個標籤一個資料夾，現在改成一個叫做 [id] 的資料夾：

app/
└── tags/
    └── [id]/
        └── page.tsx   → /tags/react、/tags/nextjs、/tags/任何值

方括號裡的 id 是你自己取的名字，它同時代表兩件事：這個資料夾是動態段，以及待會要用哪個 key 去讀出它的值。你可以叫它 [id]、[slug] 或 [tagName]，只要前後一致就好。不像靜態路由「一個資料夾對一條固定網址」，動態路由是「一個資料夾對一整類網址」。

值從哪裡讀進來：params

網址是動態的，但頁面程式碼必須知道「現在到底是哪一個標籤」。Next.js 會把 URL 上那一段變動的值，放進元件收到的 params 物件裡。看一段真實專案的寫法：

const Page = async ({ params, searchParams }: RouteParams) => {
  const { id } = await params;
  const { page, pageSize, query } = await searchParams;

  const { success, data, error } = await getTagQuestions({
    tagId: id,
    …
  });

這裡有幾個細節值得停下來看。第一，資料夾叫 [id]，所以 params 裡的 key 就是 id，名稱必須一模一樣，叫 [tag] 就得用 params.tag 讀。第二，params 是 Promise，所以範例裡寫的是 await params，這也是為什麼整個元件是 async。第三，拿到 id 之後，就能拿它去查資料庫，例如呼叫 getTagQuestions({ tagId: id, … }) 撈出這個標籤底下的問題。

所以動態路由真正的分工是這樣：URL 只負責「帶一個識別值過來」，頁面把它讀出來之後，資料從哪裡來、要顯示什麼，仍然由你自己決定。這也正是它為什麼能只用一份檔案服務無限多頁：變動的部分被收斂成一個參數。

巢狀動態：一層可能不夠

動態段可以和靜態段、甚至其他動態段混在一起。例如一篇問題的編輯頁可能是 /questions/123/edit，資料夾就長成 app/questions/[id]/edit/page.tsx：[id] 是變數，edit 是固定的一段。如果網址有兩段以上會變，也可以疊兩個方括號資料夾，例如 app/[category]/[id]/page.tsx，此時 params 會同時有 category 和 id 兩個 key。

如果不在頁面裡，怎麼讀 params？

params 是直接傳給頁面元件的 prop，適合用在伺服器元件。但如果你是在一個客戶端元件、或一個更深層的子元件裡需要這個值，可以改用 Next.js 提供的 useParams hook，它會回傳目前 URL 的動態參數。兩種方式拿到的是同一份資訊，差別只在你在哪裡用它。

小結

動態路由把資料夾名稱用方括號包住，例如 app/tags/[id]/page.tsx，一個資料夾就吃下 /tags/react、/tags/nextjs 這一整類網址。URL 上變動的那一段會以 key 放進 params，key 的名稱要和資料夾名稱一致；在 Next.js App Router 裡 params 是 Promise，要用 await params 取值。動態段可以和靜態段或更多動態段層層組合。

到這裡，你已經能在檔案樹上表達「靜態網址」與「不確定的網址」。但一個網站不只需要頁面，還需要每個區塊共同的導覽與外框，像是 navbar、側邊欄這種「每頁都要、但不屬於任何單一頁」的東西。下一篇要看的就是負責這件事的 layout.tsx。
