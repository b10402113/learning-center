資料夾就是路由：從 page.tsx 看懂巢狀 URL

Step 1/5 · 檔案式路由、layout 與 route groups

先掌握全貌：檔案樹就是路由樹

打開 AI 剛產生的 Next.js 專案，看到 app/ 底下一層又一層的資料夾，你可能會想：「這個網站到底有哪些網址？」如果只把它當成普通的檔案樹，確實很容易迷路。

但在 Next.js 裡，資料夾結構本身就是路由設定。資料夾代表 URL 的一段，裡面的 page.tsx 代表該網址要顯示的畫面。掌握這個對應關係後，你可以從檔案位置推回網址，也可以從網址反推出檔案在哪裡。後面會遇到的 layout 與 route groups，都建立在這個基礎上。

AI 常犯版：檔案是一回事，路由設定是另一回事

在純 React 專案裡，要讓不同網址顯示不同畫面，通常要先安裝 router 套件，例如 react-router-dom，再另外寫一份設定，把每個路徑逐一對應到元件：

// React Router 的寫法：路徑與元件要手動一組一組配
import { BrowserRouter, Routes, Route } from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="/contact" element={<Contact />} />
      </Routes>
    </BrowserRouter>
  );
}

這種方式的問題，不是三個頁面就一定會出錯，而是網站一大，路徑和元件的對應表就會變得難以掃讀。你得同時維護兩份資訊：一份是資料夾裡的頁面元件，另一份是路由設定裡的路徑對應。

正解版：Next.js 把路徑直接放進檔案結構

Next.js 把這兩份資訊合在一起，不需要再另外掛一張路由對應表。核心規則可以先記成一句話：

資料夾代表一段 URL，裡面的 page.tsx 代表這段 URL 要顯示的畫面。

例如，要建立 /about，就在 app/ 底下建立 about 資料夾，再放入固定命名的 page.tsx：

// app/about/page.tsx —— 對外網址就是 /about
export default function About() {
  return <main><h1>About</h1></main>;
}

這裡不需要匯入任何 router 套件，因為路由能力已經內建在 Next.js 裡。page.tsx 是框架辨認頁面的固定公約；如果改成其他檔名，Next.js 就不會把它當成這條路由的內容。

資料夾名稱也要留意大小寫。About 和 about 在 URL 上是兩條不同的路徑，因此不要把大小寫差異當成無關緊要的小事。

巢狀資料夾，就是巢狀路由

如果要建立 /projects/list，不需要再學一套新的語法。只要讓資料夾一層包一層：

app/
└── projects/
    └── list/
        └── page.tsx   → /projects/list

每一層資料夾對應 URL 的一段。projects 接上 list，中間自動形成斜線，最後由 page.tsx 提供畫面。

不過，資料夾存在不代表它本身一定是一條可以拜訪的網址。某一層如果沒有自己的 page.tsx，它可能只是用來繼續往下分層的外殼。

例如，假設只有下面兩個頁面：

app/dashboard/users/page.tsx
app/dashboard/analytics/page.tsx

那麼 /dashboard/users 和 /dashboard/analytics 都存在，但單獨拜訪 /dashboard 會得到 404。若希望 /dashboard 自己也有頁面，就要在 dashboard 資料夾裡再放一個 page.tsx。

從檔案推網址，也從網址推檔案

這條規則可以雙向閱讀，就像把地址拆成一段段，再沿著資料夾樹走回去。

看到 /dashboard/users 時，可以依序想成：

app → dashboard → users → page.tsx

反過來，看到 app/settings/profile/page.tsx，就把 app 後面的資料夾名稱串起來，得到 /settings/profile。

這種來回反推的能力很實用。尤其在檢查 AI 產生的專案時，你不必先翻遍所有設定，只要對照檔案樹，就能快速判斷實際有哪些網址，以及某個頁面是不是放錯位置。

檔案位置對外 URL
app/page.tsx/
app/about/page.tsx/about
app/projects/list/page.tsx/projects/list
app/dashboard/users/page.tsx/dashboard/users
app/contact/page.tsx/contact

表格最上方的 app/page.tsx 對應根網址 /。這是因為 app/ 本身不是 URL 的一段，而是整棵路由樹的起點。

為什麼「結構即行為」值得記住

檔案式路由不只是少寫一份設定，它也改變了閱讀專案的方式。當路徑與檔案位置是一一對應的，檔案放錯地方，就會直接反映成錯的網址，而不是藏在另一份設定裡、很難追查的錯誤。

這就像把地圖畫在街道本身：看到哪條路，就知道它通往哪裡；看到哪個地址，也能沿著地圖找到位置。這種「結構即行為」的特性，讓 Next.js 的路由容易閱讀，也比較容易抓錯。接下來的動態路由與 layout，都是在這條基本規則上增加新的慣例。

把這個觀念掛在正確的位置

Next.js 使用檔案式路由，不需要額外安裝 router 套件。app/ 底下的每個資料夾代表一段 URL，裡面的 page.tsx 則是該網址的畫面；巢狀資料夾會產生巢狀網址，例如 app/projects/list/page.tsx 對應到 /projects/list。因此，你可以由網址畫出檔案樹，也可以由檔案樹推回每一條網址。

目前看到的是靜態與巢狀路由：資料夾名稱直接寫出 URL 的內容。但真實專案裡，還有很多網址的某一段不是固定文字，例如每一個商品的詳情頁、每一篇文章的頁面。這些會持續增加的網址，下一篇會用動態路由來處理。
