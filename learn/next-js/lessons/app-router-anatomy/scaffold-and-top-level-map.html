create-next-app 產出什麼？專案頂層地圖

Step 1/4 · App Router Anatomy

學習目標

能說出 create-next-app 產生的每個頂層檔案與資料夾各自負責什麼，並解釋它們為什麼存在。

前言：一跑完指令，左邊怎麼多了一堆檔案？

你照著教學輸入一行指令，等了幾秒鐘，編輯器左邊的檔案樹突然長出一二十個檔案和資料夾。有些名字你認得，像 README.md；有些看起來很嚇人，像 tsconfig.json、postcss.config.mjs、next-env.d.ts。你心裡冒出一個很實際的問題：這些到底哪些是我要改的、哪些碰了會出事？

這個問題不只是新手會問。當你拿到一份 AI 生成的專案，它最常出錯的地方，往往不是語法，而是把東西放錯位置：設定寫進元件、圖片塞進錯的資料夾、某個套件被裝在奇怪的地方。要是你腦中沒有一張「每個檔案是幹嘛的」地圖，就只能照單全收，沒辦法判斷對錯。這一節的目標，就是先把你腳下的這張地圖畫出來。

先搞懂 scaffold 幫你跳過了哪些事

在 create-next-app 出現以前，要從零開始一個 Next.js 專案，你得自己裝 React、裝 Next、設定打包工具、接上 TypeScript、手動建立資料夾結構。這些事每一件都不難，但全部加起來就是半天的工。所以 Next.js 提供了一個叫「鷹架（scaffold）」的官方工具，把這些前置工作收成一個指令。

執行前唯一需要的東西是 Node.js 16.8 或更新的版本。這裡有個很常見的誤會：很多人以為 Node.js 是一門新的程式語言，其實它是 JavaScript 的執行環境（runtime），讓 JavaScript 可以跳出瀏覽器、在你的電腦上跑。Next.js 本身就是一支用 JavaScript 寫的程式，所以它需要 Node.js 才能執行。

Node.js 是執行環境，不是語言。它的角色是讓 JavaScript 能在瀏覽器之外的地方被執行，Next.js 和它安裝的一堆套件都靠它跑起來。

接下來要選安裝方式。你可以全部手動來，也可以一鍵自動安裝。實務上大家都用自動的那條路，因為它會依你的選擇（要不要 TypeScript、要不要 Tailwind）直接生成整個專案，省掉大量手工。而負責一鍵安裝的工具叫做 create-next-app，你用 npx 來執行它：

npx create-next-app@latest

這裡有個常被搞混的細節值得拆開講。npm（Node Package Manager，Node 套件管理器）負責「安裝」與「管理」套件；npx（Node Package eXecute）負責「執行」指令，而且用它執行時不需要把工具先全域安裝到自己電腦上。所以你用 npx 跑 create-next-app，它會執行這支工具；真正把 React、Next 等套件裝進專案的，還是 npm。安裝過程中它會依序問你幾個問題：

√ What is your project named? introduction
√ Would you like to use TypeScript with this project? No
√ Would you like to use ESLint with this project? No
√ Would you like to use Tailwind CSS with this project? No
√ Would you like to use src/ directory with this project? No
√ Use App Router (recommended)? Yes
√ Would you like to customize the default import alias? No

其中「Use App Router」這一題是關鍵。選它，你會拿到新一代的 app/ 目錄結構；不選它，你會退回舊的 pages router，很多新功能就不會出現。這一節後面的所有內容，都建立在「你選了 App Router」之上。

三種角色：把檔案分成工廠、設定與產物

面對這一大堆檔案，最有效的做法不是一個一個背，而是先分類。整個頂層其實只有三種角色：第一種是工廠區，也就是你每天真正會動手寫程式碼的地方；第二種是設定檔，它們決定專案的行為，只在需要調整時才碰；第三種是產物，由工具自動生成、你幾乎不該動手。先看整體對照，再逐一展開：

檔案 / 資料夾角色你要不要動它
app/工廠：頁面、路由與後端程式碼每天都會動，最重要
public/工廠：靜態資源（圖片、字型、影片）放素材時會動
package.json設定：專案資訊卡與指令裝套件時會被自動改
package-lock.json設定：鎖定套件版本不要刪、不要手改
next.config.ts設定：Next.js 功能設定要調功能時才改
tsconfig.json設定：TypeScript 規則少動
postcss.config.mjs設定：CSS 處理外掛少動
jsconfig.json設定：import 路徑別名想改捷徑時才動
next-env.d.ts產物：Next.js 的型別宣告絕對不要改
node_modules/產物：所有套件的倉庫不要碰
.gitignore設定：告訴 Git 忽略哪些檔案很少動，但別漏
README.md文件：專案說明書有空就補

工廠區：你每天真正會動的兩個資料夾

先講app/。它是整個專案的核心，也是你最常待的地方：前端頁面、路由、甚至後端的 API 端點，都寫在這裡面。你可以把它想成工廠的產線，所有會變成畫面的東西都從這裡生產。它的內部細節我們留到下一節專門拆，這裡只要先記住一句：任何你要新增的頁面或功能，十之八九都從這個資料夾開始。

另一個是public/。它專門放不需要經過編譯的靜態資源，例如圖示、圖片、logo、字型檔或影片。放進這裡的檔案會被自動最佳化，而且可以在整個應用的任何地方直接取用。所以當你手上有一張 PNG、JPEG 或 SVG，第一直覺就是把它丟進public/，而不是塞在元件旁邊。

設定檔：專案的行為說明書

設定檔是一群「平時不碰、要調行為時才打開」的檔案。它們不會出現在畫面上，卻決定了專案怎麼被建置、怎麼被檢查、套件怎麼被管理。以下幾個是 App Router 專案一定會見到的。

package.json 與 package-lock.json

package.json 像是專案的身分證加上名片：它記錄專案名稱、版本，以及這個專案相依的套件。相依套件又分成兩類：dependencies 是正式環境上線時也需要的套件，devDependencies 只在開發階段用到，例如負責檢查程式碼風格的 eslint。除此之外，它還有一個 scripts 區塊，裡面是可以執行的指令，用來跑測試、建置、啟動開發伺服器或部署。

package-lock.json 則是出貨清單。當你安裝套件時，它會自動被建立，並精確記下每一個套件與其子相依的版本。它的價值在一個很常見的災難情境裡：假設你把專案分享給同事，卻沒帶上這個檔案，同事照著package.json重新安裝時，npm 會去抓「最新版本」；萬一新版本有 bug 或相容性問題，同事的環境就會壞掉，於是出現那句經典的「在我電腦上明明可以跑」。所以這個檔案唯一的規矩就是：別刪，也別手動改。

其他設定檔

next.config.ts 是 Next.js 自己的設定入口，用來調整實驗性選項、圖片設定、建置設定等，該改、也預期你會改。next-env.d.ts 則是 Next.js 專用的 TypeScript 宣告檔，檔案裡通常直接寫著「本檔案不應被編輯」，它是工具生成的產物，動它只會讓型別系統出怪問題。tsconfig.json 定義 TypeScript 要檢查什麼、忽略什麼；postcss.config.mjs 是 CSS 後處理工具的設定，這個專案裡它把 Tailwind 當成外掛使用；如果你在建立時選了 Tailwind，還會多一個 tailwind.config.ts 讓你擴充顏色、尺寸與陰影。

這裡還有一個很容易被忽略、卻很實用的檔案：jsconfig.json。它就是你當初被問「要不要自訂 import 別名」時對應的設定。沒有它，跨資料夾引用會寫成一長串相對路徑：

import something from '../../components'

有了它，你就可以把根目錄./*對應到一個代號@/*，於是同樣的引用縮短成：

import something from '@/components'

設定本身長這樣：

{
  "compilerOptions": {
    "paths": {
      "@/*": ["./*"]
    }
  }
}

之後你在 AI 生成的專案裡看到滿滿的@/開頭引用，就不會再一頭霧水：那個@指的是專案根目錄。

產物區：機器在管，你別動手

最後一類是由工具自動生成、原則上不需要你介入的檔案。node_modules/ 是所有相依套件的倉庫，npm 安裝套件時就會把對應的程式碼放進來；裡面除了 React、react-dom、next 之外，還有 postcss、styled-jsx 等一大堆資料夾。它被戲稱為「宇宙中最重的物體」，因為檔案數量驚人。你不需要進去翻它，npm 會自動管理；更重要的是，它會被寫進.gitignore，這個檔案的用途正是告訴 Git「哪些東西不要納入版本控制」。把node_modules排除在外，能避免專案倉庫被塞得又肥又亂。至於README.md，則是專案的說明書，用來寫安裝方式、專案用途與協作說明。

小結

create-next-app 會用官方樣板一次生成整個專案。頂層檔案可以分成三種角色：工廠區（app/、public/）是你每天動手的地方；設定檔（package.json、package-lock.json、next.config.ts、tsconfig.json、jsconfig.json 等）決定專案行為，只在需要調整時才碰；產物（node_modules/、next-env.d.ts）由工具生成，不該動手。其中最核心的是app/，所有頁面與路由都從這裡長出來。

現在你已經知道app/是最重要的資料夾，但它裡面那幾個檔案（layout.tsx、page.tsx、globals.css）到底誰包誰、各自影響哪些路由？下一節會把app/打開，看清楚這棵渲染樹是怎麼組起來的。
