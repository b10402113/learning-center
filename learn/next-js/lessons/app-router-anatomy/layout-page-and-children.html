app/ 的核心：layout、page 與 children

Step 2/4 · App Router Anatomy

學習目標

能分辨 layout.tsx 與 page.tsx 的角色，並說出 children 這個 prop 如何把兩者接成一棵渲染樹。

前言：為什麼同一段字，有時候每頁都出現、有時候只出現一次？

上一節我們把專案頂層地圖畫完，認出app/是整個專案最重要的資料夾。現在把app/打開，你會看到兩個名字很像、卻常常被搞混的檔案：layout.tsx和page.tsx。新人最常犯的第一個錯，就是隨手把一段文字或一個元件丟進其中一個，然後納悶：「為什麼我加在layout的字，跑到每一頁去了？」

這個困惑背後，其實是一個非常清楚的分工問題。只要你能講出「誰包住誰、誰的內容只屬於哪一條路徑」，之後看任何一個 App Router 專案都不會迷路，也能在 AI 把導覽列寫進單一page時，一眼看出放錯了位置。這一節就把這棵渲染樹拆給你看。

兩個檔案，兩種影響範圍

先給最精簡的判準。layout.tsx是「版面」，它是一層外框，會套用在它底下所有路由上；page.tsx是「頁面」，它只代表某一條路徑的內容。放在layout裡的東西，會出現在它守備範圍內的每一頁；放在page裡的東西，只會出現在那一頁。用一句話記：layout 決定「每一頁都長怎樣」，page 決定「這一頁有什麼」。

layout.tsxpage.tsx
角色包住子樹的共用外框單一路由的內容
影響範圍底下所有路由只有它對應的路徑
常見內容字型、metadata、Navbar、Provider這一頁要顯示的資料與 UI
是否必要根目錄的 layout 是必須的有路由才需要

還有一層關係要記住：layout是page的「父層」。最頂層的app/layout.tsx叫做 root layout，它是整個應用的根，所有路由都被它包住；而app/page.tsx代表的是首頁，也就是/這條路徑，它的內容只會顯示在首頁，其他地方看不到。所以當你在首頁看到某段文字，它可能來自兩個地方：來自 root layout（那每頁都會有），或來自首頁的 page（只有首頁有）。

渲染樹：layout 是相框，page 是相片

如果要用一個生活化的畫面來記，可以想像layout是一個相框，page是放進去的相片。相框上的雕花、顏色、掛勾，不管裡面放哪一張相片都一樣；相片本身則每張都不同。當你造訪不同網址，Next.js 其實是在換「相片」，但相框不動，這也是為什麼換頁時 Navbar 和側邊欄不會重新閃一下。

而把相片塞進相框的機制，就是接下來要講的children。

children 是怎麼進來的？

Next.js 的 root layout 長得像這樣。它是一個被預設匯出的函式元件，接收一個叫做 children 的參數，然後把這個參數渲染在<body>裡面：

import './globals.css';

import { Inter } from 'next/font/google';


const inter = Inter({ subsets: ['latin'] });


export const metadata = {

    title: 'Create Next App',

    description: 'Generated by create next app',

};


export default function RootLayout({ children }) {

    return (

        <html lang="en">

          <body className={inter.className}>

            <p>Hello, I'm Groot </p>

            {children}

          </body>

        </html>

     );

}

關鍵在最後那個 {children}。它不是你自己傳進去的，而是 Next.js 幫你準備好、再當成 prop 交給 root layout 的；它的內容，就是「從首頁開始、一路到所有其他路由」的頁面元件。換句話說，children是一個插槽，Next.js 會依你當前造訪的路徑，把對應的page放進這個插槽，再交給你決定要擺在哪裡。

這也解釋了一個很容易讓人驚訝的現象：在<body>裡，{children}出現的位置，決定了頁面內容出現在畫面的哪個相對位置。上面那段程式碼把<p>Hello, I'm Groot</p>寫在{children}前面，所以打開首頁時，這行字會出現在「Hello World」之前。如果你把兩行的順序對調，頁面內容就會跑到那行字的前面。這不是魔法，純粹就是你把它插在哪裡、它就渲染在哪裡。

<body className={inter.className}>

   {children}

   <p>Hello, I'm Groot </p>

</body>

動手驗證：把 children 註解掉會怎樣？

想確認children真的就是頁面內容的入口，最直接的實驗是把它註解掉，然後回到瀏覽器：

// children is passed as a prop by Next.js

export default function RootLayout({ children }) {

  return (

     <html lang="en">

       <body className={inter.className}>

         <p>Hello, I'm Groot </p>


         {/* Contains the route components i.e., home route */}

         {/* {children} */}

       </body>

     </html>

  )

}

這時候你會發現，layout 裡那行「Hello, I'm Groot」還在，但首頁本身的內容消失了。因為你等於把相框上的插槽封起來，相片自然放不進去。這個小實驗一做完，「layout 是外框、page 是內容、children 是插槽」這三個角色就會在你腦中牢牢綁在一起。記得驗證完把註解取消，否則你的頁面會一直是空的。

一份真實的 root layout 長什麼樣？

課本上的範例很精簡，但真實專案裡的 root layout 通常忙得多。它既然是全站共用的最外層，所有「每個頁面都需要」的設定就會集中在這裡。以下是一份來自真實 Next.js 15 專案（DevFlow）的 root layout：

import type { Metadata } from "next";
import localFont from "next/font/local";
import { SessionProvider } from "next-auth/react";
import { ReactNode } from "react";

import "./globals.css";
import { auth } from "@/auth";
import { Toaster } from "@/components/ui/toaster";
import ThemeProvider from "@/context/Theme";

const inter = localFont({
  src: "./fonts/InterVF.ttf",
  variable: "--font-inter",
  weight: "100 200 300 400 500 700 800 900",
});

const spaceGrotesk = localFont({
  src: "./fonts/SpaceGroteskVF.ttf",
  variable: "--font-space-grotesk",
  weight: "300 400 500 700",
});

export const metadata: Metadata = {
  title: "DevFlow",
  description:
    "A community-driven platform for asking and answering programming questions. Get help, share knowledge, and collaborate with developers from around the world. Explore topics in web development, mobile app development, algorithms, data structures, and more.",
  icons: {
    icon: "/images/site-logo.svg",
  },
};

const RootLayout = async ({ children }: { children: ReactNode }) => {
  const session = await auth();

  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <link
          rel="stylesheet"
          type="text/css"
          href="https://cdn.jsdelivr.net/gh/devicons/devicon@latest/devicon.min.css"
        />
      </head>
      <SessionProvider session={session}>
        <body
          className={`${inter.className} ${spaceGrotesk.variable} antialiased`}
        >
          <ThemeProvider
            attribute="class"
            defaultTheme="system"
            enableSystem
            disableTransitionOnChange
          >
            {children}
          </ThemeProvider>
          <Toaster />
        </body>
      </SessionProvider>
    </html>
  );
};

export default RootLayout;

對照課本範例，你可以看到幾個「真實世界才會出現」的模式。第一，它用next/font/local把字型檔載進來，並把它變成 CSS 變數；第二，它匯出一個metadata物件，決定網站標題與描述；第三，它是async的，因為它要在伺服器端先await auth()取得使用者 session；第四，它把children包在SessionProvider與ThemeProvider裡，讓所有頁面共享登入狀態與主題；最後還掛了一個全域的Toaster。這些東西之所以放這裡，正是因為它們「每一頁都需要」。

這裡就帶出一個對 AI 架構的判斷點：當你在 root layout 裡看到愈來愈多東西，要想一下它是否真的屬於「全站」。把只有某些頁面需要的 Provider 硬塞進 root layout，會讓整棵樹都被它綁住，可能拖大 client bundle。這個取捨是下一節之後、第四步「東西該放哪」會專門處理的判準。

globals.css 與 CSS Modules

app/裡還有兩個處理樣式的角色。globals.css是全域樣式檔，CSS 變數、字型宣告、初始化設定都放這裡；在真實專案裡，Tailwind 的主題設定也集中在這一個檔案。留意一點：這個檔案可以改名、也可以搬位置，但它一旦改名或搬動，所有引用它的地方都要跟著更新，否則樣式就斷了。

另一種是page.module.css。檔名中間的.module.css代表這份 CSS 的作用範圍只限定在某個元件；在page.js裡用import styles from './page.module.css'把它引進來，樣式就只會套用在這個頁面，不會外洩到其他地方。全域樣式放globals.css、單一元件樣式用*.module.css，這條分界讓你避免「改一個地方，整站走鐘」的悲劇。

小結

layout.tsx是包住整棵子樹的共用外框，會套用到它底下的所有路由；page.tsx只代表某一條路徑的內容。最頂層的 root layout 是必要的，而 Next.js 會把當前路由的頁面元件當成children這個 prop 傳進來；children就是頁面內容的插槽，插在哪裡就渲染在哪裡。真實專案常把字型、metadata、Provider、Navbar、Toaster 這些「每頁都需要」的東西集中放在 root layout，並用globals.css管全域樣式、*.module.css管單一元件樣式。

到這裡，app/的靜態結構已經清楚了。但光看檔案不夠，下一步要真的把它跑起來，用 dev server 和 Fast Refresh 親眼看到「改 layout、每頁都變；改 page、只有一頁變」，讓這棵渲染樹活起來。
