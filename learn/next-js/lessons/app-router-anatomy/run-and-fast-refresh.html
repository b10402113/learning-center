把專案跑起來：dev server 與 Fast Refresh

Step 3/4 · App Router Anatomy

學習目標

能啟動 dev server、在瀏覽器看到頁面，並用 Fast Refresh 邊改 layout 與 page 邊驗證渲染樹的改變。

前言：看得見，你才會相信

前兩節我們把專案結構和 layout／page 的關係講清楚了，但那些都還停留在圖面。對工程師來說，真正的理解來自「動手改、當場看」。這一節要把你的專案在你自己的電腦上跑起來，並且建立一個你會用上幾百次的開發迴圈：改一個檔案、存檔、瀏覽器立刻變。做完之後，你不再只是知道 layout 影響全站，而是親眼看過。

動手前先確認兩件事：你已經用 create-next-app 建好一個專案（上一節講過），而且電腦上裝了 Node.js。這樣就夠了，其他步驟我們一步步來。

步驟一：切到專案目錄

打開編輯器內建的終端機，確認你現在的位置就在專案資料夾裡。如果你建立專案時是在上一層目錄、用專案名稱生成子資料夾（例如 introduction），就要先切進去：

cd introduction

這裡的 cd 是 change directory（切換目錄）的縮寫。如果你當初是用「目前的資料夾」建立專案（輸入 ./ 的那種），那你已經在正確位置，可以跳過這步。判斷方式很簡單：只要在終端機輸入 ls，能看到 package.json 和 app/，就代表位置對了。

步驟二：啟動 dev server

接著執行 package.json 裡 scripts 區塊的 dev 指令：

npm run dev

這個指令會用開發模式啟動 Next.js，它會在背景幫你盯著檔案的變化，並開啟即時重載、錯誤回報等功能。啟動成功後，終端機會告訴你服務跑在 3000 埠。打開瀏覽器，輸入這個網址：

http://localhost:3000

你應該會看到 Next.js 的預設樣板頁。這個頁面其實就是 app/page.tsx 渲染出來的內容。看到它，代表你的專案活了。

小提醒：dev server 是你本機的開發環境，只在開發時使用。當你要收工，回到終端機按 Ctrl + C 就能把它關掉。另外，正式上線用的指令是 npm run build 加 npm start，跟這裡的 npm run dev 不是同一回事，別混用。

步驟三：改 page，只影響一頁

現在做第一個實驗。打開 app/page.tsx，把預設內容全部刪掉，改寫成一個最單純的首頁元件：

export default function Home() {
  return (
    <main>
      <p>Hello World</p>
    </main>
  );
}

存檔，回到瀏覽器。你會發現畫面在你沒有手動重新整理的情況下就更新了，變成「Hello World」。這個機制叫 Fast Refresh（快速重新整理），也可以理解成 HMR（Hot Module Replacement，熱模組替換）：Next.js 偵測到檔案變動，就把改動過的模組即時換進瀏覽器，不用整頁重載。往後你每次改程式碼，都是靠它省下按重新整理的力氣。留意一點：這裡改的是 page，所以變的只有首頁。

步驟四：改 layout，全站都變

接著打開 app/layout.tsx，做兩件小事。第一，找到匯出的 metadata，把標題從原本的預設值改掉：

export const metadata = {

    title: 'Create Next App',

    description: 'Generated by create next app',

};

把 title 改成別的，例如「Hello, Next.js」，存檔，然後看瀏覽器分頁的標籤文字，它會跟著變。這就是 metadata 放在 layout 的效果：它控制的是整個網站層級的資訊。

第二件事，在 layout 的 <body> 裡、{children}的前面加一行字：

<body className={inter.className}>

  <p>Hello, I'm Groot </p>

  {children}

</body>

存檔後回到瀏覽器，你會看到「Hello, I'm Groot」出現在首頁內容的上方。注意：因為這是寫在 root layout 裡，這行字其實會在每一條路由上出現，不只是首頁。你剛剛親手證明了上一節的結論：layout 的內容是全站共用的。

步驟五：把 children 註解掉，確認它是插槽

最後做一個「破壞性」但很快能還原的實驗，把 {children} 註解掉：

{/* {children} */}

存檔，回瀏覽器。你會看到「Hello, I'm Groot」還在，但「Hello World」消失了。這確認了 children 就是頁面內容的入口。看完之後記得把註解取消，讓 {children} 恢復，否則你的網站會一直是空的。

注意：實驗時不要順手去刪 package-lock.json，也不要編輯 next-env.d.ts。這兩個檔案跟這次的練習無關，刪掉或改動只會讓專案出狀況。要動的只有app/layout.tsx和app/page.tsx。

小結

開發迴圈只有三步：npm run dev 在本機 3000 埠啟動服務，編輯 app/ 裡的檔案，存檔後靠 Fast Refresh 立即在瀏覽器看到結果。改 page，只有那一頁變；改 layout，底下每條路由都變；把 {children} 註解掉，頁面內容就消失。這三個實驗合起來，就是渲染樹最直接的體感證明。

現在你已經能跑專案、能改檔案、也能預期每個改動會影響多大範圍。下一步要把這些零散的判斷收斂成一條規則：當你拿到一個全新的需求（比如「加一個導覽列」、「加一張 logo」、「加一個只有登入後才看得到的頁面」）到底該放進哪個檔案或資料夾？最後一節會給你一份可以當場用的決策檢查表。
