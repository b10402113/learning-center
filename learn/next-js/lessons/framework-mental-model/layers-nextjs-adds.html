Next.js 多出來的六層：routing、rendering、data、backend、metadata 與 tooling

Step 3/4 · Next.js 作為 framework：加在 React 上的那一層

面對一份 AI 產生的 Next.js 專案，光看見檔名通常還不夠。你需要知道每個資料夾、檔案或 API 屬於哪一層，才能判斷它是 Next.js 提供的能力，還是純 React 專案原本就有的部分。

Next.js 附加層：定義

Next.js 附加層，是指框架內建、以慣例固定下來，開發者通常不必自行挑選與配置的能力。主要包含 Routing、Rendering、Data、Backend、Metadata，以及 Tooling／最佳化。

層Next.js 對應的檔案／API純 React 通常要自行補上的部分
Routing（路由）app/ 資料夾樹、page.tsx、layout.tsx、[id]、route groups (name)安裝並設定 React Router
Rendering（渲染）Server Components（預設）、"use client"、SSR／SSG／ISR／PPR、hydration預設以 CSR 為主，其餘能力自行配置
Data（資料）async Server Component 直接 await、擴充過的 fetch 快取、revalidate、request dedupuseEffect、狀態管理，以及重複請求處理
Backend（後端）route.ts Route Handlers（serverless functions）、Server Actions另外架設 Express 或獨立 API
Metadata（中繼資料／SEO）export const metadata、generateMetadata、sitemap.ts、robots.ts、opengraph-image手動將標籤放進 <head>
Tooling（工具鏈／最佳化）next/font、next/image、code splitting、HMR、ESLint 與 Tailwind 整合自行配置打包、轉譯、壓縮與部署

Routing：資料夾就是路由

在 App Router 中，資料夾代表網址路徑，資料夾底下的 page.tsx 代表該路徑顯示的內容。巢狀資料夾會產生巢狀路由；以 [id] 命名的資料夾代表動態路由，對應值從 params 讀取。

以括號命名的 route group，例如 (name)，可以用來分組程式碼與套用不同 layout，但不會改變網址。新增頁面時，只需要新增對應的資料夾與檔案；純 React 專案則通常需要引入 React Router 並自行撰寫路由表。

Rendering：預設在 server，需要互動才下 client

Next.js 的元件預設是 Server Component，會在伺服器上執行。檔案頂端加入 "use client" 指令後，才會成為在瀏覽器執行的 Client Component。

Next.js 支援的渲染策略包括：

  • SSG（Static Site Generation）：在 build 時產生 HTML。
  • SSR（Server-Side Rendering）：每次請求時產生 HTML。
  • ISR（Incremental Static Regeneration）：依時間或事件更新靜態內容。
  • PPR（Partial Prerendering）：在同一個頁面中混合靜態外殼與動態串流。

這些策略都屬於 Rendering 層。純 React 通常以 CSR 為主要模式，其餘渲染方式需要另外配置。

Data：在 server 直接抓資料

Server Component 可以是 async 函式，在元件內直接使用 await 抓取資料，也可以直接呼叫資料庫。Next.js 擴充了 fetch，提供快取與 request dedup：同一輪 render 中，相同網址的請求只會真正發送一次。

資料更新使用 revalidate 相關設定。純 React 常見的資料抓取方式是 useEffect 搭配 useState，重複請求與 network waterfall 則需要自行處理。

Backend：同一份專案裡的 route handler

在 app/ 底下建立資料夾，放入 route.ts，即可建立一個後端端點。檔案可以匯出 async 的 GET、POST、PUT、DELETE 等處理函式，並回傳 Response.json(...)。資料夾名稱就是端點路徑，動態 API 同樣使用 [id] 命名。

課堂上常見的放置方式，是將這些端點放在 api/ 資料夾底下。部署後，Route Handler 會成為由雲端供應商託管與執行的 serverless function。

另一種後端選項是 Server Actions。它可以讓表單直接呼叫伺服器邏輯，不必另外建立 API endpoint。

Metadata：產生 SEO 與分享資訊

Metadata 決定網站出現在搜尋結果與社群分享時的標題、描述與圖像。Next.js 提供兩種設定方式。

  • 設定式 Metadata：從 layout 或 page 匯出 metadata 物件；page 層級會覆蓋 layout 層級。
  • 檔案式 Metadata：將 favicon、icon、opengraph-image、robots、sitemap 等檔案放進 app/，由 Next.js 自動產生對應標籤；檔案式設定優先於設定式 Metadata。

動態頁面可以使用 generateMetadata 搭配路由 params，為每筆資料產生專屬的標題與描述。純 React 沒有這一層，通常需要自行操作 document 或依賴其他工具。

Tooling 與最佳化：預先配置的基礎設施

Next.js 預先處理編譯、打包、壓縮、格式化與部署等前端開發環節，並提供下列工具與最佳化功能：

  • next/font：字型最佳化。
  • next/image：圖片最佳化。
  • code splitting：依路由拆分程式碼。
  • HMR（Hot Module Replacement）：開發時的熱更新。
  • ESLint 與 Tailwind 整合：提供既有工具鏈的整合方式。

在純 React 專案中，這些功能通常需要自行設定打包、轉譯、壓縮與部署工具。

最小範例：一個 Next.js Route Handler

Route Handler 的最小形式，是匯出一個 GET 函式並回傳內容。下面的 dynamic = "force-dynamic" 表示這個端點預設會被靜態化，除非它需要讀取當下的 request。

export const dynamic = "force-dynamic"; // static by default, unless reading the request
export function GET(request) {
  return new Response(`Hello from ${process.env.VERCEL_REGION}`);
}

AWS Lambda 的 Node.js serverless function 具有相同的基本形式：

export const handler = async (event, context) => {
  console.log("EVENT: \n" + JSON.stringify(event, null, 2));
  return context.logStreamName;
};

不同雲端供應商的函式寫法不同，但都由部署後的雲端環境負責託管、擴充與執行。Next.js 的 Route Handler 就是這類 serverless function 的一種。
