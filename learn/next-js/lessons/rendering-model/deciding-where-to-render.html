判斷元件該在 server，還是 client 執行

Step 5/5 · 渲染模型：CSR / SSR / RSC / hydration

先看整張地圖：你要做的決定是什麼？

上一節我們已經弄清楚 "use client" 的機制。接下來真正會反覆遇到的問題是：每開一個新元件檔案，到底該讓它留在 server，還是把它標成 client？

這其實是一場拉鋸。server 元件可以省下 JavaScript、直接存取資料庫，也能把機密留在伺服器；但它沒有互動能力。client 元件則能處理事件、state 和瀏覽器 API，代價是程式碼會進入 client bundle，而且不能直接使用伺服器端資源。

選錯方向，輕則把一大包不必要的 JavaScript 推給使用者，重則讓資料庫連線或機密設定出現在瀏覽器裡。本課要做的，就是把這個選擇整理成一套可以實際檢查的判準。

學習目標

學完後，你應該能用「這個元件需要瀏覽器互動嗎」這個問題，判斷任一元件該留在 server，還是標成 client；也能看出把 Server Component 塞進 Client Component 檔案，或無腦加上 "use client" 的代價。

兩股張力：省 JavaScript，還是換取互動？

Server Component 把渲染與資料存取留在伺服器。送到瀏覽器的主要是 HTML，因此 client bundle 較小、首次載入較快，機密也不必離開 server。

Client Component 則把執行能力帶到瀏覽器。它可以綁定事件、管理 state、使用瀏覽器 API，但相對地，相關程式碼與部分邏輯也會被送到使用者的裝置。

選項比較：兩種元件各自換來什麼？

面向Server ComponentClient Component
執行位置server瀏覽器
送出 JavaScript少，只有 HTML多，整包進 client bundle
直接讀資料庫可以不行
保存機密可以（token、API key 留在伺服器）不行，程式碼會被送到瀏覽器
事件與互動沒有完整支援 onClick、onChange 等
state 與生命週期不支援支援 useState、useReducer、useEffect
瀏覽器 API不能用可以用
大型依賴留在 server，不佔 client 頻寬會被一起打包送出

判別問句：先問「它需要互動嗎？」

面對任何一個元件，先不要急著加 "use client"。先問自己這句話：

這個元件需要使用者互動嗎？ 需要 → Client Component；不需要 → Server Component。

如果答案仍然不夠明確，可以再把需求拆開比對。以下是 Next.js 文件整理出的常見對應關係：

你想做什麼該用哪種元件
抓資料（fetch data）Server
直接存取後端資源Server
把機密留在 server（access token、API key）Server
把大型依賴留在 server、減少 client 的 JavaScriptServer

使用 state 與生命週期（useState、useReducer、useEffect）Client

反例：判準會翻轉的情況

「需要互動就用 client、不需要就用 server」是一個很好的起點，但不是把整個頁面一刀切開。真正容易出錯的地方，通常在於互動只占很小一塊，或某個套件偷偷依賴瀏覽器環境。

只有一小塊需要互動：不要整頁標成 client

假設頁面只有一個按鈕需要互動，卻把整個頁面標成 client。這會像為了開一盞小夜燈，把整間房子的電路都搬到門外：原本可以留在 server 的資料抓取與大型依賴，也會被拉進 client bundle。

比較好的做法，是把真正需要互動的部分抽成最小的 client 元件，也就是常說的 client island；其餘頁面則維持 Server Component：

// ❌ 整頁標成 client，連資料抓取都被拉到瀏覽器
"use client";
export default function Page() {
  // fetchData() 只能在瀏覽器跑了……
}

// ✅ Page 維持 Server Component，只把按鈕抽成 client island
// page.tsx（Server Component）
import LikeButton from "./LikeButton";
export default function Page() {
  return <LikeButton />;
}

元件本身不用互動，卻依賴只能在瀏覽器執行的套件

有些第三方套件必須在瀏覽器環境中才能運作。這時，即使你的元件本身沒有按鈕或表單互動，也要把「使用該套件的那一小塊」隔離成 Client Component，或改用動態載入。

重點不是把整個頁面一起拖到 client，而是把瀏覽器專用的依賴圈在最小範圍內。

把 Server Component 放進 Client Component 檔案

"use client" 是檔案層級的界線。一旦把 Server Component import 進 Client Component 檔案，它就會被當成 client 程式碼，失去直接使用資料庫、保管機密與容納大型依賴等 server 端優勢。

如果希望 server 先算好內容，再交給 client 元件使用，正確方式是透過 props 傳入。也就是由 Server Component 產生 JSX，再把它當作 children 或其他 prop 交給 Client Component；不要在 client 檔案裡直接 import Server Component。

加上 "use client"，不代表完全不會在 server 執行

另一個常見誤解是：只要標成 client，元件就完全離開 server。實際上，Client Component 仍可能先在 server 預先渲染，產生靜態外殼，之後再進行 hydration。

所以 "use client" 表示的是「這個元件需要 client 端能力」，不代表它的靜態部分不會先在 server 上算過一次。

最後的決策規則

先問：這個元件需要使用者互動嗎？ 需要，就標成 client；不需要，就留在 server。若只有一小塊需要互動，將它抽成最小的 client island，不要把整頁拖進 client bundle；也不要把 Server Component import 進 Client Component 檔案。
