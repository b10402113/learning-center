Next.js 到底幫你買到什麼

Step 3/4 · Why Next.js

學習目標

能說出 Next.js 的四類回報（省下工具配置、全端能力、效能、SEO），並解釋每一類各自對應什麼問題。

前言：白畫面、搜不到、後端還要另開一個專案

想像你交出一個 React 專案，客戶回饋三件事：第一，首頁打開時先空白零點幾秒才跳出內容，感覺很慢；第二，用 Google 搜品牌名，網站怎麼找都排不上；第三，行銷頁文案要改，工程師卻說「要改後端 API，得開另一個專案」。這些問題看似無關，其實都指向同一件事：純 React 只負責畫面，畫面以外的基礎設施全都得你自己補。

上一節我們確認了 Next.js 是蓋在 React 之上、把這些洞補起來的框架。這一節要把「補了什麼」講得具體一點。它買到的回報可以歸成四類：省下工具配置、全端能力、效能、SEO。看清楚每一類對應哪一種痛，你之後才有能力判斷一個專案該不該用它。

回報一：省下工具配置的時間

現代前端開發的每一環都在快速演進：編譯（compiling）、打包（bundling）、壓縮（minifying）、格式化（formatting）、部署（deploying），每個環節都有各自的工具與設定。工具愈多，你花在「把工具串起來」的時間就愈多。

Next.js 把這些設定收進框架裡。你不用再為了讓編譯器、打包器、部署流程彼此配合而頭痛，可以直接把時間花在寫 React 上。剩下的路由、資料抓取、渲染、認證等，它也都備好了開源解法，你只要專注在商業邏輯。

這個效益有多大？Vercel 副總裁 Lee Robinson 曾這樣描述從自行拼裝工具鏈換到框架的差別：

Moving from React + Express + Webpack to a framework resulted in removing 20,000+ lines of code and 30+ dependencies – while improving HMR (Hot Module Reloading) from 1.3s to 131ms.

兩萬多行程式碼、三十多個相依套件，換成框架之後直接消失，而且熱更新還從 1.3 秒縮到 131 毫秒。這就是「慣例優於設定（convention over configuration）」的具體模樣：框架把大方向的決定先做掉了，你少寫很多重複的基礎建設。

回報二：全端能力，前後端收進同一個專案

Next.js 不只是一個前端框架，它是一個全端（full stack）框架，讓你在寫前端的同一份專案裡，直接寫後端程式碼。傳統做法需要一個前端專案加一個後端專案，還得處理連接埠、部署、跨來源等問題；Next.js 把這件事簡化成同一個 codebase。

更省事的是，它的後端比你想像的單純。傳統後端應用要自己設定、自己配置路由，Next.js 則幾乎不用這些手續。前面提過的「慣例優於設定」在這裡再一次發揮作用：框架已經替你決定好後端程式碼該放在哪、怎麼被呼叫，你照著填就好。這也是為什麼它敢宣稱「學習曲線低」：後端不是多一門要學的技術，而是同一套思維的延伸。

回報三：更好的效能

Next.js 內建了伺服器端渲染（SSR，Server-Side Rendering）、靜態網站生成（SSG，Static Site Generation）以及自動程式碼分割（automatic code splitting）這些機制，用來最佳化應用效能：首頁載入更快、使用者體驗更好。

話說回來，伺服器端的能力並不是 Next.js 獨有，React 自己也推出了「React Server Components」這個可以在伺服器端渲染元件的概念。那為什麼還要選 Next.js？差別在便利與生產力。用 Next.js，你可以直接享用 React 的能力，卻不必自己動手做大量設定與配置；它把很多步驟自動化，讓你專注在功能本身，而不是基礎建設與樣板程式碼。換句話說，同樣的能力，自己拼要花的力氣大得多。

回報四：SEO，讓爬蟲看得到內容

這也許是最常被忽略、卻很重要的一項。搜尋引擎最佳化（SEO，Search Engine Optimization）的關鍵，在於 Next.js 與 React 的渲染方式不同。

你可以把搜尋引擎爬蟲想成一批每天到處拜訪網站的訪客。它們來向你要頁面內容，沿著連結一一檢視、整理，用來決定排名。它們很忙，需要很快看到頁面上有什麼，否則不會喜歡你的網站。而 React 是把所有東西都放在客戶端渲染：伺服器只回一份很精簡的 HTML，加上一個很大的 JavaScript 檔，由瀏覽器執行後才長出內容。問題是，爬蟲一開始看到的那份 HTML 裡什麼都沒有，內容是 JavaScript 之後才生出來的，這就讓爬蟲難以理解和收錄完整內容。

Next.js 則提供 SSG 或 SSR。在這種模式下，伺服器送出的是完整的 HTML，加上少量只負責互動的 JavaScript。爬蟲能輕鬆取得並正確索引網站的每一頁。為什麼值得在意 SEO？因為網站被看見、被排在前面，才會有人來。能見度、使用者體驗與信任感都會跟著提升，相對競爭對手也多一分優勢。網站做得再好，如果沒人搜得到，等於白做。

加分項：持續前進與業界採用

Next.js 還有一個常被提到的特質：它一直在進步。光是某一年就釋出七個以上的版本，持續把新功能加進來，目的就是讓開發更省事。它的影響力也外溢到其他生態系，例如用來寫 React Native 的 Expo，就受到 Next.js 的檔案式路由啟發，做出了 Expo Router，改善了 React Native 沿用十年的路由方式。

至於「有沒有人在用」，Next.js 官方展示牆上的名單頗有說服力：Notion、Hulu、Netflix Jobs、Nike、HBO Max、Audible、Typeform、TED、Product Hunt、Hyundai、Porsche、Ripple、Marvel、Futurism、Material UI、Coca-Cola、Ferrari、Hashnode、The Verge 等，都只是其中一部分。企業採用得快，代表市場對這項技能的需求也在成長。

回報它解決的痛機制
省下工具配置編譯、打包、部署都要自己串內建工具鏈與慣例
全端能力前後端要開兩個專案同一份專案寫後端，免設定路由
更好的效能首屏白畫面、載入慢SSR、SSG、自動程式碼分割
SEO爬蟲看不到客戶端渲染的內容伺服器直接送出完整 HTML

小結

Next.js 買到四類回報：省下工具配置（慣例優於設定，少寫大量基礎建設）、全端能力（前後端收進同一份專案）、更好的效能（內建 SSR、SSG 與自動程式碼分割）、以及 SEO（伺服器送完整 HTML，讓爬蟲收得到內容）。此外它持續推出新版本，業界採用也廣。但這些回報不是免費的，接下來要談的就是它的代價與適用時機。

到這裡，Next.js 的好處已經攤得差不多了。但任何工具都有兩面，如果只講優點，你日後看到 AI 把 Next.js 塞進一個三頁的靜態網站時，會說不出哪裡怪。最後一節要刻意唱反調：什麼情況下，你反而不該用它？
