「use client」這條線劃在哪裡？

Step 3/5 · Server vs Client Components

學習目標

能解釋 "use client" 如何把整個模組（連同它 import 的東西）標成 client 程式碼，並說明為什麼不能在 Client Component 裡塞 Server Component。

前言：那行字只影響一個元件，還是整個檔案？

上一節我們把兩種元件分清楚了，也知道加 "use client" 會讓元件變成 Client Component。但這裡有個很容易搞錯的直覺：很多人以為它就像一顆按鈕，按下去只改變「這一個元件」的身分。

真正的規則比這個嚴格得多。"use client" 管的不是單一元件，而是一整個檔案模組，甚至會沿著 import 往外擴散。這一節要把這條線劃清楚，因為它是 Next.js 裡最常被寫錯、也最容易讓 bundle 無聲膨脹的地方。

"use client" 是一條分界線

你可以把 "use client" 想成伺服器程式碼與 client 程式碼之間的一條分界線。當你在一個檔案的最上方寫下它，這個檔案就被歸到 client 這一側；一旦這條邊界立起來，邊界裡的所有東西都會變成 client 程式碼。

這裡的「所有東西」是關鍵。當你在某個檔案裡用了 "use client"，這個檔案所 import 的其他模組，包括那些原本是 Server Component 的子元件，都會被當成 client 模組的一部分。換句話說，邊界不是畫在元件的邊緣，而是畫在模組的邊緣；凡是從 client 模組往下長出來的枝葉，全部都會被一起拉進 client 那一側。

用一個實驗看它怎麼擴散

我們把之前那個 Server Component 塞進 Client Component 裡，看看會發生什麼事。原本 ExampleClient 只顯示自己，現在讓它也 import 並渲染 ExampleServer：

"use client";

import ExampleServer from "./ExampleServer";

const ExampleClient = () => {
  console.log("I'm Client Component :)");

  return (
    <>
      <div>
        <p>This an example client component</p>
      </div>
      <ExampleServer />
    </>
  );
};

export default ExampleClient;

存檔之後，先看終端機，三行日誌都在，這不意外。但接著打開瀏覽器的 Console，你會看到一個不太對勁的畫面：連 ExampleServer 那行「I'm Server Component」也出現在瀏覽器裡了。它不是應該只在伺服器端出現嗎？

答案是，當你 import 一個 server 元件到 client 檔案裡，它就不再是純粹的 server 元件了。它被拉進了 client 模組，於是跟著整個 client 一起被送到瀏覽器、一起在瀏覽器裡執行。原本你以為它住在伺服器，實際上它被拖到了用戶端。

所以規則很簡單：不要在 Client Component 裡塞 Server Component

把上面的實驗收斂成一句話：不要把 Server Component 包在 Client Component 裡面。這聽起來有點反直覺。如果你從上往下組畫面，很自然會想把一個元件放進另一個元件裡。但在 Next.js 的模型裡，這個動作會直接抹掉那個 server 元件的伺服器身分。

那如果畫面真的需要「有互動的外層」包住「需要讀資料的內層」怎麼辦？關鍵是別讓它們在 import 關係上變成父子。做法是讓 Server Component 留在外層，把 Client Component 當成子元件匯入；如果反過來有需求，也可以把 server 元件當作內容從外層傳進去，而不是從 client 檔案裡 import。這個組合技巧的完整細節會留到後面的專門章節，但現在你至少要知道：問題的根源是 import 的方向，不是元件本身。

回頭看看正確的擺法。只要兩個元件都在頁面層級被 import，它們就各自保有原本的身分：

import styles from './page.module.css'
import ExampleClient from '@/components/ExampleClient'
import ExampleServer from '@/components/ExampleServer'

export default function Home() {
    console.log("Where do I render?")

    return (
        <main className={styles.main}>
            <h2>Welcome </h2>
            <ExampleClient />
            <ExampleServer />
        </main>
    )
}

這樣一來，ExampleClient 依然是 client，ExampleServer 依然留在 server，兩者井水不犯河水。差別不在畫面上誰包住誰，而在 import 關係上誰把誰拉了進來。

小結

"use client" 不是標記一個元件，而是標記一個檔案模組。它是伺服器與 client 之間的分界線，一旦立起來，這個模組以及它 import 的所有東西，包含子 server 元件，都會變成 client 程式碼。所以不要把 Server Component 放進 Client Component 裡；要保住 server 身分，就讓它在 import 關係上留在外層。

現在你懂了這條邊界的運作方式，也知道它會怎麼擴散。但有機制的知識還不足以應付每天的開發。真正要練的是：拿到一個元件，怎麼在三秒內判斷它該放哪一邊？下一節要用一個問題，把這個判斷變成可以反覆使用的流程。
