Server Component 與 Client Component 到底是什麼？

Step 2/5 · Server vs Client Components

學習目標

能說出兩種元件各自在哪裡執行、哪一種是預設，並用 console.log 實驗分辨日誌會出現在終端機還是瀏覽器。

前言：怎麼一眼看出這個元件在哪裡跑？

上一節我們看到，Next.js 把「在哪裡渲染」的選擇權下放到了單一元件。現在問題變得很具體：既然每個元件都能選，那我手上這個元件現在到底在哪裡執行？我又要怎麼確認？

這一節要把兩個當事人請出來，說清楚 Server Component 與 Client Component 各自是什麼，然後用一個幾乎不用設定的實驗讓你當場分辨：在元件裡加一行 console.log，看它出現在終端機還是瀏覽器。這個實驗很簡單，卻是整個架構判斷的起點。

預設是 Server Component

在 app directory 裡，有一個很容易被忽略、但非常重要的預設：你寫的每一個元件，都會被當成 Server Component，除非你明確說它不是。換句話說，Server Component 不是某種要特別開啟的模式，而是你什麼都不做時的自然狀態。

為什麼會把「伺服器」當成預設？因為從效能與安全的角度來看，能留在伺服器端處理的事情，通常比送到瀏覽器更划算。預設站在安全又省資源的那一邊，開發者只在必要時才把東西往瀏覽器推。

Server Component：在伺服器端執行，只把 HTML 送出去

Server Component 在伺服器上渲染，它產生的 HTML 再被送到 client。因為執行過程完全發生在伺服器，這類元件可以直接存取伺服器端的資源，例如資料庫或檔案系統；這也代表傳到瀏覽器的 JavaScript 變少了，載入效能因此更好。

它特別適合兩種任務：一種是需要直接使用伺服器資源的時候（例如讀取檔案系統裡的檔案），另一種是你想把敏感資訊留在伺服器上的時候，例如存取權杖（access token）或 API 金鑰。這些東西一旦送進瀏覽器，就等於公開了。

先看一個最單純的 Server Component：

const ExampleServer = () => {
  console.log("I'm Server Component :)");

  return (
    <div>
      <p>This is an example server component</p>
    </div>
  );
};

export default ExampleServer;

這個檔案裡沒有做任何特別的宣告，所以它就是一個 Server Component。注意那行 console.log，等一下我們要用它來驗證它到底在哪裡執行。

用一行 console.log 驗證：日誌跑到終端機去了

把一個頁面元件加上一行 console.log，然後觀察它出現在哪裡。以首頁為例：

import styles from './page.module.css'

export default function Home() {
    console.log("Where do I render?")

    return (
        <main className={styles.main}>
            <h2>Welcome </h2>
        </main>
    )
}

打開瀏覽器，你會發現這行訊息根本不在瀏覽器的 Console 裡。它跑到哪裡去了？答案是終端機，也就是你執行 npm run dev 的那個視窗。這個現象正好證明了它是 Server Component：程式碼在伺服器端被執行，所以日誌從伺服器印出來，而不是從瀏覽器。

Client Component：在瀏覽器執行，要加 "use client"

另一種元件是 Client Component，它在用戶端（也就是瀏覽器）渲染。要在 Next.js 裡使用它，你得在檔案最上方加上一行 "use client"。這行程式碼像是一個開關，告訴 Next.js：「這個檔案請當成 client 程式碼看待。」

"use client";

const ExampleClient = () => {
  console.log("I'm Client Component :)");

  return (
    <div>
      <p>This an example client component</p>
    </div>
  );
};

export default ExampleClient;

Client Component 適合需要瀏覽器互動的場合，例如點擊按鈕、在輸入框打字、送出表單。這些行為都得靠瀏覽器才有辦法完成，所以必須在用戶端執行。

一個讓人困惑的現象：client 的日誌也出現在終端機

到目前為止都很直覺。但當你把 ExampleClient 和 ExampleServer 一起放進頁面，再仔細看兩邊的日誌，會發現一件怪事：瀏覽器只印出 client 那一行，終端機卻把兩行都印了。Server Component 的日誌出現在終端機很正常，可是 Client Component 的日誌，怎麼也在伺服器端冒出來了？

原因跟 Next.js 的預先渲染（pre-rendering）有關。伺服器端的元件保證只在伺服器渲染；client 元件雖然主要在用戶端渲染，但 Next.js 也會在伺服器端先把它渲染一次，做出一個「靜態外殼」，目的是讓使用者更快看到畫面，同時也對搜尋引擎更友善。

更精確地說，Next.js 預設會做靜態渲染：它會先在伺服器端把能渲染的內容準備好，再送出給 client。Client Component 裡那些不需要互動、也不依賴瀏覽器的部分，就能在伺服器端先渲染完成；真正需要瀏覽器或互動的片段，則先留成佔位符，等到了瀏覽器，再由瀏覽器把 Client Component 渲染好、把佔位符填上。這個「先接上事件處理」的過程，就是 hydration（注水）。

小結

在 app directory 裡，每個元件預設都是 Server Component。Server Component 在伺服器端渲染，只把 HTML 送到瀏覽器，也因此能直接存取資料庫或檔案系統、把敏感資訊留在伺服器。Client Component 在瀏覽器渲染，需要在檔案最上方加上 "use client"，用來處理需要互動的部分。由於 Next.js 會預先渲染，Client Component 的日誌在終端機也會出現，但只有它會出現在瀏覽器。

你現在知道兩種元件差在「在哪裡執行」，也知道預設是哪一種了。但你可能已經注意到一個可疑的細節："use client" 看起來只是加在檔案最上面的一行字，它到底只影響那一個元件，還是會影響整個檔案裡的所有東西？下一節就要把這條邊界劃清楚。
