Hydration mismatch：伺服器與瀏覽器為什麼會對不上

Step 4/5 · The Web-Rendering Model

學習目標

能說出 hydration mismatch 的成因：伺服器渲染出的 HTML 與瀏覽器首次渲染的結果不一致時，React 無法把事件正確接上而報錯。

前言：畫面明明出來了，為什麼主控台在罵人？

上一節看到 Next.js 把畫面分成兩段：伺服器先畫一份 HTML，JavaScript 到了之後再用 hydration 把互動接上去。這個設計有個前提：伺服器畫的那一份，和瀏覽器「第一次」畫的那一份，必須長得一模一樣。

但實務上有時候畫面明明顯示出來了，瀏覽器卻跳出一個 hydration error，告訴你伺服器渲染的結果和用戶端對不起來。這不是隨機的故障，而是這個「兩邊必須一致」的設計，在特定寫法下必然會踩到的結果。這一節要把 mismatch 從哪裡來講清楚，你以後看到這個錯誤訊息，才知道該往哪裡找。

hydration 是一場「配對」

先回頭確認 hydration 的本質。它做的事，是拿伺服器已經產生的那份 HTML 當底稿，把 JavaScript 的事件處理接到對應的節點上。既然要「接到對應的節點」，前提就是兩邊的結構必須一一對得上：伺服器渲染出一個按鈕，瀏覽器也必須渲染出同一個按鈕，事件才掛得上去。

所以當伺服器回傳的 HTML，和瀏覽器第一次渲染出來的結果不一致時，React 就找不到該掛的節點、也無法正確接手。這種情況就是你看到的 hydration error，畫面和伺服器最初渲染的內容出現落差。

mismatch 具體長什麼樣

用 React 元件的說法：伺服器會先渲染出一組佔位結構，例如 div、form、span 這些標籤；等到瀏覽器端也要渲染同一批元件時，如果它畫出來的內容和伺服器那份對不上，你就會看到錯誤。這些「先出現、之後要被對上」的標籤，就是問題的所在。

換句話說，錯誤不是因為 HTML 壞了，而是因為「伺服器版」和「瀏覽器版」的首次渲染，說了不同的話。

為什麼兩邊會說不同的話？

關鍵在於：伺服器渲染時，是在伺服器那台機器上執行；瀏覽器渲染時，是在使用者的裝置上執行。只要元件在第一次渲染時用到了「兩邊結果不可能相同」的資訊，兩份輸出就會分歧。

最典型的情況，是依賴「只有瀏覽器才有、或每次都不一樣」的值。例如把當下時間顯示在畫面上：伺服器算出的時間和使用者瀏覽器算出的時間本來就不同，於是兩邊渲染出來的文字對不上。

// 概念示意：兩邊各自算「現在時間」，結果必然不同
function Clock() {
  return <span>{new Date().toLocaleTimeString()}</span>;
}

當伺服器先產生一份帶有某個時間的 HTML，瀏覽器再算一次卻得到另一個時間，兩份就對不起來，hydration 也就失敗了。同樣的道理，任何讓首次渲染結果依賴外部環境、而且兩邊環境不同的寫法，都可能引發 mismatch。

一致與不一致的差別

情況伺服器首次渲染瀏覽器首次渲染結果
一致相同的結構與內容相同的結構與內容hydration 成功，互動接上
不一致某一種內容另一種內容hydration error，對不上

所以正確的心態不是「把錯誤訊息壓掉」，而是理解：hydration 需要兩次渲染的結果一致。知道這件事，你才有辦法判斷哪些寫法會讓伺服器與瀏覽器各說各話。

小結

hydration 要拿伺服器渲染好的 HTML 當底稿，把事件接到對應的節點上。當伺服器渲染的佔位結構（div、form、span 等）與瀏覽器首次渲染的結果不一致時，React 就對不上而報出 hydration mismatch。根本原因是首次渲染若依賴兩邊環境不同的資訊（例如當下時間），輸出一分歧，配對就會失敗。
