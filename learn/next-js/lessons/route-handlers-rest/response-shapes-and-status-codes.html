狀態碼與 response 信封：端點對外的合約

Step 3/5 · Route Handlers 與 REST API 設計

一個端點除了要讀對路徑與參數，還要讓呼叫它的前端知道結果代表什麼。HTTP 狀態碼與固定的 response body 形狀，就是端點對外使用的合約。

學習目標

查閱常用 HTTP 狀態碼的語意、NextResponse.json 的用法，以及一致的 response 信封（success／data／error／status）格式。

回傳工具：Response 與 NextResponse

Response 是標準 Web API 物件，Next.js 支援它以對齊 Web 標準。使用 new Response 時，需要自行執行 JSON.stringify，也需要自行設定標頭：

export async function GET() {
  return new Response(JSON.stringify({ message: "Hello" }), {
    status: 200,
    headers: {
      "Content-Type": "application/json",
    },
  });
}

NextResponse 是 Next.js 在標準 Response 上提供的擴充工具。常用的 NextResponse.json() 會自動將物件序列化，並將 Content-Type 設為 application/json：

export async function GET() {
  return NextResponse.json({ message: "Hello" }, { status: 200 });
}
工具標頭額外能力適用時機
new Response自行設定無，純 Web 標準需要可攜性、不綁定 Next.js
NextResponsejson() 自動設定 application/jsoncookies、rewrite、redirectNext.js 專案中的 route handler

涉及 cookie、改寫網址或重新導向時，使用 NextResponse：

export async function GET() {
  const response = NextResponse.json({ message: "Hello" });
  response.cookies.set("myCookie", "cookieValue");
  return response;
}

請求物件：Request 與 NextRequest

Request 是標準請求物件；NextRequest 是 Next.js 的擴充版本，提供 nextUrl.searchParams 與 cookies 等方法。

使用 NextRequest 讀取查詢參數或 cookie：

export async function GET(request: NextRequest) {
  const id = request.nextUrl.searchParams.get("id");
  const cookie = request.cookies.get("myCookie");
}

使用標準 Request 時，需先以 new URL(request.url) 建立 URL，再取得 searchParams。兩者都可用，差別在於便利性與可攜性。

常用 HTTP 狀態碼

狀態碼表示請求處理的結果。以下列出 route handler 常見的狀態碼：

狀態碼語意典型使用時機
200 OK請求成功成功讀取清單或單筆資料
201 Created資源已建立POST 成功新增一筆資料
204 No Content請求成功，但沒有回傳內容刪除成功，沒有 body 可回傳
400 Bad Request請求本身不合法body 驗證失敗、欄位格式錯誤
401 Unauthorized未通過身分驗證沒有登入或 token 失效
403 Forbidden身分已識別，但沒有權限重複的資源、禁止的操作
404 Not Found找不到目標資源依 id 查詢但查無資料
500 Internal Server Error伺服器端發生非預期錯誤未捕捉的例外、資料庫故障

Response 信封：一致的回應形狀

除了狀態碼，response body 也使用固定格式。DevFlow 定義一組全域型別，讓每個端點都回傳同一種信封：包含 success 布林值，以及可選的 data、error 與 status。

type ActionResponse<T = null> = {
  success: boolean;
  data?: T;
  error?: {
    message: string;
    details?: Record<string, string[]>;
  };
  status?: number;
};

type SuccessResponse<T = null> = ActionResponse<T> & { success: true };
type ErrorResponse = ActionResponse<undefined> & { success: false };

type APIErrorResponse = NextResponse<ErrorResponse>;
type APIResponse<T = null> = NextResponse<SuccessResponse<T> | ErrorResponse>;
型別定義
ActionResponse回應信封的基底型別，包含 success，並可帶有 data、error 與 status
SuccessResponse將 success 固定為 true 的成功回應型別
ErrorResponse將 success 固定為 false 的錯誤回應型別
APIErrorResponse包裝 ErrorResponse 的 NextResponse 型別
APIResponse包裝成功或錯誤回應的 NextResponse 型別
欄位型別或內容用途
successboolean表示請求成功或失敗
data由泛型 T 決定成功時放置回傳資料
error.messagestring失敗時的錯誤訊息
error.detailsRecord<string, string[]>可選的詳細錯誤資訊，例如逐欄位錯誤訊息
statusnumber可選的狀態碼

實際回傳時，將信封物件交給 NextResponse.json，並在第二個參數指定狀態碼：

return NextResponse.json({ success: true, data: users }, { status: 200 });

端點回應格式

本節的查閱內容包含回傳工具、請求物件、HTTP 狀態碼，以及 response 信封型別。實作端點時，可依照這些定義組合 body、狀態碼與 NextResponse。

小結

使用 NextResponse.json(data, { status }) 回傳 JSON，會自動處理 application/json 標頭；cookie、rewrite 與 redirect 也使用 NextResponse。常用狀態碼包括：200 讀取成功、201 建立成功、204 刪除成功、400 驗證失敗、404 找不到資源、500 非預期錯誤。Response body 統一使用 ActionResponse 信封，包含 success、data、error 與 status。
