動態區段與 params

Step 3/5 · Routing as a Filesystem

學習目標

用方括號 [param] 建立動態路由，並解釋 params 的值與 key 各自從哪裡來。

前言：如果商品有一千個，你要開一千個資料夾嗎？

上一節我們用巢狀資料夾造出了 /projects/list 這種固定路徑。現在問題來了：假設這個專案有三個作品，網址分別是 /projects/jobit、/projects/carrent、/projects/hipnode。依照目前學到的規則，你得開三個資料夾、放三份幾乎一模一樣的 page，只差顯示的文字不同。

三個勉強還能忍。但如果使用者可以自己新增作品，作品數量是無限的呢？你不可能為每一筆資料預先開一個資料夾，更不可能把同一份詳情頁的程式碼複製一千遍。這一節要介紹的動態區段，就是讓「一條路由」服務「無限多條 URL」的機制，也是所有詳情頁、個人頁、文章頁背後的共同原理。

先看硬幹會長什麼樣

假設我們先建一個動態區段，但還沒讀出網址裡的值，那個頁面只能寫死一個標題：

export default function ProjectDetails() {
    return (
        <main>
            <h1>Project Name</h1>
        </main>
    )
}

不論你拜訪 /projects/jobit 還是 /projects/carrent，畫面都只會顯示「Project Name」。路由本身換了，內容卻沒換，因為這個元件還不知道當下是哪一筆資料。要把「網址裡的那一段」餵給元件，就得靠動態區段。

方括號就是「這裡是變數」

建立動態路由的方法，是把資料夾名稱用方括號包起來，例如 [slug]。方括號的意思是：這個區段不是固定字串，而是一個變數，任何值都可以放進來。所以 app/projects/[slug]/page.tsx 這一個檔案，會同時匹配 /projects/jobit、/projects/carrent、/projects/hipnode，以及未來任何以 /projects/ 開頭的路徑。

方括號裡的名字可以自己取。慣例上常用 slug 代表網址裡的一段可讀字串，用 id 代表識別碼；但重點是：你取的名字，會決定後面讀值時要用哪個 key。這條連結我們下一段馬上會看到。

params 從哪來：一個資料夾名對一個 key

動態區段被比對到之後，Next.js 會把「實際出現在網址裡的值」包成一個物件，當成 params 這個 prop 傳給你的 page。你只要在元件參數裡接住它，就能把值顯示出來：

export default function ProjectDetails({ params }) {
    return (
        <main>
            <h1>Project {params.slug}</h1>
        </main>
    )
}

現在拜訪 /projects/carrent，params.slug 就是 "carrent"；拜訪 /projects/hipnode，它就變成 "hipnode"。同一份程式碼，因為網址不同而顯示不同內容。

這裡的對應規則值得記牢：資料夾 [slug] 對應 params.slug；如果資料夾是 [id]，就要讀 params.id；是 [name]，就讀 params.name。方括號裡叫什麼，params 的 key 就叫什麼，兩者必須同名，沒有第二種可能。所以你不會「忘記」key 是什麼，只要回頭看資料夾名字就好。

靜態路由動態路由
資料夾寫法about[slug]
匹配的 URL只有 /about/projects/ 後面任意值
一個檔案服務幾條 URL一條無限多條
值從哪讀不需要，路徑固定params，key 等於資料夾名

Next 15 的 params 是 async 的

上面是課本為了講解而簡化的寫法。在真實的 Next.js 15 專案裡，params（以及查詢字串用的 searchParams）是非同步的，必須先 await 才能取值。以下是 DevFlow 專案裡動態題目頁 app/(root)/questions/[id]/page.tsx 的片段：

export async function generateMetadata({
  params,
}: RouteParams): Promise<Metadata> {
  const { id } = await params;

  const { success, data: question } = await getQuestion({ questionId: id });

  if (!success || !question) {
    return {
      title: "Question not found",
      description: "This question does not exist.",
    };
  }
  …

這個檔案在 app/(root)/questions/[id]/ 底下，所以它是一條動態路由；資料夾叫 [id]，於是它用 const { id } = await params 把值取出來，再拿去查詢那筆題目。你可能會想：為什麼 generateMetadata 和頁面元件都要自己取一次 params？那是因為它們是兩個不同的函式，各自接收一份。

這個 await 是審查 AI 產出時很值得盯的細節。如果你看到某段程式碼寫成 const { id } = params（少了 await），在 Next.js 15 裡 params 不再是現成的物件，這個取值會拿到 undefined，於是查詢用的 id 是空的，頁面就掛了。反過來，只要看到動態頁面在讀 params 前有 await，而且 key 跟資料夾名對得上，這條路由的基本正確性就過了一半。

小結

把資料夾名稱用方括號包起來（例如 [slug]），就建立了一個動態區段，讓一個 page 檔案服務無限多條 URL。Next.js 會把網址裡實際的那段值包成 params 傳給頁面，而 key 就是你方括號裡取的名字：[slug] 對 params.slug，[id] 對 params.id。在 Next.js 15，取值前記得 await。

動態區段解決了「一條路由服務很多 URL」。下一節換一個不同的煩惱：當 app/ 底下的資料夾愈來愈多，要怎麼兼顧檔案分類的整齊與 URL 的簡潔？答案是用括號把資料夾「藏」起來，也就是 route group。
