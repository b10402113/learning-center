資料夾就是路由：檔案路由的第一條規則

Step 1/5 · Routing as a Filesystem

學習目標

說出檔案路由的兩條規則（資料夾定義 URL 區段、page 檔定義該區段的 UI），並解釋它如何取代 React Router 的設定檔。

前言：你上一次「設定路由」是什麼時候？

想像你剛接手一份 React 專案，有人請你「把 About 頁加一條新路由」。你的第一反應可能是打開一個叫做 App.js 或 routes.js 的檔案，在裡面某一堆 <Route> 標籤之間，找到對的位置、複製一行、改個路徑。路由不是「檔案放哪裡」，而是一份要人去維護的清單。

Next.js 的 App Router 把這件事反過來做：你不再編輯一份路由表，而是用資料夾結構本身來表達路由。新增一條 /about，你就在 app/ 底下建一個 about/ 資料夾。這一節先把這個最基本的對應關係講清楚，因為之後的巢狀路由、動態路由、route group 全部都是疊在這兩條規則之上。搞懂它，你看到 AI 產出的任何一棵 app/ 樹，都能直接唸出它有哪些路由。

React 時代：路由是一份要自己維護的設定

先看看沒有檔案路由時，一條路由是怎麼被「登記」的。在 React 裡，我們常用 react-router-dom 這個外部套件，把每一條路徑對應到哪個元件，明明白白寫在一份設定裡：

import { BrowserRouter as Router, Route, Link, Routes } from 'react-router-dom';

const App = () => {
    return (
        <Router>
          <Routes>
            <Route path="/" element={<Home />} />
            <Route path="/about" element={<About />} />
            <Route path="/contact" element={<Contact />} />
          </Routes>
        </Router>
     );
};

export default App;

三條路由還好。但一個真實的電商網站會有商品列表、商品詳情、賣家後台、訂單、評價、商品底下再分價格與照片……這些路徑全部要一層一層手寫進設定檔，而且巢狀關係是用縮排和標籤的嵌套去表達的：

import React, { Fragment } from 'react';
import { BrowserRouter as Router, Route, Routes } from 'react-router-dom';

function App() {
  return (
    <Router>
      <Fragment>
        <Routes>
          <Route path="/" element={<Layout />}>
            <Route index element={<Home />} />
            <Route path="about" element={<About />} />
            <Route path="products" element={<Products />} />
            <Route path="products/:id" element={<ProductDetail />} />

            <Route path="seller" element={<SellerLayout />}>
              <Route index element={<Dashboard />} />
              <Route path="orders" element={<Orders />} />
              <Route path="reviews" element={<Reviews />} />
              <Route path="products" element={<SellerProducts />} />
              <Route path="products/:id" element={<SellerProductDetail />}>
                <Route index element={<SellerProductInfo />} />
                <Route path="pricing" element={<SellerProductPricing />} />
                <Route path="photos" element={<SellerProductPhotos />} />
              </Route>
            </Route>
          </Route>
        </Routes>
      </Fragment>
    </Router>
  );
}

export default App;

還沒有一個大網站該有的規模，這份設定就已經開始讓人頭痛了。你必須額外安裝並維護一個套件、熟記它的標籤語法，而且每當檔案搬動，你還得回來確認設定有沒有跟上。路由的真相（哪些頁面存在、誰是誰的子層）散落在兩個地方：檔案樹，和這份設定。

Next.js 的兩條規則

Next.js 用「檔案路由」把兩份真相合而為一。它的規則只有兩條：

資料夾定義路由（URL 的區段）；檔案定義那個區段的 UI。

把這句話翻成具體對應：一個資料夾的名字，就是 URL 上的一段路徑；而這個資料夾裡一個叫做 page 的特殊檔案（page.js、page.jsx 或 page.tsx），就是造訪那條路由時要顯示的畫面。上面那三條 React 路由，在 Next.js 裡只需要兩個資料夾 about、contact，再加上一個根目錄的 page.js，而且不用安裝任何路由套件。

React RouterNext.js 檔案路由
路由登記方式在設定檔手寫 <Route>建立資料夾，放進 page 檔
需要外部套件嗎需要 react-router-dom內建，不用安裝
巢狀關係怎麼表達標籤一層層嵌套資料夾一層層嵌套
路由真相在哪設定檔＋檔案樹兩份只有檔案樹一份

動手：一個資料夾就是一條路由

假設我們要 /contact 這條路由。做法就是：在 app/ 底下建立一個 contact/ 資料夾，裡面放一個 page.tsx，內容就是一個普通的 React 元件：

export default function Contact() {
  return (
    <main>
      <h1>Contact</h1>
    </main>
  )
}

就這樣，不需要動任何設定。存檔之後回到瀏覽器，網址列輸入 /contact，畫面就會切到這個元件，而且不用手動重新整理，這是 Next.js 的 Fast Refresh 在即時套用你的修改。同樣地，把上面的 contact 換成 about、把 <h1> 換成 About，就得到 /about。

這裡有個容易踩的小地方：資料夾名字會原封不動變成 URL。所以請用小寫，並遵循 kebab case（用連字號分隔單字，例如 sign-in、ask-question），不要寫成 SignIn 或 sign_in。你怎麼命名資料夾，路由就長怎樣，兩者沒有模糊空間。

為什麼看資料夾就能看懂路由

這個設計最實用的地方，是它讓「這條路由在哪裡」和「這個頁面在做什麼」變成同一個問題。打開任何 Next.js 專案的 app/ 資料夾，你不需要先找到某個 router 設定檔才能知道網站有哪些頁面，資料夾的形狀就是路由的形狀。

這一點在審查 AI 產出的架構時特別好用。如果 AI 說它做了一個「商品詳情頁」，你只要去看 app/ 底下有沒有對應的資料夾與 page 檔，就能立刻驗證。它無法靠嘴巴宣稱一條不存在的路由，因為路由必須真的以資料夾的形式落地。反過來，如果 app/ 底下冒出一堆沒有 page 檔的資料夾，那多半只是還沒接上 UI 的空殼。

小結

Next.js 的檔案路由只有兩條規則：資料夾定義 URL 區段，page 檔定義該區段的 UI。它把 React Router 那種「一份要手動維護的路由設定」換成「資料夾結構本身就是路由」，所以不需要外部套件，路由的真相也只有一份：檔案樹。資料夾命名要小寫、用 kebab case，因為它會直接變成 URL。

現在你已經會用資料夾造出單層的靜態路由了。但真實網站幾乎都有像 /projects/list 或 /dashboard/settings 這種多層路徑，而且每一頁還要共用導覽列。下一節就看巢狀資料夾如何產生巢狀路由，以及 layout 如何包住一整段子樹。
