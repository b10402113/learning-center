Route Groups：組織檔案，但不進 URL

Step 4/5 · Routing as a Filesystem

學習目標

判斷何時該用 route group 來組織檔案並套用群組專屬 layout，而不用讓資料夾名進入 URL。

前言：檔案想分類，網址想簡潔，可以兩全嗎？

走過前三步，你已經能用資料夾造出靜態、巢狀、動態三種路由。但這裡浮現一個很現實的矛盾。資料夾現在要同時扮演兩個角色：檔案分類的容器，和 URL 的來源。當這兩個角色打架時就麻煩了。

假設你要做登入頁。你希望網址是乾淨的 /sign-in，但你也希望在專案裡把登入、註冊這類「授權相關」的頁面收在一個 auth 資料夾底下，方便未來維護。可是第一節規則說得很清楚：資料夾名就是路由。你把 sign-in 放進 auth/，網址就自動變成 /auth/sign-in，分類是有了，但 URL 被污染了。這一節要處理的，就是這個「何時該用 route group 把資料夾從 URL 裡藏起來」的決定。

三個選項擺在一起看

先別急著選。面對「登入頁到底放哪」這個問題，其實有三條路，各有代價：

做法URL 長相檔案組織代價
直接放 app/sign-in/sign-in 乾淨授權頁散在頂層app/ 頂層容易被各種頁面塞爆
放 app/auth/sign-in/auth/sign-in授權頁集中多一層 auth 不是你要的 URL
放 app/(auth)/sign-in/sign-in 乾淨授權頁集中需要知道括號這個約定

Route group 就是第三條路。它的語法是把資料夾名稱用括號包起來，例如 (auth)。括號的作用只有一個：告訴 Next.js「這個資料夾是拿來分類的，請不要把它算進 URL」。於是 app/(auth)/sign-in/page.tsx 對外仍然是 /sign-in，資料夾裡的組織方式則完全保留。

判別問句：兩個問題決定要不要用

遇到一個資料夾，你可以依序問自己兩個問題。第一題：

這個資料夾的名字，我希望它出現在使用者的網址裡嗎？

如果答案是「希望」（例如 /blog 底下的文章就該是 /blog/xxx），那它就是一條正常的巢狀路由，用普通資料夾就好，不需要括號。如果答案是「不希望，但我又想把它集中收納」，那就是 route group 的時機。

第二題：

這一整組頁面，需要一套和其他區塊不同的 layout 嗎？

如果需要，route group 更是首選。因為你可以在 (auth)/ 底下放一個 layout.tsx，它就會套用到 (auth) 底下的所有路由，而完全不會影響其他區塊，同時 URL 還是乾淨的。這正是 DevFlow 專案的實際用法：(auth) 有置中的卡片外框，(root) 有導覽列加側邊欄的外框，兩組共用同一個 root layout，卻各有一套自己的外框。

反例：什麼時候「不該」用 route group

括號很好用，但它不是萬用分類標籤。有兩個情況要特別小心。

第一，當你其實希望那一段出現在 URL 裡時，就不該用。例如一個電商網站的後台，你想要 /seller/orders、/seller/products，seller 是網址結構的一部分，那它就不該被包成 (seller)，包起來反而會讓網址變成 /orders，和前台首頁的層級混淆。判準就是前面那個問句：資料夾名該不該出現在 URL。

第二，route group 之間的路徑不能撞在一起。你可以想成「括號只是被忽略，裡面的路徑仍要合併到同一張路由表」。如果兩個 group 都想定義同一條路徑（例如 (marketing)/about 和 (shop)/about），Next.js 無法決定該給誰，就會直接報錯。括號不會幫你隔離衝突，它只是讓分類不出現在 URL，衝突與否仍以最終路徑為準。

決策規則與檢查表

把上面的判斷收斂成幾條可以當場用的規則：

  1. 資料夾名要出現在 URL → 用普通資料夾，這就是一條巢狀路由。
  2. 資料夾名不要出現在 URL，但你想把相關檔案收在一起 → 用 (name) route group。
  3. 這一組頁面還需要專屬 layout → 在 route group 裡放 layout.tsx。
  4. 動態區段與 route group 可以混用：(root)/profile/[id] 表示「profile 分類下的動態頁，但 root 不出現、id 是變數」。
  5. 動手前先確認最終路徑沒有和別的 group 撞名，否則會建置失敗。

小結

Route group 用括號把資料夾名從 URL 裡拿掉，例如 (auth)/sign-in 對外就是 /sign-in。它讓「檔案怎麼分類」和「URL 長什麼樣」兩件事脫鉤，而且可以在群組內放專屬的 layout.tsx。判準是兩個問題：這個名字要不要出現在網址？這一組要不要自己的外框？要分類、不要污染 URL、想要群組外框，就用它；但切記 group 之間的最終路徑不能衝突。

到這裡，你手上已經有五塊積木：資料夾即路由、巢狀路由、巢狀 layout、動態區段、以及 route group。最後一節不再教新語法，而是把它們全部串起來，拿一棵真實專案的 app/ 資料夾樹，一步步推導出完整的路由表與每一條路由的 layout 鏈。
