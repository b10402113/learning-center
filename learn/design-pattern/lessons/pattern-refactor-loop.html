怎么读懂一个模式章节

design-pattern · pattern-refactor-loop

学习目标

能用"场景模拟 → 一坨代码 → 模式重构 → 总结"的框架去读任何一个模式章节，并带着"模式买扩展、付出类数量代价、要判断 ROI"的取舍意识。

为什么要有一个统一读法

接下来你要读 22 个模式章节。如果每个章节都从头摸索"我该看什么、跳过什么"，效率极低。好消息是：《重学 Java 设计模式》的每个章节都遵循同一套结构。你只需要学会这套结构，就能高效地读任何一章。

每个模式章节都是一次"同一套流程的重复"：先看场景，再看烂代码，再看模式重构，最后看总结里的取舍。学会这个循环，22 个模式就是 22 次同构练习。

四步阅读框架

1

场景模拟

看业务场景——这本书用真实互联网场景（积分兑换、支付聚合、审批流等）。理解"这个场景长什么样、有什么真实约束"，让模式挂靠到你认识的业务上。

2

一坨代码

看 ifelse 实现——认出坏味道。关注：这个 ifelse 按什么字段分发？每个分支在干什么？增长时会怎样？这就是上一步学的"认识坏味道"的实战。

3

模式重构

看设计模式实现——重点看结构变化。类图怎么变了？新增了哪些接口和类？原来 ifelse 里的分支逻辑跑到了哪里？对比前后代码，让结构差异"咔哒"一声。

4

总结

看总结——满足了哪些原则？带来了什么好处？付出了什么代价？这个模式适合什么场景、不适合什么场景？这是判断 ROI 的环节。

取舍意识：模式不是免费午餐

每个模式都在做一笔交易：

你买到的 你付出的
可扩展性——加新类型不改旧代码 更多的类和接口
低耦合——模块之间互不影响 间接结构——调用链变长
高内聚——每个类只干一件事 认知成本——要理解更多文件的关系
可复用——写过的代码能在别处用 过度设计风险——简单场景用模式是杀鸡用牛刀
ROI 判断是核心能力。不是所有场景都值得用模式。只有当"加新类型的频率"和"维护成本"高到一定程度时，模式才值得它的类数量代价。这本书 22 个模式都给了适合和不适合的场景——读总结时重点关注这个。

实战：用这个框架读工厂方法那一章

拿第一步学的工厂方法模式练习一下：

  1. 场景模拟：积分兑换，三种奖品（优惠券、实物商品、兑换卡），三家第三方接口完全不一样，以后还会加新产品
  2. 一坨代码：一个 awardToUser() 方法里按 awardType 做 ifelse，每种类型各自拼参数、调服务、映射返回值
  3. 模式重构：ICommodity 接口 + 三个实现类（各包装一个第三方服务）+ StoreFactory 按类型选实现。ifelse 消失了，每个产品逻辑独立成一个类
  4. 总结：满足单一职责（每个类干一件事）+ 开闭（加新产品只加类不改旧代码）。代价是多出几个类——但新产品会持续加，所以值得

后面 21 个模式，每次都走这四步。读多了你会发现，很多模式的"一坨代码"长得几乎一样——都是按 type 字段分发的 ifelse。区别只在于重构方向不同。

本节要点回顾

  • 四步阅读框架：场景模拟 → 一坨代码 → 模式重构 → 总结
  • 每步都有明确的关注点：场景认业务、ifelse 认坏味道、重构看结构变化、总结看取舍
  • 模式是一笔交易：买扩展性，付类数量代价
  • ROI 判断是核心能力——不是所有场景都值得用模式
  • 22 个模式 = 22 次同构练习，同一套流程反复用

推荐阅读：《重学 Java 设计模式》工厂方法模式章节的完整流程——从场景到总结走一遍四步框架。
