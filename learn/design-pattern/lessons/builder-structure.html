建造者模式的三層結構

設計模式 · 建造者模式 · Step 3/4
學習目標：掌握建造者模式的三層結構——IMenu 接口定義填充契約、DecorationPackageMenu 承載物料與價格計算、Builder 集中建造過程。

重構思路：三層分離

ifelse 版本的問題在於「一個方法幹三件事」。建造者模式的重構思路是把這三件事拆到三個角色：

角色職責對應類
填充契約定義「能往套餐裡加什麼物料」IMenu 接口
填充器承載物料清單、按係數計算價格DecorationPackageMenu
建造者集中所有套餐的建造過程Builder

第一層：IMenu 接口

接口定義了五個方法：

public interface IMenu {
    IMenu appendCeiling(Matter matter);  // 加吊頂
    IMenu appendCoat(Matter matter);     // 加塗料
    IMenu appendFloor(Matter matter);    // 加地板
    IMenu appendTile(Matter matter);     // 加地磚
    String getDetail();                  // 獲取明細
}

注意返回值是 IMenu 本身——這是為了支持鏈式調用。每個 append 方法把物料加入清單後返回 this，讓你可以寫成：

menu.appendCeiling(ceiling)
    .appendCoat(coat)
    .appendFloor(floor)
    .getDetail();

接口把「逐項填充物料」和「輸出明細」抽象為統一契約。具體怎麼算價格、怎麼拼清單，接口不關心——這就是「構建與表示分離」的體現。

第二層：DecorationPackageMenu 實現

實現類持有一個裝修清單（list）和價格（price），構造函數接收面積和套餐等級：

public class DecorationPackageMenu implements IMenu {
    private List<Matter> list = new ArrayList<>();
    private BigDecimal price = BigDecimal.ZERO;
    private BigDecimal area;
    private String grade;

    public DecorationPackageMenu(Double area, String grade) {
        this.area = new BigDecimal(area);
        this.grade = grade;
    }
    // ...
}

每個 append 方法做兩件事：把物料加入清單 + 按面積係數累加價格。

@Override
public IMenu appendCeiling(Matter matter) {
    list.add(matter);
    price = price.add(matter.price().multiply(new BigDecimal("0.2")).multiply(area));
    return this;
}

@Override
public IMenu appendCoat(Matter matter) {
    list.add(matter);
    price = price.add(matter.price().multiply(new BigDecimal("1.4")).multiply(area));
    return this;
}

@Override
public IMenu appendFloor(Matter matter) {
    list.add(matter);
    price = price.add(matter.price().multiply(area));
    return this;
}

@Override
public IMenu appendTile(Matter matter) {
    list.add(matter);
    price = price.add(matter.price().multiply(area));
    return this;
}

每個方法都返回 this，實現鏈式調用。getDetail() 拼接完整的裝修清單文本。

第三層：Builder 建造者

Builder 是整個模式的收口——把每種套餐的建造過程集中到一個方法：

public class Builder {
    public IMenu levelOne(Double area) {
        return new DecorationPackageMenu(area, "豪華歐式")
            .appendCeiling(new LevelTwoCeiling())   // 二級頂
            .appendCoat(new DuluxCoat())             // 多樂士
            .appendFloor(new ShengXiangFloor());     // 聖象
    }

    public IMenu levelTwo(Double area) {
        return new DecorationPackageMenu(area, "輕奢田園")
            .appendCeiling(new LevelTwoCeiling())
            .appendCoat(new LiBangCoat())            // 立邦
            .appendTile(new MarcoPoloTile());        // 馬可波羅
    }

    public IMenu levelThree(Double area) {
        return new DecorationPackageMenu(area, "現代簡約")
            .appendCeiling(new LevelOneCeiling())    // 一級頂
            .appendCoat(new LiBangCoat())
            .appendTile(new DongPengTile());         // 東鵬
    }
}

每個方法的結構一模一樣：new 裝修包 → 按順序 append 物料。差別只在於選了哪些具體物料。新增套餐？只需加一個方法，指定新的物料組合。不用動 IMenu，不用動 DecorationPackageMenu。

調用方式的變化

ifelse 版本：傳入 level=1，返回一堆物料讓你自己處理。

建造者版本：

Builder builder = new Builder();
String detail = builder.levelOne(132.52D).getDetail();
// 一步到位：建造 + 獲取明細

語義從「按數字選套餐」變成「按名字鏈式組裝」，代碼可讀性大幅提升。

測試驗證：結果完全一致

套餐ifelse 版建造者版

重構前後輸出完全一致——模式重構保持行為等價。但建造者版本的調用方式更清晰、擴展更容易。

小結：三層各自的價值

角色解決的問題
IMenu 接口統一契約，讓填充過程可替換
DecorationPackageMenu承載物料清單和價格計算，隱藏計算細節
Builder集中建造過程，新增套餐只需加方法
