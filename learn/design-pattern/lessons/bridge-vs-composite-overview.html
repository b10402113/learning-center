设计模式 · 桥接与组合 · 第 1/4 课

双维度组合 vs 部分-整体树

这一课的目标

读完之后，你能分辨出代码里两种典型的"嵌套 ifelse 不可维护"的结构问题：

  • 笛卡尔积爆炸 — 两个独立维度交叉，ifelse 变成矩阵
  • 层级递归嵌套 — 条件判断本身形成树形结构，ifelse 越嵌越深

这两种问题分别对应桥接模式和组合模式。它们都是结构型模式，都用组合替代继承来降低复杂度，但拆解的结构形态完全不同。

两种"ifelse 地狱"的真实场景

🎯 场景 A：支付聚合平台
你要对接多个支付渠道（微信、支付宝）× 多种支付方式（密码、人脸、指纹）。

每个渠道 × 每种方式的组合都得写一个分支。渠道从 2 个变 3 个，方式从 3 个变 5 个——
if (channel == WX) 里面套 if (mode == PASSWORD)，矩阵从 6 个膨胀到 15 个。
🎯 场景 B：营销优惠券决策引擎
一个优惠券发放系统要按多级条件过滤用户：先看性别，再看年龄，再看婚姻状况，再看消费金额……

每加一级过滤，ifelse 就多嵌一层。5 级条件就是 5 层嵌套，改一个条件要在N个分支里找。

这两个场景看起来都是"ifelse 太多"，但它们的结构完全不同。搞清楚这个区别，才能选对模式。

核心区别：矩阵 vs 树

问题 A：笛卡尔积爆炸

两个独立维度交叉。维度 A 有 M 个值，维度 B 有 N 个值，组合就是 M×N 个分支。

新增一个维度值，分支数线性增长；新增一个维度，分支数指数爆炸。

→ 解法：桥接模式（拆掉两个维度，用组合连接）

问题 B：层级递归嵌套

条件判断本身形成树形结构——每一级过滤是树的一个节点，节点可以有多个子条件。

新增一级过滤，嵌套加深一层；新增一个并列条件，同级多一个分支。

→ 解法：组合模式（用递归树替代嵌套 ifelse）

一图看懂

场景 A — 笛卡尔积（矩阵）：
         渠道1    渠道2    渠道3
方式1   [分支1]  [分支2]  [分支3]
方式2   [分支4]  [分支5]  [分支6]
方式3   [分支7]  [分支8]  [分支9]
→ 3×3 = 9 个分支，加一个渠道变 12 个

场景 B — 树结构（层级）：
        根过滤
       /      \
   性别过滤   年龄过滤
   /    \      /    \
  男    女   <30   ≥30
  |     |     |     |
 消费  消费  消费  消费
→ 树的深度决定嵌套层数

日常类比

🧮 桥接
乘法表 — 行×列的矩阵，每个格子是一个组合
🌳 组合
公司组织架构 — 总监→经理→员工的层级树
🎮 桥接
游戏角色 = 职业×武器 — 战士/法师 × 剑/杖/弓
📋 组合
审批流 — 总经理→部门经理→组长→组员

共同点与关键区别

桥接模式组合模式
解决的问题双维度笛卡尔积爆炸层级递归嵌套
结构形态两个独立维度的矩阵同一接口的递归树
核心手法抽象持有实现引用（组合）叶子/组合节点统一接口
维度关系两个维度独立节点之间层级关系
典型信号channelType × modeType 嵌套条件判断形成 if-else 树
一句话区分：桥接拆的是两个独立维度的交叉（矩阵变组合），组合拆的是同一接口的层级嵌套（树替代 ifelse）。

关键洞察

这两种 ifelse 地狱在你日常工作中都很常见：

  • 桥接：支付渠道 × 支付方式、消息类型 × 推送渠道、商品类型 × 展示模板——只要看到两个独立维度的嵌套 ifelse，就该想到桥接
  • 组合：审批流、决策引擎、文件系统、UI 组件树——只要看到条件判断形成层级结构，就该想到组合

接下来两课会分别深入这两个模式。先搞清楚"什么时候该用哪个"，再动手写代码。

本课小结

  1. 笛卡尔积爆炸（双维度交叉） → 桥接模式
  2. 层级递归嵌套（条件形成树） → 组合模式
  3. 两者都是结构型模式，都用组合替代继承
  4. 核心区别：桥接拆独立维度，组合拆层级嵌套
