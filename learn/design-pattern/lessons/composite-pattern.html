组合模式：用递归树结构替代深层 ifelse 嵌套

这一课的目标

读完之后，你能：

  • 识别"条件判断形成 if-else 树"的坏味道
  • 用叶子/组合节点统一接口的递归树重构嵌套 ifelse
  • 理解递归遍历在组合模式中的作用

真实场景

🎯 场景：营销优惠券决策引擎
一个优惠券发放系统要按多级条件过滤用户：
先看性别 → 再看年龄 → 再看消费金额 → 最终决定发哪种券。

每加一级过滤，ifelse 就多嵌一层。5 级条件就是 5 层嵌套。
改一个条件要在整棵树里找对应的分支。

问题是：这些条件判断的逻辑是相似的——都是"检查某个属性，通过则继续，不通过则拒绝"。
真正不同的是：检查什么属性、用什么阈值。

坏代码：if-else 树

❌ 嵌套 ifelse 树

public class EngineController {
    public String doFilter(UserInfo user) {
        if ("male".equals(user.getGender())) {
            if (user.getAge() > 25) {
                if (user.getConsume() > 5000) {
                    return "发放 VIP 券";
                } else {
                    return "发放普通券";
                }
            } else {
                if (user.getConsume() > 3000) {
                    return "发放新人券";
                } else {
                    return "不发券";
                }
            }
        } else {
            if (user.getAge() > 25) {
                // ... 还有更多嵌套
            }
        }
        // 每加一级条件，这里就多嵌一层
        return "不发券";
    }
}

✅ 组合模式重构

// 统一接口
public interface LogicFilter {
    Object filter(Object obj);
    String getKey();
}

// 叶子节点：具体过滤器
public class UserAgeFilter implements LogicFilter {
    public Object filter(Object obj) {
        // 只负责年龄判断
        return checkAge(obj);
    }
    public String getKey() { return "age"; }
}

// 组合节点：引擎遍历树
public class EngineBase implements IEngine {
    public EngineResult process(long treeId, UserInfo user) {
        TreeNode root = treeMap.get(treeId);
        return walk(root, user); // 递归遍历
    }
}

// 调用方：组装树（可配置化）

组合模式的核心结构

统一接口 LogicFilter ┌──────────────────┐ │ filter(Object) │ │ getKey() │ └──────────────────┘ │ ┌─────────┴─────────┐ │ │ ┌──────────────┐ ┌──────────────────┐ │ 叶子节点 │ │ 组合节点 │ │ UserAge │ │ EngineBase │ │ UserGender │ │ (持有子节点列表) │ │ UserConsume │ │ 递归调用子节点 │ └──────────────┘ └──────────────────┘ 树结构： 根过滤器（组合） / \ 性别过滤 年龄过滤 (叶子) (叶子) | 消费过滤 (叶子)

关键洞察：叶子和组合实现同一个接口。客户端不区分"这是一个单独的过滤器"还是"这是一个过滤器树"——调用方式完全一样。这就是组合模式的威力。

递归遍历的工作方式

组合节点（引擎）遍历树的过程是递归的：

  1. 从根节点开始
  2. 如果是叶子节点 → 执行过滤逻辑，返回结果
  3. 如果是组合节点 → 遍历所有子节点，递归调用
  4. 根据子节点的结果决定下一步（通过/拒绝/继续）

这个递归过程和你写 ifelse 的逻辑是一样的，但结构完全不同——ifelse 是硬编码在代码里的，树是数据结构，可以动态组装。

透明方式 vs 安全方式

透明方式安全方式
接口定义叶子和组合有完全相同的方法叶子和组合有不同的方法
客户端体验统一调用，不区分类型需要判断节点类型
安全性叶子可能有不该有的方法编译期防止非法操作
推荐场景叶子和组合行为一致时叶子和组合行为差异大时
一句话区分：透明方式让客户端"不操心"（统一接口），安全方式让编译器"帮你管"（类型区分）。

日常类比

  • 文件系统：文件和文件夹都实现 FileSystem 接口，文件夹可以包含文件或其他文件夹
  • UI 组件树：Button 和 Panel 都实现 Component 接口，Panel 可以包含 Button 或其他 Panel
  • 公司组织架构：员工和部门都实现 Entity 接口，部门可以包含员工或其他部门

本课小结

  1. 条件判断形成 if-else 树的信号：多级过滤嵌套越来越深
  2. 组合 = 叶子/组合节点统一接口 + 递归遍历
  3. 核心手法：用递归树替代嵌套 ifelse，数据结构可配置化
  4. 透明方式（统一接口）vs 安全方式（类型区分）的选择
