Lesson 3/3 · 迭代器模式

組織樹深度遍歷實現

Node: iterator · Step 3/3 · 行為模式

學習目標

用組織樹場景實現一個深度優先迭代器，掌握 linkMap、invertedMap、cursorIdx 三者如何配合完成樹形遍歷，並能說出迭代器模式的收益與代價。

場景：遍歷公司組織架構

大部分公司的組織架構是金字塔式的樹形結構：

        小傅哥（1）
       /          \
    花花（2）    豆包（3）
    /      \
  蹦蹦（4） 大燒（5）
            /  |  \
         虎哥  玲姐  秋雅
        （6） （7） （8）

你需要遍歷這棵樹，把所有員工按深度優先的順序輸出來：

花花 → 蹦蹦 → 大燒 → 虎哥 → 玲姐 → 秋雅 → 豆包

注意：不是按編號順序（1,2,3…），而是順著左子樹一路走到最深，再回溯走右子樹。

JDK 的 List 迭代器幫不了你——這不是一個線性列表。你需要自己實現一個迭代器。

數據怎麼存？兩張 Map

組織架構的本質是「節點」和「節點間的關係」。我們用兩個實體來表達：

  • Employee（雇員）：uId、name、desc
  • Link（鏈路）：fromId、toId——描述「誰是誰的上級」

在 GroupStructure 裡，這些數據被存成兩張 Map：

Mapkeyvalue用途
linkMap 上級節點 ID List<Link> 正向關係：從某個節點出發，能找到它的所有子節點
invertedMap 子節點 ID List<Link> 反向關係：從某個子節點出發，能找到它的上級

為什麼要兩張 Map？因為深度優先遍歷需要回溯——走到葉子節點後要「往上找」看還有沒有兄弟節點，這時候就需要反向關係。

深度優先遍歷的三步節奏

深度優先（DFS, Depth-First Search）遍歷樹的核心節奏：

  1. 一路往下：從根節點開始，沿著左子樹一路走到最深的葉子節點
  2. 回溯找兄弟：走到葉子後，往上返回一層，看看同一層還有沒有沒走過的兄弟
  3. 重複直到走完：如果沒有兄弟了，再往上返回一層；直到所有節點都被訪問

用我們的組織架構來走一遍：

步驟當前位置動作
1小傅哥（1）往下走，訪問左子樹：花花（2）
2花花（2）往下走，訪問左子樹：蹦蹦（4）
3蹦蹦（4）葉子節點，輸出 4。回溯到花花
4花花（2）還有右子樹：大燒（5）
5大燒（5）往下走，訪問第一個子：虎哥（6）
6虎哥（6）葉子，輸出 6。回溯到大燒
7大燒（5）訪問第二個子：玲姐（7）
8玲姐（7）葉子，輸出 7。回溯到大燒
9大燒（5）訪問第三個子：秋雅（8）
10秋雅（8）葉子，輸出 8。回溯到大燒→花花→小傅哥
11小傅哥（1）訪問右子樹：豆包（3）
12豆包（3）葉子，輸出 3。結束

最終順序：2, 4, 5, 6, 7, 8, 3——和我們預期的深度優先完全一致。

cursorIdx：記錄每一層走到哪了

深度優先回溯的時候，你需要知道「這一層的子節點我走到了第幾個」。這就是 cursorIdx 的作用：

  • cursorIdx 是一個 Map，key 是父節點 ID，value 是「下一個要走的子節點索引」
  • 每次從某個節點的子節點列表裡取下一個時，把 cursor +1
  • 回溯到父節點時，看父節點的 cursor 是否還有下一個子節點

它就像你在每一個路口都放了一個小紙條：「我上次走到第幾個了」。回溯的時候撿起紙條，就知道下一步該往哪裡走。

核心實現：iterator() 返回匿名迭代器

GroupStructure 的 iterator() 方法返回一個匿名內部類，實現了 Iterator<Employee>：

public Iterator<Employee> iterator() {
    return new Iterator<Employee>() {
        // 從根節點開始
        // hasNext(): 從 invertedMap 追溯到根，判斷是否還有未訪問的節點
        // next(): 沿 linkMap 往下走，用 cursorIdx 記錄進度
    };
}

整個遍歷邏輯被封裝在這個匿名類裡——調用方完全不需要知道 linkMap、invertedMap、cursorIdx 的存在。它只需要：

Iterator<Employee> iterator = groupStructure.iterator();
while (iterator.hasNext()) {
    Employee emp = iterator.next();
    System.out.println(emp.getName());
}

這就是迭代器模式的精髓：遍歷邏輯和數據結構分離。數據結構管「數據怎麼存」，迭代器管「數據怎麼走」。

收益與代價

收益代價
滿足單一職責和開閉原則 實現相對複雜，需要額外定義接口和類
調用方不需要知道內部結構 遍歷與數據結構分離，新人不易理解
方便擴展（換一種遍歷方式只需換 Iterator） 樹形結構的深度遍歷算法需要反覆練習

用源碼的話說：「雖然麻煩，但使用 JDK 時迭代器模式很好用，方便擴展與升級。」

一句話記住

組織樹迭代器 = linkMap（正向關係）+ invertedMap（反向回溯）+ cursorIdx（每層進度），三者配合完成深度優先遍歷。調用方只管 hasNext/next。

自我檢測

Q1. 組織樹迭代器為什麼需要兩張 Map（linkMap 和 invertedMap）？

  • 一張存員工，一張存部門
  • 一張存姓名，一張存 ID
  • 正向關係用於往下走，反向關係用於回溯找兄弟
  • 兩張 Map 是重複的，只需要一張

Q2. cursorIdx 的作用是什麼？

  • 記錄員工的工號
  • 記錄每一層的子節點遍歷進度，回溯時知道走到第幾個了
  • 記錄樹的深度
  • 記錄總共有多少員工

Q3. 深度優先遍歷組織樹時，2 號員工（花花）的子節點 4（蹦蹦）遍歷完後，下一步會去哪？

  • 回溯到花花，訪問另一個子節點 5（大燒）
  • 直接去 3 號員工（豆包）
  • 跳過大燒，去大燒的子節點
  • 從頭重新遍歷

Q4. 迭代器模式的主要代價是什麼？

  • 遍歷速度變慢
  • 佔用更多內存
  • 實現較複雜，需要額外定義接口和類，新人不易理解
  • 不支持併發訪問

Q5. 以下關於迭代器模式的說法，哪個是正確的？

  • 迭代器模式只適用於 List
  • 遍歷邏輯和數據結構分離，數據結構管「怎麼存」，迭代器管「怎麼走」
  • 迭代器必須是雙向的
  • 自定義迭代器不需要實現 JDK 的接口
