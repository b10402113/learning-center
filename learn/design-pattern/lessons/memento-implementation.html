Java 實現走讀：逐類對照四角色職責

design-pattern › memento › memento-implementation

學習目標：逐類走讀配置回滾的 Java 實現，把四角色從抽象概念落到真實程式碼。

ConfigFile——承載配置狀態的 POJO

public class ConfigFile {
    private String versionNo;
    private String content;
    private String dateTime;
    private String operator;

    // getter / setter 省略
}

四個欄位對應場景中的五要素（版本號、時間、內容、操作人）。ConfigFile 是一個純 POJO（Plain Old Java Object），不知道有人在存它的狀態。它就是被保存的「內容」本身。

ConfigMemento——快照的載體

public class ConfigMemento {
    private ConfigFile configFile;

    public ConfigMemento(ConfigFile configFile) {
        this.configFile = configFile;
    }

    public ConfigFile getConfigFile() {
        return configFile;
    }

    public void setConfigFile(ConfigFile configFile) {
        this.configFile = configFile;
    }
}

ConfigMemento 的全部工作就是把 ConfigFile 包起來。它不讀 ConfigFile 的內部欄位，不調用 ConfigFile 的業務方法，只是拿著一個 ConfigFile 的引用。你可以把它理解為一個「密封的快遞盒」：盒子外面看不到裡面裝了什麼，打開盒子才能看到。

設計要點：備忘錄（Memento）是原物件的「包裝引用」，不是複製。在這個例子裡，ConfigMemento 持有的是 ConfigFile 的引用。如果需要真正的深拷貝（Deep Copy），可以在建構器裡複製 ConfigFile 的所有欄位——這取決於你需不需要快照之間的狀態隔離。

ConfigOriginator——記錄者，存檔和還原的執行者

public class ConfigOriginator {
    private ConfigFile configFile;

    public ConfigFile getConfigFile() {
        return configFile;
    }

    public void setConfigFile(ConfigFile configFile) {
        this.configFile = configFile;
    }

    // 存檔：把當前狀態包成快照
    public ConfigMemento saveMemento() {
        return new ConfigMemento(this.configFile);
    }

    // 讀檔：把快照的狀態還原到當前物件
    public void getMemento(ConfigMemento memento) {
        this.configFile = memento.getConfigFile();
    }
}

ConfigOriginator 有兩個關鍵方法：

  • saveMemento()：拿當前的 ConfigFile 建構一個新的 ConfigMemento 返回出去。注意它是返回新物件，不修改當前狀態。
  • getMemento(memento)：從 ConfigMemento 裡取出 ConfigFile，直接寫給當前的 this.configFile——不是返回一個新的 ConfigFile，而是把快照內容覆蓋到當前物件上。這就是「還原」的實現位置。

ConfigOriginator 是唯一知道 ConfigFile 內部結構的角色。如果 ConfigFile 加了新欄位，只需要在 ConfigOriginator 的 saveMemento/getMemento 裡處理。

Admin——管理者，多版本歷史的容器

public class Admin {
    private List<ConfigMemento> mementoList = new ArrayList<>();
    private Map<String, ConfigMemento> mementoMap = new ConcurrentHashMap<>();
    private int cursorIdx = 0;

    // 存放快照
    public void append(ConfigMemento memento) {
        mementoList.add(memento);
        mementoMap.put(
            memento.getConfigFile().getVersionNo(),
            memento
        );
        cursorIdx++;
    }

    // 回滾：指針前移
    public ConfigMemento undo() {
        if (cursorIdx > 0) {
            cursorIdx--;
        }
        return mementoList.get(cursorIdx);
    }

    // 前進：指針後移
    public ConfigMemento redo() {
        if (cursorIdx < mementoList.size() - 1) {
            cursorIdx++;
        }
        return mementoList.get(cursorIdx);
    }

    // 按版本號定向取
    public ConfigMemento get(String versionNo) {
        return mementoMap.get(versionNo);
    }
}

Admin 的設計要點：

  • 雙結構存儲：List 保序（按時間順序），Map 按版本號索引（支持 O(1) 定向查詢）
  • 游標 cursorIdx：記錄當前位置，undo 前移、redo 後移，邊界保護（不會越界）
  • append 裡同時寫 List 和 Map：存一份快照，兩個結構各存一次
  • 不知道 ConfigFile：Admin 只操作 ConfigMemento，不讀 ConfigFile 的任何欄位

測試類：完整流程走讀

@Test
public void test_memento() {
    ConfigOriginator originator = new ConfigOriginator();
    Admin admin = new Admin();

    // 保存四份配置
    originator.setConfigFile(new ConfigFile("1000001", "哈哈", "2026-09-01", "管理員A"));
    admin.append(originator.saveMemento());

    originator.setConfigFile(new ConfigFile("1000002", "嘻嘻", "2026-09-01", "管理員A"));
    admin.append(originator.saveMemento());

    originator.setConfigFile(new ConfigFile("1000003", "么么", "2026-09-01", "管理員A"));
    admin.append(originator.saveMemento());

    originator.setConfigFile(new ConfigFile("1000004", "嘿嘿", "2026-09-01", "管理員A"));
    admin.append(originator.saveMemento());

    // 回滾一次 → 1000003
    originator.getMemento(admin.undo());
    assertEquals("1000003", originator.getConfigFile().getVersionNo());

    // 再回滾一次 → 1000002
    originator.getMemento(admin.undo());
    assertEquals("1000002", originator.getConfigFile().getVersionNo());

    // 前進一次 → 1000003
    originator.getMemento(admin.redo());
    assertEquals("1000003", originator.getConfigFile().getVersionNo());

    // 定向取 → 1000002
    originator.getMemento(admin.get("1000002"));
    assertEquals("1000002", originator.getConfigFile().getVersionNo());
}

測試的每次操作都是：先從 Admin 取出快照，再交給 Originator 還原到當前物件。四次操作全部符合預期。

小結

逐類走讀的結果：ConfigFile 是純 POJO、ConfigMemento 是包裝引用、ConfigOriginator 是存檔/還原的執行者、Admin 是多版本歷史的容器。每個類的職責清晰、邊界明確。如果未來 ConfigFile 加了新欄位，只有 ConfigOriginator 需要改；如果想把存儲從內存換成資料庫，只有 Admin 需要改。這就是四角色分離帶來的好處。
