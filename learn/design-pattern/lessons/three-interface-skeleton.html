Lesson 2/3 · 迭代器模式

JDK 三接口骨架——Iterator、Iterable、Collection

Node: iterator · Step 2/3 · 行為模式

學習目標

理解自定義迭代器參照的 JDK 三接口骨架（Iterator、Iterable、Collection）各自職責，以及它們之間的繼承關係。

三個接口，各管一件事

在 JDK 的 java.util 裡，迭代器的實現被拆成三個接口，各司其職：

接口職責核心方法
Iterator<E> 定義遍歷行為——「怎麼一個一個取出來」 hasNext()、next()、remove()
Iterable<E> 聲明「我是可遍歷的」——提供獲取迭代器的入口 iterator()
Collection<E> 定義集合操作——增刪查改 + 遍歷 add()、remove()、iterator()…

三者之間的關係：

Collection<E> extends Iterable<E>
    Iterable<E> 提供 iterator()
    Iterator<E> 定義 hasNext() / next()

關鍵設計：Collection 繼承了 Iterable，所以任何 Collection 的子類（List、Set）都可以直接用增強 for 循環，因為它們天生就是「可迭代的」。

Iterator——遍歷的執行者

Iterator<E> 是最底層的接口，只做一件事：逐個取出元素。

public interface Iterator<E> {
    boolean hasNext();  // 還有下一個嗎？
    E next();           // 取出下一個
    default void remove() { ... }  // 刪除當前元素
}

三個方法的分工很清晰：

  • hasNext()：在取之前先問「還有嗎」，避免 NoSuchElementException
  • next()：取出下一個元素，內部指針往前移一步
  • remove()：刪除剛才 next() 返回的那個元素（這是增強 for 做不到的）

Iterator 是單向的、一次性的——從頭走到尾，走完就結束了，不能回頭。如果你想再遍歷一次，就得重新調用 iterator() 拿一個新的。

Iterable——可遍歷的標記

Iterable<E> 只有一個方法：

public interface Iterable<E> {
    Iterator<E> iterator();  // 返回一個迭代器
}

它的作用是聲明：「我這個類是可以被遍歷的」。當你看到一個類實現了 Iterable，你就知道可以用增強 for 循環遍歷它。

為什麼要單獨拎出這個接口？因為它讓遍歷能力和集合能力解耦了——一個類可以是 Iterable（可遍歷）但不是 Collection（不提供 add/remove）。比如文件系統的目錄結構：它是可遍歷的，但它不是一個「集合」。

Collection——集合的全能管家

Collection<E> 是最上層的集合接口，繼承了 Iterable，提供完整的增刪查改操作：

public interface Collection<E> extends Iterable<E> {
    boolean add(E e);
    boolean remove(Object o);
    Iterator<E> iterator();
    int size();
    boolean isEmpty();
    // ... 還有很多方法
}

它把「可遍歷」和「可操作」統一在一個接口裡。你常用的 ArrayList、HashSet 都實現了這個接口。

為什麼要拆成三個接口？

初學者常見的疑問：為什麼不把所有方法塞進一個接口？

答案是職責分離：

設計如果只有一個接口拆成三個接口
靈活性 所有類都必須實現所有方法 可遍歷的不一定是集合，集合不一定是可變的
擴展性 加新操作要改接口 加新接口不影響已有實現
替換性 Iterator 和 Collection 綁死 同一個 Collection 可以返回不同的 Iterator（正向/反向/過濾）

最後一點尤其重要：因為 Iterator 是獨立接口，同一個數據結構可以提供多種遍歷方式——正序、反序、深度優先、寬度優先——調用方只需要換一個 Iterator 就行。

自定義迭代器怎麼用這套骨架？

當你要給自己的數據結構（比如組織架構樹）實現迭代器時，參照 JDK 的方式：

  1. 定義自己的 Iterator<E>，實現 hasNext() 和 next()
  2. 定義自己的 Iterable<E>，提供 iterator() 方法
  3. 定義自己的 Collection<E, L>（兩個泛型：元素類型和鏈路類型），繼承 Iterable，加上增刪操作
  4. 在具體的數據結構類（如 GroupStructure）裡實現 Collection，把遍歷邏輯寫在匿名內部類或單獨類裡

三接口的骨架和 JDK 完全一致——這樣做的好處是你以後看 JDK 源碼時可以對照學習，概念是相通的。

一句話記住

三接口分工：Iterator 管「怎麼取」，Iterable 管「我能被遍歷」，Collection 管「增刪查改 + 遍歷」。自定義迭代器照著這套骨架搭就行。

自我檢測

Q1. Iterator 接口的核心方法有哪些？

  • hasNext()、next()、remove()
  • add()、remove()、size()
  • iterator()、forEach()
  • get()、set()、contains()

Q2. Iterable 接口的作用是什麼？

  • 提供增刪查改操作
  • 實現具體的遍歷邏輯
  • 聲明「我是可遍歷的」，提供獲取迭代器的入口
  • 定義集合的大小和容量

Q3. 為什麼 JDK 要把迭代器拆成三個接口而不是一個？

  • 為了代碼更少
  • 職責分離，讓可遍歷、可操作、遍歷行為各自獨立演進
  • 為了讓增強 for 循環更快
  • 歷史原因，沒有實際好處
