責任鏈骨架：抽象類 + next 指針

學習目標

掌握責任鏈「統一抽象類 + next 指針 + appendNext 鏈式編排 + 抽象 doAuth」的核心結構。

重構思路：把 if 拆成鏈

上一步我們看到了 if-else 審批流的痛點：所有邏輯堆在一個方法裡。責任鏈的重構思路很直接——把每個審批級別變成一個獨立的類，它們通過一個 next 指針串成一條鏈。

核心機制有三個零件：

零件職責關鍵設計
抽象類 AuthLink統一所有審批節點的接口持有 next 指針 + 聲明抽象 doAuth
next 指針指向鏈上的下一個節點next == null 表示鏈尾
appendNext()追加下一個節點並返回 this支持鏈式編排

抽象類 AuthLink

public abstract class AuthLink {
    protected String levelUserId;    // 審批人 ID
    protected String levelUserName;  // 審批人姓名
    private AuthLink next;           // 下一個節點

    public AuthLink(String levelUserId, String levelUserName) {
        this.levelUserId = levelUserId;
        this.levelUserName = levelUserName;
    }

    // 追加下一個節點，返回 this 支持鏈式調用
    public AuthLink appendNext(AuthLink next) {
        this.next = next;
        return this;
    }

    // 獲取下一個節點
    public AuthLink next() {
        return this.next;
    }

    // 抽象方法：每個審批級別實現自己的業務邏輯
    public abstract AuthInfo doAuth(String uId, String orderId, Date authDate);
}

注意幾個關鍵設計：

  • next 是 private：外部不能直接修改鏈結構，只能通過 appendNext
  • appendNext 返回 this：這讓你可以寫出 a.appendNext(b).appendNext(c) 這樣的鏈式調用，把編排過程壓縮成一行
  • doAuth 是抽象方法：每個審批級別自己決定「怎麼審」，抽象類只管「怎麼傳」

三個實現類

每個審批級別是一個獨立的類，繼承 AuthLink，實現 doAuth：

// 三級審批：王工
public class Level3AuthLink extends AuthLink {
    public Level3AuthLink(String levelUserId, String levelUserName) {
        super(levelUserId, levelUserName);
    }

    @Override
    public AuthInfo doAuth(String uId, String orderId, Date authDate) {
        // 1. 先查自己是否已審
        Date authInfo = AuthService.queryAuthInfo(levelUserId, orderId);
        if (authInfo != null) {
            return new AuthInfo("00000", "三級審批完成");
        }
        // 2. 未審 → 返回待審結果（不再往下傳）
        return new AuthInfo("10003", "待三級審批負責人：" + levelUserName);
    }
}
// 二級審批：張經理（僅 618 期間參與）
public class Level2AuthLink extends AuthLink {
    private Date beginDate;
    private Date endDate;

    public Level2AuthLink(String levelUserId, String levelUserName,
                          Date beginDate, Date endDate) {
        super(levelUserId, levelUserName);
        this.beginDate = beginDate;
        this.endDate = endDate;
    }

    @Override
    public AuthInfo doAuth(String uId, String orderId, Date authDate) {
        // 1. 判斷時間範圍：不在範圍內 → 直接傳給下一個
        if (authDate.before(beginDate) || authDate.after(endDate)) {
            return next().doAuth(uId, orderId, authDate);
        }
        // 2. 在範圍內 → 查自己是否已審
        Date authInfo = AuthService.queryAuthInfo(levelUserId, orderId);
        if (authInfo != null) {
            return new AuthInfo("00000", "二級審批完成");
        }
        return new AuthInfo("10002", "待二級審批負責人：" + levelUserName);
    }
}

關鍵模式：每個節點做三件事——判斷時間範圍（該不該由我審）、查自身審核狀態（審了沒有）、決定傳遞（已審就傳給 next，未審就返回待審）。時間範圍為何可以動態決定鏈的長度？因為不在範圍內的節點直接跳過，請求跳到下一個——鏈的「有效長度」隨時間自動變化。
