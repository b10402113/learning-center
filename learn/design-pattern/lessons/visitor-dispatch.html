Lesson 2/4 · 訪問者模式

雙分派機制：visitor.visit(this) 怎麼運作

Node: visitor · Step 2/4 · 行為模式

學習目標

理解雙分派（double dispatch）的運作過程，能拆解 visitor.visit(this) 一行代碼如何同時牽動 User 與 Visitor 兩個繼承體系。

一行代碼，兩次分派

訪問者模式最核心的一行代碼是：

visitor.visit(this);

這行代碼出現在每個數據結構類的 accept 方法裡。看起來很簡單，但它其實觸發了兩次方法分派——一次決定調用哪個 visit 重載，一次決定 this 是哪種類型。這就是「雙分派」。

先看單分派：Java 多態的默認行為

Java 的方法調用是單分派（single dispatch）：運行時根據接收者（receiver）的實際類型決定調用哪個方法。

Animal animal = new Cat();
animal.speak();  // 運行時 animal 是 Cat，調用 Cat.speak()

參數的類型在編譯時就確定了——如果 speak() 有重載，Java 會選編譯時類型匹配的那個，不看運行時參數實際是什麼。

但訪問者模式需要的恰恰是：既看接收者的類型，又看參數的類型。單分派做不到，所以需要雙分派。

雙分派的兩步拆解

假設我們有 Student 類和 Principal 訪問者。調用：

// student 是 Student 實例，principal 是 Principal 實例
student.accept(principal);

第一次分派：Java 運行時看 student 的實際類型，找到 Student.accept(Visitor visitor)。這一步和普通多態一樣。

第二次分派：accept 方法內部執行 visitor.visit(this)。這裡有兩個關鍵點：

  • this 是 Student 類型（編譯時已知）
  • visitor 的實際類型是 Principal（運行時確定）

Java 根據 visitor 的實際類型（Principal）和 this 的編譯時類型（Student），匹配到 Visitor.visit(Student student) 這個重載。如果 this 是 Teacher，就會匹配到 Visitor.visit(Teacher teacher)。

完整的分派鏈

步驟分派依據結果
1. student.accept(principal)student 的實際類型 → Student調用 Student.accept()
2. visitor.visit(this)visitor 的實際類型 → Principal，this 的類型 → Student調用 Principal.visit(Student)

如果把 principal 換成 parent（Parent 類型），第二步就會調用 Parent.visit(Student)——同一份 Student 數據，不同訪問者走不同的 visit 重載。

為什麼叫「雙分派」

因為最終調用哪個方法取決於兩個變量的運行時類型：

  1. 接收者（this）的具體類型 —— Student 還是 Teacher？
  2. 參數（visitor）的具體類型 —— Principal 還是 Parent？

單分派只看一個（接收者），雙分派兩個都看。這讓訪問者模式能在運行時根據「誰被訪問」×「誰來訪問」的組合，精確路由到對應的處理邏輯。

代碼結構：兩層繼承體系

雙分派的結構前提是存在兩個獨立的繼承體系：

體系抽象實現
數據結構User（抽象類）Student、Teacher
訪問者Visitor（接口）Principal、Parent

User 提供 accept(Visitor)，Visitor 提供 visit(Student) 和 visit(Teacher)。雙方互相引用，通過 visitor.visit(this) 連接。

這就是訪問者模式被認為「燒腦」的原因——你需要同時理解兩個繼承體系的交互，而不是一個。

一句話記住

雙分派 = visitor.visit(this)：第一次看 this 是誰（Student/Teacher），第二次看 visitor 是誰（Principal/Parent），兩次分派精確路由到對應的處理方法。

自我檢測

Q1. visitor.visit(this) 觸發了幾次方法分派？

  • 一次
  • 兩次
  • 三次
  • 零次，是靜態調用

Q2. 第二次分派的依據是什麼？

  • visitor 的實際類型和 this 的編譯時類型
  • 只看 this 的運行時類型
  • 只看方法參數的編譯時類型
  • 看方法返回值的類型

Q3. 為什麼 Java 的普通多態是「單分派」？

  • Java 不支持多態
  • Java 只看參數類型
  • Java 只根據接收者的實際類型分派，不看參數的運行時類型
  • Java 的多態是靜態的

Q4. 雙分派的前提結構是什麼？

  • 一個類實現多個接口
  • 兩個獨立的繼承體系互相引用
  • 使用反射機制
  • 使用泛型

Q5. 如果 this 是 Teacher、visitor 是 Parent，最終會調用哪個方法？

  • Principal.visit(Student)
  • Parent.visit(Student)
  • Principal.visit(Teacher)
  • Parent.visit(Teacher)
