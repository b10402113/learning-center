对比：桥接 vs 组合

桥接模式

  • 两个独立维度交叉
  • 结构形态：矩阵（M×N）
  • 核心手法：抽象持有实现引用
  • 典型信号：channelType × modeType
  • 类比：乘法表、JDBC 驱动

组合模式

  • 同一接口的层级关系
  • 结构形态：递归树
  • 核心手法：叶子/组合统一接口
  • 典型信号：if-else 树嵌套
  • 类比：文件系统、组织架构

辨析：桥接 vs 适配器 vs 策略

桥接适配器策略
意图拆开两个独立维度翻译不兼容的接口替换同一行为的算法
维度数2 个独立维度1 个不兼容接口1 个行为的多种算法
时机设计阶段对接已有接口时算法可替换时
结构抽象 + 实现字段包装器类Context + 策略接口
信号A × B 矩阵格式不对要翻译同类算法 ifelse

辨析：组合 vs 责任链 vs 策略

组合责任链策略
结构树形递归链式传递Context 持有策略
遍历方式递归遍历子节点传递给下一个节点直接调用
结果汇总子节点结果汇总谁处理谁返回单个策略返回
典型场景决策引擎、文件系统审批流、过滤器链算法替换、定价

真实场景判断

🎯 场景 1：消息推送系统
要推送消息给用户，渠道有（短信、邮件、App 推送），类型有（营销、通知、验证码）。

判断：渠道和类型是两个独立维度，交叉形成矩阵。
→ 桥接模式（拆掉渠道 × 类型的笛卡尔积）
🎯 场景 2：电商促销规则引擎
促销规则按层级判断：先看用户等级 → 再看商品品类 → 再看订单金额 → 最终决定折扣。

判断：条件本身形成层级结构，每一级是树的一个节点。
→ 组合模式（用递归树替代嵌套 ifelse）
🎯 场景 3：对接三个第三方支付 API
三个 API 入参格式不同、返回值不同、错误处理方式也不同。

判断：接口不兼容，需要翻译。
→ 适配器模式（不是桥接，因为只有一个维度）
🎯 场景 4：优惠券折扣计算
按券类型（直减、满减、折扣、n 元购）用不同算法计算折后价。

判断：同一行为（折扣计算）的多种算法替换。
→ 策略模式（不是桥接，因为只有一个维度）

本课小结

  1. 看到双维度交叉（A × B 矩阵）→ 桥接
  2. 看到层级嵌套（if-else 树）→ 组合
  3. 看到接口不兼容（格式不对）→ 适配器
  4. 看到同类算法替换（ifelse 分发算法）→ 策略
  5. 四个模式都用组合替代继承，但意图和结构完全不同
