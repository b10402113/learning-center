策略/狀態/命令/模板——四種行為模式怎麼分

design-pattern › pattern-selection › behavioral-quartet

學習目標：能說出策略、狀態、命令、模板方法四種行為模式的核心區別，並用一句話判斷「這個場景該套哪一個」。

為什麼這四個容易混淆

面試官問「策略和狀態有什麼區別」，不是要你背定義——是看你在具體場景下能不能做出正確的選擇。這四個模式的共同點是：都涉及「行為的切換或編排」。但它們切換的東西完全不同：

  • 策略模式：切換的是算法——同一個動作，有多種實現方式，按需互換
  • 狀態模式：切換的是狀態——同一個對象，內部狀態變了，行為就跟著變
  • 命令模式：切換的是請求——把操作封裝成對象，解耦「誰下命令」和「誰執行」
  • 模板方法：切換的是步驟——骨架固定，子類填補具體步驟的實現

逐個拆解

策略模式：同一動作，多種算法

你在電商做優惠券，折扣計算有四種：直減、滿減、折扣、n元購。每種計算邏輯完全不同，但調用方式一樣——傳入價格，返回折後價。

策略模式的判斷標準：同一個方法的參數和返回值不變，但內部計算邏輯可以互換。你不會因為用了一種策略而改變方法的調用方式，只是換了內部的「計算公式」。

維度策略模式
切換什麼算法（同一動作的不同實現）
觸發者外部調用方選擇算法
典型代碼接口 + 多個實現類 + Context 控制類
一句話「算折扣的方法有四種，你要哪種？」

狀態模式：內部狀態驅動行為

你在做營銷活動審核系統。活動有 7 種狀態（編輯、待審核、審核通過、審核拒絕、活動中、關閉、開啟），每種狀態下允許的操作不同——編輯狀態可以提審，但不能直接開啟；審核拒絕可以撤審回編輯，但不能直接進入活動中。

狀態模式的判斷標準：同一個方法，行為會根據對象當前的內部狀態而不同。你調用的是同一個接口，但內部執行的邏輯完全不一樣——因為狀態變了。

維度狀態模式
切換什麼狀態（對象內部的當前狀態）
觸發者狀態自身（每個狀態類知道自己能流轉到哪些狀態）
典型代碼State 抽象類 + 多個狀態實現類 + StateHandler 映射
一句話「活動在編輯中，只能提審；在審核中，可以通過或拒絕」

命令模式：請求封裝成對象

你在做餐廳點單系統。顧客把菜系告訴小二，小二把菜單傳給對應廚師。顧客不關心誰做菜，廚師不關心誰點菜——小二就是中間的命令調用者。

命令模式的判斷標準：操作的「下命令」和「執行命令」是兩撥不同的人或系統。你需要把「做什麼」封裝成一個對象，讓調用者可以在不知道具體實現的情況下觸發操作。

維度命令模式
切換什麼請求（操作的封裝對象）
觸發者調用者（持有命令列表，統一執行）
典型代碼命令接口 + 具體命令（注入實現者）+ 調用者
一句話「點單的是顧客，做菜的是廚師，小二只管傳菜單」

模板方法：固定骨架，子類填步驟

你在做電商爬蟲推廣海報。爬京東、淘寶、當當，三步流程完全一樣：登錄 → 爬商品 → 生成海報。但每一步的具體實現不同——京東用京東的登錄方式，淘寶用淘寶的。

模板方法的判斷標準：多個實現共享同一個執行順序，只是每個步驟的具體做法不同。父類把流程骨架固定下來，子類只需要填補具體步驟。

維度模板方法
切換什麼步驟（固定流程中的可變部分）
觸發者父類（定義執行順序）
典型代碼抽象類（模板方法 + 抽象步驟）+ 多個子類實現
一句話「登錄→爬取→生成海報，三步順序不變，但每步怎麼做由子類定」

速判口訣

模式核心問題速判句
策略同一動作有多種算法「這個方法有幾種寫法，你要哪種？」
狀態對象行為隨狀態變「現在是什麼狀態？狀態不一樣，行為就不一樣」
命令請求與實現分離「下命令的人和做事情的人不是同一個」
模板流程固定，步驟可替「步驟順序不變，但每步怎麼做你說了算」

面試常見陷阱

策略 vs 狀態：策略是「外部選算法」，狀態是「內部自己切換」。策略的切換由調用方決定（你要算滿減還是折扣？），狀態的切換由狀態自身決定（編輯中只能提審，不能直接開啟）。

策略 vs 命令：策略關注「怎麼算」，命令關注「誰做、誰調」。策略的接口通常是無狀態的純計算，命令的接口通常帶有「執行者」的引用。

模板 vs 策略：模板是「流程級」的（多個步驟的順序），策略是「方法級」的（一個方法的實現）。模板用繼承，策略用組合。
