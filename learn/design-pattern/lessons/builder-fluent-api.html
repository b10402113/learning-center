流式 Builder 重构

Node: builder-prototype · Step 2/5

学习目标

实现流式 Builder 重构：定义 IMenu 接口、DecorationPackageMenu 实现类和 Builder 工厂，完成从 ifelse 到 fluent API 的转变。

1. 回顾：上一步的痛点

在 step 1 里，我们用一个巨大的 if-else 根据装修等级硬编码材料组合。问题很明显：

  • 新增一个套餐 → 改 if-else，违反开闭原则
  • 每种材料的单价计算散落在分支里，改一处可能漏另一处
  • 调用方没法灵活组装，只能传一个等级数字

核心矛盾：复杂对象的组装过程和最终表示耦合在一起了。Builder 模式就是要把这两件事拆开。

2. IMenu 接口：流式链的骨架

先定义接口。注意每个 append 方法都返回 this——这就是 fluent API 的关键：

public interface IMenu {
    IMenu appendCeiling();   // 吊顶
    IMenu appendCoat();      // 涂料
    IMenu appendFloor();     // 地板
    IMenu appendTile();      // 瓷砖
    String getDetail();      // 最终报价单
}

返回 IMenu（而不是 void），调用方就能把多个 append 串成一条链：

menu.appendCeiling().appendCoat().appendFloor().appendTile();

这不是语法糖，而是设计意图的表达——组装是分步的、可选的、顺序自由的。

3. DecorationPackageMenu：组装 + 计价

这是 IMenu 的唯一实现类。它内部维护一个材料列表和累计价格，每调一次 append 就加入一种材料并计算面积单价：

public class DecorationPackageMenu implements IMenu {
    private final int area;                          // 房屋面积
    private final List<String> materials = new ArrayList<>();
    private BigDecimal price = BigDecimal.ZERO;

    public DecorationPackageMenu(int area) {
        this.area = area;
    }

    @Override
    public IMenu appendCeiling() {
        // 二级顶 — 多乐士，单价 26 元/m²
        materials.add("二级顶 + 多乐士");
        price = price.add(new BigDecimal(area * 26));
        return this;  // ← 返回 this，支持链式调用
    }

    @Override
    public IMenu appendCoat() {
        // 乳胶漆 — 立邦，单价 18 元/m²
        materials.add("立邦乳胶漆");
        price = price.add(new BigDecimal(area * 18));
        return this;
    }

    @Override
    public IMenu appendFloor() {
        // 地板 — 圣象，单价 120 元/m²
        materials.add("圣象地板");
        price = price.add(new BigDecimal(area * 120));
        return this;
    }

    @Override
    public IMenu appendTile() {
        // 瓷砖 — 马可波罗，单价 150 元/m²
        materials.add("马可波罗瓷砖");
        price = price.add(new BigDecimal(area * 150));
        return this;
    }

    @Override
    public String getDetail() {
        StringBuilder sb = new StringBuilder();
        sb.append("装修方案：面积 ").append(area).append(" m²\n");
        sb.append("材料清单：\n");
        materials.forEach(m -> sb.append("  · ").append(m).append("\n"));
        sb.append("总价：").append(price).append(" 元");
        return sb.toString();
    }
}

关键设计点：

  • 不写死套餐组合——它只知道自己能装什么，不决定什么时候装
  • 计价和组装在同一个 append 里完成——单一职责：一个 append 就是一步施工
  • getDetail() 渲染最终报价——组装完成后再输出，符合"先构建后使用"

4. Builder：工厂化的套餐预设

Builder 是个静态工厂，封装三种预设套餐的组装步骤。调用方只需一行就能拿到一个"半成品菜单"，再按需追加：

public class Builder {
    public static IMenu levelOne(int area) {
        // 轻奢田园：一级顶 + 立邦 + 德尔地板 + 东鹏瓷砖
        return new DecorationPackageMenu(area)
                .appendCeiling()
                .appendCoat()
                .appendFloor()
                .appendTile();
    }

    public static IMenu levelTwo(int area) {
        // 豪华欧式：二级顶 + 多乐士 + 圣象地板 + 马可波罗瓷砖
        return new DecorationPackageMenu(area)
                .appendCeiling()
                .appendCoat()
                .appendFloor()
                .appendTile();
    }

    public static IMenu levelThree(int area) {
        // 现代简约：一级顶 + 多乐士 + 德尔地板 + 东鹏瓷砖
        return new DecorationPackageMenu(area)
                .appendCeiling()
                .appendCoat()
                .appendFloor()
                .appendTile();
    }
}

三个方法的链式调用一目了然。调用方不再需要知道内部逻辑：

// 一行搞定
IMenu menu = Builder.levelTwo(99);
System.out.println(menu.getDetail());

// 也可以在 Builder 的基础上自定义追加
IMenu custom = Builder.levelOne(120);
custom.appendTile();  // 额外加瓷砖

5. 为什么 fluent API 重要？

fluent API 不是炫技。它的核心价值是可读性——把"做什么"按步骤线性展开：

// 不用 fluent：嵌套参数，看不出每步做什么
IMenu menu = new DecorationPackageMenu(area);
menu.appendCeiling();
menu.appendCoat();
menu.appendFloor();
menu.appendTile();

// 用 fluent：链式表达，像在读施工流程
new DecorationPackageMenu(area)
    .appendCeiling()
    .appendCoat()
    .appendFloor()
    .appendTile();

更关键的是，fluent API 让 Builder 的工厂方法变得自然——每个 level 方法就是一个"标准施工流程"，读代码就像读菜单。

6. 核心收获

同一个输出，不同的结构。
ifelse 和 Builder 产出的报价单完全一样，但 Builder 把组装过程变成了可复用、可扩展的接口。这就是单一职责 + 开闭原则的实践：材料怎么装是一个职责，装哪些材料是另一个职责，两者分离后各自独立变化。

自我检测

Q1. IMenu 的 append 方法为什么返回 this 而不是 void？

  • 为了让编译器优化性能
  • 为了支持链式调用（fluent API）
  • 为了让子类能覆写返回类型
  • 没有特殊原因，只是习惯写法

Q2. 相比 ifelse 版本，Builder 模式在新增套餐时主要解决了什么问题？

  • 运行速度更快
  • 减少了类的数量
  • 新增套餐不需要修改已有代码（开闭原则）
  • 不需要再传面积参数

Q3. Builder.levelTwo(area) 返回的是什么？

  • 一个已按豪华欧式套餐组装好的 DecorationPackageMenu 实例
  • 一个空的 IMenu 接口
  • 一个 Builder 对象，需要再调用 build()
  • 一个字符串形式的报价单
