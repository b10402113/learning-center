學習目標：理解原型模式要解決的核心問題——重複創建複雜對象的開銷，以及「克隆」作為解決手段的動機。

重複創建對象，代價比你想的高

寫業務代碼時，new 一個對象似乎是零成本的操作。但如果這個對象不是一個簡單的 POJO，而是需要從資料庫查數據、調遠端 RPC、拼裝大量字段的「重量級」對象呢？

想像一個場景：你的系統需要為每位用戶生成一份試卷。試卷的題庫從資料庫載入，每道題包含題目文本、選項（A/B/C/D）、答案——有些題目甚至來自遠端服務。如果你為每位考生都重新從庫裡查一遍、再重新構造所有題目對象，代價是：

  • I/O 開銷：N 個考生 = N 次資料庫查詢 + N 次對象構造
  • 時間成本：如果每次構造需要 50ms，1000 個考生就是 50 秒的純等待
  • 網路風險：遠端 RPC 可能超時、失敗——多一次調用就多一個不確定性

但實際上，每位考生拿到的試卷「內容是一樣的」——只是順序不同。有沒有辦法只構造一次，然後從它複製出 N 份？

生活中的原型：Ctrl+C/V 與細胞分裂

這個想法其實我們天天在用：

  • 複製貼上：你在 IDE 裡選中一段代碼，Ctrl+C 複製，Ctrl+V 貼上——你複製的是「原件」的完整副本，不需要從頭重寫。每次貼上都是一個「克隆」。
  • 細胞有絲分裂：一個母細胞分裂成兩個完全相同的子細胞。自然界用「複製」代替「從零構造」，效率遠高於重新合成。
  • 影印機：一頁原件，影印 N 份。你不需要重新手寫 N 遍。

這些例子的共同點：先有一個「原型」，之後的每一份都是從原型複製出來的。複製比從零構造便宜得多。

核心思路：如果你需要反覆創建同一種複雜對象，先造好一個「原型」，之後每次都從它克隆（clone）出來，再在副本上做差異化修改。

Java 裡的落點是 Object.clone() 方法和 Cloneable 接口。多數 Java 類都提供了 clone() API，你只需要讓你的類實現 Cloneable 接口並重寫 clone() 方法。

但——且慢。光知道「要克隆」還不夠，你還得知道「怎麼克隆才對」。下一課先看看：如果不用模式、直接硬編碼，會撞上什麼問題。

關鍵要點

觸發條件說明
重複創建同一種對象需要被多次創建（N 個考生 = N 份試卷）
構造成本高每次從頭構造涉及 I/O、RPC、複雜拼裝，耗時且有風險

這兩個條件同時滿足，就是原型模式的用武之地。
