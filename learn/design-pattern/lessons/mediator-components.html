中介者核心組件的分工與協作

design-pattern › mediator › mediator-components

學習目標：能畫出 SqlSession / DefaultSqlSession / SqlSessionFactory / SqlSessionFactoryBuilder / Configuration 五個組件的協作關係，並說出每個組件的職責。

整體分工圖

中介者由五個核心組件組成，各司其職：

組件類型職責
SqlSession接口定義查詢方法：selectOne、selectList、close
DefaultSqlSession實現類持有 Connection，執行 JDBC 查詢，結果映射成對象
SqlSessionFactory接口定義 openSession()，負責打開會話
DefaultSqlSessionFactory實現類持有 Configuration，openSession 時創建 DefaultSqlSession
SqlSessionFactoryBuilder構建器啟動入口：解析 XML 配置、建立連接、構建 Configuration

還有一個輔助角色 Configuration，它是所有配置的載體——連接信息、SQL 映射表（mapperElement）都存在這裡。

組件 1：SqlSession（查詢接口）

SqlSession 是業務方直接使用的接口，定義了三個方法：

public interface SqlSession {
    <T> T selectOne(String statement, Object parameter);
    <T> List<T> selectList(String statement, Object parameter);
    void close();
}

業務方只需要知道：用 statement 字符串（命名空間 + 方法名）+ 參數來查詢，不需要知道連接怎麼來、SQL 怎麼執行、結果怎麼映射。

組件 2：DefaultSqlSession（核心實現）

這是中介者的「心臟」，把 JDBC 細節全部藏在裡面：

public class DefaultSqlSession implements SqlSession {
    private Connection connection;
    private Map<String, XNode> mapperElement;

    // selectOne：按 statement 取 SQL，執行查詢，返回第一條
    public <T> T selectOne(String statement, Object parameter) {
        XNode xNode = mapperElement.get(statement);
        // ... prepareStatement + executeQuery ...
        return (T) resultSet2Obj(resultSet, xNode.resultType);
    }

    // resultSet2Obj：用 ResultSetMetaData + 反射自動映射
    private Object resultSet2Obj(ResultSet rs, String resultType) {
        // 取列名 → 反射 setter → 返回 POJO
        // 特殊處理：Timestamp → Date
    }
}

關鍵設計：

  • statement 字符串是 namespace.id（如 org.itstack.demo.design.dao.IUserDao.queryUserInfoById），對應 XML 裡的 SQL 定義
  • 結果映射用 ResultSetMetaData 取列名，反射調用 setter，自動把結果行轉成 Java 對象
  • 業務方完全不碰 Connection、PreparedStatement、ResultSet

組件 3：SqlSessionFactory（會話工廠）

工廠模式的典型應用——openSession() 返回一個新的 DefaultSqlSession：

public interface SqlSessionFactory {
    SqlSession openSession();
}

public class DefaultSqlSessionFactory implements SqlSessionFactory {
    private Configuration configuration;

    public SqlSession openSession() {
        return new DefaultSqlSession(
            configuration.connection,
            configuration.mapperElement);
    }
}

Configuration 在啟動時就已經構建好，工廠只是在每次查詢時「打開一個會話」。

組件 4：SqlSessionFactoryBuilder（啟動入口）

這是最先被調用的組件，負責三件事：

  1. 解析 XML 配置：用 SAXReader 讀取 mybatis-config-datasource.xml，提取 dataSource 和 mappers
  2. 建立連接：Class.forName(driver) + DriverManager.getConnection(url, user, password)
  3. 構建 Configuration：把 Connection 和 mapperElement（SQL 映射表）打包存進 Configuration

Configuration 裡的 mapperElement 是怎麼來的？ Builder 會解析每個 Mapper XML（如 User_Mapper.xml），用正則 #{(.*?)} 把佔位符替換成 ?，然後把解析結果（namespace、id、sql、parameterType、resultType）存進 Map：

// mapperElement 的 key 是 "namespace.id"
// 例如 "org.itstack.demo.design.dao.IUserDao.queryUserInfoById"
mapperElement.put(namespace + "." + id, xnode);

完整啟動鏈路

把所有組件串起來，一次查詢的完整鏈路：

// 1. 加載配置
Reader reader = Resources.getResourceAsReader("mybatis-config-datasource.xml");

// 2. 構建工廠（解析 XML + 建連接 + 構建 Configuration）
SqlSessionFactory sqlMapper = new SqlSessionFactoryBuilder().build(reader);

// 3. 打開會話
SqlSession session = sqlMapper.openSession();

// 4. 查詢——業務方只需要 statement + 參數
try {
    User user = session.selectOne(
        "org.itstack.demo.design.dao.IUserDao.queryUserInfoById", 1L);
    System.out.println(user);
} finally {
    session.close();
    reader.close();
}

注意：這跟用 Mybatis 的寫法完全一樣。啟動 → 建工廠 → 開 Session → 查詢 → 關閉。中介者把 JDBC 的四步瑣事藏在了 build() 裡面。

小結

五個組件的協作可以記成一句話：Builder 解析配置 → 工廠打開 Session → Session 屏蔽 JDBC → 業務方只傳 statement + 參數。這就是 Mybatis 的原型，也是中介者模式在 ORM 場景的完整落地。
