Spring 中間件：代理對象進容器

學習目標

掌握 Spring bean 註冊套路（BeanDefinitionRegistryPostProcessor + FactoryBean），完成「代理生成 → 容器管理 → 使用者注入」的完整閉環。

代理生成了，然後呢？

上一篇我們用 Proxy.newProxyInstance 生成了一個代理對象。但這個對象還只是一個普通的 Java 對象——它不在 Spring 容器裡，業務代碼拿不到它。

問題是：怎麼把這個「運行時生成的代理對象」註冊進 Spring 容器，讓業務代碼可以通過 @Autowired 或 getBean 直接使用？

三個前置知識

在看代碼之前，先搞懂 Spring 中間件開發的三件套：

概念是什麼作用
BeanDefinitionRegistryPostProcessor Spring 提供的接口，用於在 bean 定義註冊階段做手腳 在所有 bean 定義加載完畢後、bean 實例化之前，修改或新增 bean 定義
GenericBeanDefinition 用於定義一個 bean 的基本信息（類型、作用域、構造函數參數等） 告訴 Spring「這個 bean 長什麼樣、怎麼創建」
FactoryBean 一個特殊的 bean，它本身是一個工廠 當 Spring 要創建這個 bean 時，實際調用的是 getObject()，返回你自定義的對象

一句話記：

BeanDefinitionRegistryPostProcessor 是「註冊員」，GenericBeanDefinition 是「登記表」，FactoryBean 是「工廠」。
註冊員在 Spring 啟動時填好登記表，告訴工廠「你要負責生產這個 bean」。

代碼走讀：註冊進容器

第一步：自定義注解 @Select

@Documented
@Retention(RetentionPolicy.RUNTIME)  // 必須 RUNTIME 才能被反射讀取
@Target({ElementType.METHOD})        // 只能用在方法上
public @interface Select {
    String value() default "";       // 存放 SQL 語句
}

這就是 MyBatis @Select 的簡化版。方法上標註 @Select("select ...")，運行時通過反射讀取。

第二步：Dao 層接口

public interface IUserDao {
    @Select("select userName from user where id = #{uId}")
    String queryUserInfo(String uId);
}

只有接口、沒有實現類——這正是 MyBatis 用戶的日常寫法。

第三步：代理類（MapperFactoryBean）

上一篇已經看過，MapperFactoryBean 實現了 FactoryBean，在 getObject() 中用 JDK 動態代理生成接口實現。

第四步：將 Bean 定義註冊到 Spring 容器

public class RegisterBeanFactory 
    implements BeanDefinitionRegistryPostProcessor {

    @Override
    public void postProcessBeanDefinitionRegistry(
            BeanDefinitionRegistry registry) {

        // 1. 創建 bean 定義信息
        GenericBeanDefinition beanDefinition = new GenericBeanDefinition();
        beanDefinition.setBeanClass(MapperFactoryBean.class);
        beanDefinition.setScope("singleton");

        // 2. 透傳構造函數參數（IUserDao.class）
        beanDefinition.addGenericArgumentValue(IUserDao.class);

        // 3. 包裝成 BeanDefinitionHolder，取名 "userDao"
        BeanDefinitionHolder holder = new BeanDefinitionHolder(
            beanDefinition, "userDao");

        // 4. 註冊到 Spring 容器
        BeanDefinitionReaderUtils.registerBeanDefinition(
            holder, registry);
    }

    @Override
    public void postProcessBeanFactory(
            ConfigurableListableBeanFactory beanFactory) {
        // 留空
    }
}

拆解關鍵步驟：

  1. setBeanClass(MapperFactoryBean.class)：告訴 Spring，這個 bean 的類型是 MapperFactoryBean
  2. addGenericArgumentValue(IUserDao.class)：MapperFactoryBean 的構造函數需要一個 Class<T> 參數，這裡把 IUserDao 傳進去
  3. registerBeanDefinition：把定義好的 bean 註冊進 Spring 的 bean 工廠

第五步：配置文件觸發

<!-- spring-config.xml -->
<beans default-autowire="byName">
    <bean id="userDao"
          class="org.itstack.demo.design.agent.RegisterBeanFactory"/>
</beans>

只需在配置文件中註冊 RegisterBeanFactory 這個 bean，Spring 啟動時就會自動調用它的 postProcessBeanDefinitionRegistry 方法，把代理 bean 注冊進容器。

完整流程圖

把五步串起來，整個流程是：

  1. Spring 啟動，加載 spring-config.xml
  2. 發現 RegisterBeanFactory bean，實例化並調用後置處理器
  3. 後置處理器創建 GenericBeanDefinition，把 MapperFactoryBean 註冊為 "userDao"
  4. 業務代碼調用 getBean("userDao", IUserDao.class)
  5. Spring 發現 "userDao" 是一個 FactoryBean，調用它的 getObject()
  6. getObject() 用 JDK 動態代理生成 IUserDao 的代理對象並返回
  7. 業務代碼拿到代理對象，直接調用方法，代理攔截並執行 SQL

閉環：從接口到結果

最終的測試驗證：

ClassPathXmlApplicationContext context = 
    new ClassPathXmlApplicationContext("spring-config.xml");
IUserDao userDao = context.getBean("userDao", IUserDao.class);
String result = userDao.queryUserInfo("100001");
// 輸出: SQL: select userName from user where id = 100001
// 返回: 100001,小傅哥,bugstack.cn...
全程沒有寫 IUserDao 的實現類，卻成功調用並返回結果。代理給接口生成了實現，Spring 容器管理了代理的生命周期，使用者完全無感。

代理模式的代價與收益

代價收益
額外增加很多類（代理類、工廠類、註冊類） 中間件複用性極高，可方便擴展到各個服務應用中
需要自己處理 bean 註冊的細節 代碼更整潔乾淨，易於維護
調試時代理類是隱藏的，排錯有學習成本 複雜服務變為輕量級調用，如同開關控制 220V 電線
