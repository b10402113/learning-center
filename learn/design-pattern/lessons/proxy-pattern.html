代理模式的本质与 JDK 动态代理

结构型

本课目标
用 JDK 动态代理实现一个无实现类的 DAO bean，说清 InvocationHandler 的分发原理。

场景：MyBatis 怎么做到"没有实现类"？

你用 MyBatis 写过这样的代码：

@Mapper
public interface UserDao {
    @Select("select userName from user where id = #{uId}")
    String queryUserName(String uId);
}

只有接口，没有实现类，但 Spring 容器里就是能拿到一个可用的 userDao bean。这怎么做到的？

UserDao 接口
→
JDK 动态代理
生成代理类
→
执行 SQL
返回结果

答案就是代理模式——JDK 动态代理在运行时生成一个实现了 UserDao 接口的代理类，拦截所有方法调用，读取 @Select 注解里的 SQL，执行查询并返回结果。

代理模式的核心

代理模式和装饰器长得像——都是"包一层再转发"。但动机不同：

动机对比 装饰器的动机是加功能（给原始对象加新能力）。
代理的动机是控制访问（在调用方和真实对象之间加一个中间层，屏蔽细节）。

代理控制的是"怎么访问"——可以加权限检查、日志、缓存、连接池管理、远程调用……调用方以为自己在直接操作真实对象，实际上中间隔着一层代理。

JDK 动态代理的三个关键

1. Proxy.newProxyInstance — 生成代理类

// 三个参数：
// ① ClassLoader — 用哪个类加载器加载代理类
// ② Class[] — 代理类要实现哪些接口
// ③ InvocationHandler — 方法调用的处理器
Object proxy = Proxy.newProxyInstance(
    userDao.getClass().getClassLoader(),
    new Class[]{ userDao.getClass() },
    handler
);

2. InvocationHandler — 分发中心

// 每次调用代理对象的方法，都会走到这里
InvocationHandler handler = (proxy, method, args) -> {
    // method 是被调用的方法（比如 queryUserName）
    // args 是方法参数
    // 在这里可以加任意逻辑：权限、日志、SQL执行...

    // 读取 @Select 注解
    Select select = method.getAnnotation(Select.class);
    String sql = select.value()[0];

    // 执行 SQL
    return jdbcTemplate.queryForObject(sql, String.class, args);
};

3. 调用方完全无感

// 调用方拿到的是代理对象，但它实现了 UserDao 接口
UserDao userDao = (UserDao) Proxy.newProxyInstance(
    classLoader, new Class[]{UserDao.class}, handler
);

// 调用方法——完全不知道背后是代理在执行
String name = userDao.queryUserName("uid-001");

完整实战：手写 MyBatis DAO 代理

模拟 mybatis-spring 的核心机制：定义接口 + @Select 注解，通过 JDK 动态代理生成可用的 bean。

// ① 定义接口，加 @Select 注解
public interface IUserDao {
    @Select("select userName from user where id = #{uId}")
    String queryUserName(String uId);

    @Select("select userAge from user where id = #{uId}")
    Integer queryUserAge(String uId);
}

// ② InvocationHandler — 读取注解、执行 SQL
public class JdkInvocationHandler implements InvocationHandler {
    private Class<?> mapperInterface;
    private DataSource dataSource;

    public JdkInvocationHandler(Class<?> mapperInterface, DataSource ds) {
        this.mapperInterface = mapperInterface;
        this.dataSource = ds;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args)
            throws Throwable {
        // 读取 @Select 注解
        Select select = method.getAnnotation(Select.class);
        if (select == null) return null;

        String sql = select.value()[0]
            .replace("#{uId}", args[0].toString());

        // 执行 SQL
        try (Connection conn = dataSource.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) {
            if (rs.next()) {
                return rs.getObject(1);
            }
        }
        return null;
    }
}

// ③ 创建代理对象
IUserDao userDao = (IUserDao) Proxy.newProxyInstance(
    JdkInvocationHandler.class.getClassLoader(),
    new Class[]{ IUserDao.class },
    new JdkInvocationHandler(IUserDao.class, dataSource)
);

// ④ 调用——完全无感
String name = userDao.queryUserName("uid-001");

Spring 怎么把代理注册成 Bean？

JDK 动态代理只是生成了一个对象。要让它成为 Spring 容器里的 bean，还需要两步：

BeanDefinitionRegistryPostProcessor
在 Spring 启动时，手动注册 bean 定义：指定接口类、构造函数参数、工厂 bean（MapperFactoryBean）。
MapperFactoryBean<T>
实现 Spring 的 FactoryBean 接口，getObject() 里调用 Proxy.newProxyInstance 生成代理对象。Spring 调用 getObject() 时拿到的就是代理 bean。 
// MapperFactoryBean — Spring 的 FactoryBean
public class MapperFactoryBean<T> implements FactoryBean<T> {
    private Class<T> mapperInterface;

    public MapperFactoryBean(Class<T> mapperInterface) {
        this.mapperInterface = mapperInterface;
    }

    @Override
    public T getObject() throws Exception {
        // 创建 JDK 动态代理
        return (T) Proxy.newProxyInstance(
            mapperInterface.getClassLoader(),
            new Class[]{ mapperInterface },
            new JdkInvocationHandler(mapperInterface, dataSource)
        );
    }
}

代理的典型应用场景

场景代理控制了什么
MyBatis DAO屏蔽 SQL 执行细节，接口直接用
Spring AOP拦截方法调用，织入切面逻辑
RPC 框架屏蔽网络调用，远程方法像本地调用
数据库连接池屏蔽连接获取/释放，调用方用连接即可
延迟加载首次访问才创建真实对象

关键洞察

代理 = 中间人 代理的本质是在调用方和真实对象之间加一个中间人。中间人可以做任何事：权限检查、日志记录、性能监控、远程调用……调用方以为自己在直接操作，实际上被代理拦截了。JDK 动态代理让这个中间人可以在运行时自动生成，不需要手写实现类。

本课小结

  1. 代理模式的核心：控制访问，在调用方和真实对象之间加中间层
  2. JDK 动态代理三要素：Proxy.newProxyInstance + InvocationHandler + 接口
  3. MyBatis DAO 的原理：接口 + @Select 注解 → JDK 动态代理 → 读注解执行 SQL
  4. Spring 通过 FactoryBean + BeanDefinitionRegistryPostProcessor 把代理注册为 bean
  5. 代理常见于中间件：MyBatis、Spring AOP、RPC 框架、连接池
