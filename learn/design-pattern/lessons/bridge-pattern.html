桥接模式：用组合拆掉双维度的笛卡尔积 ifelse

这一课的目标

读完之后，你能：

  • 识别"双维度嵌套 ifelse"的坏味道
  • 用"抽象持有实现引用"的组合方式重构为桥接结构
  • 理解构造函数注入在桥接中的作用

真实场景

🎯 场景：第三方支付聚合平台
你的系统要对接多个支付渠道（微信、支付宝）和多种支付方式（密码、人脸、指纹）。

每个渠道 × 每种方式的组合都得写一个分支。渠道从 2 个变 3 个，方式从 3 个变 5 个——
矩阵从 6 个膨胀到 15 个。

问题是：这些分支的逻辑大部分是重复的——校验安全、调用支付、返回结果。
真正不同的只有两件事：用哪个渠道的 SDK，用哪种方式做安全校验。

坏代码：ifelse 矩阵

❌ 笛卡尔积 ifelse

public class PayController {
    public String doPay(String channelType, 
                        String modeType, String uId) {
        if ("wx".equals(channelType)) {
            if ("password".equals(modeType)) {
                // 微信 + 密码
                return wxPayByPassword(uId);
            } else if ("face".equals(modeType)) {
                // 微信 + 人脸
                return wxPayByFace(uId);
            } else if ("fingerprint".equals(modeType)) {
                // 微信 + 指纹
                return wxPayByFingerprint(uId);
            }
        } else if ("zfb".equals(channelType)) {
            if ("password".equals(modeType)) {
                // 支付宝 + 密码
                return zfbPayByPassword(uId);
            } else if ("face".equals(modeType)) {
                // 支付宝 + 人脸
                return zfbPayByFace(uId);
            }
            // ... 还有指纹
        }
        // 每加一个渠道或方式，这里就膨胀一层
        return "0001";
    }
}

✅ 桥接重构

// 抽象：支付渠道
public abstract class Pay {
    protected IPayMode payMode; // ← 桥接！

    public Pay(IPayMode payMode) {
        this.payMode = payMode;
    }

    public abstract String transfer(String uId);
}

// 实现：支付方式
public interface IPayMode {
    String security(String uId);
}

// 调用方自由组合
Pay wxPay = new WxPay(new PayFaceMode());
wxPay.transfer("u123");

Pay zfbPay = new ZfbPay(new PayCypher());
zfbPay.transfer("u456");

桥接的核心结构

抽象（Abstraction） 实现（Implementation） ┌──────────────────┐ ┌──────────────────┐ │ abstract Pay │── 持有 ──→ │ interface │ │ IPayMode payMode│ │ IPayMode │ └──────────────────┘ └──────────────────┘ │ │ ┌───┴───┐ ┌─────┼─────┐ WxPay ZfbPay PayCypher PayFace PayFingerprint 调用方：new WxPay(new PayFaceMode()) ↑ 渠道 ↑ 方式（构造函数注入）

关键洞察：桥接就是一个字段。抽象类持有一个字段，这个字段的类型是另一个维度的接口。通过构造函数注入，调用方自由组合两个维度。

为什么叫"桥接"？

因为这个字段就像一座桥，把两个独立的维度连接起来：

  • 维度 1：支付渠道（微信、支付宝）— 由子类决定
  • 维度 2：支付方式（密码、人脸、指纹）— 由字段持有
  • 桥：protected IPayMode payMode 字段

没有这座桥，你要么写 M×N 个子类（WxPayPassword、WxPayFace、ZfbPayPassword……），要么写一个巨大的 ifelse 方法。有了这座桥，你只需要 M+N 个类（M 个渠道子类 + N 个方式实现）。

构造函数注入的作用

构造函数注入不只是"传参"——它在编译期就锁定了组合关系：

// 编译期就知道：这个 WxPay 用的是 PayFaceMode
Pay wxPay = new WxPay(new PayFaceMode());

// 运行时也可以换（如果需要）
Pay wxPay = new WxPay(new PayCypher());

调用方不需要知道 WxPay 内部怎么用 payMode，只需要在创建时传入一个 IPayMode 实现。这就是依赖倒置——高层模块（Pay）不依赖低层模块（具体的支付方式），两者都依赖抽象（IPayMode 接口）。

真实类比

  • JDBC 驱动： DriverManager（抽象）持有 Driver（实现）的引用，不同数据库提供不同 Driver
  • 品牌×产品线：联想（抽象）持有笔记本/台式机（实现）的接口，不同产品线有不同的实现
  • 消息队列：MQProducer（抽象）持有具体的 MQ 实现（Kafka/RocketMQ/RabbitMQ）

本课小结

  1. 双维度嵌套 ifelse 的信号：channelType × modeType 这种矩阵
  2. 桥接 = 抽象持有实现引用，通过构造函数注入
  3. 核心手法：用组合替代继承，避免笛卡尔积子类爆炸
  4. M×N 个分支 → M+N 个类
