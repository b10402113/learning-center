享元模式核心概念：內部狀態、外部狀態與享元工廠

design-pattern › flyweight › flyweight-concept

學習目標：理解享元模式「共享內部狀態、外部狀態分離」的意圖，以及享元工廠在服務端與客戶端兩種形態中的角色。

什麼是享元模式

享元模式（Flyweight Pattern）的核心意圖一句話：共享通用對象，減少內存使用、提升系統訪問效率。

「享元」這個名字來自 flyweight——拳擊裡的「蠅量級」，體重最輕的量級。模式的核心就是把對象做到「盡量輕」：不變的部分只保留一份，讓多個地方共用；會變的部分從外部傳入，不佔共享對象的空間。

三個核心概念

內部狀態（Intrinsic State）

內部狀態是不隨環境改變的、可共享的數據。回到秒殺場景：活動名稱「圖書嗨樂」、活動描述「第二期」、起止時間——這些信息從活動上線到結束不會變，所有用戶看到的都一樣。

內部狀態的關鍵特徵：

  • 與具體使用場景無關——不管是誰查詢，都返回相同的值
  • 可以安全地被多個地方共享
  • 存儲在享元對象內部

外部狀態（Extrinsic State）

外部狀態是隨環境改變的、不能共享的數據。秒殺場景中，庫存（已售數量）每個時刻都在變化，每個用戶查詢到的值可能不同。

外部狀態的關鍵特徵：

  • 與具體使用場景相關——不同的調用方可能拿到不同的值
  • 不能被共享，必須由調用方在使用時傳入或單獨獲取
  • 存儲在享元對象外部（比如 Redis 裡）

享元工廠（Flyweight Factory）

享元工廠是管理共享對象的核心組件。它用一個 Map 結構，以固定 id 為 key，緩存已經創建過的享元對象。查詢時先查 Map，命中直接返回，未命中才創建新的並放入 Map。

public class ActivityFactory {
    private static Map<Long, Activity> activityMap = new HashMap<>();

    public static Activity getActivity(Long id) {
        Activity activity = activityMap.get(id);
        if (activity == null) {
            // 首次查詢：創建固定信息並緩存
            activity = new Activity();
            activity.setId(10001L);
            activity.setName("圖書嗨樂");
            activity.setDesc("圖書優惠券分享激勵分享活動第二期");
            activity.setStartTime("2024-06-01");
            activity.setStopTime("2024-06-30");
            activityMap.put(id, activity);
        }
        return activity;  // 第二次及以後直接返回緩存
    }
}

享元工廠的職責：

  • 管理共享：確保同一個 id 的對象只創建一次
  • 規避線程安全：在多線程環境下，工廠需要保證 Map 操作的原子性（可以使用 ConcurrentHashMap 或 synchronized）
  • 提供統一入口：調用方不需要知道對象是新建的還是緩存的

兩種使用形態

享元模式在實際開發中有兩種典型的使用形態：

形態場景共享什麼
服務端共享數據庫連接池、線程池連接/線程對象本身
客戶端共享遊戲地圖渲染（樹木、花草）渲染素材（減少內存佔用）

服務端場景：數據庫連接池就是典型的享元——連接對象是昂貴的（TCP 握手、認證），不可能每次查詢都新建。連接池用 Map 管理一批連接，用完歸還、下次複用。

客戶端場景：遊戲地圖上有幾千棵樹，每棵樹的模型是一樣的（內部狀態），但位置不同（外部狀態）。如果每棵樹都存一份完整模型，內存很快就爆了。享元模式讓所有樹共用一個模型對象，位置信息在渲染時傳入。

享元 vs 緩存：有什麼不同？

你可能覺得「這不就是緩存嗎？」確實很像，但有一個關鍵區別：

  • 通用緩存（如 Redis）：緩存什麼都行，鍵值對任意組合，目標是減少 IO
  • 享元模式：從設計層面把「共享」和「分離」明確分開，工廠是模式的核心組件，目標是減少對象創建和內存佔用

在實踐中，享元模式的 Map 可以是內存 Map，也可以是 Redis——取決於對象是否需要跨進程共享。但不管存儲在哪裡，核心思想是一樣的：用固定 id 存放和獲取對象，避免重複構建。

小結

享元模式的三個核心概念：內部狀態（可共享的不變數據）、外部狀態（不能共享的變化數據）、享元工廠（管理共享的 Map + id 存取機制）。下一課我們會用秒殺場景，把這三個概念落地到完整的重構代碼中。
