Lesson 1/5 · 狀態模式

狀態模式是什麼？

Node: state · Step 1/5

學習目標

能說出狀態模式的核心意圖——「對象內部狀態改變時，行為隨之改變」，並用生活類比解釋為什麼需要讓狀態接管行為。

一個你每天都在做的事

打開某個網站，如果你沒登入，首頁看到的是推薦內容和登入按鈕；一旦登入，首頁變成你的訂閱源、個人中心、歷史記錄。同一個頁面，不同的「狀態」（登入 / 未登入），展示了完全不同的內容和可用操作。

這不是技術上的困難，而是人類行為的自然模式：**同一個對象，因為內部狀態不同，表現出不同的行為**。

狀態模式的核心意圖

狀態模式（State Pattern）解決的問題是：一個對象的行為會根據其內部狀態的不同而變化，而你不想用一堆 if 判斷來問「現在是什麼狀態、能做什麼」。

做法是把每個狀態封裝成一個獨立的類，讓狀態自己決定：

  • 這個操作我能不能執行？
  • 執行完之後，下一步切換到哪個狀態？

對象的行為就由當前狀態來驅動，而不是由外部的分支判斷來驅動。

類比：磁帶放音機

想像一台老式磁帶放音機，有幾個按鈕：播放、暫停、快進、倒帶、停止。

當前狀態能按的按鈕不能按的
停止播放、倒帶暫停、快進
播放中暫停、停止、快進播放（已在播放）
暫停播放、停止暫停（已在暫停）
快進中停止播放、暫停、倒帶

每個按鈕不是隨時都能按——它能不能按、按了之後磁帶機切換到什麼狀態，取決於當前狀態。這就是狀態模式的直覺：狀態決定行為。

狀態 vs. 條件分支

你可能會想：「用 if-else 判斷當前狀態不就行了？」

可以，但問題在於：

  • 每加一個新狀態，所有 if-else 分支都要改
  • 狀態越多，分支越複雜，誰加了什麼邏輯都搞不清楚
  • 新來的工程師看到一坨 if-else 根本不敢動

狀態模式把「哪個狀態能做什麼」的邏輯分散到每個狀態類裡，而不是集中在一個 if-else 巨牆上。加新狀態時，只需要加一個新類，不用改其他狀態的代碼。

一句話記住

狀態模式 = 讓對象的內部狀態接管行為，取代外部的 if-else 判斷。

自我檢測

Q1. 狀態模式的核心意圖是什麼？

  • 用工廠創建不同狀態的對象
  • 讓對象的內部狀態改變時，行為隨之改變，取代外部分支判斷
  • 把所有狀態存進數據庫，動態讀取
  • 用觀察者模式通知所有狀態變化

Q2. 磁帶放音機在「播放中」狀態時，哪個按鈕不能按？

  • 暫停
  • 停止
  • 播放（重複播放）
  • 快進

Q3. 用 if-else 判斷狀態的最大問題是？

  • 每加一個新狀態，所有分支都要改
  • 運行速度太慢
  • 不支持多線程
  • 沒辦法存儲狀態
