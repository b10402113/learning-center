JDK 動態代理：無實現類也能調用

學習目標

理解 JDK 動態代理機制（InvocationHandler + Proxy.newProxyInstance），看懂 MyBatis 為什麼「只定義接口、不寫實現類」就能跑。

從接口到實例：空缺在哪裡？

上一篇我們知道 MyBatis 的魔法是「只定義接口，不寫實現類」。但 Java 是一門強類型語言——你調用一個方法，JVM 必須找到一個具體的類來執行這個方法體。

問題來了：接口 IUserDao 只有方法簽名，沒有方法體。JVM 是怎麼找到「queryUserInfo 該幹嘛」的？

答案：JDK 動態代理

JDK 在 1.3 版本就提供了動態代理機制，它讓你在運行時為一個接口生成一個實現類——你不需要手寫這個實現類，JVM 幫你生成。

整個機制由兩個核心角色組成：

角色是什麼職責
InvocationHandler 一個接口，你提供實現 定義「方法被調用時幹嘛」——攔截所有方法調用，決定返回什麼
Proxy.newProxyInstance() JDK 提供的靜態工廠方法 為指定接口生成一個代理對象（實現類實例），把方法調用轉發給 InvocationHandler

一句話記：

InvocationHandler 是「攔截器」，Proxy.newProxyInstance() 是「生成器」。
攔截器告訴系統「方法調用時做什麼」，生成器幫你造出那個「看起來像實現類的代理對象」。

代碼走讀：代理怎麼工作的

讓我們看一下 MyBatis 風格的代理類定義：

public class MapperFactoryBean<T> implements FactoryBean<T> {

    private Class<T> mapperInterface;

    // 構造函數：接收要代理的接口類型
    public MapperFactoryBean(Class<T> mapperInterface) {
        this.mapperInterface = mapperInterface;
    }

    @Override
    public T getObject() throws Exception {
        // 1. 定義攔截器：方法被調用時做什麼
        InvocationHandler handler = (proxy, method, args) -> {
            // 從方法的 @Select 注解取 SQL
            Select select = method.getAnnotation(Select.class);
            String sql = select.value().replace("#{uId}", args[0].toString());
            System.out.println("SQL: " + sql);
            // 模擬查詢結果
            return args[0] + ",小傅哥,bugstack.cn...";
        };

        // 2. 生成代理對象
        ClassLoader classLoader = mapperInterface.getClassLoader();
        return (T) Proxy.newProxyInstance(
            classLoader,
            new Class[]{mapperInterface},  // 要代理的接口
            handler                        // 攔截器
        );
    }

    @Override
    public Class<T> getObjectType() {
        return mapperInterface;
    }

    @Override
    public boolean isSingleton() {
        return true;
    }
}

拆解核心流程

整個代理過程分三步：

第一步：定義攔截器（InvocationHandler）

你告訴系統：「當有人調用 queryUserInfo 時，幫我做這幾件事」：

  1. 從方法的 @Select 注解取出 SQL 語句
  2. 把 SQL 裡的佔位符 #{uId} 替換成實際參數
  3. 打印 SQL（模擬執行）
  4. 返回一個模擬的查詢結果

第二步：生成代理對象（Proxy.newProxyInstance）

調用 Proxy.newProxyInstance，傳入三個參數：

  • ClassLoader：用接口的類加載器，確保代理類和接口在同一個類加載體系
  • Class[]：要代理的接口列表（這裡只有一個 IUserDao）
  • InvocationHandler：你的攔截器

返回值就是一個 IUserDao 類型的對象——但它不是你手寫的實現類，而是 JVM 在運行時動態生成的。

第三步：調用代理

當你調用 userDao.queryUserInfo("100001") 時：

  1. JVM 把調用轉發給 InvocationHandler 的 invoke 方法
  2. invoke 方法取出注解裡的 SQL，替換參數，打印日誌
  3. 返回模擬結果 "100001,小傅哥,bugstack.cn..."

從使用者的角度，你看到的就是「接口有實現」——完全不知道背後是代理在工作。

關鍵理解：接口 vs 實現類

傳統方式：你手寫 UserDaoImpl implements IUserDao，JVM 直接調用你的實現。
動態代理：你什麼都不寫，JVM 在運行時生成一個隱藏的實現類，把方法調用轉發給你的 InvocationHandler。

動態代理的「動態」就體現在：實現類不是編譯時就存在的，而是運行時按需生成的。這也是為什麼你找不到 IUserDaoImpl 這個類——它根本不存在於你的源碼中。
