組合模式的四角色與引擎遍歷

設計模式 · 節點 17 · 步驟 2/3

這節課你要學會什麼

讀完這篇文章，你能說出組合模式的四個角色——節點、鏈路、果實、過濾器——各自的職責，以及引擎從樹根遍歷到果實的完整流程。

從上一節的痛到這節的解法

上一節看到：ifelse 直寫把所有判斷邏輯堆在一個方法裡，每加一個維度就指數膨脹。組合模式的解法是把判斷邏輯拆成獨立的「節點」，按樹形結構組織，由「引擎」統一執行。

但「組合成樹」聽起來很抽象。這節會拆解出四個具體角色，用營銷決策樹的場景逐一套上，最後看引擎是怎麼從根走到果實的。

四個角色

角色它做什麼決策樹場景的對應
樹節點（TreeNode） 樹的基本單位。每個節點有 nodeType 區分「子葉」（需要繼續判斷）和「果實」（最終結果） nodeType=1 是子葉（性別判斷、年齡判斷），nodeType=2 是果實（發券結果 A/B/C/D）
節點鏈路（TreeNodeLink） 連接兩個節點的邊。定義「從節點 A 到節點 B 的條件」 從根節點（性別）到子節點（年齡）的鏈路：「性別=男 → 走左邊」
過濾器（LogicFilter） 具體的判斷邏輯。接口定義 filter（做判斷）和 matterValue（取決策值） UserGenderFilter 取性別，UserAgeFilter 取年齡，各自實現判斷邏輯
引擎（Engine） 統一入口。從樹根出發，循環遍歷子葉節點，直到落到果實 TreeEngineHandle 接收用戶信息，沿著決策樹走到最終發券結果

模型結構一覽

用一張圖來看整棵決策樹的組織方式：

                    ┌──────────┐
                    │  樹根 1   │  nodeType=1（子葉）ruleKey=userGender
                    └────┬─────┘
                         │
              ┌──────────┴──────────┐
              │                     │
        ┌─────┴─────┐         ┌─────┴─────┐
        │  節點 11   │         │  節點 12   │  nodeType=1（子葉）ruleKey=userAge
        │ (男→左)   │         │ (女→右)   │
        └─────┬─────┘         └─────┬─────┘
              │                     │
       ┌──────┴──────┐       ┌──────┴──────┐
       │             │       │             │
  ┌────┴────┐  ┌────┴────┐ ┌┴────────┐ ┌┴────────┐
  │果實 111 │  │果實 112 │ │果實 121 │ │果實 122 │  nodeType=2（果實）
  │ 果實 A  │  │ 果實 B  │ │ 果實 C  │ │ 果實 D  │
  └─────────┘  └─────────┘ └─────────┘ └─────────┘
  男+<25     男+≥25      女+<25     女+≥25

每個子葉節點的 ruleKey 對應一個過濾器（userGender → UserGenderFilter，userAge → UserAgeFilter）。過濾器從用戶信息中取出對應值，和鏈路上的規則比較，決定下一步走哪個子節點。

過濾器的判斷邏輯

抽象類 BaseLogic 實現了 LogicFilter 接口，提供通用的判斷方法 filter。它支持五種規則類型：

ruleLimitType含義決策樹場景
1等於性別等於 "man" → 走左邊
2大於年齡 ≥ 25 → 走右邊
3小於年齡 < 25 → 走左邊
4小於等於—
5大於等於—

filter 方法的邏輯很簡單：取出用戶的決策值（matterValue），和鏈路上的 ruleLimitValue 比較。匹配就返回下一個子節點的 ID，不匹配就返回 -1（表示沒有匹配的路徑）。

引擎遍歷流程

引擎的核心方法是 engineDecisionMaker，從樹根出發，用 while 循環往下走：

while (nodeType == 1) {           // 還是子葉節點
    LogicFilter filter = config.get(ruleKey);   // 取出對應的過濾器
    String value = filter.matterValue(info);    // 從用戶信息取值
    Long nextNodeId = filter.filter(value, links);  // 判斷，得到下一個節點 ID
    node = treeMap.get(nextNodeId);  // 移動到下一個節點
    nodeType = node.getNodeType();
}
// 出循環時，nodeType == 2，到達果實節點
return new EngineResult(node.getValue());  // 返回結果

整個流程就是：從根出發 → 查過濾器 → 取值判斷 → 移動到子節點 → 重複 → 直到果實。日誌會逐節點打印「決策樹引擎=> treeNode：11 ruleKey：userGender」，讓你看到整條決策路徑。

配置可抽離

一個關鍵設計：EngineConfig 用一個 map 靜態註冊過濾器（key=ruleKey，value=過濾器實例）。這個 map 完全可以抽到資料庫：

  • 新增一個判斷維度（比如「地區」）：只需要寫一個 UserRegionFilter 類，然後在配置裡加一行 userRegion → new UserRegionFilter()
  • 改判斷規則：只改配置參數，不動引擎代碼
  • 不同場景用不同樹：用不同 treeId 查出不同的樹結構，引擎代碼完全不變

完整流程圖

把所有角色串起來，一次決策的完整流程：

  1. 調用方傳入 userId、userSex、userAge
  2. 引擎從 treeMap 取出樹根節點（nodeType=1，子葉）
  3. 讀取根節點的 ruleKey（userGender），從配置中取出 UserGenderFilter
  4. 過濾器取用戶性別，和鏈路上的規則比較，返回下一個子節點 ID
  5. 引擎移動到下一個子節點（userAge 判斷）
  6. 重複步驟 3-4，直到 nodeType=2（果實節點）
  7. 返回果實節點的值（果實 A/B/C/D）

小結

組合模式的四個角色是：樹節點（TreeNode）定義「是判斷還是結果」、節點鏈路（TreeNodeLink）定義「判斷後走哪條路」、過濾器（LogicFilter）實現「具體怎麼判斷」、引擎（Engine）負責「從根走到果實」。配置可抽到資料庫，新增維度只需加過濾器不改引擎。下一節會講：組合模式什麼時候該用、什麼時候不該用，以及和裝飾器、代理的區別。
