# 模板方法模式是什麼

## Learning goal

說出模板方法「固定骨架、子類填步驟」的意圖，用西游記八十一難類比記住它。

## Lesson

想像你在帶團隊做一個固定流程的活動：先報名、再排練、最後演出。報名和排練的流程是固定的——你不需要每次重新設計；但排練什麼節目、演出什麼內容，由各個小組自己決定。

模板方法模式（Template Method Pattern）做的事情完全一樣：在一個抽象父類中**定義好算法的執行骨架**，把具體實現步驟延遲到子類去填。子類不用管整體流程怎麼走，只需要關心「我的那一環怎麼做」。

用一句話記：**父類定執行順序，子類填具體步驟。**

### 西游記的八十一難

小傅哥在書裡用西游記九九八十一難做類比：每一關的套路都一樣——師傅被擄走、打妖怪、妖怪被收走。具體是什麼妖怪（白骨精？牛魔王？），怎麼打（打？請菩薩？），由你自己定。執行順序和基本策略由框架（觀音菩薩）固定。

把這個類比翻譯成設計模式的術語：

| 西游記 | 模板方法模式 |
| --- | --- |
| 觀音安排的固定通關流程 | 抽象父類的**模板方法**（定義執行順序） |
| 「打妖怪」的具體策略 | 子類實現的**抽象方法** |
| 唐僧師徒 | 具體子類 |

觀音不會告訴你打哪個妖怪，但會告訴你「先被擄、再打、最後收」——順序是釘死的。

### 與策略模式的區別

策略模式也是處理「多種算法可替換」的場景，但兩者有一個根本差異：

| | 策略模式 | 模板方法模式 |
| --- | --- | --- |
| 控制權 | 客戶端選擇用哪個策略 | 父類**釘死**執行順序 |
| 算法關係 | 各策略互相獨立、可互換 | 各步驟有**先後依賴**，不能互換 |
| 實現方式 | 接口 + 注入 | 繼承（子類覆寫父類方法） |
| 典型場景 | 優惠券計算（滿減/折扣/直減） | 爬蟲流程（登錄→爬取→生成） |

簡單記：策略模式是「算法族互換、隨意切換」；模板方法是「流程釘死、子類只能填空」。

### 模板方法的正式意圖

GoF 的經典定義：模板方法模式**定義一個操作中的算法骨架，將一些步驟延遲到子類中**，使子類不改變算法結構即可重定義某些特定步驟。

拆開來看：

- **骨架** = 父類中的一個具體方法，它按順序調用多個步驟
- **步驟** = 抽象方法，父類聲明但不實現，交由子類填充
- **不改變結構** = 子類不能改動骨架方法的調用順序，只能改動個別步驟的實現
