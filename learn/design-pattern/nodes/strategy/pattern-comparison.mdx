# 策略 vs 命令/適配器/組合

## Learning goal

能說出策略模式與命令、適配器、組合模式「結構相似但意圖不同」的具體差異，給出選型判斷依據。

## Lesson

策略模式、命令模式、適配器模式、組合模式，這四個模式的類圖長得很像——都有一個接口、多個實現類、一個持有者或調用者。如果你只看結構，很容易分不清誰是誰。但它們解決的問題完全不同。區分的關鍵不是「結構長什麼樣」，而是**意圖是什麼**。

策略模式 vs 命令模式：兩者都有一個接口 + 多個實現，關鍵區別在綁定對象。策略模式的策略類是自包含的——它自己知道怎麼算，不需要外部接收者；命令模式的命令類通常綁定一個接收者（Receiver），execute() 方法內部調用接收者的操作。判斷標準：你的類需不需要綁定一個「做事的人」？需要 → 命令模式。不需要，算法本身就是全部 → 策略模式。命令模式的典型場景是菜單按鈕、操作佇列、撤銷/重做，這些都需要「誰來執行」的接收者。

策略模式 vs 適配器模式：核心區別在接口的來源。策略模式的接口是設計者自己定義的，統一而乾淨，所有實現都遵守這個契約。適配器模式的接口是已有的、不兼容的，適配器的作用是做翻譯——把一個不兼容的接口轉換成另一個。判斷標準：接口是你的設計還是對方的遺留？你設計的 → 策略模式。對方的不兼容 → 適配器。

策略模式 vs 組合模式：這兩者差異最大。組合模式的核心是樹形結構的統一調用——讓葉子節點和組合節點用同一個接口操作，典型的例子是文件系統（文件 + 文件夾）、組織架構、菜單樹。策略模式是平級算法的互換，不是樹形結構。如果你的需求不是樹形結構，基本不會用到組合模式。

選型速查：同一動作有多種算法、未來會加新的 → 策略模式（算法自包含）；請求的發送和接收要解耦、需要撤銷/佇列 → 命令模式（命令綁定接收者）；對方的接口和我要的不一樣 → 適配器模式（接口不兼容）；樹形結構要統一調用個體和組合 → 組合模式（遞歸樹）。面試被問到「策略和命令有什麼區別」時，不要從結構入手，從意圖和核心問題出發：你要封裝的是算法還是請求？
