# 享元模式核心概念：內部狀態、外部狀態與享元工廠

## Learning goal

理解享元模式「共享內部狀態、外部狀態分離」的意圖，以及享元工廠在服務端與客戶端兩種形態中的角色。

## Lesson

享元模式（Flyweight Pattern）的核心意圖是**共享通用對象，減少內存使用、提升系統訪問效率**。「享元」來自 flyweight——拳擊裡的「蠅量級」，體重最輕的量級。模式的核心就是把對象做到「盡量輕」：不變的部分只保留一份，讓多個地方共用；會變的部分從外部傳入，不佔共享對象的空間。

三個核心概念：

**內部狀態（Intrinsic State）**是不隨環境改變的、可共享的數據。秒殺場景中，活動名稱「圖書嗨樂」、活動描述、起止時間——這些信息從上線到結束不會變，所有用戶看到的都一樣。內部狀態的關鍵特徵：與具體使用場景無關、可以安全地被多個地方共享、存儲在享元對象內部。

**外部狀態（Extrinsic State）**是隨環境改變的、不能共享的數據。庫存（已售數量）每個時刻都在變化，每個用戶查詢到的值可能不同。外部狀態不能被共享，必須由調用方在使用時傳入或單獨獲取，存儲在享元對象外部（比如 Redis 裡）。

**享元工廠（Flyweight Factory）**是管理共享對象的核心組件。它用一個 Map 結構，以固定 id 為 key，緩存已經創建過的享元對象。查詢時先查 Map，命中直接返回，未命中才創建新的並放入 Map。工廠的職責是管理共享、規避線程安全、提供統一入口。

享元模式在實際開發中有兩種典型的使用形態：服務端共享（數據庫連接池、線程池——連接/線程對象本身是共享的）和客戶端共享（遊戲地圖渲染——幾千棵樹共用一個模型對象，位置信息在渲染時傳入）。用一個類比：你在公司印名片，公司名、地址、電話這些固定信息不需要每次都重新排版——存一個模板就行。但每個人的姓名和職位是變化的，得臨時填進去。享元工廠就是那個「模板庫」。

享元模式和通用緩存（如 Redis）的關鍵區別在於：通用緩存緩存什麼都行，目標是減少 IO；享元模式從設計層面把「共享」和「分離」明確分開，工廠是模式的核心組件，目標是減少對象創建和內存佔用。在實踐中，享元模式的 Map 可以是內存 Map，也可以是 Redis——取決於對象是否需要跨進程共享。但不管存儲在哪裡，核心思想一樣：**用固定 id 存放和獲取對象，避免重複構建**。
