# 訪問者模式的意圖：穩定結構 + 易變訪問

<LearningGoal>
講清訪問者模式解決什麼問題、為何「穩定數據結構 + 易變訪問邏輯」需要解耦，並能判斷何時該用這個模式。
</LearningGoal>

## Lesson

你在學校系統裡存了學生和老師的基本信息——姓名、班級、身份。這些數據不太會變。但不同角色想從中看到的東西完全不同：家長關心自己孩子的成績排名和老師的教學水平，校長關心整個班級的學生人數和升學率。如果把這些訪問邏輯直接塞進學生/老師類裡，每來一個新角色（比如教育局督導），就得改數據類本身——這違反了開閉原則，類會不斷膨脹。

訪問者模式解決的就是這件事：**穩定的數據結構不動，把「誰來看、看什麼」的訪問邏輯抽成獨立模塊**。數據結構（學生、老師的屬性）穩定，訪問邏輯（家長視角、校長視角）多變——這就是訪問者模式的舞台。

不用訪問者模式的做法有三種壞味道：一是每個數據類裡加 `showForParent()`、`showForPrincipal()` 方法，每加視角就要改數據類；二是一個方法內部用 `if (role == PARENT) ...` 堆分支；三是數據類同時承擔數據管理和業務邏輯兩種職責。訪問者模式把操作從數據裡拆出來，讓操作可以自由擴展，數據結構保持穩定。

判據很簡單：**數據結構穩定 + 訪問邏輯多變 = 訪問者模式**。如果你的數據結構本身經常增刪類型（比如定期加新節點種類），或者只有一兩種訪問方式，就不需要用它。
