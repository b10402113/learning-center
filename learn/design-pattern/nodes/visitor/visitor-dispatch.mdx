# 雙分派機制：visitor.visit(this) 怎麼運作

<LearningGoal>
理解雙分派（double dispatch）的運作過程，能拆解 `visitor.visit(this)` 一行代碼如何同時牽動 User 與 Visitor 兩個繼承體系。
</LearningGoal>

## Lesson

訪問者模式最核心的一行代碼是 `visitor.visit(this)`，它出現在每個數據結構類的 `accept` 方法裡。看起來很簡單，但它觸發了**兩次方法分派**——這就是「雙分派（double dispatch）」。

Java 的普通多態是單分派：運行時只根據接收者的實際類型決定調用哪個方法，參數類型在編譯時就確定了。但訪問者模式需要既看「誰被訪問」又看「誰來訪問」，單分派做不到。

第一次分派和普通多態一樣：`student.accept(principal)` 時，Java 根據 `student` 的實際類型找到 `Student.accept()`。第二次分派在 `accept` 內部：`visitor.visit(this)` 裡，`this` 的編譯時類型是 Student，`visitor` 的運行時類型是 Principal，Java 據此匹配到 `Principal.visit(Student)` 這個重載。把 visitor 換成 Parent，就匹配到 `Parent.visit(Student)`——同一份 Student 數據，不同訪問者走不同的 visit 重載。

雙分派的結構前提是兩個獨立的繼承體系：數據結構側（User 抽象類 → Student、Teacher）提供 `accept(Visitor)`；訪問者側（Visitor 接口 → Principal、Parent）提供 `visit(Student)` 和 `visit(Teacher)` 兩個重載。雙方通過 `visitor.visit(this)` 互相連接，這也是訪問者模式被認為「燒腦」的原因——需要同時理解兩個繼承體系的交互。
