# 四种基础单例实现

## Learning goal

<掌握 4 种基础单例实现（静态类、懒汉、synchronized、饿汉）的代码结构与各自的致命缺陷>

## Lesson

最简单的方案是静态类加 `ConcurrentHashMap` 缓存——把方法放在一个 `final` 类里，构造函数私有化，用 `computeIfAbsent` 做懒初始化。它线程安全、无锁竞争，但没有真正的实例状态，更适合做工具类而不是有状态的全局对象。

懒汉模式（变体 1）是直觉上的标准答案：第一次调用时才 `new`。但它在多线程下有致命缺陷——两个线程同时通过 `null` 检查，各自创建了一个实例，单例约束被打破。synchronized 方法（变体 2）给整个方法加锁解决了安全问题，但每次调用都要等锁，实例创建之后 99.99% 的调用只需要读 `instance`，却依然要付锁的代价，高并发下性能损失严重。饿汉模式（变体 3）利用 JVM 类加载机制，在类加载时就创建 `static final` 实例，线程安全、没有锁、性能最好，但不支持懒加载——类一加载就创建，不管用不用，对象创建开销大时浪费资源。

四种实现的取舍一目了然：变体 0 不适合有状态单例；变体 1 有 bug 不能用；变体 2 安全但性能差；变体 3 简单可靠但不懒加载。下一步要解决的核心问题是：能不能同时做到线程安全 + 懒加载 + 高性能（不每次加锁）？答案是可以的——JVM 类加载机制（Holder 模式）、`volatile` + 双重检查锁（DCL）、以及无锁的 CAS，都能做到这一点。
