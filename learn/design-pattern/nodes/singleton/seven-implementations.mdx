# 7 種單例實現逐一拆解

<LearningGoal>
逐一拆解 7 種單例寫法的線程安全機制與懶載入取捨，能說出每種的優缺點與適用場景。
</LearningGoal>

## Lesson

七種寫法的分野集中在兩個維度：**懶不懶加載**（用到時才建 vs 啟動就建）和**線不線程安全**（多線程同時獲取會不會建出多個）。非懶加載且線程安全的有靜態類（第 0 種）和餓漢（第 3 種）；懶加載且線程不安全的只有懶漢（第 1 種）；其餘四種都是懶加載且線程安全。

**第 0 種：靜態類**——不需要實例化，直接用 static 成員，`public static Map<String, String> cache = new HashMap<>()` 在 static 區塊初始化。天然線程安全（類加載機制保證），但不支持繼承，不需要維持狀態。適用場景是純工具方法，不需要單例模式。

**第 1 種：懶漢（線程不安全）**——私有構造方法禁止外部 new，`getInstance()` 裡 `if (instance == null)` 判空後才創建。問題是多線程下，線程 A 判到 null 還沒來得及 new，線程 B 也判到 null 進去了，結果兩個實例。

**第 2 種：懶漢 synchronized（線程安全）**——在 `getInstance` 方法上加 `synchronized`，解決了線程安全問題，但每次獲取都要走鎖，哪怕實例早就創建好了，性能代價太大。

**第 3 種：餓漢（線程安全）**——`private static final Singleton_03 instance = new Singleton_03()`，類加載時就建好，JVM 保證只初始化一次，無鎖高性能。代價是不類加載時就建好，JVM 保證只初始化一次，無鎖高性能。代價是不懶加載，不管用不用都啟動即建。

**第 4 種：靜態內部類（線程安全）**——私有構造，內部類 `SingletonHolder` 持有 `private static final Singleton_04 INSTANCE`，`getInstance()` 返回 `SingletonHolder.INSTANCE`。JVM 只在首次調用時加載內部類，加載時執行靜態初始化，JVM 保證線程安全。既懶加載又無鎖，手動實現的首選。

**第 5 種：DCL 雙重鎖校驗（線程安全）**——外層 `if (instance == null)` 避免不必要的同步，`synchronized (Singleton_05.class)` 塊內二次判空後創建。需要 `volatile` 禁止指令重排序，防止其他線程拿到半初始化的對象。面試常考。

**第 6 種：CAS AtomicReference（線程安全）**——用 `AtomicReference<Singleton_06>` 包裝實例，自旋循環中先取值判空，再 `compareAndSet(null, new Singleton_06())`。CAS 不依賴傳統加鎖，靠底層硬件保證原子性，但自旋忙等消耗 CPU，高競爭時性能可能退化。

**第 7 種：枚舉（Effective Java 推薦）**——`enum Singleton_07 { INSTANCE; }`，一行搞定。JVM 保證 enum 只返回定義好的實例，Java 語言規範禁止反射創建 enum 實例，enum 天然支持序列化/反序列化不會創建新實例。線程安全、防反射、防序列化、代碼最簡，唯一限制是不能被繼承。

實戰結論：**靜態內部類**是手動首選（懶加載 + 無鎖），**DCL** 是面試常考（volatile + 雙重判空），**枚舉**是最佳實踐（防反射 + 防序列化）。不需要被繼承就用枚舉，需要被繼承就用靜態內部類。
