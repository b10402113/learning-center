# 枚举单例与七种实现的选择

## Learning goal

<掌握枚举单例的最佳实践，并能用决策树在 7 种实现中做出选择>

## Lesson

枚举单例（变体 7）是《Effective Java》推荐的方案，也是最简单的——直接声明一个 `public enum Singleton { INSTANCE; }`，使用时 `Singleton.INSTANCE` 即可，没有 `getInstance()` 方法，因为 enum 常量本身就是单例。它自动具备三项能力：序列化安全（JVM 自动处理，反序列化返回同一个实例，不需要实现 `readResolve()`）、反射攻击防御（JVM 禁止通过反射创建 enum 实例）、线程安全 + 懒加载（JVM 类加载机制天然保证）。唯一的限制是 enum 天生是 `final` 的不能被继承，但实际项目中单例需要继承的情况非常少见。

面对 7 种实现，实际选择只需要回答两个问题。第一，单例需要序列化或防反射攻击吗？如果是，用枚举。第二，不需要序列化/反射防御时，需要懒加载吗？如果不需要（对象创建开销小、一定会用到），用饿汉；如果需要，追求简洁选 Holder 模式，追求极致性能选 CAS。变体 1（懒汉线程不安全）有 bug 不能用，变体 2（synchronized 方法）性能差不应使用，它们的意义是帮你理解演进过程。日常项目中两条规则记住就够：需要序列化/防反射用枚举，其他情况用 Holder 模式。

最后提醒不要滥用单例：Spring Bean 默认就是单例的，不需要自己写单例类；无状态的工具类用静态方法就够了；需要测试替身（Mock）的类很难 Mock 单例，依赖注入比单例更容易测试。单例解决的是"全局唯一实例"的问题，如果只是想方便地共享数据，考虑用依赖注入或配置中心。
