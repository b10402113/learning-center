# 策略/狀態/命令/模板——四種行為模式怎麼分

## Learning goal

能說出策略、狀態、命令、模板方法四種行為模式的核心區別，並用一句話判斷「這個場景該套哪一個」。

## Lesson

面試問「策略和狀態有什麼區別」，考的不是背誦——是看你能不能在具體場景下做出正確的選擇。四種行為模式的共同點是都涉及「行為的切換或編排」，但它們切換的東西完全不同。

**策略模式**切換的是**算法**。同一個動作有多種實現方式，按需互換。你在電商做優惠券，折扣計算有四種：直減、滿減、折扣、n元購。每種計算邏輯完全不同，但調用方式一樣——傳入價格，返回折後價。判斷標準：同一個方法的參數和返回值不變，但內部計算邏輯可以互換。你不會因為用了一種策略而改變方法的調用方式，只是換了內部的「計算公式」。典型結構是接口 + 多個實現類 + Context 控制類，核心收益是把 ifelse 拆成獨立的類，新增算法時不動已有代碼。

**狀態模式**切換的是**狀態**。同一個對象，內部狀態變了，行為就跟著變。你在做營銷活動審核系統，活動有 7 種狀態（編輯、待審核、審核通過、審核拒絕、活動中、關閉、開啟），每種狀態下允許的操作不同——編輯狀態可以提審，但不能直接開啟；審核拒絕可以撤審回編輯，但不能直接進入活動中。判斷標準：同一個方法，行為會根據對象當前的內部狀態而不同。典型結構是 State 抽象類 + 多個狀態實現類 + StateHandler 映射，每個狀態類知道自己能流轉到哪些狀態，不需要外部 if 判斷。

**命令模式**切換的是**請求**。把操作封裝成對象，解耦「誰下命令」和「誰執行」。你在做餐廳點單系統，顧客把菜系告訴小二，小二把菜單傳給對應廚師。顧客不關心誰做菜，廚師不關心誰點菜——小二就是中間的命令調用者。判斷標準：操作的「下命令」和「執行命令」是兩撥不同的人或系統。典型結構是命令接口 + 具體命令（注入實現者）+ 調用者，核心收益是請求與實現解耦，支持撤銷、重做、批量執行。

**模板方法**切換的是**步驟**。骨架固定，子類填補具體步驟的實現。你在做電商爬蟲推廣海報，爬京東、淘寶、當當，三步流程完全一樣：登錄 → 爬商品 → 生成海報。但每一步的具體實現不同。判斷標準：多個實現共享同一個執行順序，只是每個步驟的具體做法不同。典型結構是抽象類（模板方法 + 抽象步驟）+ 多個子類實現，父類控制流程，子類只管填空。

速判口訣：策略是「同一個方法有幾種寫法，你要哪種？」狀態是「現在是什麼狀態？狀態不一樣，行為就不一樣」。命令是「下命令的人和做事情的人不是同一個」。模板是「步驟順序不變，但每步怎麼做你說了算」。

面試常見陷阱：策略 vs 狀態——策略是「外部選算法」，狀態是「內部自己切換」。策略的切換由調用方決定，狀態的切換由狀態自身決定。策略 vs 命令——策略關注「怎麼算」，命令關注「誰做、誰調」。策略的接口通常是無狀態的純計算，命令的接口通常帶有「執行者」的引用。模板 vs 策略——模板是「流程級」的（多個步驟的順序），策略是「方法級」的（一個方法的實現）。模板用繼承，策略用組合。
