# 原型模式

## Learning goal

講清原型「克隆複製、省創建成本」的意圖，用試卷混排場景。

## Steps

1. [[learn/design-pattern/nodes/prototype/why-clone|為什麼需要克隆？——重複創建對象的隱形成本]] — 理解原型模式的動機：重複創建複雜對象的開銷
2. [[learn/design-pattern/nodes/prototype/naive-implementation|一把梭實現：硬編碼試卷為什麼行不通]] — 看出硬編碼實現的順序固定與擴展性問題（after step 1）
3. [[learn/design-pattern/nodes/prototype/clone-in-practice|原型模式重構：Cloneable + clone() 實現試卷亂序]] — 掌握 Cloneable 接口 + clone() 的完整落地與試卷亂序（after step 2）
4. [[learn/design-pattern/nodes/prototype/shallow-deep-copy|淺拷貝 vs 深拷貝：clone() 的隱藏陷阱與選型邊界]] — 理解淺拷貝陷阱、深拷貝策略，以及原型模式的優缺點與適用邊界（after step 3）

## Lesson

原型模式解決一個看似簡單但代價不低的問題：當你需要反覆創建同一種複雜對象時，每次都從零構造太貴了——對象可能要查庫、調 RPC、拼裝大量字段。原型模式的核心思路是：先造好一個「原型」，之後每次都從它克隆（clone）出來，再在副本上做差異化修改。Java 層面的落點是 `Cloneable` 接口 + `Object.clone()`。

本節用「上機考試試卷混排」串起整個模式：題庫是原型，每位考生的試卷從原型克隆後亂序。從一把梭硬編碼（順序固定、無法亂序）到 Cloneable 重構（克隆 + shuffle + 選項亂序），四步走完你應該能說出原型模式的意圖、Java 實現要點、淺拷貝陷阱，以及「何時用、何時不用」的選型邊界。
