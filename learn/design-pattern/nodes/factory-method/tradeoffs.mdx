# 工廠方法的收益與類爆炸風險

<LearningGoal>
能說出工廠方法模式的開閉原則收益和類擴張代價，理解它與抽象工廠模式的銜接關係。
</LearningGoal>

## Lesson

工廠方法模式帶來三個核心收益。**避免創建者與具體產品邏輯耦合**：調用方只依賴 ICommodity 接口和 StoreFactory，不依賴任何具體的實現類，要換發放邏輯只需換實現類。**滿足單一職責原則**：每個實現類只管自己的業務邏輯，修改某種商品不會影響其他商品。**滿足開閉原則（Open-Closed Principle）**：新增一種商品只需要加一個實現類和工廠裡的一行分發，不動接口、不動已有實現、不動調用方——對擴展開放，對修改關閉。

代價是**類數量膨脹**。每新增一種商品就要新增一個實現類，三種商品是三個類，十種就是十個——有人稱之為「類爆炸」（Class Explosion）。大型電商平台可能有幾十種虛擬商品，每種的業務邏輯複雜度不同，維護成本隨類數量線性增長。緩解方式包括用工廠內部的 Map 配置或 Spring 的 `@Autowired Map<String, ICommodity>` 自動注入替代手動 ifelse（不減少實現類數量但讓工廠更乾淨），以及結合抽象工廠（Abstract Factory）或建造者模式（Builder）處理更複雜的場景。

抽象工廠是工廠方法的「升級版」：工廠方法是「一個工廠生產一種產品」，抽象工廠是「一個工廠生產一族產品」。假設未來不僅要發獎還要退款，每種商品既有發放邏輯又有退款邏輯，抽象工廠的做法是讓一個「商品工廠」接口同時定義發放和退款服務，優惠券工廠同時返回兩者。工廠方法是創建型模式的起點，理解了它的意圖和代價，才能在場景複雜時判斷什麼時候繼續用工廠方法，什麼時候升級到抽象工廠。
