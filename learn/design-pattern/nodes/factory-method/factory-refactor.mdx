# 工廠方法模式重構發獎代碼

<LearningGoal>
能用統一的 ICommodity 接口 + 三種實現類 + StoreFactory 工廠，替代發散的 ifelse 發獎分支，說清每一層的職責。
</LearningGoal>

## Lesson

重構的第一步是統一接口。定義 `ICommodity`，所有商品都實現它：方法名統一為 `sendCommodity`，入參統一為用戶 ID、商品 ID、業務 ID、擴展字段（`Map<String, String> extMap`），返回值統一為 void，異常直接拋出讓調用方統一處理。實物商品的收貨地址放在 extMap 裡傳入，不再需要為它單獨加參數。接口統一之後，調用方不需要知道具體是哪種商品——只要拿到一個 ICommodity 實例，就能用同樣的方式調用。

第二步是各管各的實現類。三種商品各自實現 `ICommodity`：`CouponCommodityService` 調用優惠券接口並判斷返回碼；`GoodsCommodityService` 拼裝 `DeliverReq` 調用實物發放接口；`CardCommodityService` 查手機號後調用第三方兌換接口。每個實現類只處理自己的業務邏輯，互不干擾。新增商品只需要加一個新的實現類，不動任何已有代碼。

第三步是工廠類 `StoreFactory`，按 `commodityType` 返回對應的 ICommodity 實例。ifelse 沒有消失，但它從調用方收斂到了工廠這一個地方。調用方的代碼變成兩行：拿到服務、調用發放。不需要知道具體是哪種商品，不需要拼裝不同的參數，不需要判斷返回值類型。對比 ifelse 版本，新增商品從「改 Controller 加分支」變成「加工廠一行 + 加實現類」，修改某種商品從「在大方法裡找分支」變成「只改對應的實現類」，單測從「三種邏輯耦合無法獨立測」變成「每個實現類可以獨立單測」。
