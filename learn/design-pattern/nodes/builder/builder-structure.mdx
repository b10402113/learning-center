# 建造者模式的三層結構

<LearningGoal>
掌握建造者模式的三層結構——IMenu 接口定義填充契約、DecorationPackageMenu 承載物料與價格計算、Builder 集中建造過程。
</LearningGoal>

## Lesson

ifelse 版本的問題在於「一個方法幹三件事」。建造者模式的重構思路是把這三件事拆到三個角色：IMenu 接口定義填充契約（能往套餐裡加什麼物料），DecorationPackageMenu 承載物料清單和價格計算（隱藏計算細節），Builder 集中所有套餐的建造過程（新增套餐只需加方法）。

IMenu 接口聲明了四個 append 方法——appendCeiling、appendCoat、appendFloor、appendTile——以及一個 getDetail 方法。每個 append 方法返回 IMenu 本身，這是為了支持鏈式調用：menu.appendCeiling(ceiling).appendCoat(coat).appendFloor(floor).getDetail()。接口把「逐項填充物料」和「輸出明細」抽象為統一契約，具體怎麼算價格、怎麼拼清單，接口不關心——這就是「構建與表示分離」的體現。

DecorationPackageMenu 實現 IMenu，持有裝修清單（list）和價格（price），構造函數接收面積和套餐等級。每個 append 方法做兩件事：把物料加入清單，按面積係數累加價格——吊頂 ×0.2、塗料 ×1.4、地板和地磚 ×面積。每個方法都返回 this，實現鏈式調用。getDetail() 拼接完整的裝修清單文本。

Builder 是整個模式的收口。它有三個方法：levelOne（豪華歐式：二級頂+多樂士+聖象）、levelTwo（輕奢田園：二級頂+立邦+馬可波羅）、levelThree（現代簡約：一級頂+立邦+東鵬）。每個方法的結構一模一樣：new 裝修包→按順序 append 物料。差別只在於選了哪些具體物料。新增套餐只需加一個方法，指定新的物料組合，不用動 IMenu，不用動 DecorationPackageMenu。

調用方式從 ifelse 版的「傳入 level=1 然後自己處理」變成「builder.levelOne(132.52D).getDetail()」——一步到位，建造加獲取明細。語義從「按數字選套餐」變成「按名字鏈式組裝」，可讀性大幅提升。測試驗證三檔套餐的報價在兩個版本中完全一致：198,064.39、119,865.00、90,897.52 元。模式重構保持行為等價，但代碼結構和擴展性質的改變。
