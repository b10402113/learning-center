# 建造者模式的意圖與場景

<LearningGoal>
理解建造者模式「將複雜對象的構建與其表示分離」的意圖，並用裝修套餐場景建立學習動機。
</LearningGoal>

## Lesson

想像你開了一家裝修公司。手上有四種物料——吊頂、塗料、地板、地磚——每種都有不同品牌檔位。吊頂有一級頂（260 元）和二級頂（850 元），塗料有多樂士（719 元）和立邦（650 元），地板有德爾（119 元）和聖象（318 元），地磚有東鵬（102 元）和馬可波羅（140 元）。老闆說要推出三種套餐：豪華歐式、輕奢田園、現代簡約，每種用不同品牌組合，按裝修面積報價。

這三種套餐本質上是同一套物料的不同組合方式。你有一個複雜的構建過程（選料、組合、算價格），最終產出不同的結果（三種套餐報價單）。這正是建造者模式要解決的問題。

**建造者模式（Builder Pattern）** 的核心意圖是：將複雜對象的構建過程與其表示分離，使得同樣的構建過程可以創建不同的表示。拆開來看，「構建過程」是選吊頂→選塗料→選地板→選地磚→計算價格，這個步驟順序是固定的；「不同表示」是豪華歐式用二級頂+多樂士+聖象，田園用二級頂+立邦+馬可波羅，簡約用一級頂+立邦+東鵬。關鍵洞察在於：步驟相同，物料不同，結果就不同。

生活類比：玩「王者榮耀」時，遊戲啟動伺服器需要按地圖模式反覆組裝場景——三條路、樹木、野怪、守衛塔。同樣的組件，按不同網絡情況和遊戲模式組裝出不同的戰場。這就是建造者模式的思路：相同的簡單對象，一步步組裝出複雜的場景。

如果只有「豪華歐式」一種套餐，你可能直接寫一個方法就完事了。但三種、十種套餐意味著每個套餐一份完整代碼，改一個物料計算方式要改十個地方。建造者模式的價值在於把「組裝動作」從「物料選擇」中抽離出來，讓你改一個地方就能影響所有套餐。

建造者模式適合的場景有兩個特徵：一是構建過程複雜，不是一個構造函數能搞定的，需要多個步驟；二是組合方式多變，同一套物料不同組合產出不同結果。裝修套餐完美符合這兩個條件。
