# 桥接与组合

## Learning goal

能把嵌套 ifelse 的"双维度"组合拆成桥接；能用树结构组织部分-整体关系。

## Steps

1. [[learn/design-pattern/nodes/bridge-composite/bridge-vs-composite-overview|双维度组合 vs 部分-整体树：桥接与组合的结构问题]] — 识别"笛卡尔积爆炸"和"层级递归"两种嵌套 ifelse 形态
2. [[learn/design-pattern/nodes/bridge-composite/bridge-pattern|桥接模式：用组合拆掉双维度的笛卡尔积 ifelse]] — 用支付聚合场景实现桥接（after step 1）
3. [[learn/design-pattern/nodes/bridge-composite/composite-pattern|组合模式：用递归树结构替代深层 ifelse 嵌套]] — 用营销决策树场景实现组合（after step 1）
4. [[learn/design-pattern/nodes/bridge-composite/bridge-vs-composite-comparison|桥接还是组合：拆双维度还是建树]] — 对比两种模式的适用边界（after steps 2–3）

## Lesson

本节处理的是开发中两种典型的"嵌套 ifelse 不可维护"的结构问题。第一种是**双维度组合**——当两个独立维度（如支付渠道 × 支付方式）交叉时，ifelse 会变成笛卡尔积矩阵，每新增一个维度值就膨胀一层；桥接模式用"抽象持有实现引用"的组合方式拆掉这个矩阵。第二种是**层级递归**——当条件判断本身形成树形结构（如优惠券决策引擎的多级过滤），ifelse 嵌套越来越深；组合模式用叶子/组合节点统一接口的递归树替代。两个模式都是结构型，都用组合替代继承来降低复杂度，但拆解的结构形态完全不同。
