# 外觀模式

## Learning goal

講清外觀「複雜子系統統一門面」的意圖，用白名單中間件場景

## Steps

1. [[learn/design-pattern/nodes/facade/facade-intro|外觀模式的意圖與白名單痛點]] — 從白名單 ifelse 爆炸說出外觀模式的意圖
2. [[learn/design-pattern/nodes/facade/facade-refactor|用門面中間件重構白名單]] — Starter + AOP + 自定義注解統一治理（after step 1）
3. [[learn/design-pattern/nodes/facade/facade-tradeoffs|外觀模式的適用邊界與取捨]] — 何時用、何時不該用、與相似模式的區別（after step 2）

## Lesson

外觀模式的核心問題是「調用方不想知道子系統的複雜細節，只想用一個簡單的入口」。白名單過濾就是最直觀的例子：每個接口都要加白名單邏輯，如果直接在每個方法裡塞 ifelse，改一個地方就要改一百個地方。外觀模式在調用方與子系統之間加一個統一的包裝層，把複雜邏輯收進中間件——業務接口零改動，只加一個注解就被治理。三步走完之後，你應該能用這個模式把自己的重複邏輯收進中間件，也能分辨它和中介者、適配器的結構差異。
