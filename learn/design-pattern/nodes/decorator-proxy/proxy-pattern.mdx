# 代理模式的本质与 JDK 动态代理

## Learning goal

能用 JDK 动态代理实现一个无实现类的 DAO bean，说清 InvocationHandler 的分发原理。

## Lesson

代理模式的动机是控制访问——在调用方和真实对象之间加一个中间层，屏蔽访问细节。MyBatis 的 Mapper 接口没有实现类却能直接用，靠的就是 JDK 动态代理在运行时生成代理类。

JDK 动态代理三要素：Proxy.newProxyInstance 生成代理对象（传入 ClassLoader、接口数组、InvocationHandler）；InvocationHandler 是分发中心，每次调用代理方法都走到 invoke(proxy, method, args)；method 参数是被调用的方法，可以读取 @Select 等注解来决定行为。调用方完全无感——拿到的是实现了接口的代理对象，调用方法跟调普通对象一样。

Spring 把代理注册为 bean 的机制：MapperFactoryBean 实现 FactoryBean 接口，getObject() 里调用 Proxy.newProxyInstance 创建代理对象；BeanDefinitionRegistryPostProcessor 在启动时手动注册 bean 定义，指定接口类和工厂 bean。代理在中间件中非常常见——MyBatis DAO、Spring AOP、RPC 框架、连接池、延迟加载都是代理的应用场景。
