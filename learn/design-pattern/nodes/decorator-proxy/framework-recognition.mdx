# 框架里的装饰与代理

## Learning goal

能认出 Spring、MyBatis、JDK I/O 里的装饰器和代理结构，并说明它们解决了什么问题。

## Lesson

JDK I/O 流是最经典的装饰器——BufferedReader(new FileReader(...)) 用构造函数注入 FileReader，在 read() 调用上加缓冲功能。Component 是 Reader/InputStream 接口，ConcreteComponent 是 FileReader/FileInputStream，Decorator 是 BufferedReader/InputStreamReader。I/O 需要灵活组合功能（缓冲+编码转换+行读取），继承会爆炸，装饰器让你像搭积木一样组合。

MyBatis Mapper 是 JDK 动态代理的典型应用——定义接口加 @Select 注解没有实现类，MapperFactoryBean.getObject() 调用 Proxy.newProxyInstance 生成代理对象，InvocationHandler 读取注解里的 SQL 并执行。Spring AOP 也是代理——为被切面覆盖的 Bean 生成代理对象（JDK 动态代理或 CGLIB），每次调用方法都经过 AOP 切面链。Spring Security FilterChain 是装饰器/责任链风格——每个 OncePerRequestFilter 在转发前后加认证、授权、CSRF 检查等逻辑。

识别技巧：看到 new A(new B(...)) 套娃想装饰器，看到接口没有实现类想 JDK 动态代理，看到 @Aspect 想代理，看到 FactoryBean getObject() 想可能是代理。框架是模式的容器，认出这些结构，读源码就不再是看天书。
