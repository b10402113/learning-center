# 装饰器模式的本质与结构

## Learning goal

能说清装饰器模式的四个角色，以及"构造函数注入 + 接口转发"的包裹机制。

## Lesson

装饰器模式的核心是"包一层再转发"——不修改原始类，通过构造函数注入被装饰对象，在接口转发前后加上新功能。

四个角色各司其职。Component 定义统一接口，所有角色都实现它。ConcreteComponent 是被装饰的原始对象（比如 SsoInterceptor）。Decorator 是抽象装饰器，构造函数接收一个 Component 实例，调用时转发给它。ConcreteDecorator 继承 Decorator，在转发前后加自己的逻辑——比如 LoginSsoDecorator 在登录检查通过后加上方法级权限控制。

核心机制只有两步：构造函数注入 + 接口转发。Decorator 持有 wrapped 对象引用，调用时 `wrapped.preHandle(...)` 转发给原始对象。ConcreteDecorator 重写这个方法，在转发前或后加上扩展逻辑。多个装饰器可以像套娃一样层层包裹：`new BufferedReader(new FileReader(...))` 就是 JDK I/O 里最经典的装饰器——BufferedReader 给 FileReader 加了缓冲功能，FileReader 是 ConcreteComponent，BufferedReader 是 ConcreteDecorator。调用方感知不到区别，因为它们实现同一个接口。
