# 装饰器 vs 代理：什么时候用哪个

## Learning goal

能从动机、意图、实现三方面区分装饰器和代理，并判断框架里的包裹结构属于哪一类。

## Lesson

装饰器和代理的代码结构几乎一样——都是构造函数注入 + 接口转发。但动机完全不同：装饰器的动机是加功能（给对象增加新能力），代理的动机是控制访问（在调用方和真实对象之间加中间层屏蔽细节）。

判断框架里的包裹结构属于哪一类，看三个问题。动机是什么——加功能（缓冲、加密、权限增强）是装饰器，控访问（权限检查、日志审计、远程调用）是代理。调用方知不知道中间层——不知道是装饰器，可能知道是代理。会不会多层嵌套——会的是装饰器（像 JDK I/O 套娃），通常只有一层的是代理。灰色地带看主要动机：加功能归装饰器，控访问归代理。

JDK I/O 的 BufferedReader 装饰 FileReader 是装饰器（加缓冲功能），MyBatis Mapper bean 是代理（控制数据库访问），Spring AOP 是代理（控制方法调用织入切面），LoginSsoDecorator 是装饰器（加方法级权限功能）。
