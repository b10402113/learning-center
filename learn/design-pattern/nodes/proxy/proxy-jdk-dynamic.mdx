# JDK 動態代理：無實現類也能調用

<LearningGoal>
理解 JDK 動態代理機制（InvocationHandler + Proxy.newProxyInstance），看懂 MyBatis 為什麼「只定義接口、不寫實現類」就能跑。
</LearningGoal>

## Lesson

MyBatis mapper 接口沒有實現類卻能調用，但 Java 是一門強類型語言——你調用一個方法，JVM 必須找到一個具體的類來執行方法體。接口 <code>IUserDao</code> 只有方法簽名，JVM 是怎麼找到「<code>queryUserInfo</code> 該幹嘛」的？答案就是 JDK 動態代理：在運行時為一個接口生成一個實現類——你不需要手寫這個實現類，JVM 幫你生成。

整個機制由兩個核心角色組成。<strong>InvocationHandler</strong> 是一個接口，你提供實現，它的職責是定義「方法被調用時幹嘛」——攔截所有方法調用，決定返回什麼。<strong>Proxy.newProxyInstance()</strong> 是 JDK 提供的靜態工廠方法，為指定接口生成一個代理對象（實現類實例），把方法調用轉發給 InvocationHandler。一句話記：**InvocationHandler 是「攔截器」，Proxy.newProxyInstance() 是「生成器」**。

具體流程分三步。第一步是定義攔截器：在 <code>getObject()</code> 方法內部，創建一個 InvocationHandler 匿名類，定義「當有人調用 <code>queryUserInfo</code> 時，從方法的 <code>@Select</code> 注解取出 SQL，替換佔位符，打印日誌，返回模擬結果」。第二步是生成代理對象：調用 <code>Proxy.newProxyInstance(classLoader, new Class[]{mapperInterface}, handler)</code>，傳入類加載器、要代理的接口列表、以及你的攔截器，返回值就是一個 <code>IUserDao</code> 類型的代理對象。第三步是調用代理：當你調用 <code>userDao.queryUserInfo("100001")</code> 時，JVM 把調用轉發給 InvocationHandler 的 <code>invoke</code> 方法，invoke 取出注解裡的 SQL，替換參數，返回結果。

關鍵理解在於「動態」二字：傳統方式是你手寫 <code>UserDaoImpl implements IUserDao</code>，JVM 直接調用你的實現；動態代理則是你什麼都不寫，JVM 在運行時生成一個隱藏的實現類，把方法調用轉發給你的 InvocationHandler。實現類不是編譯時就存在的，而是運行時按需生成的——這也是為什麼你找不到 <code>IUserDaoImpl</code> 這個類，它根本不存在於你的源碼中。從使用者的角度，你看到的就是「接口有實現」，完全不知道背後是代理在工作。
