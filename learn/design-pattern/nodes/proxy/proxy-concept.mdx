# 什麼是代理模式？

<LearningGoal>
認識代理模式「給複雜服務提供簡單可控入口」的意圖，說出三種典型場景，並理解 MyBatis「只定義接口就能跑」背後的代理思想。
</LearningGoal>

## Lesson

你家牆壁裡埋著 220V 的電線——裸露的銅線、強電流、直接摸會觸電。但你不需要懂電路，也不需要戴絕緣手套，你只需要按一下牆上的開關，燈就亮了。這個開關就是你的「代理」。它不生產電力，不改變電路，但它讓你用最安全、最簡單的方式接入了複雜的電力系統。

代理模式（Proxy Pattern）是一種結構型設計模式。它的核心思想是：在不寫實現類的情況下，通過一個「代理人」對象來間接訪問目標服務。代理人負責處理複雜的細節，調用者只需要跟代理人打交道。用一句話記：**代理 = 給複雜服務提供簡單可控的入口**。代理人就像「老大和小弟」的關係——你找小弟辦事，小弟去對接老大的複雜服務。

這個設計思想在實際系統中有三個典型場景。第一是數據庫連接池：連接池代理管理連接的創建與回收，減少應用服務擴容時數據庫連接數暴增。第二是 RPC 框架：拿到 jar 包接口描述後，服務啟動時生成對應代理類，調用接口實際是通過代理類發送 socket 信息，Dubbo 和 gRPC 都是這個套路。第三是 MyBatis Mapper：只定義接口不寫實現類，即可對 XML 或自定義注解裡的 SQL 語句做增刪改查。這三個場景有一個共同點：服務本身很複雜（連接管理、網絡通信、SQL 執行），但代理讓使用者用最簡單的方式接入。

MyBatis 的魔法是最直觀的例子。你只定義一個 <code>IUserDao</code> 接口，上面標註 <code>@Select("select userName from user where id = #{uId}")</code>，然後從 Spring 容器裡拿到實例直接調用，它居然能正常返回結果。接口沒有實現類，<code>queryUserInfo</code> 的方法體在哪裡？答案就是代理——MyBatis 在你看不見的地方，用 JDK 動態代理為你生成了一個實現類。你拿到的 <code>IUserDao</code> 實例其實是一個代理對象。

代理模式的中間件模型可以拆成兩層：上層是中間件實現（負責生成代理類、註冊到 Spring 容器，這是框架開發者寫的），下層是功能使用（定義接口、寫注解、從容器獲取實例並調用，這是業務開發者寫的）。兩層之間的分離，正是代理模式的價值所在——業務代碼完全不需要知道代理的存在，它只看到一個「有實現的接口」。
