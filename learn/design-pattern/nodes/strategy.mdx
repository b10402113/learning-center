# 策略模式

## Learning goal

講清策略模式「算法族互換」的意圖，用優惠券計算場景拆掉 ifelse，並能說出與命令/適配器/組合的結構相似而思路不同

## Steps

1. [[learn/design-pattern/nodes/strategy/strategy-intro|策略模式的意圖與痛點]] — 從優惠券 ifelse 爆炸說出策略模式的意圖
2. [[learn/design-pattern/nodes/strategy/strategy-refactor|優惠券場景的策略模式重構]] — 接口 → 四種券實現 → Context 控制類（after step 1）
3. [[learn/design-pattern/nodes/strategy/pattern-comparison|策略 vs 命令/適配器/組合]] — 結構相似但意圖不同的具體差異（after step 2）

## Lesson

策略模式的核心問題是「同一個動作，有多種算法，未來還會加新的」。優惠券計算就是最直觀的例子：直減、滿減、折扣、n 元購四種券，如果全堆在一個 if 裡，每加一種券就要改原有方法。策略模式把每種算法封裝成獨立的類，通過統一接口讓它們可以互換——新增券型只需新增實現類，不動既有代碼。三步走完之後，你應該能用這個模式拆掉自己代碼裡的 ifelse 地獄，也能分辨它和命令、適配器、組合的結構差異。
