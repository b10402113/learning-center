# 装饰器与代理

## Learning goal

能判断什么时候用装饰器加功能、什么时候用代理控制访问，并能认出框架里的装饰/代理结构。

## Steps

1. [[learn/design-pattern/nodes/decorator-proxy/decorator-essence|装饰器模式的本质与结构]] — 能说清四个角色和构造函数注入 + 接口转发的包裹机制
2. [[learn/design-pattern/nodes/decorator-proxy/decorator-vs-inheritance|为什么不用继承而用装饰器]] — 对比继承扩展与装饰器扩展的取舍（after step 1）
3. [[learn/design-pattern/nodes/decorator-proxy/proxy-pattern|代理模式的本质与 JDK 动态代理]] — 能用 JDK 动态代理实现无实现类的 DAO bean（独立于步骤 1–2）
4. [[learn/design-pattern/nodes/decorator-proxy/decorator-vs-proxy|装饰器 vs 代理：什么时候用哪个]] — 从动机、意图、实现三方面区分二者（after steps 1 和 3）
5. [[learn/design-pattern/nodes/decorator-proxy/framework-recognition|框架里的装饰与代理]] — 认出 Spring、MyBatis、JDK I/O 里的结构（after step 4）

## Lesson

装饰器和代理长得非常像：都是"包一层再转发"。区别在动机——装饰器是为了**加功能**，代理是为了**控制访问**。这个节点先分别拆解两个模式的结构，再做对比，最后到框架源码里认出它们。
