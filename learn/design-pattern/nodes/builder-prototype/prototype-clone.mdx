# 原型模式与 clone 机制

## Learning goal

理解原型模式的动机和 Cloneable 接口的实现机制，能用 clone() 克隆模板对象避免重复构建开销。

## Lesson

### 考试试卷的重复构建问题

在线考试系统需要为每个考生生成试卷。试卷包含选择题和简答题，数据来自题库数据库。所有考生拿到的题目内容相同，但题目和选项的顺序需要打乱，防止作弊。

最直觉的做法是在 Controller 里为每个考生查一次库、组装一次试卷：

```java
// 每次调用都查库、组装 → 200 考生 = 200 次重复构建
@GetMapping("/exam/paper")
public QuestionBank generatePaper(String candidateId) {
    List<ChoiceQuestion> choiceQuestions =
        questionBankMapper.selectChoiceQuestions();
    List<AnswerQuestion> answerQuestions =
        questionBankMapper.selectAnswerQuestions();
    QuestionBank paper = new QuestionBank();
    paper.setChoiceQuestions(choiceQuestions);
    paper.setAnswerQuestions(answerQuestions);
    return paper;
}
```

问题很明显：数据库查询和对象组装对每个考生重复执行，而结果完全相同。构建开销被白白浪费了。

### Cloneable 接口与 clone() 机制

原型模式的核心思想：把一个已经构建好的对象当模板，后续用 `clone()` 快速复制，而不是重新构建。就像 Ctrl+C / Ctrl+V——你做了一份完美的试卷模板，每个考生进来 Ctrl+V 一份就行。

Java 的 `Object.clone()` 是一个 native 方法，执行的是浅拷贝（shallow copy）。`Cloneable` 是一个标记接口（marker interface），没有方法，只告诉 JVM "这个类允许被 clone"。

你需要做的：让类实现 `Cloneable`，重写 `clone()` 方法，在其中调用 `super.clone()`：

```java
public class QuestionBank implements Cloneable {

    private List<ChoiceQuestion> choiceQuestions;
    private List<AnswerQuestion> answerQuestions;

    @Override
    public QuestionBank clone() {
        try {
            return (QuestionBank) super.clone();
        } catch (CloneNotSupportedException e) {
            throw new RuntimeException(e);
        }
    }
}
```

`clone()` 做了什么？它逐字段复制原始值（int、boolean 等直接复制），引用类型只复制引用本身（不复制引用指向的对象）。不调用构造函数。

### QuestionBank 重构：模板构建一次，克隆 N 次

Controller 在启动时构建一次模板，每个考生进来只调用 `clone()` 加打乱：

```java
@RestController
public class QuestionBankController {

    @Autowired
    private QuestionBankMapper questionBankMapper;

    private QuestionBank template;

    @PostConstruct
    public void init() {
        List<ChoiceQuestion> choices =
            questionBankMapper.selectChoiceQuestions();
        List<AnswerQuestion> answers =
            questionBankMapper.selectAnswerQuestions();
        template = new QuestionBank();
        template.setChoiceQuestions(choices);
        template.setAnswerQuestions(answers);
    }

    @GetMapping("/exam/paper")
    public QuestionBank generatePaper(String candidateId) {
        QuestionBank paper = template.clone();
        TopicRandomUtil.randomChoiceQuestions(paper.getChoiceQuestions());
        TopicRandomUtil.randomChoiceItems(paper.getChoiceQuestions());
        TopicRandomUtil.randomAnswerQuestions(paper.getAnswerQuestions());
        return paper;
    }
}
```

数据库查询只执行一次，每个考生进来只调用 `clone()` 加 shuffle。构建开销从 O(N) 次数据库查询降到 O(1) 次构建加 O(N) 次克隆。

### TopicRandomUtil 的打乱职责

`clone()` 出来的试卷和模板内容完全一样。打乱逻辑封装在 `TopicRandomUtil` 中，负责三件事：打乱选择题顺序、打乱每道选择题的选项顺序、打乱简答题顺序。每次 `clone()` 后调用，保证每个考生拿到的是同一套题但顺序不同。

注意：这里有个浅拷贝的陷阱——如果 `clone()` 只做了 `super.clone()` 而没有深拷贝内部的 List，克隆体和模板共享同一个 List，对克隆体 shuffle 会把模板也打乱了。深拷贝的处理细节在下一步详细讲解。

### 什么时候用原型，什么时候用 Builder 或工厂

| 场景 | 首选模式 | 原因 |
|---|---|---|
| 对象构建步骤固定，参数组合多 | Builder | 流式 API 逐步设置，可读性好 |
| 每次构建需要查库/RPC，开销大 | Prototype | 构建一次，克隆 N 次 |
| 根据类型创建不同实现类 | 工厂方法 | 封装创建逻辑，屏蔽具体类型 |

Prototype 的典型场景：在线考试和测评（构建开销大、内容相同、顺序打乱）、游戏技能模板（一套定义、多个实例各自独立冷却）、文档和报表模板（格式复杂、构建慢、克隆后填充不同数据）。

### 不要过度使用

Prototype 的适用面相对窄——只有当"构建成本高且多次构建结果相同"时才有明显优势。判断标准：构建过程确实慢（涉及 I/O、数据库、复杂计算）时考虑 Prototype；构建过程很快（纯内存操作）时用 Builder 或工厂方法就好；克隆后需要大量修改时构建可能更清晰。
