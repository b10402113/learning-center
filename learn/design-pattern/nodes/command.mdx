# 命令模式

## Learning goal

講清命令模式「請求封裝成對象、解耦請求與實現」的意圖，用點單→烹飪場景

## Steps

1. [[learn/design-pattern/nodes/command/command-concept|命令模式的意圖與角色映射]] — 說清「請求封裝成對象」的意圖，用「顧客→小二→廚師」映射三層結構
2. [[learn/design-pattern/nodes/command/command-monolith|一把梭實現：ifelse 的痛點]] — 用單類 if 實現點單系統，理解耦合問題（after step 1）
3. [[learn/design-pattern/nodes/command/command-refactor|三層重構：命令、實現者、調用者]] — 落地五要素代碼，用測試印證解耦收益（after step 2）

## Lesson

命令模式的核心問題是：**調用方不想知道「誰來做、怎麼做」，只想發出一個請求**。日常的 Ctrl+C / Ctrl+V、桌面應用的菜單按鈕，本質都是把「用戶的意圖」封裝成一個對象，交給後端去執行——調用者和實現者之間完全解耦。

這個節點用高級餐廳的點餐場景來講：顧客下單（發出請求）、小二記錄並轉交（調用者）、廚師烹飪（實現者）。三步走完之後，你能說清楚命令模式的三層各自做什麼、代碼怎麼落地、以及什麼時候該用它——包括它的代價。
