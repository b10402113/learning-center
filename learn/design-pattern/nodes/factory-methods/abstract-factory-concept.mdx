# 抽象工厂——从单产品到产品族

<LearningGoal>
认识抽象工厂——从单产品升级到产品族（多接口、多实现），用 Redis 集群升级的场景理解"工厂的工厂"解决什么问题。
</LearningGoal>

## Lesson

工厂方法解决的是"一类东西有多个品种"，但现实中有另一类问题：你需要替换的不是一种东西，而是一整套东西。比如把单机 Redis 切换到集群 Redis——EGM 集群的方法叫 `gain()`，IIR 集群的方法叫 `get()`，方法名都不一样，但做的事情一样：读写缓存。面对的不是一种产品，而是一组相关的接口（get/set/del/expire），它们各自有不同的实现。

ifelse 升级版是给每个 CacheService 方法加 `redisType` 参数，每个方法内部做 ifelse 分支。问题在于每个方法都膨胀了，更严重的是所有调用方都要额外传 `redisType` 参数，污染扩散到整个系统。抽象工厂的思路是定义适配器接口 `ICacheAdapter`（统一 get/set/setEx/del 方法名），每个集群各自实现适配器（EGM 把 `gain` 映射到 `get`），然后用 JDK 动态代理把调用路由过去。`CacheServiceImpl` 完全不需要修改——代理自动路由到对应的集群适配器。

这叫"工厂的工厂"：工厂方法创建的是产品（一个接口的多个实现），抽象工厂创建的是代理对象——你传入不同的 `ICacheAdapter`，JDKProxy 就给你一个能路由到对应集群的代理。核心价值是不修改现有代码就能切换底层实现，体现了依赖倒置和开闭原则。已有代码零修改，这是抽象工厂最大的卖点。
