# 单例模式

## Learning goal

能写出线程安全的单例，并能对比 7 种实现的取舍、说出每种该什么时候用

## Steps

1. [[learn/design-pattern/nodes/singleton/problem-and-motivation|单例模式的动机]] — 理解单例解决什么问题、多线程下"只要一个实例"为什么这么难
2. [[learn/design-pattern/nodes/singleton/simple-variants|四种基础单例实现]] — 静态类、懒汉、synchronized、饿汉的代码结构与致命缺陷（与 step 1 并行）
3. [[learn/design-pattern/nodes/singleton/advanced-thread-safe|三种进阶线程安全方案]] — Holder 模式、DCL、CAS 的原理与取舍（after step 2）
4. [[learn/design-pattern/nodes/singleton/enum-singleton-and-decision|枚举单例与七种实现的选择]] — Effective Java 枚举方案 + 决策树选型（after step 3）

## Lesson

单例模式解决的是一个朴素的问题：有些对象在整个应用生命周期里只需要一个实例——数据库连接池、Spring 容器里的 Bean、全局配置持有者。问题不在于"怎么 new 一次"，而在于多线程环境下怎么**保证只 new 了一次**，同时还要兼顾懒加载（用的时候才创建）和性能（不能每次都加锁）。本节点带你走完 7 种实现从最朴素到最优的演进路径，最终你会知道：什么场景用哪种、为什么 Effective Java 推荐枚举、以及什么时候其实不需要单例。
