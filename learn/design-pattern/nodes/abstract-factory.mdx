# 抽象工廠模式

## Learning goal

講清抽象工廠「產品族接口統一」的意圖，用 Redis 雙集群平滑升級場景

## Steps

1. [[learn/design-pattern/nodes/abstract-factory/abstract-factory-intro|抽象工廠是什麼？]] — 說清「創建工廠的工廠」概念，區別於工廠方法
2. [[learn/design-pattern/nodes/abstract-factory/abstract-factory-scenario|Redis 雙集群升級場景]] — 理解業務場景與 ifelse 壞味道痛點（after step 1）
3. [[learn/design-pattern/nodes/abstract-factory/abstract-factory-refactor|適配介面 + 動態代理重構]] — 看懂 ICacheAdapter + JDKProxy 重構方案（after step 2）
4. [[learn/design-pattern/nodes/abstract-factory/abstract-factory-summary|評估與選型]] — 說出設計原則、代價與選型邊界（after step 3）

## Lesson

抽象工廠模式解決的核心問題是：當一個「產品族」（例如 Redis 集群、作業系統、支付渠道）存在多套實現時，如何讓業務代碼不被 ifelse 綁死，而是透過統一介面按需切換。它本質上是「創建工廠的工廠」——不是直接 new 一個產品，而是決定要拿哪一族的產品工廠，再從那個工廠取得產品。

本節以 Redis 單機升級為雙集群為切入點：EGM 和 IIR 兩套集群方法名各異，業務系統必須同時兼容、平滑過渡。先看「類型欄位 + ifelse」的壞味道實現，再用適配介面 + JDK 動態代理重構，讓原類零修改即可接入新集群。最後收斂到設計原則與選型邊界。
