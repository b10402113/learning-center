# 工廠方法模式

## Learning goal

講清工廠方法「統一創建入口、屏蔽實現」的意圖，用發獎多商品場景拆 ifelse

## Steps

1. [[learn/design-pattern/nodes/factory-method/bad-smell-ifelse|發獎場景的 ifelse 壞味道]] — 從三種異構商品接口的 ifelse 一把梭說出為什麼需要工廠方法
2. [[learn/design-pattern/nodes/factory-method/factory-refactor|工廠方法模式重構發獎代碼]] — 統一 ICommodity 接口 + 三實現 + StoreFactory（after step 1）
3. [[learn/design-pattern/nodes/factory-method/tradeoffs|工廠方法的收益與類爆炸風險]] — 開閉原則收益、類擴張代價、與抽象工廠的銜接（after step 2）

## Lesson

發獎場景把三種完全不同的商品接口（優惠券、實物商品、第三方兌換卡）塞進同一個 if 裡，每加一種新商品就要改已有代碼——這是典型的「發散分支」壞味道。工廠方法模式的解法是：抽出一個統一接口 `ICommodity`，讓每種商品各自實現，再用 `StoreFactory` 按類型分發實例。新增商品只需加一個實現類和一行工廠分支，不動任何已有代碼。

三步走完之後，你應該能用這個模式拆掉自己代碼裡的 ifelse 地獄，也能說出它的收益（開閉原則、單一職責）和代價（類數量隨商品類型膨脹），以及它和抽象工廠模式之間的銜接關係。
