# 訪問者模式

## Learning goal

講清訪問者「數據結構與操作分離、雙分派」的意圖，用校長/家長視角場景，並說出為何它較「燒腦」且可能違反迪米特。

## Steps

1. [[learn/design-pattern/nodes/visitor/visitor-intent|訪問者模式的意圖：穩定結構 + 易變訪問]] — 穩定數據結構 + 易變訪問邏輯的解耦需求
2. [[learn/design-pattern/nodes/visitor/visitor-dispatch|雙分派機制：visitor.visit(this) 怎麼運作]] — 拆解雙分派的兩次分派過程（after step 1）
3. [[learn/design-pattern/nodes/visitor/visitor-implementation|校園場景完整實現：五類走通]] — User/Student/Teacher + Visitor/Principal/Parent + DataView 完整走通（after step 2）
4. [[learn/design-pattern/nodes/visitor/visitor-tradeoffs|訪問者模式的優缺點與適用邊界]] — 解耦收益 vs 複雜度成本與迪米特衝突（after step 3）

## Lesson

訪問者模式解決的是「同一份穩定數據，多個不同視角去訪問」的問題。當數據結構（比如學生、老師的基本信息）不太會變，但不同角色（家長、校長）想從中提取的字段組合完全不同時，把訪問邏輯塞進數據類本身會導致類不斷膨脹。訪問者模式把「數據結構」和「對數據的操作」拆到兩個獨立的繼承體系裡，讓操作可以自由擴展而不動數據類。代價是結構較複雜，且因為數據類要暴露 `accept` 方法給訪問者，違反了迪米特原則（最少知道原則）。
