# 組合模式的四角色與引擎遍歷

## Learning goal
掌握節點、鏈路、果實、過濾器四個角色如何協作，以及引擎從根到果實的遍歷流程。

## Lesson

上一節看到 ifelse 直寫的擴展性災難，組合模式的解法是把判斷邏輯拆成獨立節點、按樹形結構組織。但「組合成樹」聽起來很抽象，這節拆解出四個具體角色。

**樹節點（TreeNode）**是樹的基本單位，用 `nodeType` 區分兩種身份：`nodeType=1` 是子葉（需要繼續判斷，比如「性別判斷」「年齡判斷」），`nodeType=2` 是果實（最終結果，比如「發券結果 A/B/C/D」）。**節點鏈路（TreeNodeLink）**是連接兩個節點的邊，定義「從節點 A 到節點 B 的條件」——比如「性別=男 → 走左邊到年齡判斷」。**過濾器（LogicFilter）**實現具體的判斷邏輯，接口定義 `filter`（做判斷）和 `matterValue`（取決策值），`UserGenderFilter` 取性別、`UserAgeFilter` 取年齡，各自實現比對邏輯。**引擎（Engine）**是統一入口，從樹根出發，循環遍歷子葉節點直到落到果實。

抽象類 `BaseLogic` 實現了通用判斷方法，支持五種規則類型：等於（1）、大於（2）、小於（3）、小於等於（4）、大於等於（5）。`filter` 方法的邏輯很簡單：取出用戶的決策值，和鏈路上的 `ruleLimitValue` 比較，匹配就返回下一個子節點的 ID，不匹配就返回 -1。

引擎的核心方法 `engineDecisionMaker` 用 while 循環從根走到果實：取出對應的過濾器 → 取值判斷 → 移動到子節點 → 重複直到 nodeType=2。日誌逐節點打印「treeNode：11 ruleKey：userGender」，讓你看到完整決策路徑。一個關鍵設計：`EngineConfig` 用 map 靜態註冊過濾器，這個 map 完全可以抽到資料庫——新增維度只需加過濾器不改引擎，不同場景用不同 `treeId` 指向不同樹，引擎代碼完全不變。
