# 責任鏈骨架：抽象類 + next 指針

## Learning goal

掌握責任鏈「統一抽象類 + next 指針 + appendNext 鏈式編排 + 抽象 doAuth」的核心結構。

## Lesson

上一步我們看到了 if-else 審批流的痛點：所有邏輯堆在一個方法裡。責任鏈的重構思路很直接——**把每個審批級別變成一個獨立的類，它們通過一個 next 指針串成一條鏈**。核心機制有三個零件：**抽象類 AuthLink** 統一所有審批節點的接口，持有 next 指針並聲明抽象 doAuth；**next 指針** 指向鏈上的下一個節點，next == null 表示鏈尾；**appendNext()** 追加下一個節點並返回 this，支持鏈式編排。

抽象類 AuthLink 的設計值得注意：next 是 private，外部不能直接修改鏈結構，只能通過 appendNext 操作；appendNext 返回 this，讓你可以寫出 a.appendNext(b).appendNext(c) 這樣的鏈式調用，把編排過程壓縮成一行；doAuth 是抽象方法，每個審批級別自己決定「怎麼審」，抽象類只管「怎麼傳」。每個實現類（Level1AuthLink、Level2AuthLink、Level3AuthLink）繼承 AuthLink 並實現 doAuth，做三件事：**判斷時間範圍**（該不該由我審）、**查自身審核狀態**（審了沒有）、**決定傳遞**（已審就傳給 next，未審就返回待審）。時間範圍為何能動態決定鏈的長度？因為不在範圍內的節點直接跳過，請求跳到下一個——鏈的「有效長度」隨時間自動變化。

實際組裝時，通過鏈式調用把三個節點串起來：new Level3AuthLink("1000013","王工").appendNext(new Level2AuthLink("1000012","張經理", beginDate, endDate).appendNext(new Level1AuthLink("1000011","段總")))。三級在鏈首，一級在鏈尾，請求從三級開始依次傳遞。JUnit 測試驗證：鏈式構造後執行 doAuth，日誌逐級返回「待三級/二級/一級審批負責人」，最終輸出「一級審批完成…審批人：段總」。對比 ifelse 版，代碼結構變得清晰乾淨，每個模塊的職責明確，擴展時只需加一個新類。
