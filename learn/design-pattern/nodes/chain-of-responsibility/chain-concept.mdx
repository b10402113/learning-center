# 什麼是責任鏈？

## Learning goal

建立責任鏈「逐節點傳遞、先判後傳」的心智模型，能用自己的話解釋請求如何沿鏈流轉。

## Lesson

想像你在公司提了一筆報銷：10 塊錢的午餐發票，直接找你的審批人簽字就過了。但如果是 100 塊錢的會議室預訂費，審批人簽完還得交給上一級再批一次。如果是 1000 塊錢的團隊旅遊預算，上一級批完還得找老闆。你不需要知道「誰在什麼金額範圍內要找誰」——你只需要把發票遞出去，它會自動沿著一條鏈往下走，直到某個人簽了字。

**責任鏈模式**（Chain of Responsibility Pattern）是一種行為型設計模式，它把請求的發送者和接收者解耦：多個處理對象形成一條鏈，每個對象依次嘗試處理請求，處理不了就傳給下一個。請求沿著鏈流轉，直到某個節點處理它，或者到達鏈尾無人處理。經典比喻是「擊鼓傳雷」：一群人圍坐傳遞一顆點燃的炸彈，鼓聲停的時候，炸彈在誰手上誰就「爆」——也就是處理這個請求。如果鼓聲沒停（當前節點不處理），就把炸彈傳給下一個人。

關鍵詞拆解：**鏈（Chain）** 是多個處理節點串成的線性結構；**節點（Handler）** 是鏈上的每個處理者，知道自己能處理什麼、不能處理什麼；**傳遞（Forwarding）** 是不處理時請求自動傳給下一個節點；**動態編排** 是鏈的順序和長度可以在運行時決定，不需要改動每個節點的代碼。你可能想：「這不就是 if-else 嗎？」從結果上看，if-else 也能實現「A 不行找 B，B 不行找 C」。但它們有一個根本區別：if-else 把所有判斷邏輯集中在一個地方，新加一個人就要改那個方法；責任鏈把每個處理者變成獨立的類，新加一個人就加一個類，原有代碼不動。這個區別在「一個人、兩個人」的時候不明顯，但當審批流要從三級變成五級，或者要根據時間段動態決定「要不要加審批人」，if-else 的痛苦就開始指數級放大。

一旦你注意到這個結構，會發現它無處不在：.servlet Filter 鏈讓每個 Filter 決定要不要處理請求；Spring Interceptor 的 preHandle 返回 true 繼續、false 就攔截；DOM 事件冒泡讓點擊子元素的事件沿著 DOM 樹向上传遞；信用卡審批從網點到區域到總行，每級有權限上限。這些場景的共同點是：一個請求需要經過多個處理節點，每個節點有「處理或跳過」的選擇權。
