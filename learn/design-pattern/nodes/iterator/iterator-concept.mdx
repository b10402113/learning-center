# 迭代器的意圖與常見誤解

## Learning goal

說清迭代器模式「統一方式遍歷聚合對象、不暴露內部表示」的意圖，並糾正「增強 for 就是迭代器」的常見誤解。

## Lesson

你在 Java 裡遍歷一個 `List<String>`，只需要一個 `for` 迴圈——乾淨、簡潔。但如果你要遍歷的不是 List，而是一個**樹形組織架構**——每個部門有子部門，每個子部門裡有員工——你還能用同一段代碼嗎？

樹的內部是用什麼存的？數組？鏈表？兩個 Map？對調用方來說，這些統統不需要知道。迭代器模式要解決的就是這件事：**提供統一的遍歷方式，讓調用方不需要知道聚合對象的內部結構**。

迭代器模式（Iterator Pattern）的核心意圖用一句話說：提供一種方法順序訪問一個聚合對象中的各個元素，而又不需要暴露該對象的內部表示。翻譯成白話——聚合對象是你有的一堆數據（可能是 List、Set、樹、圖、甚至文件目錄），統一方式是 `hasNext()` 加 `next()` 一套代碼走天下，不暴露內部是調用方不需要知道底層是數組、鏈表還是樹。JDK 的 `java.util.Iterator` 接口就是這個模式的標準實現，幾乎所有 Java 集合都實現了它——所以你在後端開發裡其實天天在用迭代器模式，只不過它是現成的，你不需要自己寫。

**常見誤解：增強 for ≠ 迭代器。** 很多人的第一反應是「增強 for 循環不就是迭代器嗎？」不是。增強 for 循環（enhanced for-loop）本質上只是語法糖——Java 編譯器會把它轉成普通的 indexed 迴圈或者 Iterator 調用，但增強 for 本身不暴露 Iterator 接口。你沒法在增強 for 裡調用 `remove()` 刪除當前元素，也沒法在遍歷中途跳過某個元素。一句話記法：增強 for 只能「從頭走到尾」，迭代器可以「走一步看一步、走著走著還能刪」。

| 特性 | 增強 for 循環 | 迭代器模式 |
| --- | --- | --- |
| 實現接口 | 不需要任何接口 | 實現 `Iterable` 接口 |
| 遍歷方式 | 語法糖，底層可能是 indexed 迴圈 | 通過 `next()` 逐個取出元素 |
| 刪除能力 | 不支持 | 支持 `remove()` 刪除當前元素 |

什麼時候需要自己實現迭代器？JDK 的 List、Set、Map 裡已經內建了迭代器，但如果你遇到的是業務特異性強的數據結構——比如組織架構樹、審批流程鏈、文件目錄結構——JDK 的迭代器就幫不了你了。這時候你需要定義自己的迭代器接口（參照 JDK 的 `Iterator<E>`），在你的數據結構類裡實現這個接口，讓調用方用同樣的 `while(hasNext)` 方式遍歷。
