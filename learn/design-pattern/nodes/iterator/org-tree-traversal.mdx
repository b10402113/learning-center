# 組織樹深度遍歷實現

## Learning goal

用組織樹場景實現一個深度優先迭代器，掌握 linkMap、invertedMap、cursorIdx 三者如何配合完成樹形遍歷，並能說出迭代器模式的收益與代價。

## Lesson

大部分公司的組織架構是金字塔式的樹形結構——一級部門、二級部門、三級部門，每個部門裡有員工。你需要遍歷這棵樹，把所有員工按深度優先的順序輸出來。JDK 的 List 迭代器幫不了你——這不是一個線性列表，你需要自己實現一個迭代器。

**數據怎麼存？兩張 Map。** 組織架構的本質是「節點」和「節點間的關係」。我們用 `Employee`（雇員，uId/name/desc）和 `Link`（鏈路，fromId/toId）兩個實體來表達。在 `GroupStructure` 裡，這些數據被存成兩張 Map：`linkMap` 以父節點 ID 為 key、`List<Link>` 為 value，存正向關係——從某個節點出發能找到它的所有子節點；`invertedMap` 以子節點 ID 為 key，存反向關係——從某個子節點出發能找到它的上級。為什麼要兩張 Map？因為深度優先遍歷需要回溯——走到葉子節點後要「往上找」看還有沒有兄弟節點，這時候就需要反向關係。

**深度優先遍歷的三步節奏。** DFS（Depth-First Search）的核心節奏：一路往下，從根節點開始沿著左子樹一路走到最深的葉子節點；回溯找兄弟，走到葉子後往上返回一層，看看同一層還有沒有沒走過的兄弟；重複直到走完，如果沒有兄弟了再往上返回一層，直到所有節點都被訪問。用組織架構走一遍：小傅哥（1）→ 往下走訪問花花（2）→ 往下走訪問蹦蹦（4）→ 葉子節點輸出 4 → 回溯到花花 → 還有右子樹大燒（5）→ 往下走訪問虎哥（6）→ 葉子輸出 6 → 回溯到大燒 → 訪問玲姐（7）→ 葉子輸出 7 → 回溯到大燒 → 訪問秋雅（8）→ 葉子輸出 8 → 回溯到大燒→花花→小傅哥 → 訪問右子樹豆包（3）→ 葉子輸出 3 → 結束。最終順序：2, 4, 5, 6, 7, 8, 3。

**cursorIdx：記錄每一層走到哪了。** 深度優先回溯的時候，你需要知道「這一層的子節點我走到了第幾個」。`cursorIdx` 是一個 Map，key 是父節點 ID，value 是「下一個要走的子節點索引」。每次從某個節點的子節點列表裡取下一個時把 cursor +1，回溯到父節點時看父節點的 cursor 是否還有下一個子節點。它就像你在每一個路口都放了一個小紙條：「我上次走到第幾個了」。回溯的時候撿起紙條，就知道下一步該往哪裡走。

**核心實現：iterator() 返回匿名迭代器。** `GroupStructure` 的 `iterator()` 方法返回一個匿名內部類，實現了 `Iterator<Employee>`。整個遍歷邏輯被封裝在這個匿名類裡——調用方完全不需要知道 `linkMap`、`invertedMap`、`cursorIdx` 的存在。它只需要 `while(iterator.hasNext())` 加 `iterator.next()` 就能走完整棵樹。這就是迭代器模式的精髓：遍歷邏輯和數據結構分離。數據結構管「數據怎麼存」，迭代器管「數據怎麼走」。

**收益與代價。** 迭代器模式滿足單一職責和開閉原則——調用方不需要知道任何不同數據結構在遍歷上的差異，方便擴展、讓遍歷更乾淨整潔。但代價是實現相對複雜，類的實現上擴增了需要外部定義的類，使遍歷與原數據結構分開。雖然麻煩，但使用 JDK 時迭代器模式很好用，方便擴展與升級。對新人不易理解的點包括迭代器三個接口的定義、樹形結構的數據關係、樹結構深度遍歷思路，需要反覆實現練習才能真正掌握。
