# Java 實現走讀：逐類對照四角色職責

## Learning goal

逐類走讀配置回滾的 Java 實現，把四角色從抽象概念落到真實程式碼。

## Lesson

ConfigFile 是一個純 POJO，四個欄位（versionNo、content、dateTime、operator）對應配置五要素，不知道有人在存它的狀態。ConfigMemento 的全部工作就是把 ConfigFile 包起來——建構器接收 ConfigFile，提供 getter/setter，不讀 ConfigFile 的內部欄位、不調用業務方法。你可以把它理解為一個密封的快遞盒：盒子外面看不到裡面裝了什麼，打開盒子才能看到。如果需要真正的深拷貝（Deep Copy），可以在建構器裡複製 ConfigFile 的所有欄位，這取決於你需不需要快照之間的狀態隔離。

ConfigOriginator 有兩個關鍵方法：<code>saveMemento()</code> 拿當前的 ConfigFile 建構一個新的 ConfigMemento 返回出去（返回新物件，不修改當前狀態）；<code>getMemento(memento)</code> 從 ConfigMemento 裡取出 ConfigFile，<strong>直接寫給當前的 this.configFile</strong>——不是返回新物件，而是把快照內容覆蓋到當前物件上，這就是「還原」的實現位置。ConfigOriginator 是唯一知道 ConfigFile 內部結構的角色，如果 ConfigFile 加了新欄位，只需要在這裡處理。

Admin 的設計要點：<strong>雙結構存儲</strong>——List 保序支持 undo/redo 的游標移動，Map 按版本號索引支持 O(1) 定向查詢；<strong>游標 cursorIdx</strong> 記錄當前位置，undo 前移、redo 後移，邊界保護（cursorIdx 已經是 0 時不做移動，返回第一個快照）；<strong>append 同時寫 List 和 Map</strong>。Admin 只操作 ConfigMemento，不知道 ConfigFile 長什麼樣。測試類連續保存四份配置（1000001 到 1000004），每次操作都是先從 Admin 取出快照再交給 Originator 還原：undo → 1000003、再 undo → 1000002、redo → 1000003、get("1000002") → 1000002，四次操作全部符合預期。逐類走讀的結果：ConfigFile 管狀態、ConfigMemento 管包裝、ConfigOriginator 管存取、Admin 管歷史——每個類的職責清晰、邊界明確。
