# 迭代器模式

## Learning goal

講清迭代器「統一方式遍歷聚合對象、不暴露內部表示」的意圖，用組織樹遍歷場景

## Steps

1. [[learn/design-pattern/nodes/iterator/iterator-concept|迭代器的意圖與常見誤解]] — 理解迭代器「統一遍歷、不暴露內部」的核心意圖
2. [[learn/design-pattern/nodes/iterator/three-interface-skeleton|JDK 三接口骨架]] — 掌握 Iterator / Iterable / Collection 各自職責（after step 1）
3. [[learn/design-pattern/nodes/iterator/org-tree-traversal|組織樹深度遍歷實現]] — 用組織樹場景實現深度優先迭代器（after step 2）

## Lesson

迭代器模式最常見的形態就是我們每天都在用的 JDK Iterator——用 `hasNext()` 加 `next()` 逐個取出集合元素，完全不需要知道底層是數組、鏈表還是樹。但迭代器的能力遠不止遍歷 List：任何聚合對象——樹形組織架構、圖的鄰接表、文件系統目錄——只要實現同一套接口，調用方就能用同一段 `while(hasNext)` 代碼遍歷，內部結構完全封裝在實現類裡。

三步走完，你將從「增強 for ≠ 迭代器」的糾錯開始，理解 JDK 三接口骨架，最後在組織樹場景上親手實現一個深度優先遍歷的自定義迭代器，掌握 linkMap + invertedMap + cursorIdx 的配合。
