# 橋接模式

## Learning goal

講清橋接「抽象與實現分離、多維度獨立變化」的意圖，用支付渠道×支付模式場景

## Steps

1. [[learn/design-pattern/nodes/bridge/combinatorial-explosion|笛卡爾積膨脹：ifelse 的壞味道]] — 理解多維度組合帶來的類爆炸問題
2. [[learn/design-pattern/nodes/bridge/bridge-structure|橋接模式的結構與核心機制]] — 抽象類×介面、構造注入（after step 1）
3. [[learn/design-pattern/nodes/bridge/bridge-refactor|支付場景重構實戰]] — 從 ifelse 到橋接模式的完整重構（after steps 1–2）
4. [[learn/design-pattern/nodes/bridge/bridge-tradeoffs|適用邊界與模式選型]] — 適用判據、與策略/適配器的邊界（after steps 2–3）

## Lesson

橋接模式解決的核心問題是：當一個系統存在**兩個或多個獨立變化的維度**時，如何避免笛卡爾積式的類爆炸。本節以聚合支付場景（支付渠道 × 支付模式）為例，先體會 ifelse 的壞味道，再掌握「抽象類組合介面、構造注入」的橋接寫法，最後收斂適用邊界。
