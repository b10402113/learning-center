# 工厂方法与抽象工厂

## Learning goal

能用一个创建接口把 type 分发代码重构掉；能区分"单产品工厂"和"产品族工厂"，并讲清各自的适用场景

## Steps

1. [[learn/design-pattern/nodes/factory-methods/factory-method-scenario|工厂方法要解决的问题]] — 认识按 type 分发的 ifelse 为什么越来越难维护
2. [[learn/design-pattern/nodes/factory-methods/factory-method-refactor|工厂方法的重构路径]] — 从 ifelse 分发改为"创建接口 + 子类决定实例化哪个产品"（after step 1）
3. [[learn/design-pattern/nodes/factory-methods/abstract-factory-concept|抽象工厂——从单产品到产品族]] — 用 Redis 集群升级场景理解"工厂的工厂"解决什么问题（after step 2）
4. [[learn/design-pattern/nodes/factory-methods/factory-distinction|工厂方法 vs 抽象工厂——辨析与取舍]] — 区分两种工厂的适用场景，讲清各自的取舍（after step 3）

## Lesson

工厂方法和抽象工厂都解决同一类问题：把"用哪个具体实现"的决定从调用方挪走。区别在于复杂度——工厂方法处理的是一条产品线（一类东西有多个品种），抽象工厂处理的是一个产品族（多个相关接口各自有多个实现）。掌握了这两个模式，你就拿到了把 type 分发 ifelse 重构掉的第一把钥匙。
