# 模板方法模式

## Learning goal

講清模板方法「固定骨架、子類填步驟」的意圖，用爬蟲→海報場景控制執行順序

## Steps

1. [[learn/design-pattern/nodes/template-method/template-method-intro|模板方法模式是什麼]] — 說出「固定骨架、子類填步驟」的意圖，用西游記八十一難類比記住它
2. [[learn/design-pattern/nodes/template-method/template-method-scenario|爬蟲海報場景：為什麼需要模板]] — 分析「模擬爬蟲電商→生成推廣海報」三步流程（after step 1）
3. [[learn/design-pattern/nodes/template-method/template-method-structure|抽象類與子類實現]] — 說出 NetMall 抽象類骨架與三個子類的差異實現（after step 2）
4. [[learn/design-pattern/nodes/template-method/template-method-tradeoffs|模板方法的收益與邊界]] — 評估何時用、何時不用（after step 3）

## Lesson

模板方法模式解決的問題是：當多個子類的業務流程「骨架相同、細節不同」時，把執行順序固定在父類，讓子類只關心自己的那幾步。它跟策略模式的區別在於——策略模式是「算法族互換、隨意切換」，模板方法是「執行順序釘死、子類只能填空」。本節點用「模擬爬蟲電商、生成推廣海報」的場景走完四步：先認模式、再拆場景、再看類結構、最後收邊界。
