# 中介者模式

## Learning goal

講清中介者「集中協調、解耦網狀依賴」的意圖，用手寫 ORM 的 SqlSession 場景

## Steps

1. [[learn/design-pattern/nodes/mediator/jdbc-pain|一把梭 JDBC 直連的痛點]] — 看到直接 JDBC 操作的四步流程與業務擴展時的具體痛點
2. [[learn/design-pattern/nodes/mediator/mediator-concept|中介者模式的意圖與 ORM 場景定位]] — 理解中介者「集中協調、解耦網狀依賴」的意圖（after step 1）
3. [[learn/design-pattern/nodes/mediator/mediator-components|中介者核心組件的分工與協作]] — 掌握 SqlSession / Factory / Builder / Configuration 五個組件的協作（after step 2）
4. [[learn/design-pattern/nodes/mediator/mediator-validation|驗證中介者架構的收益與設計原則]] — 用測試結果與原則總結收尾（after step 3）

## Lesson

中介者模式的核心主張：當多個對象之間的交互形成網狀依賴，每個對象都要知道其他人的接口，改一個就要改一圈——不如把協調邏輯收進一個「中介者」，讓所有人只跟中介者說話，不互相 direct call。本節用「手寫 ORM 框架模仿 Mybatis」的場景來體現這個主張：一把梭的 JDBC 直連把連接、驅動、SQL 執行、結果映射全部暴露給業務方（痛點），中介者把這些細節封裝進 SqlSession、Factory、Builder、Configuration 四層組件，外部只按「statement + 參數」調用，跟用 Mybatis 一樣簡單。四步走完之後，你應該能畫出五個組件的協作關係圖，說出中介者滿足的三個設計原則（單一職責、開閉、迪米特），以及判斷「何時該引入中介者」的判據。
