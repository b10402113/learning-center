# 适配器与外观

## Learning goal

能把不兼容的第三方接口统一成自己想要的形态；能判断该用适配器还是外观来包一层。

## Steps

1. [[learn/design-pattern/nodes/adapter-facade/adapter-facade-overview|接口不兼容的两种解法：适配器与外观]] — 识别"接口不兼容"和"调用方太复杂"两种结构问题
2. [[learn/design-pattern/nodes/adapter-facade/adapter-pattern|适配器模式：让不兼容的接口变得统一]] — 用适配器统一多个第三方接口（after step 1）
3. [[learn/design-pattern/nodes/adapter-facade/facade-pattern|外观模式：用一层门面降低调用方复杂度]] — 用外观把跨切面关注点包装成中间件（after step 1）
4. [[learn/design-pattern/nodes/adapter-facade/adapter-vs-facade|适配器还是外观：何时包接口、何时包子系统]] — 对比两种模式的适用边界（after steps 2–3）

## Lesson

本节处理的是开发中一个高频出现的结构问题：拿到的接口和自己想要的对不上。适配器和外观都是"包一层"的解法，但动机完全不同——适配器解决的是"接口不兼容"（A 的输出不是 B 能吃的格式），外观解决的是"调用方太复杂"（背后有五六个子系统，调用方不该知道这些细节）。两者的共同点是不修改原始代码，不同点是适配器翻译的是接口形态，外观简化的是调用路径。掌握这两个模式之后，面对第三方集成和中间件开发，能快速判断该包接口还是包子系统。
