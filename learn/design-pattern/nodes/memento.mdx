# 備忘錄模式

## Learning goal

講清備忘錄「狀態快照與回滾」的意圖，用配置回滾場景

## Steps

1. [[learn/design-pattern/nodes/memento/memento-intent|為什麼需要備忘錄模式？]] — 建立「保存歷史狀態、可回滾」的意圖錨點
2. [[learn/design-pattern/nodes/memento/memento-scenario|配置回滾場景：從一坨代碼到模式重構]] — 用配置回滾場景體驗重構前後的完整過程（after step 1）
3. [[learn/design-pattern/nodes/memento/memento-structure|四角色分工：原物件、備忘錄、記錄者、管理者]] — 記住四角色的名稱與職責分工（after steps 1–2）
4. [[learn/design-pattern/nodes/memento/memento-implementation|Java 實現走讀：逐類對照四角色職責]] — 逐類走讀 Java 實現，把四角色落到真實程式碼（after step 3）
5. [[learn/design-pattern/nodes/memento/memento-tradeoffs|適用邊界與存儲選型]] — 掌握內存 vs 資庫存儲選型與適用邊界（after steps 1–2）

## Lesson

備忘錄模式解決一個後端開發者遲早會撞上的問題：系統狀態需要回滾，但又不想把原物件的封裝拆得七零八落。配置文件改錯了要退回上個版本、遊戲打到一半想存檔、IDE 打了二十行想撤銷——這些都是同一個需求：在不動原物件的前提下，把它的狀態快照一份存起來，需要的時候再還原回去。

五步走完，你應該能說出備忘錄的四角色分工（原物件、備忘錄、記錄者、管理者），能用配置回滾的場景把代碼講清楚，也能判斷什麼時候該用這個模式、存快照該選內存還是資料庫。
