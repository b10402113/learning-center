# 設計模式是什麼

<LearningGoal>
能說出框架源碼難讀的根源（20% 核心 + 80% 輔助代碼）與設計模式「綜合運用、經驗沉澱」的定位。
</LearningGoal>

## Lesson

讀框架源碼覺得費勁，先別歸咎於自己。小傅哥用「擦屁屁紙」開篇：一張擦屁屁紙 80% 的面積是拿來保護手的，真正起作用的部分很小。Spring、MyBatis、Dubbo 也是一樣——核心邏輯只佔約 20%，其餘八成是保證核心流程正常運行的輔助代碼（攔截、適配、配置載入、異常處理）。框架複雜度隨時間增長，讀不懂源碼不是能力問題，而是源碼本來就是「20% 核心 + 80% 輔助」的結構。

設計模式的定位是「多年工程經驗沉澱下來、在框架中被綜合運用的設計思路」。它的譜系可溯至建築學家 Alexander 的《建築模式語言》，1994 年 GoF 四人出版《設計模式》將軟件工程反覆出現的套路提煉為 23 個經典模式。關鍵在「綜合運用」：框架不只用到一種模式，而是工廠、代理、適配器、模板方法疊加——在 Spring 源碼搜 `Adapter` 就有一堆實現類，如 `UserCredentialsDataSourceAdapter`。沒讀過模式書的老手也能寫出好代碼，因為他的經驗與模式要求的高內聚、低耦合、可擴展、可復用幾乎一致。

把你已經用過的東西對上號，這節就有體感了：Spring DI 是工廠思路、AOP 是代理、MyBatis mapper「沒實現類卻能調用」是代理模式的日常、發 MQ / 事件監聽是觀察者。模式不是孤立技巧，而是你一直「隱隱覺得該這樣寫」的那種感覺，被系統地命名和講清了。
