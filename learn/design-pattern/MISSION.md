# Mission — 设计模式：从"一坨代码"到认得出模式

## Why

受够了又臭又长的业务代码。日常写 Java + Spring Boot 的 CRUD 接口，真实写过 switch/ifelse 按 type 字段分发的代码——每来一个需求就往上堆分支，越来越难维护。想从根上掌握如何拆解这类结构，而不是继续"打补丁"。

## The goal

学完整个 subject 后，你能：

1. 面对一坨 ifelse 堆出来的业务代码，自己认出该用哪个设计模式并完成重构
2. 读到 Spring / MyBatis / 中间件源码时，能认出里面用到的模式
3. 掌握 22 个 GoF 模式的意图、结构、适用场景与取舍，均匀深度（访问者、迭代器、享元也不跳过）

## How this node fits

`patterns-foundation` 是 Tier 1 的心智模型节点，为后面 21 个模式章节打地基，四步按依赖链推进：

1. **设计模式解决什么问题** — 模式不是背的公式，而是反复出现的解决方案套路（本课）
2. **认识"一坨代码"的坏味道** — 认出按 type 字段堆叠的 ifelse/switch 分发（after step 1）
3. **六大原则各自管什么** — 单一职责/里氏替换/依赖倒置/接口隔离/迪米特/开闭（after step 2）
4. **怎么读懂一个模式章节** — 场景→一坨代码→模式重构→总结的统一读法（after step 3）

## Success looks like

- 能说出设计模式解决什么问题、六大原则各自管什么
- 能从一堆代码里指出"一坨代码"的坏味道在哪里
- 拿到读任何模式章节的统一方法，敢开始 Tier 2 的工厂方法节点
