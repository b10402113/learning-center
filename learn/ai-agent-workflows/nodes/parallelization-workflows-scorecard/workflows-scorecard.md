# 成績單：context 有界、可靠度高、成本可控

形狀排得出來，並不等於知道該選哪一個。許多人第一次看到 LLM 串接出來的流程，會覺得像魔法一樣神奇。但拆開來看，這些工作流（workflow）其實全都是我們早已熟悉的程式結構，只是在中間某些步驟換成呼叫大型語言模型而已：

* **Chain（循序鏈）**：本質上就是一個函式呼叫另一個函式。
* **Router（路由器）**：就是日常寫的 `switch` 判斷式。
* **Parallelization（平行化）**：運作方式就像 JavaScript 裡的 `Promise.all`。
* **Gate（檢驗門）**：就是最基本的 `if` 判斷條件。

我們不需要引入複雜的花俏圖形函式庫（graph libraries）。一個定時任務（cron job）、一組標準函式、打幾支 API、查資料庫或驗證 JSON Schema，就能組合出強大且實用的工作流。而且這些模式可以隨意堆疊，例如在「評估者與優化者（evaluator-optimizer）」的迴圈裡，放入「投票平行化（voting parallelization）」來提高決策品質。

如果要評估這類工作流的體質，可以看這三欄成績單：

## 工作流的三欄成績單

1. **Context 有界（Bounded Context）**  
   每個步驟只會看見我們明確餵給它的資訊。把任務拆成多個 LLM 步驟的最大好處，就是能嚴格控制上下文的大小與乾淨程度。模型只在需要的時候拿到絕對必要的資訊，不會被雜訊干擾。
2. **可靠度高（High Reliability）**  
   呼叫 LLM 的次數越多，理論上產生幻覺或非確定性輸出的機率確實會上升；但工作流的每個步驟都能獨立隔離測試（isolation testing），加上我們能在步驟之間插入驗證機制，整體系統非常穩定。
3. **成本可控（Controllable Cost）**  
   因為呼叫次數完全由程式碼掌控（通常只有一兩次呼叫，即使是反覆生成的模式也有明確的終止條件），Token 的消耗在預期之內，不會莫名其妙陷入無窮迴圈而燒光預算。

## 工作流何時會遇上極限？

即使成績單表現優異，傳統工作流還是有它無法應付的情境。

以「獎學金與助學貸款資格審核」為例：系統可能要先判斷學生住哪裡、是不是家族第一代大學生、是否來自軍人家庭，或是運動員。但光是「運動員」這一個條件成立，底下又會分岔出十幾條新問題：「你是游泳隊還是籃球隊？」進了泳隊，可能又要再回答三個衍生問題。

<!--image:2-->

如果手上有幾百種獎學金，每種都有幾十項條件，而且每年甚至每學期都在變動，工程師根本不可能靠手寫把所有的 `if/else` 分支窮舉出來。這種高度動態、分支爆炸的情境，就是工作流交棒給自主代理人（Agent）的時刻。

## 失敗處理：停在半途該怎麼辦？

當工作流設有迴圈次數上限或超時機制時，系統很可能在「還沒產出滿意答案」時就觸發終止條件。這時候有兩種截然不同的收尾策略：

<!--image:3-->

### 策略一：直接報錯（Fail Early）

如果評估者對當前的輸出不滿意，而且已經用盡重試次數，最安全的做法是直接回傳錯誤訊息，例如：「糟糕，出了點問題，請再試一次。」

因為 LLM 流程出錯通常只是偶發的軌跡偏差（trajectory went off base），重新執行一次往往就能解決。與其硬把模型半生不熟、甚至開始發散的內容拼湊給使用者，不如明確報錯。寧可讓使用者看到系統錯誤，也不要給出一份爛答案；使用者看到錯誤畫面通常會先懷疑自己的網路，但收到爛答案時，失去的就是對產品的信任。

在 Orchestrator（協調者）工作流中也是同樣的原則：只要協調者在時限內沒有回應，或是產出的格式不符合 Schema 規格，就應該透過閘門（gate）直接捕捉並拋出錯誤。

### 策略二：倒數收尾與經驗記錄（Wrap Up & Log）

另一種做法是在迴圈接近上限（例如倒數最後一次 $N-1$ 輪）時介入，告訴模型：「請在下一輪做總結，給出目前最好的摘要作為結束。」

拿到這份摘要後，將它寫入日誌或資料庫中。這份紀錄有兩個價值：
* 下次使用者重新執行時，可以當作上下文參考。
* 開發團隊可以檢視哪些情境容易觸發終止條件，藉此調整系統提示詞（System Prompt）或重新界定任務範圍，讓工作流隨著時間自我進化。

## 協調者與工人的邊界

在協調者工作流（Orchestrator-Workers）中，工人往往是一組固定的專業角色（例如求職、進修訓練、資金申請）。但協調者看完第一輪工人的回覆後，如果發現結果不合理——例如求職工人一口氣給了「UX 設計師、警察、攝影師」三個毫不相干的職業建議——協調者可以把任務退回給同一個求職工人，要求重新調整再產出。

這種具備重試、反思與重新派發任務的迴圈機制，就已經站在傳統工作流與自主代理人的邊界上了。
