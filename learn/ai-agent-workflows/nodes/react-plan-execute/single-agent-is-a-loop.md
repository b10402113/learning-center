# Agent 是迴圈，不是模型

當我們開始接觸單一代理人（single-agent）系統時，事情往往會變得既令人興奮又有些棘手。在動手建置之前，必須先釐清一個核心問題：究竟什麼是 single-agent 系統？

根據 OpenAI 的定義，一個代理人包含三個要素：模型、工具，以及規範其行為的指令。

但在實際架構中，還有一個最關鍵的本質：Agent 其實就是一個迴圈（loop）。

因此更完整的定義，是迴圈、大型語言模型（LLM）、工具呼叫與指令的結合。這裡必須釐清一個常見的誤解——**Agent 是那個迴圈，而不是模型本身**。

模型只是 Agent 裡面的其中一個元件。就像在一般工作流程（workflow）中一樣，模型單純是一個「接收文字輸入、吐出文字輸出」的處理區塊。真正構成 Agent 的，是我們圍繞著它打造的這套執行迴圈：

<!--image:1-->

- LLM 在迴圈裡負責推論與決策。
- 工具在迴圈裡被呼叫並回傳結果。
- 上下文視窗（context window）裡的記憶在迴圈裡累積與傳遞。
- 任務的規劃（planning）在迴圈裡逐步進行。
- 對執行結果的反思（reflection）也是在迴圈裡發生。

## 最常被遺漏的關鍵：停止條件

在建構 Agent 系統時，有一個極為關鍵、卻常常被開發者忽略的機制：停止條件（stopping condition）。

你絕對不能讓 Agent 無休止地執行下去。常見且必要的停止條件包括：

- **最大輪數（maximum turns）**：限制迴圈最多只能來回互動幾次。
- **最大 Token 數（maximum tokens）**：設定累積消耗的 Token 上限。
- **成本上限（cost）**：直接以花費金額作為中斷點。
- **執行時間（time to run）**：限制最長執行秒數或分鐘數。

設定停止條件看似基本，卻是打造 Agent 時最容易被跳過的步驟。它之所以至關重要，是因為它能幫你或你的公司省下非常可觀的開銷。

<!--image:2-->

很多人以為關閉瀏覽器分頁、關掉終端機視窗，程式就結束了。但關閉介面並不代表後端程序（background processes）已經停止運作。現實中確實發生過有人讓模型在背景持續跑了好幾個星期，直到收到幾萬美元的帳單才大驚失色，納悶自己明明早就關掉了——事實上他們只是蓋上筆電，背後產生 API 請求的迴圈從未真正被終止。

在傳統工作流程中，執行的次數通常是固定且可預期的；但在 Agent 系統中，一旦我們把迴圈何時繼續的控制權交給模型，它到底會重複執行多少次，人類往往無法預知。

要回答「這個程式到底會跑幾次」這個問題，唯一的辦法就是由你親手為它加上明確的停止條件。
