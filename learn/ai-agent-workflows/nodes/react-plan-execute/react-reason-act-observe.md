# 推理與行動

有了停止條件，下一個問題是迴圈裡每一步到底要做什麼。當你想讓大型語言模型（LLM）幫忙規劃職涯，問題往往不是一句話就能回答的。例如使用者可能會問：「我很有創意，也喜歡幫助別人，有哪些適合我的職涯方向？有什麼進修課程可以幫我達成？學費又要怎麼負擔？」

面對這種需要多個步驟才能解決的問題，我們可以用一種名為 ReAct 的模式來打造代理人（Agent）。這裡說的 ReAct 不是前端開發常用的 JavaScript 函式庫，而是「推理與行動」（Reasoning and Acting）的縮寫。

## 思維鏈加上行動

ReAct 的概念來自 2022 年的一篇研究論文。在變化飛快的 AI 領域裡，2022 年聽起來已經算相當「古老」了。當時大家都在研究思維鏈提示（Chain-of-Thought prompting），也就是引導模型「一步一步思考」（think step by step），並發現這樣做能大幅提升語言模型的表現。

研究人員接著思考：如果把這種逐步推理的能力，和「採取行動」（acting）結合在一起，會發生什麼事？ReAct 代理人便是在這個想法下誕生的產物。

它的運作核心是一個單一代理人系統（single-agent system）。模型先推理該做什麼，接著採取行動（例如呼叫工具），再回頭觀察行動產生的結果，然後根據結果繼續思考，不斷重複這個過程，直到找出最終答案。

## Thought、Action 與 Observation 的迴圈

在 ReAct 的每一輪運作中，都包含三個核心環節：

1. **思考（Thought）**：模型針對目前已知的資訊進行推理，評估現況並決定下一步該做什麼。
2. **行動（Action）**：模型決定呼叫某個工具，輸出工具名稱與輸入參數，格式就像一般的函式呼叫。
3. **觀察（Observation）**：背後的程式碼負責執行該工具，並把執行結果附加到對話紀錄中，回傳給模型查看。

以剛才的職涯諮詢為例，ReAct 代理人的運作流程會像這樣：

首先是**思考**：「我應該先了解使用者的興趣，並提供合適的職涯建議方向。」

接著是**行動**：呼叫搜尋工具，尋找符合使用者個性與興趣的職業。

再來是**觀察**：工具回傳了搜尋結果，列出幾種不錯的選項，例如使用者體驗設計師（UX designer）、教師、心理諮商師（mental health counselor）。

看到結果後，模型再次進入**思考**：「現在我應該替這些職業尋找進修課程，接著查詢相關的學費補助方案。」

代理人會視需要重複執行「行動」與「觀察」，直到蒐集齊全所有資訊，最後輸出完整回覆：「根據您的興趣，這裡提供三條職涯路徑、您可以參考的進修課程，以及您可能符合資格的補助方案。」

大型語言模型本質上只是「文字進、文字出」，背後的工具呼叫與資料串接都是由我們的程式碼在處理。這個迴圈會一直進行，直到滿足兩個條件之一：模型產出了特殊的 `finish` 行動並給出最終答案，或是執行次數達到了系統設定的最大步數（max steps）。

## 為什麼這是 Agent，而不是 Workflow？

ReAct 代理人與一般的提示詞鏈工作流（prompt chain workflow）有著本質上的不同。

在工作流（workflow）中，執行步驟完全由程式碼寫死。例如程式明確規定：第一步永遠是挑選職業，第二步永遠是展開職涯路徑，順序完全固定。

<!--image:2-->

但在 ReAct 代理人系統中，是由語言模型自己決定要呼叫哪一個工具、傳入什麼參數、要呼叫幾次，以及什麼時候才算完成任務。

工作流是由開發者替系統決定好每一個步驟；單一代理人系統則是「給模型工具清單，讓它自己想辦法」。模型必須自己擬定計畫、自己推理、對環境採取行動、在遇到狀況時更新計畫，並持續推進直到完成。

因為掌握了自主權，代理人可以根據情況連續搜尋兩次、同時查詢兩種職業進行比較，甚至在工具呼叫失敗時自行重試。我們的程式碼只需要負責維持這個迴圈運轉。這是一個最單純的架構：只有一個語言模型、一份對話紀錄（transcript）、一個迴圈，沒有其他代理人介入，也不需要額外的協調器（coordinator）。
