# 單一 Agent 計分卡：我們換到了適應力

ReAct、Reflexion、CodeAct 都放進同一個 agent 之後，該把帳算清楚了。當我們把升學與職涯顧問系統從固定流程（workflow）換成單一 agent 架構時，整個系統的評估計分卡（scorecard）出現了明顯的變化。

如果把情境背景（context）、可靠度（reliability）、成本（cost）與適應力（adaptability）四個維度攤開來看，單一 agent 在前三項幾乎都付出了代價，但換來了一項關鍵優勢。

## 情境背景（Context）：負擔變重且容易遺失

在單一 agent 系統中，情境背景的表現明顯變差。原因在於單一模型的情境視窗（context window）必須塞進所有資訊。

<!--image:1-->

以升學與職涯顧問為例，這個視窗得裝下學生的完整背景：他們的興趣、擅長的領域、在校 GPA、居住在哪個州、家庭狀況，以及「不想離父母太遠」的要求。接著，agent 開始呼叫工具搜尋學校，抓回大量學校資料；再搜尋獎學金，又抓回成堆的申請資格條件。

可能幾萬個 token 的資料陸續湧入視窗。這時問題就來了：使用者一開始說的「我想留在父母所在的南卡羅來納州讀書」，agent 還記得嗎？

答案是：可能記得，但也可能忘了。如果情境視窗被塞滿，這句話可能直接被截斷；就算用的是百萬 token 等級的超大視窗，當關鍵句落在第 25 萬個 token 的中間位置，也很容易發生「迷失在中間」（lost in the middle）的現象。

對使用者來說，這不會顯示為程式當掉或報錯，而是讓 agent 看起來極度無能。學生明明說了想留在南卡羅來納州，系統最後卻推薦了一所奧勒岡州的學校。這種糟糕的使用者體驗，使用者通常不會再給第二次機會。

## 可靠度（Reliability）：步驟難以預測

可靠度也比原本的 workflow 差。

在固定 workflow 裡，每一步都有明確定義，我們能在步驟之間設置檢查閘門（gates），也很清楚整個流程一共呼叫了幾次大型語言模型（LLM），承擔的風險完全可控。

但在單一 agent 系統中，模型會自行決定要採取幾步行動。我們無法事先得知它會跑多少步，也就無法掌握過程中有多少可能出錯的節點，導致系統整體的可靠度稍微下滑。

## 成本（Cost）：比流程貴，但比多 Agent 便宜

成本方面，單一 agent 同樣高於固定 workflow。讓 agent 在迴圈中反覆思考、呼叫工具並評估結果，花費的 token 與運算資源，遠高於在固定節點呼叫單次 LLM。

不過，單一 agent 的花費仍然比多 agent（multi-agent）架構來得低，介於固定 workflow 與多 agent 之間。

## 適應力（Adaptability）：換取可能性的核心回報

在計分卡上，context、reliability 與 cost 都變差了，那我們到底換到了什麼？答案是適應力。

<!--image:3-->

這項特質在計分卡上或許只佔一欄，但在軟體工程的實務上，它往往決定了一項功能「能不能做出來」。如果沒有這項適應力，工程師不可能替每一種職業選擇、每一所學校、每一筆獎學金以及繁複的申請資格，窮舉寫死所有的判斷分支與路徑。

正是因為 agent 具備動態調整與處理非結構化情境的適應力，這類複雜的顧問系統才有被實現的可能。雖然我們必須謹慎設計 agent 的邊界，但如果業務場景真的需要高度彈性，agent 就是合適的工具。

## 下一步：何時該轉向多 Agent？

單一 agent 的瓶頸很直接：所有負擔都壓在同一個 agent 身上，它可能扛得住，也可能隨時超出負荷。

這時很自然會浮現一個念頭：既然單一 agent 裝不下所有東西，那何不改成多 agent 架構？然而多 agent 並非萬靈丹，它有適合的使用時機與各自適用的系統型態，必須依任務特態決定是否跨出這一步。

**補充：程式碼執行與 Prompt Injection 防護**

在構建具備工具調用或程式碼執行能力的 agent 時，防禦提示詞注入（prompt injection）是另一個常見挑戰。

單靠沙盒環境（sandbox）並不足以成為萬全的解法。沙盒是很好的第一道防線，但理想的架構應該像防範 SQL injection 一樣，採取多層防禦：

1. **沙盒隔離**：限制程式碼的執行權限與環境。
2. **確定性檢查（Deterministic Checks）**：在程式碼執行之前，用確定性的傳統程式邏輯檢查輸入內容，過濾特定惡意特徵。
3. **安全護欄（Guardrails）**：在每一步驟加入驗證機制，確認指令合規才放行。

防護機制永遠不可能達到百分之百，但只要將沙盒與確定性護欄結合使用，實務上就能攔截大約 98% 的注入風險。
