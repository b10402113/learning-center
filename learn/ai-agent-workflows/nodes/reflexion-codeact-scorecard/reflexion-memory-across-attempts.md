# Reflexion：反思累積在記憶裡

有了真實的外部訊號，還要讓它跨嘗試留下來。讓 AI Agent 解題時，最常見的挫折就是看到它在同一個任務上反覆犯下一模一樣的錯誤。就算重新執行一次，如果沒有調整提示詞或給予提示，它依然會走上原本的死胡同。

2023 年提出的「Reflexion」（名稱中的 X 是特意保留的拼法，並非筆誤）就是為了解決這個問題。它是一種提示架構（prompting framework），目的不是只優化單一次回答的品質，而是讓 Agent 能在多次嘗試同一個任務時，透過語言文字自我反思內部與外部的回饋，從前幾次的失敗中累積教訓並逐步修正。

## Reflexion 的三個核心實體

Reflexion 將整個改進機制拆解成三個各自獨立的分工角色：

<!--image:1-->

1. **Actor（行動者）**  
   負責實際做事的主體，也就是一般所說的 Agent。它接收任務、將目標轉化為動作、與環境互動，並觀察環境回傳的結果。
2. **Evaluator（評估者）**  
   負責審查 Actor 的表現。Evaluator 審查的對象不只是最終輸出，而是 Actor 執行過程的「完整軌跡（trajectory）」——包含走過的每一步、每次工具調用（tool call）以及所有中間觀察，接著為整段過程給出評分。  
   特別的是，Evaluator 不一定必須是大型語言模型（LLM）。在實務上，最精準且穩定的選擇往往是自動化單元測試（unit test）或其他確定性程式碼（deterministic checks）。
3. **Self-reflection LLM（自我反思模型）**  
   當 Actor 失敗時，這個語言模型會接過「執行軌跡」與「Evaluator 的評分」，以純文字寫下一小段反思摘要。這段話的語法非常直白，例如：「我做了 X、搜尋了 Y，但結果不如預期，因為發生了某個狀況；下次我應該改用 Z 的方式進行。」

## 運作迴圈與跨嘗試記憶

這三個角色串聯起來，構成一個循環反覆的執行迴圈：

<!--image:2-->

1. **Actor 執行任務**，產生完整行動軌跡與最終成果。
2. **Evaluator 評分**，檢查成果是否合格。
3. 如果未通過，**Self-reflection LLM** 根據軌跡與評分寫出失敗原因與改進建議。
4. 這段純文字反思會被塞回上下文（context），作為 **Actor 下一次嘗試** 的前情提要。

迴圈會持續運作，直到 Evaluator 判定答案正確，或是達到預設的終止條件（例如嘗試滿三次必須停下）。

這種架構的威力在於記憶的堆疊。當 Agent 進行第三次嘗試時，它的上下文裡不只看得到上一輪的結果，還完整保留了前兩輪犯錯後寫下的反思筆記。Agent 清楚知道「第一輪哪裡錯了」、「第二輪哪裡又有破綻」，進而能夠在不需人工介入修改程式碼或提示詞的情況下，自動避開先前踩過的坑。

舉例來說，在規劃職涯路徑與補助方案的任務中，Agent 第一次嘗試後可能會反思：「我漏掉了一些資金選項，下次除了就學貸款，我也應該一併搜尋獎學金與補助金。」當這段文字被寫入上下文，進入第二輪執行時，Agent 就會主動擴大搜尋範圍，補齊先前的缺漏。

## 在 Context 裡學習的優勢與限制

Reflexion 所有的學習與改進，完全發生在模型的上下文視窗（context window）中。

<!--image:3-->

這帶來顯著的好處：你不需要重新微調（fine-tune）模型，也不需要更新權重，反應速度快且成本極低。但這也帶來先天的物理限制——一旦任務結束、上下文被清空，這幾輪嘗試所累積的心得就隨之消失。除非將這些反思摘要整理並存入向量資料庫等長期記憶（long-term memory），下次重新指派給 Agent，否則反思就只存在於當次執行的生命週期內。

因此，實務上運用這類反思機制時，核心挑戰往往在於如何精準管理上下文的大小與保留資訊。

## Reflexion 與 ReAct 差在哪裡？

很多人容易把 Reflexion 和常見的 ReAct（Reason + Act）工作流程混淆，這兩者的反思維度截然不同：

<!--image:4-->

- **ReAct** 是「微觀的單一步驟迭代」。Agent 每做一個動作，就停下來觀察工具回傳的結果，思考下一步並動態微調計畫，一步步推導出最後答案。
- **Reflexion** 則是「宏觀的完整任務反思」。Agent 會先一口氣跑完所有步驟，產出完整答案，接著退後一步讓 Evaluator 批判這份成果是否合規；如果不合規，才寫下教訓並「重新跑一次整個任務」。

在實際生產系統中，這兩種模式經常組合使用：你可以讓內層使用 ReAct 迴圈來靈活呼叫工具、執行任務；外層則套用 Reflexion 機制，在產出結果後透過測試評估與反思文字，決定是否需要從頭再試一次。
