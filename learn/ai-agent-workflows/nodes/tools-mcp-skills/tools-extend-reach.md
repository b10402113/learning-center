# 工具讓 LLM 能與環境互動

如果把大型語言模型（LLM）單獨抽出來看，它本質上只能做兩件事：接收文字輸入，然後產生文字輸出。光靠這樣的能力，模型只能憑著預訓練階段學到的知識來「猜」答案。一旦遇到需要即時資訊、存取資料庫或操作系統的情境，它就無能為力。

要讓 LLM 真正發揮作用、成為能與真實世界互動的 agent（代理人），關鍵就在於「工具」（tools）。

## Agent 的本質只是一個迴圈

談到 agent，很多人會覺得它既複雜又神秘。但若把它拆解到最核心的骨架，agent 其實就只是一個迴圈。

這跟你剛開始學寫程式時寫的 `for` 迴圈，或是讓你感到興奮的遞迴函式沒有兩樣。Agent 的運作邏輯非常單純：

1. 做某一件事
2. 思考並觀察結果
3. 根據結果採取下一步行動
4. 繼續重複上述步驟，直到滿足終止條件、觸發 break，或是任務宣告完成

既然 LLM 本身只能輸入與輸出文字，究竟是什麼東西在驅動這個迴圈、代替模型向外延伸去接觸並影響周遭環境？答案就是工具。外部 harness 透過工具把能力接給模型，讓它能夠真正對環境產生作用。

## 工具能做什麼？

工具賦予了 LLM 與環境互動的能力。透過工具，模型可以：

- 呼叫外部資訊
- 發送 API 請求
- 執行程式碼
- 呼叫其他模型協助處理

工具可以分為「唯讀」（read-only）與「讀寫」（read-write）。這項區分在實務上極為關鍵。

<!--image:2-->

當 agent 剛問世時，大家因為模型能夠主動執行操作而興奮不已，幾乎沒有設置任何防護機制（guardrails）。結果很快就出現了災情，例如有人不小心執行了 `rm -rf` 刪除指令，甚至發生過 Replit 的正式環境資料庫（production database）被直接抹除的意外。

這些慘痛教訓讓大家意識到防護機制的重要性。而落實防護機制最直接、最簡單的位置，就是放在你提供給模型的工具裡面。

## 突破預訓練資料的限制

工具之所以讓 LLM 顯得神奇，是因為模型不再只能受限於預訓練的截止日期，靠過往的記憶來回答問題。藉由工具，agent 能夠即時取得最新、真實的外部資料。

<!--image:3-->

常見的工具範例包括大家天天都在用的「網路搜尋」（web search）。另一個更進階、目前還不是每個人都會用到的工具則是「電腦操作」（computer use）——讓 agent 直接操控你的電腦圖形介面（GUI），像真人一樣點擊按鈕、操作各種桌面應用程式。

甚至連那些原本沒有專門針對工具呼叫進行訓練的模型，只要搭配適當的提示詞（prompting），也能學會使用工具。工具正是把單純的文字生成模型，轉化為真正具備行動力之 agent 的關鍵橋樑。
