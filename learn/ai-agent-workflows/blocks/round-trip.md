# Round Trip（工具呼叫往返）

## 定義

Round trip 是一次完整工具呼叫所經過的三段流程：模型生成符合格式的 JSON 工具呼叫、應用程式解析並執行對應工具、等待結果出爐後把結果塞回 prompt 交給模型決定下一步。這三段合起來算一趟往返。

## 為什麼重要

它是 JSON 工具呼叫的主要成本來源。任務只要需要接連呼叫三、四個工具，往返就要重複三、四次；每一次都包含模型生成、外部執行與結果回填，延遲與 token 都隨工具數量疊加。理解這個單位，才能判斷什麼時候該改用 [[codeact]] 把多趟壓成一次。

## 如何運作

1. 模型輸出一段 JSON，指定工具名稱與參數。
2. 應用程式解析 JSON，找到並執行對應的工具或函式。
3. 應用程式等待執行結果。
4. 結果被放回 prompt，模型讀到後再決定下一個動作。

如果下一步又是工具呼叫，這四步就再跑一次。模型在每一趟之間都必須重新取得控制權，無法把後續查詢先寫在一起。

## 例子

一個職涯顧問 agent 要回答「有哪些職涯、哪些課程、怎麼付費」，JSON 版本會先呼叫職涯查詢工具並等待，再呼叫課程查詢工具並等待，最後呼叫助學金工具並等待。三個工具就是三趟往返。

## 邊界與常見誤解

- **不是單純的網路延遲**：瓶頸包含模型重新生成與 context 重新送入，不只是 HTTP 來回。
- **平行工具呼叫只省一部分**：若 harness 支援同一輪多個呼叫，可以減少趟數，但每次模型決策仍是一趟。
- **省往返有代價**：CodeAct 把多趟併成一段程式碼，換來的是沙箱與安全成本，不是免費加速。
- **回合數和工具數不是等號**：一個工具可能被呼叫多次，也可能一輪同時呼叫多個。

## 進階

把 round trip 當成計分卡上的「回合成本」來看：每次反思、每次重試都會再帶進完整 [[trajectory]]，因此減少不必要的往返與設定 [[bounded-retry-loop]] 同樣重要。
