# Guardrails（護欄）

## 定義

Guardrails 是套在 agent 外面的限制與邊界，用來約束它能採取哪些行動。具體做法包括：使用第三方工具或程式碼時保持謹慎、限制執行權限，以及設定明確的停止條件。

## 為什麼重要

交出控制權給 agent 並非沒有風險。2025 年就曾有早期的 agent 在正式環境中誤刪 Replit 資料庫。沒有護欄，agent 可能做出無法復原的操作，或在迴圈裡停不下來，在不知不覺中燒掉數萬美元的 API 費用。

## 如何運作

護欄從三個方向限制行動：

- **權限**：只給 agent 完成任務真正需要的最小權限，避免它能任意刪改重要資源。
- **邊界**：限制它能呼叫哪些工具、能碰哪些資料；對第三方程式碼保持謹慎。
- **停止條件**：明確定義何時該結束，例如步數上限、成本上限或任務完成訊號，避免無窮迴圈。

## 例子

Replit 資料庫被誤刪的事件，就是缺少權限邊界與停止條件的典型案例：agent 取得了足以造成不可逆破壞的行動能力，卻沒有機制在動作前攔住它。

## 邊界與常見誤解

- **護欄不是反對自主**：護欄的目的不是把 agent 綁死，而是讓它在可承受的範圍內自主。
- **護欄不是只有提示詞**：只叫模型「小心一點」不算護欄；真正的護欄落在權限、工具與程式碼層。
- **停止條件不是選配**：只要 agent 會重試或迴圈，就必須有停止條件。

## 進階

護欄要與任務的風險等級匹配：唯讀查詢可以寬鬆，能寫入或刪除資料的操作則需要更嚴格的權限與人工確認。把護欄設計好，往往比換更大的模型更能提升系統的實際可靠度。
