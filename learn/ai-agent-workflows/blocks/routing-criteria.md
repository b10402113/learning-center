# Routing Criteria（路由依據）

## 定義

Routing criteria 是分類步驟用來決定「這個請求該走哪條路」的判斷標準。同一批輸入，換一組依據，就會得到完全不同的分流結果。

## 為什麼重要

分類步驟通常很便宜，但它決定整條流程的走向。依據選錯，後面的專屬路徑再精巧也救不回來：一個該轉人工的客訴被送進產品問答，回得再流暢也是錯的。因此 routing 的品質，很大一部分取決於依據設計得好不好。

## 如何運作

常見的三類依據：

1. **主題或意圖**：判斷問題屬於技術支援、退費申請還是產品諮詢。
2. **成本與複雜度**：評估是否需要動用高成本的進階模型，或簡單規則就能解決。
3. **信心水準**：分類器對自己的判斷沒有把握時，觸發升級機制，把案件轉給人工。

實務上會先選一個主要依據，再搭配信心門檻，避免分類器在模糊地帶硬選一個標籤。

## 例子

客服入口可以先用意圖分流成三條路；其中「技術支援」再依複雜度決定走小模型或旗艦模型。若分類信心不足，就不進任何一條路，直接標記為待人工處理。這三種依據可以疊在同一條流程裡，各自負責不同層級的決策。

## 邊界與常見誤解

- **依據不是越多越好**：準則越多，分類器越難穩定分辨，標籤也越容易互相重疊。
- **信心不是正確率**：模型說有信心，不代表它真的分對了；門檻需要校準。
- **不是所有依據都能從輸入看出來**：需要外部資料（例如客戶等級）時，得先把它接進分類步驟。
- **依據一旦改動，路徑也要同步**：新增準則通常意味著新增標籤與 handler。

## 進階

把依據寫進分類 prompt，就是 [[classifier]] 的選項清單；愈清楚的選項定義，分類愈準。當信心不足或標籤不合法時，接住請求的是 [[fallback-gate]]；整體分流結構見 [[routing]]。
