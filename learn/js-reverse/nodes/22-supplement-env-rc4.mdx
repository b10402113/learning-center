## Lesson

本节点把「补环境」这件抽象的事落到两次具体实操上：先学会用最笨的方法让扣下来的浏览器代码在 Node 里跑通，再学会用 Proxy 自动探测缺了什么属性。前者给你一个能跑起来的起点，后者给你一个能复用的工作流。

补环境的核心矛盾很简单：浏览器代码默认活在浏览器里，能随手调用 `window.atob`、`window.screenX`、`window.localStorage` 这些东西；Node 里这些全都没有。你把一段扣下的加密代码原封不动丢进 Node 跑，第一行就报错——不是算法看不懂，而是环境缺了一块。补环境就是缺什么补什么，而不是把整个浏览器搬进 Node。

补完之后遇到的是一个新形态的实战案例：响应体不是明文，而是 RC4 加密后的 base64 字符串。这一类案例的特征是「请求本身没有加密参数，密文藏在响应里」，响应体解密这类案例的特征是「请求本身没有加密参数，密文藏在响应里」。破解它的链路是：atob 把 base64 字符串还原成字节数组，RC4 用固定密钥把字节数组异或回明文字节，UTF-8 解码把字节拼回中文字符串，最后 JSON 解析拿到图片列表。每条链路对应扣下的三个函数，把它们和入口 `_0x58b5da` 一起扣下来，补上 `window.atob`，就能在 Node 里复现整条解密链。

走完这个节点，你手上会多两套工具：一套是遇到任何依赖浏览器全局对象的加密代码时，能用「补环境 + Proxy 探测」两步让它跑起来；另一套是遇到响应体加密时，能识别 RC4 的特征、拆出密钥数组、写出完整的 Python 解密脚本。这两套工具在后面的 webpack 分析、拼多多风控逆向里还会反复出现。
