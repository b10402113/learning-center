# 实战：拼多多进阶补环境

## Learning goal
完整 env shim、风控 anti_content token 生成

## Steps

1. [[learn/js-reverse/nodes/25-pdd-supplement-env/env-shim|最小可用补环境]] — 在 Node 环境中补齐浏览器全局对象的最小可用 shim，并抹除暴露宿主身份的指纹。
2. [[learn/js-reverse/nodes/25-pdd-supplement-env/webpack-chunks|webpack 混淆 chunk 结构]] — 理解巨型 webpack 混淆 chunk 的注册机制，以及如何从中定位目标模块而不通读全文。（after step 1）
3. [[learn/js-reverse/nodes/25-pdd-supplement-env/loader-runtime|loader 运行时]] — 掌握 webpack JSONP loader 的最小运行时结构，能够按模块 id 按需调用目标模块。（after step 2）
4. [[learn/js-reverse/nodes/25-pdd-supplement-env/assembly-call|组装与调用 anti_content]] — 将补环境、chunk、loader 按顺序组装，并调用 get_anti_content() 生成风控 token。（after step 3）
5. [[learn/js-reverse/nodes/25-pdd-supplement-env/python-integration|Python 联调与接口请求]] — 用 execjs 在 Python 侧实时生成 anti_content，构造合法请求拉取拼多多接口数据。（after step 4）

## Lesson

拼多多风控案例把前面零散的补环境技巧收拢成一个完整可运行的端到端流程。核心思路是：把站点真实运行的 JavaScript 从浏览器里“抠”出来，在本地 Node 环境中用最小可用补环境还原它需要的全局对象，再通过 webpack loader 按需挂载混淆 chunk，最后包成一个可被 Python 调用的纯函数。每一步都靠前面步骤打下的基础——补环境让站点 JS 不再报错，loader 让巨型 chunk 变成可按 id 查询的模块库，组装脚本把分散零件变成可调用的 token 生成器。当 Python 通过 execjs 在每次请求前实时生成新的 anti_content，整个逆向链路才真正跑通。
