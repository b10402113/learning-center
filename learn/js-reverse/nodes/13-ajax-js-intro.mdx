# Ajax 与 JavaScript 引入

## Learning goal

Flask 伺服器、Ajax 请求、JS 引入方式、Ajax = requests 映射

2. [[learn/js-reverse/13-ajax-js-intro/flask-server|Flask 演示伺服器]] — 搭建本地可控目標站點（after step 1）
3. [[learn/js-reverse/13-ajax-js-intro/ajax-frontend|Ajax 前端演示頁]] — 用 jQuery Ajax 從 JS 發起非同步請求（after steps 1–2）
4. [[learn/js-reverse/13-ajax-js-intro/python-client|Python 客戶端對照]] — 用 requests 重現同一個介面，建立逆向工作流錨點（after steps 1–3）

## Lesson

這一課把你熟悉的 Python requests 世界，和瀏覽器裡 JavaScript 發出的 Ajax 請求世界，正式搭起一座橋。過去你用 requests.get() 直接對伺服器敲門，拿到回應；在瀏覽器裡，同樣一件事情是透過 JavaScript 在非同步模式下完成。表面上看，一個是 Python 腳本、一個是網頁上的程式碼，但它們做的事情完全一樣：把參數打包、送到指定 URL、拿回資料。

我們先從 URL 的長相談起。每一個請求，不管是用瀏覽器地址列輸入、按了一個超連結、送出一個表單，還是 JavaScript 在背後偷偷送的，都會對準一個 URL。把 URL 拆開，會看到四個部分：協議（https://）、域名與埠號（www.baidu.com）、路徑（/s）、查詢參數（?wd=alex）。理解了這個結構，你在 DevTools 裡看到任何請求，都能立刻判讀它到底在問伺服器什麼。

同樣是發請求，前三種方式（地址列、超連結、表單）都是瀏覽器內建的同步行為：一按下去，整個頁面就被新內容蓋過。這對一般上網很直覺，但對爬蟲來說有個大麻煩 —— 你很難只拿一小塊資料，卻要載入整個新頁面。Ajax（Asynchronous JavaScript and XML）就是為了解決這件事誕生的。它讓 JavaScript 在不換頁的情況下，偷偷在背後和伺服器對話。對爬蟲來說，這代表資料不再埋在整頁 HTML 裡，而是藏在一次一個的小請求裡。你要找的，變成了這些請求的 URL、參數和回應格式。

我們在本地架一個 Flask 伺服器當靶站。它只有三個頁面：一個首頁（會顯示目前時間）、一個登入表單頁、一個 JSON 介面（隨機回傳四本書）。這個靶站完全是為了讓你在本機反覆練習而存在 —— 不管怎麼戳它，都不影響任何真實網站，而且你可以在 DevTools 裡清楚看到每一個請求的細節。

前端示範頁用 jQuery 的 $.ajax 封裝了一個最簡單的 Ajax 流程：點一下畫面上的段落，JavaScript 就往 /books 送一個 GET 請求，拿到 JSON 陣列之後，再把書名用逗號接起來，塞回畫面裡。這個過程完全沒有換頁，資料是動態長出來的。你在 DevTools 的 Network 面板裡，會看到這次請求的 URL、方法、回應頭和回應體。

最後一個步驟是對照組：用 Python 的 requests 直接對同一个 /books 介面發出 GET 請求，呼叫 res.json() 把回應解析成 Python 列表。你會發現，瀏覽器裡 JavaScript 做的事，和 Python 腳做的事，幾乎一模一樣。這就是逆向爬蟲最關鍵的心態轉換 —— 只要你能用 requests 重現瀏覽器等效的行為，就不需要真的去執行 JavaScript；你要做的，只是看懂 JS 在背後打了什麼要求，然後用 Python 照打一次。
