## Lesson

webpack 是现代前端最常用的打包工具之一，但它产物对逆向者来说像一堆乱码：所有模块被压缩进少数几个 JS 文件，原始变量名全被混淆成短哈希。这一节的目标，是教你从这种乱码里还原出「哪个函数在哪」的地图，并在本地 Node 里复现它。

核心洞察是**加载器与模块的分离**。webpack 产物通常由两部分组成：一个负责调度（加载器）的薄壳，以及一个或多个负责实际业务逻辑的厚块（mod）。加载器暴露一个调度函数（通常挂在 `window.loader` 上），你传进模块 ID，它帮你找到并执行对应模块，把结果缓存起来。模块通过 `window.webpackJsonp.push(...)` 把自己注册进加载器——加载器劫持了这个 push 操作，把每个模块收进自己的调度表。

理解这套机制后，逆向流程就清晰了：先把 loader 和它依赖的所有 mod 一起 require 进 Node，补上 `window = global` 之类的浏览器环境垫片，然后直接调用 `window.loader("模块ID")` 就能拿到目标函数。财联社和沃邮箱两个案例会带你走通完整流程，分别展示哈希 key 调度与数字下标调度两种形态。
