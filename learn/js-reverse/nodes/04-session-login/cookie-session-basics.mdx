# Cookie 本质与 Session 自动管理

## Learning goal

掌握 Cookie 的键值对本质，理解服务器如何通过 Set-Cookie 下发、客户端自动携带，并比较手动处理与 Session 自动管理两种方式的优劣，最终用 Session 对象实现「请求一次捕获 cookie、后续请求自动携带」的标准套路。

## Lesson

伺服器每次回應你一個頁面或一筆資料，HTTP 協議本身是「無狀態」的——每一請求對伺服器來說都是陌生人。如果沒有機制記住「你是誰」，你每按一個連結都要重新輸入帳密。Cookie 就是解法：伺服器在第一次回應裡放一小段資料，瀏覽器下次自動帶上它，伺服器就認得你了。它本質上就是一組鍵值對。

Cookie 的生命週期有三個階段。第一，伺服器在 HTTP 回應頭裡帶 <code>Set-Cookie</code> 標頭，瀏覽器接收到後把 Cookie 存起來，綁定到該域名。第二，同域名的後續請求，瀏覽器自動帶上 <code>Cookie</code> 請求頭。第三，伺服器讀取 Cookie 就知道你是誰。用 Python 寫爬蟲時，<code>requests</code> 不會幫你做這件事——你需要自己管理 Cookie 的存取。

手動處理 Cookie 的做法是去 DevTools 裡翻 <code>Request Headers</code>，整段複製下來，貼到 Python 程式碼的 <code>headers</code> 字典裡。這種做法馬上能跑通，但有三個致命缺點：Cookie 有過期時間，過期後要重新抓；手動複製很煩，每次請求都要去翻；更麻煩的是有些 Cookie 的值每次登入都不一樣，手動方式根本抓不到這些動態資料。手動處理就像每次都去櫃台拿一張新的訪客證再進門——能用，但很累。

<code>requests.Session()</code> 自動管理這些鍵值對，你不用手動複製，不用擔心過期，不用預先寫死。你先用 Session 發一次請求，伺服器回傳的 Cookie 被自動存入 Session 物件。之後再用同一個 Session 發後續請求，Session 自動把存好的 Cookie 帶上去，伺服器就認得你了。Session 方式至少需要兩次請求——第一次拿 Cookie，第二次才真正拿資料。這就是為什麼你之前在雪球網只帶了 User-Agent 拿不到資料：模擬力度不夠，需要先讓伺服器「認得」你。拿不到資料，先查 Cookie——這是 Python 爬蟲的排錯第一步。

Session 物件的 API 和 <code>requests.get/post</code> 幾乎一樣，差別在它是「綁在一個物件上」：<code>session.get(url)</code>、<code>session.post(url, data=...)</code>、<code>session.headers.update({})</code>、<code>session.proxies = {}</code> ——設定一次，往後每次請求都自動帶上。
