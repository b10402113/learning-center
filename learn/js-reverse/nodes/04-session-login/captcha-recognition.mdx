# 验证码识别与打码平台接入

## Learning goal

理解工程上验证码识别的标准做法：把验证码图片 base64 编码后 POST 到打码平台（如图鉴），按 typeid 区分不同验证码类型，并将识别流程封装为可复用模块，为后续滑块/缺口验证的逆向分析建立先修认知。

## Lesson

遇到驗證碼，純爬蟲做法（OCR 辨識圖片）只對簡單文字有效，遇到計算題、座標點選、滑動驗證就徹底沒用。工程上的標準解法是接打碼平台：把驗證碼圖片 base64 編碼後 POST 到平台的 API，平台回傳辨識結果（文字或座標），你再填入表單繼續流程。這不是逆向工程，但它是滑動驗證、缺口辨識等進階主題前必須先有的認知。

打碼平台 API 的合約大同小異，核心欄位是四個：<code>username</code> 和 <code/password</code> 是你的打碼平台帳號密碼；<code>typeid</code> 告訴平台這是哪種驗證碼（純數字、計算題、缺口辨識）；<code>image</code> 是驗證碼圖片 base64 編碼後的字串。圖片要先 base64 編碼，是因為 HTTP POST 傳輸的是文字或二進制，base64 把圖片轉成安全文字，才能放在 JSON 欄位裡傳輸。流程是：讀取圖片、用 <code>base64.b64encode()</code> 編碼、放進 JSON body 裡 POST 到 <code>http://api.ttshitu.com/predict</code>、從回應的 <code>result</code> 欄位拿出辨識文字。

typeid 對照表很長，常見的包括：1（純數字）、2（純英文）、3（數字英文混合）、5（計算題）、6（漢字）、10（通用文字）、50（座標點選，回傳 1~8 個座標）、60（缺口辨識，回傳 X 軸座標）、70（拼圖辨識）。每個打碼平台支援的類型不同，圖鑒算是覆蓋率很高的，幾乎涵蓋所有常見驗證碼。滑動驗證（缺口辨識）打碼平台只負責算出缺口的 X 軸座標，你還是要用 Selenium 或 Pyppeteer 控制瀏覽器，按計算出的座標把滑塊拖過去——打碼平台幫你做最難的「看懂圖片」，你模擬最難的「拖曳動作」。

爬蟲專案裡通常會把打碼邏輯獨立成一個 <code>tujian.py</code> 模組，提供一個 <code>recognize(image_path, typeid)</code> 函式，遇到驗證碼時一行呼叫就搞定。主程式把辨識結果填入登入表單，照樣用 Session 物件帶著 Cookie 去完成剩下的模擬登入。
