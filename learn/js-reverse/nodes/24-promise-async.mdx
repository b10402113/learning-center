# Promise 与异步模式

## Learning goal
回呼地狱、Promise 语法与链式操作、async 基础

2. [[learn/js-reverse/nodes/24-promise-async/promise-basics|Promise 语法与三状态机制]] — 掌握 Promise 三状态与 then 双回调的触发条件（after step 1）
3. [[learn/js-reverse/nodes/24-promise-async/promise-chaining|链式 Promise 与 AJAX 封装]] — 用链式 Promise 拉平串行异步流程，并封装回调风格 API 为 Promise（after step 2）

## Lesson

在 JavaScript 的世界里，异步操作无处不在：发网络请求、读文件、等待定时器……这些操作不会立刻完成，程序也不能傻等结果。早期 JavaScript 用「回调函数」来处理异步——操作完成后，调用你传入的函数把结果传回来。

听起来没问题，但一旦任务之间有了先后顺序，代码就开始塌陷。请求 A 的结果是请求 B 的输入，B 的结果又是 C 的输入——于是回调里嵌套回调，代码向右偏移，形成一个三角形。这就是「回调地狱（callback hell）」：嵌套越深，越难阅读，越难定位错误，也越难在任意一步插入新的处理逻辑。

Promise 的出现就是为了解决这个问题。它把一个异步操作封装成一个对象，这个对象有三种状态：等待中（pending）、已成功（fulfilled）、已失败（rejected）。你可以用 `.then()` 在成功时处理结果，用 `.catch()` 在失败时统一处理。更关键的是，`.then()` 里可以返回一个新的 Promise，下一个 `.then()` 会等它落定再执行——于是嵌套的金字塔被拉平成一条向右延伸的链。

三步走完，你会看到：回调地狱是「串行异步 + 回调写法」的必然结果；Promise 用状态机和链式调用把串行异步重新写成扁平结构；而把任意回调风格的 API（比如 `$.ajax`）包一层 Promise，就能让老代码也享受链式调用的清爽。这些知识是读懂现代加密网站异步请求代码的基础——那些站点里，接口 A 的返回值常常是接口 B 的输入，没有 Promise 的视角，你根本追不动请求链。
