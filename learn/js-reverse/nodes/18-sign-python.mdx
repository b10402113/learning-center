# 实战：sign 逆向（Python 原生）

## Learning goal

用 Python hashlib 复现有道 sign，不依赖 JS 执行环境

## Steps

1. [[learn/js-reverse/nodes/18-sign-python/sign-reverse-flow|sign 逆向的基本流程]] — 从抓包到复现的三步法：定位加密参数、还原拼接规则、用 hashlib 生成签名
2. [[learn/js-reverse/nodes/18-sign-python/md5-hashlib|MD5 摘要算法与 hashlib.md5]] — 理解 MD5 单向散列特性，掌握 Python 中 md5 对象的 update/hexdigest 用法
3. [[learn/js-reverse/nodes/18-sign-python/timestamp-concatenation|动态时间戳与参数拼接规则]] — 拆解 mysticTime 毫秒时间戳生成，掌握 key=value 字符串拼接与排序逻辑（after step 2）
4. [[learn/js-reverse/nodes/18-sign-python/request-structure|有道翻译请求结构与 pointParam]] — 分析 POST 请求体中各字段含义，理解 pointParam 如何标记参与签名的参数（after step 1）
5. [[learn/js-reverse/nodes/18-sign-python/python-vs-execjs|Python 原生复现 vs execjs 混合路线]] — 对比两种 sign 复现策略的取舍，判断何时应坚持纯 Python、何时应切换到 execjs（after steps 3–4）

## Lesson

这一节是一个完整的 sign 逆向实战：以有道翻译的 sign 参数为目标，演示如何在不依赖任何 JavaScript 运行环境的前提下，仅用 Python 标准库 hashlib 把一段看似神秘的签名复现出来。整个流程分五步走——先从宏观上建立「抓包 → 定位 → 复现」的逆向心智模型，再深入 MD5 摘要算法和 hashlib 的具体用法，然后拆解动态时间戳生成和参数拼接规则这两个最容易踩坑的细节，接着回头审视完整的请求结构，理解 pointParam 字段如何告诉客户端哪些参数参与了签名，最后在收尾处把视野打开，对比「纯 Python 复现」与「execjs 混合路线」各自的适用场景。

这个节点的核心判断标准只有一个：当你能在 Python 脚本里独立生成一个有效的 sign，并用它成功换取到有道翻译的响应时，就算过关。所有后续的加密参数逆向——不管是更复杂的 AES 加密，还是下一节的 JS 执行路线——都建立在你对这套「定位 → 还原 → 复现」流程的熟练掌握之上。
