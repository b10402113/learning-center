# Hook 插件：函数与属性拦截监控

## Learning goal

用 hook 拦截并监控浏览器中的函数与属性，定位加密逻辑调用点、观察参数与返回值，并理解 hook 检测与反检测。

## Steps

2. [[learn/js-reverse/nodes/26-hook-interception/function-hook|函数的 hook：包裹原函数]] — 四步流程包裹函数、观察入参与返回值（after step 1）
3. [[learn/js-reverse/nodes/26-hook-interception/property-hook|对象属性的 hook：Object.defineProperty]] — 用 get/set 把属性读写变成监控入口，含不存在的属性（after step 1）
4. [[learn/js-reverse/nodes/26-hook-interception/browser-first-hook|浏览器先手 hook：atob 与 cookie]] — 在页面加载之前完成内置函数与 cookie 的 hook（after steps 2–3）
5. [[learn/js-reverse/nodes/26-hook-interception/hook-detection-bypass|Hook 检测与反检测]] — toString() 两级检测与两级破解的攻防逻辑（after step 4）

## Lesson

做 JS 逆向时最常遇到的处境是：你在某个网站里发现了一个加密函数（比如一个生成 sign 的 `add`），但你不知道它在哪些 JS 代码里被调用、每次传了什么参数、返回了什么。一个个文件去翻代码太慢。hook（钩子）就是为这个处境准备的技术——在不修改原代码、不改变调用方式的前提下，把原函数换成一个同名的新函数：新函数先打印参数，再调用真正的原函数拿到结果，打印结果，最后原样返回。调用方毫无察觉，你却看清了每一次调用。

这个「保存原函数 + 同名覆盖」的模式贯穿整个节点。函数如此，对象属性也如此——用 `Object.defineProperty` 把属性的读和写重新定义成带日志的 `get`/`set`，属性就变成了监控入口。但实战里最大的难题不是写法而是时机：网页一加载完，加密代码就跑完了，你的 hook 还没注入就晚了。所以浏览器环境下要用 DevTools 的 Script 事件监听抢在页面脚本之前暂停，再用 Snippets 注入 hook——这就是「先手 hook」。

最后一步是攻防的另一面：网站会反过来检测自己的函数有没有被 hook。手段是对函数调用 `toString()`——原生函数返回 `function atob() { [native code] }`，被 hook 后返回的是你的包裹函数源码，一眼就能分辨。破解是把 `toString` 也重写掉；对方再升级，用原型链上的 `Function.prototype.toString.call` 绕开实例上的重写；你再升级，重写原型链上的 `toString`。走完这五步，你就掌握了 hook 从概念、写法、时机到对抗的完整闭环——这是之后分析任何带加密逻辑的网站的起手式。
