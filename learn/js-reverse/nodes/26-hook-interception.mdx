# Hook 插件：函數與屬性攔截監控

## Learning goal

用 hook 攔截並監控瀏覽器中的函數與屬性，定位加密邏輯調用點、觀察參數與返回值，並理解 hook 檢測與反檢測。

2. [[learn/js-reverse/nodes/26-hook-interception/function-hook|函數的 hook：包裹原函數]] — 四步流程包裹函數、觀察入參與返回值（after step 1）

4. [[learn/js-reverse/nodes/26-hook-interception/browser-first-hook|瀏覽器先手 hook：atob 與 cookie]] — 在頁面加載之前完成內置函數與 cookie 的 hook（after steps 2–3）

## Lesson

做 JS 逆向時最常遇到的處境是：你在某個網站裡發現了一個加密函數（比如一個生成 sign 的 `add`），但不知道它在哪些 JS 代碼裡被調用、每次傳了什麼參數、返回了什麼。一個個文件去翻代碼太慢。hook（鉤子）就是為這個處境準備的技術——在不修改原代碼、不改變調用方式的前提下，把原函數換成一個同名的新函數：新函數先打印參數，再調用真正的原函數拿到結果，打印結果，最後原樣返回。調用方毫無察覺，你卻看清了每一次調用。

這個「保存原函數 + 同名覆蓋」的模式貫穿整個節點。函數如此，對象屬性也如此——用 `Object.defineProperty` 把屬性的讀和寫重新定義成帶日誌的 `get`/`set`，屬性就變成了監控入口。但實戰裡最大的難題不是寫法而是時機：網頁一加載完，加密代碼就跑完了，你的 hook 還沒注入就晚了。所以瀏覽器環境下要用 DevTools 的 Script 事件監聽搶在頁面腳本之前暫停，再用 Snippets 注入 hook——這就是「先手 hook」。

最後一步是攻防的另一面：網站會反過來檢測自己的函數有沒有被 hook。手段是對函數調用 `toString()`——原生函數返回 `function atob() { [native code] }`，被 hook 後返回的是你的包裹函數源碼，一眼就能分辨。破解是把 `toString` 也重寫掉；對方再升級，用原型鏈上的 `Function.prototype.toString.call` 繞開實例上的重寫；你再升級，重寫原型鏈上的 `toString`。走完這五步，你就掌握了 hook 從概念、寫法、時機到對抗的完整閉環——這是之後分析任何帶加密邏輯的網站的起手式。
