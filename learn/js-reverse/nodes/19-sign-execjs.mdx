# 实战：sign 逆向（JS 执行）

## Learning goal

用 execjs 执行 JS 版 sign 与 AES 解密，混合路线

## Steps

1. [[learn/js-reverse/nodes/19-sign-execjs/execjs-motivation|execjs 混合路线：什么时候该用 Python 调 JS？]] — 比较 Python 原生复现与 execjs 混合路线的适用边界
2. [[learn/js-reverse/nodes/19-sign-execjs/js-side-sign|JS 侧 sign 生成：crypto 模块与 createHash]] — 用 JS 重写 get_sign 函数（after step 1）
3. [[learn/js-reverse/nodes/19-sign-execjs/python-call-js-sign|execjs 编译与调用：Python 调 JS 拿 sign]] — 用 execjs.compile 调用 JS 函数完成请求（after step 2）
4. [[learn/js-reverse/nodes/19-sign-execjs/js-side-decrypt|JS 侧 AES 解密：crypto-js 与 createDecipheriv]] — 用 JS 重写 AES-128-CBC 解密（after step 3）
5. [[learn/js-reverse/nodes/19-sign-execjs/python-call-js-decrypt|Python 调 JS 解密：完整混合路线实战]] — 用 Python execjs 完成请求到解密的完整闭环（after step 4）

## Lesson

上一节我们用 Python 原生 hashlib 复现了有道翻译的 sign 生成，跑通了「纯 Python」路线。但现实中的加密逻辑往往更复杂：有的依赖浏览器内置对象，有的调用了 node 的 crypto 模块，有的甚至把关键函数藏在闭包里层层包装。这时候硬用 Python 去翻译每一行 JS，不仅费时，还容易踩到跨语言移植的坑。

execjs 提供了一条折中路线：让 Python 负责发请求、处理数据，把加密和解密逻辑原封不动地留在 JS 里，通过 execjs 在 Python 中直接调用 JS 函数。本节用有道翻译做完整演示——先写 JS 版 get_sign，再用 Python execjs 调用它生成 sign；接着写 JS 版 AES 解密，同样用 execjs 调用它解密响应。走完这五步，你就掌握了「Python 调 JS」的混合路线：什么时候该用、怎么用、和纯 Python 路线比有什么优劣。
