## Lesson

当你每天打开浏览器、输入网址、看到网页加载出来，背后发生的事其实很简单：你的浏览器向某个服务器发了一个 HTTP 请求，服务器收到后，把网页内容打包发回给浏览器，浏览器再把这些内容渲染成你能看懂的页面。爬虫要做的，就是让程序代替浏览器走同一条路——发请求、收响应、把想要的数据留下来。

requests 是 Python 里完成这件事最主流的第三方库。它的名字直接说明了用途：requests（请求）。安装之后，你只需要四行代码，就能把任意网页的源码搬回本地。这四行代码对应的就是 requests 爬虫最核心的**编码四流程**：指定 url → 发起请求 → 获取响应数据 → 持久化存储。

第一步，指定 url。url（Uniform Resource Locator，统一资源定位符）就是网址，它告诉程序「去哪个服务器、拿哪个页面」。比如 `http://www.eastmoney.com` 就是东方财富网的首页地址。

第二步，发起请求。用 `requests.get(url)` 这一行代码，程序就代替浏览器向服务器发了一个 GET 请求。GET 是最常见的 HTTP 请求方式，对应的是「我想看这个页面」这个动作。调用之后，服务器会返回一个 response 对象——你可以把它理解成寄回来的包裹，里面装着网页源码、状态码、headers 等所有服务器回应你的东西。

第三步，获取响应数据。response 对象身上有几个最常用的属性，它们各自回传不同格式的资料：`response.text` 回傳字串（str），拿到的是人類可讀的網頁原始碼或純文字；`response.content` 回傳二進位（bytes），是檔案的原始位元組，專門用來下載圖片、PDF 等非文字內容；`response.json()` 則直接把伺服器回傳的 JSON 字串反序列化成 Python 的字典或列表。絕大多數網頁爬蟲用的是 `response.text`，因為我們要的就是那堆 HTML 原始碼。

第四步，持久化存储。把拿到的数据写进文件、存进数据库，或者直接打印出来看一眼。对文本而言，最常见的就是 `with open('page.html', 'w', encoding='utf-8') as f: f.write(response.text)`。

但实际操作中，你很快会遇到第一个坑：中文乱码。伺服器回傳的原始資料本質上是一串數字，需要靠「編碼」（charset）這本密碼本翻譯成人類看得懂的文字。同樣的數字用不同密碼本翻譯，結果天差地遠——用 UTF-8 翻譯是「你好」，用 GBK 翻譯可能變成「浣犲傖」。很多中文網站的程式員偷懶，伺服器實際用 GBK 編碼寫網頁，卻在 HTTP 回應頭裡說謊——宣告自己是 UTF-8（或者乾脆不宣告）。requests 很聽話，伺服器說什麼編碼就用什麼編碼去翻譯，翻譯錯了就是一坨亂碼。解決辦法很暴力：直接用 `response.encoding = 'utf-8'` 覆蓋掉 requests 猜測的編碼，再存取 `response.text` 就是正常的中文了。這是寫爬蟲的第一條肌肉記憶：**一旦看到亂碼，先改 encoding**。

掌握了这四步，你就已经能写出一个最简单的爬虫：拿到任意网页的源码，存成本地文件。但这时候拿到的是一整页密密麻麻的 HTML 字符串，真正想要的——标题、价格、图片地址——还埋在裡面。要把它抠出来，就需要 xpath 这个工具，那是后面几课的事。本课先把「搬网页」这一步踩实。
