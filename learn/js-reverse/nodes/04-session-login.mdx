# Session、登入与代理

## Learning goal

cookie/session 自动管理、模拟登入、代理与验证码

## Lesson

这一节课把「会抓静态页面」升级成「能进入登录后的世界」。

第一个关键工具是 **Session 对象**。普通的 `requests.get()` 每次都带空 cookie 重新敲门，服务器会认不出你。Session 像一个持久化的浏览器标签：先发一次请求，把服务器下发的 Cookie 存进 Session，之后的请求自动携带它——不用手动复制、不用去抓包里翻 Cookie 字符串，也不用担心某次请求后 Cookie 突然变化。这是从「手动处理 Cookie」迈向「自动管理会话」的分水岭。

第二个关键是 **模拟登录的标准两次请求模型**：第一步，`session.post` 把账号密码交给登录接口，服务器回一个 Set-Cookie，Session 自动存下来；第二步，用同一个 Session 去请求需要登录才能访问的接口，服务器读到 Cookie 就知道你是刚登录的那个用户。整个流程里，Cookie 的生命周期完全由 Session 托管，你要做的只是把登录接口 URL 和表单字段名找对。

第三个关键是对抗 IP 黑名单：**代理服务器**。高频请求会被网站识别并把你的 IP 拉黑，使用代理后对方看到的是代理的 IP。代理按匿名度分三档——透明、匿名、高匿，高匿最推荐，因为它完全不暴露「我在用代理」这件事。按协议分 HTTP 和 HTTPS 两档，大多数爬虫场景需要 HTTPS。实战里单代理验证可用，大规模爬取则要上代理池：把一堆代理 IP:端口装进列表，每次随机选一个配合 `time.sleep()` 错开请求间隔，避免同一 IP 瞬间刷太多被封。

最后是 **验证码**。当网站开始弹验证码，纯请求模拟通常就到了天花板，此时工程上的标准解法是接打码平台：把验证码图片 base64 编码后 POST 到平台接口，按 `typeid` 告诉平台这是纯数字、计算题、坐标点选还是缺口识别，平台返回文字或坐标你再用。这是后续学习滑块、缺口验证码逆向前的先修认知——先知道「能买到什么服务」，再决定「要不要逆向」。

这四个知识点串在一起，你的爬虫工具链就从「能抓公开页面」升级成「能登录、能换 IP、能应付基础验证」，足以应付大多数需要登录的网站。
