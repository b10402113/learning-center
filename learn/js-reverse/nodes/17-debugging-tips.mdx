# DevTools 断点与逆向技巧

## Learning goal

呼叫堆叠回溯、关键字搜寻、加密值三大藏身处

## Steps

1. [[learn/js-reverse/nodes/17-debugging-tips/call-stack-backtrace|请求堆叠回溯]] — 从请求发送入口逐层向上回溯呼叫堆栈，定位加密函数在代码中的真实位置
2. [[learn/js-reverse/nodes/17-debugging-tips/encrypted-value-hiding-spots|加密值三大藏身处]] — 列出加密值在 HTTP 请求中最可能出现的三种位置，优先检查这三个地方（after step 1）
3. [[learn/js-reverse/nodes/17-debugging-tips/keyword-search|关键字搜寻]] — 在呼叫堆栈过深或代码被混淆时，用关键字搜索作为备选入口定位加密参数（after step 2）
4. [[learn/js-reverse/nodes/17-debugging-tips/youdao-packet-capture|有道翻译抓包实战]] — 用 requests 复刻有道翻译的完整 POST 请求，并识别出请求体中不可复用的动态参数（after step 3）

## Lesson

这一节把「抓到一个请求之后怎么找加密参数」拆成四步走。先从浏览器 DevTools 的 Call Stack 面板出发，把请求发送入口当作起点，沿着函数调用链一层层向上回溯，直到找到真正执行加密的那段代码。当调用栈过深或者代码被混淆时，关键字搜索就是你的第二把钥匙——用参数名、URL 路径、或者 md5、sha1、encrypt 这些敏感词直接定位代码位置。

但找到加密逻辑之前，你首先得知道去哪里翻。所以第二步会先建立「加密值三大藏身处」的心智模型：查询参数与 form 数据里、请求头里、cookie 里。抓到请求之后，不用把整个请求体从头看到尾，先检查这三个位置，通常就能锁定目标。

最后用一个真实案例把前面三套串起来：用 requests 复刻有道翻译的完整 POST 请求，硬编码抓包值跑通，然后亲眼看到 sign 和 mysticTime 这两个动态参数在第二次请求时失效。这一步同时也在为下一节的 sign 逆向埋下伏笔——你现在已经知道要逆的是哪个参数了。
