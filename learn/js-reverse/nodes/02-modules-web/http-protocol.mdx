<LearningGoal>
理解 HTTP 是浏览器与服务器之间的请求-响应协议，拆解请求报文与响应报文的字段，并明白"无状态"为什么意味着服务器默认不记得你是谁。
</LearningGoal>

## Lesson

打开浏览器访问一个网站，本质上是浏览器向服务器发一个请求，服务器再返回一个响应。HTTP（Hyper Text Transfer Protocol，超文本传输协议）就是这套"请求-响应"的规矩。

常见的应用分两类：一类是需要安装的桌面客户端（C/S，Client/Server），比如腾讯视频客户端连机房服务器；另一类是浏览器直接访问的网站（B/S，Browser/Server），比如百度、知乎。B/S 架构里，浏览器就是一种特殊的客户端——爬虫就是在模拟浏览器，跟 B/S 里的服务器打交道。

HTTP 的第一条特性：**请求只能由客户端发出，服务器收到请求后才响应**。服务器不会主动把数据推给你。这意味着你在 DevTools 里看到的每一个操作（点击、翻页、提交表单），都对应一对 request/response。

HTTP 的第二条特性（重要）：**协议自身不保存通信状态**。每次请求都是全新——服务器不记得上一次是谁、做了什么。就像每次进一家新店，店员都把你当陌生人。无状态是刻意设计的：为了更快处理大量事务、保证可伸缩性。但这也带来一个问题：登录后翻页，服务器怎么知道你还是你？这就催生了 Cookie 技术。

客户端发给服务器的报文分两部分：

- **请求头（Request Headers）**：请求的"自我介绍"，服务器据此获取客户端信息。
- **请求体（Request Body）**：将要发送给服务器的数据（GET 请求通常没有请求体）。

常用请求头字段：

| 字段 | 作用 |
| --- | --- |
| User-Agent | 请求载体的身份标识（什么浏览器、什么系统） |
| Referer | 表明来源页面（防盗链） |
| X-Requested-With | 值为 XMLHttpRequest 代表 ajax 访问 |
| Content-Type | 请求体的数据类型（如 application/json） |

GET 与 POST 的对比：

|  | GET | POST |
| --- | --- | --- |
| 数据位置 | URL 后面，用 ? 分隔、& 相连 | 请求体中 |
| 大小限制 | 受 URL 长度限制 | 无限制 |
| 可见性 | 明文拼在 URL 里 | URL 里看不到 |
| 常见用途 | 查询、翻页 | 登录、提交表单、上传文件 |

服务器回给客户端的报文也分两部分：

- **响应头（Response Headers）**：告诉浏览器怎么处理数据。
- **响应体（Response Body）**：实际返回的数据（HTML、JSON、图片等）。

常用响应头字段：

| 字段 | 作用 |
| --- | --- |
| Content-Type | 回送的数据类型（text/html、application/json） |
| Location | 告诉浏览器跳到哪里（重定向） |
| Set-Cookie | 服务器下发 Cookie（后面详细讲） |

响应状态码：

| 状态码 | 含义 |
| --- | --- |
| 200 | 成功 |
| 301/302 | 重定向 |
| 403 | 禁止访问（可能被反爬） |
| 404 | 找不到页面 |
| 500 | 服务器内部错误 |
