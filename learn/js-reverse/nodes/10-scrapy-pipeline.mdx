# Scrapy 管道与持久化

## Learning goal

Item 封装、Pipeline 三方法、多管道与资料库储存

## Steps

1. [[learn/js-reverse/nodes/10-scrapy-pipeline/item-pipeline-basics|Item 封装与 Pipeline 三方法]] — 掌握 items.py 定义字段、yield 提交、process_item / open_spider / close_spider 三方法
2. [[learn/js-reverse/nodes/10-scrapy-pipeline/multi-pipeline-storage|多管道优先级与数据库存储]] — 用多个管道类把同一份数据分别存到文件、MySQL、Redis（after step 1）
3. [[learn/js-reverse/nodes/10-scrapy-pipeline/builtin-pipelines|内置管道 FilesPipeline 与 ImagesPipeline]] — 用 scrapy 自带管道下载图片与文件二进制资源（after step 1）
4. [[learn/js-reverse/nodes/10-scrapy-pipeline/pipeline-integration|完整管道项目整合]] — 把多管道与内置管道组合成一个真实可跑的图片落地项目（after steps 2–3）

## Lesson

这一节把 Scrapy 里"数据落地"这件事拆成四个步骤。先从管道最根本的机制讲起——items.py 怎么定义字段、pipelines.py 里三个方法（process_item / open_spider / close_spider）各自在什么时候被调用、为什么 process_item 必须 return item 才能把数据传给下一个管道。搞清楚这个地基之后，再分两条线展开：一条是"多管道"——同一个 item 怎么同时写文件、写 MySQL、写 Redis，靠优先级数字控制流转顺序；另一条是"内置管道"——scrapy 自带的 FilesPipeline 和 ImagesPipeline 怎么靠约定字段驱动，批量下载图片和文件二进制资源。最后一步把两条线合起来，搭一个能跑通的完整项目：列表页进详情页、解析字段交管道、图片走 ImagesPipeline、元数据走多管道分别落盘数据库与文件。走完这四步，你就掌握了 Scrapy 从"爬到数据"到"把数据存到任何载体"的完整链路。
