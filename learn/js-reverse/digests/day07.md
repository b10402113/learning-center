# Digest — js逆向课件/day07

## Overview (L1)

- **核心概念（进程/线程）**：用工厂类比理解——CPU 是工厂（单核一次只能运行一个任务），进程是车间（CPU 所处理的单个任务），线程是车间里的工人（一个进程可含多个线程），车间空间被工人共享即进程内存空间被其所有线程共享。
- **进程与进程调度**：进程是操作系统中正在运行的应用程序，是资源分配与执行的基本单元；多进程"同时"运行靠调度算法实现，公认较好的是时间片轮转法（多级就绪队列、优先级越高时间片越小、用完未完成逐级下移）。
- **并发与并行**：并行=多 CPU 同时运行；并发=伪并行（时间片轮转切换，看起来同时）；关键区别是是否"同时"。吃饭接电话的类比帮助记忆。
- **进程状态与同步异步**：进程有就绪、运行、阻塞、终止四态，阻塞由网络请求、input 等耗时操作引起；同步=必须等前一步执行完才做下一步，异步=步骤一旦发起不等结束就做下一步；异步大多基于并发而非并行。
- **multiprocessing.Process**：主进程中用 Process(target=func, args=...) 创建子进程、start() 启动，即可实现异步；join() 让主进程等待子进程结束（须先 start 全部再逐个 join）；进程间数据完全隔离不共享；守护进程（daemon=True，须在 start 前设置）随主进程代码结束而终止且不能再开子进程。
- **线程与线程池**：threading.Thread 创建线程的 API 与 Process 一致；同进程内线程共享资源、线程创建开销远小于进程；join/守护线程语义与进程相同；线程池（multiprocessing.dummy.Pool）复用线程避免反复创建销毁，pool.map(func, iterable) 批量派发任务。
- **协程**：单进程/单线程下大幅提升效率的思路——自己主动监测阻塞环节并在其间切换执行，让就绪态增多以"迷惑"操作系统多分 CPU，本质是想办法把 CPU 留在自己的程序里。

## Sections (L2)

### 通俗理解并发编程中的相关核心概念

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#通俗理解并发编程中的相关核心概念]]`
- Summary: 用工厂类比建立进程与线程的直觉模型：CPU 是工厂、进程是车间、线程是车间里的工人。
- Key claims: CPU 承担所有计算任务，单核 CPU 同一时刻只能运行一个任务（如工厂电力一次只供一个车间）；进程代表 CPU 所能处理的单个任务；一个进程可以包括多个线程；一个进程的内存空间被该进程下所有线程共享，每个线程都可使用这些共享内存；大部分情况下多核计算机也只用一核。
- Learner-relevant: 用一个可长期复用的心智模型（工厂-车间-工人）为后面所有并发概念打底。

### 什么是进程

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#什么是进程]]`
- Summary: 给出进程的广义与狭义定义，并说明启动应用程序即操作系统开启进程并分配内存/资源。
- Key claims: 广义定义：进程是具有一定独立功能的程序关于某数据集合的一次运行活动，是操作系统动态执行的基本单元，既是基本分配单元也是基本执行单元；狭义定义：一个正在运行的应用程序在操作系统中被视为一个进程；每启动一个应用就是 OS 开一个进程并为其分配内存/资源；py1 和 py2 两个文件同时运行就是两个进程。
- Learner-relevant: 能准确说出"进程=运行中的程序+其占用的资源"这一定义，为后续进程/线程选择打基础。

### 进程调度

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#进程调度]]`
- Summary: 解释单 CPU 下能"同时"聊微信听音乐打游戏的原因是进程交替运行，并详解公认较好的时间片轮转法。
- Key claims: CPU 在交替运行多个进程，调度需遵循调度算法；已实现的算法有先来先服务（FCFS）、短作业优先、时间片轮转法，公认较好者是时间片轮转法；时间片轮转法：OS 创建多个就绪队列并赋予不同优先级，优先级越高的队列时间片越小（如第二队列时间片比第一队列长一倍）；新进程先入第一队列末尾，一个时间片内完成则准备撤离，未完成则转入下一队列末尾，依次下移。
- Learner-relevant: 理解"同时"的假象由调度产生，为并发 vs 并行的辨析做好铺垫。

### 并发与并行

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#并发与并行]]`
- Summary: 辨析并发与并行：并行要求多 CPU 真同时，并发是时间片轮转产生的伪并行；用户看来二者都"同时"。
- Key claims: 并行=同时运行，只有具备多个 CPU 才能实现；并发=伪并行，即看起来同时运行（时间片轮转法）；无论并行还是并发，用户看来都是"同时"运行；真实干活的是 CPU，而一个 CPU 同一时刻只能执行一个任务；吃饭类比：吃完才接电话=既不并发也不并行，停下接完再吃=并发，边吃边接=并行；并发的关键是有处理多个任务的能力（不一定同时），并行的关键是有同时处理多个任务的能力。
- Learner-relevant: 能用"是否同时"一句话区分并发/并行，这是并发编程最常被考察的概念辨析。

### 进程的状态

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#进程的状态]]`
- Summary: 列出程序运行中被调度算法控制所经历的四态：就绪、运行、阻塞、终止，并说明各态触发条件。
- Key claims: 就绪（Ready）=进程已准备好、已分配到所需资源/内存；运行（Running）=就绪态被调度后进入执行；阻塞（Blocked）=因某些事件暂时无法运行，需等待系统调用，典型来源是网络请求、input 等耗时操作；终止=进程结束、出错或被系统终止，无法再执行。
- Learner-relevant: 认识"耗时操作=阻塞"这一对应关系，它是后面同步/异步和协程概念的支点。

### 同步和异步

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#同步和异步]]`
- Summary: 辨析同步与异步：同步必须等前一步执行完才做下一步，异步发起步骤后不等待就继续；并用做饭案例说明阻塞操作下的不同行为。
- Key claims: 同步=任务每个步骤顺序执行且必须前一步完毕才执行下一步；异步=步骤仍顺序发起，但一旦某步骤被执行，无论是否结束都马上执行下一步；做饭案例中烧水/煮饭/炒菜都是耗时操作，即阻塞操作；同步/异步针对的是 CPU 执行任务遇到阻塞操作时产生的不同行为；异步可基于并行也可基于并发，但大部分情况下基于并发；实现异步的具体操作是进程、线程和协程。
- Learner-relevant: 建立异步的本质认知——不傻等阻塞，转而去干别的；这是爬虫提速（多进程/多线程/协程）的理论起点。

### Python进程的实现

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#Python进程的实现]]`
- Summary: multiprocessing 包 Process 模块的完整实操：创建/启动子进程、args 传参、用进程实现异步、join 等待、进程数据隔离实验及守护进程。
- Key claims: 运行的 py 文件是主进程，基于 Process 创建的是子进程，两进程即可实现异步；用法为 Process(target=func, args=(参数,)) + p.start()，须放在 if __name__ == '__main__' 中；同步串行三个 2 秒任务总耗时约 6 秒，改成每任务一个子进程则约 2 秒；join 让主进程等待调用 join 的子进程结束后再结束，正确写法是先 start 所有子进程再逐个 join（循环内边 start 边 join 是错的）；进程间数据完全隔离不共享——子进程中的全局变量是主进程变量的拷贝，修改不影响主进程，跨进程传值需进程通信机制（管道、信号量等，了解即可）；守护进程 p.daemon=True 必须在 start 前设置，主进程代码执行结束守护进程随即终止，且守护进程内无法再开启子进程（否则抛 AssertionError）。
- Learner-relevant: 能用 Process 写出异步爬虫骨架，理解 join 的正确位置与进程数据隔离陷阱（子进程改不了主进程变量）。

### 基本概念

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#基本概念]]`
- Summary: 定义线程为操作系统运算调度的最小单位，并给出线程相对进程的三个关键特性。
- Key claims: 线程是操作系统能够进行运算调度的最小单位（车间里的工人），被包含在进程之中，是进程中的实际运作单位；同一进程内的多个线程共享该进程的资源，不同进程内的线程资源隔离；创建线程的开销比创建进程小得多；每个进程至少包含一个线程，称为主线程；CPU 资源充足时一个进程内的多个线程可被分配到不同 CPU 实现并行，但分配由操作系统实现、不可人为控制。
- Learner-relevant: 掌握进程 vs 线程的选型依据——要共享数据用线程、要隔离用进程，线程更轻量。

### Python实现线程

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#Python实现线程]]`
- Summary: threading 模块的实操：Thread 创建/启动、join、线程内存数据共享验证、守护线程及多线程异步效果。
- Key claims: Python 多线程模块推荐 threading（比 thread 先进、支持更完善）；创建线程 Thread(target=func, args=(1,)) + t.start()，也可继承 Thread 重写 run 方法；join 语义与进程相同；线程共享内存——子线程将全局变量 n 改为 0 后主线程读到的就是 0（与进程数据隔离形成对照）；守护线程 t.daemon=True，主线程运行完毕后被销毁，无论守护线程是否执行结束；多线程对 5 个 2 秒任务并发请求总耗时约 2 秒。
- Learner-relevant: 能对照 Process 语法快速上手 Thread，并记住与进程最大的差异——线程共享全局变量。

### 线程池

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#线程池]]`
- Summary: 讲解线程池的动机（复用线程省去反复创建销毁的开销）与 multiprocessing.dummy.Pool 的用法。
- Key claims: 线程预先创建放入池中，处理完当前任务后不销毁而是接下一个任务，从而避免多次创建线程、节省创建销毁开销，带来更好性能和系统稳定性；线程池模块从 multiprocessing.dummy 导入 Pool；用法为 Pool(5) 创建含 5 线程的池，pool.map(func, urls) 批量派发——func 调用次数取决于可迭代对象元素个数，每次接收一个元素作为参数；用完 pool.close() 释放。
- Learner-relevant: 掌握 pool.map 这一爬虫批量请求的最常用写法，理解池化复用为何比裸建线程稳定。

### 协程（重要！）

- Locator: `[[sources/js-reverse/20260908/js逆向课件/day07/并发编程.md#协程（重要！）]]`
- Summary: 阐述协程的动机与原理：把多个下载任务封装进单个进程/线程，自己主动监测阻塞环节并在其间切换，使就绪态增多从而让操作系统多分配 CPU，在单进程/单线程下大幅提升效率。
- Key claims: 协程可实现在单进程或单线程模式下大幅提升程序运行效率；多进程/多线程下载网页的问题：系统中还有大量其他进程/线程，CPU 切换由操作系统实现、无法人为干涉，不一定切回下载任务，效率打折；协程做法：所有下载任务封装在一个进程/线程中，主动监测所有阻塞环节、让 CPU 在阻塞环节间切换执行，使该任务就绪态增多、迷惑操作系统，使其以为该任务阻塞少而尽可能多分配 CPU；总而言之是想尽一切办法留住 CPU 在自己的程序中。
- Learner-relevant: 理解协程"单线程内自主切换、把 CPU 留在自己程序里"的核心价值，为后续异步爬虫（如 asyncio/gevent）的学习铺好理论底座。
