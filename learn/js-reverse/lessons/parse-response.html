Response 解析与终端运行

Scrapy 框架入门 · Step 3/4

Learning goal

掌握 response.xpath 返回 Selector 对象的机制，区分 extract 与 extract_first 的取舍，并能用 scrapy crawl 运行爬虫、读懂终端日志。

Lesson

Spider 的 parse 方法拿到的是一个 response 对象，它不是纯文本，而是 Scrapy 封装好的响应体。要从中提取数据，最常用的是 response.xpath()。

response.xpath 返回的不是字符串

这是新手最容易踩的坑。response.xpath('//title/text()') 返回的是一个 Selector 对象列表，不是字符串，也不是字符串列表。数据藏在 Selector 对象的 data 属性里，必须用 extract() 或 extract_first() 把它取出来。

extract 与 extract_first

方法返回值适用场景
extract()字符串列表（所有匹配结果）匹配到多个节点
extract_first()单个字符串（第一个匹配结果）只取第一个节点
def parse(self, response):
    # 取页面标题（只有一个）
    title = response.xpath('//title/text()').extract_first()

    # 取所有链接（多个）
    links = response.xpath('//a/@href').extract()

经验法则：列表里只有一个元素时用 extract_first()，否则用 extract()。

为什么 Element 选项卡的 xpath 可能拿不到数据

浏览器 DevTools 的 Element 选项卡显示的是渲染完成后的 DOM，而 Scrapy 拿到的是服务器返回的原始响应。如果页面用 JavaScript 动态渲染，Element 里看到的节点在原始 HTML 里根本不存在。

正确做法：在 DevTools 的 Network 面板里找到对应的请求，看它的 Response 内容，或者用 Scrapy 的 response.text 直接打印原始 HTML，再写 xpath。

运行爬虫

在项目根目录执行：

scrapy crawl baidu

终端会打印大量日志：请求的 URL、响应状态码、下载速度、数据统计。这是 Scrapy 在告诉你它正在干什么。

settings 三项关键配置

默认的 Scrapy 项目跑起来会弹很多警告，也容易被网站拦截。打开 settings.py，改三行：

# 不遵从 robots.txt 协议
ROBOTSTXT_OBEY = False

# 只显示错误级别日志，减少刷屏
LOG_LEVEL = 'ERROR'

# 指定 User-Agent，伪装成浏览器
USER_AGENT = 'Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7)'

改完再跑 scrapy crawl baidu，终端会干净很多。

终端日志怎么看

  • [scrapy.core.engine] DEBUG: Crawled (200) — 请求成功，状态码 200。
  • [scrapy.core.engine] DEBUG: Crawled (404) — 页面不存在。
  • [scrapy.statscrawler] INFO: Dumping Scrapy stats — 爬取结束后的统计摘要。
