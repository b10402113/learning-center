Ajax 前端演示頁

Node 13 · Step 3 / 4 · 預估 15–18 分鐘

Learning goal

看懂 jQuery $.ajax 的事件驅動流程：點擊觸發 → 非同步請求 → 回調函式 → DOM 更新，並在 DevTools Network 面板裡辨識出對應的 XHR 請求。

Lesson

上一課我們架好了靶站，這一次要寫前端頁面，讓 JavaScript 在背後對 /books 發 Ajax 請求。關鍵不是 jQuery 本身，而是背後的「事件驅動」模型：程式不會從上往下跑到底，而是等使用者做了某個動作（點擊、輸入、滾動），才觸發對應的程式碼。

事件驅動：點一下才做事

傳統程式像食譜：第一步、第二步、第三步，照順序跑。JavaScript 在瀏覽器裡不是這樣。它像一個接線生：電話響了（事件發生），才拿起話筒（執行對應的函式）。沒事的時候，它什麼都不做。

最常見的事件是點擊。我們用 onclick 把一個函式綁到 DOM 元素上：

var btn = document.getElementById("load-btn");
btn.onclick = function() {
    // 點擊後才執行這裡的程式碼
    console.log("被點了");
};

在 onclick 裡面，我們放的就是「被點擊後要做的動作」—— 也就是發 Ajax 請求。

jQuery 的 $.ajax 封裝

jQuery 是一套古老的 JavaScript 函式庫，它把各家瀏覽器不同的 Ajax API 統一成一個簡單的 $.ajax() 呼叫。一個最簡單的 GET 請求長這樣：

$.ajax({
    url: "/books",
    type: "get",
    success: function(res) {
        console.log(res);
    }
});

三個參數各自的角色：

  • url: "/books"：對準哪個伺服器路徑。因為是相對路徑，瀏覽器會自動補上目前頁面的域名和埠號，變成 http://127.0.0.1:5000/books。
  • type: "get"：HTTP 方法。這裡是 GET，代表「我要拿資料」。
  • success: function(res) {...}：回調函式（callback）。伺服器成功回應後，Flask 回傳的 JSON 會自動解析成 JavaScript 陣列，放進 res 參數裡。

回調函式是 Ajax 最核心的概念。因為請求是非同步的，你不能寫「等它回來再繼續下一行」；你必須把「回來之後要做的事」包成一個函式，交給 success 參數。伺服器回應時，jQuery 會自動呼叫它。

把資料塞回畫面：DOM 操作

拿到 res（一個 JavaScript 陣列）之後，我們要把書名顯示在畫面上。jQuery 提供了一堆 DOM 操作的方法，這裡用的是 .html()：

success: function(res) {
    var text = res.join(",");          // 把陣列用逗號接成字串
    $("p").eq(2).html(text);           # 選第三個 
，把內容換成書名
}

$("p").eq(2) 用 CSS _selector_ 選出所有 <p> 標籤，再用 .eq(2) 取第三個（索引從 0 開始）。.html(text) 把這個 <p> 的內部 HTML 換成書名字串。

整個流程跑起來像這樣：

  1. 使用者點擊頁面上的段落。
  2. jQuery 對 /books 送出 GET 請求。
  3. Flask 收到請求，隨機抽 4 本書，回傳 JSON。
  4. jQuery 收到回應，自動把 JSON 解析成 JavaScript 陣列。
  5. success 回調被觸發，把書名用逗號接起來，塞進第三個 <p>。

從頭到尾，瀏覽器沒有換頁、沒有刷新。資料是「長」在原本頁面裡的。

在 DevTools 裡看到這一幕

打開 Chrome DevTools（F12），切到 Network 面板，重新整理頁面。你會看到：

  • 第一個請求是 index.html（Document 類型），回應是完整 HTML。
  • 點擊頁面之後，多了一個 books 請求（XHR 類型），回應是 JSON。

點開 books 請求，看它的 Headers：

Request URL: http://127.0.0.1:5000/books
Request Method: GET
Status Code: 200 OK

再看 Response：

["三體","銀河帝國","沙丘","基地"]

這就是 Ajax 請求的全部真相：一個 GET 請求，URL 是 /books，回應是 JSON 陣列。沒有魔法，就是這樣。

login.html 的對照：同步表單

為了讓你明確感受同步和非同步的差異，示範頁還附了一個 login.html：

<form action="/login" method="post">
    <input name="username">
    <input name="password" type="password">
    <button type="submit">登入</button>
</form>

按下「登入」之後，瀏覽器會把表單資料包成 POST 請求，整個頁面跳轉到 /login 的回應。你在 DevTools 會看到一個 Document 請求，回應是新的 HTML。這就是同步全覆盖。

對比之下，Ajax 的 /books 請求不會讓頁面跳轉，回應也不是 HTML，而是純資料。這就是為什麼爬蟲要分「同步」和「非同步」—— 它們的回應格式、URL 尋找方式完全不同。
