内置管道 FilesPipeline 与 ImagesPipeline

Scrapy 管道与持久化 · 步骤 3/4

学习目标

理解 scrapy 自带的 FilesPipeline 和 ImagesPipeline 的差异，掌握"约定字段驱动"与"重写方法驱动"两种模式，并能独立写出图片下载项目。

普通管道 vs 内置管道

上一节讲的管道都是"普通管道"——你自己写一个类，在 process_item 里手动处理 Item。这种方式灵活，但写起来啰嗦：你要自己发请求、自己处理二进制数据、自己写文件。

Scrapy 为二进制资源下载这个高频场景提供了两个现成的管道类：

管道适用场景驱动方式
ImagesPipeline图片、音频、视频等二进制文件重写三个方法
FilesPipeline普通文件（PDF、ZIP、Excel 等）约定字段驱动

两者最大的区别是驱动方式：ImagesPipeline 需要你重写三个方法来告诉它"怎么请求、怎么命名、怎么传下去"；FilesPipeline 则更"懒"——你只需要在 Item 里填好约定的字段，它自动下载、自动命名。

ImagesPipeline：重写三方法的图片下载管道

ImagesPipeline 是 scrapy 自带的图片下载管道。它的核心思路是：你告诉它图片链接在哪里、文件名叫什么、下载完怎么传给下一个管道，剩下的事情它全包了。

第一步：安装 Pillow（图片处理库，ImagesPipeline 依赖它）：

pip install pillow

第二步：在 items.py 里定义 Item，并加入图片相关字段：

# items.py
import scrapy

class ImageItem(scrapy.Item):
    title = scrapy.Field()
    image_url = scrapy.Field()      # 图片链接
    image_path = scrapy.Field()     # 下载后的本地路径（管道自动填）

第三步：自定义一个继承自 ImagesPipeline 的类，重写三个方法：

# pipelines.py
from scrapy.pipelines.images import ImagesPipeline
from scrapy.http import Request

class MyImagesPipeline(ImagesPipeline):

    def get_media_requests(self, item, info):
        """对图片地址发起请求，返回二进制数据"""
        url = item['image_url']
        yield Request(url)

    def file_path(self, request, response=None, info=None, *, item=None):
        """指定保存文件名"""
        # 用 title 做文件名，避免重复
        title = item['title']
        return f'full/{title}.jpg'

    def item_completed(self, results, item, info):
        """把 item 传给下一个管道"""
        # results 是一个列表，包含每个请求的下载结果
        for ok, value in results:
            if ok:
                item['image_path'] = value['path']
        return item

三个方法的职责：

  • get_media_requests(item, info)：告诉管道要下载哪张图片。对每个图片链接 yield 一个 Request。
  • file_path(request, response=None, info=None, *, item=None)：告诉管道文件叫什么名字、放在哪个子目录。
  • item_completed(results, item, info)：下载完成后调用，通常把下载结果（本地路径）写回 Item，然后 return item 传给下一个管道。

第四步：在 settings.py 里配置存储路径和缩略图：

# settings.py
IMAGES_STORE = 'girlsLib'  # 图片保存根目录
IMAGES_THUMBS = {
    'small': (50, 50),
    'big': (270, 270)
}

ITEM_PIPELINES = {
    'myproject.pipelines.MyImagesPipeline': 300,
}

IMAGES_THUMBS 会自动生成缩略图：'small': (50, 50) 表示生成 50x50 的小图，'big': (270, 270) 表示生成 270x270 的大图。原图也会保留。

FilesPipeline：约定字段驱动的文件下载管道

FilesPipeline 和 ImagesPipeline 类似，但更"傻瓜"。它的规则是：你只需要在 Item 里提供两个字段——file_urls（下载链接列表）和 files（下载结果，管道自动填）——管道就会自动下载并填充结果。

# pipelines.py
from scrapy.pipelines.files import FilesPipeline

class MyFilesPipeline(FilesPipeline):

    def file_path(self, request, response=None, info=None, *, item=None):
        """指定保存文件名"""
        # 从 URL 里提取文件名
        return request.url.split('/')[-1]

Item 必须包含这两个字段：

# items.py
class DocItem(scrapy.Item):
    title = scrapy.Field()
    file_urls = scrapy.Field()   # 必须：下载链接列表
    files = scrapy.Field()       # 必须：管道自动填下载结果

Spider 把链接放进 file_urls：

# spiders/doc.py
def parse(self, response):
    item = DocItem()
    item['title'] = response.xpath('//h1/text()').extract_first()
    item['file_urls'] = response.xpath('//a/@href').extract()
    yield item

settings.py 配置：

# settings.py
FILES_STORE = 'docs'

ITEM_PIPELINES = {
    'myproject.pipelines.MyFilesPipeline': 300,
}

FilesPipeline 和 ImagesPipeline 最大的区别是：FilesPipeline 靠约定字段驱动（你填 file_urls，它自动下载），而 ImagesPipeline 靠重写方法驱动（你告诉它每一步怎么做）。

两者选哪个？

  • 只下载图片：两者都行。ImagesPipeline 更专业（支持缩略图、自动去重），FilesPipeline 更简单（不用重写方法）。
  • 下载音频、视频：用 ImagesPipeline，因为它支持任意二进制文件。
  • 下载普通文件（PDF、ZIP）：用 FilesPipeline，配置少，开箱即用。
  • 需要自定义命名规则：两者都支持重写 file_path。

常见踩坑

  • 没装 Pillow：ImagesPipeline 依赖 Pillow，没装就直接报错。
  • FilesPipeline 的 Item 缺少 file_urls 或 files 字段：管道会直接跳过，不下载任何东西。
  • 图片链接是相对路径：ImagesPipeline 和 FilesPipeline 都需要完整 URL。相对链接要先用 response.urljoin() 补全。
  • IMAGES_STORE 或 FILES_STORE 没配：图片/文件没地方存，管道会报错。
