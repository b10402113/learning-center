crypto-js AES 解密与 iv=key 模式

实战：DES/AES 案例 · 步骤 4/4

学习目标

逐行拆解 crypto-js AES 解密的完整 API 链，理解 iv=key 这种简化模式在逆向中的识别特征，能独立写出 AES-CBC 解密函数。

解密函数全貌

上一课我们调用了 decrypt_data 函数来解密毛毛租的响应。现在打开 04 mmz.js，逐行读：

cryptoJs = require("crypto-js")

function d(e, a) {
    e = cryptoJs.enc.Utf8.parse(e);
    var l = cryptoJs.AES.decrypt(a, e, {
        mode: cryptoJs.mode.CBC,
        padding: cryptoJs.pad.Pkcs7,
        iv: e
    });
    return cryptoJs.enc.Utf8.stringify(l).toString()
}

function decrypt_data(data) {
    e = '0a1fea31626b3b55'
    return d(e, data)
}

外层函数：decrypt_data

function decrypt_data(data) {
    e = '0a1fea31626b3b55'
    return d(e, data)
}

这个函数很简单：把密钥 '0a1fea31626b3b55' 赋值给变量 e，然后调用内层函数 d(e, data)。密钥是 16 个字符，对应 AES-128 的 16 字节密钥。

内层函数：d

function d(e, a) {
    e = cryptoJs.enc.Utf8.parse(e);
    var l = cryptoJs.AES.decrypt(a, e, {
        mode: cryptoJs.mode.CBC,
        padding: cryptoJs.pad.Pkcs7,
        iv: e
    });
    return cryptoJs.enc.Utf8.stringify(l).toString()
}

这个函数接受两个参数：e 是密钥，a 是密文。

第一行：解析密钥

e = cryptoJs.enc.Utf8.parse(e);

和 CryptoJS 一样，cryptoJs.enc.Utf8.parse() 把字符串密钥转成 WordArray。注意这里把解析后的结果赋值回 e，后面的 iv: e 用的也是这个解析后的值。

第二行：执行解密

var l = cryptoJs.AES.decrypt(a, e, {
    mode: cryptoJs.mode.CBC,
    padding: cryptoJs.pad.Pkcs7,
    iv: e
});

cryptoJs.AES.decrypt() 接受三个参数：密文、密钥、配置项。注意这里的 iv 直接用了密钥 e——这就是 iv=key 模式。

加密模式：CBC

mode: cryptoJs.mode.CBC,

CBC（Cipher Block Chaining，密码分组链接） 是最常用的分组加密模式。每个明文块在加密前会先与前一个密文块做异或（XOR），第一个块则与 IV 做异或。

这样做的好处是：即使明文中有重复的块，加密后的密文也不会重复，安全性远高于 ECB。

填充方式：Pkcs7

padding: cryptoJs.pad.Pkcs7,

和 DES 一样，AES 也要求明文长度是 16 字节的整数倍。Pkcs7 的填充规则是：缺几个字节就填几个该数字。

iv=key 模式

iv: e

这里 iv 直接等于密钥 e。这是一种简化模式，虽然不够安全，但在逆向中很常见——开发者为了省事，直接把 key 当 iv 用。

识别特征很明确：解密函数的 iv 参数和 key 参数是同一个值。

第三行：输出明文

return cryptoJs.enc.Utf8.stringify(l).toString()

decrypt() 返回的是 WordArray。cryptoJs.enc.Utf8.stringify() 把 WordArray 按 UTF-8 解码成字符串，再 .toString() 确保返回的是普通字符串。

完整 API 链

把整条链串起来：

密钥字符串 ──parse──▶ 密钥 WordArray ──┬──▶ iv
                                      │
                                      └──▶ key ──┐
                                                ├──▶ AES.decrypt() ──stringify──▶ 明文
密文字符串 ────────────────────────────────────────┘

独立写出 AES-CBC 解密函数

理解了 API 链后，你应该能独立写出类似函数：

function aesDecrypt(ciphertext, key) {
    // 1. 解析密钥
    var keyHex = cryptoJs.enc.Utf8.parse(key);
    // 2. 执行解密
    var decrypted = cryptoJs.AES.decrypt(
        ciphertext,
        keyHex,
        {
            mode: cryptoJs.mode.CBC,
            padding: cryptoJs.pad.Pkcs7,
            iv: keyHex
        }
    );
    // 3. 输出明文
    return cryptoJs.enc.Utf8.stringify(decrypted).toString();
}

与 CryptoJS DES 的对比

维度CryptoJS DEScrypto-js AES
分组大小8 字节16 字节
密钥长度8 字节（64 位）16 字节（128 位）
模式ECBCBC
IV不需要需要（iv=key）
decrypt 调用传递密文对象 {ciphertext: ...}直接传递密文字符串

常见坑

  • key/iv 长度不对：AES-128 的 key 和 iv 都必须是 16 字节。
  • iv 不匹配：如果加密端用 iv=key，解密端也必须用 iv=key，否则解密出来是乱码。
  • 密文不是 Base64：crypto-js 的 AES.decrypt() 默认密文是 Base64 字符串，如果是十六进制需要用 cryptoJs.enc.Hex.parse()。

小结

crypto-js AES 解密的 API 链和 CryptoJS DES 类似，但有几个关键区别：AES 的分组是 16 字节，模式是 CBC 需要 IV，而且这个案例里 iv=key。理解这条链之后，任何 crypto-js 的 AES 解密代码都只是一个模板。
