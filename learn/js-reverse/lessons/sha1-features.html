SHA1 算法特征识别

实战：SHA1 与百度 sign · 步骤 1/5

学习目标

能从一个手写的加密函数里识别出 SHA1 的五个魔数、80 轮循环和 hex 输出特征，知道它为什么不是"自定义加密"而是标准摘要算法。

先看现象：一段不像普通加密的 JS

当你抠下一个网站的加密函数，发现它长这样：

var s = function (e) {
    var o = t.bytesToWords(e)
      , i = 8 * e.length
      , a = []
      , s = 1732584193
      , u = -271733879
      , c = -1732584194
      , l = 271733878
      , f = -1009589776;
    // ... 80 轮循环 ...
    return [s, u, c, l, f]
}

五个初始值不是 0 或 1，而是四个正数一个负数，循环次数固定为 80。这不像常见的 XOR 或 BASE64 混淆——它更像某种标准算法的「手写实现」。

SHA1 的三个识别锚点

锚点具体特征意义
五个初始魔数1732584193、-271733879、-1732584194、271733878、-1009589776SHA1 独有的初始哈希值（H0–H4），见过一次就不会认错
80 轮循环for (m = 0; m < 80; m++)，每轮用不同的常数（1518500249、1859775393、2400959708、3395469782）MD5 是 64 轮，SHA256 是 64 轮，只有 SHA1 是 80 轮
输出转 hexbytesToHex(wordsToBytes(result))输出固定 40 个十六进制字符（160 位）

为什么 Python 不需要重写它？

SHA1 是标准摘要算法，Python 的 hashlib 原生支持。但这里有一个陷阱：丁香网的 JS 函数接受的输入是一串已经拼好的字符串，内部自己做了 UTF-8 编码转换（unescape(encodeURIComponent(e))）。如果你直接用 hashlib.sha1(data.encode()).hexdigest()，会因为编码差异算出不同的结果。

所以识别出 SHA1 只是第一步——输入怎么预处理、字节怎么转单词（bytesToWords）这些细节，决定了你是直接调 Python 的 hashlib，还是老老实实用 execjs 把这段 JS 整体跑起来。

Webpack 模块加载器：可以直接搬运的信号

你可能会在代码里看到这种奇怪的包裹：

function n(e, t) {
    return t = { exports: {} }, e(t, t.exports), t.exports
}
var o = n((function (e) { ... e.exports = n ... }))

这是 Webpack 的手写模块加载器。遇到这种结构，不需要去理解它怎么调度模块——整个 n(...) 包裹的代码是自包含的，可以直接整段复制到 Node.js 里跑。只要入口函数（这里是 u(e)）能调到，依赖的内部模块就已经打包在一起了。

小结

识别 SHA1 的关键不是能默写算法步骤，而是看到五个魔数 + 80 轮 + hex 输出就反应出「这是 SHA1，可以直接调标准库或原样搬运」。下一步我们就看丁香网怎么把请求参数拼成 SHA1 的输入。
