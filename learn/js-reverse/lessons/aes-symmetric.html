AES 對稱加密實戰

學習目標：掌握 AES-128-CBC 在 Python（pycryptodome）和前端（CryptoJS）兩端的互通：16 位元組 key/iv、PKCS7 填充、先 AES 加密再 base64 編碼的傳輸套路，並能復現一個帶 sign 校驗的爬蟲閉環。

現象：請求參數裡出現看似隨機的 base64 字串

你在 DevTools 裡看到請求參數 sign 或 data 是一串 base64，但每次請求都不同，長度也遠超過一般 base64 編碼的結果。這通常是先 AES 加密，再做 base64 編碼的組合。

AES 對稱加密的核心概念

  • 對稱：加密和解密使用同一把金鑰。
  • AES-128：金鑰長度 16 位元組（128 位元）。
  • CBC 模式：Cipher Block Chaining，每個明文塊先與前一個密文塊做 XOR，第一塊與 IV（初始化向量）做 XOR。需要一個 16 位元組的 IV。
  • PKCS7 填充：明文長度必須是 16 的倍數，不足處填充位元組，值等於缺少的位元組數。例如缺 5 位元組就填 5 個 0x05。

Python 加密流程

from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad
import base64

key = b"0123456789abcdef"  # 16 位元組
iv = b"1234567890abcdef"   # 16 位元組
data = "hello world"

# 加密
aes = AES.new(key, AES.MODE_CBC, iv)
encrypted = aes.encrypt(pad(data.encode(), 16))
result = base64.b64encode(encrypted).decode()
print(result)

Python 解密流程

# 解密
aes2 = AES.new(key, AES.MODE_CBC, iv)
decrypted = unpad(aes2.decrypt(base64.b64decode(result)), 16)
print(decrypted.decode())  # hello world

前端 CryptoJS 的對應寫法

網頁裡用 CryptoJS 做同樣的 AES-128-CBC 加密：

const key = CryptoJS.enc.Utf8.parse("0123456789abcdef");
const iv = CryptoJS.enc.Utf8.parse("1234567890abcdef");
const encrypted = CryptoJS.AES.encrypt("hello world", key, {
    iv: iv,
    mode: CryptoJS.mode.CBC,
    padding: CryptoJS.pad.Pkcs7
});
console.log(encrypted.toString());  // base64 密文

關鍵對應關係：

  • CryptoJS.enc.Utf8.parse 等同於 Python 的 b"..." 或 .encode()。
  • CryptoJS.mode.CBC 對應 AES.MODE_CBC。
  • CryptoJS.pad.Pkcs7 對應 pad(..., 16) / unpad(..., 16)。
  • encrypted.toString() 預設輸出 base64 字串。

復現 sign 參數的爬蟲閉環

一個典型的帶簽名介面：伺服器要求請求帶 sign 參數，值為 base64(AES(json(參數)))。爬蟲端要做的就是摳出前端 JS 裡的 key 和 iv，在 Python 裡復現同樣的加密流程：

import json
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad
import base64

key = b"0123456789abcdef"
iv = b"1234567890abcdef"

params = {"page": 1, "limit": 20}
sign = base64.b64encode(
    AES.new(key, AES.MODE_CBC, iv).encrypt(
        pad(json.dumps(params).encode(), 16)
    )
).decode()

# 把 sign 放進請求
# requests.get(url, params={**params, "sign": sign})

常見除錯清單

  • 解出亂碼？先核對 key、iv、模式、填充四要素是否與前端完全一致。
  • key 或 iv 不是 16 位元組？檢查是否用了錯誤的編碼或少了字元。
  • 前端用 CryptoJS.enc.Base64.parse 處理 key？那 key 本身也是 base64 編碼過的，要先解回位元組。

重點整理

  • AES-128-CBC：key 16 位元組、iv 16 位元組、明文填充到 16 的倍數。
  • 傳輸套路：先 AES 加密，再 base64 編碼；解密則反過來。
  • Python 用 pycryptodome，前端用 CryptoJS，兩端結果可以互通。
  • 復現 sign 的關鍵：從 JS 裡摳出 key/iv，按同樣順序做 json.dumps → pad → AES → base64。
