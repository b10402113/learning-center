毛毛租 AES-CBC 加密与解密实战

实战：DES/AES 案例 · 步骤 3/4

学习目标

用 PyCryptodome 实现 AES-128-CBC 加密请求体并 POST，再通过 execjs 调用 decrypt_data 完成响应解密，掌握"AES 加密请求 + JS 解密响应"的完整流程。

案例背景

毛毛租（maomaozu.com）的列表接口要求请求体是 AES 加密后的密文，响应也是 AES 加密的密文。这意味着这次不仅响应要解密，请求体本身也要先加密再发送。

完整流程是：Python 加密请求 → 发送 POST → Python 拿到密文响应 → JS 解密响应。

目标接口

接口地址：

https://www.maomaozu.com/index/build.json

请求方法是 POST，Content-Type 是 application/json，但 body 不是明文 JSON，而是 AES 加密后再 Base64 编码的字符串。

构造明文请求体

加密前的原始数据是一个 JSON 字符串：

data = '{"Type":0,"page":2,"expire":1704547824158}'

Type 是列表类型，page 是页码，expire 是时间戳。

第一步：填充到 16 字节的倍数

AES 要求明文长度必须是 16 字节的整数倍。原始 JSON 字符串的长度不固定，需要先填充。代码里用了两种填充方式，其中一种是补 \b（退格符）：

data += (16 - len(data) % 16) * "\b"

计算还差几个字节到 16 的倍数，就用 \b 补上。

第二步：Pkcs7 填充

代码还用了 PyCryptodome 自带的 Pkcs7 填充：

from Crypto.Util.Padding import pad
data = pad(data.encode(), 16)

pad() 会把数据填充到 16 字节的整数倍，填充规则和 CryptoJS 的 Pkcs7 一致。

第三步：AES-128-CBC 加密

现在进入核心加密步骤：

from Crypto.Cipher import AES

key = '55b3b62613aef1a0'.encode()  # 16 字节密钥
iv = '55b3b62613aef1a0'.encode()   # 16 字节初始向量
aes = AES.new(key=key, mode=AES.MODE_CBC, iv=iv)
encrypt_data = aes.encrypt(data)

注意这里的 key 和 iv 是同一个值：55b3b62613aef1a0。这是一个简化模式，虽然不太安全，但在逆向中很常见——开发者为了省事，直接把 key 当 iv 用。

第四步：Base64 编码

加密后的二进制数据不能直接放在 HTTP body 里，需要编码成字符串：

import base64
b64encode_encrypt_data = base64.b64encode(encrypt_data)
data = b64encode_encrypt_data.decode()

Base64 编码后得到一个纯文本字符串，可以直接作为 POST 的 body。

第五步：发送 POST 请求

带上和招标网类似的 headers 和 cookies，发送请求：

response = requests.post(
    'https://www.maomaozu.com/index/build.json',
    cookies=cookies,
    headers=headers,
    data=data
)

data 参数传的是加密后的 Base64 字符串。

第六步：JS 解密响应

响应也是 AES 加密的密文，需要交给 JS 解密：

import execjs
data = execjs.compile(open("04 mmz.js").read()).call("decrypt_data", response.text)
print(data)

一行代码完成：编译 JS → 调用 decrypt_data → 传入响应文本 → 拿到明文。

毛毛租多了一个"加密请求"的步骤，这是招标网没有的。

为什么请求和响应都要加密？

网站这么做通常有两个目的：第一，防止请求被篡改或重放（加密后攻击者无法直接修改参数）；第二，保护响应中的敏感数据（即使被截获也读不到明文）。

常见坑

  • key/iv 不是字节：key 和 iv 必须是字节类型（.encode()），传字符串会报错。
  • 填充不一致：加密端用 Pkcs7，解密端也得用 Pkcs7，否则解密出来是乱码。
  • iv 不匹配：CBC 模式要求加密端和解密端的 iv 完全一致。

小结

这一课跑通了毛毛租的完整链路：Python 加密请求体 → 发送 POST → JS 解密响应。核心是用 PyCryptodome 完成 AES-128-CBC 加密，再用 execjs 调用 crypto-js 解密响应。下一步，我们深入拆解那段 JS 解密代码，理解 crypto-js AES 解密的 API 链。
