xpath 进阶：局部解析、多页翻页、防盗链与图片懒加载

js-reverse · 03-requests-xpath · Step 5/5

学习 goal

掌握局部解析的 ./ 相对路径技巧，能识别并利用 url 翻页规律实现多页爬取，理解防盗链（Referer）原理并学会携带正确 Referer 请求头，以及识别图片懒加载的伪属性并直接解析真实链接。

局部解析：./ 相对路径

上一课学的 //div[@class="song"]//a/text() 是全局搜索——不管 xpath 表达式是从哪个节点开始执行的，都会从整个文档的根节点开始找。但真实爬虫的常见套路是：先定位到多个「区块」（比如列表页上的每一个商品卡片），再在每一个区块内部单独提取标题、价格、链接。

这时候就需要局部解析。在 xpath 裡，. 表示「当前节点」——也就是 xpath 调用者本身。如果你已经用 //div[@class="item"] 定位到了一组商品卡片，接下来要在每个卡片内部找标题，表达式应该写成 ./div[@class="title"]/text() 而不是 //div[@class="title"]/text()。

区别在于：//div[@class="title"]/text() 会从整个文档找所有 title，把所有卡片的标题混在一起；./div[@class="title"]/text() 只找当前这个卡片内部的 title，保持一一对应。这是列表页爬虫最重要的技巧：先切块，再在每个块裡提取。

items = tree.xpath('//div[@class="item"]')
for item in items:
    title = item.xpath('./div[@class="title"]/text()')[0]
    price = item.xpath('./span[@class="price"]/text()')[0]

多页翻页：url 翻页规律

很少有网站把所有内容塞在第一页。翻页是爬虫必须解决的问题。翻页的本质是：不同页的数据分布在不同的 url 裡，这些 url 通常有规律。比如 https://example.com/news_1.html、news_2.html、news_3.html，或者 https://example.com/news?page=1、page=2、page=3。

破解翻页的方法是：先观察前几页的 url，找到规律，然后用迴圈批量生成所有页的 url，依次请求、解析、存储。

for page in range(1, 11):
    url = f'https://example.com/news_{page}.html'
    response = requests.get(url)
    # 解析并存储

有些网站的翻页 url 不是简单的数字递增，而是带有关键字、时间戳、页码偏移量。这时候需要抓包观察翻页时实际发出的请求，找到参数规律。但核心思路不变：找到翻页规律 → 迴圈生成 url → 逐页爬取。

防盗链：Referer 请求头

很多网站不希望自己的图片被其他网站直接引用（盗链），会在服务器端检查请求头裡的 Referer 字段。Referer 记录了「这个请求是从哪个页面跳转过来的」——如果 Referer 不是自己的域名，服务器就拒绝返回图片，或者返回一张「禁止盗链」的提示图。

破解防盗链的方法是：在发图片请求时，手动在 headers 裡带上正确的 Referer（通常是图片所在页面的 url）。

headers = {'Referer': 'https://example.com/gallery/123.html'}
response = requests.get(img_url, headers=headers)

注意：Referer 的拼写在 HTTP 协议裡就是错的（本来应该是 Referrer），但标准已经定死，所有浏览器和服务器都拼成 Referer。写爬虫时照抄即可。

图片懒加载：伪属性裡的真实链接

现代网页为了加速首屏加载，会使用图片懒加载（Lazy Loading）技术：页面刚打开时，<img> 标签的 src 属性放一张 1x1 像素的占位图或空字串，真正的图片地址藏在 data-src、src2、data-original 这类自定义属性（伪属性）裡。只有当图片滚到浏览器可视区域时，JavaScript 才会把伪属性的值写进 src，触发真正的图片下载。

如果你直接用 //img/@src 解析，拿到的就是占位图地址，下载下来是空白或 1x1 的透明图。破解方法是直接解析伪属性的值：//img/@data-src 或 //img/@src2。

怎么判断一个 img 标签是不是懒加载？打开浏览器开发者工具，看 Elements 面板裡 img 的 src 属性值——如果是一个很小的图、data:URL、或者和 Network 面板裡实际加载的图片 url 不一致，那真正的地址一定藏在某个伪属性裡。这时候在 Elements 面板裡看 img 标签的所有属性，找到那个看起来像图片 url 的属性名，用 @属性名 提取即可。

综合案例：列表页 → 详情页 → 下载

把上面所有技巧串起来，就是一个完整的聚焦爬虫套路：

  1. 请求列表页，用 xpath 解析出每个商品的详情页 url 和标题。
  2. 对每个详情页 url 发请求，用 xpath 解析出正文内容或图片地址。
  3. 如果是图片，检查是否需要带 Referer 防盗链，是否需要解析伪属性拿真实地址。
  4. 把所有数据持久化存储。

这个「列表页 → 详情页 → 下载」的三级请求链，是爬虫实战裡最常用的模式。后面学到的 Scrapy 框架，本质上就是把这套流程模板化、并发化。
