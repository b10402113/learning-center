Hook 檢測與反檢測

你用 hook 窺探網站，網站也在檢查自己有沒有被動過手腳。

學習目標

理解網站如何用 toString() 與原型鏈上的 Function.prototype.toString.call 檢測函數是否被 hook，並掌握對應的兩級破解寫法與各自代價。

第一級檢測：toString() 比對

一些網站會嚴格檢測自己的函數或屬性有沒有被人 hook。最常用的手段出乎意料地簡單：對函數調用 toString()。

JavaScript 裡，內置函數的實現是被隱藏的——atob、toString 這類原生函數調 toString() 時，返回的不是源碼，而是一個特殊標記：

atob.toString();
// 原生情況下返回：
// "function atob() { [native code] }"

[native code] 表示「這個函數的實現由瀏覽器內部完成，不給你看」。而一旦 atob 被我們同名覆蓋成包裹函數，再調 toString()，返回的就是你那段包裹函數的完整源碼——兩個結果一對比，網站立刻知道 atob 被動過了。

第一級破解：重寫實例的 toString

既然檢測靠 toString() 的返回值，那就把這個返回值也偽造掉——在 hook 裡順手重寫 atob 自己的 toString：

_atob = atob;  // 保存原函數

atob = function (str) {
    console.log("正在執行atob方法, 參數:", str);
    let result = _atob(str);
    console.log("正在執行atob方法, 返回值:", result);
    return result;
}

// 重寫 atob 函數的 toString 方法
atob.toString = function () {
    return 'function atob() { [native code] }'
}

這樣網站調 atob.toString() 時，拿到的依然是那句以假亂真的 [native code]。檢測被騙過了——暫時。

第二級檢測：原型鏈上的 toString

防守方也知道你會重寫實例上的 toString。於是檢測升級：不用 atob.toString()（這會讀到你在實例上重寫的版本），而是繞到原型鏈上，直接借用所有函數共用的那個原始版本：

Function.prototype.toString.call(atob)
// 調用函數原型對象中的 toString 進行檢測，
// 而不是 atob 實例對象上的 toString 了。

Function.prototype.toString 是所有函數默認的 toString 來源。你在 atob 實例上重寫的那個版本被直接跳過，原型上的原版一出馬，包裹函數的源碼又暴露了。

第二級破解：重寫原型鏈上的 toString

對應的破解也只能升到原型鏈上：把 Function.prototype.toString 本身重寫，讓它永遠返回原生風格的字串：

// 重寫原型鏈上的 toString 方法
Function.prototype.toString = function () {
    return `function ${this.name}() { [native code] }`
}

注意這裡用了 this.name 而不是寫死 atob。this 是 toString 的調用者——誰調它，this.name 就是誰的名字：Location.toString() 返回 function Location() { [native code] }，atob.toString() 返回 function atob() { [native code] }。如果貪省事把名字寫死成 atob，那以後任何函數調 toString() 都返回 function atob() ...——Location.toString() 也變成 atob，這種自相矛盾的結果反而成了新的破綻。

兩級攻防對照

輪次檢測方（網站）破解方（你）代價／風險
1atob.toString() 比對是否為 [native code]重寫 atob.toString，返回偽造的原生字串只蓋住實例這一層
2Function.prototype.toString.call(atob) 繞過實例重寫重寫 Function.prototype.toString，用 this.name 動態適配影響所有函數的 toString；寫死名字會製造新破綻

這條攻防鏈給逆向者的啟示是：hook 會增加被檢測的風險。每補一層偽裝，就多動了一處全域環境，也就多一分露出馬腳的可能。實戰裡要權衡：監控帶來的情報價值，是否值得承擔被網站識破的代價。
