函數的 hook：包裹原函數

四步流程，讓任何一個函數在被調用時自動彙報參數與返回值。

學習目標

能獨立寫出函數 hook 的四步流程——定義/取得原函數、保存原函數、同名包裹、調用觀察，並理解 hook 必須在原函數加載完成之後的時機要求。

四步流程

對一個具體函數做 hook，永遠是同一個四步套路。用一個簡單的 add 函數演示：

第一步：定義（或取得）原函數

function add(a, b) {
    console.log("add方法正在執行");
    return a + b;
}

在真實逆向中，這個函數不是你寫的，而是網站自己的加密函數——你要做的是先確認它「存在於哪個作用域、叫什麼名字」，這裡用 demo 把它定義出來。

第二步：保存原函數

_add = add;

目的是不修改原函數內部的實現。_add 此時指向原來那個函數對象，真正的加法邏輯一行未動。

第三步：同名包裹

add = function (a, b) {
    console.log("原函數調用前, 參數：", a, b);
    let result = _add(a, b);   // 執行原函數
    console.log("原函數調用後, 結果：", result);
    return result;
};

包裹函數的內部結構是固定的三段：打印參數 → 調用原函數 → 打印結果並原樣返回。調用方拿到的返回值和 hook 之前完全一致。

時機要求：這段 hook 代碼的位置必須在原函數加載完成之後——在原函數定義之前執行 _add = add，保存的就是 undefined。

第四步：調用並觀察輸出

add(1, 2);

控制台依次輸出：

原函數調用前, 參數： 1 2
add方法正在執行
原函數調用後, 結果： 3

調用方只寫了一行 add(1, 2)，你卻看到了完整的調用現場：進去的參數、出來的結果，以及原函數確實被執行過。

逆向場景：它到底被誰調用了

四步流程的威力在調用鏈複雜時才真正顯現。設想頁面腳本裡藏著這樣一串調用關係：e() 調 d()，d() 調 add() 再調 c()，c() 調 b()，b() 又調了一次 add()：

function add(a, b) { return a + b; }   // 加密函數

_add = add;
add = function (a, b) {
    console.log("原函數執行前，參數", a, b);
    let result = _add(a, b);           // 執行原函數
    console.log("原函數執行後，結果", result);
    return result;
};

function c() { console.log("c"); b(); }
function b() { console.log("b"); add(); a(); }
function d() { console.log("d"); add(); c(); }
function e() { console.log("e"); d(); }
e();

跑一次 e()，控制台裡「原函數執行前」的日誌出現幾次、夾在哪些函數的日誌之間，add 的調用點就一清二楚。這正是 hook 三大作用裡「便於調試和定位」的含義——你不需要讀懂整條調用鏈，只需要讓加密函數自己開口。

本節小結

函數 hook = 四步：定義/取得原函數 → _add = add 保存 → 同名包裹（打印參數 → 調原函數 → 打印結果 → 原樣返回）→ 調用觀察。記住兩個「不」：不改原函數實現、不改調用方式；和一個時機：原函數加載完成之後才能 hook。
