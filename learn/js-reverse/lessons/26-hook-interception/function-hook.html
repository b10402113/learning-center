26-hook-interception / function-hook

函數的 hook：包裹原函數

四步流程，把任何函數變成帶日誌的監控點。

學習目標

獨立寫出一個函數 hook：保存原函數、同名覆蓋、打印入參與返回值、原樣返回結果，並理解 hook 代碼必須在原函數加載之後執行。

四步流程

對一個函數做 hook，固定走四步。以加密函數 add 為例：

第 1 步：拿到原函數。它可能是你自己定義的，也可能是網站頁面裡已經存在的：

function add(a, b) {
  console.log("add方法正在執行");
  return a + b;
}

第 2 步：保存原函數。目的是不修改原函數內部的實現——後面還要靠它算出正確結果：

_add = add;

第 3 步：同名覆蓋。讓 add 指向一個新函數：先打印參數，再調 _add 拿結果，打印結果，最後原樣返回：

add = function (a, b) {
  console.log("原函數調用前, 參數：", a, b);
  let result = _add(a, b);
  console.log("原函數調用後, 結果：", result);
  return result;
};

第 4 步：像往常一樣調用，觀察輸出。

add(1, 2);
// 控制台依次輸出：
// 原函數調用前, 參數： 1 2
// add方法正在執行
// 原函數調用後, 結果： 3

一條硬性約束：hook 的位置

hook 代碼必須寫在原函數加載完成之後。原因很直接：同名覆蓋改的是「add 這個名字指向誰」。如果原函數還沒定義你就覆蓋，_add 保存的是個空；如果原函數在你覆蓋之後才定義，它的聲明會把你的 hook 沖掉。所以順序永遠是：原函數先就位，hook 再上場。

為什麼包裹函數必須 return result

調用方寫的是 let sign = add(x, y)，它指望拿到返回值繼續用。如果你的包裹函數打印完日誌卻忘了 return result，調用方拿到的就是 undefined——整個網站的邏輯鏈條在你這裡斷掉，頁面直接出錯，你也就暴露了。hook 的前提是對外行為完全等價：參數照收、結果照給，只多兩行日誌。

逆向實戰視角：定位調用點

設想頁面裡的調用鏈是 e → d → c → b → add，你只關心加密函數 add。對它 hook 之後，只要把頁面跑一遍，控制台就會打印出 add 每一次被調用的參數和返回值；再配合調用棧（DevTools 的 Call Stack，見 17-debugging-tips 節點），就能反推出是誰、在什麼場景下調了它。比起逐文件搜索「add(」，這種蹲點式觀察又快又準。
