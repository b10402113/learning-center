26-hook-interception / hook-mindset

Hook 的概念與最小可用模式

在不改原代碼、不變調用方式的前提下，看清每一次函數調用。

學習目標

理解 hook 是「攔截和修改函數行為的技術」，說出它在逆向中的用途，並記住「保存原函數 + 同名覆蓋」這個貫穿全程的最小可用模式。

先從一個真實處境說起

你在分析一個網站，翻 JS 文件時發現了一個加密函數——姑且叫它 add，它負責生成請求要帶的 sign。你真正想知道的不是它的內部實現，而是三件事：它在哪些 JS 代碼裡被調用？每次傳了什麼參數？返回了什麼？

一個頁面加載時會執行很多 JS 文件，每個文件裡又有很多函數。一個個文件翻過去找調用點，太慢，也太容易漏。你需要一種「守株待兔」的辦法：蹲在 add 的門口，誰來調它、帶了什麼、拿走了什麼，全部記下來。

這個辦法就是 hook（鉤子）。

hook 是什麼

在 JavaScript 中，hook 是一種能夠攔截和修改函數或方法行為的技術。通過 hook，你可以在現有函數執行之前、執行之後插入自己的邏輯，甚至整個替換掉函數的實現。hook 的目的是找到函數入口以及一些參數變化，便於分析 JS 邏輯。

hook 的價值有三條：

作用含義逆向中的意義
增強可擴展性不修改原始代碼就能增加或修改功能目標網站的 JS 一個字都不用動
減少侵入性新功能好管理、好維護、隨時可拆hook 代碼寫在控制台或 Snippets 裡，與原代碼完全隔離
便於調試定位在函數執行前後插入調試信息看清執行流程，定位問題源頭與調用點

最小可用模式：保存原函數 + 同名覆蓋

hook 的寫法千變萬化，但核心骨架只有兩個動作：

// 1. 保存原函數——目的是不修改原函數內部的實現
_add = add;

// 2. 同名覆蓋——新函數包裹原函數，順便打印日誌
add = function (a, b) {
  console.log('原函數執行前，參數', a, b);
  let result = _add(a, b);  // 執行原函數
  console.log('原函數執行後，結果', result);
  return result;
};

第一行把真正的 add 存到 _add 裡保管起來；第二行讓 add 這個名字指向一個新函數。新函數先打印參數，再調用保管好的原函數拿到結果，打印結果，最後把結果原樣返回。

為什麼調用方毫無察覺

關鍵在「同名覆蓋」。網站原有的代碼照樣寫 add(x, y)、照樣拿返回值去用——名字沒變、參數沒變、返回值也沒變。唯一多出來的，是控制台裡你插进去的兩行日誌。對調用方來說，這次調用和往常沒有任何區別；對你來說，每一次調用的入參和出參都被看得一清二楚。

這就是 hook 的精髓：不改原代碼、不變調用方式，只在中間加一雙眼睛。

這個模式會一直陪著你

本節點後面的每一步，都是這個骨架的變體：函數的 hook 是它的完整四步流程；對象屬性的 hook 把「保存原值 + 重新定義」搬到了 Object.defineProperty 的 get/set 上；瀏覽器先手 hook 解決的是「什麼時機注入這段代碼」；檢測與反檢測則是攻防雙方圍繞「函數被換過了」這件事的拉扯。記住這副骨架，後面每一步你都會認出它。
