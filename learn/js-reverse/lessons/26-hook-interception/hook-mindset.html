26-hook-interception / hook-mindset

Hook 的概念與最小可用模式

看懂別人的加密代碼之前，先學會在不改代碼的前提下「偷聽」每一次函數調用。

學習目標

理解 hook（攔截和修改函數或方法行為的技術）的概念、三大作用，以及「保存原函數 + 同名覆蓋」這個所有 hook 共用的最小可用模式。

逆向時最常遇到的處境

你在目標網站的 JS 裡翻出了一個可疑的加密函數——姑且叫它 add。你知道它是關鍵，但接下來的問題是：它在哪些 JS 文件裡被調用？每次傳了什麼參數？返回了什麼值？一個頁面加載時會執行幾十個 JS 文件、成百上千個函數，挨個文件去搜「add(」既不現實，也看不到運行時的真實參數。

你真正想要的，是在原代碼一行不改的前提下，讓 add 每次被調用時「自報家門」：誰調了我、傳了什麼、我回了什麼。這就是 hook 要做的事。

什麼是 hook

在 JavaScript 中，hook（鉤子）是一種攔截和修改函數或方法行為的技術。使用 hook，你可以在現有函數執行前插入邏輯、在執行後插入邏輯，或者乾脆替換函數的實現。它的目的是找到函數的入口、觀察參數的變化，從而分析 JS 邏輯。

hook 的作用有三條：

作用說明
增強可擴展性不修改原始代碼就能增加或修改功能，代碼更靈活
減少侵入性不改變原代碼的前提下加新功能，新功能更容易管理和維護
便於調試和定位在函數執行前後插入日誌，理解程序執行流程、定位問題源頭

前兩條是正規開發者關心的；第三條是逆向者關心的——hook 是逆向中定位函數調用點、觀察入參/出參的第一手段。

最小可用模式：保存原函數 + 同名覆蓋

hook 的寫法千變萬化，但核心永遠是同一個兩步模式。假設目標函數是 add：

// 第一步：保存原函數
_add = add;

// 第二步：用同名變數重新賦值，包裹原函數
add = function (a, b) {
    console.log("原函數調用前, 參數：", a, b);
    let result = _add(a, b);   // 執行原函數
    console.log("原函數調用後, 結果：", result);
    return result;
};

這兩步各自解決一個問題：

  • 保存原函數（_add = add）——目的是不修改原函數內部的實現。原函數依然是原函數，只是換了個名字被存起來。包裹函數裡調用 _add(a, b)，拿到的結果和原來一模一樣。
  • 同名覆蓋（add = function(...)）——目的是不改變調用方式。網站裡所有調用 add(...) 的地方照常工作，但它們現在調到的是你的包裹函數。包裹函數打印日誌之後，把原函數的返回值原樣 return 回去，調用方毫無察覺。

一個硬性條件：hook 的位置

hook 代碼的位置必須在加載完需要 hook 的函數（原函數）之後。如果原函數還沒定義你就執行 _add = add，保存下來的就是 undefined，包裹函數一調用 _add() 就報錯。這條時機約束在平時的 demo 裡很自然——把 hook 代碼放在原函數定義後面就行；但一旦搬到真實瀏覽器裡，它就成了最棘手的問題（怎麼搶在頁面腳本之前完成 hook），後面「瀏覽器先手 hook」一步專門解決它。

本節小結

hook = 攔截和修改函數行為的技術；逆向里用它定位調用點、觀察參數與返回值。最小可用模式只有兩步：保存原函數（不改原實現）＋ 同名覆蓋（不改調用方式）。記住時機約束：hook 必須在原函數加載完成之後執行。接下來的每一步——函數 hook、屬性 hook、瀏覽器先手 hook——都只是這個模式在不同對象上的展開。
