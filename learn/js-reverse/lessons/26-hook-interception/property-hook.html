26-hook-interception / property-hook

對象屬性的 hook：Object.defineProperty

把屬性的讀和寫，變成兩個帶日誌的監控入口。

學習目標

用 Object.defineProperty 把屬性的讀寫重新定義成帶日誌的 get/set，監控已有屬性與不存在的屬性，並理解為什麼要把原值存到外部變量。

屬性也是情報點

網站的關鍵數據不一定藏在函數裡，也常常躺在對象屬性上：用戶名、token、憑證，都是「某個對象的某個屬性」。你可能想知道：這個屬性什麼時候被讀、什麼時候被改、被改成了什麼。函數 hook 管不到屬性，這時要用另一件工具：Object.defineProperty。

Object.defineProperty 用來重新定義對象的屬性，收三個參數：

參數是什麼例子
參數 1：對象要 hook 的屬性住在哪個對象上user
參數 2：屬性名要重新定義哪個屬性"name"
參數 3：屬性描述符這個屬性怎麼讀、怎麼寫{ get(){...}, set(value){...} }

描述符裡的 get() 在讀取屬性值時執行，set(value) 在設置屬性值時執行。把日誌塞進這兩個函數，屬性的每一次讀寫就都落在你眼裡。

完整寫法：以 user.name 為例

// 1、創建一個對象
let user = {
    "name": "波波",
};

// 2、保存原屬性值到外部變量
_name = user.name;

// 3、對象屬性的 hook
Object.defineProperty(user, "name", {
    get(){ // 獲取屬性值的時候執行
        console.log("正在獲取屬性值");
        return _name;
    },
    set(value){ // 設置屬性值的時候執行
        console.log("正在設置屬性值:", value);
        _name = value;
    }
});

// 4、像往常一樣讀寫屬性
console.log(user.name)   // 觸發 get：打印「正在獲取屬性值」，再輸出「波波」
user.name = 'Jay'        // 觸發 set：打印「正在設置屬性值: Jay」
console.log(user.name)   // 觸發 get：輸出「Jay」

骨架和函數 hook 一模一樣：保存原值 + 重新定義。差別只是「同名覆蓋」換成了「用描述符重新定義讀寫行為」。

關鍵細節：原值為什麼要存到外部變量

注意 get 裡返回的是外部變量 _name，而不是 user.name。如果寫成 return user.name，這次讀取又會觸發 get，get 裡又讀 user.name……無限遞歸，直接爆棧。把值保管在外部變量 _name 裡，讀寫都經它中轉，就斬斷了自引用。

不存在的屬性也能 hook

實戰中常見的情況是：屬性是另一個 JS 文件後來才加上的。比如 xxx.js 定義了 user，ooo.js 裡才寫 user.age = 18，再往後的代碼對 user.age 做各種操作。這種「本來不存在」的屬性照樣能 hook——你先給它一個初始值，再用 defineProperty 把這個名字定下來：

// 2、保存原屬性（給它一個已知的初始值）
_age = 18;

// 3、對象屬性 age 的 hook
Object.defineProperty(user, "age", {
    get(){
        console.log("正在獲取屬性值");
        return _age;
    },
    set(value){
        console.log("正在設置屬性值:", value);
        _age = value;
    }
});

從此之後，任何代碼讀 user.age、寫 user.age = 20，都會先經過你的日誌。監控不存在的屬性，本質是「搶先定義，等別人來用」。
