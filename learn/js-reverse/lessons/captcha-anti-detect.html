Selenium 浏览器自动化

Step 5 — 验证码实战与规避检测

Learning Goal

掌握 OpenCV 缺口识别 + 动作链拖动的滑动验证解法，学会用打码平台处理点选验证码，并能用 stealth.min.js 规避 Selenium 侦测。

滑动验证码：缺口识别 + 拖动

滑动验证码是反爬的常见手段：用户把滑块拖到缺口处才能通过验证。用 Selenium 自动完成这个流程，核心是两步：算出滑动距离，模拟拖动。

第一步：用 OpenCV 算出缺口位置

OpenCV 的 cv2.matchTemplate() 可以在一张大图里找小图的位置。思路是：保存背景图（带缺口的完整图）和缺口图（滑块），用模板匹配找到缺口在背景图里的 x 坐标。

import cv2
import numpy as np
from urllib.request import urlretrieve

# 1. 下载背景图和缺口图
urlretrieve(bg_src, 'background.png')
urlretrieve(gap_src, 'gap.png')

# 2. 读取图片
bg = cv2.imread('background.png')
gap = cv2.imread('gap.png')

# 3. 模板匹配
result = cv2.matchTemplate(bg, gap, cv2.TM_CCOEFF_NORMED)
min_val, max_val, min_loc, max_loc = cv2.minMaxLoc(result)

# 4. 缺口 x 坐标
x = max_loc[0]

注意：页面显示的图片尺寸可能和原图不一样（CSS 缩放过），必须做像素单位换算：

# 页面显示宽度 278，原图宽度 360
real_x = x * 278 / 360

第二步：用 ActionChains 模拟拖动

算出距离后，用动作链完成「按住 → 移动 → 释放」：

from selenium.webdriver.common.action_chains import ActionChains

slider = browser.find_element(By.CLASS_NAME, 'slider')

actions = ActionChains(browser)
actions.click_and_hold(slider).move_by_offset(real_x, 0).release().perform()

但这样往往过不了验证，原因有两个：

  • 没有模拟人的行为：真人拖动有加速、减速、停顿，匀速直线移动会被识别为机器。
  • 被检测出是 Selenium：网站通过浏览器指纹发现你在用自动化工具。

打码平台：处理点选验证码

滑动验证码还能用 OpenCV 硬解，但更复杂的验证码（汉字点选、计算题、文字识别）就不适合自己写算法了。工程上的做法是接入打码平台——把验证码图片发给平台，平台返回识别结果。

以图鉴（ttshitsu）为例，流程是：

  1. 截图验证码区域，base64 编码。
  2. POST 到 /predict 接口，带上 typeid（验证码类型编号）。
  3. 平台返回坐标，比如 154,251|145,167。
  4. 用 ActionChains 逐个点击对应坐标。
import requests
import base64

# 1. 截图验证码区域
code_tag = browser.find_element(By.CLASS_NAME, 'geetest_panel')
code_tag.screenshot('./code.png')

# 2. base64 编码
with open('./code.png', 'rb') as f:
    b64 = base64.b64encode(f.read()).decode()

# 3. 调用打码平台
resp = requests.post('http://api.ttshitsu.com/predict', data={
    'username': 'your_user',
    'password': 'your_pwd',
    'typeid': 27,  # 点选 1~4 坐标
    'image': b64
})
result = resp.json()['data']['result']  # "154,251|145,167"

# 4. 解析坐标并点击
points = result.split('|')
for point in points:
    x, y = map(int, point.split(','))
    actions = ActionChains(browser)
    actions.move_to_element_with_offset(code_tag, x, y).click().perform()

# 5. 确认提交
browser.find_element(By.CLASS_NAME, 'geetest_commit').click()

打码平台覆盖了数英混合、计算题、汉字、坐标点选、缺口识别、拼图等类型，比自己训练识别模型成本低得多。

规避检测：stealth.min.js

大网站会检测浏览器是不是 Selenium 驱动的。检测原理很简单：正常浏览器的 window.navigator.webdriver 属性是 undefined 或 false，而 Selenium 驱动下是 true。

解法是在打开任何页面之前，注入一段 JS 把这个属性改掉。这段 JS 就是 stealth.min.js，它不仅能隐藏 webdriver 属性，还能伪装其他自动化特征（比如 Chrome 的 runtime、permissions 等）。

# 1. 读取 stealth.min.js
with open('stealth.min.js', 'r') as f:
    js = f.read()

# 2. 在打开页面前注入
browser.execute_cdp_cmd("Page.addScriptToEvaluateOnNewDocument", {"source": js})

# 3. 现在打开页面，window.navigator.webdriver 就是 undefined 了
browser.get('https://www.jd.com')

execute_cdp_cmd() 执行的是 CDP（Chrome DevTools Protocol）命令，Page.addScriptToEvaluateOnNewDocument 的意思是「在每次加载新文档时先执行这段 JS」。这样页面里的任何检测代码都读不到真实的 webdriver 值。

为什么滑动验证常失败？

京东登录的滑动验证案例揭示了两个失败原因：

  • 行为轨迹不像人：真人拖动滑块时会有抖动、加速、减速，而 move_by_offset(x, 0) 是匀速直线运动。高级反爬会记录鼠标轨迹，匀速运动直接判机器。
  • Selenium 指纹暴露：即使轨迹模拟得像人，window.navigator.webdriver = true 也会直接暴露。必须用 stealth.min.js 隐藏指纹。

实际项目中，滑动验证的通过率不是 100%，通常需要结合轨迹模拟 + stealth + 多次重试。

关键概念总结

  • OpenCV 模板匹配：cv2.matchTemplate() 在背景图中定位缺口，算出滑动距离。
  • 打码平台：把验证码图片发给第三方平台，返回识别结果，比自己训练模型成本低。
  • stealth.min.js：注入 JS 隐藏 Selenium 的自动化特征，规避反爬检测。
  • execute_cdp_cmd()：执行 CDP 命令，Page.addScriptToEvaluateOnNewDocument 在页面前注入 JS。
  • 行为轨迹：真人操作有加速减速，匀速直线运动会被识别为机器。
