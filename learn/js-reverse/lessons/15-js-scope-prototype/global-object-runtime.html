window、globalThis 与运行时全局对象

JS 逆向 · 节点 15 · 步骤 7/7

学习目标

能区分浏览器的 window、Node 的全局对象与 globalThis，并据此判断抽取 JS 在不同运行环境中的依赖。

window：浏览器专属的全局对象

浏览器里有个全局对象 window，可以理解成 JS 的全局作用域：你不写任何前缀去访问一个顶层标识符，默认就是在访问 window 上的属性。

var a = 10;
a === window.a;   // true

window.mm = "爱你";
console.log(mm);  // 爱你

window 还代表浏览器窗口本身，是浏览器对象模型（BOM）的根节点，下面挂着 navigator（浏览器信息）、screen（屏幕）、history（历史）、location（URL）、document（整个页面）等子对象。逆向时在 DevTools 的 Console 里直接打 window，就能翻到所有全局状态和入口函数。

换环境就报错：window is not defined

window 是浏览器环境专属的内置对象。在没有浏览器窗口的环境里——比如 PyCharm、纯 Node 脚本——直接写 window 会报错：

// Node 或 PyCharm 里执行：
console.log(window);
// ReferenceError: window is not defined

这个报错信息在逆向里非常重要：它告诉你"当前跑的这段代码依赖浏览器环境"。

globalThis：跨环境的全局对象

globalThis 是 ES2020 提供的统一全局对象，浏览器和 Node 都能用。用它可以写出在两种环境都不报错的全局访问/声明：

globalThis.a = 10;
console.log(a);       // 10

// 在浏览器里：
globalThis === window // true

也就是说：window 只属于浏览器，globalThis 两边通用，且在浏览器里 globalThis === window。这是你判断抽取的 JS 依赖哪个全局对象的钥匙。

常见的 IIFE 传参模式：把全局对象递进去

生产代码（尤其是混淆过的）经常用一个技巧：把全局对象作为参数传进立即执行函数，这样内部既能访问全局、又不直接裸写 window：

(function(w){
  var chi = function(){ console.log("我是吃"); };
  w.chi = chi;   // 通过参数 w 挂到全局
})(window);
chi();           // 外部就能调用了

// Node 里同样的套路：
(function(g){ g.chi = chi; })(globalThis);

逆向时看到 (function(w){...})(window) 或 (function(window, document){...})(window, document) 这种开头，要立刻识别：这是在把全局对象递进闭包，内部通过参数名访问全局。

对逆向的启示：抽取 JS 换环境跑

我们后面做 sign 逆向时，常把网页里的 JS 抠出来放到 Node 或 execjs 里执行。这时第一步就是检查它依赖哪个全局对象：

  • 代码里出现 window → 直接跑会 window is not defined，需要补一个 window 壳（shim），或先确认能否换成 globalThis。
  • 代码用 (function(w){...})(window) 开头 → 记住：传进来的那个参数就是要补的环境。
  • 只用了 globalThis → 换环境最省事，两边都不用补。
