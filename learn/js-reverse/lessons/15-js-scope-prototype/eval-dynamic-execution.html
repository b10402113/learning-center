eval 与动态执行

JS 逆向 · 节点 15 · 步骤 6/7

学习目标

能识别 eval 将字符串转为可执行代码的运行机制，并在阅读混淆脚本时判断其调试与追踪影响。

eval：把字符串当代码跑

eval 的功能一句话就能说清：把字符串当作 JS 代码来执行。它和 Python 里的 eval 一模一样：

var s = "console.log('我爱你')";
eval(s);   // 打印：我爱你

这里 eval(s) 并没有打印字符串 s，而是把 s 的内容当成代码编译并运行。记住这一条就够了：eval() 里面不论多复杂，它最终接收的一定是一个字符串。

为什么逆向一定要认识 eval

正常业务代码很少用 eval。但很多网站恰恰利用它来做反爬——把真实代码包成字符串，运行时才"解包"执行，静态读源码时你看到的就是一团乱码：

eval(function(p,a,c,k,e,d){
  e = function(c){ return (c < a ? '' : e(parseInt(c/a)))
    + ((c = c % a) > 35 ? String.fromCharCode(c + 29) : c.toString(36)); };
  if (!''.replace(/^/, String)) {
    while (c--) d[e(c)] = k[c] || e(c);
    k = [function(e){ return d[e]; }];
    e = function(){ return '\\w+'; };
    c = 1;
  }
  while (c--) if (k[c]) p = p.replace(new RegExp('\\b' + e(c) + '\\b', 'g'), k[c]);
  return p;
}('0.1(\'我爱你\')', 62, 2, 'console|log'.split('|'), 0, {}));

这就是经典的 eval 混淆：外层是一个解码函数 function(p,a,c,k,e,d)，它把压缩过的字符串解成可读代码。关键不是去读解码函数，而是记住——把 eval() 里的内容整个拷贝出来执行一次，它一定吐出一个字符串，那个字符串才是真正的代码。

逆向做法：先把字符串还原

遇到 eval(...)，最有效的做法不是硬读，而是把字符串还原出来：

  1. 把 eval(...) 里的整段内容拷贝出来。
  2. 把它单独执行一次，结果必然是一个字符串（否则 eval 也没法执行）。
  3. 把那个字符串打印或美化，就看到真实逻辑了。
// 把 eval 换成 console.log，打印解码后的字符串
var dec = (function(p,a,c,k,e,d){
  /* 解码函数同左 */
})('0.1(\'我爱你\')', 62, 2, 'console|log'.split('|'), 0, {});
console.log(dec); // console.log('我爱你')

更省事的是直接借助工具：把混淆片段丢进在线 eval 解码器（如 jb51 的 evalencode 工具）即可还原，绝大多数 eval 加密都能直接解开。

eval 对调试与追踪的影响

eval 的动态性在逆向时有三个实际后果：

  • 静态分析失效：eval 里的代码运行前在 Sources 面板里不存在，直接读文件看不到真实逻辑，必须靠"执行字符串"来还原。
  • 断点更麻烦：代码是运行时生成的，只能对 eval 调用本身下断点，或在还原后的字符串代码里断点。
  • 作用域泄漏：非严格模式下，eval 内用 var 声明的变量会泄漏到调用它的作用域。你把它抠出来单独跑时，这些"副作用"可能影响全局状态，要留意。
