requests 入门：编码四流程与响应处理

js-reverse · 03-requests-xpath · Step 1/5

学习 goal

掌握 requests 爬虫的标准编码四流程，理解 response 对象的 text、content、json() 三种属性分别返回什么数据，并能用 response.encoding 处理中文乱码。

浏览器背后发生了什么

每天打开浏览器输入网址看到网页，背后其实只有两步：浏览器向服务器发一个 HTTP 请求，服务器把网页内容打包发回来，浏览器渲染成你能看懂的页面。爬虫要做的，就是让程序代替浏览器走同一条路——发请求、收响应、把想要的数据留下来。

requests 是什么

requests 是 Python 里最主流的第三方 HTTP 库，安装方式是 pip install requests。它的 API 设计得像在浏览器地址栏输入网址一样直觉——requests.get(url) 就是发一个 GET 请求，requests.post(url, data=...) 就是提交表单。

编码四流程

用 requests 写爬虫，永远逃不出这四步：

  1. 指定 url——告诉程序去哪个服务器、拿哪个页面。
  2. 发起请求——requests.get(url) 代替浏览器向服务器发 GET 请求，返回一个 response 对象（可以理解成寄回来的包裹）。
  3. 获取响应数据——从 response 对象身上取出网页源码或数据。
  4. 持久化存储——把拿到的数据写进文件或数据库。
import requests

url = 'http://www.eastmoney.com'
response = requests.get(url)
data = response.text
with open('eastmoney.html', 'w', encoding='utf-8') as f:
    f.write(data)

response 对象的三个关键属性

属性返回类型适用场景
response.text字符串（str）网页源码、HTML、JSON 等文本数据
response.content二进制（bytes）图片、PDF、影片等二进制文件
response.json()字典或列表服务器直接返回 JSON 数据时，自动反序列化

绝大多数网页爬虫用的是 response.text，因为我们要的就是那堆 HTML 源码。

中文乱码：第一条肌肉记忆

伺服器回傳的原始資料本質上是一串數字，需要靠「編碼」（charset）這本密碼本翻譯成人類看得懂的文字。同樣的數字用不同密碼本翻譯，結果天差地遠——用 UTF-8 翻譯是「你好」，用 GBK 翻譯可能變成「浣犲傖」。

很多中文網站的程式員偷懶，伺服器實際用 GBK 編碼寫網頁，卻在 HTTP 回應頭裡說謊——宣告自己是 UTF-8（或者乾脆不宣告）。requests 很聽話，伺服器說什麼編碼就用什麼編碼去翻譯，翻譯錯了就是一坨亂碼。

解決辦法很暴力：直接用 response.encoding = 'utf-8' 覆蓋掉 requests 猜測的編碼，再存取 response.text 就是正常的中文了。這是寫爬蟲的第一條肌肉記憶：一旦看到亂碼，先改 encoding。
