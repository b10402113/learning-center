Threading 线程与线程池

js-reverse · 节点 05 · 步骤 4/5

学习目标

掌握 threading.Thread 的创建与启动，理解线程共享全局变量与进程数据隔离的差异，并学会用线程池 pool.map 批量派发爬虫任务。

Thread 的基本用法

Python 推荐使用 threading 模块（比 thread 更先进、支持更完善）。创建线程的 API 与 Process 几乎一致。

import threading

def worker(name):
    print(f"线程 {name} 执行中")

t = threading.Thread(target=worker, args=('A',))
t.start()      # 启动线程
t.join()       # 等待线程结束

也可以继承 Thread 重写 run 方法：

class MyThread(threading.Thread):
    def run(self):
        print("线程执行中")

t = MyThread()
t.start()

线程共享全局变量

与进程数据隔离相反，同一进程内的线程共享全局变量。子线程修改全局变量后，主线程立即可见。

import threading

n = 100

def modify():
    global n
    n = 0

t = threading.Thread(target=modify)
t.start()
t.join()
print(n)  # 输出 0
关键对照：进程修改全局变量不影响主进程（输出 100），线程修改全局变量主线程可见（输出 0）。这是进程与线程最核心的行为差异。

线程池

线程预先创建放入池中，处理完当前任务后不销毁而是接下一个任务，避免多次创建线程的开销，带来更好性能和系统稳定性。

线程池模块从 multiprocessing.dummy 导入 Pool：

from multiprocessing.dummy import Pool
import requests

urls = ['http://example.com/1', 'http://example.com/2', 'http://example.com/3']

def download(url):
    resp = requests.get(url)
    return len(resp.text)

# 创建含 3 个线程的池
pool = Pool(3)
# 批量派发任务
results = pool.map(download, urls)
pool.close()  # 释放池
print(results)  # [响应长度1, 响应长度2, 响应长度3]

pool.map(func, urls) 的调用次数取决于可迭代对象元素个数，每次接收一个元素作为参数。这是爬虫批量请求最常用的写法。

进程 vs 线程选型

场景推荐原因
需要数据隔离进程避免相互影响，稳定性高
需要共享数据线程天然共享全局变量
CPU 密集型进程绕过 GIL，利用多核
I/O 密集型（爬虫）线程/协程轻量，切换快
