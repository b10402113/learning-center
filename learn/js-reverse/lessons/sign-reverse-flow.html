sign 逆向的基本流程

js-reverse · 步骤 1/5 · 从抓包到复现的三步法

拿到一个带 sign 参数的请求时，你面对的核心问题其实只有一个：这个看起来很乱的 32 位十六进制字符串，到底是怎么从原始数据算出来的。答案通常藏在一个固定的模式里——把几个关键参数按特定顺序拼成一串字符，然后取 MD5。整个逆向过程就是把这个模式重新挖出来的过程。

从 Network 面板开始

在 Chrome DevTools 的 Network 面板里，有道翻译的 POST 请求体大概长这个样子：

i=apple
from=auto
to=
dictResult=true
keyid=webfanyi
sign=1a2b3c4d5e6f7890abcdef1234567890
client=fanyideskweb
product=webfanyi
appVersion=1.0.0
vendor=web
pointParam=client,mysticTime,product
mysticTime=1718611200000
keyfrom=fanyi.web

十几个参数里，真正每次请求都会变的只有两个：mysticTime 和 sign。mysticTime 是一串十三位数字，明显是毫秒级时间戳。sign 是一个三十二位的十六进制字符串，看起来完全随机。

找到变化的参数之间的因果关系

两个变化的参数之间其实有因果关系：sign 是用 mysticTime 算出来的。所以问题就简化成了：除了 mysticTime 之外，还有哪些参数参与了 sign 的计算？

答案藏在 pointParam 字段里。它的值是 client,mysticTime,product，恰好把参与签名计算的参数名字点名了出来。pointParam 就是客户端留给自己的备忘录，告诉自己在生成 sign 的时候该把哪些字段拼进去。

还原拼接顺序

确定了参与参数之后，下一步是还原拼接顺序。在 Python 版源码里，拼接的模板是固定的：

s = f"client={u}&mysticTime={e}&product={d}&key={t}"

这里的 u、e、d、t 分别对应四个值：

  • u = fanyideskweb（来自 client 字段）
  • e = 1718611200000（当前毫秒时间戳）
  • d = webfanyi（来自 product 字段）
  • t = fsdsogkndfokasodnaso（硬编码字符串）

四个值按固定顺序用 & 和 = 连接成一条长字符串，然后对整个字符串取 MD5 摘要，得到的十六进制表示就是 sign。

三步法总结

整个逆向过程可以总结成三步：

  1. 区分静态参数和动态参数——从请求体里找出每次都会变的字段。
  2. 确定签名参数和拼接顺序——通过 pointParam 字段或者直接阅读 JS 代码。
  3. 用 Python hashlib.md5 复现——把同样的字符串拼出来、算出同样的摘要。

三步都做完之后，你每次请求都只需要更新 mysticTime 这一个变量，sign 会自动跟着变，服务器就会认为这是一个合法的客户端请求。

通用性

这个三步法的价值在于它不仅仅适用于有道翻译。之后你遇到的 sign、token、_d 这类动态参数，绝大多数都是同一个套路：固定模板 + 动态变量 + 标准摘要算法。掌握了这个流程，就相当于拿到了一把能开一类锁的通用钥匙。
