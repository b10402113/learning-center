CryptoJS DES 解密 API 链

实战：DES/AES 案例 · 步骤 2/4

学习目标

逐行拆解 CryptoJS DES 解密的完整 API 链——parse key、Base64 解析密文、decrypt 调用、UTF-8 输出，能独立写出 DES-ECB 解密函数。

解密函数全貌

上一课我们直接调用了 decryptByDES 函数，但没有解释它内部发生了什么。现在打开 02 招标网.js，逐行读：

CryptoJS = require("crypto-js")

function decryptByDES(ciphertext) {
    var keyHex = CryptoJS.enc.Utf8.parse("1qaz@wsx3e");
    var decrypted = CryptoJS.DES.decrypt({
            ciphertext: CryptoJS.enc.Base64.parse(ciphertext),
        },
        keyHex, {
            mode: CryptoJS.mode.ECB,
            padding: CryptoJS.pad.Pkcs7,
        }
    );
    return decrypted.toString(CryptoJS.enc.Utf8);
}

第一行：解析密钥

var keyHex = CryptoJS.enc.Utf8.parse("1qaz@wsx3e");

CryptoJS.enc.Utf8.parse() 把字符串密钥转成 CryptoJS 内部的 WordArray 格式。密钥 "1qaz@wsx3e" 是 9 个字符，DES 密钥的有效长度是 8 字节（64 位），所以实际只取前 8 个字符 "1qaz@wsx"。

这一步的要点是：parse 是把人类可读的字符串转成 CryptoJS 能处理的二进制格式。

第二行：解析密文

ciphertext: CryptoJS.enc.Base64.parse(ciphertext),

我们拿到的密文是 Base64 编码的字符串。CryptoJS 要求密文也以 WordArray 格式传入，所以要用 CryptoJS.enc.Base64.parse() 把 Base64 字符串解码成原始字节。

这一步对应的是：把 Base64 → 二进制。

第三行：执行解密

var decrypted = CryptoJS.DES.decrypt(
    { ciphertext: ... },   // 密文 WordArray
    keyHex,                // 密钥 WordArray
    { mode: ..., padding: ... }  // 配置项
);

CryptoJS.DES.decrypt() 接受三个参数：

  • 密文对象：包含 ciphertext 字段的对象
  • 密钥：WordArray 格式的密钥
  • 配置：加密模式和填充方式

加密模式：ECB

mode: CryptoJS.mode.ECB,

ECB（Electronic Codebook，电子密码本） 是最简单的分组加密模式：把明文切成固定大小的块（DES 是 8 字节一块），每块独立加密。相同的明文块会产生相同的密文块。

模式特点适用场景
ECB每块独立加密，相同明文→相同密文简单数据、短消息
CBC每块依赖前一块，需要 IV通用场景、长消息
CFB流密码模式实时数据流

ECB 的缺点是安全性较低，但实现简单，很多老系统还在用。

填充方式：Pkcs7

padding: CryptoJS.pad.Pkcs7,

DES 要求明文长度必须是 8 字节的整数倍。如果不够，就需要填充。Pkcs7 的填充规则是：缺几个字节就填几个该数字。

例如：明文 "hello" 是 5 字节，还差 3 字节，就填充 03 03 03。解密时，CryptoJS 会自动识别并去除填充。

第四行：输出明文

return decrypted.toString(CryptoJS.enc.Utf8);

decrypt() 返回的是一个 WordArray 对象，要转回人类可读的字符串，需要用 .toString() 并指定编码。CryptoJS.enc.Utf8 表示把二进制数据按 UTF-8 解码成字符串。

完整 API 链

把四行代码串起来，就是 CryptoJS DES 解密的完整链条：

密钥字符串 ──parse──▶ 密钥 WordArray ──┐
                                      ├──▶ decrypt() ──toString──▶ 明文
Base64密文 ──parse──▶ 密文 WordArray ──┘

独立写出 DES-ECB 解密函数

理解了 API 链后，你应该能独立写出类似函数。核心只有四步：

function desDecrypt(ciphertext, key) {
    // 1. 解析密钥
    var keyHex = CryptoJS.enc.Utf8.parse(key);
    // 2. 执行解密
    var decrypted = CryptoJS.DES.decrypt(
        { ciphertext: CryptoJS.enc.Base64.parse(ciphertext) },
        keyHex,
        { mode: CryptoJS.mode.ECB, padding: CryptoJS.pad.Pkcs7 }
    );
    // 3. 输出明文
    return decrypted.toString(CryptoJS.enc.Utf8);
}

与有道翻译案例的对比

案例加密类型密钥来源Python 侧职责
有道翻译AES-CBC固定字符串发请求
招标网DES-ECB固定字符串发请求 + JS 解密

两个案例的共同点是：加密逻辑都在 JS 侧完成，Python 只负责发请求和接收结果。

常见坑

  • 密钥长度不对：DES 密钥必须是 8 字节，超长会被截断，不足要填充。
  • 密文不是 Base64：如果密文是十六进制字符串，需要用 CryptoJS.enc.Hex.parse() 代替 Base64.parse()。
  • 模式/填充不匹配：加密端用 CBC + Pkcs7，解密端也得用 CBC + Pkcs7，否则解密出来是乱码。

小结

CryptoJS DES 解密的 API 链其实只有四步：parse key、parse ciphertext、decrypt、toString。理解这条链之后，任何 CryptoJS 的 DES 解密代码都只是一层窗户纸。下一步，我们把视线转向 AES——更现代、更安全的对称加密算法。
