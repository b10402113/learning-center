loader + mod 分离：webpackJsonp.push 劫持与模块注册

学习目标：理解真实站点的 webpack 产物如何被拆成 loader + 若干 mod，loader 如何劫持 webpackJsonp.push 完成模块注册，以及如何在本地 Node 里 require 后复现加密函数。

真实站点的产物长什么样

教学 demo 是理想化的单文件，真实站点会把产物拆成一个 loader.js + 多个 mod 文件。这种拆分有两个目的：

  • 并行加载：浏览器可以同时下载多个文件，提升首屏速度。
  • 长效缓存：第三方库（lodash、core-js）单独打包成一个 chunk，业务代码改动能复用缓存。

对逆向者来说，这意味着加密函数只会在 mod 文件里，loader 本身只是调度壳。定位加密函数的第一步永远是先找到哪个 mod 文件包含了目标模块 ID。

webpackJsonp：模块注册的通道

loader 与 mod 之间的通信靠一个全局数组 window.webpackJsonp。这个名字是 webpack 默认的，有些站点会改名，但机制不变。

mod 文件的典型头部长这样：

(window.webpackJsonp = window.webpackJsonp || []).push([
  ["app"],           // chunk 名
  { 模块字典 },      // 真正的模块源代码
  [[1, "runtime", "chunk-libs"]]  // 依赖的其他 chunk
])

这行代码的含义是：向 webpackJsonp 数组 push 一条记录，告诉 loader"我这里有 app 这个 chunk 的模块，但我依赖 runtime、chunk-libs 这两个 chunk，请确保它们先就绪"。

loader 如何劫持 push

loader 在初始化时，会把 webpackJsonp.push 替换成自己的处理函数：

var u = window.webpackJsonp.push;
window.webpackJsonp.push = function(chunk) {
  // 遍历 chunk 里的模块字典，逐个注册进加载器的调度表
  chunk[1].forEach(function(moduleId, moduleSource) {
    // 调度器内部把模块 ID 和源代码绑定
  });
  // 再调用原来的 push，保留数组语义
  return u.call(window.webpackJsonp, chunk);
};

这样，每当一个 mod 文件加载执行、调用 push 时，loader 就会第一时间把它的模块字典收入自己的调度表，同时执行该 chunk 依赖就绪后的入口模块。

loader 的分工：只调度，不干活

真实站点的 loader 通常只包含以下职责，没有任何业务加密逻辑：

code>
职责对应代码说明
调度函数f(n) / u(r)传入 ID，返回 exports，带缓存
chunk 异步加载表f.e200+ 个 chunk 名到真实文件名的映射
资源根路径f.p = "/"补全异步 chunk 的 URL 前缀
依赖就绪检测u()按依赖图逐个执行入口模块

看到这样的文件，你应该一眼认出："这是加载器壳子，加密函数在 mod 里"。

外贸电商平台的完整调用链

以外贸电商平台为例，loader 末尾直接写了一个测试调用：

window.loader("MuMZ").a("123")

这行代码的意思是：找到 MuMZ 模块的 exports，然后调它的 a 函数，传入 "123"。MuMZ 是 4 位哈希 key，说明这个站点用的是哈希调度。

调用链拆解如下：

  1. 加载器从缓存 t["MuMZ"] 找到模块 exports。
  2. 模块 exports 对象上有属性 a（即该模块导出的某个函数）。
  3. 调用 a("123") 得到加密结果。

本地 Node 复现的最小流程

要在本地 Node 里复现 window.loader("MuMZ").a("123")，只需要三步：

// 1. 补浏览器环境
global.window = global;

// 2. 按顺序 require loader 和它依赖的所有 mod
require("./loader.js");          // 先加载调度器，劫持 webpackJsonp.push
require("./mod1.js");            // 注册 app chunk 的模块（含 MuMZ）
require("./mod2.js");            // 注册 chunk-libs 的第三方库

// 3. 直接调目标函数
console.log(window.loader("MuMZ").a("123"));

关键点：必须先 require loader，再 require mod。顺序反了，mod 执行时 webpackJsonp.push 还没被劫持，模块就注册失败了。

mod 文件的典型规模

真实站点的 mod 文件往往很大：

  • 外贸电商平台 mod1：33745 行、2.5 MB，200+ 个模块。
  • 外贸电商平台 mod2：38344 行，lodash + core-js + MD5。

你不需要读完每一行。正确做法是先读文件头 100-300 行判定结构，再按模块 ID 用搜索定位目标函数。99% 的模块跟你无关。
