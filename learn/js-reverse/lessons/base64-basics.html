base64 編碼與解碼

學習目標：理解 base64 是「位元組到可見字元的重編碼」而非加密，能從末尾 = 填充符和 A-Za-z0-9+/ 字元集識別它，並在 Python 裡正確編解碼含中文與特殊位元組的字串。

現象：你在抓包裡看到這種字串

當你開始逆向前端請求，最常遇到的第一類密文長這樣：

SGVsbG8gV29ybGQh
IyEk
5L2g5aW9

它們有幾個共同特徵：只包含大小寫字母、數字、+ 和 /，長度常常是 4 的倍數，末尾有時會冒出一到兩個等號。這不是加密，這是 base64。

為什麼需要 base64？

HTTP 協議是文字協定，但圖片、音訊、附件都是二進位資料。如果直接把二進位塞進 URL、JSON 或 HTML 裡，某些位元組會和協定字元衝突（例如 &、=、換行）。base64 的本質就是：把 8 位元的二進位資料，重新編碼成 6 位元的可見字元，讓二進位資料可以安全地用文字傳輸。

原理：3 位元組 → 4 字元

base64 把輸入每 3 個位元組（24 位元）切成 4 組 6 位元，每組 6 位元對應到一個可見字元。6 位元有 64 種可能，所以字元表是：

索引 0-25:  A-Z
索引 26-51: a-z
索引 52-61: 0-9
索引 62:    +
索引 63:    /

用課本裡的例子推一次：#!@ 這三個字元的 ASCII 分別是 0x23、0x21、0x40，二進位是：

00100011 00100001 01000000

重新按 6 位元切：

001000 110010 000101 000000

對應索引 8、51、5、0，查表得到 IyEk。這就是 base64 編碼結果。

填充符 = 的坑

如果原始資料不是 3 的倍數，base64 會在輸出末尾補 = 填充符，讓總長度維持在 4 的倍數：

  • 剩 1 個位元組 → 補 2 個 =
  • 剩 2 個位元組 → 補 1 個 =

逆向時最常見的錯誤：抓到的 base64 字串被截斷或去掉了末尾等號，直接解碼會報錯。Python 裡手動補齊的寫法：

import base64

data = "SGVsbG8"
data += (4 - len(data) % 4) * "="
print(base64.b64decode(data).decode())  # Hello

Python 實作

base64.b64encode 吃的是位元組，回傳的也是位元組。所以中文要先 .encode() 才能編解碼：

import base64

# 編碼
text = "你好世界"
encoded = base64.b64encode(text.encode("utf-8")).decode()
print(encoded)  # 5L2g5aW95LiW55WM

# 解碼
decoded = base64.b64decode(encoded).decode("utf-8")
print(decoded)  # 你好世界

重點整理

  • base64 是編碼，不是加密，沒有金鑰，任何人都能解。
  • 字元集：A-Z a-z 0-9 + /，末尾可能補 =。
  • 長度一定是 4 的倍數；不是的話，先補 = 再解。
  • Python 用 base64.b64encode / b64decode，記得先 .encode() 成位元組。
