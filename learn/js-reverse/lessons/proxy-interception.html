Proxy 拦截与环境探测

用 Proxy 自动发现扣下的代码读了哪些环境属性

为什么要用 Proxy？

上一课讲到「缺什么补什么」的工作流：跑代码 → 看报错 → 补属性 → 再跑。这个流程能用，但低效——每补一个属性就要重新跑一遍，遇到依赖属性多的代码，来回折腾十几次是常态。

有没有办法让代码自己「报」出它读了什么？有，用 Proxy 把 window 包装一下，代码每次读属性时，Proxy 都能感知并记录下来。这样跑一次就知道缺什么，一次性补齐。

Proxy 的基本结构

Proxy 是 ES6 引入的代理机制，能拦截对象的基本操作。对补环境来说，最常用的是 get 和 set 两个 trap：

var obj = { username: "yuan", age: 0 };

obj = new Proxy(obj, {
    get(target, p, receiver) {
        // 读取属性时触发
        console.log("读取属性:", p);
        return Reflect.get(target, p);
    },
    set(target, p, value, receiver) {
        // 写入属性时触发
        console.log("写入属性:", p, "=", value);
        Reflect.set(target, p, value);
    }
});

console.log(obj.username);  // 触发 get，输出 "读取属性: username"
obj.age = 25;               // 触发 set，输出 "写入属性: age = 25"

target 是被代理的原始对象，p 是属性名，value 是新值。Reflect.get 和 Reflect.set 是 trap 里操作原对象的正确姿势——它们等价于直接读写 target[p]，但不会再次触发 Proxy 的 trap（避免递归）。

用 Proxy 做环境探测

把上一课的 window = global 和 Proxy 结合，就能做出一个「环境探测代理」：代码读了什么属性、写了什么值，全部打印出来。跑一次就知道要补什么。

window = global;
window = new Proxy(window, {
    get(target, p) {
        console.log("读取环境属性:", p);
        return Reflect.get(target, p);
    },
    set(target, p, value) {
        console.log("写入环境属性:", p, "=", value);
        return Reflect.set(target, p, value);
    }
});

把扣下的代码接在后面跑，所有对 window 的访问都会触发 get/set，控制台输出一行行日志。跑完一遍，补环境的清单就出来了。

set trap 里还能做校验

Proxy 的 set trap 不只是记录，还能做校验。比如限制 age 字段的取值范围：

set(target, p, value, receiver) {
    if (p === "age") {
        if (value < 100) {
            Reflect.set(target, p, value);
        } else {
            console.log("age 范围不对");  // 拦截非法值
        }
    } else {
        Reflect.set(target, p, value);
    }
}

补环境时这个能力很有用：如果某个环境属性被写入了一个离谱的值（比如 window.screenWidth = 99999），可以直接拦截并提醒自己「这个值可能不对」。

一个容易踩的坑：递归

在 get trap 里写 return window['xxx'] 是错的——这会再次触发 Proxy 的 get trap，无限递归，直到爆栈。

// 错误写法
get(target, p) {
    return window['username'];  // 又触发 get → 递归！
}

// 正确写法
get(target, p) {
    return Reflect.get(target, p);  // 不触发 trap
}

在 trap 里操作原对象，永远用 Reflect.get(target, p) 或 Reflect.set(target, p, value)，不要直接访问被代理的对象。

完整工作流对比

传统补环境Proxy 环境探测
跑代码 → 报错 → 补属性 → 再跑Proxy 包装 window → 跑一次 → 看日志 → 批量补齐
每次只能发现一个缺失属性一次运行发现所有读写
适合属性少的简单场景适合属性多、依赖复杂的代码

两种方式不矛盾：简单场景用手动补，复杂场景用 Proxy 探测，发现属性后再批量补上。
