Python 聯調與介面請求

打通「JS 逆向產物 → Python 爬蟲參數」的最後一公里。

學習目標

用 execjs 在 Python 側即時生成 anti_content，構造合法請求拉取拼多多介面資料。

execjs 的角色

前面所有步驟（補環境、掛 chunk、跑 loader、包純函式）都是在 JS 世界裡把 get_anti_content() 準備好。現在要讓 Python 能呼叫它。

execjs 是一個 Python 套件，能把 JS 程式碼編譯後直接在 Python 裡執行。標準用法是：

import execjs
ctx = execjs.compile(open("05 pdd.js").read())
anti_content = ctx.call("get_anti_content")

compile 把整個 JS 檔編成一個可呼叫的上下文，call("get_anti_content") 直接執行我們包好的純函式，回傳值就是最新的 anti_content 字串。

構造請求

拿到 anti_content 後，把它放進請求參數，打拼多多商品列表介面：

import requests

url = "https://apiv2.pinduoduo.com/api/gindex/tf/query_tf_goods_info"
params = {
    "anti_content": anti_content,
    "tf_id": "...",
    "page": 1,
    "size": 20
}
headers = {
    "Origin": "https://www.pinduoduo.com",
    "Referer": "https://www.pinduoduo.com/",
    "User-Agent": "Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7)...",
    "sec-ch-ua": '"Not_A Brand";v="8", "Chromium";v="120"',
    "sec-ch-ua-mobile": "?0",
    "sec-ch-ua-platform": '"macOS"'
}

resp = requests.get(url, params=params, headers=headers)
print(resp.json())

Headers 的風控細節

拼多多不是隻看 anti_content，它還會檢查整組 headers 是否像一個正常的瀏覽器。幾個容易忽略的欄位：

欄位作用
Origin必須與 location.origin 一致，否則會被視為跨站請求
Referer必須指向拼多多頁面，不能空著
sec-ch-ua瀏覽器品牌與版本，要與 User-Agent 吻合
sec-ch-ua-platform作業系統，要與 navigator.platform 吻合

這些欄位在補環境時就已經被 JS 讀取並參與加密，所以 Python 側必須用同樣的值，否則伺服器會發現「JS 加密用的 UA 跟 HTTP headers 的 UA 不一致」，直接拒絕。

即時生成，不缓存

每次請求前都必須重新跑一次 get_anti_content()，不能把結果存起來重複使用。這是因為 anti_content 內含時間因子，舊值很快就會被伺服器認定為過期。

實務上的做法是在每個請求前都 ctx.call("get_anti_content") 一次，雖然會多一點點延遲，但能確保每次都是全新的 token。

完整閉環

把全部步驟合起來，就是一個完整的「JS 逆向 → Python 爬蟲」閉環：

  1. 從站點摳出 JS（env、mod1、mod2、loader、pdd.js）。
  2. 用 execjs 編譯 05 pdd.js。
  3. 每次請求前呼叫 get_anti_content() 取得即時 token。
  4. 構造與瀏覽器一致的 headers 與 params。
  5. 發送請求，穩定翻頁拉取資料。

這就是「補環境」這個技術在真實爬蟲裡的落地方式：不是為了跑 JS 而跑 JS，而是為了把 JS 產出的加密參數，橋接回 Python 的請求流程。
