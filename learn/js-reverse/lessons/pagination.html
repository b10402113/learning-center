多页翻页爬取

深度爬取与 POST 请求 · 步骤 2/4

学习目标

能用 URL 模板 + 页码递增的方式，让 scrapy 自动翻页爬取全站列表数据。

翻页的本质

很多网站的列表页都是分页的——新闻站、电商搜索结果、博客文章列表。第一页、第二页、第三页……每一页的 URL 通常有规律：

https://wz.sun0769.com/political/index/politicsNewest?page=1
https://wz.sun0769.com/political/index/politicsNewest?page=2
https://wz.sun0769.com/political/index/politicsNewest?page=3

翻页爬取的本质就是：解析完第 N 页后，构造出第 N+1 页的 URL，然后 yield 一个新的 Request 让 scrapy 继续抓。

URL 模板 + 页码递增

最直观的做法是定义一个 URL 模板，里面用 %d 占位，然后维护一个页码计数器：

import scrapy

class SunSpider(scrapy.Spider):
    name = 'sun'
    url_model = 'https://wz.sun0769.com/political/index/politicsNewest?page=%d'
    page_num = 1

    def parse(self, response):
        # 解析当前页的数据
        titles = response.xpath('//span[@class="state3"]/text').extract()
        for title in titles:
            yield {'title': title}

        # 翻页：页码递增，构造新 URL
        if self.page_num <= 5:
            self.page_num += 1
            new_url = self.url_model % self.page_num
            yield scrapy.Request(url=new_url, callback=self.parse)

这里的关键是 yield scrapy.Request(url=new_url, callback=self.parse)——它告诉 scrapy："抓这个新 URL，抓完之后把响应交给我自己的 parse 方法"。这就形成了一个自我循环：parse → 翻页 → parse → 翻页……

控制翻页的终止

翻页不能无限进行。上面的例子用 if self.page_num <= 5 限制只抓 5 页。实际项目中，终止条件通常有三种：

  • 固定页数：if self.page_num <= 10，适合测试或已知总页数的场景。
  • 检测"下一页"按钮是否存在：用 xpath 找页面上的"下一页"链接，如果找不到就说明到最后一页了。
  • 检测当前页是否为空：如果解析不到任何数据，说明已经超出范围。

用 xpath 找"下一页"链接

更优雅的做法是直接解析页面上的"下一页"按钮的 href，而不是自己拼 URL：

def parse(self, response):
    # 解析当前页数据
    for item in response.xpath('//div[@class="width-12"]/dl'):
        yield {'title': item.xpath('./a/text()').extract_first()}

    # 找"下一页"链接
    next_url = response.xpath('//a[@class="next"]/@href').extract_first()
    if next_url:
        yield scrapy.Request(url=response.urljoin(next_url), callback=self.parse)

这样做的好处是：不管 URL 长什么样，只要页面上有"下一页"按钮，爬虫就能自动跟着走。缺点是有些网站的"下一页"链接是 JavaScript 动态渲染的，xpath 抓不到——这时候就只能回到 URL 模板的方式。

翻页 + 进详情页的组合

翻页通常不是单独使用的。真实项目里，你往往需要先翻页遍历列表，再对每条数据进详情页抓取完整内容。这就涉及"列表页的 item 怎么传给详情页"的问题——下一节课会专门讲 meta 跨页传参。

常见踩坑

  • 忘记写 callback=self.parse：如果不指定 callback，scrapy 会用默认的 parse 方法，但如果你的 Spider 里重写了多个解析方法，就会调错。
  • 页码从 0 还是从 1 开始：不同网站的页码起始值不同，先手动访问几页确认。
  • URL 模板里的参数名写错：比如把 page 写成 p，会抓到 404 页面。
