IIFE 与闭包

JS 逆向 · 节点 15 · 步骤 3/5

学习目标

能识别 IIFE 与闭包、理解闭包如何构建私有状态，读懂混淆代码里藏在闭包里的关键变量。

匿名函数与函数表达式

JS 的函数可以不给名字——这就是匿名函数。最常见的用法是赋值给变量，变成函数表达式：

var greet = function(name) {
  return "hi " + name;
};
console.log(greet("world")); // hi world

函数表达式和函数声明的关键区别：函数表达式不会被提升，变量只提升声明、不提升赋值。所以函数表达式必须写在调用之前，否则会报错。

IIFE：定义即执行的匿名函数

IIFE（Immediately Invoked Function Expression，立即调用函数表达式）就是定义完立刻跑的匿名函数。写法是把函数包在括号里，末尾加一对调用括号：

(function(a, b) {
  console.log(a + b);
})(1, 2); // 3

还有一种变体是在函数前面加 !、+、- 这类一元运算符，把函数声明强制转成表达式：

!(function(x, y) {
  console.log(x * y);
})(3, 4); // 12

为什么非要写成这样？因为 function(){} 放在行首会被解析成函数声明，而函数声明不能直接加 () 调用。加括号或加 ! 就是告诉解析器"这是个表达式"。逆向时看到 !、+、( 开头的匿名函数，要立刻认出这是 IIFE——这是混淆代码最经典的包裹方式。

IIFE 为什么能隔离作用域

IIFE 内部声明的变量被锁在函数作用域里，外部访问不到：

(function() {
  var n = 0;
  // n 跑在 IIFE 内部，外部访问不到
})();
console.log(typeof n); // undefined

这可以当成"一次性的局部作用域"用。但它有一个局限：IIFE 跑完就没了，无法重复调用。如果想要多个各自独立的计数器，IIFE 做不到——这就需要闭包。

闭包：外层函数返回内层函数

闭包的本质是一个函数持续引用外层函数的变量。典型写法是外层函数返回内层函数：

function getCounter() {
  var n = 0; // 外层变量
  function counter() {
    n++;
    console.log(n);
  }
  return counter;
}

var c1 = getCounter();
var c2 = getCounter();
c1(); // 1
c1(); // 2
c2(); // 1（独立的 n）

getCounter() 执行完之后，按理说它的局部变量 n 应该被销毁。但因为返回的 counter 函数始终引用着 n，JS 引擎会把 n 保留在内存里——这就是闭包。每次调用 getCounter() 都会创建一份全新的、独立的 n，所以 c1 和 c2 各自计数、互不干扰。

闭包的私有性

闭包里的变量外部无法直接访问，也不污染全局：

var c = getCounter();
console.log(c.n); // undefined —— 没有 n 这个属性
console.log(n);    // ReferenceError —— 全局也没有 n

想要读到或改掉 n，只能通过闭包暴露出来的 counter 函数。这种"数据藏在函数里"的模式，正是混淆器保护关键变量和函数的标准手段。逆向时如果发现某个变量既不在全局、也不在对象属性上，首先怀疑它被藏在某个闭包里——接下来要做的就是找到持有它的外层函数。
