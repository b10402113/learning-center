爬蟲的本質：客戶端模擬與請求—響應模型

js-reverse · 00-crawler-fundamentals · Step 1/3

學習目標

理解爬蟲的本質是模擬客戶端發送網路請求並獲取數據的程式，區分 B/S 與 C/S 兩種架構下的爬蟲形態。

你每天都在做的事情

打開瀏覽器、在地址欄輸入網址、按下 Enter——這背後發生了什麼？瀏覽器向網站伺服器發出一個 HTTP 請求，伺服器收到後把網頁內容（HTML、圖片、資料）打包傳回來，瀏覽器再把它渲染成你看到的頁面。

這個過程叫做請求—響應模型（Request-Response Model）。瀏覽器扮演的是「客戶端」的角色，網站是「伺服器」。所有的網路互動，本質上都是客戶端在問、伺服器在答。

爬蟲就是用程式碼扮演客戶端

爬蟲（Web Crawler / Spider）做的事情和你用瀏覽器一模一樣：向網站伺服器發出請求，拿回數據。唯一的差別是，爬蟲是用程式碼自動化這個過程，不需要你手動打開瀏覽器、點擊按鈕。

一句話定義：爬蟲是模擬客戶端向伺服器發送網路請求並獲取數據的程式。

這裡的「模擬」很關鍵。爬蟲不是「入侵」伺服器，它和正常瀏覽器走的是同一條路——HTTP/HTTPS 協定。差別只在於：瀏覽器是給人用的，爬蟲是給程式用的。

B/S 與 C/S：兩種架構下的爬蟲

網路應用有兩種主流架構，爬蟲在兩種場景下都能工作：

架構全稱客戶端形式爬蟲對應
B/SBrowser/Server瀏覽器用 requests 等程式庫模擬瀏覽器發 HTTP 請求
C/SClient/Server桌面或行動應用程式抓包分析應用程式的網路請求，用程式碼復現

日常爬蟲以 B/S 為主——你要爬的網站都是透過瀏覽器存取的。C/S 場景更少見，但原理完全一樣：先用抓包工具（如 Charles、Fiddler）看清應用程式發了什麼請求，再用程式碼復現。

爬蟲的工作流程

一個最基本的爬蟲，不管多複雜，都遵循四個步驟：

  1. 指定 URL——你想要爬取的目標頁面或 API 地址
  2. 發送請求——用程式碼向該 URL 發出 HTTP 請求（GET 或 POST）
  3. 獲取響應——伺服器返回數據，可能是 HTML、JSON、圖片等
  4. 持久化存儲——把拿到的數據存到檔案或資料庫裡

這四步就是後續所有爬蟲實戰的骨架。不管後面加多少複雜度——登入驗證、動態渲染、加密簽名——都是在這四步上做文章。

反爬與反反爬：矛與盾

網站不希望被隨意爬取，所以會設定各種障碍阻止自動化請求，這叫做反爬機制。爬蟲工程師則要想辦法繞過這些障碍，這叫做反反爬策略。

這是一場持續的對抗。常見的反爬手段包括：

  • UA 檢測——檢查請求的 User-Agent 是不是瀏覽器
  • IP 限制——同一個 IP 請求太频繁就封鎖
  • 驗證碼——要求人工驗證才能繼續
  • 動態載入——資料不在 HTML 裡，由 JS 動態生成

後續的節點會逐步教你如何應對每一種反爬手段。現在只需要記住：反爬機制和反反爬策略是一對矛與盾，理解這個對抗關係，是學好爬蟲的前提。
