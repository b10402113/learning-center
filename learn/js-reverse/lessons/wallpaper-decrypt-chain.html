极简壁纸的完整解密链

atob → Int8Array → RC4 → UTF-8 解码

先看入口函数

扣下的解密代码入口是 _0x58b5da，它只有一行：

function _0x58b5da(_0x512f6f) {
    return _0x300484(_0x476691(_0x4176cc(_0x512f6f)));
}

这一行就是解密链的全貌。输入是 base64 加密字符串，输出是明文字符串。三个函数依次执行，每个函数做一件事。

第一步：_0x4176cc —— base64 转字节数组

    return _0x5384be;
}

做了两件事：

  1. window.atob：把 base64 字符串解码成普通字符串。这一步会用到浏览器 API，所以必须补环境（window = global）。
  2. Int8Array：遍历字符串，把每个字符转成对应的字节（0-255 的整数），得到字节数组。

输入是 "ak+9VCsq..." 这样的 base64 字符串，输出是字节数组。

第二步：_0x476691 —— RC4 异或

字节数组送进 RC4 函数，用 256 字节密钥数组做异或，输出还是字节数组，但内容已经是明文了。

function _0x476691(_0x4eff8a) {
    // KSA + PRGA 混合循环
    // 用密钥数组 _0x5f0aa7 对输入字节做异或
    return _0x114065;  // 明文字节数组
}

这一步完全在 Node.js 里跑，不需要补任何环境——因为 RC4 只用了数组运算，没碰浏览器 API。

第三步：_0x300484 —— UTF-8 字节解码成字符串

RC4 输出的是字节数组，但里面存的不是 ASCII 字符，而是 UTF-8 编码的中文字节。需要把这些字节还原成 JavaScript 字符串。

UTF-8 的字节规则：

首字节模式字符长度范围
0xxxxxxx1 字节ASCII
110xxxxx2 字节拉丁文扩展
1110xxxx3 字节中日韩常用字
11110xxx4 字节Emoji 等

这一步也不需要补环境，纯字节运算。

解密链跑通后，输出的就是一个 JSON 字符串，可以直接 json.loads 解析成 Python 字典。

为什么必须补 window.atob？

整条链只有第一步用了浏览器 API window.atob。后面两步都是纯字节运算，Node.js 原生就能跑。

所以补环境的范围非常小：只需要保证 window.atob 能工作。最简单的写法是 window = global，然后在 Node.js 里用 Buffer.from(str, 'base64').toString() 替代——但既然我们是用 execjs 跑 JS 代码，直接 window = global 让 window.atob 指向 Node.js 内置的 base64 解码就行。
