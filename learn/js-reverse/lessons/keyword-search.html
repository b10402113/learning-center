关键字搜寻

js-reverse · 步骤 3/4 · 当调用栈过深或代码混淆时的第二把钥匙

Call Stack 很好用，但它有一个前提：你能看懂函数名。真实项目里的代码经常经过压缩和混淆，函数名会变成 a、b、_0x1a2b3c 这种无意义的符号。这时候就算 Call Stack 展开了十几层，你也不知道哪一层在做加密。关键字搜索就是为这种情况准备的备选入口。

关键字搜索的三类弹药

在 DevTools 的 Global Search（Ctrl+Shift+F 或 Cmd+Shift+F）里，可以用三类关键字来定位加密相关的代码：

1. 参数名关联

你已经从抓包里知道加密字段叫 sign、token、password，直接在搜索框里搜这些词。代码里凡是读取、赋值、拼接这个字段的地方都会列出来。找到赋值的那一行，上下看几行，通常就能定位到加密函数。

2. URL 路径搜索

有时候加密参数的名字起得很隐晦，直接搜字段名搜不到。这时候可以搜请求的 URL 路径。比如有道翻译的接口是 /webtranslate，直接搜这个字符串，就能跳到发送请求的那一行代码。在这一行附近打断点，或者沿着调用链往回找，就能摸到加密逻辑。

3. 敏感词搜索

如果参数名和 URL 路径都搜不到，就只能靠敏感词碰运气了。常见的敏感词分两类：

  • 哈希与加密算法名：md5、sha1、sha256、aes、des、rsa
  • 序列化与编码函数：encrypt、decrypt、JSON.stringify、JSON.parse、btoa、atob

这些字符串即使经过混淆也经常保留原样，因为它们是 Web API 或者加密库暴露的方法名，混淆器一般不敢重命名它们。

关键字搜索和 Call Stack 的配合

在实际操作中，这两套方法经常交替使用。先用 Call Stack 快速定位一个大致范围，然后在这个范围里用关键字搜索精确定位。或者反过来：先用关键字搜索找到疑似加密函数，然后在里面打断点，触发请求后通过 Call Stack 验证调用路径。

举个例子：你搜 md5 找到了三个函数，不确定哪个是算 sign 的。在三个函数里都打上断点，触发一次请求。哪个断点先停下来，哪个就是算 sign 的那个。

搜索结果的筛选技巧

Global Search 经常返回几十个结果。不需要一个个看。注意这几点可以快速过滤：

  • 优先看 .js 文件，忽略 .map 和 .css
  • 优先看赋值语句（=）附近的上下文，而不是单纯读取变量的语句
  • 如果搜索结果里有 function 关键字紧挨着敏感词，比如 function encrypt(，这种几乎就是目标

一个实战组合拳

假设你抓到一个请求，发现请求体里有 sign=xxx，但 Call Stack 里全是混淆后的函数名。你可以这样做：

  1. Global Search 搜 sign，找到所有引用这个字段的地方
  2. 看搜索结果里有没有赋值给 sign 的语句
  3. 在赋值语句附近打断点，触发请求
  4. 断点停下来后，看局部变量里有没有明文变成密文的过程

这套组合拳不依赖函数名是否可读，也不依赖调用栈的深度，纯粹靠字符串匹配来定位。代码压缩和混淆对它就基本无效。
