丁香网参数构造与字典序拼接

实战：SHA1 与百度 sign · 步骤 2/5

学习目标

能独立构造丁香网病例搜索接口的 noncestr、timestamp、serverTimestamp 和明文串，理解参数按字典序排列后再喂给 SHA1 的拼接规则。

先看请求里藏了什么

打开 DevTools，刷新丁香网的病例搜索页，你会看到一个 GET 请求，URL 参数里除了普通的 keyword、pageNum，还多出几个看起来无意义的字段：noncestr、timestamp、serverTimestamp、sign。后三个每次都变，noncestr 是一个 8 位数字。

noncestr：8 位随机数字

noncestr 的生成规则很直接：生成一个 0 到 100000000 之间的随机整数，左补零到 8 位。

import random
noncestr = str(random.randint(0, 100000000)).rjust(8, '0')

为什么是 8 位？因为后端校验的就是 8 位。为什么左补零？因为 random.randint(0, 99999999) 可能返回 12345（只有 5 位），不补零就不符合长度要求。rjust(8, '0') 把右侧对齐、左侧填零，正好得到 "00012345" 这种格式。

timestamp 与 serverTimestamp：一对差 2 毫秒的时间戳

timestamp 是当前毫秒时间戳，serverTimestamp 则是它减 2：

import time
timestamp = int(time.time() * 1000)
serverTimestamp = timestamp - 2

为什么差 2 毫秒？这是丁香网前端自己加的偏移，不是 SHA1 的要求。它的唯一作用就是让你没法用「完全相同的时间戳」重放请求——每次请求的 timestamp 都会变，sign 也会跟着变。

关键规则：参数按字典序拼接

SHA1 的输入不是随便拼的，它要求所有参数按键名字典序排列：

data = (
    'appSignKey=4bTogwpz7RzNO2VTFtW7zcfRkAE97ox6ZSgcQi7FgYdqrHqKB7aGqEZ4o7yssa2aEXoV3bQwh12FFgVNlpyYk2Yjm9d2EZGeGu3'
    '&keyword=新冠'
    '&noncestr=00122001'
    '&pageNum=1'
    '&pageSize=10'
    '&sectionCode=0'
    '&serverTimestamp=1704717058592'
    '&timestamp=1704717058594'
)

注意顺序：appSignKey → keyword → noncestr → pageNum → pageSize → sectionCode → serverTimestamp → timestamp。这是严格的 ASCII 字典序——大写字母在小写字母前面，pageN 在 pageS 前面。

appSignKey 是一个硬编码常量，不会变。它的存在是为了给签名加一个只有前端知道的「盐」，防止别人只靠公开参数就算出 sign。

拼接错误最常见的两个坑

  1. 顺序搞错：按 URL 参数出现的顺序拼，而不是按 key 的名字典序。算出来的 sign 必然对不上。
  2. noncestr 没补零：直接用 str(random.randint(...)) 不补零，长度不固定，sign 也会变。

小结

丁香网的参数构造没有技术难点，全是细节：noncestr 补零、timestamp 取毫秒、serverTimestamp 减 2、参数按字典序拼。下一步我们就把这段明文串丢给 execjs 跑 SHA1，拿到 sign 后拼进请求。
