多管道优先级与数据库存储

Scrapy 管道与持久化 · 步骤 2/4

学习目标

用多个管道类把同一份数据分别存到文件、MySQL、Redis，并理解优先级数字如何控制 Item 在管道链中的流转顺序。

一个 Item，多个目的地

上一节我们学会了用一个管道把 Item 存到文件。但真实项目里，一份数据往往要同时存到多个地方：写一份 CSV 做备份、写 MySQL 做查询、写 Redis 做缓存队列。难道要 Spider 分别 yield 三次吗？

不需要。Scrapy 支持在 ITEM_PIPELINES 里注册多个管道类。Spider 只管 yield 一次 Item，引擎会自动把 Item 丢进管道链，让每个管道轮流处理一遍。

优先级数字：谁先谁后？

ITEM_PIPELINES 是一个字典，key 是管道类的路径，value 是优先级数字。数字越小，优先级越高，Item 越先交给它处理。

# settings.py
ITEM_PIPELINES = {
    'myproject.pipelines.FilePipeline': 300,
    'myproject.pipelines.MySQLPipeline': 301,
    'myproject.pipelines.RedisPipeline': 302,
}

Item 的流转顺序是：

  1. 先交给 FilePipeline（300，最高优先级）
  2. FilePipeline.process_item 处理完，return item
  3. 引擎把 Item 交给 MySQLPipeline（301）
  4. MySQLPipeline.process_item 处理完，return item
  5. 引擎把 Item 交给 RedisPipeline（302）
  6. RedisPipeline.process_item 处理完，return item
  7. 没有下一个管道了，Item 处理完毕

这里的关键规则是：每个管道的 process_item 都必须 return item。只要有一个管道忘了 return，Item 就会在这个管道里断掉，后面的管道全部收不到。

MySQL 管道：用 pymysql 存关系型数据库

MySQL 管道是最常见的数据库存储方案。核心流程是：在 open_spider 里用 pymysql.Connect 建立连接，在 process_item 里用 cursor 执行 SQL 并 commit，在 close_spider 里关闭游标和连接。

# pipelines.py
import pymysql

class MySQLPipeline:
    def open_spider(self, spider):
        self.conn = pymysql.Connect(
            host='localhost',
            port=3306,
            user='root',
            password='123456',
            db='movies',
            charset='utf8mb4'
        )
        self.cursor = self.conn.cursor()

    def process_item(self, item, spider):
        sql = "INSERT INTO movie (title, rating, genre) VALUES (%s, %s, %s)"
        self.cursor.execute(sql, (item['title'], item['rating'], item['genre']))
        self.conn.commit()
        return item

    def close_spider(self, spider):
        self.cursor.close()
        self.conn.close()

注意几点：

  • 连接在 open_spider 里建一次，不要每次 process_item 都重新建连。
  • SQL 执行后必须 self.conn.commit()，否则数据不会真正写入。
  • 用 %s 占位符而不是字符串拼接，防止 SQL 注入。

Redis 管道：存列表做队列

Redis 在爬虫项目里常用来做"待爬 URL 队列"或"已爬数据缓存"。Scrapy 存 Redis 最简单的方式是用 lpush 把 Item 塞进一个列表。

# pipelines.py
from redis import Redis

class RedisPipeline:
    def open_spider(self, spider):
        self.r = Redis(host='localhost', port=6379, db=0)

    def process_item(self, item, spider):
        self.r.lpush('movies', str(item))
        return item

    def close_spider(self, spider):
        # Redis 连接通常不需要显式关闭，连接池会自动管理
        pass

这里 lpush 'movies', item 的意思是：往 Redis 里名为 movies 的列表左侧（头部）插入一条数据。你可以把它想象成一叠盘子——每次新盘子都放在最上面。

文件管道：CSV 落盘做备份

文件管道和上一节讲的一样，负责把 Item 写成 CSV 或 JSON 文件。在多管道场景下，文件管道通常设为最高优先级（数字最小），这样数据会最先落盘，即使后面的数据库管道出错，文件里也有一份备份。

# pipelines.py
class FilePipeline:
    def open_spider(self, spider):
        self.f = open('movies.csv', 'w', encoding='utf-8')
        self.f.write('title,rating,genre\n')

    def process_item(self, item, spider):
        line = f"{item['title']},{item['rating']},{item['genre']}\n"
        self.f.write(line)
        return item

    def close_spider(self, spider):
        self.f.close()

多管道协作的完整流程

把三个管道合在一起，一个 Item 的生命周期是这样的：

阶段发生什么
Spider yield item引擎收到 Item，准备送入管道链
FilePipeline.process_item写入 CSV 文件，return item
MySQLPipeline.process_item执行 SQL 并 commit，return item
RedisPipeline.process_itemlpush 到 Redis 列表，return item
结束Item 处理完毕，引擎等待下一个 Item

如果 MySQLPipeline 的 process_item 忘了 return，RedisPipeline 就永远收不到 Item——但 FilePipeline 已经写入了，所以文件里还有数据。这就是为什么文件管道通常设为最高优先级：它是最后一道保险。

常见踩坑

  • 优先级数字写反了：想让文件先存，结果把 MySQL 设成 300、文件设成 302，顺序就反了。
  • MySQL 忘记 commit：执行了 execute 但没 commit，数据不会真正写入数据库。
  • Redis 存了 Item 对象：Redis 不能直接存 Python 对象，要 str(item) 或 json.dumps(dict(item)) 转成字符串。
  • open_spider 里建连失败：数据库没启动或密码错误，爬虫一启动就崩溃。建议先在 Python 交互式环境里测试连接。
