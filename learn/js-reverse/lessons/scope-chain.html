作用域链与全局污染

JS 逆向 · 节点 15 · 步骤 2/5

学习目标

能区分全局变量与局部变量、理解 var 无块级作用域、识别全局变量污染并判断变量修改的影响范围。

全局变量 vs 局部变量

函数内部用 var 声明的变量是局部变量，只在函数体内可见。函数外部声明的变量是全局变量，所有脚本都能读到。

var g = 100; // 全局

function show() {
  var l = 200; // 局部
  console.log(g, l); // 100 200
}
show();
console.log(l); // ReferenceError: l is not defined

读代码的第一步就是判断"这个变量是哪一层的"——局部变量只能在声明它的函数里访问，全局变量则到处都能碰到。

不写 var 赋值会改到全局

这是 JS 早期最反直觉的坑：函数内部如果对某个变量赋值却没声明，JS 会沿着作用域链一路往上找，一直找到全局作用域都没找到的话，就自动创建一个全局变量。这意味着函数里的赋值会"泄漏"到全局：

var x = 10;

function leak() {
  x = 100; // 没有 var，改的是全局 x
}
leak();
console.log(x); // 100

逆向时看到函数里对某个标识符赋值却没有 var/let/const，要立刻警觉——它可能正在改全局状态，而全局状态往往就是逆向要找的关键数据。

var 没有块级作用域

C/Java 系列语言里，if 块、for 块里声明的变量出了块就消失。但 var 只有函数级作用域，没有块级作用域：

if (true) {
  var b = 200;
}
console.log(b); // 200 —— 块外仍然可见

等价于 b 被声明在函数顶部（或全局顶部）。所以老代码里 if 块内 var 的变量和函数顶部的变量是同一回事。ES6 的 let/const 才引入了块级作用域，但混淆代码和老项目里 var 满天飞，看到 if 里的 var 别以为它只在 if 里有效。

作用域遮蔽（shadowing）

如果局部变量和全局变量同名，在函数内部访问时优先命中局部变量——这叫遮蔽。函数内部可以声明一个 var Math = 100，把全局的 Math 对象遮掉：

var Math = 100; // 遮蔽全局 Math

function f() {
  var Math = 200; // 局部 Math，遮蔽外层
  console.log(Math); // 200
}
f();
console.log(Math); // 100 —— 函数外部还是外层 Math

逆向时遇到同名变量，一定要沿着作用域链从内往外找，第一个命中的是哪层，就读哪层的值。

全局变量污染：同名覆盖

同一个页面可能有多个 <script> 代码块，它们共享同一个全局作用域。两个代码块都声明了同名全局变量 n，后一个会覆盖前一个：

<script>
  var n = 0;
  function counter() { n++; console.log(n); }
</script>

<script>
  var n = 10; // 覆盖前一个 n
</script>

<button onclick="counter()">点我</button>

按钮点击后打印 11，而不是 1——第二个代码块把 n 重写成 10 了。这种全局污染让多段脚本互相踩踏，是早期 JS 代码的常见问题。生产环境的解决方案就是把变量包进函数作用域，这正是下一节闭包的动机。
