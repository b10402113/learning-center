CrawlSpider 全站爬取

js-reverse · Step 4/5 · 約 20 分鐘

這節課你會學到什麼

掌握 CrawlSpider 的 rules、LinkExtractor 與 Rule 配合方式，能自動翻頁爬取全站資料，並掌握「列表頁 meta 傳 item + 詳情頁補全」的深度爬取通用套路。

情境：手動翻頁太麻煩

上一節課我們用 scrapy.Request() 手動翻頁：在 parse 裡提取下一頁的 URL，yield 一個新請求，回呼到同一個 parse。這種寫法直覺，但如果全站有 200 頁、每個頁面結構都一樣，手動寫翻頁就顯得重複且容易出錯。

Scrapy 提供一個內建爬蟲類別 CrawlSpider，專門處理「按照某種規則自動翻頁、爬全站」的場景。

CrawlSpider 的建立與核心概念

用 scrapy genspider -t crawl 建立一個 CrawlSpider：

scrapy genspider -t crawl myspider www.example.com

和普通 Spider 相比，CrawlSpider 多了一個類變數 rules，裡面放了一組 Rule 物件。每個 Rule 由兩部分組成：

  • LinkExtractor：連結提取器，決定「從頁面裡提取哪些連結」
  • Rule：規則解析器，決定「對提取到的連結發請求、用哪個回呼解析」

LinkExtractor 與 Rule 一一對應，一個 Rule 就是一條「提取 → 請求 → 解析」的流水線。

LinkExtractor：提取連結的兩種方式

1. 用 allow 正則提取

allow 接受一個正則表達式，只有符合正則的連結才會被提取。例如：

from scrapy.linkextractors import LinkExtractor

LinkExtractor(allow=r'page=\d+')

會提取所有 URL 裡包含 page=數字 的連結。如果 allow 是空正則（allow=r''），則提取頁面上的所有連結。

2. 用 restrict_xpaths 按標籤定位提取

restrict_xpaths 接受一個 XPath 表達式，只在 XPath 選取的區域裡提取連結。例如：

LinkExtractor(restrict_xpaths='//div[@class="pagination"]')

只在分頁器區域裡提取連結，避免提取到其他不相關的連結。

Rule：對提取到的連結發請求

Rule 決定對 LinkExtractor 提取到的每個連結怎麼處理：

from scrapy.spiders import Rule

Rule(
    LinkExtractor(allow=r'page=\d+'),  # 提取器
    callback='parse_item',             # 用哪個回呼解析
    follow=True                        # 是否繼續跟進提取到的連結
)
  • callback：指定回呼函式，相當於普通 Spider 裡的 parse
  • follow=True：對提取到的連結，繼續用 rules 裡的其他 Rule 提取下一層連結（預設 False）

完整範例：多頁爬取

# spiders/myspider.py
from scrapy.linkextractors import LinkExtractor
from scrapy.spiders import CrawlSpider, Rule

class MySpider(CrawlSpider):
    name = 'myspider'
    allowed_domains = ['example.com']
    start_urls = ['https://example.com/page/1']

    rules = (
        # 提取分頁連結，用 parse_item 解析，繼續跟進
        Rule(LinkExtractor(allow=r'page=\d+'), callback='parse_item', follow=True),
    )

    def parse_item(self, response):
        # 解析每個分頁裡的資料
        titles = response.xpath('//h2/text()').extract()
        for title in titles:
            yield {'title': title}

注意：CrawlSpider 的起始回呼是 parse_start_url，不是 parse。因為 LinkExtractor 提取的分頁連結裡通常不包含第一頁，所以第一頁要用 parse_start_url 解析。

深度爬取：列表頁 meta 傳 item + 詳情頁補全

很多網站的列表頁只顯示摘要（如標題、縮圖），要點進詳情頁才能看到完整內容。CrawlSpider 配合手動 scrapy.Request 的套路：

class MySpider(CrawlSpider):
    name = 'myspider'
    start_urls = ['https://example.com/list']

    rules = (
        Rule(LinkExtractor(allow=r'page=\d+'), callback='parse_list', follow=True),
    )

    def parse_list(self, response):
        # 列表頁：提取每條新聞的標題和詳情頁 URL
        articles = response.xpath('//div[@class="article"]')
        for article in articles:
            item = {
                'title': article.xpath('.//h2/text()').extract_first(),
            }
            detail_url = article.xpath('.//a/@href').extract_first()
            # 手動發請求，用 meta 把 item 傳給詳情頁
            yield scrapy.Request(detail_url, callback=self.parse_detail, meta={'item': item})

    def parse_detail(self, response):
        # 詳情頁：從 meta 取出 item，補全內容
        item = response.meta['item']
        item['content'] = response.xpath('//div[@class="content"]/text()').extract_first()
        yield item

這個套路是深度爬取的通用模式：列表頁負責「提取摘要 + 產生詳情頁請求」，詳情頁負責「補全內容 + 輸出 item」。meta={'item': item} 是跨頁傳遞資料的標準做法。

Scrapy 中四種發請求方式

學到這裡，Scrapy 中發送請求的方式已經全部登場：

  1. start_urls：起始 URL，最簡單
  2. scrapy.Request()：手動發請求，最靈活
  3. scrapy.FormRequest()：發 POST 請求（如登入表單）
  4. Rule 規則解析器：CrawlSpider 專用，自動翻頁

小結

CrawlSpider 用 LinkExtractor 按正則或 XPath 提取連結，用 Rule 對每個連結發請求並解析，從而自動翻頁爬全站。parse_start_url 解析第一頁，follow=True 讓提取到的連結繼續被規則處理。配合 meta={'item': item} 手動發請求，可以完成「列表頁提取摘要 → 詳情頁補全內容」的深度爬取。
