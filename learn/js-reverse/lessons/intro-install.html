學習目標

能說明 Pyppeteer 與 Selenium 的核心差異，並完成本地環境安裝。

從 Selenium 的痛點談起

你已經用 Selenium 驅動過瀏覽器，應該記得第一次跑起來前要搞哪些事：下載和本機 Chrome 版本對應的 chromedriver、設定路徑、處理「Chrome 正受到自動測試軟體控制」的提示條。Selenium 本身是同步的，跑多個分頁時只能排隊等，效率卡在 IO 阻塞上。

Pyppeteer 就是為了解決這兩個麻煩而生的。它的定位很明確：「非同步的 Selenium」。背後一樣是 Chromium 瀏覽器在跑渲染，但 API 走 Python async 體系，而且第一次執行時會自動下載、配置 Chromium，不用手動裝驅動。

Chromium 與 Chrome 的關係

Pyppeteer 背後依賴的 Chromium，是 Google 為了研發 Chrome 而發起的完全開源專案。兩者基於同一套原始碼構建，新功能會先在 Chromium 上驗證，再移植到 Chrome。Chromium 更新比 Chrome 更頻繁，但對爬蟲來說，這代表 Pyppeteer 能支援較新的網頁標準。

為什麼要選非同步

你在 day08 學過 asyncio 和 aiohttp。Pyppeteer 把瀏覽器操作也包進協程裡，所以你可以同時開多個分頁、同時爬多個頁面，不用等一個跑完才跑下一個。這對渲染型爬蟲特別重要——每個頁面都要等 JS 執行完，同步寫法會把時間疊上去，非同步就能壓到和最慢的那個頁面差不多。

環境安裝

Pyppeteer 採用 async 機制，要求 Python 3.5 以上。安裝只要一條命令：

pip install pyppeteer

第一次執行時，如果系統裡沒有 Chromium，Pyppeteer 會自動下載並配置好。如果你不想用內建的 Chromium，也可以透過 executablePath 指向本機已經裝好的 Google Chrome（路徑可以在瀏覽器 chrome://version/ 的「個人資料路徑」裡找到）。

面向SeleniumPyppeteer
瀏覽器Chrome / Firefox / Edge 等Chromium（為主）

設定成本高低
