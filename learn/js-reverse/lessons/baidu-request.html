百度翻译 POST 表单请求闭环

实战：SHA1 与百度 sign · 步骤 5/5

学习目标

能独立拼出百度翻译 v2transapi 的 POST 表单（query/sign/token/ts），让 sign 随 query 动态变化，跑通从输入单词到拿到翻译结果的闭环。

请求结构总览

百度翻译的接口是 POST https://fanyi.baidu.com/v2transapi，数据以 form 表单（application/x-www-form-urlencoded）提交，不是 JSON。表单字段如下：

字段类型说明
from固定源语言，如 'en'
to固定目标语言，如 'zh'
query动态要翻译的单词
transtype固定'realtime'
simple_means_flag固定'3'
sign动态由 get_sign(query) 算出
token固定硬编码字符串
domain固定'common'
ts动态毫秒时间戳

完整爬虫脚本

import requests
import execjs
import time

wd = 'banana'

# 1. 算 sign
sign = execjs.compile(open("04 百度翻译.js").read()).call("get_sign", wd)
print("sign:", sign)

# 2. 构造表单
data = {
    'from': 'en',
    'to': 'zh',
    'query': wd,
    'transtype': 'realtime',
    'simple_means_flag': '3',
    'sign': sign,
    'token': '54d75af66e933730e213ff5f038971c8',
    'domain': 'common',
    'ts': str(int(time.time() * 1000)),
}

# 3. 发 POST 请求
response = requests.post(
    'https://fanyi.baidu.com/v2transapi',
    params={'from': 'en', 'to': 'zh'},
    cookies=cookies,
    headers=headers,
    data=data
)
print(response.json())

token 和 ts：两个容易搞混的字段

token 是硬编码的，短期内不会变。它不是 sign，不是加密结果，只是一个标识客户端的令牌。ts 是毫秒时间戳，每次请求都要重新生成——如果你写死一个固定时间戳，过几分钟就会返回「请求过期」之类的错误。

为什么 sign 必须随 query 动态变化？

如果你把 sign 写死，只改 query，百度会直接返回错误。因为 get_sign 的输入是 query，不同的 query 必然算出不同的 sign。这是 sign 机制的核心目的：防止别人用一个固定签名批量刷接口。

请求头里的 Acs-Token

除了表单字段，百度翻译还要求请求头里带一个 Acs-Token。这个值也是动态生成的，但它的生成逻辑和 sign 无关——通常是一个独立的 JS 函数。如果你发现 sign 算对了还是被拦截，大概率是 Acs-Token 没带或过期了。

调试顺序

  1. 先单独跑 get_sign(wd)，确认输出格式正确（六位数.整数）。
  2. 再发请求，看返回的 JSON 里是否有 error 字段。
  3. 如果返回「请求过期」，检查 ts 是否实时生成。
  4. 如果返回「sign 错误」，检查 query 是否做了 URL 编码或 trim。

小结

百度翻译的 POST 闭环就是：输入单词 → execjs 算 sign → 拼表单（query/sign/token/ts）→ requests.post。sign 必须随 query 动态变化，ts 必须实时生成，token 可以短期固定。到这里，你已经跑通了两个最典型的 sign 逆向案例：丁香网的 SHA1 和百度翻译的位运算。
