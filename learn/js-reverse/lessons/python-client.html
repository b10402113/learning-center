Python 客戶端對照

Node 13 · Step 4 / 4 · 預估 12–15 分鐘

Learning goal

用 Python requests 重現瀏覽器對 /books 的 Ajax 請求，建立「瀏覽器 Ajax = Python requests」的映射，形成逆向爬蟲的核心工作流錨點。

Lesson

前面三課我們談了 URL 結構、架了靶站、看了 JavaScript 怎麼用 Ajax 在背景抓資料。這一步要把所有東西兜在一起：你會發現，瀏覽器裡 JavaScript 做的事，用 Python requests 幾乎可以一行對一行翻譯。這就是逆向爬蟲最關鍵的心態轉換 —— 你要爬的不是「網頁」，而是「網頁在背後打的那些請求」。

requests 做的事，和 $.ajax 一模一樣

jQuery 的 $.ajax({url: "/books", type: "get", success: fn}) 翻譯成 Python requests 是：

import requests

res = requests.get("http://127.0.0.1:5000/books")
books = res.json()
print(books)

兩者做的事情完全一樣：對 http://127.0.0.1:5000/books 發 GET 請求，拿到回應，把 JSON 解析成程式語言的原生資料結構（JavaScript 陣列或 Python 列表）。

步驟jQuery (瀏覽器)requests (Python)
發 GET 請求$.ajax({url, type:"get"})requests.get(url)
拿到回應success: function(res)res = requests.get(...)
解析 JSONjQuery 自動解析res.json()
使用資料res.join(",")",".join(books)

你會發現，jQuery 的 success 回調裡做的事，和 Python 拿到 res.json() 之後做的事，幾乎是同一件事。瀏覽器裡的 Ajax 和 Python 裡的 requests，只是在不同環境下做同一件事的兩種工具。

URL 要寫完整

前端用 url: "/books" 是因為瀏覽器會自動補上目前頁面的協議、域名和埠號。Python requests 沒有這個「目前頁面」的概念，所以你必須寫完整的 URL：

requests.get("http://127.0.0.1:5000/books")

如果只寫 "/books"，requests 會因為它不是合法 URL 而拋出例外。這是一個常見的新手坑。

res.json() 是關鍵

requests.get() 回傳的是一個 Response 物件。它包含了狀態碼、回應頭、回應體。回應體（res.text）是原始字串，但我們通常要的是解析後的資料結構。res.json() 會把 JSON 字串解析成 Python 的列表或字典：

>>> res.text
'["三體","銀河帝國","沙丘","基地"]'

>>> res.json()
['三體', '銀河帝國', '沙丘', '基地']

拿到 Python 列表之後，你就可以用所有 Python 的方式處理它：len(books)、books[0]、for b in books:、存檔、寫入資料庫，隨便你。

逆向爬蟲的核心工作流

把前面的東西串起來，就是逆向爬蟲的標準流程：

  1. 打開 DevTools，切到 Network 面板。
  2. 重現動作：點擊、滾動、換頁，讓目標請求出現在面板裡。
  3. 找到請求：在 Network 面板裡找到 XHR / Fetch 類型、回應是 JSON 的那一筆。
  4. 讀細節：看它的 URL、方法（GET / POST）、請求頭（Headers）、請求體（Payload）。
  5. 用 requests 重現：把 URL、方法、參數、請求頭原封不動翻譯成 Python 代碼。
  6. 解析回應：用 res.json() 拿到資料結構，開始處理。

這個流程的後半段（步驟 4–6）完全不需要看懂 JavaScript 代碼。你要做的，只是當一個「複製貼上」的翻譯員：把瀏覽器發出的請求，翻譯成 Python 發出的請求。

什麼時候需要看懂 JS？

如果一個請求的 URL 和參數都是固定的，例如 /api/books?category=scifi，你直接寫死就爬得到。但很多網站不會這麼老實：

  • URL 裡有一段 ?sign=a1b2c3d4，每次請求都不一樣。
  • 請求體裡有 "token": "xyz123"，不知道怎麼產生的。
  • 回應是加密過的，res.json() 會失敗。

這時候你才需要回去看懂 JavaScript 代碼 —— 去找 sign 是怎麼算的、token 是從哪裡來的、回應是怎麼加密的。這就是「JS 逆向」這個詞真正派上用場的地方。

但不管多複雜的 JS 逆向，起點都一樣：先在 DevTools 裡抓到請求，確認 URL 和參數，然後才開始追程式碼。這堂課建立的「Ajax = requests」映射，就是所有後續逆向工作的地基。
