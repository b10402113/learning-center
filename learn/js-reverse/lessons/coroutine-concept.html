协程原理与动机

js-reverse · 节点 05 · 步骤 5/5

学习目标

理解协程如何在单进程/单线程下通过自主切换阻塞环节来提升效率，为后续 asyncio 异步爬虫铺好理论基础。

多进程/多线程的问题

多进程/多线程下载网页时，系统中还有大量其他进程/线程。CPU 由操作系统调度切换，无法人为干涉，不一定切回你的下载任务，效率会打折。

协程的核心思想

协程（Coroutine）可以在单进程或单线程模式下大幅提升程序运行效率。它的做法是：

  • 把所有下载任务封装在一个进程/线程中
  • 主动监测所有阻塞环节
  • 让 CPU 在阻塞环节之间切换执行
  • 使该任务的就绪态增多，"迷惑"操作系统
  • 操作系统以为该任务阻塞少，尽可能多分配 CPU
总而言之：协程是想尽一切办法留住 CPU 在自己的程序中。

类比理解

想象你是一个厨师（单线程），要同时烧水、煮饭、炒菜：

  • 同步：烧完水 → 煮好饭 → 炒完菜（傻等）
  • 多线程：雇 3 个厨师同时干（但厨房就那么大，人会打架）
  • 协程：你一个人，水烧上就去炒菜，饭煮上就去切菜，哪个先好就先处理哪个（主动切换）

协程 vs 多线程

维度多线程协程
调度方操作系统（抢占式）程序员（主动让出）
切换开销较大（内核态切换）极小（用户态切换）
内存占用每个线程占用 MB 级栈每个协程占用 KB 级
适用场景I/O 密集型（适度并发）高并发 I/O（数千连接）

协程在爬虫中的价值

爬虫是典型的 I/O 密集型任务：发请求 → 等响应 → 解析 → 发请求……大部分时间在等网络响应。协程让你在一个线程内同时管理成百上千个下载任务，哪个响应回来就处理哪个，CPU 几乎不空等。

Python 中协程的具体实现是 asyncio（后面会学到）。协程是它的理论基础。
