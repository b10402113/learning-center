原型物件与箭头函数

JS 逆向 · 节点 15 · 步骤 4/5

学习目标

能描述原型链查找、用 call/apply 改变 this、把箭头函数还原为传统函数阅读混淆代码。

把方法挂在 prototype 上，让所有实例共享

构造函数 Person 每 new 一次，如果方法直接写在构造函数里，每个实例都会复制一份——既浪费内存，也拖慢 new。解决办法是把方法挂到 Person.prototype 上：

function Person(name) {
  this.name = name;
}
Person.prototype.eat = function() {
  console.log(this.name + " eating");
};

var p1 = new Person("Alice");
var p2 = new Person("Bob");
p1.eat === p2.eat; // true —— 共享同一个方法

读代码时看到 X.prototype.y = function(){}，要意识到所有 X 的实例都能调用 y，但 y 并不在实例自身身上。

__proto__、prototype、constructor 三者的关系

这三个属性构成原型链的核心三角：

  • p1.__code> === Person.prototype —— 实例的隐式原型指向构造函数的 prototype 对象。
  • Person.prototype.constructor === Person —— prototype 对象里的 constructor 指回构造函数。
  • p1.__proto__.constructor === Person —— 沿链上行，同样指回构造函数。

当访问 p1.eat 时，JS 先在 p1 自身属性里找，找不到就沿 __proto__ 上行到 Person.prototype 找——这就是原型链查找。读逆向代码时，如果某个方法不在对象身上，就往它的 __proto__（也就是构造函数的 .prototype）找。

call 与 apply：改变 this 指向

JS 函数的 this 默认由调用方式决定。call 和 apply 允许你显式指定函数执行时 this 指向谁：

function eat(a, b) {
  console.log(this.name + " eats " + a + " and " + b);
}
var p = { name: "Alice" };
var q = { name: "Bob" };

eat.call(p, "apple", "banana");   // Alice eats apple and banana
eat.apply(q, ["apple", "banana"]); // Bob eats apple and banana

第一个参数都是新的 this 对象。区别在后续参数：call 逐个传，apply 传一个数组。逆向时看到 fn.call(x, ...) / fn.apply(x, [...])，要立即还原：它是在用 x 作为 this 调用 fn，参数就是后面那些。混淆器经常用 call/apply 把真实调用对象藏起来。

箭头函数：普通函数的语法糖

ES6 引入的箭头函数 (x, y) => x + y 是普通函数的简写形式。两种形态：

// 单表达式隐式返回
var sq = i => i * i;
// 等价于
var sq = function(i) { return i * i; };

// 带函数体需要显式 return
var add = (a, b) => { return a + b; };

箭头函数最常见的场景是回调里一行完成映射：

var arr = [1, 2, 3];
var squares = arr.map(i => i * i); // [1, 4, 9]
// 等价于
var squares = arr.map(function(item) { return item * item; });

逆向时如果看到 =>，先在脑内还原成 function(){}，读起来会轻松很多。

箭头函数的 this 规则（逆向注意点）

箭头函数没有自己的 this，它的 this 由外层作用域决定——这和普通函数完全不同。在逆向时这个区别至关重要：

function Timer() {
  this.seconds = 0;
  setInterval(function() {
    this.seconds++; // this 指向 window，不是 Timer 实例
  }, 1000);
}

很多逆向目标用 var self = this 或者箭头函数来保住 this。看到这类写法要能识别它的意图。
