进程调度、状态与同步异步

js-reverse · 节点 05 · 步骤 2/5

学习目标

理解进程调度如何制造"同时"的假象，辨析并发与并行、同步与异步的核心差异，并掌握进程四态及其转换条件。

进程调度：制造"同时"的假象

你一边聊微信、一边听音乐、一边打游戏，看起来三个程序在"同时"运行。实际上，单核 CPU 在极短的时间片内交替执行多个进程，切换速度极快，人眼无法察觉。这就是进程调度。

时间片轮转法

操作系统创建多个就绪队列，赋予不同优先级。优先级越高的队列，时间片越小（执行时间越短）。新进程先进入第一队列末尾：

  • 一个时间片内完成 → 准备撤离
  • 未完成 → 转入下一队列末尾（时间片更长）
  • 依次下移，直到执行完毕

并发 vs 并行

概念定义关键区别
并行（Parallel）多 CPU 同时运行多个任务真正的同时
并发（Concurrent）单核靠时间片快速切换制造同时假象伪并行
吃饭类比：吃完饭才接电话 = 既不并发也不并行；停下筷子接完电话再吃 = 并发；边吃边接 = 并行。

并发的关键是有处理多个任务的能力（不一定同时），并行的关键是有同时处理多个任务的能力。

进程的四态

进程在运行中被调度算法控制，经历四种状态：

状态含义触发条件
就绪（Ready）已准备好，分配到所需资源/内存等待 CPU 调度
运行（Running）被调度后进入执行获得 CPU 时间片
阻塞（Blocked）因某些事件暂时无法运行网络请求、input 等耗时操作
终止（Terminated）进程结束、出错或被系统终止正常结束或异常
关键认识：耗时操作 = 阻塞。网络请求、用户输入、文件读写都会让进程从运行态转为阻塞态，CPU 这段时间就空闲了。

同步 vs 异步

同步（Synchronous）：任务每个步骤顺序执行，必须前一步完毕才执行下一步。

异步（Asynchronous）：步骤仍顺序发起，但一旦某步骤被执行，无论是否结束都马上执行下一步。

做饭案例

烧水、煮饭、炒菜都是耗时操作（阻塞操作）：

  • 同步做法：烧完水 → 煮好饭 → 炒完菜，总共耗时 = 三步之和
  • 异步做法：水烧上、饭煮上、菜炒上，三步几乎同时发起，总耗时 ≈ 最慢那步的时间

同步/异步针对的是 CPU 执行任务遇到阻塞操作时产生的不同行为。异步可基于并行也可基于并发，但大部分情况下基于并发。实现异步的具体操作是进程、线程和协程。
