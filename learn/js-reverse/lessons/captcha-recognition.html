驗證碼識別與打碼平台接入

js-reverse · Step 4/4 · 約 12 分鐘

這節課你會學到什麼

理解工程上驗證碼識別的標準做法：把驗證碼圖片 base64 編碼後 POST 到打碼平台（如圖鑒），按 typeid 區分不同驗證碼類型，並將識別流程封裝為可復用模組。

情境：為什麼爬蟲過不了驗證碼？

當你模擬登入、用代理池繞過 IP 封鎖之後，下一關往往是驗證碼——伺服器彈出一張扭曲的圖片，要求你輸入裡面的數字或字母，或者滑動一個方塊對齊缺口。對瀏覽器前的人類來說這幾秒鐘的事，對純 Python 爬蟲來說是斷崖。

純爬蟲做法（OCR 自己辨識）只對簡單的文字驗證碼有效，遇到計算題、座標點選、滑動驗證就徹底沒用。工程上的標準解法是買別人的辨識服務：把驗證碼圖片傳給打碼平台，平台回傳辨識結果（文字或座標），你再繼續下一步。

打碼平台長什麼樣？

以圖鑒平台（ttshitu.com）為例，它提供一個 HTTP API：你 POST 一張驗證碼圖片給它，它回傳辨識結果。概念上就像在程式裡接一個「幫你念出圖片裡文字」的遠端函式。

一個打碼平台的生命週期通常是：

  1. 註冊帳號，儲值（按辨識次數計費）
  2. 閱讀開發文件，找到 API 位址和參數
  3. 封裝成 Python 函式，你的爬蟲每次遇到驗證碼就呼叫它

打碼 API 的標準流程

打碼平台的 API 合約大同小異，核心是這三個欄位：

欄位說明
username 你的打碼平台帳號
password 你的打碼平台密碼
typeid 告訴平台這是哪種驗證碼（純數字、計算題、座標點選…）
image 驗證碼圖片（base64 編碼後的字串） 
import requests
import base64

def captcha_recognize(image_path):
    """把驗證碼圖片送到打碼平台，回傳辨識結果"""
    # 讀取圖片 → base64 編碼
    with open(image_path, "rb") as f:
        img_b64 = base64.b64encode(f.read()).decode("utf-8")

    # POST 到打碼平台
    resp = requests.post(
        "http://api.ttshitu.com/predict",
        json={
            "username": "your_username",
            "password": "your_password",
            "typeid": 1,          # 純數字驗證碼
            "image": img_b64
        }
    )
    result = resp.json()
    return result["result"]   # 辨識出的文字

一次呼叫就把「圖片 → 文字」這件事做完了。後續流程是把辨識結果填入登入表單，再送出 POST 請求，照樣用 Session 物件帶著 Cookie 去完成剩下的模擬登入。

typeid 對照表：平台能處理哪些驗證碼？

不同打碼平台支援的驗證碼類型不同，以圖鑒為例，常見的 typeid 對照：

typeid驗證碼類型
1純數字 (1111)
2純英文 (abcd)
3數字英文混合 (1a2b)
4閃動 GIF
5計算題 (1+2=?)
6漢字
10通用文字
20問答題
30Recaptcha
40旋轉角度
50座標點選（回傳 1~8 個座標）
60缺口辨識（回傳 X 軸座標）
70拼圖辨識
核心概念：打碼平台幫你做一件最難的事——「看懂圖片裡在問什麼」。你只要選對 typeid、把圖片丟過去、拿結果填入表單。

滑動驗證 vs 打碼平台

有些網站的驗證碼不只是「輸入圖片上的文字」，而是要你拖曳一個滑塊去對齊缺口（缺口辨識，typeid=60）。打碼平台能幫你算出缺口在圖片的哪個 X 軸座標，但你還是要模擬滑鼠拖曳——用 Selenium 或 Pyppeteer 控制瀏覽器，按計算出的座標拖過去。

這也是為什麼打碼平台的認知是後續學習滑動驗證逆向前的先修：先知道「平台能算出座標」，再學「怎麼用瀏覽器模擬滑鼠去拖」。

封裝成可復用模組

在爬蟲專案裡，通常會把打碼邏輯獨立成一個 tujian.py 模組：

# tujian.py
import requests
import base64

def recognize(image_path, typeid=1):
    with open(image_path, "rb") as f:
        img_b64 = base64.b64encode(f.read()).decode("utf-8")

    resp = requests.post(
        "http://api.ttshitu.com/predict",
        json={
            "username": "your_username",
            "password": "your_password",
            "typeid": typeid,
            "image": img_b64
        }
    )
    data = resp.json()
    if data.get("success"):
        return data["result"]
    else:
        raise Exception(f"打碼失敗: {data.get('message')}")

爬蟲主程式只要一行：

from tujian import recognize

code = recognize("captcha.png", typeid=1)
login_data["captcha"] = code
session.post(login_url, data=login_data)

小結

遇到驗證碼，工程上的標準解法是接打碼平台，不是自己寫 OCR。把驗證碼圖片 base64 編碼後 POST 到平台，按 typeid 告訴平台這是哪種類型（純數字、計算題、座標點選、缺口辨識），平台回傳文字或座標你再用。這不是逆向工程，但它是滑動驗證、缺口辨識等進階主題前必須先有的認知。
