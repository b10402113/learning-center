meta 跨页传参

深度爬取与 POST 请求 · 步骤 3/4

学习目标

能用 meta 字典把列表页的 item 传给详情页回调，实现"翻页 + 进详情页"的深度爬取。

什么是"深度爬取"？

scrapy 里说的"深度"不是指爬很多层，而是指数据不在同一张页面里。比如一个新闻列表页只显示标题和摘要，要看到完整正文必须点进详情页。这时候你就需要：

  1. 在列表页解析出标题，并构造详情页的 URL。
  2. 把标题带进详情页的回调函数。
  3. 在详情页解析出正文，和标题合并成同一个 item。
  4. 把完整的 item 交给 Pipeline 存储。

第 2 步就是"跨页传参"——scrapy 用 meta 字典来实现。

meta 字典的用法

在 yield scrapy.Request() 时，传入一个 meta 参数，里面放你想传递给下一个回调的数据：

yield scrapy.Request(
    url=detail_url,
    callback=self.parse_detail,
    meta={'item': item}   # 把当前 item 传过去
)

在目标回调里，用 response.meta['item'] 取出来：

def parse_detail(self, response):
    item = response.meta['item']   # 取出上一页传来的 item
    item['content'] = response.xpath('//div[@class="content"]/text()').extract_first()
    yield item

meta 本质上就是一个普通字典，你可以往里面放任何可序列化的数据——字符串、数字、列表、甚至 Item 对象。

完整示例：列表页 + 详情页

以东莞阳光网问政平台为例，列表页显示标题，详情页显示完整内容：

import scrapy

class SunSpider(scrapy.Spider):
    name = 'sun'
    start_urls = ['https://wz.sun0769.com/political/index/politicsNewest?page=1']

    def parse(self, response):
        # 列表页：解析每条新闻的标题和详情页链接
        news_list = response.xpath('//li[@class="clear"]')
        for news in news_list:
            item = {}
            item['title'] = news.xpath('./span[@class="state3"]/text()').extract_first()
            detail_url = news.xpath('./span[@class="state3"]/a/@href').extract_first()
            detail_url = response.urljoin(detail_url)

            # 把 item 带进详情页
            yield scrapy.Request(
                url=detail_url,
                callback=self.parse_detail,
                meta={'item': item}
            )

        # 翻页
        next_url = response.xpath('//a[@class="next"]/@href').extract_first()
        if next_url:
            yield scrapy.Request(url=response.urljoin(next_url), callback=self.parse)

    def parse_detail(self, response):
        # 详情页：取出 item，补上正文
        item = response.meta['item']
        item['content'] = response.xpath('//div[@class="details"]/text()').extract_first()
        yield item

注意：列表页的 parse 和详情页的 parse_detail 是两个不同的回调。列表页的 Request 用 callback=self.parse（翻页），详情页的 Request 用 callback=self.parse_detail（取正文）。

为什么不能直接 return item？

初学者常问：为什么不在列表页直接把 item yield 出去，然后在详情页再 yield 一次？

因为 scrapy 的回调是异步的——列表页的 parse 和详情页的 parse_detail 不在同一个函数调用栈里。Moonshot AI scrapy 提供的"跨回调传数据"的唯一通道。没有它，两个回调之间无法共享变量。

翻页 + 进详情页的组合

真实项目里，翻页和进详情页通常是叠加的：

  • 列表页 1 → 进详情页 1-1、1-2、1-3……
  • 列表页 2 → 进详情页 2-1、2-2、2-3……
  • ……

每一层都用 yield scrapy.Request()，每一层都可以带 meta。scrapy 会自动调度这些请求，并发下载，不会搞混。

常见踩坑

  • meta key 写错：传的时候用 meta={'item': item}，取的时候必须用 response.meta['item']，key 要一致。
  • 忘记 response.urljoin()：详情页链接可能是相对路径（/politics/123.html），必须用 response.urljoin() 补全成绝对 URL。
  • 在列表页就 yield item：如果列表页的 item 还没填完就 yield 出去，Pipeline 会收到一个不完整的 item。应该等详情页补完所有字段后再 yield。
