URL 結構與四種請求形式

Node 13 · Step 1 / 4 · 預估 12–15 分鐘

Learning goal

拆解 URL 的四個組成部分，並區分瀏覽器同步請求與 JavaScript 非同步請求的差異，判斷一個請求是否需要去 JS 代碼裡找。

Lesson

在瀏覽器裡打一個網址、按下去，畫面就跳過去了。這個再直覺不過的動作，背後其實是一整套規格很明確的結構。你要逆向爬蟲，第一步就是學會把任何一個網址拆開，然後判斷「這個請求是瀏覽器自己完成的，還是 JavaScript 在背後偷偷打的」。

把 URL 拆成四塊

每個 URL 長得像這樣：

https://www.baidu.com/s?wd=alex

拆開來是四個部分：

部分在這例子裡它決定什麼
協議（Protocol）https://用什麼規則和伺服器對話
域名與埠號（Host : Port）www.baidu.com要連哪一台機器
路徑（Path）/s伺服器上的哪一個資源
查詢參數（Query String）wd=alex附加給伺服器的鍵值對

協議幾乎都是 https://，埠號如果沒寫就是 443（https 預設）。路徑是 / 或 /s 這種斜線開頭的字串。查詢參數以 ? 開頭，多個參數用 & 分隔，例如 ?wd=alex&page=2。

向伺服器發請求的四種形式

瀏覽器向伺服器拿資料，總共只有四種方式。前三種是瀏覽器內建行為，最後一種是 JavaScript 自己打的：

形式觸發方式同步與否對頁面的影響
地址列 + 回车在網址列輸入 URL 按 Enter同步整個頁面被覆蓋
a 標籤超連結點擊 <a href="...">同步整個頁面被覆蓋
form 表單點擊 <button type="submit">同步整個頁面被覆蓋
AjaxJavaScript 執行 $.ajax() 或 fetch()非同步頁面不動，資料在背景交換

前三種的共同點是「同步」：瀏覽器送出請求，等伺服器回應，然後把整個頁面換成回應的內容。你在 DevTools 的 Network 面板裡會看到一個 Document 類型的請求，回應是完整 HTML。

Ajax（Asynchronous JavaScript and XML）則完全不同。它是 JavaScript 發起的非同步請求：瀏覽器在背景送出請求，拿到資料之後，再用 JavaScript 把資料塞進目前頁面的某個位置。整個過程你不會看到頁面跳掉或刷新。

為什麼爬蟲要分這四種？

對爬蟲來說，前三種和 Ajax 的處理方式差很多：

  • 前三種：資料通常就在 HTML 裡。你對最終載入的 URL 發一次 GET 請求，拿回來的 HTML 就包含了你要的內容。
  • Ajax：資料不在初始 HTML 裡。HTML 只是一個空殼，資料是 JavaScript 在背景從某個 JSON 介面抓回來、再填進去的。你要做的是找到那個 JSON 介面的 URL，直接對它發請求。

所以每次你在 DevTools 裡看到一個請求，第一件事就是問自己：這個請求是頁面一載入就有的（Document / 同步），還是使用者做了某個動作之後才出現在 Network 面板的（XHR / Fetch / 非同步）？如果是後者，它的 URL 和參數就是你要逆向的目標。

一個具體例子

假設你在看一個書籍網站，首頁載入時 HTML 裡只有一個空的书單 <div id="book-list"></div>。你點了一本分類之後，畫面下方突然冒出四本書。打開 DevTools Network 面板，你會看到一個新的請求：

GET /api/books?category=scifi

回應是 JSON：

["三體", "銀河帝國", "沙丘", "基地"]

這就是 Ajax。你要爬這個資料，不是對首頁的 URL 發請求，而是要找到 /api/books 這個介面，然後自己用 Python 對它發 GET 請求。
