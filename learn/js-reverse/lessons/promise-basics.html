Promise 語法與三狀態機制

掌握 Promise 的三狀態（pending / fulfilled / rejected）與 `then` 雙回調的觸發條件，能閱讀並理解任何包含 Promise 的 JS 代碼。

Promise 是什麼

Promise 是一個對象，代表一個尚未完成但未來會完成的異步操作。它像一張「取貨券」——現在還拿不到東西，但承諾之後會給你結果（或告訴你失敗了）。

創建一個 Promise 要用 new Promise()，構造函數接收一個執行器函數，執行器函數本身帶有兩個參數：resolve 和 reject。這兩個參數也是函數，分別代表「成功」和「失敗」。

function test() {
    var p = new Promise(function (resolve, reject) {
        console.log("發送ajax請求A")
        setTimeout(function () {
            let data = "hello world"
            let code = 500
            if (code === 500) {
                reject(data)   // 狀態變為 rejected
            } else {
                resolve(data)  // 狀態變為 fulfilled
            }
        }, 10000)
    })
    return p
}

三狀態：pending / fulfilled / rejected

Promise 有三種狀態，且一旦就不會再變：

  • pending（等待中）：Promise 剛創建，異步操作還沒完成。
  • fulfilled（已成功）：resolve() 被調用，操作成功。
  • rejected（已失敗）：reject() 被調用，操作失敗。

可以這樣理解：Promise 就像一顆狀態膠囊，一旦從 pending 變成 fulfilled 或 rejected，就永遠停在這裡。你回傳出去的 p 始終是那個對象，異步完成後只是內部狀態變了。

then 雙回調

Promise 對象用 .then() 來訂閱結果。then 接收兩個函數參數：第一個在狀態變為 fulfilled 時觸發，第二個在狀態變為 rejected 時觸發。

let p = test()   // p 處於 pending 狀態
p.then(function (res) {
    console.log("響應數據:", res)
    console.log("ajax請求A響應結束")
}, function () {
    // 狀態為 rejected 時走這裡
})

注意 p 可以先處於 pending 狀態，等異步操作完成後，狀態落定，對應的回調才被觸發。這和回調函數的思路完全不同：回調函數是「你給我一個函數，我完成時調用它」；Promise 是「我給你一個對象，你自己掛上去等結果」。

為什麼這很重要

在逆向調試加密網站時，你會在請求代碼裡頻繁看到 new Promise 和 .then()。掌握三狀態和 then 雙回調，你就能判斷：

  • 這段代碼何時會走進 fulfilled 分支？何時會走進 rejected？
  • resolve(data) 的 data 會傳給誰？——下一個 .then() 的第一個函數。
  • reject() 會不會被顯式捕獲？如果沒捕獲，會不會拋出未處理錯誤？

下一課，我們來看 .then() 裡回傳一個新 Promise 時，會發生什麼——這就是鏈式調用的基礎。
