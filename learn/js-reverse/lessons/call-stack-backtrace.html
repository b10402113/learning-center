请求堆叠回溯

js-reverse · 步骤 1/4 · 从请求发送入口逐层向上找加密函数

浏览器发出去的每一个 HTTP 请求，都不是凭空出现的。它是某段 JavaScript 代码运行到某一行时，决定要把某个加密后的数据送出去。我们的目标很简单：顺着代码的执行顺序，从「请求发出去的地方」一路倒推回「数据被加密的地方」。

为什么 Call Stack 是你的起点

Chrome DevTools 的 Sources 面板里有一个 Call Stack 窗口。它记录的不是「谁调用了我」，而是「我是被谁一路调用过来的」。当你在一个断点停下来的时候，Call Stack 会从上到下显示：当前执行的函数在最上面，调用它的函数在再上面，一直追溯到最初触发的那个函数。

这种「从终点倒推回起点」的结构，刚好就是逆向工程最需要的视角。正向看代码，你得先搞清楚入口在哪、什么时候触发；反向看 Call Stack，你直接站在请求发出的那一刻，沿着调用链往上爬就行。

一个六层调用链的例子

假设有一个前端页面，点击标题之后触发一串函数调用：

test01 → test02 → test03 → test04 → test05 → test06

其中 test02 负责加密数据，test06 负责发送 ajax 请求。如果你在 test06 里打一个断点，Call Stack 会这样显示：

test06          ← 当前停在这里，ajax 即将发出
test05
test04
test03
test02          ← 加密在这里发生
test01          ← 最外层入口

你不需要从 test01 开始一行行读代码。只要在 Call Stack 里看到 test06 下面紧跟着一串中间函数，然后出现一个写着「加密」或「处理数据」名字的函数——那就是你的目标。

怎么在 DevTools 里实际操作

打开 Chrome DevTools，切到 Sources 面板。找到疑似发送请求的函数入口（通常是 XMLHttpRequest.send、fetch、或者某个 ajax 调用）。在这一行打上断点。然后回到页面触发这个请求。

页面会暂停在断点处。这时候切回 Sources 面板，右侧的 Call Stack 窗口已经展开。点击 Call Stack 里的每一个函数名，DevTools 会跳到该函数的定义位置，并在侧栏显示当时的局部变量。

你的任务就是沿着这条调用链，找出哪个函数第一次碰了那个加密后的值。一旦找到，后续所有的逆向工作都从那一个函数开始——不用管上面那些中转函数。

真实网站里的调用链会深得多

演示页只有六层，但真实网站可能有十几层甚至几十层。框架调用业务逻辑、业务逻辑调用工具函数、工具函数再调用加密库。没关系，Call Stack 会忠实地把每一层都列出来。你要做的就是一层层往下点，直到看见那个把明文变成乱码的函数。

如果 Call Stack 里的函数名全是 a、b、c 这种混淆后的名字，看不清谁是加密函数，别急。下一步我们会讲怎么用关键字搜索来补位。这一节先建立「从请求出口倒推」的心智模型。
