HTTP 協議：請求、響應與無狀態

學習目標

在 DevTools 中分辨請求、響應及其欄位，理解無狀態為何需要 Cookie。

B/S 與請求—響應

在 B/S 架構中，瀏覽器是客戶端，伺服器提供資料；爬蟲就是用程式模擬客戶端。客戶端先發 request，伺服器收到後才回 response。

請求報文

GET /api/course?page=2 HTTP/1.1
Host: example.test
User-Agent: browser
部分用途
請求列方法、URL、協議版本
請求頭User-Agent、Referer、Content-Type 等背景資訊
請求體要送出的資料，GET 通常沒有

GET 把參數放在 URL 的 ? 後，以 & 連接；POST 通常把資料放進請求體，常用於登入、表單或上傳。

響應報文與無狀態

HTTP/1.1 200 OK
Content-Type: application/json

{"ok": true}

響應頭描述資料類型或重定向，響應體才是 HTML、JSON 或媒體內容；200 表示成功，301/302 表示重定向，403 常見於拒絕存取，404 是找不到資源，500 是伺服器錯誤。

HTTP 本身不保存前一次通信的狀態，每次請求都像第一次見面；登入後仍要辨識使用者，因此才需要 Cookie 或 Session。
