模擬登入流程：從登入介面拿到 Cookie

js-reverse · Step 2/4 · 約 15 分鐘

這節課你會學到什麼

模擬登入的核心是「用 Session 物件先 POST 帳號密碼，拿到伺服器給你的 Cookie，再用同一個 Session 去抓登入後的資料」。學完這節課，你能獨立重現「登入→拿 Cookie→帶 Cookie 訪問受保護介面」的完整流程。

情境：為什麼需要模擬登入？

很多網站的內容只有登入後才看得到——你的書架、付費課程字幕、個人收藏。手動打開瀏覽器登入再複製 Cookie 能用，但自動化爬蟲做不到「假裝是人類手動登入」。模擬登入就是讓 Python 程式自己完成登入動作，拿到伺服器認證後自動抓取資料。

關鍵觀察：瀏覽器登入就是表單送出一個 POST 請求，伺服器回傳 Set-Cookie，瀏覽器之後自動帶上它。我們只要用 Session 物件重現這個過程。

模擬登入的兩次請求模型

整個流程只需要兩次 HTTP 呼叫，中間靠 Session 物件自動橋接 Cookie：

順序請求發生什麼
第一次 session.post(login_url, data=form) POST 帳號密碼到登入介面，伺服器回傳 Set-Cookie，Session 自動存下
第二次 session.get(protected_url) Session 自動攜帶 Cookie，伺服器讀取 Cookie 知道你是誰，回傳受保護資料

中間你完全不用碰 Cookie——Session 幫你做完了。這兩次請求的順序不能顛倒，因為第一次拿不到 Cookie，第二次就會被擋在門外。

實戰案例：17k 小說書架

17k 小說網站的書架資料是登入後才看得到的動態載入介面。我們用 Python 重現整個流程：

步驟 1：找到登入介面

打開瀏覽器的 DevTools → Network，手動登入一次。在請求列表裡找到 POST 請求：

Request URL: https://passport.17k.com/ck/user/login
Request Method: POST

在 Payload 或 Form Data 裡找到伺服器期望的表單欄位名稱：

loginName: your_username
password: your_password

步驟 2：用 Session 發送登入請求

import requests

session = requests.Session()

login_url = "https://passport.17k.com/ck/user/login"
login_data = {
    "loginName": "your_username",
    "password": "your_password"
}

# 第一次請求：POST 帳號密碼，Session 自動存 Cookie
resp = session.post(login_url, data=login_data)
print(resp.status_code)  # 200 表示成功
為什麼用 POST 而不是 GET？帳密不該出現在 URL 裡（GET 會把它們拼在網址列上），POST 放在請求體裡，伺服器用 request.form 或 request.body 讀取。

步驟 3：用同一個 Session 請求受保護介面

# 第二次請求：Session 自動攜帶 Cookie
shelf_url = "https://user.17k.com/ck/author/shelf"
resp = session.get(shelf_url)

data = resp.json()  # 這是動態載入的 JSON 資料
print(data)

這一步的關鍵：你在程式碼裡完全看不到「Cookie」三個字。Session 已經自動從第一次請求的回應裡提取了 Cookie，並在第二次請求時自動帶上。伺服器讀到 Cookie 知道你是誰，就把書架資料回傳給你。

完整程式碼

import requests

session = requests.Session()
session.headers.update({"User-Agent": "Mozilla/5.0 ..."})

# 第一次：登入拿 Cookie
login_resp = session.post(
    "https://passport.17k.com/ck/user/login",
    data={"loginName": "your_username", "password": "your_password"}
)

# 第二次：帶 Cookie 抓書架
shelf_resp = session.get("https://user.17k.com/ck/author/shelf")
books = shelf_resp.json()
print(books)

常見踩雷

問題原因解法
第二次請求回傳 401 或導向登入頁 Session 沒拿到 Cookie，通常是第一次 POST 的表單欄位名稱錯了 檢查 DevTools 裡的 Form Data，確認 key 完全一致
被 CSRF Token 擋住 有些登入頁在表單裡埋了隱藏的 token，POST 要一起帶上 先用 GET 請求登入頁，用正則或 lxml 從 HTML 裡擷取 token，再 POST
被驗證碼擋住 連續登入錯誤太多次，伺服器開始彈驗證碼 接打碼平台（後面會教）或降低登入頻率
口訣：模擬登入 = session.post 拿 Cookie + session.get 拿資料。中間 Cookie 由 Session 自動管。

延伸：不是每個網站都用 JSON

17k 的書架是 Ajax 動態載入，回應格式是 JSON，所以可以用 .json() 解析。但有些網站登入後回傳的是 HTML 頁面，這時要用 .text 拿到 HTML 字串，再用 lxml 或 XPath 解析。兩種情境的 Session 用法完全一樣，差別只在回應的解析方式。

小結

模擬登入是「會抓公開網頁」升級成「能進入登入後世界」的關鍵技能。核心就兩步：session.post 提交帳密、Session 自動存 Cookie；session.get 訪問受保護介面、Session 自動帶 Cookie。中間你完全不用手動碰 Cookie。
