運算符：==、===、短路與三目

js-reverse · 14-js-variables-control · Step 2/4

學習目標

能分辨 == 與 === 的隱式轉換差異、理解短路運算與零值，並手工求值三目與逗號運算子的綜合表達式。

為什麼運算符是逆向的雷區

JS 加密代碼最愛用高密度的運算子來混淆邏輯：一個變數同時做了短路判斷、三目選擇、逗號求值。如果你對這些運算子的優先順序和轉換規則不夠熟，看代碼就像看天書。把這節的基礎打穩，後面再長的表達式都能一步步拆解。

== 與 === 的隱式轉換陷阱

這兩個運算子都用來比較相等，但行為完全不同：

運算子名稱行為
==寬鬆相等會做隱式類型轉換後再比較
===嚴格相等類型不同直接回傳 false

最經典的例子：

2 == "2"    // true  ：數字 2 被轉成字串 "2" 後相等
2 === "2"   // false ：型別不同（number vs string），直接 false

還有一個容易踩的坑：字串之間用 >< 比較時，是逐字比較第一個字元的字典順序，不是比數字大小。

"10" > "2"   // false ："1" 的字典順序在 "2" 前面

逆向時看到 === 通常代表工程師想精確控制型別，看到 == 則要警覺可能有隱式轉換。

零值：哪些東西在布林上下文裡是假的

JS 每種型別都有一個「零值」（falsy value），在 if 條件或邏輯運算裡會被當成 false：

型別零值
數字0
字串""（空字串）
布林false

短路運算

&& 和 || 是短路運算子——左邊已經能決定結果，右邊就不會執行。

1 && 2   // 2  ：左邊 true，回傳右邊
1 && 0   // 0  ：左邊 true，回傳右邊
0 || 100 // 100：左邊 false，回傳右邊

短路運算在逆向中很常見的用法是「守衛模式」：條件成立才執行後面的函數。

login(user, pwd) && show()
// 等於：if (login(user, pwd)) { show() }

三目運算子

三目運算子是 if-else 的單行縮寫，格式為 表達式 ? 值1 : 值2。

var age = 19
var s = age > 18 ? "成年電影" : "未成年電影"
console.log(s)  // 輸出：成年電影

逗號運算子

逗號運算子會從左到右逐個求值，但只回傳最後一個表達式的結果。

var x = (10, 20, 30)
console.log(x)  // 輸出：30

看起來少見，但在混淆代碼裡經常和三目、自增混在一起，用來把多步操作塞進一行。

綜合表達式手工求值

下面這段是逆向裡常見的「綜合題」，需要按照運算子優先順序一步步拆解：

let a = 10, b = 20, c = 5, d = 17
let e, m
e = (e = a > 3 ? b : c, m = e < b++ ? c-- : a = 3 > b % d ? 27 : 37, m++)

解讀步驟：

  1. 先算第一個括號內的 e = a > 3 ? b : c：a > 3 為 true，所以 e = b = 20。
  2. 再算 m = e < b++ ? ...：此時 e = 20，b++ 先拿原值 20 來比，20 < 20 為 false，往後走到 a = 3 > b % d ? 27 : 37。這步的 b 已經變成 21，21 % 17 = 4，3 > 4 為 false，所以 a = 37，m = 37。
  3. 最後 m++：把 37 賦給 e，然後 m 自己加 1 變成 38。

最終結果：e = 37，m = 38。

逆向時碰到這種代碼，千萬不要試圖一眼看穿。照著運算子優先順序，一個一個拆開寫在紙上，慢慢就能還原。
