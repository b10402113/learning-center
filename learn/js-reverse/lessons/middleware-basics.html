下载中间件核心概念

js-reverse · Step 1/5 · 約 15 分鐘

這節課你會學到什麼

理解 Scrapy 下載中間件在框架中的位置、三個核心方法的作用，以及 spider 參數如何實現爬蟲類與中間件的資料交互。

情境：Scrapy 框架裡，請求怎麼流動？

你在 Scrapy 專案裡發了 100 個請求，每個請求都要經過引擎、調度器、下載器、爬蟲、管道這五個組件。但你想過沒有：請求從引擎送到下載器的途中，有沒有一個「檢查站」，能在請求出發前偷偷塞一個代理 IP，或在回應回來時順手把動態頁面重渲染一次？

這個檢查站就是下載中間件（Downloader Middleware）。它位於引擎與下載器之間，所有請求和回應都必須經過它——就像海關，每份貨物都要檢查蓋章。

引擎 ──→ 【下載中間件】──→ 下載器 ──→ 網路
  ←── 【下載中間件】←── 下載器 ←── 網路

請求流向：引擎 → 中間件 → 下載器
回應流向：下載器 → 中間件 → 引擎

Scrapy 有兩類中間件：爬蟲中間件（Spider Middleware）連接引擎與爬蟲，下載中間件（Downloader Middleware）連接引擎與下載器。本節聚焦下載中間件，因為幾乎所有「改請求、改回應、掛代理、掛 UA」的需求都在這裡完成。

中間件的骨架

一類下載中間件就是一個普通 Python 類別，通常擺在專案的 middlewares.py 檔案裡。它有三個核心方法：

# middlewares.py
class MyDownloaderMiddleware:
    def process_request(self, request, spider):
        """處理每個發送前的請求"""
        pass

    def process_response(self, request, response, spider):
        """處理每個下載完成后的回應"""
        pass

    def process_exception(self, request, exception, spider):
        """處理請求發生例外的情況"""
        pass

三個核心方法

1. process_request — 請求出門前的最後改寫

process_request(self, request, spider) 攔截所有即將被發出的請求。你可以在這裡改要求標頭（headers）、塞代理 IP（request.meta['proxy']）、掛 Cookie。

這個方法回傳 None，代表「繼續往下傳給下載器」；如果回傳一個 Response 物件，Scrapy 會跳過下載器直接把這個 Response 交給爬蟲解析；如果回傳 Request 物件，則重新排程這個新請求。

2. process_response — 回應進門前的重新包裝

process_response(self, request, response, spider) 攔截所有下載完成后的回應。最常見的用途是動態頁面：當 Scrawy 拿到的回應裡沒有你需要的資料（因為資料是 JavaScript 渲染的），你可以在這裡用瀏覽器重新渲染，再用新的 HtmlResponse 替換掉原本的 response。

這個方法必須回傳一個 Response 物件（新的或舊的都可以）。

3. process_exception — 例外時的降級方案

process_exception(self, request, exception, spider) 在請求丟出例外時觸發，例如逾時、連線被拒。你可以在這裡記錄例外、換一個代理重試、或回傳一個「降級用的 Response」讓爬蟲繼續跑。

spider 參數：打通爬蟲與中間件的橋樑

三個方法都有的 spider 參數，是爬蟲類別的實例化物件。透過它，爬蟲檔案裡定義的屬性，中間件都能讀取；反過來，中間件也可以把資料塞給爬蟲。

最典型的協作模式：爬蟲檔案裡定義一個代理池，中間件裡用 spider.proxy_list 取用。

# spiders/myspider.py
class MySpider(scrapy.Spider):
    name = 'myspider'
    # 代理池定義在爬蟲類中
    proxy_list = [
        'http://11.22.33.44:8080',
        'http://55.66.77.88:3128',
    ]

# middlewares.py
import random

class ProxyMiddleware:
    def process_request(self, request, spider):
        # 從爬蟲物件拿到代理池
        proxy = random.choice(spider.proxy_list)
        request.meta['proxy'] = proxy

這種「資料源放爬蟲、消費邏輯放中間件」的分工，讓爬蟲的配置和中間件的行為解耦，後面 Selenium 案例會繼續沿用。

中間件的啟用與優先順序

寫好中間件類別後，必須在 settings.py 的 DOWNLOADER_MIDDLEWARES 字典裡註冊才會生效：

# settings.py
DOWNLOADER_MIDDLEWARES = {
    'myproject.middlewares.MyDownloaderMiddleware': 543,
}

鍵是中間件類別的完整路徑，值是優先級（0–1000 的整數）。數字越小，代表該中間件越靠近引擎、越先執行 process_request、越後執行 process_response。一個直覺記憶：

  • process_request：小數字先執行（靠近引擎）
  • process_response：大數字先執行（靠近引擎）

小結

下載中間件位於引擎與下載器之間，是 Scrapy 的全局請求／回應攔截點。三個核心方法各司其職：process_request 改寫請求、process_response 替換回應、process_exception 處理例外。spider 參數讓爬蟲檔案與中間件共享資料，是後續 Selenium 案例的基礎。
