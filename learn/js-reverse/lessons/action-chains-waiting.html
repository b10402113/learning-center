Selenium 浏览器自动化

Step 4 — 动作链与页面等待

Learning Goal

掌握 ActionChains 处理鼠标拖曳等无特定对象的动作，能按场景选择强制、显式、隐式三种等待策略。

动作链 ActionChains：处理复杂交互

前面学的 click()、send_keys() 都是针对具体元素的操作——你得先定位到一个按钮，然后点击它。但有些操作没有明确的「目标元素」：鼠标拖曳、键盘快捷键、鼠标悬停在某个区域上触发下拉菜单……这些动作需要描述「一系列移动过程」，而不是「对某个元素做某件事」。

ActionChains（动作链）就是用来处理这类场景的。它把多个动作串起来，按顺序执行。核心用法是：创建动作链 → 添加动作 → 调用 perform() 执行。

from selenium.webdriver.common.action_chains import ActionChains

# 1. 创建动作链，绑定浏览器
actions = ActionChains(browser)

# 2. 定位要拖曳的元素
tag = browser.find_element(By.ID, 'draggable')

# 3. 添加动作：点击按住 → 移动 → 释放
actions.click_and_hold(tag).move_by_offset(200, 0).release()

# 4. 执行动作链
actions.perform()

注意：动作链不会自动执行，必须最后调用 perform()，之前添加的动作只是「排队」。

ActionChains 常用动作

方法作用
click_and_hold(element)点击并按住元素
move_by_offset(x, y)从当前位置偏移移动
move_to_element(element)移动到元素中心
release()释放鼠标
drag_and_drop(source, target)拖曳元素到目标
key_down('ctrl')按下键盘按键
key_up('ctrl')释放键盘按键
send_keys('文字')输入文字（可不在元素上）

iframe 内元素定位：先切入再操作

一个常见的坑：页面里嵌了 iframe（子页面），iframe 里的元素用普通定位方式找不到，会报 NoSuchElementException。必须先「切入」iframe，定位完再「切回」主页面：

# 切入 iframe（通过 id、name 或定位到的 iframe 元素）
browser.switch_to.frame('iframeResult')

# 现在可以定位 iframe 里面的元素了
tag = browser.find_element(By.ID, 'inner-button')
tag.click()

# 操作完切回主页面
browser.switch_to.default_content()

动作链在 iframe 里同样适用，但必须先切入 iframe，否则 move_by_offset 等动作会相对于主页面执行，导致位置偏移。

页面等待：解决「元素还没出现」

动态 HTML 页面的元素出现时间不确定——可能 0.5 秒就渲染完，也可能要 3 秒。如果代码执行太快，元素还没出现就去定位，就会报错。Selenium 提供了三种等待策略：

1. 强制等待：time.sleep()

最简单也最笨：让代码阻塞固定秒数。不管元素是否已经出现，都要等够时间。

import time
time.sleep(3)  # 阻塞 3 秒

优点：简单。缺点：浪费时间（元素 0.5 秒就出现了，还要等 2.5 秒），元素一直不出现也会白等。

2. 显式等待：WebDriverWait（推荐）

「智能等待」：设定一个最长等待时间，每隔 0.5 秒检查一次目标元素是否出现，出现了就立即返回，超时才抛异常。这是最灵活、最常用的方式。

from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.common.by import By

# 最长等 10 秒，每 0.5 秒检查一次
wait = WebDriverWait(browser, 10, 0.5)

# 等待 id 为 kw 的元素出现
element = wait.until(EC.presence_of_element_located((By.ID, 'kw')))

常用的等待条件：

条件说明
presence_of_element_located元素出现在 DOM 里（不一定可见）
visibility_of_element_located元素可见（宽高都大于 0）
element_to_be_clickable元素可点击（可见且启用）
title_contains('关键字')页面标题包含指定文字

3. 隐式等待：implicitly_wait()

全局设置：之后所有 find_element 调用，如果元素没立即出现，会在 n 秒内不断重试，超时才报错。

browser.implicitly_wait(10)  # 全局隐式等待 10 秒

优点：一次设置，全局生效。缺点：只能等元素出现，不能等标题变化、元素可点击等复杂条件；而且会影响所有定位操作，可能拖慢整体执行速度。

三种等待的选择策略

场景推荐等待
调试脚本、临时停顿time.sleep()
关键元素加载（登录按钮、搜索结果）WebDriverWait
全局兜底，防止个别元素加载慢implicitly_wait()

实际项目中，通常用 implicitly_wait() 做全局兜底，关键步骤用 WebDriverWait 精确等待，调试时临时用 sleep。

关键概念总结

  • ActionChains：动作链，把多个动作串起来，处理拖曳、悬停等无特定目标元素的交互。
  • perform()：执行动作链，必须调用才会生效。
  • iframe：页面中嵌入的子页面，里面的元素必须先 switch_to.frame() 切入才能定位。
  • 显式等待：WebDriverWait + 条件，智能轮询指定元素，最灵活。
  • 隐式等待：implicitly_wait() 全局生效，n 秒内不断重试找元素。
