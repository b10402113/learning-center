execjs 调用 SHA1 与 GET 请求闭环

实战：SHA1 与百度 sign · 步骤 3/5

学习目标

能把扣下的 SHA1 JS 模块通过 execjs 挂到 Python 调用链上，拼出完整的丁香网 GET 请求，跑通从参数构造到拿到 JSON 响应的闭环。

execjs 的核心用法

execjs 只有两个关键动作：compile() 把 JS 代码编译成可调用的对象，call() 按函数名调用并传参。

import execjs

# 读取扣下的 JS 文件
js_code = open("02 丁香网.js").read()
js_compile = execjs.compile(js_code)

# 调用入口函数 u(data)，传入明文串
sign = js_compile.call("u", data)
print("sign:", sign)

这里不需要理解 JS 内部怎么算 SHA1，只需要知道入口函数名是 u，输入是明文串，输出是 40 位十六进制字符串。

完整请求闭环

把前两步串起来，就是一个完整的丁香网爬虫脚本：

import requests
import execjs
import random
import time

# 1. 构造参数
noncestr = str(random.randint(0, 100000000)).rjust(8, '0')
timestamp = int(time.time() * 1000)

params = {
    'keyword': '新冠',
    'sectionCode': '0',
    'pageSize': '10',
    'pageNum': '1',
    'serverTimestamp': timestamp - 2,
    'timestamp': timestamp,
    'noncestr': noncestr,
}

# 2. 按字典序拼接明文串
data = (
    'appSignKey=4bTogwpz7RzNO2VTFtW7zcfRkAE97ox6ZSgcQi7FgYdqrHqKB7aGqEZ4o7yssa2aEXoV3bQwh12FFgVNlpyYk2Yjm9d2EZGeGu3'
    f'&keyword={params["keyword"]}'
    f'&noncestr={params["noncestr"]}'
    f'&pageNum={params["pageNum"]}'
    f'&pageSize={params["pageSize"]}'
    f'&sectionCode=0'
    f'&serverTimestamp={params["serverTimestamp"]}'
    f'&timestamp={params["timestamp"]}'
)

# 3. 用 execjs 算 sign
sign = execjs.compile(open("02 丁香网.js").read()).call("u", data)
params["sign"] = sign

# 4. 发 GET 请求
response = requests.get(
    'https://www.dxy.cn/bbs/newweb/case-bank/page-post-info',
    params=params,
    cookies=cookies,
    headers=headers
)
print(response.text)

为什么不用 Python hashlib 直接算？

理论上可以，但有一个坑：丁香网 JS 里的 SHA1 在算哈希前，先对输入做了 unescape(encodeURIComponent(e)) 做 UTF-8 编码。如果你直接用 hashlib.sha1(data.encode()).hexdigest()，对于纯 ASCII 字符结果一样，但遇到中文（比如 keyword=新冠）就会因为编码方式不同算出不同的值。

用 execjs 就省去了对齐编码细节的麻烦——JS 怎么编码的，你就让它原样跑，保证和浏览器算出一模一样的结果。

调试技巧：先打印 sign 再发请求

写爬虫时，先别急着发请求。把算出来的 sign 打印出来，和 DevTools 里浏览器实际发出的 sign 对比。如果长度不对（应该是 40 位），或者同一参数两次算出来不同，说明明文串拼接有问题。

小结

execjs 把 JS 加密函数变成了 Python 里的一个普通函数调用。整个闭环就是：构造参数 → 字典序拼接 → execjs 算 sign → 拼进 params → requests.get。下一步我们看一个更复杂的案例——百度翻译的 sign，它不是标准算法，而是一段被混淆过的位运算。
