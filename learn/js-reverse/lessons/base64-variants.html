base64 變種與圖片

學習目標：識別 URL 安全型 base64 的字元替換規則（- 替 +、_ 替 /），能把網頁裡 data:image/png;base64 內嵌圖片還原成可查看的圖片檔案，並處理密文裡混入空格或缺失填充符的髒資料。

現象：長得像 base64，但解不開

有時候你拿到一串字元，看起來像 base64，但裡面出現 - 或 _，用標準 b64decode 會報錯或解出亂碼。這是 URL 安全型 base64。

標準 base64 使用 + 和 /，但這兩個字元在 URL 裡是保留字元（分別代表空格和路徑分隔）。為了讓 base64 可以直接塞進 URL 參數，變種把 + 換成 -、/ 換成 _。規則是固定的：

  • + → -
  • / → _

解碼前要先還原

遇到疑似變種的字串，解碼前用 replace 還原回標準字元，再做 b64decode：

import base64

variant = "SGVsbG8gV29ybGQh_tw"
standard = variant.replace("-", "+").replace("_", "/")
print(base64.b64decode(standard).decode())  # Hello world!?

實戰裡常見的是 JWT（JSON Web Token）的 header 和 payload 部分，就是標準的 URL-safe base64。

內嵌圖片：data URL

網頁裡有些圖片不是用 <img src="url"> 載入，而是直接寫在 HTML 或 CSS 裡，前綴長這樣：

data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...

這是 data URL，格式為 data:<MIME型別>;base64,<資料>。只要用最後一個逗號切開，取後半段做 base64 解碼，就能拿到原始圖片的位元組：

import base64

data_url = "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
header, b64_data = data_url.split(",", 1)
img_bytes = base64.b64decode(b64_data)

with open("output.png", "wb") as f:
    f.write(img_bytes)

常見陷阱：

  • 資料裡混入了空白字元（換行、空格），要先 strip() 或 replace() 清掉。
  • 解出來副檔名不一定對應副檔名，要依前綴的 MIME 型別決定副檔名（image/png → .png）。

髒資料處理清單

逆向時抓到的 base64 字串往往不乾淨，處理順序建議：

  1. 去空白：data.strip().replace("\n", "").replace(" ", "")
  2. 還原變種：.replace("-", "+").replace("_", "/")
  3. 補填充：data += (4 - len(data) % 4) * "="
  4. 解碼：base64.b64decode(data)

重點整理

  • URL-safe base64 把 +、/ 換成 -、_，解碼前要先還原。
  • data URL 格式：data:<MIME>;base64,<資料>，用逗號切開取後半。
  • 內嵌圖片解出來是位元組，要用 "wb" 二進位模式寫檔。
  • 髒資料處理順序：去空白 → 還原變種 → 補 = → 解碼。
