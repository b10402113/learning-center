Cookie 本質與 Session 自動管理

js-reverse · Step 1/4 · 約 12 分鐘

這節課你會學到什麼

Cookie 是伺服器在你瀏覽器裡留下的「身分證」。掌握 Cookie 的運作原理之後，你就能理解為什麼手動複製 Cookie 那麼麻煩、為什麼 Session 物件是更好的解法，以及 requests.Session() 的標準用法。

情境：為什麼伺服器需要 Cookie？

你打開瀏覽器登入微博，伺服器驗證帳號密碼後回傳了一頁內容。但 HTTP 協議本身是無狀態的——每一次請求對伺服器來說都是陌生人。如果沒有機制記住「你是誰」，你每按一個連結都要重新輸入帳號密碼。

Cookie 就是解法：伺服器在第一次回應裡放一小段資料（Cookie），瀏覽器下次自動帶上它，伺服器就認得你了。它本質上就是一組鍵值對（key-value pairs）。

Cookie 的生命週期

階段發生什麼你在 DevTools 裡看到什麼
伺服器下發 伺服器在 HTTP 回應頭裡帶 Set-Cookie Response Headers → Set-Cookie: session_id=abc123
瀏覽器存儲 瀏覽器把 Cookie 存起來，綁定到該域名 Application → Cookies → 該網站的 domain
自動攜帶 同域名的後續請求，瀏覽器自動帶上 Cookie 請求頭 Request Headers → Cookie: session_id=abc123

用 Python 寫爬蟲時，requests 不會幫你做這件事——你需要自己管理 Cookie 的存取。

方式一：手動處理 Cookie

最直覺的做法：打開 DevTools，找到目標請求的 Cookie 欄位，整段複製下來，貼到你的 Python 程式碼的 headers 裡：

import requests

headers = {
    "User-Agent": "Mozilla/5.0 ...",
    "Cookie": "session_id=abc123; username=test; token=xyz"
}
resp = requests.get("https://target.com/api/data", headers=headers)
print(resp.json())

這種做法馬上能跑通，但有三個致命缺點：

缺點說明
有時效性Cookie 過期後你要重新抓、重新貼
手動複製很煩每次請求都要去 DevTools 裡翻
動態資料抓不到有些 Cookie 裡的值每次登入都不一樣，你根本無法預先寫死
白話：手動處理就像每次都去櫃台拿一張新的訪客證再進門——能用，但很累。Session 自動管理就像刷臉進門：伺服器認得你，自動幫你通行。

方式二：Session 自動管理（推薦）

requests.Session() 是一個持久化的 HTTP 會話物件。它做的事很簡單：

  1. 你先用 Session 發一次請求——伺服器回傳的 Cookie 被 Session 自動存起來。
  2. 你再用同一個 Session 發後續請求——Session 自動把存好的 Cookie 帶上去，伺服器就認得你了。
import requests

# 1. 建立空白 Session
session = requests.Session()

# 2. 用 Session 發請求（伺服器下發的 Cookie 被自動存入）
resp = session.get("https://target.com/api/data")

# 3. 後續請求自動攜帶 Cookie
data = session.get("https://target.com/api/data").json()
print(data)

對比手動方式，Session 的優勢：

比較項目手動複製 CookieSession 自動管理
易用性每次都要手動貼自動存取
時效問題過期要重新抓伺服器刷新時自動更新
動態 Cookie抓不到自動捕獲
最少請求數1 次（第一次就得有）2 次（先拿 Cookie，再用它）
關鍵差異：Session 方式至少需要兩次請求——第一次拿 Cookie，第二次才真正拿資料。這就是為什麼你之前在雪球網只帶了 User-Agent 拿不到資料：模擬力度不夠，需要先讓伺服器「認得」你。

實戰對比：雪球網熱帖

雪球網的熱帖資料是 Ajax 動態載入的。如果只帶 User-Agent 發請求：

# ❌ 失敗：伺服器不認得你
headers = {"User-Agent": "Mozilla/5.0 ..."}
resp = requests.get("https://xueqiu.com/statuses/hot/listV2.json", headers=headers)
print(resp.status_code)  # 401 或空資料

用 Session 自動管理：

# ✅ 成功：先讓伺服器認得你
session = requests.Session()
session.headers.update({"User-Agent": "Mozilla/5.0 ..."})

# 第一次請求：觸發伺服器下發 Cookie
session.get("https://xueqiu.com/")

# 第二次請求：Session 自動攜帶 Cookie，拿到資料
resp = session.get("https://xueqiu.com/statuses/hot/listV2.json")
data = resp.json()
print(data)
核心思路：拿不到資料，先查 Cookie。這是 Python 爬蟲的排錯第一步。

Session 物件的完整 API

requests.Session() 的 API 和 requests.get/post 幾乎一樣，差別在它是「綁在一個物件上」：

操作一般 requestsSession
GET 請求requests.get(url)session.get(url)
POST 請求requests.post(url, data=...)session.post(url, data=...)
設定 Headersheaders={}（每次都傳）session.headers.update({})（設一次）
設定 Cookiecookies={}（手動）自動（伺服器下發的）
使用代理proxies={}（每次都傳）session.proxies = {}（設一次）

小結

Cookie 本質上就是伺服器在你瀏覽器裡放的鍵值對，用來記住「你是誰」。在 Python 爬蟲裡，requests.Session() 自動管理這些鍵值對——你不用手動複製，不用擔心過期，不用預先寫死。這是處理需要登入狀態的網站的第一步。
