RSA 非對稱加密

學習目標：理解 RSA 公私鑰分工——公鑰加密私鑰解密用於資料傳輸，反向用於數位簽章；能從 PEM 檔案識別金鑰，在 Python 裡用 PKCS1_v1_5 完成加解密，並認識前端 CryptoJS 的 RSA 呼叫形態。

現象：前端用公鑰加密密碼

你在 DevTools 裡看到登入請求的 password 欄位不是明文，而是一段很長的 base64 字串。檢查網頁原始碼或 JS 檔案，常會發現一段以 -----BEGIN PUBLIC KEY----- 開頭的文字。這就是 RSA 非對稱加密。

與 AES 的根本差異

  • AES 對稱：加密和解密用同一把金鑰。
  • RSA 非對稱：加密用公鑰，解密用私鑰。公鑰可以公開，私鑰必須保密。

這解決了 AES 的「金鑰分發問題」：你不需要把金鑰傳給對方，只要拿到對方的公鑰就能加密，只有持有私鑰的對方能解開。

公私鑰分工的兩種用途

用途加密者解密者
資料加密公鑰私鑰
數位簽章私鑰公鑰

爬蟲最常遇到的是第一種：前端用公鑰加密敏感資料（如密碼），傳給伺服器後用私鑰解密。

PEM 檔案格式

RSA 金鑰通常以 PEM 格式儲存，看起來像這樣：

-----BEGIN PUBLIC KEY-----
MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...
-----END PUBLIC KEY-----

PEM 本身只是 base64 編碼的文字，可以直接複製貼上到 Python 程式碼裡。

Python 實作：RSA 加解密

from Crypto.PublicKey import RSA
from Crypto.Cipher import PKCS1_v1_5
import base64

# 產生金鑰對（實務上從 PEM 匯入）
key = RSA.generate(1024)
private_key = key.export_key()
public_key = key.publickey().export_key()

# 公鑰加密
message = "hello rsa"
rsa_public = PKCS1_v1_5.new(RSA.import_key(public_key))
encrypted = rsa_public.encrypt(message.encode())
b64_encrypted = base64.b64encode(encrypted).decode()

# 私鑰解密
rsa_private = PKCS1_v1_5.new(RSA.import_key(private_key))
decrypted = rsa_private.decrypt(base64.b64decode(b64_encrypted), None)
print(decrypted.decode())  # hello rsa

注意 decrypt 的第二個參數是哨兵值（sentinel），用來偵測解密失敗，通常傳 None。

前端 CryptoJS 的 RSA 呼叫

前端用 CryptoJS 做 RSA 加密時，通常會用 JSEncrypt 或原生 CryptoJS 的 RSA 套件：

const encrypt = new JSEncrypt();
encrypt.setPublicKey(`-----BEGIN PUBLIC KEY-----
MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...
-----END PUBLIC KEY-----`);
const encrypted = encrypt.encrypt("hello rsa");
console.log(encrypted);  // base64 密文

逆向時，只要從 JS 裡擷取 PEM 公鑰，就能在 Python 裡復現同樣的加密流程。

與摘要演算法的組合

實務上 RSA 不會直接加密長訊息（RSA 有長度限制，1024 位元金鑰最多加密 117 位元組）。常見組合是：

  1. 用 AES 加密原始資料（對稱，速度快）。
  2. 用 RSA 加密 AES 金鑰（非對稱，安全傳遞金鑰）。

這就是「混合加密」，HTTPS 底層也是同樣原理。

重點整理

  • RSA 非對稱：公鑰加密私鑰解密，解決金鑰分發問題。
  • PEM 格式以 -----BEGIN PUBLIC KEY----- 開頭，可直接複製到程式碼。
  • Python 用 pycryptodome 的 PKCS1_v1_5，前端用 JSEncrypt 或 CryptoJS。
  • RSA 有長度限制，長訊息通常用混合加密（AES + RSA）。
