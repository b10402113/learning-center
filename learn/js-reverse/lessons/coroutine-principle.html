协程原理：用户空间调度

js-reverse · 06-asyncio · Step 2/4

学习 goal

能说出协程与线程/进程的本质区别（用户空间调度 vs 操作系统调度），并解释协程为什么轻量、为什么可控。

线程和进程的痛点

上一章学了进程和线程。它们都能实现异步——多个任务交替执行，不傻等 IO。但它们有一个共同问题：切换由操作系统控制。

操作系统调度线程时，用的是「时间片轮转」——每个线程跑一小段时间就被强制切走，不管它是不是正好在干关键活。更糟的是，你无法控制下一次切回来的时候，CPU 正好在跑你想要的那个下载任务。可能切来切去，CPU 花了不少时间在「切换」本身，而不是真正下载。

这就引出一个需求：能不能在用户自己的程序里手动控制切换，而不是交给操作系统？

协程是什么

协程（Coroutine），也叫微线程，是一种用户空间的调度机制。它的核心思想是：程序员自己决定什么时候挂起当前任务、什么时候恢复下一个任务。

和线程/进程的区别：

维度线程/进程协程
调度方操作系统程序员（用户空间）
切换成本高（需要系统调用）低（不需要系统调用）
可控性不可控，随机切换可控，自定义调度逻辑
资源占用较重（每个线程占 MB 级栈内存）极轻（协程只是对象，KB 级）

协程怎么切换

协程的切换只有两步：挂起当前任务，把控制权交给下一个任务。这个过程完全在用户空间进行，不需要操作系统介入，所以没有系统调用的开销。

打个比方：线程切换像是老板（操作系统）随时可能打电话叫你去做别的事，你没法拒绝；协程切换像是你自己列了个待办清单，做完一件主动换下一件，节奏完全自己掌控。

协程的两个优点

轻量级：协程的创建和销毁开销极小。一个线程占几 MB 栈内存，一个协程只是一个 Python 对象，几 KB 就够了。单线程里跑上万个协程很常见，但跑上万个线程会把操作系统拖垮。

可控性：调度逻辑由程序员自己写。你可以决定「遇到网络请求就挂起」「数据回来了就恢复」，而不是让操作系统随机切。这让协程在 IO 密集型任务里效率极高。

总原则：留住 CPU

协程的设计哲学可以用一句话概括：留住 CPU 在自己的程序中。线程/进程切换时，CPU 会进入内核态、保存上下文、恢复上下文，这些操作本身就在浪费 CPU 时间。协程把这些开销省了，让 CPU 尽可能花在真正有用的计算上。

协程与异步的关系

协程是实现异步的一种手段。多进程、多线程、协程都能实现异步，但协程在 IO 密集型场景下最轻量、最可控。Python 的 asyncio 框架就是协程的具体实现。
