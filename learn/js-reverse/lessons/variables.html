變數宣告：var、let、const

js-reverse · 14-js-variables-control · Step 1/4

學習目標

能辨識 JS 中 var/let/const 三種宣告方式、理解只宣告未賦值的 undefined 預設值，以及一行多變數宣告的常見陷阱。

為什麼變數宣告是逆向的第一步

打開一段 JS 加密代碼，你看到的第一行幾乎都是變數宣告。能不能快速看懂這些宣告，直接決定你能不能跟隨後續的邏輯。逆向裡有一個實用判斷：如果一個變數的值是 undefined，要麼它還沒被賦值，要麼它是被故意清空的——這往往是追蹤賦值時機的重要線索。

三種宣告方式

JS 提供三種宣告變數的方式，它們的關鍵差異在於「能不能重新指派」：

宣告方式能否重新指派常見用途
var可以舊式寫法，逆向中仍常見
let可以現代標準，推薦使用
const不可宣告後不能重新綁定（常數）

在逆向實戰裡，你不需要纠结該用 let 還是 var——重點是能一眼認出它們都是變數宣言。以下三行程式的效果完全相同：

var x = 100
let y = 200
const z = 300

只宣告不賦值會發生什麼

宣告一個變數卻不給值，這個變數不會報錯，而是自動拿到一個特殊值：undefined。

var z      // 只宣告，沒賦值
console.log(z)   // 輸出：undefined
z = 300          // 之後再賦值
console.log(z)   // 輸出：300

這在逆向裡很有用。如果你在 DevTools 裡看到一個變數是 undefined，代表不是還沒跑到的賦值代碼，就是被刻意清空的狀態——沿著賦值點回溯，往往能找到加密邏輯的源頭。

一行宣告多個變數

JS 允許用逗號在同一行宣告多個變數，但只有實際賦到值的才會是那個值，沒賦值的仍然是 undefined。

var a, b, c = 3, d, e = 5
console.log(a, b, c, d, e)
// 輸出：undefined undefined 3 undefined 5

這個語法在混淆代碼裡很常見，多個變數擠在一起，看起來很嚇人，但其實就是「沒賦值就 undefined」而已。

const 不是完全不能改

要稍微注意：const 保證的是「綁定」不能改，但如果綁定的是物件或陣列，裡面的內容還是可以修改。不過在你這個階段，把 const 當成「宣告後不能再重新賦值」就夠用了。
