Item 封装与 Pipeline 三方法

Scrapy 管道与持久化 · 步骤 1/4

学习目标

掌握 items.py 定义字段、yield 提交、以及 pipelines.py 中 process_item / open_spider / close_spider 三方法的调用时机与职责。

为什么需要管道？

在 Scrapy 里，爬虫（Spider）只负责"抓"——发请求、解析响应、提取字段。但抓到的数据往哪里存？怎么存？这件事不能全塞给 Spider，否则 Spider 会越来越臃肿，换个存储方式就得改爬虫代码。

Scrapy 的解法是把"抓"和"存"分开。Spider 解析完数据后，把数据封装成一个Item对象，然后 yield 出去。Scrapy 引擎收到这个 Item 后，会把它丢进一条"传送带"——这条传送带就是Pipeline（管道）。管道里可以挂多个处理类，每个类负责把 Item 存到一种载体（文件、MySQL、Redis……）。

这种分工的好处是：Spider 只管解析，存储逻辑全部集中在 pipelines.py 里。想换数据库？改管道就行，Spider 一行不动。

Item：数据的标准化信封

Item 是 Scrapy 对"一条数据"的封装。它本质上是一个类，字段用 scrapy.Field() 定义。你可以把它想成一个标准化的信封——每个信封上都有固定的格子（字段），Spider 把解析结果填进去，管道再按格子取出来存。

# items.py
import scrapy

class MovieItem(scrapy.Item):
    title = scrapy.Field()
    rating = scrapy.Field()
    genre = scrapy.Field()

在 Spider 里，先实例化 Item，再把字段填进去，最后 yield：

# spiders/movie.py
def parse(self, response):
    titles = response.xpath('//h2/text()').extract()
    for title in titles:
        item = MovieItem()
        item['title'] = title
        item['rating'] = '9.0'
        item['genre'] = 'Drama'
        yield item

注意：管道只能接收 Item 类型。如果你 yield 一个字典，管道会直接忽略它。这是初学者最常踩的坑。

Pipeline 三方法：一次请求的生命周期

一个管道类通常需要实现三个方法，它们对应爬虫运行的不同阶段：

方法调用时机典型用途
open_spider(self, spider)爬虫启动时，只调用一次打开文件、建立数据库连接、初始化 Redis 客户端
process_item(self, item, spider)每次 Spider yield 一个 Item 时调用把 Item 写入文件/数据库，必须 return item
close_spider(self, spider)爬虫结束时，只调用一次关闭文件、关闭数据库连接、释放资源

为什么是"三方法"而不是一个？因为资源管理有生命周期：数据库连接不能每次存一条数据都重新建连（太慢），也不能永远不关（会泄漏）。open_spider 和 close_spider 把资源的创建和销毁包起来，process_item 只管"来一条存一条"。

# pipelines.py
class MovieFilePipeline:
    def open_spider(self, spider):
        self.f = open('movies.csv', 'w', encoding='utf-8')
        self.f.write('title,rating,genre\n')

    def process_item(self, item, spider):
        line = f"{item['title']},{item['rating']},{item['genre']}\n"
        self.f.write(line)
        return item   # 必须 return，否则下一个管道收不到

    def close_spider(self, spider):
        self.f.close()

return item 这件事非常关键。Scrapy 的管道是链式传递的——一个 Item 经过第一个管道处理后，必须被 return 出来，才能流到下一个管道。如果你忘了 return，Item 就会在这个管道里"断掉"，后面的管道永远收不到它。

在 settings.py 里开启管道

写完管道类之后，Scrapy 默认不会启用它。你必须在 settings.py 里找到 ITEM_PIPELINES 配置项，取消注释并注册你的管道：

# settings.py
ITEM_PIPELINES = {
    'myproject.pipelines.MovieFilePipeline': 300,
}

这里的数字 300 是优先级——数字越小，优先级越高，Item 越先交给它处理。一个项目里可以同时注册多个管道，靠这个数字控制顺序。

常见踩坑

  • yield 字典而非 Item：管道只认 Item 类型，字典会被静默丢弃，不报错但数据消失。
  • process_item 忘记 return：Item 在第一个管道就断了，后续管道全部失效。
  • 在 process_item 里建数据库连接：每次存一条数据都重新建连，爬虫跑得极慢。连接应该放在 open_spider 里。
  • settings.py 没开启管道：代码写对了但数据不落盘，90% 是忘记在 ITEM_PIPELINES 里注册。
