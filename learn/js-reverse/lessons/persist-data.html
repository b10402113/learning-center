持久化存储的两条路线

Scrapy 框架入门 · Step 4/4

Learning goal

能根据场景在「终端指令式」与「管道式」之间做选型判断，并写出把爬取结果落盘到 .csv 的完整流程。

Lesson

数据抓下来只是第一步，还得存起来。Scrapy 提供了两条落盘路线：一条是终端指令式，简单但局限；一条是管道式，编码流程多但能存文件也能存数据库。

路线一：终端指令式

最简单的方式：让 parse 方法把数据作为返回值 yield 出来，运行时用 -o 参数指定输出文件。

scrapy crawl baidu -o result.csv

优点：一行命令搞定，适合快速验证。

缺点：局限性强——只能存文本文件（.csv / .json / .jl），存不了数据库，而且数据必须封装在 parse 的返回值里。

路线二：管道式（推荐）

管道式是 Scrapy 推荐的持久化方案。它的核心思路是：Spider 产出 item → 管道接收 item → 管道负责存储。

管道式六步编码流程

  1. 解析数据：在 parse 里用 xpath 提取字段。
  2. 定义字段：在 items.py 里用 scrapy.Field() 声明字段。
  3. 封装 item：把提取的数据装进 item 对象。
  4. yield 提交：用 yield item 把 item 提交给管道。
  5. 管道处理：在 pipelines.py 里写 process_item 方法接收并存储。
  6. 开启管道：在 settings.py 里解除 ITEM_PIPELINES 注释。

items.py 定义字段

import scrapy

class MyprojectItem(scrapy.Item):
    title = scrapy.Field()
    link = scrapy.Field()

Spider 里 yield item

def parse(self, response):
    item = MyprojectItem()
    item['title'] = response.xpath('//title/text()').extract_first()
    item['link'] = response.url
    yield item

pipelines.py 接收并存储

class MyprojectPipeline:
    def open_spider(self, spider):
        self.f = open('result.csv', 'w')

    def process_item(self, item, spider):
        self.f.write(f"{item['title']},{item['link']}\n")
        return item

    def close_spider(self, spider):
        self.f.close()

注意：process_item 必须 return item，否则下一个管道就收不到数据了。

settings.py 开启管道

ITEM_PIPELINES = {
   'myproject.pipelines.MyprojectPipeline': 300,
}

数字 300 是优先级，数字越小优先级越高。多个管道时，item 会按优先级从小到大流转。

两条路线怎么选

场景推荐路线
快速验证、临时抓一把终端指令式
正式项目、要存数据库管道式
同一份数据要存多个载体管道式（多管道）
