webpack 加载器原理：自执行结构与调度函数

学习目标：亲手跑通 80 行教学 demo，理解 webpack 加载器的自执行结构、缓存对象、调度函数，以及数组下标与哈希 key 两种调度方式。

为什么 webpack 产物看起来像天书

你打开一个大型站点的 JS 文件，发现里面全是 MuMZ、W2Yj、zvER 这种短标记，函数调用全是 n("W2Yj")(data) 这种形式——原始变量名、函数名全被混淆了。这是 webpack 打包后的典型产物。

但无论怎么混淆，webpack 运行时必须保留一个核心机制：加载器（loader）+ 模块字典（mod） 的分离结构。加载器是薄壳，负责调度；mod 是厚肉，装实际业务逻辑。理解这个结构，你就能在任何 webpack 站点里还原出"哪个函数在哪"的地图。

从 80 行 demo 还原加载器骨架

教学 demo 用 80 行代码还原了 webpack 加载器的最小骨架，整体是一个立即执行函数（IIFE）：

!function(模块容器) {
  // 加载器实现
}(功能模块)

外层的 ! 是把函数转为函数表达式的写法之一，效果跟 (function(){...})() 一样——定义完立刻执行，把"功能模块"作为参数塞进去。

加载器内部的三件套

加载器内部维护三个关键东西：

组件角色长什么样
t缓存对象已执行模块的 exports 按 ID 存这里
n(r)调度函数传入模块 ID r，返回模块的 exports
e[r]模块字典所有模块的源代码，key 是模块 ID

调度函数 n(r) 的核心逻辑只有三步：

function n(r) {
  // 1. 缓存命中，直接返回
  if (t[r]) return t[r].exports;
  // 2. 未命中，建一个模块容器 {id, loaded, exports}
  var o = t[r] = {i: r, l: !1, exports: {}};
  // 3. 执行模块，把 this 指向 o，参数是 (模块, 模块.exports, 调度函数)
  e[r].call(o.exports, o, o.exports, n);
  o.l = !0;
  return o.exports;
}

关键在第三行：e[r].call(o.exports, o, o.exports, n)。这行代码的意思是——把第 r 个模块的源代码拿出来执行，执行时的 this 指向模块的 exports 对象，同时把模块自身、exports、调度函数传进去，让模块内部可以引用它们。

模块如何对外导出

模块内部想要对外暴露功能，标准写法是 this.exports = 值（或者 module.exports = 值，webpack 里两种都支持）。例如：

// 模块 "hello" 的源代码
function(e, module, n) {
  module.exports = function(name) {
    return "hello, " + name;
  };
}

当调度函数 n("hello") 执行完，t["hello"].exports 就变成了那个打招呼的函数。之后任何代码再调 n("hello")，直接从缓存拿，不会再执行一遍。

两种调度方式：数组下标 vs 哈希 key

webpack 模块字典的 key 有两种形态，对应两种调度方式：

形态模块 ID调用方式典型站点
数组下标数字：437window.loader(437)沃邮箱（老站）
哈希 key4 位混淆："W2Yj"window.loader("W2Yj")财联社、外贸电商平台

数组下标版本直观，但不利于 tree-shaking；哈希 key 版本是 webpack 5+ 的主流。两种只是 key 的形状不同，调度函数本身逻辑完全一致。

把调度器挂到 window.loader

加载器做完初始化后，会把调度函数暴露出来：

window.loader = n;

之后无论浏览器控制台还是 Node 环境，只要调 window.loader("模块ID")，就能拿到任意模块的 exports。这是本地复现加密函数的关键入口。

Node 环境怎么跑浏览器产物

教学 demo 里有一行兜底代码：

window = global;

这行是在 Node 环境里补浏览器全局对象——window 在浏览器里是顶级对象，Node 里没有，所以把 global 赋值给 window，让 window.loader = n 这行不会报错。真实站点的 mod 文件通常自己会在头部写 window = global，或者用 (window.webpackJsonp || [])

跑通 demo 的最小验收

跑通这两个版本后，你应该能回答这三个问题：

  • 调度函数怎么避免重复执行同一个模块？（查缓存 t[r]）
  • 模块内部怎么对外暴露功能？（this.exports = 值）
  • window.loader("模块ID") 和 window.loader(437) 区别是什么？（key 形状不同，机制一样）
