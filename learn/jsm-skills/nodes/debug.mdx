# /debug：根因除錯迴圈

## Learning goal

能跑 reproduce → localize → hypothesize → test → fix → verify 的根因迴圈，一次只測一個可否證假設、套最小修補並加回歸測試，且拒絕偷做功能與症狀補丁。

## Steps

1. [[learn/jsm-skills/nodes/debug/investigator-and-evidence-loop|除錯是證明，不是猜：角色與六步迴圈]] — 認得調查員角色、六步迴圈、叫用時機與它和 /loop 的分野
2. [[learn/jsm-skills/nodes/debug/reproduce-and-localize|先重現，再定位：把 bug 縮到最小表面]] — 抓住症狀、取得確定性重現、二分到最小失敗面（after step 1）
3. [[learn/jsm-skills/nodes/debug/one-falsifiable-hypothesis|一次只驗一個可否證的假設]] — 寫下單一根因假設，用最小實驗證實或推翻（after step 2）
4. [[learn/jsm-skills/nodes/debug/minimal-fix-and-regression|最小修補、回歸測試與同源兄弟]] — 對症下藥只改一處，重跑、鎖回歸、grep 同源（after step 3）
5. [[learn/jsm-skills/nodes/debug/delegation-and-report|交給子代理，並用根因收尾]] — 何時外包調查，以及先講根因的收尾報告（after steps 2、4）

## Lesson

`/debug` 不是「猜哪裡壞了、改到會動為止」，而是一場有紀律的調查。它把除錯拆成一個六步迴圈：先重現，再定位，提出一個可否證的假設，用最小的實驗去測它，證實之後才在最根處動刀，最後用回歸測試把修補鎖住。整條迴圈的核心規則是「一次只動一個變因」，因為只有這樣，每個結果才真的有意義。

這個節點分五步。先建立調查員的心態：證據優先於直覺，而且它平常自己動手，只有在你連重現都給不出來時才會反問你。接著走前三步的硬功夫：把症狀講精確、拿到確定性的重現、用二分法把失敗縮到最小表面。然後是最容易被跳過、也最關鍵的一環：一次只立一個可否證的假設，被推翻就丟棄重來，絕不憑一股直覺直接跳去修。再來講修補的紀律：最小、針對根因、不順手重構、不偷做功能，並用重現重跑、周邊測試、回歸測試與同源兄弟檢查把成果守住。最後看它什麼時候把整場追查外包給子代理，以及收尾報告為什麼要「先講根因與修補，而不是先講過程」。

走完這節，你應該能拿一個真的壞掉的行為，跑完這圈根因迴圈，並說清楚每一步在防哪一種偷懶：沒重現就修、一次改一堆、修症狀不修因、修完不鎖回歸。
