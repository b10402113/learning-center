# 把想法變成活著的計畫

## Learning goal

跑 `/scope` 產出 `docs/scope/`（plan / replan / add），選 delivery style 與 depth，並解釋為何 `index.md` 有時沒打勾。

## Steps

這條路徑先建立「`/scope` 到底是什麼、不碰什麼」，接著把產出物（scope 文件）攤開，再把「怎麼切、怎麼排序」的取捨講清楚，然後跑一次完整規劃，最後收在「文件是活的」：`replan`、`add`，以及為什麼有些框永遠不會立刻打勾。

1. [[learn/jsm-skills/nodes/scope/what-scope-does|/scope 是什麼：把點子變成粗的、活著的 WHAT]] — 職責、三種行為（plan / replan / add）與它不碰的四樣東西
2. [[learn/jsm-skills/nodes/scope/scope-document-shape|scope 文件的形狀與狀態生命週期]] — At a glance 表、feature section、五種狀態與「下一個未打勾的框」（接在第 1 步之後）
3. [[learn/jsm-skills/nodes/scope/choose-build-approach|選 delivery style：四種 build approach 與 foundations-first]] — Tracer Bullet / Skateboard / Facade / Journey 的判準與先後順序（接在第 1 步之後）
4. [[learn/jsm-skills/nodes/scope/run-a-plan-pass|跑一次 plan：三條路線、問題走訪與 workflow tier]] — greenfield / brownfield / monorepo、生成問題、切粗 feature、選 depth（接在第 2、3 步之後）
5. [[learn/jsm-skills/nodes/scope/living-scope-and-done|活著的文件：replan、add，以及為什麼有些框沒打勾]] — done 不等於 existing、Assumed 決策債、replan 對帳與 add 補 feature（接在第 4 步之後）

## Lesson

`/scope` 是整條 pipeline 的第一站，它只回答「要蓋什麼、什麼順序、多講究」，不回答「怎麼蓋」。它把一個點子變成一張粗的、行進式的清單，放進 `docs/scope/`，然後在每次功能出貨後回頭對帳。

這張清單之所以能一直有用，是因為它有兩個設計：一是每個事實只出現一次，二是它會長大。功能先以一行粗描述進場，等到決定被寫成 spec，才由 `/architect` 補上「built ready」的形狀與可勾選的里程碑。所以 scope 上的框不會一次被勾完，因為勾選的推進權分散在整條 pipeline 上。

五步走完之後，你應該能自己跑一次 `plan` 產出第一版 scope、看懂四個 build approach 的取捨、選定 workflow tier，並在功能出貨後用 `replan` 把文件對回真實狀態，而不是每次重寫一份新的。
