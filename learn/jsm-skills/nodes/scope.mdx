# /scope：從點子到計畫

## Learning goal

能用 `/scope` 把一句點子變成有序的 living plan，依情境選對 approach（tracer-bullet / skateboard / facade / journey）與 `plan` / `replan` / `add` 模式。

## Steps

1. [[learn/jsm-skills/nodes/scope/scope-artifact|scope 檔案：一份會長大的計畫]] — 認得 scope 的兩段式形狀與三套標記
2. [[learn/jsm-skills/nodes/scope/intent-and-plan-run|一句 /scope，三種意圖：plan 怎麼跑完一輪]] — 意圖推斷與 plan 七步 (after step 1)
3. [[learn/jsm-skills/nodes/scope/repo-routes|三種起手式：greenfield、brownfield、monorepo]] — 判斷 repo 形狀並決定第一步 (after step 2)
4. [[learn/jsm-skills/nodes/scope/build-approaches|四種切法：Tracer Bullet、Skateboard、Facade、Journey]] — 選一種切法，所有切片都照它 (after step 2)
5. [[learn/jsm-skills/nodes/scope/living-rhythm|專案活著之後：replan 與 add 的節奏]] — 出貨後對帳與低儀式加功能 (after steps 3–4)

## Lesson

`/scope` 是整條工作流的入口。它回答的是「要做什麼、先做什麼、這件事多需要流程、哪幾件得先做決定」；至於「怎麼做」，那是 `/architect` 與 `/develop` 的事。它把這些答案寫成一份放在 `docs/scope/` 的檔案，讓計畫在對話結束後還留著，也讓下一個階段知道你走到哪裡了。

這個節點拆成五步。先看懂 scope 檔案本身長什麼樣，包含 feature 的生命週期、status，以及那個決定「出貨前要跑幾關」的 workflow tier。接著看 `/scope` 怎麼從上下文推斷你要 plan、replan 還是 add，並把 plan 的七個步驟走完。再分頭深入兩個關鍵決定：你落在哪一種 repo（greenfield / brownfield / monorepo），以及你要用哪一種 build approach 切功能。最後回到日常節奏：功能出貨後怎麼 replan 對帳，中途冒出的單一功能怎麼 add 進去。

走完這節，你應該能在一句點子上真的跑一次 `/scope`，產出一份有序、可持續更新的計畫，而不是只記得指令名字。
