# 端到端實跑與覆盤

## Learning goal

能在自己的練習專案上完整跑一遍九階段（含 spec lifecycle 流轉與何時跳過），並覆盤 jsm-skills 與自己 SDD 流程的取捨。

## Steps

1. [[learn/jsm-skills/nodes/end-to-end-run/run-map|九階段排成一條線：一次完整跑的順序與起手式]] — 排出一次完整跑的順序，並依 repo 形狀選對第一鏟挖在哪
2. [[learn/jsm-skills/nodes/end-to-end-run/spec-lifecycle-thread|規格的一生：Proposed、In Progress、Accepted，還有 Assumed 與 Superseded]] — 說出規格在九階段之間怎麼流轉、誰接哪一棒 (after step 1)
3. [[learn/jsm-skills/nodes/end-to-end-run/depth-and-skips|這次要跑多深：Prototype 到 GA，以及何時跳過]] — 用四級深度決定這次要跑哪些階段 (after step 1)
4. [[learn/jsm-skills/nodes/end-to-end-run/retro-vs-your-sdd|覆盤：把 jsm-skills 對回你自己的 SDD]] — 逐環對照自己 SDD，談取捨 (after steps 2–3)

## Lesson

前面十二個節點把這部機器的零件一個一個拆開看過了：九階段的 DAG、三層知識載體與擁有權、四條設計慣例，然後是每個 skill 的操作規則。這個節點要做的，是把它們重新組回一台會動的機器，在你自己的練習專案上真的跑一次。

「端到端」的難處不在任何單一階段，而在階段之間的交接。同一份規格會經過好幾雙手：`/architect` 寫下它、`/develop` 推進它的狀態、`/sync` 把它的狀態對回 repo；同一個驗收條件會從一句需求，變成程式碼、變成 `verify` 的檢查、再變成 `/test` 的斷言。這些交接如果沒有一條清楚的線串著，每一步看起來都對，整個流程卻會在縫隙裡漏東西。

這個節點走四步。先看整條線的順序，以及三種 repo 形狀各自的起手式；再深入那條串起全程的線，也就是規格的一生；接著學怎麼用四級 workflow depth 決定這次要跑多深、哪裡可以跳過；最後回過頭，把你自己的 SDD 流程拿來逐環對照，講清楚哪些做法值得搬走。走完之後，你手上應該有一份屬於自己的「怎麼跑、何時停、缺什麼」的判斷。
