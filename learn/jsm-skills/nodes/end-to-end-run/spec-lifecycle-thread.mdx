# 規格的一生：Proposed、In Progress、Accepted，還有 Assumed 與 Superseded

<LearningGoal>
能沿著一次實跑說出每階段的輸入輸出與誰寫誰讀，尤其規格從 Proposed 走到 Accepted 的每一棒，以及 Assumed 與 Superseded 這兩個支線狀態何時出現、由誰清掉。
</LearningGoal>

## Lesson

一份規格由 `/architect` 建立並出生為 `Proposed`（記錄已上線的東西則直接 `Accepted`），`/develop` 只讀建置需要的段落、只推狀態那一行（`Proposed → In Progress → Accepted`），`/architect` 以 `Superseded` 替換被推翻的決定，`/sync` 只 flag 過時的；若開發選擇先建再說，`/develop` 寫下唯一的 `Assumed` 小規格、欠 `/architect` 一次 ratification，而這個標記永遠不擋 done；底下還有一條驗收條件線把決定、程式碼、證明與測試串成直線。
