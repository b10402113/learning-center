# 情境→skill 導航與 git/commit 節奏

## Learning goal

卡住時能從狀況判斷該跑哪個 skill；知道哪些階段是天然 commit 點、skill 何時碰 git、何時不碰。

## Steps

1. [[learn/jsm-skills/nodes/orchestration-and-git/skills-and-feature-loop|九個 skill 與 canonical pipeline：一個階段一個 skill]] — 先建立「有哪些 skill、各自負責哪一階段」的地圖
2. [[learn/jsm-skills/nodes/orchestration-and-git/situation-to-skill-map|卡住時的地圖：從處境判斷該跑哪個 skill]] — 把「我現在的處境」對應到下一步該跑哪個 skill（after step 1）
3. [[learn/jsm-skills/nodes/orchestration-and-git/git-integration-and-branch|skill 何時碰 git：integration 開關、分支與動手前檢查]] — 判斷該不該碰 git，並在動工前完成分支與新鮮度檢查（after step 2）
4. [[learn/jsm-skills/nodes/orchestration-and-git/commit-rhythm|commit 節奏：天然提交點、訊息格式與 push 的歸屬]] — 認出提交點、用對模式與訊息格式，並知道 push/PR 不歸開發階段（after step 3）

## Lesson

這節課解決的是兩種很具體的卡住感。第一種是「我知道這有很多 skill，但現在到底該跑哪一個」——要解這個，得先有一張地圖：九個 skill 各自是一條傳送帶上的哪一站，以及只跑這次改動需要的那些站。有了地圖，才能把「我現在的處境」翻譯成「下一步的指令」。

第二種是「git 到底誰在動」。這套流程刻意把 git 拆成兩層：一層是讀取與檢查（新鮮度、分支、協作），一層是寫入歷史（commit）。前者是動手前的安全檢查，後者是跟在驗證節點上的節奏。四步走完之後，你應該能在卡住時立刻說出下一步，也知道什麼時候會出現一個自然的提交點、誰負責 push。
