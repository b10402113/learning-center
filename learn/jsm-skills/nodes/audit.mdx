# 寫 AGENTS.md context 檔

## Learning goal

跑 `/audit`（greenfield / brownfield / area / gap-fill）產出巢狀 AGENTS.md + CLAUDE.md pointer，並知道 root 為何要精簡。

## Steps

這條路徑先講「`/audit` 存在要解什麼問題、寫出來的檔長什麼樣」，再講「這次該跑哪個 phase」，然後分成兩個實作面：一個是 greenfield 的 setup，一個是既有 repo 的掃描與補洞。照順序讀，每一步都接在前一步上。

1. [[learn/jsm-skills/nodes/audit/what-audit-does|/audit 是什麼：把 durable context 寫進 AGENTS.md]] — 職責、三種執行形狀、canonical 檔規則，以及它不碰的三種檔
2. [[learn/jsm-skills/nodes/audit/agents-md-shape-and-root-brevity|AGENTS.md 的形狀：root 精簡、巢狀、兩個鏡像欄位]] — root 與巢狀模板、60 行上限，以及 `## Stack` / `## Build approach` 的來源與衝突規則（接在第 1 步之後）
3. [[learn/jsm-skills/nodes/audit/preflight-routing|pre-flight：這五個訊號決定你跑哪個 phase]] — 五個訊號、有順序的決策表，與 greenfield / brownfield 的判別條件（接在第 1 步之後）
4. [[learn/jsm-skills/nodes/audit/run-greenfield-setup|跑 greenfield setup：問清標準與工具，寫出 root AGENTS.md]] — Phase 1 的 decision panel、鏡像欄位種法、工具清單與 `git init`（接在第 2、3 步之後）
5. [[learn/jsm-skills/nodes/audit/audit-existing-repo|稽核既有 repo：whole-repo / area / gap-fill 的掃描與補洞]] — Phase 2 / 3 / 4 的掃描、巢狀文件判斷，與 root gap / proposed additions / contradiction 的處理（接在第 2、3 步之後）

## Lesson

`/audit` 是整條 pipeline 的 context 起點。它把「這個專案怎麼運作」寫成一組 `AGENTS.md` 檔，讓後面每個 skill 和每個 AI 工具都讀得到同一份事實，而不是各自在對話裡猜。它寫的只有 context 檔：不寫 spec、不寫計畫、也不碰 scope。

這組檔有一個核心設計：`AGENTS.md` 是唯一內容所在，`CLAUDE.md` 只是一行指標，匯入旁邊的 `AGENTS.md`。內容絕不重複，所以修一處就等於修全部。另一個設計是分層：root 只放全域、跨專案的事實並壓在約 60 行內，真正屬於某個 area 的慣例放到那裡的巢狀文件，讓它載入時剛好只在編輯那個 area 時出現。

`/audit` 跑起來有四個 phase：greenfield 的 setup、whole-repo 的整庫掃描、單一 area 的掃描，以及 root 已存在時的 gap-fill。走完五步之後，你應該能看著一個 repo 的訊號判斷該跑哪個 phase，產出 root 與巢狀文件加指標，並且知道 root 為什麼要精簡、遇到既有內容什麼時候只能提議不能改寫。
