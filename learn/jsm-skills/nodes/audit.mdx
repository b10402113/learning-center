# /audit：建立 AGENTS.md 與風格底線

## Learning goal

能用 `/audit` 從零或既有 repo 建立並維護 `AGENTS.md`，依 pre-flight 訊號選對 phase（greenfield / whole-repo / area / gap-fill），並選定一套 coding-style preset 當作 Rules。

## Steps

1. [[learn/jsm-skills/nodes/audit/audit-role-and-context-files|/audit 在做什麼：AGENTS.md 是唯一正本]] — 認清 `/audit` 的職責、兩層 context 檔的角色，以及它不碰哪些地盤。
2. [[learn/jsm-skills/nodes/audit/preflight-signals-and-routing|pre-flight 訊號與 phase 路由]] — 從線上訊號判斷該走哪個 phase，理解為什麼工作流設定訊號蓋過原始碼數量（after step 1）。
3. [[learn/jsm-skills/nodes/audit/greenfield-setup-and-pattern-presets|Greenfield：決策面板與四種風格 preset]] — 跑 Phase 1 的面板、選 preset 落成 `## Rules`、處理 `## Git` 與 mirrored fields（after step 2）。
4. [[learn/jsm-skills/nodes/audit/scan-phases-and-nested-docs|掃描既有 repo：whole-repo 與 area 模式]] — 跑 Phase 2/3 的掃描、判斷 nested doc、用 scout 分攤閱讀（after step 2）。
5. [[learn/jsm-skills/nodes/audit/gapfill-and-curated-content-safety|Gap-fill 與「絕不覆寫」的安全寫入準則]] — 跑 Phase 4，分辨缺漏與矛盾，守住三道保護既有內容的規則（after steps 3–4）。

## Lesson

`/audit` 是整條工作流最前面的一站：它不寫功能、不寫規格，只負責把「這個專案是什麼、怎麼寫才對」固定下來。它產出的 `AGENTS.md` 是後續每一個 skill 與 AI 工具都會讀的共用說明書，等於先替整條流程鋪好軌道。

這份說明書要放在對的地方。`AGENTS.md` 是唯一正本，裡面裝的是可以被跨工具重複讀取的專案知識；`CLAUDE.md` 只是一行指標，把內容轉接給 Claude Code，本身不重複任何知識。`/audit` 的產出因此分成 root 與 nested 兩層：root 放全局事實且保持精簡，nested 只留給真的有特殊慣例或坑的區域。

工作流給 `/audit` 四種模式，實際走哪一種，靠 pre-flight 訊號判斷。Greenfield（Phase 1）面對還沒有功能碼的新專案，會用決策面板問出一套 coding-style preset 當作 `## Rules`；whole-repo（Phase 2）掃描有碼但沒說明的既有專案；area（Phase 3）只針對指定路徑補一份 nested 文件；gap-fill（Phase 4）則在 root 已存在時，保守地補上真正缺的東西。

四種模式共享同一條底線：既有內容不覆寫。`/audit` 只在檔案缺失時建立，遇到已存在的檔案就改成提案，遇到文件與程式碼互相矛盾就回報讓人決定，並在自動生成的文件尾端留下 provenance 印章，讓後續執行能分辨哪些是機器草稿、哪些是人手校訂過的內容。
