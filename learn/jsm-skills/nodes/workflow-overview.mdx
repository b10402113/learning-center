# 工程工作流全貌

## Learning goal

用一句話講出九個 skill 各自的職責與整條 pipeline，並為專案選一個 depth（Prototype / Alpha / Beta / GA）。

## Steps

1. [[learn/jsm-skills/nodes/workflow-overview/the-nine-skills|九個 skill 與各自的職責]] — 逐一認領九個 skill，並把它們分成「產出」與「確認」兩類
2. [[learn/jsm-skills/nodes/workflow-overview/the-pipeline|整條 pipeline 與依專案型態選入口]] — 背下 canonical pipeline，並依 greenfield / brownfield / 單一改動 / monorepo 決定入口（after step 1）
3. [[learn/jsm-skills/nodes/workflow-overview/pick-a-depth|替專案選一個 depth]] — 在 Prototype / Alpha / Beta / GA 之間取捨，並理解它只是預設（after step 2）
4. [[learn/jsm-skills/nodes/workflow-overview/walkthrough-signin-todo|端到端實跑：登入＋待辦 app]] — 跟著一個 app 走完十個階段，把規則對到實際動作（after steps 2–3）

## Lesson

這套工作流的核心主張只有一句：一個改動從模糊想法走到「已出貨、已驗證、已寫成文件」，中間每一步都有一個 skill 負責，而所有重要的狀態都寫進 repo 裡的檔案，不留在對話裡。九個 skill 就像工廠裡的九個工作站——不是每個零件都要過全部九站，但每個工作站只做一件事，而且做得可重複。

前三步先建立地圖：認得九個工作站各自負責什麼，知道整條線的順序與不同專案的入口，最後替自己的專案選一個檢查深度。第四步則把整張地圖套進一個具體的 app，讓你看到抽象規則在真實情境裡長什麼樣子。走完這節，你應該能在任何時刻回答兩個問題：現在該跑哪個 skill，以及這個階段會產出或改動哪個檔案。
