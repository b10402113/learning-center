# 分階段設計對話：閘門式訪談

<LearningGoal>
照著 scope validation、framing、stages (a)–(f) 的順序跑完一場設計訪談，知道每一階段要問什麼、什麼時候該 show-and-confirm。
</LearningGoal>

## Lesson

設計訪談的順序是硬閘門：先完整讀流程檔，再跑 Scope validation（Check B 既成事實、Check A 產品願景）、用推斷做 Framing、列出承重維度，然後依序走 stages (a) 需求到 (f) 邊界（資料模型要秀出來確認、新工具要過同意閘門），最後用填滿度閘門確認沒有維度被默默跳過。
