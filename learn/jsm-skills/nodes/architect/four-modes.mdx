# /architect 的四種模式與四種操作

<LearningGoal>
看到一個情境，能判斷該用 FEATURE、ARCHITECTURE、ENHANCEMENT 還是 CROSS-CUTTING，並說出這次是 create、update、supersede 還是 ratify。
</LearningGoal>

## Lesson

`/architect` 用四種模式（FEATURE 設計新功能、ARCHITECTURE 選技術棧、ENHANCEMENT 改造既有系統、CROSS-CUTTING 統一全 repo 標準）擺出設計姿態，再用四種操作（create、update、supersede、ratify）決定這份決策怎麼落進 spec；模式決定它讀不讀程式碼與最後寫哪一段專屬規格，操作則由既有 spec 的重疊情況決定。
