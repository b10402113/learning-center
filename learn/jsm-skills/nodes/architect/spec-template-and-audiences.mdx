<LearningGoal>
能認出 spec 的段落順序，分辨 build spec 與 decision record 兩個受眾各讀哪些段落，並解釋 AC 主線、Options 必帶 con、decision-only spec 這幾條寫作規則。
</LearningGoal>

## Lesson

規格有固定段落順序且同時服務兩個受眾：Requirements、Decision、設計段、Build plan、Consequences 是給 `/develop` 讀的建置規格，Context、Options considered、Rationale、References 是給人讀的決定記錄；AC 是脊椎且 build task 與測試情境雙向對齊，寫作上每件事只說一次、每個選項都要有真 con，決策型規格不寫 Build plan。
