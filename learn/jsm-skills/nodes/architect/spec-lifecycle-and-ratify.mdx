<LearningGoal>
能用 spec lifecycle 管理規格：說出 `Proposed` → `In Progress` → `Accepted` 各由誰推進、`Assumed` 為什麼要由 `/architect` ratify，並走完寫完之後的自我檢查、跨模型 cross-check、accept 確認與 scope linking。
</LearningGoal>

## Lesson

規格有生命週期：連著 scope 功能的由 `/develop` 從 `Proposed` 推到 `In Progress` 再到 `Accepted`，獨立決定規格在批准時直接 `Accepted`，描述既成現實的一出生就 `Accepted`，而 `Assumed` 只能由 `/architect` ratify 清除；規格寫完後跑自我檢查、依流程等級推薦的跨模型 cross-check、accept 迴圈拍板，再回 scope 用 `(spec)` 後綴定位決定格並放上二到五個里程碑。
