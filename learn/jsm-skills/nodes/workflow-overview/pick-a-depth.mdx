# 替專案選一個 depth

<LearningGoal>
能依專案的風險與交付情境，在 Prototype、Alpha、Beta、GA 四個 depth 之間做選擇，並解釋為什麼它只是預設值而不是鎖死的軌道。
</LearningGoal>

## Lesson

workflow depth 只決定 `/develop` 之後的檢查尾巴（Prototype 只靠自檢、Alpha 加 `/check verify`、Beta 再加 `/test`、GA 再加不同模型的 review 與 `/document`），它是可被單一 feature 覆寫的預設值且從不扣住 done，唯一跨越所有等級的底線是承重決策必須寫進檔案。
