<LearningGoal>
能套用 /test 的寫作紀律：只改測試不改原碼、延伸既有測試不重寫、依 coverage 優先序補齊 happy path 到 a11y，並讓每個測試可追到規格的驗收條件。
</LearningGoal>

## Lesson

寫測試守住四條底線（絕不改原碼、既有測試只延伸、設定檔最小且只附加、安全敏感碼預設補安全案例），照 happy path、邊界、錯誤、狀態轉移、無障礙的順序覆蓋，套用「名稱成句、一測試一概念、arrange-act-assert、測公開介面、只在系統邊界 mock、保持確定性」等專家規則；有治理規格時每個可自動化的驗收條件都鎖成一條測試並標上 `AC-N`，無法自動化的誠實記到 `NOT_COVERED` 交給 `/check verify`。
