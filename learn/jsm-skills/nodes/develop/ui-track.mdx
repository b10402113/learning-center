<LearningGoal>
能說出 UI 的完成標準與失格清單，選對四條設計來源，並照「設計先行、整合其次」的兩趟走法與實作階段做出合規的介面。
</LearningGoal>

## Lesson

UI 軌的完成標準很硬：每個頁面都要是完整、專業的產品版面，並有六條失格清單逐條要過。走法固定兩趟，先大膽設計整個版面，再整合進 codebase 的樣式函式庫、真實 token、語意 HTML、無障礙與響應式，報告前先自己審一遍、能渲染就渲染。設計來源有四條，依規格記錄的選一條：Figma MCP、貼上的圖、既有設計系統、從零生成；什麼都沒有時，先建立並驗證設計系統再蓋。動手前先判斷是元件還是畫面，並偵測平台既有的框架、樣式、導航、亮暗與圖示系統，照它的慣例做；實作收斂到 Phase 0 到 6，無障礙貫穿其中，並有可量測的門檻（一般文字 4.5:1、大字與邊界 3:1、觸控目標 44×44、focus 3:1），token 缺了就標 TODO 而不是硬編。
