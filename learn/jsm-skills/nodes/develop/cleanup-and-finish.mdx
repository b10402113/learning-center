<LearningGoal>
能在建置落地後刪淨被取代的舊碼並證明無人引用，外科手術式更新 scope 與 spec 狀態，產生 verify 步驟，並照 git 政策分支出與提交。
</LearningGoal>

## Lesson

收尾有兩個最容易漏的動作。第一，被取代的舊碼要刪乾淨並證明無人引用：刪掉被取代的函式、不可達分支、孤立檔案與懸空 import，搜尋每個被移除符號確認沒有殘留呼叫者，並在舊碼不在的情況下讓型別檢查、建置、lint 通過；單站的新碼綠了就刪，多站等全綠那一趟再刪，唯一例外是規格明講的過渡期。第二，只標真的落地的事：原子任務勾在規格、里程碑勾在 scope、只動那個 scope 檔，並遵守收尾閘門回報勾了什麼；done 是工程師的決定，Assumed 規格不擋 done，標 done 時把治理規格從 `In Progress` 鏡射成 `Accepted` 且動手前再讀一次。每次都要從 AC 與 Value sourcing 表推出綁著 AC 的 verify 步驟，並問要存進 `verify.md` 還是只放摘要，絕不自動存。git 只在 integration 開啟時作用：開工前先開功能分支，里程碑落地照設定提交一行 Conventional Commit 加 `Co-Authored-By`，push 與 PR 永遠先確認且屬於 `/document`。
