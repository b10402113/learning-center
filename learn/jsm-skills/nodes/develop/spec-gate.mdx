<LearningGoal>
能跑 /develop 的 Step 0 規格閘門：用 input coverage 測試判斷有沒有決策欠著，分清 load bearing 與 local detail，並在需要時選對三條出路。
</LearningGoal>

## Lesson

`/develop` 只實作決策，不製造決策。Step 0 用機械化的 input coverage 測試判斷有沒有決策欠著：列出每個必須產生或顯示的值，檢查規格有沒有指名它的來源，沒指名就是欠著。承重的定義是「決定了某個值的來源，或決定了驗收條件約束的行為」，而不是看它表面大小；純實作才真的可以直接做。決策欠著時，面板推薦先交給 `/architect`，另外兩條是「判斷不必要」與「先寫一份 Assumed spec 再建」；Assumed spec 狀態固定在 Assumed、不擋 done、只有 `/architect` 能清。開工前還會查落後、未提交與隊友是否在建，三者都是警告而非硬擋。
