# /document：把變更寫成人話

## Learning goal

能從真 commits 與 diff 寫出 PR 描述、changelog、release note 與 blameless postmortem，選對文件型別與受眾，且不編造、不漏密。

## Steps

1. [[learn/jsm-skills/nodes/document/four-types-and-audiences|四種文件，四種讀者]] — 認清四種文件的來源、受眾與產出位置，以及 `/document` 的角色與型別挑選。
2. [[learn/jsm-skills/nodes/document/gather-the-record|從真 commits 與 diff 蒐集素材]] — 用 git 取變更集與規格依據，跑完 PR 三項檢查，處理 NO_TAGS / PR_EXISTS / postmortem 缺料（after step 1）。
3. [[learn/jsm-skills/nodes/document/honesty-and-safety-rules|四條不准破的底線]] — 忠於 diff、不編造、不漏密、不重複，以及無料可寫時怎麼收尾（after step 2）。
4. [[learn/jsm-skills/nodes/document/write-for-reviewers-and-developers|寫給看碼的人：PR 描述與 changelog]] — 套 PR 與 changelog 樣板，分眾措辭並守住 idempotent（after step 3）。
5. [[learn/jsm-skills/nodes/document/write-for-users-and-team|寫給不看碼的人：release note 與 postmortem]] — 把變更翻成使用者語言，並用 blameless 樣板寫事故報告（after step 3）。

## Lesson

`/document` 是整條工作流裡唯一「只寫文字、不碰程式」的階段，但它不是作文課。它回答的問題很具體：這個改動已經在 commits 與 diff 裡真實發生了，要怎麼把它講給四種不同的讀者聽：審查者、使用這套程式的開發者、終端使用者，以及一起處理事故的團隊。每一種讀者要的東西不一樣，所以要選對型別、說對話，還要寫進對的地方。

它最硬的一條紀律是「從紀錄寫，不從想像寫」。PR 與 changelog 的每一句都要能指回 diff；postmortem 的時間軸與根因只能來自工程師給的事實；規格裡沒寫的「為什麼」，不准替它編一個。這也正是這個階段失敗起來最貴的地方：一份編造出來的 release note 會讓使用者期待一個不存在的功能，一份靠猜寫成的 postmortem 會讓同一個事故再發生一次。

五步走完，你會先建立「四種文件對四種讀者」的地圖，再學會用 git 把素材撈出來、跑完 PR 需要的環境檢查，接著掌握四條不准破的底線，最後分頭練兩種寫法：給看碼的人（PR、changelog），以及給不看碼的人（release note、postmortem）。走完之後，你要能在一個真的分支上跑一次 `/document`，產出一份可以貼上、也可以被信任的文件。
