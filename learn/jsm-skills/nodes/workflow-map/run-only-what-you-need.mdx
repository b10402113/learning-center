# 只跑該跑的：四個深度與「建議不是閘門」

<LearningGoal>
能依情境決定要跑哪些階段、跳過哪些，說出 Prototype、Alpha、Beta、GA 四個深度各跑什麼，並分辨「建議的檢查尾巴」與「唯一硬性要求：重大決策要寫下來」。
</LearningGoal>

## Lesson

四個深度只是建議的檢查尾巴：Prototype 只跑 `develop` 自檢，Alpha 加 `check verify`，Beta 再加 `test`，GA 再加 `check review` 與 `document`；`done` 永遠由你宣告、跳過的階段會被誠實記錄，而調低深度並沒有關掉決策閘門，需要決策的功能仍會導向 `architect`。整套流程唯一的要求，是讓重大決策留下書面紀錄；缺決策時 `develop` 會用一紙 `Assumed` spec 把假設記下來，而不是默默替你做決定。
