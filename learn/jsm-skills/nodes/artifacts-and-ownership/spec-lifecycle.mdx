# 一份 spec 的一生

<LearningGoal>
能畫出一份 spec 的完整生命（Proposed → In Progress → Accepted，外加 Assumed 與 Superseded），並說清 Assumed 為什麼需要 ratification。
</LearningGoal>

## Lesson

一份 spec 由 architect 出生為 Proposed、由 develop 只推進狀態列到 Accepted、被 architect 以 Superseded 取代、由 sync 標記過期，而 Assumed 草稿則永遠欠一次 architect 的 ratification。
