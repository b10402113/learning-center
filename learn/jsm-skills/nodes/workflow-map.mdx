# 工作流總覽

## Learning goal

能畫出九階段的 DAG，說清每階段的輸入/輸出、何時該用與何時可跳過，並對照自己的 SDD 七階段說出差異。

## Steps

1. [[learn/jsm-skills/nodes/workflow-map/nine-stage-dag|九階段地圖]] — 每一階段回答什麼、吃什麼、留下哪份檔案，外加 debug 與裸 /scope 兩條旁路
2. [[learn/jsm-skills/nodes/workflow-map/run-only-what-you-need|只跑該跑的]] — 四個 workflow depth 各跑什麼，以及「建議不是閘門」的真正含義 (after step 1)
3. [[learn/jsm-skills/nodes/workflow-map/where-you-start|從哪裡起跑]] — greenfield / brownfield / monorepo 三種入口與 debug 迴圈 (after step 1)
4. [[learn/jsm-skills/nodes/workflow-map/compare-with-your-sdd|對照你的 SDD]] — decision gate、驗證分工、檔案即狀態三個關鍵差異 (after steps 1–3)

## Lesson

很多人第一次看到這套 jsm-skills，會把它讀成「九個必跑的關卡」，好像每次動工都要從 `/scope` 一路簽核到 `/sync`。剛好相反：它的第一句話就是「只跑這個改動需要的階段，順序自己配」。所以這張圖的骨架不是九個依序通過的檢查點，而是「檔案在階段之間流動」：每個階段吃上一階段的產出，做它唯一擅長的那件事，再把結果寫成一份留在 repo 裡的檔案，下一個階段再從那份檔案接手。

因此這一節課分四步把這張圖鋪開。先看清楚九個階段各回答什麼問題、吃什麼、留下什麼，以及 `debug` 和裸 `/scope` 這兩條可以隨時切進去的旁路；接著學會怎麼裁剪這張圖，也就是四個 workflow depth 與「建議不是閘門」的規則；再處理一個實務問題：面對全新的專案、既有的 codebase、或一個 monorepo，該從哪個階段進；最後把它對回你本來就在跑的 SDD 七階段，找出三個不同、也值得偷的地方。

走完這四步，你手上會有一張隨時畫得出來的地圖：知道現在卡在哪一階段、下一階段該拿到什麼、這一步到底是必要的還是可以跳過。有了這張地圖，後面 Tier 2 逐階段學每個 skill 的操作細節時，才不會見樹不見林。
