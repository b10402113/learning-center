問什麼、推什麼，哪些事自己查

Step 3/5 · 把決策寫成 spec

先決定：這題該問誰？

上一節我們釐清了 spec 的狀態與擁有權，也知道 /architect 會透過訪談把決策問出來。接下來有個更細、也更容易搞錯的判斷：每一個問題，究竟該直接問工程師，還是 agent 自己查、自己提出建議？

問得太少，agent 可能偷偷替你決定。例如它自行挑了一套認證方案，卻沒說明原因，等你發現時，方向早就定了。問得太多也不好，像是把「你們用 React 還是 Vue？」丟回來，但答案明明已經在 prompt 或程式碼裡。

這一節用三個抽屜整理「答案到底住在哪裡」：INFER、ASK、RECOMMEND。分類正確，才能把提問預算花在真正需要你決定的地方。

三個抽屜：先比較答案的來源

分類答案在哪裡該怎麼做典型例子
INFERprompt 或 codebase 已經透露自己查、自己推斷，絕不反問這是功能還是架構、使用什麼技術堆疊、平台是網頁或手機、已經選定的 provider
ASK只有工程師本人知道直接問，而且一題一題問需求、偏好、業務規則、合規範圍、頁面要放哪些內容
RECOMMEND專業判斷可以收斂提出首選、說明一句理由，再給備選，讓對方推翻哪個 provider、哪套 library、哪種 pattern 最合適

這裡分的是答案的來源，不是題目難不難：看得到的資訊屬於 INFER；只有工程師知道的資訊屬於 ASK；可以靠專業判斷收斂的問題則屬於 RECOMMEND。

三個判別問句：逐題確認答案住哪裡

遇到設計問題時，依序問自己這三句：

  1. 「這件事在 prompt 或程式碼裡看得到嗎？」看得到就是 INFER。先自己查，不要把已知資訊再丟回工程師。
  2. 「這件事只有工程師本人知道嗎？」如果是，就是 ASK。需求、偏好、業務規則與合規範圍，不能靠猜。
  3. 「這件事有客觀的專家答案嗎？」如果有，就是 RECOMMEND。例如哪個套件更適合現有技術堆疊，應該由 agent 先收斂成建議。

順序不能亂。第一句還沒問，就直接問工程師，容易把「你們用什麼框架」這種查得到的問題也問出去。反過來，跳過第二句而自行腦補業務規則，則可能寫出一份看似完整、實際方向錯掉的 spec。

RECOMMEND：有立場，但不越權

RECOMMEND 最容易失手，因為它同時要求 agent 提供專業判斷，又不能替工程師做最後決定。正確格式只有三個元素：

首選＋一句理由＋備選。例如：「建議使用專案既有的 BaaS 認證，理由是不用再導入新供應商，也能直接對接現有使用者資料；備選是自架一套 auth library。」工程師可以接受，也可以推翻，但一定要清楚知道 agent 建議什麼，以及為什麼這樣建議。

重點是角色分工：工程師是決策者，AI 是顧問。好的顧問不會列出五個選項後說「你自己選」，那只是把思考工作退回去；也不會悄悄選好一個方案，讓你事後才發現。它應該先把選項收斂成一個有理由的建議，再把最後的決定權留給工程師。

反例：規則什麼時候會翻轉

該 INFER，卻拿去 ASK。例如詢問「這個功能要做成網頁還是 App」，但專案的 AGENTS.md 早已寫明是 Web 產品。會這樣問，通常表示 agent 還沒讀資料就開始提問，白白浪費雙方時間。

該 ASK，卻自行 INFER。例如自行假設「訂單超過 30 天就不能退款」。這是業務規則，各家情況不同，不能從技術資料推導。這類錯誤最危險，因為不一定會報錯，卻會讓系統悄悄做錯決定。

該 RECOMMEND，卻丟出中立選單。列出四個供應商，卻不標示首選，等於把本該由專業收斂的工作原封不動丟回工程師。RECOMMEND 必須有且只有一個推薦選項。

該 RECOMMEND，卻默默決定。agent 自己挑一個方案直接往下走，工程師直到讀 spec 才發現方向已被決定。這時才改，成本通常已經提高。

把整份成品包成一個「接受或修改」面板。例如一次端出完整資料模型、整套技術堆疊或全部驗收條件，只讓工程師選擇接受或修改。這會把幾十個獨立決定綁成一顆球，工程師無法只針對其中一項表達意見。/architect 的原則是：每個真正的選擇都要有自己的問題；完整成品則留到最後的 spec 審查，再整份呈現。

當場可用的決策規則

面對任何設計問題，依序檢查：prompt 或程式碼看得到嗎？是 INFER，自己查，不要問；只有工程師知道嗎？是 ASK，直接問；有客觀的專家答案嗎？是 RECOMMEND，給首選、理由與備選。記住：RECOMMEND 不是中立選單，也不是無聲決定；完整成品也不該被包成單一的接受或修改面板。

這套分類讓每個問題都落到正確的人手上。接下來把它放進實際流程：看 /architect 如何用「一維一題、答完才往下」的分階段設計對話，在正確的時間打開正確的抽屜。
