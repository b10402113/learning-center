檔案才是記憶：四種知識載體

Step 1/5 · 知識載體與擁有權

學習目標

能說出為什麼這套流程把工作狀態放進檔案而不是聊天，並分辨四種工作載體（AGENTS.md、scope、specs、design.md）各自裝什麼、放在哪裡。

前言：昨天決定的事，今天沒人記得

先回想一個你一定遇過的畫面。昨天下午你花了四十分鐘跟 AI 討論，最後敲定資料庫要用哪一套、API 要長什麼樣子、錯誤處理要回哪些欄位。今天早上你開了一個全新的對話，它劈頭就問你：「請問這個專案要用什麼資料庫？」你把同一段話又講了一遍。如果隊友中途 pull 了你的 branch，他看到的是程式碼，看不到那四十分鐘裡做過的任何判斷。

問題出在：那些知識從來沒有真的被「存起來」，它們只是暫時活在一個對話裡。對話一結束、session 一清掉、或換一個人接手，知識就煙消雲散。這套工作流的第一個設計決定，就是把這些東西全部寫進 repo 裡的檔案。這一節要看懂它用了哪四種檔案、每一種各裝什麼。

核心想法：把狀態從對話搬進 repo

這套流程的一切都建立在一個前提上：工作流知道的每件事，都寫在專案裡的檔案。對話可以結束，session 可以清掉，隊友可以 pull 分支，而知識還在，因為它從頭到尾就沒有被關在對話裡。

這件事有兩個直接的好處。第一是跨 session：任何交接點你都可以停下來、清掉對話、之後再撿回來，什麼都不會掉。第二是跨人：因為狀態在檔案裡，整支團隊看到的是同一份當前的認知，而不是某個人腦中或某個聊天視窗裡的版本。

四種載體，四種工作

這套流程用四種檔案來承載知識。它們各管一件事，彼此不重疊，不是同一種東西換名字。

一、AGENTS.md：專案怎麼運作

第一種是情境檔（context files），檔名固定叫 AGENTS.md。它描述你的專案實際上怎麼運作：用什麼技術棧、有哪些指令、遵守什麼慣例。它寫成任何 coding agent 都讀得懂的純文字。

它有兩個關鍵設計。第一個是可以巢狀。專案根目錄放一份管全部的通則，特定資料夾裡可以再放一份管那個區域的規則。比方說一個專案可以同時有根目錄的 AGENTS.md，以及 src/payments/AGENTS.md，後者只記錄付款程式碼才遵守的規則。當某個 skill 在處理付款程式碼時，它讀「離它最近的那一份」，所以同時看到全專案規則與這個區域的規則。

第二個設計是單一真實來源。如果你用 Claude Code，專案裡還有一個很小的 CLAUDE.md，它什麼都不做，只是指向 AGENTS.md。這樣一來內容只有一份，不會出現兩份各自漂移的副本。AGENTS.md 由 audit 建立，其他每個 skill 都讀它，sync 負責讓它跟上程式碼的變化。任何 skill 都不會在你已經寫明慣例的情況下，還自己去猜你的慣例。

二、scope：要做什麼、什麼順序

第二種是範疇（scope），放在 docs/scope/。它是「要做什麼、按什麼順序做」的粗粒度計畫，由 scope 建立。

它的生命週期也值得記住：develop 在功能被建出來時推進它，把某個功能標成進行中、勾掉里程碑，但它不會自己把一個功能標成全做完，因為「建好了」和「驗證過了」是兩回事。而一個不帶參數的 scope，以及合併前的 sync，會把它重新對回程式碼現在的樣子。

三、specs：每一個真實決定的紀錄

第三種是規格（specs），放在 docs/specs/。一份 spec 是「一個真實決定」的書面紀錄，同時也是 build 必須遵循的合約。這個檔案類型最多人問，它的一生會在下一節完整展開；這裡先記住它的定位：把決定變成一份可被讀取、可被追蹤的檔案，而不是留在某個人的記憶裡。它由 architect 建立。

四、design.md：介面長什麼樣

第四種是設計系統（design system），主要是一份 design.md。它裝的是使用者介面的美術方向：整體性格，以及頁面該怎麼被組起來的規則。

這裡有一個很刻意的分家：確切的顏色與尺寸這些數值，活在專案自己的 CSS 裡，design.md 只是指向它們。所以任何一個值都不會同時寫在兩個地方，也就不會有「文件說一套、程式跑另一套」的問題。這份檔案由 develop 建立：第一次做介面時建立，或從你既有的畫面萃取出來。

小結

這套工作流讓狀態活在檔案裡，而不是對話裡，所以工作能跨 session、跨人延續。四種載體各管一件事：AGENTS.md 管專案怎麼運作（可巢狀、單一真實來源），scope 管做什麼與順序，specs 管每一個真實決定，design.md 管介面方向且只指向 CSS 裡的數值。檔案要能長期可信，就得有規則管理「誰能改什麼」，那是後面的重點。

四種載體裡，spec 因為牽涉到「決定」而最需要規矩：同一份文件要同時是「決定了但還沒做」、「正在做」還是「做完了」。下一節就把一份 spec 從出生到被取代的完整一生走一遍。
