驗證深度：Prototype 到 GA

Step 5/5 · 知識載體與擁有權

學習目標

能比較 Prototype / Alpha / Beta / GA 四種深度各跑哪些驗證，並說出為什麼它們是建議而非關卡、done 為什麼永遠由工程師宣告。

前言：改個顏色也要跑整套審查嗎？

想像兩個情境。第一個：你週末想試做一個小工具，改了一個按鈕顏色，結果被要求跑一次獨立模型審查、再補一整組測試套件。第二個：你把付款流程改了一行，卻沒有任何驗證就上線。這兩個都很荒謬，而且方向相反：一個太重，一個太輕。

顯然不是每個變更都值得同一種強度的驗證。這套流程因此讓你在 scope 階段選一個驗證深度（workflow depth），用專案預設的方式決定 `/develop` 之後「預設」要跑多少檢查。這一節把四個深度攤開比較，並且講清楚一件很容易誤會的事：深度是建議，不是把你鎖死的軌道。

四種深度，四種檢查尾巴

深度只調一件事：/develop 之後那道「檢查尾巴」有多長。四個選項依強度排開如下。

深度develop 之後跑什麼適合什麼
Prototype什麼都不加，只靠 develop 自己的 build time 自檢（型別檢查、能渲染就渲染畫面看）加上你的眼睛。因為你已經選擇跳過獨立驗證，develop 建完並自檢後就自己把功能標成 done。丟棄式 prototype、實驗、個人小專案
Alpha加一次 check 的 verify 模式，在真的跑起來的應用程式上驗證，通過後標成 done。預設不加獨立測試套件或第二意見，除非某個功能自己要。低風險功能、還是想被證明的內部工具
Beta先 check verify，再跑 test，由 test 為功能收尾。預設不做 fresh model 的審查。大多數真實產品
GAcheck verify、test、再讓另一個模型跑 check review，最後跑一次 document；而且多數功能被視為需要 spec。高風險工作、付款、登入、法遵、團隊共用的程式庫

以教材裡那個「登入後維護自己的待辦清單」的小 App 為例，scope 會推薦 Beta：功能不算高風險，但也不至於隨便做完就上。這個推薦只是基準線。單一個高風險功能仍然可以走它自己較重的路徑，而往後的階段也會讀這個預設值，所以它們不會去騷擾一個選了 Prototype 或 Alpha 的專案，硬要它跑完整條鏈。

最重要的澄清：輕，不等於跳過 architect

看到 Prototype 只跑 develop，很容易以為「選了輕深度就可以不寫規格、亂做一通」。不是這樣。輕的深度不代表跳過 architect，它代表低嚴謹度的功能本來就很少有需要做的決定，所以你自然很少走到 architect；但當某個功能確實需要一個決定時，那道 gate 還是會把你送過去，或者要求你先把假設記成一份 Assumed spec。

為什麼要這樣設計？因為驗證可以省，決定不能省。驗證沒跑，最壞就是這個功能沒被證明；決定沒寫下來，知識就從此消失在對話裡。所以無論哪個深度，流程都會要求一件事：把關鍵的（load-bearing）決定寫下來。一份建立在假設上的功能會一直掛著「欠 ratification」的標記，但那個標記永遠不會擋住你把 done 宣告下去。

建議，而非關卡

整件事的關鍵心態是：深度設定的只是「建議你在哪裡收手」，不是一道你不能跨越的門。develop 之後的每一個步驟，check verify、test、check review、document，都是建議，你隨時可以跑或跳過。而 done 永遠是你自己宣告的，不是某個 skill 扣著不給你、要你勾完所有框框才發放的獎勵。你跳過的步驟會被誠實記錄成「已跳過」，不會被拿來對付你。

這也是為什麼 Prototype 特別：它是唯一一個，你在一開始就選擇放棄獨立驗證的深度，所以 develop 會在你建完並自檢的那一刻，直接把 done 端上來。其餘深度只是在告訴你「建議先跑到這裡再收」，要不要照做，仍然是你決定。

小結

驗證深度只決定 /develop 之後那道檢查尾巴的長度：Prototype 只有 develop 自檢，Alpha 加 check verify，Beta 再加 test，GA 再加 fresh model 的 check review 與 document。它由 scope 建議、可被單一功能覆寫，而且永遠是建議不是關卡，done 永遠由工程師宣告。輕的深度不等於跳過 architect。驗證可以省，關鍵決定不能省，假設會被記成 Assumed 並持續提醒你去追認。

走到這裡，這個節點的五塊拼圖就齊了：狀態活在四種檔案裡，spec 有嚴格的一生，每個檔案有唯一的主人，驗收條件把決策串到測試，而驗證深度決定這條線要跑多遠。下一步你可以回到總覽節點，把這些零件對回九階段的流程；或者直接在練習專案上挑一個功能，實際感受一次深度選擇帶來的差別。
