稽核既有 repo：掃描整個 repo、單一 area，安全補上文件缺口

Step 5/5 · 寫 AGENTS.md context 檔

完成這一節，你會得到什麼

你會知道如何在既有 repo 上執行 Phase 2、Phase 3 與 Phase 4：

  • 掃描整個 repo，寫出精簡且準確的 root AGENTS.md。
  • 只掃描指定的 area，並判斷是否需要巢狀文件。
  • 找出 root gap、proposed additions 與 contradiction，分清楚哪些可以套用、哪些必須交回你決定。

前置條件是：repo 已經有實際功能程式碼與歷史，或你已經知道要稽核的 area；同時要先確認目前適用哪個 phase。這一節不從零建立專案，處理的是「程式碼已經在跑，但文件不完整或不存在」的情境。

先辨認你要走哪條路

真實 repo 通常不是乾淨的 greenfield。它可能已經跑了幾年，有幾百個檔案，卻從來沒有人寫過 AGENTS.md。這時不需要把整個專案重新問一遍；先讀懂既有程式碼，再寫下能長期成立的事實就好。

依照範圍與現有文件狀態，選擇下面其中一個 phase：

  • Phase 2：沒有 root AGENTS.md，要掃描整個 repo。
  • Phase 3：帶入 area 路徑，例如 /audit src/auth，只掃描一個 area。
  • Phase 4：沒有 area 參數，但 root AGENTS.md 已存在，只補真正缺少的內容。

三條路的共同原則是：先讀，再謹慎寫。文件像 repo 的路標，不能因為補一個標示，就把原本的路線偷偷改掉。

Phase 2：掃描整個 repo，先寫 root 再判斷巢狀

若 repo 有實際功能的程式碼、真實歷史，而且目前沒有進行中的 workflow setup，就走 Phase 2。目標是產生一份準確的 root AGENTS.md，再判斷哪些 area 需要自己的巢狀文件。

Step 1：探索 repo

先列出專案幾層深的目錄樹，但跳過 .git、node_modules、.next、dist、build 等產生物或外掛資料夾。接著讀取：

  • manifest。
  • CI 設定。
  • 入口檔。
  • 測試設定。
  • 所有已存在的 AGENTS.md。

這一步不用把每個檔案都抄進筆記，只要取得足夠的 repo map，知道它使用什麼技術、從哪裡啟動，以及日常怎麼驗證。

Step 2：只保留能長期成立的知識

從探索結果萃取 durable knowledge，也就是三個月後仍可能成立的資訊：

  • 技術棧與 runtime。
  • 每天會執行的指令。
  • 程式碼中看得出來的慣例。
  • 新進工程師第一週最容易踩到的雷。

實作細節、TODO 註解，以及會頻繁變動的內容都不要放進 root。每留下一條資訊前，問自己：「三個月後，這句話還成立嗎？」

Step 3：寫 root，再決定哪些 area 需要文件

先寫一份全域、精簡的 root AGENTS.md，控制在約 60 行內。不要一開始就替每個資料夾建立文件，因為大多數資料夾沒有需要額外說明的規則。

只有在 area 具備下列特徵時，才建立巢狀文件：

  • 有真正不同的慣例。
  • 有非顯而易見的規則。
  • 有自己的本地指令。
  • 有外部整合。
  • 有容易踩到的 gotcha。

若只是簡單模組，或 root 已經說清楚，就不要建立巢狀文件。對每個值得建立文件的 area，依序做三件事：

  1. 寫入該 area 的巢狀 AGENTS.md。
  2. 在旁邊建立 CLAUDE.md 指標。
  3. 在 root 的 ## Context files 下加入一行指標。

做完這一步，你應該能說清楚：root 記錄全 repo 共通的事，巢狀文件只記錄該 area 的特殊規則。

Step 4：repo 很大時，只把「讀」交給 scout

如果 repo 很大，掃描會是唯一昂貴的部分。此時可以把唯讀探索交給 scout 子代理，並指定最便宜的模型；使用 Claude Code 時是 haiku，絕不用 session 模型。

scout 只回傳精簡的 repo map。主執行緒再根據這份 map 寫檔。任何寫入 AGENTS.md 的動作，都必須留在主執行緒。

若是 monorepo，這一輪不要深入掃描每個 workspace。只依各 workspace 的 manifest 寫一份輕量 stub，之後再由 Phase 3 補深。若某個 workspace 的文件被埋在不該埋的深處，先詢問要把它移上來，還是保留為巢狀文件。

Phase 3：只掃描一個 area

當你在指令後帶入路徑，例如 /audit src/auth，就走 Phase 3。這條路適合先處理一個明確範圍，而不是一次讀完整個 repo。

Step 1：先做前置檢查

若指定的路徑不存在，立即停止並告訴你「找不到這個路徑」，不做任何修改。

若 root AGENTS.md 不存在，先執行 Phase 2 的整庫掃描；如果 repo 仍使用舊的 root CLAUDE.md，則先完成搬遷，再回來做 area 掃描。

Step 2：探索 area，記錄兩類結果

探索完指定 area 後，先檢查 root 是否漏掉只有這個 area 才看得見的資訊，例如：

  • 只有這個 area 會使用的指令。
  • root 沒提到的相關相依套件。
  • 由這個 area 突顯出來的全域規則。

這些內容記成精確的 markdown，放在 ROOT_GAPS。要保留準備插入 root 的原文，之後用 Edit 直接套用，不要在套用前重新改寫。

接著判斷這個 area 是否值得擁有巢狀文件。若它有自己的慣例、規則、指令、整合或 gotcha，就建立巢狀 AGENTS.md，並在 root 補上一行指標；若沒有，就不建立多餘文件。

Step 3：由你決定是否套用 root gap

ROOT_GAPS 不會自動寫進 root。系統會提供三個選項：

  1. 現在套用：推薦；使用 Edit 將每一條 gap 寫入 root。
  2. 先看差異：只印出準備修改的內容，不寫檔。
  3. 先跳過：維持現狀，不做任何修改。

這裡刻意停下來是必要的。root 裡的某一行可能是你刻意寫下的判斷，即使 area 掃描看起來應該補充，也不能由工具直接替你決定。

Phase 4：root 已存在，只補真正缺的洞

若沒有 area 參數、repo 中有程式庫，而且 root AGENTS.md 已存在，就走 Phase 4。剛完成舊 CLAUDE.md 搬遷的情況也算在內。

這一輪要做的是：拿整個 repo 對照既有文件，只補真正缺少的內容，絕不改寫已經有人寫下的文字。掃描結果分成四類：

發現內容怎麼處理
(a) Root 缺的全域事實每天要跑的指令、技術棧元素、全專案規則，或 scope 有、root 卻沒記錄的 build approach。記成 ROOT_GAPS，經你同意後才套用。
(b) 沒有文件的 area有獨特慣例或 gotcha，卻沒有巢狀文件。直接建立巢狀文件，並補上 root 指標。這是建立，不是覆寫，因此安全。
(c) 過時或不完整的巢狀文件既有巢狀文件漏掉某個現在為真的事。記成 PROPOSED_ADDITIONS，不自行編輯。
(d) 矛盾文件內容被程式碼或來源紀錄推翻。回報給你，永不自動修正。

把 gap 和 contradiction 分開

第三種和第四種最容易搞混。

Gap 代表「少寫了一件事」。例如 root 沒記錄某個每天要跑的指令。補上它不會破壞原本內容，所以可以先提出，再由你同意後套用。

Contradiction 代表「既有內容可能寫錯」。例如文件說測試使用 Jest，但程式庫實際使用 Vitest；或 ## Stack 與架構 spec 互相衝突。這時不能自動選一邊，必須完整回報：「文件說 X，但程式碼或 spec 顯示 Y」。最後由你決定要改文件，還是改程式。

那一行可能是你刻意留下的說明。工具可以發現衝突，但沒有資格替你判定哪一邊才是正確來源。

套用前再次停下來確認

對可套用的內容，沿用 Phase 3 的三選一：

  1. 現在套用：寫入已同意的內容。
  2. 看差異：只顯示預計修改。
  3. 跳過：不做任何變更。

完成後產出報告，分成已寫入的檔案、root gap、提議的新增，以及需要你處理的矛盾。沒有項目的區塊直接省略。

做完後，應該看到什麼

不論執行 Phase 2、3 或 4，完成後都應該得到：

  • 一份準確且精簡的 root AGENTS.md。
  • 需要時建立的巢狀 AGENTS.md。
  • 每份巢狀文件旁邊的 CLAUDE.md 指標。
  • 一份只列出「需要你決定的事」的報告。

既有內容不會被悄悄改掉。報告最後也會告訴你下一步，通常是 scope 裡第一個尚未勾選的框。

走完這五步，你就能判斷 /audit 為什麼存在、這次該走哪個 phase，以及 greenfield 和既有 repo 各自要怎麼完成。之後產出的 AGENTS.md，會成為後續每個 skill 讀取的第一份事實。

小結

Phase 2 先讀 manifest、CI、入口、測試與既有文件，留下三個月後仍成立的事實，寫出精簡 root，再判斷哪些 area 值得巢狀文件；大型 repo 可以讓唯讀 scout 負責讀，但一定由主執行緒寫。Phase 3 只掃一個 area，路徑不存在就停止，root 不存在就先補，root gap 由「現在套用／看差異／跳過」決定。Phase 4 對照既有文件補洞，區分 root 缺的事實、沒有文件的 area、提議新增，以及矛盾；可以建立或提議的內容不代表可以自動改寫，矛盾永遠交回人決定。
