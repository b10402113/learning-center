# 什麼是智能體：感知、決策、行動

## Learning goal

能用自己的話定義 AI 智能體（感知-決策-行動，朝目標前進），並理解 agent 的設計空間早於 LLM——LLM 擴展了單一智能體可推理的範圍，而不是 agent 的必要條件。

## Lesson

你已經用 LangGraph 搭過一套 multi-agent 的 RAG 分析器了。router 怎麼分派任務、檢索節點怎麼接、graph 走到哪裡收斂，你手上有肌肉記憶。但上週有人在會議上問了老王的朋友一句：「所以到底，什麼是 agent？」他張了張嘴，最後擠出來的是：「嗯……就是 LLM 加工具吧。」

會議點點頭，事情就過去了。但你自己知道，那句話不對勁。它像「車子就是引擎加輪子」——零件都對，可是車子是什麼，你一個字都沒回答。

這一課，我們把這件事講清楚。你用雙手學過的東西，這次搬回腦子裡。

### 兩台壞掉的機器

先別碰定義。我們先看兩台壞掉的機器。

第一台，會說不會做。你問它：「幫我把這週的報表整理好，寄給主管。」它回答得頭頭是道——格式、重點、語氣建議，一路講得漂亮極了。然後呢？然後沒了。螢幕外的世界一動不動：沒有報表，沒有信，主管照樣在等。它是一部很棒的顧問機，但它不是做事的機器。

第二台，會做不會想。倉庫裡一套規則引擎，每五分鐘輪詢一次庫存，低於閾值就自動補貨。很勤勞，二十四小時不睡覺。但你只要給它一個沒寫進規則的狀況——供應商漲價了、這批貨被海關扣了——它就當機給你看。或者更糟：傻乎乎照舊補貨。

好，現在我們有了兩台機器。一台有腦無手，一台有手無腦。所以矛盾來了：我們真正想要的那種機器，兩樣都得有。缺哪一樣，都是殘缺。

問題是，有沒有一個詞，專門指這種「既會想、又會做」的軟體？有。這個詞叫 agent。但在老王把正式定義搬出來之前，我們先請一顆西瓜登場。

### 一顆西瓜的三種結局

假設老王躺在沙發上，對著機器說一句：「我要吃西瓜。甜的，別超過兩百塊。」

第一種結局：聊天機器人。它回你三大段西瓜知識——品種、產地、糖度檢測原理。寫得真好，堪比科普文章。然後，老王繼續躺在沙發上，沒有西瓜。

第二種結局：助理。它說：「我找到三個賣家。A 一斤 25，B 一斤 19 但比較遠，C 一斤 22。選哪家？」你說 B。它又問：「要確認下單嗎？」你說要。它再問：「付款方式選哪個？」每一步都很貼心，每一步都要你點頭。西瓜最終會到家，但老王全程沒躺穩過，一共審了五輪。

第三種結局：智能體。它聽完那句話，安靜了幾秒，然後自己比價、自己下單、自己挑了一顆標註糖度 12.5 的。三十分鐘後，門鈴響了。你只說了目標，剩下的是它的事。

一顆西瓜，三種結局。這中間的全部差別，就是這一課要拆的東西。

### 術語登場：三個動詞，一個目標

現在，正式的東西來了。書裡的定義是這樣的：一個 AI agent 是這樣的軟體——它感知所處的環境，決定該做什麼，然後行動以達成某個目標，過程中運用 LLM 等資源（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1]]）。完整的展開在 [[learn/ai-agents-in-action/elements/ai-agent|AI 智能體 (AI Agent)]] 這個詞條裡；這裡老王用它帶你走一遍西瓜。

拆開來，四個零件。

首先是感知（perceive）：接收並處理輸入與上下文。對西瓜機來說，是你那句話、三個賣家的報價、物流狀態。對你那套 LangGraph 系統來說，是 user 的 query、檢索回來的文件、上一個節點吐出來的中間結果。

再來是決策（decide）：對「下一步做什麼」做出選擇。選 B 還是 C？先檢索還是先總結？這一步交給哪個 agent？當代這一步多半由 LLM 承擔推理，但請先把這個事實放在旁邊——後面它會變成主角，也是陷阱。

最後是行動（act）：真的對環境做出改變。下單、發請求、寫資料、呼叫工具。注意「行動」的門檻：螢幕外的世界，或者說系統外的狀態，真的動了。只輸出一段文字，不算行動。西瓜沒到家，就是沒行動。

還有第四個容易忽略的零件：目標（goal）。沒有目標，前三個動詞就是無頭蒼蠅。老王要的是「甜的、兩百塊以內的西瓜」，這個目標像一根線，把感知、決策、行動串成一條有方向的鏈子。西瓜結局一敗在沒有行動，結局二敗在沒有自主，而三個動詞加一個目標，就是結局三。

### 從助理到智能體：那條看不見的線

西瓜的第二種結局和第三種結局，機器用的工具一模一樣，差在哪？書裡給了兩個詞：自主性（autonomy）與持續性（persistence）。正是這兩個性質，把一個反應式的助理（reactive assistant）推向主動的智能體（active agent）（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1]]）。

助理也會用工具，也替你跑腿。但它的每一步都回來找你核准（approval）。智能體拿到的是目標層的核准——你批的是「買西瓜」這件事，而不是「點 B 賣家」這一步。

你在 LangGraph 裡其實兩種都寫過。那個 interrupt 節點、那個 human-in-the-loop 的 gate，就是審批點。你把它放在每個節點後面，那是助理的寫法；你只放在付款前，那是智能體的雛形。書裡講得更務實：production 等級的 agent 用的是分級管制——低風險的步驟自主放行，高風險的動作（寄信、花錢）才設閘（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1.1]]）。不是全管，也不是全放。

### 四種互動模式：一條光譜，不是一道懸崖

順著這條線，書裡把 LLM 的互動方式排成了四級（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1.1]]）：

一，直接對話（direct LLM chat）：裸模型，能說不能做。西瓜結局一。二，帶工具的 LLM（tool-augmented LLM）：模型能呼叫工具了，但流程還是你推一下、它動一下。三，助理（assistant）：會替你用工具，但每個任務都要你核准。西瓜結局二。四，智能體（agent）：對高層目標負責，自己推理、規劃、執行多步工作。西瓜結局三。

注意，這是一條光譜，不是一道懸崖。系統從第三格滑到第四格，沒有剪綵儀式，只有核准點的移動。分界用的那把尺，叫審批軸（approval axis）——核准點落在每一步，還是落在目標層，決定系統站在哪裡。這把尺下一課會專門鋪開，這裡你先記住形狀就好。

### 陷阱：LLM 是必要條件嗎？

好，現在重頭戲來了。

你可能會想：「這一切不就是 LLM 帶來的嗎？沒有 LLM，哪來的 agent？2023 年之前，誰聽過這個詞？」

停一下。這句話，是這一課最貴的一個坑。它犯的錯有個正式名字，叫範疇錯誤（category error）：把「引擎的一種」，當成了「車子的定義」。

老王問你一個問題：望遠鏡發明之前，有沒有天文學？

有。肉眼看了幾千年，照樣記錄星象、制定曆法、預測日食。望遠鏡出現之後，天文學還是天文學——只是看得遠了非常多，多到從前看不見的星系，整片整片湧進視野。

LLM 之於 agent，就是望遠鏡之於天文學。書裡說得明白：agent 的設計空間（agentic design space）遠早於 LLM（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1]]）。這個空間的全貌在 [[learn/ai-agents-in-action/elements/agentic-design-space|智能體設計空間 (Agentic Design Space)]]；下面老王帶你把家譜補齊。

### LLM 之前的那條老街

設計空間聽著抽象，我們換個說法：一條開了幾十年的老街。街上五個地標，每家我們都問同一個問題——它怎麼幫老王買西瓜？

規則式系統（rule-based）：行為寫死在規則裡。if 西瓜價格 < 40/斤，then 買。可預測、可審計，審計師的最愛。但今天市場上只剩一顆 45 塊、甜得流蜜的瓜呢？它不買。它不看甜不甜，它只看 45 大於 40。遇到沒寫進規則的狀況，當場失效。

符號系統（symbolic）：用符號和邏輯描述世界。甜度(瓜) > 12 且 價格(瓜) ≤ 200，所以 購買(瓜)。推理嚴謹得像數學證明。但前提是——世界得先被翻譯成符號。誰來翻譯「這顆看起來不錯」這句人話？

BDI（Belief-Desire-Intention，信念-願望-意圖）：老牌的心智建模。它相信市場裡有甜瓜（belief），想要西瓜（desire），於是承諾一個意圖（intention）：先去 A 市場，沒有再去 B。信念隨感知更新，意圖隨環境調整。上世紀九十年代的 agent 研究，主角就是它。

強化學習（Reinforcement Learning，RL）：不寫規則，讓 agent 在環境裡撞。買到甜瓜得獎勵，買到生瓜得懲罰。撞了幾萬次之後，策略就藏在參數裡。厲害是真厲害，但你要先容得下它撞壞幾萬顆西瓜的學費。

神經符號（neuro-symbolic）：神經網路管感知——這張照片裡是西瓜，成熟度大概八成；符號系統管推理——八成成熟且價格合理，所以買。感知與推理，各取所長，拼接成體。

好，現在我們有了整條街：規則式、符號、BDI、強化學習、神經符號。這條街開了幾十年（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1]]）。LLM，是後來才進場的新住戶。

它帶來了什麼？書裡的措辭很精確：它擴展了單一智能體所能推理的範圍（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1]]）。從前，一個 agent 的推理半徑，被它的規則、符號、訓練任務框死——框內有條不紊，框外一無所知。LLM 進場後，自然語言寫的目標、沒預先定義的題材、跨領域的常識，突然全部落進了一個 agent 的推理半徑。老王那句「甜的，別超過兩百塊」，從前要一整條街的店家合力接待，現在一家店就接住了。

所以，你可以說 LLM 讓 agent 變得萬用、變得親切、第一次走到了普通人的沙發旁邊。但你不能說，沒有 LLM 就沒有 agent。前半句是價值判斷，後半句是史實錯誤。

### 回到你的 LangGraph

講到這裡，回頭看你搭過的那套 multi-agent RAG。

你的 router 是什麼？也許是 if-else，也許是一個小分類模型——那是規則式和學習派的座位。你的重試邏輯、你的閾值、你的 fallback 分支——全是程式碼寫死的規則。真正交給 LLM 的，是檢索結果的解讀、分析的組織、答案的生成——那些模糊的、需要語義理解的部份。

你看，你早就住在這條老街上了。你的系統本來就是混合式設計：模糊的交給模型，硬邊界交給規則。這不是妥協，這是設計空間的正確用法。以後每個決策點要不要用 LLM？先問風險：低風險、定義清楚的，交給規則，便宜又可審計；模糊的、要理解人話的，才交給模型。你不是在「用 LLM」和「不用 LLM」之間二選一，你是在一條本來就很多座位的老街上，替每個決策點挑位子。

### 收尾

寫到這裡，老王想起自己第一次被問「什麼是 agent」。那時老王剛啃完一堆框架文檔，滿肚子架構圖，於是從 tool calling 講到 planner，再講到 orchestration，講了半小時。對面安靜地聽完，說：「哦，所以就是個會自己幹活的聊天機器人。」

老王當場血壓就上來了。但深夜冷靜下來想想：這句話錯了嗎？錯了一半。錯的那一半，正是今天這一課——「自己幹活」四個字背後，是幾十年的設計傳統，不是 LLM 的贈品。

你比老王幸運。你的雙手已經搭過 agent，今天只是把名字和家譜補上。下一次會議再有人問，你不用背定義。你會講兩台壞掉的機器、一顆西瓜、一條老街，和一架望遠鏡。

定義會忘，故事不會。至少老王的記性是這樣——上週才忘記自己買過西瓜，冰箱裡現在還躺著半顆。

去吧。下一課，我們把那條審批軸鋪開來講。
