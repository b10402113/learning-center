# 助理 vs 智能體：審批軸上找位置

## Learning goal

能沿審批軸分辨四種 LLM 互動模式，並為一座真實系統設計漸進式 human-in-the-loop 閘門。

## Lesson

先把你放回你自己的處境。你之前用 LangGraph 拉了一條 multi-agent 的 RAG 分析線：檢索、重排、彙總，幾個 agent 接力，跑得挺順。demo 完之後，同事丟來一句：「所以這算是 agent，還是一個高級聊天機器人？」上一課你已經學會不慌，因為這題不靠感覺，靠刻度。而且探測的時候你把這條線答得乾乾淨淨，所以老王這一課不重講基礎。我們只花一分鐘復習，然後把尺拿出來，量三樣東西：你的 RAG 線、幾座別人家的系統、一座要你從零畫閘門的維運 agent。量完，這根軸就是你的了，拔都拔不走。

**一、一分鐘復習：四個位置，一根軸。**

書裡把 LLM 的互動模式切成四種：直接 LLM 對話、工具增強 LLM（tool-augmented LLM）、助理（assistant）、智能體（agent）。切開它們的不是「有沒有用工具」，是核准的顆粒度（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1.1]]）。第一，純問答，無工具，無行動。第二，模型能呼叫工具，但每個請求由你發起，工具只服務當前這一問。第三，助理替你操作工具，但每一步都等你點頭。第四，agent 只對高層目標要一次核准，然後自己推理、規劃、執行整段多步工作。書裡的 Table 1.1 還把四個模式對上審批模型、自主等級、平台實例三欄，一眼看穿。

這就是 [[learn/ai-agents-in-action/elements/approval-axis|審批軸 (Approval Axis)]]。問題從來不是「它是不是 agent」，而是「核准點落在步，還是落在目標」。而且助理與 agent 之間不是一堵牆，是一條光譜：production 等級的 agent 標配漸進式人類介入（graduated human-in-the-loop），低風險步驟自主跑，寄信、採購這種高風險行動設閘（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1.1]]）。好，復習完畢。接下來全是應用，因為你已經懂了，懂了的東西就該拿去用。

**二、第一站：量一量你自己的 RAG 線。**

現在把你那條 LangGraph 線搬上審批軸。你發一個分析目標進去，router 分流，檢索 agent 查向量庫，重排 agent 排序，彙總 agent 出報告。全程沒有人逐步點頭。所以它在軸上的位置很清楚：目標層次的核准，往 agent 那端站。

但這裡有個更有意思的問題，老王要替你問出來：它連一個閘門都沒有，這樣合規嗎？冷靜。看它實際做了什麼。檢索、重排、彙總，全是讀操作。不改資料庫，不寄信，不花大錢，錯了重跑一次就是。按照漸進式 [[learn/ai-agents-in-action/elements/human-in-the-loop|人類介入 (Human-in-the-Loop)]] 的邏輯，低風險步驟本來就該自主執行。你的系統沒有閘門，不是因為你大膽，是因為它目前的行動面裡根本沒有高風險行動。無閘，是現狀的結論，不是設計的成就。

真正要緊的是下一個動作。假設你明天給這條線加一個工具：把報告寄給主管。瞬間，系統的風險面貌變了。寄信是對外的、不可逆的、收件人錯了收不回來的。這時你就在流程末端掛一道核准閘：報告先出草稿，你掃一眼，點頭，才寄。注意，這道閘不會把它打回 assistant。因為檢索、重排、彙總那幾十步照樣自主跑，人類只在後果不可逆的邊界上出現。核准的層次決定位置，不是有沒有核准。你的 RAG 線加閘之後，座標幾乎沒動。

順便量一個你沒注意的東西：agent 之間的交接。router 把任務交給檢索 agent，檢索交給彙總，這些 handoff 你從來不批，也不該批。它們是內部動作，風險為零。把閘門浪費在內部交接上，等於經理審批員工每按一次鍵盤。這個直覺先記住，後面講多智能體時它會回來。

**三、第二站：分類演練，四題。**

規則只有一條：不許問「它用不用工具」，只許問「誰在什麼顆粒度上批准行動」。每題先自己判，再看老王的答案。

第一題。客服知識庫問答機器人。使用者問「退貨流程是什麼」，它檢索文件，回答，結束。它不替你退貨，也不改任何東西。判：工具增強 LLM。檢索確實是工具，但每個請求你發、它答，工具服務單一請求，沒有替你行動的成分。很多人看到「接了向量庫」就喊 agent，那是被工具迷惑了。工具不是軸，核准才是。

第二題。程式編輯器裡的 AI 助手。它提出補全，你按 Tab 才套用；它跑一次跨檔改名，列出 diff，你逐個點「Apply」才落地。判：助理。教科書級的逐步核准，每個動作都停在人的手上。它聰明，但它不擁有流程。

第三題，有陷阱。你說「幫我把這週的會議訂好」。它查三個人的日曆，比對空檔，生成三個候選時段，停下來等你挑；你挑完，它自己寄出邀請、更新日曆。判：中間偏 agent。前半段是 agent 式的多步規劃，中間有一次人類介入，但注意那道閘批的是什麼？是「計畫」，不是「步」。你核准的對象是一個決策點，核准完它繼續自主收尾。計畫層次的閘，是光譜中段最常見的站牌，也是實務上最好用的那種。

第四題。維運 agent，你對它說「處理這個警報」。它自己翻日誌、關聯指標、定位到一台壞掉的 service，重啟，確認恢復，開一張 ticket 記錄。只有當它判斷需要刪除舊資料騰空間時，才暫停下來問你。判：agent，掛漸進式人類介入。低風險的讀與可逆的重啟自主跑，不可逆的刪除設閘。這正是書裡描述的 production 形態（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1.1]]）。

四題下來你應該有手感了：分類的動作永遠是同一個，找到核准點，看它的顆粒度。行銷文案寫什麼隨它去。

**四、第三站：替一座 ops agent 畫閘門圖。**

演練是判斷，現在換建造。假設我們要交付一座真正的維運 agent，工具清單如下：查日誌、查指標、重啟服務、擴容、回滾部署、開 ticket、呼叫 on-call 工程師、清理舊資料。八個工具，閘門怎麼擺？老王的方法三步。

第一步，風險盤點。把每個工具拉出來過三問：可逆嗎？對外嗎？有成本嗎？可逆性看錯了能不能 undo；對外性看影響會不會離開這台機器、這個系統；成本看花的是錢、是別人的睡眠、還是資料本身。這張表就是 [[learn/ai-agents-in-action/elements/human-in-the-loop|人類介入 (Human-in-the-Loop)]] 的設計圖底稿，日後審計也靠它。

第二步，分層掛閘。查日誌、查指標，三問全綠，自主。重啟服務、開 ticket，可逆且內部，自主，但留下完整審計記錄，出事有得查。回滾部署有點微妙：它本身是修復動作，閘太緊會耽誤救火，所以老王會讓它在「有對應部署記錄」的前提下自主，這是設計判斷，不是書裡的原文，你自己要有自己的判斷。擴容花真金白銀，掛閘。呼叫 on-call 會在凌晨三點吵醒一個真人，社會成本，掛閘。清理舊資料不可逆，掛硬閘，而且要人類確認範圍，不只確認意向。

第三步，也是最關鍵的一步：核准的層次。這座 agent 的閘門必須批「行動組」而不是批「單步」。它提出「我打算擴容兩台並清三十天前的暫存日誌」，人類一次核准這組，它自己分解執行。假如你把它做成每個工具呼叫都彈窗，恭喜，你親手把 agent 降級成助理，而且半夜警報來的時候，瓶頸是你。記住那個畫面：人類是邊界上的守衛，不是流水線上的印章。

**五、那個你憋在心裡的反對聲音。**

老王聽得見你在想什麼：「說了半天，設了閘的系統跟助理還不是一樣，都要人點頭。」這句話錯在一個字：把光譜當開關。書裡明說 assistant 與 agent 之間是沿自主性軸的光譜，production agent 本來就靠漸進式核准控制風險（[[sources/ai-agents-in-action/AI Agents in Action, Second Edi - Micheal Lanham.pdf#1.1.1]]）。差別不在要不要點頭，在你替什麼點頭。助理替每一步點頭，agent 曙光只在高風險邊界點頭。

反方向的反對也拆一下：「那我全自主，看誰敢擋。」你可以說這樣帥，但你不能說這樣省。寄錯一封信、買錯一批貨、刪錯一個庫，賠的都不是 token 費。錯誤成本不對稱的行動，自主出錯的代價由你付，不由模型付。模型當然會進步，但今天，閘門留著。

**六、往前看：這根軸會一直回來。**

第一個回訪的是多智能體。到多智能體章節你會遇到 handoff 和 orchestrator：中央 agent 把任務派給 worker，worker 之間互相交接。到時候核准問題會變形回來：人要批每一次 handoff 嗎？你今天的直覺已經能回答：handoff 是內部低風險動作，不批；閘設在系統對外的行動邊界。而 hub-and-spoke 那種中央化結構還有個副作用紅利：所有輸入輸出過一個點，閘門只畫一處就夠。軸沒變，量尺的對象變大了。

第二個回訪的是安全。後面講 MCP 會把工具變成外部伺服器，接進來的每個工具都是一條新的風險面。到時你會發現今天這張風險盤點表直接升級成安全設計：高風險工具掛人類閘，憑證限縮範圍，權限給到最小。審批軸在安全章節的角色，就是告訴你閘門該掛在哪些工具上。今天畫的圖，明天直接用。

**收尾。**

講個老王自己的事。很多年前老王寫過一支全自動清理腳本，信心滿滿，半夜定時跑。某個凌晨它把一個路徑變數當成了空字串，rm 開心地掃過去，第二天老王救回了大約一半的資料，另一半現在還活在傳說裡。從那天起，老王對「全自主」三個字始終保持著一種樸素的敬意，敬而遠之的那種。所以這一課的東西，說到底不是什麼架構時尚，是用一堆屍體換來的常識：閘門不是不信任機器，是替那個凌晨三點被警報吵醒的自己，留一條退路。你已經會讀軸了，也會畫閘了，剩下的，去你自己的系統上把那張三問表填出來。咱們下一課見。
