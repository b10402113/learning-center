# 智能體是什麼

## Learning goal
能用自己的話定義 AI 智能體（感知-決策-行動），並沿「自主性」軸分辨助理 vs 智能體，解釋 sense-plan-act-learn 迴圈與工具的作用。

## Steps
閱讀順序——deps 標示前置：

1. [[learn/ai-agents-in-action/nodes/agents-basics/what-is-an-agent|什麼是智能體：感知、決策、行動]] — 用三個動詞定義智能體，並拆穿「LLM 是必要條件」的時代錯置
2. [[learn/ai-agents-in-action/nodes/agents-basics/assistant-vs-agent|助理 vs 智能體：審批軸上找位置]] — 沿審批軸分類四種互動模式，親手設計漸進式 human-in-the-loop 閘門（接 step 1）
3. [[learn/ai-agents-in-action/nodes/agents-basics/the-spal-loop|SPAL 迴圈：agent 的運行時鐘]] — 追蹤一個目標走過多輪 sense-plan-act-learn，判斷內建推理與結構化推理的界線（接 step 1）
4. [[learn/ai-agents-in-action/nodes/agents-basics/acting-with-tools|工具：agent 的手，失敗是常態]] — 工具註冊、失敗階梯、per-agent 接線之死與 MCP 的服務端整合（接 step 3）

## Lesson
這個節點只教一件事，但這件事撐起整本書：**智能體是會感知、會決策、會行動的軟體**。三個動詞缺一不可——只會說的聊天機器人缺行動，只會跑的規則引擎缺決策。

四個步驟把這句話拆開再裝回去。Step 1 先立定義，並拆掉最常見的時代錯置：agent 的設計空間早於 LLM（規則式、符號、BDI、RL、神經符號），LLM 擴展的是單一智能體可推理的範圍，不是 agent 的入場券。Step 2 把定義裡的「自主性」變成可操作的刻度——核准點落在每一步還是落在目標層，決定系統是助理還是智能體；production 的答案是漸進式閘門，不是兩端。Step 3 給定義一張運行時鐘：SPAL 迴圈把「感知-決策-行動」拉成帶學習相位的循環，目標→任務→工具呼叫的分解鏈在 plan 階段展開。Step 4 補上行動的手：工具以 JSON 定義註冊、失敗是正常控制流，而接線的經濟學（per-agent × per-service）逼出 MCP。

走完後你手上有三個可遷移的工具：一個定義（分類任何系統）、一根軸（定位自主性）、一張迴圈圖（拆解任何 agent 的運行）。後面所有節點——五層架構、MCP、多智能體——都是這三件工具的延伸。
