# SPAL 迴圈 (Sense-Plan-Act-Learn Loop)

## Problem Statement

一個 agent 收到「幫我分析這批論文」這種目標後，接下來幾分鐘在幹什麼？如果你腦中只有「LLM 一直生字」的畫面，你設計出來的系統就會真的只剩生字。你缺的是一張運行時的骨架圖：目標怎麼變成任務、任務怎麼變成工具呼叫、這輪的教訓怎麼變成下一輪的經驗。

## Why it matters

SPAL 是「agentic loop」的核心心智模型。任何一個 agent——不管用什麼框架——都能拆進這四個階段。它也是 debug 的地圖：系統出問題時，先問卡在哪個階段，比盲目換模型有效得多。

## How it works

**SPAL 迴圈（sense-plan-act-learn loop）**是 agent 完成多任務目標的運行循環：

1. **感知（sense）**：輸入與上下文的處理——使用者訊息、工具回傳、環境狀態進來，變成可推理的上下文。
2. **規劃（plan）**：LLM 推理「下一步做什麼」——把目標分解成任務，把任務排成順序。目標 → 任務 → 工具呼叫的分解鏈就在這裡。
3. **行動（act）**：執行工具呼叫，產生輸出。
4. **學習（learn）**：評估輸出、更新記憶——這輪檢索結果好不好、哪個查詢沒用，回寫成下一輪的經驗。

工具呼叫之間，輸出可以在呼叫間**鏈接（chainable）**——上一步的輸出成為下一步的輸入。

SPAL 有族譜：它對應軍事的 **OODA（Observe-Orient-Decide-Act）**、**BDI** 架構、以及機器人學經典的 sense-plan-act 循環。當代的一個重要轉折：前沿模型已**內建推理（built-in reasoning）**，短任務上 plan 階段幾乎免設定；但**長程任務（long-horizon）**與較弱模型上，明確的 prompt/結構化推理仍然關鍵——這條界線本書後續章節（推理與規劃）會展開。

## In plain terms

做菜。先看冰箱有什麼（感知），想菜單和順序（規劃），開火炒（行動），嘗一口太鹹記下來（學習）——下一道菜少放點鹽。「目標是晚餐」分解成「三菜一湯」，再分解成「先燉湯，燉的時候切菜」——這就是目標→任務→工具呼叫。

## Practical use

拿你的 LangGraph RAG 流程對號入座：抓取論文摘要＝sense、LLM 推理下一個查詢＝plan、執行向量檢索＝act、把檢索好壞回寫＝learn。日後任何新 agent 卡住，先定位卡在哪個階段：抓不對是 sense、不知道下一步是 plan、工具出錯是 act、一直重複犯錯是 learn 沒在做。

## Questions

### Q1. SPAL 四階段各自對應什麼？
A1. 感知=輸入與上下文處理；規劃=LLM 推理與目標分解；行動=工具執行；學習=輸出評估與記憶更新。

### Q2. 關係題：前沿模型內建推理之後，結構化推理還有必要嗎？
A2. 有——分任務。短程、可逆、模型擅長的領域，內建推理足夠；長程多步、跨步維持子目標、或用較弱模型時，明確的 prompt/結構化推理仍然關鍵（書中於推理章節展開）。

### Q3. 價值判斷題：你的 agent 每輪都重複犯同一個檢索錯誤，該換模型還是改迴圈？
A3. 先改迴圈——重複犯錯是 learn 階段失能的症狀（輸出評估與記憶更新沒做），換模型不會憑空長出學習；把評估回寫機制補上，成本遠低於換模型。
