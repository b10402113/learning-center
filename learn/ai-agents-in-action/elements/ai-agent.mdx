# AI 智能體 (AI Agent)

## Problem Statement

你寫了一個聊天機器人，它很會聊。你問它「幫我把這週的報表整理好寄給主管」，它回答得頭頭是道——然後什麼都沒發生。螢幕外的世界一動不動：沒有報表、沒有信、主管照樣在等。問題出在哪？這台機器只會「說」，不會「做」。反過來，倉庫裡那台每五分鐘輪詢庫存、低於閾值就補貨的規則引擎很會「做」，但它不會「想」——遇到沒寫進規則的狀況就當機給你看。「會想不會做」和「會做不會想」，是兩種不同的殘缺。我們需要一個詞，指的是那種**既會感知、又會決策、還會動手**的軟體。

## Why it matters

這個定義不是文字遊戲。當你評估、採購或動手建造一個系統時，「它是不是 agent」決定了你該問的問題：你問聊天機器人「你會不會擅自寄信」是問錯了對象；你問規則引擎「你能不能處理沒見過的請求」也是問錯了對象。定義是你分類的工具——它告訴你手上這個系統的能力邊界在哪，責任落在誰頭上。

## How it works

**AI 智能體（AI Agent）** 是這樣一種軟體：它**感知（perceive）**所處的環境、**決定（decide）**該做什麼、然後**行動（act）**以達成某個目標——過程中運用 LLM 等資源。三個動詞，缺一不可：

1. **感知**：接收並處理輸入與上下文——使用者訊息、工具回傳、環境狀態。
2. **決策**：對「下一步做什麼」做出選擇。當代由 LLM 承擔主要推理，但決策本身不要求特定技術。
3. **行動**：真的對環境做出改變——呼叫工具、發請求、寫資料。

兩個衍生詞把光譜拉出來：**自主性（autonomy）**與**持續性（persistence）**把一個反應式的助理推向主動的智能體；**agentic** 這個形容詞，描述的就是在「感知-決策-行動」這個模式裡展現出自主性的系統。

還有一條容易被忘記的時間線：agent 的設計空間**早於 LLM**。規則式系統、符號系統、**BDI（Belief-Desire-Intention，信念-願望-意圖）**架構、強化學習、神經符號系統——全都在 LLM 之前就成立了。LLM 帶來的不是定義上的革命，而是**擴展了單一智能體所能推理的範圍**：一個 agent 現在能讀懂模糊的自然語言目標、在沒寫過規則的題材上做判斷。LLM 之於 agent，是望遠鏡之於天文學——沒有望遠鏡天文學也是天文學，有了之後看得遠得多。

## In plain terms

房東與房客的差別。房東收到訊息（感知）、考慮要不要修（決策）、叫師傅去修（行動）——目標是把房子租好。翻譯機只負責把你的話轉成房東聽得懂的語言，轉完就下班；電熱水壺水開了就跳閘，連「決策」都是焊死的。

## Practical use

下次有人推銷「AI agent 產品」，用三個動詞拆它：它的「感知」是什麼（輸入從哪來）？「決策」是誰做的（模型還是 if-else）？「行動」碰得到真實世界嗎（有沒有工具）？三問下來，很多「agent」其實只是包了殼的聊天機器人。你自己設計系統時也一樣：哪一環是模型、哪一環是程式碼、哪一環是人，說清楚了，系統的責任邊界才清楚。

## Questions

### Q1. 為什麼「不含 LLM 的系統就不是 agent」這句話是錯的？
A1. Agent 的設計空間早於 LLM：規則式、符號、BDI、強化學習、神經符號系統都早已成立。LLM 擴展的是單一智能體可推理的範圍，不是 agent 的定義條件。

### Q2. 關係題：定義裡的「自主性」和審批軸是什麼關係？
A2. 自主性是定義中的一個性質（從助理推向智能體的力量），審批軸是衡量這個性質的標尺——核准點落在每一步還是落在目標層，決定系統在軸上的位置。

### Q3. 價值判斷題：一個「會感知、會決策、但不執行行動」的系統值得稱為 agent 嗎？
A3. 依書中定義不算——缺了「行動」就不是完整的感知-決策-行動模式。但依價值判斷，它可能仍是個有用的系統（例如純 advisory 的分析助手）；只是把它叫 agent 會誤導別人對它能力邊界與責任歸屬的預期。
