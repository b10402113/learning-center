# 人類介入 (Human-in-the-Loop)

## Problem Statement

有兩種失敗都見過：一種是每步都等人批的系統，人類變成瓶頸，半夜任務全卡死，「自動化」名存實亡；另一種是全自主的系統，很流暢，直到它擅自幫你寄了一封收件人寫錯的信。你大概也想過「那到底要不要人類介入」——但這是個假二選一。真正的問題是：**哪些行動需要人類、在什麼風險層級上需要？**

## Why it matters

HITL 是 agent 從 demo 走向 production 的必要條件。錯誤成本不對稱的行動（寄信、採購、刪除）一旦 autonomous 出錯，賠的不是 token 費。閘門放對位置，你同時買到自主的效率與人類的擔保。

## How it works

**人類介入（human-in-the-loop, HITL）**是把人類核准點嵌進 agent 流程的機制。書中主張的形態是**漸進式（graduated）**：

- **低風險步驟**：讀取、檢索、排序、暫存草稿——自主執行，不等人。
- **高風險行動**：寄信、採購、刪資料、對外發布——設核准閘，人類點頭才執行。

「漸進」的意義在於風險分級：閘門密度隨行動的可逆性與影響面伸縮。這也回答了那個常見的焦慮——設閘不等於退回 assistant；核准的**層次**（步 vs 目標）才決定系統在審批軸上的位置。

## In plain terms

新來的同事。影印、查資料你讓他自己來；但要代表部門發信給客戶，抱歉，先拿來我看一下。你不是不信任他，是這封信出了錯，罰的是部門。

## Practical use

替你的 agent 做一次風險盤點：把所有工具呼叫列成清單，逐項標「可逆/不可逆」「內部/對外」「成本低/成本高」。三項全綠的放手自主；任何一項紅的，掛核准閘。這張表就是你系統的 HITL 設計圖，也是日後審計的依據。

## Questions

### Q1. 漸進式 HITL 的「漸進」是什麼意思？
A1. 閘門密度隨行動風險分級伸縮：低風險步驟自主執行，高風險行動（寄信、採購等）設人類核准閘，而非全有或全無。

### Q2. 關係題：HITL 閘門與審批軸上的定位有什麼關係？
A2. 閘門是機制，軸是座標。設不設閘不改變分類，核准落在步層次還是目標層次才改變；漸進式閘門讓系統停在光譜中段的務實位置。

### Q3. 價值判斷題：全自主與全人工核准，哪個更適合 production？
A3. 都不適合。全自主在高風險行動上錯誤成本不對稱；全核准讓人類成為瓶頸、自主性名存實亡。production 的答案是漸進式：按可逆性與影響面分級設閘。
