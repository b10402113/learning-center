# Digest — 操作系统

## Overview (L1)

- 课程总览与学习方法 — 操作系统作为硬件与应用之间的抽象层，围绕进程/内存/文件/设备四大模块；强调场景化记忆与纵向深挖，并给出高频题清单（文件 1、操作系统导学、高频热题）。
- 用户态与内核态 — 权限分级的目的（安全/隔离/统一调度）、三种切换触发（系统调用/异常/中断）、切换慢的根因（寄存器保存、栈切换、缓存失效）与减少上下文切换的手段（文件 2–5）。
- 进程、线程与协程 — 三者从资源分配到调度单位的演进、进程五态流转、fork 与写时复制、多进程架构权衡，以及协程切换为何更快（文件 6–10、25）。
- 进程生命周期与异常进程 — 守护进程的创建步骤与脱离终端的本质、守护进程 vs 后台进程、僵尸进程与孤儿进程的成因与处理（文件 12、13）。
- 进程间通信与死锁 — 六种 IPC 方式（管道/共享内存/消息队列/信号量/信号/Socket）、死锁四必要条件与避免策略、线上死锁的 jstack/Arthas 排查流程（文件 11、14、15）。
- 内存管理与虚拟内存 — 虚拟内存的扩容/隔离/抽象价值、分段/分页/段页式对比、多级页表、缺页中断、页面置换算法与 TLB 加速（文件 16–20、26）。
- I/O 模型、多路复用与零拷贝 — 同步/异步与阻塞/非阻塞及 BIO/NIO/AIO、select/poll/epoll 演进、ET 与 LT、Reactor 与 Proactor、零拷贝（sendfile/mmap）与 io_uring（文件 21–24、32、33）。
- 并发锁与文件系统 — 互斥锁/信号量、自旋锁、乐观锁与 CAS、读写锁与写饥饿、条件变量；inode、硬链接与软链接、文件描述符（文件 27–31、34–36）。

### 1.操作系统这门课主要是讲什么

- Locator: `[[sources/小哲讲八股/20260926/操作系统/1.操作系统这门课主要是讲什么.md#1.操作系统这门课主要是讲什么]]`
- Summary: 操作系统是硬件与应用之间的抽象层，把有限复杂的物理资源虚拟化为无限易用的逻辑资源，核心是管理硬件与服务软件。
- Key claims: 四大抽象为进程/线程管理、内存管理、文件系统、设备管理；四大模块通过中断、系统调用、用户态/内核态切换协作。
- Learner-relevant: 全科总纲锚点，后续每个模块都能挂到这四个抽象上。

### 2.为什么要划分用户态和内核态

- Locator: `[[sources/小哲讲八股/20260926/操作系统/2.为什么要划分用户态和内核态.md#2.为什么要划分用户态和内核态]]`
- Summary: 划分两态是为保护与隔离系统资源：内核态 Ring 0 可执行特权指令、访问全部硬件，用户态 Ring 3 受限，须经系统调用陷入内核。
- Key claims: 目的是安全性（防越权）、稳定性（故障隔离防止全系统崩溃）、统一资源调度；用户态程序崩溃只限自身，不波及内核与其他进程。
- Learner-relevant: 特权级模型的入门锚点，是所有系统调用与上下文切换讨论的前提。

### 3.什么情况下会发生用户态和内核态的切换

- Locator: `[[sources/小哲讲八股/20260926/操作系统/3.什么情况下会发生用户态和内核态的切换.md#3.什么情况下会发生用户态和内核态的切换]]`
- Summary: 用户态转内核态只有三类触发：系统调用、异常、外设中断。
- Key claims: 系统调用是程序主动发起（read/fork/send）；异常是被动内部错误（缺页、除零、非法内存访问）；中断是硬件异步信号（键盘、网卡、时钟时间片）。
- Learner-relevant: 切换的完整触发清单，衔接切换开销与减少切换手段。

### 4.为什么说从用户态切换到内核态会比较慢

- Locator: `[[sources/小哲讲八股/20260926/操作系统/4.为什么说从用户态切换到内核态会比较慢.md#4.为什么说从用户态切换到内核态会比较慢]]`
- Summary: 模式切换开销远大于普通函数调用，因为要保存/恢复现场、切换用户栈到内核栈、并经历特权级校验与缓存失效。
- Key claims: 三方面开销为寄存器上下文保存与恢复、特权级校验与栈切换、缓存命中率下降（TLB 与 L1/L2、流水线）；缓存污染是性能损耗最大处。
- Learner-relevant: 解释上下文切换为何昂贵，是协程/线程池/零拷贝优化的动机。

### 5.操作系统中有哪些技术手段可以减少上下文切换

- Locator: `[[sources/小哲讲八股/20260926/操作系统/5.操作系统中有哪些技术手段可以减少上下文切换.md#5.操作系统中有哪些技术手段可以减少上下文切换]]`
- Summary: 优化思路是尽量留在用户态、不阻塞、能复用就复用，核心是减少内核介入。
- Key claims: 手段包括协程（用户态调度）、线程池（复用线程控制数量）、无锁编程/CAS/自旋锁（忙等待替代挂起）、零拷贝（mmap/sendfile）、CPU 绑定减少跨核缓存失效。
- Learner-relevant: 高性能系统（Redis/Nginx/Kafka）优化手段总览。

### 6.对比进程线程和协程

- Locator: `[[sources/小哲讲八股/20260926/操作系统/6.对比进程线程和协程.md#6.对比进程线程和协程]]`
- Summary: 三者是并发执行的三个层次：进程是资源分配最小单位、线程是 CPU 调度最小单位、协程是用户态轻量级线程。
- Key claims: 隔离性进程最强（崩溃不互相影响）而线程最弱；切换成本进程最高（切页表刷 TLB）、线程中等（需陷内核）、协程极低（仅改寄存器，纳秒级）；通信进程最麻烦须 IPC。
- Learner-relevant: 并发模型核心对照表，串联隔离性、开销与适用场景。

### 7.操作系统中进程有哪些状态

- Locator: `[[sources/小哲讲八股/20260926/操作系统/7.操作系统中进程有哪些状态.md#7.操作系统中进程有哪些状态]]`
- Summary: 进程生命周期用五态模型描述：创建、就绪、运行、阻塞、终止，核心是就绪/运行/阻塞三态流转。
- Key claims: 单核同一时刻只有一个运行态；时间片用完运行→就绪，I/O 或申请锁运行→阻塞；阻塞事件完成后必须先回就绪再排队等 CPU，不能直接回运行。
- Learner-relevant: 调度与阻塞概念的基础状态机。

### 8.fork系统调用发生了什么？什么是Copy-on-Write写时复制

- Locator: `[[sources/小哲讲八股/20260926/操作系统/8.fork系统调用发生了什么？什么是Copy-on-Write写时复制.md#8.fork系统调用发生了什么？什么是Copy-on-Write写时复制]]`
- Summary: fork 只复制 PCB 与页表、不复制物理内存，父子进程共享物理页并靠 Copy-on-Write 在写入时才真正复制。
- Key claims: 共享页被标记只读，任一方写入触发保护异常；内核分配新页、拷贝原数据、改页表为可读写后重执行写指令；fork 后紧接 exec 的常见场景因此完全不发生内存复制。
- Learner-relevant: 进程创建与虚拟内存按需分配的经典结合，也是 Redis bgsave 等场景的底层原理。

### 9.多进程应用程序对比单进程应用程序的优缺点

- Locator: `[[sources/小哲讲八股/20260926/操作系统/9.多进程应用程序对比单进程应用程序的优缺点.md#9.多进程应用程序对比单进程应用程序的优缺点]]`
- Summary: 多进程 vs 单进程本质是资源隔离与资源共享的权衡。
- Key claims: 多进程优点是健壮性/隔离性强（Chrome 每 Tab 一进程）、可利用多核并行、支持解耦热部署（Nginx reload）；缺点是资源开销大、上下文切换慢（切页表刷 TLB）、通信须 IPC。
- Learner-relevant: 架构选型锚点：CPU 密集/高稳定选多进程，IO 密集/超高并发选单进程多线程或多路复用。

### 10.为什么有了进程以后还需要线程

- Locator: `[[sources/小哲讲八股/20260926/操作系统/10.为什么有了进程以后还需要线程.md#10.为什么有了进程以后还需要线程]]`
- Summary: 引入线程是为解决进程在并发粒度与通信成本上的局限，核心是进程"太重"。
- Key claims: 线程共享进程内存、创建只需栈与寄存器，开销低；线程切换不换页表、缓存仍有效，比进程切换便宜；线程间通信直接读写共享变量（须加锁）无需陷入内核；还能更好利用多核真正并行。
- Learner-relevant: 解释线程存在的三大理由（开销/切换/通信），承上启下对比协程。

### 11.进程间的通信方式都有哪些？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/11.进程间的通信方式都有哪些？.md#11.进程间的通信方式都有哪些？]]`
- Summary: Linux IPC 主要有六种方式，按数据传输、控制通知、跨网络三类组织。
- Key claims: 管道分匿名（父子、半双工）与命名 FIFO（无亲缘也可）；共享内存最快但有并发问题须配信号量；消息队列有格式且独立于进程；信号量实为计数器做同步互斥；信号是唯一异步机制；Socket 唯一可跨网络。
- Learner-relevant: IPC 方式全表，衔接共享内存与锁的配合。

### 12.守护进程是如何创建的？它与后台进程的区别？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/12.守护进程是如何创建的？它与后台进程的区别？.md#12.守护进程是如何创建的？它与后台进程的区别？]]`
- Summary: 守护进程创建的核心是彻底脱离控制终端，标准步骤为两次 fork + setsid + 环境清理。
- Key claims: 步骤为 fork 后父退出、setsid 新会话、二次 fork 防止再获终端、chdir("/") 防占用挂载点、umask(0)、关闭/重定向标准 IO；后台进程仍属当前 Shell 会话，终端关闭时收 SIGHUP 而退出，守护进程不受影响且无 TTY。
- Learner-relevant: 会话/进程组概念与 mysqld/nginx/sshd 的启动原理。

### 13.什么是僵尸进程和孤儿进程?如何处理它们

- Locator: `[[sources/小哲讲八股/20260926/操作系统/13.什么是僵尸进程和孤儿进程_如何处理它们.md#13.什么是僵尸进程和孤儿进程?如何处理它们]]`
- Summary: 僵尸进程是子进程已退出但父进程未 wait 而残留 PCB；孤儿进程是父进程先死子进程仍在被 init 收养。
- Key claims: 僵尸进程不占内存/CPU 但占 PID（默认 32768），无法被 kill -9 杀死，只能杀掉其父进程使其变孤儿；孤儿进程无危害，PID 1（init/systemd）自动收养并回收。
- Learner-relevant: 父子进程退出时序坑与 wait/waitpid 的工程意义。

### 14.操作系统中死锁的四个基本条件是什么?如何避免

- Locator: `[[sources/小哲讲八股/20260926/操作系统/14.操作系统中死锁的四个基本条件是什么_如何避免.md#14.操作系统中死锁的四个基本条件是什么?如何避免]]`
- Summary: 死锁需同时满足 Coffman 四条件，破坏任一即可解除。
- Key claims: 四条件为互斥、请求与保持、不可剥夺、循环等待；预防上最可行是给资源编号强制按序申请以破坏循环等待，或一次性申请全部资源；系统层面用银行家算法在分配前判断是否进入不安全状态。
- Learner-relevant: 死锁理论核心考点，串联锁与资源分配。

### 15.线上程序如何排查死锁

- Locator: `[[sources/小哲讲八股/20260926/操作系统/15.线上程序如何排查死锁.md#15.线上程序如何排查死锁]]`
- Summary: 排查线上死锁三步：找 PID → jstack 导堆栈保留现场 → 分析日志关键字。
- Key claims: 死锁时服务无响应但 CPU 通常不高（线程多在等待），CPU 飙高多为死循环；堆栈末尾常见 "Found one Java-level deadlock"，否则搜 BLOCKED 线程看 waiting to lock/locked by；Arthas `thread -b` 可一键定位。
- Learner-relevant: 死锁理论到线上诊断的落地流程。

### 16.什么是虚拟内存?为什么需要虚拟内存

- Locator: `[[sources/小哲讲八股/20260926/操作系统/16.什么是虚拟内存_为什么需要虚拟内存.md#16.什么是虚拟内存?为什么需要虚拟内存]]`
- Summary: 虚拟内存给每个进程提供一致、私有、连续的逻辑地址空间，是物理内存与硬盘之间的中间层。
- Key claims: 三大价值为突破物理内存限制（Swap 扩容）、内存保护与隔离（独立地址空间）、简化内存管理（逻辑连续、物理可碎片化）；本质是用时间换空间、用抽象换安全。
- Learner-relevant: 内存管理总纲，分页/页表/TLB 均建立其上。

### 17.分段、分页、段页式这几种方式有什么区别？对比优缺点

- Locator: `[[sources/小哲讲八股/20260926/操作系统/17.分段、分页、段页式这几种方式有什么区别？对比优缺点.md#17.分段、分页、段页式这几种方式有什么区别？对比优缺点]]`
- Summary: 分页按固定大小切（物理视角）、分段按程序逻辑切（逻辑视角）、段页式先分段再对每段分页，结合两者。
- Key claims: 分页无外碎片但有内碎片、不利共享保护，目的是管理效率；分段无内碎片、便于共享保护但有外碎片，目的是满足逻辑需求；段页式查两次表（段表+页表），代价是硬件成本与系统复杂度。
- Learner-relevant: 内外碎片与逻辑/物理单位的辨析锚点。

### 18.为什么需要多级页表

- Locator: `[[sources/小哲讲八股/20260926/操作系统/18.为什么需要多级页表.md#18.为什么需要多级页表]]`
- Summary: 多级页表解决单级页表占用内存过大且必须连续存放两个痛点，核心是按需创建与离散存储。
- Key claims: 32 位 4GB/4KB 需约 100 万页表项、每进程约 4MB 且须连续；多级页表只建顶层，用到哪部分才建下层，未用地址不分配；代价是查表次数增加（二级查两次、四级查四次），靠 TLB 弥补。
- Learner-relevant: 页表空间核算与时间换空间思想，衔接 TLB。

### 19.什么是缺页中断异常

- Locator: `[[sources/小哲讲八股/20260926/操作系统/19.什么是缺页中断异常.md#19.什么是缺页中断异常]]`
- Summary: 缺页中断是访问已映射但未加载到物理内存页面时，MMU 发现页表项存在位为 0 触发的异常。
- Key claims: 处理四步为硬件检测陷入内核、寻找空闲物理页（满则按置换算法换出）、磁盘 I/O 加载缺失页（最耗时）、更新页表存在位后重执行原指令。
- Learner-relevant: 虚拟内存按需加载的关键机制，连接页面置换算法。

### 20.常见的页面置换算法有哪些

- Locator: `[[sources/小哲讲八股/20260926/操作系统/20.常见的页面置换算法有哪些.md#20.常见的页面置换算法有哪些]]`
- Summary: 页面置换算法在"踢得准"与"踢得快"之间权衡，经典有 OPT、FIFO、LRU、Clock 四种。
- Key claims: OPT 淘汰未来最久不用者，缺页率最低但不可实现，仅作标尺；FIFO 实现简单但差且有 Belady 异常（内存增多缺页反增）；LRU 性能最接近 OPT 但硬件成本高；Clock 用访问位近似 LRU，开销小、现代 OS 最常用。
- Learner-relevant: 算法演进与局部性原理，为缺页处理与缓存淘汰打基础。

### 21.如何理解同步\异步、阻塞\非阻塞、BIO\NIO\AIO

- Locator: `[[sources/小哲讲八股/20260926/操作系统/21.如何理解同步_异步、阻塞_非阻塞、BIO_NIO_AIO.md#21.如何理解同步\异步、阻塞\非阻塞、BIO\NIO\AIO]]`
- Summary: 阻塞/非阻塞看当前线程状态，同步/异步看消息通知机制，BIO/NIO/AIO 是两者组合出的具体 IO 模型。
- Key claims: BIO 为同步阻塞（一连接一线程，无法支撑高并发）；NIO 为同步非阻塞（Selector 一线程管多连接，底层 epoll）；AIO 为异步非阻塞（内核拷好数据再回调）；NIO 与 AIO 关键区别在谁把数据从内核拷到用户空间。
- Learner-relevant: IO 模型概念骨架，串起多路复用与 Reactor/Proactor。

### 22.操作系统中如何理解IO多路复用

- Locator: `[[sources/小哲讲八股/20260926/操作系统/22.操作系统中如何理解IO多路复用.md#22.操作系统中如何理解IO多路复用]]`
- Summary: IO 多路复用用一个线程监听多个文件描述符，解决 C10K 问题，避免 BIO 的连接即线程与上下文切换开销。
- Key claims: select/poll 用轮询、每次遍历全部连接（O(n)），select 还限 1024 连接；epoll 用事件驱动、内核红黑树管理连接、就绪链表回调通知（O(1)），适合连接多但活跃度低的场景；是 Redis/Nginx/Netty 基石。
- Learner-relevant: 高并发服务端模型的核心技术锚点。

### 23.epoll的ET和LT有什么区别吗

- Locator: `[[sources/小哲讲八股/20260926/操作系统/23.epoll的ET和LT有什么区别吗.md#23.epoll的ET和LT有什么区别吗]]`
- Summary: LT 水平触发只要缓冲区还有数据就每次 epoll_wait 都通知；ET 边缘触发只在状态由不可读变可读时通知一次。
- Key claims: LT 是默认模式、编程简单、支持阻塞与非阻塞；ET 效率高（减少系统调用，Nginx 默认）但必须配非阻塞 IO 并循环读到 EAGAIN，否则剩余数据会滞留丢失。
- Learner-relevant: epoll 编程模型与易错点。

### 24.Reactor和Proactor有什么区别吗

- Locator: `[[sources/小哲讲八股/20260926/操作系统/24.Reactor和Proactor有什么区别吗.md#24.Reactor和Proactor有什么区别吗]]`
- Summary: Reactor 关注 IO 就绪事件、应用自己调用 read 拷贝数据（同步）；Proactor 关注 IO 完成事件、内核代拷贝数据（异步）。
- Key claims: Reactor 基于多路复用，代表 Netty/Redis/Nginx；Proactor 基于真正异步 IO，代表 Windows IOCP；Linux 因 AIO 不成熟而主流用 Reactor，Netty 在应用层封装得像 Proactor。
- Learner-relevant: IO 模型的两大设计范式，衔接 epoll 与 io_uring。

### 25.为什么协程切换更快

- Locator: `[[sources/小哲讲八股/20260926/操作系统/25.为什么协程切换更快.md#25.为什么协程切换更快]]`
- Summary: 协程切换快因完全在用户态自我管理，绕开操作系统内核介入。
- Key claims: 省掉用户态/内核态模式切换；上下文只存 PC 与 SP 及用户栈（线程还要存内核栈、全量寄存器、信号掩码）；调度为协作式、逻辑简单且利于保持 CPU 缓存热度；量级为纳秒级 vs 微秒级。
- Learner-relevant: 协程性能优势的三大根因，是 Go 高并发模型的解释。

### 26.什么是TLB?它如何加速地址转换

- Locator: `[[sources/小哲讲八股/20260926/操作系统/26.什么是TLB_它如何加速地址转换.md#26.什么是TLB?它如何加速地址转换]]`
- Summary: TLB（快表）是 MMU 内缓存页表项的专用硬件，缓存"虚拟页号→物理页号"映射以加速地址转换。
- Key claims: 命中时直接得物理地址、跳过内存查页表（约 1 周期）；未命中才走多级页表查询（Page Walk）并回填 TLB；利用局部性原理，命中率常达 99% 以上。
- Learner-relevant: 多级页表性能损失的补救机制，理解地址转换全链路的关键。

### 27.互斥锁（Mutex）与信号量（Semaphore）的区别？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/27.互斥锁（Mutex）与信号量（Semaphore）的区别？.md#27.互斥锁（Mutex）与信号量（Semaphore）的区别？]]`
- Summary: 互斥锁是锁、用于保护临界资源保证同一时刻仅一个线程访问；信号量是计数器、用于同步或控制并发数量。
- Key claims: 最本质区别是所有权——互斥锁谁加谁解，信号量无所有权可跨线程 P/V（适合生产者-消费者）；互斥锁只有 0/1 两态，信号量为非负整数，计数信号量可做限流。
- Learner-relevant: 锁与同步原语的语义辨析锚点。

### 28.自旋锁（Spinlock）与互斥锁的区别？什么场景下使用自旋锁？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/28.自旋锁（Spinlock）与互斥锁的区别？什么场景下使用自旋锁？.md#28.自旋锁（Spinlock）与互斥锁的区别？什么场景下使用自旋锁？]]`
- Summary: 互斥锁拿不到就让出 CPU 阻塞（上下文切换，适合长临界区）；自旋锁拿不到便忙等待空转（适合极短临界区）。
- Key claims: 自旋锁用 CPU 空转换掉上下文切换，对短等待高效；使用须同时满足临界区极短且多核 CPU（单核自旋会卡死持锁者）；涉及 IO 或复杂逻辑禁用自旋锁。
- Learner-relevant: 阻塞 vs 忙等待的权衡，解释无锁编程的适用边界。

### 29.什么是乐观锁（CAS）与悲观锁？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/29.什么是乐观锁（CAS）与悲观锁？.md#29.什么是乐观锁（CAS）与悲观锁？]]`
- Summary: 悲观锁假设冲突必发生、操作前先加锁（写多读少）；乐观锁假设冲突少、更新时才检测是否被改动（读多写少）。
- Key claims: 悲观锁实现如 synchronized/ReentrantLock/SELECT FOR UPDATE；乐观锁靠版本号或 CAS 指令（V/A/B，内存值等于预期值才换新值，常配自旋重试）；CAS 缺点为竞争激烈时 CPU 空转与 ABA 问题（用版本号如 AtomicStampedReference 解决）。
- Learner-relevant: 并发策略选型与无锁编程核心，连接 Java JUC 与数据库。

### 30.读写锁（Read-Write Lock）适用于什么场景？可能会导致什么问题（写饥饿）？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/30.读写锁（Read-WriteLock）适用于什么场景？可能会导致什么问题（写饥饿）？.md#30.读写锁（Read-Write Lock）适用于什么场景？可能会导致什么问题（写饥饿）？]]`
- Summary: 读写锁允许读共享、写独占，适用于读多写少场景（配置中心、黑白名单、路由表）以提升并发吞吐。
- Key claims: 读优先的非公平策略下，持续的读请求会让写线程永远等不到锁而饿死（写饥饿）；解决办法是公平锁（按请求先后排队）或写优先（有写等待时新读请求不许插队）。
- Learner-relevant: 锁粒度优化的副作用与公平性设计。

### 31.条件变量（Condition Variable）的作用是什么？为什么通常配合Mutex使用？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/31.条件变量（ConditionVariable）的作用是什么？为什么通常配合Mutex使用？.md#31.条件变量（Condition Variable）的作用是什么？为什么通常配合Mutex使用？]]`
- Summary: 条件变量让线程在条件不满足时挂起睡眠、条件满足时被唤醒，避免忙等待；它解决"什么时候进房间"，互斥锁解决"谁能进房间"。
- Key claims: 配合 Mutex 一是保护共享状态（判断条件即访问共享数据），二是核心的防止丢失唤醒——wait 内部原子地"释放锁+进入睡眠"，堵住"判断条件"与"真正休眠"之间的竞态窗口。
- Learner-relevant: 生产者-消费者同步原语与 lost wake-up 经典坑。

### 32.什么是零拷贝（Zero Copy）？Sendfile和mmap是如何减少上下文切换和数据拷贝的？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/32.什么是零拷贝（ZeroCopy）？Sendfile和mmap是如何减少上下文切换和数据拷贝的？.md#32.什么是零拷贝（Zero Copy）？Sendfile和mmap是如何减少上下文切换和数据拷贝的？]]`
- Summary: 零拷贝通过减少冗余数据拷贝与用户态/内核态切换提升 IO 性能；传统 read+write 需 4 次拷贝、4 次切换。
- Key claims: mmap 把内核缓冲映射到用户空间，省 1 次 CPU 拷贝但仍 4 次切换；sendfile 让数据不经用户态在内核内流转，切换降至 2 次，配 SG-DMA 可实现 0 CPU 拷贝（仅 2 次 DMA）；mmap 适合小数据量，sendfile 适合大文件（Kafka/Nginx）。
- Learner-relevant: IO 性能优化核心，连接虚拟内存与 DMA。

### 33.io_uring是什么?它与Epoll相比有什么优势

- Locator: `[[sources/小哲讲八股/20260926/操作系统/33.io_uring是什么_它与Epoll相比有什么优势.md#33.io_uring是什么?它与Epoll相比有什么优势]]`
- Summary: io_uring 是 Linux 5.1 引入的异步 IO 接口，采用完成模型（Proactor）而非 epoll 的就绪模型（Reactor），是真正的异步 IO。
- Key claims: 用共享内存中的提交队列（SQ）与完成队列（CQ）通信，无需数据拷贝；支持 SQPOLL 内核轮询模式实现零系统调用；应用提交请求后内核完成含拷贝在内的全部 IO 再通知。
- Learner-relevant: Linux 异步 IO 前沿，对比 epoll 的性能瓶颈。

### 34.操作系统中,什么是Inode？它存储了什么信息？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/34.操作系统中,什么是Inode？它存储了什么信息？.md#34.操作系统中,什么是Inode？它存储了什么信息？]]`
- Summary: inode（索引节点）是文件元数据与数据块指针的核心数据结构，是文件的唯一标识，数据存数据块、属性存 inode。
- Key claims: 存权限、UID/GID、大小、三个时间戳（ctime/mtime/atime）、硬链接数、文件类型，以及直接指针与多级间接指针（数据块"地图"）；关键点是 inode 不存文件名，文件名存在目录的数据块中，目录是"文件名→inode 号"的映射表。
- Learner-relevant: 文件系统入口锚点，衔接硬/软链接与文件描述符。

### 35.硬链接（Hard Link）与软链接（Soft Link/Symlink）的区别？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/35.硬链接（HardLink）与软链接（SoftLink_Symlink）的区别？.md#35.硬链接（Hard Link）与软链接（Soft Link/Symlink）的区别？]]`
- Summary: 硬链接是同一 inode 的多个别名，软链接是拥有独立 inode、内容为目标路径的独立文件（类似快捷方式）。
- Key claims: 硬链接不能跨分区、不支持目录、删源文件仍可用（链接计数减 1）；软链接可跨分区/跨机器、支持目录、删源文件即失效成 dangling link。
- Learner-relevant: inode 与链接计数的实务体现。

### 36.Linux 中，文件描述符（File Descriptor）是什么？

- Locator: `[[sources/小哲讲八股/20260926/操作系统/36.Linux中，文件描述符（FileDescriptor）是什么？.md#36.Linux 中，文件描述符（File Descriptor）是什么？]]`
- Summary: 文件描述符是内核给进程的非负整数，本质是进程文件描述符表（指针数组）的下标。
- Key claims: 表项指向系统级文件对象，FD 即数组索引；作用是屏蔽内核细节、作为内核与用户态的隔离墙、统一"一切皆文件"的 IO 抽象；每个进程默认打开 0/1/2（stdin/stdout/stderr），新 open 通常从 3 开始。
- Learner-relevant: 文件与 IO 系统调用的基础抽象，连接 Socket、管道与 epoll。
