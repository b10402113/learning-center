學習目標

看完這一節，你應該能說出 HotSpot 物件在記憶體中的三個部分，理解 Mark Word 為什麼會隨著鎖狀態改變，也能說明欄位重排序與 8 位元組對齊各自解決了什麼問題。

前言：一個 new 出來的物件，到底佔多少記憶體？

上一節提到，物件住在堆裡。現在假設你打開監控工具，看到某個服務的堆裡塞了幾百萬個小物件。你想估算它們總共用了多少記憶體，卻發現自己連「一個物件到底有多大」都說不清楚。

又或者，同事問你：「為什麼偏向鎖可以省下成本？」你知道答案和物件頭有關，卻無法解釋 JVM 究竟把什麼資訊放在那裡。

物件佈局正好把這些問題串了起來。看懂物件在記憶體裡怎麼排列，你就能估算記憶體用量，也能理解鎖升級時 JVM 改動了什麼，還能看懂 GC 分代年齡是存在哪裡。這是一個篇幅不長，卻很能連接 JVM 底層概念的主題。

三塊拼圖：物件頭、實例資料、對齊填充

在 HotSpot 虛擬機中，一個物件通常由三個部分組成：物件頭（Object Header）、實例資料（Instance Data），以及可能存在的對齊填充（Padding）。

可以把它想成一個包裹。物件頭像是包裹上的標籤，記錄「我是誰」和「我現在是什麼狀態」；實例資料是包裹裡真正放著的內容；對齊填充則像是為了讓包裹尺寸符合運送規格，而補上的空隙。其中，物件頭最複雜，也是面試最常追問的部分。

物件頭：物件的身分證與狀態儀表板

物件頭通常包含兩塊資訊：Mark Word 與 Klass Pointer。如果是陣列物件，還會多出一個記錄長度的欄位。

Klass Pointer（類型指標）回答的是：「這個物件屬於哪個類別？」它會指向方法區中的類別元資料，JVM 因此知道眼前的物件是 Student 還是 Person。在 64 位元 JVM 開啟指標壓縮時，它通常佔 4 個位元組。

Mark Word則是物件頭裡最關鍵、也最靈活的一部分。它可以存放物件的雜湊碼（hashCode）、GC 分代年齡、鎖狀態旗標，以及持有鎖的執行緒資訊。鎖狀態標誌包括偏向鎖、輕量級鎖與重量級鎖。

Mark Word 有個很重要的特性：它的內容與結構不是固定的。物件處於不同鎖狀態時，Mark Word 會拿來存放不同資訊。例如物件升級成重量級鎖後，Mark Word 裡可能改存指向 Monitor 的指標，而不再維持原本的雜湊碼與分代年齡資訊。

所以，所謂的「鎖升級」，在底層並不是憑空多出一把鎖。JVM 只是改寫物件頭裡的 Mark Word，讓它能描述新的鎖狀態。

Array Length（陣列長度）只有陣列物件才會擁有。JVM 需要這 4 個位元組記錄陣列有多長；普通物件則不需要，因為它有哪些欄位，在類別載入時就已經確定了。

實例資料：你寫在類別裡的那些成員變數

實例資料就是你在類別中真正定義的內容，例如 int id、String name。它也包含從父類別繼承下來的欄位。

這部分看起來最直觀，但欄位並不一定會完全照著原始碼出現的順序排列。為了節省空間，JVM 會把欄位重新排序。它傾向把大小相同或相近的欄位放在一起，例如把 long 與 double 放在一組，再排列 int 等欄位；此外，父類別定義的欄位通常會排在子類別欄位之前。

重排序是為了少留一些用不到的空間，不是為了讓記憶體看起來整齊。欄位排得越緊湊，物件就越小；物件越小，堆的整體壓力也就越低。

對齊填充：為什麼物件大小常常是 8 的倍數？

第三部分是對齊填充。它本身不包含任何實際資料，只是用來補空位元組。HotSpot 的記憶體管理系統要求物件的起始位址必須是 8 位元組的整數倍。因此，當物件頭加上實例資料後，總長度不是 8 的倍數，JVM 就會補上一些空間，把大小湊到符合對齊規則。

為什麼要這樣做？原因和 CPU 讀取記憶體的方式有關。CPU 通常不是一次只抓一個位元組，而是以字組為單位、按照對齊位置讀取資料。位址對齊時，資料比較容易落在同一筆讀取範圍內；如果沒有對齊，CPU 可能得跨越兩筆資料讀取，再把它們拼接起來，成本反而更高。

因此，對齊填充就像在箱子裡塞入幾塊泡棉。泡棉本身沒有內容，卻能讓箱子的尺寸符合搬運規格，換取更有效率的讀取方式。

舉個實際的估算例子。64 位元 JVM 開啟指標壓縮時，物件頭大約是 12 個位元組，也就是 Mark Word 佔 8 個位元組，加上 Klass Pointer 佔 4 個位元組。

如果物件只有一個 int 欄位，總大小就是 12 + 4 = 16 個位元組，剛好是 8 的倍數，不需要額外填充。但如果物件只有一個 boolean 欄位，大小會是 12 + 1 = 13 個位元組，JVM 就會再補上 3 個位元組，讓物件最後變成 16 個位元組。

這也是為什麼做記憶體估算時，常會出現「明明欄位不多，物件怎麼比想像中大」的情況。實際數字會受到 JVM 版本與參數影響，例如是否開啟指標壓縮；不過，讓物件大小符合對齊規則的原則是一致的。

把三塊拼起來看：物件佈局連到哪些概念？

這三個部分不是互相獨立的死知識。每一塊都會連到 JVM 其他重要概念：

佈局區塊裝什麼連到哪個概念
Mark Word雜湊碼、GC 分代年齡、鎖狀態、偏向執行緒 ID鎖升級（偏向 → 輕量級 → 重量級）、GC 分代年齡
Klass Pointer指向方法區的類別元資料方法區、類別載入（下一節）
實例資料成員變數，會做欄位重排序物件大小的估算
對齊填充純佔位，湊滿 8 的倍數CPU 對齊讀取、記憶體浪費

Mark Word 會隨鎖狀態改變，這點最值得記住。當面試官問「synchronized 鎖升級在底層做了什麼」，你可以從物件佈局切入：鎖的狀態記錄在物件頭的 Mark Word 裡；鎖升級的過程，就是改寫這塊資料，必要時再讓它指向 Monitor。

這樣一來，物件佈局就不只是「記憶體裡怎麼排資料」而已，它同時是理解鎖升級、GC 分代年齡和類別載入的共同入口。

小結

HotSpot 的物件由三部分組成：物件頭、實例資料與對齊填充。物件頭包含 Mark Word（存放雜湊碼、GC 分代年齡與鎖狀態，且會隨鎖狀態改變結構）和 Klass Pointer（指向方法區的類別元資料）；陣列物件另外包含長度欄位。實例資料存放成員變數，並可能經過欄位重排序；對齊填充則把物件大小補到 8 的倍數，讓 CPU 能以對齊方式讀取。
