執行緒的六種狀態：從建立、等待到結束

執行緒池打滿、任務堆積 · Step 1/6 · 學習目標：理解六種狀態的語義、觸發方式與流轉，並分清 BLOCKED 與 WAITING。

前言：CPU 100%，你的程式到底忙在哪裡？

線上服務突然變慢，你連上機器擷取一份 thread dump（執行緒快照），畫面上出現一長串執行緒。有人標成 RUNNABLE，有人是 BLOCKED，也有人停在 WAITING。

你想知道「到底是哪裡卡住了」，卻發現這些狀態看起來都像是執行緒的某種停頓。問題在於，它們背後代表的原因完全不同：有些執行緒正在搶 CPU，有些在門外等鎖，有些則是主動睡著，等待其他執行緒發出訊號。

這正是排查併發問題的第一道門檻。當執行緒池打滿、任務開始堆積時，執行緒通常不是「憑空消失」，而是大量停在某個狀態，遲遲沒有往下一步走。先把六種狀態和它們的流轉方式弄清楚，後面討論執行緒池時，才能看懂「任務排隊」「執行緒等鎖」和「執行緒閒置」究竟對應什麼情況。

先建立一個觀念：狀態描述的是執行緒目前卡在哪裡

Java 執行緒的生命週期，可以想成一條從「準備開工」走向「工作結束」的路。途中，它可能正在執行，也可能因為等鎖、等訊號或等時間而暫停。

Thread.State 定義了六種狀態：NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING 和 TERMINATED。它們不是六個互不相關的名詞，而是同一條生命線上的六個停靠點。下面依序走一遍。

NEW：物件已建立，但還沒真正開工

當你寫下 new Thread(...) 時，執行緒物件已經出現在堆裡，但它的狀態仍然是 NEW。

這時候它比較像是一份已經填好的工作單：資料存在，卻還沒有交給執行環境處理。它還沒有開始執行 run() 裡的程式碼，也還沒有真正進入執行緒的工作流程。只有呼叫 start() 之後，它才會離開 NEW。

RUNNABLE：Java 把「就緒」和「運行」合在一起

呼叫 start() 後，執行緒會進入 RUNNABLE。這是最容易誤解的狀態，因為 Java 把作業系統層級的「就緒（Ready）」和「運行（Running）」合併成同一個名稱。

因此，處於 RUNNABLE 的執行緒可能有兩種情況：

  • 它目前真的拿到 CPU，正在執行程式碼。
  • 它已經準備好執行，但暫時排在佇列裡，等待作業系統分配 CPU 時間片。

對 Java 虛擬機來說，這兩種情況都算是「可執行」。只要執行緒不是在等待鎖、訊號或特定時間，通常就會被歸在 RUNNABLE。

所以，thread dump 裡看到大量 RUNNABLE，只能先推斷這些執行緒沒有進入明確的等待或阻塞狀態，不能直接斷定每一條都正在使用 CPU。若要確認 CPU 究竟花在哪裡，還需要搭配作業系統層級的工具觀察。

BLOCKED：被動排隊等鎖

BLOCKED 指的是一個很具體的情況：執行緒想取得排他鎖（Monitor Lock），但鎖目前被其他執行緒持有，只能在門外排隊。

最典型的例子，是某條執行緒準備進入 synchronized 修飾的程式碼區塊或方法，卻發現對應的鎖還沒被釋放。它不是不想工作，而是連進門的資格都還沒有，只能等持鎖的執行緒離開。

這裡的關鍵字是被動。它沒有主動要求休息，而是因為「拿不到鎖」被迫停下來。這正是 BLOCKED 和 WAITING、TIMED_WAITING 的重要差別。

WAITING：主動掛起，等其他執行緒叫醒

WAITING 的執行緒是主動把自己掛起，而且沒有設定超時時間。常見的觸發方式包括 Object.wait()、Thread.join() 和 LockSupport.park()。

進入這個狀態後，執行緒不會自己在短時間內醒來。它必須等其他執行緒完成明確的喚醒動作，例如呼叫 notify()、notifyAll() 或 unpark()。

可以把它想成在休息室裡等隊友通知：只要沒有人送來訊號，它就會一直待在那裡。這也是為什麼排查問題時，看到大量 WAITING，要進一步確認它們到底在等誰、等什麼。

TIMED_WAITING：有鬧鐘的等待

TIMED_WAITING 和 WAITING 都是等待，但前者多了一個期限。執行緒可以等其他執行緒喚醒，也可以等時間到了之後自行醒來。

常見的觸發方式有 Thread.sleep(time)、Object.wait(time)、Thread.join(time)，以及 LockSupport.parkNanos() 和 parkUntil()。

兩者可以這樣記：

  • WAITING：等到有人叫，沒有時間上限。
  • TIMED_WAITING：等到有人叫，或等到鬧鐘響。

TERMINATED：工作結束，不能重新啟動

當 run() 正常執行完畢，或執行期間拋出沒有被捕捉的異常，執行緒就會進入 TERMINATED。

這代表它的生命週期已經走到終點。執行緒一旦終止，就不能再復生，也不能再次呼叫 start()。如果需要再次執行相同工作，通常要建立新的執行緒物件，而不是試圖重用已經結束的那一條。

最容易考倒人的地方：BLOCKED 和 WAITING 差在哪裡？

如果只看表面，BLOCKED、WAITING 和 TIMED_WAITING 都像是「沒有在執行」。但它們停下來的原因不同，排查方式也不同。

  • BLOCKED：想進入臨界區，但拿不到鎖，是被動等鎖。
  • WAITING：自己主動掛起，等待其他執行緒發出訊號，是主動等喚醒。
  • TIMED_WAITING：自己主動等待，但額外設定了超時時間。

面試很常追問這個差別，因為它能分辨你是真的理解執行緒狀態，還是只記住了幾個英文單字。看到 BLOCKED 時，要找的是持鎖者；看到 WAITING 時，則要找它正在等待的訊號或完成條件。

另一個常見誤區，是把 RUNNABLE 直接等同於「正在吃 CPU」。由於 Java 合併了「就緒」與「運行」，RUNNABLE 只能說明執行緒目前沒有進入鎖、訊號或時間等待，不能單靠這個狀態判斷它是否正在使用 CPU。

為什麼執行緒池要先學這六種狀態？

執行緒池的調度，本質上就是任務和執行緒不斷在不同狀態之間移動。

任務送進執行緒池後，工作執行緒可能因為等待鎖而進入 BLOCKED；佇列暫時沒有任務時，工作執行緒可能在 take() 上等待；如果設定了 keepAlive，非核心執行緒也可能在帶有時間限制的等待狀態中待命，時間到了便被回收。

因此，之後看到「核心執行緒都在忙」「非核心執行緒閒置被回收」或「任務持續堆在佇列裡」，其實都可以回頭對照這六種狀態。先把狀態的語義認清楚，執行緒池的行為才不會只剩下一團模糊的名詞。

小結

Java 執行緒有六種狀態：NEW 是已建立但尚未啟動；RUNNABLE 合併了就緒與運行；BLOCKED 是被動等待 synchronized 鎖；WAITING 是主動掛起等待喚醒；TIMED_WAITING 是帶有超時期限的等待；TERMINATED 則代表執行緒已結束且不能復生。最需要分清楚的是 BLOCKED（被動等鎖）與 WAITING（主動等訊號）的差別，也不要把 RUNNABLE 直接當成「正在吃 CPU」。這套狀態詞彙，是後面讀懂 thread dump 與執行緒池調度的基礎。
