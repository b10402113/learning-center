# JVM 執行時與類載入：類別怎麼被載入、物件存在哪

## Learning goal

講清楚位元組碼如何執行、五個執行時資料區各自裝什麼、物件佈局，以及類載入七階段與雙親委派。

## Lesson

這一課要回答一個很日常的問題：你寫的那一行 Java，最後到底在哪裡、以什麼形式被執行。答案拆成三層來看。

第一層是「位元組碼怎麼跑」。`javac` 把你寫的 `.java` 編譯成平台無關的 `.class` 位元組碼，真正執行的是 JVM 裡的解釋器和 JIT 編譯器——冷門程式碼慢慢解釋、熱門程式碼編譯成機器碼，兼顧啟動速度與長期效能。

第二層是「跑的時候記憶體長怎樣」。JVM 把執行時記憶體切成五塊：堆與方法區是所有執行緒共享的，虛擬機棧、本地方法棧、程式計數器則是每個執行緒自己一份。物件實例放在堆裡，而堆裡那一顆物件本身也不是一團模糊的資料，它由對象頭、實例數據、對齊填充三段組成，這正是後面理解鎖與 GC 的底層依據。

第三層是「類別是怎麼被載進來的」。`.class` 要經過加載、驗證、準備、解析、初始化七個階段才能變成可用的 `Class` 物件，其中準備階段只給靜態變數零值、初始化階段才真正賦值，這個時間差是面試常考、也常被誤解的地方。載入順序由雙親委派模型決定，它用「向上委託、向下加載」換來核心類的安全與唯一性；但在 SPI 和 Web 容器這類場景裡，這個模型反而要被刻意打破。

五步走完，你應該能對著「一個物件從哪來、存在哪、怎麼被執行」這條線，從編譯一路講到類載入而中間不缺環節。
