# 併發工具與手寫併發題

## Learning goal

能對「多執行緒要一起配合、要傳上下文、要排隊等結果」這類場景，選對並用對四組併發工具（ThreadLocal、CountDownLatch/CyclicBarrier、CompletableFuture、ForkJoinPool），並能當場手寫生產者消費者、交替打印、DCL 與死鎖這幾道經典題，講清楚每一行為什麼這樣寫。

## Steps

1. [[learn/小哲讲八股/nodes/juc-tools-coding/threadlocal-thread-isolation|ThreadLocal 執行緒隔離：每個執行緒的私有抽屜]] — 講清空間換時間、Thread 持有 ThreadLocalMap、弱 Key/強 Value 的洩漏與 remove，以及 InheritableThreadLocal 在執行緒池中的污染與 TTL 解法
2. [[learn/小哲讲八股/nodes/juc-tools-coding/countdownlatch-cyclicbarrier|CountDownLatch 與 CyclicBarrier：一個等多與多個互等]] — 從火箭發射與集合發車兩個場景，分辨語義、底層（AQS 共享模式 vs ReentrantLock 加 Condition）與一次性／可循環
3. [[learn/小哲讲八股/nodes/juc-tools-coding/completablefuture-forkjoin|CompletableFuture 與 ForkJoinPool：非同步編排與分治]] — CAS 狀態機加 Treiber Stack 的回調鏈，以及 ForkJoinPool 與 ThreadPoolExecutor 的佇列與工作竊取差異
4. [[learn/小哲讲八股/nodes/juc-tools-coding/handwrite-producer-consumer|手寫生產者消費者：等待與通知的攻防]] — 用 synchronized 加 wait/notifyAll、固定容量倉庫，踩清楚 while 防虛假喚醒與釋放鎖
5. [[learn/小哲讲八股/nodes/juc-tools-coding/handwrite-alternating-print|手寫交替打印：精準喚醒與順序輪轉]] — ReentrantLock 加多個 Condition 與取模狀態機，對比 notify 與 notifyAll 在 N 執行緒下的差別（after step 4）
6. [[learn/小哲讲八股/nodes/juc-tools-coding/handwrite-dcl-and-deadlock|手寫 DCL 與死鎖：兩個跟順序有關的陷阱]] — volatile 如何擋住半初始化，以及相反加鎖順序如何製造死鎖、破壞哪個條件能拆掉它（after step 4）

## Lesson

前面幾個節點把「多執行緒為什麼出錯」拆得差不多了：執行緒怎麼跑、池子怎麼調度、鎖與記憶體模型怎麼保證互斥與可見。但真實工作裡，多執行緒很少只是「一個變數被兩條執行緒改」這麼單純。更常見的情況是幾條執行緒要一起完成一件事，而彼此需要協調：主線程要等好幾個子任務都做完才能繼續；同一條執行緒在不同方法之間要帶著使用者身分或事務資訊；主線程不想被一個慢查詢卡住，想把好幾件事丟出去並行做，最後再把結果合併起來。這些需求用鎖硬幹，不是寫不出來，就是既囉嗦又容易出錯。

所以 JDK 另外準備了一整套工具與寫法。這一課把它們分成兩半：前半是拿來用的工具，後半是得當場寫出來的題。工具這邊有四組。ThreadLocal 管的是「執行緒自己的資料」，它換個方向解決共享問題：不讓大家共用同一份變數，而是每個執行緒發一份私有副本，代價是要處理執行緒池複用後的髒資料與記憶體洩漏。CountDownLatch 與 CyclicBarrier 管的是「誰等誰」，一個是主線程等多個子任務，一個是所有人到齊再一起走；語義看起來很像，但底層一個走 AQS、一個走 ReentrantLock 加 Condition，能不能重複使用也不一樣。CompletableFuture 與 ForkJoinPool 則是另一條線：把任務丟出去、排好依賴關係，用無鎖的回調鏈與工作竊取讓多核跑滿，適合分治與非同步編排。

後半的手寫題，考的不是你背不背得出 API，而是你懂不懂等待與通知的機制。生產者消費者要你講清楚「滿了就睡、空了就睡、睡醒再檢查」，以及為什麼條件判斷一定要用 while 而不是 if。交替打印是把「喚醒」做得更精準：用多個 Condition 點名通知，而不是把所有人叫起來再一起搶鎖。最後一題收在兩個跟「順序」有關的陷阱：DCL 單例的坑在物件初始化與引用賦值的指令順序，所以需要 volatile；死鎖的坑在兩條執行緒相反方向的加鎖順序，所以要從四條件裡拆掉「循環等待」。

走完這六步，你應該能把「這幾條執行緒要怎麼配合」翻譯成一組具體工具，以及幾段講得出為什麼的程式碼，而不是臨場憑印象拼 API。
