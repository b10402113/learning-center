# 併發工具與手寫併發題

## Learning goal

選對並用對 ThreadLocal/CountDownLatch/CyclicBarrier/CompletableFuture/ForkJoin，並能手寫生產者消費者、DCL、交替打印、死鎖。

## Steps

1. [[learn/小哲讲八股/nodes/juc-tools-coding/threadlocal-and-context-propagation|ThreadLocal 與跨執行緒上下文：隔離與透傳]] — 講清楚 ThreadLocal 的空間換時間、弱 key 泄漏，以及 ITL 串號與 TTL 的 Capture/Replay/Restore
2. [[learn/小哲讲八股/nodes/juc-tools-coding/latch-vs-barrier|CountDownLatch 與 CyclicBarrier：一個等多還是互相等]] — 從語義、可複用性與底層實作選對會合工具
3. [[learn/小哲讲八股/nodes/juc-tools-coding/completablefuture-and-forkjoin|CompletableFuture 與 ForkJoinPool：非同步編排與分治]] — 講清楚 CAS 狀態機＋Treiber Stack 與工作竊取
4. [[learn/小哲讲八股/nodes/juc-tools-coding/wait-notify-coding-questions|手寫等待與喚醒：生產者消費者、交替打印與 N 執行緒輪轉]] — 用 while、notifyAll 與精確喚醒寫對三類協作題
5. [[learn/小哲讲八股/nodes/juc-tools-coding/dcl-singleton-volatile|DCL 單例：兩次檢查與 volatile 到底在防什麼]] — 講清楚兩次檢查與 1→2→3 重排防半初始化 (after step 4)
6. [[learn/小哲讲八股/nodes/juc-tools-coding/deadlock-four-conditions|死鎖：四個必要條件與相反順序取鎖]] — 實作死鎖示例並用四條件解釋與破壞 (after step 4)

## Lesson

這個節點把 Tier 1 的併發知識收束成「會用工具、也寫得出手寫題」。前三步是工具層：ThreadLocal 用空間換時間讓每個執行緒各拿一份私有副本，但它的 key 是弱引用、value 是強引用，在執行緒池裡會漏；而父子執行緒的上下文透傳，從 InheritableThreadLocal 到阿里的 TTL，講的正是「複製的時機」放錯地方會怎麼串號。接著 CountDownLatch 與 CyclicBarrier 用「一個等多」對上「互相等」，底層一個是 AQS 共享模式、一個是 ReentrantLock + Condition，選錯會讓一次性與可循環的語義對不上。再來 CompletableFuture 用 CAS 狀態機加無鎖棧把回調串起來，ForkJoinPool 則用每執行緒獨立雙端佇列與工作竊取，回答了「分治任務該用哪種池」。

後三步換成動手：等待與喚醒的手寫題其實只有一個核心——在臨界區裡用 while 反覆檢查條件，再用精確的喚醒傳接力棒，生產者消費者、三執行緒交替打印 ABC、N 執行緒順序打印都是同一個骨架的變形；DCL 單例則把戰場移到有序性，volatile 要擋的是 new 指令 1→3→2 重排造成的半初始化；死鎖示例用相反順序取鎖，剛好把互斥、請求與保持、不剝奪、循環等待四個必要條件一次演示完。走完六步，你應該能對著面試官把「選哪個工具、為什麼」與「這段程式為什麼這樣寫」都講成機制，而不是背 API。
