# 為什麼要池化：從 new Thread 到核心與非核心

<LearningGoal>
講出 new Thread 的三個問題、執行緒池的三個優勢、CPU/IO 密集的執行緒數公式，以及核心與非核心執行緒的彈性分工。
</LearningGoal>

## Lesson

多執行緒用來利用等待時間與多核 CPU，但執行緒有上下文切換、約 1MB 堆疊與鎖競爭三種成本，數量依 CPU 密集（核心數 + 1）或 IO 密集（2 × 核心數）設定；執行緒池以池化複用降低開銷，並用核心執行緒守常態流量、非核心執行緒扛峰值。
