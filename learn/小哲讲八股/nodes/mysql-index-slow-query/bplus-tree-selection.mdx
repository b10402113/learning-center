# 為什麼是 B+ 樹：從磁碟 I/O 反推索引結構

<LearningGoal>
能從「資料存在磁碟上」這個前提，淘汰二叉樹、Hash、B 樹，講出 B+ 樹贏在哪，並用 16KB 頁反推樹高與實際磁碟 I/O 次數。
</LearningGoal>

## Lesson

索引結構的選型本質是一場磁碟 I/O 的競賽：二叉樹樹太高、Hash 不支援範圍與排序、B 樹非葉也存資料而偏高，B+ 樹以「非葉只存 key」和「葉子雙向鏈表」勝出；以 16KB 頁推算，3 層約存 2000 萬行，根節點常駐記憶體後實際物理 I/O 常只有 1 次甚至 0 次。
