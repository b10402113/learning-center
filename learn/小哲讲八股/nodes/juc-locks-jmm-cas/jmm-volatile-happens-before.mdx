# JMM、volatile 與 happens-before：為什麼改了別的執行緒看不到

<LearningGoal>
能用原子性、可見性、有序性三個問題串起 JMM 的主記憶體與工作記憶體模型，講清楚 volatile 如何保證可見性與有序性卻不保證原子性，並用 happens-before 六條規則判斷兩個操作之間的可見性。
</LearningGoal>

## Lesson

併發的三個根本問題是原子性、可見性、有序性，分別來自執行緒切換、CPU 快取與指令重排序；JMM 用主記憶體與工作記憶體的抽象解釋可見性問題。volatile 保證可見性（寫強制刷回、讓別人快取失效）與有序性（記憶體屏障禁止重排序），但不保證原子性。happens-before 是 JMM 對可見性的承諾，強調結果可見而非物理先後，六條規則中最關鍵的是傳遞性。
