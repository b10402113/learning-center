# 兩個物件算不算一樣：==、equals 與 hashCode 契約

<LearningGoal>
能用 ==、equals、hashCode 三者的契約解釋「只重寫 equals 為什麼會弄壞 HashMap」，並講出包裝類快取、BigDecimal 與浮點數的比較陷阱。
</LearningGoal>

## Lesson

== 比位址或數值、equals 預設比位址而常被重寫成比內容，hashCode 契約則是雜湊容器正確性的前提——只重寫 equals 卻不重寫 hashCode，會讓 HashMap 與 HashSet 查不到或存重複；包裝類的比較要用 equals，BigDecimal 的數值比較要用 compareTo。
