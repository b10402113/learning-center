# ==、equals 與 hashCode 契約

<LearningGoal>
能分辨「比數值、比位址、比內容」三種等值判斷，並解釋為何只重寫 equals 會讓 HashMap/HashSet 取不到資料。
</LearningGoal>

## Lesson

`==` 比的是變數裡裝的東西：基本型別比數值，引用型別比位址。`equals` 預設等於 `==`，只有重寫過的類別才比內容。HashMap 依賴 `hashCode` 決定去哪裡找，再用 `equals` 確認是不是那一個，所以兩個 `equals` 相等的物件必須有相同的 `hashCode`；只重寫 `equals` 會讓 `get` 被帶到錯誤的桶，甚至讓 HashSet 重複存入。金額比較另有陷阱：BigDecimal 的 `equals` 連精度一起比，要比數值得用 `compareTo`，而浮點數本來就不適合表示金額。
