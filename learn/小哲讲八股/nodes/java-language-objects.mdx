# Java 語言與物件：一行 Java 到底做了什麼

## Learning goal

講清楚物件如何被建立與比較（值傳遞、==/equals、不可變、字符串池、包裝類、反射/代理/泛型），並俯瞰集合框架的選型。

## Steps

1. [[learn/小哲讲八股/nodes/java-language-objects/object-creation-passing|物件從哪來、怎麼傳：new、參照、值傳遞與複製]] — 從一個 new 說起：物件建在堆上、變數存的是值或參照，Java 只有值傳遞，淺拷貝會共用參照、深拷貝才真正切斷
2. [[learn/小哲讲八股/nodes/java-language-objects/equality-and-hashcode|兩個物件算不算一樣：==、equals 與 hashCode 契約]] — 分辨 == 比地址/數值、equals 比內容，講清 hashCode 契約為何是 HashMap 正確性的前提，並帶出包裝類快取、自動裝箱與 BigDecimal 的比較陷阱（after step 1）
3. [[learn/小哲讲八股/nodes/java-language-objects/strings-and-immutability|字串為什麼不可變：常量池、intern 與拼接選型]] — 從不可變設計推出常量池與 intern 的行為，算清 new String 建了幾個物件，並決定何時用 StringBuilder 或 StringBuffer（after step 1）
4. [[learn/小哲讲八股/nodes/java-language-objects/reflection-proxy-generics|執行時看穿型別：反射、動態代理與泛型擦除]] — 反射慢在哪、怎麼優化，JDK 動態代理與 CGLIB 各靠介面或繼承，泛型只活在編譯期、擦除後為何不能有泛型陣列（after step 1）
5. [[learn/小哲讲八股/nodes/java-language-objects/collections-frame-and-list|集合框架地圖與 List 選型]] — 分清 Collection 與 Map 兩大派系，從底層結構、擴容成本與 CPU 快取比較 ArrayList／LinkedList／CopyOnWriteArrayList，並認識 fail-fast 與 fail-safe（after steps 1–2）
6. [[learn/小哲讲八股/nodes/java-language-objects/hashmap-and-concurrent-map|HashMap 兩代結構與併發 Map]] — 比較 1.7 與 1.8 的結構、插入與擴容，解釋 8/6 樹化閾值與 0.75 負載因子、1.7 死循環，再看 ConcurrentHashMap 的鎖粒度演進與 size 統計（after steps 2、5）

## Lesson

寫 Java 的人每天都在 new 物件、比字串、往 List 裡塞東西，這些動作熟到幾乎不過腦。偏偏面試的第一輪就從這裡開始問：`Integer` 為什麼 `==` 有時候是 true 有時候是 false、只重寫 `equals` 為什麼會讓 `HashMap` 查不到資料、`new String("abc")` 到底建了幾個物件、`HashMap` 為什麼要從鏈表演進到紅黑樹。這些問題的共同點是，答案都不在 API 的表面，而在物件被建立、被比較、被放進容器時，JVM 實際做了什麼。

這個節點把「一行 Java 到底做了什麼」拆成六步。第一到第四步處理語言層：物件在哪裡、參照怎麼傳、什麼叫做「一樣」、字串為什麼不可變、型別資訊在編譯期與執行期各剩多少。這些概念不是各自獨立的知識點，而是同一條線的不同切面。`equals` 與 `hashCode` 的存在，本來就是要拿來當雜湊容器的鍵，所以第五、六步很自然地轉進集合框架：先看兩大派系與 List 的選型，再深入 `HashMap` 的兩代結構與 `ConcurrentHashMap` 的鎖粒度。

走完之後，你應該能用「資料放在哪、比較靠什麼、容器怎麼找」這三個問題，串起一整套 Java 基礎題的回答，而不是背下每一題的標準答案。
