# Java 語言與物件：一行 Java 到底做了什麼

## Learning goal

講清楚物件如何被建立與比較（值傳遞、==/equals、不可變、字符串池、包裝類、反射/代理/泛型），並俯瞰集合框架的選型。

## Steps

1. [[learn/小哲讲八股/nodes/java-language-objects/object-creation-passing|物件的建立、傳遞與複製]] — 用棧幀與包裝類講清「Java 只有值傳遞」、裝箱快取與淺/深拷貝
2. [[learn/小哲讲八股/nodes/java-language-objects/equality-and-hashcode|==、equals 與 hashCode 契約]] — 分辨數值/位址/內容三層等值，講清 hashCode 契約為何會壞掉哈希集合（after step 1）
3. [[learn/小哲讲八股/nodes/java-language-objects/strings-and-immutability|String 不可變、常量池與拼接選型]] — 不可變、常量池、new String 物件數、intern 版本與 StringBuilder/Buffer 選型（after step 2）
4. [[learn/小哲讲八股/nodes/java-language-objects/reflection-proxy-generics|反射、動態代理與泛型擦除]] — 框架如何靠反射與動態代理運作、JDK 與 CGLIB 代理的取捨、泛型為何不能配陣列（after step 1）
5. [[learn/小哲讲八股/nodes/java-language-objects/collections-framework-and-list|集合框架地圖與 List 選型]] — Collection/Map 地圖、List 家族結構取捨、1.5 倍擴容、CPU 快取與 fail-fast/fail-safe（after step 2）
6. [[learn/小哲讲八股/nodes/java-language-objects/hashmap-and-concurrent-map|HashMap 演進與併發 Map]] — HashMap 1.7→1.8、紅黑樹 8/6 閾值與 0.75 負載因子、1.7 死循環、ConcurrentHashMap 鎖粒度演進（after step 5）

## Lesson

一行 Java 程式碼底下藏著好幾層機制：`new` 在堆上配置物件、參數透過棧幀複製傳遞、`==` 比的是位址或數值、`equals` 才可能比內容。這個節點從「一個物件被建立、傳遞、複製、比較」這條主線出發，把 Java 語言層最常被追問的幾個機制串起來，再往上看整個集合框架如何建立在這些機制之上。

前半段先把語言的底層講透：Java 只有值傳遞，引用型別傳的是位址的副本，所以改屬性會影響原物件、重新賦值卻不會；基本型別與包裝類之間的自動裝箱拆箱是編譯器插進去的語法糖，而 Integer 快取池會讓 `==` 的結果忽真忽假。接著講等值判斷的三個層次（數值、位址、內容）與 `hashCode`/`equals` 契約，這條契約沒守好，HashMap 和 HashSet 就會直接取不到資料。String 是這條線的延伸：不可變、常量池、`new String` 的物件數、`intern` 的版本差異，全都繞著「位址 vs 內容」打轉。

後半段換到框架視角。反射讓程式在運行時取得類別資訊並呼叫方法，動態代理讓 Spring 的 AOP 得以在運行時生成增強物件，泛型擦除則解釋了為什麼編譯期型別檢查過關、運行時卻可能冒出 ClassCastException。最後俯瞰整個集合框架：Collection 與 Map 兩大派系各有什麼結構、ArrayList 與 LinkedList 的取捨、HashMap 從 1.7 到 1.8 的演進，以及 ConcurrentHashMap 如何把鎖粒度一步步縮小。
