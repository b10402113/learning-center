# Java 語言與物件：一行 Java 到底做了什麼

## Learning goal

講清楚物件如何被建立與比較（值傳遞、==/equals、不可變、字符串池、包裝類、反射／代理／泛型），並俯瞰集合框架的選型。

## Steps

1. [[learn/小哲讲八股/nodes/java-language-objects/pass-by-value-and-equality|一行 Java 傳了什麼？值傳遞與等值判斷]] — 講清楚 Java 只有值傳遞、== 與 equals 的分層，以及 hashCode/equals 契約與 BigDecimal 比較
2. [[learn/小哲讲八股/nodes/java-language-objects/immutability-strings-wrappers|不可變、字串池與包裝類：物件怎麼被建立與複製]] — 講清楚 String 不可變與常量池、StringBuilder/StringBuffer、包裝類與自動裝箱，以及深淺拷貝 (after step 1)
3. [[learn/小哲讲八股/nodes/java-language-objects/reflection-proxy-generics|反射、代理與泛型擦除：執行時才看穿的物件]] — 講清楚反射的開銷與優化、JDK/CGLIB 動態代理、SPI 與泛型擦除 (after step 1)
4. [[learn/小哲讲八股/nodes/java-language-objects/collections-overview-and-list|集合框架與 List 選型：ArrayList、LinkedList 怎麼選]] — 用集合框架全景與 CPU 快取視角，做出 List 與 CopyOnWriteArrayList 的選擇 (after steps 1-2)
5. [[learn/小哲讲八股/nodes/java-language-objects/hashmap-internals|HashMap 內核：從 1.7 到 1.8 的結構與擴容]] — 講清楚 1.7→1.8 結構差異、紅黑樹閾值、負載因子與 1.7 死循環 (after step 4)
6. [[learn/小哲讲八股/nodes/java-language-objects/concurrenthashmap-and-iterator-safety|併發容器選型：ConcurrentHashMap 與 fail-fast/fail-safe]] — 講清楚 CHM 1.7→1.8 演進、禁 null 與 size 機制，以及迭代安全選型 (after step 5)

## Lesson

這個節點處理「日常最熟、卻最容易講不清」的一層：Java 的物件語義。第一課先把「一行程式傳了什麼」講死——Java 只有值傳遞，參考型別傳的是位址的副本；接著把 ==/equals/hashCode 的契約與金額比較的坑釘牢。第二課從不可變設計出發，串起 String 常量池、StringBuilder/Buffer、包裝類與自動裝箱，最後補上深淺拷貝。第三課換到執行期的視角：反射為什麼慢、代理怎麼在執行時生成、泛型為什麼被擦除。

看完「物件怎麼被比較與生成」之後，後三課轉向集合選型。先用一張全景圖分開 Collection 與 Map 兩派，再從隨機訪問、增刪成本與 CPU 快取的角度比較 ArrayList 與 LinkedList，並帶出 CopyOnWriteArrayList。接著深入 HashMap：1.7 的頭插法為什麼會在併發擴容時成環，1.8 又用紅黑樹、尾插與高位運算解決了什麼。最後一課處理併發場景，講清楚 ConcurrentHashMap 從分段鎖到 CAS+synchronized 的演進、為什麼禁 null、size 怎麼做熱點分散，以及 fail-fast 與 fail-safe 的差別。
