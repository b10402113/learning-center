# MySQL 與 Redis 的一致性：為什麼先寫庫、後刪快取

<LearningGoal>
講清楚旁路快取模式下為什麼刪除而非更新、為什麼先寫庫後刪快取，以及延遲雙刪、MQ 重試等最終一致性補償。
</LearningGoal>

## Lesson

MySQL 與 Redis 的一致性用旁路快取追求最終一致，標準順序是先更新資料庫再刪除快取；刪除而非更新可避開併發下後寫先至的永久髒資料，先寫庫後刪快取能把不一致窗口縮到最小，刪除失敗再用 MQ 重試、延遲雙刪或 Canal 監聽 Binlog 兜底。
