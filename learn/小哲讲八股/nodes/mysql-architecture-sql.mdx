# MySQL 架構與一條 SQL 的生命週期

## Learning goal

講清楚 Server 層與引擎層分工、一條 SQL 從客戶端到返回的完整鏈路、InnoDB 與 MyISAM 的本質差別。

## Steps

1. [[learn/小哲讲八股/nodes/mysql-architecture-sql/logical-architecture|邏輯架構：Server 層與儲存引擎層的腦手分工]] — 兩層架構、四個 Server 模組與插件式引擎各負責什麼
2. [[learn/小哲讲八股/nodes/mysql-architecture-sql/sql-lifecycle|一條 SQL 的生命週期：六道關卡走一遍]] — 從連線到返回，逐關拆解一條 SQL 的完整鏈路（after step 1）
3. [[learn/小哲讲八股/nodes/mysql-architecture-sql/innodb-vs-myisam|InnoDB 與 MyISAM：從五個維度講清本質差別]] — 事務、鎖、索引結構、外鍵、COUNT(*) 與選型（after step 1）
4. [[learn/小哲讲八股/nodes/mysql-architecture-sql/io-first-diagnosis|磁碟 I/O 決定論：把架構變成一套診斷語言]] — 用「減少磁碟 I/O」串起分層與引擎選型，並定位慢在哪一層（after steps 2–3）

## Lesson

這一課把 MySQL 拆成兩層來理解。上層是 Server 層，負責「動腦」——管理連線、解析 SQL、決定用哪個索引、按計畫呼叫下層；下層是插件式的儲存引擎層，負責「動手」——真正把資料從磁碟讀出來、寫回去。一條 SQL 從客戶端連線到返回結果，其實就是穿過這兩層的一個固定流程：連接器、查詢快取（8.0 已移除）、分析器、優化器、執行器，最後交給儲存引擎取資料。

理解這條鏈路之後，就能進一步比較不同的儲存引擎。MySQL 預設的 InnoDB 支援事務與行級鎖，主鍵用聚簇索引（葉子節點直接存完整資料行）；早期常見的 MyISAM 則不支援事務、只有表級鎖，索引與資料分開存放、靠物理位址定位。這個差別決定了兩者在併發、崩潰恢復與主鍵選型上的所有不同。

最後一步把整門 MySQL 課的主線接起來：磁碟 I/O 是資料庫最慢的一環，所以幾乎所有設計——Buffer Pool、B+ 樹、WAL、聚簇索引、覆蓋索引——都是在想辦法減少磁碟 I/O。拿到一條慢 SQL 時，你可以沿著這條鏈路問「慢在哪一層」，而不是只背答案。
