# Code review：Codex review 與第二個模型

## Learning goal

能用 Codex review（含自訂規則）與第二個模型審查，補上模型自審自己的盲點。

## Steps

1. [[learn/cordex-web/nodes/code-review-surfaces/codex-review-mode|Codex review：不帶對話脈絡的獨立審查者]] — 認識 Codex review 這個獨立 instance、兩種審查對象與自訂規則
2. [[learn/cordex-web/nodes/code-review-surfaces/self-review-blind-spot|為什麼模型審自己的 code 有根本盲點]] — 理解自審為什麼先天不足，所以需要第二個模型（after step 1）
3. [[learn/cordex-web/nodes/code-review-surfaces/second-model-review|跑一次第二模型審查：Claude 審 Codex]] — 實際在 Codex 裡叫第二個模型做 code review（after step 2）
4. [[learn/cordex-web/nodes/code-review-surfaces/adversarial-review-tradeoff|Adversarial 互審：多輪吵架，還是單次審查就夠？]] — 判斷何時值得花 token 讓兩個模型多輪互辯（after step 3）

## Lesson

Codex 內建 code review：它會用一個獨立的 instance、不帶你這次對話的脈絡，直接審 uncommitted changes 或跟某條 base branch 的差異。這件事本身很有用，但你很快就會撞到一個根本限制——同一個模型審自己寫的程式碼，視角跟訓練方式都是同一套，很多問題它天生看不見。這條限制的實務解法，是把第二個模型（例如 Claude）拉進來當審查者，它幾乎每次都能找到 Codex 漏掉的東西。這個節點沿著「工具 → 它為什麼不夠 → 怎麼補 → 補到什麼程度才划算」四步走：先認清 Codex review 是什麼、再看自審盲點的機制、接著實際跑一次第二模型審查並選對模型、最後用取捨判斷要不要升級成昂貴的 adversarial 多輪互審。
