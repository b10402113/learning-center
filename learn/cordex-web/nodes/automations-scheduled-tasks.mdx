# Automations：排程與常駐維護

## Learning goal

能用 scheduled tasks 串接 plugin 做每日工作，並知道自動化在公開站上的限制。

## Steps

1. [[learn/cordex-web/nodes/automations-scheduled-tasks/what-automations-solve|Automations 解掉什麼問題：讓 app 不用接 live 資料源也能保持最新]] — 說出 automation 是什麼、為何存在，以及它和連 live 資料源的差別
2. [[learn/cordex-web/nodes/automations-scheduled-tasks/creating-and-scheduling-an-automation|建立一個 scheduled automation：定時 prompt、排程與編輯]] — 從對話或排程頁開出一個定時 prompt，設定每日／每週／自訂時段（after step 1）
3. [[learn/cordex-web/nodes/automations-scheduled-tasks/choosing-run-mode-and-cadence|跑在同一個對話還是每次開新對話：run mode 與排程節奏的抉擇]] — 依任務性質選對 run mode 與排程節奏（after step 2）
4. [[learn/cordex-web/nodes/automations-scheduled-tasks/chaining-plugins-for-daily-work|串接 plugin 做每日工作：Gmail、Slack、GitHub 的常駐檢查]] — 安裝 plugin 並寫出每日檢查的 automation（after step 2）
5. [[learn/cordex-web/nodes/automations-scheduled-tasks/public-site-and-scope-limits|自動化做不到的事：公開站限制與 Sites 的邊界]] — 說出公開站為何不能自動重新部署，以及 Sites 只出版 web 的影響（after steps 2、4）

## Lesson

Automation 是 Codex 裡「照排程重複跑同一個 prompt」的功能：你先寫好一段指令，指定每天、每週或某個自訂時段執行，Codex 時間一到就自己跑一次。它解掉的問題是「內容會過期」——如果你做了一個會用到 Gmail、Slack 或 GitHub 資料的 app，那些資料每天都在變，但你不會想叫使用者自己去連這些外部服務；automation 讓你用 plugin 把資料抓進來、定期更新，app 就一直是新的。

這個節點把 automation 拆成五步。第一步先建立心智模型：automation 是什麼、它為什麼存在，以及它和「連上 live 資料源」根本上的差別。第二步動手做：從一段對話或排程頁建立 automation，把 prompt 與每日／每週／自訂時段的排程設好，之後還能回來查看與編輯。第三步處理兩個容易選錯的設定——這次要沿用原本的對話，還是每次開一條新對話；以及排程該排得多密。第四步是 automate 真正的主力用法：加上 Gmail、Slack、GitHub 這類 plugin，讓它每天定時替你檢查待審 PR、彙整 daily brief 這種事。最後一步講清楚它的邊界：公開網站不能靠 automation 自動重新部署（因為資料要先確認能不能公開分享），而 Sites 只出版 web，所以 companion mobile app 得走另一條發佈流程。

走完之後，你手上會有幾個常駐的例行工作——每天自動跑、替你盯著某些事——而不是什麼都得手動記得去做；同時你也會知道哪些事自動化碰不得。
