# Fixture 資料契約：穩定 ID、refresh 與 reset

<LearningGoal>
能列出一份生成式 app 必須遵守的 fixture 契約：標記虛構、固定時間基準、穩定 ID、refresh 與 reset 的差別，以及手動建立的資料永遠不被覆蓋。
</LearningGoal>

## Lesson

fixture 資料契約是對假資料的一組承諾：共同欄位標記資料虛構、固定 `referenceDate`（`2026-08-11T09:30:00-05:00`）與 `timeZone`（`America/Chicago`）、每筆紀錄有穩定 ID；slack／gmail／calendar 唯讀、tasks 可建立與更新；refresh 只補上缺少的紀錄、保留狀態、絕不覆蓋手動任務，reset 則還原成原始虛構資料集，而 app 必須完全靠這些 fixtures 運作、不需真實帳號。
