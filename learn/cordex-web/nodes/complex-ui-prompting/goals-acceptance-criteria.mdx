# Goal 與驗收條件：讓 Codex 不在一次 pass 後就停

<LearningGoal>
能說明 goal 與驗收條件為什麼能讓 Codex 長時間自走，以及前端視覺與 eval 兩種驗收條件長什麼樣。
</LearningGoal>

## Lesson

goal 是「一段指示＋一組驗收條件」的機制，讓 Codex 盯著成果反覆迭代、直到條件成立才停，並能在跑動中轉向；驗收條件有兩種型態——可自動計算的單一門檻（如 eval 的 95%）與多條件交織的完整清單——前端用視覺條件，回答品質用 golden set 加 LLM 評審。
