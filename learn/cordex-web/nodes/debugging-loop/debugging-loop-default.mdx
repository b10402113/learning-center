# 為什麼除錯迴圈才是 Codex 的默認工作流

<LearningGoal>
能說出為什麼「重現→診斷→修→驗證」才是 Codex 的默認工作流，以及為什麼「重現」必須走在最前面。
</LearningGoal>

## Lesson

除錯迴圈（重現→診斷→修→驗證）才是和 Codex 一起開發的默認工作流，「一個 prompt 一次到位」只是示範時的例外；重現必須先行，因為只有穩定重複的問題才值得追，而 Codex 會先跑一次 build 才宣告完成，所以可以把診斷與修復交給它。
