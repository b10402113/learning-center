# Plan mode 與 grilling：逼出決策

## Learning goal

能判斷何時用原生 plan mode、何時改用 grill-me／grill-with-docs 逼出 upfront 決策與 back pressure。

## Steps

1. [[learn/cordex-web/nodes/plan-mode-and-grilling/native-plan-mode|原生 plan mode：先定義、還不要動手]] — 說出原生 plan mode 在做什麼、和直接開工的差別，以及它為什麼不夠
2. [[learn/cordex-web/nodes/plan-mode-and-grilling/grill-me-design-tree|grill-me：用決策樹把設計逼到共享理解]] — 搞懂「持續訪談」、決策樹，以及「每個問題附建議」的問答機制（after step 1）
3. [[learn/cordex-web/nodes/plan-mode-and-grilling/grill-with-docs-domain-modeling|grill-with-docs：把決策寫成 context.md 與垂直切片]] — 看 grilling 如何串起 domain modeling，把答案落成可查的決策紀錄（after step 2）
4. [[learn/cordex-web/nodes/plan-mode-and-grilling/install-and-run-grilling|動手裝好並跑一輪 grilling]] — 照著安裝 skills、對一個功能發起 grilling、限兩輪拿到 up-front 決策（after step 3）
5. [[learn/cordex-web/nodes/plan-mode-and-grilling/plan-vs-grill-decision|該用 plan mode 還是 grilling？]] — 用判別問句與反例，當場選對逼出決策的方式（after steps 1–4）

## Lesson

Codex 有兩種「先別動手、先把事情想清楚」的姿勢：一種是原生內建的 plan mode，一種是社群寫的 grilling skill。多數人只認識前者，於是把 plan mode 產出的一份大計畫當成設計完成——結果等到實作才發現，裡面的關鍵決策根本沒被問過。

這一節課要建立的判斷力，是看懂兩者解決的是同一個問題：**如何在下程式碼之前，把腦中的設計逼成明確、可驗證的決策**。plan mode 提供一個定義階段的容器，但它問的問題不夠；grilling 用一連串附帶建議的問題，把設計展開成一棵決策樹，再用 domain modeling 把答案寫成 context.md，讓決定在後續對話與 compaction 之後仍然留得住。走完五步，你會知道 plan mode 的邊界在哪、grilling 的問答機制怎麼運作、怎麼把它裝起來實跑一輪，最後能在一個新功能面前，當場選對該用哪一種。
