# Permission mode：安全與自動化的取捨

## Learning goal

能選對 permission mode（approve-for-me／full access／自訂），在安全與自動化之間取捨。

## Steps

1. [[learn/cordex-web/nodes/permission-modes/permission-tradeoff|Permission mode 在解什麼問題：自動化與安全的那條線]] — 說出為什麼要有核准關卡，以及「全部要你按」與「全開」兩種極端各自壞在哪
2. [[learn/cordex-web/nodes/permission-modes/approve-for-me|Approve for me：為什麼它是預設的最佳中位數]] — 解釋 approve-for-me 用另一個安全檢查執行緒做判斷的機制（after step 1）
3. [[learn/cordex-web/nodes/permission-modes/full-access-and-custom|Full access 與自訂權限：什麼時候可以全開，什麼時候不行]] — 四種模式的機制、預設與適用邊界，以及 full access 的可接受條件（after step 1）
4. [[learn/cordex-web/nodes/permission-modes/choosing-a-mode|怎麼選 permission mode：一份可操作的決策規則]] — 依情境與並行量選模式，並養成對應的操作習慣（after steps 2–3）

## Lesson

Permission mode 是 Codex 這條迴圈上的那道閘門。Codex 會執行指令、改檔案、安裝套件，桌面版甚至能碰到你電腦裡的檔案與應用程式；這些動作裡有些完全無害，有些一旦做錯就收不回來。閘門開得太大，它可能在你不注意時刪掉東西；關得太緊，每個指令都要你親自按下去，那你就得一直盯著螢幕，也就失去了把工作交給 agent 的意義。

這個節點要建立的是那條取捨線：先理解核准關卡存在的理由（為了解決什麼問題），再拆開「approve for me」這個預設值背後真正的機制——它不是簡單的放行，而是讓 Codex 用另一個執行緒先判斷指令安不安全，安全才自動核准，不安全才回頭問你。接著把四種模式的機制與適用邊界列清楚，特別是 full access 這種「完全不問」的模式，只有在隔離、丟掉也無所謂的機器上才合理。最後收在一份決策規則上：面對自己的情境，該選哪一種，又該注意哪些操作習慣。
