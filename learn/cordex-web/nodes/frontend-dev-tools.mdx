# 桌面 app 的前端開發工具面

## Learning goal

能用內建瀏覽器、CDP、標註工具、內建生圖與 PR 分頁，就地完成前端開發與視覺驗證。

## Steps

1. [[learn/cordex-web/nodes/frontend-dev-tools/project-scoped-workflow|把 Codex 綁進專案資料夾，並在 app 內把東西跑起來]] — 建立綁定本地資料夾的 project，發 prompt、跑起來、在內建瀏覽器看到它
2. [[learn/cordex-web/nodes/frontend-dev-tools/in-app-browser-and-annotation|內建瀏覽器與標註：把視覺回饋釘在螢幕上的那個元素]] — 內建瀏覽器多出來的能力，以及標註如何把模糊回饋變成可指涉的修改（after step 1）
3. [[learn/cordex-web/nodes/frontend-dev-tools/cdp-debugging|CDP：讓 Codex 看得懂 log 與 network]] — 用 Chrome DevTools Protocol 把除錯從猜測變成查資料（after step 2）
4. [[learn/cordex-web/nodes/frontend-dev-tools/builtin-image-generation|內建生圖：先用訂閱生一張視覺方向，再開始蓋]] — 用訂閱額度生視覺資產，並在動工前驗證視覺方向（after step 1）
5. [[learn/cordex-web/nodes/frontend-dev-tools/pr-tab-and-repo-conventions|PR 分頁與把專案知識寫進 repo]] — PR 分頁、整合終端機，以及 agents.md 與 repo skills 的定位（after step 1）

## Lesson

Codex 桌面 app 對前端開發的價值，不在單一功能，而在「不用離開 app」：專案綁本地資料夾、在 app 內跑起 dev server、用內建瀏覽器看到畫面、把視覺問題標在元素上、需要時查 log 與 network、要圖就生圖、同事的 PR 也在同一個視窗裡 review。這一整串讓「改一下、看一下、再改一下」的迴圈不必在多個工具與視窗之間切換。

這個節點把那個迴圈拆成五步。第一步先把工作綁進一個本地資料夾的 project，這是後面所有工具能作用的前提；第二步講內建瀏覽器與標註工具，重點是它把「這個東西看起來不對」這種模糊回饋，變成釘在特定元素上、甚至直接改 CSS 的具體指令；第三步講 CDP，讓 Codex 讀得到 log 與 network，除錯就不必靠猜；第四步講內建生圖，它用的是你既有的訂閱額度，可拿來生網站要用的視覺資產，也可在動工前先產一張視覺方向讓你確認；第五步是查閱性質的收尾，整理 PR 分頁、整合終端機，以及把重複指示寫進 repo 的兩個位置。

走完之後，你手上會有一套「就地做前端」的標準動線，而不是每次都在想「這一步該開哪個工具」。
