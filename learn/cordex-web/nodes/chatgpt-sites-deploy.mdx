# ChatGPT Sites：部署與託管

## Learning goal

能把 prompt 或既有專案用 Sites 部署上線，設定網域、環境變數、驗證與版本。

## Steps

1. [[learn/cordex-web/nodes/chatgpt-sites-deploy/what-sites-is|Sites 是什麼：把託管、驗證與儲存都收進 Codex]] — 說出 Sites 替 Codex 解掉哪些託管問題，以及它的帳號前提
2. [[learn/cordex-web/nodes/chatgpt-sites-deploy/deploy-prompt-or-project|從 prompt 或既有專案部署上線]] — 動手把一個 prompt 或既有專案變成一個有 URL 的網站，並會改版重部署（after step 1）
3. [[learn/cordex-web/nodes/chatgpt-sites-deploy/sites-settings-reference|Sites 設定面：存取、網域、環境變數、儲存與分析]] — 查出一份 Sites 設定選項與限制的清單（after step 2）
4. [[learn/cordex-web/nodes/chatgpt-sites-deploy/when-to-use-sites-and-urls|什麼時候用 Sites、什麼時候自架：網域與版本的取捨]] — 用判別條件選對託管方式、網域與版本策略（after steps 1–3）

## Lesson

做完一個 landing page 或 dashboard 之後，下一個問題幾乎一定會冒出來：要怎麼讓別人點得到？傳統做法是另外找一個主機商、開帳號、設定部署流程，靜態頁或許還單純，但只要需要存資料、要資料庫、要公司 SSO 登入，就得再串好幾個額外服務。ChatGPT Sites 的定位，就是把這一整段「從點子到能分享」的路收進 Codex 裡——部署、分享、儲存、驗證都由 Sites 代管，你不必離開 Codex 去接另一個供應商。

這個節點把 Sites 拆成四步。第一步先建立心智模型：Sites 到底接手了哪些事、它的起點有兩種（一個 prompt 或一個既有專案）、以及至少要 ChatGPT Plus 才能發佈。第二步是核心操作：把 prompt 或既有專案變成一個有 URL 的網站，知道發佈、編輯與重新部署各自會發生什麼。第三步是一份可查閱的設定清單：存取控制（公開、SSO、workspace groups、ChatGPT identity）、自訂網域、環境變數、內建的結構化與 blob 儲存，以及基本分析。第四步是判斷：什麼時候該用 Sites、什麼時候自架更合適，以及產生的 URL、自訂網域與版本之間怎麼取捨。

走完之後，你應該能把「已經在 Codex 裡做出來的東西」直接推到一個可分享的網址，而不是卡在部署這一關。
