# Landing page：不要產出 AI 味

## Learning goal

能從一個 brief 生出不「AI 味」、有視覺方向的 landing page，並拆解其 prompt 結構。

## Steps

1. [[learn/cordex-web/nodes/landing-page-non-generic-output/avoid-generic-output|為什麼不給方向，網站就長得像 AI 生的]] — 先看見「AI 味」從哪來：模型沒有方向就退回自己的預設
2. [[learn/cordex-web/nodes/landing-page-non-generic-output/anti-slop-skills|把品味寫成 skill：write-practical-copy 與 design-ui-with-restraint]] — 兩個 repo skill 各防哪一種 AI 味（after step 1）
3. [[learn/cordex-web/nodes/landing-page-non-generic-output/choosing-a-visual-direction|自己定視覺方向，還是跟 Codex 一起想？]] — 何時自己把方向寫進 brief、何時用 voice mode 與三個概念一起決定（after step 1）
4. [[learn/cordex-web/nodes/landing-page-non-generic-output/landing-page-prompt-anatomy|拆解 landing-page prompt 的六個區塊]] — 一份可查閱的 prompt 結構清單（after steps 2–3）
5. [[learn/cordex-web/nodes/landing-page-non-generic-output/build-from-a-brief|從 brief 生出 landing page：完整操作]] — 從建立 project 到發布的完整程序（after step 4）

## Lesson

多數人第一次請 Codex 生 landing page，會得到一個「看起來沒錯、但一眼就認得出是 AI 生的」頁面：置中的大標、紫色漸層、三張卡片、幾句聽起來很宏亮卻沒說什麼的文案。問題不在模型不會做網站，而在沒有人告訴它「這個網站該長什麼樣」。模型一旦沒有方向，就會退回自己最習慣的預設；而所有人的預設都一樣，於是人人的網站也長得一樣。

這個節點要處理的，就是「怎麼不讓 Codex 產出那種預設」。它有兩條互相補強的路線。第一條是**事先給方向**：在 brief 裡講清楚視覺調性、材質、配色與字體，甚至不確定時先跟 Codex 腦力激盪出幾個概念再挑一個。第二條是**把品味編碼成規則**：用 `write-practical-copy` 與 `design-ui-with-restraint` 這兩個 repo skill，把「AI 味的文案」與「多餘的介面資訊」擋在產出之前。兩條路線合起來，才是 landing page prompt 真正在做的六件事。

五步走完，你會先看懂「AI 味」的來源，接著認識那兩個 skill，再學會怎麼取得一份夠清楚的視覺方向，然後能逐塊拆解一份可重用的 prompt，最後親手把一個 brief 變成一個不 generic 的 landing page。
