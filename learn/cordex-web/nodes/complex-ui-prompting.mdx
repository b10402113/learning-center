# 高複雜度 UI：分階段 prompt 與 goal

## Learning goal

能用分階段 prompt 與 goal 做出高複雜度（3D／動畫）的前端體驗。

## Steps

依序讀：先建立「為什麼要拆階段」的心智模型，再依三個階段各學一個操作，中間補上 goal 的機制。

1. [[learn/cordex-web/nodes/complex-ui-prompting/staged-complex-ui|為什麼高複雜度 UI 要拆階段]] — 理解複雜 3D／動畫體驗為何要分階段，以及三階段的目標
2. [[learn/cordex-web/nodes/complex-ui-prompting/structured-experience-prompt|寫第一階段的大型結構化 prompt]] — 照段落骨架寫出描述整個體驗的長 prompt（after step 1）
3. [[learn/cordex-web/nodes/complex-ui-prompting/generated-assets-iteration|第二階段：在既有 build 上疊生成資產]] — 用針對性 prompt 疊上生成資產，不重新設計（after step 2）
4. [[learn/cordex-web/nodes/complex-ui-prompting/goals-acceptance-criteria|Goal 與驗收條件：讓 Codex 不在一次 pass 後就停]] — 認識 goal 與驗收條件，以及前端與 eval 兩種用法（after step 3）
5. [[learn/cordex-web/nodes/complex-ui-prompting/polish-goal-validation-loop|打磨 goal 的驗證迴圈]] — 把「完成」定義成可重複執行的多 viewport 驗證清單（after step 4）

## Lesson

要做一個像「One Turning World」這種捲動驅動的 3D 體驗——一顆持續存在的球體、五座城市、二十五個捲動狀態、太陽軌跡、四季氛圍——你不會想在一個 prompt 裡把它一次做完。這不是模型不夠強，而是這類東西的第一版幾乎不可能一次到位：動畫很難一次抓準，生成資產更是難上加難，所以做法是把它拆成可控的階段，每一階段只解決一個問題。

這個節點沿著三階段走：先用一則大型結構化 prompt 把整個體驗的骨架講清楚（結構、規格、品質要求），讓第一版先能跑；再用一則針對性 prompt 把生成的資產疊到既有的 3D build 上，而不是重新設計；最後交給 goal，讓 Codex 對著一份可重複執行的驗收清單長時間自走，反覆打磨到真的好看為止。走完之後，你手上不只是一段能跑的程式碼，而是「大體驗怎麼切、長 prompt 怎麼寫、goal 什麼時候開」這套可搬去下一個專案的流程。會用到的環境配套——把 permission 設成 approve for me、用 pets 追蹤跑動——也一併講清楚。
