# 既有 codebase：加功能並開 PR

## Learning goal

能在既有 repo 加一個功能並自動開 PR，附上多斷點的 before／after 視覺證據。

## Steps

1. [[learn/cordex-web/nodes/existing-codebase-feature-to-pr/existing-codebase-contract|既有 codebase 的貢獻契約：只說要什麼]] — 認出共享 repo 的貢獻契約：你只描述結果，repo 提供做法
2. [[learn/cordex-web/nodes/existing-codebase-feature-to-pr/exploring-with-codex|動手探索既有專案並送功能 prompt]] — 把專案跑起來、用 Codex 看結構，送出一段只講結果的功能 prompt（after step 1）
3. [[learn/cordex-web/nodes/existing-codebase-feature-to-pr/how-the-feature-lands|功能為何能長得跟既有 dashboard 一樣]] — 拆開 AGENTS.md → skill → 範例元件與資料契約的傳導鏈（after step 2）
4. [[learn/cordex-web/nodes/existing-codebase-feature-to-pr/how-much-to-specify|要給多少指引：只說要什麼，還是指定設計系統]] — 用「repo 有沒有編碼」決定 prompt 的顆粒度（after step 3）
5. [[learn/cordex-web/nodes/existing-codebase-feature-to-pr/pr-with-visual-evidence|開一個附視覺證據的 PR]] — 在 AGENTS.md 定義證據規則，讓 Codex 自動開出多斷點 before／after 的 PR（after step 3）

## Lesson

在既有 codebase 加功能，跟從零開始做一個 landing page 是兩種不同的工作。差別不在程式碼，而在 ownership：這個 repo 不是你的，還有別人也在貢獻，而你手上只有一部分 context。Codex 能看到的也只有 repo，所以「怎麼做才對」這件事必須先被寫進 repo，它才可能照做。

這一節課走完一遍端到端的貢獻流程。第一步先講清楚貢獻契約——你只說要什麼，把「怎麼做」交給 repo 裡的 AGENTS.md 與 skill。第二步是實際操作：把 user-insights dashboard 跑起來、用 Codex 探索它的結構，再送出一段只描述結果的功能 prompt。第三步拆開功能之所以能貼合既有畫面的傳導鏈：AGENTS.md 把工作路由到 skill，skill 再把 Codex 指向範例元件、資料契約與樣式 token，於是新卡片重用既有的 primitives，連 region filter 都自動連動。第四步用「這件事有沒有被編碼進 repo」這個判準，決定 prompt 該停在只說要什麼，還是得明講設計系統。最後一步談 PR：在 AGENTS.md 寫好視覺證據規則，Codex 就會自己在多個斷點截下 before／after，並把 PR 開好，讓審查的人不必 checkout 就能看到改動。

整條線的槓桿是同一個：把知識搬進 repo。放進去了，非工程師也能安全加功能；沒放，就會換來一個審不完的 review 瓶頸。
