Permission mode：Full access 與自訂權限的使用邊界

Step 3/4 · Permission mode：安全與自動化的取捨

你可能希望 Codex 自動跑過夜任務，不要每做一步就停下來等核准；但如果它使用的是你的工作機，完全放行又可能讓刪除資料、修改檔案等動作失去最後一道阻擋。Permission mode 的差異，就在於「哪些動作需要你核准，以及誰負責判斷能不能放行」。

Permission mode：控制 Codex 是否需要核准的權限設定

Codex 有四種 permission mode：Ask for approval、Approve for me、Full access，以及 Custom。它們從「每個動作都要詢問」一路到「完全不詢問」，另外也能用 Custom 設定明確的允許或拒絕規則。

四種 permission mode 一覽

模式機制什麼時候問你適用邊界
Ask for approval每個指令、每個動作都必須你核准每一次需要全程盯著的高敏感場合；缺點是慢
Approve for me另一條安全檢查執行緒判斷，安全就自動放行只有被判為不安全時日常開發；官方建議的預設
Full access完全不經核准就執行任何動作永遠不問只在隔離、可拋棄的機器上
Custom套用你自訂的明確允許或拒絕規則依規則而定想要可預期、可重複判斷的場合

四個模式可以依照詢問頻率排列如下：

ask for approval    # 每個動作都要你核准
approve for me      # 安全檢查執行緒放行安全動作（預設）
full access         # 完全不問，僅限隔離機器
custom              # 套用你自訂的允許／拒絕規則

Full access

機制：Codex 不經核准即可執行任何動作。

詢問時機：永遠不詢問。

使用邊界：只適合隔離、可拋棄的機器。例如，準備一台專門執行過夜 agent 的機器，讓它使用獨立的 Git 帳號，且無法存取其他資料。這台機器即使被弄壞，也不會影響你輸不起的內容。

工作機不適合使用 Full access。工作機通常包含專案、憑證與私人資料；在不受限的存取模式下，Codex 可能直接刪除它判斷為不需要的資料夾，而不會先取得你的核准。

Custom

機制：套用你自訂的明確允許或拒絕規則。

詢問時機：依照自訂規則決定。

使用邊界：適合需要固定工作流程、團隊共用設定，或需要可重複、可預期權限行為的場合。

模式選擇

需求對應模式
每個動作都要親自核准Ask for approval
日常開發時自動放行安全動作Approve for me
在隔離、可拋棄的機器上完全自動執行Full access
使用固定且可重複的允許或拒絕條件Custom
Codex 的權限有四個選項：每次都要你核准的 ask for approval、由另一條執行緒判斷安全與否的 approve for me、完全不問的 full access，以及由你自訂規則的 custom。full access 只在隔離、可拋棄的機器上才站得住腳，工作機上不要用；custom 則是把模型判斷換成可預期的明確規則。日常預設還是 approve for me。
