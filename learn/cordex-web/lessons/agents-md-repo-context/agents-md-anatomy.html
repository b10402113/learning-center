AGENTS.md：一份可查閱的區塊清單

Step 2/4 · AGENTS.md：把 repo 變成 Codex 的上下文

當 Codex 不知道該跑哪個指令、該讀哪個 skill，或改完 UI 卻漏掉手機版時，問題通常不是它不會寫程式，而是 repo 沒有把規則說清楚。AGENTS.md 就是用來集中放這些專案指引的檔案。

這一課把 AGENTS.md 拆成可查閱的區塊清單。你可以在建立或檢查 repo 時，直接對照每一類是否存在、內容是否真實，而且能實際執行。

AGENTS.md 是什麼

AGENTS.md 是放在 repo 裡的專案指令檔。Codex 在動手前會讀取它，據此判斷專案有哪些指令、該載入哪個 skill，以及哪些區域不應碰觸。

它不需要寫得華麗，也不必把所有知識都塞進去。重點是每條規則都要符合專案現況，讓 Codex 能照著執行。

Codex 如何選擇與讀取 AGENTS.md

規則說明
取最接近的那一份Codex 會從執行位置往上尋找。在 repo 根目錄執行時，會讀根目錄的檔案；若從某個子資料夾執行，則會讀該子資料夾裡較接近的那一份。
可以被覆寫或疊加專案自己的 AGENTS.md 會覆寫電腦上的使用者層級設定；專案內既有的 skill 則會加入 Codex 已有的 skill 清單。
可以作為 master 檔根目錄可以放一份 master AGENTS.md，再指向 repo 其他位置的 markdown 檔。
檔名不是硬性規定它不一定要命名為 AGENTS.md，本質上是一份被編碼的指引。使用 markdown 只是因為容易撰寫與閱讀，其他格式也可以。

六類區塊

區塊回答的問題典型內容
起始指令（Start here）要執行或驗證專案，該下哪些指令？dev、typecheck、build 指令，以及「先看 package.json 再宣稱」這類規則
skill 路由要做某類工作時，該載入哪個 skill？「新增 dashboard 卡片 → 讀 blossomview-card-builder」，並說明細節應留在 skill 中
repository map哪個資料夾或檔案負責什麼？狀態擁有者、元件、資料層、樣式與斷點的位置
程式與元件慣例寫程式時要遵守哪些規則？語言與型別、import alias、可沿用的套件與設計 token
UI 驗證改完介面後，要在什麼條件下檢查？指定寬度、overflow、console 錯誤與篩選互動
PR 證據送出 PR 時要附上什麼證明？before／after 截圖、截圖命名與位置、PR 標題格式

起始指令

以下是課程 user-insights 專案的「Start here」區塊：

## Start here

- Inspect `package.json` before running or claiming a project command.
- Run `pnpm run dev` for the local Vite dashboard.
- Use `pnpm run typecheck` for focused TypeScript verification.
- Run `pnpm run build` before describing a feature as ready for a pull request.
- Do not claim that browser tests, formatting scripts, CI, a Git remote, or a hosted preview exist unless they are actually configured.
指令用途執行時機
pnpm run dev啟動本機的 Vite dashboard需要查看實際畫面時
pnpm run typecheck執行 TypeScript 型別檢查修改程式後，需要快速確認型別時
pnpm run build產出正式建置把功能描述為可以開 PR 之前

Skill 路由

以下是同一份檔案裡「Choose the matching skill」的內容：

## Choose the matching skill

- For a new dashboard card, analytics panel, chart, engagement metric, regional breakdown, table, or compact insight, read and follow `skills/blossomview-card-builder/SKILL.md`.
- Use the skill's `references/dashboard-card-patterns.md` for the existing component, data, chart, styling, and layout contracts.
- Use `assets/active-engagement-card.tsx` only as an adaptable implementation asset, not as a requirement to add that exact card.
- Keep implementation detail in the skill. Do not duplicate its full workflow here.

最小 AGENTS.md

課程 starter repo 根目錄的 AGENTS.md 只有一頁多一點，內容如下：

# General guidance

Before changing frontend code in this repo, read and follow both local skills:

- `.agents/skills/design-ui-with-restraint/SKILL.md`
- `.agents/skills/write-practical-copy/SKILL.md`

Ignore the `prompts` folder.

## Work with starter project

Keep the supplied User Insights project intact as the starting example. Make scoped changes, use deterministic public-safe data, and verify the rendered desktop and mobile experience before claiming the work is complete.
內容指定事項
Skill讀取兩個本地 skill：design-ui-with-restraint 與 write-practical-copy
禁區忽略 prompts 資料夾
工作邊界保留 User Insights 範例專案、只做範圍明確的修改、使用可公開且具決定性的資料，並驗證桌面與手機版畫面

UI 驗證

項目要求
視窗寬度390、720、721、768、1440 像素
畫面檢查console 錯誤、缺漏資源、裁切、圖表尺寸與水平溢出
水平溢出判準document.documentElement.scrollWidth <= document.documentElement.clientWidth

PR 證據

項目要求
截圖類型before／after，涵蓋 mobile、breakpoint-edge、tablet、desktop 四種寬度
檔案管理固定截圖命名與存放位置
連結格式使用上傳到 GitHub 的穩定網址，不使用本機路徑或佔位連結

查閱重點

AGENTS.md 是 repo 的專案指令檔。Codex 會讀取最接近的那一份；檔名不必是 AGENTS.md，也可以由 master 檔指向其他 markdown。常見區塊包括起始指令、skill 路由、repository map、程式與元件慣例、UI 驗證，以及 PR 證據。每條規則都應該真實、可執行。
