Plugin 是什麼：把 skill、app、MCP server 裝成一包

Step 1/4 · Plugin、App、MCP 與 Skill 的分野

學習目標

看完這一節，你應該能說清楚：plugin 是把 skills、apps、MCP servers 打包在一起的容器，也能理解 Codex 為什麼採用整包安裝，而不是要求你逐項組裝。

先看它解決什麼問題：你裝的不是單一工具

假設你請 Codex 幫忙建立一個 React Native app，同事告訴你：「先裝 React Native 那個 plugin。」你在 Codex app 的 plugin 清單中按下安裝，直覺上可能以為自己只是多裝了一個工具。

但實際上，這個包裹裡可能同時放進幾種不同的東西：教 Codex 如何完成這類工作的流程說明、讓它連到 Expo 的整合，以及能讓 agent 呼叫特定工具的伺服器。

這些零件各自解決不同問題。若把整個 plugin 當成一個單一開關，之後就容易困惑：「我明明裝了，為什麼 Codex 還是不會做某件事？」要回答這個問題，得先把包裹拆開來看。

Plugin 是一個包裹

在 Codex 的用語裡，plugin 是一個包裹，也可以叫作 package 或 bundle。它能把三種零件綁在一起：skills、apps、MCP servers。三者的分工如下：

零件它是什麼解決的問題
Skill讓 agent 照著執行的工作流程指示agent 不知道「這件事該怎麼做」
App（connector）你登入並授權後，Codex 可以代你存取的既有服務agent 碰不到 GitHub、Slack 這類外部服務
MCP server把你的工具暴露成 agent 可以使用的介面agent 不知道你的產品有哪些動作可以呼叫

以 GitHub plugin 為例，app 的部分就是那個 connector。你先完成登入與授權，Codex 才能用你的身分查看 repository、讀取 pull request。

另一類是 builder plugin，例如 Build Web Apps 或 React Native。這類 plugin 通常會放入一整組 skills，由熟悉該工作流程的人寫好指示，告訴 Codex 應該使用哪些函式庫，以及如何把這類 app 做好。

React Native plugin 還可能額外帶有 Expo 的整合，讓 Codex 能夠使用它需要的服務。由此可見，同一個 plugin 裡可以同時放入用途完全不同的零件。

為什麼要打包，而不是一件件安裝？

因為這三種零件在實際工作中常常會一起出現。你要完成某一類任務時，可能同時需要「知道怎麼做」的 skill、「連得到服務」的 app，以及「叫得動工具」的 MCP server。

如果沒有 plugin，你就得自己逐項湊齊：先找一份工作流程指示，再接上一個外部服務，最後還要想辦法把工具暴露給 agent。Plugin 則把經常一起使用的內容預先綁好，讓你安裝一次，就能取得整組零件。

它很像一包露營裝備。店家不是只給你一支手電筒，而是把生火、煮飯、照明等用品整理成一包；你拿起來就能出發，不必自己對照好幾張清單。

不過，打包的好處也帶來同一個代價：包裡可能有這趟旅程用不到的東西，例如根本不需要的營釘。因此，安裝 plugin 後真正該問的不是「我裝了哪個開關」，而是「這個包裹裡實際帶進來了哪些零件？」

邊界：Plugin 不是 Skill

最常見的誤會，是把 plugin 和 skill 視為同一件事。其實，skill 只是 plugin 可能包含的其中一種零件。

一個 plugin 可以只放一個 skill，也可以同時包含 connector 和 MCP server，甚至三種零件都有。反過來說，skill 也不一定要透過 plugin 才能存在。

所以，當你聽到「安裝某個 plugin」時，應該把它理解成：「把一組經常一起使用的零件一次帶進來。」這不等於 Codex 從此自動學會某套做法；它是否具備那套工作流程，仍取決於該 plugin 裡是否包含對應的 skill。

概念可以把它想成重點
Plugin容器或裝備包把多種零件綁在一起
Skill工作流程說明告訴 agent 事情該怎麼做
App已授權的入口讓 Codex 存取既有外部服務
MCP server工具介面讓 agent 知道有哪些動作可以呼叫

這層關係可以先記成一句話：plugin 是容器，skill、app、MCP server 是內容物。後續看到 plugin 時，先拆解它包含哪些零件，就不會把「整包」和「其中一項功能」混為一談。

小結

Plugin 是一個包裹，裡面可以放入 skills、apps、MCP servers 三種零件。因為這些零件常常一起使用，所以 Codex 把它們打包，讓你安裝一次就能取得整組內容。但 plugin 本身不是 skill，也不是任何單一零件；它只是一個容器。看懂一個 plugin，就要看懂它實際帶進來的是哪些東西。

現在包裹已經拆開了。下一步要釐清其中最容易混淆的兩個角色：app 和 MCP server 都讓 Codex 碰得到外部世界，但負責的事情不同。前者主要處理「你能不能進去」，後者則處理「進去之後有哪些動作可以呼叫」。
