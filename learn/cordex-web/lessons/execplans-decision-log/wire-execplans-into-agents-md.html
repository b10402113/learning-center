讓 Codex 自動建立 exec plan：用 AGENTS.md 設好規則

Step 4/5 · Exec plans：讓決策撐過 compaction

先確認目標與前置條件

這一課做完後，當 Codex 開始實作新功能或處理重要架構決定時，就能依照規則自動建立 exec plan，並在每完成一個步驟後更新它。你不必每次都靠記憶力提醒自己：「現在該開一份計畫了。」

動手前準備兩樣東西：

  1. 一個已經有 AGENTS.md 的 repo。如果還沒有，先完成 AGENTS.md 的設定。
  2. 上一課寫好的 exec plan，把它當作格式與內容的參考。

整個設定分成三步：先建立專屬資料夾，再把規則寫進 AGENTS.md，最後請 Codex 做一件新工作，確認它真的會自動產生計畫。

第一步：建立專屬資料夾

Codex 要自動建立文件，首先必須知道文件要放在哪裡。先在 repo 裡建立一個固定的資料夾，集中存放所有 exec plan。

資料夾名稱可以自行決定，但要固定、容易找到，並且讓所有計畫集中管理。以下是其中一種結構：

repo/
├── AGENTS.md
└── execplans/
    ├── member-system.md
    └── legacy-library.md

集中存放有兩個直接好處。第一，Codex 有明確的目標位置，不需要猜測文件該放哪裡。第二，之後要回顧 repo 裡的重要決策時，只要查看這個資料夾，就能像翻閱一本決策索引一樣，找到過去的計畫。

第二步：在 AGENTS.md 寫清楚三件事

接著把規則寫進 AGENTS.md。內容不用很長，但必須回答三個問題：

  1. exec plan 是什麼？
  2. 什麼時候要建立？
  3. 要放在哪裡？

這三個問題分別避免三種常見錯誤：沒有定義時，Codex 可能把它寫成其他類型的文件；沒有建立時機時，它可能不會主動建立；沒有指定位置時，文件可能散落在 repo 各處。

可以在 AGENTS.md 加入一個像這樣的小節：

## Exec plans

Exec plans are living markdown documents in the `execplans/`
folder that record a piece of work's purpose, progress,
surprises, and decisions.

Create a new exec plan in `execplans/` whenever you:
- implement a new feature, or
- make an important architectural decision.

Update the relevant exec plan whenever you finish a step.

這段規則的每一部分都有明確用途：

  • 第一段說明 exec plan 是持續維護的 Markdown 文件，並指定放在 execplans/。
  • 中間的清單列出建立時機：實作新功能，或做出重要的架構決定。
  • 最後一句要求每完成一個步驟就更新，讓計畫不會只在工作開始時有用，之後卻逐漸過期。

這樣一來，Codex 會同時知道「它是什麼」、「什麼時候建立」、「要寫到哪裡」，以及「建立之後如何維護」。

第三步：驗證 Codex 會自動建立

規則寫好後，不要只看 AGENTS.md 就假設設定成功。請讓 Codex 做一件全新的工作，例如要求它實作一個新功能，然後檢查 execplans/。

你要確認三件事：

  1. Codex 是否在開始動工前建立 exec plan。
  2. 文件是否建立在 execplans/ 資料夾裡。
  3. 計畫中是否記下工作的目的與目前進度，並在完成步驟後更新。

如果沒有自動建立，先檢查 AGENTS.md 的觸發條件是否夠明確。像「記錄重要的事」這種寫法太模糊，Codex 可能認為口頭說明就足夠，不一定會建立文件。

相反地，直接寫出「實作新功能」與「做出重要架構決定」這兩個條件，Codex 就有清楚的行為準則可以遵循。把觸發時機列成清單，通常也比藏在一個含糊的句子裡更可靠。

完成後的檢查結果

設定完成後，repo 應該具備以下三項：

  • 一個集中存放 exec plan 的資料夾。
  • AGENTS.md 裡有明確的 exec plan 規則。
  • 你已經讓 Codex 做過至少一件新工作，並看見它自行產生一份計畫。
要讓 exec plan 自動化，需要一個集中收文件的專屬資料夾，以及 AGENTS.md 裡一段說清楚「它是什麼、何時建立、放在哪裡」的指引。指引越明確，Codex 越能在新功能或重要架構決定出現時主動建立計畫，並在每完成一步後更新。驗證方法也很直接：請它做一件全新的事，確認資料夾裡是否自行長出一份計畫。
