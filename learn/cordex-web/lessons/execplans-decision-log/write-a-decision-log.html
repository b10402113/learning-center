寫一份撐得過 compaction 的決策日誌

Step 3/5 · Execplans：讓決策撐過 compaction

這一課要完成什麼？

你會在自己的 repo 裡建立一份最小可用的 exec plan／決策日誌，記下四件事：為什麼做、做到哪裡、途中發現了什麼，以及每個重要決定背後的理由。

這份檔案就像工作現場的黑盒子。即使之後發生 compaction 或換了 session，下一個 Codex 仍能從檔案裡找回工作方向，不必重新猜測前面發生過什麼。

開始前需要準備兩樣東西：

  1. 一個正在動工的 repo，因為 exec plan 要放在裡面。
  2. 知道哪些決策值得留下來。格式只是外殼，真正重要的是不要讓關鍵理由只停在對話裡。

這一課先練習自己寫出、看懂一份日誌；至於怎麼讓 Codex 自動建立與更新，會在下一課（步驟 4）處理。

第一步：建立檔案，先放好四塊骨架

在 repo 裡建立一個專門收 exec plan 的資料夾，再新增一個容易辨認的 markdown 檔。假設這次工作是會員系統改版，可以命名為 member-system.md。

先把下面的骨架貼進檔案。這一步的預期結果，是 repo 裡多了一份有四個段落的決策日誌；內容可以先留白，接著再逐塊補上。

# Exec plan：會員系統改版

## 目的
（這次為什麼要做、要達成什麼）

## 進度與任務
（- [ ] 待辦 / - [x] 已完成）

## 意外與發現
（過程中遇到的問題、錯誤、缺漏）

## 決策紀錄
（決定：做了什麼選擇 / 理由：為什麼）

這四塊各自保存一種容易在 compaction 或換 session 後消失的資訊。接下來逐一填寫。

第二步：寫「目的」，讓未來的你立刻回到狀況

目的只回答一個問題：我們為什麼要做這件事？

課堂上的搬站 exec plan 會在開頭說明遷移目的，因為目的就是所有後續決定的起點。如果目的消失，下一個 Codex 可能會用完全不同的角度理解同一份程式碼。

請用一到三句話寫清楚：假設六個月後有人只讀這一段，他應該能說出「原來這次改版是為了解決某個問題」。不需要寫成完整規格，先讓方向不會走失即可。

第三步：寫「進度與任務」，讓工作可以接手

這一塊回答兩件事：已經做了什麼？還剩下什麼？

把工作拆成待辦清單。完成的項目改成 - [x]，尚未完成的保留為 - [ ]。預期結果是：任何人打開檔案，都能看出目前的斷點，而不是重新翻遍整段對話。

這在長任務中特別有用。工作可能持續幾個小時，也可能反覆迭代；進度清單就像斷點續傳的錨。compaction 後，Codex 只要讀取尚未勾選的項目，就知道接下來要往哪裡走。

第四步：寫「意外與發現」，留下程式碼背後的來歷

這一塊記錄原本沒有預料到、但影響了後續做法的事情。例如課堂上的搬站工作遇到 build error（建置錯誤），也發現有部分資產缺漏。

請不要只寫「遇到錯誤」，而要記下實際發生了什麼，以及它是否改變了後續處理方式。這些資訊很容易在壓縮對話時被捨棄；日後別人看到一段看似奇怪的程式碼時，才有機會知道它是為了避開某個特定問題而保留下來的。

第五步：寫「決策紀錄」，保留選擇與理由

如果四塊只能保留一塊，保留決策紀錄。它要回答：

  • 決定：最後選了什麼做法？
  • 理由：當時為什麼這樣選？

課堂上的搬站 exec plan 曾記下兩項決定：維持資源主題頁不變，以及完全比照既有的資料結構形狀。這些內容很可能來自當下對 Codex 的要求，而 exec plan 把要求留下來，讓它不會只存在於一次性的對話裡。

每一條決策可以寫成兩行。真正能撐過時間的通常是理由：決定會過時，但「當初為什麼這樣決定」是下一個人判斷要不要改動的依據。

例如，第一課提到的舊套件若在決策紀錄裡寫著「維持舊版套件，因為安全團隊要求」，下一個 Codex 就不會只看到「這個套件很舊」，便自動把它升級掉。

第六步：每完成一件事，就回來更新

四塊骨架填完，不代表工作結束。exec plan 是活的文件，價值來自持續更新。

每完成一個步驟或一件工作，就回到 markdown 檔補上進度；如果途中出現意外，也立刻寫進「意外與發現」；如果做了影響後續的選擇，就在「決策紀錄」留下決定與理由。

想像第一課那個反覆迭代二十輪的演算法場景：你每次只改一點程式碼，卻在中途遇到 compaction。若理由只留在對話裡，Codex 可能忘記當初為什麼把演算法改成現在的樣子；若每一步都同步寫進 repo，理由就不再依賴記憶。

做完後怎麼檢查？

打開你的 repo，確認裡面有一份容易辨認的 markdown 檔，並且四個區塊都有內容：

  1. 目的：說明這次工作為什麼要做。
  2. 進度與任務：列出已完成與待完成項目。
  3. 意外與發現：留下過程中的問題、錯誤與缺漏。
  4. 決策紀錄：記下做了什麼選擇，以及為什麼這樣選。
一份最小可用的 exec plan 有四塊：目的（為什麼做）、進度與任務（做到哪、還剩什麼）、意外與發現（過程中冒出的插曲）、決策紀錄（做了什麼選擇、為什麼）。其中決策紀錄最關鍵，因為「理由」是下一個人判斷能不能改動的依據。文件寫好之後要持續更新，每完成一件事就回來補一筆，這樣 compaction 才帶不走你的理由。

完成這些檢查後，你就有了一份能被接手、能在 compaction 後恢復脈絡的決策日誌。下一步，是把這套做法接進 AGENTS.md，讓 Codex 自己建立並持續更新它。
