PR 分頁、整合終端機與 repo 知識

Step 5/5 · 桌面 app 的前端開發工具面

這一節解決什麼問題？

前四步，你已經能在 Codex 桌面 app 裡完成一整輪前端工作：圈好 project、啟動 dev server、用內建瀏覽器查看畫面、用標註調整外觀、用 CDP 查詢行為，再用生圖補上素材。

但工作做到一半，可能會遇到兩種需要切換工具的情境：同事 tag 你去 review 一個 PR，或你想在某個 git worktree 裡執行指令。Codex 桌面 app 把 PR 分頁與整合終端機放進同一個工作流程，也提供 agents.md 和 repo skills，讓專案規則與重複工作流可以直接留在 repo 裡。

功能總覽

功能用途用法
PR 分頁（pull request tab）在 review 同事的 PR 時不必離開 app在分頁裡查看組織 GitHub 上 tag 你的 PR
整合終端機（integrated terminal）在 app 內執行指令直接在目前的 app 與 worktree 環境中執行
agents.md保存 repo 的規則與背景把指示寫進檔案，讓 Codex 自動讀取
repo skills保存專案專屬的重複工作流把反覆執行的流程寫成 repo 裡的 skill

PR 分頁

如果你和同事使用 GitHub 協作，Codex app 會提供 pull request 分頁，顯示你在組織 GitHub 上被 tag 的 PR。

你可以直接在 app 內進行 review，不必先開瀏覽器、登入 GitHub，再搜尋對應的 PR。這個功能的用途很單純：review 時維持原本的工作流程，不必為了處理協作事項離開目前的工作環境。

整合終端機

Codex app 內建整合終端機，讓你可以直接在 app 裡執行指令。

它特別適合使用 git worktree 的情境。假設你正在某個 worktree 裡工作，傳統做法通常是切換到另一個終端機視窗，找到該 worktree 的目錄，再從那裡執行指令。使用整合終端機時，這些操作可以留在 app 內完成。

agents.md：保存 repo 的指示

agents.md 是放在 repo 裡的指示檔案。Codex 會讀取它，因此可以把每次新任務都會重複交代的內容集中寫在這裡。

常見內容包括：這個 repo 應該如何處理、程式碼應該如何修改，以及 PR 應該用什麼方式建立。它也是 Codex 和其他 coding agent 共用的一種慣例。

starter repo 的範例非常精簡：

# agents.md（starter repo 的極簡版）
- 忽略 prompts/ 這個資料夾
- 這個檔案才是你要更新的地方

這個範例要求 Codex 忽略 prompts/ 資料夾，避免它受到 repo 裡範例 prompt 的影響。更貼近實際專案時，agents.md 可以包含更完整的 repo 指示，讓每個新任務都能取得相同的專案背景。

repo skills：保存可重複的工作流

repo skills 用來保存專案裡會反覆執行的工作流。skill 有兩種來源：可以來自已安裝的 plugin，也可以直接存在 repo 裡。

當某個流程只適用於特定專案、卻會反覆使用時，可以把它寫成 repo 裡的 skill，讓這個流程固定保存，不必每次重新說明。

agents.md 和 repo skills 的分工如下：

項目保存內容
agents.md這個 repo 的規則與背景
repo skills這個 repo 裡反覆執行的動作

摘要

Codex 桌面 app 將協作與專案背景知識放在同一個工作環境中。PR 分頁用來 review 被 tag 的組織 PR；整合終端機用來在 app 內執行指令，特別適合 git worktree。要保存重複交代的內容，可以使用兩個位置：agents.md 放 repo 的規則與背景，repo skills 放專案專屬、可重複的工作流。前者保存規則，後者保存動作。

這五個工具合在一起，形成一條留在 app 內完成前端工作的流程：圈定 project、啟動環境、查看畫面、調整外觀、查詢行為、補充素材，最後處理協作並保存專案知識。
