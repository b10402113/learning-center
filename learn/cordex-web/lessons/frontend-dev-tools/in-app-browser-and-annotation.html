內建瀏覽器與標註：把視覺回饋釘在正確元素上

Step 2/5 · 桌面 app 的前端開發工具面

先解決一個常見問題：你說的「怪」，Codex 找得到嗎？

上一步，我們已經把頁面跑起來，也能在畫面中看到成果。接下來的前端開發，常常會卡在一句話：「這個按鈕看起來怪怪的，改一下。」

問題是，Codex 可能不知道你指的是哪個按鈕，也不知道你希望它改成什麼樣子。於是它花時間猜測，你再花時間糾正，原本應該快速完成的視覺調整，變成好幾輪來回。

桌面 app 裡的內建瀏覽器與標註工具，就是用來縮短這段溝通距離。內建瀏覽器讓你和 Codex 看見同一個頁面；標註工具則讓你直接指出畫面中的特定元素，甚至示範它應該變成什麼樣子。

內建瀏覽器：不只是把 Chrome 搬進來

Codex 桌面 app 裡有內建瀏覽器，而且近期曾經強化。它可以匯入平常瀏覽器的資料；例如，你使用 Google Chrome，也在裡面儲存了密碼，就能直接匯入 Codex 的瀏覽器。它也支援新分頁與瀏覽歷史，使用方式和一般瀏覽器相近。

不過，重點不只是「看起來像 Chrome」。這是一個為 Codex 加值、並且專屬於 Codex 的瀏覽器。Codex 可以直接在其中開啟頁面、點擊元素並進行操作，這種能力稱為 browser use。

你也可以在自己的普通瀏覽器上使用 browser use，只是直接在 Codex app 裡操作，能少掉切換視窗與轉述畫面的麻煩。頁面還能接受標註，而你可以在同一個畫面旁邊繼續和 Codex 對話，立即反覆調整。

可以把兩種情境想成這樣：普通瀏覽器像是你自己逛街，看到問題後還得回頭描述店面位置；內建瀏覽器則像把導遊帶在身邊，你指向哪個櫥窗，他就能直接看同一個位置。雙方共用同一個畫面，溝通自然精準得多。

標註：把「感覺不對」變成「這個元素要這樣改」

標註（annotation）的作用很直接：看到具體的視覺問題時，把回饋釘在那個元素上。你進入標註模式，點一下畫面中的元素，再留下意見；Codex 收到的就不再只是一句模糊的感受，而是明確知道「螢幕上的這一個元素」需要調整。

標註不只可以留言，也能直接修改字體、背景，以及網站上看得到的部分 CSS。這和使用 Chrome DevTools 有點像，但你不必先開啟 DevTools，再把修改內容重新整理成文字告訴 Codex。你可以透過標註直接示範想要的結果。

回饋方式Codex 收到的資訊常見結果
口頭描述一句模糊的形容Codex 得猜是哪個元素，容易猜錯
點選標註特定元素加上就地回饋較容易直接改到正確位置，少一輪來回
標註並修改 CSS特定元素與你示範的目標樣式連「要改成什麼樣子」都不必另外描述

兩者如何一起工作？

內建瀏覽器與標註工具解決的是兩個不同問題。

內建瀏覽器負責建立共同視角：你和 Codex 看到的是同一個頁面。標註工具負責建立明確指涉：你能指出畫面中的哪一個元素，以及它應該如何調整。

少了內建瀏覽器，Codex 可能只能靠你的描述猜畫面；少了標註，即使雙方看見同一頁，Codex 仍可能不知道你說的「這裡」究竟是哪裡。兩者合在一起，視覺迭代就從猜謎變成「指哪裡，改哪裡」。

把視覺回饋固定在畫面上

內建瀏覽器是為 Codex 加值、專屬於它的瀏覽器：可以匯入 Chrome 資料、開啟分頁、查看歷史，也能讓 Codex 直接在其中使用 browser use。標註工具則把視覺回饋釘在具體元素上，還能直接調整字體、背景與 CSS，讓「這裡怪怪的」變成「這個元素請這樣改」。兩者一起，能把視覺迭代從猜測變成精準修改。

現在，畫面長得對不對、哪個地方需要調整，你已經能清楚表達。但有些問題不是外觀，而是功能真的壞了：按鈕按下去沒有反應、資料沒有載入，或請求在背後失敗。這些情況光看畫面通常找不到原因；下一步要介紹的 CDP，會讓 Codex 直接讀取瀏覽器的 log 與 network 資訊。
