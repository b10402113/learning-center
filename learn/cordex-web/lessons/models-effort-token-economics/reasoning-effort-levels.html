Reasoning effort：讓模型多想一點，代價是什麼？

Step 2/4 · 模型、reasoning effort 與額度經濟學

為什麼同一個模型，表現還是會不一樣？

上一節我們用 Sol、Terra、Luna 三顆模型，先解決「該派誰上場」的問題。但實際使用 Codex 時，你可能會遇到另一種情況：明明是同一顆模型，有時很快就給出可用答案，有時卻思考很久，繞了一大圈，結果也不一定更好。

差別通常來自另一個旋鈕：reasoning effort。它決定模型在回答前願意投入多少思考量。這個設定不是越高越好，因為思考越多，通常也代表速度更慢、消耗更多 token；如果問題本來很簡單，開得太高甚至可能讓答案變差。

這一節會把這個旋鈕的作用、各個等級與使用時機整理清楚，讓你不必每次都憑感覺亂試。

Reasoning effort 到底在調什麼？

人遇到問題時，通常不會每次都用同樣的力氣思考。問「今天星期幾」，不需要列出完整推理；遇到難解的 bug，則可能要先拆問題、檢查假設，再逐步排除可能性。

模型也有類似的差異。你可以把 reasoning effort 想成「模型在回答前，允許自己想多久、想多深」。

effort 較低時，模型會更快產生答案；effort 較高時，則有更多機會拆解任務、檢查思路並修正錯誤。因此，同一個問題換一個 effort 等級，可能同時影響三件事：

  • 答案的品質與穩定性。
  • 回應速度。
  • 消耗的 token 與額度。

這不是把模型換成另一個模型，而是調整同一個模型要投入多少「思考預算」。

五個等級與預設值

Codex 的 reasoning effort 從低到高分成五段。另有一個把思考負擔推到極限的 max 檔位。日常工作最常用的是中間幾段：

等級它在做什麼適合的情境
low投入較少思考，優先換取速度非常簡單、只求快速完成的任務
medium（預設）在速度與思考量之間取得平衡大多數日常工作
high投入更多思考，進一步推敲答案比較複雜、希望輸出更穩定的任務
extra high再增加一層思考量難纏的 bug 或需要深挖的問題
max極度消耗算力與 token，反覆投入大量思考真正困難、值得砸下大量資源的問題

先把 medium 當成起點就好。它不是最省，也不是最強，但處理大部分日常任務已經很夠用。

如果你只在意速度，可以往 low 調；如果問題更複雜、希望模型多檢查幾輪，可以往 high 或 extra high 調。max 則應該獨立看待：它會消耗大量 token，不適合拿來處理一般小事。工作坊沒有使用 max，就是因為當時的任務不需要這麼高的思考成本。

代價一：思考越多，額度消耗越大

第一個代價是 token。

模型的思考過程本身也會消耗 token，所以提高 effort 後，即使最後輸出的文字長度差不多，整個任務使用的額度仍可能增加。對有訂閱額度上限的人來說，這不是帳面上的小差異，而是會影響一天能完成多少任務。

這也是 max 不適合處理日常小事的原因。若只是改一個簡單拼字，卻讓模型用極高 effort 反覆推敲，就像為了寄一張明信片，叫一整支研究團隊先開會討論紙張厚度：事情可能完成了，但成本完全不成比例。

代價二：想太久，反而可能更差

第二個代價更容易違反直覺：過度思考（overthinking）。

如果問題很簡單，卻把 effort 開得很高，模型可能會在不需要的地方繞遠路。這就像有人被問「今天星期幾」，卻開始推算日曆、時區和閏年，最後反而把簡單答案講錯。

思考量超過問題真正需要的程度，不會自動帶來更好的結果。它可能只會讓回應更慢、消耗更多 token，甚至增加偏離問題的機會。

因此，effort 的重點不是「越高越聰明」，而是思考量要和任務難度匹配。

實際怎麼判斷要開多高？

不同任務會需要不同的思考量。有些講者平常會在 high 與 extra high 之間切換，遇到特別刁鑽的 bug 才進一步拉高；也有人認為 medium、high 和 extra high 都有合理的使用情境。

甚至在課程中刻意埋下的 bug，medium 也足以找出來。這代表你不必把所有問題都升到最高檔，才能得到好答案。

相較之下，low 通常比較不受青睞，因為它犧牲了不少思考量，換來的速度未必值得。至於 high 和 extra high 的差異，也不一定能用一條固定界線說清楚；它會取決於你正在處理的是哪一類程式，以及問題有多難拆解。

可以先用這個原則實際判斷：

  • 簡單、明確、只求快速完成的任務：考慮 low。
  • 一般日常工作：從 medium 開始。
  • 比較複雜、需要多次檢查的任務：提高到 high。
  • 難以定位的 bug 或架構層級的取捨：考慮 extra high。
  • 真正困難、值得付出大量額度的問題：才使用 max。

每次調整時，都問自己兩個問題：這個任務真的需要更多推理嗎？我現在付出的速度與額度，是否換來了足夠的品質提升？

把 effort 放回模型選擇裡

模型與 reasoning effort 是兩個不同的調節方向。

選模型，回答的是「由誰來處理這個任務」；調 effort，回答的是「讓它投入多少思考」。先前的模型選擇解決了派誰上場，現在的 effort 選擇則是在調整這位選手要用多大力氣比賽。

所以，不要只記得哪顆模型最強，也不要把最高 effort 當成萬用解。從 medium 出發，再依任務難度往上或往下調，通常比一開始就把所有設定推到頂更有效率。

Reasoning effort 是模型在回答前願意投入的思考量，預設值是 medium。往上調通常能換來更充分的推理，但代價是更多 token 與更慢的回應；問題太簡單時，effort 開得過高還可能造成過度思考，讓結果反而變差。實務上從 medium 出發，依任務難度調整即可；max 只留給真正困難的問題。

到這裡，你已經能把「模型選誰」和「模型想多久」分開判斷。接下來的問題就不再只是單次回答要花多少力氣，而是當額度有限時，如何用 Ultra、fast mode 與委派，把有限的思考資源換成更大的工作量。
