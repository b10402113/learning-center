Ultra、fast mode 與委派：把額度花在刀口上

Step 3/4 · 模型、reasoning effort 與額度經濟學

先確認目標與前置條件

這一節要完成的不是把所有加速開關都打開，而是學會依照任務形狀分配額度：需要平行處理時使用 Ultra，需要縮短等待時間時使用 fast mode，大量重複工作則委派給較便宜的模型。

開始前，請先具備兩個條件：

  1. 你已經會調整模型與 effort，例如先用預設的 Sol 加 medium 做基本執行。
  2. 專案裡有測試或其他驗證機制，能在委派後擋住錯誤。這些測試就是品質的保護網，也是 back pressure。

如果沒有測試，先不要急著委派。便宜模型雖然能省額度，卻可能把錯誤變成更多需要人工檢查的工作。

第 1 步：先判斷任務能不能拆開

在設定任何模式前，先問自己：這是不是由多個彼此獨立的小工作組成的任務？

例如，你要同時完成幾條不同功能的垂直切片，或一個複雜問題本身就能拆成多個子工作流。這類任務適合使用子代理平行處理。

如果只是修一個小 bug，或工作前後高度相依，開 Ultra 通常只是在增加成本。這時先用預設的 Sol 加 medium 執行一次，往往更合適。

第 2 步：需要平行處理時，開 Ultra

假設你現在有十個彼此大致獨立的小工作，希望它們同時進行。你可以直接告訴 Codex：

Spawn sub-agents as needed.

Codex 會把主要任務拆開，再交給其他代理分頭處理。Ultra則把這件事自動化：它會替你生成並派出多個子代理，像是把一張大工作單一次展開成多條平行流水線。

Ultra 預設不會出現在模型選單中。若要開啟，請依序操作：

  1. 打開 Codex 的 Settings，進入 configuration。
  2. 選擇要顯示幾段 reasoning effort，並決定是否在模型選擇滑桿上顯示 ultra。
  3. 回到模型選擇器，把模式切換成 Ultra。
  4. 開始執行任務，預期會看到 Codex 自動生成一群子代理，分頭處理不同部分。

Ultra 的代價是大量 token。它之所以藏在設定裡，是因為開啟後更容易快速撞到用量上限。

若你沒有打算把大部分工作委派給便宜的 Luna，或使用每月 100／200 美元以上的方案，請不要隨意開 Ultra。任務規模不夠大時，多個子代理帶來的成本可能比節省的時間更高。

第 3 步：需要縮短等待時間時，開 fast mode

fast mode處理的是速度，不是智慧。它會讓模型輸出 token 的速度變快，但也會讓額度消耗得更快。

可以把它想成同一台車切換到高速檔：目的地沒有改變，車上的判斷能力也沒有突然變強，只是更快抵達。工作坊當天，講者為了讓流程快速完成，因此全程開啟 fast mode。

請依照你的優先順序決定：

  • 若你正在趕 demo，或想趁思路還在時快速迭代，請開啟 fast mode。
  • 若你更在意額度，而且不需要快速產出大量內容，請保持關閉。
  • 若你的重點是同時執行多個代理，而且希望它們夠聰明，速度可能不是最重要的因素。

小重現可以這樣做：先用一般模式執行一次，記下等待時間與額度使用情況；再開啟 fast mode 執行相近的工作，觀察輸出是否更快，以及額度是否消耗得更快。你應該看到的是速度與成本的交換，而不是答案品質自動提升。

第 4 步：把大量粗活委派給 Luna

如果你的目標是省額度，最直接的做法是把大量、重複、可以靠測試驗證的工作交給便宜模型。這裡的設定是使用 GPT-5 Luna，並開啟最高的 effort，也就是 max effort。

你可以把規則放進專案的 AGENTS.md 或 custom instructions：

# 放在 AGENTS.md 或 custom instructions
Delegate the grunt work to GPT-5 Luna at max effort.
Keep the tests running as back pressure so quality stays high.

這兩句各自負責一件事：

  • 第一句要求把耗工的粗活交給 GPT-5 Luna，並讓它用最高思考深度完成。
  • 第二句要求持續執行測試，讓錯誤在流程中被擋下來，而不是等到最後才由人工逐一抓漏。

實際執行後，預期會看到這種分工：高階判斷仍由你或較強的模型處理，大量重複工作則由 Luna 以較低成本完成。這特別適合讓代理整晚執行的情境，因為長時間自走很容易撞到用量上限；把粗活委派出去，就能減少額度消耗。

第 5 步：執行後一定要驗證

不論你開了 Ultra、fast mode，還是把工作委派給 Luna，最後都要回到可驗證的結果。這些設定改變的是「用多少資源換多少吞吐」，不是「答案一定正確」。

  1. 執行測試，確認測試是否通過。
  2. 檢查功能是否真的按照需求運作。
  3. 若你已經設定 goal 與驗收條件，逐項對照產出。
  4. 若驗證失敗，先修正結果，再考慮是否需要調高模型、effort 或改變委派方式。

不要因為 Ultra 成本高、或模型看起來更強，就跳過驗證。昂貴的執行只代表用了更多資源，並不代表產出自然正確。

怎麼選：三招的快速判斷

  • 很多個獨立子工作：開 Ultra，但先確認能承受較高的 token 消耗。
  • 只想讓輸出更快：開 fast mode，接受額度消耗加快。
  • 大量重複工作，且有測試保護：委派給 GPT-5 Luna，使用 max effort。
  • 小型或高度相依的任務：先維持預設的 Sol 加 medium，不要為了追求速度而增加不必要的代理。
Ultra 會自動派出多個子代理，適合多個獨立子工作或複雜任務，但非常吃 token，還要先進設定開啟；fast mode 會讓 token 輸出更快，代價是額度消耗更快，適合趕工；委派則是把粗活交給最便宜的模型 GPT-5 Luna，搭配最高 effort，再用測試當作 back pressure 守住品質。三招改變的都是資源效率，不是答案好壞，所以做完一律驗證。

做完這一節，你應該能在任務開始前，快速決定模型、effort、Ultra／fast 與委派要怎麼搭配。先看任務能不能拆，再看你更在意平行處理、等待時間，還是額度成本；執行後則用測試與驗收條件確認結果。
