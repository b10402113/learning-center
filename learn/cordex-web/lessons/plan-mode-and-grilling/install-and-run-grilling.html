動手裝好，完整跑一輪 grilling

Step 4/5 · Plan mode 與 grilling：逼出決策

知道 plan mode、grill-me 和 grill-with-docs 怎麼運作，還不代表你已經能在專案裡用起來。這一節會把整條流程搬到你的電腦上實跑一次：先安裝 grilling 家族的 skill，再讓 Codex 針對一個功能提問、收斂決策，最後產出 context.md、流程圖與垂直切片。

做完後，你會有一個已經裝好 skill 的 Codex，也會拿到一份由你親自確認過的設計決策紀錄。

學習目標

照著本節操作，安裝 grill-me、grilling、grill-with-docs、domain-modeling，並對一個功能實跑一輪 grilling。整個 grilling 流程最多進行兩輪，目標是拿到可以直接進入實作的 up-front 決策。

前置條件

開始前，先確認以下條件：

  • 你有一個可以讓 Codex 工作的專案，而且專案已經在 Codex 裡開啟。
  • 你知道專案平常怎麼啟動，也知道資料庫放在哪裡，例如是否使用 Docker Compose。
  • 你有可以執行指令的終端機。安裝 skill 要在終端機完成，不是在 Codex 對話框裡輸入。

本節安裝的是「全域」skill。安裝完成後，電腦上的任何專案都可以叫用它們。如果你不想影響其他專案，也可以改成只安裝在單一專案裡；代價是每個想使用的專案都要各裝一次。

第一步：安裝 grilling 家族的 skill

打開終端機，執行下面這行。它會使用官方的 skills 安裝工具，抓下某位開發者整理好的 skill 套件，接著讓你選擇要安裝哪些項目。

npx skills@latest add schneidenbach/skills

如果終端機先詢問「需要安裝以下套件，是否繼續」，選擇同意。接著它會列出套件中的所有 skill，請用空白鍵勾選以下四個：

  • grill-me
  • grilling
  • grill-with-docs
  • domain-modeling

其他針對特定前端風格或程式碼審查的 skill，本課用不到，可以不勾選。

接著，安裝範圍選「global」（全域），安裝方式選「symlink」（符號連結）。這樣 skill 會放在共用位置，所有專案都能使用；安裝完成後，檔案會位於 home 目錄下的 .agents/skills，也就是 Codex 讀取全域 skill 的目錄。

日後如果要移除，只要刪除 .agents 裡對應的檔案即可，不會影響你的專案。

第二步：確認 Codex 讀到了 skill

回到 Codex 對話框，輸入斜線 /。你應該會在指令清單中看到剛安裝的 grill-me、grilling 與 grill-with-docs。

如果看得到，代表安裝成功。這個檢查很重要：skill 沒有被讀到時，整條流程不會啟動。若等到 Codex 沒有提問、直接開始修改檔案才發現，通常已經太晚了。

第三步：描述功能，叫出 grilling

接著向 Codex 描述你要做的功能，並在結尾明確要求它使用 grilling。以下是課程中拍賣網站的示範，你可以把功能換成自己的需求：

I want to add on the ability to post auctions and make bids,
these should be stored in Postgres. See the Docker Compose file —
that's where the database should live. grill me with docs.

你也可以不寫 grill me with docs，而是直接叫出已安裝的 skill 名稱，因為 Codex 已經知道有哪些 skill 可以使用。不過，如果你希望它執行「grilling 加上文件紀錄」的完整流程，明確寫出這句會比較穩妥。

第四步：回答問題，最多收斂兩輪

skill 啟動後，會先讀取 skill 檔案與專案檔案，再一題一題訪談你。請依照下面的方式回答：

  1. 用代號快速採用建議。每一題通常會附上建議答案。認同時可以輸入 take recommend；如果題目列出選項，也可以直接輸入 A 或 B。第一輪預期會看到約八到十題。
  2. 不懂就要求解釋。如果你不確定題目在問什麼，直接輸入「please explain this to me better」。它會補充背景，再重新提問。不要在不理解的情況下硬選一個答案。
  3. 不同意時說明具體決定。建議只是起點，不是聖旨。例如課程中的資料庫 reset 題目，最後刻意指定為「只重建 part two 這個資料庫，並跑完所有 migration」，而不是直接採用預設值。這正是 grilling 用來逼出真實決策的地方。
  4. 最多進行兩輪。第一輪確認主要決策，第二輪補足細節。兩輪完成後就停止提問，進入實作。

不要為了省時間而回答「全部採用建議」。這樣只是跳過判斷，也失去了 grilling 存在的理由。它替你減少打字，不是替你取消決策。

第五步：驗收產出

兩輪訪談結束後，預期會看到三類產出：

  • 一份 context.md；有時內容會被寫進流程檔案。裡面記錄這次訪談確認的商業術語與需求。
  • 一張 Mermaid 流程圖，呈現使用者選擇、API 與資料庫之間的流向。
  • 一組垂直切片，例如「資料庫驅動的市集與使用者切換」、「貼出拍賣」、「出價與檢視出價」。

請逐項檢查：

  1. context.md 裡的定義是否和你的說法一致。
  2. 流程圖是否漏畫或誤畫任何部分。
  3. 垂直切片是否切得合理。

確認沒有問題後，回覆「approved the slices」。到這裡，設計階段的決策才算正式落地；接下來 Codex 才會依照切片，一個一個完成實作。

做完後，你應該看到什麼

你現在應該能驗證三件事：Codex 的指令清單中看得到 grilling 相關 skill；兩輪訪談已經把需求收斂成明確決策；專案中也有 context.md、Mermaid 流程圖與可執行的垂直切片。

安裝時執行 npx skills@latest add schneidenbach/skills，勾選 grill-me、grilling、grill-with-docs、domain-modeling 四個 skill，選擇全域與 symlink，安裝到 ~/.agents/skills。使用時描述功能並叫它「grill me with docs」；回答問題時可用 take recommend 或 A 快速採用建議，不懂就請它解釋，最多進行兩輪。最後檢查 context.md、Mermaid 流程圖與垂直切片，確認後才進入實作。

到這裡，你已經能實際使用原生 plan mode 與 grilling 家族。最後一節會處理選擇問題：面對新功能時，如何判斷該用哪一種方式，以及什麼時候該停。
