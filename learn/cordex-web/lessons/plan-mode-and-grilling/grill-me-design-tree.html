grill-me：用決策樹把設計逼到共享理解

Step 2/5 · Plan mode 與 grilling：逼出決策

學習目標

理解 grill-me／grilling 如何用一棵決策樹，把模糊的設計逐題拆成明確選擇；也能掌握「每個問題附建議」的問答機制，知道什麼時候可以快速採用、什麼時候必須自己判斷。

先看它解決什麼問題：一份看似完整、其實沒談完的計畫

上一節提到，plan mode 可能產出一份看起來很完整的計畫，卻沒有把關鍵決策逐一挑出來問。你按下接受，以為設計已經談妥，實際上只是把不確定性往後推，等到實作時才一個個爆出來。

這時候需要的，未必是另一份計畫，而是一個會追問到底的對話工具。社群裡的 grill-me 就是這樣設計的：它針對你正在建造的東西，一題接一題訪談你，直到你和模型對這件事有共同理解。

想像你正在設計一個拍賣功能。與其直接接受一份「建立拍賣頁、加入出價、設定結標時間」的計畫，不如讓它繼續追問：誰可以出價？賣家要提供哪些欄位？圖片怎麼處理？拍賣何時對外可見？結標時間怎麼定義？這些問題的答案，才是真正會影響實作的設計。

先跑一次：在 Codex 裡怎麼使用 grill-me

grill-me 不是 Codex 內建功能，而是一個自訂 skill。你在 Codex 的對話框輸入 /，會看到可用的斜線指令；內建指令和自己安裝的 skill 都會列在其中，選取 grill-me 後，它就會開始訪談。

它不會先丟給你一份完整答案，而是先問一個設計問題，並附上它認為合理的建議。你可以直接接受建議，也可以指出自己要採用不同方案。接著，它會根據你的回答繼續往設計樹的下一層追問。

例如，當它問到角色與流程時，你回答「使用預先建立的使用者」，後面可能就會接著出現「使用者怎麼切換」或「賣家能不能出價」這類問題。你回答後，問題會再往下展開，直到主要決策和由此衍生的細節都被說清楚。

如果建議是你要的，可以輸入 take recommend；若它列出選項，也可以直接輸入 A 或 B。遇到不清楚的題目，就請它再解釋一次。最後得到的不是一份禮貌性的計畫，而是一組已經被明確回答的設計決策。

grill-me 的身分：一個 custom skill

skill 可以把它想成 Codex 裡的自訂斜線指令：輸入 / 後，選擇它，就能叫出一套預先定義好的工作方式。grill-me 屬於使用者自己安裝的 custom skill，不是 Codex 內建功能；它由 Matt Pocock 製作。

它的核心任務只有一句話：持續訪談使用者，直到雙方對這件事達成共享理解。

這裡的關鍵是「訪談」，不是「規劃」。它不急著替你產出答案，而是把還沒做決定的地方挖出來，直到你沒有新的關鍵內容可以補充。

設計其實是一棵決策樹

要理解 grilling 為什麼有效，可以把設計想成一棵樹。你先做出一個選擇，這個選擇下面又會長出更多問題。

例如，你決定使用預先建立的使用者。這個決定立刻帶出「使用者怎麼切換」；如果系統裡有賣家，又會帶出「賣家可不可以出價」；如果允許出價，接著還要決定最低加價是多少。每一個答案，都可能打開下一組分支。

grill-me 做的事情，就是沿著這棵樹逐層往下走。它把原本飄在空中的「我要做一個拍賣功能」，拆成一個個可以回答的決策點。當這些分支走得夠完整，你手上就不只是方向，而是一份能拿去實作的設計。

這也說明了它和一般計畫的差別：計畫常常告訴你要做哪些大項目；grilling 則逼你把每個大項目背後的選擇說清楚。

關鍵設計一：每個問題都附建議

grill-me 不會只把問題丟回給你。它通常會先提供自己的建議，有時還會列成 A、B、C 等選項。這些建議的正確率大約有八成到九成，因此多數時候你可以直接採用，省下從零開始思考的時間。

它也把回答設計得很短：認同建議時輸入 take recommend；有選項時輸入 A 或 B；看不懂時，請它再解釋清楚。這就像有人先把選擇題和推薦答案整理好，你只需要把注意力放在「這是不是我的情境」上。

但便利不等於可以放棄判斷。可以快，不代表可以不動腦。如果每一題都無條件輸入「採用建議」，你就只是把設計權整包交還給模型，grilling 原本要逼你做決策的價值也會消失。

建議是加速器，不是自動駕駛。符合你的需求時可以快速接受；不符合時，應該具體說明你要改成什麼，讓後續問題建立在正確的前提上。

關鍵設計二：只跑兩輪

設計樹沒有天然的終點。你回答一題，通常就會長出下一層問題，因此 grill-me 可以一直問下去。可是，問題問得越多，設計不一定越好；當人開始疲累，就可能從認真判斷變成隨便選一個。

實務上會刻意把 grilling 限制在最多兩輪。第一輪先掃過主要決策，第二輪再處理第一輪衍生出的細節，接著就停止追問、進入實作。

這個上限不是功能缺陷，而是一種取捨：目標是取得一份足夠好的設計，不是把所有可能分支都窮盡。適時停手，才能讓訪談真的服務於實作，而不是變成永遠沒有終點的問卷。

把這個觀念記住

grill-me 是社群自製的 skill，透過持續訪談，讓你和模型對要建造的東西達成共享理解。它把設計看成一棵決策樹，沿著分支逐題追問；每一題通常會附上約八成到九成正確的建議，讓你能用 take recommend 或 A 快速回答。它的價值，是把模糊念頭逼成明確選擇；但它也能無止境地追問，所以實務上只跑兩輪。可以快，但不可以不動腦。

把它和前面的 plan mode 接起來看，關係就很清楚：plan mode 偏向整理出一份計畫，grill-me 則負責把計畫裡尚未決定的地方逐一攤開。可是，如果這些決策只留在對話裡，對話一壓縮或換了 session，它們就可能消失。下一節要看的，就是如何再串上一個把答案寫成文件的 skill，讓這些決定保存下來，後續還查得到。
