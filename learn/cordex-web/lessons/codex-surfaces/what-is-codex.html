Codex 是什麼？同一套 harness 的兩種面貌

Step 1/3 · 認識 Codex，以及它的各種入口

學習目標

看完這一節，你會知道 Codex 為什麼不只是寫程式的工具，也能說明它如何從 chat 走向 delegation，以及 ChatGPT Work 和 Codex 為什麼看起來不同、底層卻是同一套 harness。

前言：你是在「問」AI，還是在「交辦」AI？

回想第一次用 AI 寫程式的情境：你開啟聊天視窗，輸入問題，等 AI 產生程式碼，再自己複製回編輯器。整個過程裡，方向盤一直握在你手上，AI 比較像坐在副駕、幫你查地圖的助手。

但如果你看過別人使用 Codex，畫面可能完全不同。他只要交代一句：「幫我把這個功能做出來。」接著就去忙別的事。過一會兒回來，agent 已經修改檔案、執行測試，甚至開好 pull request；他只需要快速檢查改了什麼。

這不是兩種完全不同的產品，而是同一條產品線在不同階段呈現出的工作方式。要理解 Codex 為什麼有這麼多入口，先得弄清楚它的核心是什麼，以及它和 ChatGPT 為什麼會逐漸合在一起。

Codex 是 OpenAI 的 agent，不只寫程式

Codex 是 OpenAI 的 agent，官方描述是「for coding and other tasks」：它可以寫程式，也能處理其他工作。

它最初確實是以 coding agent 的身分出現，主要服務軟體工程工作，並很快被開發者大量採用。隨著模型在其他任務上的能力變強，越來越多人也開始用 Codex 做簡報、做試算表，或處理各種日常工作。

因此，OpenAI 做了一個重要決定：把 Codex 併進 ChatGPT。這件事發生在不久前，所以現在你下載的 ChatGPT app 裡，其實也包含了 Codex。

關鍵零件：harness

要理解這次合併，得先認識 harness。這個字原本指套在馬身上的馬具，用來控制馬匹的方向。在 AI 的脈絡裡，harness 指的是一整層協作機制：它決定模型下一步要做什麼、應該使用哪個工具，以及每一輪行動之間要如何銜接。

可以把模型想成引擎，而 harness 就像方向盤加上變速箱。引擎提供動力，但真正把動力轉成「前進、轉彎、停下來」的，是方向盤和變速箱。模型能產生想法，harness 則負責把這些想法接到實際行動上。

OpenAI 發現，這套 harness 特別適合處理 agentic 任務，因此希望原本只在網頁上提問的 ChatGPT 使用者，也能用到相同的能力。把 Codex 併入 ChatGPT，核心動機就是把這套強大的 harness 帶給更多人。

從 chat 到 delegation：三個階段的演進

人和 AI 協作的方式，大致走過三個階段。這條演進路線能幫助你理解，為什麼現在的工作方式已經不只是「問問題、拿答案」。

階段大約時間誰在開車典型動作
Chat（問答）2024人在聊天視窗提問，再把程式碼複製回自己的 IDE
IDE collaboration（協作）2025人，AI 在旁AI 直接在 IDE 裡自動補全，或接手一小部分工作
Delegation（委派）2025 年底起Agent把整項任務交出去，人只檢查最後的變更

第一階段是純粹的問答。你在 ChatGPT 或其他對話式 agent 上提出問題、取得答案，然後親手把程式碼貼回編輯器。這種方式已經很有幫助，但主導每一個動作的人仍然是你。

第二階段開始有了協作感。AI 進入 IDE，替你自動補全程式碼，或接手一整塊工作。你仍然在駕駛，但身旁多了一位能即時幫忙的副駕。

到了 2025 年底，主導權開始轉移。人們把越來越完整的任務「委派」給 agent。OpenAI 內部，以及講者認識的許多人，已經進入所謂的 full delegation 模式：他們不再逐行盯著程式碼，而是偶爾看 code review、掃過有哪些變更，主要負責溝通需求——「我要這個，我相信你，去做。」

這個轉變代表你不必再親自處理每一個細節。你可以同時把工作分派給多個 agent，就像身邊多了一整隊隨時待命的同事。

講者特別把 GPT-4.5 視為真正的轉捩點。從那之後，Codex 和 ChatGPT 的用途就不再局限於寫程式；有時候，go-to-market 團隊和財務團隊的使用量甚至比工程師還高。

為什麼會有「兩種面貌」？

既然底層只有一套 harness，為什麼介面上還要分成 ChatGPT Work 和 Codex？原因其實很人性：非開發者容易被工程細節嚇退。

當 Codex 執行任務時，畫面可能會顯示 git 分支、程式碼差異等資訊。對工程師而言，這些是確認工作狀態的重要線索；但對不寫程式的人來說，它們看起來可能像天書，讓人直覺認為：「這是工程師才會用的工具。」

問題在於，底層明明是同一套 harness，技術上也可以視為同一個工具，卻因為介面露出了 git 和 pull request，把許多人擋在門外。

因此，OpenAI 把外觀分成兩層。ChatGPT Work 面向比較不熟悉技術細節的使用者，將 git、pull request 和程式碼藏在後面，只留下「把事情交辦出去」的體驗。

Codex 則保留開發者需要的細節與功能。你也可以在 ChatGPT app 裡切換到 Codex；使用的仍然是同一顆引擎，差別只在於介面願意向你揭露多少工作細節。

把 Codex 放回正確的位置

Codex 是 OpenAI 的 agent，不只用來寫程式。它的核心是一套 harness，負責決定模型下一步要做什麼、使用哪個工具，以及每一輪行動如何銜接。從 2024 年的純問答，到 2025 年的 IDE 協作，再到後來的 delegation，掌握方向盤的人逐漸從「你」變成「agent」。ChatGPT Work 和 Codex 其實也是同一套 harness 的兩種面貌：前者把 git 和程式碼藏起來，後者保留開發者需要的細節。理解這層關係，才能知道自己該選哪個入口。

現在可以先記住一個核心關係：引擎只有一套，但入口可以有不同外觀。接下來要看的，就是這套引擎實際長出了哪些入口——桌面 app、網頁上的 Work、瀏覽器擴充功能，以及手機遠端操作，分別連到什麼地方、適合什麼工作。
