Codex 入口地圖：Chat、Work、桌面 app、瀏覽器擴充與手機 remote

Step 2/3 · 認識 Codex 的執行位置與使用入口

先解決一個常見卡點：AI 到底碰不碰得到你的檔案？

你可能遇過這種情況：人在外面，想請 AI 修改家裡筆電上的專案，卻發現它讀不到那個資料夾。或者同事把任務交給網頁版，最後卡在「它看不到我的本機檔案」。

這通常不是模型不夠聰明，而是入口接錯了地方。同一套 Codex 引擎，接到你的筆電、雲端，或瀏覽器中的某個分頁，能看見和操作的資源都不一樣。

把 Codex 想成同一顆引擎、不同的插座：引擎本身相同，但插座接到哪裡，決定它能不能碰到你的本機檔案。這一節會把各個入口攤開比較，讓你看得出它跑在哪裡、能不能讀寫本地檔案，以及各自適合什麼情境。

桌面 app：直接連到你的電腦

如果只記一件事，記住這個：桌面 app 可以直接存取你電腦上的檔案與應用程式。

當你在做開發，專案通常已經 checkout 在本機，也是在自己的環境裡執行。這時使用本機的 Codex，就能直接處理那些檔案與應用程式。

桌面 app 也提供其他入口沒有的功能，例如 automations（排程自動化）。你還可以建立 dev box，或把任務交給雲端執行。

換句話說，桌面 app 不只是一個本機入口。你可以在同一個 app 裡選擇這次要在「你的電腦」上執行，或是把任務送到「雲端」執行。

ChatGPT 網頁：Chat 與 Work 是兩個不同的 tab

打開 chatgpt.com 後，上方的 tab 容易讓人混淆，因為 Chat 和 Work 扮演的是不同角色。

Chat 就是一般問答：你提出問題，它提供回答，不會主動操作你的檔案或專案。

Work 才是內含 Codex 的 agent，也就是這門課一路討論的工作入口。不過，Work 執行在雲端。它可以連上你的 plugins，也能完成不少工作，但無法直接碰到筆電上的本機檔案。

因此，如果你偏好在雲端工作，Work 很方便；如果任務需要直接修改本機專案，就要改用能連回你電腦的入口。

瀏覽器擴充：通往桌面 app 的隧道

瀏覽器擴充看起來像是在瀏覽器裡使用 Codex，但它其實是連到正在你電腦上執行的桌面 app。

可以把它想成一條隧道：你從瀏覽器這一端操作，另一端通往本機的桌面 app。因此，擴充仍然能透過桌面 app 存取本地檔案。

這也代表瀏覽器擴充不是第三個獨立的大腦，而是桌面 app 的另一個操作面板。它的優勢是，你可以留在瀏覽器分頁裡工作，同時使用本機資源。

手機 remote：把筆電當成遠端後端

手機上的 remote 和瀏覽器擴充的邏輯相近。你從手機發出操作，但實際上是連回自己的機器，包括本地裝置與筆電。

所以人在外面時，仍然可以處理本地檔案、修改專案。這和雲端網頁版的差異很重要：

  • 網頁版 Work：工作執行在雲端，碰不到筆電上的本機檔案。
  • 手機 remote：連回你自己的機器，因此可以處理本地檔案。

CLI 與 VS Code 擴充：同一套引擎，少了視覺介面

如果你習慣在命令列或 VS Code 裡工作，也可以直接使用 Codex。桌面 app 與 CLI 採用同一套 Codex harness，並開源在 github.com/openai/codex，因此效能上沒有本質差異。

兩者主要差在操作介面。桌面 app 提供視覺化功能，例如內建瀏覽器與標註工具；CLI 沒有這些視覺功能，但 browser use 仍然可以在一般瀏覽器中運作。

把入口掛在正確的地方

Codex 的各個入口共用同一套 harness，真正的差別在於它「跑在哪裡」以及「碰不碰得到本地資源」。桌面 app 能存取檔案與應用程式，支援 automations 和 computer use，也能在本機與雲端之間切換。ChatGPT 網頁中的 Chat 只負責問答，Work 則是執行在雲端的 Codex agent。瀏覽器擴充與手機 remote 會連回你的機器，因此能處理本地檔案。CLI 與 VS Code 使用同一套引擎，只是少了桌面 app 的視覺功能。

這張地圖解決的是「每個入口能連到哪裡」。接下來真正要做的判斷是：手上的任務需要本機檔案、雲端執行，還是只是問一個問題？入口選擇會隨著這個需求改變。
