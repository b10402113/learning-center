這個任務該從哪個入口進？判準與反例

Step 3/3 · Codex 是什麼，以及如何選擇入口

先搞清楚：你要做的決定是什麼？

上一節畫出了 Codex 的入口地圖，但真正困難的不是背下每個入口，而是任務來到眼前時，能在幾秒內選對工具。

這個選擇通常卡在兩股力量之間：雲端入口方便，打開就能用，也不受裝置限制；本地入口能力更完整，能讀寫電腦上的檔案、操作應用程式，還能設定排程自動化，但需要你的機器可用。

選錯入口，通常會立刻撞牆。需要修改本地 repo 的任務交給網頁 Work，會卡在「看不到檔案」；只是問一個概念問題卻特地開桌面 app，則像為了削一顆蘋果搬出整套廚房。

這一節會先比較各個入口，再用幾個判別問句幫你做決定，最後補上規則會翻轉的反例。

先看選項：任務特徵對應哪個入口？

判斷時，先看任務是否需要碰到本機資源。這通常是最重要的分水嶺。

判別問句：依序問自己

表格適合查閱；真正要做決定時，可以照下面的順序問自己。第一個回答「是」的問題，通常就能縮小選擇範圍。

  1. 這個任務需要讀寫我電腦上的檔案嗎？如果需要，Chat 與網頁 Work 就先出局，因為它們在雲端，碰不到你的本機。這時要選桌面 app，或選擇同樣能連回本機的擴充、remote、CLI。
  2. 我需要它操作螢幕上的其他應用程式，或設定排程自動化嗎？這兩種能力目前只有桌面 app 提供。只要會用到 computer use 或 automations，就直接選桌面 app。
  3. 我要的是「得到答案」，還是「把事情做完」？如果只是確認某個做法或理解一段概念，Chat 就夠了；如果要它實際修改內容、執行工作或開 PR，就需要有 agent 能力的入口。
  4. 我人在手機上，但任務在筆電上嗎？如果是，就用 remote 連回你的機器。不要期待網頁版能隔著雲端直接碰到筆電裡的檔案。
  5. 我要在瀏覽器的某個分頁裡就地做事嗎？如果你正看著一個頁面，想直接以那個頁面為操作場景，同時又需要碰本機檔案，就選瀏覽器擴充。

反例：規則會翻轉的情況

判準好用的前提，是你也知道它什麼時候不適用。以下幾種情況很容易讓人選錯。

第一，把「方便」誤認成「能力不足」。很多人想到 Codex，就立刻開桌面 app。但如果任務只是整理一段文案、解釋一段程式邏輯，完全不需要碰本地檔案，網頁 Work 反而更輕便。為了小任務開完整環境，只是增加摩擦。

第二，把「能力較多」誤認成「一定需要」。反過來，如果任務確實要修改本機 repo，就不能因為自己現在只想用手機而勉強使用網頁版。這時應該用 remote 連回筆電，而不是選一個根本碰不到檔案的入口。

第三，面對非工程師同事時，選錯呈現方式。如果要邀請不寫程式的人一起參與，問題不在於哪個入口能力比較強，而在於不要讓 git 分支與程式碼差異先把對方嚇退。這種情境選 Work，把底層細節藏起來，協作通常更容易推進。

第四，忘了桌面 app 本身就能切換雲端。有時你會以為本地與雲端只能二選一，必須先決定入口再開始。但桌面 app 內部就能選擇這次要在自己的電腦上執行，還是交給雲端處理。當你不確定任務最後會不會碰到本機檔案時，桌面 app 是較保險的起點。

可以直接使用的決策規則

選入口時，先問一句：這個任務需不需要碰我的本機資源？要讀寫本機檔案或操作本機 app，就用桌面 app，或選擇同樣能連回本機的擴充、remote、CLI；要設定排程自動化，使用桌面 app。只是問答，用 Chat；要交辦任務又想留在雲端，用 Work；人在外面但任務在筆電上，就用 remote 連回筆電。

最後可以把整套判斷濃縮成三步：先看任務是否需要本機資源，再看你要的是答案還是實際執行，最後確認自己是否在手機或瀏覽器等特殊場景。這樣一來，入口就不再是一張要死背的清單，而是根據任務特徵做出的選擇。
