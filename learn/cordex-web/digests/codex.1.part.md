# Digest — codex (part 1)

## Overview (L1)

- **Course framing (0).** Katia Gil-Guzman (OpenAI DevEx) introduces a full-day, hands-on workshop on building, debugging, and shipping front-end with Codex. Front-end is called out as the discipline most transformed by agentic coding: low iteration cost makes ambitious animations and novel interactions cheap, and no two learners get identical output. The goal is understanding what it means to build with a coding agent, not writing perfect prompts.
- **What Codex is + ChatGPT Work vs Codex (1).** Codex is OpenAI's agent for coding "and other tasks," now merged into the ChatGPT app. The talk traces AI evolution from 2024 chat → 2025 IDE collaboration → late-2025/full delegation mode where the agent drives and humans review. The "harness" (what the model decides to do next, which tools to use, behavior between turns) is the shared engine; ChatGPT Work is the non-technical surface (hides git/PRs), Codex is the developer surface.
- **Codex app tour (2).** Walkthrough of the desktop app: add a project linked to a local folder so Codex stays scoped; ask simple questions; low reasoning for trivial tasks; visualization skill; turn output into a React app and open it in the built-in in-app browser (Cmd+J for the terminal panel); scheduled tasks, plugins, sites, PR tab; settings to prevent sleep while running.
- **Models & reasoning effort (3).** The GPT-5.6 family — Sol (flagship, used in workshop), Terra (intermediate), Luna (small/cheap/fast). Reasoning effort levels low→medium(default)→high→extra-high→max (max is compute-intensive, avoided), plus an "ultra" mode that auto-spawns sub-agents for parallel subtasks and "fast mode" (1.5x faster tokens, burns limits faster). Free plan can try everything; publishing Sites needs at least Plus (new accounts may get 30 days free).
- **Plugins & skills (4).** Plugins bundle skills + apps + MCP servers. Apps are connectors (GitHub, Slack, Notion) authenticated on your behalf; MCP servers expose tools; skills are workflow instructions (text plus optional assets/scripts). Plugin categories: work context/communication (Slack, Gmail, Drive), source control/review (GitHub), project tracking (Linear), hosting (Vercel, Cloudflare, Render, Convex), services (Supabase, Neon), and builder workflows (build web apps, iOS, macOS, React Native, web data viz, games). Codex remotes let you run tasks on your laptop from your phone using local files.
- **Front-end dev tools (5).** The desktop app keeps you in the flow: in-app browser (import Chrome data, tabs, history, annotate, browser use), Chrome DevTools Protocol (CDP) access for logs/network debugging, annotation tool (pinpoint and annotate a visual issue, even tweak CSS/fonts), in-app PR review tab, integrated terminal, built-in image generation (uses subscription, for visual assets and product concept direction), and repo conventions via `agents.md` (starter one says ignore the prompts folder) and repo skills.
- **Creating a landing page (6).** Clone `katia-openai/master-dev-workshop`, which ships example prompts, fixtures/dummy data, an asset, a starter project, and skills (practical copywriting to avoid LLM-speak; "design UI with restraint" to avoid inventing fictional-data disclaimers). The build prompt is dissected: setup/new folder, brief, visual direction (critical or output looks generic), voice mode/dictation brainstorming, content kept practical, and finish (responsive/accessible/polished + publish via Sites). Asking Codex for three visual concepts demonstrates brainstorming with image gen; Canvas view shows concepts.
- **Using Sites (7).** Sites hosts and deploys apps directly from Codex, handling deployment, sharing, storage, and auth. Start from a prompt or import an existing project and convert it with the Sites plugin. Access: personal = public; business = built-in SSO plus workspace groups; ChatGPT identity login available; bring your own provider too. Built-in structured (Mongo-style) and blob storage are auto-selected from the prompt. Features: custom domains, environment variables (API keys), simple analytics (traffic, visitors, top pages). Unlimited on Plus while in public beta; pricing TBD; custom domains extra. Redeploys save new versions.
- **Prompting with visual examples (8).** Build "Mission Control" (workday dashboard) from dummy fixtures or real Gmail/Slack plugins (installed via `@` mention). Uses high reasoning and a provided mood-board image as visual direction; Sites' plugin skills auto-generate a visual direction before building. Covers React+Vite default framework, picture-in-picture browser use (Codex clicks around/tests breakpoints), token cost of browser use, annotation feedback pinning comments to clicked components, screenshots, and the "appshot" (Cmd+Cmd on Mac) that captures app context/URL for more efficient feedback.
- **Automations (9).** Scheduled tasks (in the scheduled tab) are prompts that run on a schedule (daily/weekly/custom, chosen hour), created in a thread or manually, either in the existing chat or a new chat each run. Example: refetch data daily at 8am and redeploy the site (caveat: public sites can't be auto-redeployed because data must be re-validated). Automations commonly chain plugins (Gmail, Slack, GitHub) to check things (PRs to review, daily briefs). Also notes companion mobile apps (React Native / iOS plugins with Xcode Build MCP and iOS simulator) and that Sites is web-only.
- **Prompt strategies for complex UIs (10).** Sets up the "A Year and a Day / One Turning World" Three.js experience (scroll-driven, 25 states, multiple cities/seasons, provided visual composition and text). Recommends permissions mode "approve for me" (auto-approves safe commands via a separate safety-check thread) over approving everything or full access; custom permissions are possible. Pets overlay monitors multiple running conversations. Stages the work: initial 3D experience → add generated sprites → refine via a goal.
- **Iterating with goals (11).** Goals keep Codex focused on an outcome: give instructions plus acceptance criteria so it knows when to stop, and you can steer mid-run. Valuable for long/hard work where Codex would otherwise stop after one pass; loops until criteria validate. Frontend use: visual targets and specific checks (e.g. no globe clipping, smooth at every breakpoint). Non-frontend use: eval/golden-set criteria (the doc-agent example used 95–97% good answers, ran 10+ hours; colleagues ran goals for days). Acceptance criteria can be exhaustive (globe visible, transitions smooth, keyboard focus behavior correct).
- **Iteration Q&A (12).** Q&A: a "set goal" skill lets Codex write goals for itself (often automatic with high-agency new models, which may also spawn sub-agents/compaction unprompted). Desktop vs CLI: same Codex harness (open source at github.com/openai/codex); CLI lacks visual features (built-in browser, annotations) but browser use still works in a normal browser. Keep one conversation for context; compaction auto-summarizes the context window (configurable at a percentage threshold) and GPT-4o+ models were trained to handle it gracefully. Example branches live under `katia/examples`.
- **Using the goal prompt (13).** Runs `/goal` and pastes the goal (slash-goal clears after starting). Fixes the sprite-fading bug and adds a corrective circle. Then a real preserved bug on the `fix visual bug` branch (Tokyo sprites behind the globe) is fixed. Covers the debugging loop as the default real-world workflow: identify and reproduce the bug, then let Codex use browser use + CDP (logs, network, layout), screenshots, and computer use (for non-web apps/simulators) to diagnose→fix→verify in a loop. Debugging split is ~50/50 human-in-loop: classic SaaS bugs self-diagnose; ambitious/novel front-ends need human judgment on "what good looks like."
- **Working in existing codebases (14).** In a shared repo, all context should live in the repo so non-engineers (PMs, designers, growth) can contribute without asking. Puts knowledge in `agents.md` project instructions and repeatable workflows in repo skills (e.g. use-case creation; media asset compression/WebP/CDN). Encodes reusable helpers, a clear design system, and existing components so Codex reuses rather than reinventing. Warns of the review bottleneck when context isn't encoded (the developer-website designer PR example).
- **Exploring the user insights project (15).** The Blossom View dashboard (globe, region filters affecting the whole dashboard) is examined. Its `agents.md` holds guidelines, skill routing, run commands (`pnpm run dev`/`build`), a repo map, library conventions (Lucide React, Recharts), and UI-testing guidance (breakpoints, scroll width). Feature prompt adds an "audience momentum" panel without naming the design system/library, proving the repo carries context. Skill design principle: keep `skill.md` as navigation, push bulk into `references/` and `assets/` (scripts fetch examples only when needed) to avoid blowing context. Notes the built-in minimal IDE (click artifacts to edit) means an external IDE is rarely needed.
- **Submitting a feature PR (16).** The audience-momentum feature lands automatically looking like the rest of the dashboard, with filters reacting correctly, because `agents.md` → skill → example components drove it. Codex auto-creates a PR and, per the PR section in `agents.md`, adds before/after screenshots at multiple breakpoints (visual evidence) so reviewers approve faster (preview branches are the alternative). Clarifies `agents.md` resolution: Codex uses the closest one (root or subfolder), can reference other MD files, and it need not be named `agents.md`.
- **Examples of living frontends (17).** "Living frontends" = Codex inventing new interaction types/components on the fly rather than conventional UI. Examples from learn.chatgpt.com: the visualized skill (returns a visualization/UI instead of chat text, e.g. summarize a document or analyze data), interactive docs built by pointing Codex at the visualized-skill code, and the screenshot-to-component skill (rebuilds screenshots as responsive, theme-adaptive, editable HTML components). Codex Mini and Codex remote demos were one-hour-hackathon recreations. Also a physical-cart e-commerce interaction. Vision: expose such skills to end users/browser agents.
- **Creating a skill (18).** Use the `skill creator` skill (a skill to create skills) to scaffold a skill with the right name, description, location, and structure. The demo builds a screenshot-to-component skill for the user-insights repo (so it can fetch real components/design system); skill creator inspects the repo, infers reusable pieces, and installs the skill in the repo (or as a personal skill at Codex home for all sessions). Generalizes to any frequent workflow: analytics-driven use-case updates, standardized empty/loading states, design-system/Storybook composite UIs, and assembling illustration compositions from exported asset bits via the skill's assets folder + scripts.
- **Execplans (19).** Answering a context-degradation/compaction question: record every decision in the repo. OpenAI uses "exec plans" (a coined term) — living MD documents Codex auto-creates when adding a feature or making an architectural/important decision, explained and gated in `agents.md` with a dedicated folder. Purpose: preserve decisions across compaction, sessions, and colleagues' Codex instances, so a later instance won't undo a deliberate choice (e.g. a security-mandated legacy library). The cookbook→developers.openai.com migration exec plan logs tasks, surprises/discoveries (build errors, missing assets), and a decision log. Especially valuable for long goals and backend-heavy repos. Demo: the screenshot-to-component skill rebuilt an independent tutorial page, adding light/dark mode, though it didn't use the real globe library.
- **Codex Q&A (20).** Why desktop: local file/app access, dev boxes/cloud tasks, and features like automations unavailable elsewhere. Clarifies surfaces: ChatGPT web "Chat" = Q&A; "Work" = the agent in the Cloud (connects plugins); browser extension tunnels to the local desktop app; remote from phone connects to your machine. Design systems: declare them in `agents.md` (lightweight repo components or a full library/Storybook, or the Figma plugin); unspecified, Codex may invent components. Living frontends maintenance: automations that check for new features and re-trigger the skill to regenerate illustrations. Testing: Codex runs command tests in the terminal automatically and does visual/E2E QA via browser use/computer use (less need for Playwright MCP); put testing guidance/scenarios in `agents.md` or a testing file. Repo hygiene: run automations to scan for stale docs/skills; extra content is fine since Codex ignores unneeded files. Introduces Codex review — a context-free separate instance that reviews code against a branch or uncommitted changes, now with custom review-rule support.
- **Wrapping up (21).** Recap playbook: start with one clear task, list required results, give files/references/tools and constraints; direction (even minimal) yields less generic output; prompts need not be perfect/messy/dictated; ask Codex to reuse existing components/styles; iterate with annotations; loop/debug until final; record repeated guidance as `.cursorrules` or a skill via skill creator. Homework: adapt Mission Control with real tools/data, fix one real pending task today, and turn repeated guidance into `.cursorrules` or a skill.
