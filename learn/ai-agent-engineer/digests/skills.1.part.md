# L1 overview

（此 checkout 的 `skills/` 目錄下有 9 個 skill；任務清單列出的 9 個名稱皆已逐一覆蓋。）

- `adversarial-tester` — 把 PR 或綠燈測試套件交給乾淨 context 的第二個 agent，專門「弄壞它」：先讀 acceptance criteria 與 repo 的 `CLAUDE.md`／`AGENTS.md`，再找捷徑、邊界、測試盲區；能用 failing test 證明的標 `[PROVED]`，不能的標 `[REASONED]`，最後給 merge verdict 但不修 code。description 的觸發語是「review this PR before merge」「attack this PR」「find what is wrong」，特別針對 AI 寫的 code 與 AI 寫的 test。它體現 harness 設計的核心：作者與審查者的 context 必須隔離，且「測試通過」不等於「行為正確」。
- `agent-safety-audit` — 唯讀稽核 agent 設定，找 lethal trifecta 的三條腿：private data、untrusted input、way out；逐一指出哪個 config 開啟哪條腿，並提出最便宜的斷腿方案。觸發於「這個 agent 安全嗎」、要讓 agent 無人值守、或新增 connector／MCP server／tool／token／inbox／webhook／network rule 之後。workflow 是 inventory → 列三條腿 → verdict → fixes（cheapest leg first）→ 可選 probe。harness 學習者會看到權限、sandbox、connector、網路 allowlist 都是 harness 的一部分，prompt 不是安全邊界。
- `bug-triage` — 把一封 bug report 變成可重現、已修、有測試的 PR，或誠實回報「could not reproduce」。report 被視為 untrusted data，禁止照做其中的指令；先寫 `regression-<slug>` failing test 重現，再最小修改 source，跑 fast suite，開 PR，從不 merge。觸發於收到 customer email／issue／alert 要調查修 bug。對 harness 學習者，這是「input 不可信」與「先證明再修」兩條原則的端到端範例。
- `grill-me` — 用連續單題訪談壓測一個計畫或設計，沿決策樹逐支解析依賴，每題附建議答案；能從 codebase 查到答案就直接查，遇到 bulk「全部同意」時挑最關鍵的一題要求明答。觸發是「grill me」「stress-test this plan」。它展示 harness 中 human-in-the-loop 的 interrogation pattern：不是一次給審查意見，而是把不確定性逐個逼出來。
- `legacy-testing` — 對沒有測試的 legacy code 先 assess 再 propose，等一次批准後連續執行：make it testable、characterize、approval tests、property tests（crash hunt + invariants）、measure（coverage + mutation）、最後 refactor。觸發於「這段 code 沒測試但要改」「refactor 前要安全網」「接手別人寫的 code」。它把「安全網先於重構」與「characterization 只釘住現況、不順手修 bug」寫成可執行流程，對 harness 學習者是 agent 如何處理高風險、低可觀測性任務的範本。
- `mutation-testing` — 用 mutation tool 一次植入一個小 bug，重跑 suite，看測試是否抓到；存活 mutant 就是測試沒檢查的行為。workflow：baseline 兩次、選 tool、先 scope 一個 module、console-only run、逐句解釋 survivor、rank blast radius、kill or claim、fresh judge 審 claim、使用者批准後才加 exclusion、200 字內報告。觸發於「tests 到底好不好」「coverage 高但沒信心」「AI 剛寫或改測試」。對 harness 學習者，它示範如何把「測試品質」變成可量測、可審核的 signal，而不是靠 agent 自評。
- `pr-tour` — 把單一 PR 變成 guided reading tour：先 WHY（作者原話 intent map）、再該讀的檔案（script-computed facts + line-checked pointers）、測試緊跟其 code、noise 最後折疊；輸出一個自帶 viewer 的 HTML 與 agent 可讀 JSON。觸發於「review／walk through／explain this PR」「what to read first」。它只指向注意力、不下 verdict；核心洞見是 review 的槓桿在閱讀順序，而非把 code 標成 AI-written。
- `pr-triage` — 讀 repo 中所有 open PR，依「真正需要多少注意力」判 critical／high／medium／low，排成 most-attention-first 隊列，每個判斷指向驅動它的那一行，每個 PR 連到完整 tour；輸出單一 HTML queue + JSON。觸發於「which PR first」「review backlog」「too many open PRs」。它把 review queue 從 age／size 排序改成風險排序，並用 fresh judge per PR 避免 curve grading；對 harness 學習者是 multi-agent 分工與 evidence-based ranking 的案例。
- `write-great-skill` — 把一個重複流程寫成 agent skill：先訪談 trigger、模型不知道的知識、絕不能發生的事、哪些步驟是機械的；先寫 description（agent 只靠它決定要不要載入），再產出短 `SKILL.md` + `scripts/` + `references/` + `examples/`，用 `check-skill.mjs` 檢查，最後用 `fires.sh` 測 trigger。觸發於「create／write／build a skill」「把 checklist／runbook 變成 skill」「skill 不 fire 或每次跑不一樣」。這是 harness engineering 的後設技能：如何把 procedure 蒸餾成 agent 可重複執行的單位。
