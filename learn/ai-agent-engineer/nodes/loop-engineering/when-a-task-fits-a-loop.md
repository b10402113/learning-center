# When a task fits

知道 loop 會取代你啟動下一個 session 之後，先別急著建流程。想把一項工作交給 AI 反覆執行，卻不確定值不值得，可以先檢查三件事：工作是否經常重複、能不能自動確認完成，以及做錯一次是否能輕易丟掉重來。

三個條件都符合，才適合把任務放進 loop，也就是讓代理依照一套流程反覆執行。

## 先確認三個條件

**這件事常常重複嗎？** 如果任務很少發生，花時間把它接進流程可能不划算。只有重複得夠頻繁，建立自動化才值得投入心力。

<!--image:1-->

**能不能自動判斷完成？** 需要有明確的檢查方式，確認任務是否達標。如果連怎麼檢查「做完了」都說不清楚，就還不適合建立 loop。

**做錯一次的代價高嗎？** 如果錯誤結果可以低成本丟掉，再重新嘗試，反覆執行就比較容易接受。相反地，如果一次錯誤就可能造成難以挽回的後果，就不適合輕率地把任務交給 loop。

## 為什麼不要從開放迴圈開始

開放迴圈讓代理有很大的發揮空間，代理可能自行探索，建構出你沒有明確要求的內容。一次單代理執行可能耗用 5 萬到 20 萬個 tokens；若多個代理一起處理開放式目標，可能耗用 50 萬到 200 萬個 tokens。即使採用寬鬆的標準，也可能產出大量沒有人要求的內容。

<!--image:2-->

因此，開放迴圈通常不適合作為團隊的起點。比較穩妥的做法是先建立封閉迴圈：明確訂出目標和步驟，為每一步設計檢查方式，也決定何時停止，或何時把工作交還給你。代理只在這個框架內反覆執行，並把每一輪的結果提供給下一輪使用。

有了明確的邊界和檢查點，就能判斷任務是否完成，也比較容易在流程中發現錯誤。這是判斷一項工作是否適合放進 loop 的關鍵。

任務篩過之後，接著把一個能穩定運作的 loop 拆成六個零件。
