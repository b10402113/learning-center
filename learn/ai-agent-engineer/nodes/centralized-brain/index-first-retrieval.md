# 檢索就是 index 加 grep

你記得自己做過某個決定，卻想不起來檔案放在哪裡。或者問 AI：「我以前怎麼處理資料庫測試？」它只翻了幾行索引，就回答「沒有相關資料」。這不一定代表你沒記下來，也可能是檢索只做了一半。

一個簡單的大腦資料夾，可以靠兩件事找資料：先看 `index.md`，再用 `grep` 搜尋全文。`index.md` 是索引，每個檔案用一行摘要說明內容，讓你找出值得打開的筆記。`grep` 則是文字搜尋，能找到索引摘要沒提到、但藏在筆記正文裡的詞。

<!--image:1-->

## 先看索引，再搜尋全文

假設你想查「測試要不要 mock 資料庫」。索引可能有一行寫著「整合測試使用真實資料庫」，另一行則說明「mock 可能漏掉哪些資料庫錯誤」。光看索引，就能找到可能相關的筆記。

索引只是入口，不是完整答案。摘要不一定會列出你提問時使用的詞，所以還要搜尋筆記和來源資料中的主題詞，以及兩三個近義詞。這樣才能找到索引摘要沒寫出的細節。

筆記有幾百則時，通常先用索引加文字搜尋就足以檢索，不一定需要向量資料庫。重點是每則筆記都有清楚的索引摘要，檔案內容也能搜尋。

## 從廣到窄，讀完再回答

實際查詢時，可以依序做四件事：

<!--image:2-->

1. **讀索引。** 先了解有哪些筆記，以及每則筆記涵蓋什麼。
2. **廣泛搜尋。** 搜尋問題中的主題詞和兩三個近義詞，也要查各類筆記、來源資料和尚未整理的收件匣。
3. **仔細閱讀。** 打開最相關的兩到四則筆記，需要時再沿著連結往下追一層。
4. **根據筆記回答。** 每個重要說法都要指出出處，並附上筆記記錄的來源，讓讀者判斷證據有多可靠。

如果筆記裡沒有答案，但 `sources/` 或收件匣中有相關資料，就要說明答案還沒整理成筆記，但有已保存的材料可查。這和「完全沒有資料」是兩種不同情況。

## 搜不到之前，不要說「沒有」

只讀索引，不能證明大腦裡沒有某個主題。索引的一行摘要可能沒有寫出使用者提問時想到的詞。因此，只有全文搜尋也找不到相關內容後，才適合說「目前沒有找到這個主題的資料」。

<!--image:3-->

搜尋到資料，也不代表可以把推測寫成事實。如果只有一個未驗證的來源，就要明說證據有限。如果有多則筆記互相支持，或找到明確記錄的決策與準則，回答才有更堅實的依據。資料可能過時時，也要提醒讀者查看日期；決定已被取代時，應以新決定為準，舊決定只作為背景。

<!--image:4-->

最後，每個事實都要有筆記支撐。找不到證據時，直接說目前資料不足，比編出看似合理的答案可靠。

不過，筆記要能被查得到，前提是裡面的規則和決定寫得夠清楚；這正是下一個主題。
