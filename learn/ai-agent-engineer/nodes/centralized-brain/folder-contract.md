# 裡面有什麼

上一段把記憶分成專案層和大腦層。這一篇只看大腦層：它是一個放 Markdown 檔案的 Git 儲存庫，把跨專案共用的規則、你正在追求的目標，或某次重要決定分門別類地存放。每個資料夾各有用途，找資料或補資料時，也比較不容易混在一起。

## 先從 index 找入口

`index` 是索引：每個檔案用一行說明內容，讓人或 AI 助手先知道該打開哪篇檔案。索引不必重述所有細節，只要負責指路。新增檔案時，也要在索引裡補上一行。

## 新東西先放 inbox

`inbox` 是收件匣。剛收集到的連結、貼上的文字、截圖，或討論中做出的決定，都可以先放在這裡。整理時，再判斷內容應該歸到哪個位置，並清空收件匣，避免新資料一直堆著。

<!--image:2-->

## intents 記下想達成的目標

`intents` 用來記錄你想完成的事。每個目標各用一個檔案，寫清楚為什麼要做，以及怎樣才算完成。AI 助手規劃工作前，可以先讀目前有效的目標，讓行動有依據。

目標達成或不再追求時，不必刪除紀錄。可以標示為已完成或已放棄，並簡單說明原因。

## guidelines 記下跨專案的做法

`guidelines` 用來存放適用於每個專案的工作規則，例如整合測試要連接真正的資料庫，而不是用模擬資料庫代替。每條規則都可以說明原因和實際做法。

只適用於單一專案的規則，不要放在這裡，應留在該專案自己的 `AGENTS.md`。

## taste 表達你認為什麼才算好

`taste` 用來記錄你的偏好、底線，以及兩種選項都可行時的取捨原則。這裡回答的不是「所有專案必須遵守哪條流程」，而是「什麼樣的結果符合你的判斷」。

例如，你可能偏好常見、容易維護的方案，而不是看起來聰明卻複雜的做法。也要寫下原因，讓 AI 助手不只知道你的選擇，也了解背後的考量。

## decisions 保存重要決定的來龍去脈

`decisions` 裡一個檔案記一項決定，並標上日期和理由。決定改變時，不要刪除舊紀錄；新增一份決定，並標示新舊文件之間的關係。這樣日後才能看出先前怎麼選，以及後來為什麼改變。

<!--image:3-->

## projects 提供專案的管理概況

`projects` 每個專案各留一份簡短說明，記錄它是什麼、程式碼在哪裡、在哪裡執行、目前狀態，以及服務對象。這裡只放管理概況；專案實際的建置方式，應記在該專案自己的 `AGENTS.md`。

## notes 收納其他值得留下的知識

`notes` 用來存放不屬於上述分類、但仍值得保存的內容，例如學到的事、比較結果，或值得保留的 AI 回答。每篇筆記都要連回來源，方便日後查證。

## sources 保存未修改的原始資料

`sources` 放原始連結、貼上的文字或檔案。這裡存放的是證據，不是整理後的說法，因此不要修改原件。其他筆記可以連回這裡，方便讀者核對原始資料。

<!--image:4-->

簡單來說，`inbox` 暫存新資料，`sources` 保存原件；其他位置則把資料整理成目標、規則、偏好、決定、專案概況或筆記。`index` 讓人知道該從哪裡找起。

知道每個資料夾的職責後，接著就來看實際檢索時怎麼使用它們。
