# 什麼該放進 memory？

分清 memory 與 context 之後，下一個問題很實際：裡面到底該放什麼？

你已經向 AI agent 解釋過某項決定的理由，隔天開啟新對話時，它卻又提出同一個被否決的做法。問題可能不在程式碼不夠清楚，而是那些理由沒有存進 memory。

Memory 是 agent 每次開始工作時會讀取的檔案，決定它能知道哪些資訊。Context 則是 agent 在這次工作中，實際用來處理問題的資訊。程式碼能呈現做了什麼，卻不一定能說明為什麼這樣做，也未必記下曾經排除哪些選項。

## 記下意圖、決策理由與商業脈絡

值得放進 memory 的內容，通常是光看程式碼無法可靠推斷的資訊，例如：

<!--image:1-->

- **意圖**：專案希望達成什麼。
- **決策與理由**：為什麼選擇某種做法，以及哪些選項已被否決。
- **商業脈絡**：哪些規則已經獲得相關人員同意，不能任意更動。

例如，退款手續費訂為百分之二，是促銷合作方同意的條件，沒有他們同意就不能更改。只把費率寫在程式裡，agent 未必會知道背後的約定。把理由和限制記下來，才不會讓 agent 把它當成一般設定，自行調整。

留下這些記錄，能減少 agent 重提已被否決的選項，也不必每次都重新詢問相同的決策理由。

## 操作步驟交給 script 或 skill

操作程序應該交給 script 或 skill 處理。Memory 不適合拿來保存每一項操作程序。例如，建立資料庫測試資料的步驟，就適合放在 script 或 skill 裡。這類程序屬於 harness，也就是支援 agent 工作的工具與流程。

<!--image:2-->

簡單來說：**記下為什麼這樣做，操作步驟則交給能執行或重複使用的工具。**

## 放在 agent 找得到的地方

agent 無法從程式碼得知的資訊，適合放進 `AGENTS.md` 或 `CLAUDE.md`，並存放在自己的 Git 儲存庫中。其他較完整的知識，可以整理成獨立的 Markdown 檔案，並準備一份索引，讓 agent 先讀索引，再找到相關內容。決策也可以各自存成檔案，方便日後查閱和維護。

<!--image:3-->

判斷一段資訊該不該放進 memory，可以先問：**只看程式碼，agent 能知道這件事的理由、限制或商業背景嗎？**如果不能，而且未來的工作可能會用到，就值得記下來；如果只是重複的操作程序，就放進 script 或 skill。

知道該記什麼之後，接著要決定這些記憶實際住在哪裡。
