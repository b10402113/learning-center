# 誰來寫？

記憶該放哪裡定下來之後，還有一個分工問題。

和 agent 合作幾次後，你可能會發現，它又提起你早已否決的做法，或再次詢問某個決策的理由。這時，光看程式碼不一定找得到答案。程式碼呈現了做法，卻未必記下這麼做的原因，也未必記下哪些選項已被排除。

值得保留到下一個 session 的資訊，可以寫進 memory。它就像 agent 每次開始新 session 時會讀取的筆記。Agent 學到值得保留的事時，就可以把資訊記下來。

例如，退款手續費是 2%，而且已獲合作方同意，就可以記下這項決定及其理由，避免 agent 之後擅自改動。相對地，如何建立資料庫資料這類操作程序，適合放在腳本或工具中，不必寫進 memory。

## Agent 寫，你審查

Memory 不只是隨手記下的備忘錄，也可以放在 Git repo 裡管理。Agent 新增或修改記憶後，你可以像審查其他變更一樣檢查 `git diff`：確認內容是否正確、理由是否完整，以及是否值得長期保留。

這樣分工的重點是：**Agent 學到重要資訊時負責記下來，你負責審查變更。** 你不必每次都親手整理筆記，也不必無條件接受 agent 寫下的內容。

如果不同的 agent 共用同一份 memory，它們就能讀取相同的決策與背景，也能把新學到的資訊寫回同一處。

## 跨 session 的工作交給 loop

Memory 能讓新 session 一開始就讀到先前留下的資訊，但不會自行決定下一步，也不會自動完成長期目標。一般情況下，每個 session 結束後，你仍要閱讀結果、判斷接下來該做什麼，再啟動下一個 session。

如果目標需要跨越多個 session，就可以交給 loop。Session 內的 agent loop 負責執行工具。跨 session 的 loop 則負責觸發下一輪，並檢查工作進度。簡單來說，memory 負責讓 agent 記得重要資訊，loop 負責讓多階段工作在不同 session 之間接續進行。

memory 解決的是「記得」；下一個課題是讓多個 session 串成一個不會提早停下來的 loop。
