# Memory 決定 agent 能知道什麼，context 決定這次呼叫用什麼

harness 決定單次 run 怎麼跑；跨 session 還能留著的東西，則是 memory。

你已經告訴 agent 某個選擇不可行，也說明了原因；隔天開啟新的 session，它卻又提出同一個方案。這通常不是它故意忽略你，而是那段對話沒有被保存下來。

**Memory（記憶）是 agent 每次開始 session 時會讀取的檔案，用來延續過去的資訊。**新的 session 會重新載入設定和記憶，但不會帶著上一段對話一起開始。只在聊天中提過的決定和理由可能因此消失；對話經過精簡時，部分內容也可能不再保留。

**Context（上下文）是模型這次呼叫時讀到的所有內容。**其中可能包括系統指示、工具說明、專案文件、memory 檔案、你這次的提問，以及 agent 讀過的檔案、指令輸出和先前回答。每一輪新增的內容，都會成為後續呼叫參考的上下文。

兩者的差別可以這樣記：memory 是跨 session 保存的資訊；context 是這次呼叫實際用來判斷和作答的內容。Memory 檔案讀取後，也會成為 context 的一部分。

例如，你已決定退款手續費是百分之二，促銷合作方也已同意，在取得同意前不要更改。若這項決定只留在聊天裡，下一個 session 的 agent 可能不會知道，於是又提出調整費率。把決定和理由寫進 memory，agent 下次開始時就能讀到，比較不會再次提出已被否決的選擇。

<!--image:2-->

如果 agent 在同一個 session 裡忘了較早的指示，問題比較可能出在 context：那段內容沒有在這次呼叫中妥善保留或使用。如果它在新的 session 裡再次提出你以前否決的選擇，就要檢查這項決定是否寫進 memory。

Memory 適合保存意圖、決策及其理由，或 agent 無法從程式碼看出的業務背景。如何建立資料庫等操作步驟，則適合放在腳本或技能中。這樣，memory 保存「為什麼」，每次呼叫的 context 則提供 agent 當下要處理的材料。

既然 memory 該保存的是理由與背景，下一個問題就是：哪些內容真的值得寫進去。
