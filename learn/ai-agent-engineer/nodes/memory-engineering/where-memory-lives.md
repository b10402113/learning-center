# 記憶住在哪裡

知道哪些內容該記之後，還得決定它們放在哪裡。

每次開啟新對話，agent 都會再問一次退款費率為什麼是這個數字。你明明解釋過了，程式碼裡卻找不到當初決定的理由。這類資訊該放在哪裡，才不用每次都重講？

可以先分清楚兩件事：記憶決定 agent 平常能知道什麼；這次對話的上下文，則決定它這次會用到什麼。程式碼能顯示系統目前怎麼運作，卻不一定會留下決策理由、曾考慮但否決的選項，或不能任意更動的業務約定。

## 把程式碼看不出的事放進 AGENTS.md

`AGENTS.md` 或 `CLAUDE.md` 適合記錄 agent 無法單從程式碼得知的內容，例如你的意圖、決策理由和業務背景。

像是：「退款手續費是百分之二，這是主辦方同意的；沒有先詢問他們，不要更改。」程式碼或許看得出費率是百分之二，卻不一定看得出這項約定是誰同意的，以及為什麼不能擅自修改。

## 把其他知識放進獨立的 git repo

不必把所有記憶都塞進 `AGENTS.md`。其他需要長期保留的內容，可以放進獨立的 git repo，當作第二大腦：用 Markdown 檔整理，讓 agent 先讀索引，再依需要查看內容；每個決策各自存成一個檔案。

<!--image:2-->

操作流程不屬於記憶。例如，建立資料庫測試資料的方法，適合寫成腳本或技能。這些是 agent 使用的工具與流程，不是需要記住的決策背景。

## 讓所有 agent 共讀共寫

如果筆電上的 Claude Code、伺服器上的 agent 和雲端 agent 都連到同一個第二大腦，就能讀取並更新同一份記憶，不必各自保留一套。

<!--image:3-->

有值得留下的資訊時，可以讓 agent 提出修改。第二大腦是 git repo，所有內容變更都會呈現為差異。你可以像審閱其他程式碼變更一樣檢查，再決定是否接受。

位置與流程都定好之後，最後要講清楚：誰負責寫，誰負責審。
