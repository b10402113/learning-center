# 差別在 harness

環境裝好、課程要用的工具都到位之後，第一個要建立的是判斷力。你請 AI 幫忙改程式，結果不如預期，可能會先想到換個更強的模型。但問題不一定出在模型，也可能是指令、模型能看到的資訊，或執行任務時使用的工具與檢查方式。

Terminal Bench 是一套評測程式碼代理的測試。在測試中，只更換模型周圍的 harness，同一個模型的排名就從前三十名升到前五名。模型和任務都沒變，改變結果的是 harness。

Harness 可以想成包在模型外面的執行環境，包含可用工具、權限設定，以及代理必須通過的測試。模型像引擎；要讓它做好工作，周圍的配置也很重要。

## 失敗可以從六層找起

除了模型本身，代理的工作還牽涉六個層次。遇到失敗時，先判斷問題出在哪一層，通常比只改提示詞更容易找到方向。

<!--image:1-->

1. **Prompt（提示詞）**：為任務寫下的指令。先確認指令是否清楚說明要做什麼。
2. **Context（上下文）**：模型每次呼叫時實際取得的資訊。先確認它當下看到的內容是否足以完成任務。
3. **Harness（執行環境）**：模型周圍的工具、權限、執行流程，以及必須通過的測試。先確認執行時是否有合適的工具和檢查方式。
4. **Memory（記憶）**：代理在工作階段開始時讀取的檔案，以及學到值得保留的資訊時寫入的檔案。先確認重要經驗能不能留到下一次工作階段。
5. **Loop（迴圈）**：啟動一次執行的觸發方式，以及判斷目標是否達成的檢查。先確認任務是否適時開始，以及怎樣才算完成。
6. **Boundary（邊界）**：代理所在環境的範圍，也就是它能接觸到的內容。先確認代理可到達的範圍是否符合預期。

這六層處理不同問題：提示詞管指令，上下文管模型看到的資訊，harness 管執行時可用的工具與檢查，記憶管經驗如何延續，迴圈管任務何時開始與結束，邊界管代理能接觸的範圍。

因此，代理做不好一件事，不代表一定要先換模型。Terminal Bench 的結果顯示，同一個模型也可能因周圍配置不同而有很大差異。先找出失敗所在的層，才能知道該調整什麼；下一頁就把這七層完整排成一張地圖。
