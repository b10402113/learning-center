# Agent 的七層地圖與每層的職責

上一頁看到，同一個模型換掉周圍的 harness，排名就從前三十升到前五。這一頁把那些「周圍的東西」攤開成一張地圖。

你請 Agent 修改程式，結果它忘了先前交代的規則、猜出一個不存在的 API，或做完就停，沒有確認結果。這時先別急著重寫提示詞，問題可能出在不同層。

記住這個順序，就能先找出該檢查哪一層：

**Model → Prompt → Context → Harness → Memory → Loop → Boundary**

從裡到外看，前幾層處理單次呼叫與執行，後幾層則決定工作如何延續，以及 Agent 能接觸到哪些資源。

<!--image:1-->

1. **Model（模型）：選對引擎。**  
   模型提供推理能力。這一層要確認的是「用哪個引擎」。例如，呼叫成本太高，或程式碼不能離開自己的電腦，問題就可能出在模型層。

2. **Prompt（提示詞）：寫清楚這次的指令。**  
   提示詞是為單一任務寫下的要求。輸出格式錯誤，或 Agent 遇到空白處就自行採用預設做法，可能是指令沒有交代清楚。

3. **Context（上下文）：整理好這次呼叫會看到的內容。**  
   上下文是模型在一次呼叫中能看到的所有資訊。如果 Agent 忘了先前交代的事，或執行一段時間後開始犯錯，可能是重要資訊沒有留在它當下能看到的內容裡。

4. **Harness（執行框架）：提供工作所需的工具與檢查。**  
   Harness 是包在模型周圍的機制，包括工具、權限、掛鉤（hooks）和必須通過的測試。如果 Agent 猜測一個沒有工具可查證的 API，或自認完成工作就停下，沒有人檢查結果，就該檢查這一層。

5. **Memory（記憶）：把值得保留的資訊帶到下一次工作。**  
   記憶是存放在磁碟上的檔案。Agent 可以在工作階段開始時讀取，也可以把值得保留的經驗寫進去。如果它在新一輪工作中又重複先前已被否決的選擇，可能是記憶沒有記下來，或沒有被讀取。

6. **Loop（循環）：設定何時啟動，以及何時算完成。**  
   循環由觸發條件啟動一次執行，再透過檢查判斷目標是否達成。Agent 一直不停，或目標還沒完成就先停止，問題可能出在這一層。

7. **Boundary（邊界）：限制 Agent 能接觸的範圍。**  
   邊界決定工作環境的範圍，也包括 Agent 透過工具能接觸到的資源。如果一個錯誤指令可能碰到金鑰、其他程式庫或整個網際網路，就該檢查 Agent 能接觸到哪些資源。

可以把 Agent 理解成 **模型加上 Harness**：它透過工具反覆執行任務，直到循環中的檢查確認目標達成。一次執行結束後，上下文就會消失；記憶則負責把重要資訊留給下一次。

所以，Agent 失敗時先找層級，再選修法：提示詞不能補上缺少的測試，換更強的模型也不能解決上下文塞滿的問題。

地圖上的七層要怎麼記？最實用的記法是把 agent 拆成「模型」與「harness」兩塊，再往下看一次 run 之內與之後各自留下什麼。
