# Agent = model + harness

七層地圖上，harness 是最容易被誤解的一層。讓 AI agent 修改程式時，你可能會想知道：它這一輪能做什麼？工作結束後，又有哪些資訊會留下來？

可以先用一個簡單的式子理解：**agent = model + harness**。Model 負責產生判斷與回應。

Harness 是模型周圍的執行環境，包含可用工具、權限、hooks，以及必須通過的測試。模型會在 harness 提供的條件下使用工具，並透過循環逐步完成目標。

## 一次 run 之內：工具、任務與可達範圍

一次 run 從某個觸發開始，agent 接著使用工具處理任務。檢查結果確認目標已達成後，這個循環就會結束。

例如，讓 agent 修改程式並執行測試，就可以用測試結果判斷任務是否完成。

這一輪能處理哪些事情，它能接觸到哪些內容，取決於所處的環境。環境包括 agent 正在處理的內容，例如程式碼庫、測試、Git 歷史，以及能透過工具連線的服務。

<!--image:2-->

**boundary（邊界）** 決定環境延伸到哪裡，也就是 agent 能接觸到哪些內容。

服務或資料若在可達範圍內，就屬於 agent 工作的環境。若不在範圍內，agent 這一輪就無法透過工具接觸到它。

設定邊界，就是界定 agent 在最糟情況下可能影響的範圍。

## run 結束後：記憶留下來，這一輪不會

一次 run 結束時，這一輪的工作視窗也就結束了。agent 不會自動把整個 run 延續到下一次。

值得保留的資訊可以存成磁碟上的檔案，作為記憶。agent 可以在下一次 session 開始時讀取，也可以在學到值得留下的內容時寫入。

<!--image:3-->

因此，run 和記憶負責不同的事：**run 處理眼前的一個目標；記憶則把值得保留的內容帶到下一次。**

Loop（循環）中的觸發條件也可以啟動下一次 run，讓 agent 在沒有人介入的情況下再次開始工作。

理解這個分工，就能分清楚三件事：harness 規定這一輪的工作方式，環境是 agent 實際處理的內容與能連線的服務，而 boundary 則劃出環境的可達範圍。
