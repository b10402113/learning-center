# 把清單保持簡短

三個 server 是常見的起點，但清單不該停在三個。開始一段工作時，代理程式通常會先看到各項工具的名稱，等到真的要使用時，才載入完整定義。每多連接一個 server，工具名稱就會出現在每段工作裡；名稱相近的工具越多，代理程式越容易選錯。

所以，server 清單不必求多，只連接真正會用到的項目。若 server 下載任何內容，也要把下載來源的主機加入執行環境的允許清單。

<!--image:1-->

挑工具時，可以先看代理程式需要什麼能力：

<!--image:2-->

- 需要一套操作流程或專案知識，例如「如何部署」：用 skill。
- 已有好用的命令列工具，例如 GitHub、雲端服務或 Kubernetes：用 CLI，讓代理程式在命令列執行，不必另外連 server。
- 需要查詢即時狀態，但沒有合適的 CLI，例如瀏覽器、SaaS API，或使用代管驗證的資料庫：再用 MCP server。

把清單縮到剛好夠用，能減少相似工具造成的混淆，也讓代理程式更容易選對工具。清單定下來之後，還有一個更基本的問題：這個能力到底該用什麼形式提供？
