# 依 agent 的需要來選

清單要短，短到只留下真正需要的工具；而那個工具該長什麼樣子，是另一個問題。要讓 agent 幫忙部署時，你可能想把團隊的部署步驟交給它；要查 GitHub 或 Kubernetes，則可能只需要一個指令工具；如果要確認網頁現在實際顯示什麼，就得讓它讀取即時狀態。這三種需求，適合的做法不一樣。

**需要遵循一套程序或專案知識，就用 skill。**例如部署時要先檢查哪些項目，或遇到問題時先看哪個 log。Skill 通常以資料夾形式提供，`SKILL.md` 是入口，旁邊還可以放腳本、參考文件與範例。Agent 需要時才載入相關內容；平常只會看到 skill 的名稱和說明，不必每次都把整套文件放進上下文。

**有好用的 CLI，就直接用 CLI。**像 GitHub、雲端服務或 Kubernetes，如果已有適合在終端機執行的命令列工具，agent 可以直接在 shell 裡操作，不一定要額外架設 MCP server。

**需要讀取即時狀態，而且沒有好用的 CLI，就考慮 MCP。**MCP 讓 agent 透過 server 連接瀏覽器、文件、資料庫或 GitHub 等外部系統。它可以讀取特定版本的文件、網頁實際呈現的內容，或瀏覽器主控台裡的錯誤，而不是只憑記憶猜測。

挑工具時，先問自己：agent 需要的是「照著做的知識」、一個現成指令，還是外部系統的即時資訊？前者選 skill，有可靠 CLI 就選 CLI，必須取得即時狀態且沒有合適 CLI 才選 MCP。

MCP 也不宜接得愈多愈好。每個 server 的工具名稱都會出現在 agent 的工作環境裡；相似工具一多，agent 更容易選錯。只連接實際會用到的 server，通常更清楚。
