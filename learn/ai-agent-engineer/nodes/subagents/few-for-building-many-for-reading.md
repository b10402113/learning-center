# 建置用少數，讀取用多數

子代理各自在自己的 window 工作，只把摘要帶回主代理。既然隔離已經有了，下一個問題就是同時開幾個。你想讓多個 AI 助理同時幫忙改程式，進度看起來會快一些；但如果它們在同一份程式碼上動手，可能一個改了函式名稱，另一個卻還在呼叫舊名稱，最後讓建置失敗。

<!--image:1-->

建置工作適合交給少數助理，尤其是同一份程式碼最好由一個助理負責。不同助理也可能對同一種情況做出不一致的決定，例如一個回傳 `null`，另一個則丟出錯誤。即使沒有直接改到同一行，這些差異也可能讓整合變得困難。

讀取型工作則不同：助理只分析、不修改程式碼，彼此不會互相覆蓋，因此適合平行進行。你可以讓不同助理各自研究功能的不同面向、找出某項修改會影響哪些地方，或從獨立角度檢查程式差異。由沒參與撰寫的助理檢視差異，也比較容易看出作者忽略的問題。

如果確實要讓兩個助理同時建置，做法是替每個助理準備獨立的 Git worktree。Worktree 是同一個儲存庫的另一份工作目錄，各自使用不同分支，修改便不會直接撞在一起。完成後，再像一般合併請求一樣整合各分支。

<!--image:2-->

簡單判斷：需要分析、搜尋或檢查的工作，可以多個助理平行處理；需要修改程式碼的工作，則避免讓多個助理共用同一份工作目錄。但就算工作切得開，多開代理也不是免費的。
