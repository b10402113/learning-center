# 一個獨立的 window

你請 AI 研究一個問題，讓它搜尋網頁、讀檔案、整理資料。等它終於要開始處理真正的工作時，對話裡已經塞滿了搜尋結果和閱讀內容。

這就是主 window 容易遇到的狀況：研究過程中的每份檔案、每筆搜尋結果和每個網頁，都會占用它的上下文空間。資料愈多，留給後續工作的空間就愈少。

<!--image:1-->

另一個問題出現在自我審查。若同一個代理寫完程式後再檢查自己的成果，它仍保留著當初寫程式時的推理。原先採用的假設也跟著留在心裡，於是同一個錯誤可能看起來還是合理。

<!--image:2-->

子代理的做法，是另外開一個獨立的 window。它在自己的上下文裡讀資料、做搜尋；完成後，只有摘要會回到主 window。主 window 不必把所有研究細節都留在對話中。

這個新 window 一開始也不會看到主 window 的對話、已讀過的檔案，或曾使用的技能。它只收到一則交辦訊息，並根據這個訊息開始工作。因此，若要它協助檢查成果，主代理可以把檢查任務交給一個沒有參與原始推理的代理，讓它從不同的起點閱讀。

子代理不是讓所有內容都消失，而是把大量閱讀與搜尋留在另一個 window，只把摘要帶回來。這既能減少主 window 被研究資料塞滿，也能避免審查完全沿用原本寫作時的那組假設。
