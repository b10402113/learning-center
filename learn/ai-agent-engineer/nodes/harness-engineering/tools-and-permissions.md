# Harness 用 tools 與 permissions 補上的缺口

上一頁列出的三個缺口，前兩個剛好是相反方向。請 AI 修改專案時，可能會遇到兩種問題：它不知道怎麼操作某個系統，只能憑印象猜；或者它真的開始執行，卻做了你不希望它做的事。

Harness 是包在模型外面的執行環境。模型提出工具呼叫後，Harness 負責執行，並把結果放回對話，讓模型判斷下一步。

這個過程會反覆進行，直到模型不再呼叫工具，改以文字回覆。

模型負責判斷與生成，Harness 則讓判斷轉化為可管理的行動。

要解決「不會做」和「做過頭」這兩種問題，可以分別從 tools 和 permissions 著手。

## 不會做：用 tools 提供可靠的操作方式

如果 AI 沒有操作某個系統的工具，它可能會憑記憶寫出 API 呼叫，但猜測不一定正確。

Tools 可以明確定義需要執行的操作，由程式實際執行，再把結果回傳給模型。

<!--image:1-->

例如，工作需要查詢專案資訊時，可以提供明確的工具，讓模型透過工具取得結果，而不是自行猜測該呼叫什麼介面。

模型可以根據實際回傳的內容繼續處理，減少憑空猜測。

任務需要不同專長或工作步驟時，也可以使用 sub-agents（子代理）。

Tools 與 sub-agents 都由你定義、由程式執行，再把結果交回模型。

它們補足的是能力缺口，讓模型能透過可用的操作，完成原本不會做的事。

## 做過頭：用 permissions 限制行動範圍

工具讓 AI 有能力採取行動，但有能力不代表每個行動都該直接執行。

Permissions（權限設定）用來界定模型能做什麼，以及哪些行動需要額外把關。

<!--image:2-->

常見做法包括允許清單、沙箱，以及為破壞性操作設置核准關卡。

允許清單限制可執行的項目；沙箱限制操作範圍；核准關卡則會讓高風險行動暫停，等待確認。

Tools 和 permissions 解決的是不同問題：tools 提供完成工作的合適方法，permissions 則避免 AI 超出允許範圍。

只提供工具，可能讓 AI 做得過頭；只設限制，卻沒有合適工具，也可能讓 AI 無法完成任務。

Harness 還可以加入驗證，例如執行測試、檢查資料格式，或拒絕無法編譯的結果。

AI 犯錯時，可以把問題轉成新的規則或檢查，讓下一次執行更可靠。

工具與權限之後，harness 還缺最後一塊：讓 run 自己證明完成。
