# Window 是有限的

prompt 寫得再清楚，也得擠進模型當下讀得到的 window。你剛開始請 AI 助手修改程式，幾輪之後，它卻忘了先前交代的限制，開始犯原本不會犯的錯。這不一定是提示詞寫得不夠清楚，也可能是它的 window 已經塞進太多內容。

Window 是模型一次回應時能讀取的有限上下文。你還沒輸入訊息，window 裡就可能已經有系統提示、內建工具的說明、`AGENTS.md` 或 `CLAUDE.md`、記憶檔、技能說明，以及 Git 狀態快照。你的提示只占了這些內容的一小部分。

<!--image:1-->

對話開始後，助手讀取的檔案、每次指令的輸出，以及它先前的回答，也會不斷加入上下文。每一輪，模型都會重新讀取 window 裡的內容。

因此，除錯對話可能累積數萬個 token。Window 越滿，模型越可能忽略先前的指令，也越容易出錯。反覆改寫提示後，助手仍然以同樣的方式失準，問題可能不在措辭，而在它處理的整體上下文。

<!--image:2-->

Window 裝滿時，Claude Code 會進行 compaction：把對話整理成摘要，再用摘要取代原本的對話。摘要沒保留的內容，模型之後就看不到了。被省略的內容可能包括先前的指令、你在聊天中做出的決定，以及做出決定的理由。

<!--image:3-->

新開工作階段，不會自動帶回聊天中的內容。設定、hooks 和 `CLAUDE.md` 會重新載入，但對話會從空白開始。只在聊天中說過的決定與原因，可能在新工作階段消失，也可能在 compaction 時被摘要漏掉。
