# 四種 context 操作：select、compress、isolate、offload

知道 window 一定會滿之後，就能主動決定要讓什麼進去。

你可能遇過這種情況：一開始請 AI 助理修正一個問題，後來又加了幾項不相關的工作。對話愈來愈長，模型開始反覆嘗試，甚至忽略先前提過的限制。這時，問題可能不只是指令不夠清楚，也可能是 context window 裡放了太多內容。

Context（上下文）是模型每次回應時能讀到的資訊，包括系統提示、工具定義、專案指引、記憶檔、你的提問，以及先前讀過的檔案、指令輸出和對話。每一輪回應時，這些內容都會一起進入模型的視野。Window 有容量上限；放進去的內容愈多，重要指示就愈容易被其他資訊淹沒。

可以用四種方式管理模型實際讀到的內容：select、compress、isolate、offload。

## Select：只提供這次任務需要的內容

Select 是挑選必要資訊，不要把整個專案都交給模型。

<!--image:1-->

例如，請模型修正某個檔案時，直接提供檔案路徑，讓它依需要讀取其他檔案。不要因為怕它「不知道全部」，就貼上整個程式庫；這會讓 window 塞滿與目前任務無關的內容。

在 Claude Code 中，Skills 和 MCP 工具會在使用時才載入完整內容，代理也能依需要讀取檔案。做法的重點是先提供足夠的入口，再讓模型需要時自行取用其他內容。

## Compress：把舊對話整理成摘要

對話累積一段時間後，可以用摘要取代部分舊內容，保留重點並減少背景資訊占用。Claude Code 的 compaction（上下文壓縮）會把對話整理成摘要；也可以在適當時機使用 `/compact` 主動壓縮。

<!--image:2-->

壓縮後，摘要沒有保留的細節，模型就無法看到。因此，後續仍重要的決策、限制或待辦事項，都要確認有寫進摘要，不要假設模型還記得完整對話。

## Isolate：讓支線任務使用自己的 window

如果某項工作需要大量探索，例如調查某種行為出現在哪些檔案中，可以交給 sub-agent（子代理）處理。子代理在自己的 window 裡讀取和分析資料，最後只把摘要帶回主對話。

<!--image:3-->

例如，子代理可以搜尋上百個檔案，主對話只接收調查結果。這樣就不會讓搜尋過程的大量細節占滿主 window。

## Offload：把大量內容存進檔案

計畫、交接資訊或冗長的建置輸出，不必一直留在對話裡，可以存成檔案，需要時再讀取。

<!--image:4-->

例如，長篇建置輸出可以存放在 `build.log`，不用整段貼進對話。準備換工作階段時，也可以把目前進度寫成交接檔，讓新工作階段接著處理。

交接檔可以記下目標、已完成事項、下一步、相關檔案，以及哪些嘗試沒有成功。接著用 `/clear` 清空舊工作階段，再讀取交接檔，從「下一步」繼續。這樣比讓新任務帶著前一段對話，更能維持焦點。

<!--image:5-->

## 讓四種操作融入工作習慣

實際操作時，可以先確認任務需要哪些檔案，提供路徑，讓代理按需閱讀；研究或大量搜尋則交給子代理。遇到不相關的任務，可以開新工作階段或使用 `/clear`，避免前一項工作的雜訊一路跟過來。

如果同一個問題修正兩次後仍不理想，與其繼續在原對話裡堆疊更正，不如寫成交接檔，重新開始。若代理不斷重複、堅持已被否決的想法，或開始偏離任務，也可以結束目前的工作階段。Claude Code 的 `/context` 可以查看目前 window 裡有哪些內容，適合在繼續輸入前先檢查。

這四種操作的共同目的，是控制模型每次實際讀到的內容：挑選需要的資訊、濃縮舊內容、隔離支線工作，並把大量資料存進檔案，等需要時再取用。

model、prompt、context 都屬於單次呼叫的範圍；再往外一層，就是決定工具與檢查怎麼運作的 harness。
