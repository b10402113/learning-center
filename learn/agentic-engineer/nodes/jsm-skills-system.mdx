# JSM Skills System：安裝與九步驟地圖

## Learning goal

安裝九個 skill 並畫出完整迴圈（idea→scope→architect→develop→audit→check verify→test→review→document→sync，debug 隨時），說出每個 skill 的入口與產物。

## Steps

1. [[learn/agentic-engineer/nodes/jsm-skills-system/install-skills-system|安裝 JSM Skills System]] — 一條指令裝好九個 skill，認出它們住哪，以及「skill 只是 markdown 檔」的意義
2. [[learn/agentic-engineer/nodes/jsm-skills-system/why-the-workflow-is-structured-this-way|這套流程為什麼長這樣]] — SDLC 與 ADR 是它的來源，不是誰的個人偏好
3. [[learn/agentic-engineer/nodes/jsm-skills-system/the-nine-skills-map|九個 skill 的地圖]] — 完整迴圈、每個 skill 的角色與產物（after steps 1–2）
4. [[learn/agentic-engineer/nodes/jsm-skills-system/state-in-files-and-ownership|狀態存檔案，不存對話]] — 四種檔案、各自的 owner、/sync 如何讓文件活下去（after step 3）
5. [[learn/agentic-engineer/nodes/jsm-skills-system/finding-your-entry-point|從哪裡進入這個迴圈]] — 新專案／既有碼庫／單一變更／monorepo 的入口選擇與 /audit 的移動規則（after steps 3–4）

## Lesson

這一節是整個 workflow 模組的入口：先把 JSM Skills System 裝起來，再拿到一張「九個 skill 各自站在哪、產出什麼」的地圖。重點不在記住指令，而在建立一個可重複的形狀——**一個想法進來，經過一連串具名步驟與具名文件，最後變成被證明能跑、可交付的程式**；`/debug` 則像安全閥，任何時候東西壞了都能抽出來用。

地圖之後還要把兩件事講清楚。第一，這套流程不是某個人的偏好，它是把軟體開發生命週期（SDLC）與架構決策紀錄（ADR）搬進 agent 的對話裡，用來擋住 agent 最危險的本能——衝過還沒決定的事、自己默默補上。第二，這套系統的狀態活在檔案裡（scope、specs、`AGENTS.md`、`design.md`），不活在 chat 裡，每個檔案只由一個 skill 擁有內容，所以工作能跨 session、跨人存活；`/sync` 負責在事後把文件對回程式庫的真實樣子。最後一步回答「我該從哪裡進去」——新專案和既有碼庫的入口不同，`/audit` 的排序規則就是最明顯的證據。
