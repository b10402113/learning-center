<LearningGoal>
用讀一遍、跑一個指令、檢查漏掉的慣例與站不住腳的理由四項檢查，判斷一張生成地圖能不能拿來當變更依據，並守住「只補缺、不動既有」的界線。
</LearningGoal>

## Lesson

生成的地圖是證據不是真相：動手前用四項檢查（對著專案讀一遍、跑一個指令、找漏掉的慣例、找程式碼支撐不起來的理由）判斷能不能直接開工；缺的是區域規則就先補地圖，而且只補缺、不動既有。
