<LearningGoal>
判斷一份 audit 生成的地圖何時可以信、何時要打折扣，並說出「讀它對照實際專案、至少跑一個指令、檢查漏掉的慣例」這套驗證動作與「只補缺的、保護別人已寫的」的克制原則。
</LearningGoal>

## Lesson

audit 生成的地圖是證據不是真相：動手前要對著真實專案讀一遍、確認 stack、至少跑一個指令、檢查有沒有漏掉看得見的慣例或給出程式碼支撐不起來的理由；要防的是會影響改動的錯誤，而不是整份重寫，底層原則仍是只補缺的、保護別人已寫的。
