<LearningGoal>
認出 /audit 在一個已成熟 repo 上為什麼走整庫掃描、產出 root 與 nested 地圖各放什麼，以及它怎麼用 sub-agent 與 skills／MCP 建議而不把主對話塞滿。
</LearningGoal>

## Lesson

在已成熟的 repo 上，`/audit` 走整庫掃描而不是慣例問答：root `AGENTS.md` 記錄 stack、每日指令、慣例與風險，nested 檔案只出現在 `database`、`app` 這類有自己規則的區域，並用 sub-agent 找 skills／MCP，讓主對話只留下可判斷的結果。
