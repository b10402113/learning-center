<LearningGoal>
在舊碼庫的變更收尾時選對證明方式（先 check verify 再 check review）、判斷 skill 之間何時該 clear，並分辨哪種小修正可以跳過 /scope、哪種缺口必須退回 /architect。
</LearningGoal>

## Lesson

收尾先用 `check verify` 證明功能今天能用，再用 `check review` 換一個視角看 diff 的風險；clear 的時機是下一個 skill 只需要產物、不需要對話，小修正可跳過 `/scope`，缺少會改變行為的重要決定則退回 `/architect`。
