<LearningGoal>
在舊碼庫的變更收尾時決定用 check verify 還是 check review、判斷何時該在 skill 之間 clear、以及什麼情況下一個小修正可以跳過 /scope 直接進 /develop。
</LearningGoal>

## Lesson

收尾時用 `check verify` 證明功能今天能跑、用 `check review` 取得另一個視角（兩者不互相取代），階段間在結論已寫進文件後才 `clear`，單一小功能或一行修正可跳過 `/scope` 直接進 `/develop`，若 `/develop` 發現缺了重要決定就送回 `/architect`；原則是用這次變更值得的流程量去做它。
