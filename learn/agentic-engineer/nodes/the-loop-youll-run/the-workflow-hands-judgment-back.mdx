<LearningGoal>
說出這套 workflow 的非強制設計——每一步只是建議不是閘門、`done` 由你宣告、review 只讀不改、上網要先問、沒有默默替你做的決定——並解釋這些設計如何把判斷權留在人手裡。
</LearningGoal>

## Lesson

這套 workflow 用五個非強制設計把判斷留給人：每一階段只是建議不是閘門（tier 只決定建議的完成點）、`done` 由你宣告、review 只讀不改、要連外網先問你、遇到沒把握的決定就停下來寫成 `Assumed` spec 而非默默替你決定。它是一道很強的閘門，但不是絕對保證，漏掉的由 verify 與 test 兜底。
