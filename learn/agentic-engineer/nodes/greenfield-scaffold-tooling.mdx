# Greenfield：Scaffold、Tooling 與規範

## Learning goal

從 spec 0001 生出可跑的 scaffold、env 與 GitHub repo，用 /audit 捕捉規範、用 tooling 強制執行。

## Steps

1. [[learn/agentic-engineer/nodes/greenfield-scaffold-tooling/scaffold-and-verify|從 spec 0001 生出可跑的 scaffold]] — 跑 develop 的 scaffold subtask 生出專案、產生 example env，並用 build ＋首頁 200 證明它能跑
2. [[learn/agentic-engineer/nodes/greenfield-scaffold-tooling/capture-standards-with-audit|/audit：把專案規範捕捉進 AGENTS.md]] — greenfield audit 是 standards capture，訪談出短小的 AGENTS.md（after step 1）
3. [[learn/agentic-engineer/nodes/greenfield-scaffold-tooling/decide-testing-and-ownership|決定測試策略與 ownership 護欄]] — 不寫測試的選擇、與 spec 衝突的 reconciliation、scoped query helper（after step 2）
4. [[learn/agentic-engineer/nodes/greenfield-scaffold-tooling/enforce-standards-with-tooling|用 tooling 把規範變成機械檢查]] — Biome ＋ Lefthook pre-commit ＋ raw DB import 禁令，對回 scope／sync（after step 3）
5. [[learn/agentic-engineer/nodes/greenfield-scaffold-tooling/push-to-github|把 scaffold 推上 GitHub]] — 自動 Git、建 repo、加 remote、推 main 與 feature branch（after step 4）
6. [[learn/agentic-engineer/nodes/greenfield-scaffold-tooling/manage-skills-and-context|維持 agent 效能：skills、context 衛生與交棒]] — 只裝官方 skills、每 feature 之間 /clear，交棒資料模型（after step 5）

## Lesson

`/scope` 與 `/architect` 把點子變成 spec 0001 之後，這一課負責把它落成一個真的能跑、有規範、有護欄、也已經進版控的專案。這是一條「先讓它跑起來，再把標準固定下來，最後把標準變成機械檢查」的順序。

第一步是 scaffold：`develop` 把 spec 0001 當成 scaffold subtask，生出第一個可跑的 Next.js 16（Turbopack）專案，並立刻產生 example `.env`，讓 Supabase、Anthropic、OpenAI、TMDB、Resend 這些需要的 key 提早現形。驗收是實的——build 過、伺服器起得來、首頁回 200，才往下走。接著 `/audit` 在 greenfield 是 standards capture：它不掃程式庫，而是用訪談把架構風格（functional）、資料夾切法（by feature）、lint、pre-commit、testing、CI、Git 慣例寫進一份短的 `AGENTS.md`，`CLAUDE.md` 只留一行指標。規範定下來後，有兩個必須現在決定的取捨：測試策略（選了 type check ＋手動驗證、捨棄測試套件，並用 scoped query helper 替代測試守住 user-owned 資料的 ownership），以及怎麼讓規範不只是文件——`develop tooling` 用 Biome 與 Lefthook 把點名的規則變成機械檢查。最後把專案推上 GitHub、只裝官方 skills、每個 feature 之間 `/clear`，然後交棒給最關鍵的資料模型 feature。

走完之後，你應該能在自己的新專案上，從一份 spec 一路做到 scaffold 可跑、規範入庫、tooling 生效、程式碼進 GitHub。
