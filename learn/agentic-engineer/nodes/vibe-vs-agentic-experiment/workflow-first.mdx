<LearningGoal>
照著 scope → architect → develop → check/verify → review → test → sync 的順序走一遍，並說明每個 load-bearing 決定如何變成一條寫進 repo 的驗收條件。
</LearningGoal>

## Lesson

workflow-first 的流程是 scope → architect → develop → check/verify → review → test → sync：scope 先訪談你、把計畫寫成檔且地基優先，architect 一次問一題、逼出那個 vibe 版默默默認掉的快取決定，你選的答案會變成一條寫進 spec 的驗收條件，讓未來的你、團隊與 agent 都能讀、也都能被要求兌現。它比一句話生一個 App 多了很多步，但每一步都在把事情從「預設值」換成「決定」。
