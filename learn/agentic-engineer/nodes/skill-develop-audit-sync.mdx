# /develop、/audit、/sync：建置、建圖、對帳

## Learning goal

用 /develop 依 spec 建置（just-in-time 依賴、spec gate、Assumed 逃生口），用 /audit 產生 AGENTS.md，用 /sync 對帳 scope／specs 與實況。

## Steps

1. [[learn/agentic-engineer/nodes/skill-develop-audit-sync/develop-role-and-spec-gate|/develop 是什麼：spec gate 與 Assumed 逃生口]] — 認出它的職責、Step 0 機械判準與三個選項
2. [[learn/agentic-engineer/nodes/skill-develop-audit-sync/run-develop-and-advance-scope|跑一次 /develop：just-in-time 依賴、證明它跑得起來、推進 scope]] — 走完建置流程與 flexible route（after step 1）
3. [[learn/agentic-engineer/nodes/skill-develop-audit-sync/audit-writes-agents-md|/audit：寫出短而準的 AGENTS.md]] — 用真實 repo 寫出 root／nested context 檔（after step 2）
4. [[learn/agentic-engineer/nodes/skill-develop-audit-sync/sync-reconciles-docs|/sync：用 git 證據把文件對回實況]] — 對帳 AGENTS.md、scope 與 spec 狀態（after step 3）
5. [[learn/agentic-engineer/nodes/skill-develop-audit-sync/connect-mcp-and-resume-develop|補上資料庫：接 Supabase MCP，再續跑 /develop]] — 在 develop 停下來時接上 MCP 再續建（branches from step 2）

## Lesson

`/scope` 決定了要做什麼，`/architect` 把關鍵決定寫成 spec。這一課交給你的，是把那份 spec 變成真的能跑的東西，並且讓旁邊的文件不會腐爛：`/develop` 依 spec 建置、`/audit` 寫出所有 skill 共用的 context 檔，`/sync` 用 git 證據把文件對回實況。

三個 skill 共用同一條紀律：狀態寫在檔案裡，不在對話裡。`/develop` 的 Step 0 是一道機械的 spec gate——凡是需要的值沒有指名來源，就停下來，要嘛先去 `/architect` 補決定，要嘛記成一張 `Assumed` stub 先做、之後再補 ratification。建置本身則靠 just-in-time 依賴（只裝這一刀需要的東西）與「宣告完成前先證明它跑得起來」。`/audit` 讀的是真實存在的專案，把 stack、指令、慣例與 scope 帶過來的 build approach 縮成一份短的 `AGENTS.md`，其餘用指標帶到更深的地方；太長的通用 context 檔反而讓 agent 表現更差。`/sync` 則在 merge 前對帳：它只認 git 的檔案狀態與實作，把 scope 的框從實際程式碼勾起來，只在證據足以描述一整個區域時才寫下長期規則，其餘需要人判斷的一律回報而非自作主張。

走完之後，你應該能在自己的專案上跑一輪 scope → architect → develop，接上資料庫 MCP 讓 migration 真的落地，再用 audit 建圖、每次 merge 前用 sync 對帳。
