# Agent 迴圈：Read → Decide → Act → Observe

## Learning goal

說出 agent 的 Read→Decide→Act→Observe 迴圈，並在一個真實小 bug 上認出每個階段、理解一個壞讀取如何複利到後面每一次迴圈。

## Steps

1. [[learn/agentic-engineer/nodes/agent-loop/the-loop|Agent 迴圈：Read → Decide → Act → Observe]] — 認出每個 coding agent 共用的四階段迴圈，以及為什麼它是原子單位
2. [[learn/agentic-engineer/nodes/agent-loop/trace-a-real-bug|跟著 Login Bug 走一遍迴圈]] — 在登入按鈕沒反應的真實 bug 上逐階段辨認（after step 1）
3. [[learn/agentic-engineer/nodes/agent-loop/errors-compound|一個壞讀取如何複利到每一次迴圈]] — 為什麼壞讀取會讓後面每一圈都歪掉（after step 2）
4. [[learn/agentic-engineer/nodes/agent-loop/where-you-intervene|你能控制的三個地方：該在哪一圈出手]] — 架構師能下手的控制點與介入時機（after step 3）

## Lesson

上一課把心態立起來了：你要當架構師，去指揮 AI，而不是許願。但要指揮得好，得先知道按下 Enter 之後，底下到底發生了什麼。答案其實很樸素——不論你用哪一套工具，每個 coding agent 都跑同一個迴圈：先讀（Read），再決定（Decide），然後動手（Act），最後看結果（Observe），接著再跑一遍，直到任務完成。

這一節就是把那個迴圈攤開，拿一個登入按鈕沒反應的小 bug 當活教材，讓你在真實動作上認出這四拍。看懂之後，你會拿到一個貫穿整門課的槓桿：你沒辦法盯著它跑的每一圈，但你可以決定它被允許讀什麼、你能多清楚地幫它做決定、以及你要多仔細檢查它回報的東西。這正是「指揮而非許願」在技術上真正的落點。
