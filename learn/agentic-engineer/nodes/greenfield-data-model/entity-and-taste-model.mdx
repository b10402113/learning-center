<LearningGoal>
決定 taste profile 以 taste_vectors 表（每 facet 一列）儲存、ratings 以 rating + source 欄位正規化、profiles 以 auth.userId 為鍵、首次遷移即建九表目標模型，並說出 cold start（缺 taste vector 列＝onboarding 未完成）與 auth.users→profiles trigger 的機制。
</LearningGoal>

## Lesson

taste profile 存成 `taste_vectors` 表（每 facet 一列，避免日後拆 facets 變成破壞性變更）、兩條來源的評分合進 `ratings` 表用 `rating`＋`source` 正規化、`profiles` 以 `auth.userId` 為鍵、第一次遷移立起九張表（四張先閒置）、cold start 用「缺列」代表 onboarding 未完成，而 `auth.users` 的 insert 由一支 Postgres trigger 生出對應的 `profiles`。
