# Greenfield：Scope 與架構技術棧

## Learning goal

對自己的點子跑 /scope 與 /architect，選定決策並讓第二個模型 cross-check spec，再把 context clear 乾淨。

## Steps

1. [[learn/agentic-engineer/nodes/greenfield-scope-architect/start-greenfield-and-scope|安裝 skills，並把點子 /scope 成一份 plan]] — 裝好 skills package 並跑 /scope，把一句話變成 docs/scope/scope.md
2. [[learn/agentic-engineer/nodes/greenfield-scope-architect/choose-build-approach|選 build approach：Tracer Bullet／Skateboard／Journey／Facade]] — 用「最大的風險在哪」挑出切法（after step 1）
3. [[learn/agentic-engineer/nodes/greenfield-scope-architect/architect-the-stack|跑 /architect：把 stack 決定寫成 spec]] — 多輪決策訪談 + web 查證，寫出 index 與 rationale 的 spec（after steps 1–2）
4. [[learn/agentic-engineer/nodes/greenfield-scope-architect/wire-skills-and-mcp-to-the-stack|接上 agent skills 與 MCP servers]] — 依 stack 比對並安裝 skills 與 MCP，讀懂風險等級（after step 3）
5. [[learn/agentic-engineer/nodes/greenfield-scope-architect/cross-check-the-spec|用第二個模型 cross-check spec]] — 補齊 build 會自己發明的決定，批准後才套用（after step 3）
6. [[learn/agentic-engineer/nodes/greenfield-scope-architect/clear-context-and-continue|clear context，準備進 /develop]] — 檔案才是狀態，clear 後接 /develop（after steps 4–5）

## Lesson

Greenfield 是九步驟 workflow 最完整的一次演練：你手上只有一個點子，卻要在一行程式碼都還沒寫之前，把「這個產品長什麼樣、用什麼做」寫成檔案。這一節把課程第 13 章開場那一段拆成六步——先在乾淨視窗裝好 skills package，跑 /scope 把一句話變成 `docs/scope/scope.md`；再由你選定 build approach；接著 /architect 用多輪訪談把 load-bearing 的 stack 決定寫成 spec；選定 stack 後把對應的 agent skills 與 MCP servers 接上；動工前用第二個模型 cross-check 這份基礎 spec；最後 clear context，只把決定留在檔案裡。

這一段的核心主張是「先決定，再動工」。每一步的產物都是檔案——scope、spec、AGENTS.md——而不是聊天室裡的共識，所以你可以隨時 clear、換模型、隔天再回來。六步走完，你會得到一個可以直接交給 /develop 的起點，也會親身體會為什麼「砍掉不做的功能」與「把決定寫下來」比多寫幾行 prompt 更重要。
