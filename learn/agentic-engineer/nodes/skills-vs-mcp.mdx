# Skills vs MCP：何時用哪個

## Learning goal

在一個具體工具上分辨「skill 帶的是慣例」與「MCP 連的是你的實例」兩種機制，知道何時兩個都要。

## Steps

1. [[learn/agentic-engineer/nodes/skills-vs-mcp/skill-carries-tool-conventions|Skill 帶的是工具「現在真正的做法」]] — skill 為什麼能補上模型訓練資料過期的那個缺口
2. [[learn/agentic-engineer/nodes/skills-vs-mcp/mcp-connects-live-instance|MCP 連的是「你自己那個實例」]] — MCP 不教慣例，它接上你真實的資料與查詢（after step 1）
3. [[learn/agentic-engineer/nodes/skills-vs-mcp/when-both|何時只要 skill、何時要接 MCP、何時兩個都要]] — 一條可操作的規則，判斷一個工具需要哪一種（after steps 1–2）
4. [[learn/agentic-engineer/nodes/skills-vs-mcp/workflow-finds-and-approves|讓 workflow 幫你找，但你來放行]] — 自動找出並接上你 stack 需要的兩者，安裝與登入仍由你決定（after step 3）

## Lesson

前面的模組先把兩個機制各自介紹過：skill 是一份按需載入的操作說明書，MCP 是把外部服務接成 agent 可呼叫工具的橋。分開看都懂，但真正上工時你會遇到的問題是——面對一個具體的工具（例如 Supabase、Stripe、Next.js），我到底該帶哪一個？這一節的答案不是「二選一」，而是「它們做的是同一件工作的兩半」。

用一句話把兩半分開：**skill 帶的是某個工具現在真正的慣例，MCP 連的是你自己那個實例。** skill 教 agent 這個工具現在怎麼用——auth 怎麼設、row-level security 怎麼寫、現在的 API 長什麼樣——讓它不要靠半記得、其實已經過期的訓練資料去猜；MCP 不教慣例，它直接把 agent 接到你真實的資料庫、真實的資料、真實的查詢上。所以對同一個工具，兩者常常都要：一個負責「知道這工具怎麼運作」，另一個負責「有一條通往你實例的線」。

四步走完之後，你應該能在任何一個工具上說出這句話，並且用一條可測的問句決定此刻需不需要 skill、需不需要 MCP。最後一步會把視角拉回 workflow：它會自動幫你找出這套 stack 需要的兩者，但安裝要你點頭、真實帳號登入要你親自做——一樣是「系統做繁瑣的部分，你做決定」的那個模式。
