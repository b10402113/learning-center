<LearningGoal>
說明文件漂移與 /sync 的對帳規則：以 git diff／log 的檔案狀態（added／modified／deleted）為證據、scope 的框只從實作勾、docs／tests／config／generated 不列入證據、只在證據足夠時才寫 policy，並知道它冪等、可以每次 merge 前跑，以及 higher tier 多對帳的面向。
</LearningGoal>

## Lesson

`/sync` 在 merge 前用 `git diff --name-status` 讀 A／M／D 檔案狀態當證據，濾掉 docs／tests／config／generated 只留原始碼與依賴清單；它秉持「context 是這次發生的事、policy 是從此一直成立的事」，只在看完整個區域時才寫規則，只碰界線表授權的行，其餘 `stale spec`／`Assumed` 交給 `/architect`、context gap 交給 `/audit`，並把需要判斷的列成清單交還給你。
