# Skills：SKILL.md 解剖與親手撰寫

## Learning goal

讀懂一個 SKILL.md（frontmatter 的 description 當觸發器、body 按需載入），親手做出一個可用的 skill，並分清楚 personal 與 project skill。

## Steps

1. [[learn/agentic-engineer/nodes/skills-anatomy-authoring/the-discipline-you-did-by-hand|技能是什麼：把反覆做的紀律寫成檔案]] — 為什麼紀律總在最忙的時候破功，而 skill 用結構而非意志力解決它
2. [[learn/agentic-engineer/nodes/skills-anatomy-authoring/anatomy-of-a-skill|解剖一個 skill：description 是觸發器，body 按需載入]] — SKILL.md 的 frontmatter、body 與三種按需輔助檔案（after step 1）
3. [[learn/agentic-engineer/nodes/skills-anatomy-authoring/build-and-install-a-skill|親手做一個 skill：skill-creator 與個人／專案安裝]] — 用官方 skill-creator 做出第一個 skill，並選對安裝位置（after step 2）
4. [[learn/agentic-engineer/nodes/skills-anatomy-authoring/authoring-conventions|寫得精簡：skill 撰寫準則與自動守門]] — JSM 的撰寫準則與 check-portability 的 11 條自動規則（after step 3）

## Lesson

前面幾個模組談的是一套紀律：動手前先把 context 工程化、把真正的決定有意為之地做掉、把每次都要常駐的東西縮小、看到東西回來先檢查再相信。但你會發現，光「知道」這套紀律，跟「每一個 feature、在你很累又很晚的時候」還真的照跑一遍，是兩件完全不同的事。這一節要處理的，就是這個落差。

解法不是叫你更自律。解法是把那些反覆要記得、要排順序的小程序，寫成一個檔案交給 agent 去跑——這個檔案就是 skill。它不是更聰明的 agent，也不會讓模型變強；它改變的是你的注意力放在哪裡：把程序的重複勞動拿掉，留下真正只有你能做的那部分判斷。用一句話記住它：**skill 跑程序，你做決定。**

接下來的四步會依序拆開這件事。第一步先把「為什麼紀律會破功、skill 到底解決什麼」講清楚；第二步打開一個真實的 SKILL.md，看 name、description、body 和整包資料夾怎麼分工；第三步用 Anthropic 官方的 skill-creator 親手做出一個 skill，並分清個人與專案的安裝位置；最後一步拉回 JSM 的撰寫準則與那支自動守門腳本，告訴你一個 skill 要寫到多精簡才算及格。
