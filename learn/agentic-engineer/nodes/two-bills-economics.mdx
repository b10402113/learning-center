# 兩份帳單：Token 與 Runtime 經濟學

## Learning goal

用量級講清楚 vibe 與 workflow 兩份帳單（執行成本約 60x、建置 token 的浪費來源），並說出三個降本修正。

## Steps

1. [[learn/agentic-engineer/nodes/two-bills-economics/runtime-bill-sixty-x|執行帳單：一次開 feed 的三毛五]] — 用每次動作與每月每人的數字說出 60 倍差距，並解釋為什麼 vibe build 是「架構上無法資助」
2. [[learn/agentic-engineer/nodes/two-bills-economics/build-bill-more-tokens|建置帳單：workflow 反而更耗 token]] — 接受 workflow 真的用了更多 token，再把「思考」與「浪費」分開（after step 1）
3. [[learn/agentic-engineer/nodes/two-bills-economics/reading-the-token-bill|讀懂 token 帳單：analyze-token-usage.mjs]] — 跑分析腳本、看懂四種 token 的成本權重與該先砍哪一種（after step 2）
4. [[learn/agentic-engineer/nodes/two-bills-economics/three-token-fixes|三個降本修正：session 衛生、模型路由、subagent 起草]] — 用取捨與判準決定何時套用哪一個修正（after steps 2–3）

## Lesson

上一課用同一句 prompt 把一個 app 做了兩遍，讓你看到 vibe build 的架構級殺手。這一課把那份對照換算成錢——而且是兩筆不同的錢。第一筆帳單是「跑起來要多少」：vibe build 的 feed 每次開啟都要花約 0.35 美元，一小時一個人的用量換算下來，每個使用者每月要付約 5 美元；workflow build 的 feed 幾乎不花錢。差距約 60 倍，而且問題不只是貴——它的成本隨頁面瀏覽量成長，營收卻永遠追不上，所以是架構上無法資助，不是調個參數就能救。

第二筆帳單則是「蓋起來要多少」，而它的結論出乎意料：workflow build 其實用了更多 token。但多出來的幾乎不是思考，而是浪費——沒清的長 session 反覆重讀自己的歷史，付著最貴的模型價格，去決定一件只需要三個檔案的事。看懂這筆帳，就要能讀工具印出來的明細：哪一種 token 最貴、該先砍哪裡。最後收在三個已經被寫進工具的修正，把浪費砍掉一個數量級，同時保住全部的好處。
