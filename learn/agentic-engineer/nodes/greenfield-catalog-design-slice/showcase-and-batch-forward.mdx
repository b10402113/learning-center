# Showcase 收尾與批次推進：一次一個，還是先 batch architect

## Learning goal

跑完整條 slice（評 ~20 部、debug runtime error、拿到 12 個帶理由的 pick、收掉 feature），並判斷何時該先批次 architect 再一起 develop 來換吞吐。

## Lesson

實際滑完 onboarding、把 runtime error 餵進 debug、確認 feed 產出帶理由的 picks 並收掉 feature；方向清楚、相依低又有整塊時間時，先批次 architect 再一次 develop 換吞吐，但關鍵地基仍要一條條自己看著走。
