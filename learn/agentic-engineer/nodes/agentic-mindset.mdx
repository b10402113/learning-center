# Agentic Mindset：AI 為何崩壞，如何指揮

## Learning goal

用「你是架構師、agent 是引擎」的心態取代許願式 prompt，並能用「沒有真 context／沒有真計畫」兩個根因診斷 AI coding 為什麼崩壞。

## Steps

1. [[learn/agentic-engineer/nodes/agentic-mindset/why-ai-coding-falls-apart|AI 為什麼會壞掉：兩個根因]] — 用「沒有真 context／沒有真計畫」診斷 AI coding 為什麼會崩壞
2. [[learn/agentic-engineer/nodes/agentic-mindset/direct-dont-hope|別許願，去指揮：你是架構師，agent 是引擎]] — 把許願式 prompt 換成「架構師指揮引擎」的心態與任務形狀（after step 1）
3. [[learn/agentic-engineer/nodes/agentic-mindset/vibe-vs-agentic|Vibe Coding vs. Agentic Engineering：差別在誰在主導]] — 用判別問句在「反應許願」與「主動指揮」之間做選擇（after steps 1–2）

## Lesson

這個節點要解決的不是「哪個工具比較好」，而是每個用 AI 寫程式的人都遇過的同一個弧線：前 30 分鐘覺得「這東西改變了一切」，剪綵、接路由都難不倒它；接著開始出現裂縫——它多寫一個已經存在的函式、修好一處卻弄壞另一處、請它動一個檔它卻重寫三個。等到 context 變長、回應變慢、答案變糊，你已經在 debug 自己看不懂、又沒力氣檢查的程式碼。這一節先把「為什麼會這樣」講成兩個可以拿在手上的根因，再從根因推出這門課要你換的那顆腦袋。

兩個根因分別是「沒有真 context」與「沒有真計畫」。前者是：模型在大批公開程式碼上做下一個 token 的預測，所以它吐出來的是「這東西通常怎麼寫」的平均版本，正確但預設很通用；你的專案從來不在它的訓練裡，除非你把它放進它眼前，否則它對你的 API client、慣例、上週的決定一無所知。後者是：現代的 agent 其實會計畫——它讀檔、排做法、跑測試、失敗還會自我修正——問題出在它瞄準的是你丟給它的目標，凡是你不曾說出口的決定，它都會用「最可能的預設值」自動填掉。把這兩個加起來，就是多數人卡住的那個循環：大 prompt 換來大輸出，大到你無法驗證，一壞掉就只好丟更大的 prompt，然後更無法驗證。

知道根因之後，接下來是一顆心態的轉換：你不是在對神燈精靈許願、許不中就改寫更長的願望；你是架構師，agent 是引擎。引擎又快、又不喊累、一小時吐出的碼比你一天打的還多，但它沒有判斷力——判斷力從來都是你的工作。先建立這個心態，再去看兩個開發者拿同一句「幫我做結帳功能」會走多遠，兩者之間真正差的不是技術、也不是模型，而是「誰在主導」。
