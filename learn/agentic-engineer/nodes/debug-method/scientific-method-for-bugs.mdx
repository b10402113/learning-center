<LearningGoal>
對可重現的一般 bug 一次只改一件事，讓證據決定下一步。
</LearningGoal>

## Lesson

普通 code bug 的解法，是把科學方法套到壞掉的程式上。先把症狀釘住（observed／expected／repro），再讓它穩定重現；重現不了就加觀測，不要瞎修。接著把範圍二分縮小——沿著資料流找「好輸入變成壞輸出」的那一點，沿著歷史用 `git bisect`，並且去讀邊界上的實際值。有了範圍才下假設：單一、具體、可否證，而且是根因不是症狀（「值是 null」是症狀，「為什麼是 null」才是原因）。用最小實驗確認或推翻它，被推翻就丟掉、帶著學到的東西回頭。修的時候只修根因、只改最小幅度；最後重跑重現、跑周邊測試、補一個「沒修就會紅」的回歸測試，並 grep 出同一個根因還藏在哪裡。整條流程只有一個不能妥協的習慣：一次只改一件事，因為一個結果只能回答一個問題。
