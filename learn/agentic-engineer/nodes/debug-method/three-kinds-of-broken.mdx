<LearningGoal>
認出三種壞法各自長什麼樣，並守住「無法解釋的修好等於沒抓到 bug」這條規則。
</LearningGoal>

## Lesson

東西壞掉時，第一個動作不是修，而是問「這是哪一種壞」。第一種是普通的 code bug：可觀察、可重現，而且跟誰寫的無關，用工程師本來就在用的方法處理。第二種是 AI 寫的程式特有的失敗：呼叫不存在的函式、看似正確卻悄悄算錯、在檔案中間自己做了決定、漏掉權限或邊界，共同點是「看起來完成了」，而你沒辦法從一個不屬於你的意圖去推理。第三種是 agent 迷了路：原地重複、來回改同一批檔案、每次嘗試都讓專案更糟卻依然自信；這時叫它修沒有用，因為你叫來解決失敗的東西，現在本身就是失敗的一部分。三者底下壓著同一條規則：無法解釋的修好，就是還沒抓到的 bug——錯誤消失只證明症狀不見了，沒有證明原因被移除。
