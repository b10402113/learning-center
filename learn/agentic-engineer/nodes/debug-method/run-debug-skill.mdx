<LearningGoal>
餵 debug skill 觀察／預期／重現三件事，盯它只下一個假設，並用「修得夠小」判斷是否真的找到根因。
</LearningGoal>

## Lesson

用 debug skill 的正確方式，是把它當成一個跑得比你快的調查員，而不是許願池。開場餵它三件事：觀察到什麼、預期什麼、怎麼重現，而且具體到下一個實驗可以證明對錯——只說「這個壞了」，它就得停下來跟你要證據，這一趟來回往往就是快速與緩慢調查的全部差別。過程中盯住它的動作範圍：看到它同時改好幾個不相干的地方、希望錯誤自己消失，就喊停，要它一次只驗一個假設。它回報之後，用「修得夠小」當作真的找到根因的訊號（demo 的 `.env`／`.env.local` 案例最後只改一行），用「我能不能解釋這條因果」當作接受的門檻，並且一定要把回歸測試留下來。它贏過一般修法的地方不是步數最少，是你最後能說出為什麼結果會對。
