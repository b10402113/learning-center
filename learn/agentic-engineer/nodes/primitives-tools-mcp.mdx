# 四大原語：Tools 與 MCP

## Learning goal

用四大原語（tools／MCP／subagents／skills）當共通詞彙，說明 tools 是什麼、MCP 何時值得接、以及它的安全與 context 成本。

## Steps

1. [[learn/agentic-engineer/nodes/primitives-tools-mcp/four-primitives|四大原語：你只需要學一次的字彙地圖]] — 認出 agent 能伸手去拿的只有四樣東西，以及為什麼學會一次就夠
2. [[learn/agentic-engineer/nodes/primitives-tools-mcp/tools-what-the-model-can-call|Tools：模型能真正呼叫的動作]] — 定義 tool、五個核心工具，與「模型決定／工具執行」的分工（after step 1）
3. [[learn/agentic-engineer/nodes/primitives-tools-mcp/mcp-when-worth-it|MCP：什麼時候值得接上一個服務]] — 理解 MCP 是橋、是開放標準，並判斷該不該接（after step 2）
4. [[learn/agentic-engineer/nodes/primitives-tools-mcp/mcp-scope-and-cost|MCP 放哪裡：scope、安全與 context 成本]] — 在 global 與 project 之間選對位置，算清三個代價（after step 3）

## Lesson

前兩個模組把 agent 想事情的方式講完了：它怎麼跑 Read→Decide→Act→Observe 的迴圈、怎麼在沒有索引的程式庫裡靠 grep 認路、以及它讀進來的東西最後怎麼把 context window 塞滿。但還有一個更基本、卻容易被忽略的問題沒回答：它到底能「伸手去拿」什麼？

答案比你想的少很多。不論你用哪一家工具，一個 coding agent 能用的東西歸根究柢只有四類——tools（工具）、MCP、subagents（子代理）與 skills（技能）。這一節先把這張字彙地圖攤開，讓你之後不管遇到哪個新工具，都能把它掛回這四個位置，而不是每次從零開始。

接著聚焦其中兩類。第一是 tools：它是 chat bot 和 coding agent 真正的分界線。一個只會說話的模型，和一個能真的開檔、改檔、跑測試的 agent，差別就在於它有沒有被允許呼叫工具；而每次工具呼叫都不是「背景免費動作」，它會用掉真實的 context、留下真實的結果，餵回下一輪迴圈。第二是 MCP：當你想要 agent 碰的是「專案外面的某個真實服務」——你的資料庫、你的日曆、某個第三方 API——工具本身進不了那個世界，於是有個標準介面把服務接進來。

這一節想讓你帶走的不只是名詞，而是判斷力。tools 你看得到、每天都在發生；MCP 則需要你決定值不值得接、接在什麼位置。後面兩步就是為了那個決定而寫：先判斷一個 MCP server 值不值得接，再決定它該放全域還是綁專案，並把安全與 context 這兩筆帳算清楚。
