# 你真正會跑的那個迴圈

## Learning goal

講清楚 skill 帶狀態與流程、人帶判斷，並說出五個只有人能做的放行決定。

## Steps

1. [[learn/agentic-engineer/nodes/the-loop-youll-run/skills-carry-state-human-carries-judgment|skill 帶狀態與流程，人帶判斷]] — 這條分工線：skill 把狀態與流程記在檔案裡，人負責判斷，而 agent 無從取代判斷
2. [[learn/agentic-engineer/nodes/the-loop-youll-run/the-workflow-hands-judgment-back|工作流刻意把判斷留給你]] — 建議不是閘門、`done` 是你的、review 只讀不改、上網要問、沒有默默替你做的決定（after step 1）
3. [[learn/agentic-engineer/nodes/the-loop-youll-run/five-release-decisions|五個只有人能做的放行決定]] — 適不適合產品、清掉變泥的 session、誠實的紅燈、要證據、換個審查者（after step 2）

## Lesson

這是整個 workflow 模組的收尾，也是「你真正會跑的那個迴圈」的定義。前面每一步都在回答「怎麼做」——怎麼 scope、怎麼 architect、怎麼建、怎麼證明、怎麼交付；這一節把視角拉高，回答「這一切最後由誰負責」。答案是一條清楚的分工線：**skill 帶狀態與流程，人帶判斷**。九個 skill 把專案的狀態鎖進檔案、把每個階段該做的事固定下来，所以你可以在任何交接點停下、清掉 session、隔天從磁碟接回來，什麼都不會掉；但「這件事對不對、值不值得、安不安全」這一類問題，沒有任何一個 skill 能替你想。

原因很單純：agent 跑得飛快、從不喊累，但它對結果**沒有任何利害關係**——它不在乎你做出來的東西成不成功、安不安全、值不值得維護。速度快、不知疲倦，跟「判斷」是兩回事。所以這套 workflow 被刻意設計成把判斷權留給你：幾乎每一步都只是建議而非閘門，`done` 永遠由你宣告，review 只讀你的碼、只回報不修改，要連外網一定先問你，任何它沒把握的決定都寧可停下來問你、把假設寫下來，也不默默替你補上。這不是流程的漏洞，是設計。

最後一課把「人帶判斷」講成五個具體的放行決定，也就是這個迴圈真正需要你出手的地方：判斷建議適不適合你的產品、在對話變泥時清掉 session、獎勵誠實的紅燈勝過方便的綠燈、向 agent 要證據、以及挑一個不跟作者共享盲點的審查者。走完這三步，你手上就有一套可以自己跑的迴圈——agent 負責快與全，你負責對與值得。
