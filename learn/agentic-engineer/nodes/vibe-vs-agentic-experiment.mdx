# A/B 實驗：Vibe Build vs Agentic Build

## Learning goal

從同一句 prompt 產出的兩份程式碼，指出 vibe build 的四個架構級殺手，並說出 workflow 版本每一行程式為什麼存在。

## Steps

1. [[learn/agentic-engineer/nodes/vibe-vs-agentic-experiment/the-experiment|同一句 Prompt，兩個版本：這場實驗在測什麼]] — 受控條件、兩個版本的差別，以及為什麼 demo 不等於上線
2. [[learn/agentic-engineer/nodes/vibe-vs-agentic-experiment/watch-it-break|打開 Feed 就露餡：40 秒、老虎機與沒人做過的決定]] — 親眼看到 vibe 版在真實使用下的行為（after step 1）
3. [[learn/agentic-engineer/nodes/vibe-vs-agentic-experiment/autopsy-vibe|驗屍 Vibe 版：四個架構級殺手]] — 逐檔讀出殺手，理解「單行乾淨、架構未定」（after step 2）
4. [[learn/agentic-engineer/nodes/vibe-vs-agentic-experiment/workflow-first|Workflow-First：先決定，再讓它動手]] — scope→architect→develop→check→test→sync，決定變成驗收條件（after step 3）
5. [[learn/agentic-engineer/nodes/vibe-vs-agentic-experiment/autopsy-workflow|驗屍 Workflow 版：每一行都是某個決定的結果]] — 同一功能逐項對照，分清「要求它乖」與「讓它不可能亂來」（after steps 3–4）

## Lesson

這一課是整門課的轉折點。前面的章節一直在講「agent 的機器怎麼運作」——它怎麼跑迴圈、怎麼在你程式庫裡找路、context 為什麼會滿、skill 怎麼封裝程序。但這些都還停在「為什麼 AI coding 會崩壞」的解釋層。這一課要用一場可以被驗證的實驗，把「你為什麼需要 workflow」從主張變成證據。

實驗很簡單：同一個 App（一個電影推薦平台），同一天、同一個開發者、同一批模型，建兩次。第一個版本是純 vibe coding——你把想要的描述一遍，agent 把它生出來，沒有人在磁碟上留下一份計畫、沒有決定被寫下來、沒有測試，而且它還被給了最強的模型。第二個版本走的是課程後面要安裝的 agentic-engineering workflow——先 scope、把每個 load-bearing 的決定在寫任何程式之前就捕捉起來，不讓 agent 自己發明沒被決定的東西。

關鍵在於：vibe 版沒有爛。它做出一個會在 demo 裡讓人驚豔的 App，講師自己都說他被打動了。所以真正的問題不是「會不會動」，而是「demo 之後會怎樣」——100 個使用者、5,000 個使用者，或六週後你重新打開這份程式碼的時候。兩份 repo 都附在課程裡，每一個說法都能自己驗證。

五步走完，你應該能從同一句 prompt 產出的兩份程式碼裡，指出 vibe 版的四個架構級殺手，並說出 workflow 版每一行程式為什麼存在。這個對照是後面九步驟 workflow 系統的地基——先感受到痛，才會真的用得上那套工具。
