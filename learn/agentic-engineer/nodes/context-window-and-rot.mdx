# Context Window、Context Rot 與 Session 衛生

## Learning goal

說明 context window 為什麼會滿、rot 為什麼在裝滿前就開始掉品質、以及何時該 clear、何時該 compact。

## Steps

1. [[learn/agentic-engineer/nodes/context-window-and-rot/the-window-fills|Context Window 為什麼會滿]] — 認出 window 是單一容器，並理解填滿它的是「尋找答案的成本」
2. [[learn/agentic-engineer/nodes/context-window-and-rot/context-rot|Context Rot：品質在裝滿之前就開始掉]] — 分辨位置衰減與長度衰減兩種機制（after step 1）
3. [[learn/agentic-engineer/nodes/context-window-and-rot/topic-switching|切換主題：無關的工作如何搶走注意力]] — 理解 contextual distraction 與三個徵兆（after step 2）
4. [[learn/agentic-engineer/nodes/context-window-and-rot/clear-vs-compact|Clear 還是 Compact：兩種重置怎麼選]] — 用「是否依賴精確細節」這個判準選擇重置方式（after steps 2–3）
5. [[learn/agentic-engineer/nodes/context-window-and-rot/token-economics|Token 經濟學：什麼貴、什麼便宜]] — 分辨貴與便宜的活動，並學會事前判斷成本（after steps 1、4）

## Lesson

前一節講了 agent 怎麼讀你的程式庫——沒有索引，只有 grep、glob、read 現場找路。這一節往下追一個很自然、卻常被忽略的問題：那些被讀進來的東西，最後都到哪裡去了？答案是通通擠進同一個容器——context window，而它有一個硬上限。

這個節點要拆三件事。第一，window 為什麼會滿：主要不是你的專案太大，而是「探索」本身很貴，讀進來的大部分是尋找答案的成本，不是答案。第二，rot 為什麼在 window 裝滿之前就開始掉品質：這是被量測過、跨模型一致的現象，還分成位置衰減與長度衰減兩條不同的機制；再加上一個跟「裝多滿」無關、只跟「裝了什麼」有關的問題——session 飄過無關主題時的注意力干擾。

第三，既然知道它會壞，該怎麼重置？這裡有個真正的抉擇：clear 把 window 清空、可預期但什麼都不留；compact 把對話摘要後帶著走、省事但可能失真且你無法事先審查。最後把整個模組收在 token 經濟學上——搞清楚什麼貴、什麼便宜，你才能在動手前就判斷一個任務會逼 agent 廣泛閱讀還是精準閱讀。
