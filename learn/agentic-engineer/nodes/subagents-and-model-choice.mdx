# Subagents 與模型選擇

## Learning goal

建立並使用 subagent 把重讀取隔離掉，並用「harness 佔 80%、model 佔 20%」與 deep／fast 分層挑選模型。

## Steps

1. [[learn/agentic-engineer/nodes/subagents-and-model-choice/subagents-own-context|Subagent：把重讀取隔離到自己的 context]] — 為什麼要讓 subagent 用獨立 context、它省下什麼、什麼任務才值得派
2. [[learn/agentic-engineer/nodes/subagents-and-model-choice/configuring-a-subagent|設定並使用一個 subagent]] — 用 `/agents` 或手寫 markdown 檔建立，並用自動或指名兩種方式派出（after step 1）
3. [[learn/agentic-engineer/nodes/subagents-and-model-choice/harness-vs-model|挑模型：deep 決定、fast 執行]] — 用 harness／model 與 deep／fast 分層替任務挑模型
4. [[learn/agentic-engineer/nodes/subagents-and-model-choice/primitives-across-tools|四大原語對照：換工具不是從零開始]] — 拿四大原語對照新工具，知道哪些原樣通用（after steps 1–2）

## Lesson

上一課把 tools 與 MCP 講完，這一課補上四大原語裡的最後一塊——subagent——以及藏在所有原語底下的那顆旋鈕：模型。這兩個題目其實共用同一個核心問題：什麼東西不該塞進你眼前那個 context window。subagent 的答案是「把重讀取搬到別的地方做，只把結果帶回來」；模型選擇的答案是「把貴的推理留給真正的決定，其餘交給便宜快速的模型」。

先把 subagent 想清楚：它是一個有自己 context 的工人，你派它出去大量閱讀與搜尋，它只帶回你真正要的那幾句結論，於是主線的 window 保持乾淨。接著動手做一個：用 `/agents` 引導建立，或親手寫一個 markdown 檔（frontmatter 加一段 system prompt），放進 `agents` 資料夾，再靠自動或指名兩種方式派它出去。放到整門課的尺上看，這套「什麼任務值得一個獨立的空間」的判斷，跟你上一課對 MCP 的判斷是同一句話。

然後換一個尺度，回到模型本身。它其實只佔產出品質的兩成，另外八成是 harness——你寫的 spec、你管的 context、承擔程序工作的 skill、以及該清 session 時就清的紀律。所以選模型不是排「最貴到最便宜」，而是沿著成本、速度、推理深度三個軸挑一個點：用一句規則收斂，deciding 交給 deep tier、executing 交給 fast tier。最後把整個模組收在一張對照表上：學會四大原語一次，換到 Codex、Cursor 這些工具時，你只是聽到同一件事換個腔調，而不是從零重學。
