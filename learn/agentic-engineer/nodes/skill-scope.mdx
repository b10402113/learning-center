# /scope：動工前先挑戰想法

## Learning goal

用一句話或一份 brain dump 跑 /scope，產出 docs/scope/scope.md，並選對 build approach 與 workflow tier。

## Steps

1. [[learn/agentic-engineer/nodes/skill-scope/why-scope-defaults|為什麼動工前要先 /scope：不決定，agent 就替你決定]] — 認出每個專案都在跑的預設值，以及被 agent 悄悄決定的代價
2. [[learn/agentic-engineer/nodes/skill-scope/run-scope-to-plan|跑一次 /scope：把一句話變成 docs/scope/scope.md]] — 一句話輸入、分批問答、產出 slim index + plan，並認得 plan／replan／add（after step 1）
3. [[learn/agentic-engineer/nodes/skill-scope/choose-build-approach|選 build approach：Tracer Bullet／Skateboard／Facade／Journey]] — 用「最大的風險是什麼」挑出切法（after step 2）
4. [[learn/agentic-engineer/nodes/skill-scope/choose-workflow-tier|選 workflow tier：Prototype／Alpha／Beta／GA]] — 用「這東西是什麼」挑出嚴謹度，並知道 feature 可以覆寫（after step 2）
5. [[learn/agentic-engineer/nodes/skill-scope/read-the-plan-and-specs|讀懂產出：index 給 build、rationale 給你]] — 讀懂 plan 與 spec 的形狀、Status 與 Assumed／Superseded（after steps 3–4）

## Lesson

/scope 是九步驟 workflow 的第一個邊界：在任何程式碼之前，先把「這個專案長什麼樣」寫下來。它要處理的核心問題是——每個專案都會自己跑出一組預設值（功能先做哪個、每項變更要檢查到什麼程度、沒人決定時預設的答案是什麼），你不刻意選，agent 就會替你在每一次迴圈裡選，而且選的是當下最省事的那個。

這一節拆成五步。第一步先讓你看懂那些預設值與代價；第二步把 /scope 真的跑一遍，看一句話怎麼變成 `docs/scope/scope.md`；第三步與第四步是 /scope 唯二逼你交出來、不讓 agent 代答的決定——build approach 與 workflow tier；第五步回頭教你讀懂它產出的 plan，以及緊接著的 spec 檔（build 讀哪一半、你留哪一半）。
