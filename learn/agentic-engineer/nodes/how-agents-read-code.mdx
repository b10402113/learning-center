# Agent 如何讀你的程式庫

## Learning goal

解釋 agent 沒有索引、靠 grep/glob/read 現場找路，並用「你沒說、它沒讀＝它不知道」判斷它到底知道什麼；親手追一次「auth 在哪」的搜尋路徑。

## Steps

1. [[learn/agentic-engineer/nodes/how-agents-read-code/what-the-agent-sees|Agent 到底知道什麼：你沒說、它沒讀，它就不知道]] — context window 裡實際裝的四種東西與「context gap」
2. [[learn/agentic-engineer/nodes/how-agents-read-code/no-index-just-search|沒有索引：grep、glob、read 就是它認路的全部]] — 為什麼沒有索引，只有三個現查工具（after step 1）
3. [[learn/agentic-engineer/nodes/how-agents-read-code/trace-where-is-auth|追一次「auth 在哪」：搜尋、篩選、四次讀取]] — 在真實 demo 上走一遍搜尋路徑（after step 2）
4. [[learn/agentic-engineer/nodes/how-agents-read-code/naming-as-a-lever|命名與結構是效能槓桿，不是風格偏好]] — 何時該為 agent 的尋路成本投資命名與結構（after step 3）

## Lesson

上一課把迴圈的四拍講清楚了。這一課接著回答其中關鍵的一拍：Read——它讀的東西到底是從哪來的？多數人心裡藏著一個錯誤的預設，以為 agent 像 Google 一樣，背後有一個索引，問什麼就查什麼。實情是：沒有索引、沒有 embeddings 資料庫、也沒有預先建好的專案地圖。它認路的方式，跟你第一天踏進一個陌生 codebase 沒兩樣——搜尋，然後開檔來讀。

更麻煩的是，它每一次 session 都從零開始。你腦中那些「這個專案就是這樣運作」的常識，它一概沒有。它當下只知道 context window 裡裝著的四種東西：這次對話、它用工具真的讀過的檔案、你設定的 always-on context（例如 CLAUDE.md）、以及工具本身的系統指令。所以要判斷它「知不知道」某件事，只要問一句：你說了嗎？它讀了嗎？兩者都沒有，它就是不知道。

這一節的四步會把這件事拆開。先看清它到底「看見」什麼，再理解它為什麼沒有索引、只有 grep／glob／read 三個工具，然後親手追一次「auth 在哪」的真實搜尋路徑，最後把結論收成一個你天天用得到的判斷——命名與結構不是風格偏好，而是直接決定它要搜幾次、燒掉多少 context 的效能槓桿。
