<LearningGoal>
用三個 LLM 傾向與對應反制、加上一份 self-check，判斷一場 architect run 好不好；決定何時讓它挑戰你的前提、何時值得跑第二個模型 cross-check，並知道 reviewer 只改無害措辭、絕不默默補上缺的決定。
</LearningGoal>

## Lesson

用三個 LLM 傾向（想同意你、伸手拿常見答案、想看起來完成）與一份 self-check 判斷一場 architect run 好不好：讓 `/architect` 挑戰你的前提、要它攤開每層的建議理由與 runner-up、在跨領域問題上花夠時間；cross-check 按 tier 決定（GA／Beta 強烈建議 Another model、Alpha 視風險、Prototype 或無 scope row 建議 Skip），而 reviewer 只做決定的完整度與設計的健全度兩件事，只自動修無害措辭與機械性不一致，任何改變行為、所有權、風險或架構的缺口都只會列出來問你，絕不默默補上。
