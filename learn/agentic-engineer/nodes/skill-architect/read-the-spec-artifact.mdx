<LearningGoal>
看懂 /architect 寫出的 spec：單檔與目錄（index／rationale／verify）的形狀規則、主要 section、AC 編號，以及 Status 生命週期與 Assumed／ratify／supersede 的處理方式。
</LearningGoal>

## Lesson

`/architect` 落地的 spec 放在 `docs/specs/`（或 `.workflow/specs/`），形狀分單檔與目錄；目錄固定有 `index.md`（build spec，`/develop` 讀）與 `rationale.md`（決策紀錄，`/develop` 跳過），另有選配的 `verify.md` 與 umbrella 的 child specs，檔名為 `NNNN-kebab-case-title`、編號每個位置各自數且絕不重複命名。狀態在 Proposed／In Progress／Accepted／Superseded／Assumed 之間流動，怎麼走取決於是否有 scope feature 連著（已 ship 的工作一出生就是 `Accepted`），而 `Assumed` 由 `/develop` 建立、只有 `/architect` 能透過 ratify 清除。
