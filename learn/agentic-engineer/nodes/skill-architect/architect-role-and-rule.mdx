<LearningGoal>
說出 /architect 的職責與唯一規則（一輪只解決一個 load-bearing 決定，不是清 backlog）、它在 workflow 裡的位置，以及它寫出的 spec 為何是 /develop 與 /check verify 的契約。
</LearningGoal>

## Lesson

`/architect` 是一個「一輪只解一個 load-bearing 決定」的 skill：它先做結構化探索（四種模式 FEATURE／ARCHITECTURE／ENHANCEMENT／CROSS-CUTTING、四種操作 create／update／supersede／ratify），再把決定寫成 `docs/specs/` 的 build spec；它不寫程式碼、不更新 `AGENTS.md`，而這份 spec 同時是 `/develop` 建置與 `/check verify` 驗收共同指向的契約（`/architect` 建立並擁有內容卻不推進狀態，讓功能是否 ship 去決定其生命週期，`Assumed` 則由 `/develop` 建立、只有 `/architect` 能清除）。
