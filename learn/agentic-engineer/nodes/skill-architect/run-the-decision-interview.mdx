<LearningGoal>
照著 /architect 的節奏跑完一場決策訪談：先讀 scope／specs／AGENTS.md／git 把能自己答的答完，再用一輪一輪、一問一維度、每題帶一個建議選項與可信 runner-up 的訪談解決 load-bearing 決定，需要時派出唯讀 sub-agent 查現況並在同意閘後建議 skills／MCP。
</LearningGoal>

## Lesson

`/architect` 的節奏是：先跑 pre-flight 把 repo 能自己回答的榨乾（git 狀態、`$SPEC_DIR` 與編號、既有 spec、`AGENTS.md`、build approach、scope feature），再過 references 同意閘（只問一次）與 Agent Skills／MCP 同意閘（問是義務、搜尋不是）；開問前先讀完整份 `internal/design-conversation.md`，再以「一問一維度、每題一個建議加一個可信 runner-up 與自訂輸入」的分階段訪談解完所有承重決定，動筆前過完整度閘門，最後由主線自己寫出 spec（寫作規則只在動筆時載入）。
