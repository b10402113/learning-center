# 課程定位與設定

## Learning goal

說出課程核心主張（寫程式已商品化、判斷力才是差異）、確認自己的先備條件、把 CLI/IDE 裝好，並知道每一章要產出什麼。

## Steps

1. [[learn/agentic-engineer/nodes/course-orientation/course-thesis|這門課的主張：寫程式已成商品，判斷力才是差異]] — 說出課程核心主張與它刻意不教的事
2. [[learn/agentic-engineer/nodes/course-orientation/who-its-for|先備條件：你是不是這門課要的人]] — 用一次自檢判斷自己的技術門檻、付費方案與心態是否到位（after step 1）
3. [[learn/agentic-engineer/nodes/course-orientation/two-scenarios|兩個實戰場景：Greenfield 與 Brownfield]] — 分辨課程要帶你走的兩種真實專案（after step 1）
4. [[learn/agentic-engineer/nodes/course-orientation/install-cli|把環境裝好：安裝 CLI 與 IDE 擴充]] — 動手把 coding agent 的環境裝起來（after step 2）
5. [[learn/agentic-engineer/nodes/course-orientation/how-to-take-this-course|怎麼學這門課：邊做邊學、照順序、自己填速查表]] — 掌握五條學習守則與課程的整體形狀（after step 3）

## Lesson

這門課的起點不是工具，而是定位。它先講清楚一件不太舒服的事：能憑一句話就生出可用程式碼的時代已經到了，寫程式本身不再是門檻，所以「比別人更會寫程式」也不再是護城河。真正的差異回到判斷力——知道要做什麼、把 agent 指對方向、像資深工程師審 junior 的 PR 那樣讀它產出的東西。這門課要教的就是這件事，而且它很明確地說：它不會把你變成「用 prompt 生出自己看不懂的碼」的人。

定位完，接著是校準。這門課假設你已經會寫程式、會用終端機和編輯器，而且多半有過「在聊天視窗裡貼問題、複製答案、再貼錯誤」的經驗——這種做法會在某個專案規模上突然失效。課程要補的正是那個缺口：不是再給你一個更厲害的指令檔，而是一套 workflow。最關鍵的前提則不是技術，而是願不願意改變原本的工作方式。

知道自己是誰之後，課程給你一張地圖。它會帶你走過兩個實戰場景：一個是全新的專案（greenfield），分成接客戶的案子與做自己的點子兩條路；另一個是在既有的程式碼上動工（brownfield），包括你沒寫過、又老又半壞、還沒有文件的 legacy 專案。整門課的安排是先讓你親手感受痛（手寫或 vibe coding），再給你 workflow，然後拿它跑過這些真實場景。最後把環境裝好、把學習節奏定下來，就可以正式開始。
