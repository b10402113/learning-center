# Greenfield：Catalog、Design System 與第一個 Slice

## Learning goal

實作 catalog 與 design system、跑第一個 thin slice（core taste loop），在 showcase 收尾並講出 batch architect 的 pro tip。

## Steps

1. [[learn/agentic-engineer/nodes/greenfield-catalog-design-slice/implement-catalog-and-cache|實作 Movie Catalog 與 Cache：develop → check verify → sync]] — 用 spec 0003 走完一條資料型 feature 的 develop→check verify→sync，並看出 verify 打到真服務、真 defect 要當場修完再 sync
2. [[learn/agentic-engineer/nodes/greenfield-catalog-design-slice/architect-the-design-system|Architect Design System：把視覺方向定成 design.md 與 spec 0004]] — 跑 design system 的 architect 訪談，把 register、type、color、spacing、card shape、native-fill、a11y、icons 定成 design.md 與 spec 0004（after step 1）
3. [[learn/agentic-engineer/nodes/greenfield-catalog-design-slice/build-the-design-system-foundation|Develop Design System：tokens、components 與 /design 契約]] — 用 develop 蓋出 tokens、fonts、ShadCN、swipe deck、PWA 並用 Playwright 驗證，讀懂 /design route 是可重用的設計契約（after step 2）
4. [[learn/agentic-engineer/nodes/greenfield-catalog-design-slice/iterate-the-design-system|改主意時：compact 而非 clear，重跑 architect→develop]] — 看到成品後要改方向時，判斷該 compact 還是 clear，並用重新 architect→develop→verify 改版而不弄丟先前狀態（after step 3）
5. [[learn/agentic-engineer/nodes/greenfield-catalog-design-slice/first-slice-core-taste-loop|第一個 Slice：core taste loop 這條 walking skeleton]] — 用 architect→develop 蓋出 core taste loop 這條端到端 thin slice（auth／pool／taste vector／weighting／quota／gating），15 個 task 上 branch 再驗證（after step 4）
6. [[learn/agentic-engineer/nodes/greenfield-catalog-design-slice/showcase-and-batch-forward|Showcase 收尾與批次推進：一次一個，還是先 batch architect]] — 跑完整條 slice（評 ~20 部、debug runtime error、拿到 12 個帶理由的 pick、收掉 feature），並判斷何時該先批次 architect 再一起 develop 來換吞吐（after step 5）

## Lesson

前面幾個節點把 greenfield 的地基鋪好：scope、tech stack、scaffold、資料模型，以及對資料模型跑過一輪 check verify、check review、document。這個節點接著的是「真的把產品做出來」的那一段——從一條資料型 feature，到整個 app 的視覺語言，再到第一條端到端會走的 thin slice，最後跑起來、收尾、放大。

整條線索其實是同一個迴圈在不同尺度的重複：architect 決定、develop 建置、check verify 對真服務證明、sync 對帳。差別只在標的越換越大。catalog 與 cache 是第一條真的打外部服務的資料 feature，驗證的重點因此是「打到真服務」而不是型別過關；design system 是把「app 長什麼樣」這件事從口頭偏好變成一份 design.md 加 live contract，讓之後每一條 feature 共用同一套 tokens 與元件；core taste loop 則是第一條 walking skeleton——一條穿過登入、評分、產生推薦的窄切片，逼著所有 load-bearing 的產品決定（auth、pool、taste vector、quota）在動手前先被定下來。

這一段也把「人還是架構師」演給你看：看到成品不滿意時，你可以 compact 保狀態、重跑 architect→develop 改版，而不是推倒重來；一條 feature 走完之後，也可以先批次 architect 好幾條，再讓 agent 一起把它們 develop 出來，用一點掌控換吞吐。走完這個節點，你手上會是一個真的能操作的 app，而不只是通過測試的碼。
