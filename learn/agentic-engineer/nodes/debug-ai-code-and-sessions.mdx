# 除錯 AI 寫的碼與救回卡住的 Session

## Learning goal

對 AI 寫的碼用「把它當陌生人寫的」還原意圖，並在 agent 卡住時用五步升級與 clear／compact 判斷救回 session。

## Steps

1. [[learn/agentic-engineer/nodes/debug-ai-code-and-sessions/why-ai-code-is-different|除錯 AI 寫的碼：為什麼沒有作者記憶]] — 缺少作者記憶，並用「當陌生人寫的」避免對著猜測除錯
2. [[learn/agentic-engineer/nodes/debug-ai-code-and-sessions/recover-intent|還原意圖：從 spec、周邊程式與執行行為找線索]] — 三個還原來源，以及無 spec 時那其實是「沒做過的決定」（after step 1）
3. [[learn/agentic-engineer/nodes/debug-ai-code-and-sessions/four-failure-patterns|四種 AI 失敗模式與它們的破綻]] — 認出四種模式，記住 bug 不在出錯的那一行（after step 1）
4. [[learn/agentic-engineer/nodes/debug-ai-code-and-sessions/recognizing-the-loop|認出 agent 在打轉：迴圈與幻覺的差別]] — 用「重複但沒有進展」認出卡住的 session（entry point）
5. [[learn/agentic-engineer/nodes/debug-ai-code-and-sessions/context-asset-or-liability|一個判斷：這個 context 是資產還是負債]] — compact 與 clear 的判準與顛倒的代價（after step 4）
6. [[learn/agentic-engineer/nodes/debug-ai-code-and-sessions/five-step-escalation|五步升級與三種結局：把 session 救回來]] — 五步升級、事前預防與三種結局（after steps 4–5）

## Lesson

前一節把除錯分成三種壞，並教你對一般 code bug 用科學方法。這一節專攻另外兩種——它們的共同點是：你面對的不是一段可以純推理的程式，而是一個過程。第一種是 AI 寫的碼出錯；第二種更根本，是 agent 本身卡住了、壞掉的不是你的程式碼。

AI 寫的碼為什麼特別難查：除錯自己的碼時，你腦中還在跑「我當初為什麼這樣寫」，這份作者記憶默默做掉一半的工作；換成 AI 寫的碼，這份記憶不存在，而「看著它生成」也不算數，因為你看到的是輸出、不是推理。所以第一招是把碼當陌生人寫的來讀，並把「這行大概想幹嘛」當成待證明的假設——意圖要從 spec 的驗收條件、周邊程式的慣例、以及實際執行行為三處還原；若根本沒有 spec，你找到的往往不是 bug，而是一個從沒被做過的決定，那屬於 `/architect`，不屬於 `/debug`。接著你會認得四種反覆出現的失敗模式與它們的破綻，並記住那個通則：錯幾乎不在出問題的那一行，而在更早、沒寫下來的某個決定。

另一條線是救回 session。當 agent 開始重複同樣的動作卻沒有進展，它給你的不是錯誤內容，而是壞掉的流程——這時加指示只會更糟，因為你正在指揮的東西本身就是故障的一部分。你要做一個判斷：這個 session 的 context 是資產（compact 帶走）還是負債（clear 丟掉），判斷顛倒的代價很高。然後照五步升級走：停、問它相信什麼、給更少的任務、必要時把碼 rollback、最後清乾淨但把證據帶進新 session。事前的預防很簡單——先讓它計畫、不要編輯。
