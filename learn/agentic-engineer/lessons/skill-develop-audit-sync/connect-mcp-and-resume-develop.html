補上資料庫：接上 Supabase MCP，再續跑 /develop

Step 5/5 · /develop、/audit、/sync：建置、建圖、對帳

學習目標

/develop 做到資料模型、停下來詢問下一步時，接上 Supabase MCP，讓開發流程能繼續下去。完成後，你會有一個連上 GitHub 的 Supabase 專案、已加入 Claude Code 並完成認證的 MCP server，還能讓 /develop 直接對 live database 套用 migration。

前言：先確認起點與目標

動手前，先確認你正好卡在這個時刻：/develop 正在處理資料模型，已經判斷出需要資料庫，於是停下來問你要把環境變數直接指向 Supabase，還是先接上 MCP。

這一節會示範接上 MCP，再回到 /develop 繼續建置。完成後，agent 就能連上真實資料庫並套用 migration。課程把這段操作獨立記錄下來，因為這正是開發流程中常遇到的岔路。

起點：它停下來詢問時

/develop 走到資料模型時，會發現需要一個可以實際連線的資料庫，接著把選擇交給你：直接設定環境變數，或先接上 MCP。課程示範選擇接上 MCP，並說明認證完成後，只要重新執行資料模型的工作，它就能接著完成建置。

接下來就是把 Supabase MCP 加進 Claude Code，完成認證、確認連線，再回來續跑 /develop。

第一步：建立 Supabase 專案，並連上 GitHub

先在 Supabase 建立新專案。課程建議順手連結 GitHub repo，讓程式碼變更更容易追蹤。做法是先把目前的程式碼推到 GitHub，為 repo 命名；示範使用類似 client-feedback-app-agentic 的名稱。你可以將 repo 設為 public 以方便檢查，建立後複製 repo URL，再把程式碼推上去。

接著回到 Supabase，選取對應的 GitHub repo，並授權 Supabase 存取所有 repo，或只存取這個專案。

建立 Supabase 專案時，輸入專案名稱並產生新的資料庫密碼。這個密碼請務必妥善保存：

建立專案時產生的 database password 一定要存到安全的地方，弄丟了會很麻煩。課程特別提醒：「please don't lose it」。

完成後，程式碼應該已推到 GitHub，Supabase 專案也已建立，你可以在專案頁面看到它。

第二步：從 Supabase MCP 文件取得指令

前往 Supabase 官方的 MCP server 文件，找到「platform hosted project」區塊，選取剛建立的專案，再選擇要授予的存取權限。課程示範是讓 Claude Code 使用；選好後，文件會提供一段可直接複製的指令。

複製文件提供的指令，下一步會在終端機執行。指令會依你選擇的專案與權限而異，請以文件當下產生的內容為準。

第三步：將 MCP server 加進 Claude Code

開啟終端機，貼上剛才複製的指令並執行。這會新增一個 HTTP 型別的 MCP server。新增完成後，Claude Code 的設定裡就會有這個 server，但它還需要通過認證。

# 指令由 Supabase 的 MCP 文件產生，形狀大致如下（實際 URL 以文件給你的為準）
claude mcp add --transport http supabase <SUPABASE_MCP_URL>

新增完成後，可能需要重新載入 Claude 視窗，讓它讀取最新設定。

第四步：使用 /mcp 完成認證

課程示範時，直接在擴充介面搜尋 MCP server，會看到 Supabase 需要認證；但點進去可能出現「resource 必須是有效的 MCP endpoint」之類的錯誤。若遇到這種情況，可以改從終端機啟動 Claude。它會提示有 MCP server 需要認證，這時輸入 /mcp 並按下 Enter，就能開始認證 Supabase。

/mcp

授權頁面開啟後，選擇「authorize Claude Code」，保留原有權限設定並完成授權。看到認證成功的訊息後，Claude Code 會開始連線 Supabase。

接著開啟新視窗，在 MCP servers 底下確認狀態。剛開始可能會顯示「connecting」；重新載入頁面後，Supabase 應顯示為已連線。確認看到這個狀態，再往下走。

第五步：續跑 develop，讓 migration 實際套用

連線確認後，回到 workflow 繼續執行 /develop。它可能會自行判斷目前進度，也可能詢問你正在處理哪一項工作。課程示範時，scope 中的資料模型標示為 in-progress，因此再次執行 develop data model。

/develop data model

現在 agent 可以透過 MCP 連上真實資料庫，並自行執行 migration，把資料模型實際寫入資料庫。後續開發也會順一點。

這也呼應資料層建置的完成標準：產生 migration 檔還不算完成，必須確實對目標資料庫執行，讓 schema 上線。接上 MCP 後，agent 就能直接完成這個步驟。

課程建議接著用這套設定繼續做幾個功能，包括資料模型、設計系統與 UI，再完成第一條真正的切片。你可以在自己的 app 或課程的 app 上操作。完成後，就能進入下一個模組，看看 agentic engineering 的其他技能如何運用在實務中。

小結

當 /develop 做資料模型時停下來詢問資料庫設定，可以選擇接上 MCP。先在 Supabase 建立專案並連結 GitHub，妥善保存 database password；再到 Supabase 的 MCP 文件選好專案與權限，複製指令並在終端機執行。重新載入 Claude Code 後，使用 /mcp 完成認證，並確認 Supabase 顯示為已連線。最後再次執行 develop data model，讓 agent 透過 MCP 對 live database 執行 migration。

到這裡，第 8 章的流程已經串起來：用 /scope 規劃、用 /architect 記錄決策、用 /develop 建置並確認成果、用 /audit 建立共享的專案說明，再用 /sync 在 merge 前讓文件與實際狀態一致。需要資料庫時，則接上 MCP，讓 migration 真正套用到資料庫。接下來可以挑一個環節，在自己的專案上實際跑一輪。
