這個迴圈，該從哪裡開始？

Step 5/5 · JSM Skills System：安裝與九步驟地圖

學習目標

面對全新專案、既有程式碼庫、單一變更或 monorepo，判斷應該從哪裡開始；也能說明為什麼 /audit 在新專案排第四，在既有程式碼庫卻排第一。

前言：完整路徑，不代表每次都要從頭走

上一節你確認了狀態會存放在檔案裡，因此流程可以跨 session、跨人延續。現在手上有一張完整的九步驟地圖，下一個問題是：每次都要照順序從頭走一遍嗎？

不需要。這條完整路徑是「可能的最長路徑」，實際入口要看你手上已經有什麼。從零開始的新產品、別人留下的既有專案，和只需要改幾行的小修正，適合的起點都不同。這一節要做的決定，就是判斷眼前的專案該從哪一格切入。/audit 的位置，正好能幫你看懂這個差異。

四種起點，四條路徑

先看完整路徑，再對照四種常見情況。官方列出的順序如下：

idea → /scope → /audit → /architect → /develop → /check verify → /test → /check review → /document → /sync

實際動手時，入口會依專案狀態改變：

你手上的情況建議入口
全新專案（greenfield）從想法開始跑 /scope，再用 /architect 決定技術棧；scaffold 出專案後跑 /audit，接著進入 feature loop。
既有程式碼庫（brownfield）先跑 /audit，讓每個 skill 都了解這個專案；再用 /scope 規劃下一塊工作，接著進入 feature loop。
單一小變更只跑這次工作需要的部分。修 bug 可直接進 /debug；小改動則可以跑 /develop，再接 /check verify。
monorepo把工作範圍限定在正在修改的 workspace。它有自己的 context、scope、技術棧與指令。

用三個問句判斷該走哪條路

不用死背整張表。開始之前，先問自己三個問題：

  1. 這個專案已經有程式碼了嗎？如果還沒有，這是 greenfield，從 /scope 開始；如果已有一大包程式碼，這是 brownfield，從 /audit 開始。
  2. 你要做的是整個新產品，還是一個小改動？新產品需要用 /scope 展開計畫；如果只是修 bug 或做小調整，就不必從規劃開始，直接使用對應的工具。
  3. 這是 monorepo 嗎？如果是，確認範圍只涵蓋正在修改的 workspace，避免一次改動擴大到隔壁的 app。

為什麼 /audit 的位置會改變？

表格裡看起來有個矛盾：既有程式碼庫要先跑 /audit，全新專案卻得等到技術棧決定、專案 scaffold 完成後才跑。原因其實很直接：/audit 會讀取一個真實存在的專案，並把它的 stack、指令與慣例寫進 AGENTS.md。

如果面對的只是一個空資料夾，/audit 沒有實際內容可以讀，只能猜「像這樣的專案大概會怎麼做」，進而杜撰專案慣例。這正是 workflow 想避免的問題：不要讓 agent 用假設填補缺少的資訊。

因此，全新專案要先決定技術棧並 scaffold，等有實際內容可以檢查後，再跑 /audit 記錄專案現況。記住這個判準就夠了：/audit 描述的是證據，不是假設；它要等到有真實內容可讀時才執行。

反例：什麼時候不用照這條路走？

「greenfield 先 scaffold 再 audit、brownfield 先 audit」這條規則，適用於整個專案的起步。如果手上不是整個專案，而是單一任務，入口就可能不同。

例如，只要修一個 bug，就不需要先跑 /scope 或 /architect，直接進 /debug 即可。debugging 本來就設計成不需要 scope 或 spec 也能執行。若只是小幅調整，也可以只跑 /develop，接著用 /check verify 檢查。

所以，這張地圖不是要求你每一格都跑過，而是讓你按需要取用。要跑哪些步驟、在哪裡完成工作，都由你依手上的任務判斷。

小結：先看手上的東西，再決定入口

先判斷專案和任務的範圍：新專案從 /scope 開始，完成技術選擇並 scaffold 後再跑 /audit；既有程式碼庫先跑 /audit，再用 /scope 規劃下一步；單一 bug 直接進 /debug，小改動可用 /develop 加 /check verify；monorepo 則把範圍限在目標 workspace。只要記得 /audit 需要真實內容作為證據，就能判斷它該放在哪裡。

到這裡，這個模組的起步工作就完成了：九個 skill 已經安裝，整張地圖、狀態存放的位置，以及選擇入口的方式也都清楚了。接下來每一節會深入介紹一個 skill，你可以沿用這張地圖判斷何時使用它；遇到卡關時，也可以回頭請 AI 助教展開其中一步。
