JSM Skills System：九個 skill 的流程地圖

Step 3/5 · JSM Skills System：安裝與九步驟地圖

JSM Skills System 是一套以具名 skill 串接需求、設計、實作、驗證與收尾工作的 workflow。

學習目標

能畫出完整迴圈：idea → /scope → /audit → /architect → /develop → /check verify → /test → /check review → /document → /sync，並說明每個 skill 的角色與產物；也能指出 /debug 可隨時插入流程。

前言：九個 skill，先看一張地圖

上一節介紹了這些步驟的目的。現在，九個 skill 已經安裝完成，這一節會先列出它們在流程中的位置與各自的產物；個別 skill 的操作細節則留待後續章節說明。

以下是整條迴圈的流程地圖。每個 skill 佔據一個階段，並將產物交給後續工作：

整條迴圈

從一個想法開始，流程依序經過需求、慣例、設計、實作、驗證、測試、審查、記錄與回饋。官方文件將完整路徑列為：

idea → /scope → /audit → /architect → /develop → /check verify → /test → /check review → /document → /sync

功能建置完成後的階段，官方另外稱為「feature loop」：

/architect → /develop → /check verify → /test → /check review → /document → /sync

/debug 可在流程中任何階段使用。功能出錯、拋出錯誤或行為不符合預期時，可以用它，不必先有 scope 或 spec。

每個 skill 各據一格，各交出一個產物

下表列出各 skill 所屬階段與產物。前一階段的產物會成為後續階段的輸入。

Skill階段產物
/scope需求包含工作範圍、排除項目與優先順序的粗略計畫；計畫可隨工作進展更新
/audit慣例供每個 skill 閱讀的 AGENTS.md context 檔
/architect設計一項承重決定，以及寫在 docs/specs/ 的建構規格
/develop實作scaffold 專案，並依規格建置功能（UI 或後端）
/check verify驗證執行程式，並依驗收條件確認功能是否運作
/test保護用於阻止後續改動破壞功能的測試套件
/check review審查由另一個模型檢視同一份程式碼後產生的排序審查發現
/document記錄根據實際 diff 撰寫的 PR 文字、changelog 與 release note
/sync回饋回寫到專案文件與狀態的建構經驗
/debug復原證據、假設與根因，並交付回歸測試給 /test；可隨時使用

五個 skill 與其餘流程

依照講師在本節的說明，交付一項成果所需的五個 skill 是 /scope、/architect、/develop、/audit 與 /sync。在 Prototype 等級下，這五個 skill 就構成一條完整流程。

其餘流程用於增加驗證、測試或審查。功能越重要、風險越高時，可加入這些階段；因此，九個 skill 並非每個功能都必須全部使用。

小結

完整路徑為 idea → /scope → /audit → /architect → /develop → /check verify → /test → /check review → /document → /sync。其中，/architect → /develop → /check verify → /test → /check review → /document → /sync 是 feature loop；/debug 可隨時使用。各 skill 的產物依序包括計畫、context、規格、程式、驗證與測試結果、審查發現、文件，以及回寫專案的經驗。交付成果所需的五個 skill 為 /scope、/architect、/develop、/audit 與 /sync；其他階段可依功能需求加入。

這些產物包括規格、計畫與 context 檔，都會存成專案裡的檔案，而不是只留在對話裡。下一節將介紹流程狀態存放的位置。
