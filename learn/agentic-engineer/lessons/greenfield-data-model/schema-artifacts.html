Schema 產物：一檔一表、enums 與 movie 身分

Step 5/6 · Greenfield：設計資料模型

學習目標

認得這一輪長出來的實際 schema 產物：Drizzle schema 放在 source/db/schema、每個 entity 一個檔並由 index re-export；固定值集用 Postgres enum；movies 用 UUID 主鍵加唯一 TMDB ID 與 embedding 欄位（nullable 搭配 partial index）；以及 rating state、starter deck 布林旗標、audit events 與 model usage 的形狀。這一節是查閱用，只描述、不評價。

前言：把散落的決定收成一份可查的產物

前面幾節把表該有哪些、欄位該怎麼放、安全該怎麼守都決定完了。這些決定最後會落地成一疊實際的 schema 檔案——而這一節就是把那疊檔案攤開來，當成一份可以隨時回來查的對照表。

你之後動 schema 時，多半不會從頭重讀一遍設計理由，而是想知道「那一張表的主鍵是什麼、那個固定值集有哪幾個值、embedding 放在哪」。以下就照這個用途整理，每一項都附最小範例。

版面：一檔一表，由 index re-export

Drizzle schema 放在 source/db/schema。版面採「一個 entity 一個檔」，再由一個 index 把全部重新匯出。相對於把所有表塞進單一大檔、一次看到全部，這種排法讓每個表的定義各自獨立，之後要找某一張表時，直接開對應的檔就好。

// source/db/schema/index.ts
export * from "./enums";
export * from "./profiles";
export * from "./movies";
export * from "./ratings";
export * from "./taste-vectors";
export * from "./picks";
export * from "./model-usage";
export * from "./watchlist-entries";
export * from "./import-runs";
export * from "./audit-events";

固定值集：用 Postgres enum

固定不變的值集——例如 rating 的來源、rating 的狀態、pick 的狀態——用 Postgres enum 表示。這些值集的例子包括 rating source、rating state 與 pick state。

// source/db/schema/enums.ts
export const ratingSource = pgEnum("rating_source", ["swipe", "letterboxd"]);
export const ratingState  = pgEnum("rating_state",  ["like", "dislike", "skipped"]);
export const pickState    = pgEnum("pick_state",    ["seen", "dismissed", "saved"]);

movies：UUID 主鍵、唯一 TMDB ID、embedding 欄位

一部電影的身分由三件事決定：一個 UUID 主鍵、一個唯一的 TMDB ID、以及一個 embedding 欄位。這裡有一個時序上的限制：電影列是從 TMDB 先建立、embedding 之後才算得出來，所以 embedding 必須允許 null。為了讓「還沒有 embedding 的那些列」查得有效率，另外在這些待處理的列上建一個 partial index。

// source/db/schema/movies.ts
export const movies = pgTable("movies", {
  id:        uuid("id").primaryKey().defaultRandom(),
  tmdbId:    integer("tmdb_id").notNull().unique(),
  embedding: vector("embedding"),        // 由 TMDB 建立時還不存在，允許 null
  starterDeck: boolean("starter_deck").notNull().default(false),
}, (t) => ({
  pendingEmbedding: index("movies_pending_embedding_idx")
    .on(t.id).where(isNull(t.embedding)),   // partial index：只蓋待補 embedding 的列
}));

ratings：一列一組 user＋movie，原地更新

一個使用者對一部電影只有一列，之後更新是原地更新，而不是留下歷史。一列評分由兩部分組成：一個 rating 欄與一個 source 欄。swipe 進來的列只有 state（like／dislike／skipped），分數為 null；Letterboxd 匯入進來的列則帶著真實的評分。

// source/db/schema/ratings.ts
export const ratings = pgTable("ratings", {
  userId:  uuid("user_id").notNull(),
  movieId: uuid("movie_id").notNull(),
  rating:  numeric("rating"),                 // 匯入帶真實分數；swipe 為 null
  source:  ratingSource("source").notNull(),  // swipe / letterboxd
  state:   ratingState("state"),              // like / dislike / skipped
});   // 一個 user 對一部電影只有一列，原地更新

taste_vectors：每個 facet 一列

taste profile 存在 taste_vectors 表，每個使用者可以有 n 列，每一列是一個 facet，帶著該 facet 的 label 與 vector。

// source/db/schema/taste-vectors.ts
export const tasteVectors = pgTable("taste_vectors", {
  id:     uuid("id").primaryKey().defaultRandom(),
  userId: uuid("user_id").notNull(),
  label:  text("label").notNull(),   // 一個 facet；tracer bullet 先放 "average"
  vector: vector("vector"),
});

picks：每列一部電影推薦給一位使用者

推薦以獨立的 pick 列表示，對同一個 user 與 movie 組合唯一。每一列帶著它的理由 reason、分數 score、建立時間 created_at，以及一個 state 欄（供之後的 feed feedback 與收藏使用）。

profiles：以 auth.userId 為鍵

app 自己的使用者資料放在 profiles 表，鍵是 auth.userId。它的列由 auth.users 的 insert trigger 建立。

model_usage：每人每天每模型一列

每日的 model 額度以「一個使用者、一天、一個模型一列，帶一個計數器」的形狀儲存。這是 feature 6 會用到的表。

// source/db/schema/model-usage.ts
export const modelUsage = pgTable("model_usage", {
  userId:  uuid("user_id").notNull(),
  day:     date("day").notNull(),
  model:   text("model").notNull(),
  counter: integer("counter").notNull().default(0),
});   // 每人每天每模型一列

watchlist_entries、import_runs、audit_events

剩下三張：watchlist_entries 供 feature 10 的收藏使用；import_runs 供 feature 7 的匯入使用；audit_events 是一張通用表，存放 import 與帳號刪除的稽核紀錄（spec 0001 要求）。這三張在第一次遷移時先立起來，其中前兩張要等對應功能輪到才啟用。

starter deck：電影上的一個布林旗標

starter deck 以 movies 上的一個 boolean 欄位表示（如上例的 starter_deck）。

references：此刻沒有

在這個時間點，模型沒有加上外鍵／references。表與表之間的對應靠欄位記錄，但不由資料庫的約束強制。

小結

schema 產物落在 source/db/schema，一 entity 一檔、由 index re-export；固定值集用 Postgres enum；movies 用 UUID 主鍵＋唯一 TMDB ID＋nullable embedding 與 partial index；ratings 一列一組 user＋movie、原地更新，用 rating＋source 承載兩條來源；taste_vectors 每 facet 一列；model_usage 每人每天每模型一列。此刻沒有外鍵約束。
