四大原語對照：換工具不是從零開始

Step 4/4 · Subagents 與模型選擇

學習目標

拿四大原語對照一個新工具，知道哪些東西會一字不改地通用、唯一真正的分歧在哪裡。

四大原語對照表

四大原語（primitives）指的是 agent 工具的四種基本能力：tools（能採取的動作）、skills（按需載入的指示檔）、MCP（連到外部的協定）、subagents（有自己 context 的工人）。下面這張表列出它們在 Claude Code 與 Codex 兩套工具中的對應形式。

PrimitiveClaude CodeCodex
ToolsRead、write、edit、search、run。沒有品牌名。同樣那些動作，也是沒有名字的。
Skills資料夾裡放一個 SKILL.md同一份檔案，原封不動。
MCP同一套協定同一套協定、同一個詞。
Subagents自己的 context，回傳結果同一種機制、同一個詞。

Codex 那一欄從上到下讀起來沒有新東西：名字幾乎不變，大多數的列連名字都沒換。

Skills 是「同一份檔案」

skill 在 Codex 裡的形狀跟 Claude Code 一樣：一個資料夾，裡面放一個 SKILL.md。同樣的結構、同樣的 frontmatter、同樣的行為：agent 先讀 name 和 description，等它決定要用，才把完整指示載入。

「同一份檔案」是字面上的意思。Claude Code 專案 .claude/skills/ 裡的 skill 資料夾，可以直接複製到 Codex 專案的 skills 資料夾：不改名、不重新格式化、不做任何轉換。開一個 Codex session，給它一個符合該 skill description 的任務，Codex 會找到它、讀它、用它。一個 byte 都沒動，也能在另一家公司的工具裡運作。

唯一真正的分歧：always-on 檔案

對照表上真正不同的只有一處。

  • Codex：直接讀 AGENTS.md，不需要額外步驟。
  • Claude Code：讀 CLAUDE.md，要加一行 @AGENTS.md 才能把共用的 context 拉進來。

Subagent 設定位置與格式

工具放在哪格式值得知道的事
Claude Code.claude/agents/ 或 ~/.claude/agents/，或 /agentsMarkdown + YAML frontmatter（name、description、tools、model）內建：Explore、Plan、general-purpose
Cursor.cursor/agents/ 或 ~/.cursor/agents/Markdown + YAML frontmatter（多了 readonly、is_background）也會直接讀 .claude/agents 與 .codex/agents
Codex.codex/agents/Markdown agent 定義有 manager agent 把工作分派給平行 subagent
Gemini CLI它的 config/agents 目錄TOML 格式2026 才加入 subagent 支援
Copilot.copilot/agents/Markdown agent profiles內建 explore、plan、review、build 等專才

Claude Code、Cursor、Codex 三套幾乎一致：一個帶 frontmatter 的 markdown 檔，丟進一個 agents 資料夾，專案層級或使用者層級都可以。Cursor 甚至會直接讀 Claude 與 Codex 的 agent 資料夾。Gemini CLI 和 Copilot 也支援 subagent，只是設定方式不同：Gemini 用 TOML，Copilot 用自己的 agent profiles 加一批內建專才。概念相同（把一個有範圍的任務交給一個獨立 context 的工人，拿回結果），但那兩套的當下語法請查官方文件，那是最容易變動的細節。

面對新工具的四個問題

每個新的 agentic 工具推出時，用這四題對照：

  1. 它能採取哪些動作？（Tools）
  2. 它支不支持這種形狀的按需指示？（Skills）
  3. 它能不能連到 codebase 之外？（MCP）
  4. 它能不能把重活交給一個有自己 context 的東西？（Subagents）

名字會稍微變動，底下的形狀很少變。認出「同四個東西，換了一個新標籤」就夠了。

小結

四大原語幾乎原封不動地跨工具通用：tools 是同樣的動作，MCP 是同一套協定，subagents 是同一種機制，而 skills 更是同一份檔案：SKILL.md 資料夾可以從 Claude Code 原樣複製到 Codex。唯一真正的分歧是 always-on 檔：Codex 直讀 AGENTS.md，Claude Code 讀 CLAUDE.md，要靠一行 @AGENTS.md 把共用 context 帶進來。面對任何新工具，只要問四個問題：能做哪些動作、支不支持按需指示、能不能連到外部、能不能交出有自己 context 的重活。原語學會一次，工具只是口音。

這一節是查閱用的對照資料。實際建立 skill 與 subagent 的步驟，回到前面 skills 與 subagents 的操作章節；想理解為什麼 skills 用 description 觸發、為什麼 subagent 要有自己的 context，看對應的原理說明。
