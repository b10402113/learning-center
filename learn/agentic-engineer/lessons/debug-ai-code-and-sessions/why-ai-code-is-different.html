除錯 AI 寫的碼：為什麼沒有作者記憶

Step 1/6 · 除錯 AI 寫的碼與救回卡住的 Session

學習目標

說出除錯 AI 寫的碼與除錯自己寫的碼差在哪，並用「把它當陌生人寫的」避免對著自己猜的意圖除錯。

前言：一段不是你想寫的程式碼

想像你手上的專案裡，有一段程式是 agent 寫完之後直接交出去的。上線時一切看起來都正常，直到某個真實的輸入進來，它才開始出錯。你打開那個檔案，準備像平常一樣動手查——結果發現，平常最順手的那一招，這次完全不管用。

那一招是什麼？是「我大概記得我當初為什麼這樣寫」。除錯自己寫的碼時，你的腦中一直有一份作者記憶在偷偷幫你：這一行是為了繞過某個 API 的限制、那個判斷是為了擋某種舊格式的資料、這段刻意寫得囉唆是因為當時有個不能動的相依。你幾乎不用特別去想，它已經先幫你把一半的問題過濾掉了。

面對 agent 寫的碼，這份記憶不存在。這一節要講的，就是少了它之後，除錯這件事到底哪裡不一樣，以及一個能補上這個缺口的具體技術。

除錯自己的碼：有一半的工作，是記憶默默做掉的

先承認一件事：你讀自己的程式碼時，從來不是只靠閱讀。你同時也在回想。那份回想——也就是「當初為什麼要這樣寫」——會在你真正讀懂每一行之前，就先幫你把「這裡可能有問題」的範圍縮小。原文的說法是，這份記憶做掉了一半的工作，而你幾乎沒注意到它在做。

這也是為什麼很多時候你一眼就看得出自己的 bug：不是你的眼睛特別利，而是你的腦中存著一份正確答案的版本。兩相比對，差異自然跳出來。

面對 agent 寫的碼：那份記憶不存在

換成 agent 寫的碼，情況就變了。這不是說程式碼一定比較差，而是你失去了那份作者記憶。你不知道每一行的「為什麼」，只看得到「它是什麼」。

這裡有個很自然的反駁：我不是看著它寫出來的嗎？這樣總算記得吧？答案是：不算。你看到的是它的輸出，不是它的推理。它產出一段看起來很合理的程式碼，你能複述那段程式碼，卻說不出它為什麼選這個做法、又排除了哪些別的做法。只看到輸出的過程，不構成作者記憶。

把碼當陌生人寫的：這是一項技術

原文給的動作是：讀它，就像一個陌生人寫的；事實上，也確實是。

這句話聽起來像一句心法，但它其實是一項技術，因為它專門擋掉一個很具體的錯誤。

那個錯誤是這樣的：你看著某一行，心裡自動冒出一個念頭——「這行大概是想做 X 吧」——然後你就對著那個「大概是 X」開始改。走到這裡，你查的已經不是程式碼，而是你對程式碼的猜想。你在偵訊自己的假設，而不是在勘驗現場。

把它當陌生人寫的，意思就是把那個「大概是 X」降級：它只能是一個待證明的假設，不能是除錯的依據。至於要從哪裡把真正的意圖還原出來，那是下一節的事。

一個比喻：讀自己的日記，和讀陌生人的日記

除錯自己的碼，像重讀自己的日記。你不需要讀懂每一個字，因為你記得那一天；文字只是喚醒記憶的提示。除錯 agent 的碼，則像讀一本陌生人的日記：你只有紙上的字，沒有那一天。唯一的辦法，就是老老實實從字面、從上下文、從它後來的行為去推。你不能假裝自己記得那一天——因為那本日記不是你的。

小結

除錯自己寫的碼時，作者記憶默默幫你做掉了一半的工作；面對 AI 寫的碼，這份記憶不存在，而且「看著它生成」補不上——你看到的是輸出，不是推理。所以第一招不是技巧，是心態：把它當陌生人寫的，並把「這行大概是想幹嘛」降級成待證明的假設，而不是拿來除錯的依據。

弄懂「少了什麼」之後，下一個問題自然是「那要從哪裡補」。下一節會給你三個可以把意圖還原出來的來源，以及一個重要的分岔：如果三個來源都沒有，你找到的其實不是 bug。
