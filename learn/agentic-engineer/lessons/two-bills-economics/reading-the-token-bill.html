讀懂 token 帳單：analyze-token-usage.mjs

Step 3/4 · 兩份帳單：Token 與 Runtime 經濟學

學習目標

能跑 analyze-token-usage.mjs 並讀懂它的輸出，知道每個 token 種類的成本權重，以及該先砍哪一種。

前言：一筆看起來很嚇人的數字

上一節拆開了建置帳單的真相：多出來的 token 大多不是思考，而是浪費。不過想動手砍，得先看得到明細。現實是，agent 跑完一個 session，你眼前通常只有一個很大的總數，例如某次 architect 跑出了八萬 token。數字很嚇人，但它嚇人得有道理嗎？

這一節的工具就是來回答這個問題的。它是課程附的一支小腳本，把那個嚇人的總數打開，告訴你每個 token 屬於哪一種、各自值多少錢。讀得懂它，你才判斷得出一筆帳是真貴，還是只是看起來大。

analyze-token-usage.mjs

analyze-token-usage.mjs 是一個唯讀的 token 用量分析器。它讀取一份 Claude Code 的 session transcript，回答一個問題：「這次跑的 token 到底花去哪了？」它把「省 token」這件抽象的事，換算成一份看得懂的帳單。

它讀的是 Claude Code 自己的 session 檔，位置在 ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl。它不寫入任何檔案，也沒有任何依賴，裝好之後只負責讀。

怎麼呼叫它

它是一個命令列工具，支援以下幾種呼叫方式（以下區塊逐字引用自原始碼）：

// Usage:
//   node scripts/analyze-token-usage.mjs                # newest session for THIS project
//   node scripts/analyze-token-usage.mjs <file.jsonl>   # a specific transcript
//   node scripts/analyze-token-usage.mjs --top 15       # show the 15 heaviest turns
//   node scripts/analyze-token-usage.mjs --project <encoded-dir-name>

把所有選項並列成一張表：

呼叫方式作用
analyze-token-usage.mjs分析這個專案最新的一次 session
analyze-token-usage.mjs <file.jsonl>分析指定的那一份 transcript
analyze-token-usage.mjs --top 15顯示最重的 15 個 turn
analyze-token-usage.mjs --project <encoded-dir-name>指定要讀哪個專案的 session 目錄

預設值有兩個。--top 預設是 12；--project 預設是 null，也就是用目前工作目錄換算出的編碼名稱。

const TOP = Number(flag('--top', '12'));
const projectOverride = flag('--project', null);

token 的四種分類

這支工具不把 token 當成一個總數看，而是拆成四種，各自帶一個成本權重。同時，主線（main thread）與 subagent（sidechain）的成本分開列。

種類成本權重（相對一份未快取輸入 token）
fresh input1.0
cache-write1.25
cache-read0.1
output5.0

這些權重定義在原始碼的一個常數（以下逐字引用）：

// Approximate cost weights RELATIVE to one uncached input token (= 1.0).
// These are the standard Anthropic cache/output multipliers; they are here to
// turn raw token counts into a single comparable "cost unit", not to quote a
// dollar price (that depends on the model tier you ran on). Output dominates.
const W = { input: 1.0, cacheWrite: 1.25, cacheRead: 0.1, output: 5.0 };

四個數字排在一起，落差就很清楚了：output 一份要價五倍，cache-read 只要十分之一。所以「token 總數很大」跟「錢花很多」是兩件事：一個塞滿快取讀取的 session 看起來很胖，帳單卻很輕。

輸出的五個區塊

區塊它列出的東西
TOKENS BY THREAD主線、subagent、總計，各拆成 fresh / cache-write / cache-read / output，並給出 raw 總數、cost-units 與 turn 數
READ MEcache-read 佔比、output 佔成本的比例，以及該先砍哪一種的排序
WEBweb search 與 web fetch 的次數
SUBAGENTS SPAWNED這次 spawn 了哪些 subagent
HEAVIEST N TURNS按 output token 排序的最重幾個 turn

READ ME 那一段直接印出砍的優先順序（以下逐字引用）：

console.log(`\nREAD ME: ${cacheReadPct}% of raw tokens are cache reads (billed ~10% of a fresh token),`);
console.log(`so the raw total overstates real cost. In cost-units, output generation is ~${outCostPct}% of the bill.`);
console.log(`Lever ranking follows cost-units, not raw resident size: cut OUTPUT and FRESH input first,`);
console.log(`cache reads are already cheap. Fewer interview rounds cuts output; smaller resident files cut cache-read only.`);

最小使用範例

最單純的用法，是在專案目錄下直接跑它，看最新一次 session：

//   node scripts/analyze-token-usage.mjs                # newest session for THIS project

它會印出 TOKENS BY THREAD 那一片，欄位格式定義在原始碼的 row() 函式（以下逐字引用）：

function row(label, a) {
  const parts = [
    `fresh ${k(a.input).padStart(6)}`,
    `cache-write ${k(a.cacheWrite).padStart(6)}`,
    `cache-read ${k(a.cacheRead).padStart(7)}`,
    `output ${k(a.output).padStart(6)}`,
  ];
  return `  ${label.padEnd(16)} ${parts.join(' · ')}\n` +
         `  ${''.padEnd(16)} raw ${k(rawTotal(a))}  ·  cost-units ${k(costUnits(a))}  ·  ${a.turns} turns`;
}

小結

analyze-token-usage.mjs 是一支唯讀的分析器，讀 Claude Code 的 session 檔，回答「token 花去哪了」。它把成本拆成 fresh input（1.0）、cache-write（1.25）、cache-read（0.1）、output（5.0）四種權重，並把主線與 subagent 分開列。輸出分成 TOKENS BY THREAD、READ ME、WEB、SUBAGENTS SPAWNED、HEAVIEST N TURNS 五段，其中 READ ME 直接告訴你該先砍 output 與 fresh input，因為 cache-read 本來就便宜。

往後查這支工具的細節，就回到上面的選項表、四種權重表與五個輸出區塊。至於工具跑完之後該怎麼做（看到帳單之後你該改什麼），下一節列出課程實際採用的三個修正，附一張比較表與幾個判準，讓你能在自己的 session 上當場決定要套用哪一個。前一節「建置帳單的真相」則解釋了這些浪費是怎麼產生的。
