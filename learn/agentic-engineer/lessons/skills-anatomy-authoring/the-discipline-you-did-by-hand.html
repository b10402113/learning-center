技能是什麼：把反覆做的紀律寫成檔案

Step 1/4 · 紀律為什麼總在最忙的時候破功

學習目標

能說明 skill 是「把反覆手做的程序寫成檔案」，並解釋為什麼它靠結構（description 常駐、body 按需）而不是靠意志力省下 context。

前言：那套你很熟的紀律，為什麼會鬆掉

前面幾個模組，你其實已經把一整套紀律學完了。動手之前先把 context 工程化、把真正要做的決定有意為之地做掉、把必須常駐的東西壓到最小、東西回來先檢查再相信。每一條你都知道它在防什麼，也看過缺了它會出什麼事。

但你心裡應該也承認一件事：這些道理在課堂上聽起來都很對，真正難的是在每一個 feature、每一個累到不行的晚上，還照樣跑一遍。這一節要處理的，就是「知道」和「真的做」之間那道落差。

紀律不是一個動作，是一疊要記住的手續

先看清楚這件事為什麼難。那套紀律其實不是單一動作，而是一疊很細的小程序，而且它們是有順序的。

在寫任何一行程式碼之前，你得先找出「這次真正要做的決定」是什麼。找到之後，你得把它寫到某個地方，讓它不會在對話結束後走失。接著把工作切得夠小，小到改動可以被好好 review。最後東西做完，你還得拿它回頭對照：這真的是你原本要的嗎？

這每一件事，都是一個你必須記住、還得排對順序的步驟。而且不是做一次就結束，是每一個 feature 都要重來一遍。人會怎麼應對這種負擔？你會在最在乎的那個 feature 上把整套流程跑完，然後在已經做膩的那一個偷偷偷工。換句話說，紀律鬆掉的那一刻，剛好就是你最忙、也最需要它的那一刻。

解法：把程序寫一次，交給 agent 每次照跑

這裡就是 skill 登場的地方。它的想法很樸素：如果這段程序不用記在腦子裡，而是寫成一份檔案，讓 agent 每次都用一模一樣的方式跑一遍呢？不管你今天精神飽滿還是累到眼睛睜不開，跑法都一樣。

skill 就是一段你一直得手做的程序，被捕捉進一個檔案，所以它每次都跑得一樣。

這個定義聽起來比「skill」兩個字給人的想像低調得多，但這其實是好事。因為它意味著你可以完全弄懂它；而能弄懂，就代表你能自己做一個。這一節先把「它是什麼、解決什麼問題」講清楚，真正動手做出來的動作留到第三步。

每個 skill 都有兩層，agent 只先讀上面那層

要理解 skill 為什麼不會把 context 撐爆，你得先知道它的內部有兩層。上面是短短的名字和描述，下面是真正落落長的指示，也就是 body。

關鍵在於，agent 平常只讀上面那層。它會掃過你手上每一個 skill 的名字和描述，判斷哪一個符合你剛剛丟出來的請求；只有在挑中某一個之後，它才會把那個 skill 的完整 body 載入。至於其他沒被選中的 skill，從頭到尾都不會進入這次對話。

這件事你應該會有感覺，因為前面講 always-on context 的那個模組，就是在說「每次 session 都要付的租金，不管相不相關」。如果十套程序都用那種方式常駐，那就是十份檔案在每一個任務上收租。skill 剛好相反：十套程序擺在那裡待命，你只需要為當下真正在用的那一套付費，其他每一套大概就只佔兩行。

內容什麼時候被讀成本
上層name 與 description每次都被掃過，用來決定要不要用每個 skill 約兩行
下層（body）真正的指示、步驟只有被挑中時才整份載入只有用到的那套要付

這不是什麼可有可無的小優化。它正是你能同時擁有一整套程序、又不把 context window 撐爆的原因。這裡用的不是意志力，而是結構：把「什麼該一直待著、什麼該等到要用才拿」這件事，用檔案的形狀固定下來。

它不是更聰明的 agent，它改變的是你的注意力

接下來這一段要特別小心，因為很多開發者會在這裡想錯。skill 不會替你思考。它不是一個更聰明的 agent，也不是什麼能讓模型工程能力變強的魔法 prompt。裝上 skill 的前後，模型本身的能力完全沒有變，它跟一分鐘前一樣強。

那 skill 到底改變了什麼？它改變的是你的注意力放在哪裡。它接手的是那些程序性的勞動：記憶、排序、還有那個「我剛剛到底有沒有把 checklist 跑完」的反覆確認。把這些拿掉之後，你的注意力就空出來了，可以放回那件從頭到尾都只屬於你的事——做決定、下判斷、還有隻有你能拍板的那幾個取捨。

所以，為什麼你會覺得自己的判斷力好像一直沒被好好用上？不是因為你不擅長判斷，而是它被「每個 feature 都要按正確順序記住十五件程序性的事」埋住了。把這層負擔拿走，剩下的才是你真正擅長的工作。

小結

skill 是「一段你一直得手做的程序，被寫成檔案」。它用結構而非意志力解決 context 成本：上層的 name 與 description 每次被掃過，下層的 body 只有被選中才載入。它不會讓模型變強，只是把程序性的勞動接手，讓你的注意力回到只有你能做的判斷。一句話：skill 跑程序，你做決定。

「上層決定要不要用、下層等到要用才載入」這個分工，就是整個機制的核心。下一節不再抽象地談，我們直接打開 Anthropic 公開技能庫裡的一個真實 SKILL.md，看那兩層在檔案裡長什麼樣子，還有它旁邊那包東西是做什麼用的。
