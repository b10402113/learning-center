解剖一個 skill：description 是觸發器，body 按需載入

Step 2/4 · 打開一個真的 SKILL.md，看看黑盒子裡面

學習目標

拆開一個 skill 的資料夾之後，你能說清楚三件事：frontmatter 裡的 name 與 description 負責什麼、body 在什麼時候才被讀到、以及 scripts／references／assets 這三種輔助檔案各自會不會進 context、什麼時候進去。

前言：把黑盒子打開

上一節我們定下了一件事：skill 是一個資料夾，頂端兩行決定它什麼時候被用，真正的指示放在下面，等到被挑中才載入。道理是說得通的，但你心裡可能還是有點沒底，畢竟那是隔著一層描述在看，你沒真的掀開過蓋子。

所以這一節直接把盒子打開。教材用 Anthropic 公開技能庫裡的一個真實範例，它是一個處理 PDF 的 skill。選它沒別的原因，就是它寫得乾淨、好讀。看完之後，「skill 是什麼」對你來說就不再是一個抽象名詞了。

SKILL.md 就是一份加了表頭的 markdown

先講一個會讓你鬆口氣的事實：SKILL.md 沒有什麼神祕的特殊語法。它就是一份普通的 markdown，也就是你平常讀 readme 的那種東西，只是最上面多了一段結構化的資訊。會讀 readme，就會讀它。

打開檔案、切到原始碼模式，你會看到最上面用三條破折號框起來的一小段。這段叫 frontmatter，裡面真正要緊的只有兩樣：一個 name，一個 description。

---
name: pdf
description: 用什麼話說明「什麼時候該用、什麼時候不該用」，決定這個 skill 何時被觸發
---

（這裡以下是 body，寫給 agent 的指示）

description 是整個檔案最重要的一行

frontmatter 裡那兩樣，description 是整個檔案最重要的一行，也是我看過最多開發者草率帶過的一行。原因就是上一節講過的那個機制：agent 會讀你手上每一個 skill 的 name 與 description，拿它來判斷哪一個符合現在的任務。換句話說，description 就是觸發器。

PDF skill 會在你問到 PDF 的時候啟動、不問的時候安靜待著，靠的就是這一行。而寫在 description 底下的所有指示，在那一行說服 agent「這個 skill 跟現在的任務有關」之前，它連看都不會看一眼。

反過來想，偷懶的 description 會發生什麼事。假如你只寫「幫忙處理文件」這種話，agent 根本不知道什麼時候該伸手去拿它，結果就是在錯的任務上啟動，或是在對的任務上錯過。好的 description 會用白話把「什麼時候該用、什麼時候不該用」講清楚。這點精準度，就是一個會動的 skill 跟一個只會躺在資料夾裡的 skill 之間的差別。

body：像在對一個好隊友簡報

frontmatter 下面就是 body。你不會從頭到尾把一個 skill 讀完，agent 也不會。所以別把它當成一篇要背的文章，重點是它的形狀。

它交代的是：這個 skill 是幹嘛的、什麼情況該用哪一種作法、步驟是什麼。寫法很像你在對一個好隊友做簡報：這是工作內容、這是做法、這是大家最容易卡住的地方。就這樣，沒有更多。

skill 是一整個資料夾，不是一個檔

接下來這件事比較少人知道：一個 skill 不只是一個檔案，而是一個資料夾。以那個 PDF skill 為例，除了 SKILL.md，旁邊還躺著 forms.md、reference.md，以及一個裝著真程式碼的 scripts/ 資料夾。

聰明的地方在於它們怎麼被串起來。回到 SKILL.md，裡面的 quick reference 段落會指向 forms.md，意思等於「如果任務是要填表，就先去讀 forms.md」。所以只有你真的在填表單時，agent 才會打開 forms.md；如果你只是要從 PDF 裡把文字抽出來，那個檔案從頭到尾都不會被碰到。reference.md 也是一樣的道理，它是留給需要深細節的任務，只在真的需要時才載入。

scripts 則是這整套「精確」概念最好的示範。當某件事必須做得一字不差，例如把一份表單裡的每一個欄位都抽出來，skill 不會用英文描述一遍然後祈禱模型做對，而是直接跑一支腳本。agent 執行腳本，帶回來的只有結果，程式碼本身從頭到尾都不會進入這次對話。

把資料夾打開，這些額外的檔案幾乎都逃不出三種類型，而它們的共同點是「按需載入」。

輔助檔案放什麼什麼時候載入
scripts/需要做得精確時，agent 直接執行的程式碼只有任務真的需要時才跑，而且只有執行結果進 context
references/額外的說明文件、深細節只有任務需要那層細節時才打開
assets/樣板、圖片、skill 產出時會用到的檔案產出成品時才取用

這其實就是上一節那個概念再往下鑽一層。你不必為整個 skill 付費，只為任務當下真正碰到的那一塊付費。一個 skill 可以又大又能幹，而它大部分的內容，在你真的用到之前，成本都是零。

小結

一個 skill 是一整個資料夾：根目錄的 SKILL.md 是唯一必要的檔案，frontmatter 的 name 與 description 是觸發器，body 是寫給 agent 的指示。旁邊的輔助檔案幾乎都是三類：scripts（要精確時執行，只有輸出進 context）、references（需要時才開的深細節）、assets（產出時取用的樣板與素材），全部按需載入。一句話：description 決定何時啟動，body 說怎麼做，重的東西等你真的伸手去拿才載入。

到這裡，你已經能讀懂任何一個現成的 skill 了。但讀得懂和做得出來是兩回事。下一節不再看別人寫的，直接用 Anthropic 官方的 skill-creator 親手做出一個屬於你自己的 skill，順便搞清楚它該放在個人資料夾還是專案資料夾。
