Always-on 檔案怎麼載入：CLAUDE.md、AGENTS.md 與 import

Step 3/5 · Context Engineering

學習目標

做完這一節，你能說出 exploration（也許）與 always-on（保證）兩種規則送達方式的差別，知道 Claude Code 開機只讀 CLAUDE.md、AGENTS.md 要靠 import 才進得來，並用 /context 與 /memory 驗證這個 session 到底載入了哪些檔。

前言：規則寫了，它就一定會看到嗎？

「我把規則寫進檔案了，agent 應該會照做吧？」這是最多人會踩空的地方。規則寫下來是一回事，規則有沒有到達 agent，是完全不同的另一回事。而大家平常測試這件事的方式，大多不可靠——跑一次結果對了，就當作有效。

前面兩節把 always-on context 當成概念在談。這一節把它變成可以動手驗證的機制：做完之後，你要能百分之百確定「我這個 session 載入了哪些規則檔」，而不是靠印象、靠猜。

前置條件很簡單：一個 Claude Code 環境，加一個你自己的專案。課堂上是用「開一個新 repo、在裡面建一個新的 Next.js app」來示範，建 app 的過程本身不重要，重點是接下來規則檔怎麼被建立、怎麼被載入。

規則抵達 agent 的兩條路

規則住在一個檔案裡，但要「到達」agent，有兩條完全不同的路。開發者不斷把這兩條搞混，所以先把界線畫清楚。

第一條路是探索（exploration）。你給 agent 一個任務，它會在專案裡東看西看，想弄清楚現在有什麼。看的過程中，它可能會打開那個放規則的檔，然後遵守它。

請把注意力放在「可能」這兩個字。它會不會打開那個檔，取決於這次任務是什麼、什麼東西看起來相關，以及它願不願意多翻一下。有時候它會找到你特地留給它的規則，有時候它就這樣走過去。這條路你沒辦法指望。

第二條路是 always-on context。這是每個 session 一開始、在你打任何字之前、不管它有沒有去探索，就已經載入進去的規則。它不靠 agent 好奇，它就是每次都在。

這就是「希望 agent 找到一條規則」和「保證它有管道拿到這條規則」之間的差別。

動手：從建立專案到驗證載入

下面照著做。每一步都標了「做了什麼」和「你應該看到什麼」。若某一步的結果和預期不符，先停下來確認，不要繼續往下堆。

  1. 開一個新專案 repo，在裡面建立一個新的 Next.js app。這只是給你一個乾淨的落地場景，讓你親眼看到規則檔怎麼被建立、又是怎麼被載入 context 的。（若你已經有專案，直接用它也可以。）

  2. 把專案規則放進一個檔。這裡有一個會讓人意外的事實：Claude Code 啟動時只讀一個檔——CLAUDE.md，不是 AGENTS.md。

    這很反直覺，因為 AGENTS.md 是大多數其他工具原生就會讀的共享檔，自然是你想放專案規則的地方。但 Claude Code 自己不會讀 AGENTS.md，而且沒有 fallback——它不會因為找不到 CLAUDE.md 就退而讀 AGENTS.md。

  3. 用 import 把 AGENTS.md 接進 CLAUDE.md。在 CLAUDE.md 裡寫下面這一行：

    @AGENTS.md

    這一行就是 import。它等於告訴 Claude Code：載入 always-on context 時，把這個檔案一起拉進迴圈。有了它，AGENTS.md 才會進到保證通道裡。

  4. 驗證到底載入了什麼。不用猜，工具本身有指令可以看。

    • 跑 /context：它顯示這個 session 確切載入了什麼。先忽略 token 數字，看「memory files」那一行。
    • 跑 /memory：它會直接打開並列出檔名。你會看到 project memory（在 CLAUDE.md 底下）、你的 user memory，以及 AGENTS.md——而 AGENTS.md 之所以在清單上，正是因為它是被 import 進來的。

    你應該看到 AGENTS.md 確實出現在 memory files 裡。這個「出現」，就是整節課的重點。

  5. 反證它真的在做事。把 CLAUDE.md 裡那行 import 拿掉，重新載入 Claude Code 的視窗，再跑一次 /context。

    你應該看到 memory files 直接變成「零」。雖然 AGENTS.md 還躺在專案裡、裡面還寫著規則，Claude Code 現在卻完全不載入它。它從保證通道掉到了「也許」——只有當 agent 探索時剛好打開它，那些規則才進得來。

    提醒：拿掉 import 只是為了反證，這個動作可以還原，但你要清楚知道後果，就是上面那句「規則掉出保證通道」。

  6. 把它加回來。既然我們要那些規則是「保證」的，就把 import 寫回 CLAUDE.md。

    但請記住一件事：這不是免費的。一旦接回來，檔案裡的每一行都會在每個 session 開頭被載入，而你上一節學過——你要為每一行、每一次付費。所以要保持它小，只放那幾條 agent 絕對不能搞錯的規則。那些只在專案某個部分才重要的規則，不該待在 always-on 裡，而該靠近它被使用的地方，或放在一個只在相關時才被載入的檔案。

做完長什麼樣

你應該能打開終端機，跑 /context 或 /memory，然後確切說出這個 session 載入了哪幾個檔。而且你親眼看過這個因果：import 在，AGENTS.md 就是保證；import 不在，它就掉成「也許」。

原理的部分——為什麼 always-on 必須那麼小、一條規則該放哪裡——上一節已經講過，這裡不重複。這一節只交給你機制與兩個可靠的指令。

小結

規則有兩條路到達 agent：exploration 是「也許」，它可能逛到、可能走過去；always-on context 是「保證」，在你打字前就載入。而保證是靠 import 拿到的——Claude Code 啟動時只讀 CLAUDE.md，不是 AGENTS.md，所以要在 CLAUDE.md 裡用 @AGENTS.md 把它拉進來，沒有 fallback。要知道到底載入了什麼，別猜：跑 /context 看 memory files，跑 /memory 看檔名。

現在你知道檔案怎麼載入，也知道它每次都要付費。下一個問題就變成判斷題了：到底哪些規則「配得上」這個每次都付的位置？下一節給你一個判準，還有一個很多人踩過的坑。
