# L1 overview

- **Data Model** — The agent designs the whole target schema as one spec before any migration runs: nine tables (profiles, movies, ratings, taste vectors, picks, model usage, watchlist entries, import runs, audit events) in a single migration, with idle tables marked for later features. It settles taste vectors as one row per facet rather than a single column, ratings from swipe and Letterboxd as state-plus-score, and a scoped query helper that applies the user ID itself. A second model cross-checks the spec and finds ten gaps, three blocking. Development stalls on live-database prerequisites, then resumes after the Supabase MCP is authorized against the right account; the migration, seed, auth trigger, and RLS are proven live.
- **Use Check-Verify command for Data Model** — The first run of `/check verify` reads the verify checklist, then flags a missing `.env.local`. The agent fills the public Supabase values it can reach through MCP and guides the learner to the two password-bearing connection strings, switching to the session pooler when the machine lacks IPv6. It exercises the schema end to end, checks all 11 acceptance criteria with zero blockers, and restores a clean database.
- **Review the Data Model Audit** — `/check review` runs the implementation past a fresh model (Opus wrote, Sonnet reviews) across 37 files. It finds one major defect — no database constraint ties `score` nullability to `state`, leaving the invariant only in application code — plus four minor issues. The fix ships as a new migration rather than editing the already-applied one, because the migrator orders by timestamp and a silent edit would never reapply.
