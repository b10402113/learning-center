# L1 overview

- **Installing the Skills System** — the workflow module starts with a one-command install (`npx skills add js-mastery-pro/skills`, optional agent flag), a short prompt about installer trust and which agents to target, and no account or API key because skills are plain Markdown. Global install puts nine folders under the agent's global skills directory, each holding a `skill.md`. The hard part is not installing but knowing when to call each one.
- **Why the Workflow Is Structured This Way** — pre-empts the "one person's preferences" objection by rooting the named stages in the ordinary software development lifecycle: requirements → design → implementation → verification, one feature at a time, with decisions written down (ADRs) so reasoning survives the people who made it. Agents default to sprinting at code and silently filling in every missing decision, so the skills exist as boundaries against skipping the parts that matter.
- **Nine Skills: Finding Your Entry Point** — a one-page map, not teaching: the loop is scope → architect → develop → (scaffold, audit) → feature loop of develop → check verify → test → check review → document → sync, with `/debug` available any time. Each skill owns one stage; only five are needed to ship something real at the Prototype tier. Entry point depends on starting material: greenfield starts at `/scope`, an existing codebase starts at `/audit` then `/scope`, a small change goes to `/debug` or `/develop` + `/check verify`. `/audit` moves between third and first position because it must describe evidence (AGENTS.md from what exists), never assumptions.
- **scope: Challenge the Idea Before Any Code** — every project runs on defaults: default build order, default level of care per change, default answer when nobody decided. In the Vibe build nobody chose these, so the agent picked whatever it reached for first, nothing was out of scope, and "done" meant no proof at all. Running `/scope` converts those invisible defaults into explicit, written choices before code exists.
- **Demo: Running scope** — a full greenfield run from one sentence ("a client feedback app where I share a link, the client pins comments to a live preview, and I manage them from a dashboard"). The skill detects greenfield, loads only its template, asks a few rounds of small-batch multiple-choice questions (MVP cut, what comments pin onto, access without accounts, monetization, first-pass capabilities, rigor tier, slicing approach), and recommends tracer bullet because the risky part is a pin surviving the round trip. Output: 10 features planned, 14 deferred, tracer bullet build, beta workflow, written to `docs/scope/scope.md` with no library names.
