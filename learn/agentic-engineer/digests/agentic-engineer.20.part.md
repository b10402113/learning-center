# Digest — agentic-engineer (part 20) — Greenfield: implement catalog + design system foundation

## Overview (L1)
- Implement the Movie Catalog and Cache — Develops feature 4 (movie catalog and cache) from spec 0003, covering all 10 build-plan tasks: TMDB setup, movies catalog data layer, normalizer, and ingest client. The agent runs `check verify` against the real TMDB/ingest services; 53 of 62 checklist steps pass, one real defect surfaces (a spread overrides a custom ID with `undefined`), which is fixed and re-proven before syncing the spec.

### setup-design-system-and-ui-foundation
- Locator: `[[sources/agentic-engineer/20261014/13. Idea to First Ship — Greenfield/9. Setup Design System and UI Foundation.srt#setup-design-system-and-ui-foundation]]`
- Summary: The developer architects and builds the design system and UI foundation (spec 0004) to make the app visible for the first time. The architect skill reads the important files (including `design.md`, part of the agentic engineering workflow) and infers the stack (Tailwind V4 and ShadCN) without asking. A long Q&A settles visual direction, the two core shapes (swipe card and feed pick card), component contents, native-fill, accessibility, icons, theming, and more before writing the spec and developing it.
- Key claims: "Done when" definition — the design MD covers type, color, spacing, and components; base components handle focus and keyboard; the swipe deck is operable by keyboard, not by drag alone; preflight reported up to date with origin main, spec location `docs/specs`, next number 0004; the agent inferred Tailwind V4 and ShadCN; design-source options are a connected/screenshot Figma design, passed screenshots/images (it reads type, color, spacing), or, if none, a suggested full visual direction with type scale, palette, spacing, radiuses, and card shapes; interface register chosen as "Quiet cinema" — poster-saturated, near-black surfaces, restrained neutral text, almost no chrome, one accent used sparingly, artwork the only saturated thing on screen; type is one geometric sans for the whole app; color beyond neutrals limited to one accent (functional only); spacing kept tight with room between movies; buttons are primary with drag and keys both working; a swipe stores one of three states (like, dislike, skipped) with no score, so the deck has three outcomes, mapped right=like, left=dislike, up=skip; motion (formerly Framer Motion) drives drag and animation (the developer notes React Spring plus use-gesture could have similar impact, but motion covers velocity, spring, physics, gesture handling); native-fill chosen as safe-area insets, dynamic viewport units, sheets on mobile, dialogues on desktop, haptic feedback on swipe commit, and suppressing web tells (tap highlight, overscroll, text selection); progressive web application (installable now, offline later); Lucide icons with ShadCN UI by default; states use skeletons for loading, illustrated empties, inline errors; two cards live in shared primitives with their features; accessibility baseline is the internet standard; docs use `design.md` as the written source of truth plus a live design route showing every token and component in the real app (dev only); accent chosen as warm amber gold (reads as projector light/marquee, naturally high contrast); cards render real starter deck films with hard-coded reasons in feature 5; nav shows all four destinations now with unbuilt ones a "coming soon" page; develop split into ~10 steps (tokens in `globals.css`, fonts, `design.md`, ShadCN init against tokens, button, design route gated, accessibility baseline, focus ring, reduced motion, layout primitives, base component set, native fields, global swipe deck with motion, server-rendered pick card, installability, manifest icons, theme color, close the docs); Playwright testing found a real defect on the full-height deck page (the instructions line sits under the fixed tab bar) which it fixed by correcting the shell height model; focus ring confirmed amber at two pixels.
- Learner-relevant: Supports understanding how an `architect` skill forces upfront product/design decisions, how scope is edited after architect (setting the goal then adding task points the agent uses as reference, rather than putting everything upfront), and how the design system is verified. Concrete details: spec 0004, `docs/specs` location, `design.md` as written source of truth, Tailwind V4, ShadCN, Framer Motion (now "motion"), Lucide icons, Playwright, tokens in `globals.css`, `npm run dev` / `pnpm dev` on localhost 3000/3001, three swipe outcomes (like/dislike/skipped), accent warm amber gold, focus ring amber at 2px, and the architect→develop→verify loop requiring re-invoking `architect` then `develop` when re-architecting to a new look (e.g. passing custom UI references to shift toward an iOS liquid-glass modern movie-app look).
