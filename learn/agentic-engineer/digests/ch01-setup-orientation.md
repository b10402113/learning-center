# L1 overview

- **What This Course Will and Won't Make You** — Writing code has stopped being the hard part, so the scarce skill is judgment, not prompts. The course deliberately does not turn you into someone who prompts their way to code they don't understand; the AI becomes the fastest genius junior you've ever worked with, and you stay the engineer who directs it.
- **Prerequisites: Who is this course for** — For developers who already write code and can build a component, an API route, or a small app without hand-holding, not first-time learners. The target reader has used AI only in a chat window, or added a single `CLAUDE.md` that worked for a week then started forgetting, eating tokens, and contradicting itself — missing a workflow, not a better file.
- **The Two Scenarios You'll Build In** — The same workflow is run through greenfield and brownfield projects. Greenfield splits into client work (turn a vague, half-formed requirement set into a spec agents can build against) and your own idea (pressure-test it before code); brownfield is the day-to-day reality, including legacy codebases nobody wrote and nobody documented.
- **Install the CLI in Your IDE** — The one boring setup lesson: work in Claude Code running inside the editor, on a paid plan. Everything taught is tool-agnostic and ports to Cursor or Codex, but it is demonstrated concretely in one tool rather than taught in the abstract.
- **How to Take This Course / Use the Cheat Sheet** — A workflow course, not a theory course: build along, keep the editor open, go in order, and attempt every challenge before watching the solution. The cheat sheet ships empty on purpose and you fill it in yourself, one line per skill in your own words, because things you write yourself stick and things you download don't.

# L2 detail

- `#L1-L225` — `1. What This Course Will and Wont Make You.srt` — The framing lecture. Writing code became a commodity, so "if anyone can generate code, what makes you worth hiring?" The answer is explicitly *not* better prompts, since a model smart enough to write your code is smart enough to write your prompts; the developers doing well have judgment — they know what to build, point the agent at it, and read what comes back the way a senior reads a junior's PR. The agent doesn't give you judgment, it raises the price of not having any, and judgment can be taught: that is the whole course. AI jobs data shows roles changing shape rather than disappearing. The one thing the course is *not*: it won't turn you into someone who prompts their way to code they don't understand — you stay the engineer and the AI becomes the fastest genius junior or mid developer you worked with, and your job is to direct it.
- `#L1-L303` — `2. Prerequisites Who is this course for.srt` — Who it is for, stated as a gut check. Not for people who have never written a line of code; the floor is comfort building a component, an API route, or a small app without someone holding your hand through syntax. Two portraits: (a) you've used AI to code, but only in the chat window — paste into ChatGPT or Claude, copy back, tweak, paste the error, repeat — which works until the project is big enough that it stops working and you can't tell why; (b) you added a `CLAUDE.md` because a video told you to, it helped for about a week, then the agent started forgetting things mid-session, eating tokens, and contradicting the same file it supposedly read — that is a single instructions file being asked to carry a real project, and you're missing a workflow, not just a better file. Technical requirements are minimal: write code, use a terminal at a basic level, navigate an editor; no specific framework, AI tool, or agent knowledge required, all built from the ground up. Practical: a paid coding-agent plan is needed, smallest tier to start, upgrade only when you hit its limits. The real prerequisite is a mindset — come willing to change how you work; winners are the most open, not the most senior (20-year veterans have refused to adapt and stuck, people six months in have flown). Seniors already running agents daily should move fast through early modules but not skip them, then slow down at legacy codebases and recovery, where even strong agent users are winging it.
- `#L1-L205` — `3. The Two Scenarios Youll Build In.srt` — Why the course is practical: most courses hand you a workflow and custom skills but never show how any of it survives contact with a real job. The order is deliberate — first show how *not* to code, by hand or by vibe coding, because it looks easy but is actually the harder way, so you feel the problem yourself; then give the workflow; then run it through real situations. Scenario one, a brand-new project, splits into the two reasons you'd start one: client work, where someone hands you a vague, half-formed, sometimes frankly ridiculous set of requirements and your job is to turn that mess into a technical specification agents can build against (freelancing or a software agency), and your own idea, where a special skill pressure-tests and sharpens the idea until it's worth building before a single line of code, then turns it into a spec. Same empty-folder starting point. Scenario two, an existing project: the code already exists, you're adding the next feature, and the workflow has a path into it that skips the upfront planning you don't need to repeat. Legacy codebases belong here too — you didn't write it, it's super old, parts are broken, conventions are undocumented, and you've just been put on it — the place most developers actually live and the one almost every other course pretends doesn't exist. Greenfield and brownfield; by the end you've run the exact same workflow through both, so you're not just collecting skills but know when and how to reach for each.
- `#L1-L150` — `4. Install the CLI in Your IDE.srt` — The self-described "one boring lesson," kept fast. The instructor works in Claude Code running right inside the editor and is upfront about why: the workflow, the skills, and the way of thinking about context are tool-agnostic and port to Cursor or Codex, but rather than teach in the abstract and leave you to translate, it is shown concretely in one tool with pointers on how each piece maps to the others so you're not locked in. A poll showed the clear majority wanted Claude Code, so that's where the building happens. Honest note before installing: real agentic work runs on a paid plan — free tiers are fine for poking around but not for building; start on the smallest paid tier and upgrade when you consistently hit the wall, and if you have the money to invest, the Max plan (the instructor's own) is recommended, with current pricing linked below the lesson since prices change often. Step one: install the CLI, and if you're on VS Code (what the instructor uses) install the Claude Code extension; the rest is covered in upcoming lessons.
- `#L1-L208` — `5. How to Take This Course Use the Cheat Sheet.srt` — Five rules for getting the most out of it. (1) Build with me: this is a workflow course, not a theory course, and a workflow only becomes yours when your own hands have run it; watching is worth maybe a tenth of doing, so keep the editor open the whole time. (2) Here's the shape of what's coming: fundamentals first — how agents work under the hood and how to think about context, tool-agnostic and the foundation everything stands on; then a surprise — something built by hand with vibe coding and no skills, so you feel exactly what's painful; then the JSM workflow, where every skill lands as the fix to a pain you just felt; then the real scenarios — a project from scratch, a legacy codebase, and what to do when the whole thing breaks. (3) Don't skip the comparison module between a codebase written by manual prompting/vibe coding and one written with the workflow, even though the instinct is to jump to the shiny workflow; that module is what makes everything after it click. (4) The cheat sheet ships with the course and starts empty on purpose — each skill, what it does, when you reach for it, in your own words, with a prompt each time it's time to add a line; the official one-pager unlocks at the end to check against yours, though by then you won't need it. (5) Go in order: every module leans on the one before, and the legacy workflow will half-work and quietly frustrate you without the context layers underneath; same rule for challenges — attempt each one before watching the solution, because the struggle is the actual lesson and the solution just confirms it.
