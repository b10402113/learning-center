用啟示做設計評審：跑一輪 Heuristic Evaluation

Step 3/3 · 可用性原則與 Nielsen 十項啟示

學習目標

能拿 Nielsen 十項啟示當檢查表，對一個畫面跑一輪啟示評估，寫出每一項發現、所對應的啟示與嚴重度，形成可動手的修改清單。

前言：把「感覺怪怪的」寫成可以修的清單

前兩步你已經有了兩樣工具：六個核心原則，幫你理解摩擦從哪來；以及 Nielsen 十項啟示，一份可以逐項核對的檢查表。但清單放著不會自己發揮作用——它要被拿去「跑」一個真實畫面，才會變成有用的東西。

這一步要教的，就是把十項啟示變成一套評審流程，業界稱作 heuristic evaluation（啟示評估）。它不需要找使用者、不需要寫問卷，只要一個人和一份設計稿就能做，是很划算的第一道品質檢查。做完之後，你手上不會再是一句「感覺怪怪的」，而是一份有依據、有排序、可以直接交給自己或工程師動手的修改清單。

動手前需要準備什麼

在開始之前，請備齊三樣東西。第一，你要評的畫面——最好是一個完整的流程（例如「搜尋並預訂一間房」），或至少一個獨立畫面（例如「搜尋結果頁」）。第二，這個畫面想幫使用者完成什麼，寫成一句話，例如「讓使用者快速比較並選出想訂的房間」。第三，Nielsen 十項啟示的清單，擺在手邊逐項對照。

範圍越小越好。一次評一整個產品只會讓結果失焦，一次評一個畫面或一條流程，發現才會具體。

步驟一：選定範圍與情境

從一個畫面或一條流程開始，並寫下「使用者在這裡想完成什麼」。這一步的作用是設定檢查的角度：同一顆按鈕，在「想快速結帳」的情境下和在「想慢慢逛」的情境下，評價會不一樣。先把情境定下來，後面的判斷才有依據。預期你會得到一句清楚的情境描述，例如「新使用者第一次預訂房間，目標是順利送出訂單」。

步驟二：逐項走查十個啟示

拿十項啟示，一項一項對照畫面問自己：「這個畫面的設計，有沒有違反這一項？」關鍵在於一次只看一項。如果十項混在一起看，你很容易被整體印象帶走，只記得「這頁看起來很擠」，卻說不出具體是哪一項出了問題。

走查時可以用這種句型逼自己想清楚，例如面對「一致性與標準」就問：「返回按鈕的位置，跟這個產品其他頁面一致嗎？」面對「錯誤預防」就問：「使用者在這裡最可能犯什麼錯？畫面有先擋住嗎？」

遇到不適用的項目，直接記「不適用」就好，不要硬湊。例如一個純展示、沒有任何輸入的頁面，就不太需要談錯誤預防。硬把每一項都套上去，只會製造假問題。

步驟三：把發現寫成固定格式

每一條發現都用同一種格式記錄，這會讓後面的排序與分工容易得多。格式包含四個欄位：問題是什麼、對應哪一項啟示、嚴重度、建議怎麼修。

問題：返回按鈕放在頁首右上角
對應啟示：4 一致性與標準
嚴重度：3（重大）
建議：改回頁首左上角，與全站其他頁面一致

寫問題時要中立而具體。「返回按鈕在右側」是具體的，「這頁感覺很怪」則沒有用，因為沒人知道要改什麼。一個實用的判準是：如果一句描述沒辦法直接變成一個修改動作，那它還不夠具體。

步驟四：標嚴重度並排序

有了發現清單後，替每一條標一個嚴重度，再依嚴重度由高到低排序。這樣你才知道資源有限時，該先修哪些。

嚴重度意思處理順序
4 — 阻斷使用者根本無法完成任務，或會造成無法挽回的損失最優先
3 — 重大使用者在這裡明顯卡住、困惑或出錯優先
2 — 次要會干擾、讓人不順，但還是能完成任務有餘力再修
1 — 小摩擦吹毛求疵的小問題，影響輕微最後處理

排序完成後，你應該能用一句話說出「這個畫面最嚴重的問題是什麼」。如果你說不出來，通常代表嚴重度的判斷還沒抓準。

步驟五：收斂成一張修改清單

把重複的發現合併起來，然後把每一條改寫成可以動手的修改項：誰、改哪裡、改成什麼。走到這裡，產出應該從「一團感想」變成「一張工作清單」。例如「搜尋結果頁的排序下拉選單沒有預設值」可以寫成「在搜尋結果頁，讓排序選單預設顯示『推薦』」。

如果同一個問題在很多畫面都出現，那就是系統性問題，優先修共用元件，而不是逐頁打補丁。這通常也代表它值得被寫進設計系統的規範裡。

步驟六：修完後重跑一輪驗證

修改完成後，用同樣的範圍與情境再跑一次同一輪評估。這次要確認兩件事：原本標記的問題是不是真的消失了，以及修改有沒有引入新的問題。例如你把按鈕位置改回左上角，會不會反而遮住原本放在那裡的標題？驗證這一輪，才是把「改過」變成「改對」的關鍵。

小提醒：不要一次評太多畫面。啟示評估靠的是你的敏感度，而敏感度會隨疲勞下降；每評一到兩個畫面就休息一下，會比硬撐著評完五個畫面更準。

小結

跑一輪 heuristic evaluation 的流程是：定範圍與情境 → 逐項走查十項啟示 → 用固定格式記錄發現 → 標嚴重度並排序 → 收斂成修改清單 → 修完重跑驗證。它的產出不是「我覺得不好看」，而是一份每條都有依據、有輕重、能直接動手的清單。

做完這一輪，你手上會有一份依嚴重度排序、每條都對應到一項啟示、而且可以直接轉成 ticket 的修改清單——這就是十項啟示從「知識」變成「技能」的地方。至於每項啟示的定義與例子，回頭查上一步〈Nielsen 十項可用性啟示〉；想理解這些原則背後的原理，則見第一步〈可用性的核心原則〉。之後你在評任何設計稿時，都可以直接套用這套流程，把它當成你預設的評稿工具。
