七個能立刻動手的介面改善手段

Step 4/4 · UX 與 UI 的分野

學習目標

認得七個具體的 UI 改善手法、它們各自處理什麼狀況與關鍵數值，遇到介面問題時知道該查哪一條。

前言：一份可以查的清單

前三課回答了「設計是什麼」「包含哪些技能」「為什麼值得做」。但當你真的坐在一個畫面前，問題往往不是這麼大的問題，而是很具體的一句：「這個頁面卡卡的，我該從哪裡下手？」

這一課給你一份查閱用的清單：七個介面改善手段，每一條都是一個「看到症狀 → 想到用哪一招」的對照。它只描述每個手法是什麼、處理什麼狀況、有沒有關鍵數值，不重複解釋原理——原理與商業價值在前面的步驟已經講過。當你在自己的專案上覺得某個畫面慢半拍、不好點、太擁擠時，回到這裡查就好。

七個手段一覽

手法它處理的狀況關鍵數值或做法

拇指區 Thumb Zone單手操作搆不到重要控制放在螢幕下半部

下面逐條說明。

1. 骨架屏（Skeleton Screen）

骨架屏是載入時先出現的佔位頁面：用淺色的形狀、線條與文字框，先勾勒出頁面的結構，等真正內容載入後，再填進原本佔位的地方。它處理的是「等待」這件事。

它的關鍵事實是：使用者在看骨架屏的時候，感知到的載入時間，會比看旋轉指示器（spinner）時來得短。內容其實還沒到，但因為你先看到了結構，大腦就有了「東西快來了」的預期。

2. 拇指區（Thumb Zone）

拇指區是手機介面設計裡的用語，指的是單手握持手機時，最容易用拇指觸及的那塊螢幕區域。它依據的是拇指在自然握姿下的活動範圍，而這個區域通常在螢幕的下半部。

設計師會把重要的互動元素——按鈕、選單等控制項——放在這個區域裡，以達到最好的可及性與易用性，同時降低使用者出錯（例如誤觸其他東西）的機率。

3. 點擊目標（Tap Target）

點擊目標是觸控螢幕上使用者可以點按、藉此觸發某個動作的互動元素，例如按鈕、圖示、連結、核取方塊與表單欄位。它處理的是「手指到底點不點得到」。

關鍵數值是最小建議尺寸約 48 像素（px）。一個圖示本身可能只有 24px 寬高，但你可以靠間距把整個可點範圍補到 48px。除了尺寸，目標之間也要留足夠的間距，以減少誤觸。

4. 收集使用者回饋

這個手段是用問卷、訪談、焦點團體等方式，主動找出使用者在哪裡遇到困難、對什麼不滿意。它處理的狀況是：你其實不知道使用者在哪裡受苦。

一份簡單的做法，是在網站上放一個表單問卷。問題依你的情境而定，常見的問法包括：最希望我們改善什麼、下次更新會想要什麼功能、目前體驗裡最喜歡與最不喜歡的是什麼。有了回饋，你才能確認產品是否真的滿足使用者需求，並據此改進整體體驗。

5. 減少點擊數

減少點擊數的目標，是把使用者達成目的所需的點擊次數降到最低。點擊越少，使用者越快找到他要的內容，也越不容易在過程中失去耐心。

常見的具體做法有：記住使用者的外送地址與付款資訊，讓結帳更快；顯示他上一次的購買紀錄，讓下一次回購一鍵完成；把註冊時必填的資訊減到最少；以及用搜尋自動完成（search autocomplete）在使用者打字的當下就建議結果。

6. 留白（Whitespace）

留白指頁面上沒有被其他元素佔用的區域，包含邊距（margin）、內距（padding）與間隙（gutter）。名字雖然叫「白」，但它不限於白色——設計裡任何沒被文字、照片或插畫佔用到的區域，都算留白。

留白處理的是畫面擁擠、重點不明。它可以用來建立視覺階層、引導注意力、提升易讀性，也能讓版面看起來更寬鬆、不那麼雜亂。

7. 色彩的運用

顏色對使用者如何感知與互動產品有很大的影響，所以使用時要特別小心：色彩太多或太少都會讓人抗拒，而用錯顏色會造成刺眼或令人困惑的體驗。

還有一個容易忽略的變數是文化差異。同一個顏色在不同文化裡可能代表完全不同的意思——例如白色在西方常與純潔、清新連結，在東方則可能代表死亡與哀悼。設計給跨文化使用者時，這一層必須納入考慮。

與行動體驗有關的三件事

這份清單裡有幾個手法直接連到行動裝置，因為行動流量已經是大宗。2022 年第二季，行動平台佔整體網路流量約 59%，所以設計師必須把行動體驗做順。如果產品沒有做行動最佳化，使用者放棄的機率是 5 倍；而一個行動友善的網站，也會大幅影響搜尋引擎排名（SEO）——別忘了搜尋引擎的爬蟲也是你的訪客。

小結

這七個手段是：骨架屏（用結構佔位讓等待感覺更短）、拇指區（重要控制放螢幕下半部）、點擊目標（最小約 48px，靠間距補足）、收集使用者回饋（用問卷、訪談、焦點團體找出痛點）、減少點擊數（記住資訊、顯示上次購買、搜尋自動完成）、留白（用 margin、padding、gutter 建立視覺階層）、以及色彩（顧及對比與文化差異）。它們處理的是很具體的症狀：等太久、搆不到、點不準、不知道問題在哪、路徑太長、太擠、顏色出問題。

想知道這些手法為什麼重要，回頭看第三步的商業價值；想確認每一招在整段體驗裡的哪個位置，回去看第二步的技能地圖。但真正判斷該用哪一招，只能回到真實畫面上量測與測試——那正是後面可用性測試的主題。
