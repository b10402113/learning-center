UX 與 UI 到底在解什麼問題？

Step 1/4 · UX 與 UI 的分野

學習目標

能分辨 UX 與 UI 各在處理「使用起來的感覺」還是「看起來的樣子與操作介面」，並用生活譬喻說出兩者的分工。

前言：一個很漂亮卻讓你找不到按鈕的 app

你打開一個剛下載的 app。畫面很美，配色高級，圖示精緻，每個圓角都恰到好處。可是你想做一件很簡單的事——比如取消訂閱——卻怎麼點都找不到入口，翻了四層選單才發現它藏在一個叫「帳戶管理」的角落裡。你心裡冒出的第一句話大概是：「這個 app 是很好看，但真的很難用。」

反過來，你一定也用過另一種 app：外觀樸素，甚至有點工程師味，但每一步都滑順，你要找的東西總是在你預期的地方出現，用起來幾乎不用想。這兩種感受的差別，正好切開 UX 與 UI 這兩件事。

用一句話先抓住方向：UI 管「看起來怎樣、怎麼操作」，UX 管「用起來怎樣、有沒有解決我的問題」。這一課要把這條線劃清楚，因為後面所有的設計方法，都建立在你能分辨這兩者之上。

兩個詞各是什麼

UI（User Interface Design，使用者介面設計）處理的是數位產品裡你看得到、點得到的視覺元素：按鈕、色彩、字體排印（typography）、圖示（icon）、版面配置（layout）。它的目標，是做出一個視覺上討喜、容易理解、對使用者友善的介面。UI 設計師的日常工作，就是讓產品好看，同時讓人能輕鬆地操作它。

UX（User Experience Design，使用者體驗設計）處理的則是使用者與產品互動時的整體體驗。它在意的是產品「用起來感覺如何」「多容易上手」「多大程度滿足了使用者的需求與期待」。UX 設計師的重點放在理解使用者——他們的痛點、他們的目標——然後做出有效率、愉快、好用的產品。所以 UX 設計師會去看使用者的完整旅程：為了解決一個問題，他要走哪些步驟、得完成哪些任務、整個過程順不順。

把兩者並排看，差異就出來了：UI 是「那一層畫面上看得見的東西」，UX 是「把那一層放進整段使用過程之後，到底順不順」。

用生活譬喻理解

講師用了兩個譬喻，都把同一件事講得很清楚。

第一個是車子。UI 像車子的外觀——車色、車形，還有按鈕、旋鈕與儀表板的樣式；UX 像車子開起來的感覺——座椅的舒適度、操控的順手程度。一台車可以烤漆很美、內裝精緻，但開起來顛簸又難操控；也可以外型平凡，但開起來行雲流水。

第二個是房子。UI 像室內設計，決定外觀與整體佈局，涵蓋色彩、字體排印，以及所有構成空間美感的視覺元素。UX 則像思考這間房子會被怎麼使用：周遭環境怎麼影響整體設計、動線怎麼安排才能滿足屋主的需求、能不能住得舒適好用。房子裝潢得再美，如果動線讓人每天撞到桌角，那仍是個不好住的房子。

兩個譬喻指向同一件事：外觀和體感是兩個不同的層次，但它們都落在同一個產品身上，缺一不可。

同一個產品，兩種工作日常

把鏡頭拉到一個生鮮外送 app，看看這兩種角色實際上每天都在忙什麼。下面的對照表把兩邊的工作拆開：

領域UI 設計師在意的事UX 設計師在意的事
出發點畫面好不好看、好不好操作使用者能不能達成他的目標
典型工作字體排印、留白、色彩對比、圖示、按鈕與卡片、跨裝置的一致性使用者研究、設計策略、內容組織、互動設計、可用性測試、依回饋迭代
常用手段調整版面、選色、挑圖、畫元件訪談、問卷、畫 wireframe 與 prototype

先看 UI 設計師。他要負責字體排印，確保文字符合易讀性與可讀性的最佳做法；要留意留白（white space，也稱負空間），用空白給介面結構與平衡；要選色，確保對比足夠，兼顧可用性與可讀性；要做圖示，讓每個圖示都有意義、一眼就能辨認；要設計按鈕與卡片，挑選合適的圖像或插畫來搭配；最後還要確保介面從大螢幕到小手機都好看。

再看 UX 設計師。他會先做研究，用問卷、訪談與使用者測試，理解目標客群的需求、行為與目標。接著用研究發現定出設計策略，也就是整體的設計方向與計畫。然後把內容組織、安排成使用者容易找到、容易完成任務的樣子。再來是設計互動：畫出 wireframe（線框稿）與 prototype（原型），呈現這個 app 實際上會怎麼運作。設計出來之後，他會跑可用性測試來評估，找出可以改進的地方，並把測試回饋納入，持續修正，直到體驗真的到位。

為什麼兩者非得合作

產品的「外觀與體感」會大幅影響使用者的整體體驗，所以 UX 與 UI 是互相依賴的，必須一起合作，才能做出既實用又好看的產品。

這個互賴不是口號，用兩個壞掉的例子就看得出來。一個介面再漂亮，如果重要的按鈕被藏在死角、流程繞來繞去，使用者還是走不到終點——那是 UX 壞了。反過來，一個流程設計得很順的 app，如果按鈕小到點不到、文字對比低到看不清楚，使用者一樣會卡住——那是 UI 壞了。任何一邊鬆掉，使用者感受到的都是「這個產品不好用」，而不是「這是 UX 的問題」或「這是 UI 的問題」。

小結

UI 處理產品的視覺元素與操作介面——按鈕、色彩、字體、圖示、版面；UX 處理使用者與產品互動的整體體驗，也就是用起來的感覺、效率與好不好用。車子的外觀與操駕感、室內設計與居住動線，都是同一個區分的不同說法。兩者互相依賴，得一起做，才能同時達到實用與好看。

你現在手上有了最基本的座標：一邊是「看起來怎樣」，另一邊是「用起來怎樣」。但很多人接著會問下一個問題——「那我該走 UX 還是 UI？」下一課會指出這個問法藏了一個誤解，並把 UX 拆成一張技能地圖，帶你看看 UI 其實位在哪一層。
