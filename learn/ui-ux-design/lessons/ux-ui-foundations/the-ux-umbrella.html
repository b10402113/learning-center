UX 是一把大傘，UI 就在傘底下

Step 2/4 · UX 與 UI 的分野

學習目標

能畫出 UX 傘下的技能地圖，並解釋為什麼 UI 是 UX 的一部分、為什麼現在的設計師要兩邊都碰。

前言：一句常見的問法，藏著一個誤解

上一課把 UX 和 UI 分成兩層：一層管體感，一層管外觀。弄清楚這個區分之後，很多人馬上會問下一個問題：「那我到底該走 UX 還是 UI？」

這個問法聽起來很自然，但它默默假設了一件事：UX 和 UI 是兩條平行的路，你只能挑一條走。如果把這兩個詞畫成一張技能地圖，你會發現它們的關係並不是這樣——UI 其實長在 UX 的裡面。這一課要把那張地圖攤開，你就會知道為什麼「選一邊」這個問題本身問錯了。

UX 是一把大傘

你可以把 UX 想成一把大傘。這把傘的底下不是一個技能，而是一整排技能，每一格分別處理整段使用體驗裡的某一段。

傘下的技能它負責什麼
User Research（使用者研究）理解使用者需要什麼、想要什麼
Product Strategy（產品策略）擬定計畫以達成商業目標
Information Architecture（資訊架構）決定內容的組織與分類方式
Site Maps（網站地圖）把產品有哪些頁面、如何分層畫出來
User Flows（使用者流程）把體驗可能怎麼流動畫出來
UI Design（介面設計）用視覺與互動知識做出說得通、能達成目標的介面
Usability Testing（可用性測試）拿真人和設計或原型測試，確認方向正確

這張表本身就是這門課的地圖。User Research 和 Product Strategy 處理的是「該不該做、為誰做」；Information Architecture、Site Maps、User Flows 處理的是「東西怎麼擺、路怎麼走」；UI Design 處理的是「介面長什麼樣、怎麼互動」；Usability Testing 處理的是「做完之後，真人用起來到底行不行」。

UI Design 是傘下的一格，不是另一把傘

看清楚這張表的關鍵，就是找到 UI Design 的位置。它在傘下。在這一格裡，你會用到視覺設計、字體排印、色彩理論、版面設計、互動與圖示的知識，做出「說得通、又能達成目標」的介面。

換句話說，UI Design 是整條體驗流程裡負責「把介面做出來」的那一段。它不是跟 UX 平行、各自獨立的另一把傘，而是被包在 UX 這把傘底下的其中一個技能。所以當有人說「我做 UX」時，他可能正在做研究，也可能正在畫介面——兩件事都在這把傘底下。

那為什麼市場上還有專職的 UX 和 UI？

你可能會接著問：可是現實中確實有「UX 設計師」和「UI 設計師」這兩種職稱啊。沒錯，但那通常是兩種不同的東西。

確實存在專精的 UX 與 UI 角色，但這些位置通常是留給在特定領域有大量經驗的資深設計師。也就是說，專精不是入門時就要做的二選一，而是你在整條流程裡走得夠久、夠深之後，自然會偏到某一邊的結果。先把整把傘走過一遍，再決定要往哪一格鑽，是比較合理的順序。

現在的期待：兩邊都要會

而且，在現在的就業市場裡，對一個 UX 設計師的期待，是他能有效地把 UX 和 UI 兩邊都做出來。這也是為什麼一份完整的設計流程會把研究、架構、流程、UI、測試串在一起：你不需要每一格都變成世界級專家，但你要能自己把整條線走完。

對一個「一人出貨」的產品開發者來說，這個結論尤其重要。你要的不是在 UX 和 UI 之間挑一邊，而是具備一個人走完這把傘底下所有技能的能力——從研究、架構、流程，一路到介面與測試。接下來的課程，就會一格一格把它補起來。

小結

UX 是一把大傘，傘下包含 User Research、Product Strategy、Information Architecture、Site Maps、User Flows、UI Design 與 Usability Testing。UI Design 是傘下的一格，處理介面的視覺與互動，不是和 UX 平行的另一條路。市場上專職的 UX 或 UI 角色，通常是資深、在特定領域深耕的人才；而現在對設計師的普遍期待，是兩邊都能做。

你現在知道設計包含哪些事了。下一個非常現實的問題是：這些事到底值不值得投入？如果設計只是「功能做完後的美化」，它永遠排不進優先順序。下一課要用具體數字回答——好設計到底會不會影響產品成敗。
