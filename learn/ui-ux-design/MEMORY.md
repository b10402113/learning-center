# MEMORY — ui-ux-design

## Goal
能獨立完成一個真實產品的 UI/UX 設計並交付——從 brief → sitemap → userflow → wireframe → UI → prototype → 可用性測試，自己走完整條設計流程，把「一人出貨」缺的設計這半邊補齊。先不綁定特定專案，先把通用方法學通；就業／作品集／求職那一整段也納入（case study、作品集、CV、面試）。

## Why
一個人出貨產品時，設計是自己最弱的一環。不想再做出「功能能用、但醜又不順」的東西；要把設計變成自己能刻意掌控、能自己扛的能力。

## Prior experience
- 寫程式很強：TypeScript / Node，前端 React / Next.js，CSS；日常重度使用 Claude Code / opencode。
- 設計與 UX 幾乎沒碰過：Figma 等設計工具、UX 研究方法、視覺/互動設計都是新領域。
- CSS 那層（box model、flexbox、grid、position）是主場——ui2 模組 8「technical concepts」多數可快轉或只需對照設計脈絡。
- 長期主線是「一人當一個團隊」；已完成／進行多個 AI、後端、系統設計主題。

## Anchors
- 日常在用的產品當設計評析與 pattern 參考：**Linear / Vercel / Stripe**（開發者工具類）；**Notion / Airbnb / Apple**（內容、協作、精緻度）。
- 課程共同範例：ui2 的 **Accom.ai 訂房 App**（sitemap → userflow → wireframe → UI → 可用性測試全程用它）；ui1 的 **Pride 音樂串流 landing page** 與 grocery app 的 UI 評析。
- 暫時不綁自己的專案；先把方法學通，之後再搬回自己的題目。
- 自己的 React / Next 專案與日常工具（VS Code / opencode）——用來對照「設計決策怎麼落成實作」。

## Habits & constraints
- 每週 1–3 小時，時間零碎；每篇要能獨立讀完、可隨時中斷再繼續。
- 環境：Mac。無硬性 deadline，中等壓力。
- 成本敏感：優先免費路徑（Figma 免費版、Whimsical、Maze 免費）。
- 輸出語言 zh-Hant；程式碼、識別字、API／產品名稱保持英文。

## Knowledge type
mixed，但 **declarative 為主**（你自選）：想先把概念與方法弄懂、建立判斷力，再進實作。動手仍要有，但排在概念之後。

## How to teach me
- **先講完整套概念與原理，再進實作**（你明確選的節奏）；不要一頭栽進工具操作。
- 但每篇仍要收在「一個可檢查的產出，或一個能做的決定」上；概念不能懸空，也不要名詞轟炸。
- 密度高、不冗長；開頭先講「這解掉什麼問題」。
- 講機制（為什麼要這樣設計），幫我記住「怎麼做」。
- 用具體產品對照（Linear / Stripe / Notion / Airbnb / Apple），把抽象原則落到看得見的例子。
- Figma 這類工具操作要逐步示範到我能自己重做一次。
- 碎片化可讀；偏好先看到成品畫面／設計稿再拆解原理。
