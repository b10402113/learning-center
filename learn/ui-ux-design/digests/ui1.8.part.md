# Digest — UX/UI Design Mastery Course (part 8: Ideation Strategies)

## Overview (L1)

- 1. Ideation Techniques — Ideation generates many candidate solutions that are then narrowed to the most viable; surveys the core techniques (brainstorming, brainwriting, worst idea, sketching, storyboarding), what each is for, and how each encourages participation.
- 2. Mapping User Flows — Defines user flow as the path a user takes to complete a goal; explains the four flow types, standard diagram shapes, and the happy path vs. branching paths.
- 3. Class Project 05 - Create User Flow — Applied project: map a chosen user task (e.g. food delivery) from entry point to completion as a user flow diagram, using a Figma template or pen and paper.
- 4. Wireframing (3) — Introduces wireframes as layout blueprints free of styling; covers purpose, tools, the three fidelity levels with when-to-use guidance, and placeholder text/image conventions.
- 5. Class project 06 - Create Low-Fidelity Wireframes — Applied project: build low-fidelity wireframes in Figma covering at least three screens of a complete user flow, defining UI elements per screen.

## Sections (L2)

### 1. Ideation Techniques

- Locator: `[[sources/ui-ux-design/20261007/ui1/8. Ideation Strategies for User-Centered Design/1. Ideation Techniques.en.srt#ideation-techniques]]`
- Summary: Ideation is the stage of producing creative solutions to problems, and design teams use structured techniques to generate many ideas then narrow to the viable ones. The lesson walks through the most popular methods and the conditions each suits.
- Key claims: Ideation benefits include improved productivity/efficiency, more creativity, diverse input, fewer poor design decisions, and a larger pool of combinable ideas; brainstorming leverages group interaction and free sharing without judgment; brainwriting (5 minutes writing, pass papers, build on others) suits introverts and avoids dominant voices; worst idea invites intentionally bad solutions, then flips their negative attributes into possible solutions; sketching is a fast, low-detail way to explore and communicate ideas; storyboarding uses comic-like squares and arrows to map the steps, order, roadblocks, and desired user feelings for a task.
- Learner-relevant: Gives a reusable toolbox for the "diverge then converge" phase; each technique has a distinct purpose (volume, inclusion, fear-removal, visual thinking, journey thinking).

### 2. Mapping User Flows

- Locator: `[[sources/ui-ux-design/20261007/ui1/8. Ideation Strategies for User-Centered Design/2. Mapping User Flows.en.srt#mapping-user-flows]]`
- Summary: A user flow (UX flow / flowchart) describes the process by which users interact with a product to complete a specific goal. The lesson defines flows, classifies them, and shows a worked e-commerce purchase example.
- Key claims: Flows help determine how many screens are needed, their order, and required components; the four types are task-oriented, goal-oriented, content-oriented, and hybrid; standard shapes are circles (user actions), rectangles (screens), diamonds (decisions), and arrows (direction); the "happy path" is the simple ideal route, while real flows branch on user actions and input (e.g. missing billing info redirects to the billing page).
- Learner-relevant: Turns abstract requirements into a concrete screen inventory and navigation model; the happy-path vs. branch distinction is foundational for later wireframing and prototyping.

### 3. Class Project 05 - Create User Flow

- Locator: `[[sources/ui-ux-design/20261007/ui1/8. Ideation Strategies for User-Centered Design/3. Class Project 05 - Create User Flow.mhtml#class-project-05-create-user-flow]]`
- Summary: A guided project to create a user flow diagram for the learner's portfolio, using a provided Figma template or pencil and paper. Steps: access template, choose the user task, outline the flow steps, then convert the list into a diagram.
- Key claims: A flow maps a user task from start to finish; list all steps in advance, starting from the entry point through task completion (especially for complex flows); the example food-delivery flow enumerates 13 steps including decision points (pickup vs. delivery, add extras, confirm order); the first shape is the entry point and steps may be added or changed while drawing, which is normal.
- Learner-relevant: Produces a concrete portfolio artifact and converts the Mapping User Flows theory into practice on a self-chosen task.

### 4. Wireframing (3)

- Locator: `[[sources/ui-ux-design/20261007/ui1/8. Ideation Strategies for User-Centered Design/4. Wireframing (3).en.srt#wireframing-3]]`
- Summary: Wireframes are simplified blueprints of a layout that define element dimensions, placement, information architecture, intended behaviors, and navigation without styling, color, or graphics. They let designers iterate cheaply before committing to detail.
- Key claims: Wireframing avoids the time and expense of trial-and-error on full designs; tools include Figma, Balsamiq, Moqups, Mockplus, and UX Pin; fidelity means how closely a design matches the final look and feel, with three levels — low (basic sketches, pen/paper, good for simple/short or changing projects), medium (balance of speed and detail, good for complex/moderate projects or when unsure), and high (real images/text, specialized software, for complex interactions and prototype testing); Lorem ipsum is placeholder dummy text that should be replaced with real content as early as possible, especially for user testing or client presentations; images are often indicated with a box-with-cross or image-placeholder icon.
- Learner-relevant: Teaches picking the right fidelity for the project's timeline and uncertainty, and how to represent text/images without over-investing.

### 5. Class project 06 - Create Low-Fidelity Wireframes

- Locator: `[[sources/ui-ux-design/20261007/ui1/8. Ideation Strategies for User-Centered Design/5. Class project 06 - Create Low-Fidelity Wireframes.mhtml#class-project-06-create-low-fidelity-wireframes]]`
- Summary: A guided project to build low-fidelity wireframes in Figma for a case study, demonstrating a complete user flow of at least three screens. Steps: create device frames, build individual elements, then assemble them into frames.
- Key claims: Wireframes must clearly define intended UI elements per screen (navigation menus, buttons, visuals, text fields); choose frames for the right device/screen size to stay consistent; start with a repeated element like a content card; priority is usability, so no colors, fonts, or images are needed yet; prototype stage later turns these into mid/high-fidelity wireframes tested with users before final pixel-perfect mockups.
- Learner-relevant: Bridges user flows into screen-level layouts and sets up the following interactive-prototyping stage; produces a portfolio-ready low-fidelity artifact.
