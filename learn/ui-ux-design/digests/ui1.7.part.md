## Overview (L1)

- 1. User Personas: Getting to Know Your Users — defines the user persona as a fictional-but-realistic, data-grounded description of a target user, explains primary vs secondary personas and when to use each, and lists the attributes to include (name, photo, demographics, background, needs/wants/motivations, behaviors, a quote) plus what to avoid.

## Sections (L2)

### 1. User Personas: Getting to Know Your Users

- Locator: `[[sources/ui-ux-design/20261007/ui1/7. Understanding and Defining User Problems/1. User Personas Getting to Know Your Users.en.srt#user-personas-getting-to-know-your-users]]`
- Summary: After research, designers analyze the data and define the problem from the user's perspective; a user persona is a fictional yet realistic description of a typical/target user, built from real data gathered via market research and user testing. Personas improve UX by keeping users in mind and also help marketing/sales target likely customers. When there is more than one persona, designers differentiate a primary persona (largest, most-regular segment) from a secondary persona (smaller/occasional segment).
- Key claims: Personas are based on real data, not assumptions, and are essential to any user-centered design process; create a few distinct personas representing different user segments, with one or two being a safe bet; common attributes are name + photo (avoid celebrities/unrealistic images), background, demographics, needs/wants/motivations, behaviors, and a summarizing quote; exclude opinions, stereotypes, and excessive detail.
- Learner-relevant: Can build an accurate, empathetic persona from interview data and describe the target user.

### 2. Class Project 04 - Create User Persona

- Locator: `[[sources/ui-ux-design/20261007/ui1/7. Understanding and Defining User Problems/2. Class Project 04 - Create User Persona.mhtml#class-project-04-create-user-persona]]`
- Summary: A portfolio project exercise that applies the persona lesson: use the recordings and notes from user interviews, analyze the data, and group responses into users who share similar interests, goals, or concerns. The learner copies a Figma persona template into their file and creates 1-2 personas, changing colors when making two.
- Key claims: Identify personas by grouping interview responses by shared interests, goals, or concerns; each of two personas should represent a different group of users; add a name, image, and demographic info plus a bio conveying the user journey with goals and frustrations; use sliders for personality traits and stickies for goals and frustrations.
- Learner-relevant: Produces a portfolio artifact — a researched, Figma-built persona (or two) for their product.

### 3. Creating Effective User Journeys

- Locator: `[[sources/ui-ux-design/20261007/ui1/7. Understanding and Defining User Problems/3. Creating Effective User Journeys.mhtml#creating-effective-user-journeys]]`
- Summary: A user journey is a map of the steps a user takes to achieve a goal while using a product; it surfaces pain points and areas for improvement and guides prototypes and new features. Journeys are useful for understanding interactions, spotting blind spots, and ensuring every required step exists for new products or multi-step flows. Every journey map has five elements: user persona, scenario, journey phases, actions/mindsets/emotions, and opportunities.
- Key claims: The five components are persona, scenario (a story tied to a goal/need, existing or in-design), journey phases (high-level stages that vary by scenario), actions/mindsets/emotions (behaviors, thoughts, and ups/downs mapped per phase), and opportunities (insights on how each phase can be optimized); build by starting from "where does the user start?", brainstorming phases and pain points, mapping touchpoints, sketching simple steps, and translating it all into a visual map with icons and cues.
- Learner-relevant: Can map an end-to-end journey for a persona and turn it into concrete opportunities for improvement.

### 4. Defining the Problem Statement

- Locator: `[[sources/ui-ux-design/20261007/ui1/7. Understanding and Defining User Problems/4. Defining the Problem Statement.en.srt#defining-the-problem-statement]]`
- Summary: After empathizing, designers formulate a problem statement that defines the issue to be addressed, states the specific challenge and why it matters, and sets the stage for all later work. A strong statement aligns stakeholders on core issues and goals, frames critical evaluation, and anchors clear communication of what to do and why. It can be written using the SMART framework (Specific, Measurable, Achievable, Relevant, Time bound) and the four W's (who is affected, what the problem is, where it occurs, why it is worth solving).
- Key claims: The problem statement must be from the user's perspective and focus on the target users' key issues; a good statement is specific and narrowly focused, measurable, realistic given resources/constraints, relevant to business strategy, and time bound; example — "busy working professionals need an easy, time-efficient way to learn how to cook and eat healthily because they often work long hours and don't have time to cook at home and do grocery shopping."
- Learner-relevant: Can write a focused, testable problem statement that steers the rest of the design process.
