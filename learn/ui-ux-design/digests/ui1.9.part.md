# Digest — UX/UI Design Mastery Course (part 9: Interactive Prototyping)

## Overview (L1)

- 1. Transform Low-Fidelity Wireframes Into High-Fidelity Wireframes — Explains the move from exploratory low-fidelity sketches to high-fidelity wireframes that lock in smaller details and interactive elements (dropdowns, hover states). Gives an eight-step conversion guide (use Figma/Sketch, analyze the existing wireframe, add content hierarchy, detail labels/buttons/fonts, position and size elements, pick readable fonts, hold off on color, add breathing room) while stressing that process is personal and further detail eventually becomes redundant.
- 2. Design Systems 101: Create Consistent and Cohesive User Interfaces — Defines a design system as reusable UI components plus a style guide, component library, and pattern library. Covers why organizations adopt them (consistency, collaboration, faster time-to-market, more effective prototypes), a five-step build guide, hosting choices (recommends Figma), and canonical examples (Google Material, Apple HIG, Atlassian, Shopify Polaris).
- 3. Create Design Mockups (1) — Turns tested high-fidelity wireframes into pixel-perfect mockups with color, fonts, images, and icons. Explains the four goals of mockups, then the conversion process (choose palette, select complementary fonts, add images, polish alignment and consistency with the wireframe), and introduces prototyping: why to prototype, popular tools (Figma, Framer, Adobe XD), and how to prepare screens and interactions for a clickable prototype.
- 4. Class Project 07 - Create Final Design Mockups — Hands-on project applying the mockup process in Figma: create a new "Mockups" page in the portfolio file, then create one named frame per screen from the low-fidelity wireframes as the base for high-fidelity mockups.

## Sections (L2)

### 1. Transform Low-Fidelity Wireframes Into High-Fidelity Wireframes

- Locator: `[[sources/ui-ux-design/20261007/ui1/9. Interactive Prototyping/1. Transform Low-Fidelity Wireframes Into High-Fidelity Wireframes.en.srt#transform-low-fidelity-wireframes-into-high-fidelity-wireframes]]`
- Summary: Defines high-fidelity wireframes as the detail-focused successor to exploratory low-fidelity sketches once a promising layout is found. They outline smaller details and interactive elements such as dropdown menus and hover states, and are essential for accounting for every design detail. Notes that some designers use a medium-fidelity middle ground, and that beginners should go low-to-high then adapt to personal preference.
- Key claims: low fidelity is big-picture and exploratory; high fidelity is about smaller details and interactive elements; high-fidelity wireframes take longer but let designers communicate the UX vision in more detail and test usability before investing in building; add detail gradually and stop when further detail becomes redundant; leave icons and other highly detailed elements out for the final mockup; the eight conversion steps are use a tool (Figma/Sketch) instead of pen and paper, analyze and expand the low-fidelity design, incorporate content hierarchy, add labels/buttons/text/fonts and sizes, set element position and size, choose readable fonts with styling rules (size, weight, letter spacing, line height), hold off on colors, and add spacing so elements are not cramped.
- Learner-relevant: Bridges wireframing into UI design — teaches when to escalate fidelity and the concrete steps to do it without wasting effort on premature detail.

### 2. Design Systems 101: Create Consistent and Cohesive User Interfaces

- Locator: `[[sources/ui-ux-design/20261007/ui1/9. Interactive Prototyping/2. Design Systems 101_ Create Consistent and Cohesive User Interfaces.mhtml#design-systems-101-create-consistent-and-cohesive-user-interfaces]]`
- Summary: Explains that a design system is a collection of reusable UI components that keep interfaces consistent and cohesive, letting designers build high-fidelity mockups quickly. A design system comprises three parts: a style guide (rules for typography, color, visual elements), a component library (reusable elements like buttons and forms), and a pattern library (groups of components solving usability issues, e.g. a navbar or contact form). It covers benefits, a build guide, hosting, and notable examples.
- Key claims: design systems enhance consistency across touchpoints (same button sizes, typefaces, color schemes), accelerate collaboration between designers and developers, enable faster time-to-market through reuse, and produce more effective prototypes by reducing iterative re-mocking; the five build steps are define core principles, gather existing components into a central library, develop an iterative workflow, document via style guides and pattern libraries, and set up regular reviews; hosting options are a dedicated server (most control, expensive), cloud service (cheaper, less control), or version control, with Figma recommended for collaboration, versioning/commenting, and component libraries; in-house designers will almost certainly work within a company design system, while freelancers rarely need to build their own since projects differ and building one takes months; reference systems are Google Material Design, Apple Human Interface Guidelines, Atlassian Design System, and Shopify Polaris.
- Learner-relevant: Gives the conceptual vocabulary and practical steps to build or work within a design system — the backbone for producing consistent high-fidelity mockups and prototypes efficiently.

### 3. Create Design Mockups (1)

- Locator: `[[sources/ui-ux-design/20261007/ui1/9. Interactive Prototyping/3. Create Design Mockups (1).en.srt#create-design-mockups-1]]`
- Summary: Covers producing final, pixel-perfect mockups once high-fidelity wireframes have been tested, and then turning those static designs into interactive prototypes. Mockups add colors, fonts, images, and icons to give stakeholders a realistic sense of the product, help designers visualize and test interactivity, invite team feedback, and make iterating cheap before build. It then defines prototyping, its purpose, tooling, and how to prepare designs for it.
- Key claims: mockup goals are to show stakeholders the final look, help designers visualize and test interactivity, allow team feedback, and ease pre-build iteration; conversion steps are choose a color palette, select complementary readable fonts across screen sizes (skippable if already finalized), add or modify elements using the wireframes as a guide, add high-quality images within the palette, and polish for correct alignment and cleanliness while keeping layout consistent with the wireframe; a prototype is a simulation used for testing before launch, and its purpose is to test and validate ideas before handing to developers because engineering changes are expensive and slow; popular tools are Figma, Framer, and Adobe XD, each with trade-offs; to prepare designs, identify every screen a user can see (including variations like pop-ups), space screens out to allow connections, identify each screen's interactive elements (links, buttons), and define what happens and which screen appears on interaction.
- Learner-relevant: The core of this part — how to go from wireframe to polished mockup to clickable prototype, giving an end-to-end path to validate designs before development.

### 4. Class Project 07 - Create Final Design Mockups

- Locator: `[[sources/ui-ux-design/20261007/ui1/9. Interactive Prototyping/4. Class Project 07 - Create Final Design Mockups.mhtml#class-project-07-create-final-design-mockups]]`
- Summary: A guided class project that reuses the low-fidelity wireframes from the previous module to start building mockups in Figma. It walks through organizing the Figma file by creating a separate page for mockups, then creating and naming one frame per screen. Learners who have not completed the low-fidelity wireframes are told to go back first.
- Key claims: create a new page named "Mockups" (and rename Page 1 to "Wireframes") to organize the file, since each page has its own canvas; create frames with the F/A shortcuts or the Frame tool, choosing the appropriate device frame from the right sidebar and naming each frame after the screen it represents (e.g. "Home"); repeat until the number of frames matches the number of screens in the wireframes; this frame set becomes the base for designing the high-fidelity mockups.
- Learner-relevant: Hands-on anchor that converts the part's concepts into a concrete Figma workflow, producing the frames for the learner's portfolio-project mockups.
