### 2.1 Differences between UI & UX

- Locator: `[[sources/ui-ux-design/20261007/ui2/2.1 Differences between UI & UX Lesson Summary (Li).en.srt#ui-vs-ux]]`, `[[sources/ui-ux-design/20261007/ui2/2.1 Differences between UI & UX Lesson Summary I Designership (Li).pdf#ui-vs-ux]]`
- Summary: Distinguishes UI (User Interface) and UX (User Experience) design and shows how the two skill sets relate. UI is likened to interior design—appearance, layout, color, typography, visual elements; UX is how the product functions and meets user needs. UX is the overarching umbrella encompassing research, strategy, IA, sitemaps, user flows, UI design, and usability testing.
- Key claims: UI ≈ aesthetics/layout; UX ≈ function, usability, and user needs; today a UX designer is expected to execute both; specialist UX/UI roles are generally for senior designers with deep experience; the course focuses on a mix of UX and UI skills.
- Learner-relevant: Core career-vocabulary lesson; gives the skill-map that lets learners place every later module (research, strategy, sitemaps, flows, wireframes, UI, testing).

### 2.2 The Brief

- Locator: `[[sources/ui-ux-design/20261007/ui2/2.2 The Brief Lesson Summary (Li).en.srt#the-brief]]`, `[[sources/ui-ux-design/20261007/ui2/2.2 The Brief Lesson Summary I Designership (Li).pdf#the-brief]]`
- Summary: Mizko walks through the full technical brief for the Accomda AI accommodation-booking project. He stresses that briefs vary and the key designer skill is processing the information into an initial strategy. The brief's sections are project overview, problem statement, research findings, deliverables, and job stories.
- Key claims: Founder Steve experienced the problem firsthand (booking for a Lake Crackenback getaway with his partner); problem statement = lack of supportive information and user controls, so travellers overspend time; research shows 80% of participants hit similar issues; booking experience scores 9/10 while the research experience scores 5.1/10—so the opportunity is combining activity research with booking; 100% of booked activities influenced accommodation choice; persona is "Just Married Justin & Jasmine" (25–35, married/no kids, tools Booking.com/Airbnb/TripAdvisor); MVP should focus on one segment (hotels or B&B) and one region (Australia in the brief, adjustable to learner's locale); recommendations include intent-based filtering, price filtering/sorting, activities-on-map, clear non-negotiables, and live host/guest messaging at the stay, while deliberately skipping the preparation stage; competitor read: Airbnb 9/10 direct, Booking.com and Expedia ~6/10 indirect.
- Learner-relevant: The central context lesson—learners practice extracting problems, users, constraints, and MVP scope from a real brief before designing anything; anchors every later decision.

### 2.3 Project overview

- Locator: `[[sources/ui-ux-design/20261007/ui2/2.3 Project overview (Li).en.srt#project-overview]]`, `[[sources/ui-ux-design/20261007/ui2/2.3 Project overview I Designership (Li).pdf#project-overview]]`
- Summary: The course's first practical exercise, an editable Figma container with five framing questions to answer from the brief and research before designing. Mizko then shares his own answers, stressing there is no single correct approach in UX.
- Key claims: The five questions are: (1) primary problem being solved; (2) key sections to strategize/design from the job stories; (3) competitors to benchmark against; (4) early-adopter target; (5) how you'll approach the project. Mizko's section list: homepage, search experience, booking experience, my bookings, profile settings, authentication (plus header/footer components); primary problem: "lack of supportive information and user controls that help traveling couples find suitable accommodation"; early adopters: young tech-savvy couples seeking unique accommodation in Australia; competitors: Booking.com, Airbnb, TripAdvisor; approach: re-review research → assess competitors' baseline → focus on the unique problem set → consider practicality/resources (listings, customers, time frame).
- Learner-relevant: Turns passive reading into documented thinking; produces the aligned mental model that the sitemap module then builds on.
