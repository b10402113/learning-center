# 可用性原則與 Nielsen 十項啟示

## Learning goal

內化核心可用性原則與 Nielsen 十項啟示，把它們當成評稿與做設計判斷的檢查表。

## Steps

1. [[learn/ui-ux-design/nodes/usability-heuristics/core-ux-principles|可用性的核心原則：先降低摩擦，再談漂亮]] — 說出六個核心可用性原則，並解釋各自在降低什麼摩擦、建立什麼信任
2. [[learn/ui-ux-design/nodes/usability-heuristics/nielsen-ten-heuristics|Nielsen 十項可用性啟示：一份設計檢查表]] — 認得十項啟示的定義與代表例子（after step 1）
3. [[learn/ui-ux-design/nodes/usability-heuristics/heuristic-evaluation|用啟示做設計評審：跑一輪 Heuristic Evaluation]] — 拿十項啟示當檢查表，對照畫面寫出附嚴重度的可修正發現（after step 2）

## Lesson

一個介面「能用」跟「好用」之間的差距，幾乎都藏在摩擦裡：使用者得多想一下、多找一下、多等幾秒，或是在犯錯之後不知道怎麼回頭。這個節點要給你的，是一套判斷摩擦的語言。

前半段先把可用性的核心原則講清楚——一致性、遵循熟悉的慣例、載入速度、進度回饋、簡潔、自動儲存。這些原則背後其實是同一件事：降低使用者的認知負擔，並且用可預期性換取信任。有了這層理解，你才知道為什麼某些設計會讓人卡住。

後半段把 Nielsen 的十項可用性啟示當成一份固定的檢查表。它不只是一份清單，而是把「好用」拆成十個可以逐項核對的角度：系統狀態可不可見、語言貼不貼近真實世界、使用者有沒有控制權、錯誤能不能預防與修復。最後一步會教你怎麼把這十項套在一個畫面上，跑一輪 heuristic evaluation，把模糊的「感覺怪怪的」寫成具體、可以動手的修改清單。走完之後，這套檢查表就是你之後每一次設計與評稿的預設工具。
