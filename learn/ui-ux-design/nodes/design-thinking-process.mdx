# 設計思維與流程全貌

## Learning goal

用五階段設計思維與迭代觀，說出設計流程每一步在做什麼、為什麼可以回頭走。

## Steps

1. [[learn/ui-ux-design/nodes/design-thinking-process/design-thinking-mindset|設計思維：先解決對的問題，再做對的畫面]] — 理解設計思維是以人為本的心態，以及迭代、協作、失敗為踏腳石的意思
2. [[learn/ui-ux-design/nodes/design-thinking-process/five-stages|五階段流程：empathize、define、ideate、prototype、test]] — 逐階段說明各自在做什麼、產出什麼、用哪些手法（after step 1）
3. [[learn/ui-ux-design/nodes/design-thinking-process/from-loop-to-deliverables|從迴圈到交付：brief、sitemap、userflow、wireframe、UI、測試]] — 把迴圈對照到真實交付流程，看懂每個階段的位置與依賴（after step 2）
4. [[learn/ui-ux-design/nodes/design-thinking-process/reading-the-brief|讀懂 brief：把需求文件變成設計策略]] — 從 brief 抽出問題、使用者、限制與範疇，轉成初步策略（after step 3）

## Lesson

設計常常被誤解成「把畫面做漂亮」。但真正的起點不是畫面，而是問題：使用者在什麼情境下卡住、為什麼卡住。設計思維把這件事講成一種心態——先理解人，再定義要解的問題，然後才發想、做原型、找人測試。這五個階段不是一條只能往前走的輸送帶，而是一個可以回頭的迴圈：測試若發現使用者看不懂，你隨時能退回定義或發想重來。

把這個迴圈落到真實專案上，它就變成一連串具體的交付物。設計師拿到一份 brief，先讀懂需求與研究，接著畫 sitemap 決定有哪些頁面與層級，再用 user flow 串起頁面之間的互動，然後用 wireframe 把版面與資訊架構定下來。等結構穩了，才進到品牌與視覺，最後做出高保真 UI，再拿真使用者做可用性測試。

這個節點要給你的是整條流程的地圖。你會先建立「以人為本、可以迭代」的心態，再走過五個階段，然後把抽象迴圈對到 brief、sitemap、userflow、wireframe、UI、測試這些實際產出，最後學會讀懂流程的起點：brief。有了這張地圖，後面每一個模組你都能回答「我現在在哪一格、為什麼要在這裡做這件事」。
