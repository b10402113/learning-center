# 演示數據與 SQL 腳本

## Learning goal

能跑通建庫建表 + 插入演示數據的完整流程，理解數據規模與覆蓋範圍。

## Steps

1. [[learn/llm-project/nodes/demo-data/dw-schema-setup|數倉表結構與演示數據]] — 理解 5 張 dw 表的建表語句與演示數據的規模和覆蓋範圍
2. [[learn/llm-project/nodes/demo-data/meta-schema-setup|元數據表結構與業務含義]] — 理解 4 張 meta 表的元數據內容，理解列角色如何區分 primary_key/foreign_key/measure/dimension（after step 1）
3. [[learn/llm-project/nodes/demo-data/run-demo-pipeline|完整初始化流程與數據驗證]] — 按順序執行兩份 SQL 腳本並驗證數據完整性（after steps 1–2）

## Lesson

這個節點對應的是掌柜問數項目「從零開始跑起來」的第一步。整個 NL2SQL 系統需要兩個 MySQL 庫：`dw` 是數據倉庫，存事實表和維度表的業務數據；`meta` 是元數據知識庫，存數據字典、指標定義和列-指標的關聯關係。兩份 SQL 腳本分別完成這兩個庫的建表和數據填充。

dw 庫的數據規模很小——20 位客戶、15 件商品、6 個地區、約 60 條訂單——但覆蓋了典型的分析維度（時間、地區、品類、品牌、會員等級），足以驗證指標口徑。meta 庫則把 dw 的每一列都登記進元數據：列名、類型、角色、示例值、中文別名，以及 13 個業務指標（GMV、AOV 等）的定義和關聯列。

理解這兩個庫的結構，是後續跑通整個系統的基礎——Text2SQL 模型生成的 SQL 會在 dw 庫上執行，而模型選表、選列、寫聚合的依據來自 meta 庫的元數據。
