# 元數據知識庫結構

## Learning goal

能說清 table_info/column_info/metric_info/column_metric 四張表的設計意圖與字段含義

## Steps

1. [[learn/llm-project/nodes/metadata-tables/why-metadata|為什麼 NL2SQL 需要元數據知識庫]] — 理解自然語言問數場景下元數據知識庫的必要性
2. [[learn/llm-project/nodes/metadata-tables/table-column-info|table_info 與 column_info：結構化元數據]] — 說清表和列的元數據結構與 role 分類（after step 1）
3. [[learn/llm-project/nodes/metadata-tables/metric-column-metric|metric_info 與 column_metric：指標定義與多對多關聯]] — 說清指標定義與列-指標關聯（after step 1）
4. [[learn/llm-project/nodes/metadata-tables/metadata-complete|元數據協同：四張表如何驅動 NL2SQL]] — 說清四張表在完整查詢流程中的協同角色（after steps 2–3）

## Lesson

元數據知識庫是掌柜問數的語義中間層。用戶說「上週華東地區 GMV 多少」，LLM 不能直接猜「華東」對應 `dim_region.region_name`、GMV 對應 `order_amount` 的 SUM。四張表把「表是什麼、列是什麼、指標是什麼、指標由哪些列算出來」這四件事登記清楚，讓後續的向量召回和 SQL 生成有據可依。先搞懂為什麼需要它，再逐張看結構。
