# Digest — 尚硅谷大模型项目之掌柜问数 (part 3.prompts)

## Overview (L1)

- `correct_sql.prompt` — SQL 纠错提示词。要求模型作为数据库专家，根据错误信息对已有 SQL 做最小必要修复，严格保持业务语义不变，只输出纯文本 SQL。
- `extend_keywords_for_column_recall.prompt` — 字段召回关键词扩展提示词。从用户问题中推断回答所必需的数据字段名列表，用于 Schema 层向量召回。
- `extend_keywords_for_metric_recall.prompt` — 指标召回关键词扩展提示词。识别用户问题中的指标意图，生成指标概念级检索关键词，用于指标向量索引召回。
- `extend_keywords_for_value_recall.prompt` — 字段值召回关键词扩展提示词。从用户问题中提取可能出现在字段取值中的候选值，用于提升字段值全文检索召回率。
- `filter_metric_info.prompt` — 指标筛选提示词。从已召回的候选指标中筛选出回答当前问题所必需的最小指标集合，不做兜底选择。
- `filter_table_info.prompt` — 表与字段筛选提示词。在已召回的候选 schema 中裁剪出必需的表和字段，确保包含 JOIN 所需主外键，不做冗余保留。
- `generate_sql.prompt` — SQL 生成提示词。将用户自然语言查询转换为语法正确、性能优化的 SQL，严格遵循指标口径与数据库方言。

## Prompts (L2)

### correct_sql

- Locator: `[[sources/llm-project/20260909/尚硅谷大模型项目之掌柜问数/3.prompts/correct_sql.prompt]]`
- Summary: 根据 SQL 执行错误信息对已有 SQL 进行最小必要修复，生成可执行且性能合理的查询语句。
- Key claims: 必须严格基于错误信息修正，不得无依据重写；保持原始业务语义不变，禁止新增/删除/替换指标、维度、过滤条件或时间范围；只能使用真实存在的表与字段；指标计算必须遵循给定口径；仅允许查询操作，禁止写操作；输出纯文本 SQL，禁用 Markdown 代码块。
- Learner-relevant: 演示了 SQL Agent 中「纠错回路」的设计——约束模型只做最小修改而非重写，是 Text-to-SQL 系统鲁棒性的关键模式。

### extend_keywords_for_column_recall

- Locator: `[[sources/llm-project/20260909/尚硅谷大模型项目之掌柜问数/3.prompts/extend_keywords_for_column_recall.prompt]]`
- Summary: 从用户自然语言问题中推断回答所必需的数据字段名列表，用于 Schema 层的向量召回。
- Key claims: 仅输出字段名（列级业务语义），禁止输出取值、表名、指标或 SQL；字段名必须稳定、抽象、可复用；以「是否必需」为唯一标准；时间/人群/行为/对比等语义必须包含对应字段；存在歧义时必须补充消歧字段；不依赖外部知识或业务假设。
- Learner-relevant: 展示了 RAG 中「查询扩展」的一种——把用户问题翻译成 Schema 概念，用于提升字段检索召回率，是 NL2SQL 检索阶段的核心技巧。

### extend_keywords_for_metric_recall

- Locator: `[[sources/llm-project/20260909/尚硅谷大模型项目之掌柜问数/3.prompts/extend_keywords_for_metric_recall.prompt]]`
- Summary: 识别用户问题中的指标意图，生成指标概念级检索关键词，用于指标向量索引召回。
- Key claims: 面向「指标概念」而非字段、表或取值；优先使用指标名风格短语；显式指标必须原样保留并可补充同义词；隐含指标生成最可能对应的指标概念但不得发散；允许同义词、别名、缩写（语义等价前提）；不依赖外部知识或行业假设。
- Learner-relevant: 体现了指标检索与字段检索的分工——指标层负责「度量什么」，字段层负责「从哪里取」，两者分开召回可降低语义混淆。

### extend_keywords_for_value_recall

- Locator: `[[sources/llm-project/20260909/尚硅谷大模型项目之掌柜问数/3.prompts/extend_keywords_for_value_recall.prompt]]`
- Summary: 从用户问题中提取可能出现在字段取值中的候选值，用于提升字段值全文检索召回率。
- Key claims: 仅输出字段值层面内容，禁止输出字段名、表名、指标或 SQL；可包含枚举值、业务实体、时间语义词、角色/人群标签；必须来自问题本身的显式或隐含语义；同一语义多种表达可一并给出；不确定是否存在的取值可以生成，但明显臆造的禁止。
- Learner-relevant: 补齐了检索的三层结构——字段名、指标名、字段值，三者分别对应 Schema、度量、取值空间，是 NL2SQL 多路召回的典型设计。

### filter_metric_info

- Locator: `[[sources/llm-project/20260909/尚硅谷大模型项目之掌柜问数/3.prompts/filter_metric_info.prompt]]`
- Summary: 从已召回的候选指标中筛选出回答当前问题所必需的最小指标集合。
- Key claims: 只能从候选指标中选择，禁止新增或修改；以「是否在本次问题中被实际用于度量或统计」为唯一标准；显式提及必须选中，隐含度量诉求选最直接的基础指标；不涉及度量则返回空数组；保持最小集合，不做兜底选择。
- Learner-relevant: 演示了召回后的「精筛」阶段——先召回再裁剪，避免把无关指标喂给下游 SQL 生成，是控制幻觉与 token 成本的关键步骤。

### filter_table_info

- Locator: `[[sources/llm-project/20260909/尚硅谷大模型项目之掌柜问数/3.prompts/filter_table_info.prompt]]`
- Summary: 在已召回的候选 schema 中裁剪出回答问题所必需的表和字段。
- Key claims: 只能从候选表中选择，禁止新增表/字段或修改字段名；每张被选中的表必须至少包含一个被选中的字段；字段选择以「是否在本次查询中被实际使用」为标准；时间/人群/行为/指标等语义必须确保对应字段被选中；多表场景需包含 JOIN 所需主外键字段；禁止生成 SQL 或输出解释。
- Learner-relevant: 与 filter_metric_info 对应，完成 Schema 侧的精筛；强调「最小必要 schema + JOIN 键」是 SQL 生成前的重要约束注入。

### generate_sql

- Locator: `[[sources/llm-project/20260909/尚硅谷大模型项目之掌柜问数/3.prompts/generate_sql.prompt]]`
- Summary: 将用户自然语言查询转换为语法正确、性能优化的 SQL 语句。
- Key claims: 只能使用真实存在的表与字段；指标信息覆盖时必须严格遵循其口径、计算逻辑、过滤规则与时间口径；未覆盖时基于语义与通用业务常识；只能生成查询 SQL；语法必须符合指定数据库类型与版本；默认只生成一条 SQL；输出纯文本，禁用 Markdown 代码块。
- Learner-relevant: 是整个 Text-to-SQL 链路的最终生成阶段，其约束（口径遵循、单条 SQL、纯文本输出）直接决定了下游执行成功率。
