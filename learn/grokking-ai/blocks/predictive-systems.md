# 預測型系統

![概念示意圖](./predictive-systems-assets/image-1.webp)

## 定義

預測型系統是一種從歷史紀錄學習，並對新資料輸出「數字」或「標籤」的機器學習系統。

它學習時依賴「標籤」（也就是真實世界發生的正確答案），例如某筆交易是不是詐欺、使用者會不會點擊這篇文章。

## 為什麼重要

預測型系統是業界發展最成熟的架構。無論是推薦內容、排序動態牆，或是客服分流，幾乎所有大規模網路產品的第一道防線都是預測型系統。

如果預測型系統在第一步給出錯誤標籤，下游的所有處理流程都會跟著走錯方向。

## 如何運作

成熟的預測型系統通常圍繞四個核心環節運作：

1. **處理標籤延遲**：真實答案產生的速度不一樣。外送抵達時間可能一小時內就能確認；但信用卡詐欺往往要等數週，直到銀行發動拒付（撤回款項）時才會知道結果。
2. **採用漏斗架構**：面對數百萬筆候選項目時，系統會先用成本極低的方法篩選出幾百筆；接著再由功能更強、特徵更豐富的模型做精細排序。
3. **離線與線上評估**：
   - **離線評估**：在歷史資料上計算 AUC（模型把隨機正樣本評分高於隨機負樣本的機率）。AUC 0.5 代表純猜測，1.0 代表完美排序。
   - **線上評估**：在真實用戶上測量點閱率（CTR）。離線 AUC 表現更好的版本，才能進入 A/B 測試（新舊版本對比測試）。
4. **回饋迴路**：系統上線後，使用者實際產生的點擊或跳過行為，會回流變成新的訓練標籤，讓模型重新訓練升級。

## 例子

在客服工單系統中，當使用者回報「餐點遲到了 50 分鐘」，預測型系統會扮演分類分流器。

分類模型讀取工單文字後，輸出分類標籤「外送遲到」，並附帶信心分數 0.94。如果信心分數低於預設門檻，系統就會自動轉交給人工專員處理。

## 邊界與常見誤解

預測型系統只負責輸出數字或標籤，不負責起草文字內容，也不負責執行退款等具體操作。

一個經典的系統設計錯誤，是打算「直接用大型語言模型（LLM）為動態牆排序」：

- **忽視私有數據**：排序需要依賴個別用戶過去點擊了什麼、跳過了什麼。這些專利行為數據，預訓練好的 LLM 根本沒看過。
- **延遲與運算成本過高**：每次使用者刷新動態牆通常需要評估約 500 個項目。如果每個項目都呼叫一次 LLM，回應會極度緩慢，成本也無法負擔。

## 進階

在現代架構中，預測型模型常與大型語言模型協同運作：

- **離線提取特徵**：成熟的架構會把 LLM 放在離線階段執行。讓 LLM 閱讀每篇新發布的文章一次並產生主題標籤。這個標籤隨後會轉為一項特徵，輸入給下游的專門排序模型，大幅壓低即時運算成本。
- **跨家族接縫交接**：在混合型架構中，預測型模型負責打頭陣。例如工單分類標籤跨過接縫後，交由生成型模型起草回覆，最後再由代理型系統呼叫工具發放補償金額。
