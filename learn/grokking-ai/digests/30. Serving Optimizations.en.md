# L1 overview

- **Three shelves, tried in order**: (1) avoid calling the model, (2) tune the serving engine, (3) change the model. Shelves 2–3 mostly require self-hosting; starting at the bottom skips the biggest savings, because a call that never happens uses no GPU time. Baseline example: 100k conversations/day × 10 turns × 3,000 input + 300 output tokens at $3/$12 per M = $0.126/conversation, $12,600/day.
- **Semantic cache** (shelf 1): embed the new question, compare to stored embeddings, return the stored answer when similarity exceeds a tuned **threshold**; tune on labeled pairs, keep wrong matches near zero, prefer misses, never cache personalized answers, put an exact-match cache in front, and store the policy version with each answer so changes can drop stale entries — a wrong hit has no error message.
- **Router vs cascade**: a **router** picks the model before any answer is written (heuristics or a small trained classifier); a **cascade** tries the small model then escalates failed answers (moved-up requests cost more and wait longer). Typical routing sends 70–80% to the cheap model; both need a **golden set** to watch the quality boundary, since cheap-path failures are silent.
- **Shelf 2 engine tuning**: trimming input and capping output (output tokens cost 4× input) saves directly — 3,000→2,400 input tokens at 1M turns/day cuts $9,000 to $7,200/day. Decode is **memory-bound** (each step re-reads all weights), so **continuous batching** (refill after every step, 5–10× throughput vs naive batching), **paged attention** (KV cache in ~16-token pages + block table, wasting at most the last page, so more requests fit), and **prefix caching** (keep the KV cache for a byte-identical shared prefix to cut TTFT; one changed token ends reuse, so put shared content first) all help.
- **Shelf 3 model changes**: **quantization** (16→8 or 4 bits: 70B model 140 GB → 70 GB → 35 GB; 8-bit usually costs little quality, 4-bit may — run the golden set before/after), **distillation** (train a small student on a large teacher's answers to your real traffic, subject to terms of use), and **speculative decoding** (a small draft model guesses ~4 tokens, the large model verifies in one step, keeping tokens up to the first wrong one; ~2× faster decode with no quality loss, at the cost of a second model).
- **Measure before shipping**: semantic cache → hit rate and wrong hits; router → small-model quality and escalation rate. Order-of-magnitude expectations: caching ≈ zero model cost, routing ≈ 5× cheaper per routed request, batching serves 3–30 users per GPU. Routing 75% of traffic in the capstone leaves about one-third of the original bill — but a saving per request is not a saving on the whole bill because hard requests still pay full price.
