# L1 overview

- One test decides the family: who chooses the next step and when? A call-summary feature (transcribe → summarize → extract action items) is a workflow because a developer fixed the order in code; the chat feature is an agent because nobody knows the right steps until the system looks, so the model chooses at runtime.
- Several model calls don't make an agent; a workflow is a line with a known length, an agent is a cycle with no natural end, so the design must supply one. Each pass has three parts: reason (read context, task, earlier steps, tool list), act (request a tool call the runtime checks and runs), observe (add the result and repeat).
- A seven-step cold-food example: get customer orders (two drinks on the bill, 35 minutes late), get courier timeline (18 minutes waiting at the restaurant), search policies (refund for missing items, credit past 30 minutes), get risk signals, then apply refund plus credit — while many recent claims would have made step 6 an escalation instead.
- The trajectory (every step, tool call, and result in order) is the unit of evaluation, stored as a trace, because two tasks can end with the same reply while one takes 7 steps and the other 30 with wrong-tool retries and 5× the cost.
- The four-rung autonomy ladder: fixed workflow, one choice among developer-written branches, model chooses each step but a human approves every write, and model applies small credits within limits with daily sampled review; most production agents sit on rung 3 or rung 4 for low-risk actions only.
- Errors compound: 95% per step over 10 steps is ~60% task success (77% at 5 steps, 36% at 20), and chat answers don't compound because each result feeds the next step's context; a bigger model helps but at 99% a 10-step task still fails ~1 in 10, so bound the error with fewer steps, code checks between steps, and a cap.
- Four budgets enforced by the runtime, not the prompt: max steps (12), max cost (50 cents), wall-clock timeout (90 s), and blast radius (one refund per task); when one runs out the agent stops, summarizes progress, and escalates with state intact — the same fix as the classic unbounded retry loop.
- Cost math: a frontier model at $3/M input and $12/M output makes a 3,000-in/300-out chat answer ~1.3 cents; since each step re-reads the whole growing history (4,000 tokens, +1,500 per step), 15 steps cost ~69 cents (55× a chat answer, or 17× without growth) and 12 steps ~47 cents — so route mechanical steps to a small model at about a tenth the price, and use a hybrid: workflow intake and triage, agent core only for active order problems, with a small action space and an action gate whose failures go to a person.
