# L1 overview

- **Generative systems lose free evaluation**: a regression model has a label (predict 32 minutes, arrive at 38 → 6-minute error, average over thousands), but a support assistant answering "My order arrived 25 minutes late, can I get a refund?" has no single correct reply — answer A and answer B can both be good yet share almost no words, and a friendly answer can break policy. "Good" is a judgment: **correct (within policy and the retrieved text)**, grounded, complete, and clear. One accuracy number hides which part regressed.
- **Three-layer evaluation pyramid** (cheap/broad at the bottom): **layer 1 programmatic checks** run on every output (valid JSON with required fields, citation points to a really-retrieved source, hard business limit like no refund above $10 without approval; for code products, compile + run tests — the strongest signal there); **layer 2 an LLM judge** grades against a **rubric** (correct, grounded, complete, clear), point-wise or pair-wise; **layer 3 human evaluation** on a small sample. Each layer checks what the one below cannot: code cannot judge meaning or tone, a judge cannot be trusted until humans calibrate it, humans cannot read everything.
- **Judge biases and fixes**: length bias → rubric says length earns no credit; self-preference → use a different model family; position bias in pair-wise → run each pair twice swapped and count a flipped win as a tie. **Calibration** means humans and judge score the same outputs and you measure agreement; fix unclear rubric items and add scored examples. Pin the **judge's version** and recalibrate any new version on a fixed **anchor set** so provider updates do not shift scores overnight; rescore so you never compare two judges' scores.
- **Golden set**: a few hundred hand-curated cases (real production cases with PII removed, hard cases near a rule like 19 minutes late, adversarial cases like insisting on a $50 refund), kept separate from training data, run like **CI** on every prompt edit or model swap, with per-category regression limits that block the change. Each case also records which document search should retrieve, so you can separate a **prompting problem** (right policy retrieved, bad answer) from a **search problem** (right policy missing) — scoring only the final answer may make you fix the part that never failed. Every production failure adds a case.
- **Online beats offline**: a **canary** serves 5% of live traffic and rolls back on a worse key signal. Watch **explicit feedback** (thumbs down — cheap but sparse and skewed to annoyed users), **behavioral proxies** (regenerations, rephrases), and **task-level outcomes** (resolved without a human, no repeat contact within three days — richest and slowest). The worked case: a shorter/warmer prompt passes the golden set and raises judge scores 4%, but the canary shows regeneration 6%→9% and more repeat contacts — because shorter answers dropped the *reason* for a decision. Online wins, and the transcripts become a golden-set case plus a new rubric item ("explains the reason"). Exception: a change that breaks policy or safety never ships. Also: users who gave up never click thumbs down, so check repeat contacts and escalations.
