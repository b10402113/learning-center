# L1 overview

- "Design GitHub Copilot" is really two products sharing one name: inline completion (first token within ~200–400 ms at p99) and chat (first words in ~1–2 s); example scale is 300M completions/day vs 10M chat requests, about 30× apart, with budgets that differ ~10×.
- Completion has nothing to search — its context is the prefix and suffix around the cursor, so it uses a small (~few billion parameter) fill-in-the-middle (FIM) model on the team's own GPUs, with a 50 ms debounce, request cancellation on retype, prefix-match reuse, and speculative decoding for about 2× speedup.
- Chat is RAG over the repository: structure-aware chunking (one function per chunk), an index rebuilt on every push, plus code-native context (dependency graph, recent diffs); it runs BM25 keyword search and embedding search together because identifiers must match letter for letter.
- Two metrics and two filters: acceptance rate (scored with kept-code rate 30–60 s later) and chat's weaker signals plus weekly retention; a secrets filter scrubs outgoing context and an attribution filter blocks verbatim copies of licensed code beyond a set length.
- Privacy ships as three tiers (zero-retention API, chosen region or customer VPC, customer-hosted models); failure must be "graceful absence" — no ghost text rather than a laggy editor.
- The data flywheel turns telemetry (shown→kept events) into free training labels, gated by a golden set, a shadow run, then a 1% canary; cost example is $0.0003 per completion call × 300M ≈ $90,000/day, chat blends to ~$110,000/day with 30% routed to the frontier model at ~3 cents, and a 100M-line monorepo needs ~12.3 GB of embeddings.
