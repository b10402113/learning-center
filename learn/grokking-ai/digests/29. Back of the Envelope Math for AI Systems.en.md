# L1 overview

- **Back-of-the-envelope estimation** means rough math done out loud to size a system: pick simple numbers, multiply, round, and always end on the right **order of magnitude** plus a decision ("about $2M/year, so test a cheaper model first"), not a fake-precise figure like $1,898,000. State every assumption aloud (e.g. 200,000 documents/day) so a correction costs one line, not the whole answer.
- **Anchors** to memorize: 1 token ≈ 4 characters; frontier model ≈ $3/M input and $12/M output tokens (small model ~10× cheaper); one chat turn ≈ 1 cent; one GPU ≈ $2–4/hour writing ~2,500 output tokens/second.
- **Token bill method** — size the unit, price the unit, multiply by volume: a 4,500-word report ≈ 6,000 tokens + 500 instruction tokens = 6,500 input (1.95¢) and 500 output (0.6¢), so ~2.6¢/summary; at 200k/day that is ~$5,200/day or ~$1.9M/year. Input is ¾ of the bill even though output costs 4× per token. Routing 80% to a small model at 1/10 price gives a blended 0.28× bill (~$530k/year).
- **Fleet math** for self-hosted models: size for peak (100 req/s × 400 output tokens = 40,000 tokens/s ÷ 2,500 per GPU = 16 nodes), add **headroom** and round to 20 nodes (~$1,440/day at $3/hour). Never size from input tokens or the average: decode sets the real load, so use a per-node rate from a load test with real request lengths.
- **Memory math** decides GPUs per copy: at 16-bit precision each parameter is 2 bytes, so a 13B model needs ~26 GB and fits an 80 GB GPU, while a 70B model needs ~140 GB (2–4 GPUs per copy). **Quantization** to 8-bit (~70 GB) can fit one GPU. The leftover memory hosts the per-request **KV cache** (~2 GB each), which more often than processing speed caps concurrency.
- **Vector store sizing** = chunks × dimensions × bytes: 10M chunks × 768 dims × 4 bytes ≈ 30 GB (one server); 1B chunks ≈ 3 TB, which forces **sharding**. Cheapest fixes first: model routing, then semantic cache, then prefix cache. Naive assumptions misprice chat — 10 turns resend growing history so total input is 55,000 tokens, not 10,000, i.e. near-quadratic growth.
