# L1 overview

- The right framing is **not a ladder** of prompting → fine-tuning → RAG. The tools solve different problems: **RAG changes what the model knows**, **fine-tuning changes how it behaves**, and **prompting does a little of both and is always where you start** (cheap to try, easy to undo, and it sets the **baseline** score on the evaluation set).
- They act at different times: prompting and RAG are **online** (inside each request) and change only the text going in; fine-tuning is **offline** (before any request) and is the only one that changes the model's weights. A prompt or document change ships in minutes; a fine-tune needs a training run, evaluation, and careful release.
- **Prompting has two limits**: instructions cost tokens on every call with no memory between calls (a 2,000-token prompt × 400,000 calls/day = 800M input tokens ≈ $2,400/day), and instructions **cannot teach new facts** — pasting the whole help center does not fit or cost too much, which is exactly why retrieval exists.
- **RAG strengths/limits**: edit a policy and the next answer picks up the new indexed text; retrieval can hide documents per user and support citations. But every prompt gets longer, retrieval can return the wrong passage, and the model can still misread or mix passages — RAG **reduces** hallucination, it does not end it. Complete grounding needs three instructions (answer only from context, cite each claim, say when the context lacks the answer) plus a citation check.
- **Fine-tuning** trains on example input→ideal-output pairs (hundreds to thousands) and fits **tone**, **format** (e.g. a five-field handoff summary), and **narrow skills** (12-intent labeling). **LoRA** (low-rank adaptation) freezes the base model and trains small adapter layers — cheaper to train/store/swap, the practical default. Never fine-tune for facts: memorization is uneven, weights apply to everyone so permissions cannot be filtered, policy changes lag until the next run, and there is no source to cite.
- **Diagnosis-first decision rule**: start from the prompted baseline, then sort each failure — missing facts or changed policy → **RAG**; right facts but wrong tone/format → improve the **prompt first**, fine-tune only when better prompts stop helping; right but too costly at volume → an **economic** decision, route routine traffic to a fine-tuned small model. Never put facts or permissions in the weights; the classic production pairing is RAG for policy knowledge plus a fine-tuned small model for tone and format. Continued pre-training and training your own model are last resorts and usually interview mistakes.
