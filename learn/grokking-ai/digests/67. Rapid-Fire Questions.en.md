# L1 overview

- Format: 25 short questions grouped by module, each with a hidden answer linked to the lesson that teaches it, and every question asks for a deciding variable — the one fact that decides between two or more options (e.g. the delivery estimate needs the live route, so it runs online).
- A round has four steps: keep the answer closed and say a full reply out loud (silent reading only practices recognition, the feeling you knew an answer once you see it), keep time at ~30 seconds per answer (running past counts as a miss; silent drills train a skill the interview never tests), open and mark (a pass only if you named the deciding variable without a hint — "it runs online" is a miss because the reason is missing), and revisit every miss by rereading the linked lesson and re-drilling on a later day.
- Scoring is a practice signal, not a law: count passes out of 25; 20+ is "interview ready" as an example, and below 20 the misses show which lessons to revisit first — if several misses fall in one module, review that whole module.
- Module 1: sort the question into three families by what the model mainly outputs — a number or label (fraud score) is predictive, content is generative, actions are agentic.
- Module 2: training runs background jobs over large data and optimizes throughput, serving answers live requests and optimizes latency; between them sits training-serving skew (serving uses different features than training did, quality drops with no crash or alert), best fixed by training on the features serving logged, with a feature store's offline store (full history) and online store (latest values in milliseconds) sharing one definition; batch vs online inference turns on whether the prediction needs information that exists only at request time (then ~10–100 ms online, else a ~1 ms lookup); data drift changes inputs, concept drift changes their meaning (fraudsters change methods).
- Module 3: no single model is both good enough and cheap enough, so a funnel narrows in stages (50M videos → ~500 → ~50 → ~20 shown); position bias is fixed with propensity weighting that upweights clicks in rarely viewed positions; an ads model must be calibrated because its PCTR sets money in an auction (a predicted 2% must mean ~2 clicks per 100); a blocked fraud payment never yields a label, cured by a capped exploration slice let through on purpose.
- Module 4: an LLM reads and writes tokens (~three-quarters of an English word); prefill reads the whole prompt in parallel and sets most of time-to-first-token while decode writes one token at a time and sets total time; on your own GPUs memory often limits concurrency, and utilization sets real cost since a GPU costs the same busy or idle; optimizations sit on three shelves in order (avoid the call, e.g. semantic cache; tune the serving engine; change the model); RAG changes what the model knows, fine-tuning changes how it behaves — never put facts or permissions in weights; the evaluation pyramid is code checks at the cheap bottom, an LLM judge with a rubric in the middle, human review at the costly top, and a golden set of a few hundred hard real cases runs on every change.
- Module 5: when a RAG answer is wrong, look at retrieval first — check recall (the share of questions whose right chunks came back) before changing the prompt; vector search misses exact tokens like error codes and BM25 misses paraphrases, so hybrid runs both; enforce document permissions inside the retrieval query (after generation is too late, the model already read the text); RAG does not remove hallucination, grounding keeps each answer tied to sources.
- Module 6: images take seconds to tens of seconds of GPU time so text-to-image is asynchronous (queue a job, return a job ID); text injection can't be fully prevented because instructions and untrusted data reach the model through the same channel, so surround the model with gates and least privilege.
- Module 7: workflow vs agent is decided by who chooses the next step and when (code at design time vs model while running); a second agent earns its cost only for context isolation, parallelism, or specialization, otherwise one agent because each multiplies cost, delay, and failure modes; a tool call is a request not a command — the runtime checks it, high-stakes actions wait for a person, and autonomy climbs suggest → approve → bounded auto → audited auto with written thresholds and automatic demotion after an incident.
- Module 8: a 45-minute interview splits across seven steps — framing and success in the first 8 minutes, data and model by minute 18, serving path (the largest share) 18–30, keep it working to 38 and costs to 43, last two minutes for questions; three mistakes are reading instead of speaking, passing on a key word (saying "concept drift" is not an answer; "the same inputs now lead to a different outcome" is), and rereading answers you already pass.

# L2 detail

- `#L1-L153` — The 25-question rapid-fire drill: the four-step timed round graded on naming the deciding variable, the 20-of-25 practice bar, and the module-by-module answer keys from question families through skew, funnels, LLM serving, RAG, gates, agents, and the 45-minute clock.
