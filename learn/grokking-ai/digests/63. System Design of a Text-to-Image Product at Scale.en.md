# L1 overview

- Stated priority moves the cost step: "I care about the bill" means the fleet math goes at minutes 3–7 instead of the usual minute 38–43, because every main part (model, steps, resolution, queue) changes the GPU bill; the last step then holds the levers.
- Shape is an asynchronous job pipeline: ~10 GPU-seconds per image × 4 images per prompt is too long for request-response, so the API creates a job, returns a job ID at once, and a worker does the work.
- Fleet math: 2M images/day ÷ 86,400 s ≈ 23/s (round to 25) → ~250 busy GPUs on average; a peak hour at 2× average needs ~500; adding headroom and a warm pool means paying for ~400–450 GPUs at $2–$4/GPU-hour ≈ $20,000–$45,000/day; idle GPUs cost the same, so the gap above 250 busy GPUs is where savings live — never price only busy GPUs.
- Product numbers travel as a set: images kept per session (saved/downloaded), wait time by tier (paid reaches a GPU within seconds at P90, free within ~a minute), and safety incident rate; fleet number is utilization, targeted at 60–80% at peak, and images generated is never a success metric because it grows with the bill.
- Model portfolio chosen once at in-queue time so price is known before GPU work: a prompt enhancer (small LLM expanding short prompts so the first grid is better), a flagship diffusion model for paid, a fast low-step/high-resolution-dialed model for free, and an upscaler that enlarges only picked images; each job record keeps prompt, enhanced prompt, seed (for replay), and GPU seconds.
- Gates: the prompt gate (classifiers score the prompt before queueing, so a blocked prompt costs zero GPU time) and the image gate (classifiers check every image before any user sees it, because an innocent prompt can produce a harmful image); both fail closed, and the grid is a free but noisy label machine (a pick beats three; "four new" means none was good).
- Queue does three jobs: its order is the price list (paid buys a shorter wait, so the free promise comes from leftover capacity — e.g. ~650 GPUs peak, ~180 paid, ~470 free, free P90 ~45 s so promise "about a minute"), its growth signals the fleet to add workers, and its depth gives an honest wait estimate.
- Scheduling and reliability: batch by shared model and resolution for more images per GPU-second; workers are long-lived to avoid tens-of-seconds weight reloads; a crash retries once on a fresh worker with results and billing recorded once under the job's idempotency key, and a second crash goes to the dead letter queue with a credit refund.
- Levers in order of user pain: batching → warm pools sized from measured spikes → quality dials (fewer steps, lower resolution; a free image from ~8 GPU-seconds to ~3) → free-tier queue stretch (1 minute to a few minutes) last because it costs signups; unpicked images expire (e.g. 2 weeks), and utilization plus P90 waits plus incidents plus revenue-per-1,000 are monitored.
