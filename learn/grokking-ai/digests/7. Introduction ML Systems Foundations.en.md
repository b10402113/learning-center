# L1 overview

- Defines an **ML system** as everything needed to produce predictions, deliver them, and keep them accurate — not a model file. It has three parts: the **offline plane** (collects data, **trains** a candidate, tests and stores approved versions; schedule-triggered, throughput matters), the **online plane** (**inference** on one request, constantly available, fast), and the **feedback loop** (logs predictions with features, later joins the real outcome as a **label**, feeds the next training run, and monitors).
- Three connections join the planes: the **model registry** (every approved version with its quality results and producing data/code) flowing forward, the logs flowing back, and the **feature store** (full history for training, latest values for fast lookups) so both planes share one feature definition. Delivering predictions to users is **serving**.
- Latency framing: an estimate must appear within ~100 ms, but a small model may run in only 1–10 ms of that — fetching inputs, routing, logging, and the network take the rest, so the model is one small box inside the request.
- Worked trace of one prediction at 6.02 p.m.: three features (average prep time computed hours ago, kitchen queue counted seconds ago, route distance computed now), features ready in ~10 ms, model returns 32 minutes in ~15 ms, log write after ~20 ms; the real 38 minutes becomes the label and the prediction was 6 minutes short. Because route and queue exist only at request time, batch inference is ruled out.
- Training detail: the nightly job joins logged predictions with their labels using only feature values available at prediction time — using a later value would teach the model information it never has at checkout; a better candidate then runs in **shadow mode** and a **canary release**.
- Module roadmap: 10 more lessons following the map — first three build the model, next three serve it, next three keep it working, then a capstone; module 1's 7-step framework supplies the skeleton and this module supplies technical content for steps 2–7. Previews embeddings, on which LLM retrieval builds.
- Six mistakes to avoid: drawing only the model; assuming labels already exist; computing features twice (**training-serving skew**); reaching for the biggest model first; shipping on an offline win alone (use a careful rollout plus A-B test); forgetting the **fallback**.
