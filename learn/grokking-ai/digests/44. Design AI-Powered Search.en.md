# L1 overview

- "Add AI answers to search" is an integration problem, not a from-scratch RAG build: keep the spine (classic ranked links in ~300 ms, ads-funded) and add a lane (answer path) that can never slow the spine or worsen its results; example scale 10,000 queries/s at ~1 cent per answer.
- Name two decisions first: when to trigger an answer (most queries want a site, not a paragraph) and how to ground it (every claim cites a real result on the page); then confirm scope, e.g. English text answers.
- Success needs two ledgers — lane (groundedness, session success, good abandonment) and spine (ad revenue per search, publisher clicks) — because a fast answer that slows results is a failed launch.
- Split ownership: an in-house trigger classifier (gradient-boosted tree, ~5 ms, trained on search logs and session outcomes) and a bought mid-tier synthesizer LLM that stays inside passages and cites each claim; a semantic answer cache keyed on embedding similarity with per-topic TTLs handles the Zipfian query distribution.
- The corpus is adversarial: spam scores gate what enters the prompt, page text is sandboxed against indirect prompt injection, sensitive topics get an entailment check, and the lane fails closed (empty slot, 300 ms results unaffected, first words ~1–2 s).
- Cost math drives the design: answering everything is 864M queries/day × 1 cent ≈ $8.6M/day; dials that multiply are trigger rate (20%) and cache miss rate (half), landing near $864,000/day, so trigger and cache are the design.
