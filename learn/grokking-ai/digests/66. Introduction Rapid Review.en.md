# L1 overview

- The module teaches no new material: rereading makes ideas feel familiar, but familiarity is not the ability to say them, so it trains recall — bringing an answer back from memory without help — while the running example is the follow-up "why not fine-tune the model?".
- Shape of a strong answer to a follow-up: state the choice, then the reason that matters most — the deciding variable, the one fact that decides between options — use the course's number and say it's an example, and name the failure case or fallback where the course gave one.
- Red flags are sentences that make you sound less experienced than you are: a claim with no number, no trade-off, or no failure case ("the system should be fast and accurate"); the strong version instead gives three numbers — a success metric, a latency target, and a cost ceiling; a strong hire candidate raises risks, cost, and the feedback loop before being asked.
- Three review tools, each targeting a different weakness: rapid-fire questions (short questions from every module answered in 1–3 sentences; a pass must name the deciding variable), red flags (12 junior-sounding statements with the reason each is weak plus a stronger sentence, and three interview-wide habits), and decision cheat sheets (a compact table per decision leading with the deciding variable, each row mapping a signal in the question to an option, ending with a default).
- Three wrong ways to use the tools: they don't replace the lessons (each item is a summary; the reasoning is in the lesson), they aren't lines to memorize (an interviewer changes one number and a memorized line stops fitting), and they aren't for reading (reading an answer you know tests nothing).
- The drill has five steps: cover the answer, answer out loud on a ~30-second timer to an imagined interviewer, check and mark misses (wrong answer, ran out of time, or omitted the deciding variable or a needed number all count), go back to the specific lesson and write one sentence in your own words onto a miss list, then redrill that miss on a later day — an item leaves only after two correct answers on two different days.
- Spaced review is the point: five minutes after rereading an answer proves little, a day later is closer to the interview, and saying one item five times in an evening only shows it was fresh that evening — spread drills across days.
- Example plan (~two weeks, ~45 min/day, both numbers made up): two weeks out drill one or two modules a day of rapid-fire and start the miss list; one week out cover the deciding-variable column of the cheat sheets; three days out say a stronger version of each red flag before reading the lesson's; the day before drill only the miss list and reread the 45-minute clock, starting no new material.
- Case studies remain necessary because the tools drill single ideas while an interview joins them on a clock: keep running full 45-minute case studies out loud, timed, and recorded, graded against the five dimensions from How to Run a Case Study, and add each gap to the same miss list.
- Triage when time is short: start with the modules closest to the role (an LLM role starts with LLM and Agent modules), give Module 2 (ML Systems Foundations) special care because later modules reuse its ideas, and when many misses come from one module restart from that module's overview diagram rather than the individual lessons; order the tools Rapid Fire → Decision Cheat Sheets → Red Flags, then read the conclusion.
