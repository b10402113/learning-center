# L1 overview

- Two runs both end with a correct $3 refund, but Run A takes 4 steps and Run B takes 19, looks up the wrong order, and retries a failing refund tool 3 times — graded by final answer only they tie, yet Run B costs several times more; for an agent the unit of evaluation is the trajectory, not the output, so grade the destination and the route.
- The golden set is the test bank, and each scenario carries four things: the initial world state, success criteria (one $3 refund, ticket closed, at most 12 steps), the golden trajectory (an expert's path as an efficiency baseline, not the only right answer), and a category label (happy path, edge case, adversarial — e.g. "refund my last five orders" as prompt injection); labels let you report per-category because 93% overall can hide 50% adversarial, and every production incident becomes a permanent scenario so the same failure can never ship twice.
- Scenarios run in a sandbox with replica tools on synthetic data, and the replicas must fail like real tools (timeout, rate limit, permission denial, not found) — one scenario times out the refund tool once then succeeds; idempotency keys prevent a double payment, and real tools keep changing, so the sandbox is a system to maintain.
- Three graders score each trajectory, cheapest first: programmatic checks (certain facts and hard route rules, near-zero cost, run on every change as the regression backbone and blocking gate, though blind to reasoning), the trajectory judge (an LLM scoring against a rubric, sampled in production and only trustworthy as far as its agreement rate with humans, measured by calibration), and human review (~50 trajectories a week plus every disagreement, with two reviewers whose mutual agreement caps what the judge can claim).
- Grade against four criteria, not a step-for-step match: correct end state, no route rule broken, on budget, and recovery from errors — many valid paths can pass.
- Five route metrics: task success rate per category, step efficiency vs the golden trajectory, wrong-tool rate, dead-end rate, recovery rate (adapting after a tool error, not re-running the same failing call), and refusal correctness split into missed refusals and false blocks because they cost differently; step efficiency often moves first (steps rising 5→7 with success flat means tasks will soon hit the step limit).
- Cost is per task, not per call: 12 steps × ~2,000 tokens ≈ 24,000 tokens per attempt; at $3/M input and $12/M output, one attempt is about 9 cents, and 10,000 attempts a day is about $900/day; real steps resend instructions and history, so plan with a cautious $0.30–$0.50 per attempt, and report success alongside cost because an agent can give up cheaply or succeed expensively by brute force.
- The budget cap (12 steps, $0.50) serves two roles: a runtime control that stops the task and sends it to a human, and an evaluation threshold inside each scenario's success criteria.
- The model-swap walkthrough: 300 scenarios run three times each, checks find 15 runs over the 12-step cap, a 90%-agreement judge scores all of them, humans read the 12 disagreements — the new model wins happy and edge cases but adversarial success drops 85%→70%, recovery 80%→65%, and cost doubles $0.05→$0.10, so the team keeps the current model; a single overall success rate would have approved it.
- Sandbox scores often exceed production (92% vs 75% with real customers) because of the gap between the scenario bank and reality; check simple causes first like replica timeouts, and run a continuous pipeline that turns every failing production trace into a new scenario — and on "is an LLM judging an LLM circular?", only if the judge is never validated; trust it only as far as its agreement rate goes.
