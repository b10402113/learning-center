# L1 overview

- The three families are predictive (predictions), generative (content), and agentic (actions); an agent is a system where the model chooses some of its own next steps and those steps change real systems, so a wrong action harms differently than a wrong answer — some actions can't be undone.
- Acting adds three questions a bare "LLM wired to APIs" doesn't answer: what may the system do, who checks each action, and when does it stop.
- The loop: the model reads task state and proposes one step (often a tool call), but never runs the tool — ordinary code called the runtime acts through an action gate that checks inputs, user permissions, business rules, and whether a human must approve; the loop ends done, escalated, or out of budget.
- A refund limit in the prompt is only a request; the same limit in the tool's code is a rule the model can't change. A consequence tier sorts tools by harm: read tools, reversible writes with undo, consequential writes with limits checked in code, and irreversible/high-stakes actions requiring human approval, all under least privilege.
- Trust is earned with evidence: a trajectory is the full path of a task, a trace is the stored record, sandbox tests use copies of real tools and fake data, each production failure becomes a new scenario, and the autonomy ladder moves the agent up one tier at a time.
- Not every system that calls a model is an agent — the test is who chooses the next step; a workflow's path is fixed in advance and is easier to test and price, so a hybrid (fixed intake + agent core) is the norm. Errors compound (10 steps at 95% each ≈ 60% success), cost grows as each call re-sends the growing history, and a stuck agent can retry forever — so every loop ships with budgets.
- Walked example: budgets of 12 steps, 90 s, 50 cents; a $32 order 50 minutes late yields a $6.40 (20%) credit after the action gate verifies ownership, lateness, the $10 cap, no prior credit, and one-credit-per-conversation, with an idempotency key surviving a lost reply so the customer gets one credit; ~9 s and 4 model calls versus ~3 s and one call for the answer-only assistant.
