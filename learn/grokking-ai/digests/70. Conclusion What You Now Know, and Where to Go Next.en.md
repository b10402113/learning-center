# L1 overview

- The whole course around one problem — a vague 45-minute AI design question answered out loud — with one food delivery company as the running example: it built delivery-time prediction, then a support assistant that grew from answering questions into an agent applying credits and issuing refunds within code-set limits.
- Three tools for the 45 minutes: the family test (what does the model output? score → ranking/judging funnel, content → pipeline, actions → loop), the seven steps (frame, define success, map data, pick model, design serving, keep it working, count costs), and the clock (the serving path gets the largest share; without it you run out before the costs) — say the family and known system early, then what changes.
- Seven ideas run through every module: (1) the design is the system around the model (the delivery model used only a few ms of a 100 ms request), (2) cheap work comes first, (3) a stage that misses something can't be rescued later (if retrieval drops an item, no answer can use it), (4) rules that matter live in code not the prompt (the $30 refund cap), (5) every change passes gates like shadow mode, (6) failure behavior is decided in advance (a permission check always fails closed), and (7) price one unit then multiply by volume (in the fake-review example, human review was the largest cost, not the model).
- Module-by-module recap: M1 — a learning system breaks four assumptions (quality needs measurement, cost needs controls, drift needs a feedback loop, silent failures need a safety layer), with the capstone scoping ~40,000 conversations/day and ~$4 per human-handled ticket, refunds above $10 to a person; M2 — offline plane builds, online plane serves, feedback loop maintains, skew is prevented by a feature store, and a model moves offline eval → shadow → canary → ramp → A/B, judged on a bad tail as well as an average.
- M3 — ranking funnels judged on recall (retrieval) and precision (top of list), judging models that turn a score into money (calibrated PCTR × bid sets the auction price); M4 — LLM tokens, prefill vs decode, three optimization shelves (avoid the call, tune the engine, then change the model), a capstone cutting ~$45,000/day to ~$9,000 via routing and caching; M5 — RAG chunks, embeddings, hybrid search and entailment checks, with the permission filter inside the index query failing closed to public content.
- M6 — products around a bought model pass six stages including input and output gates, and each product's binding limit decides its shape (latency for a code assistant, GPU time for text-to-image); prompt injection can't be fixed inside the model, so gates sit outside it and injected text cannot turn off a check it cannot reach; M7 — the model proposes and the runtime decides, tools are checked before running, and the capstone agent had budgets of 12 steps, 90 seconds, and 50 cents with a $30 refund cap enforced in code; M8 — the timed answer, minutes per step with an exit criterion, graded from a recording on five dimensions; M9 — rapid-fire questions, decision cheat sheets, and red flags for the weeks before.
- Practice is a cycle: pick a variation, set a 45-minute timer, speak out loud, record, and grade the recording on the five dimensions (never grade from memory, which makes your performance seem better), then fix the weakest dimension at its source lesson; a partner who interrupts finds gaps a solo run hides, and most weak dimensions describe what you did not say, not what you did not know, while the strong-hire bar rewards what you raise unprompted.
- The course's numbers are made up, so learn the method, not the price; next steps include building a RAG system over your own notes tested with a golden set, and always reaching the feedback loop, the risks, and the cost in the interview.
