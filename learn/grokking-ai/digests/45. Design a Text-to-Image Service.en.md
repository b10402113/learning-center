# L1 overview

- Start with numbers, not the model: 2M images/day at 4 per prompt, ~10 GPU-seconds per image; the request must be asynchronous (create a job, return a job ID in ~0.2 s) because holding the connection open doesn't shrink tens of seconds of GPU work.
- Utilization is the business because an idle GPU costs the same per hour; example fleet is ~23 images/s (call it 25) → 250 GPUs busy on average, ~500 at peak, at $2–$4/GPU-hour ≈ $12,000–$24,000/day, with a warm pool pushing real cost to ~$20,000–$45,000.
- Product numbers are wait time by tier, pick-or-upscale share, and safety incident rate; wait splits into ~300 ms acceptance, tier-dependent queue wait, and model-dependent generation time.
- A prompt enhancer (small fast LLM) turns a short prompt into a detailed one, may be turned off, and must be re-checked by the prompt gate since it can add words the user never typed; each job stores both prompts, model version, settings, safety scores, and seed so it can be replayed.
- Queue depth per tier does three jobs: auto-scaling signal (watch the trend, not one moment), honest wait estimate (e.g. "about 40 s"), and revenue lever (paid tiers buy a shorter queue); workers stay long-lived to avoid reloading gigabytes of weights, with an idempotency key per job and a dead letter queue after two crashes.
- Three gates: a prompt gate (classifiers with per-category thresholds, blocks before queueing so no GPU time is spent), an image gate (checks every image in private storage), and a provenance gate (watermark plus takedown hash); checking gates fail closed, and thresholds ratchet up on misses and red-team finds, accepting false positives — with the free-tier rule "lower steps and resolution before turning users away".
