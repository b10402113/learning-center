# L1 overview

- Core reassurance: an AI system is still a distributed system; the classic parts stay, but four unspoken assumptions break with no error message and each needs one new architectural piece.
- Assumption 1 (outputs are right or wrong) breaks because quality sits on a spectrum — a 32-minute estimate against a 38-minute delivery is 6 minutes off, not a failure. Fix: a **quality measurement subsystem** that joins logged predictions to real outcomes and reports average error by city and hour; each system needs its own metric (click-through rate, resolution rate, precision/recall with a threshold).
- Assumption 2 (behavior stays fixed until deploy) breaks because of **drift** — a new city, a new stadium, summer heat all degrade the model silently. Fix: a **feedback loop** that collects data, trains a candidate, scores it against production on recent unseen data, then promotes it to a small share of traffic; check data pipelines before calling a drop drift.
- Assumption 3 (requests are cheap) breaks because an LLM call costs ~a cent versus far less than a thousandth of a cent for a database read. Worked example: 10 million review-summary page views a day at ~1 cent each is ~$100,000/day, but 50,000 restaurants changing summaries once a day is ~$500/day — 200× cheaper. Fix: **cost controls** — caching, precomputing, and routing to the cheapest sufficient model.
- Assumption 4 (failures are loud) breaks because a model returns HTTP 200 with wrong content, and LLMs add **prompt injection**. Fix: a **safety and control layer** — input checks (moderation classifier), output checks, limits enforced in code, and graceful degradation; size the checks by **blast radius** (one wrong ETA vs. a misread refund rule hitting every customer).
- Build-vs-buy for generative AI: hosted API (per token, no GPUs, provider rate limits), self-host open weights (hourly GPU cost, cheaper per call at high steady volume), or fine-tune (changes tone/format, does not teach company facts); classic ML is usually in-house because no provider has your data.

# L2 detail

- `#L1-L147` — What changes when the system learns: four classic assumptions that break and the four new components (quality measurement, feedback loop, cost controls, safety and control layers) that answer them, plus build-vs-buy for gen AI.
