# L1 overview

- Visual search is the familiar search funnel (cheap retrieval → careful ranking) with three changes: the query is a photo (an encoder turns it into an embedding; a classic inverted index cannot represent it), there are no clicks at launch, and listings sell all day so a sold item in the results is the signature failure.
- Scope: buyer uploads a photo in the app, gets similar listings for sale near her; exact product recognition and anything generative are out. Numbers: 100M available listings, ~10M photo searches/day peaking near 350/s, results within ~300 ms — no careful model can score 100M listings that fast, which is why the funnel exists.
- Success graduates in order: at launch reviewers grade a judged set of a few thousand query photos with NDCG (gates launch); then click-through (seconds, a proxy), and contact-seller rate (the online truth, days late, but decides which model ships); sold item rate is a guardrail.
- Free supervision on day zero: four photos of one listing are positive pairs, photo-to-title pairs are free, and seller photos get random crops/blur to look like buyer photos; the baseline is a pre-trained CLIP-style image-text model with zero fine-tuning behind an ANN index, then fine-tuned with in-batch and category hard negatives.
- Baseline/rank flow: retrieval returns ~200 lookalikes from a 512-number embedding (~20 ms on GPU, distilled CPU fallback), a light ranker adds price, condition and distance (second-hand sofas need pickup), giving ~30 results in ~130 ms — inside budget; category is only a soft pre-filter the buyer chooses, never a guessed gate.
- Index is perishable: the index lane embeds each new listing at creation (searchable in minutes), a sold listing gets a tombstone then leaves within the hour, and a status check catches sales inside that hour, so sold items are stopped twice; pre-filters (50 km, price) must run during ANN traversal or the index returns 200 nearest listings nationwide.
- Failure and versioning: GPU encoder → CPU fallback; slow shard → other shards answer after timeout; ranker timeout → ANN order; safety filter down → fails closed (offer text search), with fallback tags so clicks don't poison training; new encoders re-embed all 100M listings and must promote atomically with the index (version tags block silent mismatch).
- Memory/cost: 100M × 512 × 4 bytes ≈ 200 GB raw embeddings, ~1 TB with three copies and neighbor links; encoding 10M searches/day ≈ $170, one full re-embed ≈ $1,700 — the index, not the encoder, is the main cost (~3.5M listings churn/day).
