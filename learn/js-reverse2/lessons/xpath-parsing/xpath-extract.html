提取文字與屬性：/text()、//text() 與 @attr

Step 3/5 · XPath 與資料解析

學習目標

從定位到的標籤取出直系或全部文字（/text()、//text()）與屬性值（@attr），並用 ./ 在單一標籤內做局部解析。

前言：標籤到手了，資料還沒

上一節你已經能寫出一條精準的 XPath，把想要的標籤從幾千行 HTML 裡框出來。可是框出來之後，xpath() 回傳的是標籤物件，不是「李清照」這三個字，也不是那條圖片網址。標籤只是一層包裝，你要的資料在包裝裡面，還得再下一個指令把它拆出來。

這一節就是把包裝拆開。你會學到三件事：怎麼取標籤裡的文字、怎麼取標籤身上的屬性、以及當你手上已經拿著一個標籤時，怎麼只用 ./ 在它內部找東西。這三件事合起來，才算是真的把資料拿到手。

取文字：`/text()` 與 `//text()` 的差別

XPath 取文字有兩種寫法，差別在於「只取這個標籤自己那一層」還是「連底下的子標籤一起取」。原始碼裡的示範是這樣：

# ret = tree.xpath('//a[@id="feng"]/text()') #提取a标签中的文本内容
# ret = tree.xpath('//div[@class="song"]//text()')#提取div标签下所有的文本内容
#/text()提取标签直系的文本内容 //text()提取标签下所有的文本内容
# print(ret)

把這兩個寫法放到靶場頁面上看，差別就會浮現。//a[@id="feng"]/text() 只取那個 a 標籤直系的文字，也就是那句詩。//div[@class="song"]//text() 則會把 div.song 底下所有層級的文字都撈出來，包含每一個 p、span 裡的內容。整理成對照：

寫法取的範圍什麼時候用
/text()只取標籤直系的文字，不含子標籤你要的內容就在這一層，例如一句詩、一個標題
//text()取標籤底下所有層級的文字內文被拆成很多子標籤，你要全部收攏

這裡有個很常見的失誤：網站的內文常常被包在一堆 span、a 裡，如果你只寫 /text()，取到的會很零碎，甚至什麼都沒有。不確定就用 //text() 先看看，範圍大總比漏掉好。

取屬性：`//tag/@attrName`

有時候你要的不是標籤裡的文字，而是標籤身上的屬性值，例如連結的 href、圖片的 src。語法是在表達式後面接 @屬性名：

ret = tree.xpath('//img/@src')
print(ret)

這行會回傳一個列表，裡面是所有 img 的 src 網址。@ 這個符號在 XPath 裡就是「取屬性」的意思，前面放標籤定位、後面放屬性名。之後你要抓詳情頁連結的 href、抓圖片的 src、抓下一頁的網址，全都是同一個句型。

原始碼裡也示範了直接取第一個值：

a_content = tree.xpath('//a[@id="feng"]/text()')[0]
div_content = tree.xpath('//div[@class="song"]//text()')
img_src = tree.xpath('//img/@src')[0]
print(img_src)

注意 [0]：xpath() 一律回傳列表，如果你確定只有一個結果，或只要第一個，就在後面接 [0] 把值拿出來。沒有 [0] 的話，你拿到的是包著那條網址的列表，後面直接拿去請求會出錯。

局部解析：用 `./` 只在自己的標籤裡找

當結果是一大串 li，你會用迴圈一個一個處理。這時候如果又從整個文件下表達式，不只慢，還可能撈到別的 li 的資料。正確做法是用 ./，意義是「以我這個標籤當作起點往下找」：

for li in li_list:
    title = li.xpath('./a/text()')[0] # 这个.表示的是xpath的调用者，也就是li标签
    detail_url = li.xpath('./a/@href')[0]

這裡的 . 代表 XPath 的呼叫者，也就是當下的這個 li。所以 ./a/text() 就是在「這個 li 裡面」找它直屬的 a，再取文字。./ 是實戰裡高頻出現的寫法，只要你在迴圈裡逐一處理清單，就會用到它。

把零碎的文字接成一整段

用 //text() 取內文時，回傳的是列表，裡面每一項可能是半句、一行，甚至只是空白。要存成檔案，通常得先接起來、去掉前後空白：

detail_tree = etree.HTML(detail_page_text)
content = detail_tree.xpath('/html/body/div[2]/div[1]/main/section/div[1]//text()')
#将content列表转换成一个完整的字符串
content = ''.join(content).strip()

''.join(content) 把列表的每一項黏成一個字串，.strip() 去掉頭尾的換行與空白。這一步不是 XPath 的功能，而是 Python 字串處理，但幾乎每個抓內文的案例都會用到它。

動手之後你會看到什麼

做完這一節，你的程式應該可以只憑一條表達式，就回傳一段乾淨的文字或一條網址。驗收的標準是：給你一個標籤，你能說出該用 /text() 還是 //text()、該不該接 @屬性、需不需要 [0]。這些判斷靠的是經驗而不是背誦，多拿幾份真實頁面練幾次就會內化。取值的原理到這裡就夠了，剩下的都是這幾個符號的組合。

小結

取文字時，/text() 只拿標籤直系的那一層，//text() 連子標籤全收；取屬性用 @屬性名，例如 @href、@src。因為 xpath() 一律回傳列表，取單一值要接 [0]。在迴圈裡處理一個標籤時，用 ./ 把範圍限制在它內部。零碎的文字再用 ''.join(...).strip() 接成完整字串。

到這裡，單一頁面的「定位加取值」已經完整了。但真實的任務很少只有一頁，而且常常要下載的是圖片或壓縮檔，不是文字。下一節會把這套技能接上多頁爬取與二進位下載，串成一條完整流程。
