資料解析與聚焦爬蟲：從「抓下來」到「取出想要的」

Step 1/5 · XPath 與資料解析

學習目標

說出資料解析在爬蟲流程中的位置與通用原理（定位標籤、取出文字或屬性），並比較 xpath、bs4、re、pyquery 四種解析技術的取捨。

前言：抓回來一大包，然後呢？

你把 requests.get() 跑起來，狀態碼 200，畫面印出 response.text，然後是幾千行的 HTML。裡面有導覽列、有廣告、有版權宣告，你要的那個商品價格，可能只佔其中半行。抓下來很簡單，但抓下來之後，問題才剛開始：你要怎麼把那一小段資料從這一大包裡挑出來？

如果只會「抓」，你的程式永遠停在半成品：資料是抓回來了，但你沒辦法穩定地取出其中一個欄位，也沒辦法把一千筆結果排成表格。這一節先把「資料解析」這件事在整條流程裡的位置講清楚，後面四節才會動手。先知道為什麼要解析、解析在做什麼，你之後寫的每一條 XPath 才有意義。

資料解析是什麼

資料解析的定義很直白：把爬取到的資料中，你想要的部分單獨提取出來。它本身不是一個新動作，而是對「已經抓回來的東西」再加工一次。

它帶來的好處是讓爬蟲聚焦。一支只會抓頁面的程式叫通用爬蟲；加上解析之後，它才有本事只鎖定特定欄位，這就叫聚焦爬蟲。聚焦爬蟲的編碼流程比通用爬蟲多了一步，順序是：

  1. 指定 URL
  2. 發起請求
  3. 獲取回應資料
  4. 資料解析
  5. 持久化儲存

你可以對照先前的抓取流程，會發現解析正好卡在「拿到回應」與「存檔」之間。順帶一提，當你之後碰到伺服器直接回 JSON 的動態介面時，這一步可能只是 response.json() 拿欄位；但只要對方回的是 HTML，你就得靠這一節的工具。

通用原理：先定位標籤，再取值

HTML 的資料為什麼能被挑出來？因為它天生帶著結構。每一段內容都被包在一個標籤裡，標籤身上還可能掛著屬性。所以解析的通用原理只有兩句話：

在一張頁面中，想要解析的資料存在於相關的 HTML 標籤中。先把指定的標籤定位出來，再從這個標籤的內容或屬性裡把資料取出。

把網頁想成一座圖書館。你要找的那本書是資料，標籤是書架上的編號，屬性是書封上的標籤（例如語言、出版年）。資料解析在做的事，就是拿著一個書架編號走到那個位置，把書拿下來，再把你要的那頁撕下來帶走。定位與提取是兩個分開的動作，順序不能顛倒：找不到書架，就別談撕哪一頁。

這裡也藏著一個之後會一直用到的觀念：你能取到什麼，取決於你認不認得出資料被包在哪。這也是為什麼解析常常不是「寫不出表達式」，而是「不知道要對準哪個標籤」。

四種解析技術，該挑哪一個

Python 裡能做出解析的手法不只一種，各有脾氣。以下是常見的四種：

技術選擇方式特點適合的場合
xpath路徑表達式通用性最強，最重要也最常用；跨語言，之後寫 Scrapy 也是同一套結構完整的 HTML/XML，本課主線
bs4Python 物件Python 專屬，學習成本較低想快速寫完的小爬蟲
re 正則字串樣式任何文字都能用，但表達式複雜、難以維護不規則、沒有標籤結構的片段
pyqueryCSS 選擇器熟悉 jQuery 或 CSS 的人上手很快有前端背景的人

這四種沒有絕對的優劣，只有場合不同。判斷的問句是：「這份資料有整齊的標籤結構嗎？」有，就走 XPath；沒有，才考慮正則。如果你是從前端過來、對 CSS 選擇器很熟，pyquery 會讓你寫得比較順；但如果考慮到之後要接 Scrapy，學 XPath 的投資報酬率最高，因為那是同一套語言。

小結

資料解析就是在抓回來的資料裡，把想要的欄位單獨挑出來，作用是把通用爬蟲升級成聚焦爬蟲。它的通用原理只有兩步：定位標籤，然後從標籤的內容或屬性取值。技術上有 xpath、bs4、re、pyquery 四條路，其中 XPath 通用性最強，是接下來的主線。
