Base64：把任意位元組塞進文字

Step 2/5 · 編碼與摘要：URL、Base64、MD5/SHA

學習目標

說出 Base64 的字母表與「3 個位元組轉 4 個字元」的分組規則，並用 Python 的 b64encode／b64decode 完成編碼與解碼。

前言：那串看起來像亂碼的東西，其實是明文

你在 DevTools 的 Network 面板裡盯上一枚 cookie，它的值長得像 eyJ0eXAiOiJKV1QifQ。同事路過看了一眼說「這是明文的啦」，你不信，把它丟進線上的 Base64 解碼器，結果真的跑出一段可讀的 JSON。這種經驗會讓人重新思考一件事：很多你以為被「加密」的參數，其實只是換了一種寫法而已。

上一節的 URL 編碼處理的是幾個特殊字元；Base64 要處理的情境更廣，它面對的是任意位元組，包括圖片、密文這些二進位資料，目標是把它們通通塞進一串「純文字也能安全傳」的字元裡。搞懂它的分組規則，你就能一眼看穿哪些欄位其實裸奔，哪些才是真的上了鎖。

為什麼需要 Base64

很多傳輸通道只保證「安全字元」能順利通過。URL 有它的保留字，JSON 字串不能直接塞二進位，HTTP 標頭也有它的限制。可是我們手上的資料，像一張圖片的位元組、一段加密後的密文，往往不是安全字元，硬塞進去就會被截斷或誤解。

Base64 的解法是：拿 64 個大家公認安全的字元，當作一套「代號表」，把任意位元組重新編寫成這 64 個字元組成的字串。這樣不管原本是文字還是二進位，吐出來的都是安全的純文字。代價是體積會膨脹，大約多出三分之一。你可以把它想成把一張照片用文字描述出來寄給別人：資訊一點都沒少，只是換了一種一定寄得過去的表達方式。

字母表：64 個字元，每個代表 6 個 bit

Base64 的字母表是固定的 64 個字元，順序如下：

字元索引範圍
A–Z0–25
a–z26–51
0–952–61
+62
/63

另外還有一個 =，它不算字母表的一員，而是拿來補位用的。因為 64 剛好是 2 的 6 次方，每一個字元可以代表 6 個 bit，這正是整個演算法能成立的關鍵。

核心規則：3 個位元組換 4 個字元

Base64 一次讀 3 個位元組，也就是 24 個 bit。24 剛好能整除成 4 組 6 bit，每一組拿去查字母表，就得到 4 個字元。這條「3 進 4 出」的規則是理解 Base64 的全部。

用 you 當例子。這三個字元的位元組是 y=0x79、o=0x6F、u=0x75，攤開成二進位是 01111001 01101111 01110101。從頭每 6 個 bit 切一組，得到 011110、010110、111101、110101：

6-bit 分組十進位對應字元
01111030e
01011022W
111101619
110101531

四個字元拼起來就是 eW91。這就是 you 的 Base64。看懂這個例子，你就看懂了三分之二的 Base64。

補位：處理湊不滿 3 個位元組的尾巴

輸入長度不會每次都剛好是 3 的倍數，尾端總會剩東西。Base64 用 = 把輸出補成 4 的倍數：

尾端剩餘輸出例子
剩 1 個位元組2 個字元 + ==youy → eW91eQ==
剩 2 個位元組3 個字元 + =（無）
剛好整除4 個字元、不加 =you → eW91

所以不管輸入多長，Base64 輸出的長度一定是 4 的倍數。這個規律非常有辨識度，後面判斷一段字串是不是 Base64 時會反覆用到。

在 Python 裡編碼與解碼

Python 的 base64 模組把這套規則包成兩個函式。b64encode() 吃位元組、吐位元組，所以字串要先 .encode()、結果再 .decode() 轉回字串。b64decode() 則反過來，吃字串吐位元組。下面這段程式碼示範編碼：

import base64
…
# 案例2
s = "you!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!"
ret = base64.b64encode(s.encode())  # 字节处理
print(ret.decode())

執行結果是一串以 eW91 開頭的 Base64 字串：

eW91ISEhISEhISEhISEhISEhISEhISEhISEhISEhISEhISEhISEhISEhIQ==

解碼時有兩個動作要注意：b64decode() 回傳的是位元組，要再用 .decode() 才會變回可讀文字；而且如果字串長度不是 4 的倍數，直接解會出錯，得先自己補上 =。下面這段程式碼就示範了這個補位動作：

# 案例2
data = "eW91ISEhISEhISEhISEhISEhISEhISEhISEhISEhISEhISEhISEhISEhIQ"
data += (4 - len(data) % 4) * "="  # "=="
ret = base64.b64decode(data)
print(ret)
print(ret.decode())

數字看熟之後，你也可以寫成一行：base64.b64decode(s + "=" * (-len(s) % 4)).decode()，效果一樣。

它不是壓縮，也不是加密

Base64 常常被誤會成這兩件事，這裡要分清楚。它不是壓縮：Base64 反而會讓資料變大約三分之一，因為一個位元組被拆去共用 4 個字元。上面 you 只有 3 個位元組，卻要 4 個字元才寫得完。

它更不是加密：Base64 沒有金鑰、沒有祕密，任何人都能解回來。它是一種編碼（encoding），任務是「讓資料能安全通過某些通道」，而不是「不讓別人看懂」。真正的加密算完之後，往往還會再包一層 Base64 方便傳輸，所以你看到 Base64 時，要意識到它可能只是外層包裝，真正的內容還藏在裡面。

小結

Base64 用 A-Z a-z 0-9 + / 這 64 個安全字元，把任意位元組用每 6 個 bit 一組的方式重新表示：每 3 個位元組換 4 個字元，尾端不足就用 = 補到 4 的倍數。you 的結果是 eW91。它是可逆的編碼，不是壓縮也不是加密，任何人拿到都能解開；很多時候它只是加密結果外面的一層包裝。

標準 Base64 用的是 + 和 /，但這兩個字元放在 URL 或檔名裡會出問題，所以實務上還有換過字母表的變體；圖片也常被直接以 Base64 形式內嵌在網頁裡。下一節就把這兩個實戰情境拆開來講。
