Base64 變體：URL-safe 與 Data URI 圖片

Step 3/5 · 編碼與摘要：URL、Base64、MD5/SHA

學習目標

辨識並還原 URL-safe Base64（- 與 _）與 data:image/...;base64, 圖片，並補上長度不足 4 的 = 之後正確解碼。

前言：同一套 Base64，字母表被換掉了

上一節說標準 Base64 用 + 和 / 這兩個字元。問題是，這兩個字元如果出現在 URL 裡或檔名裡，會被系統解讀成別的意思：+ 在網址中可能被當成空格，/ 是路徑分隔符號。於是有人把字母表換掉，用 - 取代 +、用 _ 取代 /，這就是 URL-safe Base64。

另一種常見情境是圖片。登入頁的驗證碼、或一些小圖示，常常不是一個圖片網址，而是一長串直接寫在 HTML 裡的 data:image/png;base64,...。這一節要做的，就是把這兩種實戰變體各自還原回來：一個還原成原始文字或位元組，一個存回圖片檔。

動手前的準備

這是一節程序課，目標很明確：給定一段 URL-safe Base64 或一段 Data URI，你能在 Python 裡正確還原它。動手前你只需要先會上一節的兩件事：標準 Base64 的 b64encode／b64decode，以及「輸出長度一定是 4 的倍數、不足要用 = 補」這條規則。其他的交給下面五個步驟。

步驟一：先判斷它是不是 URL-safe

標準 Base64 的字元只會來自 A-Z a-z 0-9 + / =。只要字串裡出現 - 或 _，幾乎就可以確定它是 URL-safe 變體。反過來說，- 和 _ 在標準 Base64 裡不會出現，所以這個判準很不囉唆。

步驟二：把字母表換回標準的

還原的方式就是做一次字元替換：- 換回 +、_ 換回 /。換完之後，它就變回標準 Base64，可以直接丟給 b64decode()。下面這段程式碼就是這個流程：

import base64

# 一般规则：  + t替换 -   /替换成_
…
data = s.replace("-","+").replace("_","/")
ret = base64.b64decode(data)
print(ret)

用一組小資料看替換的效果最清楚。標準 Base64 的 //8=，經過 /→_ 之後就變成 __8=：

標準：  //8=
URL-safe：__8=

步驟三：需要時補上 =，再解碼

跟上一節一樣，b64decode() 要求字串長度是 4 的倍數。如果你從 URL 參數裡抓出來的片段被截過、或本來就沒帶 =，就要先補：s += "=" * (-len(s) % 4)。補完再 b64decode()，得到的是位元組，要文字的話再 .decode()。

步驟四：Data URI 圖片，從逗號後面切開

Data URI 的固定格式是 data:image/<型別>;base64,<資料>。前半段是宣告「這是什麼、用什麼編碼」，真正的圖片資料在逗號之後。所以第一步是切掉前綴：用 s.split(",")[-1] 取逗號後面那一大串。接著 b64decode() 把它還原成圖片位元組，最後用二進位模式 open(..., "wb") 寫成檔案。下面這段程式碼就是完整流程：

base64_img = s.split(",")[-1]
print(base64_img)

img_bytes = base64.b64decode(base64_img)
print(img_bytes)

with open("baidu_icon.png", "wb") as f:
    f.write(img_bytes)

這裡有一個很容易踩的錯：寫檔一定要用 "wb"（二進位模式），不能用 "w"（文字模式）。圖片是位元組，用文字模式寫會被編碼處理、檔案就壞了。跑完之後你應該得到一個能正常開啟的圖片檔。

步驟五：驗證結果

程式跑完，你可以用兩個方式確認自己對了。第一，看 print(img_bytes) 的開頭幾個位元組：PNG 檔一定以 b'\x89PNG' 開頭，JPEG 則以 b'\xff\xd8' 開頭。第二，直接開檔看圖片能不能正常顯示。這一步看起來多餘，卻是抓取驗證碼、準備送去 OCR 之前最省事的檢查。

什麼時候這個做法不夠用

這五步成立的前提是：對方用的還是「標準字母表換兩個符號」的 URL-safe 變體。但實務上有更狠的玩法，例如把整張字母表重新洗牌（自訂順序的 64 個字元），或是把長字串每 76 個字元折一行。遇到那類變體，單純的 replace 沒有用，你得先找到對方那張字母表，自己重建對照關係再解。課程後面講到比較進階的保護時，會回頭看到這種自訂字母表的案例。

小結

URL-safe Base64 只是把標準字母表的 + 換成 -、/ 換成 _；解碼前先 replace 回標準字母表，需要時補 =，再 b64decode。Data URI 圖片則是先切掉 data:image/...;base64, 前綴、取逗號後的內容，解碼成位元組後用 "wb" 寫檔。若對方換掉的是整張字母表，這招就不夠用，得自己重建對照表。

編碼（URL、Base64）講到這裡，共同點是「可逆」，只要有方法就能還原。但還有一類東西天生就還原不回來，而且會頻繁出現在簽名參數裡：摘要演算法。下一節來看它。
