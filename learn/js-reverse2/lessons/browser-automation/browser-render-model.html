為什麼需要瀏覽器自動化：JS 渲染與「可見即可得」

Step 1/6 · 瀏覽器自動化與動態渲染

學習目標

說出為什麼 requests 抓不到 JavaScript 渲染出來的資料、瀏覽器自動化的心智模型，以及 page_source 為什麼能拿到渲染後的 DOM。

前言：畫面上明明有，程式卻抓不到

前一個節點你已經能用 requests 把 HTML、JSON、圖片抓下來了。於是你很自然地打開一個網站，複製網址、丟進程式，結果回來的 HTML 裡翻遍了都找不到畫面上那幾筆電影資料、商品名稱或搜尋結果。

這不是你的程式壞了，而是你抓到的東西跟你眼睛看到的不是同一份。你眼睛看到的是瀏覽器執行完 JavaScript 之後的畫面，而 requests 拿回來的，是伺服器最原始吐出來的那份 HTML，裡面的內容區塊很可能還空著，等著瀏覽器用 JS 填進去。這一節不寫複雜的程式，先把這個差異講清楚，因為它是整條「瀏覽器自動化」路線的起點。

前置條件：你已完成 requests 入門與 XPath 解析，知道怎麼用 requests 發請求、用 lxml 的 XPath 取資料。這一節的操作會需要本機安裝 Chrome 瀏覽器。

你抓到的只是原始碼，不是渲染後的頁面

要理解差異，先分清楚兩個名詞。「原始 HTML」是伺服器回應裡的那份文件，也就是 requests 拿到的 response.text。它可能只有一個空的 <div id="content"></div>，資料要等瀏覽器跑完 JS 才會被塞進去。

「DOM」則是瀏覽器把 HTML 解析後、在記憶體裡長出來的文件樹。網頁上的 JavaScript 可以隨時新增、刪除、改動這個樹上的節點，畫面上你看到的內容，就是 DOM 被 JS 改完之後的結果。當你按 F12 打開 Elements 面板看到的，正是這個已經被改過的 DOM，所以它跟原始 HTML 常常長得不一樣。

一句話記住：requests 拿到的是原料，不是你看到的成品。它只負責把伺服器給的檔案下載下來，不會執行 JavaScript，所以 JS 之後才出現的內容，它當然看不到。

兩種「抓不到」要分清楚

在前一個節點，你遇過的動態資料，多半是另一種情況：資料是由瀏覽器另外發一個 XHR／Fetch 請求（網頁背景對後端 API 偷偷發的請求）拿回來的。那種資料其實伺服器已經回給你了，只是不在網址列那個回應裡；你可以用抓包工具找出那個 API，直接抄下來用 requests 重放。

這一節以及接下來幾節要處理的，是更棘手的那一種：資料根本不是任何一個 API 回來的，而是網頁的 JavaScript 在瀏覽器裡面算出來、拼出來、再畫到畫面上的。這種情況下，你就算抄遍所有封包也找不到那份清單，因為它從來沒有以完整的形式被傳輸過。遇到這種網站，唯一可靠的做法，就是「真的開一個瀏覽器，讓它把 JS 跑完」。

換一種抓法：讓真的瀏覽器跑完再取

瀏覽器自動化做的事，就是用程式碼列出「一連串要瀏覽器做的動作」：打開這個網址、在輸入框打這個字、點這個按鈕、往下滾一段。這些動作會真的發生在一個瀏覽器裡，就像有人在操作一樣。既然頁面被完整渲染過了，我們再把渲染後的內容取下來，就能拿到畫面上那份資料。

這件事有個好記的說法：可見即可得。凡是你在畫面上看得到的，渲染後的 DOM 裡就有；而我們要做的，就是把這個 DOM 取回來，接回你已經很熟的 XPath 解析流程。Selenium 就是這類工具的一種，它透過一個叫「瀏覽器驅動程式（driver）」的橋樑，去控制一個真正的 Chrome 瀏覽器。

requests瀏覽器自動化（Selenium 等）
拿到什麼伺服器回應的原始 HTML／JSON執行完 JS 之後的渲染結果（DOM）
會不會執行 JS不會會，而且是完整的瀏覽器引擎
速度與資源快、輕慢、吃記憶體，要開一個真瀏覽器
什麼時候用資料在原始回應或可重放的 API 裡資料要 JS 渲染、或要模擬登入互動

這張表的重點不是哪個比較好，而是它們解決不同的問題。能用 requests 拿下來的，就別開瀏覽器，因為又慢又重；只有當資料真的非渲染不可，或你需要像人一樣點擊、輸入、登入時，瀏覽器自動化才是對的工具。

環境：安裝 selenium 與對應的 driver

動手前先備妥兩樣東西：Python 的 selenium 套件，以及跟你的瀏覽器版本相對應的驅動程式。driver 版本若跟瀏覽器對不上，程式一啟動就會連線失敗，這是最常見的第一個坑。

pip install selenium

driver 則依你的瀏覽器與作業系統下載對應版本，例如 Chrome 用 chromedriver，下載後放到專案目錄或系統可找到的位置。安裝完成後，最小的一段程式就像這樣：

from selenium import webdriver
from time import sleep

# 后面是你的浏览器驱动位置，记得前面加r'','r'是防止字符转义的
driver = webdriver.Chrome(executable_path='./chromedriver')
# 用get打开百度页面
driver.get("http://www.baidu.com")
sleep(2)
# 关闭浏览器
driver.quit()

先別管裡面定位元素的細節，那是下一步的事。這裡只要看懂三件事：webdriver.Chrome(...) 建立一個受程式控制的瀏覽器物件，driver.get(...) 叫它打開某個網址，最後 driver.quit() 把它關掉。這三行就是整條自動化流程的骨架。

小結

requests 拿到的是伺服器原始 HTML，不會執行 JavaScript；畫面上看得到的內容，若是由 JS 渲染出來的，就只存在於瀏覽器的 DOM 裡。瀏覽器自動化用程式碼驅動一個真瀏覽器，把頁面完整跑完後再取回渲染結果，這就是「可見即可得」。它的產物可以接回你熟悉的 XPath 解析，代價是速度慢、資源重，所以只在資料非渲染不可時才用。

觀念建立好了，下一步要把這台「被程式控制的瀏覽器」真正用起來：怎麼定位頁面上的元素、跟它互動，最後把渲染後的頁面原始碼取下來交給解析器。
