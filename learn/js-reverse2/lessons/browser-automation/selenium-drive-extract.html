Selenium 基本操作：建立驅動、定位、互動、取渲染後 DOM

Step 2/6 · 瀏覽器自動化與動態渲染

學習目標

用 Selenium 建立 driver、用 By 定位元素、與節點互動、執行 JS，並以 page_source 取得渲染後的 DOM 交給解析器。

前言：把「受控的瀏覽器」真的開起來用

上一節講了為什麼需要瀏覽器自動化，那是觀念層面的事。這一節要動手，做完你會得到一支能跑的小程式：開一個受程式控制的 Chrome、在京東的搜尋框輸入關鍵字、按下搜尋、把頁面往下滾，最後把渲染完的 HTML 抓下來。這整段流程，就是後面所有瀏覽器操作的基本功。

之所以要一步步走，是因為自動化的每一個動作都對應一個明確的呼叫：開瀏覽器是一個、打開網址是一個、找到元素是一個、對元素做事又是一個。你只要能把「想做的事」對到「哪個方法」，就能組合出任何你要的操作。

前置條件：已安裝 selenium，且準備好跟你 Chrome 版本相符的 chromedriver。若還沒設定，先回到上一步的環境段落完成。

步驟一：建立 driver 並打開網址

第一件事是建立瀏覽器物件。executable_path 指到你的 driver 檔案位置，前面的 r 是防止字串裡的跳脫字元被解讀。接著用 get() 叫這個瀏覽器打開指定網址。

from selenium import webdriver
from time import sleep
from selenium.webdriver.common.by import By
#1.创建一个浏览器对象,executable_path指定当前浏览器的驱动程序
#注意：我当前是mac系统，驱动程序也是mac版本的，如果是window系统注意更换驱动
bro = webdriver.Chrome(executable_path='./chromedriver')
#2.浏览器的请求发送
bro.get('https://www.jd.com/')

跑完這兩段，你會看到一個 Chrome 視窗自己跳出來，停在京東首頁。到這裡為止，它的行為跟手動開瀏覽器沒有兩樣，差別是現在是你在用程式下指令。

步驟二：定位元素

要在頁面上做事，得先找到目標元素。Selenium 提供兩種寫法：舊式的 find_element_by_id() 這一系列，以及新的 By 常數寫法。兩種都能用，但新寫法把「用什麼方式找」與「找什麼」分開，比較清楚，也比較不會因為方法名太長而寫錯。

find_element_by_id()  
find_element_by_name()
find_element_by_class_name() 
find_element_by_tag_name()
find_element_by_link_text()
find_element_by_xpath() 
find_element_by_css_selector()

或者
from selenium.webdriver.common.by import By

driver.find_element(By.xxx,value) #返回定位到的标签

driver.find_elements(By.xx, value)  #返回列表

這裡有一個一定要記住的差別：find_element 只回傳第一個符合的元素，find_elements 回傳一整份列表。要點一個特定按鈕就用前者，要把所有商品標題一次抓出來就用後者。用錯的話，前者會漏掉其餘元素，後者會讓你拿到一個列表卻當成單一元素操作。定位方式中最常用的通常是 By.XPATH（用你在 XPath 那節學的表達式）和 By.ID（用元素的 id 屬性）。

步驟三：與節點互動

找到元素之後，就可以對它做事了。最常見的三個動作是：輸入文字用 send_keys()、清空輸入框用 clear()、點擊用 click()。把定位與互動接起來，就是下面這段：

#3.标签定位:调用find系列的函数进行标签定位
# search_box = bro.find_element_by_xpath('//*[@id="key"]')
search_box = bro.find_element(By.XPATH,'//*[@id="key"]')
#4.节点交互
search_box.send_keys('mac pro m1')#向指定标签中录入内容
sleep(2)
# btn = bro.find_element_by_xpath('//*[@id="search"]/div/div[2]/button')
btn = bro.find_element(By.XPATH,'//*[@id="search"]/div/div[2]/button')

btn.click() #点击按钮
sleep(2)

先定位到搜尋框，把關鍵字打進去，再定位到搜尋按鈕按下它。跑起來的效果就是：搜尋框自己出現文字，然後頁面跳轉到搜尋結果。這正是「像人一樣操作」的具體樣子。

步驟四：執行 JavaScript（當 API 沒提供時）

有些操作 Selenium 沒有現成的 API，例如把頁面往下捲。這時可以直接叫瀏覽器執行一段 JavaScript，方法是 execute_script()。以下片段把頁面往下捲 2000 像素：

#js注入
bro.execute_script('document.documentElement.scrollTo(0,2000)')
sleep(5)
#关闭浏览器
bro.quit()

這個能力很重要，因為很多無限滾動的頁面，就是靠滾動觸發載入下一批資料。把「捲到底」寫進流程，才能讓後面的 page_source 取到更多內容。

步驟五：切進 iframe 再定位

如果目標元素位在 <iframe>（頁面中內嵌的另一個子頁面）裡面，直接定位會失敗，因為預設的定位範圍是主頁面。這時要先用 switch_to.frame() 切進去。下面的拖曳範例，先把控制權切到 iframeResult 這個子頁面，才定位得到裡面的元素，接著用動作鏈（ActionChains）做「按住並拖曳」這種沒有特定對象的操作：

from selenium.webdriver import ActionChains
from selenium import webdriver
from time import sleep
bro = webdriver.Chrome(executable_path='./chromedriver')
bro.get('https://www.runoob.com/try/try.php?filename=jqueryui-api-droppable')
sleep(1)
#注意：如果定位的标签是存在于iframe表示的子页面中，则常规的标签定位报错
#处理：使用如下指定操作
bro.switch_to.frame('iframeResult')
div_tag = bro.find_element_by_id('draggable')

#实例化一个动作链对象且将该对象绑定到指定的浏览器中
action = ActionChains(bro)
action.click_and_hold(div_tag) #对指定标签实现点击且长按操作
for i in range(5):
    action.move_by_offset(10,10).perform() #perform让动作链立即执行
    sleep(0.5)
sleep(3)
bro.quit()

這裡多了一個新東西：動作鏈是給「滑鼠拖曳、鍵盤按鍵」這類不針對單一元素的操作用的。它把一連串動作先累積起來，呼叫 perform() 才一次執行。iframe 與動作鏈都是遇到才需要，現在先知道怎麼用就好。

步驟六（重點）：取回渲染後的 DOM

前面都是為了這一刻。透過 page_source 屬性，可以拿到瀏覽器渲染完之後的頁面原始碼，接著就能接回你原本的解析流程，用 lxml 的 XPath 把資料挖出來。以豆瓣電影類型排行頁為例：

from time import sleep
from selenium import webdriver
from lxml import etree
bro = webdriver.Chrome(executable_path='./chromedriver')
bro.get('https://movie.douban.com/typerank?type_name=%E6%82%AC%E7%96%91&type=10&interval_id=100:90&action=')
sleep(2)
bro.execute_script('document.documentElement.scrollTo(0,2000)')
sleep(2)
#获取页面源码数据
page_text = bro.page_source
#数据解析：解析页面源码数据中动态加载的电影详情数据
tree = etree.HTML(page_text)
ret = tree.xpath('//*[@id="content"]/div/div[1]/div[6]/div/div/div/div[1]/span[1]/a/text()')
print(ret)
bro.quit()

注意這裡的順序：先 get() 開頁，用 execute_script() 滾動觸發動態載入，等它渲染完，再取 page_source。取回來的字串丟進 etree.HTML()，接下來的 tree.xpath(...) 就跟你在 XPath 那節寫的一模一樣。這就是「可見即可得」在程式裡真正成立的地方：因為 DOM 已經把 JS 的成果都長出來了，原本在 requests 裡找不到的電影資料，現在 XPath 就定位得到。

做完會看到什麼

這一步成功的判準很具體：程式跑完後，主控台印出一筆筆動態載入的電影資料，而且跟你剛才在畫面上看到的一致。這就代表你已經跑通了「開瀏覽器 → 互動 → 等渲染 → 取 DOM → 解析」的完整迴圈。至於「元素為什麼有時候還沒出現」，也就是等待時機的問題，是下一步要專門處理的。

小結

Selenium 的基本迴圈是：webdriver.Chrome(...) 建立 driver、get() 開頁、find_element／find_elements 搭配 By 定位、send_keys／clear／click 互動，需要時用 execute_script() 執行 JS、用 switch_to.frame() 切進 iframe。最後的產物是 page_source，也就是渲染後的 DOM，接回 XPath 就能取得動態資料。

不過你應該也注意到，範例裡到處都是 sleep()，而且秒數看起來像猜的。等一下兩秒真的夠嗎？下一步就來比較三種等待方式，教你什麼時候該用哪一種。
