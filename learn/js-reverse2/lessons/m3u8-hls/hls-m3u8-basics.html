HLS 與 M3U8：影片為什麼變成一片片 TS

Step 1/4 · M3U8/HLS 串流下載

學習目標

能說明 HLS 為什麼把影片切成 TS 分片，並從一份 M3U8 播放清單讀出每個欄位代表什麼。

前言：那支影片的 mp4 到底在哪裡

你接到一個需求，要把某個影音網站的影片抓下來。照直覺打開 DevTools 的 Network 面板，重新整理頁面，準備找那個熟悉的 .mp4 檔。結果從頭翻到尾，一個 mp4 也沒看到，卻冒出一長串 .ts 結尾的請求，還有個名字裡帶 m3u8 的檔案。

這不是你找錯地方，而是這類網站根本沒打算給你一個完整的影片檔。它們用的是 HLS 串流技術，把影片切成一片片，讓播放器邊下邊播。想抓這種影片，就得先看懂它被切成了什麼、清單長什麼樣。這一節要建立的，就是這張地圖。有了它，後面「去哪找清單、怎麼批次下載」才接得下去。

HLS 是什麼：把一整支影片切成邊走邊吃的便當

HLS 全名 HTTP Live Streaming，是 Apple 為了改善串流效率開發的技術。它的核心做法，是把一支完整的影片切成好幾段，每一段叫一個 TS 片段（TS segment），通常只有幾秒鐘。然後它另外準備一份 M3U8 列表檔案，把這些片段依照播放順序一個一個列出來。

播放器拿到清單之後，就照著清單的順序，把一段段 TS 片段抓下來、接著播。因為每一段都不大，播放器可以邊下載邊播放，不用等整支影片下載完才開始；網路順的時候，它甚至能一次多抓幾段來追上進度。你可以把它想成吃便當：與其等整個電鍋的飯都煮好才開動，不如一碗一碗上，吃完一碗再添一碗，中間完全不用空等。

相較之下，傳統的 MP4 是一個完整檔案，播放器要先下載夠多內容、甚至整檔下載完，才能開始播。這就是為什麼影音網站大多改用 HLS，而不是直接丟一個 MP4 給你。

M3U 與 M3U8：清單本身不是影片

要抓 HLS 的資源，得先搞懂 M3U8。它其實是從更早的 M3U 格式擴充而來，所以得從 M3U 說起。

M3U 這種檔案不是音訊或視訊檔，而是一份媒體播放清單，內容是純文字。播放軟體拿到它之後，並不會「播放這個檔案」，而是照著裡面的紀錄去找到真正的媒體網路位址，再去播那些被指向的檔案。換句話說，M3U 只是一個索引，記錄了「要去哪裡拿真正要播的東西」。打個比方，它就像餐廳的菜單：你手上拿的是菜單，真正吃進肚子的是菜單上寫的那些菜。

一份最陽春的 M3U，內容就是一行一個媒體檔的路徑，例如：

E:\Users\m3u8\刘德华 - 无间道.mp4
E:\Users\m3u8\那英 - 默.mp3
E:\Users\m3u8\周杰伦 - 不能说的秘密.mp4
E:\Users\m3u8\花粥 - 二十岁的某一天.mp3
E:\Users\m3u8\周深 - 大鱼.mp4

M3U8 則是 M3U 的擴充格式，可以想成「比較高級的 M3U」，所以它也算是 M3U 的一種。字尾那個 8，指的是它採用 UTF-8 編碼，能正確處理非英語字元。

實際的 M3U8 長什麼樣

真正用在 HLS 裡的 M3U8，跟上面那種一行一個檔案的路徑清單很不一樣。它會用一大堆以 # 開頭的標籤行，描述這份清單的規則與每段影片的資訊，而真正要下載的 TS 位址，就穿插在這些標籤之間。下面是其中一個實際例子：

#EXTM3U
#EXT-X-VERSION:3
#EXT-X-TARGETDURATION:6
#EXT-X-PLAYLIST-TYPE:VOD
#EXT-X-MEDIA-SEQUENCE:0
#EXTINF:3.127,
/20230512/RzGw5hDB/1500kb/hls/YZefAiEF.ts
#EXTINF:3.127,
/20230512/RzGw5hDB/1500kb/hls/FsliUCL6.ts
#EXTINF:3.127,
/20230512/RzGw5hDB/1500kb/hls/DD7c47bz.ts
#EXT-X-ENDLIST

這份檔案裡有兩種行，看懂它們的差別，就等於看懂了整份清單：

  • 以 # 開頭的行是標籤，用來描述規則或說明，不是要下載的檔案。例如開頭的 #EXTM3U 只是宣告「這是一份 M3U 檔案」。
  • 不以 # 開頭的行才是真正的 TS 分片位址，也就是我們做爬蟲真正想拿到的目標。上面那三行 .ts 結尾的路徑，就是三小段影片，每一段都能單獨播放。

標籤行分別在說什麼

標籤行雖然不用下載，卻決定了你怎麼理解這份清單。以下把例子裡出現的幾個標籤拆開來看：

標籤意思
#EXTM3U宣告這是一份 M3U 檔案，通常是第一行。
#EXT-X-VERSION:3這份清單遵循的 HLS 協定版本。
#EXT-X-TARGETDURATION:6每個分片的目標秒數上限，這裡是 6 秒。
#EXT-X-PLAYLIST-TYPE:VOD播放清單類型。VOD 是隨選影片，整份清單固定不變；另一種常見的是直播類型，清單會持續長出新的分片。
#EXT-X-MEDIA-SEQUENCE:0這份清單第一個分片的序號。
#EXTINF:3.127,緊接在它下一行的那個 TS 分片的長度，單位是秒。所以每個 TS 前面都配一個 #EXTINF。
#EXT-X-ENDLIST宣告清單到此結束，不會再有新分片。有這一行通常代表這是完整影片，而不是直播。

特別注意 #EXTINF 和 TS 位址的搭配關係：#EXTINF 是替「下一行」的 TS 描述長度，不是替它自己。所以解析時看到一個 #EXTINF，就知道下一行會是一個分片位址。

小結

HLS 把影片切成幾秒一段的 TS 分片，再用一份 M3U8 清單列出播放順序，讓播放器邊下邊播。M3U8 由 M3U 擴充而來，本身是純文字索引、不是影片。清單裡以 # 開頭的是標籤，不以 # 開頭的才是真正的 TS 分片位址。這條規則就是後面解析清單的依據。

現在你已經知道 TS 位址藏在清單裡，也知道只有非 # 開頭的行才是目標。但新的問題來了：這份 m3u8 檔案本人要去哪裡找？拿到之後又該怎麼把那些位址一行行抽出來？下一節就從封包定位開始，把清單變成一串可直接下載的 URL。
