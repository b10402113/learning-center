抓圖片與二進位：content 與 urlretrieve

Step 5/5 · requests 入門與動態資料定位

學習目標

用 response.content 搭配 'wb' 存下圖片／影片等二進位資料，或用 urlretrieve 一行下載，並依回應型別選對取值方法。

前言：文字以外的世界

上一節你把 HTML 和 JSON 都抓下來了，那兩種都是「文字」資料。但網頁上還有一大類東西不是文字：圖片、影片、音訊、壓縮檔、安裝包。這些資料的內容是位元組流，沒有「字元編碼」這回事，所以你不能再用 response.text 去取它們，取回來的會是一團被硬翻成字元的垃圾。

這一節是最後一塊拼圖，也正好把整個節點收尾。你會學到兩種存二進位的方法，以及一個能套用到所有回應的原則：看到什麼型別的資料，就用對應的方法取。之後你抓圖片或批次下載素材時，就不會再卡在「檔案存下來打開是壞的」。

前置條件：你已完成 step 1–4，熟悉 GET 請求與存檔流程。本節程式可直接執行。

為什麼二進位要換一套寫法

關鍵在一行：文字回應要被「解碼」成字串，二進位回應則是「原封不動的位元組」。response.text 做的是前者，它會拿一套編碼去解讀位元組；如果位元組其實是一張 JPEG，硬解碼只會得到亂七八糟的字元，而且寫回檔案也不再是原本那張圖。

所以要改用 response.content。它回傳的是位元組（bytes），保留原始內容；存檔時也要用二進位的模式 'wb'，而不是文字模式 'w'。這兩個 b 很重要，少一個就會壞。

方式一：response.content + 二進位寫檔

第一種做法是走完整的四步流程，只是在取值與存檔時換成二進位版本：

 #方式1：
import requests
url = 'https://img0.baidu.com/it/u=540025525,3089532369&fm=253&fmt=auto&app=138&f=JPEG?w=889&h=500'
response = requests.get(url=url)
#content获取二进制形式的响应数据
img_data = response.content
with open('1.jpg','wb') as fp:
    fp.write(img_data)

逐行看：requests.get(url=url) 照舊送出請求；img_data = response.content 是關鍵，它把回應以位元組形式取出；最後 with open('1.jpg','wb') as fp 用二進位寫入模式開檔，把位元組寫進去。跑完之後，1.jpg 應該是一張可以正常打開的圖片。這裡的 'wb' 對應的就是前面的「b」：w 是寫入，b 是二進位。

方式二：urlretrieve 一行下載

如果你只是想把某個網址的檔案直接存到本機，不想自己管請求與寫檔，Python 標準函式庫提供了更短的寫法：

#方式2
from urllib.request import urlretrieve
#图片地址
img_url = 'https://img0.baidu.com/it/u=4271728134,3217174685&fm=253&fmt=auto&app=138&f=JPEG?w=400&h=500'
#参数1：图片地址
#参数2：图片存储路径
#urlretrieve可以根据图片地址将图片数据请求到直接存储到参数2表示的图片存储路径中
urlretrieve(img_url,'1.jpg')

urlretrieve 是 urllib.request 裡的函式。參數一是圖片地址，參數二是存檔路徑，它會自己把資料請求回來並直接寫入檔案，等於把發請求與存檔兩步包成一步。程式更短，但也更少控制，你沒辦法像 requests 那樣自由地設定標頭。

該選哪一種：看你要不要偽裝

兩種都能存圖，差別在控制程度。判斷原則很簡單：如果你需要做 UA 偽裝（或其他請求頭設定），用方式一；如果不需要，用方式二。

方式一：content + wb方式二：urlretrieve
寫法長度較長，自己發請求與寫檔一行完成
能否設定標頭可以，交給 headers不行，無法客製請求頭
適用時機需要 UA 偽裝或精細控制單純下載、不需要偽裝

原因很直白：urlretrieve 沒有地方讓你塞 headers，所以遇到會檢查身分的圖床，它可能直接被擋。這種時候就回到方式一，用 requests.get(url, headers=...) 帶上偽裝，再用 .content 存檔。

把整個節點收攏：回應型別決定取值方法

這個節點一路走下來，其實都在同一個判斷上打轉：第三步「取得響應資料」要依回應的型別選方法。把三種型別並排，你就有了一張完整的對照表：

回應型別（content-type）取值方法拿到什麼
HTML 網頁response.text字串形式的網頁原始碼
JSON（字典、列表）response.json()反序列化後的 Python 字典或列表
其他（圖片、影片、音訊、安裝包等）response.content位元組，寫檔時用 'wb'

口訣是：看到網頁用 .text、看到資料用 .json()、看到檔案用 .content。這張表會跟著你之後所有的爬取工作，是這個節點最值得記住的一件事。

做完會看到什麼

成功的標準很具體：跑完程式後，專案目錄裡出現 1.jpg，用看圖軟體打開是一張正常的圖片，不是損壞檔。如果打開是壞的，第一個要檢查的就是你有沒有用 'wb'，把二進位資料寫進文字模式，是這裡最常見的錯。

小結

圖片、影片、壓縮檔等是二進位資料，要用 response.content 取位元組、並用 'wb' 模式寫檔；想一行下載可用 urlretrieve(img_url, 路徑)，但它無法設定請求頭，需要 UA 偽裝時要改回 requests 加 headers 的方式。.text、.json()、.content 分別對應 HTML、JSON、二進位三種回應型別。

走到這裡，你已經能用 requests 抓下 HTML、JSON 與圖片，也知道了亂碼、身分、參數位置與動態資料這四個新手最常卡住的點。這個節點教你的是「抓得到」；接下來要讓抓回來的 HTML 變成能用的欄位，就輪到 XPath 解析上場了。
