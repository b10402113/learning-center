await 放哪、哪些模組會拖垮非同步

Step 3/4 · asyncio 與 aiohttp 非同步爬蟲

學習目標

判斷 await 該加在哪一行、asyncio.wait 的角色是什麼，並認出哪些同步模組會讓整個非同步效果失效。

前言：三個任務，卻還是排隊做完

上一節你已經能用 ensure_future 和事件循環跑起一個協程。現在把任務從一個變成三個：三個網址，各自等 2 秒。照理說，如果它們真的在「同時等」，總耗時應該接近 2 秒；但跑出來的結果卻是 6 秒，跟一個一個排隊做完沒什麼兩樣。

程式看起來明明照著上一節的骨架寫，問題出在哪？這一節要做的決定就是這個：哪些地方必須加 await、哪些模組一旦放進來就會把非同步效果整個吃掉。這兩件事其實是同一個問題的兩面：只要搞懂「誰在等」和「交不交出控制權」，答案就出來了。

先看沒生效的那一版

這是把任務變成三個、但總耗時仍然是 6 秒的寫法：

import asyncio
import time
start = time.time()
urls = [
    'www.1.com','www.2.com','www.3.com'
]
async def get_request(url):
    print('正在请求：',url)
    time.sleep(2)
    print('请求结束:',url)
#有了三个任务对象和一个事件循环对象
if __name__ == '__main__':
    tasks = []
    for url in urls:
        c = get_request(url)
        task = asyncio.ensure_future(c)
        tasks.append(task)
    #将三个任务对象，添加到一个事件循环对象中
    loop = asyncio.get_event_loop()
    loop.run_until_complete(asyncio.wait(tasks))

    print('总耗时:',time.time()-start)

這段程式丟出兩個問題：為什麼沒有達到非同步效果？以及 wait() 到底是什麼意思？先回答第二個，因為它牽涉到整個機制的核心。

wait() 的角色：給任務「可被掛起」的權限

loop.run_until_complete() 原本一次只收一個任務。當你有很多任務時，就要用 asyncio.wait(tasks) 把整個任務列表交給它。它的作用是：給列表中的每一個任務物件一個「可被掛起」的權限。

所謂掛起，就是讓當前正在執行的任務交出 CPU 的使用權。一旦某個任務因為阻塞而被掛起，CPU 就可以去執行其他任務，整體效率才會提升。換句話說，wait() 負責的是「讓這些任務有停下來讓位的資格」，但光有資格還不夠。

await：主動標出每一個阻塞點

問題出在 await。上面那版用的 time.sleep(2) 是完全同步的等待，它會直接讓整條執行緒睡著 2 秒，中間不會把控制權交給任何人。其他任務只能等它睡醒，所以總時間就是 2 秒加 2 秒加 2 秒。

await 解決的正是這件事。它的用途是「掛起發生阻塞操作的那個任務」：凡是會阻塞的操作前面，都必須加上 await。它等於是你主動告訴程式：「這裡要等了，把控制權交出去。」上一節為什麼會提到「不可以出現不支援非同步模組的程式碼」，原因就在這裡：沒有 await 可加的同步等待，會把整條執行緒卡死。

三組要選對的寫法

情境會拖垮非同步的寫法正確的非同步寫法
等待time.sleep(2)await asyncio.sleep(2)
發送網路請求requests.get(url)aiohttp（下一步會用）
阻塞操作前什麼都不加，直接呼叫呼叫前面加 await
多任務放進循環run_until_complete(task) 只收一個run_until_complete(asyncio.wait(tasks))

判別問句：動手前先問自己三件事

遇到一段非同步程式碼，你可以用三個問句快速判斷它會不會失效：

  1. 這一行會不會停下來等？如果會（網路請求、睡眠、讀寫），它前面就必須有 await。
  2. 這個模組支援非同步嗎？不支援的模組（例如 time.sleep、requests）不能出現在 async def 裡。
  3. 這些任務是怎麼交給事件循環的？多個任務要用 asyncio.wait(tasks) 一起放進去，否則它們根本沒有被掛起的機會。

反例：只要混進一個同步呼叫，全部陪等

最容易被忽略的是第二個問句。你可能每一行都乖乖加了 await，但只要在 async def 裡偷偷放一個 requests.get()，整個非同步效果就會中斷。原因是 requests 在等網路時是把執行緒整個睡著，而不是把控制權交出去；事件循環裡的其他任務全部得等它做完才能動。看起來只是一個小地方，實際上等於把整個協程的優勢抹掉。

正確的一版

把 time.sleep 換成 await asyncio.sleep，並用 asyncio.wait(tasks) 承接任務列表，同一份程式就會真正並行等待：

import asyncio
import time

start = time.time()

async def get_request(url):
    #特殊函数内部不可以出现不支持异步模块的代码，否则会中断整个异步效果
    print('正在请求的网址是:',url)
    #没有加await关键字之前：每一个任务中的阻塞操作并没有被执行
    #await关键字：必须要加在每一个任务的阻塞操作前，作用就是强调执行任务中的阻塞操作
    #await是用来手动控制任务的挂起操作。
    await asyncio.sleep(2)
    print('请求网址结束！')
    return 123

urls = [
    'www.1.com','www.2.com','www.3.com'
]

tasks = [] #定义一个任务列表
for url in urls: #循环3次
    #创建了3个协程
    c = get_request(url)
    #创建3个任务对象
    task = asyncio.ensure_future(c)
    tasks.append(task) #将创建好的3个任务对象依次存放到了tasks这个任务列表中

loop = asyncio.get_event_loop()
#将任务列表tasks添加到loop容器中
#wait()函数：用于接收一个任务列表，wait函数就可以给任务列表中每一个任务对象赋予一个可被挂起的权限
#一个任务被挂起，就表示当前任务对象交出了cpu的使用权
loop.run_until_complete(asyncio.wait(tasks))
print('总耗时:',time.time()-start)

換成這一版之後，總耗時會落在 2 秒左右，而不是 6 秒。差別不在任務的數量，而在每個任務遇到等待時，是否真的把控制權交了出去。

小結

判斷非同步有沒有生效，就看兩件事：await 有沒有加在每一個阻塞操作前面，以及 async def 裡有沒有混進不支援非同步的模組。asyncio.wait(tasks) 負責給任務「可被掛起」的權限，await 則負責在阻塞點實際把控制權交出。記住三個問句：會不會等？模組支不支援非同步？任務怎麼交給事件循環？

到這裡，你已經知道協程該怎麼寫、陷阱在哪裡，但範例裡的網路請求還是空的。下一節要把等待的對象換成真正的網頁：用支援非同步的 aiohttp 取代 requests，組出一支能同時抓多個頁面、並把結果交給解析函式的完整爬蟲。
