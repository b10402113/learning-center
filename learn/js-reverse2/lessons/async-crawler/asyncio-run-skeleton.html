asyncio 起手式：特殊函數、任務與事件循環

Step 2/4 · asyncio 與 aiohttp 非同步爬蟲

學習目標

用 async def、asyncio.ensure_future、asyncio.get_event_loop 與 run_until_complete 把一個協程跑起來，並用回調函式取出它的回傳值。

前言：知道為什麼快之後，得先讓它跑起來

上一節說明了協程為什麼能快：它把任務切換的主導權從作業系統拿回程式自己手上。但光知道這個道理，你還是寫不出一支能動的程式。這一節要把 asyncio 的四個零件組起來，先讓一個協程從頭跑到尾，看它印出東西。

前置條件：本機已安裝 Python 3.6 以上的版本（asyncio 從 3.6 起提供）。這一節只用到標準庫，不需要額外安裝任何套件。做完之後，你手上會有一段能跑的骨架，後面的網路請求只是把骨架裡的「假等待」換成真的請求。

第一步：用 async def 定義「特殊函數」

在函式定義前加上 async 關鍵字，這個函式就變成一個「特殊函數」。它的特殊之處有兩點：第一，呼叫它之後，函式內部的程式碼（函式體）不會立刻執行；第二，呼叫它之後，它會回傳一個「協程物件」。先用最小的例子看這句話的意思。

第二步到第五步：把四個零件接起來

下面這段程式把四個零件依序接上，註解標了每一段在做什麼：

import asyncio
import time
#特殊的函数
async def get_request(url):
    print('正在请求的网址是:',url)
    time.sleep(2)
    print('请求网址结束！')
    return 123
#创建了一个协程对象
c = get_request('www.1.com')
#创建任务对象
task = asyncio.ensure_future(c)
#创建事件循环对象
loop = asyncio.get_event_loop()
#将任务对象装载在loop对象中且启动事件循环对象
loop.run_until_complete(task)

逐段拆解。async def get_request(url) 定義了特殊函數；c = get_request('www.1.com') 這一行並不是「執行」它，而是拿到一個協程物件，所以此刻函式裡的 print 都還不會印出來。

接著 task = asyncio.ensure_future(c) 把協程物件包成一個「任務物件」。任務物件可以想成一個升級版的協程，它之後能綁定回調函式，這是它比協程物件多出來的能力。再來 loop = asyncio.get_event_loop() 取得一個事件循環物件，你可以把它當成一個容器；最後 loop.run_until_complete(task) 把任務放進去並啟動，任務裡的操作這時才真的被執行。

用回調函式取回傳值

剛才的例子裡，特殊函數最後有一行 return 123。問題是，任務是在事件循環裡被執行的，你的主程式怎麼知道它最後回傳了什麼？答案就是任務物件的回調函式：當任務執行完畢，事件循環會立刻呼叫你綁上去的那個回調。

import asyncio
import time

async def get_request(url):
    print('正在请求的网址是:',url)
    time.sleep(2)
    print('请求网址结束！')
    return 123

#如何获取特殊函数内部的返回值（任务对象回调函数来实现的）
c = get_request('www.1.com')
task = asyncio.ensure_future(c)
#给任务对象绑定一个回调函数（回头调用的函数）,该函数一定是在任务对象被执行完毕后再调用的函数
def task_callback(t): #必须有且仅有一个参数
    #函数的参数t就是回调函数的调用者task任务对象本身
    ret = t.result() #任务对象调用result()就可以返回特殊函数的内部return后的结果值
    print('我是回调函数，我被执行了，t.result()返回的结果是:',ret)
#给task任务对象绑定了一个叫做task_callback的回调函数
task.add_done_callback(task_callback)
loop = asyncio.get_event_loop()
loop.run_until_complete(task)

這裡有兩個硬規定。第一，回調函式必須有且僅有一個參數，這個參數 t 就是被執行的任務物件本身。第二，任務物件呼叫 t.result() 就能拿到特殊函數 return 的值，也就是這裡的 123。把 task.add_done_callback(task_callback) 綁上去之後，任務一完成，事件循環就會回頭呼叫它。

四個零件對照表

零件寫法它的角色
特殊函數async def get_request(url)呼叫時不執行函式體，回傳協程物件
協程物件c = get_request(url)一組尚未執行的操作
任務物件task = asyncio.ensure_future(c)升級版協程，可綁定回調
事件循環loop = asyncio.get_event_loop()裝載任務並執行它們的容器

小結

一支最小協程程式的骨架是：async def 定義特殊函數，呼叫它得到協程物件，用 ensure_future 包成任務，放進 get_event_loop 拿到的事件循環，最後 run_until_complete(task) 啟動。要取回傳值，就用 add_done_callback 綁一個「只有一個參數」的回調，在裡面呼叫 t.result()。

這段骨架還有一個地方沒交代：程式裡用的是 time.sleep(2)，它其實是同步的寫法，會讓整條執行緒停住，根本不是真正的非同步。先知道零件怎麼接就好，下一節會專門處理這個問題，告訴你 await 該放在哪，以及哪些模組一放進來就會拖垮整個非同步效果。
