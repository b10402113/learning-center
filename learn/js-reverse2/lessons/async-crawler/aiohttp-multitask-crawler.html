aiohttp 多任務非同步爬蟲

Step 4/4 · asyncio 與 aiohttp 非同步爬蟲

學習目標

用 aiohttp.ClientSession 寫出多任務非同步爬蟲，並用任務回調把抓回來的頁面交給解析函式。

前言：把骨架上空的請求，換成真的網頁

前三節都在為這一刻鋪路。你已經知道協程為什麼快、知道 asyncio 的四個零件怎麼接、也知道 async def 裡不能出現同步模組。但到目前為止，範例裡會阻塞的那一行都還是空的，還沒有真的去抓任何網頁。

這一節要把它補上：用支援非同步的 aiohttp 取代 requests，寫出一支能同時抓多個頁面的爬蟲，並在每個頁面抓回來之後，用回調把它交給 lxml 解析。做完這一節，你就有一套能重複套用的多任務非同步爬蟲範本。

前置條件：本機已安裝 Python，且先執行 pip install aiohttp（aiohttp 是第三方模組，不會隨 Python 附帶）。為了讓這支爬蟲有東西可抓，範例會先在本機跑一個小型的 Flask 伺服器當靶場。

第一步：為什麼要換掉 requests

上一節的反例已經點出原因：requests 是同步模組，它在等網路時不會交出控制權，放進 async def 會中斷整個非同步效果。所以這裡不能沿用 requests，要換成功能相似、但支援非同步的 aiohttp。它的用法和 requests 幾乎一樣，只有幾個地方要改成 async 與 await。

第二步：用 ClientSession 發出非同步請求

這是 aiohttp 的核心寫法。注意每個 with 前面都加了 async，而每個阻塞操作前面都加了 await：

async def get_request(url):
    #requests是不支持异步的模块
    # response = await requests.get(url=url)
    # page_text = response.text
    #创建请求对象（sess）
    async with aiohttp.ClientSession() as sess:
        #基于请求对象发起请求
        #此处的get是发起get请求，常用参数：url,headers,params,proxy
        #post方法发起post请求，常用参数：url,headers,data,proxy
        #发现处理代理的参数和requests不一样（注意），此处处理代理使用proxy='http://ip:port'
        async with await sess.get(url=url) as response:
            page_text = await response.text()
            #text():获取字符串形式的响应数据
            #read()：获取二进制形式的响应数据
            return page_text

逐段看。async with aiohttp.ClientSession() as sess 建立一個請求物件（session），async with 的好處是離開區塊時會自動把連線關好。async with await sess.get(url=url) as response 才是真正送出請求的那一行；await response.text() 則把回應內容以字串取出來。

參數的部分和 requests 對得上：GET 常用 url、headers、params、proxy；POST 用 url、headers、data、proxy。唯一要特別記住的是代理：requests 的寫法不能直接搬過來，aiohttp 要用 proxy='http://ip:port'。取值的部分，text() 拿字串、read() 拿二進位，和 requests 的直覺一致。

第三步：架一個本機靶場

為了看到「同時抓」的效果，先寫一個小型伺服器。它有三個路徑 /bobo、/jay、/tom，每個都會先睡 2 秒再回傳同一個頁面。因為是同步的 Flask，每個請求各自要等 2 秒，所以它是拿來測試非同步爬蟲的現成對照組：如果爬蟲真的並行，三個加起來應該接近 2 秒；如果沒有，就會是 6 秒。

#!/usr/bin/env python 
# -*- coding:utf-8 -*-
from flask import Flask,render_template
from time import sleep
#安装flask模块

#1.实例化app对象
app = Flask(__name__)

@app.route('/main')
def main():
    return 'i am main'
@app.route('/bobo')
def index1():
    sleep(2)
    return render_template('test.html')
@app.route('/jay')
def index2():
    sleep(2)
    return render_template('test.html')
@app.route('/tom')
def index3():
    sleep(2)
    return render_template('test.html')

if __name__ == "__main__":
    app.run()

把這段存成 Server.py。另外在專案底下建立一個 templates 資料夾，把 test.html 放進去（內容隨意，裡面放一個 id="feng" 的連結即可，解析時要用到）。啟動後伺服器預設跑在 http://127.0.0.1:5000。

第四步：多任務爬蟲與回調解析

現在把前面所有零件拼起來。爬蟲建立多個任務、綁上解析用的回調，再一起交給事件循環：

import asyncio
import time
import aiohttp
# import requests

from lxml import etree
start = time.time()

urls = [
    'http://127.0.0.1:5000/bobo',
    'http://127.0.0.1:5000/jay',
    'http://127.0.0.1:5000/tom'
]

#发起网络请求，爬取网页完整数据
async def get_request(url):
    #不可以出现不支持异步模块的代码
    #requests是不支持异步，更换一个支持异步的网络请求的模块（aiohttp）
    # response = requests.get(url=url)
    # page_text = response.text
    # return page_text

    #aiohttp进行网络请求的代码操作
    #1.创建一个请求对象:sess
    async with aiohttp.ClientSession() as sess:
        #2.使用请求对象发起请求
        #aiohttp发起请求的代码操作和requests几乎一致，唯一不一致的地方是，使用代理的参数proxy="http://ip:port"
        async with await sess.get(url=url) as response:
            #text()获取字符串形式的响应数据
            #read()获取二进制形式的响应数据
            #json()和以前的作用一致
            page_text = await response.text()
            return page_text
tasks = []
def parse(t): #数据解析
    page_text = t.result()
    tree = etree.HTML(page_text)
    text = tree.xpath('//a[@id="feng"]/text()')[0]
    print(text)
for url in urls:
    c = get_request(url)
    task = asyncio.ensure_future(c)
    #给任务对象绑定回调函数用于数据解析
    task.add_done_callback(parse)
    tasks.append(task)

loop = asyncio.get_event_loop()
loop.run_until_complete(asyncio.wait(tasks))

print('总耗时:',time.time()-start)

這支程式把前面幾節的零件全部用上了。迴圈裡對每個 URL 做三件事：呼叫 get_request(url) 取得協程、用 asyncio.ensure_future 包成任務、再用 task.add_done_callback(parse) 把解析函式綁上去。三個任務累積到 tasks 之後，用 asyncio.wait(tasks) 一起交給事件循環。

解析函式 parse 的寫法就是上一節回調的應用：它唯一的參數 t 是任務物件，t.result() 取得 get_request 回傳的 HTML 字串。接著用 etree.HTML() 把字串建成可查詢的樹，再用 XPath //a[@id="feng"]/text() 取出連結文字並印出。

做出來的結果

先啟動 Server.py，再執行爬蟲程式。你會在畫面上看到三筆 a 標籤的文字被印出來。最關鍵的是最後一行：總耗時。三個請求每個都要等 2 秒，但因為它們在事件循環裡並行等待，總耗時會接近 2 秒，而不是 6 秒。

如果總耗時仍然是 6 秒，先回頭檢查兩件事：get_request 裡是不是還有 requests 或 time.sleep 沒換掉，以及阻塞操作前面是不是都加了 await。這兩題正是上一節的三個問句。

小結

多任務非同步爬蟲的完整套路是：用 async with aiohttp.ClientSession() 建立請求物件，用 async with await sess.get(...) 送請求、await response.text() 取內容；把每個 URL 包成任務、綁上解析回調，累積成 tasks 後用 asyncio.wait(tasks) 交給事件循環。抓回來的 HTML 在回調裡用 t.result() 取出，交給 lxml 解析。

走到這裡，這個節點的四塊拼圖都齊了：協程的動機、asyncio 的零件、await 與同步模組的取捨，以及用 aiohttp 把整件事套在真實爬蟲上。你現在寫得出能在單執行緒下同時抓多個頁面的爬蟲；接下來的動態渲染與框架化爬取，都會站在這套非同步思維上往外長。
