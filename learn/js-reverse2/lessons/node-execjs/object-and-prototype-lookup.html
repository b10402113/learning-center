物件、原型與原型鏈查找

Step 2/5 · Node 執行、execjs 與 JS 前置知識

學習目標

從暫停頁面上的一個屬性反問「它掛在哪」，沿原型鏈判斷成員是定義在物件本身，還是某一層的原型物件上。

前言：這個屬性到底是誰給的？

上一節你學會用 execjs 把一整段 JS 丟進 Python 執行，先求有答案再說。但要真正看懂一段暫停的頁面，光會跑還不夠。你在 DevTools 裡暫停下來，滑鼠移到某一行，看到 navigator.userAgent，腦中應該冒出一個問題：這個 userAgent 是寫在 navigator 這個物件身上，還是它從別的地方「繼承」來的？

這個問題不是學術問題。後面做補環境、換 hook 的時候，你要嘛得去改這個屬性、要嘛得去假造它，而你動手的位置對不對，完全取決於你知不知道它掛在哪一層。這一節就是把 JS 的「物件、原型與原型鏈」這條線講清楚，讓你在暫停頁面上能自己回答「這個成員是誰提供的」。

建立物件有兩條路

JS 裡要生出一個物件，最常見的就是兩種寫法。一種是字面量，用大括號直接寫出鍵值對；另一種是先定義一個建構子，再用 new 去呼叫它：

let a = {'name':'bobo'}; //方法1

function B(){this.name="bobo"};
let b = new B(); //方法2

console.log(a);
console.log(b);

兩種寫法印出來的東西長得幾乎一樣，都是一個帶 name 的物件。但差別藏在表面之下：字面量方式建立的物件就是一個單純的鍵值集合；而透過 new B() 建立的物件，會跟 B 這個建構子產生一條隱形的連結。後面所有原型鏈的行為，都是從這條連結長出來的。

建構子、實例與原型對象

當你用 new 呼叫一個函式，這個函式就扮演了「建構子」的角色。它身上寫的 this.xxx，會變成每個新物件自己的屬性。以一個最典型的使用者建構子為例：

function User(name,pwd){
    this.userName = name;
    this.pwd = pwd;
    this.regist = function(){
        console.log(this.name+"在注册")
    }
}

用 new User(...) 生出來的東西叫「實例對象」。你生出幾個，它們就各自擁有一份自己的 userName、pwd：

let u1 = new User('jay','123');
let u2 = new User('tom','456');

問題來了：如果每個實例都各自複製一份方法，記憶體就浪費了。所以 JS 讓你可以把「所有實例共用」的屬性和方法，掛到建構子的「原型對象」上。你可以把原型對象想成 Python 裡類別的類屬性和類方法，定義一次，全部實例共用：

//类似于类属性
User.prototype.address = "BJ";
User.prototype.gender = "male";
//类似于类方法
User.prototype.login = function login(username, password){
    console.log(`${username}在登录`);
}

//实例对象共享原型对象存储的内容
u1.login('jay','123');
u2.login('tom','456');
console.log(u1.address,u2.address,u1.gender,u2.gender);

這裡的關鍵字是 prototype。建構子 User 身上的 User.prototype，就是它所屬的原型對象。而每一個實例，都有一條路可以取回這個原型對象，兩條路的終點是同一個地方：

User.prototype;   
u1.__proto__;
User.prototype === u1.__proto__ //true

最後那行 true 是這整節最重要的一句話：u1.__proto__ 和 User.prototype 指向的是同一個物件。所以「實例拿得到方法」，其實是因為實例身上有一條 __proto__ 連到原型對象，而方法就放在那裡。

原型鏈：找不到就往上爬

那原型對象自己呢？它也是一個物件，所以它同樣有一條 __proto__ 指向自己的原型。這種一層扣一層的結構，就是原型鏈。查詢一個成員時的規則是固定的：先看物件自己身上有沒有，沒有就往它的原型對象找，還沒有再往原型對象的原型找，一路往上，直到找到或走到鏈的末端為止。

u1.__proto__.__proto__

把這件事放到瀏覽器裡看就很有感。DevTools 裡的 navigator 物件，你按下它的原型鏈，會看到它的原型是 Navigator，也就是 Navigator.prototype：

navigator.__proto__ === Navigator
navigator.__proto__ === Navigator.prototype

這就是為什麼你搜尋 userAgent 的定義時，常常在 Navigator.prototype 那一層才找到它，而不是在 navigator 物件本身。這個判別在逆向時非常實用：如果一個屬性定義在原型對象上，你光改這個實例的屬性可能沒用，得從原型那一層下手。

名詞指的是什麼怎麼拿到
建構子用 new 呼叫的那個函式User
實例對象由建構子生出、擁有自己屬性的物件new User(...)
原型對象存放所有實例共用成員的地方User.prototype 或 u1.__proto__
原型鏈實例→原型→原型……逐一往上查找的路徑u1.__proto__.__proto__

小結

物件有兩種建立方式：字面量與 new 建構子；只有後者會與原型產生連結。實例自己的屬性存在自己身上，共用成員放在建構子的 prototype；u1.__proto__ === User.prototype。查詢成員時由內往外沿原型鏈找，找不到就往上爬，直到鏈的末端。
