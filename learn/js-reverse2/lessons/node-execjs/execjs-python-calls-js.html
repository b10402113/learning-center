用 PyExecJS 讓 Python 呼叫 JS

Step 1/5 · Node 執行、execjs 與 JS 前置知識

學習目標

用 PyExecJS 的 get → compile → eval 三步，把一段 JS 檔放進 Python 執行並取回結果，並知道什麼時候該放棄 execjs、直接用 Python 重寫演算法。

前言：把牆上那坨 JS 變成自己能呼叫的函式

你在 DevTools 裡追了半天，終於在一個簽名參數旁邊停下斷點，找到了產生它的那個函式。問題才剛開始：那是一大段位元運算、移位、加減常數的 JS，密密麻麻像天書。你要的是讓它在你的 Python 爬蟲裡能穩定跑出同樣的結果。

這裡其實只有兩條路。第一條是把它讀懂，用 Python 重寫一遍；第二條是先別管它長什麼樣，把原始 JS 原封不動搬過來執行。這一節要教你第二條路的工具：PyExecJS，讓 Python 能呼叫一段 JS 並拿回結果。它不一定是你最後會選的做法，但當演算法還沒看懂、又需要先跑出答案時，它是最快的兜底手段。

前置條件：本機要同時有 Python 和 Node.js。PyExecJS 只是 Python 這邊的「發號施令者」，真正執行 JS 的是背後的 Node，所以 Node 沒裝好，這個模組根本不會生效。

安裝：先用套件把橋搭起來

PyExecJS 是第三方模組，不會跟 Python 一起附帶，得先裝。官方來源在對岸，連線慢的時候可以改走清華大學的鏡像：

pip3 install PyExecJS -i https://pypi.tuna.tsinghua.edu.cn/simple

這一行裝的是「Python 呼叫 JS」的介面，執行時它會在底層啟動一個 Node 行程，把 JS 丟過去跑，再把結果傳回來。

四步流程：導包、取環境、編譯、執行

整段流程只有四步，而且順序固定。先看完整的範例，再逐行拆：

#1.导包
import execjs
#2.创建node对象
node = execjs.get()
#3.编译js文件返回上下文ctx对象(将js文件中的代码读取出来，被compile进行编译)
fp = open('test.js','r',encoding='utf-8')
ctx = node.compile(fp.read())
#4.使用上下文对象ctx调用eval函数执行js文件中的指定函数即可
result = ctx.eval('getPwd("123456")')
print(result)

第一步 import execjs 沒什麼好說，就是把套件載進來。第二步 node = execjs.get() 拿到一個執行環境物件，你可以把它當成「連到背後 Node 執行器的把手」。第三步用 open 把整份 JS 檔讀成字串，交給 node.compile() 編譯，回傳一個上下文物件 ctx；這個 ctx 就是接下來呼叫函式的窗口。第四步最關鍵：ctx.eval() 收的是一個「函式呼叫的字串」，不是函式本身，所以你要把函式名和參數一起寫成 'getPwd("123456")' 這樣的字串進去，它才會在 JS 環境裡執行，並把回傳值交回 Python。

搭配的 test.js 只是最單純的示範：

//test.js
function getPwd(pwd){
    return pwd;
}

這裡函式原封不動把參數傳回，所以跑完 print(result) 會印出 123456。重點不是它算了什麼，而是你親眼確認了「Python 把字串丟進 JS、JS 把結果交回 Python」這條路是通的。

一個容易踩的坑：eval 收的是字串

新手最常卡住的地方，是以為 ctx.eval(getPwd("123456")) 這樣直接呼叫就好。不行，eval 要的是字串，寫成 ctx.eval('getPwd("123456")') 才會動。換句話說，它的用法更像「你寫一行 JS 給它跑」，而不是「你把 Python 的函式物件傳給它」。

還有一點：compile 是把整份 JS 檔當成一段程式編譯進去，裡面所有函式都會被載入，所以只要 registerFunc2 之類的名字在檔案裡定義過，你都能用同一個 ctx 去 eval 不同的呼叫字串，不用每換一個函式就重新編譯。

什麼時候用 execjs，什麼時候改走 Python

execjs 的優點是「不用讀懂也能跑」：演算法再噁心，只要那坨 JS 能獨立執行，你就能靠它把結果算出來。但它的代價是每一次呼叫都要經過一次 Python 到 Node 的往返，速度比純 Python 慢，而且一旦那段 JS 依賴瀏覽器才有的東西（例如 window、document），丟進 Node 就會直接報錯。

所以判斷很簡單：如果加密邏輯是標準演算法（例如 MD5），你認得出來，那就直接用 Python 的 hashlib 重寫，又快又乾淨，不必繞路。只有當那坨邏輯是自己客製、看懂成本很高時，才先用 execjs 把它整包跑起來。這個取捨在本節點最後的實戰案例會再完整走一次。

動手驗證：另闢蹊徑的純 Python 版本

同樣的需求，Python 也有現成解法。假設你要算的是字串 123456 的 MD5：

from hashlib import md5
pwd = '123456';
obj = md5()
obj.update(pwd.encode("utf-8"))

bs = obj.hexdigest()
print(bs)

跑出來會是 96e79218965eb72c92a549dd5a330112。等一下你在最後那個案例會看到它在網站的 JS 裡也對應同樣一串值，這就是「純 Python 重寫」和「execjs 兜底」兩條路線並存的意義：先認得演算法，再決定要不要繞路。

小結

execjs 讓 Python 能呼叫 JS，流程固定四步：import execjs、node = execjs.get()、ctx = node.compile(js_source)、ctx.eval('函式呼叫字串')。它的前提是本機裝了 Node；它收的是字串不是函式。能用 Python 重寫的標準演算法就直接用 hashlib，讀不懂或高度客製的邏輯才用 execjs 兜底。

你現在能把一段 JS 塞進 Python 跑了。但真實場景裡，被丟過來的 JS 往往一執行就報錯，因為它預設自己活在瀏覽器裡。下一步我們先補另一塊底子：物件與原型鏈，搞懂暫停頁面上每個屬性和方法究竟是誰提供的；之後再回頭處理「搬到 Node 會壞掉」的問題。
