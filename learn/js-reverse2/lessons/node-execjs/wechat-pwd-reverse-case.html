案例：微信公眾平台密碼加密

Step 5/5 · Node 執行、execjs 與 JS 前置知識

學習目標

從一個 32 位密碼參數出發，用全域搜尋與斷點找回產生它的加密函式，再選擇用 Python 的 hashlib.md5 或 execjs 把演算法重現出來。

前言：把前面學的全部串成一次操作

上一節我們看到瀏覽器 JS 搬進 Node 會在哪裡出事，也知道補環境是怎麼回事。不過幸運的是，不是每個網站的加密都那麼難搞，當你認出對方用的只是標準演算法時，整個流程會乾淨很多。這個案例就是這種情況。

目標是微信公眾平台登入頁的密碼加密。我們要做的，是從一個看不懂的 32 位字串出發，用 DevTools 找到產生它的函式，然後決定要用 execjs 把原碼跑起來、還是直接用 Python 重寫。這一步會把前面學的「定位入口」和「重現演算法」兩件事，實際在一個真站上走一遍。

前置條件：已安裝 PyExecJS 與 Node，並熟悉 DevTools 的基本操作（Network 面板、Sources 面板、設定斷點）。

第一步：先猜它是什麼

開發者工具打開，登入時抓封包，你會看到密碼被加密成一串固定長度的字。這裡的關鍵線索是長度：加密後的資料剛好是 32 位。在密碼學裡，32 個十六進位字元正是 MD5 摘要的標準長度，所以第一個合理的猜測就是：這大概是 MD5 加密。

先猜不是偷懶，而是策略。認出可能的演算法，等於先圈出一個小範圍，接下來的搜尋與斷點才有方向，也才判斷得出最後該用哪種方式重現。

第二步：確認加密值被誰使用

接著看這串值出現在請求的哪個位置。這個案例裡，加密後的資料是被 pwd 這個請求參數使用的。知道參數名很重要，因為下一步的搜尋就是從它下手。

第三步：全域搜尋，定位加密環節

我們想知道「這串值是在哪裡被算出來的」。做法是在 Sources 面板對整個專案做全域搜尋，關鍵字就從參數名出發，搜 pwd 或更精準的 pwd:。這些關鍵字會把你帶到組裝請求參數的那段程式碼附近，加密函式的呼叫通常就在那裡。

這裡用到的，就是逆向裡最基礎的入口搜尋手法。如果搜尋結果太多、太雜，可以再搭配做法二：用請求堆疊反推。從 Network 面板找到發送這個請求的那一筆，從它的發起堆疊跳進 JS，再往回追值是在哪一層被算出來的。

第四步：設斷點，找到真正的加密函式

找到可疑的位置後，在那一行設斷點，然後在頁面上觸發登入動作。執行暫停時，沿著呼叫堆疊往上追，最後會看到加密的內容是由一個 P(t) 的呼叫回傳的。也就是說，P 就是那個產生 32 位字串的函式，逆向的目標就是它。

把 P 背後的實作整段抽出來之後，真正的演算法會現形。抽出來的核心長這樣（中間一大段位元運算的輔助函式先省略）：

function R(t) {
    return q(M(t))
}
…
function getPwd(t, p, n) {
    if (!p) {
        if (!n) {
            return R(t)
        } else {
            return M(t)
        }
    }
    if (!n) {
        return U(p, t)
    } else {
        return B(p, t)
    }
}

// var result = getPwd('111111')
// console.log(result)

// 96e79218965eb72c92a549dd5a330112

看到 R(t) → q(M(t)) 這種「先轉位元組、再跑壓縮函式、最後轉十六進位」的鏈，就幾乎可以確定是 MD5 的標準實作。寫死的註解 96e79218965eb72c92a549dd5a330112 也印證了這一點，那正是 '123456' 的 MD5。

第五步：路線一，用 execjs 把原碼跑起來

既然原始函式已經抽出來了，最省事的方式是直接讓 Python 呼叫它。把抽出來的 JS 存成 main.js，用前面學過的四步流程編譯並執行：

#1.导包
import execjs
#2.创建node对象
node = execjs.get()
#3.编译js文件返回上下文ctx对象(将js文件中的代码读取出来，被compile进行编译)
fp = open('main.js','r',encoding='utf-8')
ctx = node.compile(fp.read())
#4.使用上下文对象ctx调用eval函数执行js文件中的指定函数即可
result = ctx.eval('P("123456")')
print(result)

呼叫字串裡用的就是斷點找到的那個 P（在整理過的版本裡叫 getPwd，差別只在命名）。這個路線的好處是不用讀懂整段位元運算，原碼照搬即可。

第六步：路線二，認出演算法就直接用 Python 重寫

由於我們已經確定它是標準 MD5，其實有更好的做法：直接用 Python 內建的 hashlib，一行都不用搬 JS：

from hashlib import md5
pwd = '123456';
obj = md5()
obj.update(pwd.encode("utf-8"))

bs = obj.hexdigest()
print(bs)

跑出來一樣是 96e79218965eb72c92a549dd5a330112，跟第 1 步抓到的結果一致。這就是這個案例真正的價值：當演算法是標準的、你認得出來，純 Python 重寫又快又乾淨，也不必處理 Node 環境落差的問題。

最後檢查：兩條路線的取捨

回頭比較兩條路線。execjs 適合「演算法太客製、看不懂」的時候，把原碼整包丟進去跑就對了；但只要你能認出演算法，Python 重寫永遠是首選。判斷的第一個線索就是密文長度：32 位十六進位指向 MD5，其他長度則要先確認是 Base64 還是別的摘要，才不會猜錯方向。

做完之後你會得到一個可重複呼叫的加密函式（不管是 Python 版還是 execjs 版），餵進不同密碼都能吐出對應的 32 位結果，可以直接塞進登入請求的 pwd 參數。到這裡，你已經能在一個真站上走完「抓包 → 定位入口 → 斷點 → 重現」的完整迴圈，這正是往後每個簽名案例的固定套路。

小結

微信案例的流程是：抓包看到 32 位密文 → 猜 MD5 → 確認被 pwd 參數使用 → 全域搜尋 pwd: 或請求堆疊定位入口 → 設斷點找到回傳加密值的 P(t) → 抽出演算法。重現有兩條路：用 execjs 呼叫原碼（讀不懂時的兜底），或用 Python hashlib.md5 重寫（認得出標準演算法時的首選）。密文長度是判斷演算法家族的第一個線索。

五個步驟走完，你把 execjs 這座橋、原型與描述符這些閱讀工具、以及 Node 環境的落差全部串起來了。接下來可以進到「補環境與環境檢測」那個節點，把今天的最小假物件擴充成完整的八物件補丁，再往真實案例的簽名與加密前進。
