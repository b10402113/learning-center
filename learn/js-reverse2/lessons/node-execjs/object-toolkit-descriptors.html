Object 工具與屬性描述符

Step 3/5 · Node 執行、execjs 與 JS 前置知識

學習目標

用 Object 的幾個工具辨識型別、判斷自有屬性與原型物件，並用屬性描述符讀懂、甚至改寫一個屬性的可寫、可列舉與 get/set 行為。

前言：同一個取值，為什麼有時會「觸發函式」

上一節我們把原型鏈講清楚了，你已經知道成員可能藏在物件本身，也可能藏在某一層原型上。但這樣還不夠。現場還有一種更麻煩的情況：你只是讀一個屬性 obj.score，背後卻偷偷執行了一段函式；你對它賦值 obj.score = 100，結果卻像石沉大海，一點動靜都沒有。

這不是靈異現象，而是屬性的「描述符」在決定一切。同一個屬性，可能是一個單純的值，也可能是一對 get/set 函式；它可能可寫、可刪，也可能被鎖死。這一節要教你用 Object 的幾個工具把這些設定挖出來，因為之後你要寫的 hook，做的正是「攔截某個屬性的讀寫」，那背後的機制就是這裡講的描述符。

先解決一個老問題：typeof 分不清某些型別

要在 JS 裡判斷「這個東西是什麼型別」，直覺會用 typeof。它對數字、字串、布林、函式都還算準，但有兩個著名的例外：null 和空陣列 []，用 typeof 看都會回傳 object，完全分不出彼此：

console.log('空数组[]',typeof []);
console.log('null空',typeof null);
console.log('undefined',typeof undefined);
console.log('函数function (){}',typeof function (){});

這在逆向現場很致命。你從一個混淆過的變數裡拿到一個東西，想知道它到底是陣列、物件還是 null，單靠 typeof 會誤判。

更精確的做法：Object.prototype.toString.call

比較可靠的方法，是借用 Object 原型上的 toString，用 call 把它套到目標值上。它回傳的是一個帶方括號的標籤，會把真正的型別寫出來：

console.log(Object.prototype.toString.call(1));
console.log(Object.prototype.toString.call([]));
console.log(Object.prototype.toString.call(null));
console.log(Object.prototype.toString.call(function () {}));

這樣一印，數字會給出 [object Number]、陣列給 [object Array]、null 給 [object Null]，一目瞭然。這個「類別標籤」後面補環境時還會再遇到：當腳本用 window.toString() 回傳的標籤來判斷「這是不是真的瀏覽器」時，你要做的就是讓假物件吐出一模一樣的標籤。

這是它自己的屬性，還是繼承來的？

沿著原型鏈找成員時，另一個必備工具是 hasOwnProperty。它回答的是「這個屬性是不是長在物件自己身上」，繼承來的一律回傳 false：

function func(){
    this.name="bobo";
    this.getAge=function(){}
};
f = new func();
f.hasOwnProperty('name'); //true
f.hasOwnProperty('getAge'); //true
f.hasOwnProperty('toString'); //false

name、getAge 是自己 this.xxx 寫上去的，回傳 true；toString 是從原型鏈繼承來的，回傳 false。這正好補上上一節的查找規則，你可以用 hasOwnProperty 判斷「爬到某一層時，這個成員是自己有還是要繼續往上」。

跟原型直接相關的還有三個工具。Object.getPrototypeOf(f) 取得某物件的原型（等價於 f.__proto__），Object.setPrototypeOf 可以事後換掉一個物件的原型，而 Object.create(window) 則是以某個物件為原型「生一個新的」出來。最後這個在補環境時特別常見：你想造一個假物件、讓它的原型指到 window，就會用到它。

核心：屬性描述符

回到開頭那個謎題。每個屬性身上其實都掛著一組設定，叫屬性描述符。描述符本身也是一個物件，它分成兩大類，而且同一個屬性只能屬於其中一類，不能混用：

類型包含的欄位行為
資料描述符value、writable、enumerable、configurable屬性是單純的值，能被讀寫
存取描述符get、set、enumerable、configurable取值/賦值時觸發你提供的函式

兩個類型共用的三個欄位，決定了屬性的自由度：enumerable 決定它會不會出現在 for..in 迴圈裡；writable 決定它能不能被賦值改變；configurable 決定它能不能被刪除、或能不能再修改它的描述符。

要看某個屬性現在的描述符，用 getOwnPropertyDescriptor（單一）或 getOwnPropertyDescriptors（全部）：

Object.getOwnPropertyDescriptor(f,'name');
// { value: 'bobo', writable: true, enumerable: true, configurable: true }
Object.getOwnPropertyDescriptors(f);

用 defineProperty 現裝一個屬性

看得懂描述符之後，反過來你也可以自己安裝。如果一個屬性本來就存在（例如用 age = 10 直接寫出來的），那它預設是資料描述符、三個自由度全開、值可讀寫。但用 Object.defineProperty 現裝一個新屬性，你就可以逐項指定：

Object.defineProperty(User, "height", {
    enumerable:true, //该属性是否可遍历
    configurable:true,//该属性是否可配置:决定该属性是否可以被删除或修改其属性描述符。
    value:160, //属性的值
    writable:false //该属性的值是否可以通过赋值运算符改变
});

這裡把 writable 設成 false，所以之後再對 User.height = 180 賦值，數值不會變。而如果把 enumerable 設成 false，這個屬性就不會被 for..in 列出來，混淆過的程式碼有時候就是靠這招藏東西。

另一種用法是存取描述符，也就是裝一對 get/set。這是最接近「hook」原型的技巧：讀取時執行你的 get，寫入時執行你的 set，你就能在函式裡偷看、記錄、甚至改寫進出的值：

Object.defineProperty(Stu, "score", {
    enumerable:true,
    configurable:true,
    get:function (){// 当获取属性值是调用
        console.log("正在获取值");
        return temp;
    },
    set:function (value){// 当对属性进行赋值操作时调用
        console.log("正在设置值");
        temp = value;
    }
});

注意這裡沒有 value、writable，而是用 get/set 取代，這正是兩類描述符不能混用的意思。資料存在外面的 temp，讀寫都經過這一對函式。等你之後要攔截網站的某個加密參數時，靠的就是這種「把屬性換成 get/set」的手法。

小結

typeof 分不清 null 與陣列，改用 Object.prototype.toString.call 看類別標籤。用 hasOwnProperty 分辨自有與繼承屬性，用 getPrototypeOf／setPrototypeOf／Object.create 操作原型。屬性描述符分資料與存取兩類：前者管 value／writable，後者管 get／set，共用 enumerable 與 configurable；Object.defineProperty 讓你自己安裝，這正是寫 hook 的底層原語。

語言這一側的工具差不多備齊了。再來回到執行環境：你手上那些從瀏覽器抓來的 JS，一丟進 Node 常常馬上報錯，因為它們預設自己活在瀏覽器裡。下一節就來處理這個落差，看看 window 和 global 到底差在哪、又該怎麼把環境補起來。
