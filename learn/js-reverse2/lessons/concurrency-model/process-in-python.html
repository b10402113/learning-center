用 multiprocessing.Process 開子行程：start、join 與資料隔離

Step 3/5 · 行程、執行緒與協程：併發為何存在

學習目標

用 multiprocessing.Process 建立子行程、傳參、start 出非同步效果，用 join 控制結束，並說出資料隔離與 daemon 的後果。

前言：讓程式在你等的時候，去做別的事

前兩步我們把併發、非同步的觀念鋪好了。現在要動手，把「不要傻等」變成真的能跑的程式。最直觀的第一招，就是直接在原本的程式之外，再開一個獨立的行程去跑那段耗時的工作。

做完這一節，你會得到四樣具體的東西：一個能啟動子行程的最小範例、一段把三個耗時請求從同步改成非同步的程式碼、一個讓主行程正確等待子行程的 join 寫法，以及一個會讓你踩坑的現象：子行程改了變數，主行程卻看不到。動手前只需要具備一件事：知道「一個跑起來的 .py 檔就是一個行程」，這是上一節建立的心智模型。

第一步：建立並啟動一個子行程

Python 用 multiprocessing 這個套件來管理行程，其中 Process 模組負責建立行程。你正在跑的那個檔案代表「主行程」，在主行程裡再用 Process 開一個，就是「子行程」。

建立子行程的動作可以拆成三步：先匯入 Process；用 Process(target=某個函式) 建立一個子行程物件，把要它做的任務用 target 註冊進去；最後呼叫 start() 把它啟動。下面的最小範例就是這三步：

from multiprocessing import Process
def func():
    print('我是绑定给子进程的一组任务！')

if __name__ == '__main__':
    print('主进程开始执行！')
    #创建一个进程p，给该进程绑定一组任务
    p = Process(target=func)
    #启动创建好的进程
    p.start()

    print('主进程执行结束！')

跑起來後，你會看到「主進程開始執行」和「主進程執行結束」，以及夾在中間、由另一個行程印出的那句話。這裡的 target=func 是關鍵：你傳進去的是函式本身（函式物件），不是 func() 的結果。要傳參數給這個函式，用 args，而且要包成一個元組，例如 Process(target=func, args=(123, 456))。就算只有一個參數，逗號也不能省，寫成 args=(url,)，否則 Python 不會把它當成元組。

從同步到非同步：同一段請求，兩種命運

先看同步版本。下面對三個網址依序發出請求，每個請求要花 2 秒，中間用 time.sleep(2) 模擬等待：

import time
def get_request(url):
    print('正在请求网址的数据：',url)
    time.sleep(2)
    print('请求结束:',url)

if __name__ == "__main__":
    start = time.time()
    urls = ['www.1.com','www.2.com','www.3.com']
    for url in urls:
        get_request(url)
    print('总耗时：',time.time()-start)

因為是同步，第二個請求要等第一個做完才開始，總耗時大約是 2 加 2 加 2，也就是 6 秒。程式大部分時間都卡在 time.sleep(2) 這個阻塞點上發呆。

現在把迴圈裡「直接呼叫函式」改成「每個網址開一個行程」，同一批任務就變成非同步了：

import time
from multiprocessing import Process
def get_request(url):
    print('正在请求网址的数据：',url)
    time.sleep(2)
    print('请求结束:',url)

if __name__ == "__main__":
    urls = ['www.1.com','www.2.com','www.3.com']
    for url in urls:
        #创建了三个进程，表示三组任务
        p = Process(target=get_request,args=(url,))
        p.start()

三個請求幾乎同時開始，大家各自去等自己的 2 秒，所以總時間大約縮到 2 秒左右。這就是非同步的價值：把「一起等」變成「分頭等」。

用 join 讓主行程學會等待

不過上面那段非同步程式有個副作用：主行程不會等子行程。它把三個子行程啟動後，可能自己先跑到結束，於是你還沒看到子行程的輸出，整個程式就收了。要讓主行程停下來等，就用 join()：主行程一定會等到「呼叫了 join 的那個子行程」結束後，才繼續往下走。

import time
from multiprocessing import Process
def get_request(url):
    print('正在请求网址的数据：',url)
    time.sleep(2)
    print('请求结束:',url)

if __name__ == "__main__":
    start = time.time()
    urls = ['www.1.com','www.2.com','www.3.com']
    p_list = [] #存储创建好的子进程
    for url in urls:
        #创建子进程
        p = Process(target=get_request,args=(url,))
        p_list.append(p)
        #p.join() #一定不要这么写
        #启动子进程
        p.start()

    for pp in p_list:#pp就是列表中的每一个子进程
        pp.join() #是的每一个子进程都执行了join操作
        #意味着：主进程需要等待所有执行了join操作的子进程结束后再结束

    print('总耗时：',time.time()-start)

這裡有個容易寫錯的地方：p.join() 絕對不要放在建立子行程的那個迴圈裡。如果你一建立就 join，等於「開一個、等一個做完，再開下一個」，那就退回同步了，非同步的加速效果完全消失。正確做法是先用一個 p_list 把所有子行程收好，等三個都 start() 完（都已經在跑了），再另開一個迴圈逐一 join。這樣三個任務同時在跑，主行程只是在最後等它們全部收工。

會讓你踩坑的現象：行程之間的資料是隔離的

現在來看一個結果會讓你意外的例子。底下主行程裡有個全域變數 ticketNum = 10，開一個子行程去扣掉 3 張票，最後主行程印出剩下的票數：

#观察下述代码出现的问题是什么？（了解）
from multiprocessing import Process
import time
ticketNum = 10 #全部的车票
def func(num):
    print('我是子进程，我要购买%d张票！'%num)
    global ticketNum
    ticketNum -= num
    time.sleep(2)

if __name__ == '__main__':
    p = Process(target=func,args=(3,))
    p.start()
    #主进程在子进程结束之后在结束
    p.join() #只有当子进程结束后，join的调用结束，才会执行join后续的操作
    print('目前剩余车票数量为:',ticketNum) #输出结果依然是10
    #进程和进程之间是完全独立。两个进程对应的是两块独立的内存空间，每一个进程只可以访问自己内存空间里的数据。

你可能會預期印出 7，但結果是 10。為什麼？因為 ticketNum = 10 是存在主行程裡的，子行程在啟動時，是把它複製到自己那份獨立的記憶體，子行程的減法只作用在自己的那份上。主行程最後印的，仍然是主行程原本那個沒被動過的值。

這不是 bug，而是行程的本質：行程與行程之間完全獨立，各自對應一塊獨立的記憶體空間，每個行程只能存取自己空間裡的資料。呼應上一節的譬喻，就是不同車間的空間互不相通。子行程函式的回傳值也沒辦法直接傳回主行程，若真的需要互通，得動用管線、信號量這類「行程通訊機制」。不過在爬蟲場景裡你很少需要它，我們要的通常只是各抓各的、把結果寫進檔案或佇列，而不是讓行程互相改同一個變數。

守護行程：主行程一結束，子行程就跟著收

最後一個情境：如果我希望主行程結束時，它開出來的那些子行程也一起結束，該怎麼做？答案是把它設成守護行程（daemon process）。

import time
from multiprocessing import Process
def get_request(url):
    print('正在请求网址的数据：',url)
    time.sleep(2)
    print('请求结束:',url)

if __name__ == "__main__":
    start = time.time()
    p = Process(target=get_request,args=('www.1.com',))
    # 将当前p这个子进程设置为了守护进程
    p.daemon = True #该操作必须放置在子进程启动操作之前
    p.start()

    print('主进程执行结束')

這裡只有一行是關鍵：p.daemon = True，而且這行必須放在 start() 之前，順序寫反會出錯。設好之後有兩個後果要記住。第一，主行程的程式碼一執行結束，守護行程就立刻被終止，不管它自己有沒有跑完；所以這段程式的子行程那句「請求結束」很可能根本來不及印出來。第二，守護行程裡面不能再開子行程，否則會直接拋出 AssertionError: daemonic processes are not allowed to have children。

小結

開子行程的三步是：from multiprocessing import Process、Process(target=函式, args=(...))、start()。把迴圈裡的直接呼叫改成「每個任務開一個行程 start」，就能得到非同步的加速；要正確收尾，先用清單收好所有子行程、全部 start 之後再逐一 join，千萬不要在建立迴圈裡 join。行程之間資料隔離，子行程改動不會傳回主行程；daemon = True 要放在 start() 前，設了之後主行程一結束子行程就跟著被終止。

做完長什麼樣？你應該能跑出一支會開三個子行程去抓資料、總耗時明顯少於逐一等待的程式，並且能解釋為什麼子行程改了票數主行程卻看不到。至於「為什麼行程之間要這樣隔離」的底層原理，這裡不用深究，知道後果就夠用了。

行程雖然直觀，但每一次都開一個全新車間，成本不低。下一節換一個更輕量的角色上場：執行緒。它跟行程只差一個關鍵，記憶體會被共享。
