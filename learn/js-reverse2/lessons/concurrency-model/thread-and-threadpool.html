執行緒與執行緒池：threading.Thread 與 Pool.map

Step 4/5 · 行程、執行緒與協程：併發為何存在

學習目標

用 threading.Thread 與 multiprocessing.dummy.Pool(5).map 平行化一批 IO 任務，並正確處理共享記憶體與等待。

前言：把「每次開一間廠房」換成「多請幾個工人」

上一節開子行程雖然直觀，但每開一個行程，就等於重新配置一間獨立廠房，成本不低。如果我只是要同時發好幾個網路請求，其實不需要彼此隔離的記憶體，用更輕量的執行緒就夠了。這一節就把工具換成執行緒，你會看到寫法跟行程幾乎一樣，但有一個關鍵差異會讓結果完全不同：記憶體是共享的。

動手前先確認你已經掌握：執行緒是執行緒、行程是行程，同一行程內的執行緒共享記憶體，不同行程之間隔離。這是上一節親眼看過的現象，接下來要利用它。另外要記住一個小前提：Python 提供 thread、threading、Queue 等模組，其中 threading 比較先進、對執行緒的支援較完整，所以實務上推薦用 threading。

第一步：建立並啟動執行緒

最單純的建立方式和行程很像：用 Thread(target=函式, args=(...)) 建一個執行緒物件，再呼叫 start() 啟動。差別只在於匯入的是 threading 的 Thread：

from threading import Thread
def func(num):
    print('num的值是:',num)

if __name__ == '__main__':
    #创建好了一个子线程（在主线程中创建）
    t = Thread(target=func,args=(1,))
    t.start()

跑起來後，主執行緒印出 num 的值。這裡的 args 用法和行程完全相同：要傳參數就包成元組，單一參數寫成 (1,)。

另一種寫法：繼承 Thread 改寫 run

除了傳 target，也可以自己寫一個類別繼承 Thread，把要做的事放進 run() 方法，再實例化並 start()。下面同時示範了如何建立多個執行緒，以及用 join 等它們全部結束：

from threading import Thread
import time
class MyThread(Thread):
    def __init__(self):
        super().__init__()

    def run(self):
        print('当前子线程正在执行')
        time.sleep(2)
        print('当前子线程执行结束')

if __name__ == '__main__':
    start = time.time()

    ts = []
    for i in range(3):
        t = MyThread() #创建线程对象
        t.start() #启动线程对象
        ts.append(t)
    for t in ts:
        t.join()
    print('总耗时:',time.time()-start)

這裡的模式和上一步的行程 join 一樣：先建立三個執行緒、全部 start() 起來，最後才逐一 join()。三個執行緒各自睡 2 秒，因為是一起睡的，總耗時會接近 2 秒而不是 6 秒。join() 的語意也一樣：主執行緒會等待呼叫了 join 的那些執行緒結束，才繼續往下執行。

關鍵差異：執行緒共享記憶體

現在把上一節那個「改了變數主行程看不到」的例子，原封不動搬到執行緒來。主執行緒裡有全域變數 n = 1，開一個執行緒把它改成 0，然後主執行緒印出 n：

from threading import Thread
import time
def work():
    global n
    n = 0 #将全局变量修改为了0
if __name__ == '__main__':
    n = 1 #全局变量
    t = Thread(target=work)
    t.start()
    print(n) #在进程中输出全局变量的值就是线程修改后的结果为0

結果和行程相反：這次印出的是 0。因為同一個行程內的執行緒共享這塊記憶體，子執行緒改的就是主執行緒看得到的那份資料。這一點既是方便也是風險：好處是執行緒之間能直接透過共用變數交換狀態；壞處是當多個執行緒同時讀寫同一份資料，就可能互相干擾，寫程式的時候要特別小心。

守護執行緒：規則和守護行程一致

執行緒也能當守護執行緒，規則跟守護行程是同一套：不管是行程還是執行緒，都遵循「守護 xx 會在主 xx 執行完畢後被銷毀，不管它自己有沒有執行結束」。

from threading import Thread
import time
def work():
    time.sleep(1)
    print('子线程正在执行！')
if __name__ == '__main__':
    t = Thread(target=work)
    t.daemon = True #当前的子线程设置为了守护线程
    t.start()
    print('主线程结束！')

同樣地，t.daemon = True 要放在 start() 之前。設好之後主執行緒一結束，這個子執行緒就一起被收掉，所以那段「子執行緒正在執行」很可能來不及印出來。

用執行緒做非同步：一批任務一起發出去

把前面幾個零件拼起來，就是一段實用的多執行緒非同步程式：對五個網址各開一個執行緒，全部啟動後再統一 join：

from multiprocessing.dummy import Pool #导入了线程池模块
import time
from threading import Thread
start = time.time()
def get_requests(url):
    print('正在爬取数据')
    time.sleep(2)
    print('数据爬取结束')

urls = ['www.1.com','www.2.com','www.3.com','www.4.com','www.5.com']
ts = []
for url in urls:
    t = Thread(target=get_requests,args=(url,))
    t.start()
    ts.append(t)
for t in ts:
    t.join()

print('总耗时:',time.time()-start)

五個執行緒一起睡那 2 秒，總耗時就從逐一的 10 秒縮到約 2 秒。到這裡你已經能體會執行緒的輕量：不用另開廠房，多請幾個工人就能同時推進多個任務。

執行緒池：省下反覆建立與銷毀的開銷

但如果任務有上百個，難不成要開上百個執行緒？執行緒的建立與銷毀本身也要花成本。於是有了執行緒池：執行緒預先被建立並放進池中，處理完當前任務之後並不銷毀，而是被安排去處理下一個任務。這樣就避免了反覆建立執行緒，效能與系統穩定性都更好。用 multiprocessing.dummy 裡的 Pool 就能做到：

from multiprocessing.dummy import Pool #导入了线程池模块
import time
urls = ['www.1.com','www.2.com','www.3.com','www.4.com','www.5.com']
def get_reqeust(url):
    print('正在请求数据：',url)
    time.sleep(2)
    print('请求结束:',url)
start = time.time()
#创建一个线程池,开启了5个线程
pool = Pool(5)
#可以利用线程池中三个线程不断的去处理5个任务
pool.map(get_reqeust,urls)
#get_reqeust函数调用的次数取决urls列表元素的个数
#get_requests每次执行都会接收urls列表中的一个元素作为参数

print('总耗时：',time.time()-start)
pool.close() #释放线程池

這裡有幾個點要看懂。Pool(5) 表示池裡準備了 5 個執行緒；pool.map(get_reqeust, urls) 把函式和整個網址清單一起丟進去，池子會自動把清單裡的每個元素當成參數、分派給池中的執行緒去處理，你不用自己寫 for 迴圈、也不用自己管 join。函式被呼叫的次數取決於網址清單有幾個元素，每個元素都會是某一次呼叫的參數。最後 pool.close() 釋放池子。這行看似不起眼，但在批次任務裡很重要：池子用完要記得關，否則容易堆著沒釋放的資源。

小結

執行緒用 threading.Thread(target=函式, args=(...)) 建立、start() 啟動，也可以繼承 Thread 改寫 run()。收尾用 join()，一樣要全部 start 完再逐一 join。與行程最大的差別是記憶體共享：子執行緒改的全域變數，主執行緒看得到。守護執行緒的規則與守護行程相同，daemon = True 放在 start() 前。批次任務改用執行緒池 Pool(5).map(函式, 清單)，池中執行緒會被重複利用，省下反覆建立與銷毀的成本。

做完長什麼樣？你應該有兩個能跑的版本：一個是手動開多個執行緒、一個是用 Pool(5).map，兩者都能把一批 IO 任務的總耗時壓下來，而且你知道執行緒版本為什麼能讓子執行緒改動主執行緒的變數。至於執行緒池內部的排程細節，這裡交給實作去處理，你要知道的是它省下了什麼。
