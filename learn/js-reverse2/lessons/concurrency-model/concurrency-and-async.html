一次只做一件事：單核排程、併發與非同步

Step 2/5 · 行程、執行緒與協程：併發為何存在

學習目標

用單核與時間片輪轉說明併發／平行的差別、行程的四種狀態，以及同步與非同步遇到阻塞操作時的行為差異。

前言：一邊聊天一邊聽歌，到底是不是同時？

上一節我們留下一句有點反直覺的話：單核 CPU 一次只能執行一個任務。可是你剛剛才一邊回訊息、一邊聽音樂、一邊打遊戲，這些事明明看起來是同時發生的。矛盾在哪？答案不是「那顆核心偷偷變強了」，而是作業系統在極短的時間內不斷切換，快到你的眼睛分辨不出來。

這一節要把這個「切換」講清楚。搞懂它，你才有辦法回答三個之後一定會遇到的問題：為什麼我多開執行緒不一定變快？為什麼程式卡在網路請求時，整支程式都像被凍住？以及，所謂「非同步」到底非同步在哪裡。

作業系統在偷偷切換：行程排程

你能一邊聊微信、一邊聽音樂、一邊打遊戲，是因為 CPU 在交替執行多個行程。要讓多個行程輪流上場，作業系統必須排程它們；而這個排程不是隨機亂排，得遵循一定的法則，這就是所謂的行程排程演算法。

目前常見的演算法有幾種：先來先服務（FCFS）、短作業優先，以及時間片輪轉。其中被公認比較好的是時間片輪轉法。它的做法大致是：作業系統準備好幾個就緒佇列，每個佇列有不同優先順序；優先順序越高的佇列，分配給每個行程的執行時間片（也就是它被允許連續執行的時間）就越短。新行程先排進第一佇列的尾端等待；輪到它時，如果能在這個時間片內做完就離開，做不完就被挪到下一級佇列尾端，繼續排隊。低優先順序的佇列時間片較長，讓這些行程有機會一次多跑一點。

關鍵是「每個人只准跑一小段」。不管有沒有做完，時間一到就換下一個，於是所有行程都能輪流推進，使用者的感受就成了「同時」。

併發與平行：關鍵在「是不是真的同時」

有了排程的概念，就可以分清楚兩個常被混用的詞。

平行（parallelism）是真正的同時執行，前提是要具備多個 CPU（或多個核心）才辦得到。併發（concurrency）則是偽平行，是時間片輪轉切換出來的「看起來同時」，本質上一個核心在同一時刻仍然只做一件事。

用吃飯來分辨最清楚。你吃飯吃到一半，電話來了，你硬是吃完才去接，這表示你不支援併發也不支援平行。你停下來接電話，講完再回來繼續吃，這表示你支援併發：你能處理多個任務，但一次只專心做一件。你一邊打電話一邊吃飯，這才是平行，兩件事真的在同一段時間裡一起進行。

所以不管是併發還是平行，在使用者眼中都是「同時」在跑；但真實幹活的只有 CPU，而一個 CPU 同一時刻只能執行一個任務。分辨它們的關鍵，就是「是否真的同時」。

併發（concurrency）平行（parallelism）
本質偽平行，時間片輪轉切換真正同時執行
前提單核即可需要多個 CPU／核心
一句話有處理多個任務的能力，不一定要同時有同時處理多個任務的能力

行程的四種狀態

在程式執行的過程中，行程會被作業系統的排程演算法推來推去，進入不同的狀態。主要有四種：

  • 就緒（Ready）：行程已經準備好，所需資源與記憶體都分配好了，只差被排程上場。
  • 執行（Running）：就緒的行程被排到之後，進入執行狀態，真正開始跑。
  • 阻塞（Blocked）：正在執行的行程，因為某些事件而暫時無法繼續。最典型的就是網路請求、等待輸入這類耗時操作，程式發出請求後只能等對方回應，這段時間它動不了。
  • 終止：行程結束、發生錯誤，或被系統終止，無法再執行。

其中「阻塞」是爬蟲最該記住的狀態。你的程式大部分時間不是在算東西，而是在等網路，也就是處在阻塞狀態。誰能妥善利用這段空等，誰的爬蟲就快。

同步與非同步：都是順序執行，差在「等不等」

同步是指 CPU 執行一個任務時，任務的每個步驟順序執行，而且必須前一步做完了，才能做下一步。中間只要有一個步驟沒完成，你就什麼都不能做。

非同步則不一樣：步驟仍然是照順序跑，但不必等前一步結束才開始下一步。一個步驟一旦開始執行，不論它有沒有做完，都會馬上去執行下一個步驟。

用做飯來理解。同步的方式是照步驟依次做：先燒水，水開了煮飯，飯好了炒菜。在前一步沒完成之前，你不能做別的事，只能站在旁邊等。非同步的方式則是：燒水時水還沒開，你不必傻等，可以先去刷手機、回封信；等水開了再回來處理。燒水、煮飯、炒菜都是耗時操作，也就是所謂的阻塞操作。

這裡有個很精準的定義要記住：同步與非同步，講的是 CPU 在執行任務時遇到阻塞操作所產生的不同行為。同步是遇到阻塞就停下來等；非同步是遇到阻塞先跳去處理別的。如果一個任務從頭到尾都在計算、完全沒有阻塞點，那同步和非同步的差別就沒那麼大。

最後補一個常被追問的問題：非同步是基於並行還是併發？答案是不一定，它可以是基於並行的，也可以是基於併發的，但大部分情況下是基於併發，也就是靠切換，而不是靠真的多核同時跑。

同步非同步
遇到阻塞時停下來等它完成不等，先去做下一個步驟
步驟關係前一步完成才進入下一步步驟仍順序，但不互相等待
做飯譬喻等水開才去煮飯、炒菜燒水時先去刷手機、回信

小結

單核一次只做一件事，卻能看起來同時處理多個任務，靠的是作業系統的行程排程，公認較好的是時間片輪轉法。併發是時間片切換出的偽平行，平行才需要多核真正同時執行。行程會經歷就緒、執行、阻塞、終止四種狀態，其中阻塞正好對應爬蟲等待網路的時光。同步是遇到阻塞就停下來等，非同步是遇到阻塞先去做別的，這正是後面所有加速手法的分水嶺。

觀念建立好了，接下來要動手。既然非同步的價值在於「不要傻等」，那第一步就是讓程式能同時進行多件事。下一個單元先從最直觀的做法開始：直接開一個真正的子行程。
