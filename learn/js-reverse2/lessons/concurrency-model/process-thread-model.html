工廠、車間與工人：行程與執行緒的心智模型

Step 1/5 · 行程、執行緒與協程：併發為何存在

學習目標

用「工廠、車間、工人」的譬喻說出行程與執行緒的關係，並分清執行緒共享記憶體、行程之間彼此隔離。

前言：電腦明明只有一顆核心，為什麼能同時做好幾件事？

你一定有過這種畫面：電腦一邊播音樂、一邊開著微信、一邊還在跑遊戲，順得好像它同時在處理這些事。但如果你掀開機殼看規格，很多時候機器只有一顆核心。一顆核心，怎麼可能同時做三件事？

這個問題不只是好奇。你之後要寫的爬蟲，慢的原因往往不是運算不夠快，而是程式在「等」：等伺服器回你、等下載完成。如果搞不懂電腦到底是怎麼安排這些等待與工作，就很難判斷自己的程式為什麼卡住，也無從選擇該用哪種方式加速。這一節先把最基本的一組角色，也就是行程與執行緒，建起來，後面所有效能技巧都掛在這組角色上。

先看整體：CPU 是一座工廠

電腦的核心是 CPU，所有計算任務都由它扛下，就像一座日夜運轉的工廠。工廠再大，也有供電的限制；這裡的設定是：電力有限，一次只能供給一個車間使用。某個車間開工，其他車間就得停工。

把這個限制翻成電腦的語言就是：單核 CPU 一次只能執行一個任務，同一時刻只能做一件事。這點很容易被日常體驗騙過去：我們感覺電腦在「同時」做好幾件事，但底層其實不是。

行程是車間，執行緒是工人

在這座工廠裡，行程（process）就像是工廠的一個車間，代表 CPU 所能處理的單個任務。當你啟動一個應用程式，作業系統就開了一個行程給它，替它準備好對應的記憶體與資源；應用程式在跑，其實就是這個行程在跑。所以狹義地說，一個正在執行的應用程式，在作業系統眼中就是一個行程。具體一點：你有 py1.py 和 py2.py 兩個檔案，把它們各自跑起來，就是兩個獨立的行程。

車間裡不會只有一台機器，而是有很多工人協同完成任務。這些工人就是執行緒（thread）：執行緒是作業系統能拿來排程運算的最小單位，它被包含在行程之中，是行程裡實際動起來的角色。一個行程可以包含多個執行緒，而且每一個行程裡至少會有一個執行緒，這個開頭就存在的執行緒叫做「主執行緒」。

有了這組譬喻，接下來兩個容易混淆的性質就很好懂了。

什麼是共享的，什麼是隔離的

車間的空間是工人們共用的，很多房間每個工人都能自由進出。對應到程式，就是一個行程的記憶體空間，會被這個行程底下所有執行緒共享。同一行程內的執行緒可以一起讀寫這些記憶體，所以 A 執行緒改了某個變數，B 執行緒看得到，這是執行緒方便的地方。

但車間與車間之間不是這樣。每個車間有自己的空間，別的車間進不來。所以不同行程之間的資源是彼此隔離的，一個行程只能存取自己記憶體空間裡的資料，另一個行程完全看不到。這一點在寫爬蟲時特別關鍵：如果你用子行程去修改某個共用變數，很可能改了半天，主行程那邊一點動靜都沒有。

還有一個實務上的差別：建立執行緒的開銷，比建立行程要小得多。開一個車間（行程）要配置整塊廠房與資源，成本高；在同一個車間裡多請一個工人（執行緒），相對便宜。這也埋下了後面選工具的伏筆。

行程（車間）執行緒（工人）
角色CPU 能處理的單個任務行程內實際運作的單位
數量關係一個程式跑起來就是一個行程一個行程可含多個執行緒，至少一個
記憶體行程之間彼此隔離同一行程內共享記憶體
建立開銷較大較小

一個常見的誤會：多執行緒一定平行嗎？

既然一個行程可以養好幾個執行緒，那它們是不是就同時在跑？不一定。當 CPU 資源比較充足時，一個行程內的多個執行緒確實可以被分配到不同的核心上，這時候才算真正的「平行」。但這個分配是由作業系統決定的，不是你能手動控制的。所以「多開幾個執行緒」不等於「保證平行」，它只是把任務交出去，實際怎麼跑得看作業系統怎麼安排。

而作業系統到底是怎麼安排的？為什麼單核也能看起來像同時在做很多事？這就是下一步要拆開的「排程」。

小結

CPU 是一座工廠，單核一次只能供電給一個車間，所以單核一次只跑一個任務。行程是車間，代表一個被啟動的程式；執行緒是車間裡的工人，是實際運作的最小單位，一個行程至少有一個執行緒。車間內的空間（記憶體）由工人共享，但車間與車間之間彼此隔離；建立執行緒比建立行程便宜。
