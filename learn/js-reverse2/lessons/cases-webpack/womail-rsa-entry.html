沃邮箱：鎖定登入加密模組 437 並呼叫加密

Step 3/5 · 案例：webpack 打包站實戰

學習目標

在沃邮箱的登入 bundle 裡用探針鎖定模組 437，讀懂 encrypt 與 hashPassword 的匯出並呼叫它們取得加密後的密碼。

前言：登入框裡的密碼，送出去前被誰動了手？

上一節在财联社把簽名模組當函式呼叫，練的是「可呼叫的匯出」。這一節換一個情境：登入。你在沃邮箱（中國聯通的信箱服務）的登入框輸入密碼，打開開發者工具看送出的請求，發現密碼欄位已經不是你打的那串字，而是一大段亂碼。把登入用的 JavaScript 另存下來，同樣是一份 webpack 打包檔，但這次模組 id 從字串換成了數字，加密模組掛的是具名方法，呼叫端的測試程式甚至把 RSA 公鑰參數直接寫死在裡面。

這一節就把這條登入加密的路走通：讀懂這份精簡版 loader、看懂入口模組在等哪些懶載入區塊、鎖定模組 437、讀懂它的匯出，最後照測試程式的寫法把加密呼叫出來。RSA 這個演算法本身的細節（填充模式、輸出格式、Python 重現）在非對稱加密的案例節點裡；這裡練的仍然是 webpack 呼叫層——只不過這次的匯出形狀是第三種。

目標與前置條件

做完這一節，你會有一支加密密碼的小程式：餵明文密碼進去，拿回 #! 開頭的 RSA 密文，正好可以塞進登入請求的密碼欄位。動手前需要前兩節的定位與呼叫手感，以及知道 RSA 是「公鑰加密、私鑰解密」的非對稱演算法即可，不需要會推導它。

步驟一：讀這份精簡版 loader

沃邮箱的入口檔 09 沃邮箱的loader.js 開頭一樣是載入模組檔，接著是分發器。它的分發器 c(e) 比财联社的更短，探針的位置也一眼可見：

    function c(e) {
        if (t[e])
            return t[e].exports;
        var n = t[e] = {
            i: e,
            l: !1,
            exports: {}
        };

        console.log("e:::", e)
        return a[e].call(n.exports, n, n.exports, c),
            n.l = !0,
            n.exports
    }

    window.loader = c

骨架跟前面兩站完全一致：快取命中先回傳、建快取紀錄、執行模組、回傳 n.exports。差異只有細節：探針的訊息字串是 e:::（前一站是 r:::），而且這裡沒有 try/finally 的快取清理——模組若丟出例外，半成品快取會留在原地。知道這個差別就好，正常呼叫時它不會咬人。

洩漏點一樣是 window.loader = c。所以三站下來你已經可以歸納：不管分發器叫什麼名字、長什麼樣，逆向者的兩把手術刀（探針、window.loader 洩漏）插的位置都是同一組。探針的訊息字串每站不同，反而是辨認「這支 loader 被誰動過手」的小線索。

步驟二：看懂入口模組在等什麼

這支 loader 的結尾跟著一組大括號，裡面是入口模組 329：

}({
    329: function (e, n, t) {
        document.onreadystatechange = function () {
            Promise.all([t.e(0), t.e(6)]).then(t.t.bind(null, 338, 7))
        }
    }
});

它在說的是瀏覽器的行為：頁面載入完成時，先用 t.e(0) 與 t.e(6) 去抓兩個懶載入區塊，都到齊了才載入模組 338（登入畫面）。這兩個區塊的檔名對照表就在同一支檔案裡：

                    i.src = c.p + '' + ({
                        0: 'loginCommon',
                        6: 'login'
                    }[e = u] || e) + '.54f91.js',

區塊 0 叫 loginCommon、區塊 6 叫 login，就是「共用登入元件」跟「登入畫面」兩包程式碼。對逆向者來說，這整段是瀏覽器才走的路：我們的目標模組 437 不在懶載入區塊裡，它已經躺在開頭載入的模組檔中，直接用 window.loader(437) 就拿得到，完全不必模擬這段載入流程。

步驟三：打開模組 437，看它的匯出形狀

在模組檔 10 沃邮箱的mod1.js 裡搜尋 437: function，找到目標模組。它長這樣：

    437: function(t, e, n) {
        var i = n(595)
          , o = 'C4E3F7212602E1E396C0B6623CF11D26204ACE3E7D26685E037AD2507DCE82FC\n28F2D5F8A67FC3AFAB89A6D818D1F4C28CFA548418BD9F8E7426789A67E73E41';
        function r(t, e, n) {
            var r = new i;
            return r.setPublic(e, n),
            r.encrypt(t)
        }
        t.exports = {
            encrypt: r,
            hashPassword: function(t) {
                return t ? '#!' + r(t, o, '10001') : ''
            },

逐段拆開看。開頭 n(595) 取出 595 號模組——那是一個 RSA 加密函式庫，介面長得像常見的 JSEncrypt（用 setPublic 設公鑰、用 encrypt 加密）。變數 o 是一長串十六進位的公鑰模數（modulus，RSA 公鑰的一半），'10001' 是公鑰指數（exponent，另一半）。這兩個參數就硬編碼在模組裡，任何拿到打包檔的人都看得到——這正是「公鑰本來就要公開」的設計，伺服器拿私鑰解密。

再看匯出：t.exports = { encrypt: r, hashPassword: ..., loadPassword: ... }。這就是第三種匯出形狀——「具名方法的物件」，跟四川补贴的 dd88 是同一族，但方法名從單字母換成了有語意的名字。encrypt 是低階版本，三個參數自己傳；hashPassword 是高階版本，把「公鑰參數已寫好、再補上 #! 前綴」都包辦了；loadPassword 是開發用的解密工具，會從網址列的 location.hash 讀回密文解開，逆向時用不到但可以偷看它的私鑰參數。

步驟四：照測試程式呼叫加密

入口檔的最尾端留著一段環境測試，這就是現成的呼叫範例：

let t = "asdasdasd"
let o = 'e3873eb7dea99b6c0c85f9e543a7dfaa7e6f90f5794c99dadf04326673437258174a2489fe12c75f4b81af37e60f152a0bd1180e9b959784dfbdc2e95ee48e927a6c09fa0037275290b2d475bd574dcbade9492181c6f5f56b96d74148498deae93d5b7ae3b8eb965ffc4c71efa671accda941db64d3e29907c2b42e0b365e0d'
let n = '10001'
console.log(window.loader(437).encrypt(t, o, n))

呼叫寫法是 window.loader(437).encrypt(t, o, n)：數字 id 437 換回匯出物件，點上具名方法 encrypt，傳入三個參數——明文 t、公鑰模數 o、公鑰指數 n。測試用的明文是隨便打的字串，模數是另一串十六進位（跟模組裡那串不同，代表測試者想測不同的公鑰）。實際要加密登入密碼時，把 t 換成密碼字串即可；或者更省事，直接呼叫 hashPassword(密碼)，連公鑰參數都不用傳，它會自動用模組裡寫好的那組。

回傳值是一段 RSA 密文（用 hashPassword 的話前面會多一個 #!），直接放進登入請求的密碼欄位就能對上伺服器的解密邏輯。這一段密文怎麼用 RSA 還原成 Python 可產生的格式，是非對稱加密案例節點的功課；在這裡，「找到 437、按對方法、傳對參數」就是全部任務。

做完長什麼樣

執行後終端機會先吐一串 e::: 的探針訊息——其中一定有 e::: 437，證明目標模組被觸發；接著是一段 RSA 密文。把這段密文換進真實登入請求、伺服器接受登入，整條路就驗證完畢。若呼叫時出現「setPublic is not a function」之類的錯誤，多半是 595 號模組沒有先被載入——模組依賴是自動的，但環境缺件（例如瀏覽器的 navigator）仍可能讓函式庫初始化失敗，照錯誤訊息補環境就好。

小結

沃邮箱給了第三種匯出形狀：具名方法物件，encrypt 低階、hashPassword 高階。模組 id 也換成了數字——id 是字串還是數字取決於打包工具的組態，呼叫前先看清楚。入口模組等的懶載入區塊是瀏覽器的路，直接呼叫目標模組時繞過它即可。公鑰參數（模數與指數）硬編碼在模組裡是正常設計，不用懷疑自己找錯地方。

三個案例下來，你已經看過三種匯出形狀：dd88 的物件方法、W2Yj 的可呼叫函式、437 的具名方法，外加模組 id 的字串與數字兩種長相。是時候把這些經驗壓成一張隨查隨用的對照表了——下一節整理四個真實站點的 loader 變形與匯出形狀，讓你接到新站時能對號入座。
