B/S 架構與 HTTP：爬蟲為什麼要模擬瀏覽器

Step 1/4 · Web、HTTP 與 HTML：爬蟲在跟什麼打交道

學習目標

能說出 B/S 架構與爬蟲的關係，並用「請求-回應」與「無狀態」兩個特性說明 HTTP 的基本運作。

前言：爬蟲到底在做什麼

你想抓某個網頁上的資料，上網查了一下，大家都說「寫個爬蟲就好」。於是你打開編輯器，卻卡在第一步：爬蟲究竟是在做什麼？它不是真的去「打開網頁」，而是反過來，模仿瀏覽器去向伺服器要資料。要理解這個動作，得先看清楚瀏覽器和伺服器之間是怎麼對話的：它們用的是同一套規則，這套規則叫 HTTP。

這一節先把這張大圖建起來。少了這層理解，後面很多東西都會像在背咒語：為什麼要帶 User-Agent、為什麼要盯著標頭、為什麼登入要靠 Cookie。有了這張圖，你才會知道每一招落在流程裡的哪個位置，又是在解決什麼問題。

兩種架構：C/S 與 B/S

先把場景縮小到最基本的一層：任何兩個程式在互相傳資料，都可以拆成「提供資料的一方」和「來要資料的一方」。前者叫伺服器（Server），後者叫客戶端（Client）。依照客戶端是哪一種，桌面應用和網頁應用剛好對應兩種架構。

面向C/S 架構B/S 架構
全名Client / ServerBrowser / Server
客戶端要安裝的桌面程式瀏覽器本身
怎麼通訊應用程式自己定義透過 HTTP／HTTPS
常見例子騰訊視頻、微信、網盤百度、知乎、博客園

C/S 是你得先裝好一個程式才能用，例如看影片要先裝騰訊視頻。B/S 則是打開瀏覽器就能用，瀏覽器本身就是那個客戶端，不用另外安裝。所以 B/S 其實還是 C/S，只是把客戶端換成了瀏覽器，並改用 HTTP／HTTPS 向伺服器要網頁資源。

這跟爬蟲有什麼關係？關係在於：我們的目標是爬取伺服器端的特定資料，而伺服器只認得 HTTP 請求。於是爬蟲的角色就清楚了：它是你自己寫的一個客戶端程式，不經過瀏覽器介面，直接用 HTTP 去跟伺服器要資料。這也是為什麼大家常說，爬蟲是在「模擬瀏覽器」。

HTTP 是什麼

HTTP 全名是 HyperText Transfer Protocol，中文翻作超文本傳輸協定。拆開來看：超文本指的是「含有指向其他資源連結」的文本，不只是文字，還包含影片、圖片、動畫等；協定則是雙方事先約定好的溝通方式。

打個比方，這就像老電影裡土匪對暗號：「天王蓋地虎」配「寶塔鎮河妖」，外人聽得一頭霧水，但雙方一聽就懂。HTTP 就是瀏覽器和伺服器之間的這套暗號：兩邊都照同一個規矩說話，資料才傳得過去。

HTTP 其實包含兩半：瀏覽器送到伺服器要遵守的請求協定，以及伺服器送回瀏覽器要遵守的回應協定。後面兩節會把它們一行行拆開來看。

特性一：請求-回應模式

HTTP 的第一個特性是請求-回應模式。規則是：請求一定由客戶端先發出，伺服器收到之後才回應。伺服器不會在還沒收到請求之前，主動丟資料給你。這個規則決定了爬蟲的形狀：你必須先送出請求，才有可能拿到資料。

特性二：無狀態

第二個特性是無狀態（stateless）。意思是 HTTP 本身不保存前後兩次請求之間的關聯。每當有新請求進來，就會產生對應的新回應，但這個協定並不記得之前發生過什麼。對伺服器來說，每一次請求都像初次見面，即使這些請求來自同一個客戶端。有人用一句話形容這種感覺：人生只如初見。

無狀態讓 HTTP 簡單、好擴充，應付大量請求時很有效率。但它也帶來麻煩。假設你登入了一家購物網站，接著點進站內另一個頁面，伺服器根本不記得你登入過，又要你重新登入一次。為了解決這種「需要保持狀態」的需求，HTTP/1.1 引入了 Cookie 技術。Cookie 是什麼、它怎麼讓登入狀態延續下去，會是第 3 步的主題。

小結

HTTP 是瀏覽器和伺服器之間的溝通協定：客戶端先送請求、伺服器才回應，而且它天生無狀態、不記得前後請求的關聯。爬蟲就是一個自己寫的客戶端，用 HTTP 模擬瀏覽器去要伺服器端的資料；需要「記住」的狀態，則靠 Cookie 來補。
