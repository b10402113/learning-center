用 Proxy 監控缺口：讓程式自己說它缺什麼

Step 2/5 · 補環境與環境檢測

學習目標

用 new Proxy 的 get／set 攔截對物件的讀寫，用 setProxyArr 批次對多個物件掛上代理，並從日誌列出補環境要補的屬性。

前言：黑盒子不會告訴你它缺什麼

上一節說明了瀏覽器 JS 搬進 Node 會壞的兩個根因。現在問題變成：那段被你拷來的加密程式碼，可能有好幾萬行、還做了混淆，它到底用了 window 的哪些屬性、document 的哪些方法？你不可能一行行讀完再一個一個補。

這一節要裝上一個工具，把這個「猜」的過程變成「記錄」。做法是替整個 window、document 套一層代理，之後這段程式碼不管讀取或寫入這兩個物件的任何屬性，都會先經過你寫的邏輯，於是它缺什麼，會自己一筆一筆印在你的終端機上。

前置條件：你理解物件屬性的讀寫（obj.prop 與 obj.prop = v）的基本操作。Proxy 的觀念在「Hook 與 Proxy 攔截」那個節點已經建立，這裡直接用。

第一步：把一個物件包進 Proxy

先從最單純的版本開始，只代理一個物件。下面這段定義了一個 yuan 物件，然後用 new Proxy 把它包起來，get 攔讀取、set 攔寫入：

var yuan = {
    username: "yuan",
    age: 22,
    wx: "u82d1660a",
    foo:function () {
        console.log("foo")
    }
}

…

yuan = new Proxy(yuan, {
    get(target, p, receiver) {
        console.log(target, "查询了属性", p)
        // return window['username'];/// 这里如果这样写. 有递归风险的...
        // return Reflect.get(...arguments);
        return Reflect.get(target, p);
    },
    set(target, p, value, receiver) {
        console.log(target, "设置了属性", p, "值为：", value)
        Reflect.set(target, p, value);
    }
});

yuan.username;
yuan.age;
yuan.username = "rain"
yuan.age = 18
yuan.foo()
…

預期看到什麼：每當程式碼讀一次 yuan 的屬性，get 就印出一行「查詢了屬性 XXX」；每當寫入，set 就印出「設置了屬性 XXX 值為 YYY」。原本的讀寫結果完全不變，只是在旁邊多了一本流水帳。

第二步：用 Reflect 把操作交回原物件

get 與 set 收到三個關鍵參數：target 是被代理的原物件、p 是被存取的屬性名、receiver 是代理後的物件。它們的責任是把操作「以原本的語意」交還給 target，這個動作由 Reflect.get(target, p) 與 Reflect.set(target, p, value) 完成。

注意原始碼裡被註解掉的那一行：// return window['username'];/// 这里如果这样写. 有递归风险的...。這是這個工具最容易踩的坑。你在 get 裡面要回傳屬性值時，如果又去讀那個「已經被代理過」的物件，就會再一次觸發 get，然後無限遞迴下去。Reflect.get(target, p) 讀的是背後的原物件 target，不會繞回代理，所以安全。

第三步：批次代理多個物件（setProxyArr）

補環境要盯的不是一個 yuan，而是 window、document、navigator……一大堆。如果每個都照上面寫一次 new Proxy，程式碼會又長又重複。所以補環境的標準做法是寫一個函式，對一串物件名迴圈掛代理：

function setProxyArr(proxyObjArr) {
    for (let i = 0; i < proxyObjArr.length; i++) {
        const objName = proxyObjArr[i];
        const handler = {
            get(target, property, receiver) {
                console.log("方法:", "get", "对象:", objName, "属性:", property, "属性类型：", typeof property, "属性值：", target[property], "属性值类型：", typeof target[property]);

                return target[property];
            },
            set(target, property, value, receiver) {
                console.log("方法:", "set", "对象:", objName, "属性:", property, "属性类型：", typeof property, "属性值：", value, "属性值类型：", typeof target[property]);
                return Reflect.set(target, property, value, receiver);
            }
        };
        // 检查并初始化对象
        let targetObject = global[objName] || {};  // 在 Node.js 环境中使用 global
        global[objName] = new Proxy(targetObject, handler);  // 在 Node.js 中使用 global
    }
}

逐行看它在做什麼。objName 是這一輪要處理的物件名，例如 "window"。它的 get 與 set 裡都帶了 objName 與 property，所以日誌可以印出「是哪個物件上的哪個屬性被動了」，這比只看「有東西被讀」有用得多。接著 global[objName] || {} 的意思是「如果 Node 的全域已經有這個物件就用它，沒有就先給一個空物件」，再把這個物件包成代理、放回全域，如此一來，之後程式碼存取這個名字，拿到的就是被監控的代理。

你可能注意到，這裡 get 只是很單純地 return target[property]，而沒有用 Reflect.get。這是可以的：target 是原物件，不是代理本身，直接讀它不會觸發遞迴。真正要小心遞迴的寫法是「在 get 裡去讀代理後的 window」，那才會繞回自己。

第四步：把要盯的物件名列進去

函式寫好後，實際使用只要傳入一個陣列，列出你想監控的物件名：

setProxyArr(["window", "document", "navigator"])

執行之後，這些名字在全域都會被換成掛好代理的版本。你可以先跑一段你自己的測試程式碼確認日誌有動，再換成真正的黑盒子加密程式碼。

第五步：讀日誌，列出要補的屬性

最後一步不是寫程式，而是看輸出。把代理裝好後放那段黑盒子去跑，日誌會一行一行告訴你：它讀了哪個物件的哪個屬性、屬性的型別是什麼、當下的值是什麼。凡是「屬性值」印出 undefined 的，就是這個物件缺少了那個屬性，那正是你要補進去的清單。

這裡要提醒兩個判斷原則。第一，不是每一個 undefined 都要補：有些屬性程式碼只是探測性地讀一下、拿不到也無所謂（例如某些瀏覽器版本才有的物件），補了反而多餘，甚至補錯型別會造成後續行為不同。第二，補的時候要符合原本的型別與形狀：日誌已經印了「屬性值類型」，是函式就補函式、是物件就補物件，而不是一律塞一個空值進去。

做完長什麼樣

跑完這一節，你應該得到一份終端機輸出，內容是一連串「物件：window／屬性：screenX／屬性值：undefined」這樣的紀錄，而你已經能從中圈出「真正需要補」的那幾個。至於 Proxy 為什麼能攔到、Reflect 背後是怎麼運作的，屬於觀念層次，已經在「Hook 與 Proxy 攔截」節點講過，這裡只把它當成手上的工具用。

現在你有了「缺什麼」的清單，但下一個問題是：這些屬性該補成什麼樣子？下一節把所有補環境會用到的前端物件整理成一份可查的清單，也就是八大前端物件，連同那個最常被拿來檢查的 toString 標籤一起補齊。
