讀呼叫堆疊：從暫停點追回加密函式

Step 4/5 · DevTools：斷點、請求堆疊與呼叫堆疊

學習目標

斷點命中後讀懂 Call Stack 的呼叫鏈，用 step over／step into／step out 順著參數流，找出生產加密值的那個函式。

前言：暫停之後，你才是真正的偵探

上一節你學會了把程式停在對的地方。但程式一暫停，畫面會突然變得安靜：某一行反白、右邊亮起一個面板、一堆變數等著你看。這一刻，你手上有兩件事要做：第一，確認「現在是在哪一個函式裡、這個函式的輸入是什麼」；第二，回答「這個值到底是從哪一層被算出來的」。第二件事，就是讀呼叫堆疊（Call Stack）。

這一節我們不用真站，先用一個刻意寫得很單純的練習頁面，把「暫停 → 讀堆疊 → 逐步前進 → 回到上游」這個迴圈完整跑一次。跑完之後，你就有能力在真實網站上做同一件事：從某個被送出的加密值出發，順著呼叫鏈把它追回產生它的那個函式。

前置條件：你知道加密值可能在哪（Step 1）、會用請求堆疊或關鍵字找到候選程式（Step 2）、也會依情境設對斷點（Step 3）。這一節需要你實際在瀏覽器裡操作。

第一步：準備一個看得到的手術台

先做一個可以完全看懂的靶場。把下面這段網頁存成一個 .html 檔（例如 demo.html），用瀏覽器打開，頁面上會出現一個標題「断点的使用和请求堆栈」。這段程式刻意把加密過程拆成一長串互相呼叫的函式，讓你一眼就能看出「值在誰手上、又被傳給誰」。

<h3 onclick="test01()">断点的使用和请求堆栈</h3>

<script>
    function encrypt(data) {
        return "asdfghjkl"
    }

    function test01() {
        console.log("test01...")
        test02()
    }

    function test02() {
        console.log("test02：数据加密")
        data = "123456"
        let encrypt_data = encrypt(data)
        test03(encrypt_data)
    }

    function test03(encrypt_data) {
        let a = 1
        let b = 2
        let c = 3
        console.log("test03...")
        test04(encrypt_data)
    }

    function test04(y) {
        let a = 10
        let b = 20
        console.log("test04...")
        test05(y)
    }

    function test05(x) {
        console.log("test05...")
        test06(x)
    }

    function test06(encrypt_data) {
        console.log("test06: 发送ajax请求",encrypt_data)
    }
</script>

先讀一遍這段程式，理解它的結構。使用者點標題時觸發 test01；test01 呼叫 test02；test02 把 data 設成 "123456"，呼叫 encrypt(data) 取得加密結果，再把結果交給 test03；接著 test03 交給 test04、test04 交給 test05、test05 交給 test06。整條鏈是：

test01 → test02 → encrypt → test03 → test04 → test05 → test06

其中真正碰到加密值的只有兩個地方：test02 負責「把資料加密」，test06 負責「把加密結果送出去（模擬發 ajax）」。其餘的 test03 到 test05 只是在中間把值一代傳一代。這個結構正是真實網站的縮影：值會被算出來，然後經過好幾層函式才被送出。

第二步：在「值被送出去」的地方下斷點

我們先從最下游、也就是值被送出去的地方下手。在 test06 裡那一行 console.log("test06: ...") 點一下行號，設一個行斷點。選這裡的原因很實際：這是加密結果最後一次被完整看見的地方，只要停在這裡，你就能確認「被送出去的值長什麼樣」。

設好斷點後，點一下頁面上的標題文字。onclick 會觸發 test01，程式一路往下跑，跑到 test06 的那一行時就會暫停，DevTools 會自動切到 Sources 面板，那一行反白。

第三步：讀右邊的 Call Stack

程式暫停後，看右側（或下方）面板裡的 Call Stack，中文叫「呼叫堆疊」。它列出的是「現在這個函式，是被哪些函式一路呼叫過來的」，最上面是當前暫停的函式，往下是它的呼叫者，再往下是呼叫者的呼叫者，依此類推。以剛才的暫停點為例，你會看到：

順序（由上而下）函式此刻手上的值
最上（當前）test06參數 encrypt_data
往下test05參數 x
往下test04參數 y
往下test03參數 encrypt_data
往下test02區域變數 data、encrypt_data
往下test01無參數
最底（onclick 事件）觸發整個鏈的起點

這張堆疊圖就是你的地圖。它告訴你兩件關鍵的事：執行的順序（底下先跑、上面後跑），以及每一層的輸入。當你把滑鼠移到堆疊裡的任何一格，DevTools 會讓那一層的變數作用域亮起來，你就能看到那一層當下握有什麼值。點某一格，程式碼也會跳到那一層，方便你現場對照。

第四步：順著參數流往回找

現在開始往回問問題。當前這一層 test06 的參數 encrypt_data 是什麼？把滑鼠移到它上面，你會看到值，在這個示範裡是 "asdfghjkl"，也就是 encrypt 回傳的那串字。好，那這串值是哪來的？往上一層看 test03、test04、test05，它們的參數名稱換來換去（encrypt_data、y、x），但傳的值其實是同一個。真正產生這個值的地方，要再往上一層，在 test02：

data = "123456"，接著 let encrypt_data = encrypt(data)。這句話就是你要的答案：加密值是在 test02 裡，由 encrypt 這個函式對 "123456" 做出來的。從「值被送出處」追到「值被產生處」，你靠的不是讀完整份程式，而是沿著呼叫堆疊一層一層看每一格的輸入。

這裡有個很實用的觀察：中間那幾層（test03、test04、test05）的參數名稱一直在改，但值不變。這提醒你：不要被參數名稱騙了，要看值實際流到哪裡才變。值「第一次變身」的那一層，往往就是加密真正發生的地方。

第五步：用 Step 系列把過程看清楚

光看堆疊還不夠，有時候你想看某一層「是怎麼把值算出來的」。這時就輪到上方的逐步執行按鈕：

  1. Step Over（逐步跳過）：執行下一行，但如果是函式呼叫，不會跳進去，而是把它當一行做完。用來快速掠過你不關心的層。
  2. Step Into（逐步跳入）：如果下一行會呼叫函式，就跳進去從那個函式的第一行繼續。想進 encrypt 看它怎麼算，就用這個。
  3. Step Out（逐步跳出）：把當前這個函式剩下的部分執行完，直接回到呼叫它的那一層。想從深處快速回到上一層用這個。

以這個示範為例，你可以在 test02 的 encrypt(data) 那一行暫停，按 Step Into 進到 encrypt，看到它 return "asdfghjkl"；再按 Step Out 回到 test02，就會看到 encrypt_data 已經被賦值成那串字。整個過程，就是你親眼看著值被算出來、再被傳下去。

第六步：回到上游重新確認

當你確定了「加密發生在 test02」，下一步是回到那個地方，重新下一次斷點，乾淨地把整個流程再跑一次。這次在 test02 的 let encrypt_data = encrypt(data) 那一行設斷點，重新整理頁面、再點一次標題。程式這次會更早停下來，你可以直接在這個位置判斷 data 的值、按下 Step Into 深入 encrypt。這種「先在下游看一眼、再回到上游下手」的來回，就是讀呼叫堆疊最標準的節奏。

做完長什麼樣：可驗證的結果

跑完這六步，你應該能明確說出這句話：「這個被送出去的加密值 asdfghjkl，是在 test02 裡由 encrypt(data) 產生，輸入的 data 是 123456。」這句話就是你要的產物。你不需要懂 encrypt 內部用了什麼演算法（那是後面案例節點的事），你只要能把「值」和「產生它的函式」對上，逆向的第一階段就完成了。

小結

斷點讓程式暫停，Call Stack 則告訴你「現在這個函式是被誰一路呼叫過來的」。讀堆疊要看兩件事：執行的順序（底下先跑、上面後跑），以及每一層的輸入。順著參數流往上游找，值第一次發生變化的那一層，就是加密真正的入口；中間幾層的參數名稱換來換去，都不能被騙。Step Into／Step Out 讓你進出單一函式，看清楚值被算出與傳遞的過程。

單獨練熟了這套動作，接著要把整條流程接回真實世界。下一個步驟不用練習靶場，而是拿一個真實網站的請求，把「哪些欄位需要重現、要用哪條路去定位」整套規劃出來。
