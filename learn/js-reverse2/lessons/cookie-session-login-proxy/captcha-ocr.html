驗證碼辨識：接上圖鑑平台解圖形驗證碼

Step 5/5 · 會話維持：Cookie、登入、代理與驗證碼

學習目標

能說明何時該把驗證碼外包給第三方 OCR 平台，並照著流程把驗證碼圖片送去辨識、取回文字結果。

前言：登入與 IP 都通了，最後還有一張圖擋著

前幾節你依序解決了三個問題：怎麼維持登入狀態、怎麼用 Session 跑完登入流程、怎麼用代理避開 IP 封鎖。偏偏有些網站會在你送出關鍵請求之前，跳出一張驗證碼，要求你輸入圖上的文字，證明坐在螢幕前的是人而不是程式。對人來說這只是一眼的事，對爬蟲卻是一道過不去的牆。

這一節處理最後這道關卡。做法不是自己寫圖像辨識，而是把「看懂這張圖」外包給專門的 OCR 平台，爬蟲只要負責把圖片送出去、把文字收回來。做完之後，你那條「維持登入 → 帶 Cookie → 換 IP → 過驗證碼」的完整鏈路就補齊了。

前置條件與做完的結果

  • 前置：已註冊第三方驗證碼辨識平台（例如圖鑑）並取得帳號密碼；手上有一張要辨識的驗證碼圖片。
  • 做完會得到：一個能接收圖片路徑與類型、回傳辨識文字的函式。
  • 中間會用到：讀檔、base64 編碼、requests.post 送 JSON、解析回傳結果。

什麼時候該用第三方 OCR

先說清楚適用邊界，免得用錯工具。如果驗證碼是單純的圖形文字（純數字、純英文，或英數混合），那很適合外包給 OCR 平台，也就是這一節的做法。但如果它是滑動拼圖、座標點選、軌跡拖曳這一類需要操作滑鼠的驗證碼，通常就不該在純 requests 這一側硬解，而要用瀏覽器自動化（例如 Selenium）配合對應手法處理；那屬於另一條技術路線。

換句話說：圖形文字的辨識交給 OCR，行為式的驗證留給瀏覽器自動化。選錯路線，再怎麼調參數都事倍功半。

流程總覽：圖片怎麼變成文字

  1. 把驗證碼圖片以二進位讀進來，再編成 base64 字串（因為 API 用 JSON 傳輸，不能直接塞二進位）。
  2. 把帳號、密碼、圖片類型代號（typeid）與 base64 圖片打包成一個 JSON，POST 到辨識平台的 API。
  3. 平台回傳 JSON，成功時從裡面取出辨識結果字串；失敗時取出錯誤訊息。

整個流程裡，typeid 是最容易設錯、也最影響準確度的一環：它告訴平台「這張圖是哪一種驗證碼」，選錯類型，結果就會失準。

驗證碼類型（typeid）對照

平台用一個整數代號區分驗證碼的種類。常見的幾種如下（預設是 3，也就是數英混合）：

typeid類型
1 / 1001純數字
2 / 1002純英文
3 / 1003數英混合（預設）

18 / 33缺口識別（18 需兩張圖；33 單張圖，回傳 X 軸座標）

步驟：封裝辨識函式

下列程式把整個流程封裝成兩個函式。base64_api 負責讀圖、編碼、送出並取回結果；getImgCodeText 則是給爬蟲直接呼叫的介面，傳入圖片路徑與類型就回傳文字。

import base64
import json
import requests
# 一、图片文字类型(默认 3 数英混合)：
# 1 : 纯数字
# 1001：纯数字2
# 2 : 纯英文
# 1002：纯英文2
# 3 : 数英混合
# 1003：数英混合2
#  4 : 闪动GIF
#  7 : 无感学习(独家)
#  11 : 计算题
#  1005:  快速计算题
#  16 : 汉字
#  32 : 通用文字识别(证件、单据)
#  66:  问答题
#  49 :recaptcha图片识别
# 二、图片旋转角度类型：
# 29 :  旋转类型
#
# 三、图片坐标点选类型：
# 19 :  1个坐标
# 20 :  3个坐标
# 21 :  3 ~ 5个坐标
# 22 :  5 ~ 8个坐标
# 27 :  1 ~ 4个坐标
# 48 : 轨迹类型
#
# 四、缺口识别
# 18 : 缺口识别（需要2张图 一张目标图一张缺口图）
# 33 : 单缺口识别（返回X轴坐标 只需要1张图）
# 五、拼图识别
# 53：拼图识别
#函数实现忽略
def base64_api(uname, pwd, img, typeid):
    with open(img, 'rb') as f:
        base64_data = base64.b64encode(f.read())
        b64 = base64_data.decode()
    data = {"username": uname, "password": pwd, "typeid": typeid, "image": b64}
    result = json.loads(requests.post("http://api.ttshitu.com/predict", json=data).text)
    if result['success']:
        return result["data"]["result"]
    else:
        return result["message"]
    return ""


def getImgCodeText(imgPath,imgType):#直接返回验证码内容
    #imgPath：验证码图片地址
    #imgType：验证码图片类型
    result = base64_api(uname='bb328410948', pwd='bb328410948', img=imgPath, typeid=imgType)
    return result

逐段拆解：每一段在做什麼

  1. with open(img, 'rb') as f：用二進位模式讀取驗證碼圖片。'rb' 的 b 是 binary，圖片不能用純文字模式讀。
  2. base64.b64encode(f.read()).decode()：把圖片位元組編成 base64，再解碼成字串。因為等一下要用 JSON 傳輸，而 JSON 只能放文字，所以必須先編碼。
  3. data = {"username": uname, "password": pwd, "typeid": typeid, "image": b64}：把平台帳密、驗證碼類型與 base64 圖片組成要送出的內容。
  4. requests.post("http://api.ttshitu.com/predict", json=data)：用 json= 參數把整個字典當 JSON 送出。這是和送表單不同的地方，辨識 API 收的是 JSON body。
  5. result['success'] 判斷辨識成不成功：成功就回傳 result["data"]["result"]，失敗則回傳 result["message"] 的錯誤訊息。

要接進爬蟲時，呼叫 getImgCodeText(圖片路徑, 類型代號) 就能拿到文字，把那個文字填進登入表單的驗證碼欄位，再送出登入請求即可。

小結

圖形文字驗證碼交給第三方 OCR 平台：把圖片讀成 base64、連同帳密與 typeid 以 JSON POST 到辨識 API，成功時取回 data.result 的文字。關鍵是挑對 typeid，並認清它的邊界：滑動、點選、軌跡類的驗證碼要靠瀏覽器自動化，不是靠這個流程。

走完這一節，這個節點的四個工具就齊了：用 Cookie 與 Session 維持登入、用模擬登入取得登入後資料、用代理池突破頻率限制、用 OCR 過人機驗證。它們不是四個獨立技巧，而是同一條「伺服器怎麼認出你」的鏈路。實戰時，先看目標卡在哪一關，再決定拿出哪一個工具，這也是整個節點最想留給你的判斷力。
