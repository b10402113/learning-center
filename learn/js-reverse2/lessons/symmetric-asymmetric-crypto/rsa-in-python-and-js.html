用 Python 生成金鑰、重現 RSA 加解密，對照 jsencrypt

Step 4/5 · 對稱與非對稱加密：AES/DES、RSA、國密

學習目標

能用 pycryptodome 生成公私鑰、以 PKCS1_v1_5 加密成 base64 傳輸、再用私鑰解密，並對照 jsencrypt 在 Node 下的寫法與環境 shim。

前言：手上有公鑰，下一步是把它變成能跑的程式

上一節你把非對稱加密的模型想通了：公鑰加密、私鑰解密，前端只放公鑰。現在場景換成動手：你從某個站台撈到了一段公鑰 PEM，或被要求自己造一組金鑰來測試。這一節要把整個迴圈走一遍：產生一對金鑰、把公鑰拿來加密、把密文 base64 之後傳出去、再用私鑰解回來，最後跟 jsencrypt 的寫法對照，確認兩端可以互通。

動手前的前置條件

  • Python 端需要 pycryptodome，用課程的鏡像安裝：pip install pycryptodome -i https://pypi.tuna.tsinghua.edu.cn/simple/。
  • JS 端需要 Node 環境與 jsencrypt（npm install jsencrypt）。還記得要先把 window 與 self 指向 globalThis，jsencrypt 才載得起來。
  • 知道 PEM 是那種夾在 -----BEGIN ...----- 與 -----END ...----- 之間的文字格式。

第一步：產生一對金鑰並匯出成 PEM

測試時最方便的做法是直接用 Python 現場生成。下面是產生 1024 位元金鑰、並把公鑰與私鑰各存成一個 PEM 檔的程式：

from Crypto.PublicKey import RSA

# 通过相关算法生成唯一秘钥
rsakey = RSA.generate(1024)
#将秘钥保存到文件中
with open("rsa.public.pem", mode="wb") as f:
    f.write(rsakey.publickey().exportKey())

with open("rsa.private.pem", mode="wb") as f:
    f.write(rsakey.exportKey())

這裡有三個細節。第一，RSA.generate(1024) 的參數是金鑰位元數，數字越大越安全、運算越慢，1024 只是練習用的規模。第二，exportKey() 回傳的是位元組，所以寫檔要用 mode="wb"；用純文字模式寫會出錯。第三，rsakey.publickey() 從整組金鑰裡取出公鑰，rsakey 本身則是私鑰，兩者分別匯出成 rsa.public.pem 與 rsa.private.pem。

第二步：用公鑰加密，再 Base64 包起來

拿到公鑰後，加密的動作是：讀進 PEM、匯入成金鑰物件、用它建立 PKCS1_v1_5 加密物件、加密明文，最後 base64 編碼方便傳輸：

from Crypto.PublicKey import RSA
from Crypto.Cipher import PKCS1_v1_5
import base64

# 加密
data = "我喜欢你"
with open("rsa.public.pem", mode="r") as f:
    pk = f.read()
    rsa_pk = RSA.importKey(pk)
    #基于公钥创建加密对象
    rsa = PKCS1_v1_5.new(rsa_pk)

    result = rsa.encrypt(data.encode("utf-8"))
    # 处理成b64方便传输
    b64_result = base64.b64encode(result).decode("utf-8")
    print(b64_result)

逐段對應：RSA.importKey(pk) 把 PEM 文字還原成可用的金鑰物件；PKCS1_v1_5.new(rsa_pk) 指定用 PKCS#1 v1.5 這個填充方案來建立加密器；rsa.encrypt(data.encode("utf-8")) 得到二進位密文；最後一步 base64 是因為 RSA 的密文是二進位，直接塞進 JSON 或表單會壞掉，包成純文字才好傳。這裡讀檔用 mode="r"，因為 PEM 是文字。

第三步：用私鑰解密

解密就是把順序倒過來：讀進私鑰 PEM、匯入、建立 PKCS1_v1_5 物件，把收到的 base64 先解碼回二進位，再解密：

from Crypto.PublicKey import RSA
from Crypto.Cipher import PKCS1_v1_5
import base64

data = '17wJJtBBujJurHRu3teDC44jSllmqcB9a22U1DQ5/IsI0m3NuShPTxBq8pLTWRdszPapiXfjvOh47P9u5+7U4hvNZL+kKqs3H5m4BKKphORUUfqb9zTowoHb1mM9ji2LuMAYmc1l70ZR+s9XsV3HrHCV/S2FzGWngcWpNVtsTJg='
# 解密
with open("rsa.private.pem", mode="r") as f:
    prikey = f.read()
    rsa_pk = RSA.importKey(prikey)
    #创建解密对象
    rsa = PKCS1_v1_5.new(rsa_pk)
    result = rsa.decrypt(base64.b64decode(data), None)
    print("rsa解密数据:::", result.decode("utf-8"))

rsa.decrypt(base64.b64decode(data), None) 裡的 None 是第二個參數「失敗時要回傳的哨兵值」：解密失敗會回傳它而不是直接爆掉，用來提醒你「失敗也可能安靜地發生」。解密成功的話，result 是位元組，.decode("utf-8") 就得到原本的明文。

第四步：對照 jsencrypt 的 Node 寫法

同一件事在 JS 端用 jsencrypt 表達，長相如下。這裡示範的是用私鑰解密一段先前用公鑰加密的 base64 密文：

//使用私钥解密
encrypted = 'cs5vAIOCBAMtiseOlXDLFJv+vG9n/is6sT3xcTRZG3qEob75Np9sxyCh9sidlq1DN+n1KBrbww1QjpU8un02GQ=='
var decrypt = new JSEncrypt();
decrypt.setPrivateKey(PRIVATE_KEY);//设置私钥
var uncrypted = decrypt.decrypt(encrypted);//解密
console.log(uncrypted);

對照 Python 版本，四個角色一一對應：new JSEncrypt() 對應建立加解密物件；setPrivateKey(PRIVATE_KEY) 對應 RSA.importKey(prikey)；decrypt(encrypted) 對應 rsa.decrypt(base64.b64decode(data), None)；最後的輸出就是明文。jsencrypt 內部同樣採用 PKCS#1 v1.5 填充，這也是兩邊能互通的原因。

做完長什麼樣：解密拿回原文

驗收標準很單純：用公鑰加密、私鑰解密，跑完要能拿回你當初輸入的字串（例如 我喜欢你）。有一個容易誤判的地方要先講清楚：PKCS#1 v1.5 的填充帶有隨機成分，所以同一段明文加密兩次，出來的密文不會一樣。因此你不能用「兩次密文是否相同」來判斷成功，只能靠「私鑰能不能解回明文」來驗證。另外，只要公鑰私鑰是同一對，Python 加密的密文丟給 JS 解、或 JS 加密的密文丟給 Python 解，也都應該成功，這正是實際對接站台時要確認的事。

小結

RSA 的完整迴圈有四步：用 RSA.generate(1024) 產生金鑰並用 exportKey() 匯出 PEM（寫檔用 "wb"）；公鑰端用 RSA.importKey → PKCS1_v1_5.new → encrypt → base64；私鑰端把 base64 解回二進位後 decrypt(..., None)；jsencrypt 則是 setPrivateKey 搭配 decrypt，兩邊因都用 PKCS#1 v1.5 而互通。驗收看的是「能不能解回原文」，不是密文是否相同，PKCS#1 v1.5 有隨機填充，同段明文每次密文都不同。

到這裡，對稱與非對稱兩條主線都走完了。最後補上一個常被誤認成 AES 的家族，中國國密 SM3／SM4。它出現在一類特定的站台裡，逆向時你得先認出它，才不會拿 AES 的參數硬套。
