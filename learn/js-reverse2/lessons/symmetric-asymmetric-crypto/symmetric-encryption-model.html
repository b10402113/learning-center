對稱加密的運作模型：Key、Mode、Padding、IV

Step 1/5 · 對稱與非對稱加密：AES/DES、RSA、國密

學習目標

能講清楚對稱加密為什麼只需要一把 key，並說出 Key／Data／Mode／padding／iv 這五個參數各自決定什麼，以及 ECB 與 CBC 的差別。

前言：那串不是 MD5 的亂碼，多半就是它

你在上一個節點已經學過，看到一串 32 位、只有 0-9a-f 的字串，八成是 MD5；看到一串由大小寫字母、數字與 + / = 組成、長度是 4 的倍數的內容，那是 Base64。但真實的站台上還有第三種東西：一長串 Base64 解開之後，得到的不是可讀文字，而是另一坨二進位亂碼。例如某個介面回傳的內容是 X/A0fy9S7+kUI3HYQRKO46WTlid6T1DBhXutwmPdboY=，你把它 Base64 解碼，卻得不到任何人看得懂的句子。

這種「解了一層還是看不懂」的東西，通常就是對稱加密的密文。它跟 Base64 的差別在於：Base64 只是換個寫法，誰都能解回來；對稱加密則需要一把密鑰（key）才解得開，而逆向的工作，就是想辦法把這把 key 找出來。這一節先把對稱加密的運作模型講清楚，下一節再帶你實際從 JS 裡挖出參數、用 Python 重現。

對稱加密的核心：加解密共用同一把 key

對稱加密之所以叫「對稱」，是因為加密與解密用的是同一把密鑰。你拿這把 key 把明文鎖起來變成密文，別人只要拿到同一把 key，就能把密文還原成明文。整個流程可以想成家用保險箱：鎖上與打開都用同一把鑰匙，誰拿到鑰匙，誰就能開。

這帶來一個很直接的推論：對稱加密的安全性，完全押在「這把 key 有沒有被別人知道」上。演算法本身是公開的，AES、DES 的規則人人可查，真正保密的是那把 key。所以逆向這類加密時，你找的從來不是「破解演算法」，而是那把藏在程式碼裡的 key，以及它被怎麼使用。

分組密碼的五個參數

DES 與 AES 都屬於「分組密碼」（block cipher），它們不是一個字元一個字元地加密，而是把資料切成一塊塊固定大小的「分組」再處理。要把一筆資料加密成功，必須湊齊五個參數，少一個結果就會不同：

參數它是什麼決定什麼
Key（密鑰）加解密共用的那組字串用哪把鑰匙開鎖；對稱加密的機密核心
Data（資料）要被加密或被解密的內容這次要處理的明文或密文
Mode（模式）分組之間怎麼串接用 ECB 還是 CBC，直接影響安全性與是否用到 iv
padding（填充）補齊長度的規則資料不足一個分組時，怎麼補到整數倍
iv（初始向量）CBC 模式用的起始值即使明文相同，也能讓每次密文不同

先講 padding。分組密碼要求資料長度剛好是分組大小的整數倍，DES 的分組是 8 個位元組、AES 是 16 個位元組。如果資料湊不滿，就要按照 padding 規則補齊。這裡有個容易踩的點：密文長度是分組大小的整數倍這件事，其實是「加密前先 padding」的結果：AES 的密文長度一定是 16 的倍數，DES 一定是 8 的倍數。反過來說，當你看到一段密文長度是 16 的倍數，就要懷疑它是 AES；是 8 的倍數，就可能藏著 DES。

ECB 與 CBC：分組之間要不要互相牽連

加密時資料被切成一塊塊分組，這些分組彼此之間要不要有關聯，就是 Mode 在決定。最常用的是 ECB 與 CBC 兩種。

ECB 是最基礎的做法：每個分組各自獨立加密，一個接著一個輸出，組合成密文。它的問題很直白：相同的明文分組，永遠得到相同的密文分組。如果一張圖片用 ECB 加密，色塊的輪廓甚至還會隱約浮現，因為同樣的圖案加密後還是同樣的圖案。所以 ECB 雖然簡單，安全性較弱。

CBC 則是把前一個分組的密文，跟當前分組的明文先做一次 XOR 運算，再拿去加密。這樣每個分組的加密結果都會被前一塊牽動，相同的明文分組就再也加密不出相同的結果，破解難度明顯提高。也因為要「牽動前一塊」，CBC 需要一個起點，那個起點就是 iv（初始向量）。iv 通常是一個 16 位元組的隨機字串，它的作用是確保即使你加密相同的明文，每次產生的密文也不一樣。要注意：iv 只是一個「起始值」，不是祕密，但在解密時必須拿到同一個 iv 才能還原，所以傳輸或儲存時要把它一起留著。

一句話記差別：ECB 是「各塊各自加密」，同樣明文永遠得到同樣密文；CBC 是「前一塊的密文先跟這塊明文混合再加密」，同樣明文每次也不一樣，代價是要多帶一個 iv。

DES 與 AES：為什麼現在都用 AES

DES 的全名是 Data Encryption Standard（資料加密標準），是一種使用密鑰的對稱加密演算法；AES 則是後來取代 DES 的先進加密標準。兩者的差別在實務上有兩個層面：

  • 密文長度不同：DES 加密後的密文長度是 8 的整數倍，AES 是 16 的整數倍。
  • 應用場景不同：一般企業級開發，DES 的強度已經夠用；要求更高的場合則改用 AES。

在逆向現場，這個差別會直接幫你判斷。當你在 JS 裡看到關鍵字，如果呼叫的是 CryptoJS.AES.encrypt，那就是 AES；如果看到 CryptoJS.DES，那就是 DES，它的密鑰長度是 8 個位元組，不要理所當然地當成 AES 來還原，這是很多人第一次踩的坑。

認出對稱加密的關鍵字

要在 JS 裡定位對稱加密，先鎖定幾個關鍵字：

  • AES、DES：演算法名稱，出現在呼叫的函式或物件上。
  • encrypt、decrypt：加解密函式名，幾乎所有實作都這樣命名，是搜尋入口。
  • xxx key：密鑰變數。有一點要特別放心上，也是最關鍵的觀念：真實網站裡的 key 幾乎不會明晃晃地寫死在程式碼裡，它通常是另外生成、拼接或經過一層推導得來的。所以你不能只靠眼睛找一個「看起來像 key 的字串」，而要順著 key 是怎麼被算出來的那條線往上游追。

小結

對稱加密的加密與解密共用同一把 key，安全性全押在這把 key 上。DES 與 AES 都是分組密碼，一筆資料要成功加解密得湊齊五個參數：Key、Data、Mode、padding、iv。ECB 讓每塊各自加密、相同明文得到相同密文；CBC 讓前一塊密文牽動下一塊，並額外靠 iv 這個 16 位元組的起始值保證每次密文不同。DES 的分組是 8 位元組、AES 是 16 位元組，現在主流用 AES。逆向時盯住 AES／DES、encrypt／decrypt 這些關鍵字，並且記住真正的 key 多半不是寫死的。
