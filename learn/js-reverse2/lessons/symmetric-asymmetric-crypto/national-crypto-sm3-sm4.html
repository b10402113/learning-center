國密 SM3/SM4：從 sm-crypto 讀懂一條簽名管線

Step 5/5 · 對稱與非對稱加密：AES/DES、RSA、國密

學習目標

認出 sm-crypto 的 sm3／sm4 特徵，並讀懂四川補貼案例「排序拼接 → SM3 雜湊 → 轉大寫 → SM4 加密」的簽名管線，說出每個 helper 在做什麼。

前言：一包不是 AES、也不太像 MD5 的加密

前面幾步你都用同一套判斷在分流：看到 32 位十六進位就猜 MD5，看到 Base64 就找 AES 的 key。但在某些站台，尤其是對岸的政務、補貼、交易平台，你會撞見一包怎麼套都套不進去的東西：既沒有 CryptoJS，也沒有 encrypt 這種眼熟的命名，取而代之的是一行 require('sm-crypto')，以及幾個函式 sm3、sm4.encrypt、sm4.decrypt。

這就是中國國家標準的密碼演算法，簡稱「國密」。它跟 AES／MD5 長得像、用得也像，但完全是另一套實作。這一節不只要認出它，還要跟著一個真實案例（四川農機補貼平台）把整條簽名管線拆開。看懂之後，你之後遇到國密站台就能直接照抄這套拆法，而不是被 sm4 這個陌生的名字卡住。

認出國密：sm-crypto 的三個函式

案例的 JS 一開頭就載入了 sm-crypto，並把最常用的三個操作包成小函式：

// const { sm3, sm4 } = require('sm-crypto');
const sm = require('sm-crypto');

function r(e) {
    var t = sm.sm3(e);
    return t
}

function d(e) {
    var t = sm.sm4.encrypt(e, "30062AFC48C0E7B5B0918851C0445A37");
    return t
}


function u(e) {
    var t = sm.sm4.decrypt(e, "30062AFC48C0E7B5B0918851C0445A37");
    return t
}

這裡要先建立兩個對應關係，之後才看得懂整條管線：

國密函式對應的常見演算法性質
sm.sm3MD5／SHA 這類雜湊單向、不可逆、輸出固定長度
sm.sm4.encrypt / sm.sm4.decryptAES／DES 這類對稱分組密碼可逆，需要一把 key

所以 r 是「拿 SM3 做雜湊」，d 是「用 SM4 加密」，u 是「用 SM4 解密」。它們三個共用同一把 key，一串 32 個十六進位字元的字串 30062AFC48C0E7B5B0918851C0445A37，換算起來是 128 位元，正好是 SM4 的標準密鑰長度。

有兩個 SM4 的特性要特別記住。第一，sm4.encrypt 預設走的是 ECB 模式、不需要 IV，這跟 AES 常在 CBC 模式、需要 IV 不一樣；硬套 AES 的參數會對不上。第二，它回傳的是一串十六進位或 Base64 文字，不像 Python 的 AES.encrypt 回傳二進位，所以拿到的結果還要看它用哪種格式編碼。

把請求參數排成可簽名的字串：helper h

簽名的第一步，是把一坨 JSON 參數整理成一個固定順序的字串，這樣簽出來的結果才可重現。這個工作由 h 負責：

function h(e) {
    var t = JSON.parse(e)
        , n = Object.keys(t).sort()
        , i = n.map((function (e) {
            var n = t[e];
            if (n) {
                var i = ""
                    , c = encodeURIComponent(e);
                return i = "object" === typeof (n) ? JSON.stringify(n) : n,
                    "".concat(c, "=").concat(i)
            }
        }
    ));
    i = i.filter((function (e) {
            return void 0 !== e && null !== e && "" !== e
        }
    ));
    var c = i.join("&");
    return c
}

拆開來看，它做的是五件事：

  1. JSON.parse(e)：把傳進來的字串還原成物件。
  2. Object.keys(t).sort()：把鍵取出來按字母排序。這一步是關鍵，因為瀏覽器物件本身的鍵沒有保證順序，只有先排序，同一組參數才會每次都拼出相同的字串。
  3. 把每個鍵值組成 k=v：鍵用 encodeURIComponent 編碼；如果值是物件，先 JSON.stringify 再放進去。
  4. filter：把值為 undefined、null 或空字串的項目濾掉。
  5. join("&")：用 & 串成一段像是查詢字串的內容，這就是最終要拿去簽的「正規化字串」。

這種「排序後拼接」的手法在簽名裡非常普遍：沒有它，參數順序一變，簽名就對不上，伺服器驗不過。

整條管線：helper p 把兩者串起來

有了雜湊 r、加密 d、正規化 h，最後由 p 組裝出完整的簽名物件：

function p(e) {
    var t, n = Date.now();
    return e ? (e = JSON.parse(u(e.parameter)),
        e.timestamp = n,
        e = JSON.stringify(e),
        t = h(e),
        t += "&key=HD7232D2AAAKA@978D8723H211?IER&6",
        {
            sign: d(r(t).toLocaleUpperCase()),
            timestamp: d(n.toString()),
            source: "ZRCSL7V0JIRK1PHY"
        }) : (e = e || {},
        e.timestamp = n,
        e = JSON.stringify(e),
        t = h(e),
        t += "&key=HD7232D2AAAKA@978D8723H211?IER&6",
        {
            sign: d(r(t).toLocaleUpperCase()),
            timestamp: d(n.toString()),
            source: "ZRCSL7V0JIRK1PHY"
        })
}

它的流程可以濃縮成這條線：

（如果傳進來的是加密過的 parameter，先用 u 以 SM4 解密回 JSON）→ 蓋上目前時間 timestamp → JSON.stringify → 用 h 排成正規化字串 → 在尾端接上固定的密語 &key=HD7232D2AAAKA@978D8723H211?IER&6 → 對整段先做 r（SM3 雜湊）、轉成大寫，再用 d（SM4）加密，得到 sign。

其中有三個回傳欄位，各自的角色是：

  • sign：把「正規化字串 + 固定密語」先 SM3、再轉大寫、最後 SM4 加密。這是真正被伺服器拿去驗的那個簽名。注意順序是先雜湊再對稱加密，兩個動作用的都是同一把 key。
  • timestamp：把毫秒時間戳直接字串化後 SM4 加密。它同時也是簽名輸入的一部分，所以時間一變、簽名跟著變，具有防重放的效果。
  • source：一個固定常量 ZRCSL7V0JIRK1PHY，不是算出來的，多半是前端身份標記。

案子裡還有一個 aaa() 示範函式，它更進一步把手上的參數物件本身用 SM4 加密成 parameter 再回傳 {parameter, h}。也就是說，這裡不只是「簽名」，連請求的內容都被加密了，parameter 是密文，簽名則用來證明密文沒有被動過。

做完長什麼樣：重現簽名

驗收的標準是：拿同一組參數，你能產生出跟網站一模一樣的 sign。實務上有兩條路走。一條是務實派：把這段 JS 連同 sm-crypto 一起搬到 Node，用 Python 的 execjs 直接呼叫它的函式，省去重寫的功夫，這也是案例中 sichuan.py 的做法。另一條是純 Python 重寫：用支援國密的套件照著上面那條線，自己排序拼接、SM3、SM4 走一遍。第一次接觸時，先跑通 execjs 確認你讀懂了流程，之後再考慮用 Python 重寫以求穩定，是比較省力的順序。

小結

國密的特徵是 sm-crypto 這個套件，以及 sm3（雜湊，對應 MD5／SHA）和 sm4.encrypt／sm4.decrypt（對稱加密，對應 AES，預設 ECB 且不需 IV）三個函式。四川補貼案例的簽名管線是：JSON 參數先經 h 按鍵排序、編碼、濾空、用 & 串成正規化字串，尾端接上固定密語，接著「先 SM3 雜湊、轉大寫、再用 SM4 加密」得到 sign；timestamp 也是 SM4 加密，source 則是固定常量。這種站台可以把 JS 丟給 execjs 直接呼叫，也可以照這條線在 Python 重寫。

走到這裡，對稱加密（AES／DES）、非對稱加密（RSA）與國密（SM3／SM4）三個家族都認過了。之後在真實案例裡再遇到加密的請求或回應，你已經有一張清晰的地圖：先看密文的長度與字母表判斷家族，再回 JS 找 key、iv、mode、padding 或公鑰，最後在 Python 重現並對答案。
