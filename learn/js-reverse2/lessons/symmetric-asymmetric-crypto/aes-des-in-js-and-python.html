從 crypto-js 還原 AES/DES，並用 pycryptodome 重現

Step 2/5 · 對稱與非對稱加密：AES/DES、RSA、國密

學習目標

看到 crypto-js 的 AES/DES 程式碼，能依序抓出 key、iv、mode、padding，並在 Python 用 pycryptodome 寫出可驗證、可對接的加解密。

前言：認得模型之後，工作變成「把四個參數抄到手」

上一節把對稱加密的模型講完了：同一把 key、五個參數、ECB 與 CBC 的差別。觀念聽懂了，但真正下場時你面對的是一段別人的 JS：變數名稱被壓縮成 a、t、n，密鑰散在好幾行裡。這一節要做的，就是把上一節的模型當成一張清單，逐項去 JS 裡對答案：key 在哪、iv 在哪、用的是 CBC 還是 ECB、padding 是哪一種。抄齊之後，你要在 Python 用 pycryptodome 重現出一模一樣的密文，這樣才能拿它去對接介面。

動手前的前置條件

  • Python 環境要能安裝 pycryptodome，課程裡用的是清華鏡像：pip install pycryptodome -i https://pypi.tuna.tsinghua.edu.cn/simple/。
  • 要看懂 Base64，因為密文多半會先用 Base64 包一層才傳輸，這在上一個節點已經學過。
  • 知道上一節那五個參數各自的意思，這裡就不再重講。

第一步：從 JS 認出加密呼叫，讀出四個參數

先看一段典型的 crypto-js 加密程式。整段的重點只有一行 CryptoJS.AES.encrypt，其餘都是在準備它的參數：

const CryptoJS = require("crypto-js")

// 密钥（128位，16字节）
var key = CryptoJS.enc.Utf8.parse('0123456789abcdef');

// 初始化向量（IV）（128位，16字节）
var iv = CryptoJS.enc.Utf8.parse('1234567890abcdef');

// 待加密的数据
var plaintext = 'Hello, bobo!';

// 进行AES-128加密，使用CBC模式和PKCS7填充
var encrypted = CryptoJS.AES.encrypt(plaintext, key, {
    iv: iv,
    mode: CryptoJS.mode.CBC,
    padding: CryptoJS.pad.Pkcs7
});

// 获取加密后的密文
var ciphertext = encrypted.toString();

console.log(ciphertext);

從這段程式你可以一項一項對出上一節的清單：

  • key：CryptoJS.enc.Utf8.parse('0123456789abcdef')。那個 Utf8.parse 只是把字串轉成 crypto-js 內部要用的位元組形式，真正有意義的是引號裡的字串，長度 16 個字元，對應 128 位元的 AES 密鑰。
  • iv：同樣用 Utf8.parse 包起來的 '1234567890abcdef'，也是 16 個字元。
  • mode：CryptoJS.mode.CBC。
  • padding：CryptoJS.pad.Pkcs7。

逆向時最容易漏看的是：引號裡那個字串不一定是寫死的常量，很可能前面幾行是 key = md5(...) 或 key = a.slice(0,16) 算出來的。所以看到 Utf8.parse(...)，要順著括號裡的變數再往回追一層。

第二步：先判斷是 AES 還是 DES

在動手抄參數前，先確認演算法。辨認方式有三個線索，任一個成立就足以分流：

線索AESDES
呼叫的物件CryptoJS.AESCryptoJS.DES
key 長度16／24／32 位元組8 位元組
密文長度特徵16 的整數倍8 的整數倍

很多人會下意識把所有對稱加密都當 AES，結果 key 只有 8 個位元組時怎麼算都對不上。看到 DES 就改用 DES 的參數，這一分流能省下大量鬼打牆的時間。

第三步：在 Python 重現加密

參數抄齊後，Python 這邊要做的事分成四個動作：把 key 轉成位元組、把明文補到 16 的整數倍、建立 CBC 加密物件、加密完再用 Base64 包起來。對應的程式如下：

from Crypto.Cipher import AES
from Crypto.Util.Padding import pad
import base64

key = '0123456789abcdef'.encode()  # 秘钥: 必须16字节
iv = b'abcdabcdabcdabcd'  # 偏移量：16位/字节(字节类型)
text = 'alex is a monkey!'  # 加密内容
#设置加密内容的长度填充（位数为16的整数倍）
text = pad(text.encode(), 16)
#创建加密对象
aes = AES.new(key, AES.MODE_CBC, iv)  # 创建一个aes对象

en_text = aes.encrypt(text)  # 加密明文
print("aes加密数据:::", en_text) #返回二进制类型数据

#二进制密文转换成字符串格式
en_text = base64.b64encode(en_text).decode()  # 将返回的字节型数据转进行base64编码
print(en_text)

逐行看它在做什麼：

  1. '0123456789abcdef'.encode() 把字串轉成 bytes。AES 的 key 必須是位元組，而且長度只能是 16、24 或 32；這裡正好 16 個字元，就是 AES-128。長度不對，AES.new 會直接報錯。
  2. iv = b'abcdabcdabcdabcd' 用的是 bytes 字面值，一樣是 16 位元組。CBC 模式沒有 iv 會報錯。
  3. pad(text.encode(), 16) 把明文轉成 bytes 並補到 16 的整數倍。這一步就是 crypto-js 那邊 Pkcs7 做的事，兩邊的填充規則要一致，否則解出來的尾巴會多出垃圾字元。
  4. AES.new(key, AES.MODE_CBC, iv) 建立加密物件，明確指定 CBC 模式。用 ECB 的話就不需要第三個參數（iv）。
  5. aes.encrypt(text) 得到二進位密文，最後 base64.b64encode(...).decode() 包成可傳輸的字串。

第四步：在 Python 重現解密

解密的順序跟加密剛好相反：先 Base64 解碼拿回二進位密文，再解密，最後把 padding 去掉、還原成文字：

from Crypto.Cipher import AES
import base64
from Crypto.Util.Padding import unpad

key = '0123456789abcdef'.encode()
iv = b'abcdabcdabcdabcd'
aes = AES.new(key, AES.MODE_CBC, iv)
#需要解密的文本
text = 'X/A0fy9S7+kUI3HYQRKO46WTlid6T1DBhXutwmPdboY='.encode()
#将密文数据转换为二进制类型
ecrypted_base64 = base64.b64decode(text)

source = aes.decrypt(ecrypted_base64)  # 解密
#未填充数据
print("aes解密数据:::", source.decode())
#取消填充数据
print("aes解密数据:::", unpad(source, 16).decode())

有兩個地方值得注意。第一，aes.decrypt 之後如果直接 source.decode()，印出來的會在尾端多出一些控制字元，那是沒拆掉的填充，所以一定要 unpad(source, 16)。第二，解密用的 key 與 iv 必須跟加密時完全相同；key 對了但 iv 錯了，明文會被打亂成另一坨亂碼，不會報錯，只會讓你誤以為自己找錯演算法。

對照的 JS 解密長這樣，你可以看出兩邊的參數是逐項對應的：

const CryptoJS = require("crypto-js")

// 密钥（128位，16字节）
var key = CryptoJS.enc.Utf8.parse('0123456789abcdef');

// 初始化向量（IV）（128位，16字节）
var iv = CryptoJS.enc.Utf8.parse('1234567890abcdef');

// 密文数据
var encrypText = 'GYc9oxlZB/PeyfFG3ppK6Q==';

// 进行加密，使用CBC模式和PKCS7填充
var decrypted = CryptoJS.AES.decrypt(encrypText, key, {
    iv: iv,
    mode: CryptoJS.mode.CBC,
    padding: CryptoJS.pad.Pkcs7
});

// 解密
var plaintext = decrypted.toString(CryptoJS.enc.Utf8);

console.log(plaintext);

crypto-js 的 decrypted.toString(CryptoJS.enc.Utf8) 等於 Python 的 unpad(...).decode()：它一次把填充拿掉並轉回文字。

做完長什麼樣：拿密文對答案

驗證的方式很單純，就是同一組 key、iv、明文，兩邊跑出來的密文要一字不差。你可以先固定明文 'alex is a monkey!'、key 0123456789abcdef、iv abcdabcdabcdabcd，在 Python 加密得到一串 Base64；再在 Node 裡跑同一組參數，比對結果。兩串相同，代表你抄的參數正確；不同，就回頭檢查 mode、padding、iv 這三個最常抄錯的地方。接著把 Python 密文丟進解密函式，能還原成原文，整個迴圈才算閉合。之後遇到真實站的加密 body，你就能用這套動作把請求發出去，或是把回應解回來。

小結

從 crypto-js 還原對稱加密，就是把上一節的五個參數當清單逐項抄齊：先看呼叫的是 CryptoJS.AES 還是 CryptoJS.DES（key 長度 16 還是 8、密文長度 16 倍還是 8 倍），再從 Utf8.parse(...) 追出 key 與 iv，並讀出 mode 與 padding。Python 端用 pycryptodome：加密是 pad → AES.new → encrypt → b64encode，解密是 b64decode → decrypt → unpad。驗收標準只有一個：兩邊的密文一字不差。

對稱加密處理完，下一條路是它的搭檔，非對稱加密。它不用同一把 key，而是公鑰加密、私鑰解密，最常見的場景就是登入頁的密碼欄位。先搞懂它為什麼要兩把 key，再談怎麼在 Python 重現。
