病根與出路：抓不到資料＝模擬瀏覽器不足

Step 5/5 · 爬蟲、反爬與逆向的全貌

學習目標

用「模擬瀏覽器的力度不足」解釋為什麼抓不到資料，並畫出抓取→反爬→逆向的整體地圖，說明何時必須從一般抓取升級到逆向。

前言：標頭也補了、Cookie 也帶了，還是不行

走完前四節，你已經有了四步骨架，也認得各種反爬手段。於是你照著做：補上 User-Agent、帶上 Referer、換 Session 收 Cookie、掛個代理。多數情況下，資料真的就回來了。

但總有那麼一站，你把能補的都補了，回應裡卻還是沒有你要的東西；或者請求參數裡躺著一串看不出規律的長字元，每次還都不一樣。這時候再多試幾次標頭也沒用，因為問題已經不在「標頭補得夠不夠」，而在「瀏覽器在你看到結果之前，還偷偷算了什麼」。這一節要把整張地圖收攏，並且告訴你：什麼時候該停下來，換一條完全不一樣的路：逆向。

病根：一句話解釋所有「抓不到」

先把這個節點的核心結論講白：只要你的爬蟲拿不到想要的資料，唯一的原因就是模擬瀏覽器的力度不夠。而且通常，模擬的力度重點就放在請求頭裡面。

回想第一節的定義：爬蟲就是在模仿瀏覽器。那麼「抓不到」自然就是「模仿得不夠像」。這個說法之所以好用，是因為它把五花八門的失敗，全部收斂成同一個問題：瀏覽器做了、而我的程式沒做的那件事，是什麼？補上它，資料就回來；找不到它，或它根本補不了，那就是該換方法的時候。

瀏覽器到底多做了哪些事？看看下面這張對照表就懂了：

瀏覽器自動會做的事裸爬蟲預設不一定有做
送出完整的請求標頭（UA、Referer、Accept 等）只送最基本的標頭，甚至沒有 UA
自動保存並帶上伺服器給的 Cookie不帶 Cookie，每次都是「第一次」
執行頁面上的 JavaScript，把資料補進 DOM只拿回最初的 HTML，可能是一具空殼
依前端程式計算出簽名、加密參數後才送出只會照著抄到的網址與參數死送

每一列的落差，都是一種「力度不夠」。而反爬機制，正是網站刻意把這些落差放大的地方。

矛與盾：反爬與反反爬

這門課反覆出現一組對應關係：反爬機制是網站為了阻止爬蟲而制定的機制；反反爬策略是爬蟲為了突破這些機制而想出的策略。前者站在網站那一邊，後者站在爬蟲這一邊，一攻一守，就是「矛與盾」。

有趣的是，盾不是固定不變的。你補了 UA，網站就開始看 Cookie；你帶了 Cookie，它就限制頻率；你用代理繞過頻率限制，它就在參數上做簽名，逼你去理解前端程式碼。這場軍備競賽一路升級，最後會把你帶到一個補標頭已經無效的地方。

整體地圖：抓取 → 反爬 → 逆向

把前面幾節串起來，整條線其實只有三段。第一段是抓取：用四步骨架把資料拿回來，這是本節點的主體。第二段是反爬：網站開始在四個步驟上設卡，而你用補標頭、帶 Cookie、換代理、解驗證碼等方式應對。這些招式有個共同特徵，就是「網站要什麼，我就給什麼」，本質上仍是模仿瀏覽器。第三段是逆向：當網站的防守深入到「用前端 JavaScript 計算出你抄不到的參數」，光靠模仿已經不夠了，你得反過去看懂瀏覽器私下做了什麼計算，再用 Python 把它重現出來。

換句話說，抓取與反爬都是在「把瀏覽器的行為模仿得更像」，而逆向是「直接拆開瀏覽器的行為，複製它的計算」。這兩者解決的是不同層次的問題：前者處理「怎麼送」，後者處理「送出去的內容是怎麼算出來的」。

什麼時候該從抓取升級到逆向

不是每個卡關都值得動到逆向，逆向的學習成本高，能用簡單方法解決就別繞遠路。下面的判別問句可以幫你決定站在哪一邊：

  • 資料只是缺了標頭或 Cookie，補上就能拿到嗎？→ 留在抓取，別逆向。
  • 只是被頻率限制或驗證碼擋住，換代理、接 OCR 就能過嗎？→ 留在抓取，別逆向。
  • 請求參數是明文、固定值，或能從頁面直接抄到嗎？→ 留在抓取，別逆向。
  • 參數裡有一串沒規律、每次都變的長字元，是前端 JS 算出來的嗎？→ 該逆向了。
  • 回應內容是一串亂碼，要解密後才看得懂嗎？→ 該逆向了。
  • 資料非得執行頁面 JavaScript 才出現，而你又需要穩定、大量地抓嗎？→ 考慮逆向或瀏覽器自動化。

對你最終的工作目標來說，這條線的終點很清楚：目標網站把簽名（sign）、權杖（token）或整包加密的請求內容放在前端計算，你要做的就是沿著逆向這條路，把那些演算法找出來，再用 Python 穩定重現。這也是整門課後半段會一路走到的地方。

小結

抓不到資料的唯一原因，是模擬瀏覽器的力度不夠，而力度通常著重在請求頭。整條路線分三段：抓取（四步骨架）、反爬與反反爬（矛與盾，補標頭／Cookie／代理／驗證碼）、以及逆向。能用模仿解決的，就留在抓取；當保護升級到前端 JavaScript 計算的簽名或加密內容，抄不到、也補不上時，才需要逆向。看懂瀏覽器做了什麼，再用 Python 重現。

到這裡，你手上已經有一張完整的地圖：抓取的四步、反爬的卡點、以及通往逆向的分岔路。接下來整個課程，就是帶著這張地圖一塊一塊往下鑽，先把一般抓取能力（requests 的細節、解析、會話、併發、瀏覽器自動化）打穩，再進入 JS 語言、編碼與密碼學，最後才回到逆向方法論與真實案例。你會不斷回到這張地圖上確認：「我現在在哪一段？為什麼需要這一塊？」
