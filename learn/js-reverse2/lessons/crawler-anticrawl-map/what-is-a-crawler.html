爬蟲是什麼：為什麼它一定要「模擬瀏覽器」

Step 1/5 · 爬蟲、反爬與逆向的全貌

學習目標

用自己的話說明爬蟲為什麼是「模擬瀏覽器的程式」，並分辨通用、聚焦、功能、增量、分散式五種應用分類。

前言：明明看得到，為什麼程式抓不到

你打開一個網站，資料就大剌剌地顯示在眼前，於是你寫下人生第一支爬蟲：把網址丟給 requests.get()，再把回應存成檔案。滿心期待打開檔案，卻發現該有資料的地方一片空白，或者只有一個轉圈圈的載入圖示。明明用瀏覽器就看得到，為什麼程式抓不到？

這個挫折其實問到了整門課的地基。要回答它，得先弄清楚「爬蟲到底是什麼東西」。這一節先把爬蟲的定義講清楚，再看它有哪些不同用途的類型。等這個定義站穩了，後面「為什麼抓不到」、「要怎麼補」才有地方可以掛。

爬蟲就是一支模仿瀏覽器的程式

用最白話的方式說：爬蟲就是寫一支程式，去「模擬」瀏覽器上網，然後把網路上看到的資料「抓」回來。這句話裡有兩個關鍵字，值得拆開來看。

第一個是模擬。你可能沒想過，瀏覽器本身就是一台「純天然的爬蟲」。你輸入網址、按下 Enter，瀏覽器幫你送出請求、拿回資料、再把畫面渲染出來，這一連串動作，和你想要的爬蟲根本是同一回事。所謂爬蟲，只是用程式去重現瀏覽器做過的事。所以你可以這樣理解：爬蟲不是什麼新技術，而是「用程式假裝自己是瀏覽器」。而這也解釋了為什麼爬蟲總是在跟「像不像瀏覽器」這件事搏鬥。

第二個是抓取。抓取有兩種規模：一種是把一整張頁面的資料全部拿下來，另一種是只取頁面中你真正要的那一小塊。前者是後者的基礎：你得先拿到整張頁面，才有東西可以挑選。這個先後關係，正好對應到下面分類裡的「通用」與「聚焦」。

五種應用分類：爬蟲不是只有一種

「爬蟲」其實是個統稱，依用途可以分成好幾類。理解這些分類的重點不是背名詞，而是知道面對不同需求時，你手上這支程式該長成什麼樣子。

類型它做的事什麼時候用
通用爬蟲把一整張頁面的原始碼全部抓下來需要整頁內容，或還不知道要挑什麼
聚焦爬蟲在一張頁面裡，只抓局部、指定的資料有明確目標欄位，例如只要商品價格
功能爬蟲透過瀏覽器或 App 自動化操作，代替人工執行網頁或手機上的動作需要點擊、登入、填表等互動流程
增量式爬蟲監測網站資料的更新，只抓最新變動的部分定期追蹤、不想每次全抓
分散式爬蟲用多台機器組成機群，聯合且分散地爬同一個資源單機速度不夠、量體很大

其中「聚焦爬蟲」要特別注意：它是建立在通用爬蟲之上的。你得先有整張頁面，才能從裡面挑出你要的那一塊；沒有通用這一步，聚焦也無從聚焦。至於功能爬蟲，它常讓人誤會，它不見得是在「抓資料」，有時只是代替人去做一連串操作，例如自動登入、自動點擊。增量式與分散式則是從「時間」和「機器數量」兩個不同的維度去擴充：一個解決「只要新的」，一個解決「一台不夠」。

一個定義，決定後面所有事

把定義記牢之後，有一個推論會跟著你一輩子。如果爬蟲只是「模擬瀏覽器」，那當你的爬蟲程式沒有爬到你想要的資料時，原因幾乎可以收斂成一句話：你模擬瀏覽器的力度不夠。可能是少了某個請求標頭，可能是沒有帶 Cookie，可能是網站在頁面載入後才用 JavaScript 把資料補上，而你只抓到了最初的空白骨架。

換句話說，後面你會學到的每一招（換標頭、帶 Cookie、用代理、解驗證碼、拆加密參數），本質上都在做同一件事：把「模擬瀏覽器」這件事做得更完整一點。這一節先把這個座標系立起來，下一節先處理另一個更前置的問題：這樣模擬下去，界線在哪裡？

小結

爬蟲是「用程式模擬瀏覽器上網、抓取資料」的一支程式。瀏覽器本身就是天然的爬蟲，所以爬蟲的成敗，取決於它模擬瀏覽器的力度夠不夠。依用途，爬蟲可分為通用、聚焦、功能、增量、分散式五類，其中聚焦爬蟲建立在通用爬蟲之上。

既然爬蟲是在模仿瀏覽器抓取公開資料，下一個繞不開的問題就是「這件事的界線在哪」。網站有 robots 協議，法律也對「用爬蟲取得資料的行為」有話要說。下一節要把這條邊界畫清楚，讓你之後動手時心裡有底。
