Hook 是什麼：存下原本的，換上會回報的包裝

Step 1/5 · Hook 與 Proxy 攔截

學習目標

說出 hook 為什麼能攔到函式的輸入與輸出，並用「存下原本的、換上包裝的」骨架，對一般函式與物件屬性都寫出一個 hook。

前言：你知道有加密，卻不知道是誰算的

打開 DevTools 的 Network 面板，你會看到某個請求帶著一個像簽名的參數，例如 sign。你隱約知道它是被某個加密函式算出來的，但頁面載入了好幾支 JS，你既不知道那個函式叫什麼、在哪個檔案，也不知道它被誰、在哪一行呼叫。於是你開始用關鍵字搜尋、一行一行讀，讀到眼睛發酸，還是卡住。

這種時候，與其「找」那支函式，不如讓它自己現身。JavaScript 有一種做法，可以在完全不改動原始程式碼的前提下，替某個函式或屬性裝一雙眼睛：它每次被讀、被寫、被呼叫時，都把參數和結果印出來。這個做法叫 hook（掛鉤）。學會它之後，你不用再猜函式在哪，只要 hook 在對的地方，程式一跑就自己告訴你答案。

前置條件：你應該已經能讀斷點與呼叫堆疊（DevTools 那個節點），並且理解函式與物件屬性的基本語法。

Hook 是什麼

Hook 是一種攔截並修改函式或方法行為的技術。你可以在原函式執行之前、執行之後插入自己的邏輯，甚至整段替換掉它的實作。它最初是給框架與外掛用的，讓你在不改動別人程式碼的前提下擴充功能；但對逆向來說，它真正的價值是另一件事：找出函式的入口，以及參數與回傳值的變化。

為什麼這件事對逆向特別重要？因為加密參數的問題，八成不是「看不懂演算法」，而是「不知道這條線從哪裡牽過來」。Hook 把這個問題換成「程式跑一次，日誌自己記下來」。它有三個好處：不會侵入原始程式碼、可以在原功能上加東西、便於除錯與定位問題。

核心骨架：存下原本的，換上包裝

所有 hook 都從一個很簡單的動作開始：先把原本的函式存到另一個變數，再把原本的名字重新指派成一個包裝函式。包裝函式會先記錄收到的參數，轉頭去呼叫存起來的原函式，再記錄它回傳的結果，最後把結果原封不動地交出去。

先看一個普通函式：

function add(a,b){
    console.log("add方法正在执行");
    return a+b;
}

接著把原函式存起來，這是為了之後能呼叫它、又不去改動它內部的實作：

_add = add;

然後把 add 這個名字換成包裝：

add = function(a,b){
	console.log("原函数调用前, 参数：", a, b);
    let result = _add(a,b)
    console.log("原函数调用后, 结果：", result);
    return result;
}

這樣一來，任何呼叫 add(1,2) 的程式碼都不需要修改，但在結果產生前後，參數與回傳值都會被印出來。你可以把它想成把原本的店員請到後台休息，前台換一個會登記的店員：客人（呼叫方）完全沒感覺，但每一筆進出都被記了下來。原本的邏輯還在，只是外面多了一層。

這裡有一個關鍵時機：hook 必須放在原函式被定義之後。如果太早執行，_add 在那個當下還是 undefined，包裝一被呼叫就會出錯。

為什麼逆向要用它：找出誰呼叫了加密函式

瀏覽器載入一個頁面時，其實執行了非常多 JS 檔，而每個檔案裡又有大量函式。假設你已經鎖定某個叫 add 的加密函式，接下來想知道的是：它到底在哪些程式碼裡被呼叫？

做法就是對它 hook。下面的例子裡，a、b、c、d、e 互相呼叫，最後一路呼叫到加密函式 add：

function a(){
  console.log('a');
}

function b(){
  console.log('b');
  add();
  a();
}

function c(){
  console.log('c');
  b();
}

function add(a,b){
  // 加密函数
  return a + b;
}

_add = add;

add = function (a, b){
  console.log('原函数执行前，参数',a,b);
  let result = _add(a, b)  // 执行原函数
  console.log('原函数执行后，结果', result)
  return result
}

把這段放進頁面執行，再觸發一次頁面行為，你就會在 Console 看到 add 被呼叫的每一次記錄，包含傳進來的參數。原本要靠反覆讀碼才能猜的事，現在變成一份可讀的日誌。這就是 hook 在逆向裡最典型的用法：讓被鎖定的函式，把它的入口與參數自己報出來。

同一套骨架，用在物件屬性上

函式可以 hook，物件的屬性也可以。假設有個物件長這樣：

let user = {
    "name": "波波",
};

屬性沒有「被呼叫」這回事，它只有「被讀取」和「被設定」兩種操作。所以包裝要換成兩個動作：get 負責攔讀取，set 負責攔寫入。JS 提供 Object.defineProperty 來重新定義一個屬性，把它的讀寫導到我們準備好的函式上：

//1、创建一个对象
let user = {
    "name": "波波",
};

//2、保存原属性
_name = user.name;

//3、对象属性的hook
//defineProperty函数用来重新定义对象的属性。
//参数1：对象。参数2：属性。参数3：属性描述符
Object.defineProperty(user, "name",{
    get(){ // 获取属性值的时候执行
        console.log("正在获取属性值");
        return _name;
    },
    set(value){ // 设置属性值的时候执行
         console.log("正在设置属性值:", value);
         _name = value;
    }
});

//4、获取属性和设置属性操作
console.log(user.name)
user.name = 'Jay'
console.log(user.name)

你會發現它跟函式 hook 是同一個精神：_name 存的是原本的值（相當於「存下原本的」），get／set 則是換上的包裝。之後任何人讀 user.name 或寫 user.name，都會先經過這兩個函式。Object.defineProperty 的第三個參數叫屬性描述符，這裡只用到其中的 get 與 set 兩個欄位。

更妙的是，屬性原本不存在也能 hook。下面這個 user 一開始只有 name、沒有 age，但我們先把預設值存在 _age，再直接把 age 定義成一個可攔截的屬性：

//2、保存原属性
_age = 18;

//3、对象属性age的hook
Object.defineProperty(user, "age",{
    get(){ 
        console.log("正在获取属性值");
        return _age;
    },
    set(value){ 
         console.log("正在设置属性值:", value);
         _age = value;
    }
});

這個能力在後面補環境時很重要：當某個進來的腳本一直讀一個「其實不存在」的屬性，你可以主動把它定義成會被記錄的屬性，看清楚它到底在期待什麼。

函式 hook 與屬性 hook 的對照

函式 hook屬性 hook
攔什麼函式的呼叫屬性的讀取與設定
存下原本的_add = add_name = user.name
換上的包裝一個新的 functiondefineProperty 的 get／set
攔得到什麼參數、回傳值讀到的值、寫入的值
能不能攔不存在的不行，函式要先存在可以，先定義出來就行

邊界：hook 攔的是「名字」

有一點要先講清楚，免得後面對不上。上面的 hook 改變的是「add 或 user.name 這個名字之後會指向誰」。如果某段程式碼在 hook 之前就把原函式存進自己的變數，之後它呼叫的就是那個舊的引用，你的包裝攔不到。這也是為什麼 hook 的時機很重要：要在正確的時間點、針對正確的存取路徑下手。

小結

Hook 是在不改動原始碼的前提下，攔截函式或屬性進出的技術。它的骨架只有兩步：把原本的存到另一個變數，再把原本的名字換成一個會記錄、又會轉呼叫原本版本的包裝。函式靠換一個新的 function；屬性靠 Object.defineProperty 的 get／set，而且連原本不存在的屬性也能先定義出來攔。逆向時，它讓你不用再猜哪支函式在哪，只要 hook 在對的地方，程式一跑就把參數與結果自己報出來。

不過到目前為止，你 hook 的都還是「自己頁面裡定義的東西」。真正的目標站常把關鍵的編碼、解碼交給瀏覽器原生的函式，例如 atob；而且這些原生函式很可能在你打開 DevTools 之前就跑過了。下一節要處理的，就是怎麼在頁面程式碼執行之前，把這些原生 API hook 起來。
