Proxy 是什麼：替物件套一層會記錄讀寫的代理

Step 4/5 · Hook 與 Proxy 攔截

學習目標

用 new Proxy 的 get／set 攔截對物件的讀寫，並從「讀到不存在的屬性」判斷補環境時該補哪些東西。

前言：整個 window 都要盯，一個個 hook 太慢

前面三節，hook 攔的對象都是「某一個」函式或「某一個」屬性。這在已經知道目標是誰的時候很好用。但逆向到了補環境的階段，情況會反過來：一大包被壓縮的程式碼丟進來執行，你會發現它讀了一堆 window 或 document 上的屬性，而你根本不知道它讀了哪些。它可能讀 window.screenX、讀 navigator.userAgent、讀某個你可能聽都沒聽過的屬性。

一個個去 hook 是不現實的，因為你連名字都不知道。這時候需要的是另一種工具：替整個物件套一層代理，之後所有對它的讀取與寫入，都會自動先經過你指定的邏輯。這個工具叫 Proxy（代理）。它不只讓你把讀寫全部記下來，還能幫你回答「這個物件缺了什麼」，而這正是補環境時最想知道的事。

前置條件：你理解物件屬性的讀寫（obj.prop／obj.prop = v）與原型鏈的基本概念（JS 原型鏈那個節點）。

Proxy 是什麼

Proxy 是 JavaScript 的內建物件。它包住另一個物件（稱為目標物件，target），並允許你提供一個處理器（handler）來攔截對目標物件的操作。處理器裡放著一個一個的方法，這些方法被稱為捕獲器（trap），當對應的操作發生時就會被呼叫。

打個比方：原本的物件是一間倉庫，你平常直接進出拿貨。Proxy 則是在門口加了一個登記櫃檯：之後所有進出都得先經過櫃檯登記，但貨實際上還是進出原本那間倉庫。你只要決定櫃檯要登記什麼、要不要放行即可。

最基本的兩個捕獲器：get 與 set

最常用的兩個 trap 是 get（攔讀取）與 set（攔寫入）。看一個完整的例子：

//创建user对象
var User = {
    username: "bobo",
    age: 20
}
//创建代理对象，Proxy的参数1：被代理对象。参数2：处理器
User = new Proxy(User, {
    //target:被代理对象。p:属性。receiver：代理后的对象就是User
    get(target, p, receiver) {
        console.log(`获取属性${p}操作`)
        //返回代理对象的p属性值
        return Reflect.get(target, p);
    },
    set(target, p, value, receiver) {
        console.log(`设置属性${p}操作`)
        Reflect.set(target, p, value);
    }
});

console.log(User.username);
console.log(User.age);
User.username = "Jay"
User.age = 18
console.log(User.username);
console.log(User.age);

new Proxy 的參數 1 是被代理的物件，參數 2 是處理器。處理器裡有兩個方法：get(target, p, receiver) 會在有人讀取屬性時執行，其中 target 是被代理的物件、p 是被讀取的屬性名、receiver 是代理後的物件（也就是這裡的 User）；set 則在有寫入時執行。

真正把操作交還給原物件的，是 Reflect。Reflect.get(target, p) 的意思是「以原物件的語意，把 p 這個屬性讀出來」，Reflect.set 同理。它就像程式語言裡的「反射」機制（Python 也有類似的東西），讓你能用統一的介面去執行原本的預設操作。用 Reflect 是關鍵：如果你在 get 裡不小心直接回傳 User[p]，因為 User 現在是代理本身，就會再次觸發 get，一路無限遞迴下去。Reflect.get(target, p) 讀的是背後的原物件，才不會繞回代理。

用 Proxy 抓出「不存在的屬性」

Proxy 真正在補環境時發光的地方，是抓出那些「其實不存在」的屬性。看下面這段，它對同一個 User 套了代理，然後分別讀了 username、age，最後讀一個根本沒定義的 address：

//创建user对象
var User = {
    username: "bobo",
    age: 20
}

User = new Proxy(User, {
    get(target, p, receiver) {
        console.log(`获取属性${p}操作`)
        return Reflect.get(target, p);
    },
    set(target, p, value, receiver) {
        console.log(`设置属性${p}操作`)
        Reflect.set(target, p, value);
    }
});

console.log(User.username);
console.log(User.age);
console.log(User.address);

執行的時候，get 對三次讀取都會觸發並印出日誌。前兩次拿到的 username 與 age 是正常的值；但第三次讀 address 時，target 裡根本沒有這個屬性，回傳的是 undefined。這代表：這個物件缺了 address 這個屬性，如果某段程式碼依賴它，就得把它補上。

把這個模式放大到逆向的補環境上就很清楚了：當你把 window 物件套上代理，讓那一大包程式碼去跑，凡是它讀到、但 window 上不存在的屬性，都會被你的 get 記錄下來、回傳空值。你看日誌就知道「原來它在期待 window 上有這些東西」，於是回過頭去把這些屬性補進環境裡。這是從「憑空猜要補什麼」變成「它自己告訴你要補什麼」的關鍵一步。

Proxy 攔的是「透過代理」的操作

有一點和 hook 一樣要記住：Proxy 保護的是經過這個代理物件的操作。如果某段程式碼拿到的是原始 target 的引用，直接對原物件動手，就會繞過你的處理器。另外，處理器裡每個 trap 都應該用對應的 Reflect 方法把操作轉回原物件，否則很容易改變原本的語意或造成遞迴。把 get／set 想成「登記後照原樣放行」，是最安全的做法。

小結

Proxy 用 new Proxy(target, handler) 把一個物件包起來，handler 裡的 trap 負責攔截操作，最常用的是 get（讀）與 set（寫）。每個 trap 都用對應的 Reflect.* 把操作以原本的語意交還給目標物件，避免改變行為或無限遞迴。它最有價值的用法，是對 window、document 這類大物件做代理，把所有「讀到不存在的屬性」記錄下來，藉此找出補環境該補哪些東西。

你在這一節只用了 get 與 set。但有些網站不是用 obj.prop 讀屬性，而是用屬性描述符（Object.getOwnPropertyDescriptor／Object.defineProperty）；有些則是代理整個函式，去攔它的呼叫或 new。下一節是一份目錄，把六個常用 trap 一次列清楚，讓你遇到哪種寫法就查對應的那一個。
