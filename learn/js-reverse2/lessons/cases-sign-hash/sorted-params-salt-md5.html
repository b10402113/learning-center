配方一：排序拼接＋salt 的 MD5 簽名（福建電子交易平台）

Step 2/5 · 案例：簽名與雜湊演算法

學習目標

照著做能在 Python 重現「排序拼接＋salt → MD5」的簽名，並讓字串化細節與 JS 完全一致。

前言：參數一改，header 裡的簽名就得重算

上一節把簽名拆成了拼接規則、金鑰、雜湊三件東西。這一節進第一種真實配方：福建電子交易平台的招標公告列表（ggzyfw.fujian.gov.cn）。它的列表介面是 POST /FwPortalApi/Trade/TradeInfo，請求體是一包十多個欄位的 JSON——頁碼、每頁筆數、地區、公告類型、起訖時間都在裡面——而請求頭裡還掛著一個 portal-sign。只要你在 Python 裡改任何一個欄位，這個 header 就得重算，否則伺服器直接把你擋下來。

它採用的正是配方家族裡最經典的一種：把參數按鍵名排序後依序拼成一行字，前面補一串固定的 salt，最後取 MD5。這個配方有個對重現者很友善的地方——欄位先排序，所以字典的鍵入順序不影響結果；也有個很折磨人的地方——排序規則、空值處理、巢狀值的字串化，每一處細節都必須跟 JS 完全一致，差一點簽名就對不上。

目標與前置條件

這一節做完，你會得到一份純 Python 的 portal-sign 產生器：丟一個參數字典進去，吐出 32 位十六進位的簽名，掛上 portal-sign 請求頭就能拿到列表資料。動手前你需要兩樣東西：一是會用 Python 的 hashlib 算 MD5（這在編碼與摘要那個節點已經練過），二是已經能在 DevTools 裡找到簽名入口、看懂 JS 大致在做什麼。金鑰（salt）會直接給你——在真實作業裡，它是你從 JS 抠出來的戰利品。

配方在 JS 端的行為

先講清楚要重現的規則。網站的簽名函式分兩層：上層負責把參數物件拼成字串，下層負責加 salt 算 MD5。拼接那層做的事是：

  1. 把參數的所有鍵不區分大小寫地由小到大排序。
  2. 依序走訪每個鍵：值如果是空的或未定義就跳過。
  3. 值如果是物件或陣列，先用 JSON.stringify 轉成字串；否則直接轉成字串。
  4. 把「鍵名＋值」一組組直接黏在一起，中間沒有任何分隔符號。

下層做的事更短：先把空字串、未定義的欄位過濾掉，接著把 salt 黏在拼接結果的前面，整段取 MD5、轉小寫十六進位。規則聽起來不複雜，魔鬼全在細節裡。下面照著做一遍。

步驟一：把這次要簽的參數字典備好

簽名永遠是「針對這一組內容」的，所以第一步是把要送出的參數準備好。列表請求的參數長這樣：

    json_data = {
        'pageNo': 2,
        'pageSize': 10,
        'total': 3228,
        'AREACODE': '',
        'M_PROJECT_TYPE': '',
        'KIND': 'GCJS',
        'GGTYPE': '1',
        'PROTYPE': '',
        'timeType': '6',
        'BeginTime': '2025-05-01 00:00:00',
        'EndTime': '2025-11-01 23:59:59',
        'createTime': '',
        'ts': now,
    }

三個欄位要留意。ts 是當下的毫秒時間戳記（now = int(time.time() * 1000)），它會參與簽名，所以每次請求的簽名都不一樣。AREACODE、PROTYPE、createTime 是空字串，等一下會被過濾掉，不會出現在簽名字串裡。BeginTime、EndTime 的鍵名第一個字母是大寫，而 pageNo 是小寫——排序時的大小寫規則就是在這種地方見真章。

步驟二：重現「排序拼接」那一層

接著把 JS 的拼接函式翻成 Python。下面這份實作逐行對應 JS 的行為：

def u(t):
    """处理字典对象，生成排序后的字符串"""

    # 自定义排序函数
    def custom_sort(x, y):
        x_str, y_str = str(x).upper(), str(y).upper()
        return 1 if x_str > y_str else 0 if x_str == y_str else -1

    sorted_keys = sorted(t.keys(), key=functools.cmp_to_key(custom_sort))
    result = ""

    for key in sorted_keys:
        if t.get(key) is not None:
            value = t[key]
            if value and isinstance(value, (dict, list)):
                result += key + json.dumps(value, separators=(',', ':'), ensure_ascii=False)
            else:
                result += key + str(value)

    return result

逐行看它在做什麼。custom_sort 把兩個鍵名都轉成大寫再比較，回傳 1、0、-1——這就是「不區分大小寫排序」的翻譯；Python 的 sorted 本身只認大小寫（大寫排在小寫前面），所以必須用 functools.cmp_to_key 把自訂比較函式包成排序用的鍵。接著 for key in sorted_keys 依排序後的順序走訪，None 值直接跳過；值是字典或陣列時用 json.dumps 轉字串，其他值用 str(value) 轉字串；最後 result += key + str(value) 把鍵名和值無分隔地黏起來。

要特別盯住 json.dumps(value, separators=(',', ':'), ensure_ascii=False) 這一行。Python 的 json.dumps 預設會在逗號和冒號後面補空白（", "、": "），JS 的 JSON.stringify 不會；ensure_ascii=False 則是為了跟 JS 一樣保留中文字元本身，而不是轉成 \uXXXX。這兩個參數少寫一個，巢狀值的字串就對不起來，簽名必錯。

步驟三：補上 salt，算出 MD5

拼接層完成後，外面那層只負責兩件事：過濾空值、加 salt 取 MD5。

def d(t, r_a):
    """主函数：处理字典并生成MD5"""
    # 过滤空值
    t = {k: v for k, v in t.items() if v not in ["", None]}

    # 生成MD5
    text = r_a + u(t)
    return hashlib.md5(text.encode('utf-8')).hexdigest().lower()

字典推導式先把值是空字串或 None 的欄位整組剔除——這就是為什麼前面 json_data 裡的 'AREACODE': '' 不會出現在簽名字串裡。接著 text = r_a + u(t) 把 salt 黏在拼接結果的前面（注意不是後面），r_a 就是從 JS 抠出來的那串金鑰。最後整段以 UTF-8 編碼後取 MD5，hexdigest() 轉成十六進位字串，.lower() 轉小寫——JS 端的 MD5 輸出就是小寫，這一行是拿來保險的。

這個站的 salt 是：

    # Python逆向的请求加密
    r_a = "B3978D054A72A7002063637CCDF6B2E5"
    sign = d(json_data, r_a)
    headers["portal-sign"] = sign

呼叫端把 json_data 和 salt 丟給 d，拿回 32 位的簽名，直接寫進請求頭 portal-sign。注意這個站的簽名放 header，不是表單欄位——每個站放的位置不同，逆向時要順手記下來。

步驟四：送出請求，驗證簽名

最後把簽好的請求送出去。因為請求體是 JSON、簽名是針對同一包 JSON 計算的，所以必須用 json=json_data 的方式送出，確保伺服器解析到的欄位值和你簽進去的一模一樣：

    response = requests.post('https://ggzyfw.fujian.gov.cn/FwPortalApi/Trade/TradeInfo', headers=headers,
                             json=json_data)

    data_encrypt_bas64 = response.json().get("Data")

驗證有兩個層次。第一層是「伺服器收不收」：簽名對了，回應裡會有 Data 欄位；簽名錯了，你會拿到錯誤訊息。第二層更嚴格：開瀏覽器 DevTools 對同一組參數抓一次請求，比對它帶的 portal-sign 和你算出來的是否完全相同——不同輸入跑兩組都一致，才算真的抓到規則，而不是剛好蒙對一次。

三個最常翻車的細節

這個配方的簽名對不上時，九成問題出在下面三處，值得先背起來：

  • JSON 字串化不一致：Python 的 json.dumps 預設帶空白、預設把非 ASCII 轉成跳脫字元；JS 的 JSON.stringify 兩者都不做。必須顯式指定 separators=(',', ':') 與 ensure_ascii=False。
  • 排序規則不一致：JS 端比較鍵名時轉了大寫，也就是不區分大小寫；Python 的 sorted 按字元碼排，「Z」排在「a」前面。少了 custom_sort 加 cmp_to_key，鍵名有大寫的站就會排序不同。
  • 空值處理不一致：空字串、None、未定義在 JS 端會被跳過或過濾；如果你把 '' 也拼進去，字串就多出一截「鍵名」。

還有一個方向性的提醒：salt 黏在前面還是後面、鍵名和值之間有沒有分隔符號、最後要不要小寫——這些全是「JS 說了算」。重現的原則只有一條：JS 怎麼拼，Python 就怎麼拼，不要憑直覺補格式。

兩條重現路線

這個案例其實示範了兩條路。一條是本節走的純 Python 重現：把 u 和 d 抄寫成 Python，用 hashlib 算 MD5。它的好處是不依賴 Node 環境、跑得快、方便併進大規模爬蟲；代價是每處字串化細節都得自己對齊。另一條路是用 execjs 直接呼叫網站的原 JS——把整段簽名 JS 編譯進去、呼叫它的簽名函式，好處是演算法保證原汁原味，代價是要多帶一個 Node 執行環境。

取捨很單純：演算法是標準的 MD5、字串化細節可控，選純 Python；演算法跟瀏覽器環境糾纏太深、或懶得逐行對齊，選 execjs。下一節的配方二會把兩條路各走一次，你會看到它們長出完全一樣的簽名。

做完長什麼樣

完成的標準很明確：給定同一包 json_data，你的 d(json_data, r_a) 吐出的 32 位十六進位，與瀏覽器對同一包參數算出的 portal-sign 完全相同；換一組 pageNo 或時間參數，兩邊同步變出同一個新簽名。掛上 header 送出請求後，回應的 Data 欄位會給你一坨 base64 密文——那是對稱加密的解密問題，留給另一個案例節點處理。

小結

「排序拼接＋salt → MD5」的配方分兩層：先把參數按鍵名不區分大小寫排序、跳過空值、巢狀值用 JSON.stringify 規格字串化、無分隔黏成一行；再把 salt 黏在前面取小寫 MD5。純 Python 重現時，三個細節決定成敗：json.dumps 的 separators 與 ensure_ascii、用 cmp_to_key 重現大小寫不敏感排序、空字串與 None 要濾掉。演算法標準就用 hashlib 自己寫，環境糾纏深就 execjs 呼叫原 JS。

配方一的排序來自「鍵名」，下一個配方的順序來自「JS 寫死的程式碼」——xdf 新東方與有道翻譯的固定順序拼接，順便處理「簽名用原始字串、送出卻要編碼」的落差。
