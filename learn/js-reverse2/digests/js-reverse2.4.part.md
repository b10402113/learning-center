# Digest — js-reverse2 (part 4)

## Overview (L1)
- The reverse-engineering toolkit — how to instrument and navigate a live JS application, not just how to read its crypto. This cluster moves from the JavaScript language ground the debugger exposes (prototype chain, property descriptors, function call objects) into three applied tools: DevTools breakpoints and call-stack reading for locating an encryption entry point, hook/Proxy instrumentation for intercepting function and property behavior, and browser-automation libraries (DrissionPage) that drive a real browser when requests-only reversing stalls.
- The through-line is *finding the entry*: given an encrypted value in a request parameter, header, or cookie, the learner learns to (a) locate the value's source via request-stack + encrypted-data tracing or keyword search, and (b) walk the call stack / set the right breakpoint type to reach the function that produced it.
- A self-contained demo (`Day21` Flask server + `book.js`) reproduces the whole loop — a client AES-signs params, the server verifies and returns paginated data — so the learner can practice crawling a target they fully understand before attacking a real site. `03 有道翻译.py` is the counterpart real-world artifact.

## Sections (L2)

### js-pre-knowledge
- Locator: `[[sources/js-reverse2/20261005/JS逆向/day08/课堂笔记/js进阶01.md]]`, `[[sources/js-reverse2/20261005/JS逆向/day08/课上代码/03 js前置知识点.js]]`
- Summary: The JavaScript language facts a reverse engineer must hold in mind when inspecting a paused page. Covers two ways to create objects (literal vs `new` constructor) and how that distinction maps onto the prototype chain; prototype objects, instance objects, `__proto__`, and how member lookup climbs inherited prototypes (with `navigator.__proto__` as a browser example). Then the `Object` toolkit used constantly in debugging: `typeof` vs `Object.prototype.toString.call`, `Object.create(window)`, `hasOwnProperty`, `getPrototypeOf`/`setPrototypeOf`, the two classes of property descriptors (data: `value/writable/enumerable/configurable`; accessor: `get/set`), and `Object.defineProperty` for installing getters/setters. Opens with PyExecJS (`execjs` compile/eval) as the Python↔JS bridge and a worked WeChat-login case where a 32-char password hash is pinpointed by global-searching `pwd:` then breakpointing to find `return P(t)` (an MD5 implementation) and reusing the Python `hashlib.md5` alternative.
- Key claims: prototype lookup climbs until found or chain ends; `User.prototype === u1.__proto__`; `typeof []` and `typeof null` both return `object` so use `Object.prototype.toString.call`; accessor and data descriptors are mutually exclusive; `writable:false` blocks assignment and `enumerable:false` hides a property from `for..in`; PyExecJS requires Node installed and runs `ctx.eval('getPwd("123456")')`; `getPwd` hashes to `96e79218965eb72c92a549dd5a330112`; breakpointing `P(t)` reveals the real hash entry.
- Learner-relevant: Can read a paused function and reason about where a method/property lives, and can deliberately install a getter/setter with `defineProperty` — the exact primitive hooks are built on. Anchors every later instrumentation technique in concrete language semantics.

### js-hook-proxy
- Locator: `[[sources/js-reverse2/20261005/JS逆向/day09/课堂笔记/js进阶02.md]]`, `[[sources/js-reverse2/20261005/JS逆向/day09/课上代码/01 hook.js]]`, `[[sources/js-reverse2/20261005/JS逆向/day09/课上代码/02 proxy代理.js]]`
- Summary: Two instrumentation mechanisms for finding where a value is produced/consumed. **Hook**: save the original function/property (`_add = add`) then reassign a wrapper that logs args and return value before/after delegating to the original — works on plain functions and on object properties via `Object.defineProperty` get/set (including properties that don't exist yet). Applied live in the browser: open a blank page, enable the Scripts event listener, visit the target so execution pauses before page code runs, then paste the hook into the Sources **Snippets** pane, set a breakpoint, run it, and disable the event listener without refreshing. Demonstrated on browser-native `atob` (base64 decode) and on `document.cookie`. **Proxy**: wrap an object in `new Proxy(target, handler)` and intercept `get`/`set`, `getOwnPropertyDescriptor`, `defineProperty`, `apply` (function calls), and `construct` (`new`), delegating to `Reflect.*`; used to detect reads of missing properties (e.g. a `window.xxx` the page expects) and thus identify what to "patch" into the environment.
- Key claims: hooks must be installed *after* the original is defined; hooking atob requires pausing before page scripts load and never refreshing; native functions print as `[native code]`; sites detect hooks by comparing `atob.toString()` before/after (`Function.prototype.toString.call(atob)` defeats instance-level override, so you must also override `Function.prototype.toString`) — bypass returns `function ${this.name}() { [native code] }`; `getOwnPropertyDescriptor` and `defineProperty` traps catch property-descriptor-based access; `apply` sees `(target, thisArg, argList)`, `construct` sees `(target, argArray, newTarget)`.
- Learner-relevant: Can intercept a suspected encryption/signing function or a native API to capture its inputs/outputs at runtime, and can recognize and defeat the common `toString` hook-detection guard. Anchors the debugging workflow when static reading fails.

### drissionpage-automation
- Locator: `[[sources/js-reverse2/20261005/JS逆向/day10/课堂笔记/详细教程.md]]`, `[[sources/js-reverse2/20261005/JS逆向/day10/课上代码/06 Chromiumpage详解.py]]`, `[[sources/js-reverse2/20261005/JS逆向/day10/课上代码/05 模式切换实例.py]]`, `[[sources/js-reverse2/20261005/JS逆向/day10/课上代码/03 DrssionPage登录码云盘平台.py]]`, `[[sources/js-reverse2/20261005/JS逆向/day10/课上代码/04 DrssionPage爬取码云首页的库名以及链接.py]]`, `[[sources/js-reverse2/20261005/JS逆向/day10/课上代码/test.html]]`
- Summary: DrissionPage is a Python web-automation library that unifies an automated Chromium browser with a `requests`-style session. Three page classes: `ChromiumPage` (browser control), `SessionPage` (packets only), `WebPage` (both, plus `change_mode()` to switch). Covers install, setting the browser executable path (`ChromiumOptions().set_browser_path(path).save()` or `dp -p ...`), starting/attaching to a browser on a port (default 9222; `ChromiumPage(8888)` attaches to a running instance), and multi-browser coexistence via distinct `local_port` + `user_data_path`. Page actions: `get/back/forward/refresh/run_js/run_js_loaded/scroll.to_bottom`. Its bespoke element locators: `ele` (first) vs `eles` (all); `@id=one`, `@text()=`, `@@`-anded conditions, `@|`-or, `:` contains, `^` prefix, `$` suffix; CSS-style `#id`, `.class` (with `=`,`:`,`^`,`$`), `text=`, `tag:`, and `xpath:`. Element info via `html/inner_html/tag/text/texts()/attrs/attr()/link/xpath` and the list helper `eles.get.texts()/links()/attrs()`. `SessionPage` mirrors requests `get`/`post` (params/headers/cookies/data/proxies, ret/mime auto UA from an ini), returning bool, with `url/title/raw_data/html/json` attributes. The mode-switch pattern handles login-gated sites: drive the browser to log in, then switch to packet mode and fetch the authenticated page.
- Key claims: `change_mode()` re-visits the current URL in the new mode; login-flow tip — log in with ChromiumPage then crawl with SessionPage; `ele()` has built-in 10s wait; server-user login case requires reversing the password cipher first, then `SessionPage` after the browser login; element lists support `.get.texts()/.links()/.attrs()`; `tag:h3` then child `item('tag:a')` for nested extraction.
- Learner-relevant: Can automate a real browser to bypass login/anti-bot and then switch to fast packet crawling, and can locate elements with DrissionPage's compact syntax. Anchors the "use a browser when requests-only fails" decision.

### devtools-breakpoints-callstack
- Locator: `[[sources/js-reverse2/20261005/Day22/01 断点和请求堆栈.html]]`, `[[sources/js-reverse2/20261005/Day21/10 JS的断点.js]]`, `[[sources/js-reverse2/20261005/Day21/09 断点应用.py]]`
- Summary: Breakpoint mechanics and call-stack reading, taught with a chain of nested functions (`test01 → test02 → encrypt → test03 → test04 → test05 → test06`) where only `test02`/`test06` touch the encrypted payload. The HTML demo (bearing an `onclick`) plus the tiny `JS的断点.js`/`断点应用.py` scripts (a variable assignment followed by `console.log`) are minimal, inspectable stand-ins for setting a line breakpoint and stepping. Combined with the reverse-tips locator, the workflow is: identify the encrypted value → set a breakpoint at the suspected line → trigger the action → when execution pauses, read the **Call Stack** panel to see the caller chain and the arguments in each frame → step in/out and watch the argument that flows between frames → set the breakpoint upstream at the true encrypt function. The event-listener (Scripts) breakpoint is used to pause before page code executes (also the hook timing in `js-hook-proxy`).
- Key claims: reading the call stack tells you *which caller* supplied the input and in what order frames ran; stepping across frames reveals where the value changes; `test02` produces `encrypt_data` then passes it down to `test06` where the AJAX send happens; the event-listener breakpoint is what lets you pause pre-page-load; line/keyword/pause-on-XHR breakpoints are chosen by where the value is known to exist.
- Learner-relevant: Can set a breakpoint, trigger it, and read the call stack to trace an encrypted value back to its producing function. Anchors the core DevTools loop that all later reversing depends on.

### js-encryption-demo-server
- Locator: `[[sources/js-reverse2/20261005/Day21/server/Server.py]]`, `[[sources/js-reverse2/20261005/Day21/server/static/book.js]]`, `[[sources/js-reverse2/20261005/Day21/server/templates/index.html]]`, `[[sources/js-reverse2/20261005/Day21/demo/server/myServer.py]]`, `[[sources/js-reverse2/20261005/Day21/demo/server/static/book.js]]`, `[[sources/js-reverse2/20261005/Day21/demo/js加密.js]]`, `[[sources/js-reverse2/20261005/Day21/08 自己爬虫自己.py]]`
- Summary: A runnable client/server pair implementing the classic "signed request" pattern for practice (爬虫爬自己). The Flask server (`Server.py`/`myServer.py`) exposes `/books`; it pops the `sign` query param, base64-decodes it, AES-CBC-decrypts with a hardcoded 16-byte key `0123456789abcdef` and IV `1234567890abcdef`, unpads, JSON-parses, and checks the decrypted dict equals the remaining query params (`verify_sign`) — otherwise returns `["非法入侵!"]`. The browser (`book.js`) builds `params = {page, [cate]}`, stringifies, AES-128-CBC/PKCS7-encrypts with CryptoJS using the same key/IV, base64-encodes the ciphertext as `sign`, and sends it via `$.ajax`; `index.html` wires page buttons and loads jQuery + crypto-js. The attacker side, `08 自己爬虫自己.py`, progresses through three versions: v1 plain `requests.get` (no sign, rejected), v2 replay a captured `sign` (works once), v3 replicate the AES-CBC + base64 in Python to generate a fresh valid `sign` per page — i.e. the full reverse. `js加密.js` holds the CryptoJS snippet (AES config commented; active MD5 example) used as the crypto reference.
- Key claims: server returns `["非法入侵!"]` when `verify_sign` fails; key and IV are literally `'0123456789abcdef'`/`'1234567890abcdef'` (16 bytes, IV is *not* random and is not transmitted — a classic weakness); v2 replaying a fixed sign is defeated by changing `page`; v3 uses `Crypto.Cipher.AES` MODE_CBC + `pad(...,16)` + `base64.b64encode` to match CryptoJS; pagination differs (`*4` in Server.py, `*3` in myServer.py).
- Learner-relevant: Can reproduce a signed-request scheme end-to-end in code and understand why static/random IVs and exposed keys are exploitable. Anchors the real-target work by giving a fully-legible reference implementation.

### reverse-workflow-tips
- Locator: `[[sources/js-reverse2/20261005/Day22/02 关于逆向爬虫的技巧]]`, `[[sources/js-reverse2/20261005/Day22/03 有道翻译.py]]`
- Summary: A compact decision procedure for locating the encrypted value's origin. Step 1 — *where is the value*: query/form data, request headers, or cookie. Step 2 — *how to find its entry point*: Method 1 is **request stack + encrypted data** (find the request in the Network panel, use the initiator/request stack to jump to the JS that sent it, then trace back to where the value was built); Method 2 is **keyword search**, using related keys, the URL path, and sensitive tokens such as `md5`, `sha1`, `encrypt`, `decrypt`, `JSON.stringify`, `JSON.parse`. The Youdao translation script is the worked artifact: a captured POST to `https://dict.youdao.com/webtranslate` with `i=apple` and `sign`, `client=fanyideskweb`, `mysticTime`, `keyfrom` params, exactly the fields (`sign`, `mysticTime`) a reverse engineer must regenerate from the site's JS.
- Key claims: entry-point search has exactly two families (request-stack tracing, keyword search); sensitive keywords to grep include `md5/sha1/encrypt/decrypt/JSON.stringify/JSON.parse`; the encrypted value may live in data/form, headers, or cookies; the Youdao request is form-urlencoded with a `sign` and a timestamp-like `mysticTime` that must be reconstructed.
- Learner-relevant: Can systematically locate the encrypt function on an unfamiliar site and know which request fields are dynamic and need regeneration. Anchors every real-site task as the first move after opening DevTools.
