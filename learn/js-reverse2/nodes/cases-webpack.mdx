# 案例：webpack 打包站實戰

## Learning goal

對真實 webpack 站台載入 loader＋module、補環境、印模組 id，定位並呼叫簽名／加解密入口。

## Steps

1. [[learn/js-reverse2/nodes/cases-webpack/sichuan-webpack-full-loop|四川补贴：跑通一個多檔 webpack 站的完整流程]] — 載入 loader＋模組檔、補環境、印模組 id，呼叫 dd88 的 b/c/a 取得加密參數與簽名
2. [[learn/js-reverse2/nodes/cases-webpack/cailianshe-sign-entry|财联社：在真實 loader 插探針、呼叫 W2Yj 簽名模組]] — 讀懂自帶 try/finally 快取管理的 loader，鎖定並呼叫簽名模組（after step 1）
3. [[learn/js-reverse2/nodes/cases-webpack/womail-rsa-entry|沃邮箱：鎖定登入加密模組 437 並呼叫加密]] — 在登入 bundle 裡用探針找到 437，呼叫 encrypt／hashPassword（after step 1）
4. [[learn/js-reverse2/nodes/cases-webpack/real-bundle-call-shapes|真實站點對照：loader 變形與模組匯出形狀]] — 四站 loader 變形與匯出呼叫形狀的對照表，接到新站對號入座（after steps 2–3）
5. [[learn/js-reverse2/nodes/cases-webpack/reuse-vs-reimplement|抉擇：呼叫原 bundle 還是用 Python 重寫？]] — 兩條路的判準、取捨與失效邊界（after step 4）

## Lesson

在教學範例裡，webpack 的 loader 是刻意簡化過的：一個 require 函式、一袋模組、一個印模組 id 的探針。真實站台的打包檔骨架一模一樣，但外衣各有不同——有的把簽名模組藏在好幾個檔案的 JSONP 佇列裡，有的 loader 自己管理模組快取，有的把登入加密模組跟整包第三方函庫綁在同一份 bundle。外衣再怎麼變，工作項目不變：先把 loader 與模組檔照順序載進 Node、補上它會讀到的瀏覽器環境、在 require 函式裡插一行探針印出模組 id，最後用 id 呼叫那個藏著簽名與加解密的模組。

這個節點用四個真實案例把這套流程各跑一次，每一個案例都多給你一塊拼圖。四川补贴是多檔 webpack 的完整版：loader 先把 `webpackJsonp` 的 callback 裝好，兩個模組檔再把幾千個模組推進來，簽名模組 dd88 以三個方法匯出——b 加密請求參數、c 產生簽名、a 解密回應，三個呼叫構成完整的請求循環。财联社的 loader 把探針插在自己的 try/finally 快取管理裡，簽名模組 W2Yj 匯出的是一個可直接呼叫的函式。沃邮箱的 loader 精簡得多，登入加密藏在數字模組 437 裡，公鑰參數就硬編碼在呼叫端。aerfa 則把最後一塊拼圖補上：同一個簽名演算法，一邊是十行就能讀懂的獨立小檔，另一邊是幾萬行的打包檔——你可以自己翻譯成 Python，也可以直接呼叫 bundle 裡的模組。

四個案例走完，你手上有的不是四套零散的技巧，而是一份對任何 webpack 打包站都適用的作業流程，外加一個每次都要面對的抉擇：這個演算法值得呼叫原 bundle，還是乾脆用 Python 重寫？簽名與加密演算法本身的拆解交給前面的案例節點；這個節點練的是呼叫層的手感——loader 怎麼讀、探針插哪裡、模組 id 怎麼找、匯出形狀怎麼認，以及什麼時候該換一條路走。
