# 案例：對稱與串流加解密

## Learning goal

從響應／請求中的 base64 還原對稱加解密（AES/DES/SM4/RC4，含 padding 與 key==iv），並處理 URL-safe、加引號等傳輸變體。

## Steps

1. [[learn/js-reverse2/nodes/cases-symmetric-body/spot-encrypted-payload|認出密文在哪裡：整段 base64、欄位 base64 與傳輸變體]] — 判斷密文藏在響應的哪個位置，並把各種 base64 傳輸變體還原成乾淨的密文位元組
2. [[learn/js-reverse2/nodes/cases-symmetric-body/aes-cbc-decrypt-rebuild|用 Python 重現 AES-CBC 解密：Pkcs7 與 ZeroPadding]] — 用 pycryptodome 把 AES-CBC 解密寫出來，並處理兩種填充（after step 1）
3. [[learn/js-reverse2/nodes/cases-symmetric-body/recover-key-iv-forms|key 與 iv 的三種藏法：words 陣列、MD5 派生、key==iv]] — 從 JS 還原被藏起來的 key 與 iv（after step 2）
4. [[learn/js-reverse2/nodes/cases-symmetric-body/des-and-rc4-variants|不是 AES 的對稱加密：DES／ECB 與 RC4 串流]] — 認出 DES 與 RC4 兩種非 AES 的管線並各自重現（after step 2）
5. [[learn/js-reverse2/nodes/cases-symmetric-body/encrypt-request-decrypt-response|加密請求 body、解密響應：一次跑通完整對]] — 打通請求加密與響應解密的完整迴圈，注意兩個方向的 key 不同（after step 3）

## Lesson

真實站台的加解密很少長得跟課本一樣。你打開 DevTools 看到的往往不是明文 JSON，而是一串看不懂的 base64；等你真的把 JS 裡的算法翻出來，又會發現 AES 只是起點——填充有 Pkcs7 與 ZeroPadding 之分，key 被藏成整數陣列或 MD5 摘要，有的站連請求 body 都要先加密才能送，甚至演算法根本不是 AES，而是 DES 或 RC4 串流。

這個節點用五個真站案例，把「對稱加解密還原」整條流程走熟：先認出密文藏在哪、把傳輸變體洗乾淨；再用 Python 把 AES-CBC 解密重現出來；接著對付三種藏 key/iv 的手法；然後看 DES 與 RC4 這兩種非 AES 的分支；最後打通「加密請求、解密響應」的完整對。五步走完，你手上會有一套固定動作：認密文 → 還原參數 → Python 重現 → 驗收，任何對稱加密的 body 都能照這個順序拆。
