# requests 入門與動態資料定位

## Learning goal

用 `requests` 抓 HTML/JSON/圖片，修正編碼、偽裝 UA，並從封包分析定位動態（XHR）資料的 URL 與參數。

## Steps

1. [[learn/js-reverse2/nodes/requests-basics/send-first-request|第一支 requests：GET、響應物件與存檔]] — 用 `requests.get` 完成第一次抓取，讀懂響應物件與四步流程的程式碼對應
2. [[learn/js-reverse2/nodes/requests-basics/encoding-and-headers|亂碼還是被擋？編碼修正與 UA 偽裝]] — 判斷亂碼或內容不對是編碼問題還是身份問題，分別修正（after step 1）
3. [[learn/js-reverse2/nodes/requests-basics/params-vs-data|參數放哪裡：params 查詢字串與 data 表單]] — 分辨參數交給 `params` 還是 `data`，正確送出 GET 查詢與 POST 表單（after step 1）
4. [[learn/js-reverse2/nodes/requests-basics/locate-dynamic-data|從封包定位動態資料：抄 URL 與參數重放]] — 用全域搜尋找出來源請求，補 `Referer` 重放並解 JSON（after steps 2–3）
5. [[learn/js-reverse2/nodes/requests-basics/download-binary-images|抓圖片與二進位：content 與 urlretrieve]] — 用 `response.content` 與 `urlretrieve` 存下二進位檔案，依型別選對取值方法（after step 1）

## Lesson

這個節點把上一張地圖收斂成手上的工具。前面你已經知道爬蟲的骨架是「指定 URL、發送請求、取得響應、持久化」四步，也知道了網站會從好幾個地方卡你；現在要真的把 `requests` 拿起來，一次又一次地把資料抓下來，並且在抓不到時知道問題出在哪一格。

整條線是這樣走的：先用最小的一支 GET 把四步流程跑通，看清 `requests.get` 回傳的響應物件長什麼樣；接著處理兩個最常見的「回應不對」——一種是中文變亂碼，問題出在編碼，改 `response.encoding`；一種是內容明顯不是你要的，問題出在網站認不得你，補上 `headers` 裡的 `User-Agent`。這兩件事都在修同一個第三步的輸入。再來是參數該放哪裡：已知端點時，GET 查詢字串交給 `params`、POST 表單交給 `data`，這是多數請求的兩種基本型態。然後是這個節點真正的重點：當資料不在網址列那個回應裡，要用抓包工具的全域搜尋把來源請求找出來，抄下它的 URL 與參數，補上 `Referer` 重放，才能拿到那份 JSON。最後把視野擴到二進位：圖片、影片、壓縮檔要改用 `response.content` 與 `urlretrieve`，並依回應型別決定用 `.text`、`.json()` 還是 `.content`。

把這五步串起來，你就有了一套能抓 HTML、JSON、圖片的完整手法；接下來的 XPath 解析與 Session 維持，都是站在這套手法上往外長。
