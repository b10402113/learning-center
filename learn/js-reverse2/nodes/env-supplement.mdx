# 補環境與環境檢測

## Learning goal

用 Proxy 監測缺口、補上八個前端物件與 `toString` 標籤，通過「是不是瀏覽器／是不是 Node」檢測，並理解瑞數 cookie 流程。

## Steps

1. [[learn/js-reverse2/nodes/env-supplement/why-node-breaks|瀏覽器 JS 搬進 Node 就壞掉：window 與 global 的分岔]] — 說出搬移失敗的兩個根因，認出補環境要解決的正是這件事
2. [[learn/js-reverse2/nodes/env-supplement/proxy-gap-detection|用 Proxy 監控缺口：讓程式自己說它缺什麼]] — 用 setProxyArr 批次代理 BOM／DOM，從日誌列出要補的屬性（after step 1）
3. [[learn/js-reverse2/nodes/env-supplement/eight-frontend-objects|八大前端物件：要補的成員與 toString 標籤]] — 依日誌補上八個物件的成員、對齊別名並偽造 className 標籤（after steps 1–2）
4. [[learn/js-reverse2/nodes/env-supplement/env-check-strategies|兩種環境檢測：證明我是瀏覽器、不是 Node]] — 分辨「是不是瀏覽器」與「是不是 Node」兩類檢測並選對破解（after steps 1、3）
5. [[learn/js-reverse2/nodes/env-supplement/rs-cookie-flow|瑞數 cookie 流程：兩次請求與三個動態輸入]] — 講出 rs 的兩次請求、cookie1／cookie2 與 meta／ts／自執行函式三要素的角色（after steps 3–4）

## Lesson

逆向走到「把網站的加密 JS 搬回本機跑」這一步，第一個迎面而來的牆就是：那段程式碼在瀏覽器裡好好的，一放到 Node 就報錯。原因不是演算法寫錯，而是它隨手用了只有瀏覽器才有的東西——`window`、`document`、`navigator`、各種事件與計時器。所謂「補環境」，就是在 Node 裡把這些前端物件補到「夠用」為止，讓那段程式碼以為自己仍在瀏覽器中。

這個節點沿著一條真實的工作線走：先看清楚為什麼會壞，學會用 `Proxy` 對整個 `window`／`document` 掛代理、把所有讀寫記下來，讓程式自己告訴你「我缺了哪些屬性」；再照著一份可查的清單（八大前端物件）把這些缺口補上，同時把 `toString` 這個最常被拿來檢查的標籤偽造正確。補完不代表過關——網站還會主動做「環境檢測」，於是你得分清楚它問的是「你是不是瀏覽器」還是「你是不是 Node」，並選擇對應的破解。最後把整套流程放進瑞數這個代表性案例：兩次請求、一組 `cookie1`／`cookie2`，以及 `meta`、`ts`、大自執行函式三個每次都會變的動態輸入。

走完之後，你手上就有一套可重複的補環境迴圈：代理監控 → 補成員 → 過檢測 → 取回真正要的 cookie。
