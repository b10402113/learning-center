# DevTools：斷點、請求堆疊與呼叫堆疊

## Learning goal

給定一個加密參數，用請求堆疊／關鍵字搜尋定位入口，設對斷點並讀呼叫堆疊追回產生它的函式。

## Steps

1. [[learn/js-reverse2/nodes/devtools-trace/value-location|逆向值放在哪：資料、請求頭與 Cookie]] — 先確認要找的加密值出現在請求的哪個位置
2. [[learn/js-reverse2/nodes/devtools-trace/entry-search-methods|入口怎麼找：請求堆疊追蹤與關鍵字搜尋]] — 在兩條定位入口的方法之間選一條（after step 1）
3. [[learn/js-reverse2/nodes/devtools-trace/breakpoint-types|斷點怎麼下：行、事件監聽與 XHR 斷點]] — 依值的產生時機選對斷點種類（after step 2）
4. [[learn/js-reverse2/nodes/devtools-trace/call-stack-reading|讀呼叫堆疊：從暫停點追回加密函式]] — 斷點命中後讀 Call Stack、step 進出，追回產生值的函式（after step 3）
5. [[learn/js-reverse2/nodes/devtools-trace/youdao-walkthrough|整套跑一遍：有道翻譯 sign 與 mysticTime 的定位]] — 對真實請求標出動態欄位並規劃如何定位（after steps 2、4）

## Lesson

這個節點要處理的是「我已經知道某個請求裡有個看不懂的加密參數，但我不知道它是誰算出來的」這個處境。你手上有的是開發者工具（DevTools）和一個被保護的請求，目標是把產生那個值的 JavaScript 函式找出來——這是所有後續還原工作的第一步，也是整個逆向流程卡住時最常回頭補的一課。

五步的順序對應真實操作時的五個念頭。先問「值在哪裡」（step 1），因為加密值可能躲在請求資料、請求頭或 Cookie 三個位置，位置不同，之後的追法也不同。接著問「入口怎麼找」（step 2），這裡有兩條路——沿請求堆疊往回追，或直接關鍵字搜尋，取決於你手上握有多少線索。找到疑似位置後，得決定「斷點怎麼下」（step 3）：行斷點、事件監聽斷點、XHR 斷點、關鍵字斷點各有它該出場的時機。斷點命中、程式暫停之後，就是核心動作——「讀呼叫堆疊」（step 4），順著呼叫鏈和參數流找回真正的加密函式。最後用有道翻譯這個真站（step 5）把整條流程跑一遍，標出 `sign` 與 `mysticTime` 這類必須自己重現的動態欄位。

寫在前面：這個節點練的是**手法**，不是特定加密演算法。等到後面的案例節點要還原某個網站的簽名時，你會反覆回到這五步來找入口。
