# asyncio 與 aiohttp 非同步爬蟲

## Learning goal

寫出多任務非同步爬蟲，說清楚 `await` 該放哪，以及哪些同步模組會破壞非同步效果。

## Steps

1. [[learn/js-reverse2/nodes/async-crawler/coroutine-why-it-matters|協程：單執行緒也能跑的併發]] — 說出協程解決了多執行緒／多行程的什麼痛點，以及它為什麼快
2. [[learn/js-reverse2/nodes/async-crawler/asyncio-run-skeleton|asyncio 起手式：特殊函數、任務與事件循環]] — 用 `async def`、`ensure_future`、事件循環把協程跑起來並取回傳值（after step 1）
3. [[learn/js-reverse2/nodes/async-crawler/await-and-blocking-traps|await 放哪、哪些模組會拖垮非同步]] — 判斷 `await` 的位置、`asyncio.wait` 的角色，認出會破壞非同步的同步模組（after step 2）
4. [[learn/js-reverse2/nodes/async-crawler/aiohttp-multitask-crawler|aiohttp 多任務非同步爬蟲]] — 用 `aiohttp` 寫出多任務爬蟲並用回調解析頁面（after step 3）

## Lesson

這個節點要把「非同步」從一個聽起來很玄的詞，變成一隻你真的寫得出來、跑得快的爬蟲。上一課你已經弄清楚行程、執行緒與協程的差別，也知道爬蟲是典型 IO 密集工作——大部分時間都花在等網路回覆，而不是算東西。這一課要接著問：那要怎麼把「等待」的時間拿去抓別頁？

答案就是協程加上 `asyncio`。整條線這樣走：先建立一個直覺——作業系統調度執行緒時，你不確定下一次會切到誰，而協程把「切換」的主導權交還給你的程式；有了這個前提，第二步才進入 `asyncio` 的四個零件，把一段 `async def` 從協程物件、任務、事件循環一路跑到 `run_until_complete`。接著是這個節點最容易踩雷的地方：光有協程框架還不夠，阻塞操作前忘了加 `await`、或函式裡混進 `time.sleep`、`requests` 這類同步模組，整個非同步效果就會悄悄失效，所以第三步專門處理「`await` 該放哪、哪些東西不能放進來」。最後一步把這些零件換成真正的網路請求模組 `aiohttp`，寫出多任務爬蟲，並用任務回調把抓回來的 HTML 交給 `lxml` 解析。

走完之後，你手上就有一套能同時抓多個頁面的寫法。這套寫法在後面的 Scrapy 非同步引擎、以及需要高併發下載的場景（例如 M3U8 分片）都會再遇到。
