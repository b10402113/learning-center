# 爬蟲、反爬與逆向的全貌

## Learning goal

畫出「抓取 → 反爬 → 逆向」的整體地圖，說明爬蟲分類、合法性／robots、四步流程，並解釋「抓不到資料＝模擬瀏覽器不足」這個病根。

## Steps

1. [[learn/js-reverse2/nodes/crawler-anticrawl-map/what-is-a-crawler|爬蟲是什麼：為什麼它一定要「模擬瀏覽器」]] — 說明爬蟲的定義與五種應用分類
2. [[learn/js-reverse2/nodes/crawler-anticrawl-map/legality-and-robots|爬蟲的邊界：robots 協議與合法性]] — 分辨 robots 的性質與三類法律風險（after step 1）
3. [[learn/js-reverse2/nodes/crawler-anticrawl-map/crawl-flow-four-steps|抓取的四步流程：從 URL 到存檔]] — 用四步寫出最小爬蟲，並定位動態資料（after step 1）
4. [[learn/js-reverse2/nodes/crawler-anticrawl-map/anticrawl-map|反爬手段地圖：每一招卡在四步流程的哪裡]] — 認得常見反爬手段與其卡點（after step 3）
5. [[learn/js-reverse2/nodes/crawler-anticrawl-map/reverse-necessity|病根與出路：抓不到資料＝模擬瀏覽器不足]] — 收斂抓取→反爬→逆向的整體地圖（after steps 3–4）

## Lesson

這個節點要給你的不是一招半式，而是一張地圖。整門課後來會鑽進 requests、Scrapy、XPath、密碼學、DevTools、webpack、補環境，每一塊都很深；但如果腦中沒有「我現在站在哪一步、下一塊為什麼需要」，學到的技巧就會變成散落一地的工具。這五步先把「抓取 → 反爬 → 逆向」的整條線串起來。

先把主角定義清楚：爬蟲就是一支程式，模仿瀏覽器去網路上抓資料，而它模仿得像不像，直接決定抓不抓得到。接著處理兩件容易被忽略的邊界：一是法律與 robots 協議——robots 是給爬蟲遵守的君子協議，不是技術封鎖；二是抓取的通用骨架，也就是指定 URL、發送請求、取得響應、持久化這四步。有了骨架，才看得懂反爬是在哪一步動手腳：UA 檢測、Referer 防盜鏈、Cookie、頻率限制、驗證碼、動態渲染、參數加密，每一種都對應到四步裡的某個環節。最後一步把這些防守收攏成一個病根——只要抓不到想要的資料，幾乎都可以歸因於「模擬瀏覽器的力度不夠」，而當模擬再怎麼調整都補不上時，就輪到逆向上場了。
