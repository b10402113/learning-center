# Web、HTTP 與 HTML：爬蟲在跟什麼打交道

## Learning goal

讀得懂一個原始 HTTP request/response（方法、標頭、狀態碼），說得出 Cookie 為何能維持狀態，並認得爬蟲之後要解析的 HTML 標籤。

## Steps

1. [[learn/js-reverse2/nodes/web-http-html-basics/web-architecture-basics|B/S 架構與 HTTP：爬蟲為什麼要模擬瀏覽器]] — 說出 B/S 架構與爬蟲的關係，以及 HTTP 的請求-響應與無狀態
2. [[learn/js-reverse2/nodes/web-http-html-basics/http-message-anatomy|拆開一個 HTTP 報文：請求行、標頭與狀態碼]] — 看懂請求與回應報文的結構、標頭角色、GET 與 POST 差異（after step 1）
3. [[learn/js-reverse2/nodes/web-http-html-basics/cookie-and-state|Cookie 與狀態：無狀態的 HTTP 怎麼記住你]] — 解釋 Cookie 為何能維持登入狀態與它的限制（after step 2）
4. [[learn/js-reverse2/nodes/web-http-html-basics/html-document-tags|HTML 文件與標籤：爬蟲要解析的對象]] — 認得 HTML 骨架與常用標籤，知道往哪裡取值（after step 1）

## Lesson

這個節點是整條逆向路線的地基。往後不管你要抓的是普通網頁、動態載入的 JSON，還是加密過的簽名參數，最後都會回到同一件事：客戶端用 HTTP 把請求送到伺服器，伺服器用 HTTP 把結果送回來。所以第一步不是學工具，而是先看懂這條通道本身——一個請求長什麼樣子、一個回應長什麼樣子、兩邊靠哪些標頭溝通。

看懂通道之後，還有兩個繞不開的觀念。第一，HTTP 本身記不住任何事，每次請求對伺服器來說都像初次見面；是 Cookie 這種由伺服器發、存在瀏覽器裡的小紙條，才讓「登入狀態」得以延續。第二，伺服器送回來的主體通常是一份 HTML 文件，你之後能抓到什麼欄位，取決於你有沒有認出資料被包在哪個標籤或哪個屬性裡。

四步走完後，你會具備讀懂原始請求和回應、說明 Cookie 的作用，以及在 HTML 裡指出資料位置的能力。這些都是純觀念，但你之後每一次用 DevTools 看封包、用 requests 重放請求、用 XPath 取欄位，都會反覆用到它們。
