# 案例：非對稱（RSA）

## Learning goal

從 bundle 取出公鑰／私鑰 PEM 與演算法參數，重現 RSA 加密與 RSA-SHA256 簽章，並判斷「私鑰在前端」的失效模式。

## Steps

1. [[learn/js-reverse2/nodes/cases-asymmetric/recognize-rsa-in-bundle|認出 bundle 裡的 RSA：鑰匙形態與呼叫特徵]] — 分辨 RSA 加密與簽章、認出 PEM 與 modulus+exponent 兩種鑰匙形態
2. [[learn/js-reverse2/nodes/cases-asymmetric/waimao-rsa-oaep|外貿電商平台：RSA-OAEP 公鑰加密重現]] — 抽出公鑰 PEM，重現 OAEP 加密與 base64 包裝（after step 1）
3. [[learn/js-reverse2/nodes/cases-asymmetric/womail-rsa-password|沃郵箱：登入密碼的 RSA 加密重現]] — 抽出 modulus/exponent，重現密碼加密與 #! 包裝（after step 1）
4. [[learn/js-reverse2/nodes/cases-asymmetric/licaiwang-rsa-sign|理財網：RSA-SHA256 簽章重現]] — 重現簽章流程、對齊 JSON 序列化、放進 signature header（after step 1）
5. [[learn/js-reverse2/nodes/cases-asymmetric/private-key-in-frontend|抉擇：私鑰在前端的失效模式與重現路線]] — 判斷保護真正擋住了什麼，選擇重現路線（after steps 2–4）

## Lesson

非對稱加密在真站上以兩種任務出現：一種是拿公鑰把要送出的內容加密，讓伺服器用私鑰解開（外貿電商平台的 RSA-OAEP 請求加密、沃郵箱的登入密碼加密）；另一種是拿私鑰替請求簽章，讓伺服器用公鑰驗證內容沒被改過（理財網的 RSA-SHA256 signature header）。兩種任務的重現手法一致——先認出鑰匙形態（PEM 或 modulus＋exponent）與演算法參數（OAEP 的雜湊與 MGF1、SHA256withRSA 這類簽章配方），再用 Python 或重用 bundle 內建的加密庫把結果算出來。三個案例走完，最後收斂到一個判斷：鑰匙放在前端就不再是祕密——理財網把私鑰打包進 bundle，等於把簽章能力送給每一個讀者，這層保護只能擋住不會逆向的人。
