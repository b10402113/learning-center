# 行程、執行緒與協程：併發為何存在

## Learning goal

用單核排程說明併發／平行、同步／非同步，並選對 Process／Thread／Pool／協程來加速 IO 密集的爬取。

2. [[learn/js-reverse2/nodes/concurrency-model/concurrency-and-async|一次只做一件事：單核排程、併發與非同步]] — 用單核與時間片輪轉解釋併發／平行、行程狀態與同步／非同步（after step 1）

4. [[learn/js-reverse2/nodes/concurrency-model/thread-and-threadpool|執行緒與執行緒池：threading.Thread 與 Pool.map]] — 用執行緒與執行緒池平行化 IO 任務，掌握共享記憶體與等待（after step 3）

## Lesson

爬蟲慢，通常不是電腦不夠快，而是程式把大部分時間花在等待：等伺服器回應、等下載完成。這一節要處理的正是「等待」——當一個請求卡住，怎麼讓程式不傻等，轉頭去做下一件事。

要講清楚這件事，得先有兩個心智模型。第一個是行程與執行緒的關係：一個程式跑起來就是一個行程，行程裡可以有多個執行緒，而執行緒之間共享同一塊記憶體、行程與行程之間則彼此隔離。第二個是單核排程：一顆核心同一時刻只能執行一個任務，我們看到的「同時」其實是作業系統用時間片輪轉快速切換出來的。有了這兩個模型，「併發是偽同時、平行才要真多核」「同步是遇到阻塞就停下來等、非同步是遇到阻塞就切去做別的」這兩句話才有根。

模型講完，接著落到 Python 的四種做法。先開真正的子行程（`multiprocessing.Process`），親眼看到它怎麼產生非同步效果、`join` 怎麼讓主行程等子行程，以及為什麼子行程改了全域變數、主行程卻看不到（資料隔離）。再把鏡頭轉到執行緒：用 `threading.Thread` 做同樣的事，但這次共享記憶體會生效，還要認識執行緒池 `Pool(5).map` 如何省下反覆建立執行緒的開銷。最後一步是收斂成選擇：面對一批 IO 密集的爬取任務，什麼時候該用行程、什麼時候用執行緒或執行緒池，而協程又為什麼能在單執行緒下把效率再往上推一層。

走完這五步，你不只會寫這幾段程式，更重要的是知道每一種寫法各自的代價在哪裡——這正是下一步 `asyncio` 與 `aiohttp` 之所以存在的原因。
