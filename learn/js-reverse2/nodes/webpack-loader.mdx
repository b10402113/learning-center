# webpack 拆解與模組定位

## Learning goal

判斷 bundle 型態（陣列／物件／多檔 JSONP）、暴露 `require` 函式、以模組 id 記錄定位並呼叫簽名模組。

## Steps

1. [[learn/js-reverse2/nodes/webpack-loader/webpack-loader-anatomy|webpack bundle 的骨架：IIFE、require 函式與快取]] — 看懂最外層 IIFE、內部的 require 函式與模組快取，並認出 `window.loader` 這把逆向把手
2. [[learn/js-reverse2/nodes/webpack-loader/classify-bundle-shape|判斷 bundle 型態：陣列、物件與多檔 JSONP]] — 一眼分辨手上這份打包檔屬於哪一型、模組 id 長什麼樣（after step 1）
3. [[learn/js-reverse2/nodes/webpack-loader/expose-loader-log-module-id|暴露 require 函式並記錄模組 id]] — 接上 `window.loader`、插 `console.log` 記錄模組 id，再逐一呼叫以鎖定簽名模組（after steps 1–2）
4. [[learn/js-reverse2/nodes/webpack-loader/run-multifile-bundle-in-node|在 Node 跑多檔 bundle、呼叫簽名模組]] — 載入 loader 與各模組檔、靠 JSONP callback 合併模組，最後以 id 呼叫簽名模組（after steps 2–3）

## Lesson

真實網站的前端幾乎都由打包工具生成，而 webpack 是最常見的一種。它把所有模組塞進一個或多個檔案裡，另外附上一支「載入器」——一個能依模組 id 取出對應模組並執行它的 require 函式。逆向時你面對的不是一整支程式，而是「載入器 + 一袋用 id 編號的模組」：加密邏輯通常就藏在其中某個模組裡，被一個字串或數字 id 代表。

這個節點的任務，就是把這袋東西拆開。第一步先看清 bundle 的骨架：最外層是 IIFE，裡面是 require 函式與快取，而它常常被洩漏到全域，變成 `window.loader`——這就是你伸手進去呼叫模組的入口。第二步學會分辨三種常見型態：陣列版用數字索引、物件版用字串 hash key、多檔版則用 `webpackJsonp` 把好幾個檔案的非同步區塊合併起來。型態決定模組 id 長什麼樣，也決定你要去哪裡接上載入器。

有了型態判斷，第三步是真正動手：把 require 函式接到 `window.loader`，並在「模組即將被執行」的那一行前面插一個 `console.log`，讓它把每次要求的模組 id 印出來。於是你呼叫哪個 id、它就跑哪個模組，日誌清楚告訴你每個模組被誰、在什麼時候觸發。第四步把整套搬進 Node 跑一次多檔 bundle：先載入 loader，再載入每個模組檔觸發 JSONP 合併，最後用一個模組 id 呼叫簽名模組、拿回結果。走完這四步，你就有了一套對任何 webpack 打包站點都適用的定位流程。
