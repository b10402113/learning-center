# Hook 與 Proxy 攔截

## Learning goal

用 hook 攔截函式／屬性輸入輸出（含原生 API），並用 Proxy 記錄未定義屬性的讀取，同時繞過 `toString` 偵測。

## Steps

1. [[learn/js-reverse2/nodes/hook-proxy/hook-concept|Hook 是什麼：存下原本的，換上會回報的包裝]] — 用「存原函式、換包裝」的骨架攔截函式與物件屬性的進出
2. [[learn/js-reverse2/nodes/hook-proxy/hook-native-api|攔住原生函式：在頁面載入前 hook atob 與 document.cookie]] — 在頁面程式碼執行前 hook 原生 API 的完整操作順序（after step 1）
3. [[learn/js-reverse2/nodes/hook-proxy/hook-detection-bypass|被偵測到了：toString 檢測與它的兩層破解]] — 分辨兩層 toString 檢測並選對破解（after steps 1–2）
4. [[learn/js-reverse2/nodes/hook-proxy/proxy-monitor|Proxy 是什麼：替物件套一層會記錄讀寫的代理]] — 用 get／set 記錄讀寫，並從缺漏屬性判斷該補什麼環境
5. [[learn/js-reverse2/nodes/hook-proxy/proxy-traps|Proxy 處理器全覽：六個 trap 各攔什麼]] — 六個 handler trap 的攔截對象、參數與最小範例（after step 4）

## Lesson

這一節要裝上兩件「觀察工具」。當你在 DevTools 裡盯著一個參數，卻看不出它是被哪一段程式碼算出來的，靜態讀碼很容易卡住；hook 與 Proxy 讓你反過來，在程式執行時把那些函式與屬性的進出全都記下來。

它們的共同點是「不改變原本的行為，只在中間多一層觀察」。hook 是把它攔住的函式或屬性存一份原始版本，再換成一個會記錄輸入輸出的包裝；Proxy 則是替整個物件套一層代理，之後所有對它的讀寫都得先經過你指定的處理器。這一節先講兩者的觀念與骨架，再示範怎麼把它們用在原生 API、物件屬性，以及補環境時的缺口偵測上。

攔截之後，下一個問題就來了：網站會不會發現自己被攔截？會，而且最常見的檢查方式就是比較函式的 `toString`。所以這一節也包含一組「檢測與反檢測」的取捨，讓你攔得進去、也留得下來。
