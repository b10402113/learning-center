# 瀏覽器自動化與動態渲染

## Learning goal

用 Selenium／Pyppeteer／DrissionPage 處理 JS 渲染與登入，正確設定等待，並隱藏 `navigator.webdriver` 指紋。

## Steps

1. [[learn/js-reverse2/nodes/browser-automation/browser-render-model|為什麼需要瀏覽器自動化：JS 渲染與「可見即可得」]] — 說清楚 `requests` 為什麼抓不到 JS 渲染的資料，以及真實瀏覽器自動化的心智模型
2. [[learn/js-reverse2/nodes/browser-automation/selenium-drive-extract|Selenium 基本操作：建立驅動、定位、互動、取渲染後 DOM]] — 用 driver 開頁、`By` 定位、與節點互動，最後用 `page_source` 取回渲染後 HTML（after step 1）
3. [[learn/js-reverse2/nodes/browser-automation/wait-strategies|等還是不等：強制、顯式與隱式等待的取捨]] — 在強制、顯式、隱式三種等待中選對時機（after step 2）
4. [[learn/js-reverse2/nodes/browser-automation/evade-webdriver-fingerprint|被認出來了：`navigator.webdriver` 指紋與 stealth 注入]] — 看懂偵測指紋的原理，並在頁面載入前注入腳本隱藏它（after step 2）
5. [[learn/js-reverse2/nodes/browser-automation/pyppeteer-async|Pyppeteer：不必自己管 driver 的非同步瀏覽器操作]] — 用 `async` 啟動 Chromium 並在頁面內執行 JS（after step 2）
6. [[learn/js-reverse2/nodes/browser-automation/drissionpage-mode-switch|瀏覽器還是封包？DrissionPage 的模式切換]] — 在 `ChromiumPage`／`SessionPage`／`WebPage` 之間選對工具，用模式切換處理登入（after step 3）

## Lesson

前一個節點你已經能用 `requests` 把 HTML、JSON、圖片抓下來了。但只要網站的內容是靠 JavaScript 在瀏覽器裡即時組出來的，`requests` 拿回來的就只是一副空殼——這一節要處理的，正是這個牆。

核心轉念是：既然資料要瀏覽器執行完 JS 才看得到，那就不要用 HTTP 客戶端去猜，而是真的開一個瀏覽器，讓它把頁面跑完，你再把「畫面看到的東西」取下來。這就是瀏覽器自動化，也是「可見即可得」的意思。

六步的安排是這樣走的：先建立這個心智模型（step 1），再用 Selenium 把整套動作跑一遍——建立 driver、定位元素、互動、最後用 `page_source` 把渲染後的 DOM 交給解析器（step 2）。動態頁面最常出錯的地方是「元素還沒出現就去找它」，所以 step 3 專門比較強制、顯式、隱式三種等待的取捨。再來是實務上的關鍵：許多大站一眼就認出你在跑自動化，靠的是 `navigator.webdriver` 這個指紋，step 4 講它怎麼被偵測、又怎麼在頁面載入前就被藏掉。最後把視角拉寬到另外兩個工具：step 5 的 Pyppeteer 用非同步與自動下載 Chromium 省去管 driver 的麻煩，step 6 的 DrissionPage 則把「開瀏覽器登入」與「用封包快速採集」合成一個流程，讓你知道什麼時候該切換。
