# 案例：簽名與雜湊演算法

## Learning goal

辨識並重現各類簽名配方（排序拼接＋salt→MD5、固定順序＋secret→MD5/SHA1、自家 hash），在 Python 與 execjs 兩路都跑通。

## Steps

1. [[learn/js-reverse2/nodes/cases-sign-hash/sign-three-ingredients|簽名的三個組成：拼接規則、密鑰、雜湊]] — 看到一個 sign 欄位時，把問題拆成「拼了哪些欄位、加了什麼密鑰、用哪個雜湊」三件事來追
2. [[learn/js-reverse2/nodes/cases-sign-hash/sorted-params-salt-md5|配方一：排序拼接＋salt 的 MD5 簽名（福建電子交易平台）]] — 在 Python 重現「排序拼接＋salt → MD5」，並讓字串化細節與 JS 完全一致（after step 1）
3. [[learn/js-reverse2/nodes/cases-sign-hash/fixed-order-secret-md5|配方二：固定順序＋固定密鑰的 MD5 簽名（xdf 與有道翻譯）]] — 重現「固定順序拼接＋固定密鑰 → MD5」，處理簽名用原始字串、送出要編碼的落差（after step 1）
4. [[learn/js-reverse2/nodes/cases-sign-hash/identify-the-hash|不一定是 MD5：辨識雜湊與選擇重現路線]] — 判斷雜湊是標準演算法還是自家配方，決定翻 Python 或直接 execjs（after steps 2–3）
5. [[learn/js-reverse2/nodes/cases-sign-hash/layered-hash-loader-sign|打包檔裡的雙層雜湊：財联社的排序→SHA1→MD5 簽名]] — 進 webpack 打包檔定位簽名模組，拆出「排序序列化 → SHA1 → MD5」並呼叫它（after step 4）

## Lesson

真實網站的簽名（sign）看起來五花八門，但拆開來都由同樣三件東西組成：一份「把哪些欄位按什麼順序拼成一條字串」的拼接規則、一個藏在 JS 裡的固定密鑰（salt、UUID 或 key），以及一個把「字串＋密鑰」壓成定長輸出的雜湊演算法。逆向的任務就是把這三件事一件件認出來，再用 Python 或 execjs 把整條配方重現出來。

配方的變化集中在拼接規則與雜湊選擇兩處。拼接規則有兩大類：一類是「排序拼接」——把參數按鍵名排序後依序拼起來，代表案例是福建電子交易平台的 portal-sign（排序＋salt → MD5）；另一類是「固定順序拼接」——照 JS 寫死的欄位順序拼成查詢字串，代表案例是 xdf（paramString＋固定 UUID → MD5）與有道翻譯（固定查詢字串＋固定 key → MD5）。雜湊則不能看到 32 位十六進位就斷定是 MD5：丁香網用的是自己帶的純 JS SHA1，百度翻譯更是一套以 gtk 為種子的自家 hash；到財联社這種 webpack 打包檔裡，簽名甚至是「排序序列化 → SHA1 → MD5」兩層雜湊串起來的。

每個案例都用兩條路跑通：先純 Python 重現（hashlib 加上與 JS 一致的字串化細節），失敗或演算法與瀏覽器環境糾纏太深時，改用 execjs 直接呼叫原 JS。走完這個節點，你手上會有一份可套用的判讀流程——先拆三個組成、認出拼接與雜湊的家族、再決定重現路線。
