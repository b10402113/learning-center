CodeRabbit 安全掃描的七大類問題

Step 2/5 · 大規模 PR 安全審查

前言

上一節我們說，面對上萬行的 PR，你要靠一張「地圖」來決定看哪裡；而地圖上最要緊的一塊，是安全掃描清單。現在問題來了：當 CodeRabbit 在清單上寫下 authorization bypass 或 SSRF，你分得出這是嚴重問題，還是可有可無的提醒嗎？

這七個詞是後端安全的基本字彙。它們不只是縮寫，每一個都對應一種真實的攻擊方式，也對應你程式碼裡某個特定的錯誤寫法。這一節是一份查閱表：把每個詞的定義、它防的是什麼、以及它通常出現在哪裡，一次列齊。你不需要在這裡背下來，但當審查清單出現某個詞時，你要能立刻知道它指的是哪一類危險。

這七類問題的英文與縮寫沿用原始掃描報告，方便你對照。定義各自獨立，可以跳著查。

總覽

名稱一句定義最常出現的位置
Injection（注入）把使用者輸入當成指令或查詢語法的一部分執行資料庫查詢、系統指令、動態字串拼接
Authorization bypass（授權繞過）通過了身分檢查，卻能存取不屬於自己的資源API 端點、資源讀取與寫入
XSS（跨站腳本）把未處理的使用者內容輸出到網頁，被瀏覽器當成腳本執行Web dashboard、任何渲染使用者內容的頁面
SSRF（伺服器端請求偽造）讓伺服器代為請求攻擊者指定的位址抓取圖片、webhook、任何「幫你連外」的功能
CSRF（跨站請求偽造）借用使用者已登入的憑證，在不知情下送出變更請求以 cookie 為憑證的表單與 API
Broken authentication（身分驗證失效）登入、session 或 token 的處理有缺陷，可被繞過登入流程、token 驗證、密碼重設
Security misconfiguration（安全設定錯誤）安全相關的設定沒關好，暴露出多餘的攻擊面環境變數、CORS、錯誤訊息、除錯模式

Injection（注入）

當使用者輸入被直接拼進一段有語法的字串——最典型的是 SQL 查詢——輸入裡的內容就不只是「資料」，而會被當成「指令」執行。參數化查詢（parameterized query）是標準的防線：把查詢語法和資料分開傳，資料永遠不會被當成語法。

// 危險：輸入直接拼進字串
db.query(`SELECT * FROM users WHERE email = '${email}'`);

// 安全：語法與資料分開
db.query("SELECT * FROM users WHERE email = $1", [email]);

Authorization bypass（授權繞過）

這類問題不是「沒登入」，而是「登入了，但看到了不該看的」。端點只確認請求帶有有效的登入憑證，卻沒有確認這個資源屬於這位使用者。症狀是：把網址裡的資源編號改成別人的，一樣拿得到資料。防線是每一次資源存取都從登入身分推出「你是誰」，再比對「這筆資料是不是你的」。

XSS（跨站腳本）

當一段含有 HTML 或 JavaScript 的使用者內容，沒有被轉義（escape）就送進網頁，瀏覽器會把它當成頁面的一部分執行。它主要影響有網頁介面的部分，例如員工 dashboard。防線是輸出時一律轉義，或使用框架預設會轉義的方式渲染，避免直接插入未處理的 HTML。

SSRF（伺服器端請求偽造）

如果一個功能會「用伺服器的身分去連某個網址」，而那個網址使用者可以控制，攻擊者就能借用伺服器去探測它自己的內部網路、或讀取雲端環境的 metadata 端點。它常出現在「幫你抓一張遠端圖片」這類看似無害的功能裡。防線是限制可連線的目標（白名單），而不是照單全收使用者給的位址。

CSRF（跨站請求偽造）

當網站用 cookie 當作登入憑證，而變更狀態的請求又沒有額外驗證來源，攻擊者就能引導已登入的瀏覽器在背後送出請求。防線是使用 SameSite cookie、CSRF token，或改用不會被瀏覽器自動附帶的憑證（例如放在 header 的 Bearer token）。

Broken authentication（身分驗證失效）

這是登入與 session 機制本身的缺陷，例如 token 沒有驗簽章、密碼重設的判斷可被猜中、登入端點沒有速率限制而能被暴力破解。它和 authorization bypass 的差別在於：這裡壞掉的是「證明你是誰」的過程，而不是「證明你有權存取這筆資料」。

Security misconfiguration（安全設定錯誤）

程式邏輯沒有錯，但設定留下了缺口：CORS 開放成所有來源、生產環境還開著除錯模式、錯誤訊息把內部路徑或資料庫細節吐給使用者、忘記加上該有的安全標頭。它通常是「預設值沒有依實際情境收緊」造成的。

這七個詞的共同點是：程式都能正常運作。它們描述的不是「壞掉」，而是「可以被利用」。認得名稱，只是為了在清單出現時，知道該往哪個方向查。

名詞認得之後，下一節要動手了：把上萬行的改動真的開成一條分支與 PR，讓 CodeRabbit 跑完審查與安全掃描，再把它的輸出讀成一張能用的清單。
