前言：清單上那些看不懂的名詞

上一節你接受了「規模本身就是問題」，也同意要改用結構化的工具。現在你把 PR 交給 CodeRabbit，它掃完之後，安全區塊列出幾個英文字：injection、authorization bypass、XSS、SSRF、CSRF、broken authentication、security misconfiguration。

問題來了。如果這些名詞在你腦中只是一團模糊的「聽過、好像很危險」，你就沒辦法判斷哪一則該緊張、哪一則可以先放。這一節是一份查閱表：把這七類問題並排，說清楚每一類在防哪種攻擊、攻擊者實際怎麼利用它、以及在程式碼裡通常長什麼樣子。你不需要背下來，但要能在看到 finding 時，立刻知道它屬於哪一類、可能造成什麼後果。這是下一節「讀懂審查輸出」的前置配備。

CodeRabbit Security 是什麼

CodeRabbit Security 是 CodeRabbit 內建的功能，把程式碼審查與安全掃描合併在同一個 AI 平台上：它在每個 PR 上掃描整個 codebase，找出各類安全問題，並把每一則標上嚴重度與修復建議。這份清單就是「七大類」的來源。它掃的範圍比這七類更廣，但這七類是最常在大型 AI 生成 PR 上出現、也最容易造成實際損害的頭幾名。

七大類速查表

類別在防什麼攻擊者怎麼利用常見長相
Injection（注入） 使用者輸入被當成程式指令或 SQL 執行 送出帶有指令片段的輸入，讓資料庫或系統執行非預期動作 把字串拼進 SQL，而非用參數化查詢
Authorization bypass（授權繞過） 沒確認「這個人有沒有權利做這件事」 直接拿別人的資源 id、或改一個 role 參數，取得不該有的存取 只驗登入、不驗擁有權（典型是 IDOR）
XSS（跨站腳本） 攻擊者的腳本被當成網站內容，在別人的瀏覽器執行 把惡意 script 塞進留言或欄位，等其他人打開頁面時觸發 使用者內容直接塞進 HTML，沒有轉義
SSRF（伺服器端請求偽造） 伺服器被誘導去請求攻擊者指定的位址 指定內網位址或雲端 metadata 端點，讓伺服器代為取得機密 使用者可控的 URL 直接餵給 fetch
CSRF（跨站請求偽造） 冒用使用者已登入的身分，發出他沒同意的請求 引誘已登入的使用者點連結，借他的 cookie 送出狀態改變請求 改資料的端點只靠 cookie 驗身分，沒有 token 或 SameSite
Broken authentication（身分驗證失效） 登入、session、token 的實作有洞，讓人冒充他人 偽造或重用憑證，直接變成另一個使用者 token 沒驗簽章、session 可預測、密碼處置不當
Security misconfiguration（安全設定錯誤） 預設值、除錯開關、過寬的權限設定留下破口 利用除錯模式、外洩的錯誤訊息或過寬的 CORS 取得資訊 生產環境開著 debug、錯誤頁吐出完整 stack trace

每一類再多一句

Injection 的關鍵字是「把資料當指令」。資料庫看到的應該是「一段文字」，但如果你的程式把使用者輸入直接接到 SQL 字串後面，資料庫會把它當成語法的一部分。下面這組對照就是最典型的樣子（示意用，非課程原始碼）：

// 危險：使用者輸入直接拼進查詢
const q = `SELECT * FROM users WHERE email = '${email}'`;
// 輸入 ' OR '1'='1 就能改變查詢邏輯

// 安全：參數化查詢，輸入永遠只是資料
const q = sql`SELECT * FROM users WHERE email = ${email}`;

Authorization bypass 和 broken authentication 常被混在一起，但兩者防的東西不同。後者問「你是誰、你真的登入了嗎」；前者問「你登入了，但這件事你有權做嗎」。實務上很常見的破口是：API 只檢查「有沒有登入」，卻沒有檢查「這筆資料是不是你的」，於是改一下網址裡的 id 就能讀到別人的預約紀錄。

XSS 是前端版的 injection：把使用者的內容當成程式碼。它的傷害發生在「別人」的瀏覽器上，所以一個被注入的留言欄位，可能影響所有打開該頁面的人。SSRF 則是讓你的伺服器變成攻擊者的代理：你的伺服器通常處在內網、握有雲端憑證，攻擊者只要控制它去請求一個 URL，就能借它的身分碰到它不該碰的東西。CSRF 的重點在「借用你已經登入的事實」：攻擊者不需要偷你的密碼，只要讓你在已登入的狀態下送出一個請求。

Broken authentication 是身分驗證本身的實作瑕疵，例如 token 只解碼、不驗簽章，或 session 識別碼可以被猜出來。Security misconfiguration 則不是程式邏輯的洞，是設定留下的門：開發用的除錯模式忘了關、CORS 開放成星號、錯誤訊息把內部路徑與版本號都吐出來，這些都能幫攻擊者更快找到入口。

怎麼用這張表

當 CodeRabbit 丟出一則 finding，先用這張表定位它屬於哪一類，你就會同時知道兩件事：這件事最壞的後果是什麼，以及它是不是那種「不影響功能、但可以被利用」的問題。定位之後，修不修、先修哪一則，就交給第 4 步的判斷準則；至於實際怎麼把 PR 開起來、怎麼讓 CodeRabbit 產出這份清單，是下一步的操作範圍。

小結

CodeRabbit Security 把程式碼審查與安全掃描合併在一個平台。最常見的七類問題是：injection（把資料當指令）、authorization bypass（登入了但無權限）、XSS（把使用者內容當程式碼）、SSRF（讓伺服器代打內網）、CSRF（冒用已登入身分）、broken authentication（驗身分有洞）、security misconfiguration（設定留了門）。看到 finding 先定位是哪一類，就知道最壞後果與該不該緊張。

你手上現在有分類地圖了。下一步要把抽象的類別變成實際的畫面：開一個 branch、把上萬行改動推成 PR，讓 CodeRabbit 掃完，然後讀懂它的 summary、Change Stack 與安全區塊。
