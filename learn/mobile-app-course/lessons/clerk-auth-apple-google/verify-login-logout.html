實測 Google、Apple 登入：別只看按鈕有沒有跑完

Step 5/5 · Clerk 多供應商登入

這一節要完成什麼

這一節的目標，是完整驗證一輪 sign-up → 在 Clerk dashboard 確認使用者 → sign out → 再次 sign in。你也會知道為什麼 Apple 登入在模擬器上可能失敗，以及什麼時候應該改用真機測試。

開始前，請先確認 onboarding 尾端已經有 Google 與 Apple 兩顆登入按鈕，而且你的 app 是用 dev build 執行，不是 Expo Go。這一節主要不是新增登入程式，而是把「看起來成功」驗證成「真的成功」。

先記住驗收標準：畫面跑完不等於登入成立

按下登入按鈕後，授權畫面關閉、app 回到主畫面，並不一定代表 Clerk 已經建立使用者。它可能只表示流程沒有當掉。

因此，我們不只看 app 畫面，而是要到 Clerk dashboard 的 Users 清單確認。清單裡真的出現使用者，才是較可靠的證據。你可以把它想成寄包裹：門鈴響了不代表包裹已經簽收，還是要回到物流紀錄確認。

第一步：用 Google 完成一次 sign-up

在模擬器裡走完 onboarding，按下「Continue with Google」。接著選擇一個 Google 帳號並同意授權。

若流程正常，授權畫面關閉後，app 會回到已登入狀態。先不要把這個畫面當成最終驗收，下一步還要到 Clerk 後台確認使用者是否真的建立。

如果流程卡住，或按下按鈕後完全沒有反應，請依序檢查以下三項：

  • .env 裡的 publishable key 是否填寫正確。
  • native applications 是否已啟用。
  • app 是否使用 dev build 執行，而不是 Expo Go。

這三項是目前階段最常見的失敗原因。

第二步：到 Clerk dashboard 確認使用者

打開 Clerk dashboard，進入 Users 清單。

如果剛才的 Google 登入真的成功，清單應該會多出一筆使用者，並顯示對應的 email 與登入方式。這一步確認的是伺服器端的紀錄，而不只是 app 上的畫面。

之後每次修改登入相關程式，都可以把 Clerk Users 清單當成第一個驗收站：若畫面看起來正常，但清單沒有新增對應使用者，就代表流程還沒有真正完成。

第三步：登出，再用同一個帳號登入

接著測試 sign out。在 app 裡找到登出按鈕；如果你的介面還沒有按鈕，也可以在程式碼中呼叫 Clerk 的 sign out。完成後，確認 app 回到未登入狀態。

接著再次按下「Continue with Google」，並選擇剛才使用的同一個帳號登入。

這次要驗證的不是「能不能登入」而已，而是它真的在登入既有使用者，而不是重新註冊一個新帳號。請回到 Clerk dashboard 的 Users 清單檢查：

  • 若使用者數量維持一筆，代表同一個 Google 帳號被正確辨識。
  • 若使用者數量變成兩筆，代表前後兩次使用了不同的識別邏輯，這是需要修正的問題。

第四步：處理模擬器上的 Apple 登入

現在輪到 Apple。請在模擬器按下「Continue with Apple」。你很可能會直接看到錯誤，而不是 Apple 授權畫面。

這不一定是你的程式寫壞了，而是 Sign in with Apple 在模擬器上有額外限制。課程對這個問題採取兩種務實做法：

  1. 把錯誤訊息連同截圖交給 agent，請它協助修正。它通常會提供一條需要在終端機執行的指令；執行後，再回到 app 重試。
  2. 若指令暫時無法解決，就先記下錯誤，將 Apple 登入延後到真機測試。
重點心態：不要為了在模擬器上把 Apple 修到能跑，而卡住整個進度。若 agent 提供的指令暫時沒有效果，可以先往後進行，等 dev build 安裝到真機後再驗證。這門課的安排是：Google 在模擬器驗證，Apple 留到真機測試。

第五步：準備 dev build，讓真機測試 Apple

若要在真機測試 Apple 登入，前置條件是先產出開發用建置。請先安裝 expo-dev-client，接著在 iOS 上執行：

npx expo run ios

這會編譯出原生的 ios 與 android 資料夾，並產生真正的開發版 app，而不是透過 Expo Go 執行的沙盒。

將這個 dev build 安裝到 iPhone 後，再測試 Apple 登入。dev build 的完整流程會在下一個大主題深入處理；目前只要記住，Apple 的真機驗證必須建立在這個開發版 app 上。

照表驗收

檢查項目怎麼確認通過的標準
Google 登入走完授權並回到 appapp 進入已登入狀態
使用者真的建立看 Clerk dashboard 的 Users清單多出一筆對應的使用者
登出呼叫 sign out回到未登入狀態
再次登入同一帳號再登一次使用者數量沒有變多
Apple 登入模擬器或真機測試真機上可完成；模擬器可延後

完成後，你應該看到什麼

完成這一輪後，你應該能確認以下結果：

  • Google 登入可以讓 app 進入已登入狀態。
  • Clerk dashboard 的 Users 清單會出現對應使用者。
  • 登出後再次使用同一個 Google 帳號登入，不會多出第二筆使用者。
  • Apple 登入若在模擬器失敗，可以先交給 agent 處理，或延後到真機上的 dev build 驗證。

登入解決的是「你是誰」，但還沒有解決「你的 app 認識你」。即使 Clerk 已經有使用者，你自己的資料庫仍然可能是空的。下一個節點會處理 webhook，將 Clerk 的使用者自動同步到你的資料庫，讓 app 從「能登入」跨到「有自己的個人資料」。

小結

驗證登入不能只看畫面，而要確認 Clerk dashboard 的 Users 清單真的出現那筆使用者。完整跑一輪 sign-up → 後台確認 → sign out → 再 sign in，並確認同一個帳號不會被重複建立。Apple 登入在模擬器上可能因限制報錯，課程的做法是把錯誤交給 agent 修正，或直接延後到真機測試。真機測試需要 expo-dev-client 與 npx expo run ios 產生的 dev build。登入成立後，資料庫仍然是空的；這正是下一個 webhook 節點要接上的缺口。
