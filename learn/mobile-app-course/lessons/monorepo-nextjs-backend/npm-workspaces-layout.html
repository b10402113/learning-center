用 npm workspaces 擺好 apps/mobile 與 apps/web

Step 2/5 · Monorepo 與 Next.js 後端骨架

學習目標

把 Expo app 移進 apps/mobile、建立 apps/web，並用根目錄的 scripts 從一個地方啟動兩邊。

前言：上一節談形狀，這一節把它擺出來

上一節我們確認了 Dentify 的骨架：一個 monorepo，裝著 apps/mobile 和 apps/web 兩個 app，商業邏輯留在 web。但「確認要這樣做」和「把它做出來」中間還差一步：這兩包程式碼到底要放在哪個資料夾、package.json 要怎麼寫、`npm install` 要在哪裡跑，還有最重要的：怎麼用一個指令把兩邊都開起來。

做完這一節，你的專案根目錄會長成apps/底下兩個資料夾的樣子，而且不管你在哪個目錄，都能從根目錄用 npm run web 啟動後端、用 npm run mobile 啟動手機 app。做出來就驗證得到，不用憑感覺。

動手前需要先具備什麼

  • 一台裝好 Node.js 的電腦（這個專案要求 Node 22 以上）。
  • 一個已經用 create-expo-app 建好、也執行過 reset-project 的 Expo 專案（前一個節點做的事）。
  • npm。它會隨 Node 一起裝好，你不需要再額外安裝任何 monorepo 工具。

先講清楚一件事：以下每個指令你都不一定要自己敲。這個課程的工作流是把指令交給 AI agent 執行，你負責確認結果。這裡把它拆成步驟，是為了讓你知道 agent 到底動了哪些檔案，出錯時才有辦法判斷哪裡不對。

步驟一：先建立 apps/，把 Expo app 移進 apps/mobile

如果你現在的 Expo 專案是直接躺在根目錄（這是 create-expo-app 加 . 的預設結果），第一步是先在根目錄開一個 apps/ 資料夾，再把整個 Expo 專案搬進 apps/mobile。搬完之後，根目錄本身不再是一個 app，而是一個「裝 app 的容器」。

mkdir apps
mv ./apps/mobile  # 把 Expo 專案的所有檔案移進 apps/mobile

搬動時有一個容易出錯的地方：不要只搬 app/ 或 src/，而是要把整個 Expo 專案該有的檔案（package.json、app.json、設定檔、原始碼目錄）全部一起搬到 apps/mobile/。搬完後用檔案總管或 ls apps/mobile 確認 package.json 在裡面。

步驟二：在 apps/web 建立 Next.js 專案

接著建立後端那包。用官方的 Next.js 建立指令，指定路徑為 apps/web，它就會在 apps/ 底下生出一個完整的 Next.js 專案。這一步做出來的東西，就是上一節說的「員工後台 + 手機 API + webhook」三合一。

npx create-next-app@latest apps/web

完成後，根目錄的 apps/ 裡應該同時有 mobile/ 與 web/。此刻兩包程式碼還是各過各的，它們各自的 package.json 只管自己。要讓它們變成同一個大專案，關鍵在下一步的根目錄設定。

步驟三：寫根目錄的 package.json，把兩包綁在一起

在根目錄建立一個 package.json。它不需要有依賴，也不需要有自己的原始碼；它的工作只有兩件：用 workspaces 宣告哪些資料夾是子專案，以及提供一組從根目錄操作的 scripts。

{
  "name": "dental-app",
  "private": true,
  "workspaces": [
    "apps/*",
    "packages/*"
  ],
  "scripts": {
    "mobile": "npm run start -w apps/mobile",
    "build:ios": "npm run build:ios -w apps/mobile",
    "build:android": "npm run build:android -w apps/mobile",
    "web": "npm run dev -w apps/web",
    "test": "npm run test -w apps/web",
    "typecheck": "npm run typecheck --workspaces --if-present",
    "db:generate": "npm run db:generate -w apps/web",
    "db:migrate": "npm run db:migrate -w apps/web",
    "db:seed": "npm run db:seed -w apps/web",
    "db:seed:stream": "npm run db:seed:stream -w apps/web",
    "stream:check": "npm run stream:check -w apps/web",
    "db:studio": "npm run db:studio -w apps/web"
  },
  "engines": {
    "node": ">=22"
  }
}

裡面最關鍵的是 -w 這個參數。它的意思是「到指定的 workspace 裡執行這個 script」。例如 "web": "npm run dev -w apps/web"，翻成白話就是：當我在根目錄打 npm run web，請你進到 apps/web 這個子專案，執行它自己的 dev 指令。所以根目錄的 scripts 其實是一層轉接頭，真正的指令定義在各個 app 的 package.json 裡。

這也是為什麼 typecheck 那行用的是 --workspaces --if-present：它會輪流跑過每個子專案，有這個 script 的就跑，沒有就跳過。這種寫法讓根目錄可以一次檢查整個 repo，而不用記兩個路徑。

步驟四：在根目錄執行一次 npm install

設定完成後，在根目錄執行：

npm install

這是 npm workspaces 的關鍵行為：你只需要在根目錄裝一次，npm 就會把兩個子專案的依賴一起裝進根目錄的 node_modules。往後你新增套件時，也要看清楚是要裝在哪個 app，例如 npm install zod -w apps/web；如果你只在根目錄跑 npm install zod，它會變成根目錄的依賴，而不是某個 app 的。

步驟五：從根目錄啟動兩邊，確認結果

現在回到最實際的驗證。開一個終端，在根目錄執行：

npm run web

這會啟動 Next.js 的開發伺服器，通常會在 http://localhost:3000 開起來。課程裡就是這樣跑：在終端機打 npm run web，Next.js 專案就開始執行。

再開另一個終端，同樣在根目錄執行：

npm run mobile

這會啟動 Expo 的開發伺服器，出現讓你選 iOS 模擬器、Android 模擬器或掃 QR code 的畫面。到這裡，你已經能用兩個指令、在同一個地方啟動一個 repo 裡的兩個 app。往後開發 Dentify 時，你常常就是這樣開著兩個終端：一個跑 web，一個跑 mobile。

一個容易踩的坑：別急著換成 pnpm

如果你對 monorepo 有經驗，可能會想改用 pnpm。上一節提過原因，這裡再具體說一次：Expo 的 Metro 打包工具無法解析 pnpm 用符號連結組出來的 node_modules。要讓它跑起來，你得把 pnpm 設成 hoisted 模式，而那等於放棄 pnpm 最主打的嚴格依賴隔離。這個專案只有兩個 app，也還不需要 Turborepo 或 Nx 這種建置協調器。用 npm，是因為它原生就會 hoist、而且已經裝在機器上。

小結

把 Expo 專案移進 apps/mobile、用 create-next-app 建立 apps/web，再寫一份根目錄的 package.json：用 workspaces 宣告子專案，用 -w 把 npm run web、npm run mobile 轉接到對應的 app。依賴在根目錄 npm install 一次就裝齊。做完會得到一個能用兩個指令同時啟動兩個 app 的 repo。
