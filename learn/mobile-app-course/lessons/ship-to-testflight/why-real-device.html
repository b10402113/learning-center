從模擬器到真機：Expo、EAS 與 TestFlight 各自負責什麼

Step 1/6 · EAS Build、真機與 TestFlight

朋友說：「裝到我手機上看看」

你在模擬器上把功能調到滿意：畫面順、動畫正確，於是截圖傳給朋友。朋友回了一句：「看起來不錯，裝到我手機上讓我用看看。」這時你才發現，自己只知道 app 怎麼在這台 Mac 上跑，卻還不知道它要怎麼離開這台 Mac。

這不是能力不足，而是模擬器製造了一個很舒服的假象。它和你共用同一台 Mac、同一個網路，以及同一份原始碼，因此不太會碰到「裝到別人的手機」才會出現的問題，例如簽章、裝置註冊、雲端建置，以及版本不一致。

這一節先把「寫完程式之後」的整條路畫出來。你會先看懂每個工具負責哪一段，接著再到後面的五節逐段動手。可以把它想成一條出貨線：程式碼是原料，build 是包裝完成的產品，而散布則是把產品送到測試者手上。

學習目標

完成這一節後，你應該能說明從「模擬器能跑」到「真機與測試者裝得到」之間，Expo、EAS、Apple Developer Program 與 TestFlight 各自扮演的角色，也能分辨兩條把 development build 裝進 iPhone 的路線。

為什麼模擬器不夠用

模擬器是開發時很方便的幫手，但它終究只是電腦裡的一個程式。它不一定能反映真實手機上的網路切換、相機、推播等硬體或系統行為；更重要的是，模擬器能跑，也不代表另一支手機就能安裝。

只要你想把 app 交給第二個人，就會多出兩件事：先把程式建置（build）成可以安裝的檔案，再把這個檔案散布（distribution）到對方手上。Expo 生態系的價值，就在於把這兩件原本容易卡關的工作，收斂成一條比較順的流程。

四個角色，各管一段

這條路上會反覆出現四個名字。先把分工看清楚，之後遇到任何步驟，你就知道自己正在使用哪個工具，以及它正在替你解決什麼問題。

角色它負責什麼你可以這樣理解
Expo讓同一份程式碼同時跑在 iOS 與 Android跨平台的那一層地基
EAS（Expo Application Services）在雲端建置、散布 build，也處理送審你專案的雲端工廠與物流
Apple Developer Program提供 App Store 送審與對外散布的資格進入 App Store 這座場館的門票
TestFlight提供上架前的測試環境，可邀請他人安裝測試正式演出前的彩排場

其中最核心的一段是 EAS（Expo Application Services）。你不必在自己的電腦上安裝完整的建置環境，建置工作會在 Expo 的雲端平台完成。產生的 build 可以直接安裝、分享給其他人，之後也能沿著同一條路送到 App Store、Play Store 或 TestFlight。

Apple Developer Program 則是一道繞不過的門檻。只要你想把 app 發布到 App Store，就必須申請並支付年費；這不是開發者可以自行省略的選項。美國的定價是每年 99 美元。若所在國家的購買力較低，價格可能會打折，例如課程作者在土耳其申請時支付了大約 20 到 25 美元。實際金額依國家而定，申請前可以再確認一次。

TestFlight 可以先理解成一個測試沙盒。你把 app 部署成接近正式上架的樣子，再邀請隊友加入測試。測試者可以真的把 app 裝到自己的手機上操作，而不是只能看你傳來的截圖。

EAS 的方案：先從免費開始

開始使用 EAS 不需要先付費。免費方案每月可以產生 15 個 build，只是會排在低優先度的佇列中，因此等待時間可能比較長；付費方案則會排在高優先度佇列。

如果你還在驗證想法，或目前使用者不多，免費方案通常已經足夠。等到 app 有了穩定用戶，例如達到上萬名月活躍使用者，再考慮升級到 starter 或 production 方案即可。

兩條把 dev build 裝進 iPhone 的路

接下來會談到 development build，也就是開發版建置，簡稱 dev build。它是一個可以安裝在真機上的 app；不過在開發時，畫面與 JavaScript 仍然由你電腦上的開發伺服器提供，所以你修改程式碼後，通常可以很快看到變化。

要把這種 build 裝進 iPhone，有兩條路可以選。差別不在於哪一條才是正確答案，而在於建置工作發生在你的 Mac，還是 Expo 的雲端。

路線一：USB 本機建置路線二：EAS 雲端建置
做法用傳輸線接上 iPhone，執行帶 --device 的指令把專案交給 EAS，在雲端完成建置
建置在哪你自己的 MacExpo 的雲端
拿到 build 的方式直接寫進接線的手機建置完成後掃 QR code 安裝
適合手機就在手邊、想最快看到結果不想被線綁住、想留下雲端紀錄

路線一的關鍵指令是 npx expo run ios --device。只要在原本的 run ios 後面加上 --device，Expo 就會請你從清單中選擇已接線的手機。

路線二則把建置工作交給 EAS。你的電腦不需要負責編譯，等雲端完成後，系統會提供一個 QR code，你用手機掃描就能安裝。

兩條路沒有絕對的優劣：手機就在手邊時，USB 本機建置像是直接把成品送到櫃檯，速度快；想讓其他人安裝，或希望保留雲端建置紀錄時，EAS 就像替你處理製造與物流。後面的實作會走路線二，因為它更貼近「把 app 交給別人」的真實情境。

小結

模擬器能跑，只證明程式在你的電腦裡能跑；要交到別人的手機上，還得先建置，再完成散布。這條路上有四個角色：Expo 讓一份程式碼跨 iOS 與 Android，EAS 在雲端負責建置與散布，Apple Developer Program 提供送審與對外散布的資格（每年 99 美元起，部分國家有折扣），TestFlight 則是上架前的測試沙盒。把 dev build 裝進 iPhone 有兩條路：用 USB 接線走本機建置（--device），或交給 EAS 在雲端建置，再掃 QR code 安裝。EAS 免費方案每月可產生 15 個 build，雖然排在低優先度佇列，但足以讓專案起步。

現在可以把這些工具放回同一張地圖：Expo 是跨平台的基礎，EAS 是建置與散布的雲端工廠，Apple Developer Program 是進入 Apple 發布體系的資格，而 TestFlight 則是正式上架前讓真人試用的場地。下一節會沿著路線二動手，從產生 EAS 設定檔開始，逐步把 dev build 送進你的 iPhone。
