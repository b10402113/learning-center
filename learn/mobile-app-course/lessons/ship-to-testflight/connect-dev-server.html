讓真機上的 app 連上 Metro：dev server 與 tunnel

Step 3/6 · EAS Build、真機與 TestFlight

這一節要完成什麼

做完這一節，你會把已安裝在 iPhone 上的 development build 連到 Metro 開發伺服器，讓 app 顯示真正的介面。若手機無法直接連線，你也會知道如何改用 --tunnel，並在必要時把伺服器網址手動貼進真機上的 dev client。

開始前，請先確認兩件事：

  1. 你已經把 development build 安裝到 iPhone，並能看到 app 圖示。
  2. 你人在行動專案的資料夾裡，可以使用終端機啟動 Expo。

先看完整流程：外殼已經有了，現在要送進畫面

上一節你已經把 development build 裝進 iPhone。點開 app 後，如果只看到 logo 和「正在尋找開發伺服器」，不代表 build 壞了，而是 app 還在等它的畫面來源。

可以把 development build 想成已經裝好引擎與各種零件的車子。相機、推播和其他 native module 都包在這個原生外殼裡；但你每天修改的畫面與 JavaScript，並沒有放進這個安裝檔，而是由電腦上的 Metro 即時提供。

因此，這一節的接線順序是：

  1. 啟動 Metro 開發伺服器。
  2. 如果手機無法直接連線，改用 tunnel。
  3. 若 app 沒有自動找到伺服器，就把正確網址手動貼進 dev client。
  4. 在真機上完成實際操作，確認整條連線真的成功。

第一步：啟動 Metro

先確認終端機所在位置是行動專案的資料夾，接著執行：

npx expo start

啟動後，終端機會印出一段訊息，其中包含網址與 QR code。

如果 iPhone 和 Mac 連在同一個 Wi-Fi，而且網路沒有阻擋裝置彼此連線，app 通常會自動找到 Metro 並載入畫面。這是最直接的連線方式。

第二步：連不上時改用 tunnel

若 app 仍停在「正在尋找開發伺服器」，先不要急著重新 build。常見原因是手機和 Mac 不在同一個網路，或公司、學校的 Wi-Fi 阻擋裝置之間的連線；也可能是 Mac 位於手機無法進入的子網段。

這時候，問題不是你少跑了一次同樣的指令，而是原本的網路路徑根本不通。請改用 tunnel：

npx expo start --tunnel

加上 --tunnel 後，Expo 會透過公開通道把開發伺服器轉送出去。只要手機能上網，就有機會連到這個伺服器。

判斷順序很簡單：先執行一般的 npx expo start。如果 app 沒有連上，再停止或改跑 npx expo start --tunnel。兩次終端機輸出的網址會不同；使用 tunnel 時，手機能從外部連線的會是 tunnel 版本提供的那組網址。

第三步：把完整網址貼進 app

如果 dev client 沒有自動連上 Metro，就在 dev client 的啟動畫面中找到手動輸入網址的按鈕。按下後會出現輸入框，接著把終端機印出的伺服器網址貼進去。

這裡要複製的是完整位址：從 http 或 https 開頭，一路複製到結尾的 /direct 為止。

不要只貼前半段，也不要在結尾多加或少掉內容。這整段才是 dev client 用來連線的完整網址。

貼上並連線後，app 會開始下載 JavaScript bundle 並執行。第一次載入可能會稍微久一點，因為 Metro 需要把你的程式碼打包後送到手機。

連線成功後，你修改程式碼並存檔，變更就會即時反映在真機畫面上，體驗會和在模擬器上使用熱更新類似。

若 iOS 要求開啟開發者模式

第一次在真機上執行這類 development build 時，iOS 可能會提示你開啟開發者模式。這是系統層級的設定，不是在 app 裡面。

如果系統出現提示，請依照指示開啟。設定位置大致在「設定 → 隱私權與安全性」底下；如果沒有看到提示，就不需要特別前往尋找。

第四步：用真實操作確認連線成功

最直接的檢查方式，是看 app 是否已經顯示你熟悉的介面，而不是停在 logo 或尋找伺服器的畫面。

課程中的驗證流程是：

  1. 登入 Google 帳號。
  2. 確認登入流程順利完成。
  3. 進入首頁。
  4. 實際點選幾個畫面，確認功能正常運作。

當真機顯示出和模擬器一樣的介面，並且能完成一個真實操作，就表示整條路已經接通：build 已在雲端建好、成功安裝到真機、JavaScript 由 Metro 提供，而且 app 正在真機上執行。

這也是 Expo 搭配 EAS 的開發體驗：同一支 app 可以同時在模擬器與真機上執行，而你修改的 JavaScript 能透過開發伺服器即時送到裝置。

不要把「沒有畫面」誤判成 build 壞掉

一個常見誤解是：畫面沒出來，就以為 build 壞了，於是重新 build 一次。多數情況下 build 根本沒問題，缺的只是開發伺服器。先確認 Metro 有沒有在跑、tunnel 有沒有開、網址有沒有貼對，比重新建置快得多。

遇到 app 卡在啟動畫面時，請依照這個順序檢查：

  1. Metro 是否已在行動專案資料夾中啟動。
  2. 一般連線是否因網路環境而失敗。
  3. 若一般連線失敗，是否改用 npx expo start --tunnel。
  4. 手動輸入時，是否完整複製從 http 或 https 到 /direct 的網址。

完成後，你應該看到什麼

development build 只是原生外殼，畫面與 JavaScript 來自電腦上的 Metro 開發伺服器。請在行動專案資料夾執行 npx expo start；若手機連不上，改用 npx expo start --tunnel。接著把終端機印出的網址，從 http 複製到結尾的 /direct，手動貼進 app 的輸入框。若 iOS 提示開發者模式，請到「設定 → 隱私權與安全性」開啟。

可驗證的成功標準是：app 在真機上顯示你的介面，並能完成一個真實操作。

到這裡，你已經能把 build 裝進真機並啟動。不過，「自己測試」和「把 app 交給別人測試」是兩件不同的事。下一節會比較 dev build、internal distribution 與 TestFlight，協助你判斷不同情境該使用哪一種方式。
