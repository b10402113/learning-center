用 EAS 在雲端產生 dev build：從 eas.json 到掃 QR code 安裝

Step 2/6 · EAS Build、真機與 TestFlight

這一節要完成什麼

這一節要把 Expo 專案的「外殼」裝進你的 iPhone：先準備 EAS 設定、註冊裝置，再讓 EAS 在雲端產生一份 development build，最後掃描 QR code 安裝到真機。

完成後，你會在 iPhone 主畫面看到一個 app 圖示。不過，點開它時畫面還不會自己跑起來，因為 dev build 比較像一個準備好的外殼；真正的介面要等下一節接上開發伺服器。這一節先把外殼裝好，啟動問題留到下一節處理。

開始前的準備

動手前請確認你有以下三樣東西：

  • 一個已經納入 git 版控的 Expo 專案。
  • 一個 EAS 帳號，可以免費註冊。
  • 一台 iPhone。

如果你的專案放在 monorepo 裡，行動 app 通常位於類似 apps/mobile 的子資料夾。接下來的 EAS 指令都要在這個資料夾裡執行，別讓指令跑錯地方。

第一步：切進行動專案，產生 eas.json

先切換到行動 app 的目錄。假設你的專案結構如下，指令會是：

cd apps/mobile

接著在這個資料夾裡產生名為 eas.json 的設定檔。這是 EAS 在雲端建置時使用的「施工圖」；沒有它，就沒有可依設定執行的雲端 build。

第一次使用時，先登入 EAS，再執行初始化流程。它會引導你建立這個檔案，並詢問幾個平台與方案相關的設定。這份檔案的用途，是告訴 EAS 專案有哪些建置設定，例如開發用、預覽用，以及正式上線用。

下面是一份精簡的 eas.json。通常初始化流程會幫你產生，不一定要手動輸入；但看得懂它，之後遇到問題才知道要從哪裡調整：

{
  "build": {
    "development": {
      "developmentClient": true,   // 這份 build 內含 dev client，會連回你的開發伺服器
      "distribution": "internal"   // 用內部散布：直接裝進你註冊過的裝置
    },
    "preview": {
      "distribution": "internal"   // 給測試者用的預覽版，一樣走內部散布
    },
    "production": {}               // 正式版設定，之後送審時用
  }
}

這裡先記住兩個關鍵設定：

  • developmentClient：讓 build 具備連接開發伺服器的能力，這是開發模式會用到的那條線。
  • distribution：決定 build 如何送到裝置。internal 代表內部散布，直接提供給已註冊的裝置安裝，不需要經過 App Store。

第二步：註冊你的 iPhone

使用內部散布前，EAS 必須知道你要安裝到哪一台裝置。因此，下一步是執行裝置註冊指令，並依照 EAS 的引導完成登記。

這通常只需要做一次，因為 EAS 會記住已註冊的裝置。若你換了手機，或要讓第二位測試者安裝，就必須替新的裝置再註冊一次。

如果註冊時遇到看不懂的畫面，可以直接截圖，並把「我現在卡在裝置註冊」一起交給你的 coding agent。讓它根據畫面一步步帶你操作，通常比自己在陌生選項裡猜測更快。之後除錯 build 時，也能沿用這個方法。

第三步：在雲端產生 development build

裝置註冊完成後，就可以送出 iOS 的雲端建置：

eas build --profile development --platform ios

執行這個指令後，專案會上傳到 EAS 雲端，編譯工作也會在雲端完成；你的 Mac 不需要負責實際建置。你可以到 Expo 的儀表板 expo.dev 查看進度，看它依序經過排隊、編譯，以及各個步驟的完成狀態。

第一次執行時，終端機可能會連續詢問幾個設定問題。若你還沒有特殊需求，可以先依照預設值一路按 Enter，讓建置流程開始。

不要把「build 失敗」當成壞事。真實世界很少一次就整排綠燈，設定的細節非常多，第一次失敗幾乎是常態。關鍵是失敗之後要怎麼處理，那正是 最後一節要教的：把完整 log 交給 AI，讓它讀出是哪個設定壞掉。這一節先把成功的流程走順。

若要建置 Android，流程相同，只要把平台參數改成 android：

eas build --profile development --platform android

Expo 的方便之處就在這裡：兩個平台共用大部分流程，只需要在少數地方指定差異。

第四步：掃 QR code，把 build 安裝到手機

建置完成後，終端機會顯示 QR code，Expo 儀表板上也會出現這份 build。拿起 iPhone，用相機掃描 QR code，接著依照系統引導完成安裝。

安裝完成後，iPhone 主畫面會多出一個 app 圖示。看到這個圖示，表示 dev build 已經成功進到真機。

先確認：為什麼打開後沒有畫面？

這裡有一個容易誤判的地方：不要期待 dev build 像一般 app 一樣，打開後立刻顯示完整介面。

第一次點開時，你多半只會看到 app 的 logo 與名稱，並顯示正在尋找開發伺服器。這不是安裝失敗，而是 dev build 的設計：它本身主要是外殼，介面並不直接放在安裝檔裡，而是等待你電腦上執行的開發伺服器提供。

下一節會啟動 Metro 開發伺服器，讓 app 真的顯示畫面；如果一般連線方式不通，也會改用 tunnel，或把 dev server 的網址手動貼進手機裡的 app。

完成檢查

做到這裡，可以依序確認以下結果：

  1. 你已經切進行動 app 的資料夾。
  2. 專案裡已經有 EAS 使用的 eas.json，而且 development profile 啟用了 developmentClient 與 distribution: internal。
  3. 你的 iPhone 已完成裝置註冊。
  4. EAS 已經完成 development build，或至少已在 expo.dev 顯示建置進度與結果。
  5. 你已掃描 QR code，並在 iPhone 主畫面看到 app 圖示。
雲端建置的流程是：cd 進行動專案、產生 EAS 需要的設定檔 eas.json（開發設定用 developmentClient 加 distribution: internal）、註冊你的 iPhone、執行 eas build --profile development --platform ios、在 expo.dev 儀表板看著它完成，最後掃 QR code 安裝。Android 只差把 platform 換掉。第一次跑會被問幾個設定問題，失敗也是常態；build 裝好後 app 不會自己顯示畫面，因為它還缺一個開發伺服器。

現在外殼已經在手機上了，還缺把 JavaScript 介面送進去的那條線。下一節就來啟動 Metro 開發伺服器，讓這個 dev build 從「裝好了」變成「真的能看到 app 畫面」。
