接上 Neon：設定 Drizzle client 與 drizzle.config

Step 3/5 · Neon + Drizzle 資料建模

這一節要完成什麼？

這一節的目標，是把 app 和 Neon 資料庫真正接起來。完成後，伺服器端的 API route 與背景 task 都能使用同一個 db 物件存取資料，drizzle-kit 也能找到你的 schema，為後續建立與更新資料表做好準備。

你會完成三件事：把 Neon 的連線字串放進環境變數、建立 Drizzle client，最後設定 drizzle.config.ts，讓命令列工具知道 schema 在哪裡，以及 migration 要輸出到哪裡。

動手前先確認兩樣東西都已經準備好：

  • 一個已建立的 Neon 專案，以及從中取得的 Postgres 連線字串。
  • 上一節完成的 schema.ts，也就是 users 與 meals 的資料表定義。

先看整體：把藍圖、程式與資料庫接成一條線

上一節讀完了 users 與 meals 兩張表，你手上已經有一份資料藍圖。不過，藍圖只是檔案裡的定義，還沒有連線把程式和 Neon 接起來。

這一節就像替房子接上水電：DATABASE_URL 是管線位置，db 是程式實際使用的入口，而 drizzle.config.ts 則是告訴 drizzle-kit 該去哪裡找藍圖、該把施工紀錄放在哪裡。

第一步：把連線字串放進 DATABASE_URL

到 Neon 的專案頁面，在 Connect 面板複製 Postgres 連線字串。它大致會長這樣：

postgresql://user:password@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require

接著在專案根目錄建立或編輯 .env，把連線字串放到名為 DATABASE_URL 的環境變數中。

同時，請把 .env 加進 .gitignore。這個檔案裡有資料庫密鑰，不能提交到版控；一旦跟著程式碼流出去，就等於把資料庫的鑰匙一起交給別人。

完成後，預期結果是：任何會讀取環境變數的指令，都能從 process.env.DATABASE_URL 取得這串連線字串。若讀不到，下一步建立 client 時就會直接報錯。

第二步：建立共用的 Drizzle client

在 src/db/index.ts 建立資料層入口。之後伺服器端程式只要 import 這個檔案，就能使用同一個 db 物件：

import { neon } from "@neondatabase/serverless";
import { drizzle } from "drizzle-orm/neon-http";

import * as schema from "./schema";

// Server-only. Never import this from a screen or component — Metro would
// bundle the driver into the app.
const url = process.env.DATABASE_URL;
if (!url) throw new Error("DATABASE_URL is not set");

export const db = drizzle({ client: neon(url), schema, casing: "snake_case" });

export * from "./schema";

這段程式可以分成幾個動作來看。

  1. neon(url) 建立 Neon 的 serverless HTTP driver。它不是維持傳統的長連線，而是透過 HTTP 傳送查詢，適合 serverless 環境。

  2. schema 匯入整包資料表定義。把它交給 Drizzle 後，Drizzle 才知道有哪些表，也能根據這些定義提供相對應的型別。

  3. drizzle({ client: neon(url), schema, casing: "snake_case" }) 把連線、schema 與命名規則組合起來，產生程式真正會使用的 db。

  4. export * from "./schema" 讓其他檔案從同一個 index.ts 就能同時取得 db 和資料表定義，少一層轉手。

為什麼要設定 casing？

TypeScript 的屬性通常使用 camelCase，例如 clerkUserId、loggedAt；Postgres 的欄位則常使用 snake_case，例如 clerk_user_id、logged_at。

casing: "snake_case" 會替你處理這個命名落差。程式碼可以維持容易閱讀的 camelCase，Drizzle 則會用 snake_case 對應到資料庫欄位。沒有這項設定時，你可能得在每個欄位上手動標明資料庫名稱。

讓設定錯誤立刻失敗

這兩行是刻意安排的快速失敗（fail fast）：

const url = process.env.DATABASE_URL;
if (!url) throw new Error("DATABASE_URL is not set");

如果連線字串不存在，程式會在 import 這個檔案時立刻報錯，而不是過了好幾個步驟後才出現一個模糊的資料庫錯誤。錯得早、錯得清楚，通常比錯得晚、錯得難追好處理。

警告：db 是 server-only

不要在畫面或元件裡 import src/db/index.ts。

手機 app 使用 Metro 這個打包器。只要畫面 import 了 db，相關的 Neon driver 就可能被打包進 app bundle，讓資料庫連線能力出現在手機端程式碼中。

因此，這個 db 只能在 API route、背景 task 等伺服器端位置使用。若 X 是畫面或元件，則不要 import db；若 X 是伺服器端程式，才可以透過它查詢資料。

第三步：設定 drizzle.config.ts

接著建立或編輯 drizzle.config.ts。這個檔案是給 drizzle-kit 命令列工具使用的，不是 app 執行時的資料庫 client：

import { defineConfig } from "drizzle-kit";

process.loadEnvFile(); // Node built-in, no dotenv needed

export default defineConfig({
  schema: "./src/db/schema.ts",
  out: "./drizzle",
  dialect: "postgresql",
  casing: "snake_case", // must match src/db/index.ts
  dbCredentials: { url: process.env.DATABASE_URL! },
});

請逐項確認這份設定：

  • schema：告訴工具去哪裡讀取資料表定義。
  • out：指定產生的 migration 檔案要放在哪個資料夾。
  • dialect: "postgresql"：指定使用的資料庫種類。
  • dbCredentials：提供連線 Neon 所需的 URL。

這裡的 casing: "snake_case" 必須和 src/db/index.ts 裡的設定一致。若 runtime 使用 snake_case，但產生 migration 的工具採用另一套規則，兩邊推算出的欄位名稱就可能不同，最後會變成很難追查的錯誤。

另外，process.loadEnvFile() 是 Node 內建的功能，可以用來讀取 .env，因此不需要另外安裝 dotenv。

第四步：確認資料庫指令已接上

打開 package.json，確認 scripts 至少包含以下資料庫指令：

"db:generate": "drizzle-kit generate",
"db:migrate": "drizzle-kit migrate",
"db:push": "drizzle-kit push",
"db:studio": "drizzle-kit studio"

這一節不用先把所有指令都背起來。現在先記住兩個重點：

  • db:generate 與 db:migrate 會在下一節成為主角。
  • db:studio 會開啟圖形介面，讓你查看資料庫中的表與資料，也適合用來驗證連線是否成功。

驗證：確認這條線真的通了

執行 db:studio。如果連線設定正確，應該會開啟資料庫瀏覽介面，並讀得到 Neon 上的資料庫。

此時畫面可能還是空的，這不代表設定失敗。因為資料表還沒建立，資料也還沒灌入；這些工作會在後面的章節完成。這一節只驗證一件事：程式能不能透過設定好的連線找到 Neon。

完成後，你應該得到什麼？

接上 Neon 分成三個檔案。把連線字串放進 DATABASE_URL 並排除在版控外；在 src/db/index.ts 用 neon() 加上 drizzle() 建立 db，設定 casing: "snake_case" 對齊兩邊的命名，並在缺少環境變數時立刻報錯；在 drizzle.config.ts 告訴 drizzle-kit 去哪裡讀 schema、產生的 migration 放哪裡。切記這個 db 是 server-only，不能被畫面 import。設定完成後，用 db:studio 驗證連線。

完成後，你應該能在伺服器端程式中 import db，也能用 db:studio 連到 Neon。資料庫裡暫時沒有表是正常的，因為目前只完成了連線與工具設定。
