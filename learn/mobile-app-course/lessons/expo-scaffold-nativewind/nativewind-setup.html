安裝與接線 NativeWind

Step 4/5 · 建立 Expo 專案與 NativeWind

這一節要完成什麼

完成本節後，你的 Expo 專案就能使用 NativeWind：在 React Native 元件上寫 className，並讓 Tailwind CSS 的工具類別轉成對應的原生樣式。

你會依序完成這些工作：

  1. 安裝 nativewind 與 Tailwind CSS v3。
  2. 建立 tailwind.config.js 與 global.css。
  3. 接好 Babel、Metro 與 root layout。
  4. 清除快取並重啟 Expo，確認設定已被讀取。

開始前先確認專案狀態

請使用第二節清理完成的空白專案，並確認終端機目前位在專案根目錄。src/app/ 裡應該只剩下 index.tsx 和 _layout.tsx，而專案根目錄已經有 create-expo-app 產生的 package.json。

為什麼要看懂每條接線

上一節已經說明過，NativeWind 可以想成建置階段的翻譯官：你寫下 Tailwind 的 class，Babel 與 Metro 會在打包過程中把它接到 React Native 的樣式系統。

實務上，你也可以把 NativeWind 官方文件整份交給 coding agent，請它照文件設定。這確實能省下逐一比對版本的時間，但前提是你看得出設定是否正確。

少一個 preset、content 掃錯資料夾，或忘記 import 樣式，都可能造成「沒有紅字錯誤，但畫面完全沒反應」的沉默失敗。接下來我們把安裝拆成幾個可檢查的步驟，讓每個檔案都像電路上的接點一樣清楚。

步驟一：安裝套件

npx expo install nativewind
npm install --save-dev tailwindcss@^3.4.17

這裡要特別留意版本。安裝 tailwindcss 時，請指定 v3，不要直接安裝最新版。NativeWind v4 目前搭配的是 Tailwind v3 的規則與 preset，兩個版本的設定格式並不完全相容。

第一行使用 npx expo install，是讓 Expo 根據目前的 Expo SDK 選擇相容的 nativewind 版本。第二行則把 tailwindcss 放進 devDependencies，因為它只在建置階段使用，不會成為 app 執行時的依賴。

步驟二：建立 tailwind.config.js

在專案根目錄新增 tailwind.config.js：

// tailwind.config.js
/** @type {import('tailwindcss').Config} */
module.exports = {
  content: ['./src/**/*.{js,jsx,ts,tsx}'],
  presets: [require('nativewind/preset')],
  theme: {
    extend: {},
  },
  plugins: [],
};

這個檔案有兩個關鍵設定。

第一個是 content。它告訴 Tailwind 要去哪裡掃描 class 名稱。這裡會掃描 src/ 底下所有 JavaScript 與 TypeScript 原始碼。如果日後把元件移到其他資料夾，這個 glob 也要一併更新；否則新位置的 class 可能被漏掉。

第二個是 presets。nativewind/preset 提供 NativeWind 所需的對照規則，讓 Tailwind class 能轉成 React Native 樣式。少了這個 preset，就像翻譯官沒有字典，許多 class 便無法正確對應。

步驟三：建立 global.css

在 src/ 底下新增 global.css：

/* src/global.css */
@tailwind base;
@tailwind components;
@tailwind utilities;

這三行是 Tailwind 的標準入口指令，分別載入基礎樣式、元件層與工具類層。

檔案本身很簡單，真正重要的是它必須交給 Metro 編譯。下一步的 Metro 設定會指定這個檔案，讓它成為 NativeWind 的 CSS 入口。

步驟四：接上 babel.config.js

專案原本應該已經有 babel.config.js，請把內容改成：

// babel.config.js
module.exports = function (api) {
  api.cache(true);
  return {
    presets: [
      ['babel-preset-expo', { jsxImportSource: 'nativewind' }],
      'nativewind/babel',
    ],
  };
};

這個檔案負責 JSX 的轉換。請確認兩個設定都存在：

  • jsxImportSource: 'nativewind'：讓 JSX 轉換知道要由 NativeWind 處理 className。React Native 原生元件本身沒有這個 prop，必須透過這條設定接進來。
  • nativewind/babel：把 className 的處理流程接到 NativeWind。
注意：修改 Babel 設定後，單純存檔觸發的 hot reload 不會重新載入這些設定。你必須完整重啟 Metro，新的 Babel 設定才會生效。

步驟五：接上 metro.config.js

預設的 Expo 專案不一定會有 metro.config.js。如果沒有，請在專案根目錄新增；如果已經有，則調整成這個階段需要的形式：

// metro.config.js
const { getDefaultConfig } = require('expo/metro-config');
const { withNativeWind } = require('nativewind/metro');

const config = getDefaultConfig(__dirname);

module.exports = withNativeWind(config, { input: './src/global.css' });

這裡的核心是最後一行。withNativeWind() 會包住 Expo 原本的 Metro 設定，而 input 則明確指定 CSS 入口：

  • 若使用 NativeWind，就用 withNativeWind(config, ...) 包裝設定。
  • 若 CSS 檔案位於 src/global.css，就把 input 設為 './src/global.css'。

這個路徑必須和步驟三實際建立的檔案完全一致。少打一個資料夾名稱，NativeWind 就找不到要編譯的來源。

日後在完成版的 Cal AI 專案中，你可能會看到更複雜的 metro.config.js：外層可能包了 Sentry 設定，也可能加入給 trigger.dev 使用的 resolver 條件。那些是後面加入原生模組後才需要的設定，目前不用處理。無論外層包了幾層，NativeWind 的核心接線仍然是最後那個 withNativeWind。

步驟六：補上型別宣告

在專案根目錄新增 nativewind-env.d.ts：

/// <reference types="nativewind/types" />

這個檔案只有一行。它不參與 app 的執行流程，而是告訴 TypeScript 認得 NativeWind 的型別，包含 className 這個 prop。沒有它時，編輯器可能會把你寫的 className 標成錯誤。

如果你使用的是純 JavaScript 專案，可以略過這一步。

步驟七：在 root layout 載入樣式

這是最容易漏掉的一步。即使套件、Tailwind、Babel 與 Metro 都設定正確，如果沒有在會被載入的地方 import global.css，畫面仍然不會有任何變化。

請修改 src/app/_layout.tsx：

// src/app/_layout.tsx
import '@/global.css';
import { Stack } from 'expo-router';

export default function RootLayout() {
  return <Stack />;
}

這裡的 @/ 是專案別名，對應到 src/，因此 @/global.css 實際上指向 src/global.css。

如果專案沒有設定這個別名，也可以改用相對路徑 ../global.css。重點只有一個：這份 CSS 必須在某個會被載入的地方 import 一次。

步驟八：清除快取並重啟

npx expo start -c

-c 會清除 Metro 快取。因為這次修改了 Babel 與 Metro 設定，而這些設定通常只會在啟動時讀取一次，所以舊快取可能仍然保留先前的打包結果。

若看到 Metro 正常啟動，且終端機沒有紅字錯誤，就代表這次接線已經完成。此時畫面仍然是一張空白頁也沒關係；className 套到畫面上是不是真的有效，下一節再驗證。

完成後逐項檢查

請對照下表確認每個檔案與設定都已到位：

檔案完成狀態
package.json有 nativewind（dependencies）與 Tailwind CSS v3（devDependencies）
tailwind.config.jscontent 指向 ./src/**，presets 載入 nativewind/preset
src/global.css包含三行 @tailwind 指令
babel.config.js包含 jsxImportSource: 'nativewind' 與 nativewind/babel
metro.config.js使用 withNativeWind(config, { input: './src/global.css' })
nativewind-env.d.ts包含一行 NativeWind 型別參照
src/app/_layout.tsximport 了 @/global.css

你現在應該得到的結果

完成 NativeWind 設定可以分成三組動作：安裝 nativewind 與 Tailwind CSS v3；建立 tailwind.config.js 與 global.css；接好 Babel 的 jsxImportSource 與 preset、Metro 的 withNativeWind，以及 root layout 的 global.css import。都完成後，執行 npx expo start -c 清除快取並重啟。每個設定都對應 NativeWind 建置流程中的一個接點，漏掉任何一個，都可能出現「不報錯，但 className 沒反應」的結果。

做到這裡，專案已經具備使用 NativeWind 的條件。不過，「檔案設定正確」和「樣式真的生效」是兩件事。下一節會在 index.tsx 寫入一段 className，直接觀察畫面是否變成藍底白字；如果沒有，再依照這些接點逐一排查。
