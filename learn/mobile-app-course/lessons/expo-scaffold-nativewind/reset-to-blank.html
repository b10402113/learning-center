reset-project：把範例清成空白

Step 2/5 · 建立 Expo 專案與 NativeWind

學習目標

能跑 npm run reset-project 把 Expo starter 的範例清成單一畫面，並說明「搬到 example」與「直接刪除」兩種選擇的差別。

前言：能跑的範例，反而是種干擾

上一節結束時，你已經有一個能在模擬器裡跑的 Expo 專案。但它跑的是 Expo 附的示範畫面：幾個 tab、一些展示元件、一堆 components、constants、hooks 的檔案。這些東西你沒寫過，也不是你的 app 需要的。

留著它們會有什麼問題？當你之後請 AI agent 照著 plan.md 開工時，它會先讀到這堆範例程式碼。有些範例檔案的名稱和你的需求很像，agent 可能誤把範例當成既有基礎，圍繞著它修改，而不是長出你真正要的結構。與其讓它在一座別人搭好的樣品屋裡繞來繞去，不如先把屋子清空，再從一張白紙開始蓋。

這一節要做的事很單純：跑一個 Expo 附帶的腳本，把範例清掉，換來一個只有單一畫面的乾淨起點。

reset-project 是什麼

Expo 的 starter 範本裡附了一支腳本，路徑是 scripts/reset-project.js，並且在 package.json 裡登記成一個 npm script：

"reset-project": "node ./scripts/reset-project.js",

換句話說，執行 npm run reset-project 時，npm 會去呼叫這支 Node 腳本。這就是整個 reset 流程的入口。

動手前：先停掉開發伺服器

如果你上一節的 npx expo start 還開著，先在終端機按 Ctrl + C 把它停掉，並且把畫面清一清。這樣等等 reset 的輸出會比較好讀，也避免伺服器在你刪檔案的同時還在讀那些檔案。

執行 reset 腳本

在專案根目錄執行：

npm run reset-project

腳本接著會問你一個問題，原文是：

Do you want to move existing files to /example instead of deleting them? (Y/n):

這個提問給你兩條路：

  • 輸入 y（或直接按 Enter）：腳本會建立一個 example/ 資料夾，把舊的 src/ 與 scripts/ 整包搬進去，而不是刪掉。你可以先進去翻一翻，確認沒有想留下的東西，再自己把 example/ 刪掉。
  • 輸入 n：直接把舊的 src/ 與 scripts/ 刪除。乾淨俐落，但沒有回頭路。

提問後面那個 (Y/n) 透露了預設值。程式碼在讀到你的輸入後，會先轉小寫、去掉空白，如果什麼都沒輸入就用 "y"：

const userInput = answer.trim().toLowerCase() || "y";

課程裡的做法是選 y，先讓它搬到 example/，確認之後再把整個 example/ 資料夾刪掉。這樣做等於「有備份地清空」，比較安心。

這支腳本會搬動或刪除 src/ 與 scripts/，是有破壞性的操作。只在剛 scaffold 出來、還沒開始寫自己的程式碼的專案上跑它。如果專案裡已經有你的心血，千萬不要執行。

該選 y 還是 n？

兩種選擇其實對應兩種心態。如果你對 Expo 的範例還有一點好奇，或者擔心之後想參考它的某個寫法，那就選 y，讓它先把東西搬到 example/。這個資料夾不參與打包，放在那裡不會影響 app，你之後可以隨時進去翻，確認不需要了再整個刪掉。

如果你很清楚自己不會回頭看範例，選 n 直接刪掉最省事，少一個資料夾要管理。課程裡雖然選了 y，但緊接著就把 example/ 也刪了——換句話說，它只是用「先搬再刪」換取一點心理上的安全感，最終結果和選 n 是一樣的。

不管選哪一個，重點都是：過了一段時間、專案已經有自己的程式碼之後，就不要再回頭跑這支腳本了。它設計的場景是「剛 scaffold、還沒有任何自己的東西」，不是一個可以反覆重設的按鈕。

它清理之後留下了什麼

腳本會重新建立一個 src/app/ 目錄，並放入兩個最小檔案。第一個是主畫面 src/app/index.tsx，內容只有一個置中的文字：

import { Text, View, StyleSheet } from "react-native";

export default function Index() {
  return (
    <View style={styles.container}>
      <Text>Edit src/app/index.tsx to edit this screen.</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    alignItems: "center",
    justifyContent: "center",
  },
});

第二個是路由的外框 src/app/_layout.tsx，內容只有一個 Stack：

import { Stack } from "expo-router";

export default function RootLayout() {
  return <Stack />;
}

注意 src/app/index.tsx 裡的樣式寫法：它用的是 StyleSheet.create，也就是 React Native 原生的樣式物件。這個寫法等下一節談 NativeWind 時會再碰面，到時你會看到它跟 className 的差異。

腳本跑完也會在終端機印出後續步驟，提醒你「畫面與 layout 檔放在 src/app，其餘應用程式碼放 src」，並且提示你可以把 reset-project 這個 script 從 package.json 移除、把腳本檔刪掉——因為 reset 一輩子只需要在專案最開始做一次。

驗證：重新跑起來

清完之後，重新啟動開發伺服器：

npx expo start

跑起來後在終端機按 r 重新載入，或在模擬器裡重新整理。這次畫面應該只剩下一行簡單的文字，不再是那個多 tab 的範例。如果還有舊畫面殘留，通常是快取問題，可以改用 npx expo start --clear 清掉 Metro 的快取再啟動。

看到那行單一文字，就代表你成功了：專案回到乾淨的起點，接下來要加的每一張畫面，都會是你自己的。

反過來說，如果畫面還是那個多 tab 的範例、或出現找不到模組的錯誤，通常是三種原因：reset 根本沒跑成功（回頭看終端機有沒有出現取代完成的訊息）、伺服器還吃著舊的快取（用 --clear 重啟）、或者新產生的 src/app 沒有被正確載入。這幾種狀況都不難修，重點是知道「成功長什麼樣」，才有辦法判斷自己現在在哪一步。

小結

npm run reset-project 會把 Expo starter 的 src/ 與 scripts/ 搬到 example/ 或直接刪除，然後重建一個只含 index.tsx 與 _layout.tsx 的 src/app/。它只能在新專案上執行，跑完就得到一個單一畫面的乾淨起點。

現在專案很乾淨，但也還很樸素——畫面上那行字幾乎沒有樣式。接下來就要處理「怎麼漂亮地寫樣式」這件事。在網頁上你會直接用 Tailwind，但在手機上沒有瀏覽器與 CSS 引擎，於是一套叫做 NativeWind 的工具登場了。下一節先把它的運作原理講清楚。
