reset-project：把 Expo 範例清成一張白紙

Step 2/5 · 建立 Expo 專案與 NativeWind

這一步要完成什麼

這一節完成後，你會得到一個沒有官方示範畫面的 Expo 專案。首頁只顯示一行提示文字，之後你可以從 src/app/ 開始建立自己的 app。

開始前，請先確認你已經建立好 Expo 專案，而且曾經用 npx expo start 跑起開發伺服器。這一節要執行的 cleanup script 會搬移或刪除檔案，所以動手前不要把自己的程式碼放進專案裡。

為什麼先清掉官方範例

上一節跑起專案時，你可能看到分頁列、範例卡片、示範元件，還有淺色與深色模式切換。畫面看起來很完整，但那是 Expo starter 的展示品，不是你的產品骨架。

如果把這些檔案留在原地，之後叫 agent「加一個首頁」時，它很可能參考現有的分頁結構、命名方式和範例元件。結果就像在別人畫滿草稿的紙上繼續作畫：你寫的是自己的 app，資料夾裡卻一直混著別人的設計。

常見的兩種做法都不理想：

  • 全部留著：專案裡會多出一堆永遠用不到的檔案，agent 每次搜尋時都要先分辨哪些內容相關。
  • 直接在範例上加功能：最後容易變成一半是官方樣板、一半是你的程式碼，兩套結構互相干擾。

因此，這一步先把範例移走或刪除，再重建一個最小的 src/app/。乾淨的起點，會比要求 agent 一直繞開樣板更可靠。

第一步：停止開發伺服器

先切回執行 npx expo start 的終端機，按下 Ctrl+C 停止伺服器。

接下來的腳本會搬動、刪除並重新建立檔案。若讓 Metro 同時監看這些變化，終端機可能出現不必要的警告。清理完成、確認畫面正確後，再重新啟動即可。

第二步：執行 reset script

在專案資料夾執行：

npm run reset-project

終端機會詢問：

Do you want to move existing files to /example instead of deleting them? (Y/n):

這個問題是在確認：舊的範例檔案要保留在 example/ 資料夾，還是直接刪掉。

  • 若輸入 y，或直接按 Enter：把 src/ 和 scripts/ 搬到 example/ 底下，檔案仍然保留。
  • 若輸入 n：直接刪除 src/ 和 scripts/。

目前還沒有自己的程式碼，因此兩種選擇都不會傷到你的內容。實務上可以選 y，先保留範例當參考，等確定不需要後再刪掉 example/。

第三步：了解腳本重建的內容

不論你選 y 或 n，腳本接著都會建立最小的 src/app/。其中的 index.tsx 會長這樣：

// src/app/index.tsx
import { Text, View, StyleSheet } from "react-native";

export default function Index() {
  return (
    <View style={styles.container}>
      <Text>Edit src/app/index.tsx to edit this screen.</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, alignItems: "center", justifyContent: "center" },
});

首頁元件匯入 React Native 的 Text、View 和 StyleSheet。View 負責容器，Text 顯示提示文字，而 styles.container 讓文字置中。

路由外框則是：

// src/app/_layout.tsx
import { Stack } from "expo-router";

export default function RootLayout() {
  return <Stack />;
}

_layout.tsx 只回傳一個空的 <Stack />，也就是保留 Expo Router 的基本路由外框，但不預先加入分頁或其他示範畫面。

這支腳本做的事情其實很直接：

  1. 如果選擇保留範例，就建立 example/。
  2. 把舊的 src/ 和 scripts/ 用 rename 搬走，或用 rm 刪除。
  3. 用 mkdir 建立新的 src/app/。
  4. 用 writeFile 寫入新的 index.tsx 和 _layout.tsx。
警告：這支腳本會真的刪除或搬移檔案，動作不可逆。請只在專案還沒有自己的程式碼時執行。開始寫自己的畫面後，不要再跑它，否則你的程式碼也可能被清掉。package.json 裡的 reset-project 指令用完可以移除。留著只是方便下次重新清理專案。

第四步：確認清理結果

如果你選擇保留範例，而且已經確定不需要參考，可以先刪除 example/ 資料夾。接著重新啟動 Expo：

npx expo start

啟動後按 i 開啟模擬器。畫面中央應該只出現這一行文字：

Edit src/app/index.tsx to edit this screen.

看到這行，就表示官方範例已經清掉，現在的畫面只剩最小的首頁與路由設定。你也可以立即驗證修改流程：把 index.tsx 裡的文字換成自己的內容並存檔，模擬器應該會更新。之後做畫面時，你會一直重複「修改、存檔、查看結果」這個循環。

完成後的專案狀態

執行 npm run reset-project 後，Expo starter 的 src/ 與 scripts/ 會被搬到 example/ 或直接刪除，接著重建新的 src/app/。裡面只有 index.tsx（顯示一行置中文字）與 _layout.tsx（空的 <Stack />）。重新啟動並看到單行提示文字，就是乾淨的開發起點了。

做完這一步，專案的內容已經清楚了，但樣式寫法仍然比較囉嗦。單純把文字置中，就需要建立 StyleSheet.create 和一個 style 物件。下一節會把 NativeWind 帶進 React Native，讓你能用熟悉的 Tailwind className 寫樣式，並先把需要的設定處理好。
