跑起來，確認 NativeWind 樣式真的生效

Step 5/5 · 建立 Expo 專案與 NativeWind

這一步要完成什麼

這一節的目標，是在 Expo 模擬器中用 className 改變畫面，並透過「存檔後立即更新」確認 NativeWind 已經接通。完成後，你應該會看到藍色背景與白色文字；如果樣式沒有出現，也能依序檢查匯入、content glob、Babel 與 Metro 設定。

開始前，請先完成前面幾節的準備：Expo 專案已建立、NativeWind 相關套件與設定已接上，而且你知道首頁檔案位在 src/app/index.tsx。這一步不用再安裝任何東西，只要把整條管線跑起來，確認它真的能運作。

先知道整體流程

接下來會依序做四件事：

  1. 啟動 Metro，並開啟 iOS 或 Android 模擬器。
  2. 在 src/app/index.tsx 寫入一個使用 className 的畫面。
  3. 存檔，觀察模擬器是否即時變成預期的樣子。
  4. 如果樣式沒有出現，就按照固定順序排查設定。

前面把該裝的裝了、該接的接了，但「檔案寫對」和「真的生效」中間還隔著一哩路。設定檔出錯時，常常不會跳出明顯錯誤，只是讓樣式安靜地消失。沒有親眼看到畫面變化，就還不能算完成驗收。

步驟一：啟動 Metro 與模擬器

如果 Metro 目前沒有執行，先啟動它。因為上一節曾經調整設定，這次建議直接清除快取重新開始：

npx expo start -c

等 Metro 啟動完成後，按 i 開啟 iOS 模擬器，或按 a 開啟 Android 模擬器。

一切正常的話，終端機不會出現紅色錯誤訊息。若看到與 Babel 或 NativeWind 有關的錯誤，先繼續完成後面的步驟，再依照排查順序處理。

步驟二：用 className 寫首頁

打開 src/app/index.tsx，把內容換成下面這段：

// src/app/index.tsx
import { Text, View } from "react-native";

export default function Index() {
  return (
    <View className="flex-1 items-center justify-center bg-blue-500">
      <Text className="text-white text-2xl font-semibold">
        NativeWind 生效了
      </Text>
    </View>
  );
}

這段程式碼可以分成兩個重點來看。

  • View 使用 flex-1 撐滿畫面，再用 items-center justify-center 把內容放到中央，背景則是 bg-blue-500。
  • Text 使用 text-white 顯示白字，text-2xl 放大字級，font-semibold 調整字重。

這和清理專案後的版本不同。原本的寫法使用 StyleSheet.create，需要在檔案底部另外宣告 style 物件，再用 style={styles.container} 套用。現在則把樣式直接寫在 className 裡，使用方式和網頁上的 Tailwind 很接近。

同樣的效果，一個版本需要額外宣告 style 物件，另一個版本只要在元件旁寫 class 字串。畫面一多、元件開始重複，這個差異就會慢慢放大；而且 className 用的是共通的設計數值，例如顏色、間距與字級，不必每個檔案各自發明一組數字。

步驟三：存檔並確認畫面

現在直接存檔，不需要再下其他指令。Metro 會偵測檔案變更，重新打包受影響的部分，再把更新推送到模擬器。

幾秒內，你應該看到：

  • 整個畫面是藍色背景。
  • 畫面中央顯示白色文字「NativeWind 生效了」。

如果畫面如預期變化，代表從 className 到 NativeWind style 的整條流程已經接通：Babel 能處理 className，Metro 能編譯 global.css，Tailwind 能掃描檔案中的 class，而 NativeWind 能把這些 class 轉成 React Native 的 style。

你也可以做一個小測試。把 bg-blue-500 改成 bg-emerald-500，再把 text-2xl 改成 text-4xl。存檔後，背景顏色和文字大小應該會立即改變。

這個「改一點、存檔、看結果」的循環，就是接下來製作每一張畫面時都會使用的基本工作方式。

如果樣式沒有出現：依序排查

如果藍色背景與白色文字都沒有出現，畫面仍然和清理專案後一樣，通常表示某個設定漏掉了。請按照下面順序檢查，每次只修改一個地方，修改後先存檔觀察結果。

  1. 確認 root layout 有匯入 global.css。 打開 src/app/_layout.tsx，確認第一行有 import '@/global.css';。這是最常見的漏項；沒有這行，前面的設定就不會被載入。
  2. 確認 content glob 指向正確位置。 打開 tailwind.config.js，確認 content 是 ./src/**/*.{js,jsx,ts,tsx}。如果畫面檔案不在 src/ 底下，這裡也必須跟著調整，否則 Tailwind 掃不到你寫的 class。
  3. 確認 Babel 設定。 檢查 babel.config.js 是否同時包含 jsxImportSource: 'nativewind' 與 nativewind/babel。少了其中任何一個，className 都不會被正確處理。
  4. 確認 Metro 的 input 路徑。 檢查 metro.config.js 是否使用 withNativeWind(config, { input: './src/global.css' })。這個路徑必須和實際的檔案位置完全一致。
  5. 確認 tailwindcss 版本。 檢查 package.json。如果安裝的是 v4，可能會出現不相容問題；需要時重裝 tailwindcss@^3.4.17。
  6. 清除快取並重新啟動。 如果你剛修改 Babel 或 Metro 設定，hot reload 不會套用這些變更。請停止伺服器，再重新執行 npx expo start -c。
最容易搞混的一點：改「原始碼」會即時更新，改「設定檔」不會。 className 寫錯或想換顏色，存檔即可；但只要動到 babel.config.js、metro.config.js 或 tailwind.config.js，就一定要重啟 Metro，因為這些設定只在啟動時讀一次。

步驟四：用一個小變更再次驗收

排查完成後，再把 bg-blue-500 改成 bg-emerald-500，存檔確認畫面是否更新。若背景顏色能跟著變，表示你看到的不只是一次成功畫面，還有後續的開發循環能不能正常跑。

接下來製作 welcome、onboarding 或首頁時，都會反覆使用這個循環。差別在於，之後除了確認樣式有沒有生效，還會把模擬器截圖和設計稿比對，再一步步調整到接近。那個更完整的比對流程，會在下一個節點處理。

完成後應該看到什麼

完成這一步後，你應該有一個能執行、也能用 className 撰寫樣式的 Expo 專案。首頁會顯示藍色背景與中央白字「NativeWind 生效了」，而且修改 class 後，存檔就能在模擬器中看到變化。

這也代表你已經走完建立專案、清理成白紙、接上 NativeWind 設定，以及驗證樣式生效的流程。原理細節可以放到其他章節深入理解；在這裡，先確認這套流程能穩定跑出預期的結果。

小結

驗證 NativeWind 的方法很直接：在 index.tsx 用 className 寫一段樣式，存檔，觀察模擬器是否變成預期的樣子。生效代表 Babel → Metro → Tailwind → NativeWind 的管線已經接通；沒有生效，就依序檢查 root layout 的 global.css import、Tailwind 的 content glob、Babel 的 jsxImportSource 與 preset，以及 Metro 的 withNativeWind input，最後用 npx expo start -c 清除快取。記得：原始碼改動會即時更新，設定檔改動必須重啟 Metro。
