用 create-expo-app 建立專案

Step 1/5 · 建立 Expo 專案與 NativeWind

學習目標

能在一個空資料夾裡用 create-expo-app 生出 Expo 專案，看懂它替你長出哪些檔案，並把第一個預設畫面開進 iOS 模擬器。

前言：計畫寫完了，第一個指令下在哪裡？

規劃階段結束時，你手上有一份寫著 goals、features、pages 與 tech stack 的 plan.md。但計畫再完整，它終究只是一份文件；要讓後面的 UI、登入、資料庫有地方落腳，你得先有一個真的能在手機上跑起來的專案。

第一個動手的時刻，通常是最容易卡住的地方。你會發現自己盯著一個空資料夾，不確定該先裝什麼、要下哪一行指令，也不知道跑完之後那些冒出來的檔案各自在做什麼。這一節就是把這一步走完：從一個空資料夾開始，用一行指令長出一個 Expo app，並在模擬器裡看到畫面。做完之後，你得到的是後面每一張畫面都會依附的「地基」。

動手前先確認的事

開始之前，先確定環境具備這幾樣東西：

  • 電腦上已安裝 Node.js 與它的套件管理器 npm，終端機可以執行 node 與 npm。
  • 一個空專案資料夾。官方指令會把整包檔案倒進你當下所在的目錄，所以資料夾裡最好先不要有其他東西。
  • 一個能跑手機模擬器的環境。macOS 上裝好 Xcode 就能開 iOS 模擬器；Windows 則可以安裝 Android 模擬器。
  • （可選）你的 coding agent。這些指令其實也能交給它跑，但第一次建議自己手動執行一次，你才會親眼看到專案長什麼樣子。

第一步：從官方文件複製建立指令

建立 Expo 專案的起點，是官方文件 expo.dev 上的那行指令。Expo 是目前開始一個手機 app 專案相當順手的方式：它把從開發、建置到上架 App Store 與 Play Store 需要的工具都放在同一條流程裡，而且可以免費開始。若你之後認真要上架，才需要考慮付費方案。

把官方文件裡的建立指令複製到終端機，並在結尾加上一個點：

npx create-expo-app@latest .

那個點就是「在目前這個資料夾建立專案」的意思。不加點的話，指令會另外開一個以專案名稱命名的子資料夾；加了點，整包專案就會直接長在你現在的位置，也正好對上「我已經先準備好一個空資料夾」這個前提。

第二步：回答 SDK 版本的提問

指令開始跑之後，會先問你要用哪個 SDK 版本。錄這門課的時候是 SDK 57，但你看到這篇文章時，數字可能已經往上跳了。

這件事不用緊張。版本會隨時間演進，Expo 官方文件上的預設值就是當下建議的版本，你直接按 Enter 接受即可。真正要記住的不是「57」這個數字，而是「建立專案時跟著官方當下的建議走」。

第三步：認識它生出來的檔案

安裝完成後，你會看到一整排新檔案。第一次看到很容易被數量嚇到，但其實可以分成幾類來理解：

檔案或目錄它在做什麼
package.json專案的套件清單與指令表，之後安裝套件、跑腳本都看它
app.jsonapp 的設定檔：名稱、icon、bundle id、權限與外掛
babel.config.js決定 JavaScript／JSX 怎麼被編譯
metro.config.jsMetro 打包工具的設定，決定 bundle 怎麼組成
tsconfig.jsonTypeScript 的設定
src/app/（或 app/）畫面與路由所在，Expo Router 用它來決定每個畫面
assets/字型、圖片、app icon 等靜態資源

其中 package.json 裡的 scripts 區塊值得先看一眼，因為你之後最常下的幾行指令都寫在這裡：

"scripts": {
  "start": "expo start",
  "reset-project": "node ./scripts/reset-project.js",
  "android": "expo run:android",
  "ios": "expo run:ios",
  "web": "expo start --web",
  "lint": "expo lint",
  …

start 負責啟動開發伺服器；reset-project 是下一節的主角；ios 與 android 則是之後要做原生建置時用的。現在你只需要先跟 start 混熟。

第四步：開進模擬器

專案建好之後，在專案資料夾裡啟動開發伺服器：

npx expo start

伺服器啟動後，終端機會列出幾個快捷鍵。macOS 上按 i 會開啟 iOS 模擬器，Windows 或想跑 Android 的人按 a。第一次啟動模擬器會慢一些，因為它要開機、安裝並把 JS bundle 送進去，但之後再啟動就快得多。

伺服器跑著的時候，終端機還會提供一個 r 快捷鍵重新載入 app。之後你每次改完程式碼，不需要重新下指令，畫面會自動或手動更新。

Expo 最近的版本也讓 Windows 使用者能執行 iOS 模擬器，這是比較新的能力。如果你是 Windows 開發者又需要 iOS 模擬器，可以去官方文件確認目前的做法。

做完會看到什麼

如果一切順利，你會在模擬器裡看到 Expo 附的預設範例畫面：通常是幾個 tab、一些展示元件，還有一段示範文字。這代表你的專案已經活起來了。

但這個畫面是 Expo 的範例，不是你 app 的畫面。它裡面帶著一堆你沒寫過、也不需要用的元件與常數。接下來要做的第一件事，就是把這層範例清乾淨，讓專案回到一張白紙。為什麼要特別做這件事，以及怎麼做，就是下一節的內容。

還有一件事先埋個伏筆：這個階段你預設是在 Expo Go 這個通用容器裡看畫面。它能讓你很快看到純 JavaScript 的畫面，但之後用到 Expo Go 沒有內建的原生模組時就不夠用了。那是後面章節的題目，這裡先知道有這條分岔路就好。

小結

用 create-expo-app 在結尾加一個點，就能把 Expo 專案直接長在目前的空資料夾裡。它會生出 package.json、app.json、設定檔與 src/app 等結構，接著用 npx expo start 搭配 i 或 a 開進模擬器。你得到的是一個能跑、但還塞滿官方範例的地基。

有了能跑的專案，下一步就是把它清成真正屬於你的空白起點。下一節要處理 Expo starter 附的那個 reset-project 腳本，看它到底刪了什麼、留了什麼。
