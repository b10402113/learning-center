用 create-expo-app 建立可執行的 Expo 專案

Step 1/5 · 建立 Expo 專案與 NativeWind

這一節要完成什麼？

這一節要做的，是在一個空的專案資料夾裡建立 Expo 專案，認識它生成的關鍵檔案，並在 iOS 或 Android 模擬器中把第一個畫面跑起來。

開始前，請準備好三樣東西：

  • Node.js：從 nodejs.org 安裝即可，使用預設值就好。
  • 一個空的專案資料夾，例如 cal-ai-tut，並用 VS Code 或 Cursor 打開。
  • 可以執行指令的終端機視窗，編輯器通常已經內建。

Mac 和 Windows 使用的指令相同。差別主要在模擬器：Mac 可以跑 iOS 模擬器，Windows 則以 Android 模擬器為主。以下用 Mac 示範，但指令兩邊都通用。

先看整體流程：從空資料夾到第一個畫面

上一站你已經把想法整理成 plan.md，裡面記錄了頁面、第一版的範圍，以及後端服務。現在要把這份計畫放進一個真的能執行的專案裡。

這個階段先不要急著把功能全部交給 agent。專案的資料夾結構、路由方式和樣式系統，就像房子的地基；地基歪了，後面每一層都會跟著難修。

接下來會依序做三件事：

  1. 用 create-expo-app 在目前的空資料夾建立專案。
  2. 檢查 Expo 生成的檔案，理解畫面和路由放在哪裡。
  3. 啟動 Metro bundler，讓專案在模擬器中顯示出來。

第一步：在目前的資料夾建立 Expo 專案

先在專案資料夾裡執行：

npx create-expo-app@latest .

這行指令最後的 . 很重要。它代表「就在目前這個資料夾裡生成專案」。

如果你省略這個點，只執行 npx create-expo-app@latest，工具會另外建立一個以專案名稱命名的子資料夾。原本的空資料夾裡就會再套一層資料夾，之後開啟檔案、執行指令時容易搞錯位置。

指令開始執行後，工具會詢問要使用哪個 template（樣板）。直接接受預設選項，並選擇最新的 SDK 即可。錄製當下是 SDK 57，但 Expo 會持續推出新版本；如果你看到更高的版號，代表版本更新，不是環境出錯。

確認選項後，工具會下載依賴套件，通常需要等待一兩分鐘。完成後，你的空資料夾就會長出一棵可以執行的專案檔案樹。

第二步：確認生成了哪些檔案

安裝完成後，打開資料夾，你會看到類似這樣的結構：

cal-ai-tut/
├── src/
│   └── app/
│       ├── _layout.tsx      # 整個 app 的路由外框
│       └── index.tsx        # 首頁畫面
├── assets/                  # icon、啟動畫面等圖片
├── scripts/
│   └── reset-project.js     # 下一步要用的清理腳本
├── app.json                 # app 名稱、icon、scheme 等設定
├── package.json             # 依賴與指令，main 指向 expo-router/entry
├── tsconfig.json            # TypeScript 設定
└── eslint.config.js         # 程式碼風格檢查

先看 src/app/：畫面和路由的所在地

src/app/ 是 Expo Router 的地盤。Expo Router 採用檔案式路由，概念很像把檔案直接當成地圖：放進一個畫面檔，就會多出一個對應的路由，不需要另外維護一份路由對照表。

_layout.tsx 是這一層的路由外框，會包住底下的畫面。之後如果需要放 Provider，也會是很適合的位置。index.tsx 則是預設首頁。

再看 package.json：app 從哪裡開始

package.json 裡有這行設定：

cal-ai-tut/
├── src/
│   └── app/
│       ├── _layout.tsx      # 整個 app 的路由外框
│       └── index.tsx        # 首頁畫面
├── assets/                  # icon、啟動畫面等圖片
├── scripts/
│   └── reset-project.js     # 下一步要用的清理腳本
├── app.json                 # app 名稱、icon、scheme 等設定
├── package.json             # 依賴與指令，main 指向 expo-router/entry
├── tsconfig.json            # TypeScript 設定
└── eslint.config.js         # 程式碼風格檢查

其中 "main": "expo-router/entry" 表示 app 啟動時，不是從某個 App.tsx 開始，而是交給 Expo Router 的進入點決定要顯示哪個畫面。這也是畫面會集中放在 src/app/，而不是散落在各處的原因。

最後看設定與輔助檔案

app.json 放的是整個 app 的設定，例如顯示名稱、slug、icon、深淺色模式，以及 scheme。scheme 是讓外部連結可以開啟 app 的協定，之後處理登入回跳時會用到。

scripts/reset-project.js 則是 Expo 附上的開發輔助腳本，功能是清掉預設範例畫面。這些範例就像鷹架，方便你確認專案能跑；但要開始蓋自己的 app 前，下一步會把它移除。

第三步：啟動專案並打開模擬器

檔案結構確認後，在同一個專案資料夾執行：

npx expo start

這會啟動開發伺服器，也就是 Metro bundler。終端機會顯示一個可以用手機掃描的 QR code，並列出幾個快捷鍵：

  • 按 i：開啟 iOS 模擬器。
  • 按 a：開啟 Android 模擬器。

第一次啟動模擬器時，通常需要等待冷啟動，所以畫面可能會比平常慢一些。這不代表指令失敗，先讓模擬器完成啟動即可。

確認開發流程：改檔、存檔、看結果

模擬器裡的 app 比較像一個外殼，並不會把你的 JavaScript 全部裝在裡面。它會向本機的 Metro 伺服器索取打包好的 JavaScript，接著在模擬器中執行。

因此，只要 Metro 還開著，你修改檔案並存檔，畫面通常就會立即更新。這就是 hot reload。接下來製作每一張畫面時，你會反覆使用「改檔、存檔、看模擬器結果」這個節奏，不必每次都重新 build 整個 app。

如果啟動順利，你會在模擬器看到 Expo 預設的示範畫面，通常包含幾個分頁和一些範例元件。看到這個畫面，就表示第一個可執行的 Expo 專案已經建立完成。

先用模擬器，不急著做 development build

Expo 把建置、打包，以及上架到 App Store 和 Play Store 的流程收斂成幾個指令，而且免費就能開始。等到需要認真經營、頻繁產生 build 時，才會考慮約每月 20 美元的方案。對一人開發者來說，這是一個省力的起點。

現在也不需要立刻製作 development build。用模擬器搭配 Metro，就夠你寫畫面、驗證樣式了。

若專案開始使用原生模組，例如相機、影片通話或錯誤監控，才是該考慮切換到 dev build 的時候。這個判斷與切換細節已在前面的 Expo 心智模型中說明；目前只要記住：在地基階段，先用模擬器就對了。

完成檢查

做到這裡，你應該能確認以下結果：

  • 空資料夾中已生成 Expo 專案。
  • 專案包含以 src/app/ 為核心的檔案結構。
  • _layout.tsx 是路由外框，index.tsx 是首頁。
  • package.json 的進入點是 Expo Router。
  • 執行 npx expo start 後，可以用 i 或 a 開啟模擬器。
  • 修改檔案並存檔後，模擬器會即時更新。
用 npx create-expo-app@latest .（別忘了那個點）在空資料夾生成 Expo 專案，它會長出以 src/app/ 為核心的檔案樹，其中 _layout.tsx 是路由外框、index.tsx 是首頁，package.json 的進入點是 Expo Router。用 npx expo start 然後按 i／a，模擬器會從本機 Metro 伺服器取得 JS，改檔存檔就即時更新。這一刻你拿到的是能跑、能改的專案，但裡面還塞著 Expo 的示範畫面。

預設畫面看起來很完整，有分頁，也有範例元件，但那些都不是你的產品。若保留它們，後面 agent 很容易沿用範例的寫法拼貼，讓專案從一開始就偏離原本的方向。

下一節會使用 scripts/reset-project.js，把這張已經畫滿 Expo 範例的草稿紙擦乾淨，準備放入自己的畫面。

延伸閱讀：Expo 官方文件 docs.expo.dev，尤其可以對照版本化的 /versions/ 目錄，因為 Expo 的 API 變動不算慢。
