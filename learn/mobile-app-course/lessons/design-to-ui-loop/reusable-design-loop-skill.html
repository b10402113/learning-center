把比對迴圈固化成可重用的 skill

Step 5/5 · 從設計到 UI 的比對迴圈

先確認目標與前置條件

這一節的目標很明確：把「建立畫面、截圖、比對、修改，直到一致」的流程寫成一份 skill。完成後，你只要對 agent 說「把 profile 畫面做得像這張圖」，它就會自動照這套流程工作，不必每次重新貼上整串指令。

動手前，請先準備一段已經穩定有效的指令。也就是說，你已經用前面的 screenshot-compare 迴圈成功完成過畫面，知道這套說法對你的 agent 有用。

如果原本的指令還不穩定，先不要急著把它做成 skill。否則就像把歪掉的模具固定下來，之後每次套用都會複製同一個問題。

為什麼要把重複指令變成 skill？

當你完成第一個畫面後，接著要做第二個、第三個，甚至第五個畫面，麻煩就會開始出現。每次都要重新說明「從模擬器截圖、跟參考圖比對、修改，再比對到一致」，不只浪費時間，也可能漏掉其中一句，讓 agent 的表現忽好忽壞。

這種反覆出現、而且內容大致固定的指令，就是適合固化成 skill 的訊號。把它從「每次重打的文字」變成「專案裡的一份流程說明」，之後就能重複使用。

第一步：確認 skill 要放在哪裡

不同的 AI agent 會讀取不同的位置。為了讓課程中的工具都能找到同一套 skill，作者把它同時放在兩個資料夾：

資料夾給誰讀
.claude/skills/只有 Claude Code 會讀
.agents/skills/Codex、Cursor 等各種 agent 都讀

如果你主要使用 Codex，至少要準備 .agents/skills/。如果也希望 Claude Code 使用同一套流程，再放一份到 .claude/skills/。兩邊都放最穩妥，內容保持一致即可。

第二步：把重複指令建立成 skill

  1. 找出重複的指令。

    挑出你已經重複使用三、四次的比對迴圈，確認每次的內容大致相同。這就是要固化的流程。

  2. 請 agent 建立 skill。

    把原本那段迴圈指令附在後面，直接告訴 agent：「我不想每次都打這一串，可以幫我建立一個 skill，放到 agents 資料夾，也放到 claude 資料夾嗎？」

  3. 確認檔案真的存在。

    agent 應該會建立一個以 skill 命名的資料夾，裡面放一份 SKILL.md。請打開檔案，確認內容確實是你要的截圖、比對與修改流程。

    如果 agent 誤解了流程，這時就直接請它修正，不要把錯誤版本留下來。

  4. 用一句話測試。

    開啟新的對話，對 agent 說：「把 profile 畫面做得像這張圖。」然後觀察它是否自動進入截圖、比對與修改的迴圈。

如果它能在沒有重新貼上完整指令的情況下照流程執行，就表示 skill 已經被正確載入。

第三步：用最小指令驗證實際效果

作者在課程裡採用的做法，就是對 Codex 說：「我不想每次都打這一串，幫我建立一個 skill，放到 agents 與 claude 資料夾。」接著把原本的比對迴圈交給它整理成 skill 檔案。

建立完成後，新的工作不需要再從頭解釋整個流程。你只要附上參考圖，再說一句「把這個畫面做得像這樣」，agent 就會依照 skill 執行。

測試時，請特別確認兩件事：

  • 如果 agent 自動進入截圖與比對流程，表示 skill 已載入。
  • 如果 agent 只修改畫面，卻沒有照完整迴圈執行，請回頭檢查 SKILL.md 的內容與檔案位置。

skill 為什麼能被自動使用？

skill 的關鍵不在於它是一個特別的魔法指令，而在於它會在對話開始時自動載入。你不必每次提問都把完整內容貼進去，agent 一開始就會讀到這些工作指示。

因此，「把 profile 畫面做得像這張圖」這句話雖然很短，背後仍然能觸發完整流程，因為截圖、比對與反覆修改的細節早已寫在 skill 裡。

skill 就像貼在爐子旁邊的一張護貝小卡。你不必每次煮菜都憑記憶複誦整份食譜，需要時抬頭看一眼，照著卡片做就好。

第四步：把專案慣例寫進規則檔

除了可重複使用的流程，專案裡還有一類內容也值得固定下來：專案慣例。

例如，你明明交代過要使用 Expo 的 native tabs，agent 卻隔幾次又改回自製的 tab bar。這種「同一個錯誤反覆出現」的情況，表示它不該只存在某一次對話裡，而應該寫進專案層級的規則檔。

課程裡的專案把這些規則寫在 AGENTS.md，以及供 Claude 讀取的 CLAUDE.md。這些是純文字的指示檔，內容描述整個專案始終都要遵守的規則，並會在對話開始時自動載入。

作者曾遇過 native tabs 被 agent 改掉的回歸問題，後來就在 AGENTS.md 補上一句「永遠使用 native tabs」。之後 agent 在修改畫面前就能先讀到這條規則，比較不會再次犯同樣的錯。

可以用這個方式分辨兩者：

  • skill：放一個可以重複執行的流程，例如「截圖、比對、修改到一致」。
  • 慣例檔：放整個專案都適用的規則，例如「永遠使用 native tabs」。

兩者的共同點，是把一次性的對話指示，變成之後每次都會自動生效的預設值。

完成後，你應該看到什麼？

完成這個程序後，專案中應該有一個包含 SKILL.md 的 skill 資料夾，並依照使用的工具放在 .agents/skills/、.claude/skills/，或兩者都有。

開啟新的對話後，你只要提供參考圖並說「把這個畫面做得像這樣」，agent 就應該能自動執行原本的截圖比對迴圈。專案中反覆適用的規則，則應該寫進 AGENTS.md 或 CLAUDE.md，避免每次再提醒。

當一段指令已經重複使用，就把它固化成 skill。請 agent 幫你建立，放到 .agents/skills/（所有 agent 可讀）與 .claude/skills/（Claude Code 專用）。skill 會在對話開始時自動載入，所以之後一句「把這個畫面做得像這樣」就能觸發完整的比對迴圈。專案層級的規則則寫進 AGENTS.md，讓慣例不必每次重講。

到這裡，整套方法就串起來了：先把 plan 變成設計與 design system，再用截圖迴圈逐一完成畫面；過程中用假資料撐起 UI，修改時控制好範圍，最後把穩定的比對流程固化成可重用的 skill。

下一次遇到全新的畫面時，你不必再從零開始，也不必重新背誦整套指令。套用已經整理好的流程，就能把注意力放回真正的畫面與產品需求上。
