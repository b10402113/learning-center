<LearningGoal>
解釋 clerkMiddleware 如何在每個請求上附掛 Clerk 的 auth context，讓 Route Handler 讀得到 Expo 帶來的 Bearer token，以及為什麼 proxy.ts 刻意不做 path matching。
</LearningGoal>

## Lesson

Next 16 的 `proxy.ts` 只做一件事：用 `clerkMiddleware` 把每個請求（含 Expo 的 Bearer token）驗成身分脈絡，讓 Route Handler 的 `auth()` 讀得到。
