# Token endpoint 與 channel endpoint：server wrapper 與短效憑證

<LearningGoal>
能在 Next.js 後端寫出 mint token 與取得 patient clinic channel 的兩個端點，並說明短效 token 為什麼要設計成可重複刷新。
</LearningGoal>

## Lesson

用一支單例的 server wrapper 集中 Stream 連線，寫出 token 端點（requireAuth → syncStreamUser → 回傳可公開 apiKey 與短效 token，同一支端點也負責刷新）與 channel 端點（病人取得 patient-{id} 對話及成員名單，員工回傳 null）。
