## Lesson

前端等分析結果有兩條路：掃描頁等的是單一 run，所以用 useRealtimeRun 訂閱、直接讀 run.output 分辨成功／失敗／not-food，publicAccessToken 由觸發 task 的 handle 自帶；首頁面對一批餐點，用條件式輪詢，只在有任何一筆 status 為 analyzing 時每 3 秒重問；判準是「等一個目標還是一批資料」，並記得新增餐點成功時 invalidate MEALS_KEY，因為首頁在原生分頁背後不會自己更新。
