<LearningGoal>
做出一個真正合規的 in-app 刪帳號流程：先確認，再從 identity provider 與資料庫刪除，並把媒體與關聯資料一起 cascade 清掉。
</LearningGoal>

## Lesson

合格的刪帳號要處理三層：Clerk 身分、資料庫關聯資料、媒體儲存。流程是先跳原生確認框（取消不送請求、按鈕 disable）、由 server 從已驗證身分推導要刪的對象（絕不信 client 傳來的 id）、先鎖寫入再刪／停用身分、成功後才 cascade 清理 DB 與媒體。Clerk 刪除要能重試，404 視為已完成；關聯刪除用 schema 的 onDelete cascade，媒體用 user id 前綴整批刪；最後在三層驗證並確認重新註冊會重走 onboarding。
