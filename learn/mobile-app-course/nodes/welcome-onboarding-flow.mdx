# Welcome 與 Onboarding 流程

## Learning goal

建多頁 welcome / onboarding，批次建造並正確 gate（onboarding 先於 auth、空狀態處理）

## Steps

1. [[learn/mobile-app-course/nodes/welcome-onboarding-flow/welcome-entry-and-routing|Welcome 匿名入口：登入狀態怎麼決定去哪一頁]] — 先看懂 welcome 為什麼是匿名入口，以及登入狀態如何決定分流
2. [[learn/mobile-app-course/nodes/welcome-onboarding-flow/declarative-questionnaire|把問卷寫成資料：steps.ts 的宣告式步驟]] — 用一份步驟陣列描述九頁問卷，而不是一頁一個元件
3. [[learn/mobile-app-course/nodes/welcome-onboarding-flow/dynamic-step-flow|一條流程串起 N 頁：動態 renderer 與共用版型]] — 用動態頁面與共用元件把 N 個步驟接成一條流程（after step 2）
4. [[learn/mobile-app-course/nodes/welcome-onboarding-flow/batch-build-and-verify|批次建造 onboarding：設計參考與驗證迴圈]] — 分批交給 agent 建造，用設計參考與驗證迴圈收斂多頁 UI（after steps 2–3）
5. [[learn/mobile-app-course/nodes/welcome-onboarding-flow/onboarding-as-hard-gate|Onboarding 硬 gate：為什麼一定要先於登入]] — 決定問卷與登入的先後，並處理持久化與空狀態（after steps 1、3）

## Lesson

手機 app 面對的第一個問題，不是「功能怎麼寫」，而是「使用者還沒登入時，看到什麼」。Welcome 與 onboarding 就是這條序曲：welcome 是一個匿名入口，onboarding 則在拿到帳號之前就先問完幾個問題，換到一份個人化結果，再把人推向登入。順序一旦顛倒，體驗就散了——先要人註冊、才願意給價值，多數使用者會在這一關流失。

這個節點把一個多頁 onboarding 拆成五步。前兩步建立模型：welcome 如何依登入狀態分流，以及為什麼整份問卷應該是一份「資料」而不是九個各寫各的畫面。第三步把資料接成一條流程，用單一動態頁面加共用版型渲染每一步。第四步換到建造手法：多頁 UI 一次丟給 agent 會爆掉，所以分批、附設計參考、再用自我驗證迴圈收斂。最後一步處理最容易做錯的架構問題——onboarding 與登入的先後、重新載入後的持久化，以及資料還沒回來時的空狀態。

走完之後，你手上會有一條可重複的流程：資料驅動的問卷、批次建造、以及一道擋在登入前面的硬 gate。
