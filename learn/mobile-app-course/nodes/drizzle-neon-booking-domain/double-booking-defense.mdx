<LearningGoal>
能分辨應用層守衛與 Postgres 排除約束各自擋下什麼，並說出為什麼不能只靠其中一層。
</LearningGoal>

## Lesson

應用層守衛與 Postgres 排除約束不是替代品，而是互補：能用「哪些列不得同時存在」描述的規則（同一位醫師、時間區間重疊）交給資料庫的 `EXCLUDE USING gist`，由它提供跨請求的原子仲裁；需要業務語意才能判斷的（3am、非級距、前置期內、醫師不提供的服務）留在應用層的 `classifySlot`。應用層不必重寫約束，只要認出 Postgres `23P01`，把它轉成乾淨的 409。
