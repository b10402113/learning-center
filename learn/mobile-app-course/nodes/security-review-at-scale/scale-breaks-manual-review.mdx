# 為什麼上萬行的 PR 不能靠人眼審

<LearningGoal>
判斷一份 PR 是否已大到人眼無法逐行審查，並理解為什麼需要結構化輸出。
</LearningGoal>

## Lesson

人眼 review 的隱含假設是「diff 量可以消化」；當一份 PR 大到數十個檔案、上萬行，這個假設會破功——注意力崩潰、能跑但危險的漏洞躲過檢查、而測試又涵蓋不到你沒想到的輸入。解法不是看更快，而是改用能掃描整個 codebase、依類別與嚴重度整理問題、並產生可執行修復的結構化工具。
