# 走一遍 POST /api/appointments

<LearningGoal>
能照著順序把守衛、Zod 驗證、寫入與 409 例外處理串成一個完整的寫入 handler，並說出每一步為什麼存在。
</LearningGoal>

## Lesson

完整的寫入 handler 依序做：驗身分與請求形狀、確認所有權與服務／牙醫存在、server 推導結束時間並重跑可預約性、寫入後推導通話 id、最後把資料庫的排除約束違反轉成 409 `slot_taken`，其餘錯誤交給 `route()`。
