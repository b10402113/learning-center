# 走一遍 POST /api/appointments：受保護的預約寫入

<LearningGoal>
能照順序寫出一個受保護的寫入 handler：驗身分 → 驗輸入 → 驗擁有權 → 重跑可預約檢查 → 寫入 → 把資料庫例外轉成 409，並回傳 server 組好的形狀。
</LearningGoal>

## Lesson

受保護的寫入 handler 有固定順序：`requireAuth` 驗身分、Zod 驗輸入、`requireOwnedPatient` 驗擁有權、載入服務與醫師、伺服器算 `endsAt`、`assertSlotBookable` 重跑可預約引擎、寫入並把 `23P01` 轉成 409、推導 `streamCallId`，最後 `serialize` 後回 201。
