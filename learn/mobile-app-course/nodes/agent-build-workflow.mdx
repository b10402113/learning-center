# Agent 工作流與 repo 慣例

## Learning goal

跑起 plan → build → self-check → review → commit 的建造迴圈，並用 AGENTS.md / CLAUDE.md 固定專案慣例

## Steps

1. [[learn/mobile-app-course/nodes/agent-build-workflow/build-loop-map|建造迴圈：plan → build → self-check → review → commit]] — 五個階段各自產出什麼、為什麼不能跳過
2. [[learn/mobile-app-course/nodes/agent-build-workflow/agent-context-files|AGENTS.md 與 CLAUDE.md：寫給 agent 的專案說明書]] — 自動載入的專案慣例要放哪、怎麼分工（after step 1）
3. [[learn/mobile-app-course/nodes/agent-build-workflow/self-check-screenshot-loop|自我驗證迴圈：截圖比對到畫面收斂]] — 用截圖比對讓 UI 收斂到參考設計（after step 1）
4. [[learn/mobile-app-course/nodes/agent-build-workflow/context-injection-tactics|餵 context 的三種手段：skill、官方文件、Context7]] — 新工具或重複流程該用哪種方式餵 context（after step 2）

## Lesson

用 AI agent 蓋 app，成敗很少卡在「模型會不會寫程式」，而是卡在「循環跑得順不順」。這一節把整條迴圈拆成五個階段：先 plan 把模糊的想法逼成 concrete 的規格，再 build 一次做一個功能，接著 self-check 用畫面與資料確認它真的能跑，然後 review 讓另一個 agent（或另一個視角）檢查產出，最後 commit 把可用的狀態固定下來。每一個階段都有對應的產出，缺少任一段，錯誤就會被帶進下一段、放大成更難修的問題。迴圈之外，還需要 AGENTS.md / CLAUDE.md 這類 repo 慣例檔，把「這個專案永遠這樣做」的規則寫死，讓 agent 每次開新 session 都知道專案怎麼運作，不必重講。最後你會學到判斷什麼時候該把重複的指示寫成 skill、什麼時候該貼官方文件、什麼時候該用 Context7 拉最新 API 文件。
