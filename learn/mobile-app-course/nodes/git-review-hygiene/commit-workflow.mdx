<LearningGoal>
能照著 stage → 讓 AI 產生 commit message → commit → publish/sync 的順序完成一次提交，並判斷哪些改動可以直接 commit、哪些要走分支與 PR。
</LearningGoal>

## Lesson

日常流程用「有沒有牽涉邏輯」決定要不要開分支：小設定直接 commit 到 main，涉及程式碼就走分支加 PR。操作順序是建立分支 → stage → 讓 agent 產生 commit message → commit → publish/sync，驗證方式是到 GitHub 確認分支與最新 commit 都在。
