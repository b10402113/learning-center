# Expo / React Native 心智模型

## Learning goal

說清楚 Expo / React Native 怎麼跑、JS 與 native 的界線在哪裡，以及在什麼情況下非用 development build 不可、不能只靠 Expo Go。

## Steps

1. [[learn/mobile-app-course/nodes/mobile-stack-model/react-native-render-target|React Native 不是網頁：JS 與 native 的界線]] — 先建立底層圖像：React 的 render target 從 DOM 換成了手機的原生元件
2. [[learn/mobile-app-course/nodes/mobile-stack-model/expo-toolchain|Expo 是什麼：包住 React Native 的整條工具鏈]] — 分清楚 React Native 與 Expo 各自負責哪一層（after step 1）
3. [[learn/mobile-app-course/nodes/mobile-stack-model/expo-go-vs-dev-build|Expo Go 還是 dev build：什麼時候非真機建置不可]] — 用「有沒有用到 native module」決定要用哪一種執行方式（after step 2）
4. [[learn/mobile-app-course/nodes/mobile-stack-model/native-modules-and-rebuild|native module 與重建：為什麼裝個套件要重新編譯]] — 補上「新增 native module 為什麼一定要重建」的機制（after step 3）
5. [[learn/mobile-app-course/nodes/mobile-stack-model/expo-router-app-shell|從 _layout.tsx 看 Expo Router 的 App Shell]] — 用真實的 root layout 檔把 Provider 疊法與路由守衛串起來（after steps 1–2）

## Lesson

這一節課的目標不是教你寫 React Native 元件，而是先把你腦中「網頁」的預設值換掉。你熟悉 Next.js，知道瀏覽器負責畫 DOM、伺服器負責送資料；但手機上沒有 DOM，React Native 把同一套 React 元件樹接到 iOS 與 Android 的原生畫面上，中間隔著一條 JavaScript 與 native 的界線。這條線在哪裡、誰在線的哪一側，決定了很多事——為什麼樣式不能直接寫 CSS、為什麼有些套件裝了要重新編譯、為什麼 Expo Go 到某個階段就會不夠用。

五步走完，你會有兩層收穫。第一層是機制：React Native 的 JS 執行環境、Expo 這條工具鏈的角色、以及 native module 與重建的因果。第二層是判斷：面對一個新功能，你能在動手前就說出它會不會逼你離開 Expo Go，而不是做到一半才發現得整包重建。最後一步會拿課程裡真實的 `_layout.tsx` 當收尾，把抽象的「Provider 疊起來、路由依登入狀態分流」變成一張看得懂的 App Shell 結構圖——這正好也是後面每個 app 都會重複用到的骨架。
