# 串流 AI 助理

## Learning goal

做會逐字串流的 app 內 AI 助理，對話歷史持久化到 DB，支援圖片附件與領域 prompt。

## Steps

1. [[learn/mobile-app-course/nodes/ai-assistant-streaming/streaming-response-model|串流回應的心智模型：為什麼 AI 助理不該只轉圈圈]] — 建立逐字串流的心智模型，分清楚它與一般 JSON 端點的差別
2. [[learn/mobile-app-course/nodes/ai-assistant-streaming/server-ai-endpoint|在 Next.js Route Handler 串出 AI 回應]] — 寫出會串流的端點：領域 prompt、緊急短路、傳輸閘門、OpenAI 轉 ReadableStream（after step 1）
3. [[learn/mobile-app-course/nodes/ai-assistant-streaming/client-streaming-ui|手機端逐字渲染與對話介面]] — 用 useApiStream 邊收邊畫，處理過期回應與錯誤降級（after step 2）
4. [[learn/mobile-app-course/nodes/ai-assistant-streaming/conversation-history|把對話歷史持久化到資料庫]] — 受 ownership 檢查的對話 resolver、GET 回灌、DELETE 清除（after step 2）
5. [[learn/mobile-app-course/nodes/ai-assistant-streaming/image-attachments|圖片附件：存進 ImageKit 的助理回合]] — 照片上傳、不呼叫模型的固定回合、點擊才顯示的模糊縮圖（after step 4）

## Lesson

前面幾個節點已經把後端骨架、API 守衛與背景 AI 任務鋪好，這個節點要蓋的是「使用者直接對著打字的那個 AI 助理」。它和背景任務最大的差別，是使用者正盯著螢幕等回應：如果每問一句都轉圈圈十幾秒，體驗會差到讓人直接關掉 app。所以這個節點的主軸是把「等一整包回應」換成「一個字一個字浮出來」。

這件事會同時牽動三個地方。在 server 端，回應不再是先組好一包 JSON 再送出，而是開一條純文字的串流，把模型的輸出邊產生邊推出去；在 client 端，畫面不能再等到整個回應結束才更新，而要一邊收一邊畫；在資料層，每一輪對話都要落地，重新打開 app 才看得到歷史。三步環環相扣，少一個都會讓功能變得半殘。

除此之外，助理還有兩個不能省的規矩。第一是「範圍」：它回答什麼、不回答什麼，必須由 server 端的 system prompt 決定，不能只靠前端擋。第二是「安全」：遇到緊急狀況要先給制式的處理指示，而且在資料能不能送到 OpenAI 這件事上，預設要是關的。這些規矩不是加在功能旁邊的裝飾，而是 LLM 功能在醫療或敏感場域能不能上線的前提。
