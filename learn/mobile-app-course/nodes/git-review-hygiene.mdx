# 版控與 AI Code Review

## Learning goal

用分支 / PR / AI commit message / CodeRabbit 安全地版控 agent 產出，並把 secrets 擋在 repo 外。

## Steps

1. [[learn/mobile-app-course/nodes/git-review-hygiene/review-is-the-bottleneck|為什麼 agent 寫得越快，你越需要版控與審查]] — 建立信念：審查不是收尾，而是 agent 時代真正的瓶頸
2. [[learn/mobile-app-course/nodes/git-review-hygiene/branch-commit-pr-model|分支、commit、PR：把功能隔離在 main 之外]] — 用時間線理解 branch / commit / PR / merge 四個動作（after step 1）
3. [[learn/mobile-app-course/nodes/git-review-hygiene/commit-workflow|每天的 git 流程：建立分支、寫 commit message、push]] — 走一次 stage → AI commit message → commit → sync，並分辨 config-only 與邏輯改動（after step 2）
4. [[learn/mobile-app-course/nodes/git-review-hygiene/coderabbit-ai-review|用 CodeRabbit 對 PR 做 AI code review]] — 讓工具審查 agent 的產出，再把彙整意見交回 agent 修（after step 3）
5. [[learn/mobile-app-course/nodes/git-review-hygiene/secrets-in-repo|secrets 不進 repo：什麼該 commit、什麼只能留本機]] — 用 .gitignore 與可檢查的判準守住 secrets（after steps 3–4）

## Lesson

這個節點處理一個很容易被跳過的環節。當你把建造工作交給 agent，產出的速度會快到讓人忘了「寫出來」和「可以信任」是兩件事——Claude Code 這類工具能在十分鐘內生出上萬行程式碼，速度早已不是瓶頸，願不願意逐行審查才是。課程裡三條路線最後都收斂到同一套做法：每一個功能都在自己的分支上完成，用 AI 產生 commit message，開 PR，讓 CodeRabbit 逐行審查，把彙整後的意見丟回 agent 修掉，再合併回 main。這套流程同時解決兩個問題：一是把還沒驗證的改動隔離在 main 之外，二是用工具去檢查人眼看不完的程式碼。

五步分成三層。第一層是「為什麼」：先建立信念，理解為什麼工作程式碼仍可能藏著安全與慣例問題。第二層是「怎麼做」：先懂 branch / commit / PR / merge 的模型，再實際走一次 commit 流程，最後把 PR 交給 CodeRabbit 並讀懂它的輸出。第三層是決策：判斷哪些檔案該進 repo、哪些 secrets 永遠只能留本機，並學會在 agent 於背景偷偷改動時把它看出來。走完之後，你拿到的不是幾個指令，而是一個每次功能收尾都能重複套用的安全網。
