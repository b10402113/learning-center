# 訪談式規劃：從想法到 plan.md

## Learning goal

用訪談式 plan mode 把想法收斂成 goals / features / pages / stack，產出 plan.md 並完成 V1 取捨

## Steps

1. [[learn/mobile-app-course/nodes/idea-to-plan/plan-before-build|為什麼先規劃？跳過規劃的代價]] — 理解 AI 不會通靈，沒有 context 就會替你亂猜功能
2. [[learn/mobile-app-course/nodes/idea-to-plan/interview-plan-mode|訪談式 plan mode：讓 AI 反問你]] — 開 plan mode、貼規劃 prompt，用分批反問把需求講清楚（after step 1）
3. [[learn/mobile-app-course/nodes/idea-to-plan/v1-scope-tradeoffs|砍出 V1：該留什麼、該砍什麼]] — 用「先做出能動的 demo」當判準，砍出可上線的第一版（after step 2）
4. [[learn/mobile-app-course/nodes/idea-to-plan/choose-tech-stack|選定 tech stack：三種後端範式的取捨]] — 在規劃階段就鎖定 auth、後端、樣式的組合（after step 2）
5. [[learn/mobile-app-course/nodes/idea-to-plan/plan-md-artifact|plan.md 的結構與用途]] — 把訪談結果寫成一份餵給後續 UI 與功能拆解的計畫文件（after steps 3–4）

## Lesson

規劃是整條 pipeline 的第一站，也是最常被跳過的一站。多數人拿到一個點子，第一反應是打開 agent 就說「幫我做一個記帳 app」；結果 agent 只能靠猜——猜你的使用者是誰、猜有哪些頁面、猜要不要登入——於是你花在來回修改的時間，遠比一開始就坐下來講清楚還多。這節課把規劃拆成一條可重複的路徑：先建立「不規劃就會被 AI 亂猜」的信念，再學會用訪談式 plan mode 讓 agent 反過來訪問你，接著在過程中做兩個關鍵取捨（V1 該砍到多小、stack 該選哪一套），最後把訪談結果固化成一份 `plan.md`。走完這五步，你手上不會有任何程式碼，但會有一份能直接餵給下一階段生成 UI 與拆解功能的計畫。
