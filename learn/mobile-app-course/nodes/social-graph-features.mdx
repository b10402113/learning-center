# 社交圖與貼文功能

## Learning goal

用 posts / likes / comments / follows / bookmarks / 全文搜尋 / index / 分頁建模並查詢社交圖。

## Steps

1. [[learn/mobile-app-course/nodes/social-graph-features/social-graph-schema|社交圖的資料模型：用表與索引表達關係]] — 看懂 posts / likes / comments / follows / bookmarks 為何這樣拆，以及每個複合索引在保證什麼
2. [[learn/mobile-app-course/nodes/social-graph-features/indexed-feeds-and-relations|用索引查 feed 與社交關係]] — 用 withIndex 查 home / explore / profile 三種 feed 與 followers / following 清單（after step 1）
3. [[learn/mobile-app-course/nodes/social-graph-features/cursor-pagination|Cursor 分頁：從列表到可持續捲動的 feed]] — 用 cursor 分頁回傳可能被過濾的列表，處理稀疏 feed（after step 2）
4. [[learn/mobile-app-course/nodes/social-graph-features/idempotent-social-writes|可重試的寫入：toggle、計數器與 requestId 冪等]] — 實作 like / follow / bookmark 的 toggle、計數器維護與 comment 冪等與串聯清理（after steps 1–2）
5. [[learn/mobile-app-course/nodes/social-graph-features/fulltext-search|全文搜尋：什麼時候該用 searchIndex]] — 判斷全文搜尋與一般複合索引各自適用的時機（after steps 2–3）

## Lesson

社交功能看起來是「按讚、留言、追蹤」這些直覺的小動作，但背後真正決定成敗的，是資料怎麼被建模、查詢怎麼走索引。這一節點把 Codexgram 的貼文與社交圖拆成五步：先看懂 schema 為什麼把「誰對誰做了什麼」拆成獨立的關聯表，並用複合索引保證「一個人只能按一次讚、只能追蹤一次」；再學會用索引查 home / explore / profile 三種 feed 與追蹤清單；接著處理列表必定遇到的問題——cursor 分頁，以及稀疏 feed 過濾後如何不卡住；然後把寫入做對，讓 like / follow / bookmark 在重試下安全、計數器不亂、comment 用 requestId 冪等；最後判斷什麼時候該動用全文搜尋索引。

一句話總結這條主線：**社交圖的每個查詢與寫入，都應該是一條走索引的路徑，而不是把整張表抓回來慢慢篩。** 這個節點和前面的 Convex 後端模型直接相連——schema 是共同真相，索引是你餵給資料庫的查詢路線圖；也為後面的即時私訊與 seed / 測試打底，因為訊息、inbox 的 unread 判定和測試的權限驗證，用的都是同一套「唯一索引＋衍生欄位」的手法。
