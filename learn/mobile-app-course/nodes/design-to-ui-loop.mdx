# 設計到 UI 的比對迴圈

## Learning goal

從 plan 產出 UI 設計與 design system，用 screenshot-compare 迴圈把畫面做到與參考一致。

## Steps

1. [[learn/mobile-app-course/nodes/design-to-ui-loop/plan-to-ui-design|從 plan 到 UI 設計：產出整份介面與 design system]] — 把 plan.md 變成 UI 生成 prompt，跑出整份設計與可被 agent 讀取的 design system
2. [[learn/mobile-app-course/nodes/design-to-ui-loop/screenshot-compare-loop|screenshot-compare 迴圈：把參考圖變成一致的畫面]] — 跑完「附參考圖 → 截圖比對 → 修正 → 重跑」的核心 loop（after step 1）
3. [[learn/mobile-app-course/nodes/design-to-ui-loop/fake-data-first|先用假資料把 UI 做完整]] — 後端還沒好之前，用假資料與空狀態先把整個介面建出來（after step 2）
4. [[learn/mobile-app-course/nodes/design-to-ui-loop/one-fix-at-a-time|一次只改一個問題、只動該動的地方]] — 用判準決定修改的粒度，並避免把已經對的部分改壞（after step 2）
5. [[learn/mobile-app-course/nodes/design-to-ui-loop/reusable-design-loop-skill|把比對迴圈變成可重用的 skill]] — 把 loop 寫成 skill / AGENTS.md，之後一句話就能觸發（after steps 3–4）

## Lesson

這個節點接在「專案 scaffolding 完成」之後，處理的是很多人會整段跳過的一步：**畫面到底怎麼從一份規格變成 App 上長得對的樣子**。多數人第一次用 AI 蓋 UI，會直接叫 agent「做一個登入頁」，然後對結果不滿意，就以為 AI 做不出好看的介面。課程示範的做法剛好相反——先把設計定下來，再讓 agent 對著設計反覆比對。因為真正讓畫面「對」的，不是更厲害的 prompt，而是一個可以自我檢查的迴圈。

整個流程分成兩半。前半是把 plan.md 變成看得見的設計：請 agent 依照 plan 產生一份 UI 生成 prompt，丟進圖像模型跑出整份 App 的畫面，再拆出 design system 與各畫面的獨立參考圖。這些圖不是給人看的裝飾，而是 agent 之後讀得到顏色、字體、元件的「真相來源」。後半是把設計變成程式：對每一個畫面跑 screenshot-compare 迴圈——附上參考圖、請 agent 建畫面、從模擬器截圖、跟參考圖比對、修正、再比對，直到夠像為止。

五個步驟沿著這條線展開。第一步建立「設計先於程式碼」的模型，說明 design system 為什麼要獨立存在、設計圖與 runtime 資產該放哪。第二步是核心技術：把比對迴圈當成可執行的程序走一次。第三步處理順序問題——後端和資料庫還不存在時，先用假資料與空狀態把 UI 做完整。第四步是決策：修改要一次只改一項，還是整批一起改；哪些時候該只動局部、保留已經滿意的部分。第五步把這個迴圈收斂成可重用的 skill，讓你之後不必每次重打一長串指令。走完這一節，你手上會有一套把任何設計圖翻成畫面的可重複方法。
