# Clerk 與資料庫同步（Webhook）

## Learning goal

分清 identity 與 app data，用 Clerk webhook + 背景 task + ngrok 把使用者自動同步進 DB

## Steps

1. [[learn/mobile-app-course/nodes/clerk-db-sync-webhooks/identity-vs-app-data|身分歸 Clerk，資料歸你：為什麼登入了 DB 還是空的]] — 分清 Clerk 與 app DB 是兩個獨立來源，理解不同步的後果
2. [[learn/mobile-app-course/nodes/clerk-db-sync-webhooks/webhook-event-mechanics|Webhook 是什麼：事件、簽章與重送]] — 看懂 event、簽章驗證、Svix 重送與冪等，以及為何永遠回 200（after step 1）
3. [[learn/mobile-app-course/nodes/clerk-db-sync-webhooks/local-webhook-with-ngrok|本機接 Clerk Webhook：ngrok 與簽章密鑰]] — 建 endpoint、開 ngrok 通道、把簽章密鑰寫進 .env（after step 2）
4. [[learn/mobile-app-course/nodes/clerk-db-sync-webhooks/handler-to-background-task|Webhook 收到之後：直接寫 DB 還是丟背景任務？]] — 用 retry 語意與失敗處理判斷何時該交給 trigger.dev（after step 3）
5. [[learn/mobile-app-course/nodes/clerk-db-sync-webhooks/implement-and-verify-sync|實作同步：signature → task → upsert/delete，並端到端驗證]] — 寫出可驗證的同步鏈路並用刪帳號再註冊測試（after step 4）

## Lesson

登入成功不等於你的 app 認識這個人。Clerk 是身分來源——它保管帳號、登入方式與 session；你的 Postgres 才是應用資料來源——它保管 profile、餐點紀錄、預約這些只屬於這個 app 的東西。兩座倉庫各自獨立，中間沒有天然連線，所以「Clerk 有人、DB 沒人」是預設狀態，不是 bug。這個節點要處理的，就是把這條連線補起來：先認清兩個來源的邊界，再用 Clerk 的 webhook 事件把使用者自動鏡射進自己的 users 表。中間會遇到幾個真實世界的難題——webhook 要能被本機收到、事件要能證明真的來自 Clerk、資料庫掛掉時工作不能白白失敗、同一個事件被重送也不能長出兩筆使用者。走完這五步，你手上會有一條 event → 驗簽 → 背景 task → upsert/delete 的同步鏈路，並且知道怎麼用「刪掉使用者再重新註冊」來確認它真的在跑。
