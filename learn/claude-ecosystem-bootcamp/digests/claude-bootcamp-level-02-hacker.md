- 2.9 When you should use projects — Recap of Claude chat projects as persistent workspaces and a decision rule for when to make one: when work repeats, when you keep re-supplying the same context, or when output quality depends on your specific context; the golden rule is one project, one job.
- 2.10 Create a new project — Build the "Ollama Mastery" design-phase project: use Firecrawl to crawl ollama.com and write `brand-guidelines.md`, then design a full course structure (modules + lesson titles) with research mode and save it as `course-structure.md`.
- 2.11 Create survey form with Tally — Design 8–10 audience survey questions with Claude first (mixed multiple-choice and short answer), refine them in conversation, then enable the Tally connector and have Claude build the "Quick Audience Survey — Ollama & Local AI" form and hand back the share link.
- 2.12 Create email template — Use the `/humanize` skill (product-launch email skill ready) to write a friendly course-announcement email with the survey link, then connect Gmail and have Claude draft a review email to josh@code4startup.com with the template pasted in.
- 2.13 Simulate the form submissions — Use the Claude Chrome extension on the live Tally form to invent and submit three realistic responses from different respondent types (Alex the developer, Maya the data scientist, Jordan the student), useful for testing form layout and question clarity before sharing.
- 2.14 Analyze survey responses — Ask Claude for the response count, then analyze all responses into a full audience report; redesign the course structure to v2 around the audience, and finally generate a 3-page premium print-ready brochure as an HTML artifact from `brand-guidelines.md` (uses the Opus model).
- 2.15 Several commom mistakes — Five common Claude-project mistakes and their fixes: projects that are too broad (one project, one job), uploading files that are too large (Claude only grabs fragments), messy file management (clear names; CSV over Excel), using a project where a skill belongs, and confusing Chat projects with Cowork projects.
- 2.16 Cowork recap — Cowork is to Claude chat what "having someone drive for you" is to "giving directions": it connects directly to a local folder, reads/writes/moves real files, generates real deliverables (Excel, PDF), doesn't time out, handles multi-step tasks with sub-agents, and works best with Opus or Sonnet.
- 2.17 Use case 1 — Configure Cowork first (turn on the Dispatch beta, set the default working folder, write a global instruction), then run the Downloads-folder workflow: summarize the folder, organize files into type subfolders, rename generic files, check duplicates, and delete stale files with approval.
- 2.18 Use case 2 — The quarterly-expenses workflow: point Cowork at a folder of receipts and invoices (PDFs, JPEGs, PNGs), extract date/vendor/amount/currency/category for each, then produce a sorted `Expenses_Report_2026.xlsx` with a summary tab, unclear items flagged in Notes.
- 2.19 Why Cowork Projects — Cowork projects beat Chat projects because Chat projects can't create real files, run code, or touch local folders; Cowork projects add a persistent workspace, custom instructions, scoped memory, and scheduled tasks, and can be created from scratch, imported from Claude chat, or wrapped around an existing folder.
- 2.20 How context layers work — Cowork uses a layered context: global instruction (who you are, all sessions), project instructions written to `claude.md` in the folder (project rules/format), subfolder `claude.md` files, reference files in the folder, and finally your prompt — with the more specific layer winning conflicts.
- 2.21 Project 1 — Build a Client Research & Report project: drop client briefs/interview notes/reference docs into `clients/<name>/`, define locations and output prefs (.docx, max 6 pages, exec summary) via a project instruction, and have Claude generate the report into `outputs/<name>/`; the setup compounds across every future client.
- 2.22 Project 2 — Build a Branded Content project: define brand context (positioning, audience, voice), analyze sample images to extract a `design-system.md` (colors, typography, layout, graphic style, tone), generate on-brand carousel HTML slides, then package the workflow into the reusable `brand-generate` skill.
- 2.23 What are live artifacts — Live artifacts are persistent, interactive HTML pages built in Cowork that stay connected to your data and refresh every time you open them, unlike chat artifacts which are static snapshots stuck inside a conversation; current limitations are that they are desktop-only, not shareable, and run connectors without asking each refresh.
- 2.24 Build 1 — Build a Freelancer Client Dashboard live artifact: create the Airtable "Client Projects" base and "Projects" table, import the sample CSV, then generate a dashboard with three KPI tiles, an interactive grouped bar chart, and a colour-coded project table that pulls fresh Airtable data on refresh.
- 2.25 Build 2 — Build a Daily Morning Brief live artifact pulling from Gmail (top unread), Google Calendar (today's events), and Tally (recent form submissions), arranged into three sections, then iterate to cross-reference Airtable and add a client badge; artifacts keep version history.
- 2.26 Package the skill — The `brand-generate` skill only worked inside the brand-context project because the skill read the project's `context/` folder; fix it by bundling the skill file and the context folder into one zipped skill package, uploading via Create skill → Upload a skill, so the brand travels with the skill into any project or device.
- 2.27 Dispatch — Dispatch lets you send tasks from your phone to Claude running on your desktop (one synced conversation thread); it needs a Claude subscription, the latest desktop app, the mobile app, and an awake desktop, and is demoed by producing a one-page PDF sales report plus a draft Gmail to a manager while away from the desk.
- 2.28 Schedule 1 — Schedule tasks run on autopilot: create the Slack channels `#morning-brief` and `#weekly-content`, connect Slack, then use `/schedule` with a prompt so Claude every morning at 8am triages Gmail, drafts replies for urgent mail, checks today's Google Calendar events (flagging back-to-back meetings), and posts a "Morning Latte" report to Slack; test with Run now.
- 2.29 Schedule 2 — The second scheduled workflow uses a "Weekly Notes" Airtable table (Links, Notes, Read boolean): every Friday at 5pm Claude deletes read records, scrapes the remaining links with Firecrawl, writes a highlights report, and sends it to `#weekly-content`. Closes Level 2 and teases Level 3 (Claude Computer, Claude Design, Claude Code).
