# Digest — Claude Bootcamp Level 01 — Fundamental

## Overview (L1)

- 1.1 The world has already shifted — AI is now infrastructure, not a trend; 91% of businesses use it; the value shift favors those who direct and check AI, who earn 56% more.

- 1.3 Where does Claude fit in — Claude (by Anthropic) is the assistant trusted for serious work; it is an ecosystem (Chat, Code, Cowork, integrations), not just a chatbot.
- 1.4 Your roadmap — a four-level progression from Fundamental to building autonomous AI systems; Level 1 gets you comfortable using Claude day-to-day.
- 1.5 What is Claude — an AI collaborator by Anthropic defined by Capable, Stable, Responsible; contrasted with chatbots; five core capabilities.
- 1.6 Register a new account & pricing — create the account at claude.ai and choose Free / Pro / Max plans by usage and feature needs.

- 1.10 Projects — dedicated workspaces that persist custom instructions, files, and conversation history so you stop re-explaining context.
- 1.11 Artifact — Claude builds a live, separate artifact (app, doc, webpage, chart, ebook) in a side panel instead of dumping into chat.
- 1.12 Skills — a saved instruction package that teaches Claude a repeatable workflow once and reuses it automatically on the matching trigger.
- 1.13 Connectors — one-click bridges (via MCP) that let Claude read and act on your apps like Calendar, Gmail, Drive, Slack, and GitHub.
- 1.14 Plugins — role-based bundles of skills, connectors, and sub-agents that make Claude work like it was built for your job.
- 1.15 Overview — the four main tools: Chat (desk), Cowork (workshop), Code (machine room), Design (creative studio) — same intelligence, different equipment.
- 1.16 Claude Chat — the conversation tool for writing, explaining, brainstorming, quick analysis, research, and one-off drafting.
- 1.17 Claude Cowork — agentic delegation: give a goal, Claude plans and executes multi-step work on your actual files and folders.
- 1.18 Claude Code — a coding assistant that reads your whole project, plans, writes, runs and tests code — for developers and non-developers alike.
- 1.19 Claude Design — describe a visual and Claude builds an interactive, brand-aware result; needs Pro/Max/Team/Enterprise and has its own usage limit.
- 1.20 Chrome browser extension — Claude in the browser to read pages and act on them; subscription-only, caveats around sign-in and blank context.
- 1.21 Claude Code CLI — install and run Claude Code in your terminal; how to log in, switch models, and build files from a prompt.
- 1.22 Claude Code in IDE — bring Claude Code into VS Code, Cursor, or Anti-Gravity and run it beside your code.
- 1.23 Claude Code extension — a visual panel inside the IDE that knows the open file and shows code diffs before applying edits.
- 1.24 Slack — install Claude in Slack; DM it privately or @mention it in channels for team-wide collaboration.
- 1.25 Excel — Claude as an Excel add-in that cleans messy data and validates/fixes formulas.
- 1.26 From prompts to agents — the mental-model module: Prompt Engineering, Context Engineering, and the Agent Harness.
- 1.27 Prompt engineering — crafting the right instruction works for simple tasks but breaks down across multi-step work.
- 1.28 Context engineering — managing everything in the context window (system instructions, retrieval, memory, tools, history) beats a single clever prompt.
- 1.29 AI Harness — the system around the model (tools, memory, guardrails, lifecycle, validation) that turns an agent into a reliable product.

### 1.8 Claude models explained
- Locator: `[[sources/claude-ecosystem-bootcamp/20260929/Claude Bootcamp Level 01 - Fundamental/1.8. Claude models explained.en.srt]]`
- Summary: Claude is a family of models, not one AI. Haiku is the lightest and fastest, built for speed and volume (quick summaries, simple questions, repetitive tasks) but hits a depth ceiling. Sonnet is the everyday default used ~90% of the time; the current version is Sonnet 4.6 with a 1 million token context window (roughly 2,000–3,000 pages), and it thinks before answering rather than flattering you. Opus 4.8 is the most powerful, same large context but stronger (SWE Bench 87.6%, PhD-level science 94.2%, ran 7 hours straight on complex refactors) yet expensive and token-hungry — use it for high-stakes, hard problems. Above Opus is Mythos; the lesson recounts that in June 2026 Anthropic tried to release the power publicly as Faber 5, but after 72 hours the US government issued an export control directive citing national-security concerns, and Anthropic pulled both Faber 5 and Mythos 5 globally — both are currently suspended with no confirmed return timeline.
- Key claims: Haiku = fast/simple/high-volume; Sonnet 4.6 = everyday default with 1M token context; Opus 4.8 = most powerful for hard, high-stakes work; Mythos is Anthropic's most powerful model; Faber 5 / Mythos 5 suspended after a US export-control directive; recommended pattern is Sonnet daily, Opus when it really matters.
- Learner-relevant: Core model-selection skill the course keeps returning to for cost and quality control.
- Resources: Haiku, Sonnet (Sonnet 4.6), Opus (Opus 4.8), Mythos, Faber 5, Mythos 5; SWE Bench, PhD-level science question benchmarks

### 1.10 Projects
- Locator: `[[sources/claude-ecosystem-bootcamp/20260929/Claude Bootcamp Level 01 - Fundamental/1.10. Projects.en.srt]]`
- Summary: Opens with a content-creator scenario: every new chat you must re-paste your role, task, brand voice, audience avatar, and files, and any miss causes output drift. ### 1.12 Skills
- Locator: `[[sources/claude-ecosystem-bootcamp/20260929/Claude Bootcamp Level 01 - Fundamental/1.12. Skills.en.srt]]`
- Summary: Uses a marketing-agency onboarding workflow (research client industry/competitors, audit content, identify 3–5 content angles, map formats, write a strategy brief) to show the problem: Claude starts fresh every conversation and has no memory of how you do things, so complex workflows must be re-explained every time. - Key claims: a skill is a saved instruction package that auto-triggers from its description; project = context, skill = process; Claude announces when it reads a skill; start by listing repetitive tasks you keep re-explaining.
- Learner-relevant: Teaches automation of repeatable workflows — a direct lever on consistency and time savings.
- Resources: Customize > Skills; default skill "Skill Creator" by Anthropic; Canvas Design skill; example skill name "Product Launch Email"; rules: keep under 180 words, never use "excited" or "thrilled"; example product "Leo Wireless"; price $95

### 1.13 Connectors
- Locator: `[[sources/claude-ecosystem-bootcamp/20260929/Claude Bootcamp Level 01 - Fundamental/1.13. Connectors.en.srt]]`
- Summary: Connectors are bridges between Claude and the apps you already use, so instead of copying information into Claude, Claude reaches into the app and pulls it. Under the hood connectors use MCP (Model Context Protocol), a standard for securely talking to your apps. As of 2026 there are over 50 connectors in the directory (Gmail, Google Calendar, Google Drive, Slack, Notion, GitHub, Asana, Figma, and more) and connecting takes one click. Two scenarios: Google Calendar (ask "what meetings do I have this week, any conflicts" and Claude checks the real calendar) and GitHub (ask Claude to summarize open pull requests and flag anything sitting more than three days). The setup demo walks through Customize > Connectors > browse > search calendar > add > select account > grant access, then set permissions (reads always allowed; write/delete need approval). Important points: Claude only accesses data when you ask (not background watching), connectors can be toggled on/off or disconnected, and Anthropic does not use your calendar/email data to train their model — data stays private.
- Key claims: connectors remove copy-paste by reading your apps directly; built on MCP; 50+ connectors as of 2026; read vs write permission controls; Anthropic does not train on your connected data; Claude works with your data rather than you feeding it.
- Learner-relevant: The bridge from chatting to real-live-data automation; Level 2 deepens multi-connector workflows.
- Resources: MCP (Model Context Protocol); connectors: Gmail, Google Calendar, Google Drive, Slack, Notion, GitHub, Asana, Figma; Customize > Connectors

### 1.17 Claude Cowork
- Locator: `[[sources/claude-ecosystem-bootcamp/20260929/Claude Bootcamp Level 01 - Fundamental/1.17. Claude Cowork.en.srt]]`
- Summary: Introduces Cowork as delegating work to AI rather than chatting: Claude Chat is for conversation, Claude Cowork is for getting actual work done. Cowork is a desktop app from Anthropic designed for what it calls "agentic work" — instead of one question/one answer, you hand Claude a whole task and it figures out the steps, executes them, and returns a finished result. With Chat you are the driver steering every step; with Cowork you are a manager who gives a goal and Claude handles execution (output is a real finished file: document, spreadsheet, report). Context also differs: Chat context resets unless you are in a project, but Cowork has access to your actual folder, reading existing files and saving new ones directly there. Three real examples: (1) business contract review — point Claude at a folder of 50 contracts, flag high-risk clauses, get a summary memo and risk report; (2) marketing competitor analysis — with the Chrome extension connected, ask Claude to research five competitors and build a comparison table by visiting their sites; (3) morning briefing — a scheduled task that at 7am checks your calendar, pulls top Slack messages, reviews email highlights, and sends a summary. Key features: folder access (only what you allow; everything else off-limits), scheduled tasks (daily/weekly/monthly, run while the desktop app is open), sub-agents (breaks bigger tasks into parts run in parallel), dispatch (send tasks from your mobile phone to the desktop), and browser automation (via the Claude Chrome extension). Rule of thumb: use Chat for quick questions, short drafts, back-and-forth; use Cowork for multi-step tasks involving real files/folders, large data, repetitive work to automate, or research across many sources — if it would take you more than 30 minutes manually and involves files or information gathering, it's a Cowork task.
- Key claims: Cowork = agentic delegation; it has direct access to a permitted folder; outputs are real deliverables; folder access is scoped/safe; scheduled tasks, sub-agents, dispatch, and browser automation are its core features.
- Learner-relevant: The pivotal shift from using AI to directing it; Level 2 goes deeper.
- Resources: Claude Cowork (desktop); Claude Chrome extension; scheduled tasks at 7am; sub-agents; dispatch; Slack, Calendar, Gmail connectors

### 1.18 Claude Code
- Locator: `[[sources/claude-ecosystem-bootcamp/20260929/Claude Bootcamp Level 01 - Fundamental/1.18. Claude Code.en.srt]]`
- Summary: Introduces Claude Code as Anthropic's AI coding assistant that is not just for developers — if you want Claude to build a tool, write a script, or set up a web app on your computer, Claude Code is how. It is like a senior developer sitting next to you who never tires and works fast: it can read and understand your entire project, plan what needs doing, write code, create files, make changes across multiple files, run commands and tests, and show you what it is doing before it's done. Contrast with Cowork: Cowork is like a smart office assistant (access to a specific folder; documents, research, writing, organizing; great for knowledge work) while Claude Code is a full development environment (whole project, runs code/commands, interacts with the terminal, actually builds things) — "if Cowork is your office assistant, Claude Code is your dev team." Two examples: a personal finance dashboard web app that reads a CSV and charts monthly income vs expense ("give me a simple web app that reads my CSV file and shows a monthly income versus the expense chart"), and a marketing script that reads a list of URLs and pulls company names, emails, and contact pages into a CSV to automate 18 hours/week of work. Where to use it: local (desktop app Code tab; local terminal; inside your IDE — Visual Studio Code, Cursor, Anti-Gravity) and remote (connect to a GitHub repo and run entirely in the cloud; remote control from mobile via the Claude mobile/web app; dispatch tasks from anywhere; channels like Telegram, Discord, iMessage). ### 1.27 Prompt engineering
- Locator: `[[sources/claude-ecosystem-bootcamp/20260929/Claude Bootcamp Level 01 - Fundamental/1.27. Prompt engineering.en.srt]]`
- Summary: Explains prompt engineering as crafting a clever instruction to get AI to do exactly what you want — choosing the right words in the right order. Example: instead of "hey, write me an email," say "write me a short, friendly email to a client explaining the project delay. Keep it under 100 words, don't make excuses, and with a clear next step." It works great for simple one-off, single-turn tasks, which is what early AI tools mostly handled. But it falls apart with ambitious multi-step work: reading email, drafting a reply, checking the calendar, scheduling a follow-up, and logging outcomes are five dependent steps, and a clever prompt for step one doesn't carry over — the AI doesn't remember two steps ago, forgets key details, uses tools wrong, or makes things up to fill the gap. The big idea: prompt engineering is one instruction; context engineering is the whole system that makes AI reliable across many steps. Analogy: prompt engineering is writing one great line in a movie script; context engineering is being the director making sure every actor knows their role, the scene is set, and the story flows. The people building powerful AI ask what information Claude needs at every step, how to stop it forgetting, and how to connect it to tools/data/workflow. The next lesson defines context engineering.
- Key claims: prompt engineering = one instruction, good for simple/one-off tasks; it breaks on multi-step dependent work; context engineering is the system that makes AI reliable across steps; winners think in systems, not one magic prompt.
- Learner-relevant: Reframes the learner from prompt-hacking toward system design.
- Resources: example prompt: "write me a short, friendly email to a client explaining the project delay. Keep it under 100 words, don't make excuses, and with a clear next step."

### 1.28 Context engineering
- Locator: `[[sources/claude-ecosystem-bootcamp/20260929/Claude Bootcamp Level 01 - Fundamental/1.28. Context engineering.en.srt]]`
- Summary: Defines context engineering, opening with an Andrej Karpathy quote that it is "the delicate art and science of filling the context window with just the right information for the next step." A context window is everything Claude reads on each message — your message, the full conversation history, and any files or instructions loaded in; Claude has no persistent brain, so it only sees "what's on the whiteboard right now," and the window has a size limit. Context engineering is bigger than prompt engineering: prompt engineering = one sentence, context engineering = the entire system that delivers that sentence plus everything around it. Real example: "hey book me a hotel in Paris for the AI conference next month" fails alone because Claude doesn't know which Paris, your budget, or company travel policy; with a proper system (calendar access, travel rules, past preferences, a live hotel-pricing tool) it gets the right answer every time. Five things context engineering controls: system instructions (background rules like "you are a travel booking assistant, always follow company travel policy, never book a hotel over $200 per night"), RAG / retrieval documents (pull only the relevant policy section, not a 50-page doc), memory (what gets saved and brought back), tool descriptions (what each tool does and when to use it), and conversation history (how much past conversation to keep — all or a summary). Key surprise: more context is not always better — as context grows, performance gets less reliable even on simple tasks (finding your keys in a small room vs a massive warehouse). LangChain's four strategies for context engineering: write (set a solid instruction first), select (only pull what the task needs), compress (summarize long conversations), and isolate (keep different information types separate — don't mix HR policy with marketing campaign, it creates noise).
- Key claims: context window = everything Claude reads per turn; prompt engineering is one sentence, context engineering is the whole system; more context can hurt reliability; five inputs (system instructions, retrieval, memory, tool descriptions, history); LangChain's four strategies: write, select, compress, isolate; Karpathy defines context engineering.
- Learner-relevant: Central mental model for building reliable AI systems; explains why the same Claude can feel completely different.
- Resources: Andrej Karpathy quote; example prompt "hey book me a hotel in Paris for the AI conference next month"; system instruction example ("never book a hotel over $200 per night"); LangChain; strategies write / select / compress / isolate

### 1.29 AI Harness
- Locator: `[[sources/claude-ecosystem-bootcamp/20260929/Claude Bootcamp Level 01 - Fundamental/1.29. AI Harness.en.srt]]`
- Summary: Closes the module and Level 1 by introducing the agent harness. Even with perfect context, the AI needs someone in charge to say where to start, what to do, not go off track, and stop when done — that is the harness. One-line version: the model is a brain, the harness is everything else. Chatbot vs agent: a chatbot is texting someone a question and getting one reply; an AI agent is hiring someone for a project — you tell them the goal, they figure out the steps, use tools, and come back. The key difference is that the AI runs in a loop: does a step, checks the result, does the next, and so on, carrying memory of every prior step (so by step 47 a lot of information has built up, which is exactly why it needs a harness). Analogy: a horse is powerful and fast but doesn't know where to go (might run in circles, bolt, or stop) — you need a harness to guide it, control where it goes, how fast, and when to stop; the model is the horse, the harness is the system around it. Harnesses handle five main things: tools (search, calculator, file access), memory (what to remember or forget between steps), guardrails (rules on what the agent may or may not do), lifecycle (start, stop, restart, recover from crashes), and validation (check output and catch bad results before passing it on). Division of labor: the agent handles the what and why (thinks, reasons, generates output), the harness handles the how and where (executes, knows where things live, manages environments, validates) — "the agent thinks, the harness acts." Loop example: the harness creates a task list like a plan, then picks a task, gives the agent its context, the agent works only that task and validates the result, marks it done, and moves on, finally delivering the output. This breaks one massive task into small steps with a fresh clean context per loop, which is how modern AI tools build whole apps and process huge projects without losing track. Real example: OpenAI's Codex team built a production application with over 1 million lines of code where no human wrote a single line — engineers designed the harness and the AI wrote everything. Closing stack: prompt engineering is still used but small; context engineering manages memory, tools, and information on top; harness engineering wraps around everything creating the environment where the agent runs and produces reliable results — they don't replace each other, they stack. Wrap-up: a chatbot answers one question at a time; an AI agent works in a loop using tools and building on each step; the harness is the system around it (tools, memory, guardrails, structure). The model is a brain and the harness is what makes it actually useful. Level 2 goes deeper into connectors, skills, MCP, plugins, and Claude Cowork.
- Key claims: model is the brain, harness is everything else; agents run in a loop and accumulate memory; harness handles tools, memory, guardrails, lifecycle, validation; agent thinks, harness acts; harnesses give each loop a fresh clean context; OpenAI's Codex team built a 1M+ line production app with no human-written code by designing the harness; prompt/context/harness stack rather than replace each other.
- Learner-relevant: The capstone concept of Level 1 and the foundation for autonomous systems in Level 4.
- Resources: horse/harness analogy; harness components tools/memory/guardrails/lifecycle/validation; OpenAI Codex team 1M+ line application example; Level 2 topics: connectors, skills, MCP, plugins, Claude Cowork
