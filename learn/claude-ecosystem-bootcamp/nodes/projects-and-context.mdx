# 專案與三層 context

## Learning goal

能為重複性工作建立 Chat / Cowork 專案，並理解 global / 專案 claude.md / 子資料夾三層 context 的覆蓋規則。

## Steps

1. [[learn/claude-ecosystem-bootcamp/nodes/projects-and-context/why-projects|「專案」是什麼：把重複的背景一次講清楚]] — 專案的三個組成，以及「何時該開、一次只做一件事」的判斷規則
2. [[learn/claude-ecosystem-bootcamp/nodes/projects-and-context/create-a-chat-project|動手開一個 Chat 專案]] — 用自訂指令加知識庫，實際開一個範圍明確的專案（after step 1）
3. [[learn/claude-ecosystem-bootcamp/nodes/projects-and-context/cowork-projects|Cowork 專案：會動手的專案]] — 和 Chat 專案的差別、多出的四樣東西與三種建立方式（after step 1）
4. [[learn/claude-ecosystem-bootcamp/nodes/projects-and-context/context-layers|三層 context 與覆蓋規則]] — global 指令、claude.md、子資料夾如何疊起來，衝突時誰贏（after step 3）
5. [[learn/claude-ecosystem-bootcamp/nodes/projects-and-context/common-mistakes|五個常見錯誤與修法]] — 從範圍太廣到專案 vs skill 的診斷清單（after steps 2、4）

## Lesson

你已經會用 Chat 對話，也會叫 Cowork 整理本機檔案了。但如果你每天都做同一類工作——每開一個新對話就要重新自我介紹、重貼品牌語氣、重傳同一批檔案，那每次都在浪費前五分鐘，而且只要漏講一句，產出就會走鐘。

這個節點要解決的就是這個問題：把「重複的背景」變成一個可以重複使用的空間。專案（project）就是這個空間——它保留你的指令、檔案與對話歷史，讓 Claude 每次都知道你在做什麼。這裡有兩條路：Chat 專案負責記住脈絡、產出文字與 artifact；Cowork 專案則接管一個真實資料夾，能讀檔、寫檔、跑排程。兩種專案共用同一套「分層 context」的心法：越靠近任務的那一層，講話越大聲。

這個節點的五步依序回答：專案是什麼、什麼時候該開；怎麼實際開一個 Chat 專案；Cowork 專案多了什麼能力；多層 context 最後是怎麼疊起來、衝突時聽誰的；最後把大家最常踩的五個坑一次列出來。走完之後，你應該能替一項重複性工作開出一個範圍明確、背景齊全的專案，並且知道要改語氣或規則時該去動哪一層。
