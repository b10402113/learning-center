開始前的設定：工作資料夾與全域指令

Step 2/4 · Cowork 接手本機檔案

學習目標

能開啟 Dispatch、指定預設工作資料夾，並寫出一段讓 Cowork 先問清楚、先給計畫、命名清楚、刪除前先問過的全域指令。

前言：交辦之前，先把規矩講好

上一節我們確定了 Cowork 會「動手」，也知道它會在你指定的資料夾裡工作。但在你把第一個任務丟給它之前，還有一件事要先做：把規矩講清楚。

想像你請了一位新助理。你不會第一天就讓他自己翻遍你的檔案櫃，然後期待他每一件事都猜中你的習慣。你會先花十分鐘交代：有不懂的就先問、動工之前先講一下你打算怎麼做、檔名取清楚一點、要丟掉的東西先問過我。把這些講完，之後你才可以放心把事情整個交給他，不用每次在旁邊盯著。這一節就是把這段「入職說明」寫好，而且只寫一次。

設定一：開啟 Dispatch

第一個開關是 Dispatch，它之後會讓你從手機把任務丟給桌機上的 Claude。現在先把這個 beta 功能打開就好，細節等後面的節點再展開。它是一個「先用不到，但之後會用到」的開關，順手開起來。

設定二：指定一個預設工作資料夾

第二個設定，是給 Cowork 一個固定的家。建立一個專門的資料夾，例如放在桌面上、命名叫 my cowork，把它設成預設工作資料夾。

這個動作其實就是在回答上一節那個問題：它到底能碰哪裡？你設了這個資料夾，它就以此為主要活動範圍。好處有兩層：一來你的日常工作資料夾不會被它意外動到，安全；二來你自己也清楚「它做的東西都會出現在這裡」，找檔案不用猜。

立規矩：寫一段全域指令

再來是重頭戲：全域指令（global instruction）。它適用於所有 Cowork 工作階段，是你放「偏好、慣例與不可妥協事項」的地方。你把規則寫在這裡，之後每一個任務都會自動套用，不必每次重打。

這是一段可以直接拿去用的範例：

Before starting any task, use AskUserQuestion tool to ask me 2–3 clarifying questions if anything is unclear. Always show me your plan before you begin. When creating files, name them clearly and descriptively. Never delete anything without asking me first.

翻譯成白話，這四句話分別代表了四條規則。先把它們一條一條拆開來看，你就會明白每一條在防什麼：

  1. 動手前先問清楚：如果任務裡有任何不確定的地方，先問我 2 到 3 個釐清問題，不要自己猜。
  2. 動手前先給計畫：開始執行之前，先把你的計畫攤給我看。
  3. 命名要清楚：建立檔案時，取一個描述性的、看得懂的名字。
  4. 刪除前先問：任何刪除動作，都要先問過我。

為什麼「先計畫再動手」是關鍵

這四條裡，最重要的其實是第二條。有了它，Cowork 的執行會變成兩個階段：先規劃，暫停下來等你看過，你點頭之後才真正動手。

這個節奏有個好處：你永遠不會在回來時發現它已經做了一堆你不想做的事。它在動手前一定先讓你看見它打算怎麼做，你覺得不對就喊停，修改的成本幾乎是零。相反地，如果它是一路做到底才給你看結果，等你發現方向錯了，可能已經刪錯檔案、或改壞了資料。

第一條「先問清楚」則是搭配著用的。很多時候任務指令本身就寫得不夠精確，與其讓它硬著頭皮猜，不如讓它主動回來問你。這兩條加在一起，等於在流程的起點與動工點各設了一道檢查。

把規則放進全域指令，任務就能維持簡短

你可能會想：那我每次下任務的時候再講不就好了？可以，但很麻煩。把這些通用規則集中寫在全域指令，你之後下的任務指令就只需要交代「這次要做什麼」，不用每次重複「要問我、要給計畫、要好好命名」。這是 Cowork 的核心節奏：設定一次，之後反覆使用。

而且這些規則是「底線」性質的東西：不管這個任務是整理檔案、做報表還是研究資料，你都不希望它亂刪、亂命名。既然每一種任務都適用，放進全域指令就再自然不過。

小結

動手之前先把環境與規矩準備好。開啟 Dispatch、指定一個預設工作資料夾，把它圈在你的安全範圍裡；再寫一段全域指令，讓 Cowork 先問清楚、先給計畫、命名清楚、刪除前先問過。其中「先給計畫」最關鍵，它把執行拆成「先規劃、你同意、再動手」兩段，讓你在它真正動作前有機會修正。規則寫一次，之後每個任務都套用。

規矩立好了，接下來就可以真的交辦事情。下一節要跑第一個真實任務：把一團亂的 Downloads 資料夾整理乾淨：分類、改名、抓重複檔，全部交給它。
