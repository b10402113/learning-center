為什麼要用 Cowork：把工作交出去，而不是一直對話

Step 1/4 · Cowork 接手本機檔案

學習目標

能說出 Cowork 與 Chat 的差別，判斷哪些任務該交給 Cowork，並認得它的核心能力。

前言：方法你都懂了，動手的還是你

先想像一個週末下午。你的 Downloads 資料夾裡躺著三百多個檔案，照片、安裝檔、電子帳單、來路不明的壓縮檔全混在一起。你打開 Claude，問它「要怎麼整理下載資料夾」，它給你一套很漂亮的步驟：先按類型分類、再重新命名、最後揪出重複的。你看完點點頭，覺得講得真好。然後呢？然後你還是得自己開 Finder，一個檔案一個檔案慢慢拖。

你拿到的是「方法」，不是「結果」。這個落差就是這一節要處理的事：Claude 除了坐在對話框裡回答你，還有一個介面會直接動手。它叫 Cowork。認得它之後，你會開始分得清楚哪些事根本不該再自己來。

關鍵一：Chat 的天花板在哪裡

先講清楚 Chat 為什麼幫不了你動手，才不會對它抱錯期待。Claude Chat 有幾個很具體的上限：一次對話大約只能處理 25 個檔案，每個檔案上限約 30MB。更根本的限制是，它碰不到你電腦裡的檔案系統，也沒辦法執行程式。

這兩件事合起來，決定了 Chat 的角色。它可以把「整理資料夾」的步驟講得頭頭是道，但它拿不到你電腦裡的那些檔案，也沒辦法真的把它們搬動。再加上對話本身有 context 與時間的上限，遇到長時間、很多步驟的任務，很容易做到一半就接不下去。

這跟模型聰不聰明無關，是介面設計的邊界。把 Chat 想成一張桌子：你在桌面上問、它回答，桌上不會出現倉庫的鑰匙。要拿到鑰匙，得換一個工具。

關鍵二：Cowork 把「回答」變成「交辦」

Cowork 是 Anthropic 的桌面應用程式，它主打的是所謂的 agentic work，直接翻就是「代理式工作」。什麼意思？以前的模式是你問一個問題、它回一個答案，一來一往；現在的模式是你把一整個任務交給它，它自己想清楚要做哪些步驟、依序執行，最後把做好的成品交回來。

打個比方。用 Chat 的時候，你是開車的人，方向盤在你手上，Claude 只是副駕駛幫你看路、給你建議。用 Cowork 的時候，你變成主管：你講清楚要達成的目標，把方向盤交出去，它自己規劃路線、開到目的地，然後回來跟你報告。

兩者最直接的差別反映在產出上。Chat 回你的是一段文字，你還得複製貼上、自己動手；Cowork 會在指定的資料夾裡產出真實的檔案，像是文件、試算表、報告，直接放在你電腦上。它做出來的是一份「可以拿去用的東西」，不是一份「教你怎麼做的說明」。

關鍵三：context 也跟著不同

除了誰動手，還有一件事不一樣：它們各自記得多少背景。Chat 除非你把它放進 project，否則每次對話的 context 都會重置，你得重新交代一次來龍去脈。Cowork 則直接連著你的資料夾，讀得到裡面既有的檔案，也能把新產出的檔案存回同一個地方。它天生就帶著一份「現場資料」。

這份存取權是安全的，因為它是被你圈住的。你指定哪個資料夾，它就只能在那一區活動；沒有被允許的地方，它一律碰不到。換句話說，鑰匙是你一把一把交出去的，而不是它自己拿的。

關鍵四：五個核心能力

Cowork 之所以能接手多步驟任務，是因為它身上裝了幾樣工具。先把這五樣記起來，後面幾節都會用到：

能力它在做什麼什麼時候派上用場
資料夾存取讀取、寫入、搬移你指定的資料夾任何牽涉本機檔案的整理與產出
排程任務每天、每週、每月自動執行（桌面 app 開著時）固定的晨報、週報這種例行工作
sub-agents把大任務拆成小塊，同時平行處理一次要處理幾十個檔案的時候
dispatch從手機把任務丟給桌機上的 Claude人不在電腦前、只想先交辦出去
瀏覽器自動化透過 Claude Chrome 擴充功能實際操作網頁需要上網查資料、填表的時候

其中「排程任務」只在桌面 app 開著的時候才會跑，這點先有個印象就好，之後的節點會專門講。現在你只要知道，這些能力讓 Cowork 除了「會回答」，還能「有手腳可以做事」。

關鍵五：多步驟任務，模型挑穩一點

如果你還記得前面談過的模型家族，這裡有一個實際的差別：Chat 的日常對話用 Sonnet、Haiku 就很夠；Cowork 因為常跑多步驟、長時間的任務，建議用 Opus 或 Sonnet，讓它在規劃與判斷上穩一點。這是經驗法則：任務越長、越不能出錯，就越值得用聰明一點的引擎。

一句話判斷：30 分鐘原則

那到底什麼時候該用 Chat、什麼時候該用 Cowork？記一條就好：如果這件事你自己手動做會超過 30 分鐘，而且牽涉到檔案或資訊蒐集，就是 Cowork 任務。

反過來，如果只是快速問答、寫一段短草稿、需要你來我往討論，Chat 反而更順手。判斷的標準不是「哪個比較厲害」，而是「這件事需不需要動手做，還是只需要動腦想」。

三個你會馬上想交出去的任務

為了讓這件事具體一點，這裡有幾個典型情境，看你會不會覺得「這種事真的好想丟出去」：

  1. 合約審閱：把 Cowork 指向一個裝了 50 份合約的資料夾，請它標出裡面的高風險條款，最後產出一份摘要備忘錄與風險報告。你自己讀完 50 份合約，可能就是一整個下午。
  2. 競品分析：接上 Chrome 擴充功能，請它研究五家競爭對手、實際走訪它們的網站，整理成一張比較表。原本要開五個分頁自己抄重點，現在是它去跑。
  3. 晨間簡報：排一個每天早上 7 點的任務，讓它檢查你的行事曆、抓出 Slack 重點訊息、看過 email 的重要信件，然後送一份摘要給你。你睜開眼睛，摘要已經躺在那裡。

這三個例子分別展示了 Cowork 的不同面向：第一種是大量檔案的處理，第二種是跨網站的資訊蒐集，第三種是自動排程。它們共同的特徵都是「步驟多、牽涉檔案或外部資訊、手動做很花時間」，正是 Chat 幫不上忙、而 Cowork 拿手的地方。

小結

Chat 幫你想，Cowork 幫你做。Chat 碰到本機檔案、長時間多步驟任務就會卡住；Cowork 直接連上你指定的資料夾，產出真實的檔案。它身上有五樣工具：資料夾存取、排程任務、sub-agents、dispatch 與瀏覽器自動化。選擇的判準很簡單：手動做會超過 30 分鐘、又牽涉檔案或資訊蒐集的任務，就交給 Cowork；多步驟工作用 Opus 或 Sonnet 會比較穩。

知道「該不該交出去」之後，下一個問題是「交出去之前要先講好什麼」。下一節要先把環境準備好：開啟 Dispatch、指定一個工作資料夾，然後寫一段「全域指令」，讓它動手前先問清楚、先給你看計畫、刪東西前先問過。這是一份交給它之前，必須先立好的規矩。
