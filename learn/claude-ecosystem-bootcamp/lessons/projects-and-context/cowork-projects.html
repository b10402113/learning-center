Cowork 專案：會動手的專案

Step 3/5 · 專案與三層 context

學習目標

能說出 Cowork 專案和 Chat 專案差在哪裡、它多出哪四樣東西，以及建立 Cowork 專案的三種方式。

前言：它記得，但它不動手

上一節我們開好了一個 Chat 專案，Claude 會記得你的背景、知道你要什麼語氣，也能產出品牌指南和課程結構這樣的文件。聽起來很夠用，對吧？但用久了你會撞到一面牆。

想像你要它「把這個資料夾裡的收據整理成一份 Excel 報表」。在 Chat 專案裡，它會告訴你「你可以這樣做」，然後給你步驟、給你公式，甚至給你一段看起來能用的程式碼。但它沒辦法真的打開你電腦上的資料夾、讀那些收據、把 Excel 檔存回去。它只能說，不能做。

這個落差，就是 Cowork 專案要補上的那一塊。

Chat 專案的天花板在哪裡

先把界線講清楚。Chat 專案很會「記住脈絡」，能讓你在不同對話之間保有連續性，不必每次重講。但它有三件事做不到：它不能建立真正的檔案、不能執行程式，也不能碰你本機的資料夾。

這跟設計好壞無關，它的定位本來就是「對話」。你在裡面得到的東西，大多還是文字；要變成檔案或實際動作，得靠你自己接手。當任務牽涉到一堆檔案、需要真的產出檔案、又得跑上一段時間時，對話的形式就綁手綁腳了。

Cowork 專案多出來的能力

Cowork 專案不一樣。它是一個桌面代理（desktop agent），能讀你真正的檔案，也能把真正的文件（PDF、Word、試算表）直接存進你的資料夾。同樣那句「整理收據成 Excel」，在 Cowork 專案裡是真的會發生的事。

除了能動手，Cowork 專案相比一般對話還多了四樣東西：

它多出來的白話解釋
持久的工作空間專案本身記得它在處理哪個資料夾、做過什麼
自訂指令設定一次，這個專案裡每次任務都自動套用
範圍化的記憶記憶留在這個專案裡，不會滲到其他工作去
排程任務可以設定讓某些事按時間自動執行

其中「範圍化的記憶」可以多講一句。它指的是這個專案學到的東西只留在這裡，不會跑到你其他專案去亂講話。你替某個客戶建立的偏好，不會突然出現在另一個客戶的報告裡，這對同時處理多份工作的人來說很重要。

建立 Cowork 專案的三種方式

要開始一個 Cowork 專案，有三條路可走，你可以依手上的狀況挑一條：

  • 從零開始。全新開一個專案，適合全新的工作。
  • 從 Claude chat 匯入。把你已經在 Chat 裡養好的專案搬過來，讓它從「會聊」升級成「能做」。你之前累積的指令和檔案可以延續。
  • 包在既有資料夾外面。指向一個你本來就有的資料夾，讓 Cowork 專案以它為工作範圍。這種最適合你已經有一堆檔案、只想讓 AI 接手的情況。

推薦的第一句提示：讓它自己報到

剛建好一個 Cowork 專案時，建議你先不要急著派任務，而是讓它做一次「自我報到」。具體做法是請它讀完資料夾裡的每一個檔案，然後回報：它知道這個工作空間在做什麼、以及它接下來會遵守哪些指令。

這一步的價值有兩個。第一，你能立刻看出它有沒有讀懂你的設定。如果它報出來的東西跟你預期的不一樣，代表 context 還沒設好，趁現在修正最省事。第二，這等於幫你確認資料夾裡的內容跟你想的一致，有時候你自己都忘了某個舊檔案還躺在裡面。等它報到正確，再開始派真正的工作，成功率會高很多。

小結

Chat 專案會記得脈絡，但不能建立真檔案、不能執行程式、也碰不到本機資料夾。Cowork 專案是桌面代理，能讀真檔案、存真文件，還多了四樣東西：持久工作空間、自訂指令、範圍化記憶、排程任務。建立方式有三種：從零開始、從 Chat 匯入、包在既有資料夾外面。剛開好時，先用「讀完所有檔案並回報你知道了什麼」這句提示讓它自我報到，確認設定正確再派工。

不管是哪一種專案，「知道你的規矩」都是靠一層一層的設定疊出來的。下一節要把這套分層打開來看：global 指令、專案 claude.md、子資料夾的 claude.md，這些層是怎麼疊起來的，萬一互相衝突又該聽誰的。
