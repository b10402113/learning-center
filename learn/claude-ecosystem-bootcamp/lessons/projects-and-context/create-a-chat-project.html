動手開一個 Chat 專案

Step 2/5 · 專案與三層 context

學習目標

能照著步驟建立一個範圍明確的 Chat 專案：寫好自訂指令、把兩個參考檔案放進知識庫，並用一句話在專案裡直接下新需求。

前言：從「知道該開」到「真的開好」

上一節我們把判斷規則講清楚了：工作會重複、你常重講背景、成果取決於你的情境，這三件事出現時就該開一個專案；而且範圍要窄，一個專案只做一件事。但知道規則不等於會操作，就像看懂食譜跟真的把菜煮出來是兩回事。

這一節我們用一個具體的例子走完一次：假設你正在規劃一堂線上課程「Ollama Mastery」，主題是教人用 Ollama 在自己的電腦上跑 AI 模型。這個專案我們刻意只做「設計階段」，也就是產出品牌指南和課程結構這兩份文件，影片腳本和教材先不管。範圍先框好，後面的操作才不會失焦。

為什麼先框範圍：設計階段就只做設計

把專案命名為「Ollama Mastery：設計階段」，本身就是一個決定。它告訴 Claude：這個專案現在的任務是「把課程的外型跟骨架定出來」，而不是「把整堂課做完」。

這麼做不是龜毛，是上一節黃金規則的實際演練。當一個專案試圖包辦所有事，Claude 會失去焦點，產出跟著變差。先把範圍切在「設計」這一刀，你待會下的每個需求都會落在同一類工作上，結果自然更集中。

第一步：建立專案、寫好自訂指令

在 Claude 的專案區建立一個新專案，命名之後，先寫自訂指令。自訂指令是這個專案的「入職說明」，至少涵蓋四件事：你是誰、這個專案在做什麼、要什麼語氣、要避開什麼。以這個例子來說，大致會長這樣：

我在規劃一堂線上課程「Ollama Mastery」，
教開發者與對技術好奇的學習者用 Ollama 在自己電腦上跑 AI 模型。
這個專案目前只做設計階段：品牌指南與課程結構。
語氣清楚、務實，不要浮誇的行銷腔。
不要幫我寫影片腳本或教材，那是以後的事。

寫完之後，這個專案裡的每一段對話都會自動帶著這段背景。你不需要在每次開新對話時重貼它，這也是專案存在的意義。

第二步：用 Firecrawl 做出品牌指南

接著要產出第一份文件：品牌指南。這一步會用到一個外部工具 Firecrawl。它是一個能讓 Claude 直接讀取網頁內容的連接器（connector，可以想成讓 Claude 伸手去拿外部資料的插座）。在這個專案裡把它接上之後，Claude 就能自己爬取網站，不用你把資料一段一段複製貼上。

在這個專案裡，我們請 Claude 去爬 ollama.com 的首頁，分析它的主要色與次要色、字體與排版、視覺風格和整體語氣，然後把分析寫成一份品牌指南文件。提示可以這樣下：

用 Firecrawl 爬取 https://ollama.com/ 的首頁。
分析這個頁面的主要色與次要色、字體與排版、
視覺風格，以及整體語氣。
然後根據這個分析建立一份品牌指南文件，
存成 brand-guidelines.md

跑完之後，你就得到第一份可用的文件 brand-guidelines.md。整段過程你沒有手動去截圖、抓色碼或翻字體，是連接器直接幫你完成的。

第三步：用研究模式設計課程結構

第二份文件是課程結構。這一步換一個角度：不爬網站，改請 Claude 幫你做規劃。這裡可以開啟研究模式（research mode），讓它在回答前先做較深入的搜尋與整理，適合像「設計一整堂課的模組與課名」這種偏向規劃的工作。

在同一個專案裡開一段新對話，下這個提示：

我正在做一堂線上課程叫 Ollama Mastery。
對象是想用 Ollama 在自己電腦上跑 AI 模型的
開發者和對技術好奇的學習者。
這堂課要從初學者設定一路做到打造一個
本機 AI 應用。
幫我設計完整的課程結構，包含模組名稱與
每一課的標題，然後存成 course-structure.md

跑完之後，你會得到第二份文件 course-structure.md，裡面是模組名稱和一課一課的標題。到這裡，設計階段要的兩份產出就都齊了。

第四步：把兩份文件放進知識庫

最後一步是把 brand-guidelines.md 和 course-structure.md 加進這個專案的知識庫。這動作看起來很小，卻是整個流程的關鍵。上一節提過，檔案一旦被放進知識庫並被指名引用，就變成可重複使用的知識。

之後你在這個專案裡開新對話，只要說「根據品牌指南做一張宣傳圖」或「照課程結構寫一段課程介紹」，Claude 就抓得到這兩份檔案，不必你再上傳一次。這就是「設定一次、之後都算數」的實際樣子。

還有一點：這類牽涉深度規劃的工作，換上更強的模型（例如 Opus）往往能得到更好的結果，代價是花費的用量更多、等待時間更長。你可以先用一般模型跑，覺得不夠滿意再升級。

小結

開一個 Chat 專案的四步是：建立專案並寫好自訂指令、用連接器（例如 Firecrawl）產出第一份參考文件、用研究模式做深度規劃產出第二份文件，最後把兩份文件放進知識庫。範圍要先框窄，這個例子只做設計階段；因為專案一旦想包辦所有事，Claude 就會失焦、產出變差。專案加上連接器，等於用對話就拿到兩份現成文件，過程中不必手動做研究。

到這裡，你已經做出一個會記住背景、能重複使用的 Chat 專案。但 Chat 專案有個天生的天花板：它記得脈絡，卻沒辦法真的動手碰你的檔案。下一節要看的是 Cowork 專案，它能讀檔、寫檔，把「記得」升級成「做到」。
