五個常見錯誤與修法

Step 5/5 · 專案與三層 context

學習目標

能認出專案最常見的五個錯誤（範圍太廣、檔案太大、檔案命名混亂、該用 skill 卻開專案、把 Chat 專案當 Cowork 專案用），並說出各自的修法。

前言：專案壞掉時，通常不是它壞了

你有沒有遇過這種感覺：專案明明設好了，Claude 卻開始答非所問，給的答案跟你上傳的資料對不上，彷彿它突然變笨了。多數人第一個反應是「模型是不是退步了」，但實際上，問題幾乎都出在專案本身的設定方式。

前面四節把該做的都講了：什麼時候開、怎麼開、Cowork 多什麼、context 怎麼疊。這一節換個角度，把最常見的五個錯誤列出來。它比較像一份診斷清單。當你覺得專案不聽話時，照著這五項逐一檢查，通常就能找到兇手。

錯誤一：專案範圍太廣

第一個錯誤已經在第一步出現過，但它太常見，還是得放進清單。症狀是：你把客戶報告、社群貼文、財務對帳、履歷修改全塞進同一個專案，結果每一種產出都變得很平庸。

原因是 Claude 無法判斷你「現在」到底在做哪一件工作，只能取一個模糊的中間值，於是什麼都沾一點、什麼都不精。這看起來像它能力不足，問題出在你給的範圍太模糊。修法是把大專案拆開，遵守「一個專案，只做一件事」。判斷時機很簡單：當某個專案裡的需求開始讓你覺得「這好像跟原本的不太一樣了」，就該拆了。

錯誤二：上傳太大的檔案

第二個錯誤很隱蔽。你上傳了一份幾百頁的大文件，心想「資料越完整越好」，結果 Claude 的回答開始偏題，甚至講出文件裡根本沒有的內容。你以為它壞了，問題是檔案太大。

當一份檔案超過它能好好處理的份量時，它只能從中抓片段、拼拼湊湊。片段沒對上，產出就看起來像在胡說。修法是先修剪檔案：只留這個任務真正需要的章節或段落，把不相關的部分切掉。資料齊全不等於資料有用，重點是「對得上眼前這件事」。

錯誤三：檔案管理混亂

第三個錯誤是你的資料夾本身太亂。檔名像 final_final_v3(2).xlsx、未命名文件1.docx，一堆檔案看不出差別。Claude 得靠檔名判斷內容，檔名一亂，它就抓錯檔案，回答自然也亂。

修法有兩個。第一，用清楚、描述性的檔名，讓人跟 Claude 一看就知道裡面是什麼。第二，能用 CSV 就別用 Excel，CSV 是純文字的表格格式，資料乾淨、沒有隱藏的工作表或格式殘留，Claude 讀起來更準。把資料夾整理得像給新同事交接一樣整齊，它就少犯很多錯。

錯誤四：該用 skill 的時候卻開了專案

第四個錯誤是工具選錯。你想讓 Claude 穩定地用某種風格寫東西，於是開了一個專案。這沒有錯，但你搞混了一件事：專案「留在原地」，skill 則「跟著你跑」。

差別在哪裡？專案只作用在它自己那一個地方，你到別的專案就沒有這套規則了。skill 不一樣，它是可以帶著走的能力，你在任何專案裡都能叫它出來用。所以當你問「這件事我只需要在這一處用，還是希望到處都能重複用？」答案如果是後者，那你要的是 skill，不是再多開一個專案。選錯工具，就會遇到「為什麼換個地方它就不會了」的挫折。

錯誤五：把 Chat 專案和 Cowork 專案搞混

最後一個錯誤是概念混淆。很多人以為 Chat 專案和 Cowork 專案是同一種東西的兩種版本，於是對著 Chat 專案要求它「去整理我電腦裡的資料夾」，當然做不到。

兩者的定位要分清楚：Chat 專案是一個持久的工作空間，很會記得脈絡、產出文字與文件，但它碰不到你的本機檔案。Cowork 專案則是一個可執行的工作空間，能讀檔、寫檔、跑排程，專門處理本機檔案與自動化。要用哪一種，取決於你的任務是「需要它記得」還是「需要它動手」。

小結

當專案不聽話，先別怪模型，照這五項檢查：範圍太廣就拆成「一個專案一件事」；檔案太大就修剪成跟任務相關的段落；檔案管理亂就改用清楚的檔名、能用 CSV 就用 CSV；想重複使用某種做法就改用 skill（專案留在原地，skill 跟著你跑）；最後別把 Chat 專案當 Cowork 專案用：一個記得脈絡，一個動手做本機檔案。大多數「它變笨了」的狀況，都是這五個之一。

走完這個節點，你手上有一套完整的專案能力：知道為什麼要開、怎麼開 Chat 與 Cowork 兩種、context 怎麼分層、以及壞掉時怎麼診斷。下一步就是把這套能力放進真實的重複性工作裡。開一個能長期運作、越用越順的專案，你需要的條件已經齊了。
