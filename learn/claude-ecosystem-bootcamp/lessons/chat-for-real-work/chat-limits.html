Chat 的界線：什麼時候該改找 Cowork 或 Code

Step 4/4 · 用 Chat 做真實工作

學習目標

能指出 Chat 的三個限制，並在需要碰本機檔案、排程或代操作電腦時改找 Cowork 或 Code。

前言：知道它不能做什麼，才算真的會用

上一節我們列了六類最適合 Chat 的任務，你現在大概已經知道該把手上的寫作、解釋、腦力激盪往哪裡丟。但真正讓一個人會用一個工具，關鍵往往在於他知道這個工具做不到什麼。

因為如果你把一件 Chat 根本辦不到的事硬丟給它，你會得到一種很挫折的結果：它很客氣地回你一段話，聽起來像在幫忙，實際上什麼都沒動。你會以為是自己 prompt 寫不好，其實是找錯了工具。這一節要把 Chat 的三條界線畫清楚，並告訴你越界之後該改敲哪一扇門。

界線一：不會存取你的檔案

第一條界線是檔案。Claude Chat 不會去讀你電腦裡的檔案，也讀不到你本機資料夾裡的文件。你可以在對話裡上傳檔案給它看，那是你主動餵給它的；但它不會自己去翻你的硬碟、也不會自動去某個資料夾把檔案抓出來。如果你需要的是「請 AI 直接接手我這個資料夾」，那已經不是 Chat 的工作。

界線二：不會照排程自動執行

第二條界線是時間。Chat 不會在你沒開口的時候自動做事。它沒有「每天早上七點自己醒來跑一遍」這種能力。你必須主動打開對話、送出訊息，它才會回應。所以任何「要它按時間自動反覆執行」的需求，都不是 Chat 能承接的。

界線三：不會在你電腦上代你操作

第三條界線是動手。Chat 不會在你的電腦上替你做動作。它不會幫你開啟軟體、不會替你存檔改名、不會在你電腦上跑一串操作。它給你的是答案、是文字、是判斷；至於把這些答案真的落實在電腦上的動作，它不負責。這也是它和「會自己動手的 AI」最根本的分野。

把這三條合起來看，其實就是一句話：Chat 是對話工具，不是替你動手的工作工具。你問，它答；但「你沒問它不會自己動」「你電腦裡的東西它不碰」「你電腦上的操作它不代勞」。

越界之後：改找 Cowork 或 Code

那如果我的任務剛好越過這三條線呢？答案是換工具。Claude 生態系裡有另外兩個介面，就是為了接住這些 Chat 辦不到的事：

你的需求該找誰
直接接手本機資料夾，讀取既有檔案、把新檔案存回去Cowork
設定每天、每週、每月自動執行的任務Cowork
讓 Claude 在你的電腦上執行多步驟的工作Cowork
讀懂整個專案、跑程式、改動多個檔案、使用終端機Code

這裡先建立一個簡單的對照就好，這兩個工具後面各有專門的節點會細講。你現在要記住的是分工：Chat 處理只需要對話就能完成的事；一旦牽涉到本機檔案、時間排程，或要 AI 真的在你的電腦上動手，就換 Cowork 或 Code。

有一個很實用的經驗法則可以先放進口袋：如果一件事你自己手動做會超過三十分鐘，而且過程牽涉到一堆檔案或到處蒐集資訊，那它八成不是 Chat 的活，該交給 Cowork。這個判準之後還會再回來用。

繞回原點：Chat 的定位

講完界線，我們其實繞回了 Chat 最核心的定位：它是一個對話工具，是你日常的思考夥伴。你帶著問題來，它帶著答案回。它不碰你的檔案、不排你的時間、不替你操作電腦，這不是它不夠好，它的設計本來就專注在「陪你對話、幫你想清楚」這件事上。

當你能一眼分辨「這件事是問答，還是動手」，你就真的會用 Chat 了：該聊的事情留給它，該動手的任務交給 Cowork 或 Code。這個節點從「在哪裡用」講到「它強在哪」，再講到「該把什麼交給它」，最後收在「什麼不該交給它」，這四步合起來，就是一套完整的工具判斷力。

小結

Claude Chat 有三條界線：它不會存取你電腦裡的本機檔案、不會照排程自動執行、也不會在你電腦上代你操作。合起來說，它是一個對話工具，不是替你動手的工作工具。你沒問它不會自己動，你電腦裡的東西它不碰，你電腦上的操作它不代勞。當任務越過這三條線，就換工具：需要接手本機資料夾、設定排程或執行多步驟電腦工作，找 Cowork；需要讀懂整個專案、跑程式、改動多個檔案，找 Code。最實用的判準是：如果一件事手動做會超過三十分鐘、又牽涉一堆檔案或資訊彙整，那通常不是 Chat 的活。把 Chat 留給「想一想、寫一寫、讀一讀」，需要真的動手時再換工具，你就算真的會用了。

這個節點到此完成。你現在手上有一套清楚的判斷：Chat 是對話與思考的夥伴，負責寫作、解釋、腦力激盪、快速分析、研究問答與一次性草稿；一旦需要碰本機檔案、排程或代操作電腦，就換 Cowork 與 Code。接下來，我們會正式踏進 Cowork，看看「把手上的檔案整個交給 AI」是什麼樣子。
