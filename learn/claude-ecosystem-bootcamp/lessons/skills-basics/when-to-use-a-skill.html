何時該用 skill，而不是每次重打提示詞？

Step 2/3 · Skill 是什麼、安裝一個來用

先從一個常見情境開始

你每週都要請 Claude 寫幾篇社群貼文。每次都得重新貼上相同的要求：先抓住讀者注意力、使用指定語氣、控制字數、加上行動呼籲，最後還要依照固定格式輸出。

第一次這樣做很快；但做久了，提示詞會像一張越寫越長的便利貼。某次漏掉一條規則，產出的格式就變了；換到另一個專案，又得重新整理一次。

這時，你可能會想把這套做法存起來。不過，並不是所有提示詞都值得做成 skill。上一節我們知道，skill 是一份把做法存起來、能在符合任務時自動觸發的指令包。現在要解決的是：什麼時候該用 skill，什麼時候直接打一段提示詞、開一個專案，或使用 connector？

先把四個選項放在一起比較

面對一項工作，你其實有四種工具可以選。它們處理的問題不同，也可以搭配使用。

選項它主要解決什麼適合的時機
一次性提示詞立刻取得一個結果只做一次，或做法還在摸索
專案（project）保留背景、資料與工作情境需要固定使用同一批檔案，或維持同一個角色設定
Skill固定「怎麼做」的步驟與規則步驟固定、在意一致性，而且會跨專案重複使用
Connector讓 Claude 直接讀寫外部工具需要接上 Gmail、Slack 這類服務

最容易混淆的是 skill 和專案。可以先記住這句話：專案跟著工作場合走，skill 跟著你走。

專案保存的是某個工作情境裡的背景，例如品牌指南、受眾資料或特定檔案。離開那個專案，這些內容就不一定還在。Skill 保存的則是做事方法，不管你在哪個專案、哪個對話，只要任務符合，就能再次使用。

兩者也可以一起用。你可以在專案裡放品牌指南和受眾資料，再用 skill 保存寫貼文的流程。這樣一來，Claude 既知道「這次工作是為誰做」，也知道「這類工作要怎麼做」。

用幾個判別問題做決定

不用死背規則。遇到一項工作時，依序問自己下面幾個問題，通常就能看出合適的工具。

  • 這件事我做過不只一次嗎？如果只做一次，完成後就不會再用到，直接打一段提示詞通常最省事。Skill 的價值，來自它會被反覆使用。
  • 我是不是每次都在重貼同一套步驟或規則？如果你一直複製同一段要求，那就是把它抽出來存成 skill 的訊號。這能減少遺漏，也讓每次的做法更一致。
  • 這套做法換到別的專案、別的地方還成立嗎？如果成立，適合做成 skill；如果它只依賴某一批特定資料，就比較像專案要處理的問題。
  • 卡住我的，是「做法沒講清楚」，還是「資料拿不到」？前者適合用 skill，後者可能需要專案或 connector。
  • 我要的是「照著做」，還是「接上某個工具」？如果你要 Claude 依照固定方法完成任務，選 skill；如果你要它讀寫某項外部服務，選 connector。

其中最關鍵的兩個判準是會不會重複與步驟是否固定。兩者都回答「是」，skill 通常就是合適的選擇。

有些情況，規則會翻轉

即使某項工作看起來很適合整理成 skill，也要留意下面幾種反例。它們會讓原本的判斷改變。

只做過一次：即使步驟很固定，只跑一次的任務也不一定需要 skill。花時間把它整理成檔案，省下的可能只有未來一次重新輸入提示詞的時間，通常不划算。

做法還在改：如果你每次執行都在調整步驟，表示這套方法還沒有定型。現在就固化，之後可能得不斷回頭修改 skill。等做法穩定，再把它存起來會比較合適。

結果取決於特定資料：如果產出好不好，關鍵在於 Claude 有沒有讀到你的品牌指南，那要處理的是專案。Skill 可以保存做法，但不會自動提供只有某個工作情境才有的檔案。

需要 Claude 操作外部工具：如果任務是寄信、排貼文或查資料庫，問題不只是「要怎麼做」，還包括「能不能連到那個服務」。這是 connector 的工作；skill 只負責教 Claude 怎麼做，不負責打通外部管道。

只是微調一小段文字：把一句話改得更順、替標題換個說法，這種當下就結束的請求，直接打一段提示詞最省事，沒有必要為它建立 skill。

把判準變成一個可立即使用的規則

選工具時，先看三件事：重複性——這件事會不會一直做；一致性——你是否在意每次都遵守相同的做法；跨專案——這套方法換到別的工作情境是否仍然適用。

三者都成立，就做成 skill；問題只有背景資料，就開專案；只做一次或做法還在摸索，就直接打一段提示詞；需要讀寫外部服務，就使用 connector。記住：專案跟著場合走，skill 跟著你走。

有了這套判準，你就能先判斷工具，再開始動手，不必每次都從頭猜。下一節會進入實作：從 GitHub 取得一個現成的開源 skill，裝進 Claude，並用兩種方式觸發它。
