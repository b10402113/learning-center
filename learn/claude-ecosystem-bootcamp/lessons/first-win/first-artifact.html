第一個 Artifact：用一句話讓 Claude 做出可互動的工具

Step 3/3 · 第一次對話與第一個 Artifact

學習目標

能寫出一個 artifact prompt，讓 Claude 在側邊面板生出可互動、可分享的工具。

前言：有些東西，聊天框裝不下

上一節你已經很會跟 Claude 講話了。但聊到一個程度，你會碰到對話框的天花板：答案跟聊天紀錄混在一起，滑幾下就找不到；而且它只能讀，你沒辦法按、沒辦法輸入數字看結果。偏偏很多你在工作上真正想要的東西，是「可以操作的」而不是「可以讀的」。

想像一個很具體的需求：你想算清楚「如果我買一間 1,200 萬的房子，頭期款付兩成、貸款利率 2.2%、分 30 年還，每個月要繳多少、總共要付多少利息」。用 Excel 從零拉公式、排版、再畫一張攤還曲線圖，認真做大概要 30 到 60 分鐘，而且這種一次性小工具，做完通常也就用這麼一次。這種時刻，就是讓 Claude 的 artifact 上場的時候。你要它做的，是直接做出一個能用的東西。

Artifact 是什麼：Claude 替你動工的那個面板

最直覺的說法是這樣：對話框是你跟 Claude 講話的地方，artifact 是它替你動工的地方。當你請它做一個工具、一份文件、一張圖表，它不會把成品塞在密密麻麻的文字訊息裡，而是在對話旁邊開一個獨立的面板，把做出來的東西放在那裡。那份成品通常是獨立的一段 HTML 與 CSS，所以它真的有介面、真的能互動、真的會即時更新。

這也是 artifact 跟一般回覆最根本的不同。一般回覆是一段文字，你看完就過去了；artifact 是一個可以反覆使用、可以下載、可以分享的實體。它可能是下列這幾種型態：

型態內容
文件一份排版好的報告、企劃或說明書
程式碼一段可以直接拿去跑的程式
網頁一個有版面的頁面
互動應用像計算機、儀表板這種可以輸入、可以操作的小工具
視覺圖表、圖示、流程圖這類把資料畫出來的東西
電子書把一系列內容整理成可翻閱的形式

我們先從最實用、最有感的一種開始：互動應用。

實作：一個房貸計算機

回到前面那個房貸需求。你要下的 prompt 是「build a mortgage calculator（做一個房貸計算機）」，但就像上一節學到的，光這樣講還不夠。真正好用的寫法是把它要的輸入和輸出講清楚。以這個例子來說：

類別要交代的內容
輸入欄位房價、頭期款百分比、貸款利率、貸款年限
輸出結果每月還款金額、總利息、攤還曲線圖
額外需求加上房屋稅的估算

把這些寫進 prompt 之後，用 Sonnet 4.6、把 effort 設在 medium 就可以送出。之所以用 medium 而不是最高級，是因為做這個計算機的邏輯並不複雜，中等投入就足以把公式和介面都做對；把 effort 開到最大只是讓你多等，不會讓成品好多少。

它會先畫在對話裡，再變成 artifact

送出之後，你可能會注意到一件事：Claude 不會立刻跳到側邊面板，而是先在對話裡把這個計算機「內嵌」畫出來給你看。這是比較新的功能，叫做 inline visualizer（對話內視覺化），意思是它先在對話串裡直接渲染一個看得見、可以試按的版本，讓你馬上知道自己要的是不是這個樣子。

如果你看了覺得方向對，想把它變成一個正式、獨立、可以下載的成品，只要接著說一句：「regenerate this as an artifact」（把這個重新做成一個 artifact）。它就會把剛剛那個內嵌版本，轉換成側邊面板裡的獨立 artifact。從這一刻起，它有了自己的位置，不再跟對話紀錄混在一起。

這個「先內嵌、再轉 artifact」的節奏其實很好用：內嵌版讓你低成本地快速確認方向，覺得不對就繼續調整 prompt，不用一開始就生成正式成品；確認對了，再一句話升級成 artifact。你也可以反過來，一開始就明確說「做成一個 artifact」，端看你想要哪種節奏。

做出來之後：下載與分享

artifact 做好之後，有兩件很實用的事可以做。

第一是下載。你可以把這個 artifact 存成 HTML 檔帶走，放到自己的電腦、丟進專案資料夾，或之後再打開來用。等於你真的「拿到」了這個工具，而不是只能在 Claude 裡看。

第二是發布與分享。你可以把 artifact 發布（publish），系統會產生一條可以分享的連結，你就能傳給同事或朋友，讓他們也在瀏覽器裡使用這個工具。用完之後，如果不想再讓它公開，可以再執行取消發布（unpublish），連結就失效，artifact 又回到只有你自己看得到的私人狀態。要不要公開、什麼時候收回，都握在你手上。

寫 artifact prompt 的公式

把房貸計算機這個例子抽掉具體內容，你會得到一個可以重複套用的寫法。一個好的 artifact prompt，基本上就是回答三個問題：

  1. 是什麼？先講清楚你要做的是什麼東西：一個計算機、一張圖表、一份文件，還是一個網頁。
  2. 輸入什麼？使用者要能填哪些欄位、按哪些按鈕。這決定了它的互動性。
  3. 輸出什麼？它要算出什麼、畫出什麼、顯示成什麼樣子。

以房貸計算機為例，對應起來就是：它是一個計算機；輸入房價、頭期款百分比、利率、年限；輸出每月還款、總利息、攤還圖，再加一個房屋稅估算。你把這三格填滿，Claude 就不太需要猜，做出來的東西也會更接近你心裡想的。

還有一個小提醒：artifact 和你上一節玩過的「對話內視覺化」雖然長得像，但層級不同。對話裡的視覺化是為了讓你「當下看一眼」，而 artifact 是為了讓你「留下來、反覆用、分享出去」。當你發現某個東西你不想只用一次、而是想一直留著，那就值得把它做成 artifact。

小結

對話是講話的地方，artifact 是動工的地方。當你要的是一個能操作、能下載、能分享的工具，就請 Claude 做一個 artifact。寫 prompt 時把三件事講清楚：它要是什麼、輸入有哪些欄位、輸出要顯示什麼。以房貸計算機為例，輸入房價、頭期款百分比、利率與年限，輸出每月還款、總利息與攤還圖，再補上房屋稅估算。Claude 會先在對話裡內嵌畫出來讓你確認，你滿意後說一句「regenerate this as an artifact」，它就變成側邊面板裡的獨立成品；之後還能下載成 HTML，或發布取得分享連結、再用取消發布收回。

恭喜你，這個節點的最後一步完成了。你現在手上有兩個具體的成果：一次把 prompt、語音、搜尋、看圖、延伸思考都用上的真實對話，以及一個真的能按、能算的 artifact。這兩個能力會一直跟著你。後面不論是建專案、接工具還是寫自動化，起點都是「把需求講清楚，然後讓 Claude 做出東西」。接下來，我們要讓這些成果留下來、重複使用。
