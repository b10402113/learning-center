Euler 角度與旋轉順序

three-js / transforms / step 3 — 約 10 分鐘

Learning goal

理解 rotation 是 Euler 弧度，能轉換度數並用 reorder 修正旋轉順序。

Lesson

上一節提到 rotation 是 Euler（歐拉角），不是 Vector3。這不是 cosmetic 差異——它帶來了三個至關重要的實際影響，不理解這些你遲早會在旋轉上踩坑。

1. 弧度：Three.js 的原生語言

Three.js 的 rotation 三個分量全是弧度（radians），不是角度（degrees）。弧度的定義是：

Math.PI = 180°   （半圈）
Math.PI * 2 = 360°  （完整一圈）
Math.PI / 2 = 90°   （四分之一圈）

大多數人寫角度比較直覺，所以 Three.js 提供了一個轉換函式：

import { MathUtils } from 'three';

mesh.rotation.y = MathUtils.degToRad(45);  // 45° → Math.PI / 4

MathUtils.degToRad() 把角度數字乘以 π / 180，讓你用熟悉的度數寫，又能正確傳給 Three.js。這是最常見的轉換，務必記住。

2. 旋轉順序：XYZ 不是直覺上那個順序

你可能以為 rotation.x、rotation.y、rotation.z 三個角度是「依照你賦值的順序」生效。不是。Euler 有一個 internal 預設順序：XYZ。這意味著 Three.js 永遠先繞 X 轉，再繞 Y 轉，最後繞 Z 轉，不管你設定的時間順序。

為什麼這很重要？因為旋轉是有方向性的——同一個物件，先繞 X 轉 90 度再繞 Y 轉 45 度，跟先繞 Y 轉 45 度再繞 X 轉 90 度，最終朝向完全不同。

實驗看看：

// 這兩個結果不同！
mesh.rotation.x = MathUtils.degToRad(90);
mesh.rotation.y = MathUtils.degToRad(45);

// 等效於這段代碼（XYZ 順序）
// Three.js 先套 X 90°，再套 Y 45°
// 不是先 Y 再 X

在預設 XYZ 順序下，即便你把 Y 寫在前面、X 寫在後面，Three.js 還是會先套 X。所以 rotation.y 的「行為」會受到 rotation.x 的值影響。這就是所謂的 Euler coupling（歐拉角耦合）。

3. 用 reorder() 修正旋轉順序

當默認 XYZ 順序給出奇怪的結果時，可以用 .reorder() 改變 Euler 角的應用順序：

mesh.rotation.order = 'YXZ'; // 先套 Y，再 X，最後 Z
mesh.rotation.set(
  MathUtils.degToRad(45),  // X
  MathUtils.degToRad(90),  // Y
  0                          // Z
);

另一個寫法是直接在物件上設定：

mesh.rotation.reorder('YXZ');

最常見的調整場景：你想要物件「先繞著自己（Y 軸）轉 360 度，再輕微傾斜（X 軸）」。預設 XYZ 下，Y 的轉動會被 X 的傾斜「吃掉」。改成 YXZ 就正常了。

實用判斷法：當旋轉結果看起來「怪怪的」、好像被某個角度干擾了，第一時間就懷疑是 Euler 順序問題，先試試 .reorder()。

Key takeaways

  • rotation 是 Euler 角，三軸全是弧度。
  • MathUtils.degToRad(角度) 把度數轉成弧度。
  • 預設旋轉順序是 XYZ——Three.js 永遠先套 X 再套 Y 再套 Z。
  • Euler coupling：改變一個軸的值會影響其他軸的視覺結果。
  • 用 .reorder('YXZ') 等方法改變順序，修正奇怪的旋轉。
