實戰：用 Group 組織 die/stack 場景

能將場景中的多個物件用 Group 分層組織，並理解層級結構對後續動畫與互動的影響。

IC 編輯器的場景結構

你的最終目標是打造一個 3D IC 可視化編輯器。在這個編輯器裡，場景會包含多個 stack，每個 stack 裡面又有多個 die。這種「stack 包 die」的結構，天然適合用 Group 來分層。

scene
  └─ stackGroup（一個 stack）
      ├─ die_0
      ├─ die_1
      └─ die_2
  └─ stackGroup（另一個 stack）
      ├─ die_0
      └─ die_1

每個 stack 是一個 Group，每個 die 是一個 mesh。移動 stackGroup，整疊 die 跟著動；移動單個 die，只有它自己動。

用程式碼建立 stack 結構

建立一個包含三個 die 的 stack，可以這樣寫：

const stackGroup = new THREE.Group();
scene.add(stackGroup);

const dieHeight = 0.5;
for (let i = 0; i < 3; i++) {
  const die = new THREE.Mesh(geometry, material);
  die.position.y = i * dieHeight;  // 每個 die 往上疊
  stackGroup.add(die);
}

這裡的 die.position.y 是相對於 stackGroup 的本地座標。第一個 die 在 y = 0，第二個在 y = 0.5，第三個在 y = 1.0。它們會整齊地往上疊。

為什麼不把所有 die 直接放進 Scene？

如果 200 個 die 全部直接掛在 Scene 下面，會發生什麼事？

  • 移動某個 stack 時，必須手動更新這個 stack 裡所有 die 的位置。
  • 做動畫時，想讓整疊 die 一起擺動，必須逐個更新。
  • 做互動時，想知道「使用者選了哪一堆」，必須自己遍歷所有 die 檢查位置。

有了 Group，這些問題都解決了：移動 stackGroup 就整疊移動，動畫只要對 stackGroup 做，互動時直接檢查被點擊的 stackGroup。

層級結構決定了後續擴充性

需求 沒有 Group 有 Group
移動整疊 die 手動更新每個 die 移動 stackGroup 即可
整疊旋轉 逐個計算新位置 旋轉 stackGroup 即可
點擊選中一整疊 遍歷所有 die 比對位置 直接判斷被點擊的 stackGroup
整疊隱藏 逐個設 visible = false 設 stackGroup.visible = false

巢狀 Group 的實戰價值

Group 裡面可以再放 Group，這在 IC 編輯器裡非常實用。例如：你可以把「stackGroup」再包進一個「waferGroup」，代表整個晶圓。移動 waferGroup，所有 stack 一起動；移動單個 stackGroup，只有那疊 die 動。

scene
  └─ waferGroup
      ├─ stackGroup_A
      │   ├─ die_0
      │   └─ die_1
      └─ stackGroup_B
          ├─ die_0
          └─ die_1

這種分層思維是 Three.js 場景管理的核心。一旦你習慣用 Group 來對應真實世界的「容器—內容」關係，場景就會變得直覺又好維護。
