完整渲染迴圈與 controls.update()

能寫出包含 controls.update()、影格獨立動畫與 renderer.render() 的完整渲染迴圈。

把前幾課拼起來

我們已經有了三塊拼圖：

  • requestAnimationFrame：預約下一幀，讓迴圈持續跑。
  • THREE.Clock：提供 delta，讓動畫影格率獨立。
  • controls.update()：讓 OrbitControls 的 damping 和 autoRotate 生效。

現在把它們組合成一個完整的渲染迴圈。

完整程式碼

const clock = new THREE.Clock();

function animate() {
  requestAnimationFrame(animate);  // 1. 預約下一幀

  const delta = clock.getDelta();  // 2. 取得影格時間差

  // 3. 更新控制器（damping / autoRotate 需要每幀呼叫）
  controls.update();

  // 4. 影格獨立動畫
  cube.rotation.x += 0.5 * delta;
  cube.rotation.y += 0.3 * delta;

  // 5. 渲染
  renderer.render(scene, camera);
}

animate();  // 啟動

這個迴圈就是所有 Three.js 應用的心臟。從現在起，幾乎每個專案都會看到它。

順序很重要

迴圈裡的步驟順序不是隨便排的：

  1. 預約下一幀：放在最前面，確保即使後面出錯，迴圈也不會意外中斷。
  2. 取得 delta：在更新動畫之前取得，才能正確反映這一幀的時間差。
  3. 更新控制器：controls.update() 必須在 renderer.render() 之前呼叫，否則 damping 會延遲一幀才生效。
  4. 更新動畫：用 delta 調整物體狀態。
  5. 渲染：最後才把場景算成畫面。

什麼時候才需要 controls.update()？

OrbitControls 有三種常見設定，決定了你是否需要每幀呼叫 controls.update()：

設定 需要 update()？ 原因
無 damping、無 autoRotate 否 控制器的狀態在使用者操作時已經即時更新，不需要每幀重算
啟用 damping 是 放開滑鼠後攝影機還會滑行，滑行過程必須每幀微調
啟用 autoRotate 是 自動旋轉必須每幀累加角度，否則場景不會動

最簡單的做法：永遠在迴圈裡呼叫 controls.update()。即使當前設定不需要，多呼叫一次也不會有副作用，卻能避免之後加了 damping 或 autoRotate 時忘記補這一行。

零延遲的秘訣

這個節點的目標是「零延遲 render loop」。所謂零延遲，不是指每幀跑得飛快，而是指畫面永遠即時反映狀態變化：

  • 拖曳放開後，damping 滑行平滑跟上——因為 controls.update() 每幀都在跑。
  • 方塊旋轉速度在所有裝置上一致——因為乘了 delta。
  • 畫面不卡頓、不跳幀——因為 requestAnimationFrame 與螢幕刷新率同步。

做到這三點，你的 Three.js 應用就會看起來「跟手」，用起來像原生程式。

之後的擴充點

這個基本迴圈是之後所有功能的骨架。未來你會陸續在迴圈裡加入：

  • 物理引擎的 world.step()
  • 動畫混合器的 mixer.update(delta)
  • 自訂的粒子系統更新
  • 資料驅動的物件狀態同步

但不變的核心永遠是：預約下一幀 → 取得 delta → 更新控制器 → 更新動畫 → 渲染。
