空間操作：距離與鄰近偵測

Three.js 座標系統 · Step 3/3
在 3D IC 編輯器裡，你不需要手動計算畢氏定理。
Vector3 已經把距離公式打包好了——你只要叫它「算距離」就行。

觀察：物件之間有多遠？

假設場景裡有一個 die 和一個攝影機，你想知道它們之間的距離。在純數學裡，這要套用畢氏定理：

// 自己算距離（別這樣做）
const dx = a.x - b.x
const dy = a.y - b.y
const dz = a.z - b.z
const dist = Math.sqrt(dx*dx + dy*dy + dz*dz)

Three.js 的 Vector3 已經把這個公式包進 distanceTo() 方法裡：

// Three.js 幫你算（這樣就對了）
const dist = die.position.distanceTo(camera.position)

當你在 IC 編輯器中判斷「滑鼠游標是否靠近某個 die」，或是「兩個 die 是否靠太近」，就是靠這個距離計算。

理解：copy() 保留位置快照

有時候你需要「記住」某個物件此刻的位置，稍後拿出來比對。如果直接用賦值，兩個變數會指向同一個 Vector3 物件，當物件移動時，你以為保存過的舊位置也跟著變了。

// 錯誤：oldPos 會跟著物件一起動
const oldPos = die.position

// 正確：oldPos 是獨立副本，不受物件移動影響
const oldPos = die.position.clone()

clone() 創造一個全新的 Vector3 副本，與原本的物件互不影響。這是遊戲開發和編輯器中常見的模式：每一幀記錄物件位置，然後跟前一幀比對，計算位移或速度。

理解：distance2() 的效能優勢

Vector3 還提供一個較少人知的方法：distance2()。它的用途跟 distanceTo() 一樣，但回傳的是「距離的平方」，而不是實際距離。

什麼時候用平方版本？當你只需要「比較遠近」，而不需要知道「實際長度」的時候。例如：在 200 個 die 中找出最接近游標的那個。

let nearest = null
let minDist2 = Infinity

for (const die of dies) {
  const d2 = die.position.distance2(mouseVector)
  if (d2 < minDist2) {
    minDist2 = d2
    nearest = die
  }
}

因為 distance2() 省掉了 Math.sqrt() 的開銷，在大規模場景中能有效提升效能。雖然 Three.js 官方文件較常用 distanceTo()，但許多高效能遊戲引擎的底層都是跑平方距離比較。
