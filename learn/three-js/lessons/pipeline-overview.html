三大支柱：Scene、Camera、Renderer

能說出 Scene、Camera、Renderer 各自的角色，並畫出它們之間的資料流。

為什麼需要三個物件？

想像你在拍電影。首先需要一個場景——演員、道具、燈光全部放在裡面。然後需要一台攝影機——決定觀眾從哪個角度、看到多大範圍。最後需要底片或數位感光元件——把鏡頭看到的東西變成一張照片。

Three.js 的結構完全對應這三個角色：

  • Scene（場景）：一個容器，裝進所有可見物件——網格（mesh）、燈光、背景。物件之間有父子關係，父物件移動時子物件跟著動。
  • Camera（攝影機）：決定「從哪裡看」和「看多廣」。沒有攝影機，場景再豐富也看不到。
  • Renderer（渲染器）：把 Scene 和 Camera 的資料算成一張圖片，畫到畫布（canvas）上。

資料流：一幀是怎麼畫出來的？

每一幀的繪製都走同一條管線：

  1. Renderer 讀取 Scene 裡所有物件的位置、材質、燈光。
  2. Renderer 根據 Camera 的位置和視角，計算哪些物件在視野內、該怎麼投影到二維畫面。
  3. Renderer 把計算結果寫進 canvas，變成你看到的那一格畫面。

這個過程每秒重複約 60 次，就形成了動畫。這個重複呼叫 Renderer 的迴圈叫做渲染迴圈（render loop）。

好萊塢片場類比

電影片場 Three.js 負責的工作
場景（set） Scene 裝進所有物件，管理父子階層
攝影機 Camera 決定視角、位置、視野範圍
底片 / 感光元件 Renderer 把場景算成圖片，輸出到 canvas

最小可行結構

一個最精簡的 Three.js 應用程式只需要這三行核心物件：

const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, width / height, 0.1, 1000);
const renderer = new THREE.WebGLRenderer({ canvas });

但這樣只會建立物件，不會畫出任何東西。要讓畫面動起來，還需要把物件放進 Scene、把 Camera 放到正確位置、然後在渲染迴圈裡反覆呼叫 renderer.render(scene, camera)。
