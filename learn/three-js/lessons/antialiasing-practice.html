在程式裡實作抗鋸齒

學會用 setPixelRatio 控制像素密度，並在 WebGLRenderer 開啟 antialias 旗標，寫出正式上線的抗鋸齒設定。

兩行程式碼解決兩種路線

前兩課我們認識了硬體（提高像素密度）和軟體（邊緣柔化）兩種抗鋸齒路線。在 Three.js 裡，它們各自對應一行程式碼：

  • 硬體路線：renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))
  • 軟體路線：在建立渲染器時傳入 antialias: true

把兩者組合起來，就是大多數專案的標準設定。

為什麼要 Math.min(devicePixelRatio, 2)

window.devicePixelRatio 在普通螢幕上是 1，在 Retina 螢幕上是 2，但在某些高密度手機螢幕上可能是 3 甚至 4。

如果直接把 devicePixelRatio 傳進去，在 4K 手機上渲染器會用 4 倍密度去畫——GPU 直接爆量，幀率掉到不能玩，但肉眼根本看不出來差別。所以實務上會用 Math.min(devicePixelRatio, 2) 把上限卡在 2，在畫質和效能之間取得平衡。

完整範例

// 1. 建立渲染器時開啟軟體抗鋸齒
const renderer = new THREE.WebGLRenderer({
  canvas: myCanvas,
  antialias: true
});

// 2. 設定硬體像素密度上限為 2
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

// 3. 別忘了初始尺寸
renderer.setSize(window.innerWidth, window.innerHeight);

這三行通常放在你的初始化函式裡，在建立 Scene 和 Camera 之後、開始渲染迴圈之前。

注意：antialias 只對初始設定生效

antialias: true 必須在建立 WebGLRenderer 時就傳入。如果你之後才想開啟，必須重新建立一個新的渲染器。而 setPixelRatio() 則可以隨時呼叫，不需要重建。

什麼時候可以關掉 antialias

在少數情境下，你會想關掉軟體 AA：

  • 你已經用了很高的 pixelRatio（例如 2），鋸齒已經夠細，不需要再柔化。
  • 你在做後製效果（post-processing），有些後製流程會自己處理反鋸齒。
  • 你正在測量效能，想單獨比較 AA 的消耗。

但對大多數應用，尤其是像 IC 編輯器這種需要清晰邊緣的工具，開著 antialias: true 是比較安全的選擇。
