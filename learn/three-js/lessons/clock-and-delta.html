THREE.Clock 與影格獨立時間

理解 THREE.Clock 如何提供 getDelta() 與 getElapsedTime()，並用 delta 實現影格率獨立的動畫。

一個陷阱

我們在上一課建立的渲染迴圈裡寫了：

cube.rotation.x += 0.01;

這段程式碼看起來沒問題，但其實藏著一個陷阱：它假設每一幀的時間間隔是固定不變的。事實上，在 60Hz 螢幕上每幀約 16.67 毫秒，但 30Hz 的舊手機可能只有 33.33 毫秒，而效能低落時甚至會掉到 50 毫秒。

結果就是：同一台裝置上動畫速度一致，但換到不同裝置上就變得忽快忽慢。在 120Hz 螢幕上，同樣的 += 0.01 會讓方塊旋轉速度快一倍——因為它每秒跑了 120 次，而不是 60 次。

影格率獨立（frame-rate independent）

我們要的是一種動畫方式，讓物體的真實移動速率不隨裝置的影格率而改變。無論你在 30Hz 的平板、60Hz 的桌機、還是 120Hz 的高刷螢幕上，物體的移動速度都一樣。

做法很簡單：用「自從上一幀過了多少時間」來調整每幀的增量。時間間隔大就多移一點，時間間隔小就少移一點，總速率不變。

這個「上一幀到這一幀的時間差」叫做 delta time（影格時間差），在 Three.js 裡由 THREE.Clock 類別提供。

THREE.Clock 是什麼？

THREE.Clock 是 Three.js 內建的計時器工具。你建立一個 Clock 物件後，它會從建立的瞬間開始計時，並提供兩個方法：

方法 回傳值 用途
clock.getDelta() 自從上次呼叫後經過的秒數（浮點數） 取得影格時間差，用於計算每幀增量
clock.getElapsedTime() 從 Clock 建立以來的總經過秒數 用於週期性動畫（sin/cos）的時間參數 
const clock = new THREE.Clock();

function animate() {
  requestAnimationFrame(animate);

  const delta = clock.getDelta();  // 上一幀到這一幀的時間差（秒）

  cube.rotation.x += 0.5 * delta;  // 每秒旋轉 0.5 弧度，不受影格率影響

  renderer.render(scene, camera);
}

無論裝置跑 30fps 還是 120fps，delta 會自動調整大小，所以 0.5 * delta 累積起來每秒永遠等於 0.5 弧度。

getDelta() vs getElapsedTime()

兩個方法適用不同場景：

  • getDelta()：適合持續性的運動——旋轉、平移、沿路徑前進。你把 delta 乘上一個速率，物體就以那個速率移動，不隨裝置而異。
  • getElapsedTime()：適合週期性的動畫——用 Math.sin(time) 做上下振盪、用 Math.cos(time) 做圓周運動。時間自然增長，不需要手動累計。

注意：呼叫 getDelta() 時 Clock 內部的計時器會重設；呼叫 getElapsedTime() 則不會。兩者不要混在同一幀裡各自想當然——要知道它們各自影響 Clock 的內部狀態。

為什麼不手算 delta？

你也可以自己手算：

let prevTime = performance.now();

function animate() {
  requestAnimationFrame(animate);

  const now = performance.now();
  const delta = (now - prevTime) / 1000;
  prevTime = now;

  cube.rotation.x += 0.5 * delta;
  renderer.render(scene, camera);
}

這和 THREE.Clock 的效果完全相同。Clock 只是把這套邏輯包裝好了，讓你少寫幾行，也不會忘記除以 1000（performance.now 回傳的是毫秒）。

常見誤區

cube.rotation.x += 0.01; // 沒有乘 delta — 不是影格率獨立

這是最常見的錯誤。在效能好的裝置上跑得順，換到舊手機就突然慢了一半。只要涉及「持續改變數值」，都應該乘上 delta。

cube.rotation.x += 0.5 * delta; // 影格率獨立 ✓
