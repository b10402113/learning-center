OrthographicCamera 參數與寬高比校正

理解 OrthographicCamera 的參數意義、無透視特性，以及如何用寬高比校正避免畫面拉伸。

沒有透視的攝影機

OrthographicCamera（正交攝影機）和 PerspectiveCamera 最大的差別是：物體大小不會隨距離改變。不管物體在遠處還是近處，它在畫面裡都一樣大。

這讓正交攝影機非常適合技術視覺化、等距遊戲（isometric game）、UI 疊圖，以及——對我們最重要的——IC 編輯器。在編輯器裡，你不希望 die 因為位置遠近而看起來大小不同，否則會干擾你判斷尺寸。

六個參數，不是四個

OrthographicCamera 不用 FOV 和 aspect，而是用「距離值」來定義可視範圍：

const camera = new THREE.OrthographicCamera(left, right, top, bottom, near, far);
參數意義
left可視範圍的左邊界（從相機中心算起的距離）
right可視範圍的右邊界
top可視範圍的上邊界
bottom可視範圍的下邊界
near近裁剪面（和 PerspectiveCamera 一樣）
far遠裁剪面（和 PerspectiveCamera 一樣）

這些參數定義的是一個「可視盒子」（frustum box）：只有在這個盒子內的物體才會被渲染。

為什麼 -1, 1, -1, 1 會拉伸？

很多人第一次寫 OrthographicCamera 會這樣寫：

const camera = new THREE.OrthographicCamera(-1, 1, -1, -1, 0.1, 1000);

這定義了一個「正方形」可視盒子（寬 2、高 2）。但你的螢幕是矩形（例如 1920×1080），所以 Three.js 會把這個正方形內容「拉伸」到整個矩形螢幕上——圓變橢圓，正方形變長方形。

寬高比校正

解法：把 left 和 right 乘以螢幕的寬高比，讓可視盒子也變成矩形：

const aspect = window.innerWidth / window.innerHeight;
const camera = new THREE.OrthographicCamera(
  -1 * aspect, 1 * aspect, 1, -1, 0.1, 1000
);

這樣可視盒子的形狀就會匹配螢幕比例，物體就不會被拉伸了。當視窗大小改變時，同樣需要重新計算並更新這些值。

什麼時候該用正交？

選擇攝影機的核心問題是：「我希望使用者怎麼感知這個場景？」

  • PerspectiveCamera：適合遊戲、展示、任何需要「身臨其境」感的場景。
  • OrthographicCamera：適合編輯器、CAD、等距視圖、任何需要「精確測量尺寸」的場景。

對 IC 編輯器來說，正交攝影機是首選——因為你希望 die 的視覺大小等於它的實際尺寸，不會因為在場景中放遠一點就看起來比較小。
