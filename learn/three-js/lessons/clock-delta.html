用 Clock + delta 做 frame-rate independent 動畫

用 THREE.Clock 的 getElapsedTime 與 delta 時間，寫出在不同幀率下速度一致的動畫。

問題：為什麼 += 0.01 不夠？

上一課的寫法：cube.rotation.x += 0.01。看起來能用，但有一個隱藏問題：

  • 60 Hz 螢幕：每秒執行 60 次 → 每秒轉 0.6 弧度
  • 144 Hz 螢幕：每秒執行 144 次 → 每秒轉 1.44 弧度
  • 30 FPS 的舊筆電：每秒執行 30 次 → 每秒轉 0.3 弧度

同樣一段程式碼，在高速螢幕上轉得快，在慢速螢幕上轉得慢。這在遊戲裡叫做「幀率依賴（frame-rate dependent）」——動畫速度被硬體綁架了。

解法：delta 時間

不要每幀加固定值，而是乘上「離上幀過了多久」：

const speed = 2; // 每秒 2 弧度
cube.rotation.x += speed * delta;

這樣一來：

  • 60 FPS：每幀約 0.0167 秒 → 每幀轉 0.033 弧度 → 每秒 2 弧度
  • 144 FPS：每幀約 0.0069 秒 → 每幀轉 0.014 弧度 → 每秒 2 弧度
  • 30 FPS：每幀約 0.0333 秒 → 每幀轉 0.067 弧度 → 每秒 2 弧度

不管幀率多少，每秒轉的弧度都一樣。這就是「frame-rate independent」。

THREE.Clock 的用法

Three.js 內建 THREE.Clock 幫你算時間。它有兩個常用方法：

getElapsedTime()
從 Clock 建立後經過的總秒數（浮點數）。適合做 sin/cos 振盪。
getDelta()
離上一次呼叫 getDelta() 過了幾秒。適合做 frame-rate independent 動畫。

注意：getDelta() 會更新內部狀態，所以每幀只能呼叫一次。

完整程式碼：frame-rate independent 旋轉

const clock = new THREE.Clock();
const speed = 2; // 每秒 2 弧度

function animate() {
  requestAnimationFrame(animate);

  const delta = clock.getDelta();        // 離上幀過了幾秒
  cube.rotation.x += speed * delta;      // 乘上 delta

  renderer.render(scene, camera);
}
animate();

不管使用者的螢幕是 60Hz 還是 144Hz，方塊每秒都轉 2 弧度。

手動算 delta 的寫法

如果你不想用 Clock，也可以自己記錄時間：

let previousTime = performance.now();

function animate(currentTime) {
  requestAnimationFrame(animate);

  const delta = (currentTime - previousTime) / 1000; // 轉成秒
  previousTime = currentTime;

  cube.rotation.x += speed * delta;

  renderer.render(scene, camera);
}
requestAnimationFrame(animate);

requestAnimationFrame 會把當前時間（毫秒）傳給回呼函式。用目前時間減去上次時間，就是 delta。除以 1000 是為了從毫秒轉成秒。

什麼時候用 getElapsedTime，什麼時候用 getDelta？

  • getDelta()：用在「每幀累加」的動畫，例如移動、旋轉。重點是「速度一致」。
  • getElapsedTime()：用在「跟總時間綁定」的動畫，例如 sin/cos 振盪。重點是「知道現在是第幾秒」。
