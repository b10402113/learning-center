什麼是 Three.js

理解 Three.js 是什麼、GPU/WebGL/Three.js 的技術棧，以及學習前的預備知識與文件閱讀習慣。

從一個問題開始

你想在瀏覽器裡畫出 3D 圖形，但不想直接面對幾百行 WebGL 繪圖指令。這就是 Three.js 存在的理由：它是一個高階 JavaScript API，幫你把低階 GPU 繪圖包裝成直覺的物件操作。

技術棧：GPU → WebGL → Three.js

瀏覽器裡的 3D 圖形，底層是這樣一層層疊上來的：

  1. GPU：顯示卡上的特化硬體，擅長同時做幾千個簡單計算（例如「這個像素是什麼顏色」）。
  2. WebGL：瀏覽器內建的低階 API，讓你用 JavaScript 直接控制 GPU。缺點是：畫一個三角形就要寫幾十行程式碼。
  3. Three.js：建在 WebGL 之上的高階庫。你寫 new THREE.Mesh(geometry, material)，Three.js 幫你搞定背後的 WebGL 細節。

你可以把 Three.js 想成「WebGL 的語法糖」——它沒有拿走任何彈性，只是讓你用更少的程式碼做更多的事。

你需要什麼預備知識？

好消息：門檻比你想像的低。

  • JavaScript 基礎：變數、物件、迴圈、函式就夠了。這門課大多在叫 Three.js API，不會玩進階 JS 技巧。
  • 基本數學：會一點就好。Three.js 幫你處理大多數數學，你只要知道「座標」和「角度」的概念。
  • 工具：Chrome 瀏覽器 + VS Code。Blender 只在一個單元用到，而且老師有提供現成模型。

講師 Jesse 自己就是從 Python / 資料科學背景轉過來的，所以非傳統程式背景完全不是問題。

學習策略：從文件與範例出發

這門課的官方說法是：「學 Three.js 的最佳實踐就是讀文件」。threejs.org 的文件雖然不是最精美的，但它附帶大量原生範例，而且你可以直接查看它們的原始碼。

推薦的學習迴圈：

  1. 找一個你覺得酷的範例。
  2. 打開它的原始碼。
  3. 改改看，然後故意弄壞它，觀察會發生什麼事。

這就是在本課會反覆使用的「Hack the Example」方法——先讓它跑起來，再慢慢理解它。

第一個心靈目標

這門課的最終目標是做一個個人化的 3D 作品集（第三人稱遊戲風格，含 3D 角色）。Jesse 用這個作品集在六個月內拿到工作。你先不用想到那麼遠，只要記得：每一個你寫的程式碼，都是為了把一個 3D 物件放上螢幕。
