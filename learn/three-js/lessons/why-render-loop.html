為什麼需要渲染迴圈

理解為什麼單次渲染無法呈現動畫與互動，以及渲染迴圈在 Three.js 應用中的角色。

一張靜止的畫面

到目前為止，你的 Three.js 應用程式只呼叫了一次 renderer.render(scene, camera)。這一呼叫就像快門閃了一下——畫面確實出現了，但從此停住不動。方塊靜靜掛在原地，不會旋轉、不會回應滑鼠拖曳、不會跟著視窗縮放。

這不是 bug，是設計如此。renderer.render() 就是「把這一瞬間的場景算成一張圖片」，它不知道時間在流動，也不會在没人叫它的時候自己重畫。

動畫是怎麼回事？

你在電影、遊戲裡看到的動畫，其實是快速播放的一連串靜止畫面。每一幀都和前一張微小幅不一樣——方塊轉了 0.5 度、角色往前走了一小步。當這些畫面以每秒 60 張的速度閃過，大腦就會把它們連成流暢的動作。

所以要讓 Three.js 動起來，你需要做的是同一件事：不斷改變場景狀態，然後重新畫一張。這個「改變→重畫」的重複過程，就是渲染迴圈（render loop）。

不只是動畫

渲染迴圈不只服務動畫。任何需要「持續更新畫面」的功能都依賴它：

  • 視角控制：OrbitControls 啟用 damping（阻尼）時，放開滑鼠後攝影機還會慢慢滑行停下。這個滑行必須每幀更新。
  • 自動旋轉：autoRotate 讓場景自己轉，同樣需要每幀微調攝影機角度。
  • 資料驅動變化：感測器數值變化、網路傳來新資料、任何隨時間改變的狀態，都要在畫面上反映出來。

換句話說，只要你的應用不是「一張截圖」，就需要渲染迴圈。

黏土動畫模型

理解渲染迴圈最好的類比是做黏土動畫：先捏一個姿勢、拍一張照片；再微微調整姿勢、再拍一張；重複幾百次之後，把照片連起來播，黏土就活了。

在程式裡，這個迴圈寫起來像這樣：

function animate() {
  // 1. 做動作：改變場景狀態
  cube.rotation.x += 0.01;

  // 2. 拍照片：重新渲染
  renderer.render(scene, camera);
}

但現在還有個問題：這個 animate() 函式只會跑一次。要讓它持續跑下去，你得想辦法讓瀏覽器在每一幀都重新呼叫它。這就是下一課的主角——requestAnimationFrame。
