視窗調整的標準做法

學會用 resize 事件更新渲染器尺寸與攝影機比例，讓視窗放大縮小時畫面不變形。

為什麼畫面不會跟著視窗變大

你第一次建立 WebGLRenderer 時，給了它一個寬度和高度。從那一刻起，渲染器就認定了這個尺寸——不管使用者怎麼拉動瀏覽器視窗，它都畫著同一張固定大小的圖片。結果不是畫面被裁切，就是旁邊多出一圈黑邊。

問題出在兩個地方：渲染器不知道新的視窗大小，攝影機也不知道。你必須在視窗改變時，主動告訴它們。

三步更新法

視窗大小改變時，必須依序做三件事，缺一不可：

  1. 更新渲染器尺寸：renderer.setSize(width, height) 告訴渲染器新的畫布大小。
  2. 更新攝影機長寬比：camera.aspect = width / height 告訴攝影機新的畫面比例。
  3. 重算投影矩陣：camera.updateProjectionMatrix() 讓攝影機把新的長寬比套用到 3D 投影計算裡。

很多人忘了第三步。camera.aspt 只是一個數字，改了不會自動生效；一定要呼叫 updateProjectionMatrix()，Three.js 才會根據新數字重新算出物體在畫面上的位置。

放在對的地方：resize 事件

把這三步放進 window.addEventListener('resize', ...) 回呼函式裡，就能確保只在視窗真正改變時才執行，而不是每一幀都跑一遍。

window.addEventListener('resize', () => {
  // 1. 更新渲染器
  renderer.setSize(window.innerWidth, window.innerHeight);

  // 2. 更新攝影機長寬比
  camera.aspect = window.innerWidth / window.innerHeight;

  // 3. 重算投影矩陣
  camera.updateProjectionMatrix();
});

這個模式就是 Three.js 官方範例用的標準做法。記住：改完 aspect，一定要 updateProjectionMatrix()。

什麼時候不該用這個模式

如果你需要「每幀都根據目前視窗大小微調」（例如搭配某些 UI 動畫），可以把尺寸更新放進渲染迴圈裡。但大多數情況下，resize 事件就夠了，而且效能更好。
