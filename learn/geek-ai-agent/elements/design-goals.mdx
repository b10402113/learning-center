# 四大設計目標 (The Four Design Goals)

## Problem Statement

一個「Agent 底座」如果沒有可衡量的設計準則，很容易長成什麼都做、什麼都不精的大雜燴。今天這個團隊想加語音，明天那個部門想要流程畫布，後天又要接一個雲平台的賬號體系。沒有錨點，範圍就擴散，做出來一個無法部署、無法審計、無法解釋的系統。

## Why it matters

四大設計目標是把研究階段的願景翻譯成可測量的設計標準的那一步，也是後面所有文件（需求、技術方案、AI 編程指南的憲法）共同引用的錨。記住這四個字，你隨時能判斷一個新需求該不該進 OryxOS 的範圍。

## How it works

四大目標是四個字，每個字後面都拖著一長串具體承諾。

統一。很多業務 Agent 共享一個底座，通用能力下沉到 OryxOS，一份 Profile YAML 就能拉起一個新 Agent。它的反面是每個 Agent 各建一套，重複建設。

私有。數據完全留在企業內；模型用外部或本地 Ollama/vLLM 都可以，OryxOS 不收集企業數據。這是受監管行業的硬底線。

易接入。標準 Spring Boot 結構，跟 ERP、CRM、CMDB、SSO、監控直接整合，複用 Nacos/Sentinel/SkyWalking/Arthas，工具通過 MCP 或 Spring Bean 接入。落進現有技術棧，而不是要求企業重造環境。

可觀測。Prometheus 指標、結構化 JSON 日誌、健康檢查、Web 儀表盤，出了問題能查、能追、能排障。

這四個詞承接自研究階段的四字願景（統一、私有、易接入、可觀測），到需求文檔變成設計準則，到 AI 編程指南再變成憲法原則的來源。設計目標是「為什麼做這些能力」，五項能力是「具體做什麼」，兩者不是一回事，但互相咬合。

## In plain terms

四個詞就是一句話：所有 Agent 用一個底座（統一），數據不出公司（私有），隨便接進現有系統（易接入），出問題查得到（可觀測）。做任何範圍決定時，拿這四個詞對一遍，對不上的先別做。

## Analogy

四大目標是一家公司的規矩。統一像公司只有一個財務部，不許每個部門自己記賬；私有像公司的賬本和客戶資料只能鎖在自己保險櫃；易接入像公司用標準的辦公軟體，新員工進來不用重新學一套工具；可觀測像每個月有清晰的報表，錢花到哪、事辦到哪都對得上。

## Practical use

在 OryxOS 的需求、技術方案和 AI 編程指南三份文件裡，四大目標是被反覆引用的判據。讀到一個功能提案，用四個詞各問一遍：它服務統一嗎？尊重私有嗎？符合易接入嗎？支持可觀測嗎？四個都答是才進核心範圍，否則放到擴展或社區。

## Questions

### Q1. 四大設計目標是哪四個字？各自對應一條什麼承諾？
A1. 統一（很多業務 Agent 共享一個底座，一份 Profile YAML 拉起新 Agent）、私有（數據完全留在企業內，OryxOS 不收集企業數據）、易接入（標準 Spring Boot 結構，直連 ERP/CRM/CMDB/SSO，MCP 或 Spring Bean 接工具）、可觀測（Prometheus 指標、結構化日誌、健康檢查、Web 儀表盤）。

### Q2. 四大目標和五項核心能力是什麼關係？
A2. 目標回答「為什麼」，是設計準則；能力回答「做什麼」，是具體功能。目標是能力的判據，能力是目標的落地。

### Q3. 拿到一個新功能提案，怎麼用四大目標快速決定它進不進核心範圍？
A3. 四個詞各問一遍：服務統一嗎、尊重私有嗎、符合易接入嗎、支持可觀測嗎。四個都答是才進核心範圍，否則放到擴展或社區。設計目標章節的四條承諾要能逐字對上需求文檔。
