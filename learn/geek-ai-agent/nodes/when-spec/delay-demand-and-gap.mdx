# 延遲投遞的需求與現況缺口

<LearningGoal>
能說明延遲投遞在哪些場景出現、它的精確度與可靠性分級，並指出現有方案（MQ、SDK、獨立服務）共同的邊界缺口。
</LearningGoal>

## Lesson

延遲投遞是在指定時刻把訊息精確送達下游；需求真實、廣泛而長期，但現有做法——中介軟體內建延遲、Redis ZSet SDK、獨立服務嘗試——不是綁死特定基礎設施，就是停留在小規模或已停滯，通用、獨立的延遲投遞服務至今沒有事實標準，這個空缺正是 When 的立足點。
