# OryxOS AI 編程指南

## Learning goal

能用兩階段混合模式（Spec-Kit 主體 + 手動提示詞增量）把需求與技術方案轉成按 user story 拆分的可執行任務。

## Steps

1. [[learn/geek-ai-agent/nodes/oryxos-ai-programming-guide/two-phase-strategy|兩階段混合模式：主體 Spec-Kit、增量手動提示詞]] — 判斷什麼工作用 Spec-Kit、什麼用手動提示詞
2. [[learn/geek-ai-agent/nodes/oryxos-ai-programming-guide/preparation-artifacts|準備階段：constitution、spec、plan 三份 artifact]] — 把既有文件餵成三份可執行 artifact（after step 1）
3. [[learn/geek-ai-agent/nodes/oryxos-ai-programming-guide/split-by-user-story|按 user story 拆解：US-1 → US-2 → (US-3 ∥ US-4) → US-5]] — 依賴驅動的任務拆解與五個 US 的任務類別（after step 2）
4. [[learn/geek-ai-agent/nodes/oryxos-ai-programming-guide/implementation-guardrails|實施護欄：analyze 防漂移與五個易錯點]] — 跨 US 協作動作與跑偏時怎麼修（after step 3）
5. [[learn/geek-ai-agent/nodes/oryxos-ai-programming-guide/increment-phase|增量階段：手動提示詞工作流與 artifact 對接]] — issue → fork → PR 流程與 artifact 對齊（after step 3）

## Lesson

這個節點處理的是「文件都寫好了，然後呢」這一段。OryxOS 的需求文件與技術方案已經把「要什麼」與「怎麼做」講清楚了，但文件不是可執行的東西——它不會自己變成一個能編譯、能跑的系統。AI 編程指南的任務，就是把這兩份文件轉成一組 AI agent 能直接照著做的任務。它的核心策略是一句話：**不要重寫文件，把它們餵給 Spec-Kit**。需求文件進 `/speckit.specify` 變成 5 個 user story，技術方案進 `/speckit.plan` 變成九個模組的實施計畫，設計目標與關鍵決策進 `/speckit.constitution` 變成不可協商的項目憲法。

這裡的關鍵判斷是「按 user story 拆，不按時間拆」。Spec-Kit 的 `/speckit.tasks` 天生就按 user story 組織任務，而 OryxOS 的五個核心能力恰好有清楚的依賴：US-1 對接 LLM 是地基，US-2 的 ReAct 迴圈依賴它；US-3 的 Memory 與 US-4 的 Plugin Tool 都架在 US-2 上、彼此獨立可以並行；US-5 的 Web Service 要等前四個都到位。這條 `US-1 → US-2 → (US-3 ∥ US-4) → US-5` 的鏈，就是整份指南的主幹。

走完之後，你拿到的不是一份「Spec-Kit 教學」，而是一套可複製的判斷：什麼階段用重武器、什麼階段換輕工具、AI 會在哪些地方跑偏、跑偏了拿什麼把它的行為拉回來。
