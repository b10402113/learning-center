# 故障注入與不可收買的判官

<LearningGoal>
能用故障注入設計三個分散式驗收案例，並說出讓判官無法被 AI 收買的具體制度。
</LearningGoal>

## Lesson

把最糟的時刻變成可重複的故障注入測試（殺容器、網路分割、延遲與丟包），用三個案例反覆驗證不變式：不遺失（殺 Master 後從 Redis 恢復且全部投遞）、10 秒接管（為故障到新 Master 開始排程打時間戳）、腦裂與選舉（任何時刻最多一個 Controller 與每個輪一個 Master）。為了不讓 AI 改測試假裝過關，要靠公開 Harness 禁改測試、實作與驗證分離、CI 當外部判官；判官還分快慢兩層，並以關鍵失效模式而非覆蓋率數字來設計驗收。
