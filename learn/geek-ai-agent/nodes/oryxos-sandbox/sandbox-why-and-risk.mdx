# 為什麼 Agent 一定要有沙箱：風險模型與四維隔離

<LearningGoal>
能說出 Agent 情境為什麼不能沿用「信任自己寫的程式」的舊假設，並用檔案系統、網路、程序/系統呼叫、資源四維隔離去拆解任何沙箱要防守的風險面。
</LearningGoal>

## Lesson

Agent 情境顛覆了「信任自己寫的程式」的舊假設——指令是 LLM 在運行時產生的，未經人工審查，可能來自提示注入、模型失誤或多租戶越界；因此沙箱是 Agent 敢不敢做有副作用動作的前提，落腳在五元件的 Environment 上。四維隔離（檔案系統、網路、程序/系統呼叫、資源）是拆解任何沙箱技術的眼鏡：看到一個方案，先問四維各覆蓋到什麼程度、代價多大。
