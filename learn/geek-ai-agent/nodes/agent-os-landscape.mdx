# Agent OS 與 OryxOS 定位

## Learning goal

說清 Agent OS 是什麼、企業為何需要私有可控底座、為何選 Java，以及 OryxOS 的定位、邊界與從單機到分散式的演進路線。

## Steps

1. [[learn/geek-ai-agent/nodes/agent-os-landscape/what-is-agent-os|Agent OS 是什麼：運行時之上的作業系統]] — 定義 Agent OS 與它的五大職責，並與 runtime、編排平台、框架、SaaS 劃清界線
2. [[learn/geek-ai-agent/nodes/agent-os-landscape/open-source-landscape|開源賽局：OpenClaw、Hermes 與它們留下的空白]] — 兩個代表專案的定位與共同空白（after step 1）
3. [[learn/geek-ai-agent/nodes/agent-os-landscape/why-private-base-and-java|為什麼企業要私有底座，又為什麼是 Java]] — 嚴監管四鐵律與「有框架、沒底座」的 Java 缺口（after steps 1–2）
4. [[learn/geek-ai-agent/nodes/agent-os-landscape/oryxos-positioning-and-boundary|OryxOS 的定位、邊界與安全設計]] — 一句話定義、四字願景、runtime 邊界與 day-one 安全（after step 3）
5. [[learn/geek-ai-agent/nodes/agent-os-landscape/single-to-distributed-evolution|從單機到分散式：狀態外置與 Agent 協作的遠景]] — 無狀態實例、狀態外置與跨節點協作（after step 4）

## Lesson

這一節回答一個看似簡單、卻決定整條 OryxOS 學習線的問題：當企業要同時跑很多個 Agent 時，底座該長什麼樣、為什麼非得自己做、又為什麼該用 Java 寫。五個步驟像剝洋蔥一樣往裡走。

第一步先把名詞釘死：Agent OS 不是「更強的 Agent」，而是讓一**群** Agent 在企業裡被管理起來的底座層——它管生命週期、對外渠道、對內接入、統一記憶與工具沙箱，本身不做視覺化編排。第二步看開源賽局：OpenClaw 把個人體驗做到極致、Hermes 往企業方向探路，卻共同留下企業治理、IT 深度整合與 Java 生態三個空白。第三步把「為什麼私有」與「為什麼 Java」綁在一起談：嚴監管企業的四條鐵律把選項收斂到私有可控底座，而 Java 生態有框架、沒底座，正是可以切進去的缺口。第四步落到 OryxOS 身上：一句話定義、四字願景（統一、私有、易接入、可觀測）、做 runtime 不做編排的邊界，以及把安全當第一天設計。第五步把視線拉到未來：從單機走向分散式的關鍵不是多開幾台，而是「實例無狀態、狀態外置」，之後才談得上高可用、水平擴展與更遠的跨節點 Agent 協作。

走完之後，你手上會有一份可以對照自己公司的判斷地圖：哪些流程該留在平台、哪些該沉澱進自建底座，以及這個底座該具備哪幾層能力。
