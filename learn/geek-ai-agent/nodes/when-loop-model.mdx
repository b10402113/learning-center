# When Loop 模型與驗收體系

## Learning goal

能設計 When 的兩次 Loop 跑法、公開/模組兩層 Harness，與不可收買的測試驗收體系（測試金字塔＋故障注入）。

## Steps

1. [[learn/geek-ai-agent/nodes/when-loop-model/two-runs-plan|為什麼拆兩次 Loop：單機核心與分散式 HA]] — 說出「能一次跑完 ≠ 應該一次跑完」，以及兩個部分各自的範圍與里程碑（deep）
2. [[learn/geek-ai-agent/nodes/when-loop-model/loop-raw-material|Loop 原料與一輪迴圈：把計畫變成可判定驗收]] — 寫出一份 part doc 要有的六塊輸入，並走完一輪 do/test/fix（after step 1, deep）
3. [[learn/geek-ai-agent/nodes/when-loop-model/harness-two-layers|兩層 Harness：公開護欄與模組自帶驗收]] — 分清一次建好的公開 Harness 與跟著任務卡走的模組 Harness（after step 2, deep）
4. [[learn/geek-ai-agent/nodes/when-loop-model/test-pyramid|測試金字塔：五層判官與分散式正確性]] — 講出五層測試各抓什麼，以及分散式正確性為何最難（after step 3, deep）
5. [[learn/geek-ai-agent/nodes/when-loop-model/fault-injection-and-judge-integrity|故障注入與不可收買的判官]] — 用故障注入設計三個驗收案例，並守住判官不被改寫（after step 4, deep）

## Lesson

When 的技術方案是一份清楚的施工圖，但圖畫好了不代表要一筆一畫自己刻。這個節點把「怎麼把施工圖交給 Loop 去蓋」講成一條可操作的路線：先決定跑幾次、怎麼切，再把每一塊寫成可判定的原料，接著把護欄分成兩層疊好，最後用一套不可收買的測試體系當作迴圈的判官。

整條路線的核心其實只有一句：**Loop 會放大你事先設計的驗收品質**。你給它弱的判官，它就會自信地、快速地放大錯誤；你給它強到不能作弊的判官，它才能自己收斂到正確。所以拆分的依據是可驗證性，不是哪個技術比較酷：單機核心路徑最容易驗，適合先跑；分散式正確性最難驗、出錯最貴，所以獨立成第二跑，並配上故障注入這種主動製造災難的驗收方式。

走完五步，你手上會有一份完整的 Loop 設計：兩次跑的分工、一份 part doc 的格式、公開 Harness 與模組 Harness 的界線、五層測試金字塔，以及讓 AI 無法偷改測試來假裝過關的制度。
