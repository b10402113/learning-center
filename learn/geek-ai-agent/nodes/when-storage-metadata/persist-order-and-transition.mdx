<LearningGoal>
能複述 create 的固定寫入順序、原子 transition 如何保證只有一個執行者取得投遞權，以及重啟時為何要先載資料再對外服務。
</LearningGoal>

## Lesson

`create` 以固定順序（序列化 → Pipeline 寫本體與索引 → Redis 成功 → 進記憶體 → 回傳）保證「記憶體有的，儲存一定有」；`transition` 用比較並交換讓並行的狀態轉移只有一個成功、只有一個執行者取得投遞權，排程執行緒不做同步 Redis IO；節點重啟要先用 `loadPendingByTimeWheel` 把還在等的訊息載回記憶體時間輪，才能對外服務。
