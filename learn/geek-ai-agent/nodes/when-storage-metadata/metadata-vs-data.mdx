<LearningGoal>
能說出元數據與訊息資料在一致性與生命週期上的差異，並用能力契合度與維運負擔比較 ZK／etcd／Consul 後選出 etcd。
</LearningGoal>

## Lesson

When 把資料分成兩條線：大量、短命、求快的延遲訊息放 Redis，量小、要強一致與變更通知的叢集元數據放 etcd；元數據包含節點註冊與 Controller（綁 Lease）、時間輪分配與叢集組態（持久）。ZK、etcd、Consul 都能協調，選 etcd 是因為 Put／Get／Watch／Lease 原語最貼合需求，且雲原生環境普遍、維運負擔最輕。
