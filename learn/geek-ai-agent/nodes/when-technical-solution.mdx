# When 技術方案

## Learning goal

看懂 When 的六大技術決策、整體架構、多層時間輪、Master/Slave 複製、持久化 key 設計與部署形態。

## Steps

1. [[learn/geek-ai-agent/nodes/when-technical-solution/six-decisions|六大技術決策與 3 週 HA 的理由]] — 六個選型各擋掉什麼，以及為何三週敢做 HA（deep）
2. [[learn/geek-ai-agent/nodes/when-technical-solution/cluster-architecture|整體架構與同質節點]] — 四塊架構、單一 Controller 角色、節點模組與擴縮容（after step 1, deep）
3. [[learn/geek-ai-agent/nodes/when-technical-solution/multilayer-timewheel|多層時間輪的設計]] — 環加指針、跨層降級、多輪分片與排程精度（after step 2, deep）
4. [[learn/geek-ai-agent/nodes/when-technical-solution/replica-failover|Master/Slave 複製與 10 秒接管]] — 非同步複製、Lease 偵測、接管順序與 at-least-once（after step 3, deep）
5. [[learn/geek-ai-agent/nodes/when-technical-solution/persistence-deploy|持久化 key 設計與部署形態]] — Redis key 結構、避開 big-key、重啟恢復與三種部署（after step 4, deep）

## Lesson

需求文件回答 When「要蓋什麼」，技術方案回答「怎麼蓋」。這個節點把技術方案文件壓成一條可複述的主線：先看六個不可動搖的技術決策與它們各自擋掉的替代方案，再看這些決策如何長成一個由同質節點組成的叢集，最後下鑽兩個最難的機制——時間輪與 Master/Slave 複製——並收在持久化 key 與部署形態上。

主線的核心是一個判斷：When 把「可靠」與「協調」外推給成熟的外部元件（ETCD 管協調、Redis 當唯一真相），自己只專心做一件事——用記憶體中的多層時間輪，以 O(1) 完成延遲訊息的排程與觸發。節點刻意保持同質，Controller 只是一個會被選舉出來的角色而非一台專用機器；副本只為快速切換而存在，不追求強一致性。這套取捨讓三週的 MVP 就能涵蓋叢集、HA 與自動 failover，也讓每個模組的邊界可以用一句話說清楚。
