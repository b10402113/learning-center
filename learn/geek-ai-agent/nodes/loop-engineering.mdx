# Loop Engineering

## Learning goal

掌握 Loop 的五要素、判官與停止條件，並理解 SDD → Harness → Loop 的三層關係與業界收斂。

## Steps

1. [[learn/geek-ai-agent/nodes/loop-engineering/why-loop|為什麼是 Loop：從下指令到設計迴圈]] — 說出 Loop Engineering 的定義與它真正解決的問題（確信感）
2. [[learn/geek-ai-agent/nodes/loop-engineering/five-elements|Loop 五要素：讓迴圈轉得動、安全、可信]] — 列出五要素，講清前兩者／中間兩者／最後一者各決定什麼（after step 1）
3. [[learn/geek-ai-agent/nodes/loop-engineering/judge-integrity|判官與防作弊：不讓迴圈自己騙自己]] — 講出作弊模式與鐵律，以及實作／驗證分離與分層判官（after step 2）
4. [[learn/geek-ai-agent/nodes/loop-engineering/run-the-loop|跑一輪：循環、停止條件與任務卡]] — 走完一輪循環、四個停止條件，寫出六欄位任務卡（after steps 2–3）
5. [[learn/geek-ai-agent/nodes/loop-engineering/three-layer-and-boundary|三層關係與邊界：什麼交給 Loop、什麼留給人]] — 畫出 SDD→Harness→Loop，用可驗證性判準分流任務（after steps 1、4）

## Lesson

Loop Engineering 是 2026 年前線實務者收斂出來的一套做法：**把執行交給迴圈，把判斷留給人**。它要解的不是「打字太慢」，而是一個人做專案時最貴的成本——確信感：什麼時候能交付、東西對不對、要重工幾次。作法是把任務切成小塊、固定輸入／輸出／驗收，讓 AI 在一個能自我判定的迴圈裡反覆「做—測—修」，直到驗收通過或撞到停止條件才回來。注意力因此從「寫提示詞」搬到「設計環境與規則」，也就是 Harness。

這條 node 用五步把這個轉變講到底。先問為什麼——人從 2023 的 Prompt Engineering 一路退到 2026 的 Loop Engineering，但退的永遠只是「執行」，定義目標、設規則、判斷結果從不外包。再把 Loop 拆成五個要素：可判目標、可驗證的判官、隔離工作區、邊界與停止、人類檢查點；前兩者決定迴圈能不能轉，中間兩者決定安不安全，最後一者決定輸出可不可信。接著處理迴圈最脆弱的一環——判官，AI 會偷改測試、放寬斷言來「假裝過關」，所以要有鐵律與實作／驗證分離。有了原則就落成操作：一輪循環、四個停止條件、一張六欄位任務卡，讓 `/loop` 這樣的自組 Skill 接手跑。最後把它放回全局：Loop 站在 SDD（想清楚）與 Harness（造環境）之上，並用「可驗證性／出錯成本」這條線決定什麼進迴圈、什麼永遠由人主導。
