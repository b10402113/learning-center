# 動手前先想清楚：三個陷阱與顯式映射

<LearningGoal>
能逐一說出設計 Provider 前必須釘死的三個陷阱（型別無法區分多 Provider、Spring AI 自動執行工具、未驗證 starter 依賴），並解釋「顯式 name→ChatModel 映射、不靠型別掃描」為什麼是首要原則。
</LearningGoal>

## Lesson

動手前先釘死三個陷阱：多 Provider 同型別無法靠掃描區分（所以必須維護顯式 name→ChatModel 映射）、Spring AI 會自動執行工具（所以要關閉並把執行權留給 ToolExecutor）、範例 provider 名未必有對應依賴（所以先跑 mvn dependency:tree 驗證）；每個陷阱都應化成一條回歸測試。
