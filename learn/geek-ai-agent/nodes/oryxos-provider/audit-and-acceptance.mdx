# llm_calls 審計與驗收 Harness

<LearningGoal>
能解釋 llm_calls 為何成功與失敗都要落庫（day-one 審計、兩欄位設計、手寫 schema 而非 ddl-auto），並說出頂尖三條測試的由來與 mock／integration 測試的切分。
</LearningGoal>

## Lesson

llm_calls 核心階段就必須成功與失敗都寫入（success 布林＋error_message 兩欄、手寫遷移腳本而非 ddl-auto），避免真實事故不留痕跡；驗收上以 mock ChatModel 單元測試涵蓋路由、驗證、審計、翻譯，integration 冒煙測試用 @Tag 標示由 CI 跳過，並用手動清單確認 BOM 可解析、真打成功、無明文金鑰——完成線是一次穩定成功的呼叫，fallback 與 hedging 留到擴展階段。
