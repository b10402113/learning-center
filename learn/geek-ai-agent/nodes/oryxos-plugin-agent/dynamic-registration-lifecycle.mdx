# 動態管理：免重啟掃描、上傳即上線與生命週期編排

<LearningGoal>
能設計「免重啟」的動態註冊：兩條錄入路徑共用同一個 register，並說出刪除／更新為何必須先處理排程 handle。
</LearningGoal>

## Lesson

一個真相源 `.oryxos/agents/`、兩條錄入路徑（API 上傳與目錄即時監看）共用 `WorkspaceWatcher` 這個唯一註冊入口，所以上傳即上線等於丟目錄即上線；`AgentLifecycleService` 只負責編排與失敗回滾，刪除必須「先註銷排程 handle、再移索引、最後封存目錄」，更新若動到排程要先註銷舊 handle，否則會留下 cron 觸發到不存在 Profile 的時序漏洞。
