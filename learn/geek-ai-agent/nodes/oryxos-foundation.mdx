# 工程地基（init skill）

## Learning goal

理解並能重建 OryxOS 的六塊工程地基（日誌、監控、HTTP、API 規範、代碼標準、安全、CI），以及 oryxos-init skill 如何把它壓成一個可重用流程。

## Steps

1. [[learn/geek-ai-agent/nodes/oryxos-foundation/foundation-first|先起地基，再寫業務]] — 兩階段順序與「地基決定工程品質」的紀律（deep）
2. [[learn/geek-ai-agent/nodes/oryxos-foundation/six-foundation-blocks|六塊工程地基]] — 六塊各自是什麼、用什麼工具落地（after step 1）
3. [[learn/geek-ai-agent/nodes/oryxos-foundation/own-init-skill|為什麼要寫自己的 init skill]] — 通用 skill 的落腳處與專屬 skill 的價值（after step 2）
4. [[learn/geek-ai-agent/nodes/oryxos-foundation/init-skill-flow|oryxos-init skill 做什麼]] — 一份 SKILL.md 把十步壓成六階段、四者分工（after step 3）
5. [[learn/geek-ai-agent/nodes/oryxos-foundation/foundation-acceptance|現場演示：把地基起好]] — 9 模組骨架 → skill 安裝 → mvn verify 全綠（after step 4）

## Lesson

這個節點的主線只有一句：把「先起地基，再寫業務」從口號變成可執行、可驗收、可重用的流程。做法是先把六塊與業務無關的工程地基（日誌、監控、HTTP server、API 規範、代碼標準、安全掃描）逐一釘死選型，再問「這些東西每個專案都要，為什麼不把它寫成一個 skill」——於是 oryxos-init 用一份 SKILL.md 把十個初始化步驟壓成六個階段，配合 constitution 釘死規範、CI 執行強制、Spec-Kit 專注寫業務，最後用一次真實演示證明：跑完 skill，mvn verify 全綠，地基階段的驗收清單全部達標。
