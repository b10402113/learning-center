# OryxOS 技術方案

## Learning goal

看懂 OryxOS 的四層架構、七大技術決策、五大能力如何互相供養、九個 Maven 模組與持久化選型。

## Steps

1. [[learn/geek-ai-agent/nodes/oryxos-technical-solution/seven-decisions|七大關鍵技術決策]] — 七個決策各擋掉什麼風險，以及整體技術棧（deep）
2. [[learn/geek-ai-agent/nodes/oryxos-technical-solution/layered-architecture|四層架構與五大能力的互相供養]] — access／engine／capability／foundation 與能力鏈（after step 1, deep）
3. [[learn/geek-ai-agent/nodes/oryxos-technical-solution/capability-design-tradeoffs|五大能力的設計取捨]] — Provider／ReAct／Memory／Tool／Web 各自的關鍵設計決定（after step 2, deep）
4. [[learn/geek-ai-agent/nodes/oryxos-technical-solution/module-and-support-structure|九個 Maven 模組與支撐層]] — 模組依賴方向與 Profile／Context／Channel／CLI／Config（after steps 2–3, deep）
5. [[learn/geek-ai-agent/nodes/oryxos-technical-solution/persistence-selection|持久化選型：SQLite、MEMORY.md 與檔案系統]] — 為什麼不用向量庫，以及三條升級路徑（after steps 3–4, deep）

## Lesson

需求文件回答「要蓋什麼」，技術方案回答「怎麼蓋」。這個節點把 OryxOS 的技術方案文件壓成一條可複述的主線：先看七個不可動搖的關鍵決策，再看它們如何長成四層架構與一條五大能力互相供養的鏈，最後落到工程上——九個 Maven 模組、支撐層與持久化選型。

主線的核心是一個判斷：核心階段只要最短可跑的 runtime kernel，凡是會讓「跑起來」變慢的企業級需求（多租戶、認證、向量檢索、容器隔離、多 Agent）全部推遲到擴展階段，但介面先留好。技術方案的價值不在堆功能，而在於把每個「先不做」寫成一句可驗證的理由，讓後續實作不會走偏。
