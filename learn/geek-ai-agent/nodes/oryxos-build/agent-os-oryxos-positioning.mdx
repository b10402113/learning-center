# Agent OS 概念與 OryxOS 定位

<LearningGoal>
理解 Agent OS 的定義、五大能力、與相鄰概念的邊界，以及 OryxOS 為何選 Java、如何定位。
</LearningGoal>

## Lesson

### 從一家公司說起

一家公司請了很多員工（Agent）。每個員工都要領電腦、領門禁卡、走報銷流程。如果每個員工都自己搞定這套行政，公司會亂成一團。行政部門做的事：統一發電腦（模型接入）、發門禁卡（通道與權限）、記考勤（記憶）、審核支出（審計）。業務部門只需要招人（配置 Agent）和安排具體工作（寫 Tool）。這個「行政部門」，就是 Agent OS。

Agent OS 是裝在用戶或企業自己的機器上、用來運行和管理多個 AI Agent 的基礎系統。它和 agent runtime 是兩層東西：runtime 讓一個 Agent 跑起來，Agent OS 管的是 N 個 Agent 在企業裡同時運行時的共享基礎設施。一個合格的 Agent OS 至少要提供五件事：Agent 配置與生命週期、統一外部通道（IM/郵件/Web/HTTP）、統一內部系統訪問（LLM/工具/IT 系統/知識庫）、統一記憶、Tool 調用與沙箱執行。這就是口號「Agent 是配置出來的，不是寫出來的」的來歷。

### 一把尺：四類產品的邊界

理解了五項能力，你就能把任何 AI Agent 產品分清楚。Agent OS 產出的是配置好的常駐 Agent（OryxOS、OpenClaw、Hermes）；編排平台產出的是工作流（Dify、Coze）；框架產出的是代碼（LangChain、Spring AI）；大廠 SaaS 產出的是綁定雲的完整應用（Glean、Agentforce）。編排平台可以跑在 Agent OS 上當後端，框架可以當 Agent OS 的底層元件，兩者互補不競爭。Agent OS 是開源、可私有部署、不鎖定生態的那一檔。

### Java 生態的空白與 OryxOS 定位

最有代表性的兩個開源 Agent OS——OpenClaw（Node.js，30 萬星）和 Hermes Agent（Python，15 萬星）——共同留下的三塊空白：完整企業治理（多租戶 RBAC、SSO、審計）、與企業 IT 系統的深層整合、Java 生態缺位。Java 有 Spring AI、Spring AI Alibaba，但全是庫，產出是代碼，沒有一個 Java 項目把自己定位成 Agent OS。OryxOS 落在這塊空白上：企業可控、Java 原生、私有可審計的統一 Agent 底座。

四大設計目標是四個字：統一（很多業務 Agent 共享一個底座）、私有（數據完全留在企業內）、易接入（標準 Spring Boot 結構，直連 ERP/CRM/CMDB/SSO）、可觀測（Prometheus 指標、結構化日誌、健康檢查）。做任何範圍決定時，拿這四個詞對一遍，對不上的先別做。

OryxOS 的定位原則是「錨定需求，不錨定概念」：「Agent OS」這個詞會被換掉或被吸收，但「受監管企業需要一個完全可控、私有、可審計、對齊 Java 的 Agent 底座」這個需求不會變。OryxOS 把腳踩在需求上。它的邊界是 runtime，不做可視化流程編排；安全是 day-one 設計，刻意反著 OpenClaw 的弱點來。
