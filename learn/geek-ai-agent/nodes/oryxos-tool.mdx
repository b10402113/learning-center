# Tool 體系

## Learning goal

掌握 OryxTool／ToolRegistry 單一抽象、三級 Plugin Tool（SKILL.md+MCP／自寫 MCP／Java Bean）與內建工具，並讓每次執行先過安全白名單。

## Steps

1. [[learn/geek-ai-agent/nodes/oryxos-tool/tool-is-the-hands|Tool 是什麼：Agent 的「手」與內建工具全景]] — LLM 只產文字、工具讓 Agent 動手；九個內建工具與內建／Plugin 分界
2. [[learn/geek-ai-agent/nodes/oryxos-tool/oryxtool-unified-abstraction|OryxTool 單一抽象與 ToolResult]] — 四個方法、四個欄位，ReAct 不問工具出身（after step 1）
3. [[learn/geek-ai-agent/nodes/oryxos-tool/three-tier-plugin-tools|三級 Plugin Tool：零代碼、輕代碼、重代碼]] — 方式一 MCP+SKILL.md、方式二自寫 MCP、方式三 Java Bean（after step 2）
4. [[learn/geek-ai-agent/nodes/oryxos-tool/toolregistry-executor-sandbox|ToolRegistry、ToolExecutor 與安全白名單]] — 註冊、過濾、執行前先過白名單（after steps 2–3）
5. [[learn/geek-ai-agent/nodes/oryxos-tool/builtin-tools-industry-standard|把內建工具補齊到業界水準]] — 五個高頻工具與「新增工具成本恆定」（after step 4）

## Lesson

Tool 是 Agent 的「手」：LLM 只會產文字，真正讀檔案、跑命令、呼叫 API 的動作全靠工具。ReAct 迴圈在 Act 這一步要能呼叫任何能力的工具，這要求 OryxOS 先把工具「長相」統一——不管工具來自內建程式碼、外部 MCP server 還是 Spring 容器裡的 Java Bean，對迴圈而言都只是「一個有名稱、有描述、有輸入 schema、能執行並回傳結果的 OryxTool」。

統一抽象之上是兩條主線：**擴充**與**安全**。擴充靠三級 Plugin Tool——零代碼寫 SKILL.md 並複用現成 MCP server、輕代碼自己寫一個 MCP server、重代碼寫 Java Spring Bean；選型規則恆定為「能用簡單的就不用複雜的」。安全靠一條硬規則——任何工具執行前都必須先通過路徑／命令／網域白名單的 Sandbox 檢查，再寫入 tool_invocations 審計表。最後用「把內建工具補齊到業界水準」的五個新工具驗證整套設計：新增工具成本必須恆定，否則抽象就是失敗的。
