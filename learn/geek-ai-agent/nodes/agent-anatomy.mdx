# Agent 五元件與真偽判別

## Learning goal

能用 LLM + Tools + Memory + Loop + Environment 五元件拆解任何號稱 Agent 的系統，並判別真 Agent 與聊天機器人、工作流、LLM 包裝的差別。

## Steps

1. [[learn/geek-ai-agent/nodes/agent-anatomy/technical-definition|Agent 的技術定義：感知、決策、行動、回饋迴圈]] — 說出定義，並解釋為什麼定義裡不提 LLM
2. [[learn/geek-ai-agent/nodes/agent-anatomy/five-components|五元件拆解：LLM + Tools + Memory + Loop + Environment]] — 講清五個元件各負責什麼、少了它會怎樣（after step 1）
3. [[learn/geek-ai-agent/nodes/agent-anatomy/loop-mechanics|Loop：ReAct 迴圈與它必須處理的四件事]] — 畫出 Reasoning→Acting→Observation，講清四個必管事（after step 2）
4. [[learn/geek-ai-agent/nodes/agent-anatomy/confusable-concepts|真偽判別：Agent vs LLM、聊天機器人、工作流]] — 用「缺席測試」分辨真 Agent 與否（after steps 2–3）
5. [[learn/geek-ai-agent/nodes/agent-anatomy/explain-real-products|用五元件拆解真實產品與 Agent OS]] — 用五個問題拆解任何產品，並分清 Agent 與 Agent OS（after steps 2、4）

## Lesson

「Agent」這個詞已經被用爛了：會呼叫 API 的腳本、套了 ChatGPT 的聊天視窗、固定排程的自動化流程，全都自稱 Agent。這條節課要給你的是一把**技術尺規**——把任何號稱 Agent 的東西拆成五個元件來看，真偽立刻現形。

尺規的第一層是定義：Agent 是一個會感知環境、自主決策、採取行動、並靠回饋迴圈不斷迭代的程式。注意這個定義裡沒有「LLM」——強化學習的 Agent、遊戲裡的 NPC 都符合定義，LLM 只是把工程門檻拉低了，並不構成 Agent 的本質。第二層是五個元件：LLM 是決策引擎、Tools 是行動能力、Memory 是狀態載體、Loop 是循環執行、Environment 是互動目標；五個元件加一個迴圈，就是完整的技術骨架。第三層把重心壓在 Loop 上：Reasoning → Acting → Observation 的 ReAct 迴圈是 Agent 的心跳，單次 LLM 呼叫只是聊天機器人，只有循環的決策—行動—觀察才是 Agent，而一個好迴圈必須處理停止條件、錯誤恢復、上下文壓縮、多模型切換四件事——這也是框架八成複雜度的所在。

有了尺規，判別就變成機械動作：Agent 與 LLM 是「元件 vs 整台機器」的差別，聊天機器人是「拿掉 Tools 與 Loop 的 Agent」，工作流是「確定性流程」而 Agent 是「探索性迴圈」。當一個系統說不出它的自主決策迴圈在哪，它就不是 Agent。最後把尺規拿去拆真實產品——ChatGPT 加了 Code Interpreter 才算 Agent、Claude Code 是五元件全開的 Coding Agent、LangChain 只是工具箱、AutoGPT 有歷史意義而無技術意義——並且把視野從「一個 Agent（應用）」抬到「Agent OS（跑很多 Agent 的作業系統）」，因為企業真正的問題從來不是跑一個 Agent，而是穩定地跑很多個。這條線往下會接上 OryxOS 的專案層。
