# 驗收 harness 與安全順序：enforce 必須在 send 之前

<LearningGoal>
能說明兩批測試各測什麼、為何 enforce-before-send 的順序斷言是白名單防線的關鍵，以及「未設定」要 loudly fail 而不能靜默。
</LearningGoal>

## Lesson

驗收拆兩批：`WebhookNotifyAdapterTest` 用 MockWebServer 斷言 body 帶 content、URL 來自 config 不 hardcode、5xx 往上拋絕不吞掉；`NotifyToolsTest` mock Sandbox 與 Adapter，斷言「未設定 notify_channels 要 fail loud、缺 channel 用第一個、enforce 先於 send」——其中用 InOrder 釘死的 enforce-before-send 是最關鍵的一條，順序反了等於白名單被繞過。
