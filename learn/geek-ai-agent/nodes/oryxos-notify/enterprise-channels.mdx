# 擴到企業主流渠道：場景、webhook 差異與延伸路徑

<LearningGoal>
能依場景選通知渠道、看懂各家 webhook 格式差異與対接坑，並用三原則決定「純文字→webhook、特殊格式→專用 adapter、富卡片→MCP」的延伸路徑。
</LearningGoal>

## Lesson

企業渠道按場景挑（團隊協作／個人通知／告警值班／正式觸達），核心可達的判準是「一次 POST 到 URL」；核心 WebhookNotifyAdapter 送的是 `{"content": ...}`，但各家渠道 payload 格式都不同（釘釘三選一安全設定、飛書簽名可選、Teams 經典 webhook 退役），對接照「建機器人→環境變數→Profile→白名單→測試訊息」五步走；payload 對不上時用三原則選路——純文字走 webhook、特殊格式走專用 adapter、富卡片走 MCP，而 `NotifyChannelAdapter.send(NotifyTarget, String)` 簽名始終不變；webhook URL 的 token 本身就是憑證，絕不明文落盤／入 log／進 Git。
