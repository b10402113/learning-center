# 單一編排器：AgentService、ProfileContext、ContextLoader

<LearningGoal>
能說清 AgentService.process 為什麼是 CLI／Web／排程唯一的編排入口，以及 ProfileContext（ThreadLocal）與 ContextLoader（每次重讀、不落快取）各自解決什麼問題。
</LearningGoal>

## Lesson

CLI、Web、排程共用同一個編排入口 AgentService.process（同一入口重用不重寫），因為 OryxTool.execute 簽名不帶 Profile，用 ThreadLocal 的 ProfileContext 在同一條執行緒上傳遞身分、並在 finally 清掉防執行緒重用時的洩漏；ContextLoader 每次組 prompt 都重讀 Bootstrap／SKILL.md、不落快取，讓改檔立即生效，Profile 引用的檔案缺失則直接報錯不靜默跳過。
