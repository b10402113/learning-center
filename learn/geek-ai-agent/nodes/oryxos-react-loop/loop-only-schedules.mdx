# 迴圈只做排程：職責分離與為什麼手寫

<LearningGoal>
能畫出 ReActLoop／PromptBuilder／ProviderService／ToolExecutor 的職責分工，說出為什麼要手寫而不用框架黑盒，並指出三個經典陷阱。
</LearningGoal>

## Lesson

主迴圈只有幾十行，難的是邊界：ReActLoop 只排程、PromptBuilder 組上下文、ProviderService 呼叫模型、ToolExecutor 執行工具，四個職責各自獨立；手寫不用框架黑盒，是因為停止條件、工具失敗、上下文成長、模型切換都得自己可控；三個經典陷阱是沒有迭代上限、上下文無界成長、回應與結果沒累積回 Session。
