# 五狀態訊息狀態機與轉移語義

<LearningGoal>
能畫出 PENDING／DELIVERING／DELIVERED／FAILED／CANCELLED 五個狀態與五種合法轉移，並說明為什麼每次轉移都必須原子且只有一個執行者能持有投遞權。
</LearningGoal>

## Lesson

狀態機把一則訊息的一生收斂成五個狀態與五條合法轉移；DELIVERING 的存在是為了讓投遞權同時只被一個執行者持有，所有狀態變更都必須走原子的 transition，且權威狀態存在 Redis、時間輪只是可從 Redis 重建的記憶體排程索引，終態訊息在保留期內仍可查詢。
