# 契約先行與 Message 公共模型

<LearningGoal>
能說明為什麼 When 必須先統一公共模型再分模組實作，並描述一則 Message 的身份／時間、投遞意圖與執行狀態三組欄位。
</LearningGoal>

## Lesson

契約先行不是先寫文件，而是先讓所有模組面對同一組事實：若各模組自行定義訊息與狀態，單元測試都會過，整合時卻會因欄位名稱、狀態值與生命週期不一致而崩潰。When 用一份共用的 Message 走遍接入、路由、調度、儲存與投遞，欄位分成身份／時間、投遞意圖、執行狀態三組，並禁止任何模組重新定義等價的訊息物件；契約要改時，先改定義處，再逐一檢查所有實作者與使用者。
