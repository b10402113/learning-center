# gRPC 傳輸契約與驗證分層

<LearningGoal>
能說明 When 為何對內用 gRPC、對外用 HTTP，設計出 Submit／Query／Cancel 三個 RPC 的 proto 契約，並分清契約層結構驗證與執行時配置驗證。
</LearningGoal>

## Lesson

gRPC 契約用 proto 作為語言無關的權威定義：對內用 gRPC 求效率與強型別，對外用 HTTP 求整合便利，when-api.proto 只 import 公共模型而不重新定義，sink_config 用強型別 oneof 免去猜 key。gRPC server 刻意只做解析、結構驗證、委派與錯誤映射，URL 可達性、Kafka 連線等執行時驗證留給投遞模組。
