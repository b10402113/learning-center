# Sandbox

## Learning goal

能用四維隔離與四檔方案定位風險，實作應用層白名單並接進既有工具，且守住介面不被第一檔帶偏。

2. [[learn/geek-ai-agent/nodes/oryxos-sandbox/sandbox-four-tiers|四檔方案與隔離強度/開銷光譜]] — 白名單→容器→microVM→完整 VM 的強度/開銷看板、業界選型與縱深防禦（after step 1）
3. [[learn/geek-ai-agent/nodes/oryxos-sandbox/sandbox-interface-design|介面先行的 Sandbox 抽象：不讓第一檔帶偏]] — 方向/介面/實作三層、Sandbox 意圖介面、microVM 反向驗證、升級訊號（after step 2）
4. [[learn/geek-ai-agent/nodes/oryxos-sandbox/sandbox-whitelist-impl|實作 WhitelistSandbox 並接進既有工具]] — 最小物件先釘介面、三個私有檢查、每個 @Tool 一行 enforce 接線（after step 3）

## Lesson

Sandbox 是 OryxOS 把 Agent 從聊天玩具推向生產的最後一道前提：Agent 會在運行時自己產生並執行指令，這些指令未經人工審查，可能來自提示注入或它自己的破壞性失誤；再加上多租戶、多 Agent 共存，租戶 A 的 Agent 絕不能讀到租戶 B 的資料。因此「隔離」不是選項，而是敢不敢讓 Agent 做任何有副作用動作的前提。

這個節點的學習路線是一條從「看見風險」到「守住抽象」的單向鏈。先建立風險模型——為什麼舊的「信任自己寫的程式」假設失效，以及四維隔離（檔案系統／網路／程序與系統呼叫／資源）怎麼當成拆解任何沙箱技術的眼鏡。接著把解決方案定位成一條「越深越安全、越重越貴」的四檔光譜（應用層白名單 → 容器 → microVM → 完整 VM／物理隔離），並用「你跑的是誰的程式」與業界真實系統（Claude Code、Hermes、E2B／gVisor）學會選型；同樣重要的是縱深防禦意識——沒有一層是萬能的，沙箱是三種以上的組合。第三步把設計原則落成介面：方向（往容器／microVM 走）與介面（Sandbox.enforce 只表達意圖）現在就釘死，實作只做第一檔——關鍵是絕不讓第一檔把介面帶偏，要用「microVM 能不能乾淨塞進來」反向驗證，並只被真實訊號觸發升級。最後一步動手寫：用 Sandbox／SandboxAction／ActionType 最小物件先凍結介面，實作 WhitelistSandbox 的 `checkFilePath`／`checkShellCommand`／`checkHttpUrl` 三個私有檢查，然後在每個 @Tool 開頭插一行 `sandbox.enforce(...)`——正確的抽象讓接線成本小得不成比例。

四步合起來回答同一個問題：怎麼在不寫第二檔的前提下，為未來的容器／microVM 留下一個不會被第一檔綁死的安全介面。
