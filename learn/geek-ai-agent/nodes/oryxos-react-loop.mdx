## Lesson

ReAct（Reasoning + Acting，推理與行動）迴圈是整個 Agent 底座的「心跳」：模型負責想、工具負責做、迴圈負責把兩者串起來重複到任務完成。沒有這個迴圈，一次 LLM 呼叫就是聊天機器人；有了它，Agent 才能自主做多步決策。這個節點的目的，是讓你把這個心跳親自寫一遍，而不是從框架黑盒裡拿。

主線有三條。第一，"**迴圈只做排程**"——真正的迴圈主體只有幾十行，它自己不呼叫模型、不執行工具，而是把這兩件事委派給 ProviderService 與 ToolExecutor，自己只負責決定做哪件事、檢查要不要停。第二，"**上下文自己管**"——每一輪模型的回應與工具的結果都要累積回 Session，才能在下一輪被看到；PromptBuilder 每輪重新組裝 system prompt、記憶、近 N 輪對話與工具清單，ContextLoader 每次重讀文件、不落快取，讓每一輪都有最新上下文。第三，"**執行權只在一處**"——工具到底能不能跑、怎麼跑，全部收斂在 ToolExecutor 一個地方，因此要關掉 Spring AI 的自動工具執行，否則一個工具會被呼叫兩次。

共識不是憑空來的：Claude Code、Cursor、LangChain 的 Agent 底層都是這個模式，差別只在工具與環境的深度。要不要出工具、執行到第幾輪停、context 塞不下怎麼辦，這些邊界必須在設計時就決定，而不是事後打補丁——這是本節反覆強調的紀律，也是後面每個模組（Memory、Tool、Sandbox、Web）都跟著遵守的骨架。
