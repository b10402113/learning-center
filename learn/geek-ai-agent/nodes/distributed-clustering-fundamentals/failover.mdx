# 故障接管：偵測、決策、回填資料缺口

<LearningGoal>
能把故障接管拆成偵測、決策、執行三個階段，並解釋為什麼回填非同步複製留下的資料缺口是最難、最容易出錯的一步。
</LearningGoal>

## Lesson

故障接管依序為租約偵測、唯一 Controller 決策、切換角色並回填資料缺口；非同步複製留下的資料缺口最難處理，When 靠新 Master 從 Redis 重新載入對帳來補齊。
