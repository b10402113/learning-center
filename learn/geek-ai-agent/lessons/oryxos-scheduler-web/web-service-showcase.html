Web Service：10 端點把引擎變成 REST 介面

Step 4/5 · 定時任務與 Web Service

學習目標

能說清 oryxos serve 如何把引擎變成對外 REST 介面：10 個端點、6 個控制器、兩條整合路徑，以及 admin 平台只靠這 10 個端點就能運作、反過來證明 API 的完整性。

沒有 Web Service，OryxOS 只是一個 CLI 工具

到目前為止，你要跟引擎互動的方法只有一個：坐在伺服器面前打字。任何想呼叫它的業務系統——ERP、CI/CD、另一支服務——都找不到入口。Web Service 就是 OryxOS 的對外門面（outward facade）：執行 oryxos serve，啟動 Spring MVC，監聽 8080 埠，把引擎的內部能力翻譯成一組任何 HTTP 客戶端都能呼叫的 REST 端點。

10 個端點、6 支控制器

全部端點掛在 /api/v1 下，分散在六支控制器：

控制器端點做什麼
SessionApicreate / post message / get / deletesession 的生命週期管理與多輪對話
AgentApiPOST /agents/{name}/invoke無狀態的一次性完整 ReAct
ProfileApiGET /profiles列出所有 Agent（Profile）
MemoryApiGET /memory讀取 MEMORY.md 核心記憶
ToolApiGET /tools列出可用工具
SystemApiGET /health、GET /info系統健康與版本資訊

10 個端點其實只做四件事

別被數字嚇到。這 10 個端點只涵蓋四類工作：

  1. session 管理——建立、送訊息、取歷史、刪除。
  2. Agent 呼叫——invoke 一趟無狀態的完整 ReAct。
  3. 資訊查詢——profiles、memory、tools。
  4. 系統狀態——health、info。

每一支控制器都只做三件事：驗證參數、包裝回應、處理錯誤，然後把真正邏輯委派給核心層——薄控制器、引擎不岔開。

業務系統的兩條整合路徑

外部系統要接進來，大多走兩種其中一條：

  • 連續對話：先建立一個 Session，之後每次送訊息都用那個 session id——適合多輪、有狀態的互動。
  • 一次性呼叫：直接 POST /agents/{name}/invoke，引擎內部組一個一次性 session、跑完整趟 ReAct、回傳結果——適合無狀態的短任務（例如「把這段文字翻成英文」）。

admin 平台：唯一的證明是「它真的只有消費 API」

第一版的管理平台是一個純靜態的 Vue 前端，掛在 /admin。它只呼叫上面這 10 個端點，不碰任何內部類別。這是一個低調但極有說服力的證明：只要一個純消費者能靠這些端點畫出完整介面，就證明這組 API 已是完整的對外通道——不需要任何旁路。

把 Web Service 想成銀行的 ATM：後端帳戶邏輯完全不動，ATM 只是把「查詢餘額、提款」翻譯成機器可讀的指令。OryxOS 的引擎是銀行後端，Web Service 是 ATM，admin 平台是最早的一張「真實使用者」。
