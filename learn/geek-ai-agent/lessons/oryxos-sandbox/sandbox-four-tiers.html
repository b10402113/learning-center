四檔方案與隔離強度/開銷光譜

Step 2/4 · Sandbox

學習目標

能沿「越深越安全、越重越貴」的光譜定位四檔隔離方案，並用「你跑的是誰的程式」與亂鬥的誤信助理（confused deputy）判斷業界系統為何選不同檔。

一條線先擺好：強度越好、代價越高

任何沙箱方案都站在同一條線上取點：隔離強度越強，開銷越大、啟動越慢。這條線的另一個方向是——隔離邊界越深，越安全（隔離邊界 = 保障在哪一層落地）。

選哪一檔的本質問題只有一個：「你跑的是多不可信的程式，你願意為隔離付多少價？」

把四個維度（檔案系統／網路／程序／資源）用越深的邊界去擋，就越安全，但也越貴、越重。

四檔方案，由淺到深

檔次邊界在哪強度代價
第一檔：應用層白名單（Application Whitelist）程式碼層——執行前先檢查最弱零基礎設施、零效能開銷、單一可執行檔
第二檔：容器（Container）程序／作業系統層——Linux namespaces + cgroups + seccomp中每個執行都活在精簡隔離世界；啟動比行程慢
第三檔：microVM核心層——每個沙箱一個輕量核心強Firecracker 定義檔啟動約 100ms、小記憶體，密度接近容器
第四檔：完整 VM 與物理隔離硬體／物理層最強最重、最貴，只用在極端合規場景

第一檔的誠實邊界：勸阻，不是禁錮

應用層白名單不提供真正的系統隔離，它只是在執行前做程式碼檢查：這個路徑准不准、這個指令在不在黑名單、這個網域准不准。零基礎設施、零開銷、單二進位，很好用。

但它的致命弱點是：勸阻（dissuasion），不是禁錮（confinement）。任何沒被覆蓋的繞過方式——指令拼接、symlink、編碼變體、白名單沒列到的指令——都能繞開。它擋得住愚蠢的失誤，擋不住蓄意攻擊。

第一檔永遠只該當縱深防禦的第一層，不該當唯一的生產防線。OryxOS 用它的時候，必須老實貼上這個標籤。

第二檔與第三檔：為什麼 microVM 是當今黃金標準

容器（第二檔）用 Linux namespaces 隔離檔案系統／網路／程序的視野，cgroups 限制資源，seccomp 限制系統呼叫。生態成熟、覆蓋全面，是大部分跑不可信程式的主要方案。天花板是：共享 host 核心——核心一旦有漏洞被利用，就能逃出容器；所以純容器對「完全不可信」的程式通常被認為不足。

microVM（第三檔）給每個沙箱一個自己的輕量核心，拿到 VM 邊界的隔離，卻接近容器的速度與密度：Firecracker（啟動約 100ms、記憶體極小）、Kata Containers（容器般的體驗跑在輕量 VM 上）、gVisor（使用者空間核心）。它在 Agent 時代很熱，因為大量不可信程式（例如雲端 coding 直譯器跑數百萬份使用者程式）需要「強隔離 + 容器級啟動與密度」；旁路是把沒用到的裝置模擬砍掉的極簡 VMM。

選型即路線：成熟平台多數走「容器 → Kata → Firecracker」的升級路線。

縱深防禦：沙箱是組合，不是開關

四檔是一條強度遞增的演化線，但成熟系統是把多層疊起來：應用層白名單攔下明顯的，容器／microVM 提供強隔離，再加上網路出口管控、資源配額、全鏈審計。

沒有一層是萬能的。就算上了 microVM，出口管控、配額、審計照樣不可少——這三件事不隨隔離檔次改變，每一檔都得有。

業界怎麼選：決定因素是「跑誰的程式」

真實系統分三類，選檔全由這一個問題決定，不是「越強越好」：

  • 本地 coding agent（Claude Code 一類）跑在你信得過的機器上，威脅 = 失誤 + 提示注入，於是第一檔權限閘 + 可選第二檔 OS 沙箱（macOS Seatbelt、Linux bubblewrap+seccomp+socat），不上 microVM。
  • 可插拔多後端的 Agent（Hermes）把隔離做成可換的終端後端，六個選項（local／Docker／SSH／Singularity／Modal／Daytona）。
  • 雲端程式直譯器（OpenAI gVisor、E2B Firecracker、Daytona）跑陌生人的程式，直接上 microVM。

OryxOS 刻意站回最左邊（第一檔），對齊 Claude Code 的威脅模型：核心階段只跑你自己信的程式，不值得為此付容器／microVM 的代價。

學界的提醒：亂鬥的誤信助理（confused deputy）

最大的一課來自一個真實的分類：Agent 握有高權限，但一個低權限的注入輸入騙它濫用這些權限——這叫亂鬥的誤信助理（confused deputy，誤信助理困局：持有高權限的程式被不可信輸入騙去做壞事）。純白名單／核准閘只驗請求的「形狀」，不驗它是不是被髒資料誘發的。

所以：就算隔離再強，一個「依法被授權」的工具在被毒化的指示下照樣能造成傷害。審計（第一天就有）與最小權限（Profile 的 tools 欄位）和隔離同等重要。
