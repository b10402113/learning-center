拆解真實產品與 Agent OS

Step 5/5 · Agent 五元件與真偽判別

學習目標

能用「五個問題」的儀式拆解任何新 Agent 產品（以 ChatGPT、Claude Code、Cursor Agent mode、LangChain、Hermes Agent、AutoGPT 為例），並說清 Agent（一個應用）與 Agent OS（跑很多 Agent 的作業系統）的差別。

把尺變成儀式：五個問題

面對任何一個新出現、號稱 Agent 的產品，不要先看它的宣傳，先照順序問五個問題：

  1. LLM 是什麼？——決策引擎用哪個模型、能不能換。
  2. Tools 有哪些？——它真的能對外部世界做什麼。
  3. Memory 怎麼做？——短期脈絡之外，有沒有跨 session 的長期記憶。
  4. Loop 長什麼樣？——有沒有自主決策迴圈，還是一次性問答。
  5. Environment 在哪？——它活在什麼容器裡，能碰什麼、碰不到什麼。

五題問完，一個產品的能力與邊界就攤在桌上了。這也是「真偽判別」從概念落地成動作的關鍵一步。

同一件事，不同實作：六個產品拆一遍

產品它是什麼五元件視角下的關鍵
ChatGPT經典版是聊天機器人接上 Code Interpreter（能寫能跑程式碼的工具）後補回 Tools 與 Loop，才成為 Agent
Claude Code最成熟的 Coding Agent五個元件全開；它的 Skill 是 Tools 與 Memory 的混合體
Cursor Agent modeAgent（一般模式只是輔助編輯／問答）Agent mode 才有自主決策迴圈；普通模式沒有
LangChain框架，不是產品它是一箱工具與零件（toolbox），不是一個 Agent
Hermes Agent會自我進化的 Agent與 Claude Code 差最大的是 Memory：跨 session 的持久記憶
AutoGPT歷史意義大於技術意義早期嘗試把迴圈拉長，但工程成熟度不足

這六個產品拆完會發現一件事：它們是同一件事的不同實作——都是五元件加一個迴圈，差別只在每個元件做得多深。以 Claude Code 與 Hermes 為例，兩者都有決策、工具、迴圈，最大的分歧點落在 Memory：Claude Code 的記憶偏專案／session 範疇，Hermes 則主打跨 session 的持久記憶。看懂這個，你就不會被「誰才是真 Agent」的口水戰帶著跑，而是能指出「它們在第三個元件上做了不同選擇」。

從一個 Agent 到 Agent OS

學會拆一個 Agent 之後，還要往上抬一層。企業真正的問題從來不是「跑一個 Agent」，而是「穩定地跑很多個 Agent」——這就需要 Agent OS。

打個比方：Agent 是一個應用程式，Agent OS 是跑很多應用程式的作業系統。作業系統負責的事——行程管理、工作區隔離、模型路由、沙箱、可觀測性——正是多 Agent 場景下真正麻煩的部分。而且有一個重要心態：多 Agent 不是單 Agent 的升級版，而是一個複雜度更高的新問題。所以順序是先把單一 Agent 做好，再談多 Agent。

用一個場景感受五個元件如何在 Agent OS 裡協作：凌晨三點，監控告警透過 webhook 路由到維運 Agent → ReAct 迴圈啟動 → 在沙箱裡執行 log_query 工具 → 發現 OOM，並在長期記憶裡查到過去同類事件的緩解做法 → 執行 restart_service → 用 Notify 推送到企業通訊軟體。整件事無人值守、資料不出內網、每一步可審計，而且這次事故被寫進長期記憶，下次更快。這條路徑就是 OryxOS 這條線要往下走的地方。
