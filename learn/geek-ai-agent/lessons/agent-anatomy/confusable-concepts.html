Step 4/5 · Agent 五元件與真偽判別

學習目標

能分辨 Agent 與 LLM（元件 vs 整台機器）、聊天機器人（拿掉 Tools 與 Loop 的 Agent）、工作流（確定性流程 vs 探索性迴圈）的差別，並用「有沒有自主決策迴圈」這個缺席測試判斷一個系統是不是真 Agent。

一組最常見的混淆

先把三組最常被混為一談的東西並排看清楚。這三組的答案，其實都指向同一個元件：Loop。

Agent vs LLM：零件與整台機器

LLM 是 Agent 的其中一個元件——決策引擎；Agent 則是包含 LLM、Tools、Memory、Loop、Environment 的完整系統。用電腦打比方：LLM 是 CPU，Agent 是整台電腦。你不會說「我買了一顆 CPU」等於「我買了一台電腦」，同樣地，也不該把「用了 LLM 的程式」直接叫 Agent。這個區分是後面所有判別的基礎。

Agent vs 聊天機器人：拿掉兩塊的 Agent

傳統聊天機器人就是把 Tools 與 Loop 拿掉之後的 Agent：它只有 LLM 與對話歷史，你問一句它答一句，不會自己決定去查資料、去改檔案、去再試一次。反過來說，當同一個對話視窗接上了 Code Interpreter（能寫並執行程式碼的工具），它就補回了 Tools 與 Loop，從聊天機器人升級成 Agent。這也是判別 ChatGPT 的關鍵：沒有工具與迴圈的 ChatGPT 是聊天機器人，加上 Code Interpreter 才是 Agent。

Agent vs 工作流：確定性 vs 探索性

工作流（workflow）的步驟是事先定義好的，A 完做 B、B 完做 C，結果可預期；Agent 的下一步不是寫死的，而是每一輪由模型根據當前狀態自己決定，所以本質是探索性的。兩者的差別用一句話概括：

工作流是預先定好的流程，Agent 是探索性的迴圈。

「每天早上定時把天氣寄成 email」是典型的工作流——步驟固定、沒有自主決策。要注意的是，這不代表工作流比較低級：很多平台（例如 Dify）同時提供工作流節點與 Agent 節點，兩者各有適用場景；而且工作流可以被包成一個工具，讓 Agent 在需要時呼叫它。工作流是 Agent 可以使用的零件，不是 Agent 的競爭對手。

缺席測試：有沒有自主決策迴圈

把上面三組收斂成一個動作——檢查那個系統有沒有自主決策迴圈。這是判斷真偽的核心測試：

系統有自主決策迴圈？判定
直接問答的聊天視窗沒有聊天機器人
固定步驟的自動化流程沒有工作流
只把 LLM 包一層的 API沒有LLM 包裝
能自己選工具、看結果、再決定下一步有Agent

這個測試的好處是：你不必先知道它用了什麼模型、哪個框架，只要問「它的自主決策迴圈在哪裡」。找不到，就不是 Agent——不管行銷文案怎麼寫。
