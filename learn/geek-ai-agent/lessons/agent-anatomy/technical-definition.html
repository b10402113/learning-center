Agent 的技術定義

Step 1/5 · Agent 五元件與真偽判別

學習目標

能說出 Agent 的技術定義（感知環境、自主決策、行動、靠回饋迴圈迭代），並解釋為什麼這個定義刻意不提 LLM——「用 LLM 做的」不等於「Agent」。

先想：為什麼需要一把尺

「Agent」這三個字在 2026 年已經被用爛了。一支會呼叫 API 的 Python 腳本叫 Agent、把 ChatGPT 包進去的聊天視窗叫 Agent、固定每天早上寄信的自動化流程也叫 Agent。詞被濫用的結果，是它失去了判別力——你沒辦法再用「它是不是 Agent」來決定要不要投入。

所以要先把詞放一邊，問一個更硬的問題：從技術上看，一個東西要具備什麼，才夠格叫 Agent？先有定義，才有判準。

一句話定義，五個字都要算數

Agent 是一個程式：它感知環境、自主決策、採取行動，並靠回饋迴圈不斷迭代。這句話裡每個詞都不是修辭，而是要拿來檢查的條件：

要素它在問什麼反例（缺這項就不算）
感知環境它拿得到外部世界的狀態嗎？只能讀使用者打的一行字，看不到檔案、網路、資料庫
自主決策下一步是它自己選的，還是被寫死的？流程圖規定 A 完做 B、B 完做 C
採取行動它真的能改變外部世界嗎？只輸出文字，什麼都動不了
回饋迴圈行動的結果會回到它身上、影響下一步嗎？一次性輸出，結果再也不看
迭代它能重複這個循環直到達成目標嗎？問一句、答一句，結束

定義裡為什麼沒有 LLM

關鍵在最後這個觀察：這個定義從頭到尾沒提「LLM」。這不是疏漏，是刻意的——Agent 比 LLM 老得多。強化學習（RL，Reinforcement Learning）訓練出來的 Agent、遊戲裡會追著玩家跑的 NPC，全都符合上面的定義，而它們跟語言模型一點關係都沒有。

那 LLM 扮演什麼角色？它把工程門檻拉低了。以前要讓機器「自主決策」，你得自己設計狀態機、獎勵函數、訓練流程；現在你把任務用自然語言丟給 LLM，它就能規劃、選工具。所以正確的說法是：LLM 讓做 Agent 變便宜了，但「用 LLM 做的」不構成 Agent 的本質。一個把 LLM 包一層、問一句答一句的聊天視窗，同樣沒有資格叫 Agent。

「用了 LLM」是實作細節，「有沒有自主決策迴圈」才是本質。把這兩件事混在一起，是這個詞被濫用的根源。

這個定義能拿來幹嘛

有了這句定義，你就得到一把不隨技術潮流漂移的尺：不管明年流行的是新模型、新框架還是新協定，你都可以拿這五個條件去檢查一個系統。接下來的四步會把尺的刻度做細——先看五個元件（Step 2），再放大看迴圈（Step 3），然後用它分辨真偽（Step 4），最後拿去拆真實產品（Step 5）。
