五元件拆解

Step 2/5 · Agent 五元件與真偽判別

學習目標

能用 LLM（決策引擎）、Tools（行動能力）、Memory（狀態載體）、Loop（循環執行）、Environment（互動目標）五個元件拆解任何一個號稱 Agent 的系統，並說出每個元件負責什麼、少了它會怎樣。

把定義展開成骨架

上一歩的定義講的是「Agent 會做什麼」；現在要問「它由什麼組成」。把任何一個 Agent 系統拆開，零件永遠是這五個：

Agent = LLM + Tools + Memory + Loop + Environment。再加上一個把前四者串起來的迴圈，就是完整的技術骨架。這不是某個框架的設計，而是一把可以套用到任何系統的拆解鏡頭——再複雜的系統，複雜的也只是每個元件裡做得更深，不是多出第六個元件。

五個元件各負責什麼

元件角色具體內容少了它會怎樣
LLM決策引擎理解任務、規劃、挑工具與參數、解讀結果、判斷是否完成沒有大腦，不知下一步做什麼
Tools行動能力本地檔案、網路、資料庫、系統指令、MCP 工具只能輸出文字，動不了世界
Memory狀態載體短期脈絡（context）＋長期（結構化／向量／混合）每一輪都失憶，只是個工具而非助手
Loop循環執行ReAct 的決策—行動—觀察反覆進行問一句答一句，沒有自主性
Environment互動目標檔案系統、網路、資料庫、使用者介面、其他 Agent沒有施展能力的舞台與邊界

LLM 只出命令，執行動作的不是它

要特別澄清一件事：LLM 在 Agent 裡只負責輸出結構化的呼叫意圖——「我要呼叫 read_file，參數是 README.md」。真正去讀檔、去執行的是外面的框架。把 LLM 想成出主意的人，工程層才是動手的人。

Tools 的邊界就是自主的邊界

一個 Agent「能自主到什麼程度」，等於「你給它多少工具」。只給唯讀查詢工具，它就是個顧問；給了寫檔、送信、下單的工具，它的行動後果才真的發生。MCP（Model Context Protocol）的價值就在這裡：它把「工具怎麼接」標準化，工具就能像插件一樣插拔。

Memory 分短期與長期

短期記憶是當下的對話脈絡（context），這是必要的；長期記憶是跨session 留下來的知識——結構化資料、向量檢索或兩者混合，這是進階的。判斷標準很簡單：沒有 Memory 的 Agent 不是助手，只是工具——它每次都要你從頭講一次。

Environment 決定能力上限與安全底線，Sandbox 是它的安全設計

環境是 Agent 存在的容器：它能碰哪些檔案、連哪些網路、操作哪個資料庫。這既是能力上限，也是安全底線。當你限制它能碰的範圍，這個「限制」的工程實作就是Sandbox（沙箱）——它是 Environment 這一元件在安全面向的設計。

走一遍：翻譯 README 怎麼用到全部五個元件

用一個最小任務把抽象架構變具體：「讀取 README → 翻譯成中文 → 寫出 README.zh.md」。

回合元件參與發生什麼
任務進入Environment → Memory使用者指令經環境進來，被存進當下脈絡
第 1 輪LLM → Tools → ObservationLLM 決定呼叫 read_file，框架讀到 README 內容並回填
第 2 輪LLM（無工具）LLM 自己把內容翻譯成中文——不是每一輪都要叫工具
第 3 輪LLM → Tools → ObservationLLM 呼叫 write_file 寫出 README.zh.md
第 4 輪LLM → 結束LLM 判斷任務完成，迴圈停止

這個只有五個零件的小結構，就是所有複雜 Agent 系統的原型：再大的系統，都只是把這五塊各自做深、做強。
