Demo 二：目錄帶子指令的每日科技日報

Step 2/6 · Demo 與發布

學習目標

能說明把長篇排版規範放進目錄子指令、用 read_file 按需載入的做法，並解釋為何一份 seed 進長期記憶的偏好能讓之後每天的日報都把 AI／晶片排前面。

光桿 AGENT.md 不夠用時，多出來的那一層

天氣 Agent 只需要一句話 body 就夠了，但日報不一樣。日報有一份很長的「組稿排版規範」：要挑幾則、每則怎麼寫、怎麼排序、開頭要不要總覽。如果把這整份規範直接塞進 AGENT.md 的 body，它就會天天佔著系統提示的一大塊，而且大部分時候根本用不到——只有真的要組稿那一步才需要它。

解法是把規範從 body 搬出去，放進 Agent 目錄底下的 skills/digest-format.md，body 只留一句「組稿的時候去讀它」。Agent 在需要的那一刻才呼叫 read_file 把規範載進來。這個做法叫漸進式揭露（progressive disclosure）：能力都在同一個目錄裡，但只在對的時候曝光對的部分，平常不佔上下文。

先解決「新聞從哪裡來」

日報要有新聞來源，有兩條路，選哪條決定了 Demo 的風險落在誰身上。

路徑一（預設，穩）：用內建的 http_get 去打一個免金鑰、回 JSON、穩定的新聞源，讓 LLM 自己挑選與重組。只要把該網域加進 http.allowed_domains 白名單就好，整個過程沒有外部行程，Demo 的命運握在你自己手上。

路徑二（MCP 練習，險）：在 .oryxos/mcp_servers.yaml 宣告一個新聞 MCP server，然後用 oryxos tool list 確認它的工具真的註冊進來。要走這條路，就得事先自己寫好、驗證過一個最少幾十行的 news-mcp，不要臨時去賭社群 server。原因很實際：連不上的 MCP server 只會被 WARN 跳過（這是第二十八節的既有行為），不會讓整個啟動失敗——也就是說，日報會直接啞掉，而你一時還找不到原因。

播種一個跨日生效的偏好

接下來用一句話把偏好種進長期記憶。對任何一個 Agent 說「以後幫我關注科技新聞的話，我更關注 AI 和芯片方向」，模型就會呼叫 save_memory 把它存起來。這一步的價值不在當下，而在之後每一天：日報組稿時會讀到這個偏好，於是把 AI 與晶片的條目排到前面。這正是記憶從「當次對話」跨到「跨日累積」的兌現。

寫出這個目錄

整個 Agent 目錄是 .oryxos/agents/daily-tech-digest/，只有兩個 Markdown 檔，零 Java。AGENT.md 的 frontmatter 是這樣：

---
name: daily-tech-digest
provider: deepseek/deepseek-chat
tools: [http_get, read_file, notify]
schedules:
  cron: "0 0 9 * * *"
  zone: Asia/Shanghai
  message: 到点了，按你的说明执行。
---

跟天氣 Agent 相比，tools 多了一個 read_file——不是隨便加的，而是因為它要讀 skills/digest-format.md 這份子指令。body 描述的流程是：抓新聞 → 讀子指令取排版規範 → 依記憶偏好決定優先順序 → 通知。

子指令 skills/digest-format.md 裡放的是真正的排版規範：挑 5 到 8 則重要新聞，每則一行，寫成「標題＋一句評論＋連結」，依重要性排序且偏好優先，開頭加一段總覽，結尾不加口號。這些細節如果寫在 body，每天都會佔用系統提示；放進子指令，就只有組稿那一刻才被載入。

還有一個容易漏的 Sandbox 前提：file.allowed_paths 必須涵蓋 .oryxos/agents/daily-tech-digest/。不然 read_file 連自己的子指令都讀不到——白名單不認目錄，再正確的設計也動不了。

對賬時，比天氣多盯兩件事

日報的除錯流程和天氣一樣（先推再看時鐘），但對賬時要多確認兩個地方，因為它們是這個 Demo 獨有的機制：

  • 子指令真的被按需讀取：tool_invocations 裡要能看到一筆對 skills/digest-format.md 的 read_file 呼叫。這是漸進式揭露確實發生的證據，而不是規範被偷偷塞進了系統提示。
  • 偏好真的生效：產出的日報要把 AI／晶片條目排前面。手動推一次看不出這點的全部價值，要連續兩天都對，才證明記憶是跨日累積、穩定生效的。

驗收硬指標因此是：零 Java、MCP 工具確實註冊（若走路徑二）、日報內容反映記憶偏好。這裡的核心觀念是「能力在目錄裡、曝光在需要時」——同一份子指令，放錯位置是負擔，放對位置就是彈藥。
