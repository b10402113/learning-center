Loop 五要素

Step 2/5 · Loop Engineering

學習目標

能列出 Loop 的五個要素，並說出前兩者決定迴圈能不能轉、中間兩者決定安不安全、最後一者決定可不可信。

先問：一個能用的迴圈，缺一樣會怎樣

不是任何「反覆執行」都叫 Loop Engineering。讓 AI 一直跑、一直改，如果沒有任何東西告訴它「這樣對不對」，那只是在高速地放大錯誤。所以要設計一個可用的迴圈，得先問：它至少要具備哪些零件，才會轉得動、而且值得信任？答案是五個。

五個必備要素

要素它在解決什麼缺了它會怎樣
可判目標（Judgeable goal）任務有沒有清楚的完成定義不知道何時算做完，迴圈沒有方向
可驗證的判官（Verifiable judge）有沒有一個自動機制說「對／錯」迴圈盲目地轉，錯誤被快速放大
隔離工作區（Isolated workspace）AI 改壞了能不能不影響主線一次亂改就污染真正的程式碼
邊界與停止（Boundaries / stop）什麼不准做、什麼時候必須停無限迴圈、越界修改、失控
人類檢查點（Human checkpoints）哪些關鍵決定必須由人拍板產出没人敢收，可信度歸零

五個要素分成三組作用

這五個不是並排的清單，而是三組不同性質的保障：

  • 前兩者決定「迴圈能不能轉」——目標可判、結果可驗，迴圈才有前進的依據。沒有這兩樣，它根本轉不起來，或只是空轉。
  • 中間兩者決定「安不安全」——隔離工作區與邊界／停止，確保即使 AI 做錯，災難也被限制在一個可收拾的範圍內。
  • 最後一者決定「可不可信」——人類檢查點把關那些「自動驗證測不出來、但錯了很貴」的判斷，讓產出真的能被收下。

一句話記：目標與判官讓它轉，隔離與邊界讓它安全，檢查點讓它可信。五個都是必需品，缺一個就不是完整的迴圈。

最常被跳過的是判官

實務上，五個要素裡最常被省略的是判官。很多人急著讓 AI 跑起來，卻沒有先設計「怎麼判定它做對了」——自動化測試、型別檢查、編譯、lint、CI。結果是：迴圈轉得飛快，卻是在盲目地轉，錯誤被同樣飛快地放大。沒有判官的迴圈，只是一個加速犯錯的機器。

反過來說，判官的品質決定迴圈的成敗。每一個回合都需要有東西能說「這是對的，或這是錯的」，AI 才有修正的依據。這也正是為什麼 Loop 會自然綁上TDD（測試驅動開發）：先有會失敗的測試，再讓實作追著把它變綠。你事先設計的驗證品質有多好，迴圈能放大的就有多好——它只會放大你設計的驗證，不會無中生有。

迴圈是擴音器：你先把「什麼叫對」設計得多清楚，它就能把這份清楚放得多大。判官模糊，迴圈只會把模糊放大。

Harness 的三個面向

判官不是憑空長出來的，它住在 Harness 裡。實務上 Harness 有三個面向，共同構成迴圈的工作台：

面向具體內容對迴圈的意義
程式碼規範結構、命名、分層、lint讓每次產出的形狀一致，減少來回修
安全紅線不准硬編密鑰、用環境變數、不得越權防止 AI 用「能跑就好」的方式繞過安全
驗收判官單元／整合／CI 測試迴圈唯一的裁判，決定能不能停

Harness 決定你要重工幾次。公開、共通的部分做一次（例如全專案的規範與安全紅線），各功能區塊再各自帶上自己的驗收——這樣判官既一致又貼身。

把 Loop 當成要管理的對象

還有一層視角：當 Agent 能自主跑上數十步，迴圈本身就變成一個需要被管理的東西。管理它有三根槓桿——控制粒度（一次讓它做多大）、檢查點（在哪裡停下來看）、回滾（錯了怎麼退回）。這三根槓桿的價值在於：你能讓它跑長任務，又能隨時停下來檢視、並把錯誤退回去。這是三個方法論支柱中年紀最輕、工具仍在成形的一塊。
