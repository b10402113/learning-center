為什麼是 Loop

Step 1/5 · Loop Engineering

學習目標

能說出 Loop Engineering 的定義與它真正解決的問題（確信感），並解釋為什麼人只從「執行」退守、從不從「判斷」退守。

先想：一個人做專案，最貴的成本是什麼

假設你自己一個人做一個後端元件。沒有 QA、沒有 code review、沒有同事可以接手。這時候卡住你的通常不是「打字不夠快」——現在 AI 已經能很快吐出程式碼。真正讓你睡不著的是不確定感：這東西什麼時候能交？它到底對不對？要重工幾次？

這三件事合起來叫確信感（certainty）。對一人公司或超級個體（OPC，One-Person Company）來說，缺少的正是確信感——沒人幫你驗、沒人幫你擋，於是「我怎麼知道它是對的」變成最大的成本。Loop Engineering 要解的就是這個問題：它不是讓你寫得更快，而是讓 AI 在一個能自己判定的迴圈裡工作，把確信感生產出來。

從「下指令」到「設計迴圈」

傳統用法是：你打一句指令，AI 回一段，你再打下一句。整條路徑由你一步一步推著走——你是驅動者。Loop 的用法換了一個位置：你先設計好一個環境與規則，讓 AI 在裡面自主地「做 → 測 → 修」反覆跑，只在關鍵點才介入。你從驅動者變成設計者。

這個轉變的重點在注意力搬家：過去你的精力花在寫提示詞、糾正 AI 的每一步；現在精力搬到「設計那個讓它自己跑起來的環境」。那個環境與規則，就是 Harness。你甚至可以離開座位，迴圈仍會繼續跑——因為判定對錯的機制已經內建在環境裡，不需要你在場一句一句餵。

一句話定義 Loop Engineering：設計一個有判官、能自己跑的迴圈，讓工作在你不在場時仍然完成。執行交給迴圈，判斷留給人。

人類退守的模式：只退執行，不退判斷

把這幾年拉成一條線，會看到一個清楚的模式：

階段人的角色退守的是什麼
2023 Prompt Engineering把話講清楚，讓模型輸出對的東西退掉「自己動手寫」
2024 Agent orchestration安排 Agent 調工具、串流程退掉「自己逐步操作」
2026 Loop Engineering設計環境與規則，讓迴圈自己跑退掉「自己在場盯著每一步」

看起來人一直在往後退，但退的永遠只是「執行」。有三件事從第一天到現在都沒退過：定義目標（要做什麼、什麼叫完成）、設定規則（邊界在哪、不准做什麼）、判斷結果（這東西能不能收）。所以 Loop 不是讓人閒下來，而是把人升級：從執行的工人，變成迴圈的設計者與驗收的判官。

這條 node 要帶你去哪

這一步只建立了動機與定義。接下來四步會把「怎麼設計這個迴圈」拆開：Step 2 講五個必備要素，Step 3 講最脆弱的判官與防作弊，Step 4 講實際跑一輪的循環、停止條件與任務卡，Step 5 把 Loop 放回 SDD 與 Harness 的三層關係，並劃出「什麼交給迴圈、什麼永遠留給人」的邊界。
