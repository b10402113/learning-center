何時該加哪一道

Step 6/6 · Harness Engineering

學習目標

能依任務風險與熟悉度決定要加哪幾道 Harness，並用 Superpowers（Skills 強制流程）與 Hermes（自主技能與記憶）校準自己對 Harness 的判斷。

選型：依風險與熟悉度決定加什麼

六個工具不是清單，是選項。真正要練的判斷是：這個任務該加哪幾道？兩個維度決定一切——任務有多熟、做錯的代價有多大。

情境建議加的工具理由
熟悉的增量、小改動CLAUDE.md + Skill已能覆蓋約八成需求，其他工具只是拖慢
不熟悉、有風險、第一次做再加 Plan Mode方向未定，先把計畫對齊再動手
會碰禁區或不可逆操作再加 Permission用規則把高代價動作擋在門外
長時間、你不在場再加 Hooks沒人盯著時，機器替你驗證結果
大型、多模組、可切分再加 Subagents隔離上下文，避免越做越笨

從 CLAUDE.md 起步的三步落地

不用一次全上。最務實的順序是：

  1. 先寫一份最小 CLAUDE.md——半小時就能完成，投報率立刻出現。
  2. 選一個 SDD 模式——讓目標先清楚，Harness 才有東西可約束。
  3. 增量加工具——依序補上 Hooks、Permission、Subagents、Plan Mode、Skills。

這個順序的原則是：先建立上下文，再約束目標，最後才是能力槓桿與防線。工具不是越多越好——克制是工程師的態度。每一道防線都增加了摩擦，只有在它擋下的風險值得這份摩擦時，才該加上去。

為什麼是 SDD 加 Harness 這一對

方法論很多，但被選中的判準是三個：成熟度、可教學性、覆蓋完整工程流程。Vibe Coding 是一種態度而非方法；Context Engineering 尚未標準化；ReAct／TAO 太窄；TDD 是其中一步；Plan-then-Execute 已被 Plan Mode 涵蓋。SDD 與 Harness 剛好一個管目標、一個管邊界，合起來才是閉環。

業界範例一：Superpowers——把紀律變成會自動觸發的 Skills

Superpowers 是一個「agentic skills 框架」，同時也是一套開發方法論。它把「一個認真的軟體工程師該做什麼」打包成 Skills，並強制嵌入 AI 的工作流。它的判斷很明確：它不是 SDD 工具，而是一套給 agent 用的工程紀律框架。

它內建約 20 個核心 Skill，涵蓋 brainstorming、writing-specs、writing-implementation-plans、subagent-driven-development、tdd、debugging-systematically、root-cause-analysis，以及用來寫新 Skill 的元技能 writing-skills。這些 Skill 靠 description 比對自動觸發，不是你要手動挑模板。

一次跑通的工作流

  1. 你只丟一句需求。
  2. brainstorming 先問「為什麼、要達成什麼」，再問「怎麼做」。
  3. writing-specs 把規格拆成 5–20 個可逐塊簽核的片段。
  4. writing-implementation-plans 產出「以分鐘計」的任務，每個都附精確檔案路徑與指令。
  5. subagent 在隔離的 worktree 裡執行，事後做兩段審查：先驗規格符合度，再驗程式品質。
  6. 收尾——合併、開 PR、保留或捨棄，並清理 worktree。

它用五元件拆解時只動了兩塊：Memory（一個大型的工程方法論 Skills 庫）與 Loop（一套強制、每階段有通過條件的流程），其餘三個元件照用。這帶來可攜性與解耦——也解釋了它為什麼能跨多種 agent 通用。它的代價是：對小事很慢、對小專案過度工程、學習曲線不短。工程哲學是「慢即是快」——流程看似慢，總時間差不多，但產出是真的能用，而不是還要再修一輪。

業界範例二：Hermes——讓 agent 自己維護自己的 harness

如果 Superpowers 是「人被動地把紀律安裝給 AI」，Hermes Agent 則是相反方向的極致：agent 自己維護自己的 harness。

它的核心是一條閉合學習循環：agent 自己整理長期記憶（MEMORY.md 與 USER.md，並注入系統提示詞）、自主創建技能、在使用中自我改進技能，還有一個自主的 curator 定期整頓。這正是 Harness 的思路推到極致——約束與能力不再由人寫死，而是由 agent 在運行中長出來。它與 OryxOS 的對照價值在於：一邊是企業可控的固定底座，一邊是個人長期演化的工作夥伴。

收束：工具會換，工程紀律不會

Superpowers 和 Hermes 都可能在幾年內被別的產品取代。但它們在示範的事不變：真正稀缺的不是工具，而是把工程紀律安裝進 AI 工作流的能力。Harness 六工具與三道防線就是你手上的那組安裝工具——知道每個工具擋下什麼、什麼時候該加哪一道，比背下某個工具的指令更重要。
