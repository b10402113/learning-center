專案規則與能力槓桿

Step 3/6 · Harness Engineering

學習目標

能寫出一份堪用的 CLAUDE.md（含四大區塊），並說清 Skill 是什麼、SKILL.md 如何組成、Capability Uplift 與 Encoded Preference 的差別，以及何時該自己沉澱一個 Skill。

CLAUDE.md：AI 每輪都會讀到的專案手冊

你一定遇過這種場景：每次開新對話，都要重新跟 AI 解釋「這個專案用什麼框架、怎麼跑測試、不要碰哪個目錄」。講一次兩次還行，講第十次就變成純浪費。

CLAUDE.md（在其他工具裡叫 AGENTS.md、.cursorrules）就是解這個問題的檔案：放在專案根目錄，AI 每一輪都會自動載入。它不是寫給人看的設計文件，而是寫給 AI 的專案手冊。

區塊寫什麼
專案概述這個專案是什麼、技術棧、架構分層的一句話摘要
執行指令怎麼建置、怎麼跑測試、怎麼啟動——直接可複製的指令
程式規範命名、註解、錯誤處理、提交訊息等團隊約定
禁區絕對不能碰的檔案、目錄、指令或設定

關鍵在於它會隨專案一起長大。不要一開始就想寫完，先寫一個半小時能完成的極簡版本：概述三行、指令五條、規範三條、禁區兩條。它的投報率是即時的——因為它是每一輪對話的第一份上下文，AI 從第一步就站在你的專案裡，而不是站在它的預設值裡。

Skills：把「怎麼做」封裝成可重用的能力

CLAUDE.md 解決的是「AI 知不知道你的專案」，Skills 解決的是「AI 會不會做某件事、做得像不像你」。

一個 Skill 可以想成「流程沉澱 + 工具調用」，也就是一份 SOP 加一個工具箱。它是一個目錄，核心是一個 SKILL.md：開頭是 YAML frontmatter（name 與 description），下面是 markdown 寫的操作指引。標準結構包含五塊：用途、觸發時機、工作流程、約束、範例。

它跟其他機制怎麼分工

機制負責什麼
MCP工具供給側——把外部工具接進來
Skills行為標準——定義怎麼用這些工具把事做好
Subagents任務分派——把子任務丟到乾淨的 context 執行
Plugins打包——把一組能力封裝成可安裝的單位
Commands顯式入口——由你手動觸發的指令

漸進揭露：為什麼裝很多 Skill 也不會爆 context

Skill 採用三層漸進揭露（progressive disclosure），只有在需要時才把細節載入：

層內容成本
第一層metadata（name + description）約 100 tokens，常駐
第二層SKILL.md 內文被觸發時才載入
第三層references / scripts 等附件真的用到才讀

這也解釋了為什麼 Skill 格式能跨 8 種以上工具通用——它是一套開放標準。

兩類核心價值

每個 Skill 的價值型態不同，判斷它是哪一類，你才知道該不該裝：

型態它改變什麼例子
Capability Uplift（能力提升）讓 AI 學會做「原本做不到的事」，通常帶外部工具或專門知識PDF 處理、Firecrawl 抓網頁
Encoded Preference（偏好編碼）AI 本來就會做，但要它「照你的方式做」——通常只有文字約束前端設計規範、React 最佳實踐

選擇時要按你的場景挑，而不是按熱度挑。同一個 Skill，對別人是能力提升，對你可能只是偏好編碼。

什麼時候該自己沉澱一個 Skill

三個訊號出現任一個，就值得寫：

  • 同一件事你已經做第三次了；
  • AI 對某個任務一直做錯，每次都要糾正；
  • 這個模式跨專案、跨團隊都會用到。

寫的時候，description 是最關鍵的一行：它要同時講清楚場景、關鍵詞與邊界，長度控制在 50–200 字。description 寫得好，Skill 才會在對的時機被自動叫用。name 與 description 之外，把內文分層：SKILL.md 放核心流程，長範例、腳本、參考資料放到附件目錄。

存放位置有三層：個人層（~/.claude/skills/）、專案層（專案內的 .claude/skills/）、團隊層（獨立 repo）。先放個人層試，成熟了再往上升。

常見反模式

  • 把 SKILL.md 當手冊寫，塞一堆背景知識——它該是操作指引，不是教材。
  • Skill 內容與 CLAUDE.md 重疊——專案規則放 CLAUDE.md，流程能力才是 Skill。
  • 只裝不讀——沒讀過 SKILL.md 就裝，你根本不知道它會讓 AI 做什麼。
  • 同時裝好幾個相似 Skill 來「比較」——它們會互相干擾。

下一個步驟，我們把視角從「AI 知道什麼、會什麼」轉到「AI 在哪裡做、什麼時候做」——也就是 Subagents 與 Plan Mode。
