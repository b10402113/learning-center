五大能力

Step 2/5 · OryxOS 需求

學習目標

能逐一說出五大能力各自解決什麼問題、核心階段做到哪個程度、又把什麼推遲到擴展階段，並解釋這五個能力如何互相供養。

為什麼是這五個，而不是別的

把任何一個 Agent 系統拆開，零件永遠是那幾塊；OryxOS 只是把它們做成一個企業底座該有的樣子。核心階段只做最短可跑的一條鏈，剛好是五個能力：

能力它在回答什麼問題類比
Provider要用哪個模型、怎麼呼叫它引擎的燃料供應
ReAct 迴圈Agent 怎麼一步步想與做心跳
Memory怎麼記住上一輪與上一次記憶
Tool 體系怎麼真的動手做事手腳
Web Service外部怎麼叫它對外窗口

能力一：Provider 抽象

Provider 把「呼叫一個模型」收斂成一個介面，用 Spring AI Alibaba 的 ChatClient 連接器去接各家模型。每個 Provider 有一組基本屬性：名稱、模型、API key、選填的 base URL；Profile 只用 Provider 名稱來引用它。

核心階段的取捨很克制：不做失敗降級與競速（hedge racing），模型出錯就往上拋；成本透明也只做基本盤——把 tokens、Provider、模型記進日誌。而 Provider 之所以排第一，是因為模型迭代的速度遠快於業務程式碼；把它做成插件，換一家供應商就不用動上層業務。

能力二：ReAct 迴圈

ReAct 迴圈是 Agent 的大腦，核心演算法就是 Reason + Act 反覆進行：把訊息附加進上下文 → 組裝 prompt → 呼叫 LLM → 如果 LLM 要呼叫工具，就執行工具並把結果附加回去 → 再問 LLM，直到它給出最終回覆或撞到最大迭代次數（預設 10 次）。

loop (max 10):
  resp = llm(prompt)
  if resp.hasToolCall:
      result = execute(resp.toolCall)
      context.append(result)
  else:
      return resp

這段核心迴圈只有幾十行，而且自己手寫、不用框架黑盒。核心階段刻意不做的事：工具呼叫是循序的（不並行）、不做上下文壓縮、不做子 Agent 委派。最大迭代次數可在 Profile 覆寫。真正的工程重點不在演算法，而在可觀測性——每一輪的 Reason / Act / Observe 都要留下痕跡。

能力三：Memory 三層記憶

設計上規劃了三層，但核心階段只做兩層：

層核心階段做法
會話記憶做存 SQLite，用 channel + user + profile 定位；超出上下文視窗就截斷
長期記憶做就是一個 MEMORY.md 檔案；靠 save_memory / recall_memory 兩個工具寫入與召回，啟動時注入，約 4000 字上限
情景記憶推遲核心階段不做

注意長期記憶在核心階段是一個檔案，不是一張資料庫表。也不做自動事實抽取、語義檢索、Memory Wiki、矛盾偵測。這裡的判斷標準很樸素：先讓 Agent「記得住上一句話」，跨會話的智慧留到後面。過度設計記憶比沒有記憶更糟——它會污染上下文。

能力四：Tool 體系

工具分成兩類。一是內建工具：檔案讀寫與列目錄、帶白名單的 Shell、HTTP get/post、save_memory / recall_memory。二是Plugin Tool，依成本分三級：

級別形式什麼時候用
第一級零程式碼：SKILL.md + MCP能用現成能力解決就優先用這級
第二級輕程式碼：自寫 MCP server需要一點客製邏輯時
第三級重程式碼：Java @Tool Bean要深度接進企業系統時

選擇標準是能用第一級就別用第二級，能用第二級就別用第三級。安全上，核心階段靠應用層白名單（路徑、指令、網域三類檢查）擋住越權，不啟用 SecurityManager；完整的 Tool Policy 與容器沙箱留到擴展階段。

能力五：Web Service

Web Service 把引擎變成 REST 介面。核心階段先做 10 個端點，涵蓋六類操作：

  • Session：建立、送訊息、取歷史、歸檔
  • Agent：直接 invoke
  • 查詢：profiles、memory、tools
  • 維運：health、info

另外 15 個端點推遲。核心階段不做認證（預設跑在內網）、不做 SSE / WebSocket / RBAC。它能支援的整合場景包含：同步呼叫、保持 session 的對話、webhook 觸發、跨語言呼叫。至於渠道，核心階段只有 CLI Channel（oryxos chat）；企業 IM（企業微信、飛書、釘釘、Slack）留到擴展階段，而且屆時是去呼叫 Web Service，不是重寫 Agent 邏輯。

五個能力如何互相供養

它們不是五個獨立模組，而是一條鏈：Provider 讓迴圈「有得想」，Tool 讓迴圈「能動手」，Memory 讓每輪「不必從頭」，ReAct 把前四者串成一個會自己迭代的過程，Web Service 再把整個過程開放給外界。缺任何一環，Agent 都會退化——沒有 Tool 只能動嘴，沒有 Memory 每次失憶，沒有 Provider 就沒有腦。
