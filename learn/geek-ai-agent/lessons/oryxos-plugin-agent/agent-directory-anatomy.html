一個 Agent 目錄長什麼樣：AGENT.md、scripts、skills、REFERENCE.md

Step 2/5 · 插件化 Agent 與動態管理

學習目標

能畫出一個 Agent 目錄的完整結構，並說出哪個檔案在什麼時機才進入上下文（progressive disclosure）。

用一個真實的 Agent 走一遍

抽象地講「一目錄一 Agent」不好懂。用一個貫穿全課的例子來看：每日對賬 Agent（daily-reconcile）。它每天早上比對交易庫與清算庫的訂單數與金額，產生一份分級報告，推到運維群。

這個例子特別值得看，因為它同時用到全部四種資源：主指令、腳本、子指令、參考檔案。目錄長這樣：

.oryxos/agents/daily-reconcile/
├── AGENT.md              # 主指令：frontmatter 是設定，body 是任務指令
├── REFERENCE.md          # 選用：欄位字典 + 已知可接受的差異
├── skills/
│   └── report-format.md  # 子指令：報告結構與分級規則
└── scripts/
    └── reconcile.py      # 腳本：確定性的抓取與比對邏輯

存放位置固定：`.oryxos/agents//`，而 `` 既是目錄名、也是這個 Agent 的唯一識別碼。

AGENT.md：frontmatter 是這個 Agent 的 Profile

AGENT.md 是核心，它分成兩半。上半是 YAML frontmatter，也就是這個 Agent 自帶的 Profile——身分、模型、能力、推送目標、排程時間，全部集中在這裡：

欄位作用
name唯一識別碼，等於目錄名
description一句話說明它是什麼
identity（agent_name／prompt／provider／model／temperature／tools）人設、用哪個模型、開放哪些系統能力，例如 [shell, read_file, notify, save_memory]
notify_channels跑完的結果往哪推
schedules{id, cron, zone, message}，例如 0 0 9 * * * 搭 Asia/Shanghai

這正好對上前面那條邊界：一個 Agent 把身分、模型、能力、推送、排程全帶在自己身上，所以以前那份獨立的 `.oryxos/profiles/` 設定就被移除了。排程從 Agent 自己身上長出來，不是另外設定的。

AGENT.md 的 body：只負責「編排」

下半是 body，也就是給 LLM 的任務指令。要注意的是：body 只做編排，不塞細節。它的內容大致是：

  1. 執行 python scripts/reconcile.py，拿到一份確定性的 JSON。
  2. 看 JSON 裡的 diffs 分支。
  3. 若出現差異，用 read_file 讀 skills/report-format.md，取得報告結構與 P0／P1／P2 分級規則。
  4. 若某個差異的分級不確定，再讀 REFERENCE.md。
  5. 最後 notify 推送，並 save_memory。

真正的報告規格、欄位定義、抓取邏輯，全都住在另外三個檔案裡。body 之所以能這麼薄，靠的就是漸進式揭露。

三個檔案，各自用到才進上下文

這是整個目錄設計的精華。同一個 Agent 內的四個檔案，進入 LLM 上下文的時機完全不同：

檔案何時進上下文靠什麼能力
AGENT.md body觸發時常駐系統提示ContextLoader 注入
scripts/reconcile.py用到時執行；只有輸出的 JSON 進上下文，程式碼不進shell／python
skills/report-format.md出現差異、要寫報告時才讀read_file
REFERENCE.md分級不確定時才讀read_file

關鍵在第二列：腳本執行完，進上下文的是結果，不是原始碼。這代表確定性的工作（抓資料、比對、算差額）不會消耗 token 去讓模型「重算一遍」，也就不會出錯。這是把「該用程式做的」和「該用模型判斷的」分開。

而這整件事完全不需要新的底層能力——它只用到底座既有的 read_file 與 shell。漸進式揭露不是一個新功能，而是一種用法。

腳本吐出什麼、報告如何分級

看具體內容會更清楚。範例腳本載入兩份匯出的 CSV，算出三類差異：missing_in_settle（清算庫缺）、missing_in_orders（交易庫缺）、amount_mismatch（金額不符），然後輸出一份 JSON，帶 date／counts／amounts／diffs。report-format.md 再定義分級：

級別條件處理
P0總差額 > 10000，或單筆差額 > 5000可能財務損失，立即處理
P1至少一筆 missing_in_settle當日查清
P2只有 missing_in_orders，或 0.01 的尾差觀察即可

一個 Agent 目錄，四個檔案合起來就是「一個完整、可執行的 Agent」。這裡的 daily-reconcile/ 是由 spec-kit 從課程素材生成的參考產物——課件是輸入，程式碼是被生成出來的。
