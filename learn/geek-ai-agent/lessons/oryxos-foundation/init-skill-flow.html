oryxos-init skill 做什麼

Step 4/5 · 工程地基（init skill）

學習目標

能描述 oryxos-init 的一份 SKILL.md 如何把十個初始化步驟壓成六個階段，以及 skill、constitution、CI、Spec-Kit 四者之間的分工。

先看壓縮的結果：十步重複動作 → 六個階段

上一課建立了「開發應該把可重複流程寫成 skill」的方法論。oryxos-init 就是這套方法論的成品：一個 SKILL.md，把過去要人工做十個步驟的初始化工程，壓成六個階段。這不是刪掉工作，而是把重複的動作整理成一條可重建的流水線：

骨架 → 日誌／監控 → HTTP／API → 代碼標準 → 安全檢查 → CI／驗證
階段內容
1. 骨架建立 Maven 多模組骨架（模組結構 + parent pom + oryxos-boot）
2. 日誌／監控裝結構化日誌與監控指標
3. HTTP／APIHTTP server、OpenAPI、統一回應與全局異常
4. 代碼標準Google 格式＋Alibaba P3C 兩層規約
5. 安全檢查SpotBugs / Find Security Bugs / PMD / OWASP 四件套
6. CI／驗證把前面所有檢查接進驗證流程，一鍵跑綠

一份 SKILL.md 如何裝下整套流程

skill 的主體就是一個 SKILL.md：用結構化的指令描述「每階段做什麼、驗收條件是什麼」。AI 讀到它就知道按順序執行，而不是靠人記得步驟或讓 AI 自由發揮。這解決了兩個問題：

  • 重複性——任何一次初始化都跑同一套，結果可重現。
  • 完整性——階段順序寫死，不會漏掉某一塊地基。

兩層標準：機械與規約分工

代碼標準這塊特別值得講。它分成兩層：

層級工具職責
機械格式化Spotless 套 Google 格式自動把所有程式碼格式化成同一種 style——不靠人記得
規約檢查Alibaba P3C檢查阿里巴巴 Java 開發規範的規則集——提醒團隊慣例

機械的事交給工具（格式），慣例的事也交給工具（規約），人只需要在規範選擇上有共識。

安全四件套：一條指令全上

安全檢查是「四件套」：SpotBugs、Find Security Bugs、PMD、OWASP 依賴掃描。它們各自盯不同面相——靜態 bugs、安全模式、自訂規則、已知 CVE——但被 skill 接進同一條驗證指令：mvn verify。跑一次建構，四種檢查全部執行，任何一個紅燈，建構就紅。

真正的分工：skill、constitution、CI、Spec-Kit 各做一件事

這一段是把整個 OryxOS 協作方式講清楚的關鍵。地基不是只有 skill 一件事，而是四個角色各司其職：

角色它做什麼
skill（oryxos-init）安裝——把地基裝好、把標準工具落地
constitution（憲法）釘死規範——寫明技術選型與不可違背的原則，之後所有實作都照它走
CI（持續整合）強制執行——每次提交自動跑檢查，規範被守死、不回退
Spec-Kit寫業務——地基完成後，把需求與技術方案轉成任務，開始寫五大能力

一句話記法：skill 安裝、constitution 釘死、CI 執行、Spec-Kit 隨後寫業務。地基階段的終點不是「裝完六塊」，而是「這四分工作各就各位，接下來可以安心寫業務了」。
