開源賽局：OpenClaw、Hermes 與它們留下的空白

Step 2/5 · 先看清別人做到哪，才知道缺口在哪

學習目標

比較 OpenClaw 與 Hermes 的定位與安全取捨，並指出兩者共同留下的三個空白，說明這為何是 OryxOS 的起點。

2026 年，這一層已經擠滿了人

在談兩個開源專案之前，先看大局。2026 年企業 Agent 平台已成兵家必爭之地：華為 AgentArts、阿里悟空與 AgentScope、字節 Coze／HiAgent、百度 AgentBuilder、騰訊元器全都進場。它們有個共同點——沒有人只賣模型，賣的都是「底座＋生態」，把 Agent 的運行、編排、治理包成一個平台。

它們的差異在路線：雲廠商從基礎設施往上蓋，平台玩家從應用生態往下長；一個賭「企業最終會自己跑 Agent」，另一個賭「先把量做起來，標準就是我的」。但不管哪條路線，都解決不了同一件事——企業自己那些差異化的流程、私有資料與治理要求。這正是自建底座的起點。

兩個最具代表性的開源專案

在這片賽局裡，開源側有兩個繞不開的名字。

OpenClaw：把個人體驗做到極致

項目內容
語言／授權Node.js／TypeScript，MIT
發布2025 年 11 月，由 Peter Steinberger 推出；作者 2026 年 2 月加入 OpenAI
規模約 24.7 萬顆星、25 個渠道、社群技能超過 13,729 個
定位個人／開發者優先，社群生態爆炸性成長
企業短板安全設計薄弱：曾有 CVE-2026-25253 一鍵 RCE，Cisco 評為「不可接受的資安風險」；身分、權限、審計、合規不是第一天設計，Tank OS 只是補丁

OpenClaw 證明了「一個人也能有一支 Agent 大軍」這件事有多迷人，但它的問題是結構性的：當安全與治理是事後補的，補丁永遠追不上開放生態帶來的攻擊面。

Hermes Agent：往企業方向探路

項目內容
語言／授權Python，MIT
發布2026 年 2 月，由 NousResearch 推出
規模約 13.5 萬顆星、18 個渠道
技術亮點三層記憶＋Honcho 12 層使用者建模；自演化 Curator 每 7 天對技能庫評分、合併、修剪；記憶寫入會掃描 prompt injection
企業短板多租戶只是切換 HERMES_HOME，不是 RBAC／SSO；審計得自己加；商業化靠 PTG 以 4 萬美元＋顧問費提供企業管理服務

Hermes 是「最接近企業」的開源選項，但它仍是個人到小團隊的定位——企業要的治理，還是得自己二次開發。

它們共同留下的三個空白

把兩者放一起看，缺口就非常清楚：

空白具體缺什麼
1. 完整企業治理多租戶 RBAC、SSO、審計、合規——是第一天設計，不是事後補丁
2. 深度企業 IT 整合與 ERP／CRM／CMDB／監控等既有系統的深度對接
3. Java 生態真空OpenClaw 是 Node.js、Hermes 是 Python，Java 在底座這一層完全缺席

注意第三點的分量。前兩點也許還有廠商願意補，但第三點是整個生態層級的缺位——這不是「做得比較差」，而是「根本沒有人站在那個位置」。

為什麼「空白」等於「機會」

三個空白不是拿來抱怨的，是拿來定位的。它們定義出一個不同象限：OpenClaw 服務個人，Hermes 服務小團隊，而嚴監管企業那個象限——Java、私有、day-one 治理——還沒有人認真佔住。

同樣是 Agent OS 這一類，但定位不同：OpenClaw 是個人級，Hermes 是小團隊級，留給企業級的位置是空的。

而且這個空白不是靠「更強的模型」能填的。治理、整合、生態是工程與設計問題，模型再強也不會自動長出 RBAC 與審計。

一個容易誤讀的地方

看到這三個空白，很容易得出「那 OryxOS 要打敗 OpenClaw 和 Hermes」的結論——這是錯的。它們是同一類，但不是同一場競爭：定位不同、服務對象不同，甚至在標準上可以互通（例如技能描述檔的開放標準）。真正的競爭對象不是這兩個專案，而是「企業願不願意把核心 Agent 交給一個不透明的黑盒」。

帶回自己

把清單對照回你公司：你的企業治理（RBAC、SSO、審計）現在是誰在管？你的 Agent 要接的 ERP／CMDB 是自建還是 SaaS？如果答案都是「還沒有」，那你不是在挑工具，而是在缺一層底座。這一課的價值，是讓你用「缺口」而不是「功能清單」來判斷一個 Agent 平台值不值得投入。
