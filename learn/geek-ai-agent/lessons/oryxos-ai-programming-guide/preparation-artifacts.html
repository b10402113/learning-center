準備階段：把既有文件餵成三份 artifact

Step 2/5 · OryxOS AI 編程指南

學習目標

能說出需求文件、技術方案、設計目標分別餵給哪個 Spec-Kit 命令，並列出三份 artifact 各自該長什麼樣。

核心心法：不要重寫，餵進去

OryxOS 最幸運的地方，是它的需求文件與技術方案早就寫好了。所以 Spec-Kit 在這裡的工作是轉換，不是重新發想。每一份既有文件，都有它對應的 Spec-Kit 命令與產出 artifact：

既有文件餵給哪個命令產出 artifact
需求文件/speckit.specifyspec.md：五個 user story
技術方案/speckit.planplan.md：技術棧、九個模組、關鍵決策、資料流
設計目標與關鍵決策/speckit.constitutionconstitution.md：不可協商的項目憲法
課程裡的五個 demo（併入 spec 的驗收標準）每個 user story 的驗收條件

這裡有一個必須守住的前提：務必餵最新版的技術方案。文件版本錯了，plan 就會按錯誤的模組數去拆——例如按十一模組而不是九模組拆，後面全部要重來。

先裝好工具：Specify CLI 加 Claude Code

環境準備兩件事：用 uv 安裝 specify CLI（需要 Python 3.11 以上），並設定好 Claude Code 作為主要 AI agent。跑一次初始化，工作區會生成 .specify/ 目錄與 .specify/memory/constitution.md 等占位檔。這一步的細節跟著官方文件走——Spec-Kit 版本迭代很快，指令細節會變。

第一份：constitution（憲法）

constitution 是整個專案的行為約束，而不是給人看的設計文件。它是寫給 AI agent 看的：AI 在 implement 階段會主動引用它，違反原則的方案會被擋下。

這份憲法把 OryxOS 的關鍵決策釘死成大約六到七條非協商原則，涵蓋：

  • 技術棧鎖定：JDK 21 加 Spring Boot 3.x 單體、Maven 多模組、單一執行檔（單一 binary），GraalVM 延後。
  • 五個核心能力優先：先做五能力，不要被周邊功能分心。
  • 自己實作 ReAct 迴圈：不用 Spring AI 的 Agent 抽象，自己寫（控制在約一百行內）。
  • Plugin Tool 三級制：零碼（SKILL.md 加 MCP）、輕碼（自寫 MCP server）、重碼（@Tool）三級都要有，且優先零碼。
  • 儲存固定：SQLite 加 Spring Data JPA 加 MEMORY.md 關鍵字檢索，向量檢索延後。
  • Audit（審計表）第一天就寫：不是功能做完才補。
  • 可跑優先於完美：每個 user story 都要有一個能跑起來的 demo。

其中兩條最容易被漏掉：Spring AI 只用一半（只拿它做協定轉換與 @Tool schema，關掉它的自動工具執行）與審計表第一天就要寫。憲法一旦寫定，AI agent 不得單方面修改；如果某條原則錯了，要停下來和人討論。

第二份：spec（五個 user story）

把需求文件餵給 /speckit.specify，產出 spec.md，內容是五個 user story。這裡有兩個容易搞錯的細節：

  • user story 的順序按依賴關係排，不是按重要性排。US-5（Web Service）排最後，是因為它依賴前四個，不是因為它不重要。
  • 不要標 P1／P2／P3 優先級。P1/P2/P3 的標法會讓人誤讀成「後面的可以選做」，而這裡的後排純粹是依賴使然。

驗收標準可以直接沿用課程裡那五個 demo。/speckit.clarify 是可選的，但強烈建議跑——它會逼你把 spec 裡的模糊點回答清楚，減少 plan 階段返工。

第三份：plan（實施計畫）

把技術方案加 spec 加 constitution 一起餵給 /speckit.plan，產出 plan.md：技術棧、九個模組各自的職責、關鍵決策、資料流。計畫生成後一定要人工複審，並且照著一份清單逐項檢查：

  • Memory 沒有被併進 Session（兩者是不同層）；
  • Tool 沒有被拆成好幾個模組（要保持單一抽象）；
  • SkillLoader 沒有被誤當成 Tool；
  • Spring AI 的自動工具執行有被明確關掉。

複審通過後鎖定 plan.md，不再讓 AI 任意更動。

複審不是走形式。AI 生成的 plan 常常「語法正確、語意跑偏」——模組合併、職責重疊這種錯，只有人看得出來。

準備階段的交付物

跑完這一步，repo 裡應該有：.specify/memory/constitution.md、spec.md、plan.md、原始的兩份文件（需求與技術方案），以及 Claude Code 與 Specify CLI 的設定筆記。到這裡，五個 user story 都已經有實作依據，可以正式開工。
