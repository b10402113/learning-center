# Digest — 03-01 1. 开篇： 课程设计思路、教学思路与学习指南

## Overview (L1)

- Course design thinking — The training camp is summarized by three words: 认知 (cognition), 驾驭 (mastery), 进阶 (advancement) — a progression, not parallel; cognition is the foundation, mastery the main body, advancement the extension.
- Cognition layer — Answers what AI programming is, industry status, tool system, where it's going, and the engineer's position; the biggest risk in the AI era is lack of judgment, not lack of tool skill.
- Mastery layer — 80%+ of content; not "using AI tools" but "using AI to get things done"; four real projects in the oryx-labs GitHub space: OryxOS, When, DifyPro, mq9.
- Advancement layer — Open source + long-term co-building; even in the AI-coding era, open source remains a programmer's best calling card.
- Teaching approach — A general-then-specific structure with two principles: projects lead methodology (not the reverse), and every project runs the same rhythm; hands-on practice is what truly deepens cognition.
- Learning guide — Preview cognition materials, all mastery content must be hands-on, and the advancement layer offers three optional things; three study intensities all pay off.

### mastery
- Locator: `[[sources/geek-ai-agent/20260922/03-01 1. 开篇： 课程设计思路、教学思路与学习指南.html#mastery]]`
- Summary: Mastery means actually getting things done with AI, not being tool-fluent; it distinguishes one-shot skill from engineering ability requiring a scaled, historical, constrained real project.
- Key claims: 80%+ of the ~11 weeks is mastery; four real projects were chosen — OryxOS (Agent OS, companies need one; can build from 0→1 or based on open source), When (distributed delay component: orders timing out, coupons expiring, scheduled notifications; gRPC/etcd/cluster/time wheel), DifyPro (Dify secondary development, the 2026 enterprise internal-AI-platform de facto standard, training AI collaboration in a large unfamiliar codebase that remains valuable even if Dify fades), mq9 (Rust Agent communication infra aiming for Apache top-level; real open-source contribution with low entry cost).
- Learner-relevant: Connects each project to a real enterprise pain point and a transferable skill.

### advancement

- Key claims: even in the AI-coding era open source is a programmer's best calling card; those with visible community contributions rarely have poor careers; the advanced layer suits a minority but is the most valuable compounding asset over 3–5 years.

### teaching-approach
- Locator: `[[sources/geek-ai-agent/20260922/03-01 1. 开篇： 课程设计思路、教学思路与学习指南.html#teaching-approach]]`
- Summary: A general-then-specific structure: the general is cognition (opening + 6 cognition PDFs), the specific is mastery across projects, and advancement is open source + long-term co-building.
- Key claims: two principles — (1) projects string methodology together rather than methodology stringing projects; (2) every project runs the same rhythm (state requirements/design and decisions → hands-on build with AI → a review lesson to compound lessons learned).
- Key claims (principle 1 detail): SDD, Skills, Subagents, Hooks, Spec Coding, AI reverse-engineering, cross-language vibe coding, and Claude Agent SDK are scattered naturally across the four projects (When uses SDD, DifyPro uses Subagents, OryxOS uses Skills, mq9 uses AI reverse-engineering).
- Learner-relevant: Explains why methodology is taught in-context rather than up front.

### teaching-rhythm
- Locator: `[[sources/geek-ai-agent/20260922/03-01 1. 开篇： 课程设计思路、教学思路与学习指南.html#teaching-rhythm]]`
- Summary: Three of the four projects (OryxOS 4 weeks, When 3 weeks, DifyPro 2 weeks) share one rhythm: before coding, put requirements and technical design on the table and explain what/why/key decisions (the 6 project docs carry most of this); then build with AI (the main body, with lots of real "I'm stuck → what Claude said → how I judged → next step" scenes); then a review lesson.
- Key claims: mq9 occupies only one week as an open-source contribution experience; its share can be adjusted if learners want more.
- Learner-relevant: Sets expectations for how each project week will unfold.

### hands-on
- Locator: `[[sources/geek-ai-agent/20260922/03-01 1. 开篇： 课程设计思路、教学思路与学习指南.html#hands-on]]`
- Summary: Cognition matters, yet most time is spent building because only by doing does cognition really sink in: getting stuck on the time-wheel edge case teaches "AI compromises when it doesn't understand"; being lost in DifyPro's legacy code teaches the value of AI reverse-engineering; sandbox pitfalls teach why Permission + Hooks safety nets are needed.
- Key claims: cognition and practice nourish each other — cognition is the root, practice the plant; without thinking, hands-on is rootless and copied code breaks when the scenario changes.

### learning-guide-cognition
- Locator: `[[sources/geek-ai-agent/20260922/03-01 1. 开篇： 课程设计思路、教学思路与学习指南.html#learning-guide-cognition]]`
- Summary: Pre-course PDFs are the main carrier of cognition and are required pre-reading, divided into three types with distinct purposes: cognition (market, essence, workflow, tool landscape, personal value, methodology, closing), teaching guide (this article), extension (Skills research, industry practitioner views, Spec-Kit/OpenSpec tutorials, Hermes Agent), and project (each project's research/requirements/technical design/AI-coding guide plus an open-source contribution guide).

### learning-guide-mastery
- Locator: `[[sources/geek-ai-agent/20260922/03-01 1. 开篇： 课程设计思路、教学思路与学习指南.html#learning-guide-mastery]]`
- Summary: Mastery ability is 100% hands-on: all four projects run locally, and every prompt, tool, and decision should be reproduced on the learner's own machine; the self-check is "can you explain what you did and why."
- Key claims: reproduction reveals that the teacher's prompts, judgments, and skipped details don't transfer directly — those "whys" are the real learning; don't blindly copy, learn with thinking; in the AI era operation gets cheap and judgment gets valuable.
- Learner-relevant: The honest standard for whether a project was truly learned.

### learning-guide-advancement
- Locator: `[[sources/geek-ai-agent/20260922/03-01 1. 开篇： 课程设计思路、教学思路与学习指南.html#learning-guide-advancement]]`
- Summary: Three optional advancement actions: (1) write a short review note after each project (what AI did well/poorly, your judgments, next-time adjustments) — this becomes your own methodology; (2) organize frequently used prompts, tool configs, and Skills into a personal library; (3) try one open-source PR (mq9 or anything you like).
- Key claims: doing or not doing these doesn't affect finishing the camp, but doing them pays off years later; a GitHub contribution record is a résumé that stays with you.
- Learner-relevant: Concrete, optional compounding actions.

### three-intensities
- Locator: `[[sources/geek-ai-agent/20260922/03-01 1. 开篇： 课程设计思路、教学思路与学习指南.html#three-intensities]]`
- Summary: Three study intensities: cognition + basic mastery (read all 14 PDFs, follow the three projects' core tasks → run AI coding smoothly in enterprise projects); cognition + mastery + partial advancement (deepen one project, compound notes and tool library); cognition + mastery + full advancement (finish mq9, submit a PR, join long-term co-building).
- Key claims: all three paths hold; less investment isn't shameful and more isn't pressured — the camp's value is that it genuinely gives you something.
- Learner-relevant: Lets the learner pick a sustainable commitment.

### closing
- Locator: `[[sources/geek-ai-agent/20260922/03-01 1. 开篇： 课程设计思路、教学思路与学习指南.html#closing]]`
- Summary: A pre-class note: the industry's most interesting thing is never tools but the people using them; tools keep changing while those who thrive keep curious, keep acting, and keep pushing forward; AI doesn't replace you or make you better — it amplifies who you already are.
