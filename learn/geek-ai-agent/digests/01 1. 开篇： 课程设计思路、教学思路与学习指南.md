# Digest — 01 1. 开篇： 课程设计思路、教学思路与学习指南

## Overview (L1)
- 一、课程设计思路 — 训练营骨架是"认知、驾驭、进阶"三层递进：认知是地基（看清 AI 编程是什么），驾驭是主体（约 11 周、80% 内容、四个真实项目 When/DifyPro/OryxOS/mq9），进阶是延伸（开源贡献与长期共建）。
- 二、教学思路 — "总分结构"：总论+6 份认知 PDF 打底，四个项目反复跑同一套工作流；项目串方法论而非方法论串项目；每个项目按"方案讲解 → AI 实战 → 复盘"同一种节奏；实操是加深认知的地方。
- 三、学习指南 — 认知层必须看预习 PDF；驾驭层所有内容必须动手复现、以"能不能讲清楚为什么"自检；进阶层可做复盘笔记、个人提示词/Skills 库、开源 PR；三种学习强度都成立。
- 四、写在开课之前 — 工具会迭代，判断会留下；AI 只是放大你本身；训练营真正交付的是一种"愿意从零学、敢动手、会复盘"的状态（少年依旧）。

### 1.1 认知： 看清楚 AI 编程是什么
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#1.1 认知： 看清楚 AI 编程是什么]]`
- Summary: 认知层回答 AI 编程本质、行业现状、工具体系、走向与工程师定位，被描述为最"刚需"的一层。
- Key claims: 工程师最大风险是没有判断（看到傻代码说 AI 没用、看到 demo 说被取代）；没有认知，驾驭就是依样画葫芦；工具会过时，认知会留下。
- Learner-relevant: 支撑"认知篇" 7 份预习材料的定位——为何先建认知再动手。

### 1.2 驾驭：把 AI 用熟，把事情做成
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#1.2 驾驭：把 AI 用熟，把事情做成]]`
- Summary: 区分"会用 AI 工具"（单点技能）与"用 AI 把事情做成"（工程能力），列出四个真实项目及其训练意图。
- Key claims: OryxOS（AI Agent OS，对比 Hermes Agent/OpenClaw，0→1 与二开）、When（分布式延时组件，gRPC/etcd/时间轮）、DifyPro（Dify 二开，大型陌生代码库）、mq9（Rust Agent 通信基础设施，开源贡献全流程）；项目都放于 oryx-labs GitHub 组织；四项目反复训练同一套工作流成肌肉记忆。
- Learner-relevant: 识别四个项目各训练什么能力（从 0→1、改造、分布式、开源贡献），支撑后续节点内容。

### 1.3 进阶：在驾驭基础上多走一步
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#1.3 进阶：在驾驭基础上多走一步]]`
- Summary: 进阶层指向开源贡献与长期共建，被描述为"最有价值的复利资产"。

- Learner-relevant: 支撑复利资产/开源相关的认知内容。

### 二、教学思路
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#二、教学思路]]`
- Summary: 说明训练营"总分结构"与几条教学原则：项目串方法论、统一项目节奏、实操加深认知。
- Key claims: 总=认知层（开篇总论+6 份认知 PDF），分=驾驭层（三/四个项目跑同套工作流），进阶=开源+长期共建。
- Learner-relevant: 理解方法论（SDD/Skills/Subagents/Hooks 等）散落在项目中的教学组织方式。

### 2.1 项目串方法论，而不是方法论串项目
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#2.1 项目串方法论，而不是方法论串项目]]`
- Summary: 对比"先讲工具再 Demo"的常规课程，主张用大型项目内化方法论，方法论在具体痛点场景中才可理解。
- Key claims: SDD、Skills、Subagents、Hooks、Spec Coding、AI 反推整体逻辑、跨语言 Vibe Coding、Claude Agent SDK 自然散落四项目（如 When 用 SDD、DifyPro 用 Subagents、OryxOS 用 Skills、mq9 用 AI 反推）。
- Learner-relevant: 支撑后续各项目节点的方法论编排（哪些方法论出现在哪个项目）。

### 2.2 每个项目跑同一种节奏
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#2.2 每个项目跑同一种节奏]]`
- Summary: 前三个项目（OryxOS/When/DifyPro，4/3/2 周）内部节奏一致：先摆需求与技术方案文档，再动手实战，最后复盘。
- Key claims: 直播课做方案深度讲解与答疑；实战演示大量真实"卡住—AI 回应—判断—下一步"场景；复盘沉淀经验；mq9 占一周，为开源体验。
- Learner-relevant: 预期各节点的学习节奏与产出（方案→实战→复盘）。

### 2.3 实操才是真正加深认知的地方
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#2.3 实操才是真正加深认知的地方]]`
- Summary: 论证为何大部分时间做项目而非讲理论：认知只有动手才进得去，但只动手不思考则实操无根。
- Key claims: 例子——When 时间轮边界 case 让人理解"AI 不理解时会凑合"；DifyPro 理解"让 AI 反推整体逻辑"价值；OryxOS 沙盒安全坑让人理解 Permission+Hooks 安全网；认知是根，实操是植物本体。
- Learner-relevant: 锚定"认知与实操互相滋养"的教学哲学。

- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#3.1 关于认知层：预习材料一定要看]]`

### 3.2 关于驾驭层：所有内容必须动手
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#3.2 关于驾驭层：所有内容必须动手]]`
- Summary: 驾驭能力 100% 是动手能力，须在自己机器上复现，并以"能否讲清楚做了什么、为什么这么做"自检。
- Key claims: 复现差异是宝贵学习材料；操作越来越便宜，判断越来越值钱；训练营真正价值在训练判断力。
- Learner-relevant: 支撑 /tackle 之类自检与"讲清楚为什么"的验收标准。

### 3.3 关于进阶层：多走一步，沉淀下来
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#3.3 关于进阶层：多走一步，沉淀下来]]`
- Summary: 给出进阶层三件事：每项目写复盘笔记、整理个人提示词/工具配置/Skills 库、尝试提一个开源 PR。
- Key claims: 复盘笔记积累成个人方法论；提示词/Skills 库是复利资产；GitHub 贡献记录是随身简历。
- Learner-relevant: 支撑复利资产与开源相关内容。

### 3.4 三种学习强度都不亏
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#3.4 三种学习强度都不亏]]`
- Summary: 给出三种投入强度（认知+驾驭基础 / +部分进阶 / +完整进阶）对应的完成路径。
- Key claims: 基础层=14 份 PDF+三项目核心任务；进阶层=深入改造+沉淀+mq9 与开源 PR；投入少不丢人。
- Learner-relevant: 学习强度分级，支撑学习者自我定位。

### 四、写在开课之前
- Locator: `[[sources/geek-ai-agent/01 1. 开篇： 课程设计思路、教学思路与学习指南.html#四、写在开课之前]]`
