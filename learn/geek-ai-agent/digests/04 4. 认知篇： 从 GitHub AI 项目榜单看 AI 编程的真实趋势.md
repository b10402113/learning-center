### 3.1 行业当前仍在第一阶段
- Locator: `[[sources/geek-ai-agent/04 4. 认知篇： 从 GitHub AI 项目榜单看 AI 编程的真实趋势.html#3.1 行业当前仍在第一阶段]]`
- Summary: 判断 2026 年 AI 行业停在"为 AI 议题做工具/基础设施"的第一阶段，类比 1849 加州淘金（先卖镐头铲子）。
- Key claims: 四个原因——地基没打稳（MCP 2024 底才出现）、模型可靠性不够（Opus 14.5h/50%）、工作流还在重塑、商业模式没跑通（基础设施易卖应用难）；推断时间窗 2025-2026 基础设施大爆发、2027-2028 应用层起来、2029+ 大规模落地（推断非预测，6-12 个月校准）。
- Learner-relevant: 把握行业阶段，指导学习/职业投入时点。

### 3.2 AI 编程工具的能力在收敛
- Locator: `[[sources/geek-ai-agent/04 4. 认知篇： 从 GitHub AI 项目榜单看 AI 编程的真实趋势.html#3.2 AI 编程工具的能力在收敛]]`
- Summary: 工具都支持 MCP/Subagents/Permission/Hooks/Spec-Driven 工作流，能力趋同、差异化缩小。
- Key claims: "会用工具"门槛降低但"用熟工具"差距放大（好用者多并行工作流 vs 差用者单线对话，效率差不止数倍）；真正拉开差距的是判断力。
- Learner-relevant: 工具趋同时代把投资放在判断力而非追工具。

### 3.3 Agent 是 2026 年最大赛道
- Locator: `[[sources/geek-ai-agent/04 4. 认知篇： 从 GitHub AI 项目榜单看 AI 编程的真实趋势.html#3.3 Agent 是 2026 年最大赛道]]`
- Summary: 证据=Top7 中 6 个是 Agent 类 + Gartner 预测 2026 底 40% 企业应用含 AI agent（2025 年 5%）。
- Key claims: 未来代码分两类——"给 Agent 用的代码"（接口/工具/数据）与"Agent 本身的代码"（工作流/记忆/决策/协作）；Agent 是长跑、有状态、有目标、可中断的执行体，传统请求-响应思维不够用。
- Learner-relevant: 面向 Agent 编程的新工程领域，支撑 Agent 相关项目（OryxOS/mq9）。

### 3.4 AI 编程基础设施层正在长出来
- Locator: `[[sources/geek-ai-agent/04 4. 认知篇： 从 GitHub AI 项目榜单看 AI 编程的真实趋势.html#3.4 AI 编程基础设施层正在长出来]]`
- Summary: 判断这层是 AI 编程的"操作系统层"（类比 80 年代 Unix 工具链、90 年代 IDE 体系），组件=MCP/Mem0/agentmemory/superpowers/agentskills.io/Spec-Kit/OpenSpec/Subagents/Hooks/Permission。
- Key claims: 学这层"抽象"比追"具体工具"长青，工具半年换一波、抽象层换得慢，3-5 年还在受益。
- Learner-relevant: 学习投资策略——投抽象层。

### 3.5 No-code 工具的流行不意味着编程消失
- Locator: `[[sources/geek-ai-agent/04 4. 认知篇： 从 GitHub AI 项目榜单看 AI 编程的真实趋势.html#3.5 No-code 工具的流行不意味着编程消失]]`
- Summary: Top5 里三个是可视化构建器，但推断其反而提高了对工程师的要求。
- Key claims: 原型可用和生产可用之间有工程鸿沟；会消失的是"代码工"（只会按需求写代码），不会消失的是"工程师"（能做架构/判断/识别工具边界）。
- Learner-relevant: 明确工程师与代码工的区别，定位自身增值方向。

### 3.6 AI 自主编程仍在 Demo 阶段
- Locator: `[[sources/geek-ai-agent/04 4. 认知篇： 从 GitHub AI 项目榜单看 AI 编程的真实趋势.html#3.6 AI 自主编程仍在 Demo 阶段]]`
- Summary: 证据=Devin/OpenDevin/swe-agent + Anthropic 保留人工 review + 失败数据；判断"AI 完全自主编程"还在 Demo 阶段。
- Key claims: Devin 在 Nubank 的 monolith 拆分是"特定场景下有监督的自主编程可行"（范围明确、有参考实现、全程监督），不等于全自动可行；教"驾驭"比教"全自动"更有工程价值。
- Learner-relevant: 训练方向定为"驾驭"而非"等待全自动"。

### 3.7 SDD 不是营销词，是真方法论标准
- Locator: `[[sources/geek-ai-agent/04 4. 认知篇： 从 GitHub AI 项目榜单看 AI 编程的真实趋势.html#3.7 SDD 不是营销词，是真方法论标准]]`
- Summary: 证据=Spec-Kit 94.5k stars（纯方法论工具）+ SDD 被 Kiro/Tessl/OpenSpec/superpowers 多个实现。
- Key claims: SDD 与传统方法论核心区别——规格用于执行而非沟通、规格是真理而非代码、规格领先于代码。
- Learner-relevant: 支撑 SDD 为训练主轴。

### 3.8 MCP 已成全行业共识
- Locator: `[[sources/geek-ai-agent/04 4. 认知篇： 从 GitHub AI 项目榜单看 AI 编程的真实趋势.html#3.8 MCP 已成全行业共识]]`
- Summary: 判断 MCP 是 AI 编程时代的"HTTP"，地位与跨厂商共识类似。
- Key claims: 熟悉 MCP 是必要基础——不止"会用"，还要理解核心抽象（Resources/Tools/Prompts）、连接模式（stdio/SSE）、自己能写 MCP Server，三层次决定能力位置。
- Learner-relevant: 明确 MCP 学习深度要求。

### 3.9 "AI coding" 与 "AI for coders" 在分化
- Locator: `[[sources/geek-ai-agent/04 4. 认知篇： 从 GitHub AI 项目榜单看 AI 编程的真实趋势.html#3.9 "AI coding" 与 "AI for coders" 在分化]]`
- Summary: 两类工具目标用户与设计取舍完全不同，不应混为一谈。
- Key claims: AI coding（不会编程的人，易用性优先，产出原型，代表 OpenClaw/Dify/Hermes）vs AI for coders（专业开发者，可控性优先，产出生产代码，代表 Claude Code/Cursor/Spec-Kit）；目标生产代码选 AI for coders。
- Learner-relevant: 按目标产出选择工具阵营。
