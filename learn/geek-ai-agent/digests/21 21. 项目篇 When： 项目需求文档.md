# Digest — 21 21. 项目篇 When： 项目需求文档

## Overview (L1)
- 1. 项目概述 — When 是通用的、独立部署的分布式延时投递组件（Java），HTTP API 提交、存储调度投递到任意下游；双重定位（真实业务需求 + 训练营 AI 编程教学样本）；需求分三档（训练营 MVP / 学员持续维护 / 社区共建）。
- 2. 术语和概念 — 统一延时消息、投递、Sink、调用方、时间轮/多层时间轮/时间轮实例、节点、Master/Slave、Controller 等术语；投递语义为至少一次。
- 3. 设计目标和不做的事 — 五个词概括目标（通用、可扩展、可靠、易接入、可运维）；明确不做任务调度平台、消息队列、worker 执行框架、大而全 MQ、业务消息内容解析、下游业务逻辑保障。
- 4. AI 编程开发约束 — 硬性约束：核心代码至少 90% 由 AI 完成（目标 95%）、全部 review；工程化使用 AI（Spec/CLAUDE.md/Skills/Hooks/Plan Mode）；列明不允许的开发方式与从一句话需求到上线部署的七阶段完整链路及度量和验收。
- 5. 用户和典型场景 — 四类用户（业务开发者、运维、平台管理员、社区贡献者）；三个典型场景（电商订单超时取消、推送定时发送、任务失败重试）；列出不建议使用的场景。
- 6. 训练营版本（3 周 MVP）— 主流程优先：提交/查询/取消三 API、HTTP+Kafka 两种 Sink、Redis 存储、单节点多层时间轮、Docker/K8s 部署、Web 管理台两页面、基础可观测；明确做与不做的完整范围。
- 7. 后续维护阶段 — 补齐生产级可靠性（集群协调+Controller 选举、Master/Slave+故障切换）和高频功能；GitHub 社区接力机制与两档学员目标。
- 8. 社区共建方向 — 多语言 SDK、多租户隔离、自定义存储后端、跨地域部署、Kubernetes Operator、MCP Server 完全开放给社区。
- 9. 非功能需求 — 训练营/长期两档指标：QPS、精度（99% 正负 1 秒）、存储规模、可运维、兼容性、安全。
- 10. 关键流程 — 消息写入、调度投递、节点重启恢复三条核心流程。
- 11. 数据模型 — 延时消息核心字段（message_id、deliver_at、sink_type、sink_config、payload、status 等）。
- 12. 训练营 3 周里程碑 — 第一周需求设计、第二周核心调度存储、第三周 Kafka Sink/管理台/部署/可观测，各周末检查点。
- 13. 风险与未决事项 — Redis 大 Key、时间轮内存膨胀、单节点重启不可用、集中到期四大风险与未决事项。
- 14. 验收标准 — 七项验收（功能/精度/性能/部署/可观测/演示/AI 编程产出）。
- 15. 相关文档 / 16. 总结 — 文档体系（调研、技术方案、部署运维、API、贡献者指南）与整体收束。

### users-and-scenarios

### bootcamp-mvp
- Locator: `[[sources/geek-ai-agent/21 21. 项目篇 When： 项目需求文档.html#6. 训练营版本（3 周 MVP）]]`
- Summary: 定义 3 周 MVP 的完整能力：主流程 API、两种 Sink、Redis 存储、单节点时间轮、部署、管理台、可观测，并明确做与不做的清单。
- Key claims: 三个核心 API：POST/GET/DELETE /api/v1/messages（提交/查询/取消）；延时时长 1 秒到 30 天、精度 99% 正负 1 秒、单条消息上限 64KB、透传；状态机 pending→delivering→delivered/failed、可 cancelled；内置 HTTP 和 Kafka 两种 Sink（覆盖约 80% 场景），Sink 经 SPI 扩展；存储用 Redis（按消息 ID 拆 key 规避大 Key，索引按时间轮维度拆分，支持 Redis 5.0+）；时间轮单节点内存版，重启从 Redis 重载未投递消息兜底；部署：docker-compose/单机生产/K8s 三环境、半小时内可起；管理台两个页面（任务列表、投递日志），独立 Web 应用经 HTTP API 通信；可观测：Prometheus 核心指标（写入 QPS、投递 QPS、当前消息数、成功率、耗时分布）、JSON 结构化日志带 trace ID、/health 接口；明确不做：集群协调、Master/Slave、其他 Sink、鉴权限流、DLQ、优先级队列等。
- Learner-relevant: 是技术方案（源 22）的范围依据，也是训练营验收标准的来源。

### key-flows
- Locator: `[[sources/geek-ai-agent/21 21. 项目篇 When： 项目需求文档.html#10. 关键流程]]`
- Summary: 描述消息写入、调度投递、节点重启恢复三条核心流程（训练营版本）。
- Key claims: 写入：POST → 参数校验 → 生成全局唯一 message ID → 写 Redis（消息体+时间索引）→ 加入内存时间轮 → 返回 ID，目标 P99 ≤100ms；调度投递：指针推进到当前秒批量取消息 → 投递线程池按 Sink 插件投递 → 结果回写 Redis（delivered/failed）→ 失败按重试策略重回时间轮；重启恢复：从 Redis 加载 pending/delivering 消息重建时间轮，重启期间不可用。
- Learner-relevant: 时间轮与存储交互的流程基线，技术方案（源 22）在此基础上细化。
