# Digest — 01-03 课程导论（目录）

## Overview (L1)

- Week 1 · 总论 (general introduction) — Establishes the AI-programming cognition map, from "why learn" to "how to run an enterprise-scale project with AI" (sections 1–7).
- Project 1 · OryxOS guide (weeks 1–5) — A five-week, project-centered arc that builds an enterprise Agent OS from requirements analysis through Provider / ReAct / CLI / Notify / Tool / Memory / Sandbox / scheduling / Web Service, then integration, pluginization, and release (sections 8–32).
- Project 2 · When guide (weeks 6–8) — A three-week contrast project: a distributed delayed-delivery component built with Loop programming, where all effort goes into preparing loop "raw material" (spec + task + harness + acceptance) before letting AI run the loop (sections 33–55).
- Note — The outline is a living document; content may be adjusted per instructor delivery.

## Sections (L2)

### week1-total
- Locator: `[[sources/geek-ai-agent/20260922/01-03 课程导论（目录）.html#week1-total]]`
- Summary: Seven opening sections: a letter to learners, course architecture/learning path, cognition power, tool-selection power, an OryxOS website demo class, methodology (SDD/Harness/Loop Engine), and workflow design power.
- Key claims: what you learn is judgment, not a tool; the core five-stage loop is design · think · decompose · execute (AI) · verify; tools are classified via a seven-layer architecture; SDD gives goals, Harness gives boundaries, Loop gives controlled execution; your own workflow is the moat.
- Learner-relevant: Frames the "why → what → which tool → which method → how to run a big project" sequence for the whole course.

### oryxos-design
- Locator: `[[sources/geek-ai-agent/20260922/01-03 课程导论（目录）.html#oryxos-design]]`
- Summary: Design rationale for the OryxOS arc — five weeks on one real project covering cognition and mastery, with cognition/judgment prioritized over coding; each module follows the same rhythm (principle → think first → implement with AI → verify by tests → explain code).
- Key claims: writing code is no longer the scarcest ability; the value is in front-loaded design/thinking/decomposition and back-loaded verification; weekly "extension chapters" add material without disturbing the main line.
- Learner-relevant: Explains why the early weeks are talk-heavy and code-light, setting learner expectations.

### oryxos-week2
- Locator: `[[sources/geek-ai-agent/20260922/01-03 课程导论（目录）.html#oryxos-week2]]`
- Summary: OryxOS start (sections 8–14): what an Agent/Agent OS is, reading the project, Spec-Kit fundamentals, requirements-to-task decomposition, and a live Spec-Kit demo.
- Key claims: an Agent decomposes into five components + one loop; OryxOS is a ready-to-use enterprise Agent runtime base; Spec-Kit is a workflow layer above the AI agent; use Spec-Kit for the main build and manual prompts for increments.
- Learner-relevant: The conceptual bridge from AI coding methods to the concrete OryxOS codebase.

### oryxos-week3
- Locator: `[[sources/geek-ai-agent/20260922/01-03 课程导论（目录）.html#oryxos-week3]]`
- Summary: Base capability development (sections 15–20): init-skill engineering groundwork, Agent Provider, ReAct, CLI, Notify, and the Tool system.
- Key claims: Provider is a thin unified abstraction over LLMs; ReAct is a Reason→Act→Observe loop with explicit boundaries; CLI is a thin entry layer; Notify pushes results out; Tool uses a unified OryxTool abstraction with three-tier plugin access and a whitelist.
- Learner-relevant: First hands-on core capabilities; the "principle → implement → code walkthrough" pattern begins.

### oryxos-week4
- Locator: `[[sources/geek-ai-agent/20260922/01-03 课程导论（目录）.html#oryxos-week4]]`
- Summary: Core capabilities and support (sections 21–26): Memory (short vs long term), Sandbox (application-layer whitelist isolation), scheduling module, and Web Service plus the first management console.
- Key claims: short-term memory is session-scoped while long-term memory is MEMORY.md; sandboxing uses path/command/domain whitelists in the core stage with container isolation deferred; the scheduling module pairs naturally with Notify.
- Learner-relevant: Teaches safety, persistence, and automation — the capabilities that make an Agent production-usable.

### oryxos-week5
- Locator: `[[sources/geek-ai-agent/20260922/01-03 课程导论（目录）.html#oryxos-week5]]`
- Summary: End-to-end integration, pluginization, release, and wrap-up (sections 27–32): full-flow connection, Skill-defined plugin Agents, dynamic Agent management via API, and two real Agents (weather, daily report).
- Key claims: integration is where it becomes real; a Skill can declaratively configure an Agent — the key expression of "OS"; the two runnable Agents are the acceptance evidence of the mastery layer.
- Learner-relevant: The first-stage payoff and the hand-off toward open source and long-term growth.

### when-design
- Locator: `[[sources/geek-ai-agent/20260922/01-03 课程导论（目录）.html#when-design]]`
- Summary: Design rationale for When — a standalone distributed delay-delivery component built with Loop programming over three weeks; the focus is almost entirely on "before running the loop," preparing each module's raw material (spec + task + harness + auto-runnable acceptance).
- Key claims: hard constraint is 90%+ of core code written by AI with full human review; acceptance must be concrete enough for machines to auto-run; the overall Harness must catch loop drift; loop success equals the quality of the prepared raw material.
- Learner-relevant: Teaches designing environments and acceptance so AI can autonomously deliver a distributed system.

### when-week6
- Locator: `[[sources/geek-ai-agent/20260922/01-03 课程导论（目录）.html#when-week6]]`
- Summary: When start (sections 33–39): requirements and industry research, technical review (ETCD/Redis/multi-layer time wheel/Master-Slave/HTTP-gRPC/Java), deep dive on Loop and Harness, designing When's loop model, homepage/README/docs, and distributed architecture decomposition.
- Key claims: existing delayed-delivery options are locked to MQ, large keys, or cloud vendors — the empty niche justifies When; the cluster architecture map is the checklist for per-module raw material.
- Learner-relevant: The methodology spine for the Loop-based second project.

### when-week7
- Locator: `[[sources/geek-ai-agent/20260922/01-03 课程导论（目录）.html#when-week7]]`
- Summary: Per-module Loop raw material (sections 40–47): pluggable storage + Redis, gRPC proto interfaces, access + routing layers, time wheel, node cluster registration, Master/Slave replication, Controller, and pluggable Sink delivery (HTTP + Kafka).
- Key claims: each section outputs function + task + harness + acceptance; the time wheel is the O(1) scheduling core spanning seconds to months; at-least-once semantics with idempotent downstream; Master/Slave plus Controller provide high availability.
- Learner-relevant: The per-module muscle of turning a distributed design into machine-verifiable loop inputs.

### when-week8
- Locator: `[[sources/geek-ai-agent/20260922/01-03 课程导论（目录）.html#when-week8]]`
- Summary: Wrap-up and payoff (sections 48–55): observability (Prometheus + structured logs + health checks), deployment and CI (compose/single-node/K8s + GitHub Actions), Web console, designing the overall loop Harness, executing the loop in three sessions, and final summary/community.
- Key claims: the overall Harness is the key to running the whole project in one loop; deployment scripts are also AI-written; the last step is packaging and releasing a real running system.
- Learner-relevant: Completes the "one-sentence requirement to production" chain and connects to long-term open-source contribution.
