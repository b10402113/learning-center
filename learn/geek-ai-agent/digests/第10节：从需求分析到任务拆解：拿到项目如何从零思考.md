# Digest — 第10节：从需求分析到任务拆解：拿到项目如何从零思考

## Overview (L1)

- Traditional vs AI programming — Traditional flow is gather requirements → design → hand-write code → debug, centered on "writing code"; AI programming shifts the core action to "orchestrating AI to get things done", producing code through judge → execute → accept (判断 → 执行 → 验收).
- What changed / unchanged — The purpose (deliver value faster) and engineering judgment stay; the path and center of gravity change (core action, thinking focus, success metric, from "feel" to "judgment").
- Think in three mindsets, not code writing — Use SDD (怎么拆分), Harness (怎么立规范), and Loop (怎么自动化) as three angles for approaching any project, not as three tools.
- One thinking path — Think clearly what to do → set rules and boundaries → design automated execution → human verifies and closes out.
- Control stays with you — AI executes; you own decomposition, specs, key technical decisions, and acceptance criteria.

### AI 编程：做法和思路

### 哪些变了，哪些没变
- Locator: `[[sources/geek-ai-agent/20260922/第10节：从需求分析到任务拆解：拿到项目如何从零思考.pdf#哪些变了，哪些没变]]`
- Summary: Separates what is stable (purpose, requirement clarity before acting, engineering judgment, CS fundamentals) from what changed (core action, thinking focus, success metric, reliance on judgment over feel).
- Key claims: "AI replaces programmers" is a misread — the path changed, the purpose did not.
- Learner-relevant: prevents both clinging to old cognition and being misled by replacement panic.

### 用三种思维，不是写代码思维
- Locator: `[[sources/geek-ai-agent/20260922/第10节：从需求分析到任务拆解：拿到项目如何从零思考.pdf#用三种思维，不是写代码思维]]`
- Summary: Approaching a project from "how to get it done" rather than "first line of code", using SDD, Harness, Loop as three thinking angles.
- Key claims: ask "how to do this faster and better", not "how to write this code"; the three mindsets are thinking angles, not tool operations.
- Learner-relevant: anchors the three pillars (from section 5) as a project-entry heuristic.

### 三种思维：拿到项目这样想
- Locator: `[[sources/geek-ai-agent/20260922/第10节：从需求分析到任务拆解：拿到项目如何从零思考.pdf#三种思维：拿到项目这样想]]`
- Summary: SDD mindset = decompose vague requirements into clear executable blocks; Harness mindset = set boundaries, rules, and verification; Loop mindset = decide which steps AI runs autonomously in a loop and where checkpoints go.
- Key claims: think in the head first, then land in tools; going through all three angles beats starting from code.
- Learner-relevant: concrete prompts for each mindset when scoping a new project.

### 一条思考路径：先做什么、后做什么
- Locator: `[[sources/geek-ai-agent/20260922/第10节：从需求分析到任务拆解：拿到项目如何从零思考.pdf#一条思考路径：先做什么、后做什么]]`
- Summary: Four-step skeleton — think clearly (SDD) → set norms/boundaries (Harness) → design automated execution (Loop) → human verifies and closes out.

- Learner-relevant: a reusable from-zero planning path for the project chapters that follow.

### 但控制权，在你手里
- Locator: `[[sources/geek-ai-agent/20260922/第10节：从需求分析到任务拆解：拿到项目如何从零思考.pdf#但控制权，在你手里]]`
- Summary: Divides who decides vs who executes: you own decomposition, norms/boundaries, key technical decisions, acceptance criteria; AI generates code within bounds, executes per spec, runs checks, reports blockers.
- Key claims: judgment cannot be delegated, execution can; you are the workflow designer, not a bystander.
- Learner-relevant: the accountability boundary for the whole course and the project work.
