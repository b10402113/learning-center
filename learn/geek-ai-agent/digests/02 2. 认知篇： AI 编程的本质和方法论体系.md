# Digest — 02 2. 认知篇： AI 编程的本质和方法论体系

## Overview (L1)
- 一、目的从未变过 — 程序员职业的目的从来不是写代码，而是更快更好地产生价值；代码只是手段，杠杆从底层能力→框架平台→云原生→驾驭 AI 一路变化，每一次都只淘汰没跟上杠杆的人。
- 二、路径变了什么 — 从最表层到最深层三层递进变化：核心动作从写代码变驾驭 AI（手感→判断）、能力杠杆点从勤奋变清晰度、身份从"写代码的人"变"用 AI 把事情做成的人"。
- 三、这意味着什么 — 四个推断：杠杆位置上移（这次杠杆本身具备智能）、责任结构重写（责任全在驾驭者）、两极分化加速（差距指数化）、超级个体可能但门槛比想象高。
- 四、个人层面的回应 — 不要把 AI 编程当新职业（是旧角色升级）、重心从"做"转"想"、学工具是基础但工具不是目的；核心训练是"想"的工程化能力。
- 五、方法论的当前景观 — 列出 SDD、Harness Engineering、Vibe Coding、Context Engineering、ReAct/TAO、Test-Driven AI、Plan-then-Execute、AI-First Architecture 等当下方法论，成熟度不一。
- 六、为什么主轴是 SDD 加 Harness — 按"成熟、可教、覆盖完整工程"三条标准，当下同时满足的只有 SDD（解决"想"）与 Harness（解决"做"），互补闭环。
- 七、其他方法论的位置 — Vibe Coding 是底色、Context Engineering 是长期方向、ReAct/TAO 等是延伸阅读；主轴反复锤炼、景观完整呈现、边界清晰交代。

## Sections (L2)
### 一、目的从未变过
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#一、目的从未变过]]`
- Summary: 破除"程序员价值就是写代码"的假设，指出职业目的是产生价值，AI 编程只是又一次杠杆变化。
- Key claims: 杠杆演变：二十年前底层能力（C/C++）→十几年前框架平台（Java/Python/Rails）→前几年云原生分布式→今天驾驭 AI；没有一次杠杆变化淘汰程序员，只淘汰没跟上杠杆变化的人。
- Learner-relevant: 消解"AI 替代"焦虑，建立"路径变了、目的没变"的认知起点。

### 二、路径变了什么
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#二、路径变了什么]]`
- Summary: 从表层到深层拆解新旧路径三层差异：核心动作、能力结构杠杆点、身份认同。
- Key claims: 三层层层递进；这次变化改的是工程师本身（你是谁、关心什么、杠杆在哪），不是工具本身。
- Learner-relevant: 为"驾驭 AI"训练方向提供理论依据。

### 1.最表层的变化是核心动作变了
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#1.最表层的变化是核心动作变了]]`
- Summary: 核心动作从"手写代码"变成"驾驭 AI 写代码"，代码经"你的判断→AI 执行→你的验收"新链路产生。
- Key claims: 核心能力从"手感"变"判断"；手感靠时间堆，判断靠认知建。
- Learner-relevant: 区分手感与判断两种能力的训练方式。

### 2.往深一层，能力结构的杠杆点变了
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#2.往深一层，能力结构的杠杆点变了]]`
- Summary: 新路径里勤奋不再是关键变量，清晰度才是；想清楚的人几条 prompt 即可，想不清楚的人反复拉扯无产出。
- Key claims: 工程师差距从线性变指数级；中等工程师被 AI 的猜错反复拖累，反而比不用 AI 还慢。
- Learner-relevant: 支撑"训练想的能力"（Spec 等）的核心动机。

### 3.再往深一层，身份认同变了
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#3.再往深一层，身份认同变了]]`
- Summary: 身份从"写代码的人"变"用 AI 把事情做成的人"，职责从只产代码扩展到定义、判断、对交付负责。
- Key claims: 关心点从手段层面（代码质量/架构优雅）转向目的层面（是否真有用、用户是否真需要）；这是与过去任何工具迭代最大不同。
- Learner-relevant: 重新定位工程师职责边界（人做判断、AI 做执行）。

### 三、这意味着什么
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#三、这意味着什么]]`
- Summary: 把上述变化推到极致得出的四个进一步判断：杠杆上移、责任重写、两极分化、超级个体。
- Key claims: 四个判断都是真实的但很多人不愿正视。
- Learner-relevant: 建立对 AI 时代的冷静预期，避免被夸大/贬低叙事带走。

### 1. 杠杆位置在持续上移
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#1. 杠杆位置在持续上移]]`
- Summary: 杠杆从稀缺技术→平台→架构→驾驭 AI 持续上移，且这一次幅度更大。
- Key claims: 前几次基础设施仍要人写（Kubernetes 还是工程师写的）；这次杠杆本身具备智能，工程师从"使用工具"变"管理一个能力极强但需约束的执行者"，无前例可参考。
- Learner-relevant: 引出 Harness（约束执行者）的必要性。

### 2. 责任结构在被重写
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#2. 责任结构在被重写]]`
- Summary: 代码由 AI 写但责任全在驾驭者；不是"AI 写错了"而是"我没驾驭好 AI"。
- Key claims: AI 不是法律主体、无法被追究；过去只对写的代码负责，现在要对 AI 产出的整个模块负责，包括没逐行看过的部分。
- Learner-relevant: 强调人的验收与兜底责任，支撑 Human-in-the-loop 与 Hooks/复核。

### 3. 两极分化在加速
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#3. 两极分化在加速]]`
- Summary: 好工程师与中等工程师差距从线性变指数级，不动就是退步。
- Key claims: 门槛没有降低只是位置变了——新门槛是"会驾驭 AI 产生真实价值"，大多数人跨不过。
- Learner-relevant: 认清"门槛提高在另一维度"，避免被"降低门槛"错觉误导。

### 4. 超级个体成为可能，但门槛比想象中高
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#4. 超级个体成为可能，但门槛比想象中高]]`
- Summary: 澄清"超级个体"两点：非 AI 时代才出现（Carmack/Linus/Notch 早就是），标志不是产出快而是产出有价值。
- Key claims: 超级个体=判断力+执行力+价值感知力合一；AI 放大执行力，但放大不了判断力与价值感知力。
- Learner-relevant: 强调判断力/价值感是人的核心资产。

### 五、方法论的当前景观
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#五、方法论的当前景观]]`
- Summary: 摆出当下业界讨论的主要方法论及其解决的核心问题与工具支撑。
- Key claims: SDD 解决"AI 不知道你要什么"（Spec-Kit/OpenSpec/Tessl）；Harness Engineering 解决跑偏/失控/上下文污染/不可逆操作（System Prompt/Tools/Context/Permission/Hooks/Plan Mode）；Vibe Coding 解决用不熟；Context Engineering 解决上下文质量；ReAct/TAO 解决多步任务；Test-Driven AI 解决事后验证；Plan-then-Execute、AI-First Architecture 还在概念阶段。
- Learner-relevant: 完整方法论地图，支撑后续对 SDD/Harness 的深入。

### 六、为什么主轴是 SDD 加 Harness
- Locator: `[[sources/geek-ai-agent/02 2. 认知篇： AI 编程的本质和方法论体系.html#六、为什么主轴是 SDD 加 Harness]]`
- Summary: 按"成熟、可教、覆盖完整工程"三条标准筛出 SDD 与 Harness 为训练营主轴，解释二者互补关系。
- Key claims: SDD 把"想清楚"工程化（spec 是显性契约，Spec-Kit 四阶段 specify/plan/tasks/implement）；Harness 把"AI 怎么做"工程化（约束机制把 AI 从"放飞的执行者"变"可控的协作者"）；SDD 告诉 AI 做什么、Harness 保证 AI 做对；共享底层假设"AI 不是被信任的，是被工程化使用的"。
- Learner-relevant: 训练营方法论主轴的选择理由，支撑 07 号材料的深入。
