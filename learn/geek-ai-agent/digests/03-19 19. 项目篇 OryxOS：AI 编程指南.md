# Digest — 03-19 19. 项目篇 OryxOS：AI 编程指南

## Overview (L1)

- 实施总览 — Two-phase hybrid mode: main development with Spec-Kit (predictable full spec-driven flow for the 9-module greenfield project), increment development with manual prompting + Claude Code (small 1–3 file changes); existing requirements/tech docs are fed to Spec-Kit, not rewritten.
- Spec-Kit 跟 OryxOS 的匹配度评估 — Spec-Kit fits medium-large greenfield projects with clear requirements, AI-agent collaboration, and methodology goals; OryxOS matches all criteria; known limits (over-heavy for small increments, spec doesn't auto-sync, context limit, fast iteration) and their responses.
- 准备阶段 — Scaffolding before implementation: install Specify CLI + configure Claude Code, then produce three artifacts — constitution (non-negotiable principles), spec (5 user stories), plan (tech stack + 9 modules + decisions).
- 基于 Spec-Kit 的实施拆解 — Per-user-story decomposition (US-1 LLM, US-2 ReAct, US-3 Memory, US-4 Plugin Tool, US-5 Web Service): goals, involved modules, task-splitting approach, key task granularity, acceptance demo.
- 项目交付物 — OryxOS 1.0 as minimal complete runtime kernel; project homepage; retained Spec-Kit artifacts; community docs.
- 增量阶段：手动提示词模式 — After core, switch to manual prompting with Claude Code; issue→fork→Claude→PR→review workflow; retain constitution/spec as references.
- 风险和注意事项 — Spec-Kit limits (version locking, official docs, cautious use of 70+ extensions) and common challenges (AI drifting from constitution, cross-US context breaks, skipped analyze, MCP integration pitfalls, Java fundamentals prerequisite).
- 总结 — Two-phase implementation; Spec-Kit fits OryxOS strongly; the key strategy is feeding existing docs (latest version) to Spec-Kit and splitting by user story, not by time.
