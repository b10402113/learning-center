# Digest — 03-23 23. 项目篇 When：AI 编程实施指引

## Overview (L1)

- Purpose — an execution guide (not methodology) for how, over the 3-week camp, to actually build When with AI end-to-end: what to do each step, which tools, why, and how to hand tasks to AI.
- Overall approach — full-chain AI collaboration with humans judging at a higher level; AI participates in requirement clarification, Spec, architecture, implementation, testing, deployment, monitoring. When uses the "lightweight hand-rolled mode" (CLAUDE.md + Skills + hand-maintained task list) rather than a heavy SDD tool like Spec-Kit, while retaining SDD's core (spec-first, AI codes to spec, human review).
- Six-step path — ① design Harness guardrails; ② break Spec from requirements/design (the intellectual core); ③ task execution (AI codes, humans review each PR); ④ testing (AI writes unit/integration/fault-injection/perf tests, humans supplement edge cases); ⑤ deploy scripts + CI; ⑥ deploy online and monitoring/ops.
- Harness — root CLAUDE.md (project identity, tech stack/constraints, forbidden zones/principles), per-module CLAUDE.md (seven core modules), Skills library (repeated standard patterns like add-sink/add-api-endpoint/add-metric), Hooks (Spotless, Checkstyle/SpotBugs/PMD, JaCoCo+Surefire, full Maven build), and Plan Mode rules for risky operations.
- Spec breakdown — document-driven + task list; first layer = seven core modules + infrastructure; second layer = concrete tasks; granularity 100–500 lines of core code, single responsibility, clear acceptance, no cross-module jumping; task card fields (ID, title, goal, input, output, acceptance, forbidden zones, estimate); one task = one Issue = one PR; worked examples TW-001 (single-layer wheel) and RP-002 (Master→Slave gRPC sync); the list is not one-shot, evolves via PR.
- Task execution and review — pick a completable task, branch, load CLAUDE.md, hand the card to AI; complex tasks Plan-first, simple ones go direct; intervene at key decisions, near-completion, and test failures; when stuck, fix the card/CLAUDE.md/granularity not the AI; review order = correctness → quality → tests → integration; merge requires CI green, at least one real review, all acceptance criteria met, clear commits, and synced card updates.
- Testing — unit tests written with the code (80% coverage gate), AI's common test anti-patterns (coverage-padding, only happy path, coupling to internals); integration tests with Testcontainers; fault-injection tests (kill Master <10s takeover, ETCD/Redis outage, network partition via toxiproxy); performance tests with JMH + wrk, run weekly not per-PR.
- Deploy/CI/ops — AI writes Dockerfile, docker-compose, K8s yaml, GitHub Actions (build/unit/integration/docker/publish), PR/Issue templates; CI-failure handling guidance; deployment in three environments with a staged cadence; Prometheus + Grafana; AI-assisted debugging (collect evidence then analyze); Runbooks as ops knowledge.
- Tools and anti-patterns — a per-stage tool panorama (Claude Code, CLAUDE.md, Skills, Hooks, Markdown/Issues, Git/PR, JUnit/Mockito/JaCoCo/Testcontainers/JMH/wrk/Toxiproxy, Docker/K8s/GitHub Actions, Prometheus/Grafana); seven disallowed anti-patterns (AI as autocomplete, human rewrite, 50/50 mixing, no-review merge, bypassing CLAUDE.md with ad-hoc constraints, mutating task cards mid-flight, tool-stacking to mask missing thought).
- Three-week landing — week 1 Harness + task list; week 2 core scheduling/storage and single-node end-to-end; week 3 cluster/HA/other Sinks/console/deploy; weekly retro on AI ratio, review quality, coverage, CI stability; end-of-camp deliverables and community onramp.

### 5-第三步：任务执行

- Locator: `[[sources/geek-ai-agent/20260922/03-23 23. 项目篇 When：AI 编程实施指引.html#5-第三步任务执行]]`
- Summary: How to start a task, work with AI, handle getting stuck, and review.
- Key claims: pick a task you can fully complete, branch, start Claude Code (auto-loads CLAUDE.md), hand over the full card plus any extra context before starting; complex tasks Plan-first, simple ones direct; intervene at key technical decisions, near-completion, and test failures (check whether the test or the code is wrong); when stuck — re-read the card (unclear spec), re-check CLAUDE.md (constraint gap), supply missing context, or re-split (too-large granularity) — fix the source, not the AI; review importance order correctness/quality/tests/integration with AI's common pitfalls listed; merge conditions: CI green, ≥1 real review comment, all acceptance met, clear commit messages, card updates merged.
- Learner-relevant: A repeatable human-AI task loop and review discipline.

### 6-第四步：测试

- Locator: `[[sources/geek-ai-agent/20260922/03-23 23. 项目篇 When：AI 编程实施指引.html#6-第四步测试]]`
- Summary: Unit, integration, fault-injection, and performance testing.
- Key claims: unit tests written alongside code (not after), 80% JaCoCo gate in CI; AI's test pitfalls (coverage-padding getters/setters, only happy path, tight coupling to internals) and how to correct via specific scenario lists in the card; integration tests with Testcontainers covering the core end-to-end scenarios (30s delivery, 1000-message precision, kill Master <10s, cancel, Kafka sink), run in CI not locally; fault-injection tests (kill Master, ETCD/Redis outage, network partition via toxiproxy) — review carefully as test code can be buggy; performance tests with JMH + wrk, run weekly, not per-PR.
- Learner-relevant: Testing as the only way to turn "looks right" into "runs right".

### 10-反模式：这些做法不允许

- Locator: `[[sources/geek-ai-agent/20260922/03-23 23. 项目篇 When：AI 编程实施指引.html#反模式这些做法不允许]]`
- Summary: Seven disallowed practices.
- Key claims: (1) AI as IDE autocomplete; (2) human rewrite after AI; (3) hand-half/AI-half mixing (an AI-generated ratio cannot be measured); (4) merge without review (empty approval does not count); (5) bypassing CLAUDE.md with ad-hoc conversation constraints (repeat constraints belong in CLAUDE.md); (6) mutating a task card mid-flight (stop and re-split, or append a new task); (7) tool-stacking to mask missing thought; keeping these makes 90% AI a natural result, not a fudged number.
- Learner-relevant: Guardrails that preserve the collaboration posture.
