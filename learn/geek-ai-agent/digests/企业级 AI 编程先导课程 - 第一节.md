# Digest — 企业级 AI 编程先导课程 - 第一节

## Overview (L1)

- Purpose and cognition map — The first pre-course lesson builds the full cognition map before any technique: the essence of AI programming, the real state of the industry, the tool landscape, and the SDD + Harness methodology.
- Essence — A programmer's purpose never changed (deliver value faster and better); what changed is the path, in three layers: surface (coding → AI-driven judgment), middle (diligence → clarity), deep (code producer → value producer).
- Industry reality — Four judgments: infrastructure is still in a boom phase, tools are converging in capability, investing in abstractions outlasts tools, and real productivity gains are ~30%, not 10x.
- Tools — A seven-layer architecture (models → tools → config → collaboration → protocol → workflow → methodology) plus three questions to place any new tool.
- Methodology — SDD solves "thinking," Harness solves "doing"; together they form the current most complete closed loop.
- Summary/next — Consolidates essence, market map, and methodology; previews core competitiveness.

### essence
- Locator: `[[sources/geek-ai-agent/20260922/企业级 AI 编程先导课程 - 第一节.pdf#essence]]`
- Summary: The programmer's leverage changed four times (low-level capability → frameworks → cloud-native → AI-driving). The essence never changed: value, not code. The path shifted in three layers, triggering chain reactions.
- Key claims: code is the means, value is the end; surface layer — from coding feel to judgment/acceptance/decision; middle layer — from diligence to clarity; deep layer — from code producer to value producer; leverage now has intelligence, so the engineer manages a powerful but constrained executor; responsibility is rewritten (you own AI's output even unread lines); polarization accelerates; super-individuals are possible but the bar is higher (judgment + execution + value perception).
- Learner-relevant: Core mental model that removes tool anxiety and reframes what to train ("thinking" engineered).

### industry
- Locator: `[[sources/geek-ai-agent/20260922/企业级 AI 编程先导课程 - 第一节.pdf#industry]]`
- Summary: Four grounded judgments about the industry, plus expectation management backed by IBM + AWS production data.
- Key claims: 2026 is still an infrastructure boom (like selling shovels in 1849); Claude Code/Cursor/Codex core abilities converge; learn abstractions behind tools (MCP/SDD/Subagents outlive specific tools); production reality is ~30% development-time reduction vs the unsupported "10x" marketing claim, and most enterprise pilots show no significant return.
- Learner-relevant: Calibrates expectations and redirects effort from chasing tools to durable abstractions.

### seven-layer-tools
- Locator: `[[sources/geek-ai-agent/20260922/企业级 AI 编程先导课程 - 第一节.pdf#seven-layer-tools]]`
- Summary: A classification anchor for tools across seven layers, plus three questions to judge any new tool: which layer, what problem it solves, and whether you need it now.
- Key claims: the number of tools is not the problem — lacking a classification anchor causes anxiety; ~95% of new tools are irrelevant to your current situation, so put them down.
- Learner-relevant: A reusable framework for locating and evaluating tools rather than chasing them.

### methodology-overview
- Locator: `[[sources/geek-ai-agent/20260922/企业级 AI 编程先导课程 - 第一节.pdf#methodology-overview]]`
- Summary: Landscape of methodologies and the three selection criteria (mature, teachable, covers the full engineering lifecycle).
- Key claims: main axes are SDD and Harness Engineering; Vibe Coding is the foundation (needs practice, not teaching); Context Engineering is a long-term frontier still evolving; ReAct/TAO and Test-Driven AI are supplements with narrower scope.
- Learner-relevant: Justifies why the course focuses on SDD + Harness as the backbone.

### sdd
- Locator: `[[sources/geek-ai-agent/20260922/企业级 AI 编程先导课程 - 第一节.pdf#sdd]]`
- Summary: Spec-Driven Development with a four-phase workflow: /specify → /plan → /tasks → /implement.
- Key claims: spec is the truth and code serves it; SDD engineers "thinking clearly" into clear inputs AI can consume; without SDD, collaboration is intuitive chatting; with it, there is an explicit contract.
- Learner-relevant: The first pillar — how to make AI depend on specs rather than guessing.

### harness
- Locator: `[[sources/geek-ai-agent/20260922/企业级 AI 编程先导课程 - 第一节.pdf#harness]]`
- Summary: Harness Engineering — four pillars: System Prompt (CLAUDE.md/AGENTS.md), Tools (Skills/slash commands/MCP), Context (subagents/memory/worktrees/plan mode), Subagents, plus Permission/Hooks.
- Key claims: Harness turns a "runaway executor" into a "controllable collaborator"; pre-constraint (Permission) plus post-check (Hooks) form the safety net.
- Learner-relevant: The second pillar — how to keep AI on rails with rules, tools, context, and verification.

### sdd-harness-synthesis
- Locator: `[[sources/geek-ai-agent/20260922/企业级 AI 编程先导课程 - 第一节.pdf#sdd-harness-synthesis]]`
- Summary: Combines the two methodologies: SDD answers "what to do," Harness guarantees "doing it right."
- Key claims: shared underlying assumption — AI is not trusted but is used in an engineered way; learning SDD alone means specs are good but AI can drift with no control; both together form the closed loop.
- Learner-relevant: The central synthesis the whole course builds on.

### other-methodologies
- Locator: `[[sources/geek-ai-agent/20260922/企业级 AI 编程先导课程 - 第一节.pdf#other-methodologies]]`

- Learner-relevant: Shows where the remaining methods belong so the learner can decide when to use each.
