# Digest — 03-02 2. 认知篇： AI 编程的本质和方法论体系

## Overview (L1)

- Purpose unchanged — Programmers' purpose was never to write code but to deliver value faster/better; code is the means, value is the end. Each era's leverage changes (low-level → frameworks → cloud-native → now, driving AI).
- Path changed — Three telescoping changes: core action (write code → drive AI), ability structure (diligence → clarity), identity (code producer → value producer using AI).
- Implications — Leverage keeps rising, responsibility is rewritten onto the person driving AI, polarization accelerates, the "super individual" becomes possible but its bar is higher than assumed.
- Personal response — Do not treat AI programming as a new career; shift from doing to thinking; learning tools is foundational but not the goal.
- Methodology — Of the crowded landscape, only SDD (spec-driven development) and Harness Engineering are mature, teachable, and cover the full engineering chain; they solve "thinking" and "doing" respectively and are complementary.

### 一、目的从未变过
- Locator: `[[sources/geek-ai-agent/20260922/03-02 2. 认知篇： AI 编程的本质和方法论体系.html#目的从未变过]]`
- Summary: Refutes the assumption "programmer's value = writing code"; the profession's end is producing value for users/business.
- Key claims: leverage changed from scarce low-level skill (C/C++, OS/game engines) → frameworks/platforms (Java/Python/Rails) → cloud-native/distributed (K8s, microservices) → driving AI; every leverage shift produced "programmers will be obsolete" claims; none eliminated programmers, only those who failed to follow the leverage shift.
- Learner-relevant: Dissolves the learner's existential anxiety with a historical frame.

### 二、路径变了什么
- Locator: `[[sources/geek-ai-agent/20260922/03-02 2. 认知篇： AI 编程的本质和方法论体系.html#路径变了什么]]`
- Summary: Three progressively deeper changes: core action, ability leverage point, identity.
- Key claims: core action becomes driving AI, moving the core ability from feel (手感, built by time) to judgement (判断, built by cognition); diligence no longer the key variable — clarity is, making engineer gaps exponential instead of linear; identity shifts to "someone who gets things done with AI," caring about purpose (is it useful) over means (elegant code).
- Learner-relevant: Defines the specific skill to train (judgement/clarity) and why.

### 三、这意味着什么
- Locator: `[[sources/geek-ai-agent/20260922/03-02 2. 认知篇： AI 编程的本质和方法论体系.html#这意味着什么]]`
- Summary: Four harder judgements pushed to their extremes.
- Key claims: leverage position keeps rising and this time the leverage itself is intelligent (manage a powerful but constrained executor); responsibility is rewritten — code is AI-written but responsibility is entirely the driver's ("I didn't harness AI well"); polarization accelerates; "super individual" (超级个体) existed before AI (Carmack, Linus, Notch) and is defined by value produced, not speed.
- Learner-relevant: Corrects over-optimistic self-expectations and clarifies accountability.

### 五、方法论的当前景观
- Locator: `[[sources/geek-ai-agent/20260922/03-02 2. 认知篇： AI 编程的本质和方法论体系.html#方法论的当前景观]]`
- Summary: Surveys the methodology landscape and its maturity differences.
- Key claims: SDD (spec-first, Spec-Kit/OpenSpec/Tessl); Harness Engineering (harness a strong but unbounded AI — System Prompt/Tools/Context/Permission/Hooks/Plan Mode); Vibe Coding (chemistry/fluency); Context Engineering (context quality decides output, still evolving); ReAct/TAO agent frameworks (autonomous plan-execute-reflect, narrow scope); Test-Driven AI (tests constrain AI, a practice not a full methodology); plus Plan-then-Execute, AI-First Architecture.
- Learner-relevant: Gives the learner the full landscape before choosing a training spine.

### 六、为什么主轴是 SDD 加 Harness
- Locator: `[[sources/geek-ai-agent/20260922/03-02 2. 认知篇： AI 编程的本质和方法论体系.html#为什么主轴是-SDD-加-Harness]]`
- Summary: Selection criteria are maturity, teachability, full-engineering coverage; only SDD and Harness pass.
- Key claims: SDD solves "thinking" — engineering spec turns fuzzy needs into AI-digestible explicit inputs; Harness solves "doing" — constraints keep AI within bounds; they are complementary (SDD says what, Harness guarantees correct) and share the assumption "AI is not trusted, it is engineered-used" (AI is a powerful executor lacking judgement boundaries).
- Learner-relevant: Justifies the course spine and gives the unifying mental model.
