# Digest — 03-18 18. 项目篇 OryxOS：技术方案文档

## Overview (L1)

- 方案概述 — OryxOS is a Spring Boot 3.x monolith on JDK 21 using Spring AI Alibaba for LLM calls with a self-implemented ReAct loop; single executable JAR; tech stack JDK 21 + Spring Boot 3.x + Spring AI Alibaba + self-built ReAct + SQLite + Picocli. Lists 7 key decisions (self-implement ReAct, Spring AI boundary, sync + virtual thread, @Tool + OryxTool, Spring MVC + virtual thread, path/pattern whitelist sandbox, SQLite + MEMORY.md + audit day-one).
- 整体架构 — A single Spring Boot monolith with two entrances (CLI Channel, Web Service) feeding one ReAct engine that schedules Provider/Memory/Tool over a storage layer; four layers (access, engine, capability, foundation); the five capabilities' collaboration relationship.
- 核心能力一：对接 LLM（Provider 抽象） — ProviderService wrapping Spring AI's ChatClient, Function Calling adaptation (format conversion only, no auto-execution), provider config, explicit provider-name to ChatModel mapping; no fallback in core; basic cost transparency.
- 核心能力二：ReAct 循环 — The core loop algorithm, ReActLoop/PromptBuilder/ToolExecutor modules, MAX_ITERATIONS, message accumulation, context-length management.
- 核心能力三：Memory 三层记忆 — MemoryService as a unified facade over session + long-term memory; LongTermMemory (MEMORY.md) with append/load/recallByKeyword/truncateIfNeeded; MemoryTools (save_memory/recall_memory); injection into system prompt; MEMORY.md vs USER.md; deferred items.
- 核心能力四：Tool 体系 — OryxTool abstraction; five builtin tools; Plugin Tool three ways (zero-code SKILL.md+MCP, self-written MCP server, Java Spring Bean); ToolRegistry; Sandbox path/pattern whitelist checker.
- 核心能力五：Web Service — WebServer, six ApiControllers, GlobalExceptionHandler, OpenAPI; core 10 endpoints; deferred endpoints; error codes/CORS/size/timeout; deferred auth/SSE; integration scenarios.
- 支撑模块 — Workspace init, Profile config/registry, ContextLoader (Bootstrap+Skill unified), Channel access (CliChannel), three run modes, CLI (12 subcommands), config/secrets loading.
- 数据持久化 — SQLite + Spring Data JPA for relational; MEMORY.md + keyword for long-term memory; why not a vector DB in core; three upgrade paths (LanceDB/pgvector/JVector); three tables (sessions, tool_invocations, llm_calls); SQLite ALTER TABLE update risk warning; file-system data.
- 项目工程结构 — 9 Maven modules with responsibilities and decoupling via interfaces.
- 关键流程 — Five end-to-end demos wired through the capabilities, matching requirements ch.13.
- 实施节奏（4 周） — Weekly implementation content and demos.
- 性能和可扩展性考虑 — Virtual threads, 1000 concurrent sessions memory, MEMORY.md file IO, startup time (CLI split, GraalVM later).
- 总结 — Recap of the technical plan and five capabilities.
