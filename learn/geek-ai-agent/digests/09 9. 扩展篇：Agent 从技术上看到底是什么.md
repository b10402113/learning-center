# Digest — 09 9. 扩展篇：Agent 从技术上看到底是什么

## Overview (L1)
- 一、Agent 的一句话技术定义 — Agent 是能感知环境、自主决策、执行动作、并基于反馈循环迭代的程序；定义里没有 "LLM" 三个字，Agent 抽象早于 LLM。2026 年工程实现为 5 组件 + 1 循环：LLM + Tools + Memory + Loop + Environment。
- 二、Agent 的五个技术组件 — 逐一展开 LLM（决策引擎）、Tools（行动能力）、Memory（状态承载）、Loop（循环执行）、Environment（交互对象）的职责、工程实现与关键判断。
- 三、五个组件怎么串成一个 Agent — 用"读 README 翻译成中文"的例子展示任务在五组件里转圈流转，说明所有复杂 Agent 都是这个最小结构的放大版。
- 四、用 5 组件解释你见过的所有 Agent 产品 — 拆解 ChatGPT、Claude Code、Cursor、LangChain、Hermes Agent、AutoGPT 六个产品，验证"都是同一个抽象的不同实现"。
- 五、Agent vs 几个容易混淆的概念 — 区分 Agent vs LLM、Chatbot、Workflow，Workflow 确定性 vs Agent 探索式。
- 六、从单个 Agent 到 Agent OS — Agent 是应用程序，Agent OS 是操作系统（进程管理、工作空间隔离、模型路由、安全沙盒、可观测）；并区分 Single-Agent 与 Multi-Agent。
- 七、Agent 技术栈的三层结构 — L1 基础模型层、L2 Agent 运行时层、L3 Agent 应用层；L2 是 2026-2028 年最缺人、最值得进入的层。
- 八、2026 年 Agent 技术的真实状态 — 已形成共识（ReAct、MCP、五组件）、还在争论的（Agent OS 形态、Memory、Multi-Agent、安全）、快速演进的（Multi-Agent、MCP 生态、loop 深度）。
- 九、用 5 组件抽象自测一下 — 四道判断题检验抽象是否真正掌握。
- 十、总结 — 五组件 + 一循环的抽象有四价值：判断、设计、比较、沟通；Agent OS 是让很多 Agent 稳定共存的操作系统。

### five-technical-components
- Locator: `[[sources/geek-ai-agent/09 9. 扩展篇：Agent 从技术上看到底是什么.html#二、Agent 的五个技术组件]]`
- Summary: 逐一展开五个组件：LLM 负责理解、规划、调工具、解读结果、判断完成；Tools 是行动手段（本地/网络/数据库/系统/MCP 工具）；Memory 分短期（context）与长期（外部存储）；Loop 是 ReAct 循环；Environment 是 Agent 的"世界"。
- Key claims: LLM 不碰真实世界只下指令，干活的是框架；Tools 边界 = Agent 自主性边界；短期记忆必需、长期记忆高阶；Loop 决定 80% 的工程质量，早期死循环 Agent 问题都出在 Loop；Environment 能力上限决定安全底线（沙盒是其安全设计）；MCP 是 2025-2026 Tools 标准化的重要进展。
- Learner-relevant: 提供 5 组件的每个组件独立解释，可支撑"Agent 本质""工具调用""记忆系统""ReAct 循环"等元素。
