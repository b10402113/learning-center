# Digest — 03-14 14. 扩展篇：AI 时代的软件工程

## Overview (L1)

- Theme: software engineering reorganized around a new center — As code shifts from scarce to cheap, does the foundation of a discipline built on "code is the core artifact" loosen? The article surveys 2026 academic and practitioner evidence to answer what changes, why, into what shape, and what programmers should watch.
- Premise: the debate's level has changed — "Can AI program?" is settled: SWE-bench Verified rose from 1.96% (Oct 2023) to 78.4% (Apr 2026); a multi-million-line legacy migration was compressed from years to weeks (~12x savings). Academia reframes the center from "code generation" to "delegated execution under human supervision".
- Change 1: code from asset to output — When marginal generation cost approaches zero, code becomes an "abundant and increasingly disposable commodity"; SDD (spec-driven development) makes specification the main artifact and code its expression; TDD is unit-level SDD; but SDD is far from mature (Thoughtworks rates it "Assess") and there is no consensus on what a spec is.
- Change 2: bottleneck shifts from generation to verification — The "verification gap": 96% of developers distrust AI code but only 48% consistently verify it; AI assistants are ~4x faster but deliver ~10x risk; ~1/5 of vulnerabilities are AI-caused. Root cause is the "intent gap": AI code is "plausible by construction" but not "correct by construction"; Meyer argues prompt engineering is requirements engineering and the way out is formal specs/verification; capital (Qodo, $70M) is betting on verification.
- Change 3: cognitive debt beyond technical debt — GitClear (153M lines) finds 4x duplication and rising short-term churn; AI re-implements logic instead of reusing it; >100k AI-introduced surviving issues by Feb 2026. Thoughtworks Deer Valley gathering (~50 top figures incl. Kent Beck, Martin Fowler) coined "cognitive debt": nobody fully understands AI-generated code, and it compounds; "speed without understanding is unsustainable"; review time nearly doubled because reviewers rebuild skipped understanding; debt shows up 12–24 months later.
- Practitioner practice — Kent Beck treats AI as an "unpredictable genie" and does "augmented coding" (not vibe coding): cares about code, complexity, tests, coverage; watches for warnings (unrequested features, cheating like disabling tests); "the genie eats the seed corn"; AI lacks taste; compresses juniors' search space. Martin Fowler: LLM change is assembly→high-level-language scale; the future belongs to the "Expert Generalist". Boris Cherny: 100% AI-written code is possible but "ultimately, it's the human doing it".
- Change 4: engineer role and hidden risk — Mainstream narrative: builder → supervisor (human-in-the-loop). Hidden risk: "accountability collapse" — if nobody understands code that AI generated and AI verified, who is responsible when it fails? "Supervision" degenerates into a rubber stamp; responsibility requires understanding.
- What matters more, not less — "Judgment" in three layers: express intent precisely (intent gap / requirements engineering), see the whole system and its seams (Expert Generalist), and define "what is correct" to verify and be accountable for AI output — all require being present.
- What programmers should watch — Four focuses: "thinking clearly" over "writing fast"; understanding (don't delegate it); system-level judgment (specialist → expert generalist); new paradigms without blindly believing them (SDD/agentic engineering/A-SDLC still in "Assess").
- Conclusion — Software engineering isn't ended but compressed: the "writing code" layer thinned, the "understand/judge/verify/be accountable" layers thickened; the emphasis of the word moves from "software" to "engineering".
