# Digest — 05 5. 认知篇：AI 编程市场观察和工具全景

## Overview (L1)
- 一、AI 编程的认知三阶段 — 把 AI 当写代码工具（Copilot 时代，天花板 1.5x）→ 学习 AI 工具的奇技淫巧（当下最大最焦虑人群）→ 意识到这是工作流的事（业界正形成的共识）。
- 二、"越学越焦虑"的根源 — 本质不是工具，是怎么用好工具；"用得好"=知道目的+用对工具，不等于知道更多工具；判断力才是要训练的。
- 三、市场的真实状态：有共识，缺方法 — 大多数人停留在"学工具"阶段是真实市场需求，少数人靠打磨工作流快速进化；需要两张地图（市场地图+工具地图）。
- 四、看清工具，先看清它的层次 — 工具焦虑根源是缺少分类锚点，给出七层架构作为分类框架。
- 五、AI 编程工具的七层架构 — 模型层→工具层→配置与约束层→协作机制层→协议与生态层→工作流层→方法论层，每层有职责与代表工具。
- 六、不同层的工具怎么配合 — 三个场景（写新模块/改造大型陌生项目/接进 CI/CD）展示多层协同，真正的工程感是"同时调用多层"。
- 七、新工具来了怎么判断 — 三个问题：属于哪一层？解决什么问题？现在需要吗？识别 95% 工具噪音 vs 5% 结构性变化。
- 八、总结 — 焦虑解法是拿到市场地图+工具地图两张认知地图，判断能力迭代比工具迭代有价值。

### 第一阶段：把 AI 当写代码工具。
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#第一阶段：把 AI 当写代码工具。]]`
- Summary: 最早把 AI 当"写代码的工具"（生成代码/补函数/改 bug/解释源码），Copilot 时代典型用法。
- Key claims: 这个理解没错但太浅；把 AI 限定为"代码生成器"，红利顶多 1.5 倍速度，天花板低。

### 第二阶段：学习 AI 工具的奇技淫巧。
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#第二阶段：学习 AI 工具的奇技淫巧。]]`
- Summary: 意识到 AI 不只是写代码工具后开始学各种用法（prompt/agent 模式/hook/MCP/Skills/Subagents）。
- Key claims: 这是当下最大人群、也是最焦虑的人群；"用得好 AI"被误等同于"知道更多 AI 技巧"，越学越多越乱。
- Learner-relevant: 识别"奇技淫巧陷阱"。

### 第三阶段：意识到这是工作流的事。
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#第三阶段：意识到这是工作流的事。]]`
- Summary: 少数人意识到 AI 编程是整个软件工程工作流的事，AI 从需求那一刻起就应介入全链路。
- Key claims: AI 编程本质是"AI 进入你的工程链路"而非"AI 帮你写代码"；Anthropic/GitHub 等都在强调；但中间不平滑，业界自己也在摸索，缺方法。
- Learner-relevant: 建立"工作流"视角，这是后续全部内容的支点。

### 二、"越学越焦虑"的根源
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#二、"越学越焦虑"的根源]]`
- Summary: 根源是一句话——本质不是工具，是怎么用好工具；两个本质不同的事被搞混。
- Key claims: "用得好"=知道目的+用对工具，"不等于知道更多工具"；奇技淫巧没有尽头；真正要训练的是看到新工具时先问"它解决什么问题、我现在有没有、比现有的好在哪里"的判断力。
- Learner-relevant: 训练工具判断力，避免追新循环。

### 三、市场的真实状态：有共识，缺方法
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#三、市场的真实状态：有共识，缺方法]]`
- Summary: 说清市场两面的真实分布：大多数人停留在学工具（真实市场需求），少数人在快速进化。
- Key claims: 市面 80% 的 AI 编程课教工具操作、5% 讲思想但用不上；进化快的是把基础工具跑通并反复打磨工作流的人；"会用 AI 玩"与"会用 AI 把事情做成"差距前所未有地大。
- Learner-relevant: 选择站在"把事情做成"一边，需要两张认知地图。

### 五、AI 编程工具的七层架构
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#五、AI 编程工具的七层架构]]`

- Key claims: 看到任何 AI 编程相关的东西都能定位到某一层，判断要不要学。

### 5.1 第一层是模型层
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#5.1 第一层是模型层]]`
- Summary: 提供 AI 编程"原料"的一层：闭源（Claude/GPT/Gemini）、开源（DeepSeek/Qwen/Llama/Mistral）、私有部署（Ollama/vLLM/LM Studio）。
- Key claims: 模型是原料不是工具本身——同一模型可被 Cursor/Claude Code/Cline 调用；"用 Claude"讲模型、"用 Cursor"讲工具，不是同一维度。
- Learner-relevant: 分清模型层与工具层，正确选型。

### 5.2 第二层是工具层
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#5.2 第二层是工具层]]`
- Summary: 把模型变成可用编程工具的层，三种形态：IDE 内嵌（Cursor/Windsurf/Copilot/Trae）、终端 CLI（Claude Code/Codex CLI/OpenCode/Aider）、SDK（Claude Agent SDK/OpenAI Agents SDK）。
- Key claims: 三种形态不是替代是配合（IDE 日常编码+CLI 复杂任务+SDK 造工具）；工具层数量最多迭代最快噪音最大，占市面 80% 讨论，要带着上面几层视角学。
- Learner-relevant: 工具形态选型，避免"比 IDE vs CLI 谁强"的错误问题。

### 5.3 第三层是配置与约束层
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#5.3 第三层是配置与约束层]]`
- Summary: 让 AI 工作时遵守规则的层：项目说明（CLAUDE.md/AGENTS.md/.cursorrules）、能力封装（Skills/Slash Commands）、约束机制（Permission/Hooks）。
- Key claims: 没有这层 AI 是"什么都能做但不知道项目规则"的通用助手；有了它变"懂你项目的协作者"，产出质量差几个层次；会不会这层决定你是"AI 编程的用户"还是"AI 编程的工程师"。
- Learner-relevant: 工程化核心层，支撑 Harness 相关训练。

### 5.4 第四层是协作机制层
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#5.4 第四层是协作机制层]]`
- Summary: 让 AI 能并行、能隔离、能规划的层：任务隔离（Subagents）、任务并行（Worktrees）、任务规划（Plan Mode）。
- Key claims: 单 Agent 两个问题=上下文污染与串行慢；Subagents 解决污染、Worktrees 解决并行、Plan Mode 解决乱动手；学会后是"和 AI 团队工作"，生产力从个体升到团队水平。
- Learner-relevant: 从"一个 AI"到"一个 AI 团队"的关键一跳。

### 5.5 第五层是协议与生态层
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#5.5 第五层是协议与生态层]]`
- Summary: 让 AI 连接外部世界的层：协议（MCP）与集成（gh CLI、CLI 工具、API 包装）。
- Key claims: MCP 是 AI 编程从孤立到联通的转折点，类比"USB-C"；一个 MCP Server 写一次，Cursor/Claude Code/Cline 都能用；学会后 AI 从"代码助手"变"工程助手"。
- Learner-relevant: 理解 MCP 的生态价值，衔接 04 号材料 MCP 判断。

### 5.6 第六层是工作流层
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#5.6 第六层是工作流层]]`
- Summary: 让 AI 编程从"交互式"变"自动化"的层：Headless Mode（claude -p 接 CI/CD）、工作流编排（GitHub Actions/Jenkins/n8n+AI）、事件触发。
- Key claims: 前几层是"人在循环里"，这层是"人不在循环里"；是 AI 编程最高效率形态，产出是"自动化的工作流"而非"代码"；顶级工程师必须掌握，是真正拉开收入差距的层。
- Learner-relevant: 设定工作流自动化的进阶目标。

### 5.7 第七层是方法论层
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#5.7 第七层是方法论层]]`
- Summary: 用工具的"思想"层，决定怎么组织前六层：SDD（规格先行）、Harness Engineering（让 AI 好好干活的工程框架，核心机制 System Prompt/Tools/Context/Subagents）、Vibe Coding（用熟比会用更重要）。
- Key claims: 没有方法论前六层是"散装零件"，有了变"统一系统"；工具会迭代，方法论才真正持久；学工具建短期生产力，学方法论建长期判断力。
- Learner-relevant: 方法论作为顶层框架，衔接 07 号材料。

### 5.8 总结
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#5.8 总结]]`
- Summary: 七层架构合起来，任何 AI 编程相关的东西都能在这张图上找到位置。
- Key claims: 判断新工具属于哪层、补哪层能力、和已会工具什么关系，这种判断能力比掌握多少工具都重要。
- Learner-relevant: 七层图作为工具判断的持久框架。

### 六、不同层的工具怎么配合
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#六、不同层的工具怎么配合]]`
- Summary: 用三个常见场景展示七层如何联动，真正的工程能力在不同层的流畅协作。
- Key claims: 场景化理解比抽象分层更重要。
- Learner-relevant: 为各项目（When 新模块/DifyPro 改造/mq9 CI）提供分层配合示例。

### 6.1 场景一：用 AI 写一个新模块。
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#6.1 场景一：用 AI 写一个新模块。]]`
- Summary: 给已有项目加"用户认证"模块，七层协同：SDD 思路→Spec-Kit 落地→CLAUDE.md 约束→Plan Mode 规划→Claude Code 执行→Claude 生成→Hooks 收尾验证。
- Key claims: 七层不是顺序使用，是同时存在、协同工作；"同时调用"的能力才是真正的工程感。
- Learner-relevant: 新模块开发的标准多层配合模式。

### 6.2 场景二：让 AI 给一个大型陌生项目做改造。
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#6.2 场景二：让 AI 给一个大型陌生项目做改造。]]`
- Summary: 接手十万行开源项目（如 Dify）做企业级二开：Subagents 并行读模块、CLAUDE.md 沉淀架构、OpenSpec 写 delta spec、Permission 限改 extension 目录、Hooks 跑全套测试、MCP 接外部工具。
- Key claims: 大型改造难点不是会写代码，是不破坏原系统增量改造；配置层和协作层比工具层更重要（Permission/Hooks/Subagents 是关键，Claude Code 只是执行层）。
- Learner-relevant: 直接支撑 DifyPro 项目的训练重点。

### 6.3 场景三：把 AI 编程接进 CI/CD。
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#6.3 场景三：把 AI 编程接进 CI/CD。]]`
- Summary: 每次 PR 提交让 AI 自动 review/测试/生成部署预览/汇总：GitHub Actions+Headless 触发、claude -p 执行、gh CLI 评论 PR、CLAUDE.md 定标准。
- Key claims: 工作流层是核心，把前面所有层串成无人值守流水线；有 AI 工作流的团队和无的产出差几倍。
- Learner-relevant: 工作流自动化的实际落地形态。

### 6.4 总结
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#6.4 总结]]`
- Summary: 七层架构的真实价值是"知道在什么场景下让哪几层协作"，而非"知道有这些层"。
- Key claims: 不再问"该不该学这个工具"，而问"我现在的场景需要哪几层能力、现有工具够不够好"——从被工具裹挟到主导工具。
- Learner-relevant: 场景驱动选型的心智转变。

### 七、新工具来了怎么判断
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#七、新工具来了怎么判断]]`
- Summary: 新工具来了回答三个问题：它属于哪一层？它解决什么问题（相对现有代表工具的差异）？你现在需要它吗？
- Key claims: 三个问题问完大多数"新工具焦虑"自动消解；要警觉真正结构性变化（如 MCP 普及改变了"AI 和外部工具怎么连接"本身）；七层架构过滤 95% 噪音，关注 5% 结构性变化。
- Learner-relevant: 识别结构性变化的标准，避免被营销带偏。

### 八、总结
- Locator: `[[sources/geek-ai-agent/05 5. 认知篇：AI 编程市场观察和工具全景.html#八、总结]]`
- Summary: 焦虑解法是拿到市场地图（阶段/卡点/前方）+工具地图（层次/定位/投入取舍）两张认知地图。
- Key claims: 追上"工具迭代"本身没有价值，有价值的是"判断能力的迭代"；自己的工作流跑顺才是真正属于你的资产。
- Learner-relevant: 全文收束——用地图替代追新。
