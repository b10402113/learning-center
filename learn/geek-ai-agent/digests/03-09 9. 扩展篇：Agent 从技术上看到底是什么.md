# Digest — 03-09 9. 扩展篇：Agent 从技术上看到底是什么

## Overview (L1)

- Theme: a five-component ruler for Agent — The word "Agent" is overused (API-calling scripts, ChatGPT wrappers, fixed automation all claim it), so the article gives a technical ruler: five components to dissect any claimed Agent and tell real from fake.
- Technical definition — An Agent is a program that perceives its environment, decides autonomously, acts, and iterates via a feedback loop. Each word matters: perceive / decide / act / feedback loop / iterate. The definition omits "LLM" — Agents predate LLMs.
- Five components — LLM (decision engine), Tools (action capability), Memory (state carrier), Loop (cyclic execution), Environment (interaction target); 5 components + 1 loop = the full skeleton.
- How they compose — A concrete README-translation example traces Environment → Memory → 4 ReAct turns, showing all five components participate.
- Explaining real products — Uses the five components to dissect ChatGPT (chatbot vs. Agent after Code Interpreter), Claude Code, Cursor Agent mode, LangChain, Hermes Agent, AutoGPT; six products are the same thing differently implemented; the ritual is to ask five questions about any new Agent product.
- Distinguishing confusable concepts — Agent vs. LLM (CPU vs. whole computer), Agent vs. Chatbot (chatbot is Agent with Tools and Loop removed), Agent vs. Workflow (deterministic vs. exploratory); the core absence test is "the autonomous decision loop".
- Agent vs. Agent OS & Multi-Agent — Agent OS is infrastructure to run many Agents stably (process management, isolation, routing, sandbox, observability); single-Agent should be done before multi-Agent, which is a complexity-higher problem.
- Three-layer stack & 2026 state — L1 base models, L2 Agent runtime (scarcest, 2026–2028 most worth entering), L3 Agent apps; consensus (ReAct, MCP, five-component abstraction) vs. still-contested (Agent OS form, Memory, Multi-Agent, security); self-test quiz.

### five-components

- Locator: `[[sources/geek-ai-agent/20260922/03-09 9. 扩展篇：Agent 从技术上看到底是什么.html#five-components]]`
- Summary: Expands the five components: LLM (understand task, plan, pick tool/params, interpret results, judge completion), Tools (local/network/DB/system/MCP), Memory (short-term context vs. long-term structured/vector/hybrid), Loop (ReAct), Environment (filesystem, network, DB, user interface, other Agents).
- Key claims: LLM is not all of an Agent but its core; the autonomy boundary equals the Tools boundary; Memory short-term is necessary and long-term advanced; Loop design quality determines engineering quality (80% of complexity); Sandbox is the security design of Environment.
