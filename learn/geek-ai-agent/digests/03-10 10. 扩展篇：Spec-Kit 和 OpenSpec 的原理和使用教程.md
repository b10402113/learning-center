# Digest — 03-10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程

## Overview (L1)

- 一、为什么需要 SDD — Explains the 2024–2026 paradigm shift and why "vibe coding" (凭感觉写代码) fails at medium/large scale: requirement drift (需求漂移), architecture loss of control (架构失控), hard rollback (回退困难), poor collaboration. SDD (Spec-Driven Development) adds a structured requirement layer above prompt engineering; surveys the 2025–2026 tool landscape (Spec-Kit, OpenSpec, Kiro, Tessl).
- 二、Spec-Kit 详解 — GitHub's spec-as-source tool: a CLI + slash commands over an AI agent. Philosophy: non-negotiable constitution, a 4-phase closed loop (specify → plan → tasks → implement), 3 optional quality commands. Details the 6+3 command set, full workflow, and fit/limits.
- 三、OpenSpec 详解 — Fission-AI's delta-spec tool: lightweight, flexible, brownfield-first. Uses ADDED/MODIFIED/REMOVED delta markers and a Propose → Apply → Archive state machine, `/opsx:` commands, RFC 2119 / Given-When-Then specs, and custom schemas.
- 四、Spec-Kit 与 OpenSpec 对比 — Contrasts philosophy (spec-as-source vs delta-spec), process (rigid 4-phase vs flexible 3-state), output volume (~3x difference), and fit; provides a decision tree and recommends learning Spec-Kit first, then OpenSpec.
- 五、SDD 在 AI 编程时代的位置 — Compares SDD to waterfall, vibe coding, Cursor Rules / Claude Project docs, and AGENTS.md; argues SDD is a workflow layer that persists decisions and makes spec a human-AI contract.
- 六、学习重点 — Core concepts to master, recommended reading, and hands-on exercises; course preview: OryxOS built with Spec-Kit, OpenSpec as contrast.
- 七、总结 — Spec-Kit and OpenSpec are complementary, not replacements; mastering the SDD paradigm matters more than any single tool.

### 一、为什么需要 SDD

### 二、Spec-Kit 详解

- Locator: `[[sources/geek-ai-agent/20260922/03-10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#二、Spec-Kit 详解]]`
- Summary: Explains what Spec-Kit is, its three-part design philosophy, the 6+3 command system, the standard end-to-end workflow, and its fit/limits.
- Key claims: Spec-Kit is a workflow layer over an AI agent supporting 20+ agents; spec-as-source is its purest form; the constitution is the non-negotiable project charter; the 4-phase loop has no cross-phase shortcuts; analyze is the core anti-drift tool; ~800-line specs are too heavy for small increments.
- Learner-relevant: Concrete Spec-Kit mechanics and the "heavy weapon" selection judgment; also why OryxOS chose Spec-Kit.

### 三、OpenSpec 详解

- Locator: `[[sources/geek-ai-agent/20260922/03-10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#三、OpenSpec 详解]]`
- Summary: Explains OpenSpec's lightweight, incremental philosophy, its delta-spec format, the Propose → Apply → Archive state machine, `/opsx:` commands, workflow, and fit/limits.
- Key claims: Delta specs describe only what changed using ADDED/MODIFIED/REMOVED markers; each change is an independent folder so parallel changes do not conflict; 1.0 upgraded to an action-based workflow; brownfield-first is its differentiator; specs use RFC 2119 keywords plus Given/When/Then; it supports 30+ AI tools.
- Learner-relevant: The incremental SDD alternative for existing codebases; delta-spec is what Spec-Kit cannot imitate.

### 四、Spec-Kit 跟 OpenSpec 的对比

- Locator: `[[sources/geek-ai-agent/20260922/03-10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#四、Spec-Kit 跟 OpenSpec 的对比]]`
- Summary: Compares philosophy, process, output artifacts, and applicable scenarios, ending with a selection decision tree.
- Key claims: Spec-Kit ≈ a modern waterfall with strict upstream design; OpenSpec ≈ a productized agile with incremental evolution; artifact volume differs ~3x; greenfield mid/large → Spec-Kit, brownfield incremental → OpenSpec, personal small tools → neither; recommended to learn Spec-Kit first then OpenSpec.
- Learner-relevant: The core comparison and selection framework for the two SDD schools.
