# Digest — 03-17 17. 项目篇 OryxOS：需求文档

## Overview (L1)

- 项目概述 — What OryxOS is, what it can do (five core capabilities: LLM access, ReAct loop, three-layer Memory, Plugin/builtin Tool set, Web Service), the role of Channels, and the document's three-tier scope (core / extension / community) under a hard 4-week, 12-hour core-phase constraint.
- 术语和概念 — Unifies core terms (Agent, Profile, Provider, ReAct loop, Tool, Memory, Channel, Web Service, Session, Sandbox, Tool Policy, Skill, Bootstrap, Workspace) aligned with the open-source Agent OS de-facto standard.
- 设计目标 — Four words: 统一 (unified), 私有 (private), 易接入 (easy to integrate), 可观测 (observable).
- 典型场景 — Three scenarios (ops assistant, knowledge-management assistant, sales assistant) showing the full-form usage.
- 核心功能 — The core-phase minimum viable chain: configure an Agent via Profile, chat via CLI, call LLM and tools, expose via REST API. Thirteen subsections (5.1–5.13) cover workspace init, Profile, Provider, ReAct, Memory, Tool, Channel, Web Service, Session, run modes, CLI, config/secrets, project homepage.
- 扩展功能 — Production-necessary but out-of-core capabilities including the enterprise governance layer: channels/models, memory/skills, tools/security, governance/ops, enterprise integration.
- 社区共建功能 — Long-term community directions (docs, Skills Marketplace, multi-language SDK, visual Profile editor, Kubernetes Operator, etc.).
- 非功能需求 — Performance, reliability, operability, compatibility, security, compliance targets.
- 关键流程 — Step-wise flows for workspace init, Profile creation/Agent start, message processing, Tool calling, Session context management.
- 数据模型 — Field descriptions for Profile, Session, Memory, Tool Invocation, LLM Call.
- 里程碑规划 — The 4-week plan with weekly capabilities and demos.
- 风险与未决事项 — Identified risks (scope, Spring AI compatibility, tool safety, Java startup, community uncertainty, misread positioning) and open questions left to the technical plan.
- 验收标准 — Four acceptance tiers (functional, performance, operability, scenario) with five demo Agents as the hard release condition.
- 总结 — OryxOS as Java-based enterprise Agent OS; core phase builds the runtime kernel, extension/community builds the governance layer.

### 5.2 Profile 配置

### 5.3 Provider 抽象（核心能力一：对接 LLM）
- Locator: `[[sources/geek-ai-agent/20260922/03-17 17. 项目篇 OryxOS：需求文档.html#5.3 Provider 抽象（核心能力一：对接 LLM）]]`
- Summary: Provider abstracts LLM calls via Spring AI Alibaba ChatClient connectors; each Provider has name/model/API key/optional base URL; Profile references by provider name.
- Key claims: core phase does no fallback/hedge racing (errors surface directly); cost transparency is basic (log tokens/provider/model).
- Learner-relevant: capability one requirements.

### 5.4 ReAct 循环（核心能力二：Agent 大脑）
- Locator: `[[sources/geek-ai-agent/20260922/03-17 17. 项目篇 OryxOS：需求文档.html#5.4 ReAct 循环（核心能力二：Agent 大脑）]]`
- Summary: Core algorithm Reason + Act: append message, assemble prompt, call LLM, if tool call then execute and append result, loop until final response or max iterations (default 10); core loop ~dozens of lines, self-implemented.
- Key claims: max iterations overridable in Profile; tool calls sequential (no parallel), no context compression, no sub-agent delegation in core.
- Learner-relevant: the agent's core mechanism requirements.

### 5.5 Memory 三层记忆（核心能力三：让 Agent 记得住）
- Locator: `[[sources/geek-ai-agent/20260922/03-17 17. 项目篇 OryxOS：需求文档.html#5.5 Memory 三层记忆（核心能力三：让 Agent 记得住）]]`
- Summary: Three layers designed; core does two — session memory (SQLite, channel+user+profile, truncation) and long-term memory (MEMORY.md file, save_memory/recall_memory tools, injected at startup, ~4000-char truncation); episodic deferred.
- Key claims: core does not do automatic fact extraction, semantic search, episodic memory, Memory Wiki, contradiction detection.
- Learner-relevant: the "Agent remembers across conversations" differentiator requirements.

### 5.6 Tool 体系（核心能力四：让 Agent 能干事）
- Locator: `[[sources/geek-ai-agent/20260922/03-17 17. 项目篇 OryxOS：需求文档.html#5.6 Tool 体系（核心能力四：让 Agent 能干事）]]`
- Summary: Builtin tools (file read/write/list, Shell with whitelist, HTTP get/post, save_memory/recall_memory) plus Plugin Tool three tiers (zero-code SKILL.md + MCP; light-code MCP server; heavy-code Java @Tool); app-layer whitelist sandbox, no SecurityManager.
- Key claims: choice standard — prefer tier 1 over 2 over 3; MCP client minimal in core; Tool Policy/container sandbox deferred.
- Learner-relevant: the business-extension mechanism.
