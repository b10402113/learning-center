# Digest — 10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程

## Overview (L1)
- 一、为什么需要 Spec-Driven Development — vibe coding 在中大规模项目暴露需求漂移、架构失控、回退困难、无法协作；SDD 主张在生成代码前先生成 spec 作为事实来源；2025 到 2026 年初是 SDD 工具爆发期（Spec-Kit、OpenSpec、Kiro、Tessl）。
- 二、Spec-Kit 详解 — GitHub 2026 年 5 月开源的 spec-as-source 纯形式 CLI 工具链，constitution + 4 阶段闭环（specify→plan→tasks→implement）+ 3 可选命令，6 加 3 个 /speckit. 命令。
- 三、OpenSpec 详解 — Fission-AI 2026 年 1 月 1.0 的开源 SDD 工具，delta-spec 范式、Propose→Apply→Archive 三态流程、brownfield-first，/opsx: 前缀命令。
- 四、Spec-Kit 跟 OpenSpec 的对比 — 设计哲学（spec-as-source vs delta-spec）、流程（4 阶段 vs 3 态）、输出量（约 3 倍差距）、适用场景、选择决策树。
- 五、SDD 在 AI 编程时代的位置 — 与传统瀑布、vibe coding、Cursor Rules/Claude Project docs、AGENTS.md 的差异；SDD 是工作流层、强制阶段化、持久化决策。
- 六、你的学习重点 — 必须理解的核心概念（spec-as-source vs delta-spec、constitution、RFC 2119、Given/When/Then 等）、延伸阅读、课前练习、课程预告（训练营用 Spec-Kit 开发 OryxOS）。
- 七、总结 — Spec-Kit 重流程适合 greenfield 中大项目，OpenSpec 轻流程适合 brownfield 增量；掌握 SDD 范式比掌握具体工具更重要。

### spec-kit-overview
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#二、Spec-Kit 详解]]`
- Summary: 介绍 Spec-Kit 是 GitHub 2026 年 5 月开源的 SDD 工具链，支持 20+ AI agent，是 spec-as-source 最纯粹形式：spec 文件是项目源头，其他一切从它派生。
- Key claims: 装一次 Spec-Kit 可用任何 AI agent；spec 变了下游一切重新生成；它是套在 AI agent 之上的工作流层，不是 agent 本身。

### spec-kit-design-philosophy
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#2.2 设计哲学]]`
- Summary: 三个核心点：constitution 是非协商的项目宪法（技术栈、编码规范、测试要求固化）；4 阶段闭环 specify→plan→tasks→implement 每阶段有正式 artifact；3 个可选命令（clarify/analyze/checklist）加强质量，analyze 是防 spec 漂移的核心工具。
- Key claims: 每个项目第一件事写 constitution.md，所有命令引用它；没有跨阶段 shortcut；analyze 做跨 artifact 一致性检查。
- Learner-relevant: 理解 spec-as-source 的哲学支柱 constitution，支撑"非协商原则"与阶段化流程元素。

### spec-kit-commands
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#2.3 核心命令体系]]`
- Summary: 6 个核心命令（constitution、specify、plan、tasks、taskstoissues、implement）加 3 个可选命令（clarify、analyze、checklist），全部以 /speckit. 前缀触发。
- Key claims: specify 输出 5+ user story 加 acceptance criteria；taskstoissues 把任务转 GitHub issues；clarify 在 specify 后 plan 前反问用户；analyze 是只读的一致性检查。
- Learner-relevant: 提供 Spec-Kit 命令速查表，支撑实操与命令记忆。

### spec-kit-workflow
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#2.4 典型工作流]]`
- Summary: 从初始化（specify init 生成 .specify/ 工作区）到写 constitution、specify、clarify、plan、tasks、analyze、implement、review 加 commit 的完整流程，spec 通常约 800 行。
- Key claims: constitution 一次定下来不再改；implement 建议逐个 task 跑方便审查；人始终在 review 环节。
- Learner-relevant: 给出端到端的 Spec-Kit 实操路径，支撑课堂跟做。

### spec-kit-fit-and-limits
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#2.5 适用场景和局限]]`
- Summary: 适合 medium-large greenfield 项目、需求清晰、AI agent 协作；不适合小 feature、大型 brownfield 改造、探索性研究、个人快速实验。
- Key claims: 社区共识 800 行 spec 对小增量过重；brownfield 扩展效果不如 OpenSpec；Spec-Kit 是"重武器"，工具选择匹配项目规模与团队成熟度。
- Learner-relevant: 提供工具选型的判断维度（greenfield/brownfield、规模、团队），支撑选型决策。

### openspec-overview
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#三、OpenSpec 详解]]`
- Summary: 介绍 OpenSpec 是 Fission-AI 2026 年 1 月发布 1.0 的开源 SDD 工具，Node.js 20.19.0+，openspec init 初始化工作区，支持 30+ AI 编程工具并自动预选检测到的工具。
- Key claims: 设计哲学与 Spec-Kit 对立：轻量、灵活、增量友好；init 时扫描 .claude/、.cursor/ 等配置目录。

### openspec-design-philosophy
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#3.2 设计哲学]]`
- Summary: 三个核心点：delta-spec 范式（用 ADDED/MODIFIED/REMOVED 三个 marker 描述增量差异）；3 态流程 Propose→Apply→Archive（每个 change 是独立 folder 的状态机）；brownfield-first（假设项目已有代码）。1.0 最新版本升级为 action-based workflow。
- Key claims: 两个并行 change 可同时改同一 spec 不同 requirement 互不冲突；archive 时 delta 合并进主 spec；官方口号 "fluid not rigid, iterative not waterfall, easy not complex, brownfield-first"。
- Learner-relevant: 理解 delta-spec 与状态机思想，支撑增量规格化元素。

### openspec-commands
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#3.3 核心命令体系]]`
- Summary: core profile 命令（propose、explore、apply、sync、archive）加扩展 profile（new、continue、ff、verify、bulk-archive、onboard），以 /opsx: 前缀触发；支持 custom schemas 自定义 artifact 类型。
- Key claims: explore 只讨论不产 artifact；verify 在 archive 前做一致性检查；custom schemas（如 ADR）是 OpenSpec 比 Spec-Kit 更灵活之处。
- Learner-relevant: 提供 OpenSpec 命令速查，支撑实操与对比记忆。

### openspec-workflow
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#3.4 典型工作流]]`
- Summary: 从 openspec init、写 project.md、propose 一个 change（生成 proposal/design/tasks/delta specs）、人工 review、apply（可断点 resume）、verify、archive 到进入下一个 change 的完整流程。
- Key claims: propose 是设计协商不是一次定终身；spec 写法用 RFC 2119 keywords（MUST/SHALL/SHOULD/MAY）加 Given/When/Then，与 BDD 一致方便转测试用例；多个 change 可并行。
- Learner-relevant: 给出 OpenSpec 端到端实操路径，与 Spec-Kit 工作流对照学习。

### openspec-fit-and-limits
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#3.5 适用场景和局限]]`
- Summary: 适合 brownfield 增量改造、多 change 并行、快速迭代、小 feature 上 SDD、与现有 AI 工具集成深；不适合 0 到 1 大型新项目、企业合规重项目、需要完整方法论训练。
- Key claims: delta-spec 范式是 Spec-Kit 不能模仿的差异化；OpenSpec 是"轻武器"，约束力不够是短板；同功能 Spec-Kit 约 800 行规格、OpenSpec 约 250 行。
- Learner-relevant: 提供 OpenSpec 选型边界，与 Spec-Kit 组成互补判断框架。

### spec-kit-vs-openspec

- Summary: 从设计哲学（瀑布的现代化 vs 敏捷的工程化）、流程（4 阶段刚性闭环 vs 3 态灵活）、输出物（约 3 倍差距）、适用场景、选择决策树五个维度对比。

### sdd-position-in-ai-programming
- Locator: `[[sources/geek-ai-agent/10 10. 扩展篇：Spec-Kit 和 OpenSpec 的原理和使用教程.html#五、SDD 在 AI 编程时代的位置]]`
- Summary: 对比传统瀑布（死的 spec）、vibe coding（prompt-driven、需求易失）、Cursor Rules/Claude Project docs（静态 context 不约束工作流）、AGENTS.md（项目说明书不强制产 artifact），突出 SDD 独特价值。
- Key claims: SDD 的 spec 是给 AI 看的（同时也给人看），是 AI 的 system prompt；SDD 强制工作流阶段化并持久化决策；没有 SDD 的 AI 编程 = 没有版本控制的传统编程：能跑但不可持续。
- Learner-relevant: 定位 SDD 在 AI 编程辅助谱系中的独特性，支撑"工作流层 vs context"元素。
