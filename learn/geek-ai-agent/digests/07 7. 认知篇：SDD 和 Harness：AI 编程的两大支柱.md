# Digest — 07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱

## Overview (L1)
- 一、SDD 和 Harness 各自解决什么 — SDD 解决"想"（把想清楚工程化，结构化的 spec 让 AI 拿到清晰执行依据），Harness 解决"做"（把 AI 怎么做工程化，配置约束让 AI 在边界内工作），二者互补闭环。
- 二、SDD 的三种落地模式 — Spec-Kit 自动化模式（/specify→/plan→/tasks→/implement）、OpenSpec 手动控制+delta spec、轻量手工模式（只用 CLAUDE.md+Skill）；对比全局视角/误差放大/任务粒度/发现问题时机/工程师角色/能力要求，按场景选用。
- 三、Harness 的约束落地工具 — 六个工具：CLAUDE.md/AGENTS.md（项目说明）、Skills/Slash Commands（能力封装）、Subagents（任务隔离）、Plan Mode（先规划后执行）、Permission（事前权限）、Hooks（事后检查），组合成前中后三道防线。
- 四、SDD 和 Harness 合起来才是闭环 — 只学 SDD 有目标没控制力，只学 Harness 有控制力没目标；共享底层假设"AI 不是被信任的，是被工程化使用的"。
- 五、为什么是这两个，不是别的 — 按"成熟、可教、覆盖完整工程"三条标准只有 SDD 和 Harness 同时满足；其他方法论（Vibe Coding/Context Engineering/ReAct/Test-Driven AI/Plan-then-Execute/AI-First Architecture）都差火候。
- 六、怎么落地：从今天开始的三步 — 从写 CLAUDE.md 开始→选一种 SDD 模式→逐步加 Harness 其他工具；按需取用而非堆砌。

### 1.1 SDD 解决"想"的问题
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#1.1 SDD 解决"想"的问题]]`
- Summary: "想"和"做"被 AI 分开后，"想"必须工程化，否则陷入"凭直觉聊天"的反复纠正循环。
- Key claims: spec 是有结构、有验收、有边界的可执行规格（知道做什么/做到什么程度/什么不该做/做完怎么验证）；SDD 灵魂是把"想"从隐性知识变显性产物（可审查、可共享、可被 AI 消化）。
- Learner-relevant: SDD 的动机与 spec 的本质。

### 1.2 Harness 解决"做"的问题
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#1.2 Harness 解决"做"的问题]]`
- Summary: "挽具"比喻：AI 是烈马（能力强但缺判断边界），Harness 让它在合理边界内工作。
- Key claims: AI 会跑偏/失控/上下文污染/做不可逆操作；Harness 通过 System Prompt（规则）、Tools（能力封装）、Context（合适上下文）、Permission（事前拦）、Hooks（事后验证）、Plan Mode（先规划后执行）把 AI 从"放飞的执行者"变"可控的协作者"。
- Learner-relevant: Harness 的机制全貌，衔接 3.x 工具详解。

### 二、SDD 的三种落地模式
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#二、SDD 的三种落地模式]]`
- Summary: SDD 核心动作是写 spec、拆任务、执行任务；三种模式（自动化/手动控制/轻量手工）覆盖不同场景。
- Key claims: 三种模式一起讲 SDD 图景才完整。
- Learner-relevant: SDD 落地的模式菜单。

### 2.1 Spec-Kit：自动化模式
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#2.1 Spec-Kit：自动化模式]]`
- Summary: GitHub 2025 推出的 SDD 工具，四个命令工作流：/specify（定义需求→spec.md 含背景/目标/用户故事/验收标准/非目标）、/plan（规划架构→plan.md 含技术选型/架构决策/模块划分/风险）、/tasks（拆任务→tasks.md 约 40-50 个可执行任务）、/implement（执行+最后整体 review）。
- Key claims: 适合中等复杂度、探索性开发、新手、团队协作、时间紧；代价=AI 拆任务质量的天花板是 spec 质量、两轮推断叠加误差相乘、任务粒度偏大 AI 易凑合/幻觉、AI 不理解时不会停下来问。
- Learner-relevant: Spec-Kit 工作流与局限，支撑 When 等项目的 SDD 用法。

### 2.2 OpenSpec：手动控制 + delta spec
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#2.2 OpenSpec：手动控制 + delta spec]]`
- Summary: 社区驱动开源工具，强调手动控制（人写 spec/plan 并自己拆任务，AI 只执行单个任务，每个任务 review）和 delta spec（增量规格：这次改什么/改成什么样/为什么改/不破坏什么）。
- Key claims: 适合 0→1 新项目、系统级项目、关键路径代码、有经验工程师；delta spec 在改造场景价值大（不需要完整 spec），也适用开源 PR 描述、加 feature、修系统性 bug；Spec-Kit 当下还没有 delta spec 机制。
- Learner-relevant: delta spec 直接支撑 DifyPro 改造与 mq9 PR。

### 2.3 轻量手工模式：不用 SDD 工具，只用 CLAUDE.md 和 Skill
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#2.3 轻量手工模式：不用 SDD 工具，只用 CLAUDE.md 和 Skill]]`
- Summary: 不用任何 SDD 专用工具，人在脑子里完成方案设计与任务拆分，AI 一段一段执行、人一段一段 review，工具只用 CLAUDE.md+Skill。
- Key claims: 五个优势——质量可控（AI 不做创造性决策）、代码可 review（每段小到能看清）、代码可维护（风格像自己写的）、速度其实不慢（AI 决策错成本更高）、工具学习成本极低；适合熟悉技术栈/能想透的逻辑/增量/关键路径；不适合陌生领域/大量探索/规模过大/纯产品验证；本质是 OpenSpec 手动控制的进一步轻量化。
- Learner-relevant: 提供最轻量、判断力最强的 SDD 姿态。

### 2.4 三种模式的本质区别
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#2.4 三种模式的本质区别]]
- Summary: 从六个维度对比三种模式：全局视角在谁手里、AI 误差放大倍数、任务粒度、发现问题时机、工程师角色、对工程师能力要求。
- Key claims: 自动化模式=AI 双视角/两轮推断相乘/任务偏大/最后才发现问题/像产品经理/要求低；手动控制=全局在人手/一轮推断/任务按功能/每任务即时 review/像 team leader/要求高；轻量手工=全局在人手/一轮推断/任务最小/每段即时 review/就是工程师本人/要求最高不能藏拙；新手用自动化、中级用手动、资深用轻量。
- Learner-relevant: 按水平与场景选择模式的决策表。

### 2.5 你应该选哪个
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#2.5 你应该选哪个]]`
- Summary: 按具体情况给出选型建议：新手/中级新项目中等复杂度用 Spec-Kit 自动化；资深系统级新项目用 OpenSpec 手动；资深熟悉项目增量/关键路径用轻量手工；老项目改造用 delta spec；开源贡献用 delta spec 写 PR；团队可混用。
- Key claims: 三种模式互补不替代，成熟工具箱里三种都该有、按场景切换。

### 3.1 CLAUDE.md 和 AGENTS.md：项目说明
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#3.1 CLAUDE.md 和 AGENTS.md：项目说明]]`
- Summary: 项目根目录 Markdown 作为 AI"项目说明书"：Claude Code 读 CLAUDE.md、Codex CLI 读 AGENTS.md、Cursor 读 .cursorrules，启动时作为 system prompt 前置。
- Key claims: 最小可用包含四块——项目概况、运行命令、代码约定、禁区；没有它 AI 用通用知识凑（风格不合/用错库/改错文件/跑错命令）；CLAUDE.md 是用出来的不是想出来的；任何持续用 Claude Code 的项目第一天就该写。
- Learner-relevant: 各项目第一步落地动作。

### 3.2 Skills 和 Slash Commands：能力封装
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#3.2 Skills 和 Slash Commands：能力封装]]`
- Summary: Skills 把可复用能力封装成 Claude 可调用的 skill（~/.claude/skills/ 个人跨项目、.claude/skills/ 项目团队共享，含 SKILL.md 描述是什么/何时触发/怎么用）；Slash Commands 是斜杠命令（.claude/commands/ 下 markdown 文件触发预定义工作流）。
- Key claims: Slash Commands 手动触发、Skills 由 AI 在合适场景自动选择；封装反复做的流程（代码审查/PR 描述/脚手架）质量稳定；是个人和团队能力沉淀到 AI 上的核心机制。
- Learner-relevant: 能力封装机制，支撑复利资产与项目内复用。

### 3.3 Subagents：任务隔离
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#3.3 Subagents：任务隔离]]`
- Summary: 从主对话启动子代理做独立的事，子代理在隔离上下文里工作，主对话只接收总结。
- Key claims: 解决上下文有限导致的"聊着聊着就忘关键约束"；可在 .claude/agents/ 预定义专用 subagent（code-reviewer/test-runner）；典型场景=读大量代码（改造必选）、并行做几件事、保护主对话上下文不被脏数据污染；注意轻量手工模式下 Subagents 反而是负担（不是越多越好）。
- Learner-relevant: 上下文管理工具，支撑大型改造场景。

### 3.4 Plan Mode：先规划后执行
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#3.4 Plan Mode：先规划后执行]]`
- Summary: 开启后 AI 在任何写操作前先输出完整 plan（做什么/顺序/改哪些文件/风险），确认后再动手。
- Key claims: 解决"AI 乱动手"；看 plan 比看代码容易（结构化几百字 vs 几百行散落代码）；三类场景必开=重要操作（生产配置/核心模块/大重构/数据库 schema）、不熟悉代码区域、第一次协作的新场景；日常熟悉小任务可不开。
- Learner-relevant: 安全网前置，关键操作保护。

### 3.5 Permission：事前权限
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#3.5 Permission：事前权限]]`
- Summary: 事前约束机制，配置在 ~/.claude/settings.json 或项目级 .claude/settings.json，三类规则：allow（不需确认）、ask（必须问）、deny（绝对不能）。
- Key claims: 给你"中间空间"避免两个极端（每操作确认累 / 放任怕）；例子：allow 读写 src/ tests/ 与跑测试、ask 写 package.json/装依赖/改 .gitignore、deny 删文件/改 .env/生产部署；改造与 CI/CD 场景尤其重要，日常至少配几条 deny 红线。
- Learner-relevant: 权限边界设计，支撑 DifyPro 与安全场景。

### 3.6 Hooks：事后检查
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#3.6 Hooks：事后检查]]`
- Summary: 事后检查机制，Claude 调工具前（PreToolUse）或后（PostToolUse）自动触发任意脚本，配置在 .claude/settings.json。
- Key claims: 把"AI 做完人验证"变"AI 做完机器自动验证"，是反馈循环工程化的核心；最低限度两条=Edit PostToolUse 跑 lint、Edit PostToolUse 跑相关测试；进阶可加 Bash PreToolUse 查命令安全、Write PostToolUse 自动 format、Edit PostToolUse 更新文档；没有 Hooks 是手工作坊，有才进入工业化；轻量手工模式下 Hooks 是可选（人 review 就是反馈循环）。
- Learner-relevant: 反馈循环落地的具体配置，衔接 06 号材料反馈循环概念。

### 3.7 Harness 工具的整体协作
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#3.7 Harness 工具的整体协作]]`
- Summary: 六个工具组合成完整 Harness：CLAUDE.md 基础、Skills/Slash 杠杆、Subagents 上下文管理、Plan Mode 安全网前置、Permission 安全网中置、Hooks 安全网后置。
- Key claims: 是前中后三道防线+上下文隔离+能力杠杆+项目规则的合奏；不是所有场景都六工具全上，按场景取用（轻量手工只用 CLAUDE.md+Skill，批量自动化 Hooks+Permission 核心，改造大型项目 Subagents+Permission 必选）；"克制"才是真正工程师姿态。
- Learner-relevant: Harness 的整体图景与按需取用原则。

### 四、SDD 和 Harness 合起来才是闭环
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#四、SDD 和 Harness 合起来才是闭环]]`
- Summary: 只学 SDD 有清晰目标没控制力（AI 看着 spec 也可能写偏），只学 Harness 有强控制力没清晰目标（AI 做对但做错东西）。
- Key claims: SDD 给目标（做什么/程度/不做什么），Harness 给边界（范围/方式/怎么验证）；共享底层假设"AI 不是被信任的，是被工程化使用的"；抗拒二者本质是抗拒该假设；前期投入一次性、回报持续，是 AI 编程 ROI 最高的两件事。
- Learner-relevant: 两根支柱合一的理由。

### 五、为什么是这两个，不是别的
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#五、为什么是这两个，不是别的]]`
- Summary: 三条标准（成熟、可教、覆盖完整工程）过一遍，只有 SDD 和 Harness 同时满足。
- Key claims: Vibe Coding 是姿态无步骤；Context Engineering 方向对但无标准工具/成熟工作流；ReAct/TAO 只适合自主决策型 Agent 应用；Test-Driven AI 是 SDD 落地的一步；Plan-then-Execute 已在 Plan Mode 落地；AI-First Architecture 太新。
- Learner-relevant: 选择主轴的完整论证，与 02 号材料互文。

### 六、怎么落地：从今天开始的三步
- Locator: `[[sources/geek-ai-agent/07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#六、怎么落地：从今天开始的三步]]`
- Summary: 三步落地：第一步写 CLAUDE.md（最小版半小时，立刻见效）；第二步选一种 SDD 模式（不熟用 Spec-Kit、熟用轻量手工、改造用 delta spec）；第三步逐步加 Harness 其他工具（Hooks 先加两条→Permission deny 红线→Subagents→Plan Mode→Skills/Slash）。
- Key claims: 别扭感正常（"直接写代码不就行了"）；不是所有工具都必须上，轻量手工模式下 CLAUDE.md+Skill 覆盖 80% 场景；三步走完就在用 SDD+Harness 跑完整工作流，和不用这套的人以惊人速度拉开差距。
- Learner-relevant: 可执行的入门路径，支撑各项目实操起点。
