# Digest — 12 12. 扩展篇：Superpowers 深度介绍

## Overview (L1)
- 先回答你心里的疑问 — 澄清 Superpowers 是 agentic skills 框架兼软件开发方法论，不是 SDD 工具。
- 一句话定义 — "严肃软件工程师该做的事"打包成 Skills 强制嵌进 agent 工作流；官方自述 "an agentic skills framework and software development methodology that works"。
- 它要解决什么真实问题 — AI 写代码快但散；这是工作流问题不是模型问题；20 万 stars 与进 Anthropic 官方插件市场说明痛点真实。
- 核心设计：Skills 框架 — 每个 Skill 是 SKILL.md（brainstorming 等 20+ 内置）、自动激活机制、writing-skills 元技能。
- 完整工作流：一次跑通 — 从一句话到 brainstorm→writing-specs→writing-implementation-plans→subagent 执行加两阶段 review→收尾，与"直接让 AI 写"对比。
- 用 5 组件抽象拆解 — 只改 Memory（大型 Skills 库）和 Loop（强制结构化流程），LLM/Tools/Environment 全复用。
- 跟 Spec-Kit、OpenSpec 的边界 — 前两者是"做 SDD 的工具"，Superpowers 是"管 agent 纪律的框架"，SDD 只是它内部一个 Skill；可一起用但边界要小心。
- 跨 agent 支持 — 官方支持 Claude Code、Codex CLI/App、Cursor、Gemini CLI、OpenCode、GitHub Copilot CLI、Factory Droid，Claude Code 上支持最完整。
- 工程哲学 — Agent as contractor、两阶段 review、真红绿 TDD、YAGNI 与 DRY 写进 Skill、Worktree 隔离、慢就是快。
- 怎么开始用 — /plugin install superpowers@claude-plugins-official、第一个 demo、写自己的 Skill、与现有工作流对接。
- 它的局限 — 慢、重、新 Skill 难进主仓库、学习曲线。
- 我的判断 — 有用但需要筛选，大概率是过渡产物；代表 AI 编程从"快但散"走向"慢但稳"。
- 总结 — 工具会过时，工程方法论不会。

### skills-framework
- Locator: `[[sources/geek-ai-agent/12 12. 扩展篇：Superpowers 深度介绍.html#核心设计：Skills 框架]]`
- Summary: 讲解 Skills 框架：一个 Skill 是含 frontmatter（name+description）和指令的 SKILL.md（示例 brainstorming）；内置 20+ Skill（brainstorming、writing-specs、writing-implementation-plans、subagent-driven-development、tdd、debugging-systematically、root-cause-analysis、writing-skills）；Skill 靠 description 由 agent 自动激活；writing-skills 教 agent 自己造新 Skill。

### full-workflow
- Locator: `[[sources/geek-ai-agent/12 12. 扩展篇：Superpowers 深度介绍.html#完整工作流：一次跑通]]`
- Summary: 以"加 newsletter 订阅功能"为例走完整流程：brainstorming 先问目标与合规、writing-specs 逐块确认 spec（5-20 块需签字）、writing-implementation-plans 拆成几分钟一个的精确任务、subagent 独立 worktree 执行加两阶段 review（spec 合规 + 代码质量）、收尾跑全套测试给四个选项。
- Key claims: plan 要清晰到"有热情但品味差的新手都能照做"；两阶段 review 是 agent as contractor 哲学的落地；流程总耗时与直接写差不多但质量高、基本不用修。
- Learner-relevant: 具象展示 Superpowers 的端到端体验，与原生 Claude Code 流程对照。

### five-component-breakdown
- Locator: `[[sources/geek-ai-agent/12 12. 扩展篇：Superpowers 深度介绍.html#用 5 组件抽象拆解]]`
- Summary: 用 5 组件抽象拆解：LLM 复用 agent 自带的（不绑定模型）、Tools 复用但不给新能力只给新纪律、Memory 是大型 Skills 库（Jesse 几十年经验沉淀）、Loop 是强制结构化流程（传统 ReAct 像自由演员、Superpowers 像有剧本有导演的演员）、Environment 复用。
- Key claims: 只改两个组件（Memory 和 Loop）其他全复用，因此可移植性强、与 agent 演化解耦、价值聚焦；"少做但做透"是它涨到 20 万 stars 的根本原因。
- Learner-relevant: 用既有 5 组件抽象理解 Superpowers，巩固抽象应用能力。

### boundary-with-sdd-tools

- Learner-relevant: 全文最关键的一章，明确三者选型与组合边界。

### engineering-philosophy
- Locator: `[[sources/geek-ai-agent/12 12. 扩展篇：Superpowers 深度介绍.html#工程哲学]]`
- Summary: 五个工程哲学：Agent as contractor（承包商而非同事，给 spec 严格验收）；两阶段 review（spec 合规 + 代码质量）；真红绿 TDD（必须先看到失败）；YAGNI 和 DRY 写进 Skill；Worktree 隔离（subagent 独立 worktree 并行不冲突）。
- Key claims: 很多人用 AI 编程不顺的根源是把 agent 当同事期待它有判断力；"慢就是快"——流程慢点但总耗时不长且可维护性强。
- Learner-relevant: 提炼可迁移的工程纪律思想，支撑"agent 协作模式"元素。

### limitations
- Locator: `[[sources/geek-ai-agent/12 12. 扩展篇：Superpowers 深度介绍.html#它的局限]]`
- Summary: 诚实列出局限：慢（修 typo 走整套流程 overkill）；重（个人小项目、prototype 过度工程化）；新 Skill 难进主仓库（社区 PR 接受率低）；学习曲线（要适应不立刻写代码、接受"啰嗦"和"反复"）。
