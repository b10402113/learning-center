# Digest — 03-07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱

## Overview (L1)

- Two pillars — SDD solves the "thinking" problem (engineering fuzzy needs into executable specs); Harness solves the "doing" problem (harnessing AI within safe boundaries). Together they close the loop; only one is insufficient.
- SDD's three modes — Spec-Kit (automated: /specify → /plan → /tasks → /implement), OpenSpec (manual control + delta spec), and a lightweight hand-rolled mode using only CLAUDE.md + Skill. They differ in who holds the global view, error amplification, task granularity, when problems surface, the engineer's role, and required seniority.
- Harness's six tools — CLAUDE.md/AGENTS.md (project rules), Skills/Slash Commands (capability encapsulation), Subagents (context isolation), Plan Mode (plan-before-act), Permission (pre-action limits), Hooks (post-action checks). Not all are needed in every scenario.
- Shared assumption — AI is not trusted, it is engineered-used: a powerful executor lacking judgement boundaries needing precise direction, strict constraint, and continuous verification.
- ROI — SDD + Harness has the highest ROI in AI programming; start with CLAUDE.md, pick an SDD mode, then add Harness tools incrementally.

### 二、SDD 的三种落地模式
- Locator: `[[sources/geek-ai-agent/20260922/03-07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#SDD三种落地模式]]`
- Summary: Spec-Kit automation, OpenSpec manual+delta, and the lightweight handmade mode.
- Key claims: Spec-Kit's four commands and its fit (mid-complexity, exploration, SDD beginners, team alignment) and costs (spec quality ceiling, two-round inference error multiplication — 80%×80%=64%, coarse granularity, no stopping to ask); OpenSpec manual mode (human splits tasks, AI executes one at a time) fits 0→1, system-level, critical-path, experienced engineers; delta spec fits retrofits, PR descriptions, feature additions, systemic bug fixes; lightweight mode (human thinks through the whole plan, AI executes tiny segments, only CLAUDE.md+Skill) offers quality control, reviewability, maintainability, competitive speed, near-zero tool learning and is suited to familiar stacks/critical paths but not unfamiliar/exploratory/oversized/product-validation work.
- Learner-relevant: Equips the learner to choose the right SDD mode per scenario.

### 2.4–2.5、三种模式的本质区别与选型
- Locator: `[[sources/geek-ai-agent/20260922/03-07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#三种模式区别与选型]]`
- Summary: Six axes of difference plus selection guidance.
- Key claims: global view in human vs AI hands; AI error amplification (two-round vs one-round inference); task granularity (AI-chosen large vs your functional vs smallest per-function segments); timing of problem discovery (end-review vs per-task vs per-segment); engineer roles (PM-like vs team-lead-like vs engineer-as-engineer); required seniority (low → high, no tool crutch). Selection: beginners/mid on new mid-complexity → Spec-Kit; senior on new system-level → OpenSpec; senior on familiar/incremental → lightweight; legacy retrofit → OpenSpec delta; open-source contribution → delta spec; teams → mixed. A mature toolbox keeps all three.
- Learner-relevant: Converts the modes into a concrete decision matrix; highlights SDD's core is a thinking method, not a tool.

### 三、Harness 的约束落地工具
- Locator: `[[sources/geek-ai-agent/20260922/03-07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#Harness约束落地工具]]`
- Summary: Detailed how/what/when for each of the six Harness tools.
- Key claims: CLAUDE.md/AGENTS.md/.cursorrules as project manual (four blocks: overview, run commands, code conventions, forbidden zones; grow it iteratively); Skills/Slash Commands for reusable capabilities (SKILL.md structure; auto-selected vs manually triggered); Subagents for context isolation (three use cases; a burden in lightweight mode); Plan Mode for plan-before-acting (mandatory for risky/unfamiliar/first-time scenarios); Permission with allow/ask/deny JSON rules (pre-action boundary space between "confirm everything" and "let it run"); Hooks PreToolUse/PostToolUse (minimum two: lint + related tests after edits; a concern mainly when you're not present). Combined: three defense lines (pre/mid/post) + context isolation + capability leverage + project rules; use tools only as needed, restraint is the engineer's stance.
- Learner-relevant: The most directly actionable Harness implementation guide; supports hands-on practice.

### 四、SDD 和 Harness 合起来才是闭环
- Locator: `[[sources/geek-ai-agent/20260922/03-07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#合起来才是闭环]]`
- Summary: Why both are required and the shared underlying assumption.
- Key claims: SDD without Harness = clear goal but no control (AI may write non-conforming code, skip edge cases, touch forbidden files); Harness without SDD = strong control but no clear goal (blocks wrong code but can't catch "correct code you didn't want"); together AI advances within SDD's goals and Harness's boundaries; shared assumption — AI is not trusted, it is engineered-used; upfront investment is one-off, returns continuous; highest-ROI pair.
- Learner-relevant: The key integration idea; frames the learner's mental model.

### 五–六、为什么是这两个 + 从今天开始的三步
- Locator: `[[sources/geek-ai-agent/20260922/03-07 7. 认知篇：SDD 和 Harness：AI 编程的两大支柱.html#为什么是这两个与落地三步]]`
