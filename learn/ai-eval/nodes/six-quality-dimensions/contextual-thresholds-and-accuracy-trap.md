# 儀表板全綠卻客訴翻倍？評估門檻設定與單一準確率的盲點

指標分好類之後，最後一步是替每一類訂門檻；門檻訂錯，前面量得再細也救不了決策。

許多團隊在剛推出 AI 產品時，都有過類似的經驗：監控儀表板上的指標一片綠字，團隊以為 Agent 運作順暢，結果上線一週後打開使用者回饋、Reddit 或 Twitter，卻發現使用者正在抱怨體驗糟糕，甚至在客服管道上要求真人介入的案件量直接暴增。

這種「數據全綠、用戶氣炸」的狀況，通常源自於兩個評估核心觀念的偏差：門檻設定脫離了業務風險，以及把「模型準確率（Accuracy）」當成唯一的驗收標準。

## 評估指標的兩大維度：AI 指標與業務指標

要建立合理的評估門檻，先把上一節的兩類指標拿回來對照（這裡只取結論，不重講定義）：

1. **AI 指標**：衡量模型本身的品質，例如品質分數（quality score）、準確率（accuracy scores）等。
2. **業務指標**：衡量實際對使用者與營運造成的影響，例如真人客服升級率（escalations）、使用者滿意度或倒讚數。

這兩類指標必須放在一起看。上線的標準究竟是 50%、70% 還是 90%？答案取決於「犯錯的成本」與產品用途。

## 依使用情境與風險設定不同門檻

在實際落地中，不同情境的驗收標準差異極大：

<!--image:1-->

* **內部員工使用的問答 Agent**：若僅用於內部問答，不涉及調用外部資料或執行高風險的更新操作，團隊可以採用較寬鬆的門檻（例如 50%）。因為是在內部受控環境下發布，即使回答不夠完美，只要能在部分指標達到標準，就可以快速上線迭代，避免為了追求完美而拖慢團隊步調。
* **法律或金融領域的 Agent**：在這類領域中，犯錯的代價極高。驗收門檻必須拉到 90% 以上，而且不能只看模型分數，還必須搭配引用來源檢查（citations）以及最上層的確定性規則檢查（deterministic checks）。

在快速交付與嚴格把關之間取得平衡，關鍵在於依據錯誤帶來的業務衝擊，訂出合理的驗收標準（acceptance criteria）。

## 「92% 全綠但客訴翻倍」說明了什麼？

有些團隊在打造第一版（V1）產品時，容易過度執著於「準確率」。但即使在法律或金融等講求精準的領域，單看準確率依然存在嚴重的盲點。

以一個實際的客服 Agent 為例：
* **模型準確率評估**：達到 92%，儀表板全綠。
* **業務營運結果**：轉接真人客服的升級率（escalations to a human）翻了一倍（2×）。

為什麼 92% 的高準確率攔不住翻倍的客訴？因為**準確率評估只衡量了模型本身的品質（quality），卻對產品行為（behavior）與可靠度（reliability）完全盲目。**

<!--image:2-->

一個 Agent 可以有 92% 的單次回覆在事實上完全正確，但整體對話行為卻可能讓人沮喪——例如答非所問、無法推進流程，或是在錯誤的時間點放棄對話，導致使用者最終仍必須求助真人客服。

## 如何找出單一指標沒抓到的問題？

遇到這種情況時，評估流程不能只停留在單回合（single turn）的模型準確度：

1. **從被升級的完整對話（sessions）著手**：轉接真人客服是一個「對話層級（session-level）」的結果，單一回合的問答往往看不出破綻。必須抓出上週所有轉接真人的完整對話紀錄來檢視。
2. **標註與分類失敗原因**：人工檢視 Agent 為何在這些對話中放棄或激怒用戶，並建立錯誤分類體系（failure taxonomy）。例如，檢查是否有特定錯誤代碼顯著增加（如「理解意圖錯誤 Wrong Intent」）。
3. **將新場景納入常態測試**：找出這些先前未涵蓋的場景後，將它們補進未來的回歸測試（regression test cycles）中，避免相同的問題在後續版本重演。

<!--image:3-->

評估 AI 不能當成單純的斷言（assertion），而要將品質視為一種分佈。除了模型準確性之外，團隊還需要兼顧行為、可靠度、安全性、成本與延遲等維度，才能避免陷入指標漂亮、使用者卻不買單的困境。
