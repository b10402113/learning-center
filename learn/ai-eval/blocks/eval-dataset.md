# Eval Dataset（評測資料集）

<!--image:1-->

## 定義

評測資料集（Eval Dataset）是用來評估 AI 或大型語言模型應用的測試情境（test scenarios）集合。

它通常包含具體的輸入提示、情境脈絡，以及對應的預期結果（ground truth 或 golden scenarios）。

團隊能藉此以標準化方式，反覆驗證模型的輸出品質。

## 為什麼重要

只靠隨意輸入幾句提示詞來測模型，無法保證系統更新後依然穩定。

評測資料集將測試標準具體化與規格化，帶來幾個核心好處：

- **防止效能倒退**：調整提示詞、更換模型或修改系統邏輯時，可以用同一組資料集跑回歸測試（regression test），確保原有的回答品質沒有下滑。
- **量化評估成果**：團隊不用再憑感覺判斷。大家能基於同一組標準測試案例，比較不同實驗（experiments）在成本、速度與品質上的表現。
- **支援跨團隊協作**：資料集能集中管理並開放權限。產品經理、工程師與領域專家在判定「什麼是正確回答」時，能擁有相同的依據。

## 如何運作

在實務上，建立與管理評測資料集通常遵循以下流程：

1. **定義測試情境與目標**：依評測目的分類，例如單元測試資料集、回歸測試資料集，或是資安紅隊（red teaming）對抗資料集。
2. **匯入與欄位對應**：把包含測試案例的 CSV 或試算表匯入評測工具。系統通常會自動把輸入、上下文與預期輸出對應到特定欄位。
3. **版本控制**：發現新問題或邊界情境時，持續加入新案例並標註版本，確保每次實驗都能追溯當時的測試基準。
4. **小規模驗證再擴大**：對整組資料集執行自動化評測前，先挑選少數案例在互動環境（Playground）中快速除錯與測試。

## 例子

評測資料集可以依測試用途拆成不同檔案，常見情境如下：

- **回歸測試資料集**：包含 50 個客戶常見的退款與查詢問題。每題都附有標準解答與關鍵資訊清單，每次修改系統提示詞時都要全部重跑一次。
- **資安紅隊資料集**：包含各類越獄攻擊、提示詞注入（prompt injection）與刺探機密資料的提問。預期結果是模型必須安全拒絕回答。

## 邊界與常見誤解

- **誤解：沒有完美的標準答案（Ground Truth）就不能開始評測**。許多團隊因為手上缺少完整的標準答案，遲遲不敢展開測試。其實評測資料集可以先抓 10 到 20 個關鍵情境，從小規模起步再逐步擴充。
- **誤解：評測資料集只要建好一次就不用管**。資料集不是靜態檔案，需要隨著產品生命週期持續維護。從真實使用者互動的追蹤紀錄（traces）中挑出失敗案例，持續補進測試集，才能貼近線上真實狀況。

## 進階

進階做法會搭配線上監控機制，實現「追蹤回流」（trace-to-dataset）。

當系統在線上出現滿意度低、信賴度低或呼叫失敗的紀錄時，系統會自動或半自動篩選這些真實請求，直接放進回歸測試資料集。

團隊也可以利用專門的模型或 Agent 自動生成合成案例，快速拉高邊界條件與極端案例的測試覆蓋率。
