# 為什麼未修正的通過率會騙人：judge 的誤差往哪邊推

你已經有一個能用的 LLM-as-judge。它在 dev set 上表現穩定，你也很滿意，於是把 prompt 凍結，拿去跑 test set。

跑完後，你得到兩個數字：judge 判為 Pass 的比例，以及它和人工標註比對後的準確度。

接著，你把同一個 judge 丟到幾千筆未標註的 production trace，數一數其中有幾筆被判為 Pass，再除以總數。這個比例，就是你看到的「通過率」。

聽起來很合理，但問題在於：judge 並不完美。它偶爾會漏掉真正做對的輸出，也偶爾會把做錯的判成通過。你直接數它投出的 Pass，等於把它的錯誤也一起算進成功率裡。

這一課要做的，就是把這個偏差扣掉，再替修正後的數字加上誤差範圍。第一步，先搞清楚偏差會往哪個方向跑。

## 先把兩個錯誤率講清楚

要談偏差，得先把 judge 會犯的兩種錯誤講清楚。這裡用兩個比率來描述。

**TPR（true positive rate）**是「真正該 Pass 的案例中，judge 正確判成 Pass 的比例」。

可以把它想成 judge 辨認真正成功案例的能力。TPR 低，代表很多真正做對的輸出，被 judge 誤判成失敗。

**TNR（true negative rate）**是「真正該 Fail 的案例中，judge 正確判成 Fail 的比例」。

它代表 judge 擋下真正失敗案例的能力。TNR 低，表示很多真正做錯的輸出，被 judge 放行了。

<!--image:1-->

這兩個數字不是憑感覺填的。做法是準備一份人工標註過的 test set，再把 judge 的預測和人工標籤逐筆比對，算出 TPR 與 TNR。

這也是為什麼前面要先花力氣，把 judge 調到 TPR、TNR 都穩定：你需要一組可信的錯誤率，才有辦法校正後面的通過率。

## 觀察到的通過率是什麼

定義很簡單。假設你讓 judge 跑過 \(m\) 筆新的、未標註的 trace，其中有 \(k\) 筆被判為 Pass，那麼觀察到的通過率就是：

<!-- derived -->

```text
p_obs = k / m
```

這個 `p_obs` 代表的是「judge 認為有幾成通過」。它測量的是 judge 的行為，不是 agent 的真實表現。

換句話說，judge 不完美，而你只數它判為 Pass 的筆數，得到的就會是真實通過率的有偏估計。

## 偏差的方向，取決於哪一種錯誤比較多

這個偏差不是隨機的，方向可以預測。

用一個思想實驗來看會最清楚：假設人工標註集裡有 50 筆成功、50 筆失敗；而更大的未標註資料集，真實通過率是 80%。

注意，實務上你並不知道這個 80%。這裡只是先假設一個答案，讓偏差的方向更容易看出來。

第一種情況，judge 漏掉很多真正的成功，也就是 **TPR 低**。

這時，judge 會把一堆做對的輸出判成失敗。因此，你數出來的原始通過率會遠低於真實的 80%。

隨著 TPR 提高，原始通過率才會慢慢爬回 80%，不確定性也會跟著縮小。

第二種情況，judge 把很多真正的失敗判成成功，也就是 **TNR 低**。

這時，judge 會放行一堆做錯的輸出，讓原始通過率高於真實的 80%。

隨著 TNR 提高，原始通過率才會降回 80%，估計區間也會跟著變窄。

<!--image:2-->

四種組合攤開來看，後果不太一樣：

- **TPR 高、TNR 高**：估計較準，區間也較窄。
- **TPR 高、TNR 低**：假陽性把觀察到的成功數灌大，修正後的估計會往下修，區間也會變寬。
- **TPR 低、TNR 高**：假陰性把觀察到的失敗數灌大，修正後的估計會往上修，區間也會變寬。
- **TPR 低、TNR 低**：估計不可靠，區間會非常寬。這時該做的是先修 judge，而不是急著下結論。

## 哪個方向會讓你誤判

兩個方向都會讓你算錯，但代價並不對稱。

如果原始通過率被壓低，你會以為東西比較差，可能因此多花一輪時間，去修理一個其實沒有問題的 agent。

這是浪費時間，但通常不會直接造成事故。

原始通過率被抬高的那一側才危險。judge 放行真正的失敗，你看到一個漂亮的通過率，於是把功能送上線；但使用者遇到的，正是那些 judge 沒有抓到的錯誤。

這種誤判不會在 dashboard 上發出警報。它往往要等到你事後回頭檢查 trace，才會慢慢浮出來。

<!--image:3-->

所以，「未修正的通過率會騙人」最該記住的是它的方向性：

**當 TNR 不夠高時，你看到的數字會比真實情況好看，而這正是最容易讓人做出錯誤上線決定的方向。**

## 知道方向還不夠，你需要一個數字

到這裡，你只能說「通過率可能偏高」或「可能偏低」，但還說不出到底偏高、偏低多少。

如果要真正把偏差從通過率裡扣掉，就需要一個能把 `p_obs`、TPR 和 TNR 三個數字連起來的公式，也要知道這個公式在什麼情況下會失效。
