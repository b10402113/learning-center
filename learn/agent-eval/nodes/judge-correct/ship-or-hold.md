# 看區間下決定：ship、補資料，還是先修 judge

上一篇最後留下了一個卡住的情境：

θ̂ = 0.87，95% 信賴區間是 [0.81, 0.93]，團隊門檻則是 0.85。

點估計超過門檻，但下界沒有。

這時真正該問的，不是「0.87 大於 0.85 嗎？」而是：

**我手上的證據，夠不夠支持這個決定？**

這個問題沒有公式能代替你回答，但它有一套清楚的判斷順序：

1. 先看區間落在門檻的哪一側。
2. 再看判斷錯誤時，代價有多大。

## 三種區間位置，三種結論

把門檻畫成一條水平線，信賴區間大致會出現三種位置。

第一種，整個區間都在門檻之上。

例如 [0.85, 0.89]。這代表即使真實值落在區間的最低點，也仍然達到門檻。無論真實值靠近哪一端，結論都一樣：它夠好。

這是可以安心 ship 的位置。

第二種，區間跨過門檻。

目前的 [0.81, 0.93] 就是這種情況。點估計高於門檻，但最差情況可能只有 0.81。這是最麻煩的位置，因為你能不能上線，取決於功能是否承受得起這個結果。

第三種，整個區間都在門檻之下。

這時 θ̂ 再怎麼好看也沒有用，因為真實值很可能達不到要求。接下來該做的是回頭修 judge，而不是琢磨怎麼讓數字變漂亮。

這三種情況比的是區間的兩端，不是點估計。

只有一個點時，你只能拿數字互相比較；有了區間，才看得出這個比較到底有多可靠。

## 跨過門檻時，看代價

對 [0.81, 0.93] 這個案例，實務上的處理方式很直接：

**根據判斷錯誤的代價，決定要不要行動。**

如果一個成功率只有 81% 的功能一旦上線，就可能對使用者造成嚴重傷害，那麼這個區間太寬，就不能放心 ship。

這時可以收集更多 test 資料，或改進 judge，讓區間收窄。

反過來，如果這個功能風險很低，81% 的表現仍在可接受範圍內，那就可以直接 ship，再持續監控。

同一組數字，可能導向兩種完全相反的行動。差別不在統計數字本身，而在於你能不能接受「真實值真的只有 81%」這件事。

低風險功能可以帶著不確定性上線，因為出錯成本小，之後還能修正。高風險功能則不能這樣做，因為一旦出錯，可能沒有回頭的機會。

<!--image:2-->

這也是為什麼統計必須和決策放在一起看。

θ̂ 和信賴區間沒有善惡，它們只是把「你還不知道多少」量化出來。至於要不要在不確定的情況下行動，仍然是人的判斷，不是公式替你做的決定。

## 兩條收窄區間的路，代價不一樣

如果你判斷區間太寬、還不能 ship，下一步通常有兩條路：

- 收集更多 test 資料
- 改進 judge

這兩件事處理的是不同問題，不能混為一談。

補資料，補的是 **TPR 和 TNR 的樣本量**。這兩個數字都是從資料估計出來的，標註資料越多，估計通常越穩定。

如果 test set 只有幾十筆，重抽樣得到的 TPR*、TNR* 可能大幅跳動，信賴區間自然會很寬。多標註一些資料，可以降低這部分的抽樣波動。

修 judge，改的是錯誤率本身。

前面的思想實驗顯示，當 judge 漏掉很多真正成功的案例，也就是 TPR 偏低時，原始通過率會遠低於真實值，不確定性也會很大。提高 TPR 之後，區間才會明顯縮小。

改善 TPR，也就是提升 judge 辨認真正成功案例的能力，對收窄區間的效果最大。原因不難理解：當 TPR 很低時，修正公式會把 `p_obs` 放大很多倍。這會讓 TPR 一點點抽樣誤差，最後變成 θ̂ 的大幅波動。

因此，兩條路的判準不同。

如果 judge 已經不錯，只是 test set 太小，補資料通常最快。

但如果 judge 本身的 TPR 很低，補再多資料，也只是把一個偏掉、而且很分散的估計算得更精確。你可能得到一個很窄的區間，卻發現它是穩穩地圍著錯的位置。

## 還有一個更前面的判斷

前面討論的是「什麼時候可以 ship」。但思想實驗裡還有一個提醒，應該放在整條決策鏈的更前面。

judge 的錯誤，主要會讓不確定性變大，也就是把區間變寬，不一定會把修正後的估計整體推向錯的方向。

這件事的實務意義是：修正不是萬靈丹。它能可靠地移除兩種極端錯誤模式造成的偏差，代價則反映在區間寬度上。

因此，當你看到一個非常寬的區間，第一個念頭不該是「再算一次，說不定會變窄」，而應該是：

**我的測量工具是不是還不夠好？**

區間寬是診斷，不是雜訊。

## 把這一節收起來

回到一開始的 0.87。

現在你能說的，已經比單看點估計多很多。你知道這個數字是根據 judge 的 TPR、TNR，以及一批未標註的 trace 算出來的 `p_obs`。

你也知道，如果 judge 放行失敗，原始通過率會偏高，而這個方向可能讓你錯誤地把功能上線；修正公式在分母接近零時必須停手；[0.81, 0.93] 這個區間則是重抽樣 test set 兩萬次得到的結果，用來衡量 TPR、TNR 這兩個估計有多不穩定。

所以最後的判斷不該停在：

> 0.87 > 0.85，所以 ship。

而是：

> 這個區間跨過門檻，而我的功能承受得起 81% 嗎？

如果承受得起，就上線並持續監控。

如果承受不起，就先補 test 資料，或提升 judge 的 TPR。等區間收窄到整段都落在門檻之上，再來談上線。

決定你是否有足夠證據採取行動的，是**區間的寬度**，不只是點估計。
