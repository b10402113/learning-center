# L1 overview

- Every project runs on defaults whether or not you define them explicitly.
- Those defaults cover the order features are built, the level of care before shipping, and how indecision is handled.
- In the Vibe build, undefined decisions produced haphazard feature development.
- Scope was never defined, so all features were included rather than a chosen subset.
- The proof required to call a feature complete was minimal, and the cheapest solution was prioritized.
- Key issues were never discussed or documented, so problems only surfaced after the code was written.
- Adding scope prevents these outcomes by making the defaults explicit.
