# L1 overview

- Presents one debugging method for the plain-bug kind that works in any language, on any codebase, regardless of whether a human or an agent wrote the code.
- Defines debugging by contrast: not changing things until the error disappears (which is why bugs return), but the scientific method applied to a broken program.
- Describes the core loop: observe the failure, form one specific explanation, test it, and let evidence decide the next step, changing one thing at a time.
- Notes the six steps live below the video and are meant to be reread rather than memorized.
- Explains that the method still matters even though the debug skill can run it, because only the human can judge whether the skill proved the cause or merely hid the symptom.

# L2 detail

- `#L1-L13` — States the method's portability, rejects change-until-it-works debugging, and describes the observe-hypothesis-test loop.
