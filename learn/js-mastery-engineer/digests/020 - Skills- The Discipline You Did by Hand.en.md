# L1 overview

- Recaps the discipline taught so far: engineer context before building, make real decisions on purpose, keep always-on context small, and check output before trusting it.
- Argues knowing a discipline and actually running it every time differ, because the discipline is a stack of small procedures in a required order on every feature.
- Observes that people cut corners exactly when busiest, which is when the discipline matters most.
- Defines a skill as a procedure you kept doing by hand, captured in a file so it runs the same way every time, and stresses it is less magical than the name suggests and fully understandable.
- Explains a skill has two parts: a short name and description at the top, and a long body of instructions; the agent reads only the name and description, decides relevance, and loads the full body only for the chosen skill.
- Explains the cost model: unlike always-on context, ten procedures cost about two lines each until used, so you only pay for the one being used.
- Clarifies a skill does not make the model smarter or think for you; it runs the procedure and frees your attention for decisions and judgment.
- Summary sentence: the skill runs the procedure, you make the calls.
