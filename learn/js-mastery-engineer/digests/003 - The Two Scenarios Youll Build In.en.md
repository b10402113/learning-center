# L1 overview

- Sets up the course as practical: it first shows how not to code, by hand or by vibe coding, so the learner feels the pain, then introduces the workflow.
- Scenario one is a brand-new project, split into two paths: client work that turns vague requirements into a real technical specification, and a personal SaaS idea pressure-tested before code.
- Scenario two is an existing project: adding the next feature to code that already exists, using a workflow path that skips unnecessary upfront planning.
- Legacy codebases fall under scenario two: old code the learner did not write, partly broken, undocumented, and assigned rather than chosen.
- Names the two scenarios Greenfield and Brownfield and promises the same workflow will be run through both.
- Concludes that the learner will not just collect skills but know exactly when and how to reach for each.
