# L1 overview

- The exercise: pick a real idea you genuinely want to exist, run it through /scope, then run the first load-bearing decision through /architect.
- There is no answer key by design; the purpose of the skills is to make the scope, build approach, tier and stack choices yours.
- The agent is not neutral and has a grain from how language models are trained; three tendencies are worth watching.
- Tendency one: the agent wants to agree with you, so a leading description like "Uber for dog walkers" can make it plan an Uber-shaped product and every later decision inherits the wrong premise.
- The counter is built in — /architect challenges the premise, and during /scope you should answer truthfully rather than choosing whatever ends the interview fastest.
- Tendency two: the agent reaches for the common answer calibrated to the median project, so you should test its reasoning (and the runner-up) against your actual constraints, not just the tool name.
- Tendency three: the agent wants to look finished and will fill gaps with plausible assumptions, so a suspiciously short interview should make you cautious; cross-cutting questions about access, ownership, privacy, failure behaviour, permissions and lifecycle rules deserve time.
- Before finishing, check that the build approach attacks your greatest risk, the tier is honest, you understood each architectural reason, and each produced value/state/permission has a named source.
