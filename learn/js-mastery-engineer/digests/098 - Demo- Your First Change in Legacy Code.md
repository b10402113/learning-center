# L1 overview

- The lesson shows how to make a change in an existing codebase without disrupting its established functionality, using scope, architect and develop.
- Start by understanding the existing codebase rather than immediately suggesting changes.
- Use /scope to assess the project's structure and identify which parts are involved in the change.
- For larger changes, always begin with scope so the project remains intact.
- /architect determines the correct integration point for new features based on the existing implementation.
- Respect existing behaviour and keep disruption minimal; /develop follows existing patterns for consistency.
- Check the specs so expected and existing behaviours are documented, and change only what needs updating.

# L2 detail

- `#L1-L9` — the lesson's goal: change mature code using its existing architecture and conventions.
- `#L10-L26` — key takeaways: understand first, scope larger changes, architect the integration point, respect behaviour, follow patterns, check specs, avoid unnecessary changes.
