# L1 overview

- Addresses the objection that a workflow with named steps and required documents is just one person's preferences dressed up as engineering.
- Traces it to the software development lifecycle: work out what you are building, make important technical decisions and write them down, set conventions, build one feature at a time, and prove it works before calling it finished.
- Notes this predates Claude, Cursor, and other AI coding tools, with requirements feeding design, design feeding implementation, and implementation feeding verification.
- Writing decisions down is also old practice: architecture decision records exist because reasoning that lives only in someone's head disappears, and later changes then reintroduce the exact problem the original decision prevented.
- Careful teams leave evidence rather than relying on memory.
- Argues this matters more with an agent because an agent's instinct is to sprint at code, quietly filling in every missing decision itself within seconds, looking productive while building on decisions the developer never made.
- The skills do not invent a new process; they make the agent follow the process a good engineering team should already follow, one stage at a time with each decision feeding the next.
- Cites GitHub SpecKit and Amazon Qiro as similar premises, and flags the open question of what happens to those documents on day 30.
