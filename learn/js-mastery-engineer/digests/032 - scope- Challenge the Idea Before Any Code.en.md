# L1 overview

- Argues every project runs on defaults: a default feature order, a default level of care before shipping, and a default answer when nobody has decided.
- The developer either chooses those defaults deliberately or they get chosen one feature at a time by whatever the agent reaches for.
- In the vibe build nobody decided build order, so the agent built whatever it reached for first; nobody decided scope, so nothing was out of scope; nobody decided how much proof a feature needed, so the agent picked the cheapest answer, nothing.
- None of it was discussed, written down, or visible until it had become code.
- Running the scope skill is presented as the way to stop those project defaults from happening.

# L2 detail

- `#L1-L9` — Explains project defaults (feature order, care level, undecided answers) and shows how the vibe build let the agent choose all of them implicitly.
- `#L10-L11` — States that those were the project's defaults and that running scope prevents them.
