## Problem Statement

即使主題變數已經定義完成，如果每個頁面都從零開始製作按鈕、卡片和輸入欄位，最終會產生視覺不一致的問題。你需要一個共享的元件庫，讓所有頁面使用相同的基礎構件。

## Why it matters

型別化元件庫確保每個按鈕看起來一致、每個卡片遵循相同的間距規則，而 TypeScript 在編譯時就能捕獲錯誤的 prop 用法。它是設計系統的實作層，把 Token 的抽象定義轉化為可直接使用的 UI 磚塊。

## How it works

型別化元件是指帶有 TypeScript props 定義的 React 元件，props 的型別約束會強制使用者遵循設計系統的規範。一個典型的設計系統元件庫會包含 Button、Card、Badge、Input 等基礎元件，每個元件內部引用 Tailwind 的工具列類別（例如 `bg-primary`、`text-heading-lg`）來套用主題變數。核心規則是「先重用、再新增」——當現有元件能滿足需求時，絕不自行建立新元件。

## In plain terms

想像樂高積木：每塊積木都已經預先切割好尺寸和顏色，可以互相扣合。你不會自己雕刻一塊新積木，而是從積木組中挑選合適的規格來搭建。

## Practical use

在 Vertex 平台中，代理在一次工作階段內完成了整個元件庫的建構。元件統一存放在共享目錄中，後續的每個頁面——首頁、課程卡片、搜尋結果頁——都從同一個元件庫匯入。平台還設有一個包含 14 個區段的展示路由，用於視覺驗證所有元件的各種變體是否正確渲染。
