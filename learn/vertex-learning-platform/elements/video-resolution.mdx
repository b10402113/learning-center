## Problem Statement

Learning platform 的每一堂課都需要真實的影片內容來驅動播放、搜尋與字幕擷取。如果課程關聯的 YouTube URL 是憑空捏造的，播放器會直接報錯，搜尋功能也無法從不存在的字幕中建立索引。Video Resolution（影片解析）正是解決這個問題的機制——它在 seed 階段將每一堂課對應到一支真實存在的 YouTube 影片，確保後續所有功能都在可靠的基礎上運作。

## Why it matters

Vertex 平台的核心價值在於「搜尋任何影片，精確跳轉到某一秒」。這意味著整個系統依賴真實的影片字幕來建立可搜尋的 `video` 文件。如果 seed 階段關聯了無效的 URL，後續的 caption ingestion pipeline 無法取得字幕，搜尋功能形同虛設，影片播放也會失敗。換言之，Video Resolution 是整條功能鏈的起點：沒有真實影片，就沒有字幕；沒有字幕，就沒有搜尋；沒有搜尋，平台就失去核心價值。

## How it works

Video Resolution 的核心是一個名為 `videos.json` 的靜態 JSON 檔案。它是一個扁平的 JSON 物件，包含 120 個 key，每個 key 對應一堂課的 lesson id（與 `seed.ndjson` 中使用的 id 一致）。每個 value 是一個物件，包含五個欄位：

- **`id`** — YouTube 影片的唯一識別碼（YouTube video ID）
- **`title`** — 影片的原始標題
- **`channel`** — 上傳頻道名稱
- **`duration`** — 影片時長，以秒為單位（從幾分鐘到約 20 分鐘不等）
- **`query`** — 當初用來搜尋到這支影片的 YouTube 搜尋字串

`studio/scripts/seed/resolve-videos.mjs` 讀取這個檔案，將每堂課的 seed 記錄與對應的真實 YouTube URL 綁定。這個過程不依賴 YouTube Data API，而是透過影片 ID 直接構造可播放的 URL。Seed schema 只接受 YouTube、Vimeo 或 Bunny 的 URL，且以唯一 URL 為 key 確保每支影片不重複。

影片的搜尋字串（`query`）扮演關鍵角色。這些查詢是真實的教學搜尋語句，例如 "react server components explained tutorial" 或 "nextjs app router file system routing"，確保搜尋結果回來的影片確實是與課程主題匹配的教學內容，而非隨意的娛樂影片。搜尋完成後，duration 欄位從 `videos.json` 流入 seed，讓課程和模組的總時長能正確累加。

## In plain terms

想像你在為一個圖書館建立書目。你不能在書架上放一本「假書」然後告訴讀者「這裡有一本關於 Python 的書」——讀者走過去只會看到空蕩蕩的書架。Video Resolution 就像是在建書目之前，先親自去書店確認每一本書確實存在、確實有內容，然後把書的真實 ISBN 和位置記錄下來。這樣當讀者搜尋「Python 入門」時，系統才能準確地帶他走到正確的書架前。

## Practical use

在 Vertex 平台的 seed 流程中，120 支影片平均分配在十個課程主題上：Next.js、React、TypeScript、AI 應用開發、RAG 檢索、Python、系統設計、PostgreSQL、DevOps 與 Web 安全，每個主題 12 支影片，總計約 22.75 小時的真實教學內容。頻道來源包括 Codevolution、Web Dev Simplified、ByteByteGo、KodeKloud 等知名教學頻道。

整個流程分為三個階段：

1. **建立 videos.json** — 針對每堂課的主題，以真實的 YouTube 搜尋語句找到對應的教學影片，記錄其 id、標題、頻道、時長與搜尋字串
2. **resolve-videos.mjs** — 讀取 videos.json，將每堂課的 seed 記錄綁定到真實的 YouTube URL，確保 seed.ndjson 中的每一堂課都有可播放的影片
3. **ingest pipeline** — 後續的 `studio/scripts/ingest/` 腳本利用這些真實 URL 去擷取每支影片的字幕（captions），建立可搜尋的 `video` 文件

這三個階段環環相扣：videos.json 是資料真相來源，resolve 確保 seed 正確，ingest 讓搜尋功能真正可用。seed 的 durations 也從此處流出——模組時長是其下所有課程時長的總和，課程時長是其下所有模組時長的總和，這些數字全部源自 videos.json 中的真實影片長度。

## Questions

**Q1: 為什麼不能在 seed 階段使用假造的 YouTube URL？**
A: 假造的 URL 無法播放（播放器會報錯），後續的 ingest pipeline 也無法從不存在的影片中擷取字幕，導致搜尋功能完全失效。

**Q2: videos.json 中的 `query` 欄位有什麼作用？**
A: `query` 記錄了當初用來在 YouTube 上搜尋到該影片的搜尋字串。它確保每支影片都是透過與課程主題相關的真實搜尋語句找到的，而非隨機挑選。這個欄位也讓未來重新驗證或替換影片時有據可循。

**Q3: resolve-videos.mjs 如何確保每支影片不重複？**
A: Seed schema 以唯一 URL 為 key，每個 URL 只能出現一次。resolve-videos.mjs 在處理時會遵循這個約束，確保 120 堂課各自對應到不同的真實影片。
