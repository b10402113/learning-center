## Problem Statement

AI 可以讓單一畫面看起來很好看，但當你要求它做一個多頁應用時，它會開始自作主張——下一頁加了一個漸層、又一頁換了字體、間距也自己調了。每一頁 individually 看起來都「還行」，放在一起卻是四種不同的視覺語言。問題的根源是 AI 沒有視覺約束：它不知道你的品牌色是什麼、按鈕該長什麼樣、字級該用哪一級。沒有約束，AI 的「創造力」就會在每一個頁面各自發明一套不一致的設計——這不是 bug，這是它的預設行為。

## Why it matters

設計系統 (Design System) 是人類設計者和 AI 實作者之間的契約。它把 Typography、色彩、按鈕、卡片、Badge、輸入框、可複用的 Pattern 都定義成具體規格，然後要求 AI 嚴格照著做。有了這份契約，AI 不再「自由發揮」，而是照著同一套規格在每一個頁面重複使用相同的 token 和元件。多頁 UI 的一致性不是靠 AI 的品味，而是靠一份寫下來的設計系統。沒有它，首頁的按鈕可能是藍色，課程頁變成綠色，搜尋頁又冒出紫色——而每一個顏色都是 AI 自己選的。

## How it works

設計系統包含以下具體內容：

- **Typography**：每一個 heading 級別的字型、大小、粗細、行高，全部定義成 token。
- **色彩系統**：primary color、neutral color、語義色（成功、警告、錯誤），每個色階有明確的 hex 或 Tailwind 變數名。
- **間距系統**：統一的 spacing scale，例如 `4px / 8px / 16px / 24px / 32px / 48px`，避免 AI 每次都猜一個新的 magic number。
- **Border-radius 與 Shadows**：按鈕的圓角、卡片的陰影、輸入框的 border，全部在同一個 token 裡定義。
- **元件規格**：按鈕有哪些 variants（primary / secondary / ghost）、大小（sm / md / lg）、hover 與 disabled 的狀態；輸入框的 placeholder color、focus ring 的顏色與寬度；Badge 的颜色對應語義（免費、付費、進行中）；Card 的 padding、border、shadow 組合。
- **可複用 Pattern**：例如 CourseCard、LessonCard、InstructorCard，這些都從上面的 token 和元件組合而來，不是每次重新設計。

設計系統對 AI 的約束方式是：AI 在實作任何 UI 之前，先讀取設計 token 和元件規格，然後照著它們建構——不能自己加漸層、不能自己選色、不能自己发明新的間距值。設計稿的截圖是 source of truth，AI 的職責是精確複製它，而不是「改善」它。操作手冊（AGENTS.md）明確寫了「You do not design UI」，AI 的創造力只被允許用在實作層面——響應式的 column 重排、sidebar 折疊——而不是設計層面。

在 Vertex 的專案中，設計稿被放在 `design/` 資料夾，AI 讀取它們後用 Tailwind v4 的 theme variables 實作成 token-backed 的元件庫。設計系統只建一次，之後每一個功能頁面（首頁、課程頁、搜尋頁）都從同一套元件庫渲染，保持視覺一致。

## In plain terms

設計系統就像一本食譜，給廚師（AI）用。沒有食譜時，廚師每次做菜都隨興發揮——這次多加鹽、下次換個擺盤、再下次換盤子的顏色。有了食譜，每道菜都遵循同一套配方、食材和擺盤標準，不管做幾道菜，看起來都像同一家餐廳出品。

## Practical use

在 Vertex 專案裡，設計系統的落地方式很具體：

- 設計稿圖片放在 `design/` 資料夾，跟 `public/` 同級。AI 每次做 UI 都從這裡讀取參考。
- 設計系統被轉譯成 Tailwind v4 的 CSS 變數（theme tokens），寫進 `globals.css`——所有 typography、colors、shadows、utilities 都在這裡統一管理。
- 型別化的元件庫（typed component library）從 token 建立，每一個元件都有 TypeScript 介面和 Tailwind class 的對應。
- 有一個 showcase 頁面讓你在瀏覽器裡一次看完所有 token 和元件的實際渲染，驗證它們是否正確。
- 沒有設計系統時：首頁用藍色按鈕、課程頁用綠色按鈕、搜尋頁用紫色按鈕，AI 自己選了三種顏色，看起來像三個不同產品。有了設計系統後：所有頁面的按鈕、卡片、Badge 都從同一套 token 渲染，視覺語言統一。

## Questions

### Q1. 為什麼 AI 在單頁應用上「看起來不錯」，但在多頁專案上就會失敗？
A1. 單頁時 AI 只需做一次設計決定，它可以集中注意力把那個畫面做好。但多頁時，每做一個新頁面它就重新做一次設計決定——選色、字級、間距、元件樣式——而這些決定在不同頁面之間幾乎不可能自然一致。設計系統把這些決定提前鎖死，AI 在每頁只需「照抄」而不需要「決定」。

### Q2. 設計系統和操作手冊（AGENTS.md）的 UI 規則有什麼關係？哪一個才是真正的約束？
A2. 操作手冊是「規則」——它說「You do not design UI」，定義了 AI 的行為邊界；設計系統是「規格」——它提供了 AI 該照著做的具體內容。兩者缺一不可：有規則但沒有規格，AI 知道不能設計但不知道該做什麼；有規格但沒有規則，AI 可能還是會在規格之外自己加東西。兩者一起才能讓 AI 的 UI 自由度被完全關進盒子。

### Q3. 在 Vertex 專案中，設計系統建成後對後續頁面（首頁、課程頁、搜尋頁）的具體影響是什麼？
A3. 設計系統建成後，每一個後續頁面都從同一套 Tailwind v4 theme variables 和 typed component library 渲染——首頁的卡片、課程頁的影片嵌入框、搜尋頁的結果卡片都使用相同的 border-radius、shadow、spacing 和 color tokens。AI 不需要在每個頁面重新決定視覺風格，因此不會出現「首頁藍色按鈕、課程頁綠色按鈕」的不一致問題。
