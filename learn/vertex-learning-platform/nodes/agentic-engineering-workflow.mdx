# 代理式工程的工作流根基

## Learning goal

能說出「為什麼先 plan 再 code」——human 是產品思考者、AI 是實作代理；product-first 讓 stack 自己選定；掌握九步 loop 與 scope 邊界（build only what is listed）。

## Steps

1. [[learn/vertex-learning-platform/nodes/agentic-engineering-workflow/agentic-engineering-foundation|Agentic Engineering 基礎：先給 AI 一套系統，再讓它動手]] — 為什麼「prompt 到能用」會崩潰，human 是產品思考者、AI 是實作代理
2. [[learn/vertex-learning-platform/nodes/agentic-engineering-workflow/product-first-thinking|產品優先思考 (Product-First Thinking)：先定義產品，技術選型自然浮現]] — 用檢查清單定出產品輪廓，讓 stack 自己選定（after step 1）
3. [[learn/vertex-learning-platform/nodes/agentic-engineering-workflow/scope-boundary|範圍邊界 Scope Boundary：只建清單上列出的東西，擋下 overbuild]] — build only what is listed，standout feature 決定一切（after step 2）
4. [[learn/vertex-learning-platform/nodes/agentic-engineering-workflow/implementation-loop|實作迴圈 Implementation Loop：先批准再寫碼的九步流程]] — 寫 implementation prompt、拿到人工批准、才寫 code、跑 checks、回報（after step 3）

## Lesson

這一節把「讓 AI 寫程式」從盲目 prompt 變成一套可重複、可控的工作流。第一步不是挑框架，而是想清楚人跟 AI 的分工：人保留產品思考與架構決策，AI 只做執行——方法是先定義產品、畫出範圍邊界，再讓技術選型自然浮現；執行的時候，每一步都走「先寫實作 prompt、拿到人工批准、才寫 code、跑檢查、回報」的九步迴圈。四個步驟照順序讀，走完就能說出整套工作流的骨架，並看懂 AGENTS.md 為什麼是這個工作流裡最重要的檔案。
