# 設計系統：把 AI 的 UI 自由度關進盒子

## Learning goal

能說明為什麼需要 design system（阻止 AI 自行發揮），把設計稿轉成 Tailwind v4 token 與 typed component library，並用 showcase 驗證。

## Steps

1. [[learn/vertex-learning-platform/nodes/design-system-boundary/why-design-system-for-ai|AI 為什麼需要 Design System？多頁 UI 一致性的秘密]] — 說明 AI 在多頁應用中會自行發揮導致不一致，以及 design system 如何作為視覺合約
2. [[learn/vertex-learning-platform/nodes/design-system-boundary/tailwind-v4-tokens|Tailwind v4 @theme 設計 Token 實戰：從設計稿到 globals.css]] — 從設計參考圖提取 token，寫進 Tailwind v4 globals.css（after step 1）
3. [[learn/vertex-learning-platform/nodes/design-system-boundary/typed-component-library|Tailwind v4 Token 建立 Typed Component Library 完整指南]] — 用 token 建立 button、card、badge、input 等可重用元件，確保 TypeScript 型別安全（after step 2）
4. [[learn/vertex-learning-platform/nodes/design-system-boundary/showcase-validation|Design System 截圖驗證：用 Headless Chrome + Visual Diff 自動比對設計稿]] — 建 showcase 路由，截圖對比參考圖，整合進 agentic workflow（after step 3）

## Lesson

AI 能把單一頁面做得很好看，但一旦要建多頁應用，它的「創造力」反而成了問題——每個頁面可能選不同的字體、用不同的間距、甚至自己加上喜歡的漸層色。設計系統就是解法：先把 typography、color、spacing、buttons、cards 等視覺規格定義清楚，再讓 AI 嚴格照著做。在 Vertex 專案裡，設計參考圖放在 `design/` 資料夾，AI 讀完 AGENTS.md 的 UI rules（「你不是設計師，你是實作者」）後，用 Tailwind v4 的 `@theme` 指令把顏色、字級、間距寫成 CSS 變數，再用這些 token 建出帶型別的元件庫。最後用 14-section 的 showcase 頁加上 headless Chrome 截圖，逐步對齊到參考圖，確保整套系統在 AI 手裡不會走樣。四步走完之後，你應該能說明「為什麼不能讓 AI 自由發揮 UI」，也能把設計稿變成可重用、可驗證的前端基礎。
