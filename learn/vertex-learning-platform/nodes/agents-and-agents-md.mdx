# Skills 與 AGENTS.md：兩層上下文

## Learning goal

能分辨「工具知識放 skills、專案規則放 AGENTS.md」的分層，並照 15 節結構為自己的專案寫一份 operating manual。

## Steps

1. [[learn/vertex-learning-platform/nodes/agents-and-agents-md/skills-vs-context|Skills vs AGENTS.md：AI 工具知識與專案規則的分層策略]] — 能說出「工具知識放 skills、專案規則放 AGENTS.md」的分層理由，並在實作前安裝與驗證 agent skills
2. [[learn/vertex-learning-platform/nodes/agents-and-agents-md/agents-md-anatomy|AGENTS.md 完整解剖：15 節結構逐節拆解]] — 能照 15 節結構逐一解釋每節的意圖與邊界
3. [[learn/vertex-learning-platform/nodes/agents-and-agents-md/agents-md-decisions|AGENTS.md 決策鎖定、資料模型與安全陷阱]] — 能列出 decisions、data-model、traps、when-in-doubt 的核心內容，並說明它們如何防止 AI 做出產品/架構錯誤決策（after step 2）
4. [[learn/vertex-learning-platform/nodes/agents-and-agents-md/write-your-own|從零寫 AGENTS.md 的八步驟完整指南]] — 能從零為自己的專案寫出一份完整的 AGENTS.md，涵蓋所有必要章節（after steps 1–3）

## Lesson

AGENTS.md 是代理式工程的工作流裡，人類保持產品控制權的核心載體。它不是 README，而是寫給 AI 代理看的操作手冊——定義產品、邊界、規則、工作流程，讓 AI 只在人給定的系統內執行。这份手冊的關鍵在於「分層」：工具知識（skills）說明工具怎麼用，專案規則（AGENTS.md）說明你的專案是什麼，兩者各自獨立、互不污染，才能在工具更新時只改 skill、在專案決策變動時只改 AGENTS.md。15 節結構從角色定義、產品描述、工作流程，一路到資料模型、搜尋行為、安全陷阱與檢查清單，每一節的存在都是為了攔下一類 AI 不該自己做的決策。寫好之後，它就是整條生產線的單一事實來源（single source of truth）。
