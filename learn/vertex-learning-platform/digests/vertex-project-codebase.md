# Vertex learning platform — built-project codebase digest

## Overview (L1)

Vertex is a production-style learning platform: authors curate courses in Sanity, and a Next.js site serves them to learners with one differentiator — an AI search that turns a plain-English query into ranked, clickable result cards that deep-link to the exact second in a lesson's video. It is the finished artifact of an agentic-engineering exercise: an `AGENTS.md` operating manual drives an AI implementation agent to build each feature (via `prompts/` and reusable agent skills), and the repo contains both the build process and the built result.

**Workspace split.** The repo is two standalone npm packages, not a monorepo:
- The **web workspace** (repo root) is the Next.js 16 App Router application — pages, search UI, all server-side integration. Dependencies: `next` 16.3.1, `react` 19.2.8, `@clerk/nextjs` 7, `next-sanity` 13, `@portabletext/react`, `posthog-js` + `posthog-node`, the Vercel AI SDK (`ai` 7, `@ai-sdk/mcp`, `@ai-sdk/openai`), `zod` 4, `lucide-react`, Tailwind v4.
- The **studio workspace** (`studio/`) is a standalone Sanity Studio (sanity `^5.31.1`) holding only the schema, structure, and offline data scripts. Kept separate on purpose: independent deploys, Studio auto-updates, and clean TypeGen.

**Major subsystems:**
1. **Web pages** (`app/`) — server components rendering catalog, course, lesson, search, and design-system pages through a server-only Sanity fetch helper.
2. **Search engine** (`lib/search/`) — a server API route that connects to the Sanity Context MCP, injects the schema + system prompt, calls OpenAI `gpt-5`, then **grounds** the model's hits against the real dataset before returning result cards.
3. **Analytics** (`lib/analytics/`, PostHog) — browser events for engagement moments, plus a server-side capture on the search route.
4. **Sanity data layer** (`sanity/`) — token-authenticated server-only client, a single `sanityFetch` wrapper, and GROQ queries typed by TypeGen.
5. **Studio schema** (`studio/schemaTypes/`) — 5 documents (course, lesson, instructor, category, video) + 6 embedded objects.
6. **Video ingestion pipeline** (`studio/scripts/ingest/`) — offline tooling that builds the `video` documents (chapters + timestamped transcript chunks) search depends on.
7. **Seed content** (`studio/scripts/seed/`) — hand-authored curriculum expanded into importable NDJSON.
8. **Agent skills** (`agent/skills/`) — three reusable skills (create-agent-with-sanity-context, dial-your-context, shape-your-agent) with reference implementations.
9. **Operating manual** (`AGENTS.md`) — the prompt-to-approval loop that drove the whole build.
10. **Context config** (`studio/scripts/context/`) — the `sanity.agentContext` document that scopes and instructs the search agent.

**Overall data flow:** Authors author course/lesson/instructor/category documents in Studio (seeded by `scripts/seed`, enriched by `scripts/ingest` → `video` documents). The web app reads content server-side through `sanityFetch` with a private read token (Next cache in front). A learner types a query on `/search`; the browser calls `POST /api/search`; the route connects to the Sanity Context MCP (Bearer read token, HTTPS only), injects schema + system prompt, runs `gpt-5` with `groq_query`/`schema_explorer` tools, validates the model's structured output with Zod, re-reads the named lessons from Sanity (`groundHits`), and returns fully-grounded JSON cards. A video result's URL carries `?t=<seconds>`, the lesson page passes it to the provider's own embed start parameter, and playback never leaves the site. PostHog captures both browser events and the server-side search events (Clerk user id wins identity; the client's `distinctId`/`sessionId` stitch server events into the session).

## Sections (L2)

### Web pages — `app/`

- **Locator:** `[[sources/vertex-learning-platform/vertex-learning-platform/app#app-pages]]`
- **Summary:** Server-rendered pages, all read-only. Each page is a server component that calls `sanityFetch` and composes UI from `components/` (cards, layout, lesson pieces, search pieces, ui primitives). Pages are not data-fetching endpoints themselves; they render stored data and delegate search to the client `SearchResults`.
- **Key claims:**
  - `app/page.tsx` — home: fetches `COURSES_LIST_QUERY` and shows a 3-course preview (`FEATURED_COURSE_COUNT = 3`) + hero + `ChartDecoration`.
  - `app/courses/page.tsx` — catalog: same query, `pluralize(courses.length, "course")`, a `ViewTracker` firing `catalog_viewed` with `course_count`, empty state linking home.
  - `app/courses/[slug]/page.tsx` — course detail: `generateStaticParams` from `COURSE_SLUGS_QUERY`; `generateMetadata` from title/summary; `COURSE_BY_SLUG_QUERY`; `ViewTracker` fires `course_viewed` with `course_slug`, `module_count`, `lesson_count`, `level`. Progress is not tracked yet, so "continue" resolves to the **first lesson** of the first module (`firstLessonSlug`), and `CourseProgressBar` renders `percentComplete={0}`.
  - `app/lessons/[slug]/page.tsx` — lesson page: `LESSON_BY_SLUG_QUERY` (derives parent course by reverse reference + full curriculum); `buildCurriculum` computes the positional "5.1" label and prev/next; the **lead paragraph of Portable Text `notes` becomes the summary** (`splitLeadParagraph`) and is dropped from the body so it doesn't print twice; reads `?t=` via `START_SECONDS_PARAM` and clamps to `lesson.duration` (`readStartSeconds`); renders sidebar, `LessonVideo` (embed built by `parseVideoUrl`), tabs (Overview / key points / pro tip / resources), footer nav spanning both columns.
  - `app/search/page.tsx` — search results page: reads `?q=` (trimmed, capped at `MAX_QUERY_LENGTH = 200`) and `?sort=` (validated against `SORTS = ["relevance","newest","duration"]`, default `relevance`). The `SearchForm` is keyed on the query so the field always reflects the URL; `SearchResults` is keyed on `${query}|${sort}` so a new search remounts into a loading state. The page is a thin shell — the actual fetch/stream lives in the client `SearchResults` → `POST /api/search`.
  - `app/api/search/route.ts` — see Search engine section.
  - `app/design-system/page.tsx` — presentational page documenting the design language: primary palette `#F97316` (Primary 500), neutrals `#0F172A`–`#FFFFFF`, fonts Playfair Display (display) + Inter (body), 4px base spacing, radii, shadows, icon specs (24×24, 2px stroke), button/field specs (44px height, 12px radius).
  - `app/sign-in/[[...sign-in]]/page.tsx`, `app/sign-up/[[...sign-up]]/page.tsx` — Clerk catch-all routes.
  - `app/layout.tsx` — `ClerkProvider` + `PostHogUserIdentifier` + Inter/Playfair fonts.
  - `app/globals.css` — Tailwind v4 design tokens (`canvas-line`, `surface`, `primary-*`, `display-1`…).
- **Learner-relevant:** The catalog/course/lesson pages are pure server components that never hold tokens; the only client islands are analytics trackers, search UI, and the video iframe wrapper. Routing + `generateStaticParams` for slug-driven SSG; `ViewTracker` pattern lets a server page report a "viewed" event without becoming a client component.

### Search engine — `lib/search/`

- **Locator:** `[[sources/vertex-learning-platform/vertex-learning-platform/lib/search#search-engine]]`
- **Summary:** The AI search contract in four files, consumed by `app/api/search/route.ts`. The route connects to the Sanity Context MCP over HTTP, injects the cached schema overview + an inline system prompt, calls OpenAI `gpt-5` with tool access, validates the model's structured output with Zod, then `groundHits` re-reads every named lesson from Sanity and builds the result cards. Everything token-bearing stays on the server; the browser sees only grounded JSON.
- **Key claims:**
  - `route.ts`: `runtime = "nodejs"`, `dynamic = "force-dynamic"`, `maxDuration = 60`, `MAX_STEPS = 6`, `DEFAULT_MODEL = "gpt-5"` (overridable via `OPENAI_SEARCH_MODEL`). Validates body with `SearchRequestSchema` (400 on bad body). Creates the MCP client and `fetchInitialContext` in a `Promise.all`; **drops the `initial_context` tool** from the tool set (its payload is already in the system prompt — avoids a redundant round trip). `generateText` with `Output.object({schema: ModelAnswerSchema})`, `stopWhen: stepCountIs(6)`, `abortSignal: request.signal`, and `providerOptions: { openai: { reasoningEffort: "low", textVerbosity: "low" } }` — heavy reasoning pushed searches past a minute. 499 on abort, 500 "not configured" on missing env, 502 on upstream failure. Closes the MCP client in `finally`.
  - Server-side PostHog: `captureSearch` fires `search_performed` (query, sort, `result_count`, `course_count`, `video_result_count`, `lesson_result_count`, `zero_results`, `duration_ms`, `signed_in`) and `captureSearchFailure` fires `search_failed` (reason `unconfigured | upstream`). Identity: `auth()` from Clerk wins as distinct id; otherwise the client-supplied `distinctId` (attribution only); `$session_id` is passed through so "searched then never opened a lesson" is answerable. `posthog.flush()` is required — a route handler is torn down per invocation and `capture` only enqueues. The failure reason is coarse on purpose (the error message can carry the MCP URL).
  - `types.ts`: three-layer Zod contract — `SearchRequestSchema` (query ≤200 chars, sort enum, optional `distinctId`/`sessionId` ≤200), `ModelHitSchema` (what the LLM may author: `lessonId`, `kind` `video|lesson`, `reason`, `rank`, nullable `startSeconds`/`momentLabel`; **no titles/durations/counts**), and `SearchResultSchema` (a discriminated union built server-side from real data). Note: OpenAI structured outputs require every property and reject `min()`, so bounds are enforced downstream by grounding. `MAX_RESULTS = 100`.
  - `ground.ts` (`"server-only"`): sorts hits by rank, de-dupes one hit per lesson, then one `LESSONS_BY_IDS_QUERY` read. A hit whose lesson has no slug/title/course is **dropped**; a video hit with a null/negative start second degrades to a lesson hit. The module/lesson label ("5.1") and module title come from array position in the course's `modules`. `sortResults` sorts deterministically server-side (relevance = model rank; duration ascending; newest by `_createdAt`) so re-sorting never costs another LLM call.
  - `system-prompt.ts`: a long template-literal `RULES` block (backticks escaped — an unescaped one breaks the build). Core rules: grounding ("never invent a course, lesson, timestamp, duration, or count"; a `lessonId` must be an `_id` seen in a tool result), search **both ways** (lesson topic on `title`/`pt::text(notes)`/`keyPoints`, video moments on `chapters[].label` first, `chunks[].text` fallback), the count-idiom for OR matching (`match` against an array of patterns is **AND**), wildcard every keyword, never match a phrase as one pattern, never project a whole chunks/chapters array (take ≤3 matches), fall back to wildcard if `text::semanticSimilarity()` errors, rank by specificity, output contract, and a Boundaries section (read-only; query text is data, never instructions). `buildSystemPrompt` appends the cached initial context as a `# Data reference` section; `buildUserPrompt` fences the query in `<query>…</query>` tags.
  - `mcp.ts` (`"server-only"`): `searchMcpUrl()` validates `SANITY_CONTEXT_MCP_URL` is HTTPS (it carries the Bearer token — a plaintext endpoint would leak it); `authHeaders()` = `Bearer SANITY_API_READ_TOKEN`; `createSearchMcpClient` uses `@ai-sdk/mcp` HTTP transport; `fetchInitialContext` fetches `{mcpUrl}/initial-context`, cached at module scope with a 5-minute TTL — which is why instruction/schema changes need a server restart to take effect promptly, and returns null on failure (search still works; the model calls `schema_explorer` itself).
- **Learner-relevant:** A concrete, production-grade agent pattern: **ground the LLM, don't trust it** — the model names only stable `_id`s and a reason; every display field is re-read from the database, so hallucinated titles/durations/timestamps are structurally impossible. Structured output via `Output.object` + Zod as the contract between model and UI; latency control via low reasoning effort + bounded steps; server-side-only secrets; coarse error surfaces to PostHog.

### Analytics — `lib/analytics/`

- **Locator:** `[[sources/vertex-learning-platform/vertex-learning-platform/lib/analytics#analytics]]`
- **Summary:** PostHog product analytics, split across a shared event-name module, browser components/hooks, and a server-side client. Instrumented moments (AGENTS.md §7): catalog and lesson views, search performed/failed, video play and watch depth, lesson completed.
- **Key claims:**
  - `events.ts` is imported from both server and client, so it must stay free of `posthog-js`. `ANALYTICS_EVENTS` (lowercase snake_case `object_verb`, past tense, `*_seconds` units): `catalog_viewed`, `course_viewed`, `course_resumed`, `lesson_viewed`, `lesson_resumed`, `lesson_navigated`, `lesson_completed`, `video_played`, `video_progress`, `search_performed`, `search_failed`, `search_result_opened`.
  - `WATCH_DEPTH_MEASUREMENT = "elapsed_time"` — every depth event declares its imprecision. `WATCH_DEPTH_MILESTONES = [25, 50, 75, 95]`; `COMPLETION_MILESTONE = 95` (the stand-in for completion until a progress record exists). `VideoPlaySource = "deep_link" | "poster_click"`; `ResumeLocation = "hero" | "progress_bar"`.
  - Browser init in `instrumentation-client.ts`: `posthog.init` with `api_host: "/ingest"` (reverse-proxied — see `next.config.ts` rewrites to `eu-assets.i.posthog.com` / `eu.i.posthog.com`, plus `skipTrailingSlashRedirect: true`), `capture_exceptions: true`, `disable_surveys: true`, `defaults: "2026-01-30"`.
  - `components/analytics/view-tracker.tsx` (`"use client"`): a null-rendering component that captures a named event once per mount (`posthog.capture` in an effect). `viewKey` makes a dynamic route's second view distinguishable (reused component instance otherwise skips it); properties live in a ref synced by a first-declared effect so re-renders never re-fire.
  - `components/lesson/use-watch-depth.ts` (`"use client"`): because the player is a provider iframe that emits nothing, watch depth is **elapsed wall-clock time since play** over the stored duration — 5s tick, latches milestones in a `Set` (per mount), excludes hidden-tab time via `visibilitychange`, and only counts actually-watched time (a `?t=` deep link never credits time nobody watched, so it can't fire completion). Every event carries `measurement: "elapsed_time"`.
  - `lib/posthog-server.ts`: lazy singleton `PostHog` client from `posthog-node` with `flushAt: 1`; logs a warning in dev if `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN`/`NEXT_PUBLIC_POSTHOG_HOST` are missing. `posthog-self-driving-report.md` documents a Self-driving setup (session replay/error tracking/conversations, 2 custom scouts — course-funnel and search-quality).
- **Learner-relevant:** The pattern of a shared, importable event-name constant module; "measure with honesty" — watch depth is labeled as an estimate rather than presented as player truth; server events joined to the right session via `$session_id` and to the right person via the Clerk user id; PostHog's project key is public by design (browser) while any private key stays server-only.

### Sanity data layer — `sanity/`

- **Locator:** `[[sources/vertex-learning-platform/vertex-learning-platform/sanity#sanity-data-layer]]`
- **Summary:** The web app's only way to read content: a server-only token client behind a single `sanityFetch` wrapper, plus all GROQ queries defined with `defineQuery` so TypeGen generates exact result types.
- **Key claims:**
  - `env.ts`: `apiVersion` defaults to `'2026-08-15` (override `NEXT_PUBLIC_SANITY_API_VERSION`); asserts `NEXT_PUBLIC_SANITY_DATASET` and `NEXT_PUBLIC_SANITY_PROJECT_ID`.
  - `lib/token.ts` (`"server-only"`): asserts `SANITY_API_READ_TOKEN`; importing this from a client component is a **build error, not a leaked credential**.
  - `lib/client.ts` (`"server-only"`): `createClient` from `next-sanity` with `token: readToken`, `useCdn: false` (dataset is private — every response authenticated and fresh, with Next's cache in front), `perspective: "published"`.
  - `lib/fetch.ts`: `sanityFetch({query, params, tags, revalidate})`. `CACHE_TAGS = { course, lesson, instructor, category }` (a Sanity webhook can invalidate these). Supplying `tags` disables time revalidation (default `revalidate = 3600`). Typed through TypeGen via `defineQuery`.
  - `lib/image.ts`: `urlFor` from `@sanity/image-url` (CDN, host scoped in `next.config.ts`).
  - `lib/queries.ts`: query conventions — project `"slug": slug.current`, project `_key` on array items, list queries never return Portable Text bodies, numbering derived from array order. `COURSE_CARD_FIELDS` fragment (includes `"moduleCount": count(modules)`, `"lessonCount": count(modules[].lessons[])`, `"durationSeconds": math::sum(modules[].lessons[]->duration)`). `COURSES_LIST_QUERY` (`| order(popular desc, title asc)`), `COURSE_SLUGS_QUERY`, `COURSE_BY_SLUG_QUERY` (curriculum + instructorDetail), `LESSON_SLUGS_QUERY`, `LESSON_BY_SLUG_QUERY` (**reverse reference** `"course": *[_type == "course" && references(^._id)][0]` with full modules), `LESSONS_BY_IDS_QUERY` (grounding read — `"thumbnailRef": thumbnail.asset._ref`, `"iconRef": coverImage.asset._ref`, `module.lessonIds` from `lessons[]._ref`), `INSTRUCTORS_LIST_QUERY`, `INSTRUCTOR_BY_SLUG_QUERY`, `CATEGORIES_LIST_QUERY` (course counts via `count(*[_type == "course" && category._ref == ^._id])`).
  - `sanity.types.ts` (663 lines) is generated by Studio's `typegen` script (`sanity schemas extract && sanity typegen generate`), keying result types off the query variable name (hence globally-unique query names).
- **Learner-relevant:** The "single fetch wrapper" pattern with explicit cache tags per content type; `server-only` as an enforced boundary; deriving aggregates (`moduleCount`, `durationSeconds`) in GROQ with `count()`/`math::sum` instead of storing them; reverse references for the "child doesn't know its parent" model; GROQ query-name uniqueness as the TypeGen contract.

### Studio schema — `studio/schemaTypes/`

- **Locator:** `[[sources/vertex-learning-platform/vertex-learning-platform/studio/schemaTypes#studio-schema]]`
- **Summary:** The Sanity content model — 5 document types and 6 embedded object types, wired in `schemaTypes/index.ts`. Author-facing docs (course/lesson/instructor/category) are editable in Studio; `video` is read-only (pipeline-built).
- **Key claims:**
  - **course** (`course.ts`): groups `overview` / `marketing` / `curriculum`. Fields: `title`, `slug` (source title, max 96), `summary` (required, ≤200), `coverImage` (image + required `alt`, hotspot), `instructor` (reference), `category` (reference), `level` (enum beginner/intermediate/advanced, radio), `price` (USD, 0 = free, `min(0)`), `popular` (boolean → catalog badge), `studentCount` (display only), `learningOutcomes` (array of `learningOutcome`, ≤6), `modules` (array of `module`, required, ≥1). Preview subtitle `level · instructor`.
  - **module** (`objects/module.ts`): an embedded object — "no life outside the course that contains it"; numbering is derived from array order, never stored. Fields `title` (required), `summary` (≤240), `lessons` (array of references to lesson, required ≥1 unique).
  - **lesson** (`lesson.ts`): groups `content` / `video` / `extras`. Fields: `title`, `slug`, `videoUrl` (custom validation against `SUPPORTED_VIDEO_HOSTS` — youtube.com, www.youtube.com, youtu.be, vimeo.com, player.vimeo.com, iframe.mediadelivery.net, video.bunnycdn.com — with an https-only URI rule), `thumbnail` (image + alt), `duration` (seconds, required positive integer), `freePreview` (badge, not access control), `studentCount`, `notes` (`blockContent`), `keyPoints` (string array ≤6), `proTip` (≤280), `resources` (array of `resource`). A lesson does **not** store its parent course.
  - **instructor** (`instructor.ts`): `name`, `slug`, `photo` (+alt), `expertise` (string tags, required 1–8, `unique()`), `bio` (`blockContent`, required).
  - **category** (`category.ts`): `title`, `slug`, `description` (required ≤200).
  - **video** (`video.ts`): read-only, "built by scripts/ingest; not authored here". Fields `videoId` (provider-side id; Bunny is `<libraryId>/<videoId>`), `url` (matches lesson `videoUrl`), `provider` (enum youtube/vimeo/bunny), `chapters` (array of `videoChapter`, may be empty), `chunks` (array of `videoChunk`, required ≥1), `ingestedAt` (datetime). Preview shows "N chapters · M chunks".
  - **blockContent** (`objects/blockContent.ts`): shared rich text (notes + bios) — block styles normal/h2/h3/h4/blockquote, bullet/numbered lists, decorators strong/em/code, link annotation (https), and image members with alt+caption.
  - **learningOutcome** (`objects/learningOutcome.ts`): `icon` constrained to an enum of lucide names the web app actually ships (`sparkles`, `layers`, `code`, `rocket`, `shield`, `gauge`, `puzzle`, `workflow`) — an author can't pick an icon the frontend can't render; `title` ≤60; `description` ≤160.
  - **resource** (`objects/resource.ts`): `type` enum (pdf/link/repo/code/slides), `title` required, `description` ≤160, `url` https.
  - **videoChapter** / **videoChunk**: each has `startSeconds` (required integer ≥0) + `label`/`text`; both use `timecode()` (from `objects/timecode.ts`) for preview formatting.
  - **structure.ts**: Studio nav — Courses, Lessons, divider, Instructors, Categories, divider, then "Video intelligence" (read-only internal lookup).
  - **sanity.config.ts**: `name: 'vertex'`, plugins `structureTool({structure})` + `visionTool`.
- **Learner-relevant:** The schema enforces its own domain rules (allowed video hosts, lucide icon whitelist, order-derived numbering) so the frontend and search can trust the data; embedded objects (`module`, `resource`, `learningOutcome`, `videoChapter`/`videoChunk`) vs. reference-linked documents; `readOnly` on machine-built documents to prevent desync.

### Video ingestion pipeline — `studio/scripts/ingest/`

- **Locator:** `[[sources/vertex-learning-platform/vertex-learning-platform/studio/scripts/ingest#ingestion]]`
- **Summary:** Offline tooling (never runs in the request path) that builds the `video` documents: one per unique video URL, holding chapter markers (table of contents) and the transcript split into short timestamped chunks. Run: `npm run ingest:videos` → `ingest:build` → `ingest:import` (all auth via the Sanity CLI, no token needed).
- **Key claims:**
  - `ingest-videos.mjs` (runner): queries the dataset for every lesson's `videoUrl` (`*[_type == "lesson" && defined(videoUrl) && !(_id in path("drafts.**"))].videoUrl`) so hand-authored lessons are covered too; dedupes by document id (two lessons sharing a video → one document); flags `--limit=N` (smoke run; malformed limit bails) and `--force`. `PROVIDERS = { youtube, vimeo: null, bunny: null }` — a provider is supported only when both ingestion **and** playback exist; Vimeo/Bunny URLs are reported as skipped. Throttles 1200ms between fetches. **Nothing partial is cached**: a video whose captions don't come back is a failure, retried next run, never written as an empty document. Persists to `.cache/<documentId>.json` as it goes (an interrupted run loses nothing). `ingestedAt` is stamped per video at fetch time.
  - `providers/youtube.mjs`: **undocumented, brittle YouTube internals** — the caption `baseUrl` from the watch page answers 200 with an empty body; the working path is the InnerTube player endpoint (`youtubei/v1/player`) with the **iOS client context** (`clientName: 'IOS'`, version `20.10.4`), using the long-public InnerTube web key. Caption tracks are scored (English > other; human-authored `kind !== 'asr'` beats auto-generated); body parsed as `fmt=json3` JSON (or falls back to XML). Chapters are collected by walking `ytInitialData` for both renderers (`chapterRenderer` and `macroMarkersListItemRenderer`), deduped by start time, clamped to duration, optional (empty array is fine). If YouTube changes, this one file is the only fix.
  - `chunk.mjs`: merges caption cues into chunks at `MAX_CHUNK_SECONDS = 45` or `MAX_CHUNK_CHARS = 350`, whichever comes first, **never splitting mid-cue** — so every chunk's `startSeconds` is a real seekable moment. Cleans HTML tags and double-encodes entities (YouTube double-encodes some). Folds back chunks that share a start second.
  - `parse-video-url.mjs`: mirrors the parsing half of `lib/video.ts` (the two workspaces are separate packages, so the `.mjs` script can't import the TS module — keep host rules in step). `videoDocumentId` produces deterministic ids `video.<provider>-<id>` with anything outside `[A-Za-z0-9_-]` replaced by `-` (Sanity ids accept only `[A-Za-z0-9._-]` — the slash in a Bunny id is the case that matters).
  - `build-ndjson.mjs`: expands the cache into `videos.ndjson`, **re-implementing the schema's validation rules** (Studio validation doesn't run on import): id regex, videoId, https url, provider enum, non-empty chunks, ascending strictly-increasing startSeconds for both chapters and chunks, unique `_id`s, valid `ingestedAt`. Refuses to write on any problem. Array `_key`s are deterministic (`chapter-<startSeconds>`, `chunk-<index>`), so `--replace` import is idempotent with no diff noise.
- **Learner-relevant:** The "internal lookup document" idea — searchable machine-built data kept read-only and out of the request path; deterministic ids + deterministic `_key`s making imports idempotent; chunking rules (time OR char cap, never mid-cue) that guarantee every timestamp is real; self-checking NDJSON builders as a substitute for Studio validation on import.

### Seed content — `studio/scripts/seed/`

- **Locator:** `[[sources/vertex-learning-platform/vertex-learning-platform/studio/scripts/seed#seed]]`
- **Summary:** Hand-authored sample content for the `production` dataset, expanded into NDJSON and imported idempotently. Scale: 6 categories, 5 instructors, 10 courses, 4 modules/course, 3 lessons/module = **120 lessons**, each with its own real YouTube video. Run: `seed:videos` → `seed:build` → `seed:import`.
- **Key claims:**
  - `content.mjs` is the source of truth — edited by hand so the curriculum is coherent top to bottom ("a module's lessons genuinely cover that module's topic… Search quality depends on that"). Categories: web-development, ai-engineering, backend-infrastructure, data, languages, security. Instructors (fictional, with randomuser.me portraits): mira-kovac (React/Next.js), daniel-okafor (TypeScript/PostgreSQL), priya-raman (LLMs/RAG), tomas-berg (Python/data/system design), alina-costa (Docker/K8s/security) — each teaches exactly two courses.
  - 10 courses (slug → title): `nextjs-app-router-in-depth` (Next.js App Router in Depth), `react-performance-engineering`, `typescript-for-application-developers`, `building-ai-apps-with-llms`, `retrieval-augmented-generation-from-scratch`, `python-for-data-work`, `system-design-foundations`, `postgresql-for-developers`, `devops-with-docker-and-kubernetes`, `practical-web-security`. Each lesson carries a `search` phrase (what the resolver puts into YouTube), `summary`, `points` (key points), optional `resource`; every lesson also gets the course `docs` link as a resource.
  - `resolve-videos.mjs`: no YouTube Data API key — reads the public search results page, extracts candidates from the `ytInitialData` blob, filters to 3–90 min non-Short videos, ensures **one unique video per lesson** (no two lessons share), and **verifies each pick against the public oEmbed endpoint** before committing. Results cached in committed `videos.json` (120 entries) so re-runs are offline.
  - `build-ndjson.mjs`: deterministic ids (`category.<slug>`, `instructor.<slug>`, `course.<slug>`, `lesson.<course-slug>-<lesson-slug>`) so `--replace` is idempotent; lesson slugs are **prefixed with the course slug** because `LESSON_BY_SLUG_QUERY` matches on the slug alone; lesson `duration` = the real resolved video length so `math::sum` aggregates are exact; `freePreview: position === 0` (one free preview per course). Images upload as **real assets** at import via `_sanityAsset` (`image@<url>`): covers from picsum.photos, thumbnails from the video's own `i.ytimg.com/vi/<id>/hqdefault.jpg` poster, portraits from randomuser.me — nothing hotlinks at runtime. `keyOf()` builds stable `_key`s (slugified; over-long keys append an 8-char sha1 digest instead of bare truncation, which collided on long slugs). Student counts decay through the curriculum and never exceed the course count. Re-implements validation and refuses to write on failure; checks for orphaned lessons.
- **Learner-relevant:** Hand-authoring coherent content as a quality lever for search (garbage-in-garbage-out); deterministic-id + `--replace` import discipline; deriving (rather than storing) durations and counts; stable `_key`s to keep imports diff-clean; `_sanityAsset` to upload real assets at import; verification against oEmbed before trusting scraped ids.

- **Summary:** Three reusable skills (also mirrored under `.claude/skills` and `.agents/skills`) that encode how to build and tune a Sanity-Context-backed agent. `create-agent-with-sanity-context` covers wiring; `dial-your-context` covers the Context document's Instructions/filter; `shape-your-agent` covers the system prompt.

### Context config — `studio/scripts/context/`

- **Locator:** `[[sources/vertex-learning-platform/vertex-learning-platform/studio/scripts/context#context-config]]`
- **Summary:** The search agent's runtime configuration as a `sanity.agentContext` document, imported rather than authored in the Studio UI. This is the "dial-your-context" output: the `groqFilter` (what the agent can see) and `instructions` (how it should query and rank).
- **Key claims:**
  - `vertex-search.ndjson`: one document, `_id: "agentContext.vertex-search"`, `_type: "sanity.agentContext"`, `slug: vertex-search`.
  - `groqFilter`: `_type in ["course", "lesson", "instructor", "category", "video"] && !(_id in path("drafts.**"))` — content types only, drafts excluded.
  - `instructions` (pure deltas): lessons don't store their parent course (derive via `*[_type == "course" && references(^._id)][0]`); module/lesson numbers are positional; `modules` is an inline object array with `lessons[]` references; `notes` is Portable Text → `pt::text(notes)`; `duration` is seconds; `freePreview` is a badge, never filters; **`match` against an array of patterns is AND, not OR** → use the count idiom (`count($terms[^.title match @ || pt::text(^.notes) match @ || ^.keyPoints[] match @]) > 0`); `text::query("a OR b")` returns nothing on this dataset; `video` docs are an internal lookup (never results on their own — tie back via `videoUrl == url`); resolve moments chapters-first, chunks-fallback; never project a whole chunks/chapters array (≤3 matches per video, e.g. `"hits": chapters[label match $terms][0...3]{startSeconds, label}`); **always run both the lesson lookup and the video lookup**; rank by specificity.
  - Why imported not authored: the `@sanity/context` Studio plugin peers on `sanity@^6` and this Studio is on `sanity@^5` — per AGENTS.md §12 the plugin isn't installed; the MCP reads the document from the dataset either way. `npm run context:import` re-imports; edits reach the agent on the next request, but the inline system prompt and cached initial context need a server restart.
  - MCP URL ends with the slug: `https://api.sanity.io/v2026-03-03/context/mcp/<projectId>/<dataset>/vertex-search`. The MCP only serves a dataset with a deployed Studio app.
- **Learner-relevant:** The exact mechanism by which an AI search agent is scoped and instructed without a code change — content filter + instructions as data, the model behavior reinforced by the inline system prompt because the model follows it more reliably; the constraint dance between the Studio plugin's Sanity major and the Studio's own.
