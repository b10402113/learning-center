把 Agent Loop 跑到底：從 Goal 到四種終止狀態

Step 4/4 · 入門實作：Tool Dispatcher 與 Loop Map

先確認目標與前置條件

這一節會把前面準備好的 tool call、執行限制、dispatcher 與 evaluation 接成一個完整的 expense-claim agent loop。完成後，你會得到一個 agent_loop.py：它能審核費用報銷，留下可查核的 trace，並且只會停在四種明確結果中的一種：

  • APPROVED：符合自動核准規則。
  • ESCALATED：需要轉人工處理。
  • FAILED：必要資料取得失敗，安全停止。
  • LIMIT_REACHED：用完執行回合上限。

這裡的重點不是讓 agent「想出一個答案」，而是讓它沿著可檢查的流程前進：先取得資料，再檢查資格，最後只有在證據齊全時才能結束。

開始前需要 Python 3.10 以上、終端機、編輯器，以及 Python 函式、字典與類別的基本概念。這個 lab 不需要雲端服務、外部套件或 API key，所有資料都在本機，方便你重複驗證。

先建立資料夾與程式檔：

mkdir lab01_agent_loop
cd lab01_agent_loop
touch agent_loop.py

Step 1：準備場景與輸入資料

財務團隊希望在報銷送到真人複核前，先由 agent 做第一輪判斷。自動核准必須同時滿足五個條件：申請存在、費用類別被允許、有收據、金額不超過上限，而且最後的決定附有支持證據。

只要條件不符合，就轉人工；如果連必要資料都拿不到，就安全失敗。這個差別很重要：資料不存在時，agent 不能自行補出一筆申請。

把兩筆模擬資料放進程式。一筆是符合條件的小額設備費，另一筆金額超限且缺少收據：

import json
import sys
from dataclasses import dataclass, field
from typing import Any

CLAIMS = {
    "CLM-1042": {
        "employee": "Maya",
        "amount": 850.00,
        "category": "equipment",
        "receipt_present": True,
    },
    "CLM-2048": {
        "employee": "Noah",
        "amount": 1650.00,
        "category": "equipment",
        "receipt_present": False,
    },
}

EXPENSE_POLICY = {
    "version": "2026.1",
    "allowed_categories": ["travel", "equipment", "training"],
    "automatic_approval_limit": 1000.00,
    "receipt_required": True,
}

Step 2：建立能記住進度的 state

Agent 每一回合都要回答三個問題：目前知道什麼、還缺什麼、這次做了什麼。若沒有集中管理這些資訊，它可能重複呼叫工具、忘記已取得的證據，或在條件未完成時提早宣布結束。

ToolResult 統一工具的成功與失敗格式；AgentState 則保存目標、輸入、進度、證據、目前狀態與完整 trace。max_turns 是防止 loop 無限執行的防線。

@dataclass
class ToolResult:
    ok: bool
    data: dict[str, Any] = field(default_factory=dict)
    error: str | None = None

@dataclass
class AgentState:
    goal: str
    claim_id: str
    max_turns: int = 5
    turn: int = 0
    status: str = "RUNNING"
    claim: dict[str, Any] | None = None
    policy: dict[str, Any] | None = None
    eligibility: dict[str, Any] | None = None
    evidence: list[str] = field(default_factory=list)
    trace: list[dict[str, Any]] = field(default_factory=list)

Step 3：定義一次只做一件事的工具

每個工具都只負責一個動作，並以 ToolResult 回報結果。特別是 fetch_claim：查不到申請時，它回傳失敗結果，而不是把例外丟到 loop 外面。這樣「資料查不到」就會成為 evaluator 可以處理的 observation。

def fetch_claim(claim_id: str) -> ToolResult:
    claim = CLAIMS.get(claim_id)

    if claim is None:
        return ToolResult(
            ok=False,
            error=f"Claim {claim_id} was not found.",
        )

    return ToolResult(ok=True, data=claim)

def fetch_policy() -> ToolResult:
    return ToolResult(ok=True, data=EXPENSE_POLICY)

接著讓 check_eligibility 逐項檢查政策。它不只回傳是否符合，也累積不符合的原因，並把判斷使用的原始事實放進 evidence。

def check_eligibility(
    claim: dict[str, Any],
    policy: dict[str, Any],
) -> ToolResult:
    reasons = []

    if claim["category"] not in policy["allowed_categories"]:
        reasons.append("The expense category is not allowed.")

    if policy["receipt_required"] and not claim["receipt_present"]:
        reasons.append("The required receipt is missing.")

    if claim["amount"] > policy["automatic_approval_limit"]:
        reasons.append(
            "The amount exceeds the automatic-approval limit."
        )

    return ToolResult(
        ok=True,
        data={
            "eligible": len(reasons) == 0,
            "reasons": reasons,
            "evidence": [
                f"category={claim['category']}",
                f"receipt_present={claim['receipt_present']}",
                f"amount={claim['amount']}",
                f"policy_version={policy['version']}",
                (
                    "approval_limit="
                    f"{policy['automatic_approval_limit']}"
                ),
            ],
        },
    )

為什麼證據要跟著結果一起保存？因為 APPROVED 或 ESCALATED 只是標籤，不足以說明判斷是否合理。evidence 讓人可以回頭核對：這次決定到底根據哪些資料。

Step 4：用 select_action() 決定下一步

下一步不是憑空決定，而是檢查 state 還缺哪一塊資料。若沒有申請，先取申請；若沒有政策，先讀政策；若還沒算資格，先檢查資格；全部完成後才進入 finish。

def select_action(state: AgentState) -> str:
    if state.claim is None:
        return "fetch_claim"

    if state.policy is None:
        return "fetch_policy"

    if state.eligibility is None:
        return "check_eligibility"

    return "finish"

這段函式的價值，在於把 action selection 變成清楚可讀的規則。下一步不藏在模型的黑盒判斷裡，而是可以直接檢查 state 後推導出來。

Step 5：用 execute_action() 管住可執行的動作

select_action() 只回答「應該做什麼」；「哪個函式可以被執行」則由 execute_action() 管。這一層就像一道 dispatcher 關卡：它把 action 名稱對應到工具，檢查必要參數，遇到未知 action 時也回傳失敗結果，不讓程式直接失控。

def execute_action(
    action: str,
    state: AgentState,
) -> ToolResult:
    if action == "fetch_claim":
        return fetch_claim(state.claim_id)

    if action == "fetch_policy":
        return fetch_policy()

    if action == "check_eligibility":
        if state.claim is None or state.policy is None:
            return ToolResult(
                ok=False,
                error="Claim and policy data are required.",
            )

        return check_eligibility(
            state.claim,
            state.policy,
        )

    if action == "finish":
        return ToolResult(
            ok=True,
            data={"ready_to_finish": True},
        )

    return ToolResult(
        ok=False,
        error=f"Unknown action: {action}",
    )

Step 6：用 evaluate_observation() 判斷能否繼續

工具只回報「發生了什麼」，evaluator 才把 observation 放回整體 goal 中解讀。它會把成功結果寫進 state，也會在收尾時檢查兩件事：資格結果是否存在，以及證據是否存在。

若工具失敗，立即進入 FAILED。若資格符合且證據齊全，進入 APPROVED；若資格不符合，進入 ESCALATED。如果有人要求完成，卻沒有證據，仍然必須 FAILED，不能只因為流程走到最後就宣布成功。

def evaluate_observation(
    action: str,
    observation: ToolResult,
    state: AgentState,
) -> str:
    if not observation.ok:
        state.status = "FAILED"
        return f"Stop safely: {observation.error}"

    if action == "fetch_claim":
        state.claim = observation.data
        return "Claim loaded; policy is still required."

    if action == "fetch_policy":
        state.policy = observation.data
        return "Policy loaded; eligibility must be checked."

    if action == "check_eligibility":
        state.eligibility = observation.data
        state.evidence.extend(observation.data["evidence"])
        return "Eligibility checked; evidence is ready."

    if action == "finish":
        if state.eligibility is None or not state.evidence:
            state.status = "FAILED"
            return (
                "Stop safely: completion was requested "
                "without evidence."
            )

        if state.eligibility["eligible"]:
            state.status = "APPROVED"
            return (
                "Goal complete: the claim meets "
                "the approval rules."
            )

        state.status = "ESCALATED"
        reasons = "; ".join(state.eligibility["reasons"])

        return (
            "Goal complete: human review is required. "
            f"{reasons}"
        )

    state.status = "FAILED"

    return (
        "Stop safely: the observation "
        "could not be evaluated."
    )

Step 7：接起主迴圈與終止規則

現在把選擇、執行與評估接成 loop。每一回合固定做四件事：

  1. 由 select_action() 選出 action。
  2. 由 execute_action() 執行工具。
  3. 由 evaluate_observation() 更新 state 並判斷是否停止。
  4. 把本回合的 action、observation、evaluation 與 status 寫進 trace。

loop 只有在狀態仍是 RUNNING 且回合數尚未達到 max_turns 時才會繼續。若回合用完仍沒有終止，改成 LIMIT_REACHED，並把停止原因也寫入 trace。

def run_agent(claim_id: str) -> AgentState:
    state = AgentState(
        goal=(
            "Review the expense claim and approve it, "
            "escalate it, or fail safely."
        ),
        claim_id=claim_id,
    )

    while (
        state.status == "RUNNING"
        and state.turn < state.max_turns
    ):
        state.turn += 1

        action = select_action(state)
        observation = execute_action(action, state)
        evaluation = evaluate_observation(
            action,
            observation,
            state,
        )

        state.trace.append(
            {
                "turn": state.turn,
                "action": action,
                "observation": {
                    "ok": observation.ok,
                    "data": observation.data,
                    "error": observation.error,
                },
                "evaluation": evaluation,
                "status": state.status,
            }
        )

    if state.status == "RUNNING":
        state.status = "LIMIT_REACHED"

        state.trace.append(
            {
                "turn": state.turn,
                "action": "stop",
                "observation": {
                    "ok": False,
                    "error": "Turn limit reached.",
                },
                "evaluation": "Execution budget exhausted.",
                "status": state.status,
            }
        )

    return state

Step 8：輸出可查核的結果

最後把 state 輸出成 JSON。除了最終狀態與使用回合數，結果還包含證據和完整 trace。這樣你看到的不只是「核准」或「轉人工」，還能追蹤 agent 如何走到那個結論。

def print_result(state: AgentState) -> None:
    result = {
        "goal": state.goal,
        "claim_id": state.claim_id,
        "final_status": state.status,
        "turns_used": state.turn,
        "evidence": state.evidence,
        "trace": state.trace,
    }

    print(json.dumps(result, indent=2))

if __name__ == "__main__":
    claim_id = (
        sys.argv[1]
        if len(sys.argv) > 1
        else "CLM-1042"
    )

    final_state = run_agent(claim_id)
    print_result(final_state)

Step 9：驗證四條路徑

不要只確認程式「有輸出」。請確認它是因為正確的理由停下來。依序執行下面四條路徑：

  1. 核准路徑：執行 python3 agent_loop.py。

    預期結果是 "final_status": "APPROVED"、"turns_used": 4。四回合的 action 順序應為 fetch_claim、fetch_policy、check_eligibility、finish。

  2. 轉人工路徑：執行 python3 agent_loop.py CLM-2048。

    預期結果是 "final_status": "ESCALATED"。trace 中應能看到收據缺失與金額超過自動核准上限。這仍然算成功，因為 agent 完成了自己的 goal：把有風險的申請交給人，並附上原因與證據。

  3. 安全失敗路徑：執行 python3 agent_loop.py CLM-9999。

    這筆申請不存在，因此預期結果是 "final_status": "FAILED"，trace 只應有失敗的 fetch_claim。agent 不應繼續讀政策、編造申請資料，或在工具失敗後繼續往前跑。

  4. 回合上限路徑：暫時把 max_turns 改成 2，再執行預設申請。

    預期結果是 "final_status": "LIMIT_REACHED"。兩回合足以取得申請與政策，卻還來不及檢查資格與收尾。測試後，記得把 max_turns 改回 5。

完成檢查：每個抽象概念都要落到程式

這個 lab 的成果，不只是讓一筆報銷跑完，而是把 agent loop 的每個抽象元素對到具體程式：

  • goal 是 AgentState 裡的目標文字。
  • state 是 AgentState。
  • action selection 是 select_action()。
  • tool execution 是 execute_action() 與各個工具函式。
  • observation 是 ToolResult。
  • evaluation 是 evaluate_observation()。
  • 完成條件是通過資格檢查，並且保有證據。
  • 終止狀態是 APPROVED、ESCALATED、FAILED、LIMIT_REACHED。
  • 執行上限是 max_turns。
  • 可審計的執行軌跡是 state.trace。

當四條路徑都得到預期結果，你就驗證了這個 loop 會在明確、可查核的終點停止，而不是只產生一段看起來像答案的回覆。
