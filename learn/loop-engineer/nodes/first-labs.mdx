# 入門實作：Tool Dispatcher 與 Loop Map

## Learning goal

動手把 tool call 接進 loop，並端到端追蹤一個 agent loop 的 goal→completion 路徑。

## Steps

1. [[learn/loop-engineer/nodes/first-labs/tool-call-as-action|Tool Call 是 Loop 的 Action]] — 用「模型出請求、harness 才執行」建立 tool call 的可控邊界，並認得安全工具的四個部分
2. [[learn/loop-engineer/nodes/first-labs/judge-tool-safety|判斷一次 Tool Call 能不能跑、能不能重試]] — 用 read-only／side-effecting、schema 邊界與 idempotency 決定執行、拒絕或安全重試（after step 1）
3. [[learn/loop-engineer/nodes/first-labs/build-tool-dispatcher|實作 Python Tool Dispatcher]] — 寫出 dispatch_tool()，把請求驗證、路由與執行收斂成固定的 observation（after steps 1–2）
4. [[learn/loop-engineer/nodes/first-labs/map-agent-loop|端到端追蹤一個 Agent Loop]] — 組出 expense-claim agent loop，用 trace 說明它為何停在四種終止狀態之一（after step 3）

## Lesson

前兩個節點把 loop 的骨架和 goal 契約講清楚了，但那個 loop 還沒有手：它能決定、能評估，卻沒有真正把動作送到外面的世界。這個節點要補上那雙手，並且用兩段可以真的跑起來的 Python 程式，把前面抽象的名詞一一對回可執行的地方。

第一步先把 tool call 的定位釘死：它不是模型偷偷伸出去的一隻手，而是模型交出的一張結構化請求單，真正決定什麼能跑的是外面的 harness。第二步處理更難的判斷：這張請求單該不該放行、失敗了能不能再送一次。第三步動手寫出最小可用的 tool dispatcher，把請求驗證、路由、執行與錯誤包成一個固定形狀的 observation。最後把這些零件組回一個完整的 expense-claim agent loop，沿著 trace 走完 goal → APPROVED、ESCALATED、FAILED、LIMIT_REACHED 四條收尾路徑。

走完之後，你不只會說「tool call 是 action step」，還能在紙上指出：請求在哪裡被擋下、結果從哪裡回來、loop 憑什麼理由停下來。
