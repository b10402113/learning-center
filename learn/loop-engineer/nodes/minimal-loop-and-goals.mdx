# 最小可執行 Loop 與 Goal 契約

## Learning goal

寫出並跑起一個四階段最小控制迴圈，並把模糊需求寫成可驗收的 goal 契約。

## Steps

1. [[learn/loop-engineer/nodes/minimal-loop-and-goals/four-stage-control-cycle|四階段控制迴圈：Goal → Act → Observe → Evaluate]] — 認清每個階段的職責與契約，並接受「停下來」也是設計的一部分
2. [[learn/loop-engineer/nodes/minimal-loop-and-goals/goal-as-executable-contract|把模糊需求寫成 Goal 契約與完成條件]] — 把一句含糊需求翻成 outcome / scope / inputs / constraints / success evidence（after step 1）
3. [[learn/loop-engineer/nodes/minimal-loop-and-goals/build-a-minimal-executable-loop|設計最小可執行 Loop：可除錯的骨架]] — 寫出可跑的 control loop，並把 state / tools / policy / evaluator 拆成獨立介面（after steps 1–2）
4. [[learn/loop-engineer/nodes/minimal-loop-and-goals/boundaries-before-autonomy|先設界線再放自主]] — 在加能力之前先放 max steps、timeout、dry-run 與 approval gate（after step 3）

## Lesson

這個節點把「最小可跑的 agent」拆成兩件不可跳過的事：先有一個四階段控制迴圈，再有一個可驗收的 goal 契約。很多人反過來做——先寫 prompt、先接工具、先想架構——結果迴圈跑得起來，卻沒人說得清它什麼時候算做完。這四步要建立的是相反的順序：Goal 定義成功、Act 選一個能力去動、Observe 拿回真實證據、Evaluate 拿證據對照 goal 決定繼續或停；而在這條迴圈外面，goal 契約先寫好「done 長什麼樣」，界線先設好「最多跑幾步、多久、哪些動作要人點頭」。四步讀完，你手上會有一個能指著每一步說出契約、也敢讓它上場的最小迴圈。
