# Loop Engineering 基礎與四層堆疊

## Learning goal

說出 loop 的核心循環，並分清 model / harness / tools / execution environment 四層的邊界與何時該用 agent。

## Steps

1. [[learn/loop-engineer/nodes/loop-foundations/what-is-loop-engineering|什麼是 Loop Engineering？]] — 用「受控執行器」的觀點說出 loop engineering 在設計什麼，以及圍繞模型的六個控制層
2. [[learn/loop-engineer/nodes/loop-foundations/four-layer-stack|Model、Harness、Tools 與 Execution Environment]] — 分清四層的職責與契約，理解可靠性來自邊界（after step 1）
3. [[learn/loop-engineer/nodes/loop-foundations/single-call-vs-loop|單次 LLM 呼叫 vs. Agentic Loop]] — 用「最小可靠機制」決定何時該用 loop、何時單次呼叫就好（after steps 1–2）
4. [[learn/loop-engineer/nodes/loop-foundations/when-to-use-an-agent|什麼時候該用 Agent、什麼時候不該]] — 用判別問句決定問題適不適合 agent，並描述先窄後廣的導入順序（after step 3）

## Lesson

Agent 這兩個字很容易被想成一顆更聰明的模型，但真正讓系統「像 agent」的，從來不是模型本身，而是它外面那一圈又一圈的控制設計。這個節點要先把視角從「模型多強」換成「這個 loop 怎麼被設計」：第一步先建立一個核心圖像——agent 是一個受控執行器，loop engineering 就是設計它重複執行的 plan → act → observe → improve 循環；第二步把這個執行器拆成 model、harness、tools、execution environment 四層，逐層問「它被允許做什麼、必須回傳什麼、失敗了怎麼辦」；第三步用「最小可靠機制」的原則，判斷什麼時候單次 LLM 呼叫就夠、什麼時候才值得啟動一個 loop；最後把鏡頭拉遠，用一個判別問句決定一個問題到底適不適合交給 agent，並安排企業內先窄後廣的安全導入順序。

走完這四步，你手上會有一組可以反覆套用的判準：看到任何 agent 產品或架構，都能指出它的 loop 在哪裡、四層邊界畫在何處，也能在動手前先問一句「這裡真的需要 agent 嗎」。
