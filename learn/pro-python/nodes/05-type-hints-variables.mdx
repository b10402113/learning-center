# Type hints for variables and generics

## Learning goal

Annotate variables, use list/dict/tuple generics, union operator

2. [[learn/pro-python/nodes/05-type-hints-variables/generic-collections|Generic collection types]] — Use `list[int]`, `dict[str, int]`, `tuple[str, ...]` (after step 1)
3. [[learn/pro-python/nodes/05-type-hints-variables/union-operator|Union operator and Optional]] — Express "either/or" with `|` and `Optional` (after step 1)
4. [[learn/pro-python/nodes/05-type-hints-variables/annotated-example|Putting it together]] — Build a fully annotated data model (after steps 2–3)

## Lesson

Function signatures are only half the picture. Once you can annotate parameters and return types, the next move is to bring that same clarity to the variables inside your functions and the data structures you build.

Variable annotations use the same colon syntax as function parameters: `name: type = value`. They tell readers and tools what shape a variable is expected to hold, even though Python still won't enforce it at runtime. The real payoff comes with generic collections — `list[int]`, `dict[str, int]`, `tuple[str, ...]` — which let you describe not just "this is a list" but "this is a list of integers." When a value might be one of several types, the union operator (`int | None`) or `Optional[int]` expresses that directly.

Together these tools turn vague containers into self-documenting data models. The steps in this node build from single-variable annotations up to a fully annotated example that ties generics and unions together.
