<LearningGoal>
理解為什麼本地開發該用 Docker 跑 Postgres，而不是直接裝在主機上。
</LearningGoal>

## Lesson

到目前為止，我們的 FastAPI 應用每次重啟伺服器，資料就全部消失。這就像《今天暫時停止》——每天醒來都回到原點。問題出在我們沒有真正的資料庫，資料只存在記憶體裡。要治好這個失憶症，我們需要一個能永久保存資料的 PostgreSQL 資料庫。

PostgreSQL 是生產環境網頁應用的業界標準，跟 Python 的搭配特別好。它免費、穩定、功能完整，幾乎所有你聽過的科技公司都在用。

既然 PostgreSQL 這麼好，為什麼不直接裝在主機上？在 macOS 上直接安裝 PostgreSQL 是一件很麻煩的事——版本衝突、設定複雜、除錯費時。如果你同時做兩個專案，一個需要 Postgres 15、另一個需要 Postgres 17，主機安裝根本無法應付。

Docker 解決了這個問題。用 Docker 跑 PostgreSQL 有四個好處：版本鎖定（每個專案可以用自己的 Postgres 版本，互不干擾）、隔離環境（資料存在 named volume 裡，不會污染主機系統）、一鍵清理（<code>docker compose down -v</code> 就能砍掉重練）、可重現（換一台電腦，<code>docker compose up</code> 就跑出一模一樣的環境）。

同樣的模式可以用在 Redis、Kafka、或其他任何你不想裝在主機上的服務。Docker 讓本地開發環境變得乾淨又好管理。
