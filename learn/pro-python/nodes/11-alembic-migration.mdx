# Alembic — initial migration

## Learning goal

Set up Alembic, generate and apply the first migration

## Steps

1. [[learn/pro-python/nodes/11-alembic-migration/alembic-setup|安裝與設定 Alembic]] — 把 Alembic 裝進專案，並理解 `env.py`、`script.py.mako` 與 `alembic.ini` 各自負責什麼
2. [[learn/pro-python/nodes/11-alembic-migration/migration-concepts|遷移修訂的運作方式]] — 理解 `upgrade()` 與 `downgrade()` 如何讓資料庫前進與回溯（after step 1）
3. [[learn/pro-python/nodes/11-alembic-migration/generate-and-apply|產生並套用第一次遷移]] — 用 `--autogenerate` 偵測模型變更並執行 `upgrade head`（after steps 1–2）
4. [[learn/pro-python/nodes/11-alembic-migration/wire-models|把 SQLModel 接上 API]] — 把 Pydantic 模型換成 SQLModel，讓 API 真的從 Postgres 回傳資料（after step 3）

## Lesson

這節課把資料庫從「每次重啟就失憶」的模擬資料，升級成由 Alembic 管理、真正寫入 Postgres 的持久狀態。Alembic 是 SQLAlchemy 生態系的遷移工具，它不會幫你寫模型，而是幫你追蹤模型變更，並把這些變更翻譯成資料庫看得懂的 SQL。

第一步是安裝與設定。`alembic init` 會建立一個 `alembic.ini` 和一個 `env.py`，但這兩個檔案預設不知道你的資料庫在哪、模型在哪。你得手動告訴 `env.py` 去匯入 SQLModel 的 metadata，並指向你的資料庫 URL。`script.py.mako` 則是遷移檔的樣板，設定好之後，每次產生的遷移檔都會自動 `import SQLModel`，不用你每次手寫。

第二步理解遷移檔的結構。每個遷移檔都是一個 Python 檔案，裡面有 `upgrade()` 和 `downgrade()` 兩個函式。`upgrade()` 描述如何從上一個版本走到這個版本，`downgrade()` 描述如何走回去。這讓你在生產環境出錯時，可以安全地回溯到上一個版本，而不是只能砍掉重練。

第三步是產生並套用第一次遷移。`alembic revision --autogenerate` 會比對 SQLModel 定義與資料庫現狀，自動產生遷移檔。`alembic upgrade head` 則把所有還沒套用的遷移檔按順序跑完。跑完之後，你應該能在 Postgres 裡看到對應的表格。

最後一步是把 API 接上。原本路由檔裡可能有一個手寫的 Pydantic `ProjectRead` 模型，用來模擬回傳格式。現在改成從 `models.py` 匯入 SQLModel 定義，API 就會真的去 Postgres 查詢並回傳資料。這一步做完，你的 API 才真正從 prototype 變成 production-ready。
