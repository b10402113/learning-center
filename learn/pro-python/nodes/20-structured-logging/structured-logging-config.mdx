<LearningGoal>
Replace `logging.basicConfig` with a programmatic `configure_logging` function that emits structured log lines with timestamps, level, module name, and message.
</LearningGoal>

## Lesson

`logging.basicConfig(level=logging.INFO)` 是最快的起步方式，但它的格式固定、等級寫死在程式碼裡，不適合正式環境。正式環境通常需要時間戳、模組名、以及透過環境變數調整等級的能力。解決方法是寫一個 `configure_logging` 函式，用程式化方式設定 logging。

`configure_logging` 接受一個 `debug: bool` 參數。如果 `debug` 為 `True`，log 等級設為 `DEBUG`，否則設為 `INFO`。同時指定一個結構化格式字串 `"%(asctime)s %(levelname)s %(name)s %(message)s"`，讓每行 log 都包含時間戳、等級、模組名和訊息。

格式字串的佔位符各有用途：`%(asctime)s` 是 log 發生的時間戳，`%(levelname)s` 是 log 等級（INFO、DEBUG…），`%(name)s` 是 logger 名稱（通常用模組名），`%(message)s` 是實際的 log 訊息。有這些欄位，log 聚合系統（例如 Data Dog、ELK）就能自動解析、搜尋、過濾。

設定完成後，log 輸出會像這樣：

```
2026-09-04 10:30:15,234 INFO __main__ GET /projects/1 → 200 (12.34 ms)
2026-09-04 10:30:15,567 DEBUG app.db SELECT * FROM projects WHERE id = 1
```

一個細節：Python logging 使用 `%s` 延遲格式化（lazy formatting）。如果 log 等級被過濾掉，字串不會被格式化，節省計算。用 f-string 則無論如何都會先算好字串，浪費效能。所以 `logger.info("User %s logged in", username)` 比 `logger.info(f"User {username} logged in")` 更好。
