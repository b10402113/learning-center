<LearningGoal>
Understand what FastAPI middleware is, how `app.middleware` registers it, and why execution order matters when multiple middlewares wrap each other.
</LearningGoal>

## Lesson

Middleware（中介層）是一段在每個請求進來之前、每個回應出去之前都會執行的程式碼。它像一個檢查站，讓你在端點（endpoint）被呼叫之前先處理請求，也在端點回傳之後再處理回應。FastAPI 用 `@app.middleware("http")` 裝飾器把一個 async 函式註冊成 middleware，之後每個 HTTP 請求都會通過它。

最簡的 middleware 骨架只需要兩個參數：`request` 和 `call_next`。`call_next(request)` 是middleware 的核心——呼叫它會把請求往下傳給路由端點（或下一個 middleware），等端點跑完再回傳 `response` 物件。這讓你在 `call_next` 之前做 pre-route 工作（記錄開始時間、驗證 token、修改請求標頭），在 `call_next` 之後做 post-route 工作（記錄回應時間、加上自訂標頭、修改回應內容）。

一個 FastAPI app 可以註冊多個 middleware，它們會像俄羅斯娃娃一樣層層包覆。重點是：註冊順序和執行順序相反。最後一個註冊的 middleware 最先接觸請求，最先接觸回應；第一個註冊的最後接觸請求，最後接觸回應。這代表請求進來時，外層 middleware 先跑，然後才進到路由端點；回應出去時，路由端點先回傳，再依序經過內層、外層 middleware。

理解執行順序是正確設計 middleware 的關鍵。如果你有一個「驗證使用者身分」的 middleware 和一個「記錄請求時間」的 middleware，你會希望記錄時間那層在外層，這樣即使驗證失敗，時間還是會被記錄下來。搞錯順序會讓某些請求跳過驗證，或記錄不到完整資訊。
