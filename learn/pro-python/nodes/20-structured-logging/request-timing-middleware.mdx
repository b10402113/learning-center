<LearningGoal>
Build a FastAPI middleware that measures how long each request takes and emits a structured log line with the method, path, status code, and duration.
</LearningGoal>

## Lesson

請求計時 middleware 結合了兩個技巧：middleware 的 pre-route / post-route 分界，以及 Python 標準函式庫的 `logging` 模組。目標是建立一個 FastAPI middleware，記錄每個請求的方法、路徑、狀態碼和花費時間（毫秒），讓你掌握 API 的效能，並在出問題時快速定位。

完整程式碼只有幾行。首先用 `time.perf_counter()` 記錄開始時間，然後 `await call_next(request)` 把請求傳給路由端點。端點跑完後，用 `time.perf_counter() - start_time` 算出耗時，乘以 1000 轉換成毫秒。最後用 `logger.info()` 搭配 `%s` 格式化字串，把方法、路徑、狀態碼、耗時寫進 log。

用 `time.perf_counter()` 而不是 `time.time()` 很重要。`time.time()` 會受系統時鐘調整影響（例如 NTP 同步），可能導致測量不準確。`time.perf_counter()` 是單調遞增（monotonic）的計時器，專門用來測量時間間隔，不會往回跳。

log 輸出的樣子像這樣：

```
INFO __main__: GET /projects/1 → 200 (12.34 ms)
INFO __main__: POST /projects → 201 (45.67 ms)
```

這讓你在開發時就能看到每個端點的回應時間，正式環境也可以餵進 log 聚合系統（例如 Data Dog）做監控。

middleware 和 exception handler 雖然都適用於所有路由，但角色不同。middleware 在每個請求前後執行，能拿到 `response` 物件，適合記錄時間、修改標頭、驗證。exception handler 只在拋出例外時觸發，只能拿到 `request`，適合捕捉特定錯誤（例如 `IntegrityError`）並轉回 409 Conflict。兩者互補，不要混用。
