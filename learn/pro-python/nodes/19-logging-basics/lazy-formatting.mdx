## Learning goal
能解釋為什麼 f-string 在 logging 裡會浪费效能，以及如何用 %s 延遲插值。
## Lesson

很多人直覺用 f-string 寫 log：`logger.debug(f"payload: {payload}")`。問題是 f-string 會先算出完整字串，才傳給 logger。如果 logger 等級是 INFO，這條 debug 訊息根本不會輸出，但 f-string 已經跑完了。當 log 訊息包含昂貴運算（例如 `repr(payload)` 或 JSON 序列化），這些運算就白白浪費了。

logging 提供另一種寫法：`logger.debug("payload: %s", payload)`。這裡 `payload` 不會馬上被轉成字串，logging 內部會先檢查等級——如果這條訊息最後不會被輸出，`payload` 就不會被插值。這在 production 特別重要，因為大量 DEBUG 訊息被過濾掉，f-string 的昂貴運算就白白浪費了。

使用 `%s` 還有另一個好處：像 structlog 或 Data Dog 這類工具，會把 `payload` 當成「獨立欄位」索引，而不是混在字串裡。現代 linter（例如 Ruff）也會強制檢查 f-string 用在 logging 的情況，自動建議你改用 `%s`。
