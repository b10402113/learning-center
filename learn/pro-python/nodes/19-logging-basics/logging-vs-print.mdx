## Learning goal
能說明為什麼 print 在正式上線環境會出問題，以及 logging 如何解決這些問題。
## Lesson

在正式上線的 Python 服務裡，`print()` 不只是「不好看」——它是一個安全風險。很多團隊的 CI 管線會靜態檢查 `print(` 的出現，因為一旦它進入 production log，就可能被 log 收集系統（Data Dog、Splunk）永久存檔，裡面如果夾帶了客戶的 email、token、或請求 payload，就構成了資料外洩。

print 的根本問題是它沒有開關。每一行 `print()` 都會忠實輸出，不管你現在是在本機開發還是線上 production。你無法在執行時決定「我要看 DEBUG 就好」或「關掉這個模組的日誌」。logging 標準庫就是為了解決這個問題而設計的：你在程式裡寫 log 呼叫，執行時再決定要不要輸出、輸出到哪、用什麼格式。

把 print 換成 logging 之後，你可以在開發環境看到所有 DEBUG 細節，在 production 只記錄 INFO 以上，全部只要改設定檔。這不只是風格問題，而是讓你的服務具備「可觀察性（observability）」的第一步。
