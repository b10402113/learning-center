# APIRouter refactoring

## Learning goal

Split routes into feature-based routers, use include_router

## Steps

1. [[learn/pro-python/nodes/18-apirouter/why-apirouter|為什麼需要 APIRouter？]] — 理解單體 main.py 的痛點與 APIRouter 的定位
2. [[learn/pro-python/nodes/18-apirouter/create-router|建立 routers 套件與移動端點]] — 建立 routers 套件、實作 projects 路由器（after step 1）
3. [[learn/pro-python/nodes/18-apirouter/register-and-verify|註冊路由器並驗證重構]] — 用 include_router 接回 main.py 並跑測試確認行為不變（after step 2）

## Lesson

當 FastAPI 專案只有一個 `main.py` 時，所有端點、依賴注入、例外處理全部塞在同一個檔案裡。這在端點不到十個時還能應付，但隨著功能增長，檔案會變得難以瀏覽、難以重構、難以多人協作。

`APIRouter` 是 FastAPI 提供的大型應用組織工具。它讓開發者把路由按照功能拆分到不同模組，每個路由器有自己的前綴（prefix）和標籤（tags），最後再透過 `app.include_router()` 把它們掛回主應用程式。拆分之後，`main.py` 變成一個輕量的組合入口——一眼就能看到整個 API 的結構，但不用逐行閱讀端點實作。

這個節點的三個步驟會帶你走過完整的重構流程：先理解為什麼需要 APIRouter，再建立 `routers/` 套件並把專案端點搬過去，最後在 `main.py` 註冊路由器並用測試確認一切行為不變。
