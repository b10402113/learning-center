## Learning goal

Use the `name: type = value` syntax to annotate variables, and understand what hints actually do at runtime.

## Lesson

Function signatures are only half the picture. Once you can annotate parameters and return types, the next move is to bring that same clarity to the variables inside your functions.

Variable annotations use the same colon syntax as function parameters. The pattern is `name: type = value` — the colon goes between the variable name and the type, and the assignment works exactly as before.

```python
count: int = 0
name: str = "Untitled"
rates: list[float] = []
```

The hint tells readers and tools like mypy what shape the variable is expected to hold. But here is the critical thing: Python does not enforce this at runtime. You can reassign a typed variable to a completely different type and Python will not complain.

```python
count: int = 0
count = "urgent"   # No error — Python ignores the hint at runtime
```

The hint is a promise to readers and static analyzers, not a runtime constraint. If you want enforcement, you need an external tool like mypy or Pydantic.

So when should you annotate? The rule is simple: annotate when the type is not obvious from the right-hand side. Empty collections are the classic case — `items: list[str] = []` tells the reader what belongs in that list. Complex containers like `cache: dict[str, int] = {}` benefit the same way. Values that start as `None` and get filled in later also deserve a hint so the reader knows what type they will eventually hold.

Simple cases like `name = "Alice"` rarely need an annotation. The type is already clear from the literal. Adding `: str` there would just repeat information the reader already has.
