## Learning goal

將變數註解、泛型與 union 結合成一個自述型的資料模型。

## Lesson

現在把各部分組合起來。想像一個任務追蹤 API。一個任務有標題、一個可能還沒設定的優先級，以及一組標籤。以下是註解一個建構函式的方式：

```python
def make_task(title: str, tags: list[str], priority: int | None = None) -> dict[str, object]:
    task: dict[str, object] = {
        "title": title,
        "priority": priority,
        "tags": tags,
    }
    return task
```

每個變數和參數現在都帶有它預期的形狀。讀者一眼就能看出 `priority` 允許為 `None`，而 `tags` 是字串的 list。

當一個值分步驟建構時，註解累加器讓意圖保持清晰：

```python
def slugify(name: str) -> str:
    cleaned: str = name.strip().lower()
    parts: list[str] = cleaned.split()
    slug: str = "-".join(parts)
    return slug
```

這些註解沒有一個會改變執行時的行為。它們的存在是為了讓下一個讀這個函式的人理解每個步驟產出什麼。

不是什麼都該註解。如果右側已經讓型別很明顯，註解反而會變成雜訊：

```python
# 好 —— 型別很明顯
name: str = "alice"

# 雜訊 —— 註解重複了已經很清楚的資訊
name: str = get_name()   # get_name 已經回傳 str
```

在能增添資訊時才註解：空集合、union 型別，以及複雜的巢狀結構。當字面值或建構子已經說明一切時，就跳過註解。
