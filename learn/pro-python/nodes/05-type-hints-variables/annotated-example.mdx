## Learning goal

Combine variable annotations, generics, and unions into a self-documenting data model.

## Lesson

Now put the pieces together. Imagine a task-tracking API. A task has a title, a priority that might not be set yet, and a list of tags. Here is how you would annotate a function that builds one:

```python
def make_task(title: str, tags: list[str], priority: int | None = None) -> dict[str, object]:
    task: dict[str, object] = {
        "title": title,
        "priority": priority,
        "tags": tags,
    }
    return task
```

Every variable and parameter now carries its expected shape. A reader can see at a glance that `priority` is allowed to be `None` and that `tags` is a list of strings.

When a value is built in steps, annotate the accumulator so the intent stays clear:

```python
def slugify(name: str) -> str:
    cleaned: str = name.strip().lower()
    parts: list[str] = cleaned.split()
    slug: str = "-".join(parts)
    return slug
```

None of these annotations change runtime behavior. They exist so the next person reading this function understands what each step produces.

Do not annotate everything. If the right-hand side already makes the type obvious, an annotation adds noise:

```python
# Good — type is obvious
name: str = "alice"

# Noise — the annotation repeats what's already clear
name: str = get_name()   # get_name already returns str
```

Annotate when it adds information: empty collections, union types, and complex nested structures. Skip it when the literal or constructor already tells the whole story.
