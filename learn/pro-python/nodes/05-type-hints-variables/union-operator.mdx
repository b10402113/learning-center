## Learning goal

使用 `|` union 運算子和 `Optional` 來表達「這個值可以是多種型別之一」。

## Lesson

有時候一個變數合法地承載超過一種型別。函式可能在成功時回傳結果，失敗時回傳 `None`。設定值可能是 int 也可能是 str。Union 型別就是在描述這種情境。

Python 3.10 引入了 `|` 運算子來表示 union。把管線符號讀作「或」：

```python
def find(user_id: int) -> User | None:
    if user_id in cache:
        return cache[user_id]
    return None
```

`User | None` 代表「不是 User 就是 None」。你可以串接超過兩個：`int | float | str`。

在 `|` 出現之前，同樣的概念是用 `typing` 模組裡的 `Optional[X]` 來寫。`Optional[X]` 和 `X | None` 完全相等。它在很多老程式碼裡仍然經常出現，所以你必須看得懂：

```python
from typing import Optional

def find(user_id: int) -> Optional[User]:
    ...
```

兩種形式意義完全相同。在新的程式碼裡，偏好 `X | None` —— 它更短，也不需要 import。

如果你用過 TypeScript，這組對應會很直覺：`User | None` 就是 TypeScript 的 `User | null`，`int | float | str` 就是 `number | string`。Python 用 `None`、TypeScript 用 `null`，但概念一模一樣。

當你有 union 型別的值，在使用型別專屬的操作之前要先收窄它。型別檢查器會利用這個收窄來判斷你位於哪個分支：

```python
result: int | None = compute()

if result is not None:
    print(result + 1)   # mypy 知道這裡 result 是 int
```

`is not None` 的檢查讓工具知道你正在處理哪個型別。沒有它的話，mypy 會抱怨 `result` 可能是 `None`。

Narrowing 的邏輯跟 TypeScript 幾乎一樣。兩者的型別檢查器都會要求你在使用只有特定型別才支援的操作之前，先證明「現在是哪個型別」。
