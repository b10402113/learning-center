# CRUD refactoring

## Learning goal

Extract database operations into a crud.py module, separate concerns

## Steps

1. [[learn/pro-python/nodes/14-crud-refactor/extract-crud|把資料庫操作抽到 crud.py]] — 把 main.py 裡的資料庫操作抽到獨立的 crud.py 模組，理解為什麼 HTTP 路由和資料庫交易應該分開
2. [[learn/pro-python/nodes/14-crud-refactor/verify-with-tests|用既有測試驗證重構]] — 執行既有測試來確認重構沒有破壞任何 API 行為（after step 1）
3. [[learn/pro-python/nodes/14-crud-refactor/simplify-routes|用 Annotated 依賴簡化路由]] — 用 ProjectDep 和 Annotated 型別別名消除每個路由重複的查詢與 404 樣板碼（after step 1）
4. [[learn/pro-python/nodes/14-crud-refactor/global-exception-handling|全域例外處理：把 IntegrityError 變成 409]] — 用 FastAPI 的 exception_handler 全域捕捉 IntegrityError，把 500 錯誤換成有意義的 409 Conflict（after step 3）

## Lesson

這節課把之前塞在 main.py 裡的資料庫操作抽出來，讓路由只關心 HTTP，資料庫邏輯只待在 crud.py。重構完之後，你會用既有測試當安全網確認一切沒壞；接著用 Annotated 依賴把每個路由重複的「查不到就 409」樣板碼抽出來；最後用全域例外處理把資料庫的 IntegrityError 換成有意義的 409 Conflict。
