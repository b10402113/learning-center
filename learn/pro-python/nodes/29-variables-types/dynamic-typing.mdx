<LearningGoal>
能解釋 Python 動態型別的行為：型別跟著值走、變數可重新指派成不同型別、type hint 在執行時不強制檢查。
</LearningGoal>

## Lesson

從 Java 開發者的角度，<code>priority = 13</code> 少了型別宣告。Python 是<strong>動態型別（dynamically typed）</strong>語言：變數的型別從它目前綁住的值推論出來。原則是——<strong>值有型別，名字沒有</strong>：<code>13</code> 是 <code>int</code>、<code>"urgent"</code> 是 <code>str</code>，而 <code>priority</code> 只是一個標籤，貼在誰身上，推論出的型別就是誰（<code>type(priority)</code> 可隨時檢查）。

動態型別最大的 gotcha（陷阱）：變數可以重新指派成不同的型別，完全合法——

```python
priority = 13          # priority 現在是 int
priority = "urgent"    # 完全合法的 Python！
```

在生產程式碼裡，這是整類型別 bug 的溫床：函式前半段把變數當數字、後半段有人把它換成字串，下游的運算就在執行到那一刻才以 <code>TypeError</code> 爆炸。

Python 的回答是 type hint（型別提示）：<code>priority: int = 13</code>。但 hint <strong>只是提示，不在執行時強制檢查</strong>——就算宣告了 <code>int</code>，重新指派成字串照樣通過。要讓 hint 生效，必須靠 mypy 這類靜態型別檢查工具，在程式跑起來之前把錯誤指派抓出來。動態型別曾是 Python 最常見的 bug 來源之一，現代 Python 幾乎全面採用 type hint + 靜態檢查，就是因為它解決了整類的微妙 bug。讀沒有 hint 的舊程式碼時，看到變數被重新指派要特別警戒。
