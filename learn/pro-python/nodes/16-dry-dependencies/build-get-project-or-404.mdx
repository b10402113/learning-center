# 實作 get_project_or_404 依賴函式

## Learning goal

能寫出 `get_project_or_404` 依賴函式，讓查詢與 404 判斷集中在一處。

## Lesson

上一課我們看到了三個路由各自重複的 404 判斷。現在來把那段邏輯搬到一個獨立的函式裡。

```python
# dependencies.py
from fastapi import Depends, HTTPException
from sqlmodel import Session

def get_project_or_404(project_id: int, session: SessionDep) -> Project:
    project = crud.get_project(session, project_id)
    if project is None:
        raise HTTPException(status_code=404, detail="Project not found")
    return project
```

這個函式做了三件事：

1. 接收 `project_id` 和 `session` 兩個參數。
2. 用 `crud.get_project()` 查詢資料庫。
3. 找不到就丟 `HTTPException(404)`，找到了就回傳 `Project`。

FastAPI 在呼叫這個函式時，會從路由的參數裡自動解出 `project_id`（路徑參數），並從依賴注入系統解出 `session`（你在 node 15 定義的 `SessionDep`）。這種「依賴依賴另一個依賴」的連鎖，就是 FastAPI 依賴注入最有力的地方。

把這段邏輯集中到一個函式之後，你要修改錯誤訊息、更換查詢條件、甚至加上權限檢查，都只需要改一個地方。每個路由再也不需要自己處理 404，它們只管接收一個確定存在的 `Project` 物件。

下一課會教你如何把這個函式包裝成一個 `Annotated` 型別別名，讓路由簽章變得更乾淨。
