# 找出重複的 lookup-or-404 模式

## Learning goal

能辨認 FastAPI 路由裡重複出現的「查不到就 404」樣板，並說出為什麼它需要被抽出來。

## Lesson

假設你在維護一個專案管理 API，有三個路由都需要載入 Project：

```python
@app.get("/projects/{project_id}")
async def get_project(project_id: int, session: SessionDep):
    project = crud.get_project(session, project_id)
    if project is None:
        raise HTTPException(status_code=404, detail="Project not found")
    return project

@app.put("/projects/{project_id}")
async def update_project(project_id: int, data: ProjectUpdate, session: SessionDep):
    project = crud.get_project(session, project_id)
    if project is None:
        raise HTTPException(status_code=404, detail="Project not found")
    # 更新邏輯...

@app.delete("/projects/{project_id}")
async def delete_project(project_id: int, session: SessionDep):
    project = crud.get_project(session, project_id)
    if project is None:
        raise HTTPException(status_code=404, detail="Project not found")
    # 刪除邏輯...
```

一眼看上去，每個路由的前兩行幾乎一樣：`crud.get_project()` 查詢，結果是 `None` 就丟 `HTTPException(404)`。這段邏輯本身不描述任何商業規則，它只是在做「確保這個 Project 存在」。

這種重複帶來三個問題：

- **容易遺漏**：忘記加 404 判斷，路由會在 `None` 上呼叫屬性，回傳 500。
- **修改成本高**：如果錯誤訊息要改（例如改成中文），得同步改四、五個地方。
- **路由噪音**：真正的業務邏輯被埋在重複的樣板裡，可讀性下降。

當你在一個專案裡看到同一段邏輯出現三次以上，就該考慮把它抽出來。在 FastAPI 的世界裡，「抽出來」的意思就是寫成一個**依賴（dependency）**。接下來的步驟會教你如何把這段樣板變成一個可複用的依賴函式。
