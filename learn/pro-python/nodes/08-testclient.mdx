# Testing API endpoints with TestClient

## Learning goal

Use FastAPI's TestClient to test routes, assert status codes and responses

## Steps

1. [[learn/pro-python/nodes/08-testclient/testclient-setup|設定 pytest 與 TestClient，寫出第一個 GET 測試]] — 設定 pytest 開發依賴、建立 TestClient 實例，並寫出一個發送 GET 請求、驗證狀態碼的測試函式
2. [[learn/pro-python/nodes/08-testclient/assert-response-body|驗證 response.json() 的內容與結構]] — 從 response.json() 取出資料，並用 assert 驗證回應內容是否符合預期（after step 1）
3. [[learn/pro-python/nodes/08-testclient/test-error-responses|測試錯誤回應：404 與 HTTPException]] — 為「找不到資源」的端點撰寫測試，驗證端點正確回傳 404 狀態碼與 detail 訊息（after step 1）
4. [[learn/pro-python/nodes/08-testclient/evolve-tests|端點改了，測試跟著改：從 name 過濾到 slug 過濾]] — 理解端點行為改變時，測試必須同步更新，並動手修改查詢參數與斷言（after step 2）

## Lesson

這一節要解決一個很具體的問題：寫好 FastAPI 端點之後，怎麼確認它真的在運作？

傳統做法是啟動伺服器、用瀏覽器或 curl 手動打請求。這樣做能跑，但慢、不重複、也沒辦法放進 CI。FastAPI 內建了 `TestClient`，本質上是一個記憶體級的 HTTP 客戶端——它直接呼叫 ASGI 應用程式，不經過網路層，所以測試跑得快、結果確定、又能自動化。

這一節的四個步驟會帶你走完整個流程：從零開始設定 pytest 和 TestClient、寫出第一個只驗證狀態碼的測試、進一步驗證回應內容、處理 404 錯誤回應，最後在端點行為改變時跟著更新測試。走完之後，你會擁有一個能自動驗證端點行為的測試骨架，後續加新功能時只要照這個模式擴充就行。
