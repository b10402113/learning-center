<LearningGoal>
能解釋 HTTP 409 Conflict 與 400 Bad Request、404 Not Found 的差異，並說明爲什麼資料衝突該用 409 回應。
</LearningGoal>

## Lesson

HTTP 狀態碼不只是數字——它們告訴呼叫端發生了什麼事，以及接下來該怎麼處理。選錯狀態碼，呼叫端就無法做出正確的反應。

以下是三個容易混淆的狀態碼：

| 狀態碼 | 名稱 | 語意 | 典型情境 |
| --- | --- | --- | --- |
| 400 | Bad Request | 請求格式有問題，伺服器看不懂 | JSON 缺少必要欄位、型別錯誤 |
| 404 | Not Found | 資源不存在 | 查詢一個不存在的專案 ID |
| 409 | Conflict | 請求與目前資源狀態衝突 | 建立重複名稱的專案 |

為什麼不是 400 Bad Request？400 代表「你發過來的請求有問題，請修正之後再試」。但建立重複名稱的請求，格式是完全正確的——欄位都有、型別也對。問題不在請求本身，而在於它跟資料庫現有資料衝突。所以 400 不對。

為什麼不是 404 Not Found？404 代表「你找的資源不存在」。但建立重複名稱的請求，目標是新增一筆資料，不是查詢。資源不存在在這裡不是重點——重點是已經有一筆相同的資料了。所以 404 也不對。

409 Conflict 的正確語意是：你的請求跟伺服器目前的狀態衝突了，請解決衝突之後再試。對重複名稱的專案來說，這就是精確的描述：資料庫裡已經有一個同名專案，新的寫入會違反唯一約束。

呼叫端看到 409，就知道應該提示使用者「這個名稱已經存在，請換一個」，而不是表單驗證錯誤或 404 頁面。
