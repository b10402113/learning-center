## Lesson

寫一個測試，用重複的專案名稱送出 POST 請求，並斷言回應狀態碼為 409 Conflict 且包含有意義的 detail 訊息。

測試的價值在於確認處理器真的在重複名稱時回傳 409，而不是 500。測試會幫我們捕捉回歸——萬一有人改壞了處理器，測試會先失敗。

測試步驟如下：先建立一個專案（第一次 POST 應該成功）；用同一個名稱再送一次 POST；斷言回應狀態碼是 409；斷言回應 body 包含 detail 訊息。

除了狀態碼，我們也檢查 `detail` 欄位是否存在。這確保處理器確實回傳了 JSON 回應，而不是空 body 或 HTML 錯誤頁面。

如果未來有人移除了處理器，或者把狀態碼改成了 400 或 500，這個測試就會失敗。它守護的是「API 對資料衝突的回應方式」這個契約。
