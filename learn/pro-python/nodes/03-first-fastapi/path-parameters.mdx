# 路徑參數與自動型別驗證

## Learning goal

在路由裡用 `{param}` 語法定義路徑參數，並觀察 FastAPI 如何自動驗證型別。

## Lesson

RESTful API 的核心設計原則之一是「資源放在 URL 裡」。在 FastAPI 裡，這透過**路徑參數（path parameter）** 實現——用花括號 `{}` 在路由字串中宣告一個參數佔位符：

```python
@app.get("/projects/{project_id}")
def get_project(project_id: int):
    project = PROJECTS.get(project_id)
    if project is None:
        return {"error": "Project not found"}, 404
    return project
```

這段程式碼做了兩件事：路由字串裡的 `{project_id}` 宣告「URL 這個位置會帶一個值」；函式參數 `project_id: int` 用型別提示告訴 FastAPI「這個值必須是整數」。FastAPI 自動把 URL 裡的值拿出來，轉成 `int`，然後傳進函式。

FastAPI 最強大的地方在於**自動型別驗證**。訪問 `/projects/1`，`project_id` 拿到整數 `1`，正常回傳資料。訪問 `/projects/hello`，FastAPI 嘗試把 `"hello"` 轉成整數——失敗了，直接回傳 422 Unprocessable Entity，回應主體是一個 JSON 陣列，清楚指出 `path.project_id` 不是有效的整數。

你沒有寫任何驗證邏輯。在 Flask 裡，你需要手動 `int(project_id)` 加上 `try/except ValueError`。在 FastAPI 裡，型別提示就是驗證規則——寫一次，到处生效。

注意程式碼用的是 `PROJECTS.get(project_id)`，而不是 `PROJECTS[project_id]`。兩者的差別：

| 寫法 | 找不到時 |
| --- | --- |
| `PROJECTS[project_id]` | 拋出 `KeyError`，伺服器回 500 內部錯誤 |
| `PROJECTS.get(project_id)` | 回傳 `None`，你可以優雅地處理 |

用 `.get()` 讓你檢查回傳值是不是 `None`，然後回傳一個有意義的 404 回應，而不是讓伺服器崩潰。這是一個簡單的防禦性寫法，但很重要——生產環境中，500 錯誤通常是 bug，404 則是預期行為。

路由字串裡的參數名稱必須跟函式參數名稱**完全一致**。FastAPI 用名稱來匹配，不是位置：

```python
# ✅ 正確：名稱一致
@app.get("/projects/{project_id}")
def get_project(project_id: int): ...

# ❌ 錯誤：名稱不一致，FastAPI 報錯
@app.get("/projects/{project_id}")
def get_project(pid: int): ...
```

FastAPI 用名稱匹配，名字不同，它不知道哪個對應哪個。

把前面的程式碼組合起來，現在你有兩個路由：`GET /projects` 列出所有專案，`GET /projects/{project_id}` 根據 ID 取得單一專案。打開 `/docs`，Swagger UI 自動更新了——新的路由帶了一個 `project_id` 參數欄位，你可以輸入數字直接測試。
