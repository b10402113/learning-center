# 什麼是 FastAPI？為什麼選它？

## Learning goal

能說出 FastAPI 的核心定位，並解釋它跟 Flask、Django 的差異。

## Lesson

Python 世界裡有三個主要的 Web 框架，落在一個光譜上。**Django** 是全功能框架（batteries-included）——內建 ORM（物件關聯對映）、模板引擎、後台管理，什麼都幫你做好。**Flask** 是微框架（micro-framework）——核心只做路由和請求處理，其他功能靠擴充套件手動組裝。

**FastAPI** 也是微框架，但跟 Flask 不同：它內建了驗證、非同步（async）支援、自動文件生成。打個比方——Django 像一間裝潢好的套房，搬進去就能住；Flask 像一塊空地，你自己蓋；FastAPI 像一塊附了水電的土地，結構自己蓋，但最重要的基礎設施已經到位。

FastAPI 建立在兩個開源專案之上：

| 支柱 | 底層專案 | 帶來什麼 |
| --- | --- | --- |
| 非同步路由 | Starlette | 高效能 HTTP 處理，支援 `async def` |
| 資料驗證 | Pydantic | 用型別提示定義和驗證資料結構 |

第三個支柱是 **Python 型別提示（type hints）** 本身。FastAPI 用你寫的型別提示來做三件事：編輯器自動補全、請求參數自動驗證、OpenAPI 文件自動生成。你不需要寫額外的 DSL 或設定檔——你寫的 Python 就是規格。

這帶來一個實際的好處：**免費的 API 文件**。FastAPI 自動根據路由和型別提示生成 OpenAPI 規格，提供兩個互動式頁面：Swagger UI（`/docs`，可以直接在瀏覽器測試 API）和 ReDoc（`/redoc`，排版更適合閱讀）。不需要寫任何文件程式碼，路由寫好，文件就有了。

在框架選擇上：如果你的專案是 API-first（先設計 API，前端另外接），FastAPI 是目前 Python 世界裡開發體驗最好的選擇。2023 年它超越了 Flask，成為 Python 第二大 Web 框架。在需要高效能、型別安全、快速開發的場景——特別是微服務和 API 服務——FastAPI 已經是首選。
