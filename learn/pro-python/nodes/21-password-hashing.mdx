# Password hashing

## Learning goal

Hash passwords with Argon2id before storing, verify on login

## Lesson

使用者認證是任何正式 API 的第一步，而密碼雜湊正是這道門的基礎。這門課從「為什麼明文密碼是災難」出發，帶你理解雜湊的單向本質與加鹽如何讓相同密碼產生不同結果，最後用 Python 現代函式庫 `pwdlib` 搭配 Argon2id 演算法，在註冊與登入端點完成完整的雜湊與驗證流程。

第一步談風險：資料庫外洩、SQL 注入、備份外流、雲端設定錯誤，任何一種都可能讓明文密碼一次曝光。由於使用者常在多站重複使用密碼，一次外洩可以引爆連鎖危機。這不是理論問題，而是每個儲存密碼的系統都必須面對的底線。

第二步進到機制。雜湊是把任意長度輸入轉換成固定長度字串的單向函數，理論上無法從雜湊值回推原始密碼。但單純雜湊還不夠——如果兩個使用者密碼一樣，雜湊值也會一樣，攻擊者可以用預先算好的彩虹表快速比對。為每個密碼加一段隨機「鹽值（salt）」就能解決這個問題：即使密碼相同，加鹽後的雜湊結果也會不同。現代演算法如 Argon2id 刻意設計成緩慢且耗記憶體，讓暴力破解變得不划算。

第三步進入實作。Python 社群推薦使用 `pwdlib` 搭配 Argon2id——一個現代、持續維護的密碼雜湊庫。安裝只需要一行 `uv add "pwdlib[argon2]"`，之後用 `pwdlib.Argon2Hasher` 的 `hash()` 方法就能把密碼轉成帶有鹽值的完整雜湊字串，用 `verify()` 方法就能比對輸入密碼是否正確。

第四步把前面三步串成完整流程。註冊端點收到密碼後先雜湊再存入資料庫，登入端點拿到使用者輸入的密碼後，從資料庫拿出預先存好的雜湊值呼叫 `verify()`，比對成功就放行。整段流程中，伺服器始終不需要知道使用者的原始密碼——這是雜湊最重要的安全特性：即使整顆資料庫被偷，攻擊者拿到也是一堆無法回推的雜湊值。
