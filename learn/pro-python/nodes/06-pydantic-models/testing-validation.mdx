<LearningGoal>
能使用 `pytest.raises` 撰寫測試，確認 Pydantic 模型在收到不合法資料時確實拋出 `ValidationError`。
</LearningGoal>

## Lesson

寫測試不只是確認「對的資料能通過」，也要確認「錯的資料會被擋下來」。如果你的 API 依賴 Pydantic 來驗證請求，那測試就應該涵蓋驗證失敗的錯誤路徑（error path）。

如果只測試成功情境，你可能會遺漏一些邊界情況：例如使用者傳入空字串、負數、或者完全省略必填欄位。這些情境如果沒被測試覆蓋，未來很可能在生產環境中出錯。

pytest 提供了 `pytest.raises` 上下文管理器（context manager），用來確認某段程式碼確實會丟出指定的例外。對於 Pydantic 驗證，我們可以這樣寫：

```python
import pytest
from pydantic import ValidationError
from myapp.models import Computer

def test_computer_requires_brand():
    with pytest.raises(ValidationError):
        Computer(ram_gigabytes=16, hard_drive_gigabytes=512)
```

這段測試預期 `Computer` 在缺少 `brand` 欄位時會拋出 `ValidationError`。如果測試通過，代表驗證邏輯如預期運作。

除了缺少欄位，你也可以測試型別錯誤的情況：

```python
def test_computer_requires_int_ram():
    with pytest.raises(ValidationError):
        Computer(brand="Apple", ram_gigabytes="sixteen", hard_drive_gigabytes=512)
```

這裡 `ram_gigabytes` 傳入的是字串 `"sixteen"`，而非整數。Pydantic 應該要拋出 `ValidationError`，測試就能驗證這個行為。

在專案終端機中執行測試：

```bash
uv run pytest
```

如果測試通過，你會看到綠色的輸出；如果失敗，pytest 會顯示詳細的錯誤訊息，幫助你定位問題。

測試的最佳實踐包括：每個驗證規則都應該有對應的測試；測試名稱應該清楚描述情境，例如 `test_computer_requires_brand`；不要只測試「對的資料」，也要測試「錯的資料」；使用 `pytest.raises` 時，可以進一步檢查例外訊息的細節。
