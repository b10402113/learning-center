<LearningGoal>
理解 Pydantic 如何在物件建立時自動驗證資料，並能捕捉 `ValidationError` 處理不合法的輸入。
</LearningGoal>

## Lesson

Pydantic 的驗證發生在物件建立的那一刻。當你呼叫 `Model(...)` 時，Pydantic 會檢查每個欄位的值是否符合宣告的型別。如果不符合，它會拋出一個 `ValidationError`，並清楚指出哪個欄位出了問題。

這和 Python 內建的型別提示不同。Python 的型別提示只是給開發者和檢查工具看的，執行時不會強制驗證。Pydantic 則是真正在執行時把關。

假設我們有一個 `Computer` 模型：

```python
class Computer(BaseModel):
    brand: str
    ram_gigabytes: int
    hard_drive_gigabytes: int
```

如果我們傳入錯誤的資料，Pydantic 會立刻報錯：

```python
try:
    computer = Computer(brand="Apple", ram_gigabytes="16", hard_drive_gigabytes=512)
except ValidationError as e:
    print(e)
```

這裡 `ram_gigabytes` 傳入的是字串 `"16"`，而非整數 `16`。Pydantic 的錯誤訊息會明確指出 `ram_gigabytes` 欄位發生了 `type_error`。

如果某個欄位沒有預設值，它就是必填的。省略它一樣會觸發 `ValidationError`：

```python
try:
    computer = Computer(ram_gigabytes=16, hard_drive_gigabytes=512)
except ValidationError as e:
    print(e)
```

這裡沒有提供 `brand`，Pydantic 會回報 `field required`。這讓你在 API 開發階段就能捕捉到資料不完整的情況，而不是等到資料庫寫入時才發現。

`ValidationError` 的錯誤訊息通常包含以下資訊：哪個欄位出錯；錯誤的類型（例如 `type_error`、`value_error`、`missing`）；實際收到的值是什麼。

在 FastAPI 中，如果請求資料驗證失敗，Pydantic 會自動把 `ValidationError` 轉換成 422 Unprocessable Entity 回應，並附上詳細的錯誤細節。這讓 API 消費者能清楚知道哪個欄位填錯了。
