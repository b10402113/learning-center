<LearningGoal>
能在 FastAPI 端點使用 `response_model` 參數，確保 API 輸出符合 Pydantic 模型定義的結構。
</LearningGoal>

## Lesson

在 FastAPI 中，端點函式通常會回傳一個字典或資料庫物件。如果直接回傳，FastAPI 會嘗試把它序列化成 JSON。但有時候你回傳的物件可能包含敏感欄位（例如密碼雜湊），或者你希望確保回傳的資料結構完全符合預期。

`response_model` 就是 FastAPI 提供的機制：它會在回應發送前，用指定的 Pydantic 模型過濾和驗證回傳的資料。只有模型裡定義的欄位才會出現在最終的 JSON 回應中。

假設我們有一個 GET 端點，要根據 ID 回傳專案資料。我們可以在路由裝飾器中加上 `response_model` 參數：

```python
@app.get("/projects/{project_id}", response_model=ProjectRead)
def get_project(project_id: int):
    project = projects_db.get(project_id)
    if project is None:
        raise HTTPException(status_code=404, detail="Project not found")
    return project
```

這裡的 `response_model=ProjectRead` 告訴 FastAPI：無論 `get_project` 回傳什麼，都要用 `ProjectRead` 模型來過濾和驗證。

當端點回傳一個物件時，FastAPI 會執行以下步驟：嘗試用 `ProjectRead` 模型來解析回傳的資料；如果資料中缺少 `ProjectRead` 定義的欄位，或者型別不符，FastAPI 會回傳 500 錯誤；如果資料中有 `ProjectRead` 沒有定義的欄位，多餘的欄位會被自動過濾掉；最終只輸出 `ProjectRead` 中宣告的欄位。

這意味著你的 API 回應結構永遠是可控的，不會意外洩漏內部資料。

假設你的資料庫模型有一個 `notes` 欄位，用來儲存內部備註，不應該暴露給 API 消費者。你可以定義一個 `ProjectRead` 模型，只包含 `id`、`name`、`slug`，然後在端點使用 `response_model=ProjectRead`。即使端點回傳的物件包含 `notes`，它也不會出現在 JSON 回應中。
