## Learning goal

理解單體 main.py 的成長痛與 APIRouter 的定位

## Lesson

剛開始寫 FastAPI 時，把所有端點放在 `main.py` 是最快的起步方式。一個檔案搞定路由、依賴注入、例外處理，啟動伺服器就能看到結果。但當端點從 5 個變成 20 個、50 個，這個檔案會開始出現幾個明顯的問題。

**瀏覽困難**是第一個症狀。滾動一條漫長的檔案，很難一眼看出 API 提供了哪些功能。你得在檔案裡反覆搜尋，才能找到某個端點的實作位置。這在兩人以上的團隊裡特別致命——每個人都得花額外時間定位程式碼。

**重構風險**緊跟在後。當所有端點和全域設定都擠在同一個檔案，修改一個端點時，可能意外動到旁邊的端點或全域變數。這種「牽一髮動全身」的感覺，會讓開發者越來越不敢改動現有的程式碼。

**協作衝突**則是團隊開發的噩夢。多人同時開發不同功能，全部擠在同一個檔案容易產生 Git 合併衝突。想像兩個人同時修改 `main.py`——一個加端點、一個修例外處理——合併時就得手動解衝突，浪費時間又容易出錯。

FastAPI 提供 `APIRouter`（API 路由器）來解決這個問題。它本質上是一個「輕量版的 FastAPI 應用程式」——你可以用同樣的裝飾器語法定義路由，但這些路由先掛在路由器上，最後再透過 `app.include_router()` 把它們掛回主應用程式。

把 `main.py` 想成一本書的目錄頁。單體檔案像是把所有章節內容直接寫在目錄頁上；APIRouter 則是把各章節拆成獨立檔案，目錄頁只需要列出章節名稱與頁碼。

路由器有兩個關鍵參數值得認識。`prefix` 設定路由前綴，例如 `APIRouter(prefix="/projects")` 會讓底下所有端點自動掛在 `/projects` 路徑下。`tags` 設定分組標籤，Swagger UI 會把同標籤的端點歸在同一區，方便瀏覽。

重構前後，端點的写法幾乎一模一樣，只是把裝飾器從 `@app.get` 改成 `@router.get`，並且因為 `prefix` 已經幫我們加上路徑，原本寫在端點上的前綴可以省略。URL 路徑完全沒變，但程式碼的責任被拆分了：路由器負責定義端點，主程式負責組合。
