## Learning goal

建立 routers 套件、實作 projects 路由器

## Lesson

建立 `routers/` 資料夾，並加上 `__init__.py` 讓它變成 Python 套件。這一步看起來沒什麼作用，但它是後續所有相對匯入的基礎。沒有 `__init__.py`，Python 不會把資料夾當成套件，相對匯入會直接失敗。

```
routers/
  __init__.py
  projects.py
```

在 `projects.py` 檔案開頭建立 `APIRouter` 實例。這裡的 `prefix="/projects"` 表示底下所有端點都會掛在 `/projects` 路徑下；`tags=["projects"]` 則讓 Swagger UI 把它們歸在同一區。這兩個參數都是可以根據需求調整的，但通常會把 prefix 設定為該功能模組的路徑前綴。

接下來把原本寫在 `main.py` 的專案相關端點全部移到 `routers/projects.py`。移動時只需要把 `@app.get`、`@router.post` 等裝飾器從 `app` 改成 `router`，函式本體完全不用改。注意路徑要扣掉 prefix 的部分——原本寫 `/projects`，因為 prefix 已經涵蓋了，改成 `""` 即可；原本寫 `/projects/{project_id}`，改成 `/{project_id}`。

因為路由器現在位於 `routers/`` 子資料夾，匯入上層模組時要使用相對匯入（relative import）。兩個點 `..` 代表「往上一層目錄」。例如要匯入 `models.py` 或 `dependencies.py`，就得寫 `from ..models import Project`。如果專案結構更深，就繼續加點。

要注意的是，相對匯入必須在套件內部使用。如果直接執行 `routers/projects.py` 會報錯，但透過 `uv run` 或 `app.include_router()` 匯入就沒問題。這是 Python 套件的標準限制，不是 FastAPI 特有的。

搬移完成後，`routers/projects.py` 會包含列表、讀取、更新、刪除等所有專案端點。每個端點的函式本體與依賴注入設定都跟原本在 `main.py` 時一模一樣，差別只在於裝飾器從 `app` 變成 `router`。
