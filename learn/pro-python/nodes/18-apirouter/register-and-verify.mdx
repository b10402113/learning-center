## Learning goal

用 include_router 接回 main.py 並跑測試確認行為不變

## Lesson

端點搬完之後，`main.py` 會變得乾淨許多。原本塞滿端點的位置，現在只剩下幾行 `include_router` 呼叫。這就是所謂的「組合根（composition root）」——一眼就能看出這個 API 有哪些功能模組，但不用逐行閱讀端點實作。

```python
from fastapi import FastAPI
from routers.projects import router as projects_router

app = FastAPI()
app.include_router(projects_router)
```

`app.include_router(router)` 會把路由器裡的所有路由合併到主應用程式。合併時會保留路由的路徑（含 prefix）、HTTP 方法、依賴注入設定、請求/回應模型、標籤與說明文件。也就是說，對外部呼叫者而言，這次重構完全是無感的——URL 沒變、行為沒變、文件位置也沒變。

重構最重要的一步是「確認行為沒變」。FastAPI 的 `TestClient` 搭配 pytest 是驗證的好工具。如果之前的測試有寫好，重構後跑一次 `uv run pytest`，全部綠燈就代表這次重構是安全的。測試就像是搬家時的裝箱清單——搬完之後逐項核對，確認所有東西都還在、都能正常運作。

重構之後，`main.py` 不再負責端點實作，而是專注於：建立 FastAPI 實例、註冊路由器、掛中介軟體、註冊例外處理常式。這種拆分讓每個檔案的職責單一，後續不管是加新功能、修 bug、還是加測試，都能更精準地定位。

FastAPI 官方文件有一篇「Bigger Applications」教學，專門講解多檔案專案結構與 `APIRouter` 的使用方式。這篇教學是免費的，也是目前最推薦的參考資料。當你的專案成長到一個檔案塞不下的時候，可以先翻這篇。
