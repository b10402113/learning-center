# DRY dependencies with ProjectDep

## Learning goal

Extract the lookup-or-404 pattern into a reusable dependency

## Steps

1. [[learn/pro-python/nodes/16-dry-dependencies/spot-the-pattern|找出重複的 lookup-or-404 模式]] — 辨認每個路由裡重複的「查不到就 404」樣板
2. [[learn/pro-python/nodes/16-dry-dependencies/build-get-project-or-404|實作 get_project_or_404 依賴函式]] — 把查詢與 404 邏輯打包成單一函式（after step 1）
3. [[learn/pro-python/nodes/16-dry-dependencies/annotated-type-alias|用 Annotated 建立可複用的型別別名]] — 用 Annotated 把回傳型別和依賴綁在一起（after step 2）
4. [[learn/pro-python/nodes/16-dry-dependencies/simplify-routes|用 ProjectDep 簡化路由處理器]] — 在路由中直接注入已驗證的 Project 物件（after step 3）

## Lesson

在 FastAPI 專案裡，只要多個路由需要透過主鍵載入同一個實體（例如 Project），幾乎都會出現一樣的樣板：用 `session.get()` 查詢，結果是 `None` 就 `raise HTTPException(404)`，否則繼續處理。這段邏輯本身不描述商業規則，卻在四、五個路由裡重複出現。

這一課教你如何把這段「查不到就 404」的樣板抽出來，變成一個可以跨路由複用的依賴。第一步是辨認模式——哪些路由在做一樣的事、為什麼每次手寫都容易出錯。第二步是實作一個 `get_project_or_404` 依賴函式，讓查詢和 404 判斷集中在一處。第三步用 `Annotated[Project, Depends(...)]` 把回傳型別和依賴解析綁成一個型別別名 `ProjectDep`，讓路由簽章自我描述。最後一步把路由處理器簡化到只剩核心邏輯——每個路由拿到的是已經驗證存在的 `Project` 物件，不需要再處理 404。

走完這四步之後，你會理解為什麼「可複用的依賴」是 FastAPI 依賴注入系統最有力的設計工具：消除樣板、集中錯誤處理、讓路由只做路由該做的事。
