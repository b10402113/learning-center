<LearningGoal>
能匯入待測函數，使用 `assert` 寫出一個驗證 `slugify` 輸出結果的測試函數。
</LearningGoal>

## Lesson

假設你有一個 `slugify` 函式，它把專案名稱轉換成 URL 友好的格式：去掉前後空白、轉成小寫、用底線取代空格。你希望確保這個函式在任何情況下都正確運作。

pytest 讓寫測試變得很直覺：匯入函式、呼叫它、用 `assert` 檢查輸出是不是你預期的結果。

待測函式長這樣：

```python
# src/slug.py
def slugify(name: str) -> str:
    return name.strip().lower().replace(" ", "-")
```

這個函式做了三件事：`strip()` 移除前後空白、`lower()` 轉小寫、`replace(" ", "-")` 把空格換成底線。

第一個測試會這樣寫：

```python
# tests/test_slug.py
from src.slug import slugify

def test_slugify_lowercases_and_dashes_spaces():
    assert slugify("Release Tracker") == "release-tracker"
```

這段測試做了四件事：匯入待測函式、定義一個以 `test_` 開頭的測試函數、呼叫 `slugify("Release Tracker")`、用 `assert` 檢查結果是否等於 `"release-tracker"`。

`assert` 是 Python 的內建關鍵字。它後面的表達式如果為 `True`，程式繼續執行；如果為 `False`，則拋出 `AssertionError`，pytest 會捕捉這個錯誤並標記測試為失敗。這比標準庫 `unittest` 的 `self.assertEqual()` 更直覺——你不需要記住各種斷言方法，直接用 `==` 比較就好。

測試函數的名稱應該描述它的行為。常見的命名模式是 `test_情境_預期結果`，例如 `test_slugify_lowercases_and_dashes_spaces`、`test_slugify_removes_leading_trailing_spaces`、`test_slugify_handles_empty_string`。當測試失敗時，清晰的命名能讓你立刻知道哪個情境出了問題。

測試檔案裡用了 `from src.slug import slugify`。這代表你的專案必須是一個可匯入的套件，或者 `src/` 目錄必須在 Python 的搜尋路徑裡。如果你的專案結構不同，匯入路徑也要跟著調整。重點是：測試檔案必須能正確找到並匯入待測函式。
