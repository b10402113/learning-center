# 解讀 pyproject.toml

<LearningGoal>
能讀懂 pyproject.toml 的每個欄位，理解它如何定義專案的中繼資料與依賴。
</LearningGoal>

## Lesson

`uv init` 產生了一堆檔案，其中最重要的就是 `pyproject.toml`。它是整個專案的身份證——每個工具鏈（UV、pip、ruff、mypy、pytest）都讀它。在 PEP 518（2016）之前，Python 專案用 `setup.py`、`setup.cfg`、`requirements.txt` 等多個檔案分散管理設定，造成混亂。`pyproject.toml` 用統一的 TOML 格式取代了這一切。

打開它，你會看到這樣的內容：

```toml
[project]
name = "python-for-pros"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.14,<3.15"
dependencies = []
```

逐欄位拆解：

| 欄位 | 值 | 意義 |
| --- | --- | --- |
| `name` | `"python-for-pros"` | 專案名稱，用於套件安裝和 PyPI 發布 |
| `version` | `"0.1.0"` | 語意化版本號（SemVer），`0.x` 表示開發中 |
| `description` | `"Add your description here"` | 一行簡述，UV 的預設文字，記得改 |
| `readme` | `"README.md"` | 指向專案說明文件 |
| `requires-python` | `">=3.14,<3.15"` | Python 版本範圍，釘死在 3.14.x |
| `dependencies` | `[]` | 依賴列表，用 `uv add` 新增 |

注意 `requires-python` 不是只寫 `>=3.14`，而是加了上限 `<3.15`。Python 的小版本更新（3.14 → 3.15）可能引入不相容的變更。加上上限確保專案只會在 3.14.x 上執行——這是一種防禦性編程，告訴未來的自己和隊友：「這個專案在 3.14.x 上測試過，其他版本不保證。」

`dependencies` 目前是空的。當你需要安裝第三方套件時，不要手動編輯這個列表，而是用 `uv add fastapi`。UV 會自動下載套件到虛擬環境、在 `dependencies` 加入套件名稱和版本範圍、產生 `uv.lock` 鎖定精確版本。這比手動 `pip install` 然後忘記記錄依賴安全多了。

TOML 格式本身很直覺：`[section]` 是分節標頭，`key = "value"` 是鍵值對，`#` 開頭是註解。你不需要記住所有語法，只要認識這兩種結構就夠讀懂 `pyproject.toml`。
