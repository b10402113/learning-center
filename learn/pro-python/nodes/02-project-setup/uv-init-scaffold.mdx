# 用 UV 初始化專案

<LearningGoal>
能用 `uv init` 建立一個新的 Python 專案，並理解每個產生檔案的用途。
</LearningGoal>

## Lesson

每個 Python 專案都從一個空白資料夾開始，但「空白」不等於「什麼都不放」。你需要一個結構——讓套件管理器知道依賴在哪裡、讓 linter 知道規則在哪裡、讓 Git 知道哪些檔案不用追蹤。手動建立這些檔案很繁瑣，而且容易遺漏。

**UV（用 Rust 寫的 Python 專案管理器）** 幫你一秒搞定。打開終端機，輸入：

```bash
uv init my-project --python ">=3.14"
```

這一行做了三件事：建立資料夾、初始化 Git 倉庫、產生專案骨架。執行完畢後，你的資料夾裡會有這些檔案：

```text
my-project/
├── .git/               ← 本地 Git 倉庫（未連接遠端）
├── .gitignore          ← 排除 .venv/ 等不需要追蹤的檔案
├── .python-version     ← 釘選 Python 版本為 3.14
├── main.py             ← 範例程式碼（hello world）
├── pyproject.toml      ← 專案設定檔（核心）
└── README.md           ← 專案說明
```

每個檔案都有明確的用途。**`pyproject.toml`** 是整個專案的身份證——記錄名稱、版本、Python 版本要求、依賴列表。所有工具鏈（UV、pip、linter）都讀它。**`.python-version`** 釘選 Python 版本，確保團隊成員和 CI 環境都用同一個版本。**`main.py`** 是起點，放你的第一行程式碼。**`.gitignore`** 排除虛擬環境等暫存檔案，不讓它們汙染 Git 歷史。

為什麼不直接用系統預裝的 Python？因為系統 Python 通常版本過舊（macOS 和 Linux 預設往往是 3.9 甚至更舊），缺少現代 Python 的新功能——`match` 語句、更好的型別提示、效能改善。UV 會自動幫你下載正確版本，只要在 `uv init` 時指定就好。

注意 `uv init` 自動建立了 `.git/` 資料夾，但只是本地 Git 倉庫，還沒有連接 GitHub。你需要自己執行 `git remote add origin <url>` 來連接遠端。
