# SQL query patterns — where, join, selectinload

## Learning goal

Master the three core operations for efficient relational queries

## Lesson

Task 和 Project 有關聯，查詢時必須處理「跨表」和「關聯載入」這兩個問題。這一節介紹的三個工具——<code>where</code>、<code>join</code>、<code>selectinload</code>——是 SQLModel / SQLAlchemy 裡最重要的 relational query 基礎元件。

<code>where</code> 在查詢裡加入篩選條件，相當於 SQL 的 <code>WHERE</code> 子句。每次呼叫會回傳一個新的 statement 物件（immutable pattern），不會修改原本的查詢。多個 <code>where</code> 會用 <code>AND</code> 串起來。

當你想用「關聯表」的欄位來篩選，就需要 <code>join</code>。例如列出所有屬於某個專案的 tasks，但你想用專案的 <code>slug</code> 來篩選。<code>join(Project)</code> 會自動用外鍵關聯找出對應的 project，篩選條件仍然用 <code>where</code> 加上去。

N+1 問題是 ORM 最常見的效能陷阱：先查一次拿到 N 筆 tasks，然後每筆 task 要存取關聯的 project 時又各自多查一次，總共 1 + N 次查詢。<code>selectinload</code> 在一次查詢裡就把關聯資料全部撈回來，之後存取 <code>task.project</code> 就不會再打資料庫。

三者經常出現在同一條查詢裡：用 <code>join</code> 切到關聯表，用 <code>where</code> 下條件，用 <code>selectinload</code> 讓後續讀取關聯物件不爆量查詢。
