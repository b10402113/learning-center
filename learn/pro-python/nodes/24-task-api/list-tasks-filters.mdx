# List tasks with conditional filters

## Learning goal

Build dynamic queries with keyword-only filter parameters and immutable where-clauses

## Lesson

真實世界的 API 幾乎不會只用固定條件查詢。Task list 端點要讓呼叫方自己決定要按什麼篩選：專案、狀態、優先級、逾期與否，全部可選。這一節教你用「條件式 where-clause 堆疊」在 SQLModel 裡動態組裝查詢。

<code>list_tasks</code> 的第一個參數是 <code>session</code>，後面的篩選條件全部用 <code>*</code> 隔開，強制變成 keyword-only 參數。每個參數預設都是 <code>None</code>，代表「不套用這個篩選」。這種簽章讓呼叫方可以只傳需要的篩選，不需要把每個條件都填滿。

核心 pattern 是「先建基底查詢，再按需堆疊 <code>where</code>」。每次 <code>where</code> 都回傳新 statement，舊的保持不動。這種 immutable 寫法讓邏輯清晰又好測試。

<code>*</code> 之後的參數必須用關鍵字指定，不能按位置傳。這避免了一長串 positional arguments 難以閱讀的問題，也讓未來新增篩選條件不會破壞現有呼叫。

「逾期」本質上是三個條件的組合：due_date 不是空值、due_date 早於今天、狀態不是已完成。全部用 <code>AND</code> 串起來，一次查詢解決。
