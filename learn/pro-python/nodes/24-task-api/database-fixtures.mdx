# Database fixtures with pytest

## Learning goal

Use in-memory SQLite and fixture chains for isolated, repeatable testing

## Lesson

之前的測試都只驗證 Pydantic 模型或工具函式，沒碰到資料庫。Task API 有真實的資料庫操作，測試必須在隔離的環境裡跑，才不會污染彼此的狀態。這一節教你用 pytest fixtures 自動建好測試資料庫，並在每次測試結束後自動清除。

SQLite 的 in-memory 模式把整個資料庫放在 RAM 裡，速度快，測試跑完就消失，不留殘留。SQLModel 可以直接用 <code>sqlite:///:memory:</code> 連線字串建立。但 SQLite 跟 Postgres 仍有差異：enum 型別、部分 constraint 行為不同。所以測試能過不代表正式環境一定沒問題，但涵蓋多數邏輯已經足夠。

In-memory SQLite 資料庫在連線關閉後資料就消失了。為了讓同一個 engine 的多條連線都能存取同一份資料，SQLModel 建議用 <code>StaticPool</code>，這樣所有連線都共享同一個 in-memory 資料庫。

pytest fixtures 可以相依成鏈。先建 engine，再建 session，再在 session 裡塞 sample data。每個測試只拿到最後一層的 fixture，但底層會自動跑好。這樣每個測試都會拿到乾淨的 database、session、以及一份 sample data。

測試隔離確保 A 測試新增的一筆 task 不會污染到 B 測試的查詢結果。如果每一輪測試都重新建資料庫，執行順序就不會影響結果，測試就是可重複的（repeatable）。
