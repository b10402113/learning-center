# Task router setup and imports

## Learning goal

Set up the task router with absolute imports and the three dependencies (project, session, task)

## Lesson

Task router 看起來幾乎和 project router 一樣，但多了一層對 <code>Project</code> 的關聯，以及一組新的 <code>task_dep</code> 依賴。這一節先把骨架搭好——導入風格、依賴宣告、APIRouter 初始化——讓後續的 CRUD 和查詢邏輯可以疊上去。

Python 的兩種導入寫法在執行期完全等價，但可讀性和重構難易不同。相對導入用點號標記目前 package 的位置，絕對導入則寫完整模組路徑。講師偏好絕對導入，因為重構時搜尋檔名更容易，移動檔案時也不易出錯。不管選哪種，團隊風格統一才是重點。

Task router 需要三個依賴一起運作：<code>project_dep</code> 透過 project_id 或 slug 查一筆專案，找不到就 404；<code>session_dep</code> 注入資料庫 session，結束時自動關閉；<code>task_dep</code> 查一筆 task，找不到就 404——這組 pattern 和 project_dep 完全一樣，只是物件類型不同。

一個值得留意的程式碼氣味：當 import 一行塞了十幾個名字，通常暗示該模組該拆成 sub-modules。這不是硬性規則，但是一個值得留意的 refactoring signal。
