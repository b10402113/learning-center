<LearningGoal>
能設定 pytest 開發依賴、建立 TestClient 實例，並寫出一個發送 GET 請求、驗證狀態碼的測試函式。
</LearningGoal>

## Lesson

寫好一個 FastAPI 端點之後，最直覺的驗證方式是啟動伺服器，用瀏覽器或 curl 手動打請求。這種做法能跑，但慢、不重複、也沒辦法放進 CI。FastAPI 內建了 `TestClient`，本質上是一個記憶體級的 HTTP 客戶端——它直接呼叫 ASGI 應用程式，不經過網路層，所以測試跑得快、結果確定、又能自動化。

在 UV 專案裡，pytest 通常作為開發依賴安裝：

```bash
uv add dev pytest
```

接著建立慣例的測試目錄與檔案：

```bash
mkdir tests
touch tests/test_main.py
```

FastAPI 專案慣例上把 API 測試放在 `tests/test_main.py`，因為 `main.py` 通常包含 FastAPI 應用程式實例。

打開 `tests/test_main.py`，寫入以下內容：

```python
from fastapi.testclient import TestClient
from main import app

client = TestClient(app)

def test_list_projects():
    response = client.get("/projects")
    assert response.status_code == 200
```

這段程式碼做了四件事：從 `fastapi.testclient` 匯入 `TestClient`；從 `main` 模組匯入 FastAPI 應用程式實例 `app`；建立 `client`，綁定到 `app`；在測試函式裡用 `client.get("/projects")` 發送 GET 請求，並斷言狀態碼為 200。

在終端機執行 `uv run pytest`，如果端點正常回傳 200，你會看到一個測試通過。這就確認了：你的端點在沒有真實伺服器的情況下，通過了自動化測試。
