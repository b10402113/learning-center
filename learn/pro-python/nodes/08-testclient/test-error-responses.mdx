<LearningGoal>
能為「找不到資源」的端點撰寫測試，驗證端點正確回傳 404 狀態碼與 detail 訊息。
</LearningGoal>

## Lesson

一個設計良好的 API 不只是在成功時回傳 200，還必須在失敗時回傳有意義的錯誤碼。如果客戶端請求一個不存在的資源，API 應該回傳 404 Not Found，而不是 500 Internal Server Error。測試錯誤回應能確保你的端點在異常情況下依然行為正確。

當查詢不到資源時，FastAPI 端點會用 `HTTPException` 主動拋出錯誤：

```python
from fastapi import HTTPException, status

@app.get("/projects/{project_id}")
def get_project(project_id: int):
    project = db.get(project_id)
    if project is None:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Project not found"
        )
    return project
```

這裡用了 `status.HTTP_404_NOT_FOUND` 而不是硬編碼整數 `404`。FastAPI 的 `status` 模組提供了所有 HTTP 狀態碼的命名常數，可讀性更好。

測試很直覺：請求一個不存在的 ID，然後驗證狀態碼是 404：

```python
def test_get_project_not_found():
    response = client.get("/projects/999")
    assert response.status_code == 404
    assert response.json()["detail"] == "Project not found"
```

這個測試同時驗證了兩件事：狀態碼正確（404），而且錯誤訊息（detail）也符合預期。

如果端點在找不到資源時只 `return None`，FastAPI 會把它變成 204 No Content 或直接報 500。客戶端無從區分「資源不存在」還是「伺服器壞掉了」。用 `HTTPException` 搭配明確的狀態碼，才能讓 API 的行為對客戶端來說是可預測的。
