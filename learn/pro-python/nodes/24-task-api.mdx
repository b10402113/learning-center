# Task API and relational queries

## Learning goal

Build task endpoints, use join/selectinload for relational queries

## Steps

1. [[learn/pro-python/nodes/24-task-api/task-router-setup|Task router setup and imports]] — Set up the task router with absolute imports and the three dependencies (project, session, task)
2. [[learn/pro-python/nodes/24-task-api/crud-endpoint-mapping|CRUD methods and endpoint mapping]] — Map CRUD operations to FastAPI endpoints following the project router pattern (after step 1)
3. [[learn/pro-python/nodes/24-task-api/sql-query-patterns|SQL query patterns — where, join, selectinload]] — Master the three core operations for efficient relational queries (after step 2)
4. [[learn/pro-python/nodes/24-task-api/list-tasks-filters|List tasks with conditional filters]] — Build dynamic queries with keyword-only filter parameters and immutable where-clauses (after step 3)
5. [[learn/pro-python/nodes/24-task-api/database-fixtures|Database fixtures with pytest]] — Use in-memory SQLite and fixture chains for isolated, repeatable testing (after step 3)

## Lesson

This node completes the task API: a new router that mirrors the project router but adds relational data, dynamic filtering, and eager loading. The task model is more complex than project — it has status fields, due dates, and a relationship to project. Building it teaches the SQL query patterns (`where`, `join`, `selectinload`) that keep relational queries efficient and avoid N+1 problems, plus the conditional-filter pattern that grows a SQL statement only when a filter is actually provided. The final step introduces database fixtures with pytest so every test runs against its own isolated in-memory SQLite database.
