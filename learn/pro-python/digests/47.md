# Digest — 47.md

## Overview (L1)

- Setting up pytest fixtures for database testing: each test gets an isolated in-memory SQLite instance wired to override the production session.
- In-memory SQLite is fast (tests created in seconds) but does not enforce Postgres-specific behaviors (native enum types, some constraints).
- The static pool pattern and fixture chain build pre-populated sample data for each test, reducing boilerplate.
- Trade-off: SQLite test databases are fast but may hide subtle Postgres-specific bugs; 100% SQLite coverage does not guarantee production correctness.
