## Sections (L2)

### Reinstalling pytest in a New Project
- Locator: [[sources/pro-python/completed/20260903_25.md#reinstalling-pytest]]
- Summary: After creating a new project and deleting the old pyproject.toml, pytest must be reinstalled as a dev dependency with `uv add dev pytest`, and a `tests/` directory must be created.
- Key claims: `uv add dev pytest` reinstalls pytest as a dev dependency; `tests/test_main.py` is the convention for API tests; the test directory should be clean with only relevant tests.
- Learner-relevant: Project setup hygiene — ensuring dependencies are declared and test directories are organized — is critical for reproducible environments.

### FastAPI TestClient
- Locator: [[sources/pro-python/completed/20260903_25.md#fastapi-testclient]]
- Summary: FastAPI includes a `TestClient` (from `fastapi.testclient`) that wraps Starlette's test client, providing a simple way to simulate HTTP requests against the app without running a server.
- Key claims: `TestClient(app)` creates a client bound to the FastAPI app instance; `client.get("/projects")` sends a GET request; `response.status_code` and `response.json()` provide assertion targets.
- Learner-relevant: TestClient eliminates the need for a running server during tests, making API testing fast and deterministic.

### Writing and Running the Test
- Locator: [[sources/pro-python/completed/20260903_25.md#writing-and-running-the-test]]
- Summary: Writes a `test_list_projects` function that hits the `/projects` endpoint, asserts status 200, and verifies the response JSON contains 3 projects; runs successfully with `uv run pytest`.
- Key claims: `assert response.status_code == 200` verifies successful response; `assert len(response.json()) == 3` verifies expected data count; one passing test confirms the endpoint works.
- Learner-relevant: Combining status code and response body assertions is the standard pattern for API endpoint testing.
