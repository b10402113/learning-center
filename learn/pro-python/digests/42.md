# Digest — 42.md

## Overview (L1)

- Tasks are added to the project model, each with state fields: status, priority, and optional due date.
- `StringEnum` is used for task status (planned, in progress, blocked, done) and priority (low, medium, high, urgent) to enforce valid values at the database level.
- The task model follows the same three-schema split as projects: TaskBase (shared fields), Task (table model with DB-only fields), plus create/update/read variants.
- SQLModel stores enum values as strings and adds a database-level constraint rejecting invalid values.

## Sections (L2)

### Task Status and Priority Enums
- Locator: [[sources/pro-python/completed/20260903_42.md#task-enums]]
- Summary: Defines `TaskStatus` and `TaskPriority` as `StringEnum` classes with explicit valid values.
- Key claims: StringEnum gives enforcement and reduces errors; SQLModel stores enum values as strings with DB constraints; task status includes planned/in progress/blocked/done, priority includes low/medium/high/urgent.
- Learner-relevant: Using StringEnum for categorical fields prevents invalid data at both the Python and database level.

### Task Schema Variants
- Locator: [[sources/pro-python/completed/20260903_42.md#task-schemas]]
- Summary: Introduces the three-schema split pattern for Task: TaskBase (shared fields like title, details, status, priority, due_date), Task (database table), and create/update/read variants.
- Key claims: TaskBase inherits from SQLModel and contains the shared API fields; Task inherits TaskBase and adds database-only fields; TaskCreate, TaskUpdate, TaskRead handle API-specific shapes.
- Learner-relevant: The schema variant pattern separates API contracts from database concerns, making the codebase more maintainable.

### Task Name Constraint
- Locator: [[sources/pro-python/completed/20260903_42.md#task-name-constraint]]
- Summary: Establishes a string length constraint for task titles, similar to the project name constraint.
- Key claims: Each entity type needs its own named constraint; refactoring shared constraints is an opportunity for later improvement.
- Learner-relevant: Named constraints improve error messages and make database schemas easier to reason about.
