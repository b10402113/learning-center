- Creating `get_project_or_404` function that handles lookup and 404

## Sections (L2)

### Creating the ProjectDep dependency
- Locator: [[sources/pro-python/completed/20260903_35.md#creating-the-projectdep-dependency]]
- Summary: Defines `get_project_or_404(project_id: int, session: Session)` in `dependencies.py` that calls `crud.get_project()` and raises `HTTPException(404)` if not found, returning a `Project` instance.
- Key claims: The function takes `project_id` (from path) and `session` (from `SessionDep`) as parameters; it calls `crud.get_project(session, project_id)`; it raises `HTTPException(status_code=404)` if the project doesn't exist; the return type is `Project`.
- Learner-relevant: Custom dependencies encapsulate cross-cutting concerns — once defined, they're reusable across every route that needs a project.

### Annotated type alias
- Locator: [[sources/pro-python/completed/20260903_35.md#annotated-type-alias]]
- Summary: `ProjectDep = Annotated[Project, Depends(get_project_or_404)]` creates a reusable type alias that combines the return type with the dependency resolution.
- Key claims: The `Annotated` syntax binds the type (`Project`) with the dependency (`Depends(get_project_or_404)`); routes just declare `project: ProjectDep` and FastAPI handles the entire lookup chain; this eliminates the "if not project" boilerplate from every route.
- Learner-relevant: Type aliases with dependencies make route signatures clean and self-documenting — the dependency name tells you exactly what's being injected.

### Simplified route handlers
- Locator: [[sources/pro-python/completed/20260903_35.md#simplified-route-handlers]]
- Summary: After replacing the repeated boilerplate with `ProjectDep`, route handlers become much shorter — they just receive a validated `Project` object and perform their specific operation.
- Key claims: Delete, update, and get routes all receive a pre-validated `Project` via `ProjectDep`; no route needs to handle the 404 case manually; the route focuses on its core logic (delete, update, respond).
- Learner-relevant: Less boilerplate per route means fewer bugs, easier maintenance, and more readable code.
