# Digest — 45.md

## Overview (L1)

- Building the task router: imports, endpoint definitions, and CRUD operations for tasks with project relationships.
- Introduces absolute vs. relative import styles (`from release_tracker.dependencies import ...` vs `from .dependencies import ...`); team style guides should decide the preference.
- The task router adds a `task_dep` dependency alongside `project_dep` and `session_dep`.
- Refactoring signals: long import statements may indicate a module that should be split.

## Sections (L2)

### Task Router Setup and Imports
- Locator: [[sources/pro-python/completed/20260903_45.md#task-router-setup]]
- Summary: Sets up the task router with imports from FastAPI, CRUD modules, and model variants (TaskCreate, TaskRead, TaskUpdate, TaskPriority, TaskStatus).
- Key claims: Absolute imports (`from release_tracker.dependencies import ...`) are preferred by the instructor for easier refactoring and searching; both styles are equivalent.
- Learner-relevant: Import style is a team convention; consistency matters more than which style is chosen.

### CRUD Methods and Endpoints
- Locator: [[sources/pro-python/completed/20260903_45.md#crud-endpoints]]
- Summary: Reviews the CRUD methods needed for tasks and how they map to FastAPI endpoints.
- Key claims: The task router follows the same endpoint pattern as the project router; CRUD methods handle the database operations behind each endpoint.
- Learner-relevant: The CRUD + router pattern is reusable across entities; understanding it once makes adding new entities straightforward.

### Refactoring Signals
- Locator: [[sources/pro-python/completed/20260903_45.md#refactoring-signals]]
- Summary: Notes that long import statements are a flag that a module may need refactoring.
- Key claims: If a single import line lists many items from one module, it may be time to split that module into sub-modules.
- Learner-relevant: Recognizing code smells early helps maintain clean, navigable codebases as projects grow.
