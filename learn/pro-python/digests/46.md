# Digest — 46.md

## Overview (L1)

- CRUD implementation for tasks: introduces `where`, `join`, and `selectinload` for querying with relationships.
- `list_tasks` is a beefier method that accepts optional filter parameters (project_id, project_slug, status, priority, overdue_only) using keyword-only arguments after a `*` separator.
- `selectinload` from SQLAlchemy ORM is imported to eagerly load related data and avoid N+1 queries.
- Conditional filter logic builds up a SQL statement dynamically: each `where` clause is appended only when the corresponding filter is provided.

## Sections (L2)

### SQL Query Patterns: Where, Join, Selectinload
- Locator: [[sources/pro-python/completed/20260903_46.md#sql-query-patterns]]
- Summary: Explains the three key SQL query operations used in the task CRUD: `where` for conditional predicates, `join` for filtering by related table columns, and `selectinload` for efficient relationship loading.
- Key claims: `where` specifies conditions applied to the query; `join` filters by related table columns; `selectinload` prevents N+1 by loading relationships in a single query.
- Learner-relevant: These three operations are the foundation for building efficient relational queries in SQLModel/SQLAlchemy.

### List Tasks Method Signature
- Locator: [[sources/pro-python/completed/20260903_46.md#list-tasks-signature]]
- Summary: Shows the `list_tasks` method with session as the first positional arg and keyword-only filter parameters (project_id, project_slug, status, priority, overdue_only).
- Key claims: The `*` separator forces all filter params to be keyword-only; each filter defaults to None so queries are flexible.
- Learner-relevant: Keyword-only parameters with defaults make CRUD methods composable and easy to call with only the filters you need.

### Conditional Filter Logic
- Locator: [[sources/pro-python/completed/20260903_46.md#conditional-filters]]
- Summary: Demonstrates building up a SQL statement by appending `where` clauses conditionally: `statement = statement.where(...)` only when a filter value is provided.
- Key claims: Each `where` call returns a new statement (immutable pattern); the overdue filter combines due_date != None, due_date < today, and status != done.
- Learner-relevant: The conditional where-clause pattern is a clean way to build dynamic queries without duplicating query logic.
