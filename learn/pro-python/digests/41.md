# Digest — 41.md

## Overview (L1)

- Middleware is code that runs before and after every request in a FastAPI application, acting as a bridge between the client and route handlers.
- Middleware is set up using the `app.middleware` decorator with `async def`, receiving `request` and `callnext` parameters.
- Multiple middlewares wrap each other: the first registered runs closest to the route, and the last registered runs closest to the client.
- Middleware is used for logging, auth checks, header modification, and response interception before they reach the client.

### Middleware Basics and Setup

- Summary: Explains what middleware is and how to set up an HTTP middleware using `app.middleware`.
- Key claims: Middleware intercepts both incoming requests and outgoing responses; `callnext` passes the request down the chain to the route handler and returns the response object after the handler finishes.
- Learner-relevant: Can add pre-route work (before endpoint) and post-route work (after endpoint) in a single middleware function.

### Middleware Execution Order
- Locator: [[sources/pro-python/completed/20260903_41.md#middleware-execution-order]]
- Summary: Describes how multiple middlewares execute in reverse registration order for requests and forward order for responses.
- Key claims: On requests, last middleware runs first, then middle ones, then first, then route; on responses the order reverses.
- Learner-relevant: Understanding execution order is critical for correct middleware layering and avoiding unexpected side effects.

### Why Middleware
- Locator: [[sources/pro-python/completed/20260903_41.md#why-middleware]]
- Summary: Brief note on the practical reasons for using middleware in production FastAPI apps.
- Key claims: Middleware is useful for cross-cutting concerns like logging, timing, and error handling that apply to all routes.
- Learner-relevant: Middleware is a standard pattern in FastAPI projects for implementing cross-cutting functionality without duplicating logic across routes.
