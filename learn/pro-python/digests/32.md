## Sections (L2)

### Write endpoint implementation
- Locator: [[sources/pro-python/completed/20260903_32.md#write-endpoint-implementation]]
- Summary: Implements POST (create), PATCH (update), and DELETE endpoints for projects, using SQLModel schemas for input validation and SQLAlchemy sessions for database operations.
- Key claims: POST creates a new project from a `ProjectCreate` schema; PATCH partially updates from a `ProjectUpdate` schema; DELETE removes a project by ID; each endpoint uses `session.add()`, `session.commit()`, `session.refresh()`.
- Learner-relevant: Write endpoints complete the CRUD cycle — they're where data enters and changes in your system.

### Slug generation
- Locator: [[sources/pro-python/completed/20260903_32.md#slug-generation]]
- Summary: A `slugify` function converts project names to URL-friendly slugs by lowercasing, filtering to alphanumeric characters and spaces, then joining with dashes. Uses a generator expression for cleanup.
- Key claims: `c.isalnum() or c == " "` filters characters; `.lower()` normalizes case; `" ".join(...).split()` and `"-".join()` creates the slug; in production, use a library like `python-slugify` instead of hand-rolling this.
- Learner-relevant: Slug generation is a common API requirement — it creates human-readable, URL-safe identifiers from arbitrary text.

### Soft vs hard deletion
- Locator: [[sources/pro-python/completed/20260903_32.md#soft-vs-hard-deletion]]
- Summary: Hard deletion permanently removes records; soft deletion uses a flag (e.g., `archived`) to hide records while preserving them for audit or recovery purposes.
- Key claims: Soft deletion is preferred in production for audit trails; an `archived` boolean flag can hide records from the frontend while keeping them in the database; the API can filter out archived records by default.
- Learner-relevant: Choosing between soft and hard deletion is an architectural decision that affects data retention, audit compliance, and recovery capabilities.
