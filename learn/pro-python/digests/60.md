## Sections (L2)

### Timestamp Fields: created_at and updated_at
- Locator: [[sources/pro-python/completed/20260903_60.md#timestamp-fields]]
- Summary: Explains the addition of `created_at` and `updated_at` fields to the Task model, using `datetime.utcnow()` as both default and on-update factory.
- Key claims: `created_at` records when a task was made; `updated_at` records the last update; both use a UTC datetime default factory; `onupdate` calls the same function on every update.
- Learner-relevant: Timestamps are a common production pattern for auditing and tracking changes.

### Cascade Delete on Project-Task Relationship
- Locator: [[sources/pro-python/completed/20260903_60.md#cascade-delete]]
- Summary: Explains `on_delete=True` on the project-task relationship, which deletes all tasks when their parent project is deleted.
- Key claims: Cascade delete makes the relationship explicit; when a project is deleted, all its tasks are deleted automatically.
- Learner-relevant: Cascade delete prevents orphaned records and is a standard pattern for parent-child relationships.

### Frontend Integration Notes
- Locator: [[sources/pro-python/completed/20260903_60.md#frontend-notes]]
- Summary: Briefly discusses how the demo connects the frontend and why that approach should not be used in production.
- Key claims: The demo's frontend integration approach is for demonstration only; production apps should use a different pattern.
- Learner-relevant: Understanding the gap between demo and production frontend integration helps you make better architectural decisions.
