# Digest — 51.md

## Overview (L1)

- JWT (JSON Web Tokens) carry user identity across stateless HTTP requests after login.
- A JWT has three base64-encoded parts: header (metadata + signing algorithm), payload (claims like `sub` and `exp`), and signature (hash of header+payload with a secret key).
- The token is cheap to verify, hard to forge, and self-contained — the server doesn't need to store session state.
- The header and payload are encoded but not encrypted; anyone can read them but cannot change them without invalidating the signature.

### Why JWT for Identity
- Locator: [[sources/pro-python/completed/20260903_51.md#jwt-identity]]
- Summary: Explains that HTTP is stateless, so the server gives the client a token after login, and the client sends it with every subsequent request.
- Key claims: The token must be cheap to verify, hard to forge, and self-contained; the server doesn't need to store session state.
- Learner-relevant: JWT is the standard approach for stateless authentication in APIs; understanding why it works helps you use it correctly.

### JWT Structure: Header, Payload, Signature
- Locator: [[sources/pro-python/completed/20260903_51.md#jwt-structure]]
- Summary: Describes the three parts of a JWT: header (signing algorithm), payload (claims), and signature (hash with secret key).
- Key claims: Header and payload are base64-encoded (not encrypted); the signature prevents tampering; common claims are `sub` (subject/user) and `exp` (expiration).
- Learner-relevant: Knowing the JWT structure helps you debug token issues and understand what data is exposed in the token.

### Token Verification
- Locator: [[sources/pro-python/completed/20260903_51.md#token-verification]]
- Summary: Explains that verifying a JWT means decoding it with the signing key and checking the signature matches.
- Key claims: If anyone changes the header or payload, the signature won't match and verification fails; the secret key must be kept private.
- Learner-relevant: Understanding verification helps you reason about token security and why the secret key is critical.
