# Digest — 54.md

## Overview (L1)

- Exercise: build a registration endpoint, write two tests (register + register-and-login), generate a JWT secret key, and create the users table migration.
- Three-step auth flow: register (hash password, store user), login (verify credentials, return JWT), and authenticated requests (send JWT in Authorization header).
- Common errors addressed: Pydantic JWT secret missing, 500 from wrong `crud.create_user` arguments, 422 from non-JSON request body.
- The registration endpoint is tested through the Swagger docs UI to confirm everything works end-to-end.

## Sections (L2)

### Three-Step Auth Flow
- Locator: [[sources/pro-python/completed/20260903_54.md#auth-flow]]
- Summary: Outlines the registration-login-authenticated-request flow: user registers, server hashes and stores, user logs in and gets JWT, client sends JWT on subsequent requests.
- Key claims: Registration hashes the password and stores the user; login verifies credentials and returns a signed JWT; protected endpoints verify the token to identify the caller.
- Learner-relevant: This three-step flow is the standard pattern for password-based JWT authentication in APIs.

### Common Errors and Troubleshooting
- Locator: [[sources/pro-python/completed/20260903_54.md#common-errors]]
- Summary: Addresses common issues: JWT secret not set in .env, wrong `crud.create_user` arguments causing 500, and non-JSON body causing 422.
- Key claims: JWT secret must be at least 32 characters and loaded correctly; `create_user` takes email and password as keyword args; registration body must be JSON, not form data.
- Learner-relevant: Knowing these common pitfalls saves debugging time during the exercise.
