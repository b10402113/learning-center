### Exercise setup
- Locator: [[sources/pro-python/completed/20260903_30.md#exercise-setup]]
- Summary: Checking out the exercise branch wipes local changes; `uv sync` mirrors pyproject.toml dependencies into the virtual environment; `docker compose up` starts the Postgres container.
- Key claims: Always stash or commit before switching branches; `uv sync` ensures dependency consistency; Docker Compose manages the Postgres lifecycle; new files in the exercise include configuration for database connection.
- Learner-relevant: A clean exercise setup ensures you start from a known-good state — critical for following along with the course.

### Port conflict troubleshooting
- Locator: [[sources/pro-python/completed/20260903_30.md#port-conflict-troubleshooting]]
- Summary: If Postgres is already running on the host (e.g., installed via Homebrew), the Docker port mapping will conflict. The solution is to stop the host Postgres or change the port mapping.
- Key claims: Homebrew-installed Postgres often runs on port 5432 by default; Docker Compose maps container port 5432 to the host; stopping the host Postgres or adjusting port mapping resolves conflicts.
- Learner-relevant: Port conflicts are a common Docker development issue — knowing how to diagnose and fix them saves significant debugging time.

### Seeding the database
- Locator: [[sources/pro-python/completed/20260903_30.md#seeding-the-database]]
- Summary: After Alembic generates the project table, a seed script or manual SQL inserts sample records so the API has data to serve.
- Key claims: Alembic migrations create the table structure; seed data provides realistic test records; the combination lets you immediately test API endpoints against real database data.
- Learner-relevant: Having seed data transforms the development experience from abstract to concrete — you see your API returning real data from a real database.
