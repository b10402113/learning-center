## Sections (L2)

### Quality Tools as Dev Dependencies
- Locator: [[sources/pro-python/completed/20260903_55.md#quality-tools]]
- Summary: Adds Ruff, MyPy, pytest, and coverage as dev dependencies with `uv add --dev` for reproducible quality checks.
- Key claims: Ruff handles linting and formatting; MyPy checks static types; pytest runs tests; coverage reports test coverage; all are run from the terminal for reproducibility.
- Learner-relevant: Having quality tools as explicit dev dependencies ensures all contributors can run the same checks regardless of their editor or environment.

### Dockerization Basics
- Locator: [[sources/pro-python/completed/20260903_55.md#docker-basics]]
- Summary: Introduces Docker for freezing the app's Python interpreter, dependencies, and creating a single artifact that runs the same way everywhere.
- Key claims: Docker images freeze the runtime environment; Python 3.15-slim is used for smaller images; pinning versions prevents surprises from new releases.
- Learner-relevant: Dockerizing ensures the app runs identically on dev laptops, CI, and production.

### CI with GitHub Actions
- Locator: [[sources/pro-python/completed/20260903_55.md#github-actions]]
- Summary: Describes setting up GitHub Actions to run quality checks (Ruff, MyPy, pytest, coverage) on every push.
- Key claims: CI catches broken code before it reaches main; quality checks should run automatically, not manually.
- Learner-relevant: CI is essential for team projects — it prevents broken main branches and enforces quality standards.
