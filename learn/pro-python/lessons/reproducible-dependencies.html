步驟 2 / 4

用 UV 安裝可重現的生產依賴

能在映像檔中固定 UV 版本，並用 uv sync --no-dev 只安裝生產依賴。

建置環境也需要固定

即使 Python image 已固定，建置工具本身也可能更新。今天的 UV 與下週的 UV 若解析依賴或產生環境的行為不同，image 就不再容易重建。把 UV 版本寫死，讓建置工具成為可追蹤的輸入。

FROM ghcr.io/astral-sh/uv:0.8.17 AS uv
FROM python:3.14-slim
COPY --from=uv /uv /uvx /bin/

這個多階段片段只把指定版本的 uv 與 uvx 帶進 Python image。版本號應與專案實際驗證過的版本一致，不要把範例版本當成永遠正確的版本。

先複製鎖定檔，再安裝

WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN uv sync --locked --no-dev

pyproject.toml 描述專案與依賴，uv.lock 鎖定解析後的確切版本。先複製這兩個檔案，Docker 可以重用依賴安裝層：只有依賴檔改變時才重跑安裝。

--locked 要求鎖定檔與專案設定一致，避免建置時偷偷重新解析。--no-dev 排除 pytest、Ruff、MyPy 等開發依賴，讓 production image 不攜帶不需要的工具。

依賴層與程式碼層分離

COPY pyproject.toml uv.lock ./
RUN uv sync --locked --no-dev
COPY src ./src

如果你只修改 src，前兩層仍可使用快取，建置速度會比每次先複製整個專案再安裝快。這種順序同時表達了一個邊界：依賴由鎖定檔管理，應用程式由原始碼管理。

Production image 的目標是「能執行服務的最小集合」，不是「把開發機完整搬進容器」。
