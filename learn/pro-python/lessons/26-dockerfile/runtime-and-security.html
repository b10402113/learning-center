設定容器執行時行為與檔案邊界

能使用 Python 執行環境變數、編譯 bytecode、明確複製檔案與 EXPOSE 8000，建立較安全且可預期的容器。

讓輸出適合容器

ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

PYTHONDONTWRITEBYTECODE=1 避免 Python 在執行時產生額外的 .pyc 檔案。PYTHONUNBUFFERED=1 讓 stdout 與 stderr 不長時間留在緩衝區，日誌能更即時地被 Docker runtime 收集。

如果預先編譯 bytecode，則可在安裝階段使用：

RUN uv sync --locked --no-dev --compile-bytecode

這把啟動前的編譯工作移到建置時，減少服務第一次載入時才處理的工作。

明確決定要放進 image 的檔案

COPY pyproject.toml uv.lock .python-version .env.example ./
COPY src ./src

不要在不清楚內容的情況下使用 COPY . .。它可能把本機的 .env、測試資料、快取與版本控制目錄一併帶入 image。明確列出檔案，能降低 secrets（密鑰）意外進入交付物的風險。

更完整的防線仍包括 .dockerignore、CI secret 注入與 runtime secret management。Dockerfile 的明確複製只是其中一層。

EXPOSE 不是埠號映射

EXPOSE 8000

EXPOSE 是 image 的文件化 metadata，表示服務預期監聽 8000。它不會替你把主機埠號打開；真正的映射要在執行時使用 docker run -p 8000:8000，或交給 Compose、Kubernetes 等執行平台設定。

容器內的 8000 與主機的 8000 是兩個不同的網路命名空間；映射是連接它們的設定。
