用 Dockerfile 固定 Python 執行環境

能用 python:3.14-slim 作為基底，理解 Dockerfile 如何把應用程式包成可移植的映像檔。

先解決「在我電腦上可以」

FastAPI 服務不只包含 Python 原始碼，還依賴 Python 版本、套件版本與作業系統環境。開發機、CI 與 production 若各自安裝，差異會在部署時才暴露。

Docker image（映像檔）把這些執行條件封裝成一個可分發的產物。Container（容器）則是這個映像檔啟動後的隔離程序。重點不是把程式「變成 Docker」，而是讓啟動它所需的環境可重建。

最小 Dockerfile

FROM python:3.14-slim
WORKDIR /app
COPY pyproject.toml uv.lock ./
COPY src ./src
RUN pip install uv
RUN uv sync --no-dev
EXPOSE 8000
CMD ["uv", "run", "fastapi", "run", "src/main.py", "--host", "0.0.0.0"]

FROM 選擇起點，WORKDIR 固定後續指令的目錄，COPY 把必要檔案放進 image，RUN 在建置時執行命令，CMD 定義容器啟動時執行的預設程序。

為什麼選 slim

python:3.14-slim 保留執行 Python 應用所需的核心內容，但比完整映像檔小。映像檔越小，下載、建置與部署通常越快，攻擊面也較少。這不是「越小越好」的絕對規則；若套件需要編譯工具，仍要在建置階段補足工具，或採用多階段建置。

把 image 當成應用程式的交付物：它應能在另一台機器上，用同一組輸入重建出相同的執行環境。

建置與啟動

docker build -t release-tracker .
docker run --rm -p 8000:8000 release-tracker

最後的 . 是 build context（建置上下文），代表 Docker 可以讀取目前目錄中送入建置的檔案。-p 將主機的 8000 埠映射到容器的 8000 埠。
