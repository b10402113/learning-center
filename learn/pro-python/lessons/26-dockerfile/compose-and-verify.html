用 Compose 啟動並驗證完整服務

能用 Docker Compose 把 FastAPI 與 Postgres 一起啟動，並透過依賴與健康檢查驗證服務可用。

為什麼需要 Compose

FastAPI 與 Postgres 是兩個不同服務。手動建立網路、設定環境變數、啟動順序很快就會變成容易出錯的腳本。Docker Compose（多容器編排工具）用一個 YAML 檔描述服務、網路、volume 與健康條件。

services:
  api:
    build: .
    ports:
      - "8000:8000"
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:17-alpine
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U release_tracker"]

api 使用目前目錄的 Dockerfile 建置，db 使用 Postgres image。depends_on 描述啟動依賴，健康條件則要求資料庫通過 healthcheck 後才啟動 API。

啟動並查看狀態

docker compose up -d
docker compose ps

-d 讓服務在背景執行。docker compose ps 顯示容器、狀態與埠映射；資料庫顯示 healthy 比只有 Up 更有意義，因為它表示健康檢查已通過。

docker compose logs api
docker compose logs db

若 API 無法啟動，先看 API 日誌；若資料庫沒有 healthy，查看 db 日誌與 healthcheck 指令。容器啟動不等於應用程式已能連線。

做一次真正的驗證

curl http://localhost:8000/health
docker compose exec db psql -U release_tracker -d release_tracker -c "\\dt"

第一個命令從主機呼叫 API 的 health endpoint。第二個命令進入 db 容器列出資料表。這兩個檢查分別驗證 HTTP 入口與資料庫程序，不能只看容器名稱就判定整個 stack 正常。

完成測試後，可用 docker compose down 停止並移除容器。若加上 -v，也會移除 named volume，資料庫資料會被清除，適合明確要重置本地環境時使用。
