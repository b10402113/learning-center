Slug generation

Node 13 · Step 1 of 4

Learning goal

Write a slugify helper that converts arbitrary project names into URL-friendly slugs, and understand when to hand-roll versus reach for a library.

Why slugs matter

Imagine you're building a release tracker. A project called "My Cool App!" needs a clean URL — something like /projects/my-cool-app. Humans can read it, search engines can index it, and it won't break when someone copies the link into an email. That transformation from a display name to a URL-safe identifier is called slug generation（slug 產生）。

The rules are simple: lowercase, no punctuation, spaces become dashes. But the edge cases are where the bugs hide — multiple spaces, leading/trailing whitespace, non-ASCII characters, and names that are already mostly clean.

Building slugify from scratch

Start with the core idea: iterate over every character, keep only what's safe, then join the survivors with dashes.

def slugify(value: str) -> str:
    cleaned = " ".join(
        c for c in value.lower()
        if c.isalnum() or c == " "
    )
    return "-".join(cleaned.split())

Walk through what happens with "My Cool App!":

StepResult
value.lower()"my cool app!"

"-".join(...)"my-cool-app"

The generator expression c for c in value.lower() if c.isalnum() or c == " " is the heart of the function. It walks the string once, keeping only letters, numbers, and spaces. Everything else — punctuation, emoji, symbols — gets silently dropped.

Notice the two-step join/split pattern: " ".join(...).split(). The split() with no arguments collapses consecutive whitespace, so "my cool" becomes ["my", "cool"] instead of ["my", "", "", "cool"]. That prevents double dashes in the final slug.

Adding a default value

What if someone passes an empty string? The function would return "", which is a terrible slug. Add a fallback:

def slugify(value: str) -> str:
    cleaned = " ".join(
        c for c in value.lower()
        if c.isalnum() or c == " "
    )
    slug = "-".join(cleaned.split())
    return slug or "project"

slug or "project" returns "project" when slug is empty. It's a small touch, but it keeps your URLs predictable even when the input is garbage.

When to stop hand-rolling

This implementation works for ASCII names, but it falls apart the moment you need to handle real-world text:

  • "Über Project" → "ber-project"（德語母音變音被剔除）
  • "我的專案" → ""（中文字元全部消失）
  • "100% Pure" → "100-pure"（百分號被剔除，但數字保留）

In production, reach for a library like python-slugify. It handles Unicode normalization, transliteration, and edge cases you haven't thought of yet. The hand-rolled version is a great learning exercise — and a great interview answer — but don't ship it to users.

Using slugify in a FastAPI endpoint

Once you have the helper, generating a slug inside a POST endpoint is a one-liner:

@app.post("/projects", response_model=ProjectRead)
def create_project(project_in: ProjectCreate, session: Session = Depends(session_dep)):
    slug = slugify(project_in.name)
    project = Project(**project_in.model_dump(), slug=slug)
    session.add(project)
    session.commit()
    session.refresh(project)
    return project

The slug is derived from the name, not accepted from the client. That's the key insight: slugs are a server-side concern. Letting clients choose their own slugs invites collisions, injection, and inconsistency.
