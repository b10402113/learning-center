SQL query patterns — where, join, selectinload

學習目標：Master the three core operations for efficient relational queries

Why this step matters

Task 和 Project 有關聯，查詢時必須處理「跨表」和「關聯載入」這兩個問題。這一節介紹的三個工具——where、join、selectinload——是 SQLModel / SQLAlchemy 裡最重要的 relational query 基礎元件。

Where: conditional predicates

where 在查詢裡加入篩選條件，相當於 SQL 的 WHERE 子句。每次呼叫會回傳一個新的 statement 物件（immutable pattern），不會修改原本的查詢。

statement = select(Task)
statement = statement.where(Task.status == "pending")
statement = statement.where(Task.priority == "high")

多個 where 會用 AND 串起來。

Join: filter by related table columns

當你想用「關聯表」的欄位來篩選，就需要 join。例如：列出所有屬於「專案 X」的 tasks，但 task 表裡只有 project_id，而你想用專案的 slug 來篩選。

statement = select(Task).join(Project)
statement = statement.where(Project.slug == "my-project")

join(Project) 會自動用外鍵關聯找出對應的 project。篩選條件仍然用 where 加上去。

Selectinload: avoid N+1 queries

N+1 問題是 ORM 最常見的效能陷阱：先查一次拿到 N 筆 tasks，然後每筆 task 要存取關聯的 project 時又各自多查一次，總共 1 + N 次查詢。selectinload 在一次查詢裡就把關聯資料全部撈回來。

from sqlalchemy.orm import selectinload

statement = select(Task).options(selectinload(Task.project))

這会让 SQLAlchemy 用第二條 IN 查詢把相關 projects 一次抓回記憶體，之後存取 task.project 就不會再打資料庫。

When to use which

Tool用途
where篩選目前表的欄位
join用關聯表的欄位篩選
selectinload讀取關聯資料時避免 N+1

Putting them together

三者經常出現在同一條查詢裡：用 join 切到關聯表，用 where 下條件，用 selectinload 讓後續讀取關聯物件不爆量查詢。
