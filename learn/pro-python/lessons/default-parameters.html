Default parameters, keyword-only args, and the mutable default trap

學習目標：為函式加上預設參數值、用 * 強制關鍵字傳參，並避開「可變預設值」這個經典難查 bug。

Why this step matters

打開任何 Python API 或框架的原始碼，你都會看到滿滿的預設參數和 keyword-only 參數——FastAPI 的路由裝飾器、SQLModel 的 Field()、你公司 codebase 裡的每一個工具函式。這一步教你讀懂它們，也教你避開其中最陰險的一個陷阱。

預設參數值：最常見的 API 人體工學

回顧上一課的 slugify。假設有時你想要不同的分隔符號，與其開兩個函式，不如給參數一個預設值：

def slugify(name, separator="-"):
    cleaned = name.strip().lower()
    return cleaned.replace(" ", separator)

print(slugify("Payments API"))
# payments-api（用預設的 "-"）

print(slugify("Payments API", separator="_"))
# payments_api（覆蓋預設值）

不傳 separator，就用預設的 "-"；要客製，明確傳進去覆蓋。一個簽名同時服務兩種使用情境，這就是預設參數讓 API 更好用的方式。

關鍵事實：預設值在函式定義時評估，而且只評估一次

這句話是本課的地基。separator="-" 的 "-" 不是「每次呼叫時新造一個」，而是 Python 執行到 def 那一行時算好、然後記住的那一個值。之後每次呼叫，用的都是同一份。

對字串、數字這種不可變（immutable）值，這完全沒問題——反正誰也改不了它。但對 list、dict 這種可變（mutable）物件，故事就完全不同了。

陷阱：可變預設值

先看一個看似無害的寫法——把空 list 當預設值：

def add_tag(name, tags=[]):        # 危險！
    tags.append(name)
    return tags

print(add_tag("python"))
# ['python']

print(add_tag("fastapi"))
# ['python', 'fastapi']  ← 為什麼 python 還在？！

print(add_tag("docker"))
# ['python', 'fastapi', 'docker']  ← 越積越多

第二次呼叫沒有傳 tags，直覺上應該拿到一個新的空 list，結果卻拿到上一次的舊 list。原因正是剛才那句話：預設值只評估一次。那個 [] 在函式定義時就誕生了，之後每次呼叫共用同一個 list。你在其中一次呼叫 append 的東西，會一直留到下一次。

這類 bug 特別難查，因為它不會報錯——程式照常執行，只是結果慢慢變得不對勁。你會浪費很多時間懷疑呼叫方、懷疑資料來源，最後才發現問題出在定義那一行。

正解：None 慣用語（the None idiom）

標準解法是把預設值設為 None，在函式裡檢查後再新建 list：

def add_tag(name, tags=None):     # 正確
    if tags is None:
        tags = []
    tags.append(name)
    return tags

print(add_tag("python"))
# ['python']

print(add_tag("fastapi"))
# ['fastapi']  ← 每次都是新的 list

None 是不可變的，所以共用它沒有副作用；if tags is None: tags = [] 保證每次呼叫都拿到新造的 list。這個 pattern 你會在 Python codebase 裡不斷看到，看到就應該立刻認出來。

Keyword-only 參數：用 * 畫一條線

參數列表裡一個單獨的 * 是分隔符：它之前的參數可以照位置傳，它之後的參數必須用關鍵字傳：

def create_release(name, *, draft=True, prerelease=False):
    ...

create_release("v1.0")                      # OK
create_release("v1.0", draft=False)         # OK
create_release("v1.0", False)               # TypeError！draft 必須用關鍵字傳

你在 type hints 那個節點已經見過這個語法。它存在的理由：當多個參數型別相同或語意容易搞混時，強迫呼叫方寫出參數名，呼叫端的意圖就一目瞭然——create_release("v1.0", False) 裡的那個 False 是 draft 還是 prerelease？沒人讀得出來。這也是為什麼幾乎所有現代 Python API（包括 FastAPI）都大量使用它。

組合起來：一個現代風格的簽名

def slugify(name: str, *, separator: str = "-") -> str:
    cleaned = name.strip().lower()
    return cleaned.replace(" ", separator)

位置參數 name 在前，* 之後是可選的 keyword-only 參數 separator。type hint、*、預設值三件事各司其職——這就是你在現代 Python 專案裡會看到的典型函式簽名。
