把資料庫操作抽到 crud.py

學習目標：理解為什麼 HTTP 路由和資料庫交易應該分開，並把 main.py 裡的資料庫操作抽到獨立的 crud.py 模組。

為什麼要分離？

想像你走進一家餐廳。服務生負責接待客人、寫單、上菜；廚師負責炒菜、控制火候。如果服務生自己跑進廚房炒菜，整個餐廳就會大亂——服務生得同時懂點單系統和烹飪，任何一邊出錯都要找服務生。

FastAPI 的 main.py 就像服務生：它該處理 HTTP 請求、決定狀態碼、回應 JSON。而資料庫操作——session.add()、session.commit()、session.refresh()——就像炒菜，是廚房裡的事。當這兩種邏輯混在同一個檔案，main.py 就得同時懂 HTTP 和交易邊界，任何一邊改動都可能破壞另一邊。

分離之後，誰做什麼？

分離的原則是：HTTP 歸 HTTP，資料庫歸資料庫。

crud.py 負責所有跟資料庫直接打交道的工作：

# crud.py
from sqlmodel import Session, select
from .models import Project

def get_project(session: Session, project_id: int) -> Project | None:
    return session.get(Project, project_id)

def create_project(session: Session, project: Project) -> Project:
    session.add(project)
    session.commit()
    session.refresh(project)
    return project

main.py 只負責 HTTP 層面的事：接收請求、呼叫 crud.py 的函式、決定狀態碼、處理例外。

# main.py
from fastapi import FastAPI, HTTPException
from . import crud

@app.post("/projects/", status_code=201)
def create_project(project: ProjectCreate, session: Session = Depends(get_session)):
    db_project = crud.create_project(session, project)
    return db_project

注意：main.py 裡完全沒有 session.add()、session.commit()、session.refresh()。交易邊界被完整封裝在 crud.py 裡。

重構不改行為

這次重構最重要的規矩是：API 行為完全不變。路由回傳什麼、狀態碼是什麼、錯誤怎麼回傳，全部跟重構前一樣。我們只是把「怎麼跟資料庫講話」這件事搬到另一個檔案，不是加新功能。

這表示重構前後，你可以跑同一套測試，結果應該完全一樣。如果測試通過，代表我們成功地把程式碼搬動了，同時沒有弄壞任何東西。
