定義與檢查 StrEnum：繼承為什麼重要

學習目標：能用 StrEnum 定義一組固定狀態值、在 REPL 檢查成員，並解釋為什麼必須繼承 StrEnum 而不是寫普通類別。

Why this step matters

上一步看過 TaskStatus 的長相了。這一步把它放進 REPL 裡翻來覆去檢查——這是你日後讀陌生 codebase 時最快的理解手法——並回答一個關鍵問題：這看起來就只是個普通類別加幾個欄位，為什麼非要繼承 StrEnum 不可？

定義：兩種寫法，同一件事

from enum import StrEnum

class TaskStatus(StrEnum):
    PLANNED = "planned"
    IN_PROGRESS = "in_progress"
    DONE = "done"

StrEnum 是 Python 3.11 加入的字串列舉。更舊的程式碼裡你會看到它的前身寫法——混合繼承 str 與 Enum：

from enum import Enum

class TaskStatus(str, Enum):        # 舊式寫法，效果相近
    PLANNED = "planned"
    IN_PROGRESS = "in_progress"
    DONE = "done"

讀舊 codebase 時認得後者就行；自己寫新程式碼，用 StrEnum。

放進 REPL 檢查

把這個類別貼進 REPL，幾個操作就能摸清它的行為：

>>> TaskStatus.PLANNED
<TaskStatus.PLANNED: 'planned'>

>>> TaskStatus.PLANNED.name       # 成員的名字
'PLANNED'

>>> TaskStatus.PLANNED.value      # 成員攜帶的值
'planned'

>>> print(TaskStatus.PLANNED)    # 印出來清楚可讀
TaskStatus.PLANNED

每個成員都有兩個面向：.name 是你在類別裡寫的成員名（PLANNED），.value 是你指派給它的值（"planned"）。檢查一個成員時，你看到的是它的型別與身份——TaskStatus.PLANNED——比起一個裸字串，這種輸出除錯時好讀得多。

StrEnum 還有一個實點性質：成員本身就是字串。

>>> TaskStatus.IN_PROGRESS == "in_progress"
True

所以字串列舉是你最常會遇到的一種——值可以直接跟字串比較、直接存進資料庫欄位。

關鍵問答：為什麼一定要繼承？

課堂上有人問了完全正確的問題：這些「就只是普通類別欄位吧？為什麼要繼承 StrEnum？」答案：沒有那個繼承，你拿到的就只是一個普通類別加上幾個字串屬性——Enum 的全部機制都不會生效：

  • 成員不會被當成列舉成員，編輯器的自動補全與檢查幫不上忙；
  • 下一課的 auto() 完全沒有作用；
  • .name、.value、按值查找這些 Enum 行為一概不存在。

繼承就是在宣告「這是一個 string enum 型別」。這個語法確實有點笨重——因為 enum 是後來才加進 Python 的，語法只能長這樣。多包一層看起來不優雅，但換來的是整套機制。

需要數字？用 IntEnum

狀態不一定是字串。若你需要的是數字狀態（例如各種 legacy 系統的 status code），標準庫備好了 IntEnum：

from enum import IntEnum

class Priority(IntEnum):
    LOW = 1
    MEDIUM = 2
    HIGH = 3

>>> Priority.HIGH == 3
True

成員本身就是整數。選哪一種取決於你的值是字串還是數字——兩者的機制完全相同。

配對 match / case：乾淨的分支

列舉配上一個狀態的多種處理方式時，match/case（結構化模式匹配）是最自然的分支語法：

match task.status:
    case TaskStatus.PLANNED:
        schedule(task)
    case TaskStatus.IN_PROGRESS:
        notify_owner(task)
    case TaskStatus.DONE:
        archive(task)

每個 case 直接對成員匹配，意圖一目瞭然——比一串 if status == ... 好讀也好維護。
