SQLModel：FastAPI 的 ORM 首選

理解 SQLModel 如何同時擔任 Pydantic 驗證與 SQLAlchemy ORM 的角色，並用它定義資料表模型。

ORM 是什麼？

ORM（Object-Relational Mapping，物件關聯對映）讓你用 Python 物件來操作資料庫，不需要手寫 SQL。你定義一個 Python 類別，ORM 會自動把它對應到資料庫表格。如果你用過 Java 的 Hibernate、.NET 的 Entity Framework、Rails 的 Active Record、或 Node.js 的 Sequelize，概念都一樣。

為什麼選 SQLModel？

SQLModel 跟 FastAPI 是同一個作者寫的，所以兩者整合得天衣無縫。它底層用的是 SQLAlchemy 2.0——Python 界最成熟、最強大的 ORM。但 SQLModel 多做了一件事：它讓你同時擁有 Pydantic 的資料驗證能力。

雙重身份：Pydantic + SQLAlchemy

在傳統的 FastAPI 專案裡，你通常要寫兩套模型：一套給 Pydantic 驗證請求/回應，一套給 SQLAlchemy 對應資料庫表格。這導致大量重複的欄位定義。SQLModel 解決了這個問題——一個類別同時扮演兩個角色。

定義一個 SQLModel

用 table=True 告訴 SQLModel 這個類別要對應到資料庫表格：

from sqlmodel import SQLModel, Field
from typing import Optional

class Book(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    title: str = Field(index=True)
    author: str
    pages: Optional[int] = Field(default=None)

每個欄位的意義

欄位 說明
id: Optional[int] 主鍵，新增前是 None，新增後資料庫會自動填入
Field(default=None, primary_key=True) 標記為主鍵，預設值為 None
title: str = Field(index=True) 設為索引，因為書名是常用搜尋條件
pages: Optional[int] = Field(default=None) 可選欄位，有些書可能沒有頁數資訊

安裝與使用

用 UV 安裝 SQLModel：

uv add sqlmodel

安裝後就能在程式碼裡 import 並定義模型。定義好之後，你會用 Alembic 來建立對應的資料庫表格——這個我們下一節會學到。
