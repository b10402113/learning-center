Node 22 — Step 3/3 · JWT tokens

產生與驗證 JWT token

學習目標

能用 Python 套件產生 JWT、設定過期時間，並用伺服器端的密鑰驗證 token 是否合法。

用 PyJWT 產生 token

在 Python 上，最常見的 JWT 套件是 PyJWT。安裝：

uv add pyjwt

產生一個 token 只需要三件事：payload（要放的 claims）、secret key（伺服器密鑰）、演算法。

import jwt
from datetime import datetime, timedelta, timezone

SECRET_KEY = "your-256-bit-secret"
ALGORITHM = "HS256"

payload = {
    "sub": "alice",
    "exp": datetime.now(timezone.utc) + timedelta(hours=24),
}

token = jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)
print(token)
# eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

exp 是 JWT 標準 claim，PyJWT 會自動把它轉成 Unix timestamp。一旦 token 過期，驗證就會失敗——你不需要自己寫過期檢查。

驗證 token

收到 token 後，用同一個 secret key 解碼：

try:
    decoded = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    print(decoded["sub"])  # alice
except jwt.ExpiredSignatureError:
    print("Token 已過期")
except jwt.InvalidTokenError:
    print("Token 無效")

jwt.decode 會自動驗證 Signature 和 exp。如果 token 被竄改、過期、或簽章不對，就會拋出例外。

密鑰就是一切

JWT 的安全性完全取決於 secret key。如果攻擊者拿到你的 key，他就能簽發任何 token、冒充任何人。所以：

  • 不要把 key 寫死在程式碼裡——用環境變數或 .env 管理
  • 用足夠長的隨機字串（至少 256 位元）
  • 如果 key 外洩，立刻輪換——但輪換會讓所有已發出的 token 失效
JWT 的「難以偽造」不是魔法，是數學：沒有 key 就無法產生對的雜湊。保護 key 就是保護整個認證系統。

在 FastAPI 裡的典型用法

登入成功後，伺服器產生 token 並回傳給客戶端：

@app.post("/login")
def login(form: OAuth2PasswordRequestForm = Depends()):
    user = authenticate(form.username, form.password)
    if not user:
        raise HTTPException(status_code=401, detail="登入失敗")
    token = jwt.encode(
        {"sub": user.username, "exp": datetime.now(timezone.utc) + timedelta(hours=24)},
        SECRET_KEY,
        algorithm=ALGORITHM,
    )
    return {"access_token": token, "token_type": "bearer"}

之後客戶端在 Authorization 帶上 Bearer <token>，伺服器用 jwt.decode 驗證——不需要查 session 資料庫。
