五種嚴重等級與過濾行為

從 DEBUG 到 CRITICAL，以及「門檻」怎麼運作

五個等級（由低到高）

等級數字用途
DEBUG10開發時的詳細診斷資訊
INFO20一般操作事件，例如「服務啟動」
WARNING30預期外的狀況，但程式還能跑
ERROR40嚴重問題，某個操作失敗
CRITICAL50程式可能無法繼續執行

門檻過濾

設定等級就像設定「門檻」：只有這個等級以上的訊息才會被輸出。設定 INFO 時，DEBUG 被擋下，INFO 以上通過。

開發環境：level=DEBUG → 全部看得到
正式環境：level=INFO  → DEBUG 被過濾

什麼時候用哪個等級？

  • DEBUG：route 收到的參數、SQL 查詢內容、迴圈裡的變數值
  • INFO：請求完成、服務啟動、資料庫連線成功
  • WARNING：重試連線、使用棄用 API、磁碟空間不足
  • ERROR：資料庫斷線、API 呼叫失敗、檔案讀取錯誤
  • CRITICAL：記憶體耗盡、設定遺失、服務即將關閉

環境變數切換等級

常見做法是讀環境變數，在開發時用 DEBUG，上線後用 INFO：

import os
import logging

level = logging.DEBUG if os.getenv("ENV") == "dev" else logging.INFO
logging.basicConfig(level=level)
DEBUG 訊息太雜，會拖垮 log 系統和儲存。">
