Secrets, health checks, and failure diagnosis

安全地提供必要設定，並用失敗位置縮小診斷範圍。

秘密不屬於 YAML

JWT secret、資料庫密碼和 API key 不應寫入 workflow、原始碼或 log。把它們存成 GitHub repository 或 environment secret，在 job 中透過環境變數注入。workflow 只描述「需要一個叫什麼名字的值」，不保存值本身。

env:
  JWT_SECRET: ${{ secrets.JWT_SECRET }}

steps:
  - run: uv run pytest
    env:
      DATABASE_URL: ${{ secrets.DATABASE_URL }}

測試若不需要真實服務，就不要注入真實 production secret。CI 用專用、最小權限的值，並避免用 echo 印出環境變數。

健康檢查是服務層的 gate

@router.get("/health")
def health(session: SessionDep) -> dict[str, str]:
    session.exec(select(1))
    return {"status": "healthy"}

select(1) 是一個極小的資料庫查詢。它不取資料，只確認應用程式能否透過 session 連到資料庫。Docker 或部署平台可以呼叫 /health，把回應當成容器是否準備好的訊號。

按照失敗層次排查

  1. workflow 層：YAML 語法、觸發事件、權限。
  2. 環境層：checkout、Python、UV、依賴安裝。
  3. 品質層：Ruff 或 MyPy 找到程式問題。
  4. 測試層：pytest assertion 失敗或 fixture 出錯。
  5. 服務層：資料庫不可達、secret 缺失、health endpoint 失敗。

先修最早失敗的層次，再重新執行。不要在依賴尚未安裝成功時猜測測試內容，也不要把資料庫連線錯誤誤判成 Ruff 問題。
