CI quality gates

把四種不同問題交給四個清楚的檢查。

同一組命令，兩個地方執行

uv run ruff check .
uv run ruff format --check .
uv run mypy .
uv run pytest
uv run coverage run -m pytest
uv run coverage report

本機和 CI 應該使用同一組命令。這樣 CI 不是另一套神秘規則，而是把你在提交前應該做的檢查自動化。把 Ruff、MyPy、pytest 和 coverage 加入開發依賴，能讓每位貢獻者取得相同工具，而不依賴編輯器外掛。

每個工具回答不同問題

工具它問的問題常見失敗
Ruff程式風格與明顯問題是否合格？未使用 import、格式不一致
MyPy型別推理是否一致？回傳值與註記不符
pytest行為是否符合測試？assertion 失敗、例外
coverage測試實際走過多少程式？覆蓋率低於門檻

不要把 coverage 當成正確性的證明。覆蓋率只表示哪些行被執行過；測試仍然必須檢查正確結果。

讓失敗可讀

可以把檢查拆成獨立 steps。這會讓 CI 清楚指出是格式、型別、行為或覆蓋率出了問題。若所有命令塞在一個長 shell 指令中，任何失敗都可能只顯示一大段不易定位的輸出。

- name: Lint
  run: uv run ruff check .
- name: Type check
  run: uv run mypy .
- name: Test
  run: uv run pytest
- name: Coverage
  run: uv run coverage run -m pytest && uv run coverage report
