GitHub Actions workflow foundations

把「每次 push 都執行檢查」變成一個可重複的流程。

先看結果

push → workflow → job → runner → checks → pass / fail

持續整合（Continuous Integration，CI）解決一個實際問題：程式在你的電腦上能跑，不代表合併後仍然安全。GitHub Actions 會在儲存庫事件發生時，建立乾淨的執行環境，執行事先寫好的命令，並把結果回報到提交或 pull request。

四個層次

  1. 事件（event）：例如 push 或 pull request，決定何時觸發。
  2. 工作流程（workflow）：放在 .github/workflows/ 的 YAML 檔，描述整體自動化流程。
  3. 工作（job）：一組在同一個 runner 上執行的步驟。
  4. 步驟（step）：例如 checkout 程式碼、安裝環境、執行測試。

一個工作失敗時，後續步驟通常停止，整個 workflow 標記為失敗。這個失敗訊號就是團隊阻止壞變更進入主分支的依據。

最小 workflow

name: CI

on:
  push:
  pull_request:

jobs:
  checks:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: uv run pytest

uses 引入可重用的 action；run 執行 shell 命令。先用一個簡單 job 建立心智模型，再逐步加入 Python、UV、Ruff、MyPy 與 coverage。不要把「workflow 失敗」直接等同於「程式錯誤」；它也可能是 runner 或依賴安裝出了問題。
