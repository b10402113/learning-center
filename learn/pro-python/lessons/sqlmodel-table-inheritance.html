SQLModel 表格繼承與 base/table 分離

學習目標：理解 SQLModel 如何同時作為 Pydantic 驗證模型與 SQLAlchemy 表格，並掌握 base/table 分離的設計模式。

從 Pydantic 到 SQLModel

在之前的課程裡，我們用 Pydantic 的 BaseModel 來驗證請求資料。Pydantic 很擅長一件事：檢查進來的 JSON 對不對、能不能轉成 Python 型別。但它完全不知道資料庫長什麼樣子。

SQLModel 的出現，就是為了解決這個斷層。它由 FastAPI 的同一位作者打造，把 Pydantic 的驗證能力和 SQLAlchemy 的資料庫對應（ORM）黏在同一個模型裡。

table=True 的魔法

要讓一個 SQLModel 類別變成真正的資料庫表格，只需要多做一件事：在類別設定裡加上 table=True。

from sqlmodel import SQLModel, Field

class ProjectBase(SQLModel):
    name: str
    description: str | None = None

class Project(ProjectBase, table=True):
    id: int | None = Field(default=None, primary_key=True)

看到差別了嗎？ProjectBase 繼承 SQLModel，但它沒有 table=True，所以它只是一個單純的 Pydantic 驗證模型。Project 繼承 ProjectBase，加上 table=True，SQLModel 就會為它在資料庫裡建一張真正的表格。

為什麼要拆成兩層？

這是 SQLModel 最核心的設計模式：把「欄位定義」和「資料庫表格」分開。

角色 用途 有 table=True？
ProjectBase 定義共享欄位，給請求/回應模型重用 沒有
Project 對應資料庫表格，產生 SQL 有

這樣拆的好處是：你可以讓 ProjectCreate（給 POST 請求用）、ProjectRead（給回應用）、Project（給資料庫用）全部繼承同一個 ProjectBase，欄位改一次就全部生效。

實際程式碼長這樣

from sqlmodel import SQLModel, Field
from datetime import datetime, timezone

# 純驗證模型，不建表格
class ProjectBase(SQLModel):
    name: str = Field(min_length=1, max_length=100)
    description: str | None = None
    slug: str = Field(min_length=1)

# 資料庫表格，會自動生成 CREATE TABLE
class Project(ProjectBase, table=True):
    id: int | None = Field(default=None, primary_key=True)
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))
    updated_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))

重點整理

  • SQLModel 同時繼承 Pydantic 和 SQLAlchemy，一個類別兩用。
  • table=True 是告訴 SQLModel「請為我建表格」的開關。
  • base 類別放共享欄位，table 類別加上 table=True 和資料庫專用欄位（如 id、created_at）。
  • 這種分離讓請求模型、回應模型、資料庫模型可以共用欄位定義，減少重複。

隨堂測驗

子類別會繼承父類別的所有欄位，再加上自己的欄位，一起成為表格的欄位。
