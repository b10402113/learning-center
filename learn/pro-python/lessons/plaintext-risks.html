為什麼不該儲存明文密碼？

學習目標

理解明文密碼儲存的風險：資料庫外洩、SQL 注入、備份外流與設定錯誤都可能一次曝光所有使用者的原始密碼，且因密碼重複使用會引發連鎖危機。

明文外洩的四條攻擊路徑

想像一個情境：你的 API 資料庫因為雲端儲存桶設定失誤，被搜索引擎索引到了。如果資料庫裡存的是明文密碼，攻擊者不需要任何技術門檻——直接打開就能看到幾千使用者的帳號和密碼。這不是假設，而是真實發生過幾十次的外洩事件。

攻擊路徑如何發生為什麼致命
資料庫被入侵SQL 注入、未修補漏洞、內部威脅攻擊者直接拿到所有密碼
備份外流備份檔放在物件儲存、外接硬碟、Git 倉庫備份權限通常更鬆散，明文會不斷複製
雲端設定錯誤S3 bucket 公開、連接埠對外開放、環境變數暴露規模可以從幾千到幾億筆
SQL 注入輸入欄位塞入惡意 SQL 拉走整個資料表明文密碼毫無防備能力

連鎖危機：密碼重複使用

真正讓明文密碼變成災難的，不是單一外洩事件，而是密碼重複使用（Password Reuse）。多數人會在不同網站使用相同或類似的密碼。當一個小論壇的明文資料庫外洩，攻擊者拿這批帳號密碼去主流服務嘗試登入，這個手法稱為憑證填充（Credential Stuffing）。一次小外洩可以引爆連鎖性的帳戶接管。

開發者的責任是假設資料庫「總有一天會被入侵」，並在那一天到來之前，確保即使資料表被整包偷走，攻擊者也無法拿到可以用來登入的密碼。
