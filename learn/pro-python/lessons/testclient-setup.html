步驟 1 / 4

設定 pytest 與 TestClient，寫出第一個 GET 測試

能設定 pytest 開發依賴、建立 TestClient 實例，並寫出一個發送 GET 請求、驗證狀態碼的測試函式。

為什麼需要 TestClient？

寫好一個 FastAPI 端點之後，最直覺的驗證方式是啟動伺服器，用瀏覽器或 curl 手動打請求。這種做法能跑，但有三個問題：慢（每次都要啟 server）、不重複（手動操作無法自動化）、無法放進 CI（持續整合流程不能等人工）。

FastAPI 內建了 TestClient，本質上是一個記憶體級的 HTTP 客戶端——它直接呼叫 ASGI 應用程式，不經過網路層。測試跑得快、結果確定、又能自動化。

第一步：安裝 pytest 並建立測試目錄

在 UV 專案裡，pytest 通常作為開發依賴安裝：

uv add dev pytest

接著建立慣例的測試目錄與檔案：

mkdir tests
touch tests/test_main.py

FastAPI 專案慣例上把 API 測試放在 tests/test_main.py，因為 main.py 通常包含 FastAPI 應用程式實例。

第二步：建立 TestClient 並寫出第一個測試

打開 tests/test_main.py，寫入以下內容：

from fastapi.testclient import TestClient
from main import app

client = TestClient(app)

def test_list_projects():
    response = client.get("/projects")
    assert response.status_code == 200

這段程式碼做了四件事：

  1. 從 fastapi.testclient 匯入 TestClient
  2. 從 main 模組匯入 FastAPI 應用程式實例 app
  3. 建立 client，綁定到 app
  4. 在測試函式裡用 client.get("/projects") 發送 GET 請求，並斷言狀態碼為 200

第三步：執行測試

在終端機執行：

uv run pytest

如果端點正常回傳 200，你會看到一個測試通過。這就確認了：你的端點在沒有真實伺服器的情況下，通過了自動化測試。

重點回顧

  • TestClient(app) 建立一個綁定到 FastAPI 應用的記憶體級 HTTP 客戶端
  • client.get("/path") 模擬 GET 請求，回傳一個 Response 物件
  • response.status_code 提供 HTTP 狀態碼供斷言
  • 測試慣例放在 tests/test_main.py，用 uv run pytest 執行
