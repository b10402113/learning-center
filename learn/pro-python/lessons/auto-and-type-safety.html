auto() 與免費的型別安全

學習目標：能用 auto() 消除重複的值指派，並解釋 Enum 免費提供的型別檢查，以及它作為資料庫欄位驗證的用途。

Why this step matters

定義 StrEnum 時你可能有個疑問：PLANNED = "planned"——同一個字打兩遍，這不是另一種重複嗎？這一步用 auto() 把重複消掉，然後看 Enum 送你的另外兩樣禮物：不用 type hinting 就有的型別檢查，以及資料庫欄位驗證的殺手級用法。

抱怨是對的：PLANNED = "planned" 很重複

class TaskStatus(StrEnum):
    PLANNED = "planned"          # 打了兩次 planned
    IN_PROGRESS = "in_progress"  # 又打了兩次
    DONE = "done"                # 再一次……

成員少還好，成員一多就全是大寫與小寫的複製貼上。這正是 auto() 存在的理由。

auto()：讓值自動生成

auto 跟 StrEnum 住在同一個 enum 模組裡：

from enum import StrEnum, auto

class TaskStatus(StrEnum):
    PLANNED = auto()             # 值是 "planned"
    IN_PROGRESS = auto()         # 值是 "in_progress"
    DONE = auto()                # 值是 "done"

在 StrEnum 裡，auto() 產生的值就是成員名的小寫形式——跟你自己手打 "planned" 結果完全相同。等於宣告一次名字，值就自動長好，重複指派整個消失，拼字錯誤也跟著少一個來源。（若用在沒有混入型別的普通 Enum，auto() 給的是 1、2、3 這種遞增整數。）

新手常踩的坑：忘記把 auto 加進 import。你會拿到一個 NameError: name 'auto' is not defined——訊息很直白，補上 import 就好。

免費的型別安全：成員必須是字串

課堂上有人問：自己寫個普通類別、手動放這些欄位，難道不行？差別之一藏在這裡——StrEnum 明確宣告了「這個列舉的成員必須是字串」。你在裡面塞一個非字串的值：

class TaskStatus(StrEnum):
    PLANNED = auto()
    DONE = 1        # TypeError！成員必須是字串

Python 直接拒絕。注意這個檢查不需要任何 type hinting——Enum 本身就給了你。它同時是一道護欄：Python 平時愛做隱性的型別轉換（coercion），但這裡它不會把 1 偷偷轉成 "1"，而是明確報錯。你等於免費拿到了一份「成員型別保證」。

殺手級用法：資料庫欄位的固定值集合

講師點出這套東西真正發威的地方：資料庫欄位只接受一組固定值的時候。任務狀態欄、優先權欄——值就是那幾個，多一個都不行。Enum 讓驗證變成一個二元問題：

def validate_status(value: str) -> TaskStatus:
    try:
        return TaskStatus(value)      # 按值查找成員
    except ValueError:
        raise ValueError(f"{value} 不是合法的任務狀態")

>>> validate_status("planned")
<TaskStatus.PLANNED: 'planned'>

>>> validate_status("banana")
ValueError: 'banana' 不是合法的任務狀態

「這個值是不是欄位接受的其中之一？」——是或不是，一行解決。若你自己寫類別做這件事，等於重造一套會員清單與檢查邏輯，徒增負擔。這也是之後所有驗證工作的基礎：Release Tracker 專案裡的任務狀態與優先權，就是這樣大規模使用 Enum 的。
