for 迴圈與 dict 迭代

學習目標：能用同一套 for 語法走訪 list、tuple、set、dict，並用 .items() 搭配 tuple unpacking 在迴圈裡同時拿到 key 與 value。

Why this step matters

前面兩步把四種容器備齊了，這一步把它們全部「走一遍」。走訪資料是每個 endpoint、每個 crud 函式的骨架：回傳一排專案前你要逐個處理、算未完成任務數前你要逐個檢查。Python 的 for 迴圈只有一種寫法，對四種容器全部通用——學會一次，到處能用。

for ... in ...：一套語法走四種容器

fruits = ["apple", "banana", "cherry"]

for fruit in fruits:
    print(fruit)

讀法：對於 fruits 裡的每一個 fruit，執行縮排區塊。迴圈變數（fruit）是你取的方便名字，每一輪自動更新成下一個值。這套語法對 list、tuple、set 完全一樣——換容器不用換寫法。

迴圈變數的殘留

for fruit in fruits:
    print(fruit)

print(fruit)   # 還在！停在最後一個值 "cherry"

一個要留心的行為：迴圈變數在迴圈結束後不會消失，會留在原地、停在最後一輪的值。多數時候無害，但如果你在迴圈後又用同一個名字、或拿它判斷「迴圈有沒有跑過」，就可能踩到 bug——空的容器走完後，這個名字甚至可能根本沒被定義過。知道它會殘留，寫 code 時就會避開這些坑。

dict 迭代：keys、values、還是兩個都要

person = {"name": "Carol", "city": "Taipei"}

for key in person.keys():        # 只要 key
    print(key)

for value in person.values():    # 只要 value
    print(value)

for key, value in person.items():   # key 和 value 同時拿
    print(key, value)

第三種寫法是重點：.items() 回傳一對對的 (key, value) 配對，而 for key, value in ... 這個 loop header 用的正是上一步學過的 tuple 解包（unpacking）——每一輪把一個配對拆成兩個變數，兩者同時更新。這是 Python 裡最常見的 dict 走訪寫法，FastAPI 專案裡到處都是。

巢狀結構：list of dicts

真實世界的資料不會只有一層。在接上真資料庫之前，課程專案用的 mock database 就是這個形狀——一個 list，元素是 dict（或類別的實例）：

tasks = [
    {"title": "Write docs", "done": True},
    {"title": "Fix login bug", "done": False},
    {"title": "Deploy API", "done": False},
]

for task in tasks:
    print(task["title"], task["done"])

外層 list 提供順序，每個 dict 裝一筆記錄。這些結構會一層疊一層、越來越複雜——但拆開來看，每一層都還是這四種基本容器的組合。

四種容器，一張總結表

容器保序？可變？特色
list✔✔最常用；新增、刪除、排序都行
tuple✔✘固定綁在一起的一組值
set✘✔自動去重，附贈集合運算
dict—✔名字對應值；JSON 資料最常見的形狀

「哪種資料放哪種容器」是 Python 的基本功：會變的序列用 list、固定的一組用 tuple、要唯一用 set、要查找用 dict。下一步，把這張表上最常見的操作——轉換和過濾——收進一行 comprehension。
