雜湊與加鹽如何運作？

學習目標

理解密碼雜湊的單向本質：雜湊將任意輸入轉為固定長度字串，加入隨機鹽值讓相同密碼產生不同結果，而現代演算法刻意緩慢以抵抗暴力破解。

雜湊的三個關鍵特性

如果你直接拿密碼 "mypassword123" 去跟資料庫裡的 "mypassword123" 比對，看起來可行，但只要資料庫被偷，攻擊者就直接拿到所有人的密碼。密碼雜湊的核心思路是：永遠不存密碼本身，只存它的「指紋」。

特性意義對密碼儲存的影響
確定性同輸入永遠產生同輸出登入時可以用相同密碼產生雜湊值來比對
固定長度不管輸入多長，輸出長度都一樣資料庫欄位大小固定，不用擔心密碼太長
不可逆從雜湊值無法回推原始輸入即使資料庫被偷，攻擊者也無法還原密碼

為什麼需要鹽值？

光是不可逆還不夠。攻擊者可以预先算好常見密碼的雜湊值，然後一一比對——這就是彩虹表（Rainbow Table）攻擊。為了解決這個問題，每個密碼在雜湊之前，都會加上一段隨機產生的鹽值（Salt）。

即使兩個使用者用了完全相同的密碼，因為鹽值不同，最終產生的雜湊值也會完全不同：

密碼鹽值雜湊結果
mypassword123a1b2c3d4e5f6...$argon2id$v=19$...xYz
mypassword123f6e5d4c3b2a1...$argon2id$v=19$...qWe

攻擊者就算拿到雜湊值和鹽值，也得針對「每個鹽值」重新跑一次暴力破解。當資料庫裡有十萬使用者，他就得跑十萬次。

現代演算法為什麼要「慢」？

早期的 MD5 或 SHA-1 設計目标是快——攻擊者一秒可以算幾十億次雜湊。Argon2id 則相反，它要求大量記憶體和計算時間，讓攻擊者在有限預算下只能嘗試極少數組合。

雜湊不是為了「加密」密碼（加密暗示可以解密），而是把密碼轉成一個無法回推、即使外洩也無法快速破解的指紋。
