pytest 的自動發現機制

能說出 pytest 如何自動發現測試檔案與測試函數，並按照命名慣例建立 tests/ 目錄。

從問題開始

在很多測試框架裡，你必須手動註冊每一個測試案例，或是在設定檔裡列出所有測試模組。只要忘記新增，那些測試就不會執行，你還不自覺。

pytest 採用完全不同的策略：它會自動掃描專案裡的檔案，按照命名慣例找出所有測試。你不需要手動註冊，只要遵守命名規則，pytest 就會幫你執行。

發現規則的三個層級

pytest 的自動發現機制依賴三個命名慣例，全部符合才會被執行：

層級 慣例 範例
目錄 必須放在 tests/ 目錄下 tests/test_slug.py
檔案 檔名必須以 test_ 開頭 test_slug.py
函數 函數名必須以 test_ 開頭 test_slugify_lowercases()

目錄結構長這樣

my-project/
├── pyproject.toml
├── uv.lock
├── src/
│   └── slug.py
└── tests/
    └── test_slug.py

注意 tests/ 目錄要放在專案根目錄，跟 src/ 或 pyproject.toml 同層。pytest 會自動找到它。

命名慣例的細節

檔名慣例有兩種常見寫法，pytest 都認得：

  • test_*.py：例如 test_slug.py、test_user.py
  • *_test.py：例如 slug_test.py、user_test.py

函數名稱則一定要以 test_ 開頭，而且要是獨立函數，不能是類別裡的方法（除非你使用類別，但函數還是要符合慣例）。

為什麼不用手動註冊？

自動發現機制背後的設計理念是「慣例優於配置（convention over configuration）」。只要所有人遵守同一套命名規則，工具就能自動理解專案結構，不需要額外的設定檔或註冊碼。

這代表你新增測試時，只要檔案放對位置、命名正確，下次執行 uv run pytest 就會自動包含它。
