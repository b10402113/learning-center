用 session.get() 查詢單筆資料

學習目標

用 session.get(Model, id) 從 Postgres 抓回一筆 Project，並在 API 路由中回傳。

從 dictionary 到資料庫

之前的課程用 Python dictionary 模擬資料：

PROJECTS = {
    1: {"id": 1, "name": "Project Alpha", "slug": "project-alpha"},
}

@app.get("/projects/{project_id}")
def get_project(project_id: int):
    return PROJECTS[project_id]  # 找不到會噴 KeyError

問題是：dictionary 不是執行緒安全的、關掉伺服器資料就沒了、找不到會噴 KeyError 而不是 404。

session.get() 的用法

session.get(Model, primary_key) 是 SQLModel / SQLAlchemy 最基本的查詢方法。給它模型和主鍵，它回傳那筆記錄，找不到就回傳 None：

from sqlmodel import SQLModel, Field

class Project(SQLModel, table=True):
    id: int = Field(default=None, primary_key=True)
    name: str
    slug: str

@app.get("/projects/{project_id}")
def get_project(project_id: int, session: Session = Depends(get_session)):
    project = session.get(Project, project_id)
    return project

session.get() 會根據主鍵產生 SELECT * FROM project WHERE id = ?。因為用主鍵查，SQLAlchemy 內部會先檢查快取（identity map），如果這筆記錄已經在 session 裡，就不會真的去資料庫查。

回傳 SQLModel 實例

session.get() 回傳的是一個 Project 實例。FastAPI 搭配 response model 宣告，會自動把它序列化成 JSON：

@app.get("/projects/{project_id}", response_model=Project)
def get_project(project_id: int, session: Session = Depends(get_session)):
    project = session.get(Project, project_id)
    return project

response_model=Project 做兩件事：驗證回傳資料符合 Project 結構、在 API 文件裡顯示回應格式。

找不到會怎樣？

session.get() 找不到時回傳 None，不是拋例外。如果直接回傳 None，FastAPI 會回 null 而不是 404——這通常不是你要的。下一步課會教你怎麼處理。

小結

session.get(Model, id) 是用主鍵查單筆記錄的標準方法。找不到回傳 None，需要自己決定怎麼處理。
