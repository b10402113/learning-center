欄位定義與 Annotated 可重用約束

學習目標：使用 Annotated 與 StringConstraints 定義可重用的欄位型別，並區分 SQLModel Field 與 Pydantic Field 的差異。

重複的驗證規則，怎麼不寫死？

假設你的系統裡有十個模型都需要「名稱」欄位：不能為空、長度 1-100。最笨的方法是在每個模型都寫一次 Field(min_length=1, max_length=100)。但這樣改規則的時候，你要改十個地方。

Python 的 Annotated 型別提示，搭配 SQLModel 的 StringConstraints，可以讓我們把這段驗證規則「打包」成一個型別，到時候直接重用。

Annotated 是什麼？

Annotated[str, StringConstraints(min_length=1, max_length=100)] 的意思是：這個欄位的基本型別是 str，但身上還附加了 StringConstraints 這組驗證規則。

from typing import Annotated
from sqlmodel import StringConstraints

# 把驗證規則打包成一個型別別名
NameType = Annotated[str, StringConstraints(min_length=1, max_length=100)]

class Project(SQLModel, table=True):
    name: NameType

這樣一來，name 欄位就自動擁有「不能為空、最長 100 字」的驗證，而且其他模型也可以直接重用 NameType。

SQLModel Field vs Pydantic Field

這裡有個容易踩坑的地方：SQLModel 的 Field 和 Pydantic 的 Field 雖然名字一樣，但功能不同。

來源 主要用途
pydantic.Field 設定驗證規則（min_length、max_length、regex）
sqlmodel.Field 設定資料庫層級設定（primary_key、unique、index、sa_column） 
from sqlmodel import SQLModel, Field, StringConstraints
from typing import Annotated

# 用 Annotated + StringConstraints 做應用層驗證
NameType = Annotated[str, StringConstraints(min_length=1, max_length=100)]

class Project(SQLModel, table=True):
    # SQLModel 的 Field 負責資料庫設定
    id: int | None = Field(default=None, primary_key=True)
    name: NameType = Field(unique=True)  # unique 是資料庫約束

實際案例：可重用的 constrained 型別

from typing import Annotated
from sqlmodel import StringConstraints

# 定義可重用的欄位型別
NameType = Annotated[str, StringConstraints(min_length=1, max_length=100)]
SlugType = Annotated[str, StringConstraints(min_length=1, max_length=50, pattern=r"^[a-z0-9-]+$")]
DescriptionType = Annotated[str, StringConstraints(max_length=500)]

class Project(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: NameType
    slug: SlugType
    description: DescriptionType | None = None

這樣做的好處是：驗證規則集中管理，模型定義乾淨可讀，資料庫約束和應用驗證各司其職。

重點整理

  • Annotated[str, StringConstraints(...)] 把驗證規則打包成可重用的型別。
  • SQLModel 的 Field 主要負責資料庫設定（如 primary_key、unique）。
  • Pydantic 的 Field 主要負責應用層驗證（如 min_length）。
  • 把常用約束抽成型別別名，可以讓多個模型共用同一套規則。
