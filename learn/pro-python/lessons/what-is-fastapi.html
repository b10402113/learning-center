什麼是 FastAPI？為什麼選它？

學習目標

能說出 FastAPI 的核心定位，並解釋它跟 Flask、Django 的差異。

Python Web 框架的光譜

Python 世界裡有三個主要的 Web 框架，它們落在一個光譜的兩端：

框架定位特色
Django 全功能框架（batteries-included） 內建 ORM、模板引擎、後台管理、表單處理。什麼都幫你做好。
Flask 微框架（micro-framework） 核心只做路由和請求處理。其他功能靠擴充套件手動組裝。
FastAPI 現代微框架 核心只做路由，但內建驗證、非同步支援、自動文件。介於 Flask 和 Django 之間。

打個比方：Django 像一間裝潢好的套房，搬進去就能住；Flask 像一塊空地，你自己蓋；FastAPI 像一塊附了水電的土地——結構自己蓋，但最重要的基礎設施已經到位。

FastAPI 的三大支柱

FastAPI 建立在兩個開源專案之上，形成了三個核心優勢：

1. 型別提示驅動（Type Hints）

FastAPI 用 Python 原生的型別提示來做一切。你寫 def get_item(item_id: int)，FastAPI 就知道 item_id 必須是整數。不需要額外的 DSL、不需要設定檔——你寫的 Python 就是規格。

這帶來的好處：

  • 編輯器支援：自動補全、型別檢查，寫程式更順
  • 自動驗證：傳錯型別直接回 422 錯誤，不用自己寫
  • 自動文件：OpenAPI 規格從型別提示自動生成

2. 建立在 Starlette 之上（非同步）

Starlette 是一個輕量的非同步（async）Web 框架。FastAPI 把 Starlette 的路由和請求處理包在底層，讓你可以用 async def 寫路由，處理並發請求時不會阻塞。

在效能基準測試中，FastAPI 是最快的 Python 框架之一，跟 Node.js 和 Go 的框架在同一個量級。

3. 建立在 Pydantic 之上（驗證）

Pydantic 是一個資料驗證庫，用型別提示定義資料結構。FastAPI 用 Pydantic 來驗證請求資料、序列化回應資料——下一章會詳細看。

免費的 API 文件

FastAPI 自動根據你的路由和型別提示生成 OpenAPI 規格，然後提供兩個互動式文件頁面：

  • Swagger UI（/docs）：可以在瀏覽器直接測試 API
  • ReDoc（/redoc）：排版更適合閱讀的文件

你不需要寫任何文件程式碼。路由寫好，文件就有了。想測試 API？打開 /docs 頁面，點一下就能送請求——連 curl 都不用。

為什麼選 FastAPI？

如果你的專案是 API-first（先設計 API，前端另外接），FastAPI 是目前 Python 世界裡開發體驗最好的選擇。它把 Flask 的簡潔和 Django 的實用功能結合在一起，同時加上了現代 Python 的型別安全和非同步支援。

2023 年 FastAPI 超越了 Flask，成為 Python 第二大 Web 框架（僅次於 Django）。在需要高效能、型別安全、快速開發的場景——特別是微服務和 API 服務——FastAPI 已經是首選。

小結

FastAPI 的核心賣點：用 Python 型別提示驅動路由、驗證、文件。它建立在 Starlette（非同步）和 Pydantic（驗證）之上，是 API-first 專案的現代選擇。下一步，我們動手寫出第一個路由。
