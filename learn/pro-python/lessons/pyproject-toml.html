Node 02 — Step 2/3 · 專案設定

解讀 pyproject.toml

學習目標：能讀懂 pyproject.toml 的每個欄位，理解它如何定義專案的中繼資料與依賴。

專案的身份證

上一步你用 uv init 建立了專案。現在讓我們打開核心檔案 pyproject.toml，看看裡面寫了什麼。這是整個專案的身份證——每個工具鏈都會讀它。

一個典型的 pyproject.toml 長這樣：

[project]
name = "python-for-pros"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.14,<3.15"
dependencies = []

看起來很簡單，但每個欄位都有意義。讓我們逐行拆解。

逐欄位解讀

欄位值意義
name "python-for-pros" 專案名稱。用於套件安裝、PyPI 發布。通常和資料夾名稱一致。
version "0.1.0" 語意化版本號（SemVer）。0.x 表示開發中，1.0 表示穩定版。
description "Add your description here" 一行簡述專案用途。UV 產生的預設文字，記得改成你自己的描述。
readme "README.md" 指向專案的說明文件。通常是 Markdown 格式。
requires-python ">=3.14,<3.15" Python 版本範圍。這裡釘死在 3.14.x，不允許 3.15。
dependencies [] 專案的依賴列表。目前是空的，之後會用 uv add 新增。

為什麼版本範圍是 >=3.14,<3.15？

你可能注意到 requires-python 不是只寫 >=3.14，而是加了上限 <3.15。這是有意為之的。

Python 的小版本更新（3.14 → 3.15）可能引入不相容的變更。如果你只寫 >=3.14，未來有人用 Python 3.15 開啟這個專案時，可能會遇到詭異的錯誤。加上上限 <3.15 確保專案只會在 3.14.x 版本上執行，避免意外。

💡 重點：釘選版本範圍是一種防禦性編程。你告訴未來的自己和隊友：「這個專案在 3.14.x 上測試過，其他版本不保證。」

dependencies 列表

目前 dependencies = [] 是空的。當你需要安裝第三方套件時，不要手動編輯這個列表，而是用：

uv add fastapi
uv add "uvicorn[standard]"

UV 會自動：

  1. 下載套件到虛擬環境
  2. 在 dependencies 加入套件名稱和版本範圍
  3. 產生 uv.lock 鎖定精確版本

這比手動 pip install 然後忘記記錄依賴安全多了。

pyproject.toml 的歷史背景

pyproject.toml 是 PEP 518（2016）引入的標準。在此之前，Python 專案用 setup.py、setup.cfg、requirements.txt 等多個檔案分散管理設定。這造成混亂——每個工具都有自己的格式。

pyproject.toml 用統一的 TOML 格式取代了這一切。現在 UV、pip、poetry、ruff、mypy、pytest 都讀同一個檔案。這是現代 Python 的基石。

TOML 格式速覽

TOML（Tom's Obvious, Minimal Language）是一種設定檔格式，設計目標是可讀性。語法很直覺：

# 這是註解
[section]
key = "value"        # 字串
number = 42          # 整數
flag = true          # 布林值
list = ["a", "b"]    # 陣列

你不需要記住所有語法，只要知道 [section] 是分節標頭，key = value 是鍵值對就好。

小結

pyproject.toml 是現代 Python 專案的中央設定檔。它記錄專案名稱、版本、Python 版本要求、依賴列表。用 uv add 管理依賴，不要手動編輯。下一步我們要看看 .python-version 和 uv sync 如何確保環境一致性。
