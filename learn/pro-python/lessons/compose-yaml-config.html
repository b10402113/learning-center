compose.yaml 的結構與設定

能讀懂並寫出一個 Postgres 服務的 compose.yaml，包含映像檔、連接埠、環境變數、volume 與健康檢查。

compose.yaml 是什麼？

compose.yaml 是 Docker Compose 的設定檔，用 YAML 格式描述你要跑哪些服務、它們怎麼設定、資料怎麼保存。把它放在專案根目錄，VS Code 會自動認出這個檔案並給它專屬圖示。

基本結構

一個最簡單的 compose.yaml 包含兩個頂層區塊：services 和 volumes。

services:
  db:
    image: postgres:17-alpine
    ports:
      - "5432:5432"
    environment:
      POSTGRES_DB: release_tracker
      POSTGRES_USER: release_tracker
      POSTGRES_PASSWORD: very_secure_release_tracker
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U release_tracker -d release_tracker"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  postgres_data:

每個設定在做什麼？

設定 用途
image: postgres:17-alpine 指定映像檔版本，alpine 是精簡版，體積小
ports: "5432:5432" 把主機的 5432 對應到容器的 5432，讓本機應用能連到資料庫
environment 設定資料庫名稱、使用者、密碼，容器啟動時自動建立
volumes 把 named volume 掛載到容器內的 Postgres 資料目錄，確保資料持久化
healthcheck 定期用 pg_isready 檢查資料庫是否真的可用，而不是只有容器在跑

健康檢查的細節

健康檢查不只是確認容器在跑，而是確認資料庫真的能接受連線。pg_isready 是 Postgres 內建的工具，它會實際嘗試連線。設定裡 interval: 10s 表示每 10 秒檢查一次，timeout: 5s 表示每次最多等 5 秒，retries: 5 表示連續失敗 5 次才標記為不健康。

環境變數的安全性

範例中的密碼 very_secure_release_tracker 只適合本地開發。正式環境的密碼絕對不能寫在 compose.yaml 裡，要用 .env 檔案或 secrets 管理。
