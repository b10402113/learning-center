Catching Exceptions

Node 34 · Step 2 / 4 · pro-python

Learning goal

Use try/except to catch specific exceptions and handle errors gracefully without swallowing them.

The try/except block

When you call code that might raise, you can catch the exception and decide what to do. The try block runs the risky code. If an exception bubbles up, Python checks each except clause for a matching type.

try:
    validate_project_name("")
except ValueError:
    valid_name = "default"

If validate_project_name raises ValueError, the except block runs and sets a default. If no exception occurs, the except block is skipped entirely.

Catch specifically

Always name the exception you expect. A bare except: catches everything — including KeyboardInterrupt (Ctrl+C) and SystemExit. That means your program can't be stopped cleanly.

# Bad — catches KeyboardInterrupt, SystemExit, everything
try:
    do_something()
except:
    pass

# Good — catches only what you expect
try:
    do_something()
except ValueError as e:
    logger.warning("Invalid value: %s", e)
Never write except: with no type. It hides bugs and makes debugging a nightmare. If you must catch everything, use except Exception: — but only when you have a very good reason.

Multiple except clauses

You can handle different exceptions differently. Python checks them in order, so put more specific exceptions first.

try:
    data = fetch_project(project_id)
except ProjectNotFoundError:
    return Response(status_code=404)
except DatabaseConnectionError:
    return Response(status_code=503)
except Exception:
    logger.exception("Unexpected error fetching project")
    return Response(status_code=500)

The else and finally clauses

else runs only if no exception was raised — it keeps the happy path separate from error handling. finally runs no matter what, even if you return early or re-raise. Use it for cleanup.

try:
    connection = pool.acquire()
except PoolExhausted:
    metrics.increment("pool.exhausted")
    raise
else:
    metrics.increment("pool.acquired")
finally:
    logger.debug("Pool acquire attempt complete")

Don't catch just to ignore

Catching an exception and doing nothing is worse than letting it crash. At minimum, log it. If you can't handle it meaningfully, let it propagate to something that can.
