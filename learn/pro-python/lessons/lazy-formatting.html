懶加載格式化：用 %s 而不是 f-string

避免不必要的字串插值

f-string 的問題

很多人直覺這樣寫：

logger.debug(f"處理 payload: {payload}")

看起來沒問題，但有一個隱藏成本：f-string 會先算出完整字串，才傳給 logger。如果 logger 等級是 INFO，這條 debug 訊息根本不會輸出，但 f-string 已經跑完了。

百分號語法（lazy formatting）

logging 提供另一種寫法：

logger.debug("處理 payload: %s", payload)

這裡 payload 不會馬上被轉成字串。logging 內部會先檢查等級——如果這條訊息最後不會被輸出，payload 就不會被插值，省下運算。

什麼時候差異最大？

當你的 log 訊息包含「昂貴運算」時，差異最明顯：

# 昂貴：f-string 會先呼叫 repr(payload)
logger.debug(f"payload: {repr(payload)}")

# 便宜：只有真的輸出時才呼叫 repr
logger.debug("payload: %s", repr(payload))

在 production 環境，DEBUG 訊息被過濾掉，f-string 的 repr 運算就白白浪費了。

結構化 logging 的優勢

使用 %s 還有另一個好處：像 structlog 或 Data Dog 這類工具，會把 payload 當成「獨立欄位」索引，而不是混在字串裡。這樣你之後可以搜尋 payload.status_code = 500，而不是用正則表達式挖字串。

Ruff 會提醒你

現代 linter（例如 Ruff）會強制檢查 f-string 用在 logging 的情況，自動建議你改用 %s。這已經成為 Python 社群的共識慣例。
