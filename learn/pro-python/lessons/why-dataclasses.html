為什麼需要 @dataclass？

學習目標：能說出傳統手寫資料類別的样板問題，以及 @dataclass 如何自動生成 __init__、__repr__、__eq__ 來消除重複。

從一個痛點開始

假設你要描述一個「專案」，需要名字、slug 和一個標記是否已封存的布林值。最直覺的做法就是寫一個 class，然後手動定義建構子、列印方法和相等比較。

class Project:
    def __init__(self, name, slug, archived=False):
        self.name = name
        self.slug = slug
        self.archived = archived

    def __repr__(self):
        return f"Project(name={self.name!r}, slug={self.slug!r}, archived={self.archived!r})"

    def __eq__(self, other):
        if not isinstance(other, Project):
            return NotImplemented
        return (self.name, self.slug, self.archived) == (other.name, other.slug, other.archived)

這段代碼裡，真正跟「專案」業務邏輯相關的只有第一行 name, slug, archived。剩下的全部都是樣板（boilerplate）：把參數一一塞進屬性、自己拼出可讀的列印格式、手動比對每個欄位是否相等。

樣板長什麼樣子

如果你曾經手寫過這種類別，你就會發現每次新增一個欄位，至少要改三個地方：__init__ 的參數列表、self.xxx = xxx 的指派、還有 __repr__ 和 __eq__ 裡的欄位清單。少改任何一個，不是印出來的東西落相等比較就漏了一項。

常見陷阱：忘記更新 __eq__ 會導致兩個明明不同的物件被誤認為相等，或者兩個一樣的物件被判成不相等。這種 bug 通常很難追蹤，因為它不會噴錯誤，只會讓判斷式靜悄悄地給出錯的結果。

@dataclass 怎麼解決

Python 的 @dataclass 裝飾器（decorator）的核心想法是：既然這些樣板都長得差不多，那就讓機器幫你產生。你只需要宣告「這個類別有哪些欄位、分別是什麼型別」，剩下的 __init__、__repr__、__eq__ 全部自動生成。

from dataclasses import dataclass

@dataclass
class Project:
    name: str
    slug: str
    archived: bool = False

這樣就夠了。三行欄位宣告取代了十幾行樣板，而且行為完全等價：你可以寫 Project(name="demo", slug="demo")，印出來會得到漂亮的 Project(name='demo', slug='demo', archived=False)，兩個物件也能直接比較。

自動得到的三件事

方法做什麼為什麼重要
__init__按照你宣告的欄位順序建立建構子不用自己寫 self.x = x
__repr__產生可讀的字串表示印出來或除錯時不會看到 <__main__.Project object>
__eq__逐欄位比較兩個實體是否相等不用自己寫 self.x == other.x and ...
重點：dataclass 不是魔法，它只是把「宣告欄位 → 產生樣板」這件煩人的事自動化。你仍然可以隨時把手寫的方法加進去，需要客製行為的時候再客製就好。

什麼時候該用

一個簡單的判斷準則：如果你的類別主要目的是裝資料，而且你發現自己正在寫一堆 self.x = x，那八成該用 @dataclass。如果類別裡面已經有一大堆自訂方法、複雜的初始化邏輯、或者需要繼承階層裡做奇怪的事，那手寫完整類別可能還是比較合適——這會在最後一課詳細比較。
