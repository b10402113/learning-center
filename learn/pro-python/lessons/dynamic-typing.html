動態型別：變數沒有固定型別

學習目標

能解釋 Python 動態型別的行為：型別跟著值走、變數可重新指派成不同型別、type hint 在執行時不強制檢查。

從 Java 開發者的疑問說起

如果你從 Java 這類靜態型別語言過來，看到這行程式一定會問：型別宣告在哪裡？

priority = 13

Java 要寫 int priority = 13;，編譯器靠宣告檢查型別。Python 不用——因為 Python 是動態型別（dynamically typed）語言：變數的型別是從它目前綁住的值推論出來的，不需要宣告。

型別跟著值走

上一步說過：變數只是綁在值上的名字。所以型別的歸屬是——

  • 值有型別：13 是 int、"urgent" 是 str
  • 名字沒有型別：priority 只是一個標籤，貼在誰身上，推論出的型別就是誰

你隨時可以用 type(priority) 檢查現在貼著的值是什麼型別。

重新指派成不同型別——合法的陷阱

動態型別的直接後果，也是最大的 gotcha（陷阱）：

priority = 13          # priority 現在是 int
priority = "urgent"    # 完全合法的 Python！

這段程式不會報任何錯。對小腳本無妨，但在生產程式碼裡，這正是整類型別 bug 的溫床：函式前半段把 priority 當數字用，後半段有人把它重新指派成字串，下游的 priority + 1 就會在執行時爆炸（TypeError: can only concatenate str to str）——而且是在跑到那一行的當下才爆。

type hint：提示，不是執行時的強制

Python 的回答是 type hint（型別提示）：寫下來給人和工具看，但不在執行時檢查。

priority: int = 13
priority = "urgent"    # 執行時照樣通過，不會報錯

hint 只是提示。要讓它「生效」，必須靠外部工具——最常見的是 mypy 這類靜態型別檢查器，在你的程式跑起來之前就把這種指派抓出來。歷史上動態型別曾是 Python 最常見的 bug 來源之一；現代 Python 幾乎全面採用 type hint + 靜態檢查，就是因為它解決了整類的微妙 bug。

讀你手上那份 Django/Flask 專案時：有 type hint 的函式，簽名就是契約；沒有 hint 的舊程式碼，看到變數被重新指派時要特別警戒。
