__post_init__ 與可變預設值

學習目標：能使用 __post_init__ 在建構後執行驗證，並用 field(default_factory=...) 避開可變預設值的共享陷阱。

建構之後還想做點事

@dataclass 幫我們產生了 __init__，但有時候我們不只想把參數塞進屬性，還想在建構之後多做一步。例如，自動根據 name 產生 slug，或者檢查欄位值是否合法。

dataclass 留了一個掛鉤（hook）：如果你的類別裡定義了 __post_init__，它會在 __init__ 執行完之後立刻被呼叫。post init 的字面意思就是「初始化之後」，這個時機點非常適合做驗證或衍生計算。

@dataclass
class Project:
    name: str
    slug: str
    archived: bool = False

    def __post_init__(self):
        if not self.slug:
            raise ValueError("slug 不能是空字串")

現在如果有人試圖建立 Project(name="demo", slug="")，就會立刻得到一個 ValueError。這種驗證邏輯放在 __post_init__ 裡，而不是另外寫一個「建立之後記得呼叫 validate」的方法，因為後者很容易忘記。

可變預設值的陷阱

如果你在類別的欄位上寫 tags: list = []，會發生什麼事？Python 函數的預設值只會求值一次，所以所有沒有傳 tags 的實體會共用同一個列表。修改其中一個，另一個跟著變。

@dataclass
class Project:
    name: str
    tags: list = []  # 危險！所有實體共用同一個 list
共用陷阱：當你寫 p1.tags.append("a")，結果 p2.tags 也多了 "a"，這種 bug 非常難抓，因為看起來是兩個不相干的物件。

這個陷阱不是 dataclass 獨有，Python 所有函數都有這個問題。但 dataclass 提供了一個專門的解法：field(default_factory=...)。

用 default_factory 每次產生新的

default_factory 接收一個「零參數函數」，每次建立實體時都會被呼叫一次，產生一個全新的預設值。這樣每個實體就有自己獨立的列表。

from dataclasses import dataclass, field

@dataclass
class Project:
    name: str
    tags: list = field(default_factory=list)

現在 Project("a") 和 Project("b") 各自擁有自己的 tags 列表，互不干擾。同樣的原理適用於任何可變物件，例如 dict、set、或者其他自訂的可變實例。

常見的 factory 選擇

你想預設成用這個 factory
空列表 []default_factory=list
空字典 {}default_factory=dict
空集合 set()default_factory=set
其他可變物件default_factory=你的工廠函數
記住：欄位的可變預設值永遠用 field(default_factory=...)，不可變預設值（數字、字串、None、布林）直接寫就好。

__post_init__ + default_factory 合併使用

這兩個功能經常一起出現。例如，建立專案時如果沒給 tags，預設是空列表；同時我們希望 tags 裡面不要有重複值：

@dataclass
class Project:
    name: str
    tags: list = field(default_factory=list)

    def __post_init__(self):
        self.tags = list(set(self.tags))  # 去重

這樣就把「給預設值」和「清理資料」兩件事分開處理，各自都有明確的位置。
