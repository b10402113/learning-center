Function basics — def, return vs print

學習目標：用 def 定義帶參數的函式並回傳值，說得出「回傳」和「印出」的差別，以及為什麼函式應該回傳而不是印出。

Why this step matters

你每天讀的 Django/Flask 程式碼、FastAPI 的每一個 dependency、每一個 CRUD 函式，骨架都是一個 Python 函式。這一步把骨架本身拆開看：def 語法、縮排區塊、以及一個會影響你可測性的決定——回傳還是印出。

解剖一個 def

Python 用 def 關鍵字定義函式，後面依序是：函式名稱、小括號、參數列表、冒號。冒號之後，縮排的程式碼就是函式本體：

def slugify(name):
    cleaned = name.strip().lower()
    return cleaned.replace(" ", "-")

如果你寫過 Java 或 JavaScript，這裡最不一樣的是：Python 沒有大括號。縮排本身就是語法——往下縮一層的程式碼，就屬於上面那一行。在 VS Code 裡打完冒號，編輯器會自動幫你縮排；如果縮排不對，Python 會直接報錯，而不是猜你的意思。

一個完整的小例子：slugify

要把「Payments API」變成 URL 用的「payments-api」，正規做法是 regular expression 或現成庫，但這裡用最基本的字串方法手工完成，正好複習函式怎麼組合：

def slugify(name):
    cleaned = name.strip().lower()
    return cleaned.replace(" ", "-")

print(slugify("Payments API"))
# payments-api

用 uv run 執行這個檔案，就會印出 slugified 的結果。strip() 去掉前後空白、lower() 轉小寫、replace() 把空白換成連字號——三個動作串起來，包在一個有名稱的函式裡。

回傳 vs 印出：一個決定，兩種命運

以下兩個版本執行起來結果一樣：

# 版本一：回傳值
def slugify(name):
    cleaned = name.strip().lower()
    return cleaned.replace(" ", "-")

result = slugify("Payments API")

# 版本二：直接印
def slugify(name):
    cleaned = name.strip().lower()
    print(cleaned.replace(" ", "-"))

slugify("Payments API")

版本二「能動」，但它是個陷阱。差別在於資料的控制權在誰手上：

  • 回傳版本：呼叫方拿到字串，可以繼續處理——想轉大寫？slugify("Payments API").upper()。想存進資料庫、寫進測試斷言？都可以。
  • 印出版本：值變成 terminal 上的一行文字，程式裡誰也拿不到。呼叫方完全沒有選擇權。

把 print 寫在函式裡，還會讓除錯變得困難：函式應該小而專注，一個把結果印掉的函式，你沒辦法對它寫測試、沒辦法組合、也沒辦法在別的脈絡裡重用。讓函式回傳值，把「要不要印」的決定留給呼叫方。這也是為什麼 pytest 能對 slugify 直接寫 assert slugify("Payments API") == "payments-api"——前提是它有回傳值。

return 是可選的

函式不一定要有 return。沒有 return 的函式照樣能執行（例如只做副作用的函式），但 Python 會讓它回傳 None：

def greet(name):
    print(f"Hello, {name}")

result = greet("Andy")
print(result)   # None

所以如果你看到 result 是 None，第一個要檢查的通常是：這個函式是不是忘記 return 了？
