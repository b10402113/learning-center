結構化 logging 設定

用程式化設定取代 basicConfig，輸出有時間戳、等級、模組名的結構化 log

basicConfig 的限制

logging.basicConfig(level=logging.INFO) 是最快的起步方式，但它的格式固定、等級寫死在程式碼裡，不適合正式環境。正式環境通常需要：時間戳、模組名、可透過環境變數調整等級。

程式化設定 configure_logging

import logging

LOG_FORMAT = "%(asctime)s %(levelname)s %(name)s %(message)s"

def configure_logging(debug: bool = False) -> None:
    level = logging.DEBUG if debug else logging.INFO
    logging.basicConfig(level=level, format=LOG_FORMAT)

這個函式把 log 等級從參數決定，並指定一個結構化格式。之後在 app 啟動時呼叫一次即可。

格式字串拆解

佔位符說明
%(asctime)slog 發生的時間戳
%(levelname)slog 等級（INFO、DEBUG…）
%(name)slogger 名稱（通常用模組名）
%(message)s實際的 log 訊息

預期的 log 輸出

2026-09-04 10:30:15,234 INFO __main__ GET /projects/1 → 200 (12.34 ms)
2026-09-04 10:30:15,567 DEBUG app.db SELECT * FROM projects WHERE id = 1

有時間戳和模組名，log 就能被 log 聚合系統（例如 Data Dog、ELK）解析、搜尋、過濾。

在 app 啟動時呼叫

from fastapi import FastAPI
from .config import configure_logging

configure_logging(debug=True)  # 或從環境變數讀
app = FastAPI()

為什麼不用 f-string 格式化？

Python logging 使用 %s 延遲格式化（lazy formatting）：如果 log 等級被過濾掉，字串不會被格式化，節省計算。用 f-string 則無論如何都會先算好字串，浪費效能。

# 好：延遲格式化
logger.info("User %s logged in", username)

# 壞：立即格式化
logger.info(f"User {username} logged in")
