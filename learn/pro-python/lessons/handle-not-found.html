查詢不到資料時回傳 404

學習目標

當 session.get() 回傳 None 時，拋出 HTTPException(status_code=404) 回傳標準 REST 錯誤。

為什麼不能直接回傳 None？

如果 session.get() 找不到記錄，直接回傳 None：

@app.get("/projects/{project_id}")
def get_project(project_id: int, session: Session = Depends(get_session)):
    project = session.get(Project, project_id)
    return project  # 找不到時回傳 null

API 會回應 200 OK 加上 body null。客戶端不知道是「找到了但值是空」還是「根本不存在」——這違反 REST 語義。

用 HTTPException 回 404

FastAPI 提供 HTTPException，直接對應 HTTP 狀態碼：

from fastapi import HTTPException

@app.get("/projects/{project_id}")
def get_project(project_id: int, session: Session = Depends(get_session)):
    project = session.get(Project, project_id)
    if project is None:
        raise HTTPException(status_code=404, detail="Project not found")
    return project

raise HTTPException(...) 會立即停止路由執行，FastAPI 把它轉成對應的 HTTP 回應：

HTTP/1.1 404 Not Found
Content-Type: application/json

{"detail": "Project not found"}

用 is None 而不是 == None

Python 慣例用 is None 判斷空值，因為 is 比較物件身份（identity），比 == 更精確。

detail 可以帶任何 JSON 資料

detail 不只能是字串，任何 JSON 可序列化的資料都可以：

raise HTTPException(
    status_code=404,
    detail={"message": "Project not found", "project_id": project_id},
)

常見狀態碼速查

狀態碼什麼時候用
200成功讀取或回傳
201成功建立新記錄
204成功但不需要回傳 body
400請求格式錯誤
404資源不存在
409資料衝突（例如重複的唯一值）
422驗證錯誤（FastAPI 自動處理）
500伺服器內部錯誤

小結

session.get() 找不到時回傳 None，你要自己判斷並拋 HTTPException(status_code=404)。這是 REST API 的標準寫法——資源不存在就用 404，不要回 null。
