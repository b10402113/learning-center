用集中式例外處理器攔截 IntegrityError

Centralized exception handling · Step 2

學習目標

能使用 FastAPI 的 @app.exception_handler 裝飾器，建立一個全域的 IntegrityError 處理器，將資料庫衝突轉換為清晰的 JSON 回應。

集中式例外處理器的位置

在 FastAPI 裡，你可以在應用程式層級註冊一個處理器（exception handler），它會捕捉整個應用程式裡未被處理的特定例外。寫一次，所有路由都適用。

註冊處理器：@app.exception_handler

使用 @app.exception_handler(IntegrityError) 裝飾一個函式，FastAPI 就會在 IntegrityError 往上傳播時呼叫它，而不是讓它變成 500。

from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse
from sqlalchemy.exc import IntegrityError

app = FastAPI()

@app.exception_handler(IntegrityError)
async def integrity_error_handler(request: Request, exc: IntegrityError):
    return JSONResponse(
        status_code=409,
        content={"detail": "資料衝突：這筆資料已經存在。"},
    )

處理器函式接收兩個參數：request（當下的請求）和 exc（被拋出的例外）。你可以從它們身上取得足夠的資訊來建構回應。

另一個寫法：add_exception_handler

除了裝飾器，你也可以用 app.add_exception_handler(IntegrityError, handler) 註冊。兩種方式效果完全相同，裝飾器只是比較常見。

處理器何時生效？

處理器會在例外往上傳播到 FastAPI 層時介入。如果某個路由裡面已經用 try/except 把 IntegrityError 吞掉了，處理器就不會收到它。所以最好的做法是：讓例外自然傳播，由處理器統一處理。

回應的內容

處理器回傳一個 JSONResponse，狀態碼設為 409，body 裡面放一個 detail 欄位說明原因。呼叫端可以讀取這個欄位，決定如何提示使用者。

{
  "detail": "資料衝突：這筆資料已經存在。"
}

總結

用 @app.exception_handler(IntegrityError) 註冊一個回傳 409 的處理器，就能把原本會變成 500 的資料庫約束違反，轉換成對呼叫端有意義的回應。寫一次，全部路由受益。
