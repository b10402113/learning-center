Conditionals — if / elif / else

學習目標：用 if/elif/else 寫出多分支邏輯，靠縮排（而非大括號）定義程式碼區塊，並在函式裡組合條件判斷。

Why this step matters

你在 codebase 裡讀到的每一個函式，幾乎都會「看情況辦事」：參數帶什麼值，就走哪條路。條件判斷就是這個「看情況」的語法。這一步講 if/elif/else 的規則，再用一個真實的 is_overdue() 把函式和條件組合起來。

語法：三個關鍵字，只有 if 是必須的

if 條件一:
    ...
elif 條件二:
    ...
elif 條件三:
    ...
else:
    ...

規則很簡單：

  • 一定從 if 開始；elif 可以接任意多個，也可以一個都不要；else 最多一個，而且可省略。
  • 條件從上往下依序檢查，第一個成立的分支執行完，整串就結束——不會再往下比。
  • 每個關鍵字結尾都是冒號，本體靠縮排定義，跟 def 一模一樣。

縮排錯了就是錯了

Python 的分支不像 Java/JavaScript 靠大括號配對，而是靠縮排對齊。一個 else 如果沒對齊它的 if，Python 不會猜你的意思，直接報錯：

if status == "done":
    return False
        else:          # IndentationError: 沒有匹配的 if
            ...

錯誤訊息會告訴你「找不到匹配的 if 區塊」。遇到這種錯，先檢查縮排階層——這是 Python 新手（和從大括號語言轉過來的人）最常踩的坑，看起來像邏輯錯，其實是排版錯。

實戰：is_overdue()——函式裡的分支

Release tracker 裡的任務有到期日和狀態。「這筆任務逾期了嗎？」這個問題需要三層判斷，正好是一個標準的 if/elif/else 結構：

from datetime import date

def is_overdue(due_date, status):
    if due_date is None:
        return False
    elif status == "done":
        return False
    else:
        return due_date < date.today()

在 REPL 裡實測：

january_1st = date(2026, 1, 1)

is_overdue(january_1st, "not done")
# True（1 月 1 日早就過了，任務又沒做完 → 逾期）

把這個函式逐步追一遍：

  • 沒有到期日（due_date is None）？根本談不上逾期，回傳 False。
  • 已經完成了（status == "done"）？不管日期多舊都不算逾期，回傳 False。
  • 其他情況：到期日比今天早，就是逾期——due_date < date.today() 這個比較本身回傳布林值，直接 return 它。

注意最後一行的寫法：條件已經是布林值，不需要再寫 if due_date < date.today(): return True else: return False。直接回傳比較結果，一行結束。

每個分支各自獨立

這個函式還展示了一個容易誤會的點：if/elif/else 裡的三個 return「彼此沒有從屬關係」。它們不是三段連續執行的程式碼，而是三條互斥的路——哪個條件先成立，就走哪條、回傳、離開函式。剩下的分支完全不執行。

這就是「函式 + 條件」的基本形：隨著傳進來的參數不同，函式內部走不同的路、回傳不同的結果。你讀過的每一個 service 函式、每一個 FastAPI endpoint，放大來看都是這個結構的變形。
