為什麼生產環境用 logging 而不是 print？

從 print 到 logging 的第一步

場景：print 在 production 會出什麼事？

你在本地跑腳本，順手寫了幾個 print() 看變數。程式跑得好好的，你推上 CI/CD，一切正常——直到某天 log 裡出現客戶的 email 或 token。

print 的問題不是它不好，而是它沒有開關。一旦程式上線，每一行 print 都會忠實輸出，不管現在是 debug 還是 production。

print 的三個致命傷

問題printlogging
無法分級全部輸出DEBUG / INFO / WARNING / ERROR
無法關掉要刪程式碼改設定就好
沒有脈絡不知道從哪來自動帶模組名、行號

CI/CD 的 print 檢查

很多團隊的 CI 管線會跑一個靜態檢查，只要看到 print( 就擋下來。這不是找麻煩——print 在 production log 裡可能夾帶敏感資料，而且無法被 log 收集系統（Data Dog、Splunk）正確解析。

logging 的承諾

Python 標準庫 logging 提供一個統一介面：你在程式裡寫 log 呼叫，執行時再決定要不要輸出、輸出到哪、用什麼格式。開發時看 DEBUG，上線後只看 INFO 以上，全部只要改設定。
