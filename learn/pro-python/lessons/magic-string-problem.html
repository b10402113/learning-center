魔術字串問題：為什麼需要 Enum

學習目標：能說出散落在程式碼裡的「魔術字串」造成哪些問題，並解釋 Enum 如何用一組固定值解決它們。

Why this step matters

你每天都在讀別人寫的 Django/Flask 程式碼。追過狀態欄位嗎——任務是「進行中」，但資料庫裡存的字串到底是 in_progress、In Progress 還是 INPROGRESS？這一步教你認出這類痛點的名字，以及 Python 標準庫提供的解法。它會是後面所有「固定值集合」場景的地基。

現象：同一個字串，散落各處

假設你的程式裡有一個任務狀態，整個 codebase 都會用到：

def can_edit(task):
    return task.status == "in progress"     # 是這樣嗎？

def notify(task):
    if task.status == "in_progress":        # 還是這樣？
        send_email(task.owner)

# 三個月後，另一個檔案裡……
if task.status == "IN_PROGRESS":            # 全大寫？
    ...

每次要寫這個狀態，你都得先回答一連串問題：底線還是空格？一個字還是兩個字？大小寫怎麼配？答案不在手邊——你只能翻遍程式碼，找出當初是怎麼寫的，然後祈禱每個人都寫得一樣。

這個痛點有名字：魔術字串

直接寫死在程式碼裡、沒有單一定義處的字面字串，叫做魔術字串（magic string）。它「魔術」的地方在於：程式能跑，但光讀其中一行，沒有人知道這個欄位的合法值有哪些。它帶來三個具體問題：

問題實際發生什麼事
沒有自動補全編輯器幫不了你，只能靠記憶重打精確的值
拼錯不會報錯"in_progres" 是完全合法的字串，比較永遠失敗，bug 靜靜藏著
無效狀態難拒絕任何字串都能塞進 status，"banana" 也行，出事才發現

解法：Enum——一組固定不變的值

Python 標準庫的 enum 模組提供的列舉（Enum），就是為「一組固定不變的值」而生：把所有合法狀態收進一個具名類別，每個狀態是它的一個成員（member）：

from enum import StrEnum

class TaskStatus(StrEnum):
    PLANNED = "planned"
    IN_PROGRESS = "in_progress"
    DONE = "done"

之後整個程式碼庫只寫 TaskStatus.IN_PROGRESS。不用再猜拼法——合法值全部定義在同一個地方，一處就是真相。

三個問題，一次解決

回頭對照上面的表格：

  • 自動補全回來了。打 TaskStatus.，編輯器列出全部成員——用選的，不用背的。你不再需要記住 TaskStatus 的進行中到底長什麼樣。
  • 拼錯當場現形。TaskStatus.IN_PROGRES 這個成員不存在——編輯器會標出來，真的跑起來也會直接報 AttributeError。錯誤發生在寫下的那一刻，不是三個月後的 production。
  • 無效狀態更容易拒絕。合法值就只有定義裡那幾個成員，多出來的值在驗證時一眼就能擋下。

這是講師明確推薦的做法：需要固定值集合時就用它；字串類的枚舉是你最常見到的那一種。

這是之後一切的基礎

「一組固定值」接下來會不斷出現：任務狀態、優先權、資料庫欄位允許的值。下一步深入 StrEnum 的定義細節——為什麼非要繼承不可、在 REPL 裡怎麼檢查成員——之後再用 auto() 連重複的值指派都省掉。
