命名 logger 與層級：getLogger(__name__) 的慣例

每個模組擁有自己的 logger

慣例：用 __name__ 當 logger 名字

在每個模組最上方，寫這一行：

import logging

logger = logging.getLogger(__name__)

__name__ 會自動被設成模組路徑，例如 routers.projects。log 輸出就會顯示訊息來自哪個模組，不再全是 root。

層級繼承

Logger 名字用點號分隔，形成一層一層的結構：

routers.projects
routers.tasks
routers          ← 上面兩個的父層
root             ← 最頂層

當你設定 routers 的等級，routers.projects 和 routers.tasks 都會跟著改。這讓「整個 routers 套件用 DEBUG」這種批量設定變成可能。

實際使用

# routers/projects.py
import logging

logger = logging.getLogger(__name__)

@router.get("/{project_id}")
def get_project(project_id: int):
    logger.info("取得 project %s", project_id)
    ...

輸出：

INFO:routers.projects:取得 project 42

什麼時候用 root，什麼時候用命名 logger？

規則是：應用程式碼用命名 logger，第三方套件用 root。套件作者通常會用 logging.getLogger(__name__)，所以你只要設定 root，就能控制所有套件的 log 等級。
