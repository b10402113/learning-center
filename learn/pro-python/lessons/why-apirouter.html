為什麼需要 APIRouter？

理解單體 main.py 的痛點與 APIRouter 的定位

單體 main.py 的成長痛

剛開始寫 FastAPI 時，把所有端點放在 main.py 是最快的起步方式。一個檔案搞定路由、依賴注入、例外處理，啟動伺服器就能看到結果。但當端點從 5 個變成 20 個、50 個，這個檔案會開始出現幾個明顯的問題：

  • 瀏覽困難：滾動一條漫長的檔案，很難一眼看出 API 提供了哪些功能。
  • 重構風險：修改一個端點時，可能意外動到旁邊的端點或全域設定。
  • 協作衝突：多人同時開發不同功能，全部擠在同一個檔案容易產生合併衝突。

APIRouter 的定位

FastAPI 提供 APIRouter 來解決這個問題。它本質上是一個「輕量版的 FastAPI 應用程式」——你可以用同樣的裝飾器語法定義路由，但這些路由先掛在路由器上，最後再透過 app.include_router() 把它們掛回主應用程式。

比喻：把 main.py 想成一本書的目錄頁。單體檔案像是把所有章節內容直接寫在目錄頁上；APIRouter 則是把各章節拆成獨立檔案，目錄頁只需要列出章節名稱與頁碼。

APIRouter 的兩個關鍵參數

參數 用途 效果
prefix 設定路由前綴 APIRouter(prefix="/projects") 會讓底下所有端點自動掛在 /projects 路徑下
tags 設定分組標籤 Swagger UI 會把同標籤的端點歸在同一區，方便瀏覽

重構前後對照

重構前，所有端點都掛在 app 上：

@app.get("/projects")
def list_projects():
    ...

@app.get("/projects/{project_id}")
def get_project(project_id: int):
    ...

重構後，端點改掛到路由器，再用 include_router 接回主程式：

router = APIRouter(prefix="/projects", tags=["projects"])

@router.get("")
def list_projects():
    ...

@router.get("/{project_id}")
def get_project(project_id: int):
    ...

# main.py
app.include_router(router)

URL 路徑完全沒變，但程式碼的責任被拆分了：路由器負責定義端點，主程式負責組合。
