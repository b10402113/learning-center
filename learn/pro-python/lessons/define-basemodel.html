定義 Pydantic 模型與型別欄位

能獨立定義一個 Pydantic BaseModel 子類別，並正確宣告帶有型別的欄位。

從問題開始

假設你在開發一個 API，需要回傳一個專案的資料。這個專案有 id、name 和 slug 三個欄位。如果只用 Python 字典，你無法保證呼叫端傳回的欄位名稱正確、型別無誤。萬一某個地方不小心把 id 寫成字串，API 消費者可能會收到錯誤的資料格式。

Pydantic 的 BaseModel 就是為了解決這個問題：它讓你用類別的方式定義資料結構，每個欄位都有明確的型別，並且在建構時自動驗證。

定義第一個模型

要使用 Pydantic，首先匯入 BaseModel，然後建立一個繼承它的子類別。每個欄位都用型別提示（type hint）宣告：

from pydantic import BaseModel

class ProjectRead(BaseModel):
    id: int
    name: str
    slug: str

這段程式碼做了三件事：

  1. 宣告 ProjectRead 是一個 Pydantic 模型。
  2. 定義三個欄位，並指定它們的型別。
  3. 讓 Pydantic 在建立物件時自動檢查這些型別。

建立物件與序列化

定義好模型之後，你可以直接傳入資料來建立實例（instance）：

project = ProjectRead(id=1, name="My Project", slug="my-project")

Pydantic 模型內建了 .model_dump() 方法，可以把它轉回字典，方便 JSON 序列化：

project.model_dump()
# {'id': 1, 'name': 'My Project', 'slug': 'my-project'}

這個能力在 FastAPI 特別重要——API 回傳的回應通常需要是 JSON 格式，而 Pydantic 模型可以無縫轉換。

為什麼不用 dataclass？

Python 內建的 @dataclass 也能定義資料容器，但它不會在執行期驗證型別。如果你傳入一個字串給 id: int，dataclass 會默默接受，直到後續程式碼出錯才發現問題。Pydantic 則在物件建立的當下就檢查，讓錯誤提早曝光。
