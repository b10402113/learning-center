Variable type annotations

Node 05 · Step 1 of 4 · pro-python

Learning goal

Use the name: type = value syntax to annotate variables, and understand what hints actually do at runtime.

Why annotate variables?

You already know how to annotate function parameters and return types. The same colon syntax works on plain variables inside a function body. It tells readers — and tools like mypy — what shape a variable is expected to hold.

The syntax

count: int = 0
name: str = "Untitled"
rates: list[float] = []

The pattern is name: type = value. The colon goes between the variable name and the type; the assignment works exactly as before.

Hints are not enforcement

Type hints are not checked at runtime. Python will happily let you reassign a typed variable to a completely different type:

count: int = 0
count = "urgent"   # No error — Python ignores the hint at runtime

The hint is a promise to readers and static analyzers, not a runtime constraint. If you want enforcement, you need a tool like mypy or Pydantic.

When to annotate

Annotate when the type isn't obvious from the right-hand side:

  • Empty collections: items: list[str] = []
  • Complex containers: cache: dict[str, int] = {}
  • Values that start as None and get filled later

Simple cases like name = "Alice" rarely need an annotation — the type is already clear.
