Node 02 — Step 3/3 · 專案設定

Python 版本管理與 uv sync

學習目標：理解 .python-version 檔案的作用，並能用 uv sync 建立虛擬環境。

為什麼需要釘選 Python 版本？

你的電腦可能裝了多個 Python 版本。系統內建的可能是 3.9，你自己裝的可能是 3.12，而這個專案需要 3.14。如果你不小心用了錯誤的版本，可能會遇到詭異的錯誤——某些語法不存在、某些函式行為不同。

.python-version 檔案就是為了解決這個問題。它告訴 UV：「這個專案要用 Python 3.14」。當你執行 uv run 或 uv sync 時，UV 會確保使用正確的版本。

.python-version 檔案

打開你專案根目錄下的 .python-version 檔案，內容應該只有一行：

3.14

這個檔案的作用：

  • uv sync 會讀取它，確保虛擬環境使用 3.14
  • uv run 會讀取它，確保執行腳本時使用 3.14
  • pyenv 也會讀取它（如果你安裝了 pyenv）
💡 重點：.python-version 是給命令列工具看的。大多數 IDE（VS Code、PyCharm）會偵測到它，但有時你需要手動設定 IDE 的 Python 解釋器路徑。

IDE 注意事項

雖然 .python-version 對命令列工具很有效，但 IDE 的行為不一致：

  • VS Code：通常會自動偵測 .python-version，並在右下角顯示正確的 Python 版本
  • PyCharm：可能會嘗試用自己的設定覆蓋。如果 PyCharm 堅持用錯誤的版本，你需要手動到設定裡指定 Python 解釋器

如果你發現終端機和 IDE 使用不同版本，檢查 IDE 的 Python 解釋器設定。

uv sync — 建立虛擬環境

當你克隆一個新專案，或剛執行完 uv init，你需要建立虛擬環境。虛擬環境是一個獨立的 Python 環境，讓每個專案的依賴不會互相干擾。

執行：

uv sync

uv sync 會做這些事：

  1. 讀取 .python-version 確認 Python 版本
  2. 建立 .venv/ 虛擬環境（如果不存在）
  3. 讀取 pyproject.toml 的 dependencies 列表
  4. 安裝所有依賴到虛擬環境
  5. 產生或更新 uv.lock 鎖定精確版本

完成後，你可以用 uv run python main.py 執行程式碼，UV 會自動使用虛擬環境中的 Python。

uv.lock — 鎖定版本

uv sync 會產生一個 uv.lock 檔案。這個檔案記錄了每個依賴的精確版本號（例如 fastapi==0.115.0 而不是 fastapi>=0.100）。

為什麼需要鎖定？因為 pyproject.toml 裡寫的是版本範圍（>=0.100），不同時間安裝可能會拿到不同版本。uv.lock 確保每次安裝都拿到完全一樣的版本，避免「在我電腦上可以跑」的問題。

💡 重點：把 uv.lock 提交到 Git。這樣團隊成員和 CI 環境都會安裝完全相同的依賴版本。

小結

.python-version 釘選 Python 版本，uv sync 建立虛擬環境並安裝依賴，uv.lock 鎖定精確版本。這三個工具一起確保你的專案在任何環境都能一致執行。

現在你已經有一個完整的 UV 專案：pyproject.toml 定義身份、.python-version 釘選版本、uv.lock 鎖定依賴。下一步，我們要開始寫第一個 FastAPI 應用程式。
