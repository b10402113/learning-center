Comprehensions：一行完成轉換與過濾

學習目標：能把簡單的 for 迴圈改寫成帶過濾條件的 list comprehension，認識 dict/set comprehension、generator 與 zip，並判斷何時該退回普通迴圈。

Why this step matters

Comprehension（推導式）是 Python 最招牌的功能之一：把「簡單、重複」的迴圈收進一行，從既有的集合建成新的集合。你在 crud 層會天天看到 [t["title"] for t in tasks if not t["done"]] 這種一行——讀不懂它，讀 codebase 就會處處卡住；會寫它，很多函式瞬間變短。這一步從你已經會的 for 迴圈出發，一行一行把它變過去。

從 for 迴圈到一行

任務：把一排專案名稱轉成 URL slug（還記得 slugify 嗎）。用 for 迴圈是這樣：

project_names = ["Payments API", "Ops Console", "Portal"]
slugs = []
for name in project_names:
    slugs.append(name.lower().replace(" ", "-"))

Comprehension 把整個「建 list → 迴圈 → append」收成一行：

slugs = [name.lower().replace(" ", "-") for name in project_names]
# → ['payments-api', 'ops-console', 'portal']

讀法是固定的：左邊是輸出元素的長相（每個元素經過什麼轉換），右邊是來源迴圈（從哪個集合、用什麼變數名拿出來）。左邊的邏輯可以相當複雜——但先記住這個骨架：[轉換 for 變數 in 集合]。

過濾：把 if 放到最後

第二個任務：從任務清單裡抓出「還沒做完」的標題。先看一個錯的版本——它其實沒有過濾：

tasks = [
    {"title": "Write docs", "done": True},
    {"title": "Fix login bug", "done": False},
    {"title": "Deploy API", "done": False},
]

[t["title"] for t in tasks]              # 沒有過濾：三個標題全進來
[t["title"] for t in tasks if not t["done"]]
# → ['Fix login bug', 'Deploy API']      # 過濾：只要未完成的

條件放在整個推導式的最後：[轉換 for 變數 in 集合 if 條件]。條件不成立的元素直接被跳過。順帶複習 dict 存取：t["title"] 是中括號存取——key 一定存在時用它；key 可能缺失時，換上一步學的 t.get("title")。

拿 comprehension 算數

「未完成的任務有幾個？」——每個未完成任務貢獻一個 1，通通加起來：

sum(1 for t in tasks if not t["done"])
# → 2

注意這裡連方括號都省了：comprehension 直接當參數傳進 sum()。同一家族還有兩個常用的內建：any() 檢查「是不是至少一個符合」、all() 檢查「是不是全部符合」：

any(not t["done"] for t in tasks)   # 還有未完成的嗎？→ True
all(t["done"] for t in tasks)       # 全部都完成了嗎？→ False

Generator comprehension：懶惰版本

方括號版會一次把整個 list 建在記憶體裡。資料小的時候無所謂；資料大的時候，把方括號換成括號，就得到 generator comprehension：

gen = (1 for t in tasks if not t["done"])
print(gen)        # <generator object ...>——看不到內容！

sum(1 for t in tasks if not t["done"])   # 餵給 sum() 照常工作

generator 不預先建表，而是被要求的當下才產生下一個值，值用完就結束——所以你沒辦法像 list 那樣把它印出來、索引它。它適合「值只需要走一遍」的場景：sum()、any()、all()、只跑一次的 for 迴圈。要走多遍、要保留結果，就用回 list comprehension。原則很簡單：一次性消費用 generator（省記憶體），要留下來用就 list。

dict comprehension、set comprehension 與 zip

Comprehension 不是 list 的專利——換括號就換容器，只是各自的語法略有出入：

{name.lower() for name in project_names}          # set comprehension：去重的轉換結果
{t["title"]: t["done"] for t in tasks}            # dict comprehension：key: value 的轉換結果

最後一個好用的配角是 zip：把兩個 list 依位置配對（第 0 個對第 0 個、第 1 個對第 1 個……），配好的東西餵給 dict() 就快速變出一個字典：

keys = ["name", "slug"]
values = ["Payments API", "payments-api"]
dict(zip(keys, values))   # → {"name": "Payments API", "slug": "payments-api"}

何時不要用

Comprehension 的適用條件，一次列清楚：

  • 你在轉換資料（每個元素經過同樣的處理）
  • 邏輯短——可能加一個 if 過濾
  • 一行讀起來清楚

經驗法則：超過兩行就退回普通 for 迴圈。Comprehension 是讓短邏輯變清晰的工具，不是把長邏輯硬塞成一行的方法——可讀性輸了，它就失去了存在意義。

練習驗收

拿出紙筆或開個 REPL，用這一步的東西做兩件事（這正是課程練習的前兩題）：

  1. 把一個「for 迴圈 + append」的轉換，改寫成一行 comprehension。
  2. 從 tasks 這個 list of dicts 裡，抓出所有未完成任務的標題。

寫完對照：[name.lower().replace(" ", "-") for name in project_names] 與 [t["title"] for t in tasks if not t["done"]]。兩行都讀得順、寫得出，這個節點的目標就達成了。（練習的另外兩題——raise/except 與 dataclass——屬於各自的節點。）
