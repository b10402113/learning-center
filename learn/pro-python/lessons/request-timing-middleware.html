請求計時 middleware

在 middleware 裡為每個請求計時，並輸出結構化 log 行

目標

建立一個 FastAPI middleware，記錄每個請求的方法、路徑、狀態碼和花費時間（毫秒）。這些 log 行可以讓你掌握 API 的效能，並在出問題時快速定位。

完整程式碼

import time
import logging
from fastapi import Request

logger = logging.getLogger(__name__)

@app.middleware("http")
async def log_requests(request: Request, call_next):
    start_time = time.perf_counter()
    response = await call_next(request)
    duration_ms = (time.perf_counter() - start_time) * 1000
    logger.info(
        "%s %s → %s (%.2f ms)",
        request.method,
        request.url.path,
        response.status_code,
        duration_ms,
    )
    return response

逐步拆解

  1. 記錄開始時間：time.perf_counter() 是高解析度計時器，適合測量短時間間隔。
  2. 呼叫端點：await call_next(request) 把請求傳給路由端點，等它跑完拿到 response。
  3. 計算耗時：用結束時間減去開始時間，乘以 1000 轉換成毫秒。
  4. 輸出 log：用 logger.info() 搭配格式化字串，把方法、路徑、狀態碼、耗時寫進 log。

為什麼用 time.perf_counter()？

time.time() 會受系統時鐘調整影響（例如 NTP 同步），可能導致測量不準確。time.perf_counter() 是單調遞增（monotonic）的計時器，專門用來測量時間間隔，不會往回跳。

預期的 log 輸出

INFO __main__: POST /projects → 201 (45.67 ms)
INFO __main__: DELETE /projects/1 → 204 (8.90 ms)

Middleware vs Exception Handler

MiddlewareException Handler
執行時機每個請求前後只有抛出例外時
適用場景記錄時間、修改標頭、驗證捕捉 IntegrityError 回傳 409
