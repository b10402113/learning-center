List tasks with conditional filters

學習目標：Build dynamic queries with keyword-only filter parameters and immutable where-clauses

Why this step matters

真實世界的 API 幾乎不會只用固定條件查詢。Task list 端點要讓呼叫方自己決定要按什麼篩選：專案、狀態、優先級、逾期與否，全部可選。這一節教你用「條件式 where-clause 堆疊」在 SQLModel 裡動態組裝查詢。

The method signature

list_tasks 的第一個參數是 session，後面的篩選條件全部用 * 隔開，強制變成 keyword-only 參數。每個參數預設都是 None，代表「不套用這個篩選」。

def list_tasks(
    session: Session,
    *,
    project_id: int | None = None,
    project_slug: str | None = None,
    status: TaskStatus | None = None,
    priority: TaskPriority | None = None,
    overdue_only: bool = False,
) -> list[Task]:
    ...

這種簽章讓呼叫方可以只傳需要的篩選，不需要把每個條件都填滿。

Conditional where-clause stacking

核心 pattern 是「先建基底查詢，再按需堆疊 where」：

statement = select(Task)

if project_id is not None:
    statement = statement.where(Task.project_id == project_id)

if project_slug is not None:
    statement = statement.join(Project).where(Project.slug == project_slug)

if status is not None:
    statement = statement.where(Task.status == status)

if priority is not None:
    statement = statement.where(Task.priority == priority)

if overdue_only:
    statement = statement.where(Task.due_date != None)
    statement = statement.where(Task.due_date < date.today())
    statement = statement.where(Task.status != TaskStatus.done)

每次 where 都回傳新 statement，舊的保持不動。這種 immutable 寫法讓邏輯清晰又好測試。

Why keyword-only matters

* 之後的參數「必須」用關鍵字指定，不能按位置傳。這避免了一長串 positional arguments 難以閱讀的問題，也讓未來新增篩選條件不會破壞現有呼叫。

The overdue filter pattern

「逾期」本質上是三個條件的組合：due_date 不是空值、due_date 早於今天、狀態不是已完成。全部用 AND 串起來，一次查詢解決。
