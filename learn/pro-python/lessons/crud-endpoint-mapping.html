CRUD methods and endpoint mapping

學習目標：Map CRUD operations to FastAPI endpoints following the project router pattern

Why this step matters

Task router 的 endpoint 形狀和 project router 幾乎一樣。學好這一步，等於把整個 CRUD + router 的 pattern 複用一遍。之後要加新的實體（entity），照著這套 pattern 走就行。

The CRUD methods you need

Task CRUD 需要五個方法，每個對應一個 endpoint：

CRUD methodHTTP verbEndpoint purpose
createPOST建立新 task
readGET /{task_id}讀取單筆 task
listGET列出 tasks（帶 filter）
updatePATCH /{task_id}更新 task 欄位
deleteDELETE /{task_id}刪除 task

每個方法都接受 session 作為第一個參數，其他參數用 keyword-only（等等會看到）。

Endpoint mapping pattern

FastAPI 的 decorator 把 HTTP verb 和路徑綁定到 function：

@router.post("/tasks", response_model=TaskRead, status_code=status.HTTP_201_CREATED)
def create_task(
    task_in: TaskCreate,
    session: SessionDep,
    project: ProjectDep,
):
    return crud.create_task(session=session, project=project, task_in=task_in)

關鍵：endpoint function 本身幾乎不做邏輯，只是把參數傳進 crud module。這讓 route layer 保持精簡，真正的工作都在 crud.py 裡。

Dependencies in the signature

Task endpoint 需要同時拿到 session 和 project，所以在 function signature 裡一起宣告：

session: SessionDep,
project: ProjectDep,

FastAPI 會自動呼叫這兩個 dependency 的函式，把回傳值注入進來。task_dep 則用在 read / update / delete 這三個需要拿到既有 task 的 endpoint。

Why this separation helps

把 HTTP 處理（status code、response model）和資料庫操作分開，有兩大好處：測試時可以直接測 crud.py 不必跑 API；換框架時 crud.py 幾乎不用改。
