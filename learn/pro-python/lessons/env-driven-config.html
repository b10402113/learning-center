環境變數控制 log 等級

用 .env 檔和 config.py 讓開發環境輸出 DEBUG、正式環境保持 INFO，程式碼不用改

目標

本機開發時看到詳細的 DEBUG 訊息，正式環境只顯示 INFO 以上。要做到這件事，log 等級必須由環境變數決定，而不是寫死在程式碼裡。

config.py 助手

import os

def get_debug() -> bool:
    return os.environ.get("DEBUG", "false").lower() == "true"

def get_database_url() -> str:
    return os.environ.get(
        "DATABASE_URL",
        "postgresql://user:pass@localhost:5432/app",
    )

config.py 把「讀環境變數」集中成一個地方。os.environ.get("DEBUG", "false") 有就用環境變數的值，沒有就用預設值 "false"。

.env 檔案

DEBUG=true
DATABASE_URL=postgresql://dev:dev@localhost:5432/app

.env 檔放在專案根目錄，記錄本機開發設定。VS Code 可以設定在開啟 Python terminal 時自動載入 .env，這樣你不用手動 export DEBUG=true。

把 debug 傳進 configure_logging

from .config import get_debug

configure_logging(debug=get_debug())

這樣本機開發時 DEBUG=true，log 等級就是 DEBUG；正式環境沒設 DEBUG 或設為 false，log 等級就是 INFO。

設定 VS Code 自動載入 .env

在 VS Code 的 workspace settings 裡加上：

{
  "python.terminal.activateEnvironment": true,
  "python.envFile": "${workspaceFolder}/.env"
}

之後每次打開 VS Code 的 terminal，.env 裡的變數會自動載入，get_debug() 就能讀到 DEBUG=true。

.env 不要送進版本控制

.env 通常包含資料庫密碼、API key 等敏感資訊。一定要在 .gitignore 加上一行 .env，避免密碼被 push 到 GitHub。

完整流程

  1. 開發者在本機建立 .env，寫入 DEBUG=true
  2. VS Code 自動載入 .env
  3. get_debug() 回傳 True
  4. configure_logging(debug=True) 設定 level=DEBUG
  5. 正式環境沒設 DEBUG，預設 level=INFO
