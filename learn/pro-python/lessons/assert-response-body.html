驗證 response.json() 的內容與結構

能從 response.json() 取出資料，並用 assert 驗證回應內容是否符合預期。

為什麼要驗證回應內容？

只驗證狀態碼為 200 其實不夠。一個端點可能回傳 200 但內容是錯的——例如空陣列、錯誤的欄位、或者少了一筆資料。API 測試的標準模式是同時驗證狀態碼與回應主體（response body），這樣才能確認端點「不但活著，而且回傳正確的資料」。

從狀態碼延伸到回應內容

之前的測試只檢查狀態碼：

def test_list_projects():
    response = client.get("/projects")
    assert response.status_code == 200

現在加上回應內容的斷言：

def test_list_projects():
    response = client.get("/projects")
    assert response.status_code == 200
    assert len(response.json()) == 3

response.json() 會將回應主體解析為 Python 資料結構（通常是 list 或 dict），這樣你就可以對它做各種斷言。

回應內容斷言的常見模式

斷言 它驗證什麼 適用情境
assert len(response.json()) == N 回應陣列有 N 筆資料 列表端點，確認筆數正確
assert response.json()["name"] == "API v2" 回應物件的某個欄位符合預期 單一資源端點，確認欄位值
assert "api-v2" in response.json()["slug"] 回應內容包含特定字串 模糊比對，不用精確相等
assert response.json() == expected_dict 整個回應完全符合預期的 dict 結構簡單、內容固定的端點

常見錯誤：忘記 .json() 會回傳什麼

response.json() 回傳的是 Python 資料結構，不是 JSON 字串。所以你不能這樣寫：

# 錯誤：拿 dict 當字串比對
assert response.json() == '{"name": "API v2"}'

# 正確：直接比對 Python dict
assert response.json() == {"name": "API v2"}

重點回顧

  • response.json() 將回應主體解析為 Python list 或 dict
  • 標準 API 測試模式：同時驗證 status_code 與回應內容
  • 列表端點常用 len(response.json()) 確認筆數
  • 單一資源端點常用 response.json()["欄位"] 確認欄位值
  • 比對時記得用 Python 資料結構，不要轉成 JSON 字串
