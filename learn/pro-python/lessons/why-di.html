為什麼需要依賴注入？

學習目標

理解依賴注入解決了什麼問題：手動管理資料庫 session 的生命週期容易遺漏 commit 或 close，導致連線洩漏與資料不一致。

手動管理 session 的風險

現在你已經會寫 CRUD 端點了，但每次都要自己手動拿到 session、手動 commit、手動 close。看起來還行，但只要一個端點忘了 close，資料庫連線就會洩漏；忘了 commit，資料就沒寫進去。當端點變多，這些生命週期的細節會變成隱藏的炸彈。

先看看沒有 DI 的時候，一個典型的端點長什麼樣子：

@app.get("/projects/{project_id}")
def get_project(project_id: int):
    session = Session(engine)
    try:
        project = session.get(Project, project_id)
        if project is None:
            raise HTTPException(status_code=404)
        return project
    finally:
        session.close()

你拿到 session 之後，必須確保不管發生什麼事，session 都要被關掉。如果中間出了例外，你還得決定要不要 rollback。這些邏輯跟真正的業務無關，但每一行都在分散注意力。

把生命週期交給框架

依賴注入（Dependency Injection，DI）把「資源怎麼來、怎麼結束」這件事從端點裡面抽出來，交給框架管理。FastAPI 的 DI 系統讓你在端點函式上宣告「我需要一個資料庫 session」，框架就會在請求進來時自動建立 session、在請求結束時自動清理，你不需要自己寫 try/finally。

現在把 session 的建立和關閉交給 FastAPI：

@app.get("/projects/{project_id}")
def get_project(project: ProjectDep):
    return project

端點裡面只剩下真正的業務邏輯：查詢、判斷、回傳。

DI 帶來的好處

DI 不只是少寫幾行 code。它改變了端點的責任邊界：端點只負責「拿到資源之後要做什麼」，資源的生命週期交給框架。這樣一來：

  • 測試的時候你可以注入假資源，不需要真的連資料庫
  • 部署的時候你可以換成連線池，端點本身都不用改
  • 生命週期邏輯集中管理，不會遺漏 commit 或 close
