frozen=True 與不可變值物件

學習目標：能解釋 frozen=True 如何讓 dataclass 實體變成不可變物件，以及這種不可變性在設計值物件時為什麼有用。

預設情況下，dataclass 是可變的

目前為止，我們寫的 @dataclass 實體都可以事後修改屬性：p.name = new_name 完全合法。大多數時候這很方便的，但有時候這會帶來麻煩。

舉例來說，你把一個實體放進 set 裡，或者當作 dict 的 key，事後又改了其中一個欄位，會發生什麼事？雜湊值（hash value）變了，但容器不知道，結果就是找不到那個物件，或者出現不一致的狀態。

frozen=True 的意思

在 @dataclass 裝飾器加上 frozen=True，就會讓這個類別的實體在建構之後變成不可變（immutable）：任何試圖修改屬性的動作都會直接拋出 FrozenInstanceError。

from dataclasses import dataclass

@dataclass(frozen=True)
class Coordinate:
    x: float
    y: float
>> c = Coordinate(1.0, 2.0)
>>> c.x = 3.0
dataclasses.FrozenInstanceError: cannot assign to field 'x'

這就像 Python 的內建型別 tuple 或 frozenset 一樣，一旦建立就不能更動。任何你以為在修改它的動作，其實都是在建立一個全新的實體。

什麼是不可變性帶來的好處

不可變物件最大的價值是**安全**：你不用擔心某個函式偷偷改了你的資料，也不用擔心多執行緒環境下同時修改造成競爭條件（race condition）。只要物件被建立，它的狀態就永遠固定了。

第二個好處是可當**值物件（Value Object）**使用。所謂值物件，就是它的身份（identity）是由它的值來決定的，不是由它在記憶體的位置決定。兩個 Coordinate(1.0, 2.0) 應該被視為相同的東西，就像兩個整數 5 相等一樣。frozen=True 的 dataclass 正好符合這個語意：值一樣就是一樣，而且你不會意外動到它。

frozen 實體可以當 dict key 或放進 set

Python 要讓一個物件能放進 set 或當 dict key，它必須是 hashable 的。一般的 dataclass 實體是 unhashable 的，但 frozen=True 的實體會自動產生 __hash__ 方法，讓它變成 hashable。

@dataclass(frozen=True)
class Coordinate:
    x: float
    y: float

points = {Coordinate(1.0, 2.0), Coordinate(3.0, 4.0)}
重點：frozen=True 不只是防止修改，它還讓你的值物件可以安全地用在需要雜湊的容器裡。

如果需要「修改」frozen 實體呢？

既然不能修改，那如果真的要得到一個狀態不同的實體，該怎麼辦？dataclass 提供了一個函式 dataclasses.replace()，它會建立一個新實體，並允許你覆蓋部分欄位：

from dataclasses import replace

c1 = Coordinate(1.0, 2.0)
c2 = replace(c1, x=3.0)  # 建立一個新實體，x 改了，y 不變

這就像 tuple 沒有 append 一樣，你要嘛建一個新的，嘛就用 replace 這種顯式的「建立副本再改」的方式。

什麼時候該用 frozen

情境建議
座標、貨幣金額、日期範圍等值物件用 frozen=True
主要承載資料，但經常需要修改欄位不用 frozen
物件會被放進 set 或當 dict key用 frozen=True
多執行緒下共用的資料優先考慮 frozen=True
注意：frozen=True 是淺層的不可變。如果你的欄位是一個 mutable 物件（例如 list），那個 list 裡面的內容仍然可以被修改。frozen 只限制屬性本身不能重新指派。
