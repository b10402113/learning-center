Node 04 — Step 3/3 · Type hints for functions

Keyword-only arguments via `*` separator

學習目標

理解 * 在函式參數列表中的作用：強制其後的參數必須用關鍵字傳入，不能依照位置傳入。

位置參數 vs 關鍵字參數

在講 * 之前，先快速複習兩種傳參數的方式。假設有一個函式：

def create_user(name, email, role):
    return {"name": name, "email": email, "role": role}

你可以用位置傳入：

create_user("Alice", "alice@example.com", "admin")

也可以用關鍵字傳入：

create_user(name="Alice", email="alice@example.com", role="admin")

位置傳入的問題是：三個字串排在一起，你很容易搞錯順序。"admin" 還是 "alice@example.com"？傳錯了不會報錯，但資料是錯的。

* 的作用

在參數列表裡放一個單獨的 *，它會把參數分成兩部分：* 之前的參數可以依照位置或關鍵字傳入；* 之後的參數必須用關鍵字傳入。

def create_user(name, email, *, role):
    return {"name": name, "email": email, "role": role}

這樣呼叫就合法：

create_user("Alice", "alice@example.com", role="admin")

這樣呼叫會報錯：

create_user("Alice", "alice@example.com", "admin")

Python 會丟出：

TypeError: create_user() takes 2 positional arguments but 3 were given

* 本身不是參數——它是一個分隔符。它不接受任何值，只是告訴 Python：「後面的參數請用關鍵字傳入。」

為什麼要這樣設計？

兩個主要原因：

  1. 防止位置參數搞錯：當函式有多個相同型別的參數時，位置傳入很容易弄錯順序。強制關鍵字傳入，就能避免這種 bug。
  2. 提升 API 可讀性：呼叫方在閱讀程式碼時，能清楚看到每個參數的意義。create_user("Alice", "alice@example.com", role="admin") 比 create_user("Alice", "alice@example.com", "admin") 更容易理解。

FastAPI 和其他現代框架大量使用這個語法，所以你在讀框架源碼時會很常看到 *。

跟 type hint 一起用

* 和 type hint 可以混用。Hint 寫在參數名後面，* 放在你想強制關鍵字化的參數之前：

def create_user(name: str, email: str, *, role: str) -> dict:
    return {"name": name, "email": email, "role": role}

注意 * 後面的參數還是有 type hint，只是呼叫時一定要寫 role="admin"。

進階：* 搭配預設值

* 後面的參數可以有預設值，也可以沒有。有預設值的選擇性參數，通常放在 * 後面：

def create_user(name: str, email: str, *, role: str = "viewer", active: bool = True) -> dict:
    return {"name": name, "email": email, "role": role, "active": active}

這樣呼叫時，role 和 active 都可以省略，但如果要傳就必須用關鍵字：

create_user("Alice", "alice@example.com")
create_user("Alice", "alice@example.com", role="admin")
create_user("Alice", "alice@example.com", role="admin", active=False)

常見錯誤

把 * 當成參數傳值

# 錯誤：把 "admin" 當成 * 的值
create_user("Alice", "alice@example.com", *, "admin")

* 是語法分隔符，不是參數。你不能在呼叫時對 * 做任何事。

忘記用關鍵字傳入

# 錯誤：role 在 * 後面，必須用關鍵字
create_user("Alice", "alice@example.com", "admin")

這是最常見的錯誤。記住：* 之後，全部用關鍵字。

小結

單獨的 * 在參數列表中是一個分隔符，強制其後的參數必須用關鍵字傳入。它不是一個參數，不接受任何值。這個語法在 FastAPI 和其他框架中非常常見，能防止位置參數搞錯順序，也提升了 API 的可讀性。到這裡，Node 04 的三個步驟都完成了——你現在能寫出有完整 type hint 的函式，理解 hint 不會在執行時驗證，也知道怎麼用 * 強制關鍵字參數。
