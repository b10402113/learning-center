Generic collection types

Node 05 · Step 2 of 4 · pro-python

Learning goal

Use list[int], dict[str, int], and tuple[str, ...] to describe the contents of collections.

Beyond "a list"

Saying items: list tells the reader almost nothing. Generic types let you say what's inside the container: list[str] means "a list of strings." This is the difference between "a box" and "a box of screws."

The three you'll use most

# A list of integers
scores: list[int] = [1, 2, 3]

# A dict with string keys and int values
ages: dict[str, int] = {"alice": 30, "bob": 25}

# A tuple of fixed length — first item str, second item int
pair: tuple[str, int] = ("alice", 30)

# A tuple of variable length — all items are str
names: tuple[str, ...] = ("alice", "bob", "carol")

list, dict, tuple are the built-in generic types. The square brackets hold the type arguments — one for list, two for dict, and either fixed positions or ... for tuple.

Nested generics

Generics nest naturally. A dict mapping strings to lists of ints reads left to right:

groups: dict[str, list[int]] = {
    "odd": [1, 3, 5],
    "even": [2, 4, 6],
}

Don't panic at the depth — read it as "dict of str to list of int."
