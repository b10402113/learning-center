安裝與設定 Alembic

把 Alembic 裝進專案，並理解 env.py、script.py.mako 與 alembic.ini 各自負責什麼，讓它知道去哪找資料庫與 SQLModel 定義。

為什麼需要 Alembic？

你的 FastAPI 應用程式已經能跑起來了，但每次重啟伺服器，資料就消失——因為之前用的是模擬資料。現在你要接上真正的 Postgres 資料庫，用 SQLModel 定義表格結構。問題是：當你想修改表格結構時（例如新增一個欄位），該怎麼把變更安全地套用到資料庫，同時保留現有的資料？

這就是 Alembic 的工作。它是 SQLAlchemy 生態系的遷移（migration）工具，負責追蹤你對資料模型所做的每一次變更，並把這些變更翻譯成資料庫看得懂的 SQL 語句。

安裝與初始化

首先，把 Alembic 和 pydantic-settings 加進專案依賴：

uv add alembic pydantic-settings

接著在專案根目錄執行初始化指令：

alembic init alembic

這會在專案裡建立一個 alembic/ 目錄和一個 alembic.ini 設定檔。

三個關鍵檔案

Alembic 初始化後有三個檔案需要你理解並設定：

alembic.ini

Alembic 的主要設定檔，儲存資料庫連線 URL 和腳本位置。你不需要每次手動輸入資料庫位置，它會從這裡讀取。

env.py

每次執行 Alembic 指令時都會跑的 Python 腳本。它負責：

  • 讀取你的資料庫 URL（通常從設定或環境變數來）
  • 匯入 SQLModel 的 metadata，這樣 Alembic 才知道你定義了哪些表格
  • 設定遷移的執行環境

預設的 env.py 不會知道你的 SQLModel 定義在哪，你必須手動修改它。

script.py.mako

遷移檔的樣板（template）。每次產生新的遷移檔時，Alembic 會根據這個樣板產生 Python 程式碼。預設的樣板不會 import SQLModel，但你可以修改它，讓每次產生的遷移檔都自動加上必要的匯入，不用你每次手寫。

設定 env.py 的關鍵步驟

要讓 Alembic 認識你的專案，env.py 通常需要：

  1. 匯入你的 SQLModel 定義（或含有 SQLModel.metadata 的模組）
  2. 從你的設定（例如用 pydantic-settings 讀取的 DATABASE_URL）取得資料庫連線字串
  3. 把這些傳給 Alembic 的 context 設定

設定好之後，每次你跑 alembic revision 或 alembic upgrade，它都會自動載入這些設定。

重點整理

  • Alembic 是 SQLAlchemy 的遷移工具，負責把模型變更翻譯成 SQL
  • alembic init 會產生 alembic.ini、env.py 和 script.py.mako
  • env.py 是每次執行 Alembic 都會跑的腳本，必須讓它知道資料庫 URL 和 SQLModel metadata 在哪
  • script.py.mako 是遷移檔的樣板，設定好可以省去每次手寫匯入的麻煩
