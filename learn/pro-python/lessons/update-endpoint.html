Update endpoint (PATCH)

Node 13 · Step 3 of 4

Learning goal

Implement a PATCH endpoint that partially updates an existing record, regenerates the slug when the name changes, and returns the updated object.

Why PATCH, not PUT

REST offers two ways to update a resource. PUT replaces the entire resource — the client sends every field, even the ones that haven't changed. PATCH applies a partial update — the client sends only the fields they want to change.

For a project with five fields, a PUT request looks like this:

PUT /projects/1
{
  "name": "New Name",
  "description": "Old description",
  "version": "0.1.0",
  "slug": "old-slug",
  "created_at": "2025-01-01T00:00:00"
}

The client had to fetch the existing record first, then resend everything. If they forgot a field, it gets overwritten with a default. That's fragile.

A PATCH request is simpler:

PATCH /projects/1
{
  "name": "New Name"
}

Only name changes. Everything else stays as-is. This is the pattern most real APIs use.

Designing the update schema

The update schema looks like the create schema, but every field is optional — the client can send any subset:

class ProjectUpdate(BaseModel):
    name: str | None = None
    description: str | None = None
    version: str | None = None

Using str | None = None means "if the client omits this field, it stays None in the schema, and we skip updating it." This is the key difference from ProjectCreate, where name was required.

Writing the endpoint

The update endpoint has three stages: fetch the existing record, apply only the provided fields, then commit:

@app.patch("/projects/{project_id}", response_model=ProjectRead)
def update_project(
    project_id: int,
    project_in: ProjectUpdate,
    session: Session = Depends(session_dep),
):
    project = session.get(Project, project_id)
    if not project:
        raise HTTPException(status_code=404, detail="Project not found")

    data = project_in.model_dump(exclude_unset=True)
    for key, value in data.items():
        setattr(project, key, value)

    if "name" in data:
        project.slug = slugify(data["name"])

    session.add(project)
    session.commit()
    session.refresh(project)
    return project

The magic of exclude_unset=True

project_in.model_dump() would return {"name": "New Name", "description": None, "version": None}. If you applied that directly, you'd overwrite description and version with None — destroying data the client never intended to change.

exclude_unset=True tells Pydantic to only include fields the client actually sent. If the request was just {"name": "New Name"}, the dump returns {"name": "New Name"}. The other fields are excluded from the dictionary entirely.

This is the single most important detail when implementing PATCH. Forget it, and your endpoint silently nullifies fields.

Applying changes with setattr

The loop for key, value in data.items(): setattr(project, key, value) iterates over the provided fields and updates the SQLModel object in memory. setattr(project, "name", "New Name") is equivalent to project.name = "New Name", but it works for dynamic keys.

After the loop, the object in memory reflects the partial update. session.add(project) stages it, session.commit() writes the UPDATE statement, and session.refresh() pulls back any database-side changes (like an updated_at timestamp managed by a trigger).

Regenerating the slug

When the name changes, the slug should change with it. The check if "name" in data detects whether the client sent a new name. If they did, regenerate the slug from the new name.

If the client didn't send name, the slug stays as-is. This is correct — you don't want to regenerate a slug that's already stable just because the description changed.

Handling the 404 case

session.get(Project, project_id) returns None if no row matches the ID. The endpoint raises HTTPException(status_code=404) to signal "not found." FastAPI converts that into a proper 404 response with the detail message.

This is the same pattern used in the read endpoint. Consistency matters — clients learn your error format once and apply it everywhere.
