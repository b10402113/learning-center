啟動容器並驗證 Postgres 是否正常

能用 docker compose 啟動 Postgres，並用健康檢查與連線測試確認它真的在跑。

啟動容器

在專案根目錄下執行以下指令，背景啟動 Postgres 容器：

docker compose up -d

-d 表示 detached 模式，容器會在背景跑，不會佔用你的終端機。

檢查容器狀態

用 docker compose ps 查看服務狀態。如果健康檢查通過，狀態會顯示 (healthy)：

$ docker compose ps
NAME      IMAGE                STATUS                   PORTS
python-db-1   postgres:17-alpine   Up 10 seconds (healthy)   0.0.0.0:5432->5432/tcp

查看日誌

如果容器沒有顯示 healthy，可以用日誌排查問題：

docker compose logs db

常見的錯誤包括連接埠被佔用、volume 權限問題、或環境變數拼錯。

實際連線測試

容器健康不代表應用連得上。最保險的方式是實際連進去查資料。如果你有 psql，可以用：

psql -h localhost -p 5432 -U release_tracker -d release_tracker

或者直接進容器裡下指令：

docker compose exec db psql -U release_tracker -d release_tracker -c "\dt"

這會列出目前資料庫裡的表格。剛開始應該是空的，因為我們還沒建表。

停止與清理

想重來？用 docker compose down 停止並移除容器。要連資料一起刪，加上 -v：

docker compose down -v

這會把 named volume postgres_data 也刪掉，下次 up 就是一個全新的資料庫。
