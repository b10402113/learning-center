命名慣例與 None

學習目標

會用 snake_case 命名變數、避開 list/dict 等內建名稱，並用 is None 正確檢查「值刻意缺失」。

snake_case：Python 的命名慣例

Python 變數的慣例命名是 snake_case（蛇形命名）——全小寫、單字之間用底線：

payments_api = "payments-api"
total_tasks = 13
user_name = "nina"

不是 camelCase（totalTasks）、不是 PascalCase（TotalTasks）。你讀的 Django/Flask 專案裡看到的都會是這個風格——跟著慣例走，別人讀你的程式碼才不會卡在奇怪的斷字上。

千萬不要蓋掉內建名稱

上一步說過，list、dict、set、int、str 這些名字是內建的——本來就在命名空間裡。所以這行程式完全合法：

list = [1, 2, 3]        # 合法，但這是埋雷
other = list("abc")     # TypeError: 'list' object is not callable

一旦把變數取名為 list，這個名字就指向你的 list 物件了——原本的 list() 建構子被遮蔽（shadow），模組裡後續所有 list(...) 的呼叫都會壞掉，而且錯誤訊息完全不會提示你「是你自己蓋掉的」。dict、set、int、str、print 同理。規則很簡單：內建名稱永遠不拿來當變數名。

None：刻意表達「沒有值」

None 是 Python 的 null——一個特殊關鍵字，意思是「刻意地沒有值」。典型用法是當旗標（flag）：

current_user = None    # 一開始：還沒有使用者

if current_user is None:
    print("尚未登入")
else:
    print(f"歡迎回來")

重點在語意的區分：None、空字串 ""、數字 0 是三種不同的東西。"" 和 0 是真實存在的值（空的名字、數量為零）；None 是「這個位置還沒有值，或故意不放值」。該用哪個取決於你想表達什麼——「使用者還沒填」用 None，「填了但留空」用 ""。混用會讓讀程式碼的人猜不出你的意圖。

用 is None 檢查，不是 == None

檢查某變數是不是 None，慣用寫法是身分比較：

if current_user is None:   # 慣用、正確
    ...

if current_user == None:  # 別這樣寫
    ...

is 問的是「是同一個物件嗎」，== 問的是「相等嗎」。None 全 Python 只有一個實例，用 is 檢查既精確又快；== None 在簡單情境能用，但自訂類別可以覆寫 __eq__ 讓 == None 回傳怪結果——所以 Python 社群的鐵律是一律 is None。你在別人程式碼裡看到 if x is None:，現在你知道為什麼了。
