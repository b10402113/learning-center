Task router setup and imports

學習目標：Set up the task router with absolute imports and the three dependencies (project, session, task)

Why this step matters

在之前的節點你已經建好 project router 和 CRUD 模組。Task router 看起來幾乎一樣，但多了對 Project 的關聯，還有 task_dep 這組依賴。這一節先把骨架搭好——導入風格、依賴宣告、APIRouter 初始化——讓後續的 CRUD 和查詢邏輯可以疊上去。

Absolute vs relative imports

Python 兩種導入寫法等價，但可讀性和重構難易不同：

# Relative import
from .dependencies import project_dep, session_dep

# Absolute import
from release_tracker.dependencies import project_dep, session_dep

講師偏好絕對導入，原因有二：重構時搜尋檔名更容易，移動檔案時不易出錯。不管選哪種，團隊風格統一才是重點。

Dependencies for task router

Task router 需要三個依賴一起運作：

  • project_dep — 透過 project_id 或 slug 查一筆專案，找不到就 404
  • session_dep — 注入資料庫 session，結束時自動關閉
  • task_dep — 查一筆 task，找不到就 404（跟 project_dep 同一種 pattern）

三個依賴各自用 Annotated[..., Depends(...)] 宣告，再在每個 endpoint 的 function signature 裡組合。

Refactoring signal: long imports

import 一行塞了十幾個名字，通常暗示該模組該拆了。例如 from release_tracker.models import TaskCreate, TaskPriority, TaskRead, TaskStatus, TaskUpdate 可以考慮拆成 release_tracker.models.task_models。這不是硬性規則，但是一個值得留意的程式碼氣味（code smell）。

Putting it together

一個最小的 task router 骨架長這樣：

from fastapi import APIRouter, status
from typing import Annotated, Any

from release_tracker.dependencies import (
    project_dep,
    session_dep,
    task_dep,
)

from release_tracker import crud
from release_tracker.models import (
    TaskCreate,
    TaskPriority,
    TaskRead,
    TaskStatus,
    TaskUpdate,
)

router = APIRouter()

注意 router = APIRouter() 在 import 宣告之後才建立。順序是：外部套件 → 內部依賴 → CRUD → 模型 → 建立 router。
