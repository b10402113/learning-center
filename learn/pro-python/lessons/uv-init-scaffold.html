Node 02 — Step 1/3 · 專案設定

用 UV 初始化專案

學習目標：能用 uv init 建立一個新的 Python 專案，並理解每個產生檔案的用途。

為什麼需要專案管理工具？

想像你要蓋房子。你可以隨便找塊空地開始堆磚頭，但比較聰明的做法是先畫藍圖、準備工具、搭好鷹架。Python 專案也一樣——你不能只在一個資料夾裡放一個 .py 檔就開始寫。你需要一個結構，讓工具鏈（linter、測試框架、套件管理器）知道該怎麼幫你。

在現代 Python 開發中，UV 就是幫你搭鷹架的工具。它是一個用 Rust 寫的 Python 套件與專案管理器，速度極快，同時處理虛擬環境（virtual environment）和 Python 版本管理。

一行指令，建立專案

打開終端機，輸入：

uv init my-project --python ">=3.14"

這一行做了什麼？

  • uv init — 告訴 UV 建立一個新專案
  • my-project — 專案資料夾名稱
  • --python ">=3.14" — 指定需要的 Python 版本

執行完畢後，你會看到一個全新的資料夾，裡面有這些檔案：

my-project/
├── .git/               ← Git 倉庫（自動初始化）
├── .gitignore          ← 排除不需要追蹤的檔案
├── .python-version     ← Python 版本釘選
├── main.py             ← 程式碼起點
├── pyproject.toml      ← 專案設定檔（核心！）
└── README.md           ← 專案說明

每個檔案是做什麼的？

檔案用途誰會讀它？
pyproject.toml 專案的中繼資料：名稱、版本、Python 版本要求、依賴列表 UV、pip、其他工具鏈
.python-version 釘選專案使用的 Python 版本 UV、pyenv、部分 IDE
main.py 範例程式碼（通常是 hello world） 你（開發者）
.gitignore 告訴 Git 忽略哪些檔案（如 .venv/） Git
.git/ 本地 Git 倉庫（尚未連接 GitHub） Git
README.md 專案說明文件 人類讀者

為什麼系統 Python 不夠用？

你的電腦可能已經裝了 Python，但大概率是過時版本。macOS 和 Linux 預設的 Python 往往是 3.9 甚至更舊，缺少現代 Python 的新功能（像是 match 語句、更好的型別提示支援）。

UV 會自動幫你下載正確版本的 Python，不需要手動安裝。你只要在 uv init 時指定版本，UV 就會確保專案使用该版本。

💡 重點：每個專案都應該釘選自己的 Python 版本。這樣團隊成員和 CI 環境都會使用相同的版本，避免「在我電腦上可以跑」的問題。

Git 自動初始化

注意 uv init 會自動建立 .git/ 資料夾。這表示你的專案從第一天起就有版本控制。不過它只是本地 Git 倉庫——還沒有連接 GitHub 或任何遠端倉庫。你需要自己執行 git remote add 來連接。

小結

uv init 一秒建立完整的專案骨架。你得到一個有版本控制、版本釘選、專案設定的乾淨起點。下一步，我們要拆開 pyproject.toml 看看每個欄位的意思。
