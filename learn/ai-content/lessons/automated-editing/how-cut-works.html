/cut 怎麼運作：逐字時間戳與 last clean take

Step 3/6 · Automated Editing：RUBRIC Editor＋/cut

學習目標

看懂 /cut 如何靠逐字時間戳判斷要保留哪一段，了解它為什麼預設保留最後一次乾淨的 take，也能分辨不同轉錄服務在成本與速度上的差異。

前言：它沒看過你的稿子，憑什麼知道要砍哪裡

在這條自動剪輯流程裡，你先把原始錄影交給 /cut，它再透過轉錄找出每個字出現的時間，據此剪出影片，最後把成品送到 RUBRIC Editor，讓你檢查。這一步就是把一段長錄影整理成可以審閱的剪輯結果。

上一節你已經裝好 RUBRIC Editor，也讓 /cut 處理過第一支原始錄影。看到剪輯結果後，你可能會想：它沒看過我的腳本，怎麼知道哪一段該留、哪一段是講錯後重來，應該剪掉？

要教它剪得更符合你的習慣，得先知道它目前怎麼判斷。就像幫人糾正發音，得先聽出他把哪個音說錯，才知道該怎麼回饋。這一節就來拆解 /cut 背後的判斷方式。

關鍵在兩份資料：原始錄影與逐字時間戳

呼叫 /cut 時，你會透過檔案路徑交給它一支原始錄影，MKV 或 MP4 格式都可以。接著，agent 會替影片做轉錄，也就是把影片裡說的話轉成文字。

這份轉錄不只記下「說了什麼」，也會記下每個字出現的時間。換句話說，產出的資料像是一份附有時間標記的逐字稿，讓 agent 能知道你在第幾秒說了哪個字。

如果手上只有純文字稿，你只知道「他講了什麼」；加上逐字時間戳後，你也知道「他什麼時候講的」。判斷停頓或重來的片段，就需要這些時間資訊。

預設規則：保留最後一次乾淨的 take

有了逐字稿和時間資訊，/cut 就能開始判斷。它的出廠預設規則是：每一行保留最後一次乾淨的 take（last clean take）。這裡的 take 指一次錄製或重講的片段；「乾淨」則是指內容講得完整、沒有明顯錯誤的版本。

為什麼預設保留最後一次？很多人錄影時會先講錯，或是講得不完整，接著重講一次。像一句話先講到一半發現不對，再從頭說一次，通常比較完整的版本會在後面。因此，這條規則會優先留下最後一次講得乾淨的片段。

但「留最後一次」只是出廠預設，代表多數人的說話習慣，不一定符合你的方式。每個人的停頓長短、重講頻率和語速都不同，所以這條規則可以調整。你持續使用 RUBRIC Editor 並留下評論，/cut 就能逐漸學到哪些片段該剪、哪些停頓該留。下一節會進一步說明這個回饋迴路。

剪輯完成後，agent 會讀取剛做好的最終 cut，並上傳到 RUBRIC Editor，讓你播放和檢查。課程示範中，一支約 14 分鐘、對著提詞機錄製的單一長 take，被剪成 8 支獨立短片。也就是說，錄影 14 分鐘，就完成了 8 支短影音的素材。

它用哪個服務做轉錄？三種選擇

逐字時間戳的品質與速度，會受到轉錄服務影響。/cut 預設使用 AssemblyAI，但也可以改用其他服務。三者主要差在費用、速度，以及轉錄工作跑在雲端還是你自己的電腦上：

服務費用速度跑在哪
AssemblyAI付費，按小時計（預設）快：1 小時影片約 33 秒雲端
OpenAI Whisper免費慢：1 小時影片約 15 分鐘，看 CPU 強弱你自己的電腦
ElevenLabs Scribe比 AssemblyAI 貴一點和 AssemblyAI 差不多快雲端

Whisper 在你自己的電腦上執行，因此轉錄需要多久，會受到 CPU 效能影響。AssemblyAI 和 ElevenLabs 則在雲端執行，速度快很多。課程建議：如果你已經付費訂閱 ElevenLabs，選用 Scribe 很合理；否則就依照自己對成本和速度的偏好選擇。

選 AssemblyAI 或 ElevenLabs 時，需要 API key，也就是讓程式連上服務、取得使用權限的一組金鑰。你可以到對應網站申請，再請 Claude 說明如何安全地接上。請記得：不要把 API key 貼進聊天紀錄，或放進任何會分享出去的檔案。

若要更換服務或接上自己的 key，課程提供了這段可以直接傳給 agent 的提示：

Set up the transcription for my /cut skill. Ask me one question at a time.

1. Ask me which one I want: AssemblyAI (the default, fast and paid per hour), Whisper from OpenAI (free, runs on my computer, much slower) or ElevenLabs Scribe (fast, a bit pricier, good if I already pay for ElevenLabs).
2. If it needs an API key, open the right page for me, tell me where to click to make the key, and show me the safest way to give it to you. Never paste my key into a chat log or a file I share.
3. Change /cut to use it, and run a quick test on a short clip to check the words come back with their times.
4. Tell me in plain words how long an hour of video will take and roughly what it costs.

這段提示會先問你想用哪個服務，再協助處理 API key、修改 /cut 的設定，並用一小段影片測試轉錄結果是否附有時間資訊。最後，agent 會用白話說明一小時影片大約需要多久、費用大概多少。這樣一來，選服務和更換設定就能透過幾輪問答完成，不必自己翻 API 文件。

小結

/cut 會使用兩份資料：你提供的原始錄影，以及 agent 產生、每個字都帶有時間戳的逐字稿。有了時間資訊，它就能依照預設規則「每行保留最後一次乾淨的 take」來剪；而你在 RUBRIC Editor 留下的評論，能逐步幫它學會你的習慣。轉錄服務則要在成本、速度，以及工作跑在雲端或本機之間取捨：AssemblyAI 快但付費、Whisper 免費但較慢、Scribe 速度快但稍貴。

把這個觀念掛回自動剪輯流程來看：逐字時間戳提供判斷依據，預設規則負責挑選片段，而你的評論則讓規則逐漸貼近自己的習慣。下一節會進入 RUBRIC Editor，實際走一遍審片並教會 /cut 的回饋迴路。
