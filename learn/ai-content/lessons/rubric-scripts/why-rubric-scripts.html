為什麼要有 RUBRIC Scripts：別讓腳本散落在對話框裡

Step 1/5 · RUBRIC Scripts：從點子到腳本

學習目標

能說出 RUBRIC Scripts 存在的理由：它把腳本從對話框集中到一個地方、與 agent 搭配運作，並且讓你的 /hooks 與 /tone 越用越強。

前言：生完稿之後，稿子跑去哪了？

前面幾個節點，你已經有了九種 hook 句型（/hooks），也建立了一份屬於自己的 /tone。上週又用 /outliers 和 /latest 收了一批候選點子。現在把點子丟進 agent，回來一篇還不錯的腳本，看起來整條產線都通了。

問題是，然後呢？這篇腳本就躺在對話視窗裡。過兩天你想回頭改某一支、想找回當時挑的 hook、想把三支腳本湊成一頁照著唸，結果得在長長的對話紀錄裡一路往上滑。腳本一多，它們就開始散、開始掉，幾乎沒辦法拿來比較或優化。

這一節要講的不是操作，而是先回答一個「為什麼」：為什麼要多裝一套軟體，不能繼續在對話框裡做就好？把這件事想通，後面的安裝、生稿、改稿才會有方向，你也才知道自己到底在為什麼花時間。

RUBRIC 是什麼？

課程裡會一直出現「RUBRIC」這個字。它是 RoboNuggets 社群自己開發、自己提供的一組客製軟體與系統。它的每一個成員都被設計成「跟 AI agent 一起用」。課程用 agent-ready 來形容這件事，意思是軟體不自己硬幹，而是把 agent 當引擎來操作。RUBRIC Scripts 就是這組裡專門管腳本的那一套。

你可以把它想成一個「工作台」，而不是一個「工具」。工具是你每次要用才開一次，用完就關掉；工作台則是你所有的半成品、草稿、待辦都擺在固定的檯面上，走過去就看到，隨手就能拿起一份來改。RUBRIC Scripts 想做的，就是腳本的工作台。

用對話框也能做，那差在哪裡？

課程本身也承認：光是 chat 就能做了。把點子貼給 Claude，叫它用 /hooks 跟 /tone，回來的腳本其實已經不錯。所以 RUBRIC Scripts 不是在解決「生不出稿」這個問題，它解決的是「生出來之後的管理」。差別具體有三個。

第一，會散失。腳本只存在某一條對話串裡，你開新對話、清掉紀錄、或換一台裝置，它就找不回來了。第二，難比較、難優化。你想看這週五支腳本的標題哪個最順、哪支太長，在對話框裡只能一遍又一遍往上滑，眼睛會累，也很難真的排在一起比。第三，版面擠。一支要發的短影音不只有正文，還有 hook、caption 和參考連結，全部塞進同一條對話裡，看起來就是一團亂，很難一個一個好好檢查。

RUBRIC Scripts 把這些東西集中到一個跑在你自己電腦上的網頁（本機 localhost）：左邊是你的點子，中間是腳本，旁邊是 caption 和參考資料，一次攤開來 review。這就是它和「在對話框裡做」最根本的分野。

核心機制：agent-ready 與複利迴路

它最關鍵的設計是「用 skill 驅動」。你在頁面上看到的操作，背後幾乎都是把你的意圖寫成一段交給 agent 的指令，由 agent 去讀寫你的 skill。你之後會用到的主要入口，就是下面這個指令：

"""/rubricscripts turn these ideas into scripts for short videos:

1. [idea one, plus the link it came from if I have one]
2. [idea two]
3. [idea three]

Use my /hooks and /tone skills, give me 3 hooks for each script, write a caption for each one, and add the links you used as references. Never make up a fact, a number or a link. When they're in RUBRIC Scripts, give me the link to open it."""

這段看起來只是「把點子貼給 agent」，但它的位置不同了：它是在工作台裡運作，產出會落在那個固定的檯面上，而不是消失在對話裡。想先挑清單再寫，也有另一條路，下一節會細講。

這個設計還帶出整件事最有價值的一個想法：複利迴路。你在這個工作台上留下的每一則回饋，不只改掉眼前這篇稿，還會回頭強化你的 /tone。你的 tone skill 越準，RUBRIC Scripts 生出來的下一批稿就越像你；越像你，你要手動改的地方就越少。這是一個會自己變好的循環。課程講得很直白：你越改進自己的 tone-of-voice skill，RUBRIC Scripts 就越強。

它不是固定產品，而且有些功能要等 Wk4

先講它「不」是什麼。它不只是配 /hooks 和 /tone 而已。課程說，你自己寫的 skill、規則，甚至別的小軟體，都可以整合進來。而且整個介面是可改的（malleable）：想要四個 hook 而不是三個、想把 caption 每次都縮短、想刪掉用不到的視窗，直接叫 agent 改這個 app 就好。所以它不是一個鎖死的產品，而更像一塊你自己的地。

另外有一個邊界要先講清楚，免得你一打開就困惑：頁面裡那個「影片預覽視窗」和 TikTok、Instagram、Threads、YouTube Shorts 一整排，是 Wk4（內容發布）才會講的東西。現在看到它，先知道「那是之後的事」就好，這週不用管。

小結

RUBRIC Scripts 的存在，不是為了替你生稿，而是把「生稿之後」的整理、比較、優化集中到一個跑在你電腦上的本機工作台。它用 skill 驅動、讓 agent 當引擎；你留下的回饋會同時改稿，也回頭加強你的 /tone，形成越用越準的複利。它不是固定產品，介面和它能吃的 skill 都能被你改。至於影片與平台那些功能，是 Wk4 才輪到的事。

觀念講完了。下一節就把它裝到你的電腦上，從下載 zip、把安裝指令交給 agent，一路開到 localhost 為止。
