寫 AEO caption 的四條規則

Step 4/5 · Captions 與 AEO

學習目標

這一步接在前三節之後：你已經了解 caption 的用途，也知道 AEO（Answer Engine Optimization，讓內容更容易被搜尋引擎與 AI 答案找到及引用）在爭取什麼。現在要把這些觀念變成一段能直接放進貼文的文字。

完成後，你會寫出一段符合 AEO 的 caption：點出具體工具或主題，而不是重複含糊的 hook；每一行都能獨立讀懂；加入真實數字；並在文末列出「Questions we answered」。

前言：觀念有了，現在把它變成一段字

前三節已經說明，照片與輪播貼文的 caption 是演算法能讀到的文字；平台也成了人們搜尋資訊的地方。AEO 要爭取的，則是讓內容有機會被 AI 答案引用。接下來的問題很實際：這段字該怎麼寫？

這一節會帶你照著四條規則動手。你需要一則已定案的貼文和它的 hook，也要清楚貼文實際在講什麼。做完後，你會得到一段能直接貼進貼文欄位的 caption，既讓讀者看得懂，也方便搜尋引擎與 AI 理解。原理已在前面幾節說明，這裡就專注在寫法。

動手前，你手上該有什麼

開始前，先確認這兩樣材料都準備好了：

  • 一則已經定案的貼文，以及它的 hook。Hook 是貼文開頭用來勾起好奇的那句話，通常會故意寫得含糊一些，讓讀者想知道後續。
  • 清楚知道貼文在講什麼。例如，它談的是哪個工具或主題，以及解決了什麼具體問題。這些資訊會成為 caption 的內容。

如果你還說不清楚貼文的主題，先把主題釐清再開始。寫 caption 的前提，是你已經知道自己要講什麼。

規則一：指名工具，不要重複 hook

Hook 通常會故意保留一點含糊，好讓人好奇；caption 的任務則相反：要讓搜尋引擎與 AI 看得出貼文在講什麼。

因此，不要把 hook 原封不動抄進 caption，而要直接寫出主題。例如，貼文談的是 Claude Code，就明確寫出「Claude Code」，不要只寫「這個 AI 工具有夠猛」。有人搜尋的可能正是工具名稱；把名稱寫出來，搜尋引擎與 AI 才能把內容和主題連起來。

課程書面頁也提醒，hook 可以保留含糊感來引起好奇，但 caption 應該說清楚實際談的是什麼，讓搜尋和 AI 答案有機會找到內容。課程也指出，在探討 Claude Code 的內容中，直接點出 Claude Code 的貼文，比語焉不詳的寫法更容易被 AI agent 抓取。

預期看到的結果：caption 至少出現一個具體的工具名或主題名，而且是讀者可能真的會搜尋的字詞。

規則二：讓每一行獨立成立

Caption 很容易寫成需要前後文才能理解的段落，例如第一行接著 hook，第二行再用「它」繼續說明。但搜尋引擎與 AI 讀取 caption 時，可能會把內容拆開；如果某一行離開上下文就看不懂，這行就不容易被採用。

所以，試著讓每一行單獨拿出來也說得通。你可以把一行剪出來檢查：如果它得靠「它」、「這個」或「上面說的」才能成立，就改寫成能獨立理解的句子。

這樣寫也能照顧滑得很快的讀者：他們可能只看到前幾行，但每一行都能獨立成立，就不必讀完整段才知道你在說什麼。

預期看到的結果：把 caption 任一行單獨貼出來，仍然看得懂它在說什麼、指的是什麼。

規則三：放進真實數字

抽象的描述很難讓人知道實際情況。具體數字則能把差異說清楚。與其寫「大幅加快」，不如寫「把原本要半小時的流程縮到三分鐘」；與其寫「很多人用」，不如寫出你實際觀察到的數量。

數字是容易辨認的具體細節，也比較容易被搜尋引擎與 AI 引用。不過，數字必須是真實、站得住腳的事實，不能為了讓文案好看而誇大或編造。

預期看到的結果：caption 至少包含一個確切、能查證的數字，而不是只寫「很多」、「很快」或「大幅」這類說法。

規則四：文末加上「Questions we answered」

在 caption 最後加上一個區塊，標題寫「Questions we answered」（我們回答了哪些問題），再列出貼文實際回答的問題。

這個區塊通常會放在「摺線以下」，也就是讀者按下「更多」或「看更多」後才會看到的位置。大多數人不會滑到那裡，因此它不太會打擾閱讀貼文的人，卻能補充這則內容回答了哪些問題。

課程把這個區塊形容成貼文附帶的一層說明或中繼資料。這些資訊對搜尋有幫助，也能支援越來越重要的 AI 搜尋。

預期看到的結果：caption 最後有一段以「Questions we answered」為標題的問題清單，並放在「更多」之後。

把四條規則合起來：壞例子與好例子

先看一個沒有套用規則的寫法。它重複含糊的 hook、句子彼此依賴，沒有數字，也沒有問題區塊，因此提供給搜尋引擎與 AI 的具體資訊不多：

你一定猜不到這個 AI 工具有多扯 😱
它真的讓我整個流程變超快，看完你就懂。
真的不要再這樣做了，留言告訴我你的想法！
#AI #工具 #效率 #生產力 #教學 #推薦

再看一個套用四條規則的版本。它點出工具名稱，每一行都能獨立理解，加入了數字，最後也列出貼文回答的問題：

我把 Claude Code 接進每天的開發流程，省下大量手動打字。
Claude Code 是 Anthropic 出的命令列 AI 編碼工具。
實際測試：同一段重構，手動花了 28 分鐘，交給它跑完只要 4 分鐘。
下面是我怎麼設定它讀取專案脈絡的完整做法。

Questions we answered:
- Claude Code 是什麼？
- 怎麼把 Claude Code 接進現有的開發流程？
- 用 Claude Code 做重構真的比較快嗎？

兩個版本談的是同一件事，但第二個版本提供了更明確、可搜尋與可引用的資訊。這就是四條規則合起來的效果。

小結

寫 AEO caption 有四條規則：一，指名具體工具或主題，不要只重複含糊的 hook，讓搜尋與 AI 有明確字詞可以對應；二，讓每一行都能單獨看懂，因為內容可能會被拆開閱讀；三，加入真實、能查證的數字，取代「很多」、「很快」這類籠統說法；四，在文末加上「Questions we answered」區塊，補充貼文回答的問題，又不會太打擾讀者。

做完這一步，你就有一段符合四條規則的 caption。下一節會接著處理更省時的做法：hashtag 還要不要用、該用幾個，以及能不能把這種 caption 交給 agent 自動撰寫。
