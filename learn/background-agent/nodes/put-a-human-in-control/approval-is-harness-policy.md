# 批准不是萬用的安全盾

當我們讓背景代理人（Background Agent）自動監控並維護系統時，最直覺的安全防線通常是「人工批准」：只要牽涉到寫入或變更操作，就停下來等人點擊確認。

這種做法看似萬無一失，實務上卻很容易踩進兩個盲區。一是誤以為只要有工程師把關，系統就不會出事；二是當系統每動一步都要審核，背景代理人就會退化成普通的對話機器人，讓人整天盯著收件匣疲於奔命。

## 批准是 Harness 的政策，不是模型的自我意識

在建構代理人系統時，核心架構由大型語言模型（LLM）與負責執行環境的骨幹程式（Harness）共同組成。發出審核請求的從來不該是模型，而是 Harness 的政策邊界。

系統在定義工具時，會透過硬編碼的政策來標記哪些操作屬於讀取、哪些需要人工審核：

<!-- source: sources/background-agent/20261105/server/tool-policy.ts#L1-L15 -->

```typescript
import type { ActionName } from '../shared/types'

// The harness reads policy metadata; it does not branch on checkout fault flags.
export const actionPolicy: Record<
  ActionName,
  'read' | 'write' | 'approval' | 'help' | 'terminal' | 'wait'
> = {
  inspect_logs: 'read',
  inspect_changes: 'read',
  disable_feature: 'write',
  rollback_release: 'approval',
  request_help: 'help',
  complete: 'terminal',
  wait: 'wait',
}
```

模型只能看見工具清單中有 `rollback_release` 這個動作，卻完全不知道這個動作需要人類同意。

刻意隱瞞這項政策，是為了避免模型「自作聰明」。大型語言模型具備很強的目標導向特質，如果它在提示詞或工具描述中得知某個動作需要等待人類核准、而且人類通常要很久才會回信，它很可能會為了盡快完成任務，刻意改選其他不需要審核的次級替代方案，甚至編造看似合理的藉口來繞過正常流程。

把規則留在 Harness，模型的決策流程就能保持純粹。它依據情境選擇當下最合適的動作，而 Harness 負責攔截這個呼叫，將它轉化為一筆待審核的提議（proposal），而不是直接執行工具。

## 為什麼有人核准依然可能出事

很多人把批准當成萬靈丹，認為只要人類看了沒問題就等於安全，但現實中的攻擊與失誤往往發生在審核之前。

模型做出危險提議的原因，很可能源自先前讀取到的不可信資料。舉例來說，讀取系統日誌通常是唯讀操作，不需任何審核；然而日誌內容若混入了惡意輸入（Prompt Injection），模型就可能受到污染，進而在下一步提出錯誤或有害的操作。

<!--image:2-->

審核介面如果只顯示「代理人提議回滾版本」，而沒有標示資料來源與推導脈絡，審核人員往往會直接點擊批准。這意味著「不需核准的讀取」直接催生了「通過核准的破壞」。

有效的批准必須具備清楚的範圍限制（Scoped Capability）：它只能適用於特定的執行階段、特定動作，以及當下預期的系統狀態版本。如果系統在審核通過後沒有重新比對版本，原本合法的操作就可能因為環境變化而引發嚴重的競態問題（TOCTOU）。

## 何時該從「增加關卡」轉向「去風險化」

在剛上線或風險未明的階段，把所有具破壞性或帶有寫入權限的動作都放進審核清單，是合理的起點。但這不該是系統的終點。

如果你的背景代理人每天在收件匣塞進幾十個批准請求，整個團隊就會被噪音淹沒。這時系統已經失去背景運作的價值，你只是被迫在另一個介面裡跟它一問一答。

<!--image:3-->

當審核頻率高到影響生產力時，該做的事不是增加更多審核欄位，而是設法「去風險化」（De-risking）：

- **縮小爆炸半徑（Blast Radius）**：將一次性全面變更改為漸進式發布，例如先影響 10% 的流量，確認穩定後再逐步提升至 20% 與 40%。
- **建立快速復原機制**：設計可靠的回滾流程，確保就算模型判斷失誤，影響也能在幾秒內復原，讓出錯的代價變得極低。
- **保留高價值審核**：唯讀的排查操作完全放行，只在動作真正不可逆、代價高昂，或是依據模糊不清的少數關鍵決策上，才要求人類介入。

安全的代理人架構不是靠無止境的人工審查堆出來的。比起依賴疲憊的人類在每一步蓋章，把執行環境設計得就算出錯也不會釀成災難，才是背景代理人真正能放心運行的關鍵。
