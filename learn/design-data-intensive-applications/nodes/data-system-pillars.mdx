# 資料系統的三個支柱

## Learning goal

區分 reliability / scalability / maintainability，能在設計討論中用這三個詞準確描述系統的非功能需求

## Steps

1. [[learn/design-data-intensive-applications/nodes/data-system-pillars/reliability-and-fault-tolerance|可靠性與容錯：從硬體、軟體到人為故障的完整拆解]] — 定義可靠性，區分 fault vs failure，解釋 fault-tolerance 的設計哲學
2. [[learn/design-data-intensive-applications/nodes/data-system-pillars/scalability-and-performance|Scalability 與 Performance Metrics]] — 用 load parameters 和 performance metrics 描述系統負載，比較 scaling up vs out
3. [[learn/design-data-intensive-applications/nodes/data-system-pillars/maintainability-and-operability|Operability、Simplicity、Evolvability 三大原則降低維護成本]] — 解釋 operability / simplicity / evolvability 三個設計原則如何降低長期成本
4. [[learn/design-data-intensive-applications/nodes/data-system-pillars/pillars-as-tradeoffs|資料系統三大支柱的取捨：Reliability、Scalability、Maintainability 的設計框架]] — 用真實案例展示三個支柱之間的取捨關係，作為後續章節的設計框架 (after steps 1–3)

## Lesson

設計資料系統時，你需要同時考慮三個支柱：**可靠性**（系統在出問題時仍能正確運作）、**可擴展性**（系統能應對負載增長）、**可維護性**（系統容易操作、理解與演進）。這三者不是獨立的——強化其中一個往往會影響另外兩個，例如同步複製提升可靠性但增加寫入延遲，水平擴展提升吞吐但引入分散式系統的複雜度。本章建立這三個詞的精確定義與心智模型，作為後續所有技術章節的設計框架。
