# 資料模型與查詢語言

## Learning goal

比較 relational / document / graph 三種模型的取捨，為一個具體應用場景選出合適的模型

## Steps

1. [[learn/design-data-intensive-applications/nodes/data-models-and-query-languages/relational-model-vs-nosql-history|關聯模型稱霸三十年與 NoSQL 運動：資料模型的歷史選擇]] — 理解關聯模型為何主導 30 年，以及 NoSQL 運動的四大驅動力
2. [[learn/design-data-intensive-applications/nodes/data-models-and-query-languages/document-vs-relational|Document Model vs Relational Model 的核心取捨]] — 比較文件模型與關聯模型在 impedance mismatch、schema 彈性、資料局部性上的取捨（after step 1）
3. [[learn/design-data-intensive-applications/nodes/data-models-and-query-languages/graph-models-and-query-languages|圖資料模型與查詢語言：Property Graph、Triple-Store、Cypher vs SQL 完整比較]] — 理解圖模型為何最適合多對多關係，比較 Cypher / SPARQL / Datalog 的表達力（after step 2）

## Lesson

資料模型（Data Model）决定了你如何組織、儲存和查詢資料。不同的模型對同一份資料給出截然不同的操作邊界——某些查詢很快，某些查詢很彆扭。本 node 從關聯模型的歷史主導地位出發，帶你走過 NoSQL 運動的四大驅動力，比較文件模型與關聯模型的核心取捨（impedance mismatch、schema 彈性、資料局部性），最後引入圖模型和三種查詢語言，建立一個完整的資料模型選擇框架。三步走完之後，你應該能為一個具體應用場景，說出「選這個模型，因為……」。
