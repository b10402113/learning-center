# 單 leader 複製

## Learning goal

解釋 sync / async / semi-sync 複製的取捨，能列舉 replication lag 導致的三種異常（reading your own writes, monotonic reads, consistent prefix）

2. [[learn/design-data-intensive-applications/nodes/single-leader-replication/replication-lag-anomalies|複製延遲導致的三種異常]] — 列舉非同步複製延遲的具體問題與解法（after step 1）

## Lesson

在單 leader 複製架構中，所有寫入都由一個 leader（主節點）處理，資料再複製到多個 follower（從節點）。這個架構的核心問題是：leader 確認寫入的時機——是等 follower 回報才算成功，還是先寫完就回報？

同步複製保證資料一致但犧牲延遲和可用性；非同步複製換來低延遲但可能丟資料；半同步在兩者之間找平衡。非同步複製的延遲會導致三種使用者可感知的異常：讀回自己寫的內容、時間倒流、因果倒置。而複製的實現方式——從原始 SQL 語句到邏輯日誌——決定了複製能支援什麼樣的系統架構。
