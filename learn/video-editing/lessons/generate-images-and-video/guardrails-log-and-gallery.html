成本護欄、sidecar log 與 gallery

Step 5/5 · 用 /generate 生圖生影

學習目標

讀完這一節，你能判斷一筆生成該用便宜模型先試還是直接上頂級模型，能說出五條成本護欄各自防的是什麼，並知道 sidecar log 與 gallery 如何讓每一筆輸出都留得下來、看得見。

前言：工具都架好了，接下來是「怎麼花錢」

前面四節把系統架起來了：金鑰就位、skill 寫好、模型 recipe 也接上。現在你終於可以打一句「幫我做三張產品廣告圖」，然後帳單就開始跳。

圖片的錢很省，一張草稿只要一、兩分美金，你可以放心生二十張來挑。但影片完全是另一個量級：每秒 $0.20–$0.35，一支十秒影片就是兩、三美元。同一個 prompt 你手滑重跑五次，十幾美元就沒了。所以真正決定這套系統好不好用的，不是生成能力，而是你有沒有替「花錢」這件事設好護欄。

這一節同時也收尾：把五條護欄講清楚，加上一份寫在每張圖旁邊的 sidecar log，最後用一面 gallery 牆把所有成果攤在眼前。這是整條產線裡，讓「自架」真正勝過「訂閱」的地方。

先決定：這筆生成該怎麼花？

每次要生成之前，其實你都在做一連串的取捨。把最常遇到的兩股張力列出來：

選項適合什麼代價
便宜模型先跑草稿還在找方向、要看很多版構圖畫質普通，但一張只要一、兩分錢
頂級模型直接上已經定稿、要見人的最終成品一張 $0.05–$0.15，影片更貴
先報價再生成影片任何要跑的影片工作多花一點等待確認的時間
不報價直接生影片幾乎沒有適合的情況一次十幾個 prompt 可能刷掉數十美元

這張表的核心原則是：把「探索」和「定稿」分開花錢。探索用最便宜的那顆模型，等你挑到喜歡的再讓同一組 prompt 上頂級模型定稿。這樣你付的每一分錢，都花在真正會被用到的版本上。

三個可以問自己的判別句

  • 「這一版是給我自己看的草稿，還是要交付出去的成品？」：草稿走便宜路線，成品才升級。
  • 「我現在要生的是安靜的圖片，還是會燒錢的影片？」：影片一律先報價、等明確同意再跑。
  • 「我手上有真實的參考圖檔嗎？」：沒有就先去要，絕不用文字描述頂替。

五條護欄，各防一種損失

這五條規則在你上一節寫的 `SKILL.md` 裡就已經列好了。這裡補充它們各自防的是什麼：

1. 影片先報價（Quote before video）

影片是最貴的一條路。agent 要先報出模型、長度、解析度與預估金額，然後等你明確說「好」。關鍵在兩個字：報價不等於同意，而且一次同意只對應一次生成。這樣才不會在你還沒搞清楚要什麼之前，就先燒掉一輪影片的錢。

2. 草稿便宜、定稿才漂亮（Draft cheap, finish pretty）

先在便宜模型上迭代，等挑到喜歡的那一版，才把同一個 prompt 重跑在品質模型上。這樣你就不會為了一堆最終會丟掉的草稿，付出頂級模型的價錢。

3. 用真圖，不用文字描述（Real refs, never described）

用文字描述一個 logo，回來的圖幾乎一定不對：形狀錯、顏色錯、還可能出現憑空捏造的細節。正確做法是把真實檔案放在 generations/refs/，在 API 呼叫時當作參考圖傳進去。

4. 一個扁平資料夾（One flat folder）

所有輸出都放進同一個資料夾，不分子夾。把檔案分門別類聽起來很整齊，實際上會弄壞每一個讀取這個媒體庫的工具，而且你到最後也不會記得自己當初怎麼分類。

5. 每存一張，就寫一份 sidecar log

這條標為「可選，但強烈建議」。三個禮拜後你看著某張圖，心想「這到底是用什麼 prompt 生的？」答案就在那份 log 裡。每次存檔後，agent 會在媒體檔旁邊寫一個同名、副檔名為 .json 的小檔案：

HERO_THUMBNAIL_1774912000.JSON · SITS BESIDE
HERO_THUMBNAIL_1774912000.JPG
{
    "model": "your-image-model",
    "prompt": "the full text prompt that was sent to the API",
    "refs": ["refs/logo.png", "refs/headshot.jpg"],
    "params": { "aspect": "16:9", "size": "2K" },
    "created": "2026-07-30T09:41:00Z"
}

整個功能就這樣。合約是「同檔名加上 .json」，所以未來任何工具、甚至單純的資料夾搜尋，都能還原某個檔案當初是怎麼做出來的。這是整套系統「prompt 不會弄丟」的關鍵。

規則什麼時候會翻轉？

護欄不是鐵板一塊，遇到特殊情況要懂得放寬。最典型的反例是：當某顆模型有別顆沒有的能力時，草稿階段就得直接用它。例如只有 GPT Image 2 能穩定地把可讀文字排進圖裡，那你要做海報時，就不能硬用更便宜但做不到的模型先跑草稿。護欄防的是「無謂的花費」，不是禁止你使用真正必要的工具。

把成果收進 gallery 牆

當 generations 資料夾開始累積，你要的是一眼看完所有產出。下面這段 prompt 可以原封不動貼給 agent，它會把資料夾變成一個單檔、免伺服器、用瀏覽器打開就能看的本地畫廊：

build me a single web page that shows every image and video my ai generates, all in one place, like a bento wall.
- it reads one folder on my computer called generations and shows everything sitting in it, newest at the top
- lay it out as a masonry wall - tiles keep their own shape, nothing gets cropped or squashed, rounded cards with even
gaps, 4 columns wide and fewer as the window gets smaller
- videos start playing quietly when i hover over them and stop when i move away, images just sit there
- click any tile and it opens up big in the middle of the screen, click outside to close
- no search, no filters, no tabs, no side panels - just the wall of everything
keep it to one file so it runs by opening it, and make it feel like a proper finished gallery, not a rough draft.


when the page is done, add a line to my CLAUDE md so that from now on anything the /generate skill makes gets saved
straight into that same generations folder, so it turns up on this page automatically. don't make the page pop open
every time, just save the file there.

它之所以成立，是因為第四條護欄：skill 一律扁平地存進同一個資料夾，所以這面牆永遠不需要更新，新的生成會自己出現。而最後那段話才是關鍵：它把資料夾規則寫進 agent 的記憶檔（`CLAUDE.md`），讓 skill 和 gallery 永遠指向同一個地方。

擁有自己的素材庫後，你還能加上客製功能。例如一個 styles 區：點一下某個「電影感液態玻璃」風格，它就複製該風格的 prompt 加上參考圖檔路徑，直接送給 Claude 重現。這讓風格變成可重複套用的資產，而不是一次性的 prompt。

實際跑起來是什麼樣子

把這一切串起來看一個例子。你 invoke `/generate`，貼上一段 prompt：要為一款真實產品（ketone-IQ 能量飲）做多張形象廣告，並附上參考圖讓 agent 理解品牌過去的設計系統。你在規則裡設定總預算是 $3、要求用不同模型（GPT Image 2、Nano Banana 2、Nano Banana Pro）各生三張，並指定用已連接來源中最便宜的供應商。Claude 負責撰寫 prompt、路由到對應供應商，最後回傳每個模型三張、彼此刻意不同的圖，這正是用來比較、鎖定風格的好方法。

接著在同一段對話裡，你複製某張喜歡的圖的檔案路徑，請 Claude Code 用它做一個網站：把該圖用 Kling 轉成影片當背景、讓網站配色對齊那張圖、再生成幾張同風格的圖。結果是一分鐘內做出大約七到八成的成品網站。這就是「素材路徑留在手邊」的威力：生成與後續應用能共用同一批資產。

最後的檢查表

生之前，先問三件事：這是草稿還是成品（草稿走便宜模型）？是圖片還是影片（影片一律先報價、等同意）？手上有真實參考圖嗎（沒有就先去要）？生成之後，確認檔案扁平地進了 generations、旁邊有同名 sidecar log。要做 gallery，就把那段 prompt 貼給 agent，並把資料夾規則寫進 CLAUDE.md。護欄防的是無謂的花費；當某顆模型的能力真的不可替代時，該用就用。

走到這裡，你手上已經是一整套系統：路由、護欄、模型庫、prompt 紀錄、gallery。真正有價值的從來不是「生成一張漂亮的圖」，那件事誰都會，有價值的是環繞在生成外面的這套系統本身。
