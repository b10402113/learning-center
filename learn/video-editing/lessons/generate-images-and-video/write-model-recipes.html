一模型一 recipe：五個模型與三種認證

Step 4/5 · 用 /generate 生圖生影

學習目標

這一節是查閱用的參考。讀完後，你能照著範本為一個模型寫出 recipe 檔，並能查表找到五個推薦模型的 id、供應商與價位，分辨三種認證形狀，以及每個模型是同步還是非同步。

前言：agent 要怎麼知道怎麼呼叫一顆模型？

上一節的 `SKILL.md` 在 Models 表裡寫著「Video (default)：your video model，recipe 在 models/video-model.md」。那個 recipe 檔就是這一節的主角。

你可以把 recipe 想成一本「模型的說明書」：端點在哪、要用哪把 key、request 的 JSON 長什麼樣、回應要從哪個欄位拿檔案。少了它，agent 空有路由規則卻不知道怎麼打電話。這一節先把範本與五顆值得接的模型列清楚，做法是把供應商的 API 文件打開，照著填，一顆模型大約十分鐘，填過一次就不用再填。

recipe 範本：一顆模型一份 Markdown

每個模型在 `models/` 底下有自己的檔案，內容照這個模板填：

# Model Name


One line on what this model is best at and when to pick it.


| Field | Value |
|---|---|
| Model ID | the-exact-model-id |
| Provider | Kie AI / fal.ai / WaveSpeed AI |
| Method | Sync (instant reply) or Async (submit, then poll) |
| Type | Image or Video |
| API key | .env -> KEY_NAME |
| Docs | link to the provider's page for this model |
| Cost | rough price per image / per second |


## Endpoint
POST https://...


## Request format
(the exact JSON body from the docs, with prompt, aspect ratio,
resolution, reference image fields)

## Response handling
(where the image/video lives in the reply: base64 field, or a URL
to download. For async: the status endpoint and the field that
says "done".)

## Notes
(gotchas: rate limits, max sizes, content rules, upload quirks)

幾個欄位值得先講清楚：Model ID 要填供應商文件上的精確字串，不能靠記憶；Method 要標明是同步還是非同步，因為弄反是第一次嘗試「看起來卡住」最常見的原因；Response handling 則要寫明圖或影片出現在回應的哪個欄位（可能是 base64，也可能是下載網址）。

非同步的標準流程

多數影片模型都不是「叫了馬上回」，而是走非同步。這套流程固定得像食譜，背下來就好：

1. POST the job             -> the reply contains a task id
2. Poll the status URL       -> every 5 to 10 seconds, patiently
3. Status says complete      -> the reply now contains a file URL
4. Download immediately      -> result URLs often expire in hours
5. Save into your generations folder, then write the log

先送工作、拿到 task id，接著每隔幾秒去問狀態，等它說完成，回覆裡就會出現檔案網址。這裡有個容易吃虧的地方：結果網址常常幾小時後就失效，所以拿到要立刻下載，存進 generations 資料夾再寫 log。建議先接兩份 recipe，一顆便宜的圖片模型、一顆影片模型，之後需要再加。

三種認證形狀：同一件事，三種寫法

這是新手最常卡住的地方。三家的認證方式不同，但只要每家搞懂一次，該家所有模型就都能用：

供應商形狀放法
Google AI Studiokey 放在網址裡POST .../models/{model-id}:generateContent?key={GOOGLE_KEY}
fal.ai標頭，用 Key 這個字POST https://fal.run/{model-id}，標頭 Authorization: Key {FAL_KEY}
Kie AI標頭，用 Bearer 這個字POST api.kie.ai/api/v1/jobs/createTask，標頭 Authorization: Bearer {KIE_KEY}

同步還是非同步，一顆一顆看

GPT Image 2、Nano Banana 與 Seedance 屬於同步：一次呼叫就回傳完成的結果。Kling 與 Veo 屬於非同步：先給你一個 job id，之後每 10–15 秒去問狀態端點，直到它說 done。務必把每顆模型用的是哪一種寫進它的 recipe，因為弄反，正是第一次嘗試看似當掉的最常見原因。

不要第一天就把五顆全接上

建議先接 Nano Banana 2 Lite（圖片）與 Kling 3.0（影片）。這兩顆是各自領域裡最便宜的，剛好又能讓你練習兩種模式，一個同步、一個非同步。之後再視需求擴充：第一次需要圖內可讀文字時接上 GPT Image 2；當 Kling 的動態不夠好、需要一張主視覺時接上 Veo 3.1；想把參考圖動起來時再接 Seedance 2.0 Fast。

之後怎麼加新模型

模型會隨供應商改版而變動。當呼叫回傳「model not found」，就到該供應商的模型頁複製最新 id，更新 recipe 檔即可，這也是整套系統唯一需要的日常維護。要加入一顆全新的模型，例如 Google 的 Omni Flash，做法是到 fal.ai 點右上角的「Copy content for LLMs」，把複製到的內容連同一句「把這個加進 /generate skill」交給 Claude，agent 就會照著文件建立新的 recipe。

這份參考怎麼用

需要呼叫一顆模型時，答案都在它的 recipe 檔裡：Model ID 用精確字串、Provider 決定路由、Method 標明 sync 或 async、Response handling 指明檔案在回應的哪個欄位。五顆推薦模型與三種認證形狀查上面的表就好。先從 Nano Banana 2 Lite 與 Kling 3.0 開始，其餘按需求再補。
