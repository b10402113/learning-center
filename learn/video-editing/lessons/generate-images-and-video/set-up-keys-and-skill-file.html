取得金鑰並寫出 SKILL.md

Step 3/5 · 用 /generate 生圖生影

學習目標

做完這一節，你的專案會有一個寫好三把金鑰的 `.env`，以及一份帶著模型表、供應商路由規則與護欄的 `.claude/skills/generate/SKILL.md`，可以開始被 agent 讀取。

前言：先讓 agent 拿得到鑰匙

前兩節把「為什麼」和「長什麼樣」講完了，現在要開始動手。這一步做完，你不會有任何生成的成品，但會把整套系統的骨架立起來，這是後面所有操作的前提。

想像你要把一間店交給店長。你得先給他進貨用的通行證（金鑰），再給他一本寫清楚怎麼選供應商、東西放哪裡的員工手冊（`SKILL.md`）。兩者缺一不可：沒有通行證，什麼都叫不動；沒有手冊，店長每次都得重新猜你的規矩。這一節就是把這兩樣東西準備好。

第一步：申請三個聚合商的 key

你不需要向每一家 AI 實驗室各自開帳號。聚合商把很多模型放在同一把 key、同一張帳單後面。只要申請下面三家，幾乎所有重要的圖像與影片模型都能碰到：

供應商申請網址.env 中的金鑰名稱它在這裡的角色
Kie AIkie.aiKIE_API_KEY熱門模型常是最便宜的路，還能把本機圖片上傳成公開網址
fal.aifal.aiFAL_KEY快、模型目錄大、文件最好，是第一順位備援
WaveSpeed AIwavespeed.aiWAVESPEED_API_KEY模型庫廣，前兩家缺模型或被拒時派上用場，是第二順位備援

到各家的後台複製 API key，接著在工作區根目錄建立一個 `.env` 檔，把三把 key 填進去：

KIE_API_KEY=your_key_here
FAL_KEY=your_key_here
WAVESPEED_API_KEY=your_key_here

這個檔案一定要排除在版本控制之外（把 `.env` 加進 `.gitignore`）。skill 會告訴 agent 從這裡讀 key，而不是把 key 貼進程式碼裡。這樣就算你把專案分享出去，也不會連鑰匙一起送人。

為什麼要三把而不是一把？因為後面「路由」的邏輯是先試最便宜的、不行再退到下一家。只接一家，就沒有備援可言；哪家臨時掛掉或沒收錄某顆模型，整個流程就卡住。

順手認識一下行情

在開始花錢之前，先對價錢有個概念。以下是當時的大致價格（會變動，實際以供應商定價頁為準）：

工作大約價格說明
草稿圖，便宜模型$0.01–$0.03你的預設，可以放心大量迭代
成圖，頂級模型$0.05–$0.15只留給定稿，等你挑到喜歡的草稿再跑
影片，每秒$0.20–$0.35十秒影片就是 $2–$3.50，這就是為什麼需要成本護欄

第二步：寫出 SKILL.md

建立檔案 `.claude/skills/generate/SKILL.md`。它的 frontmatter 告訴 agent 什麼時候該用這支 skill，本文則告訴它怎麼用。下面這份可以直接複製，再把模型與資料夾路徑換成你自己的：

---
name: generate
description: Generate images and videos via AI model APIs. Triggers on
  /generate, generate image, generate video, create image, thumbnail,
  animate.
---


# /generate


## Models


| Task | Default model | Recipe |
|---|---|---|
| Image (default) | your cheap image model | models/image-model.md |
| Image (quality) | your hero image model              | models/image-model-pro.md |
| Video (default) | your video model                   | models/video-model.md |


Read the recipe file before every generation.


## Provider routing
1. Default to the LOWEST COST provider that runs the model well
   (check Kie AI, fal.ai, WaveSpeed AI).
2. If the cheapest route lacks the model, fails auth, or errors,
   fall back to the next provider.
3. Never hide a provider swap. Say which route ran and why.


## Output
- Save every file FLAT into my generations folder: [your path here]
- No subfolders. Reference images live in generations/refs/
- Naming: {project}_{description}_{timestamp}.{ext}

## Rules
- Quote the cost and wait for my explicit go before any paid
  video run. One approval = one run.
- Draft on the cheap image model first. Only rerun on a quality
  model when I pick a favourite.
- Never describe a logo or face in text. Pass the real image
  file as a reference. If it's missing, stop and ask me for it.
- Run multiple generations one at a time to avoid rate limits.
- After every save, write the sidecar log (see Logging).

這份檔案的幾個區塊各有任務，值得逐一看懂：

  • frontmatter 的 description：這行最重要。agent 就是靠它來判斷「現在該不該動用這支 skill」，所以要把你平常真的會打的字都列進去，例如 `/generate`、generate image、thumbnail、animate。
  • Models 表：把任務對應到預設模型與 recipe 檔路徑，並要求「每次生成前先讀 recipe」。
  • Provider routing：明確規定先試最便宜的供應商，缺模型、認證失敗或出錯才往下退，而且換供應商不能偷偷來，要說清楚跑了哪條路、為什麼。
  • Output：規定檔案扁平地存進你的 generations 資料夾、參考圖放 refs、命名採用 {project}_{description}_{timestamp}.{ext}。記得把 [your path here] 換成你自己的完整路徑，而且之後不要搬動它。
  • Rules：這就是整份合約。成本要先報價、草稿先用便宜模型、logo 與人臉要用真圖、多次生成一次跑一個、每次存檔都寫 sidecar log，這些護欄都從這裡生效。

填寫時有兩個地方特別容易漏。第一，description 若寫得太籠統，agent 會在你需要生圖時想不起這支 skill；第二，Output 的路徑若和後面 gallery 指的路徑不一致，成果就不會出現在同一面牆上。這兩個路徑一定要對齊。

做完會看到什麼

完成後，你的工作區會多出一個 `.env` 與一個 `.claude/skills/generate/SKILL.md`。此時還不能生圖，因為 Models 表指向的 recipe 檔還不存在。但你已經完成了最關鍵的骨架：金鑰就定位，規則也白紙黑字寫死。

這裡刻意不解釋「為什麼路由要最便宜優先、護欄為什麼這樣設計」的原理，那些留到最後一節的抉擇單元再談。現在只要記得：手冊先立好，之後要改規矩，永遠是改這一份文件。
