calibrate：把回饋吸收進 skill，然後再跑一輪

Step 5/5 · 打造並校準 /animate skill

前言：規則寫好了，但 skill 還沒變

到目前為止，你手上有一份帶著什麼、何時、永遠或絕不的 pattern 清單，也可能已經把幾個常用元件登記進了元素庫。但先別高興得太早，這些東西目前都還在你這邊，那份 agent 實際會讀的 skill 檔，一個字都還沒動。

這就像你把一整疊修改意見寫在便條紙上，卻沒有把它交給剪輯師。下一支影片，agent 還是照著原本那份舊的、粗的 skill 做事，你這一輪的判斷等於白費。

這一課要把循環收尾，也是最後一哩：用一句 calibrate，讓 agent 把這一輪的觀察「吸收」進檔案；然後分辨什麼叫做一次好的更新；最後拿同一份 brief 再跑一輪，直到輸出不再讓你驚訝。

學習目標與前置條件

學完這一課，你應該能用 calibrate 指令更新 skill，判斷更新有沒有把規則「吸收」進去，並跑完 render→compare→calibrate 的迴圈；最後，把整條流程收斂成一行指令。

動手前，你需要的是一份寫好、夠通用的 pattern 清單。如果你手上還沒有，先回到上一課把它寫出來；校準的品質，取決於你餵進去的規則品質。

步驟一：送出 calibrate 指令與這一輪的 pattern

更新的動作通常只要一句話。你把 calibrate 指令和這一輪的 pattern 貼給 agent，格式大致如下：

calibrate my /animate skill with this feedback:
- Every transition is 0.4 seconds, sharp in and sharp out, with motion blur while it moves, then a clean hold.
- Subtitles show at most two words at once, timed to the actual audio, with the current word in orange.
- Every number the narration says gets its own big orange count-up on screen, over half a second.
Fold each one into the rule it belongs to instead of adding a new section at the bottom. Keep the skill short. Write the reason next to each rule, not the date. Then tell me exactly what changed.

這段指令裡藏了三個要求，每一個都在防止 skill 走向「愈改愈亂」：把規則折進它原本所屬的那條規則，而不是在檔案最後新增一個區塊；保持檔案簡短；把原因寫在規則旁邊，而不是寫上日期。最後一句「告訴我到底改了什麼」，則讓你可以在幾秒內檢查這次更新有沒有走偏。

步驟二：用三個標準判斷更新好不好

agent 回報更新完成後，不要只看它有沒有跑完，要用三個標準檢查：

標準好的樣子壞的警訊
吸收，而非附加新規則取代舊規則原本的措辭，就地更新檔案長出一個標著「round 4 fixes」的日期區塊
原因跟著規則走規則旁寫著「一次兩字，因為手機讀者只看一眼」，下一輪還判斷得出適不適用只寫「週二定案」，下一輪沒人知道它還算不算數
檔案保持簡短校準後的 skill 通常比前一版更短長度不斷增加，代表 agent 在堆疊而不是吸收

如果 agent 開始在檔案底下堆積一整排「本輪修正」，你要主動推回去。因為那些堆疊的區塊不會互相對話，下一輪的 agent 讀到的是一團互相矛盾的新舊規則，反而更容易做錯。

The rule is absorbed, not appended. If the skill grows a dated "round 4 fixes" block, push back. The new rule should replace the old wording where it lives.

記住這個反直覺的判準：好的校準會讓檔案變短。如果每次更新都讓檔案更長，通常不是因為你學得更多，而是因為 agent 把新規則疊在舊規則上，而沒有真的把它融進去。

步驟三：跑 render → compare → calibrate 的迴圈

更新完 skill 之後，不要急著拿它去做正式專案。先跑一輪完整的比較：

  1. 用更新後的 skill，拿同一份測試 brief 再算一次。
  2. 把新版本和上一版並排播放，記下哪些改善了、哪些還是礙眼。
  3. 寫下一輪的 pattern：這次有效的，升格成「永遠」；還是沒改好的，寫成「絕不」。
  4. 再一次 calibrate。

這個迴圈要跑到什麼時候？答案是：當輸出不再讓你驚訝。打開新版本，心裡沒有冒出「咦，這裡怎麼這樣」，而是「對，就是這樣」，那就差不多了。接下來，你就可以把這顆 skill 指向一支真實的錄影，而不只是測試 brief。

這裡的心態很重要：校準不是一次性的修正，而是一個每次都跑一點的習慣。每一輪都會把更多你的判斷寫進檔案，下一次的起點就更高。累積幾輪之後，你會發現需要的留言愈來愈少，因為 agent 已經慢慢長出你的品味。

想更省事？把「更新 skill」也變成一顆小 skill

如果你不想每次都手打 calibrate 指令，可以把它獨立成一顆專門的小 skill，在每支影片收工後呼叫它。它做的事情是讓 agent 自己做一次賽後檢討，回來給你幾條可採用的建議：

recommend to me bullet point ideas on how it can calibrate our skills, our memory, in order to make itself better at the end of every session.

這一步是可選的加速器，不是必需品。先用最土砲的方式手動跑循環，等到你熟悉這個節奏、也確定哪些規則值得沉澱，再考慮把它自動化。順序反過來，只會讓你自動化一組還不夠好的規則。

最後一哩：把它收斂成一行指令

轉錄、剪片、套用設計系統、算圖、檢查，整條流程都被吸收進同一顆 skill 之後，你就可以把它從「一步一步下指令」收斂成「一行」。做法是請 agent 把目前為止做過的一切打包成一個可重複使用的 skill：

now turn everything we just did into one reusable skill called /animate, so next time a single prompt does the whole edit.
- save it as a skill, or whatever your setup calls a saved instruction
- it takes one thing: the path to my raw video
- it runs the steps in order: transcribe and cut, animate with my design system, render, then check the frames
- keep DESIGN.md inside the skill so every video gets my look
- it reads my AssemblyAI key from the .env file, never from this chat
- add every fix i asked for in this session as a rule, with the reason behind it, so you don't repeat the mistake
- test it once on a short clip and show me the result
whenever i correct a video from now on, add the fix to the skill so it gets better every time.

打包完成後，下一支影片的指令就只剩下一行：把路徑指給它就好。而這段 prompt 裡最值得留下的一句，是最後那行：「從現在起，每次我修正一支影片，就把那個修正加進 skill，讓它一次比一次好」。這等於把整個循環寫成一條常駐的規定，讓它自動持續下去。

當然，skill 裡除了「怎麼改」，也要有「什麼時候該停」。例如這類護欄規則：一份 composition 完成前一定要先跑檢查，確認零錯誤；遇到要花錢的生成步驟，先報價、等到明確同意再呼叫。這些規則和前面的風格規則一樣，都該帶著原因寫進檔案，而不是靠你每次口頭提醒。

Always run `npx hyperframes@latest lint` before claiming a composition is done. It must come back with 0 errors.

小結

calibrate 是讓回饋真正生效的一步：把這一輪的 pattern 貼給 agent，請它折進規則原本所在的地方、保留原因、保持檔案簡短，然後拿同一份 brief 再算一次、再比一次。好的更新會讓檔案變短，而不是長出一堆日期區塊。這個迴圈要跑到輸出不再讓你驚訝為止，最後再把它收斂成一行指令，並加上一條常駐規定：每次修正都回寫進 skill。

到這裡，你已經走完打造與校準 skill 的五個步驟：從「skill 是一份檔案」的觀念，到三步循環，到把觀察寫成 pattern、把元件登記進元素庫，最後用 calibrate 收尾。回頭看會發現，真正值錢的從來不是那一句 starter prompt，而是你一輪又一輪餵回去的品味。starter prompt 幾分鐘就能拿到，但那份愈用愈準的 skill，是你在每一次修正裡慢慢養出來的。
