三步循環：知道工具、給回饋、更新 skill

Step 2/5 · 打造並校準 /animate skill

前言：第一版拿到手之後，多數人就停了

上一課我們確認了一件事：skill 就是一份 agent 會先讀的 markdown 檔，而第一版本來就粗。現在你手上有一份能跑的第一版，也看過它做出來的測試影片了。問題是，接下來呢？

很多人在這裡就停了。他們把「能跑」當成「做完了」，於是每一支影片都在同一種預設感裡打轉。少數人隱約知道要改，卻改得很隨機：今天覺得轉場太慢，就補一句「轉場快一點」；明天覺得字幕太擠，再補一句「字幕短一點」。不久之後，那份 skill 檔變成一本愈來愈厚的流水帳，agent 讀起來反而更糊塗。

真正有效的做法不是一直加東西，而是跑一個固定的循環。這個循環只有三步，卻能反覆把粗略的第一版，養成一份你真的敢拿出去用的 skill。這一課要把這三步攤開來看，你之後每一次 refine，都會回到這個節奏。

學習目標

學完這一課，你應該能說出這三步循環，也就是知道工具、給結構化回饋、更新 skill，並理解它是一個持續的迴圈，不是一次性的修正。

三步循環長什麼樣

先把全貌放在你面前。這三步是：

步驟你要做的事一句話記法
Step 1知道工具，做出第一版先做出一個能反應的東西
Step 2把回饋寫成 pattern 餵回去強化喜歡的，修掉其餘，一律寫成規則
Step 3請 agent 更新 skill一句 calibrate，把回饋吸收進檔案

看懂這張表之後，剩下的都只是細節。重點是：這三步不是一次走完就結束，而是走完之後再回頭走一次。第二輪的 Step 1 不必重建，直接拿更新過的 skill 跑同一份 brief 就好。

Step 1：知道工具，做出第一版

第一步的門檻比你想像的低。你不需要學會操作 HyperFrames，也不需要搞懂 AssemblyAI 的 API，更不需要會寫程式。你只需要「知道」每個工具負責什麼：HyperFrames 把 HTML 變成影片，AssemblyAI 把錄音轉成帶時間的字幕，而 agent 負責讀 skill、把整件事串起來。

用烹飪來比喻，這一步就是先確認廚房裡有哪幾樣器具。你不需要會打鐵做刀，只要知道哪把刀切菜、哪個鍋燉湯，就能開始做第一道菜。真正的功力之後再磨，現在只要先把菜端出來，你才有東西可以評論。

所以 Step 1 的產出，永遠是一支可播放的測試影片，外加一份粗略的 skill 檔。它的價值不在品質，而在於它是後面兩步的素材。

Step 2：給結構化回饋（整個循環裡最重要的一步）

第二步是這個循環的心臟。它的原則只有一句：強化你喜歡的，修掉其餘的，而且一律寫成規則，不要寫成一次性的修正。

「一次性的修正」是這樣：「第 12 秒的標題太大了。」這句話只對這支影片有效，下一支影片 agent 還是不會知道你的偏好。「可複用的規則」則會長成：「所有標題都不要超過畫面高度的五分之一。」前者是補丁，後者是通則。

要把觀察寫成好規則，有三種餵法：第一種是給它參考設計，把你想要的樣子的設計系統或截圖丟進去，說「照這個做」；第二種是新增規則，一句一條，講清楚永遠要怎樣、永遠不要怎樣，以及為什麼；第三種是建立元素庫，把你喜歡的元件登記一次，讓下一支影片直接重用。這三種餵法，會是下一課與下下課的主角。

這裡先記住一個判準：好的回饋帶著「什麼、何時、永遠／絕不」三個成分。缺了其中一個，agent 就只能猜。至於怎麼把「這裡怪怪的」翻譯成這三個成分，下一課會用真實例子拆給你看。

Step 3：更新 skill，然後再跑一輪

第三步出乎意料地簡單，通常只要一句話。你把這一輪的 pattern 貼給 agent，請它校準你的 skill：

calibrate my /animate skill with this feedback

agent 收到之後，會把這些規則折進 skill 檔裡。接著你要做的，是拿同一份測試 brief 再算一次，把新版本和上一版並排看：哪些改善了、哪些還是礙眼。然後回到 Step 2，寫下一輪的 pattern，再一次校準。

這裡有個關鍵心態：不要停在第三步。校準不是「用完就收」的一次性修正，而是每次使用都要走一遍的習慣。每跑一輪，你對「好」的判斷就更完整地寫進檔案裡，下一次的起點就更高。

同一個循環的三種說法

你之後會在不同教材裡看到這三步被取不同的名字，但骨頭是同一副。有人把它整理成 Build、Integrate、Tune：先建出第一版並引導它往「好的樣子」走，再把這一輪的引導整合進 skill，最後持續調校它，讓 agent 慢慢長出你想要的品味。

也有人乾脆把「更新 skill」獨立成一顆專門的小 skill，每次做完一支影片就呼叫它，讓 agent 自己做一次賽後檢討，回來給你幾條可以採用的調整建議。它收的指令大致是這樣：

I want to capture all of the learnings in this session and update the HyperFrames helper skill based on my feedback to you and all the best practices that you captured based on our conversation.

說法不同，做的事情一樣：把這一輪學到的東西，回寫進那份會被讀進去的檔案。你不必一次就建立這套自動化，先用最土砲的方式手動跑循環，等到節奏熟了再考慮把它包成一個指令。

小結

把粗略 skill 養成可交付 skill 的，是一個三步循環：Step 1 只要知道工具就做出第一版；Step 2 把觀察寫成可複用的 pattern 餵回去，這是整個循環最重要的一步；Step 3 用一句 calibrate 讓 agent 把回饋吸收進檔案，然後拿同一份 brief 再算一次、再比一次。它不是一次性修正，而是每次都要跑的迴圈。

現在你有了全貌：skill 是一份會決定成品的檔案，而 refine 它的方法是一個三步循環，其中第二步，也就是給結構化回饋，回報最高。下一步就是把這個最關鍵的步驟拆開來練。下一課會示範怎麼把「這裡怪怪的」翻譯成帶著什麼、何時、永遠或絕不的規則。
