元素庫與 catalog：讓喜歡的元件找得回來

Step 4/5 · 打造並校準 /animate skill

前言：每次都在重新發明同一個東西

做第二支影片的時候，你請 agent 做一個數字往上跳的動畫。做第五支的時候，你又請它做一次。做第十支的時候，你終於想起來：「等等，這個我好像做過。」於是你翻遍資料夾，找到一個看起來像的檔案，卻不確定它是不是最新版，也不確定當初的動畫參數在哪裡。

這種情況很常見。你其實一直在重複使用同樣的幾塊積木，數字 count-up、瀏覽器外框、一組小圖示，但因為沒有好好收納，每次都得從頭再來一遍。

上一課提到，把回饋餵回 skill 有三種管道，其中第三種就是「元素庫」。這一課要把這件事講清楚：元素庫是什麼、為什麼光是「把檔案存起來」還不夠，以及那個讓庫真正能被重複使用的關鍵動作。

學習目標

學完這一課，你應該能說明為什麼喜歡的元件要「登記一次」進元素庫，以及為什麼少了這個登記的動作，一座庫就會退化成一個沒人找得到東西的資料夾。

元素庫是什麼

元素庫的定義很直白：任何你喜歡的、想重複使用的元件，都把它收進同一個地方，登記一次。下一次做影片時，skill 直接取用，而不是重新發明一個八成像的版本。

它收的東西不一定很大。可能是一個數字往上跳的動畫、一個模擬瀏覽器視窗的外框，或是一組風格一致的圖示。三個例子都有一樣的特性：它們會一而再、再而三地出現在你的影片裡，而且每次重做都很浪費。

An element library. Any piece you liked (a count-up number, a browser frame, an icon set) gets registered once so the next video reuses it instead of reinventing it.

關鍵詞是 registered once，也就是登記一次，不是隨手丟進某個資料夾。這兩者的差別，就是下一段要談的重點。

存檔不等於建成一座庫

很多人以為，把做好的元件丟進一個資料夾，就叫作建立了元素庫。但過一陣子你就會發現：資料夾裡躺著十七個檔案，檔名一個比一個像亂碼，你不知道哪個可以再用、哪個已經過時、哪個才是你要的那版。於是你還是從頭做了一個新的。

差別在哪裡？差在你只「存了檔」，卻沒有「登記」。存檔是把東西放進抽屜，登記是替它寫一張標籤。有標籤，你下次才找得到它、才敢用它。沒有標籤的抽屜，東西再多也等於不存在。

Register every piece you keep in a catalog, or it is a folder, not a library.

這句話值得多想一下：一個你再也找不到的元件，不是庫藏，只是一個檔案。真正的元素庫，是由一份「知道每個元件是什麼、放在哪、什麼時候該用」的目錄撐起來的。這份目錄就是元素庫的靈魂，檔案本身只是它的身體。

登記一次，為什麼就夠了

「登記一次」聽起來很省事，但它其實是一個很強的承諾。它代表這個元件從此有了明確的身分，而不是散落在無數次對話裡的某個產出。之後要重做一支影片，skill 可以沿著這份目錄找到它、取用它，你不必再重新描述一遍「我要一個橘色的、跑半秒的、往上跳的數字」。

更實際的好處是品質穩定。你自己重做同一個動畫兩次，很可能得到兩個八成像但不完全一樣的結果，速度差一點、緩動曲線差一點。取用同一個登記過的元件，每次就都是同一個樣子。這正是「像同一個節目」和「像同一個人的隨手作品」之間的差距。

元素庫在整個循環裡的位置

回頭看三步循環，元素庫是 Step 2「給結構化回饋」的第三種餵法。它和參考設計、新增規則不同的地方在於：另外兩種改變的是 agent 的行為，元素庫累積的是你的資產。

也因為如此，建好庫並不代表事情結束。你還要在 Step 3 的校準裡，讓 skill 知道這個庫的存在，否則它不知道有東西可以取用，還是會照自己的預設重做一遍。庫是你的資產，校準是把這份資產接進 skill 的動作，兩者要一起做才有意義。

這也是為什麼前後幾課會一直回到同一個節奏：觀察、寫成 pattern、餵回 skill、更新。元素庫不是一條岔出去的路，而是這個循環裡專門處理「重複使用」的那一支。

小結

元素庫收的是你一再用到的元件，數字 count-up、瀏覽器外框、一組圖示。它的重點是「登記一次」，不是把檔案存起來，讓每個元件有明確的身分與位置，skill 下次才找得到、才敢重用。少了登記，一座庫就只是一個沒人翻得懂的資料夾，有了登記，它才會隨著你做的每一支影片愈長愈大。

到這裡，你已經有了兩種把東西餵回 skill 的方式：描述行為的 pattern，以及累積資產的元素庫。但這兩樣東西目前都還放在你手上，skill 本身還沒有變。最後一課要把整個循環收尾：用一句 calibrate，讓 agent 把回饋真正「吸收」進檔案，然後再跑一輪，直到輸出不再讓你驚訝。
