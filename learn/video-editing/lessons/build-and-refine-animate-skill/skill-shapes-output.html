skill 就是一份 markdown 檔：同一段素材，兩種結果

Step 1/5 · 打造並校準 /animate skill

前言：換了模型，成品卻還是同一種味道

你花了週末把一支影片從素材剪到成品。畫面能看，節奏也順，但你心裡清楚：那套轉場、那組字體、那種字幕出現的方式，跟你上個月做的另一支影片一模一樣，甚至跟網路上很多人做出來的東西也很像。

你換了模型、重寫了 prompt、多丟了幾句「做得更有質感一點」，看起來卻還是同一種味道。於是問題很容易被歸咎到模型身上：是不是它不夠強？但你會發現，換一個更貴的模型，味道通常只是從「A 牌的預設感」變成「B 牌的預設感」。

真正的問題，可能出在一個很少人會打開來看的地方：你的 agent 動手之前，讀的那份規則檔。這份檔案叫做 skill，它裝著 agent 對「好」的預設理解。這一課要把 skill 到底是什麼講清楚，並且讓你看懂：為什麼同一段素材，餵給校準程度不同的 skill，會跑出完全不同的結果。

學習目標

學完這一課，你應該能說出 skill 其實就是一份 agent 在動手前會讀的 markdown 檔，並且解釋為什麼同一段素材會因為 skill 校準程度不同，而產出「勉強能看」與「眼睛一亮」兩種結果。

skill 不是外掛，是一份會被讀進去的檔案

先破除一個常見的誤解。skill 聽起來很像某種外掛、某種模型設定，或某種要安裝的功能。但說穿了，它就是一份 markdown 檔案，一份純文字。差別只在於 agent 在執行某類任務之前，會先把這份檔案讀一遍，再照著裡面的規定做事。

你可以把它想成給新進剪輯師的一份工作手冊。手冊裡不會寫「請做出好影片」這種空話，而是寫下具體的規矩：轉場要多長、字幕一次露幾個字、數字出現時要怎麼處理。手冊愈貼近你的審美，剪輯師端出來的東西就愈像你要的；手冊愈含糊，他就只能用自己的直覺補洞，補出來的通常就是他的直覺，而不是你的。

以這個課程的主角 /animate 來說，它負責的事情是：吃進一段原始素材或一份腳本，吐出一支剪好的短片。skill 檔裡寫的，就是這段「素材進、影片出」的轉換必須遵守的所有規則。

turns HTML into video
AssemblyAI
transcribes the recording
Codex or Claude Code
the agent that runs the skill

上面這三行，是這顆 skill 背後的三個角色。你不需要會寫程式去操作它們，你只需要知道它們各自負責什麼，然後把「你要它們怎麼做」寫進 skill 檔。剩下的，交給 agent 去執行。

同一段素材，兩種結果

現在來看看 skill 的校準程度，會造成多大的差別。想像同一段原始影片，交給兩份不同的 skill。

輸入經過的 skill輸出
原始影片未校準的 skill（一個 prompt 生出來的粗略第一版）勉強能看（meh）
原始影片已校準的 skill（你的規則、你的參考）眼睛一亮（wow）

兩邊用的是同一段素材，很可能也是同一個模型。差別只有一個：那份檔案裡裝了多少你的品味。

這張表推翻了很多人對 AI 剪片的直覺。大家習慣把注意力放在「模型選哪一顆」、「prompt 怎麼下」，卻忽略了模型只是執行者，真正決定風格的是那份被讀進去的規則。就像同樣一位廚師，給他一本隨手寫的食譜和一本你家傳的食譜，端出來的會是兩道菜。

未校準的 skill：能跑，但長得像別人的

未校準的 skill 是怎麼來的？通常就是一句 prompt。你請 agent 用某兩個工具做出一顆剪片 skill，它很快就生出一份可以用的檔案，也很快交出一支測試影片。這個階段一點都不難。

麻煩的地方在於：這份第一版會直接繼承 agent 的預設值。它不知道你的品牌配色、不知道你喜歡的轉場節奏，只能用它訓練時看過的大量素材，猜一個「大概沒問題」的樣子。結果就是，任何一個跳過校準、直接用預設 skill 的人，拿到的都會是同一套設計感。

這種「大家都長一樣」的結果，常被形容成一種看起來很順、但沒有靈魂的預設風格。它不算壞，只是不特別。而多數人停在這裡，以為自己已經完成了，於是每支影片都停在「還行」。真正拉開差距的，是接下來那份檔案能不能被餵進你的判斷。

第一版本來就粗，重點是之後的迴圈

這裡要先給你一個誠實的期待：第一版本來就是粗的，那不是失敗，是設計。它便宜又快速，一句 prompt、幾分鐘，就有了一支你可以立刻打開來看的測試影片。先求一個「看得到、能反應」的起點，不用一次到位。

真正讓 skill 變成你的，是之後的迴圈。每一輪你看著輸出，說出你喜歡什麼、想改什麼，再讓 agent 把這些意見折進檔案裡。於是 skill 愈來愈準，而且有意思的是，檔案通常會愈來愈短。因為好的校準是把規則收斂成更精確的說法，而不是在檔案尾巴不斷追加新的補丁。

這也解釋了為什麼同一份手冊，有人養成一把鋒利的小刀，有人養成一疊沒人想翻的剪貼簿。差別不在天份，而在有沒有把每次的觀察，好好地餵回那份檔案。

小結

skill 就是一份 agent 動手前會讀的 markdown 檔。同一段素材、同一個模型，餵進未校準的 skill 得到「勉強能看」，餵進帶著你的規則與參考的 skill 得到「眼睛一亮」。決定成品的是那份檔案裡裝了多少你的品味，不是模型。第一版一定粗，那是設計的一部分；真正的工作，是之後把觀察折回檔案的那個迴圈。

現在你知道 skill 是一份會被讀進去、也會決定成品樣貌的檔案。下一個問題很自然：這份檔案要怎麼從粗略變成精準？答案是一個只有三步的循環，不是哪一句神奇 prompt。下一課會把這個循環攤開來看。
