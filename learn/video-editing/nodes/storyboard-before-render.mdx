# 先分鏡，再渲染

## Learning goal

能用 HTML 分鏡（場景、時間、文案預覽）先規劃影片，並用帶時間碼的釘選留言定調，再進入渲染。

## Steps

1. [[learn/video-editing/nodes/storyboard-before-render/why-storyboard-before-render|為什麼要先分鏡再渲染]] — 說明第一個 prompt 通常不夠精確，先分鏡能把「發現方向錯了」的成本壓到最低，並把修正拉到大約前三分之一的位置
2. [[learn/video-editing/nodes/storyboard-before-render/what-a-storyboard-contains|一頁 HTML 分鏡裡有什麼]] — 列出分鏡該有的欄位：影片描述、場景數、總時長、逐場景秒數、每幕靜態畫面與文案預覽（after step 1）
3. [[learn/video-editing/nodes/storyboard-before-render/the-storyboard-prompt|怎麼要 agent 先做分鏡]] — 寫出「先不要做影片、先分鏡、停下來等我留言」的 prompt（after step 2）
4. [[learn/video-editing/nodes/storyboard-before-render/pin-comments-with-timecode|用帶時間碼的釘選留言定調]] — 在畫面上釘選帶鏡頭、時間、座標的留言，一次複製全部貼回（after step 3）
5. [[learn/video-editing/nodes/storyboard-before-render/storyboard-to-render-decision|再分鏡一輪，還是直接進渲染？]] — 用「離目標多近、留言是大方向還是小修」決定要不要再跑一輪分鏡（after step 4）

## Lesson

分鏡是介於「一句話 one-shot」和「正式渲染」之間的便宜檢查點。它的做法很樸素：在東西開始動之前，把每一幕做成靜態的 HTML 畫面、截圖、排成一頁，並標上開始時間與一句描述；你先看這一頁、在畫面上釘選留言，把方向拉正，再讓 agent 去 build 或 render。這個節點把分鏡從「聽起來很合理」變成「我能自己發 prompt、跑完一輪留言、判斷什麼時候可以進渲染」：先講清楚為什麼要分鏡（把修正放在便宜的地方），再看一份分鏡該包含哪些欄位，接著學會怎麼要求 agent 產出分鏡、怎麼在畫面上釘選帶時間碼的留言，最後用一個 title-card 的真實案例，練習判斷「再分鏡一輪」或「直接進渲染」。
