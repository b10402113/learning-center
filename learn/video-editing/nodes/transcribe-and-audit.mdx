# 轉錄與逐字稿稽核

## Learning goal

能把原始素材轉成可信的逐字稿（AssemblyAI／Whisper／Scribe 的取捨），管好 API key，並產出原稿 vs 乾淨稿的並排稽核頁。

## Steps

1. [[learn/video-editing/nodes/transcribe-and-audit/transcript-as-backbone|逐字稿：agent 聽懂素材的方式]] — 說明為什麼轉錄是產線第一站，以及字級時間碼在剪片與動畫裡的角色（入口）
2. [[learn/video-editing/nodes/transcribe-and-audit/choose-transcription-tool|選轉錄工具與 API key]] — 在 AssemblyAI、Whisper、Scribe 之間取捨，並把金鑰放進 `.env`、不貼進對話（after step 1）
3. [[learn/video-editing/nodes/transcribe-and-audit/transcribe-raw-footage|跑轉錄：雲端與本機兩條路]] — 用 starter prompt 走 AssemblyAI，或用 faster-whisper 在本機取得字級時間碼（after step 2）
4. [[learn/video-editing/nodes/transcribe-and-audit/audit-side-by-side|原稿 vs 乾淨稿：並排稽核頁]] — 在剪片前產出並排稽核頁，確認要保留的完整文字（after step 3）

## Lesson

這一節處理的是整條產線最前面、卻最容易被跳過的一步：把影片裡的語音變成一份可信的逐字稿。你會發現 agent 剪片時其實不是「用眼睛看」你的素材，而是「用逐字稿讀」你的素材——它靠這份文字判斷哪裡是停頓、哪一句是 NG 重錄、哪個詞該在畫面上配一張圖。所以逐字稿的品質，直接決定了後面剪輯與動畫的品質。

這條線上有三個關鍵判斷。第一是選工具：AssemblyAI 快、需要一把 API key；Whisper 免費、跑在自己的電腦上但要等；ElevenLabs Scribe 適合本來就有訂閱的人。第二是把金鑰放對位置——寫進專案的 `.env`，讓工具自己去讀，永遠不要貼進對話。第三是在動刀之前先產出一張「原稿 vs 乾淨稿」的並排稽核頁，把要保留的完整文字攤開來讓你確認。三個判斷做完，你手上會有一份帶字級時間碼的逐字稿，以及一個經過你點頭的剪輯計畫，接下來才輪到真正的剪切。
