# 用 HyperFrames 算圖與品管

## Learning goal

能用 HyperFrames 渲染出對齊逐字稿的動態圖像影片，並做品管（composition 契約、Studio 時間軸、1080p 抽格檢查）。

## Steps

1. [[learn/video-editing/nodes/animate-with-hyperframes/composition-contract|什麼是 composition 契約：讓 HTML 能被穩定算成影片]] — 認出 composition 的結構與確定性規則，理解為什麼同一份 HTML 每次都能算出一樣的影片
2. [[learn/video-editing/nodes/animate-with-hyperframes/build-transcript-aligned-graphics|把動態圖像對齊逐字稿]] — 下動畫指令，讓圖像依逐字稿時間出現、套用 DESIGN.md，並先用一頁 storyboard 定調版面與卡片節奏（after step 1）
3. [[learn/video-editing/nodes/animate-with-hyperframes/studio-timeline-review|用 HyperFrames Studio 時間軸預覽與微調]] — 在 localhost 時間軸上預覽卡片與字幕、做小範圍微調，挑出要定稿的版本（after step 2）
4. [[learn/video-editing/nodes/animate-with-hyperframes/render-and-frame-qa|算 1920×1080 並抽格品管]] — 過 lint、渲染 1920×1080，抽開頭中段結尾三格檢查並確認長度一致（after step 3）

## Lesson

前面的節點已經把素材剪成一支乾淨的 `cut.mp4`、準備好 `DESIGN.md`，也畫出了分鏡。這個節點要把它接成一支真正的影片：用 HyperFrames 把動態圖像疊到剪好的畫面上，對齊逐字稿的時間，最後算成 1920×1080 的 MP4。

HyperFrames 的運作方式和生成式影片模型不同。它把你的 composition（一份 HTML，加上 CSS 與 JavaScript）在瀏覽器裡播放，再逐格錄成影片；畫面上的每個元素都是一個「片段」，各自帶著開始時間、長度與所在軌道。因為要「逐格」錄，composition 必須是確定性的：同樣一份 HTML，任何時候播放都要算出同樣的畫面。這套規則就是這裡說的 composition 契約，也是整個節點的地基。

契約之上，工作分成三段。第一步是把動態圖像對齊逐字稿：字幕與卡片要在講到那句話時出現，卡片一次只動一張，文字照著講出來的話走；版面則分成全畫面與「畫面縮到右下角直式卡片、左側放圖像」兩種，樣式一律取自 `DESIGN.md`。第二步是進 HyperFrames Studio：這是一個跑在 localhost 的時間軸介面，讓你在正式算圖前先預覽卡片與字幕、直接拖動片段的起點與長度，把版本調到滿意。第三步才是算圖與品管：算圖前先讓 lint 到 0 error，輸出 1920×1080，並抽出開頭、中段、結尾三格確認沒有遮到臉、沒有跑出畫面，而且長度與 `cut.mp4` 一模一樣，聲音才不會對不上。

四個步驟走完，你手上會有一支「有動態圖像、和逐字稿同步」的影片，以及一套可以重複的品管節奏。至於逐格回饋與限定範圍重算的「執導」，屬於下一個節點。
