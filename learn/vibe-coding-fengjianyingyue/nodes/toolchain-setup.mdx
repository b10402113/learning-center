# 工具鏈就緒：Claude Code / Node / git / JDK+Maven

## Learning goal

能在新機器從零把 Claude Code、Node、git 與 JDK/Maven 裝好並逐項驗證。

## Steps

1. [[learn/vibe-coding-fengjianyingyue/nodes/toolchain-setup/agent-runtime-and-version-checks|代理的底座：Node.js、git 與 Claude Code 全域安裝]] — 認得 Claude Code 是 npm 全域套件，用四個版本命令驗證底座
2. [[learn/vibe-coding-fengjianyingyue/nodes/toolchain-setup/jdk-maven-and-env-vars|JDK 與 Maven：安裝之後，真正麻煩的是環境變數]] — 設定 JAVA_HOME／MAVEN_HOME／PATH 並讓兩個版本命令講同一套話（after step 1）
3. [[learn/vibe-coding-fengjianyingyue/nodes/toolchain-setup/prompt-driven-readiness-inspection|用白話讓 agent 檢查與設定環境]] — inspect-only 提示詞與「人給路徑、agent 接線」的分工（after steps 1–2）

## Lesson

工具鏈就緒不是「裝好四樣東西」而已，而是三件事先各自站穩：裝得上、接得對、驗得出。這個節點把整條 vibe coding 產線的底座補齊。前面的 Claude Code 跑在 Node.js 與 git 上，後面的企業級 Java 階段（Spring Boot + MyBatis）又需要一套 JDK 與 Maven。兩半的安裝方式不同，但驗收邏輯一模一樣：每一個工具都用它自己的版本命令回答「我到底有沒有裝成功、是哪一個版本」。

第一個關鍵概念是 install → verify 這個循環。Claude Code 是發佈在 npm 上的全域套件，所以 Node.js 是它的執行環境、git 是它改檔案與做版本控制的底層；裝完之後不是憑感覺說「應該好了」，而是打 `claude --version` 看它自己報號。這個循環會一路重複到 JDK、Maven，甚至之後每一個 CLI 工具。

第二個關鍵概念是環境變數的接線。JDK 與 Maven 下載解壓只算辦完一半，`JAVA_HOME` 指到哪裡、`PATH` 把哪個 `java` 排在前面，才是真正決定 `mvn` 用哪套 JDK 的地方。這裡最常見的翻車不是「沒裝」，而是「裝了兩個版本，工具挑到錯的那個」，而且它安靜地跑，直到編譯出怪錯才被發現。

第三步把前兩步的操作收斂成提示詞工藝：你可以用白話請 agent「只檢查、不動手」先做環境就緒診斷，再用「路徑由我給、OS 相關設定交給 agent」的方式補上環境變數。走完這三步，你手上就有一套在任何新機器都能重跑的工具鏈檢查表，這也是後面每個階段能開工的前置條件。
