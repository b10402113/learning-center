# 專案骨架與 agent 說明書：角色化資料夾 + AGENTS.md/CLAUDE.md

## Learning goal

能為新產品搭出角色化資料夾骨架，並寫出讓 agent 不亂搞的 AGENTS.md/CLAUDE.md。

## Steps

1. [[learn/vibe-coding-fengjianyingyue/nodes/project-skeleton-and-agent-config/role-based-folder-skeleton|角色化資料夾骨架：把整條產線排成一個專案]] — 用角色命名資料夾，讓每個交付階段都有自己的容器
2. [[learn/vibe-coding-fengjianyingyue/nodes/project-skeleton-and-agent-config/agent-config-files|AGENTS.md 與 CLAUDE.md：一份給 agent 的專案說明書]] — 寫出專案概述、結構、指令、技術棧、設計系統與資料模型（after step 1）
3. [[learn/vibe-coding-fengjianyingyue/nodes/project-skeleton-and-agent-config/pin-agent-skills|把 agent 技能當依賴管：skills-lock.json 與技能落地位置]] — 用 source 與雜湊釘住第三方 skill，並放進 agent 讀得到的位置（after step 1）
4. [[learn/vibe-coding-fengjianyingyue/nodes/project-skeleton-and-agent-config/write-your-own-project-brief|換成你的產品：從骨架到第一份 AGENTS.md]] — 把骨架與說明書套到自己的產品，寫出第一版（after steps 1–3）

## Lesson

Vibe coding 最貴的浪費，是讓 agent 每次開工都重新猜一遍：這個專案用什麼棧、資料長什麼樣、指令怎麼跑、檔案該放哪。它猜錯你不一定馬上發現，等你發現時，它已經把一份資料模型寫成另一份、把新頁面丟到錯的目錄。

這節課處理的是開工前的那層地基。第一步先把專案排出**角色化資料夾**，讓產品經理、設計、前端、後端、DBA、測試、交付、營運各自有落腳處，也讓整條產線的順序直接寫在目錄名稱上。接著寫**agent 說明書**：`AGENTS.md` 與 `CLAUDE.md` 是一份內容、兩個入口，把專案概述、結構、指令、技術棧、設計系統與資料模型一次講清楚，agent 就不必再猜。最後把第三方 skill 當依賴來管，用 `skills-lock.json` 記下來源與內容雜湊，讓 agent 的能力來源可追溯、可重現。

四步走完，你會有一套固定的開場：先開資料夾，再寫說明書，再釘技能，最後把自己的產品套進去。
