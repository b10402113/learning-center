# 版本控制與 MCP：讓每次 AI 編輯都可回復

## Learning goal

能用白話讓 agent 初始化 repo、存檔、查歷史、回退，並接上 GitHub MCP。

## Steps

1. [[learn/vibe-coding-fengjianyingyue/nodes/version-control-safety-net/inspect-before-mutate|先檢查、不動手：用「只檢查」提示詞摸清環境]] — 用「只檢查、不做其他操作」的提示詞確認 git 環境與可否版控
2. [[learn/vibe-coding-fengjianyingyue/nodes/version-control-safety-net/commit-as-save-point|把 commit 當存檔點：初始化 repo 與第一次存檔]] — 建立本地 repo，完成第一次存檔並讓 agent 自動總結訊息（after step 1）
3. [[learn/vibe-coding-fengjianyingyue/nodes/version-control-safety-net/history-and-rollback|查歷史與回退：AI 改壞了怎麼還原]] — 列出存檔紀錄、挑 hash，把專案回退到指定版本（after step 2）
4. [[learn/vibe-coding-fengjianyingyue/nodes/version-control-safety-net/github-mcp|接上 GitHub MCP：讓 agent 能操作遠端 repo]] — 安裝並驗證 GitHub MCP，把本地專案推到遠端（after step 2）

## Lesson

Vibe coding 的節奏是「叫 agent 改一大段、看結果、再改」。這個節奏有一個前提：改壞了要能一鍵還原。沒有這個前提，你每次都得盯著 agent 的一舉一動，快不起來。版本控制就是那張安全網，它把 agent 每一次動手的結果切成一個一個「存檔點」，壞掉時退回上一個點，不必整包重做。

這節課談的是**用白話把版本控制外包給 agent**：怎麼先只檢查環境、怎麼讓 agent 初始化 repo 並自動寫好存檔訊息、怎麼查歷史並回退、最後怎麼接上 GitHub MCP 把成果推到遠端。四步走完，你手上會有一套固定的提示詞，以後任何新專案都能照著開場。
