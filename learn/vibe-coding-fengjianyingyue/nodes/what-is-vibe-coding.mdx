# 什麼是 vibe coding？何時白話快跑、何時該升級成 SDD

## Learning goal

能分辨「白話快跑的 vibe coding」與「工程化 SDD」兩種模式，並在正確時機選對。

## Steps

1. [[learn/vibe-coding-fengjianyingyue/nodes/what-is-vibe-coding/what-vibe-coding-is|什麼是 vibe coding？]] — 白話當介面：用日常語言描述意圖，讓 agent 產出能跑的東西（entry）
2. [[learn/vibe-coding-fengjianyingyue/nodes/what-is-vibe-coding/the-prompt-loop|白話快跑的迴路]] — 描述、產出、跑起來看、修正，以及 AI 生成碼的典型失敗模式（after step 1）
3. [[learn/vibe-coding-fengjianyingyue/nodes/what-is-vibe-coding/precise-plain-language|讓白話變精確]] — agent 說明書、逐頁規格、先計畫再寫碼（after steps 1–2）
4. [[learn/vibe-coding-fengjianyingyue/nodes/what-is-vibe-coding/when-to-upgrade-to-sdd|什麼時候該升級成 SDD？]] — 用風險、規模、協作、正確性判斷換模式的時機與交接（after step 3）

## Lesson

vibe coding 不是「叫 AI 幫忙寫幾行」，而是把日常語言本身當成開發介面：你說清楚要什麼，agent 產出能跑的東西，你看結果再修正。它的價值在速度——一句話就能讓點子變成畫面上的雛形。它的代價也在速度——繞過了規格、測試與審查，錯誤會用更難察覺的方式出現。

這門課的第一個節點先建立判斷力，而不是直接教你下指令。四個步驟會依序回答：它到底是什麼（1）、實際怎麼運轉、又會怎麼壞（2）、怎麼用幾個小道具讓白話變得精確（3）、以及什麼時候該停下來，換成工程化的 SDD 流程（4）。走完之後，你要能看著一個任務，先決定「這一場該用哪種模式」，再決定怎麼動手。

這套模式的細節，會用一個真實做過的全端專案當示範：財務管家（一個記帳 App）——從一句話、一份 PRD、一批 AI 生成的 UI，一路做到前端、後端、資料庫、跨端 App、測試與上線。你在後面的節點會反覆看到它的角色化資料夾與提示詞，這裡先拿它的 `AGENTS.md`、逐頁功能規格與測試提示詞當例子，看白話如何變成精確的工作指令。
