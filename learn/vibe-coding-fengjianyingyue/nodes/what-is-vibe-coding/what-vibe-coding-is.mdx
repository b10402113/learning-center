<LearningGoal>
能用一句話說出 vibe coding 是什麼、它跟「自己動手寫程式」差在哪，並說出它為什麼現在才變得可行。
</LearningGoal>

## Lesson

vibe coding（白話驅動開發）指的是：把日常語言本身當成開發介面。你用中文描述你要什麼，AI agent 產出能跑的東西，你看結果再修正。

這件事的意義，放在「開發介面換了」這個角度上看最清楚。以前你和電腦之間的介面是語法，你得用它能接受的符號講話；現在介面變成你平常講話的方式。介面一換，會寫程式的人和不會寫程式的人之間的距離就縮短了。這裡的 agent 也不是普通的聊天視窗，它能自己讀寫專案檔案、執行終端機指令，例如 Claude Code、opencode、Codex。你給它一句話，它會去開檔、改檔、跑指令，最後交給你一個可以打開來用的成品。

你的角色也跟著換。自己寫程式時，你的產出是一行一行的程式碼；用白話開發時，你的產出變成一段一段清楚的描述。你像導演：演員會演戲，但導演要決定這一幕要什麼情緒、哪裡不對、要不要重來。你不需要自己會演，但你得看得出好壞。這門課後面所有的技巧，本質上都在訓練這個判斷力。

「用白話叫電腦做事」這個念頭不新，早期的語音助理就試過，但只能做查天氣、設鬧鐘這種封閉小事。差別在於模型現在能一次讀懂一整個專案、記住脈絡，還能主動執行動作。當模型只會回你一段文字，白話開發就只能停在「幫我想個函式」；當它能讀你的資料夾、改你的檔案、跑你的指令，白話開發就變成一條完整的產線。

這條產線能走多遠，課程裡用一個真實做過的全端專案示範：財務管家，一個記帳 App。起點只是一句話，終點是一個可交付的產品，包含網頁前端、後端 API、MySQL 資料庫、Java 企業級重寫、營運後台、跨端 App、測試報告、上線文件，甚至推廣文案與影片。這整條路被整理成 12 個階段，每個階段對應一種角色，各自有資料夾與提示詞，一個人可以走完。這才是這門課要教的東西：不是零星的 AI 小技巧，而是一條能重複使用的交付流程。

白話開發最大的優點是快，最大的風險也來自快。它繞過規格、測試與審查，錯誤不會消失，只會換成更難察覺的樣子：程式看起來能跑，關鍵功能其實是假的；測試全部綠色，其實什麼都沒測；文件說做了，程式裡根本沒有。知道它怎麼壞，你才有資格用它來做真東西。
