接上 GitHub MCP：讓 agent 能操作遠端 repo

Step 4/4 · 版本控制與 MCP：讓每次 AI 編輯都可回復

這一步要完成什麼

完成後，你應該能做到三件事：安裝 GitHub MCP server、重啟 agent 後確認連線成功，並用白話提示詞把本地專案推送到指定的遠端 repo。同時，你也要知道 token 為什麼不能進版控。

完整實跑：從安裝到推送

1. 先讓 agent 接上 GitHub

到目前為止，存檔點都只在本機。硬碟故障、換電腦，或要和別人協作時，這些存檔就幫不上忙。要讓成果離開本機，得把它推到遠端倉庫，最常見的選擇就是 GitHub。

但 agent 預設只能看到本機檔案，不能列出你的遠端 repo、建立新倉庫，也不能把專案推上 GitHub。這裡需要一個對外的接口：MCP（Model Context Protocol，模型上下文協定）。

MCP 是讓 agent 接上外部工具的一套共用規格。GitHub 提供了 github-mcp-server；安裝後，agent 才有操作 GitHub 的能力。你可以把它想成替 agent 裝上一個外掛：沒裝時只能在本機活動，裝好後才伸得出手去碰遠端服務。

你可以直接這樣提示 agent：

幫我安裝 GitHub 的 MCP 工具。這是位址：https://github.com/github/github-mcp-server.git

也可以用一行指令把設定寫進去，同時指定連線方式與授權：

claude mcp add-json github '{"type":"http","url":"https://api.githubcopilot.com/mcp","headers":{"Authorization":"Bearer <你的 TOKEN>"}}'

這行設定可以拆成三部分：

  • type 是 http，表示使用 HTTP 連線。
  • url 是 GitHub 的 MCP 端點。
  • Authorization 標頭用來證明你有權限操作 GitHub。

設定完成後，先重啟 agent。MCP 設定通常是在 agent 啟動時讀取；只改設定、不重啟，就像把新工具放進工具箱卻沒有打開工具箱，agent 不會知道它已經存在。

2. 先做唯讀測試

不要一接上就直接推送或修改遠端內容。先用一個只讀問題確認連線：

查看我的 GitHub 所有的倉庫名稱。

這一步會同時檢查兩件事：agent 是否真的連上 GitHub，以及 token 是否有效。若連 repo 清單都列不出來，代表設定還沒完成；此時繼續要求它推送，只是在對著沒有接通的電話講話。

如果 agent 能列出倉庫名稱，才進入寫入操作。

3. 再把專案推到指定 repo

確認連線後，可以用白話提示詞要求同步：

把工作空間的 xxxxxx 這個專案推送同步到 test-claude-abc。

推送前，先確認兩個名稱：本地專案是不是正確的 xxxxxx，遠端目標是不是正確的 test-claude-abc。推送是把本地存檔送到遠端的寫入動作；一旦推錯位置，程式碼可能會出現在不該出現的 repo，變成公開在別人看得到的地方。

token 是鑰匙，不是一般設定值

Bearer 後面的 token 等於你在 GitHub 上的身分證明。拿到它的人，可能用你的名義操作倉庫，所以有兩條鐵律：

  • 不要把 token 寫進任何會被提交的檔案。
  • 不要把 token 貼到會留下紀錄的地方。

這也和前面提到的存檔流程接在一起。因為你不會手寫每一行，也不會逐一檢查 agent 做過的每個動作，更要依靠 .gitignore 與存檔前檢查，確認 token、.env 等敏感內容沒有被放進 repo。

AI 生成碼的風險不只在程式邏輯，也包括它可能把敏感資訊硬編碼進檔案，或在你沒注意時把它一起推上遠端。安全網要能擋住這種手滑，流程才算完整。

為什麼固定是「安裝、重啟、測試」

這是接入 MCP server 的固定節奏：

  1. 安裝：讓 agent 知道有哪些外部工具可用。
  2. 重啟：讓 agent 重新讀取最新設定。
  3. 測試：先用唯讀操作確認連線與權限，再進行寫入。

少了重啟，agent 可能根本沒載入新工具；少了唯讀測試，你就可能在連線尚未確認時直接做寫入操作。把流程切成這三步，問題會更容易定位，也比較不會把「設定錯誤」誤認成「推送失敗」。

本機存檔、遠端備份，三件套才完整

走到這裡，你有一個完整循環：

  • 本機有存檔點，出錯時可以回退。
  • 遠端有備份，換機器、協作與交付都接得上。
  • 每次操作前都有檢查，避免把錯的專案或敏感資訊推上去。

這些動作可以用白話提示詞完成，不必先背熟 git 指令。Vibe coding 之所以能快，是因為每一步都有機會回到上一個存檔；但速度的前提，是你真的知道存檔在哪裡、推送到哪裡，以及 agent 手上的權限有多大。
