把 agent 技能當成依賴管理：skills-lock.json 與技能落地位置

Step 3/4 · 專案骨架與 agent 說明書：角色化資料夾 + AGENTS.md/CLAUDE.md

這一課要完成什麼

你會看懂 skills-lock.json 為什麼要記錄技能來源、技能檔位置與內容雜湊，也會知道如何把第三方 skill 放進 .agents/skills 或 .claude/skills，讓對應的 agent 找得到、載入並使用。

agent 的能力，不只來自模型

前面兩步處理的是「agent 知道什麼」。但真正決定它能做什麼的，還有另一半：它能不能產生 PPT、審查一份 skill，或撰寫公眾號文章。

這些能力通常不是模型天生具備，而是靠一份份 skill 疊出來。你可以把 skill 想成 agent 的工作手冊：裡面寫著什麼情況要啟用、該走哪些步驟，以及可以使用哪些資源。

一個 skill 通常就是一個資料夾，裡面放一份 SKILL.md。把它放到 agent 會讀取的位置，agent 就多了一項可執行的工作能力。許多 skill 直接來自 GitHub 上其他人維護的專案。

麻煩也從這裡開始：第三方 skill 本質上是別人寫的指令，而 agent 會照著這些指令行動。它可能改版，也可能被改壞；今天安裝的內容，和下個月重新安裝的內容不一定相同。若只靠記憶，很快就會搞不清楚自己到底裝了哪個版本。

先看完整結果：skills-lock.json

示範專案根目錄的 skills-lock.json，就是 agent 能力的依賴帳本。它記住版本格式，以及每個 skill 的來源、技能檔位置和內容指紋：

{
  "version": 1,
  "skills": {
    "html-ppt": {
      "source": "lewislulu/html-ppt-skill",
      "sourceType": "github",
      "skillPath": "SKILL.md",
      "computedHash": "977bae0cdd515696cf400bb050b1c8741e8d911466fb1ec011138f4411396a03"
    }
  }
}

這個專案一共釘住四個技能：

技能來源（GitHub）技能檔位置
find-skillsvercel-labs/skillsskills/find-skills/SKILL.md
html-pptlewislulu/html-ppt-skillSKILL.md
skill-vetteruseai-pro/openclaw-skills-securityskills/skill-vetter/SKILL.md
wechat-article-writeriamzhihuix/happy-claude-skillsskills/wechat-article-writer/SKILL.md

這三類欄位各自回答不同問題：

  • source 與 sourceType：這個 skill 是誰的、從哪裡取得？
  • skillPath：技能檔在來源專案的哪個位置？
  • computedHash：目前記錄的內容，之後有沒有被改動？

computedHash：技能內容的指紋

computedHash 是根據技能內容計算出來的指紋。內容就算只改了一個字，重新計算出的指紋也會完全不同。

它主要防兩種情況：

  • 你以為安裝的是 A 版本，實際拿到的卻是 B 版本。
  • 有人，或某次更新，改動了技能指令，而你沒有察覺。

這和 package-lock.json 記錄 npm 套件版本與雜湊的概念相同：程式依賴需要可重現，agent 的能力來源也一樣。當 agent 能做的事愈來愈像一個小型系統，就不該只靠印象記得「我好像裝過什麼」，而要把能力來源當成依賴管理。

專案裡的 skill-vetter 來自 useai-pro/openclaw-skills-security，用途就是審查 skill。社群會出現專門檢查技能的工具，正好提醒你：從網路抓下來的技能，本來就不該無條件信任。

鎖檔有了，技能還要放到 agent 找得到的地方

skills-lock.json 只記錄「專案有哪些技能」。要讓 agent 真的使用，還必須把技能放進它會讀取的資料夾。示範專案有兩個位置，分別對應不同 agent：

  • .claude/skills/：Claude Code 會讀這裡；專案裡放了 weekly-report/SKILL.md。
  • .agents/skills/：Codex 等其他 agent 會讀這裡；專案裡放了 html-ppt/、skill-vetter/、wechat-article-writer/。

這和上一課的 AGENTS.md、CLAUDE.md 是同一種設計思路：不同 agent 有不同的讀取約定，因此同一類設定要放在它認得的位置。

可以把它想成一間倉庫：

  • skills-lock.json 是帳本，記錄有哪些能力、來源是哪裡。
  • .agents/skills 與 .claude/skills 是倉庫，放著 agent 實際要載入的技能。

因此，鎖檔列出四個技能，但某個 agent 的資料夾只放其中幾個，並不矛盾。鎖檔管理的是整個專案的能力清單；技能資料夾則決定某個 agent 實際載入哪些能力。

真正要記住的風險

把第三方 skill 當成依賴，表面上是工程管理，實際上也是 vibe coding 的安全習慣。當你讓 agent 使用網路上的 skill，就等於讓它依照陌生人寫的指令做事。

有了鎖檔，你至少能回答三個關鍵問題：

  1. 這項能力從哪裡來？
  2. 我現在使用的是哪一版內容？
  3. 它之後有沒有被動過？

反過來，如果你連自己裝了哪些 skill 都說不清楚，就很難追查 agent 為什麼突然多做一步，或多改一個檔案。能力來源不清楚，行為出錯時也就沒有可靠的起點可查。
