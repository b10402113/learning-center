先把代理的底座架好：Node.js、git 與 Claude Code

Step 1/3 · 工具鏈就緒：Node.js / git / Claude Code

Claude Code 為什麼要依賴 Node.js？

Claude Code 不是下載後直接點開的獨立應用程式，而是發佈在 npm 上的全域套件。可以把它想成建築物：Node.js 是地基，npm 是搬運材料的工具，Claude Code 則是蓋在上面的房子；git 另外負責記錄和管理專案的變更。

因此安裝順序很固定：

  1. 先準備 Node.js 與 git。
  2. 使用 npm 安裝 Claude Code。
  3. 逐一執行版本指令，確認每一層真的能運作。

最後一步不能省。指令沒有報錯，只代表安裝程序結束，不代表終端機真的找得到工具，也不代表工具能正常啟動。

三個底層工具，各自負責什麼？

Node.js、npm 和 git 常常一起出現，但它們不是同一件事：

工具角色驗證指令
Node.jsJavaScript 的執行環境，Claude Code 會在這上面執行node --version
npmNode.js 的套件管理器，用來安裝 Claude Codenpm --version
git版本控制工具，讓 agent 能追蹤與回復檔案變更git --version

安裝 Node.js 時通常會一併取得 npm，不需要再另外安裝。macOS 使用者可以用 nvm 管理 Node.js 版本；日後要切換或重裝時，檔案會比較乾淨，也比較不容易和系統權限打架。

實跑：安裝 Claude Code

確認 Node.js、npm 和 git 都已經就緒後，執行全域安裝指令：

npm install -g @anthropic-ai/claude-code

-g 代表全域安裝。沒有這個參數時，套件只存在目前的專案資料夾；切換到其他目錄後，終端機可能找不到它。加上 -g 後，claude 命令可以從任何目錄呼叫。

安裝完成後，立刻確認版本：

claude --version

如果能印出版本資訊，代表目前的終端機已經找得到 Claude Code。若出現錯誤，先不要急著重裝，先判斷是路徑、權限、Node.js 版本，還是 Node 版本切換造成的問題。

四個最常見的安裝陷阱

1. command not found: claude

npm 可能已經安裝成功，但全域套件所在的執行檔資料夾沒有放進 PATH。PATH 就像終端機的地址簿：只有地址在裡面，它才知道要去哪裡找 claude。

先詢問 npm：全域套件的根目錄在哪裡？

npm prefix -g

這個指令會印出全域安裝根目錄；執行檔通常位於其下的 bin/ 資料夾。把該 bin/ 路徑加入 PATH，終端機才會找得到 claude。

2. EACCES 權限錯誤

看到權限錯誤時，直接加上 sudo 似乎很快就能通關：

sudo npm install -g

但這通常只是把問題往後推。安裝出的檔案可能變成 root 所有，之後更新或移除套件時，npm 就會和檔案權限互相衝突。

macOS 上較乾淨的做法是使用 nvm，或把 npm 的全域 prefix 設定到自己的家目錄。這樣套件由自己的帳號管理，不需要每次都借用 root 權限。

3. 切換 Node.js 版本後，Claude Code 消失

如果使用 nvm，要記得：全域套件是每個 Node.js 版本各自一份。例如你在 Node.js 22 裝了 Claude Code，再切換到 Node.js 20，Node.js 20 的環境不會自動繼承那份安裝。

所以切換版本後出現 command not found，不一定代表 Claude Code 壞了。切回原本的 Node.js 版本，命令通常就會回來；如果你打算在新版本工作，就在該版本重新執行安裝指令。

4. Node.js 版本太舊

Claude Code 有最低 Node.js 版本要求。版本太舊時，可能在安裝階段失敗，也可能安裝成功，卻在真正執行時出錯。

遇到看不懂的錯誤，先確認目前版本：

node --version

再依需求使用 nvm 升級到目前仍受支援的版本。先確認執行環境，通常比反覆重裝更快找到原因。

最後實跑：四行檢查表

這套流程的核心不是「把指令貼上去」，而是讓每一層都自己回報狀態。照順序執行下面四行：

node --version
npm --version
git --version
claude --version

四個指令都能回應，代表 Node.js、npm、git 和 Claude Code 已經在目前的終端機環境中就緒。之後遇到任何 CLI 工具「明明裝了卻叫不到」，都可以沿用同一個排查順序：先確認工具是否存在，再查它被安裝到哪裡，最後檢查那個位置是否在 PATH 中。

遇到「明明裝了卻打不到」，第一步是詢問工具或套件管理器：「你被裝到哪裡？」不要先重裝。重裝往往只是讓同一個問題再演一次。
