JDK 與 Maven：解壓只是起點，環境變數才是接線

Step 2/3 · 工具鏈就緒：Claude Code / Node / git / JDK + Maven

檔案已經在硬碟上，系統卻還找不到

JDK 與 Maven 通常是下載後解壓縮即可使用。問題是，解壓縮不代表系統知道它們在哪裡。

因此你可能會遇到這些訊息：

  • 輸入 mvn，出現 command not found。
  • 執行編譯時，系統說找不到編譯器。
  • java 看似正常，但 Maven 實際使用的是另一個 Java 版本。

把工具目錄接到系統上，靠的是環境變數。它們就像地圖上的路標：檔案本身已經存在，但沒有路標，系統就不知道該往哪裡走。

三個環境變數，分別負責什麼

變數應該指向哪裡沒設好會發生什麼事
JAVA_HOMEJDK 的安裝根目錄Maven 找不到 Java，或使用錯誤版本
MAVEN_HOMEMaven 的安裝根目錄部分工具找不到 Maven；新版 Maven 多半只需要設定 PATH
PATH加入 JDK 與 Maven 的 bin/ 目錄輸入 java 或 mvn 時，系統找不到指令

最容易設錯的是 JAVA_HOME。它要指向 JDK 的根目錄，不是裡面的 bin/，也不是 JRE。

許多工具會把 JAVA_HOME 當成「這台機器要使用哪套 Java」的明確答案，而不是從 PATH 裡猜。Maven 就是其中之一。

PATH 則是告訴系統去哪裡找可執行檔。要讓你在任何目錄都能輸入 java 與 mvn，至少要把 $JAVA_HOME/bin 和 Maven 的 bin/ 加進去。

先跑一次完整驗證

不要只看安裝資料夾是否存在，直接執行這三個命令：

java -version
javac -version
mvn -version

這三個命令各自驗證不同事情：

  • java -version：確認目前找到的 Java 執行環境。
  • javac -version：確認編譯器存在，也就是你使用的是完整 JDK。
  • mvn -version：確認 Maven 版本，以及 Maven 實際採用的 Java 版本。

只驗證 java 不夠。某些環境可能只有 JRE，能執行 Java 程式，卻沒有 javac，因此無法編譯。JDK 9 之後，JRE 已整合進 JDK；只要 javac 存在，基本上就代表完整的 JDK 已被找到。

最有判斷力的是 mvn -version。它除了顯示 Maven 版本，也會印出 Java version。如果這裡顯示的版本不是你預期的，問題通常在環境變數或版本指向，而不是 Maven 本身。

四個最容易踩到的坑

1. JAVA_HOME 指到 JRE

JRE 只有執行環境，沒有編譯器。這種錯誤很容易造成「看起來一切正常」的假象：

  • java -version 有正常回應。
  • 真正開始編譯時，Maven 才報找不到 javac。

檢查 $JAVA_HOME/bin，確認裡面同時有 java 和 javac。

2. PATH 裡的系統 Java 搶在前面

macOS 的 /usr/bin/java 可能只是轉接用的 stub。第一次執行時，甚至可能跳出要求安裝 Java 的提示。

如果 $JAVA_HOME/bin 排在它後面，java -version 找到的可能不是你安裝的 JDK。把 $JAVA_HOME/bin 放到 PATH 前面，才能讓你的 JDK 優先被使用。

3. 多個 JDK 彼此指向不同版本

這是最容易讓人誤判的版本錯亂：

  • 單獨執行 java -version，結果看起來正確。
  • 單獨執行 mvn -version，也有正常回應。
  • 真正編譯時，卻出現版本不相容的錯誤。

原因可能是 PATH 裡的 java 和 JAVA_HOME 指向不同 JDK。換版本時，要一起檢查：

  • JAVA_HOME 指向哪一套 JDK。
  • PATH 裡的 java 來自哪裡。
  • IDE 指向哪一套 JDK。

三者要指向同一個版本，不能只改其中一處。

4. 設定檔改錯地方，或改完沒有重新載入

macOS 目前預設使用 zsh，相關設定通常要寫在 ~/.zshrc。如果設定寫在 ~/.bash_profile，可能不會生效。

修改後要開新的終端機視窗，或執行：

source ~/.zshrc

另外，從圖形介面啟動的程式，例如某些 IDE，不一定會讀取你在 shell 裡設定的 PATH。終端機中的 java 明明正確，IDE 卻可能仍使用另一套 JDK；這時要到 IDE 自己的設定中檢查 Java 指向。

為什麼 Maven 特別看重 JAVA_HOME

Maven 的啟動腳本會先讀取 JAVA_HOME，用它決定要執行哪個 Java。只有在 JAVA_HOME 沒有設定時，才會退回使用 PATH 裡找到的 java。

所以即使 PATH 已經指向新版本，只要 JAVA_HOME 還留著舊版本，Maven 仍然會使用舊的 JDK。這就是「直接執行 java 沒問題，但 mvn 用錯版本」的常見原因。

換 JDK 時，不要只改一個地方。同步檢查 JAVA_HOME、PATH 裡的 JDK bin，以及 IDE 的 JDK 設定。最後重新執行 java -version、javac -version 和 mvn -version；三個結果一致，環境才算真的接好。
