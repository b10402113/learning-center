# Digest — 测试提示词 (vibe-coding prompt playbook: testing)

## Overview (L1)

- `测试提示词.txt` — a three-message sequence for having the agent analyze, scaffold, and run tests across the three clients. Emphasizes "don't write code yet", real assertions, failure screenshots, and an HTML report.

## Sections (L2)

### message-1-analyze-and-plan

- Locator: `[[sources/vibe-coding-fengjianyingyue/20260926/测试提示词.txt#message-1-analyze-and-plan]]`
- Summary: analyze frontend/backend/uniapp — identify stack, structure, start method; find core business modules; find high-risk features; design a layered test plan.
- Key claims: "不要立刻写代码，先输出测试计划" — plan before code; one plan per project, not one combined plan.
- Learner-relevant: the plan-first prompt pattern; risk-based test scoping.

### message-2-scaffold

- Locator: `[[sources/vibe-coding-fengjianyingyue/20260926/测试提示词.txt#message-2-scaffold]]`
- Summary: create the test project structure — new `tests/` dir, test framework, test commands, report output dir, and a purpose note per test file; must not touch existing business code.
- Key claims: tests are additive and isolated; every file's purpose must be documented.
- Learner-relevant: safe, non-invasive test scaffolding.

### message-3-run-and-report

- Locator: `[[sources/vibe-coding-fengjianyingyue/20260926/测试提示词.txt#message-3-run-and-report]]`
- Summary: test the most core business flows (auth, CRUD). Requirements: cover all features; every step has a real assertion; auto-screenshot on failure (or record steps); produce an HTML report; ban no-op tests like `expect(true).toBe(true)`.
- Key claims: anti-pattern called out explicitly; real assertions and a human-readable report are mandatory.
- Learner-relevant: guarding against fake-green AI tests; the assertion-quality bar for AI-written tests.
