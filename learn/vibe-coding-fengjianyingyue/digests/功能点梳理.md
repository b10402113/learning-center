# Digest — 功能点梳理 (vibe-coding prompt playbook: feature specs by page)

## Overview (L1)

- `功能点梳理.txt` — page-by-page feature specs with an explicit instruction to implement backend business logic against the database and hand it to the frontend. Covers 首页 (home), 统计 (statistics), 明细 (transaction history), 设置 (settings), 记一笔 (add record), plus a repeated "missing features" section for 明细/统计/首页.

## Sections (L2)

### home-spec

- Locator: `[[sources/vibe-coding-fengjianyingyue/20260926/功能点梳理.txt#home-spec]]`
- Summary: three blocks — current month header (`2028年12月`) with 本月收入/支出/结余 computed from DB; top-3 spending categories this month; latest 3 transactions sorted by time.
- Key claims: every value must be derived from real DB data, not mocked.
- Learner-relevant: turning a mock screen into a data-backed feature via a written spec.

### statistics-spec

- Locator: `[[sources/vibe-coding-fengjianyingyue/20260926/功能点梳理.txt#statistics-spec]]`
- Summary: five blocks — year selector, income/expense/balance by year, expense pie chart by category, 12-month income+expense line chart, and Excel export.
- Key claims: aggregation, grouping, time-series, and export are specified as discrete deliverables.
- Learner-relevant: spec decomposition for dashboards; charting + export as common AI-buildable features.

### history-spec

- Locator: `[[sources/vibe-coding-fengjianyingyue/20260926/功能点梳理.txt#history-spec]]`
- Summary: month-grouped list, expense/income/all filter, 20-per-page pagination with two triggers — desktop scroll-down and mobile swipe-up.
- Key claims: pagination behavior differs by device; infinite scroll is the requested UX.
- Learner-relevant: pagination/infinite-scroll as a cross-platform concern.

### settings-and-add-record-spec

- Locator: `[[sources/vibe-coding-fengjianyingyue/20260926/功能点梳理.txt#settings-and-add-record-spec]]`
- Summary: accounts and categories are full CRUD against the DB; avatar upload persists to DB; the add-record page pulls categories and accounts from the DB and saves a new transaction.
- Key claims: settings and add-record share the same underlying account/category tables; the add-record form is the write path.
- Learner-relevant: the write path that makes the read-only dashboards meaningful; shared data model across pages.

### gap-list-repeat

- Locator: `[[sources/vibe-coding-fengjianyingyue/20260926/功能点梳理.txt#gap-list-repeat]]`
- Summary: after the spec, the same 明细/统计/首页 features are restated as "目前缺失以下功能" (currently missing).
- Key claims: a spec is not a delivery — features must be re-prompted until implemented.
- Learner-relevant: how to close a requirements-vs-implementation gap with targeted re-prompts.
