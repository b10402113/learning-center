# L1 overview

- Routines as the third part of the "arms framework" — after skills and memory; they let Claude Code run on a schedule instead of requiring a conversation every time.
- Why ordering matters — without working skills and memory, routines only automate output that is not up to spec; with them, the setup produces useful work day after day.
- Token trade-off — the more you automate, the more tokens you burn; later lessons cover techniques and routines that use no tokens at all.
- Example use case — a recurring weekly PDF report or presentation that gets generated without the user lifting a finger.
- Guiding principle — state clearly what you want and when you want it, and Claude does most of the heavy lifting.
- Three routine types — local routines on your desktop/device, cloud routines that run even when the device is off, and a bonus deterministic routine that incurs no tokens.
