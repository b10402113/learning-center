# Create 的第一步：先決定有哪些區塊，再用 /html 預覽

你想做一個一頁式網站，打開 Claude Code，第一句就說：「幫我做一個漂亮的 landing page。」沒多久，agent 交出一頁網站。畫面看起來不差，你卻說不上來哪裡不對。

問題通常不在顏色或字體。你還沒想清楚這個網站要替誰回答什麼問題，就讓 agent 開工了。

CRAFT 的 Create 階段，要求你把順序倒過來：先規劃前端，再讓 agent 生成。這篇只談第一步：列出網站需要的區塊、刪成第一版清單，最後用 `/html` 預覽。

## 先計畫，再生成，順序不能反

Create 階段分成兩部分：先規劃前端，再把前端建出來。

課程的做法很直接：先研究 agency 網站需要哪些區塊，再用自己的判斷把清單砍到第一次做剛好的長度，最後才讓 agent 生成一頁式前端。

為什麼不直接跳到生成？因為「網站該有哪些區塊」是設計問題，跟生成無關。區塊清單如果錯了，後面的 design system 做得再細，也只是把錯誤包裝得更好看。

## 第一步：研究網站需要哪些區塊

不要只靠感覺列清單。課程要你研究的是「2026 年一個網站實際需要哪些區塊」，先看清楚別人怎麼做，再開始規劃。

課程附有一份 section-planning prompt，專門用來研究與規劃區塊。把它交給 agent，就能先得到一份區塊清單。

這份清單是「完整版」，回答的是「一個網站可以有哪些區塊」，不是「你的第一版要做哪些區塊」。

## 第二步：把完整版砍成第一版

完整版的作用是給你有東西可以取捨，不用全部做完。

想想哪些區塊一少，網站就說不清楚自己是什麼；哪些區塊晚一點再加，也不會有太大影響。前者留下，後者往後排。

課程給的理由很實際：對初學者來說，縮短清單是最快把東西做出來的方法。第一版只要能讓網站成形就好，不必面面俱到。

砍掉的區塊並沒有消失，只是排到第二版或第三版。先做出一頁能跑的網站，再慢慢加上去。

## 第三步：用 `/html` 先看一眼再 build

清單確認後，先別急著進 design system。把計畫交給 `/html` skill，讓它渲染成一份乾淨的 HTML 頁面，方便你審閱。

看得見，才審得出來。只有文字清單時，你不容易看出區塊之間的節奏；變成頁面後，區塊順序對不對、內容會不會太擠、哪一段話太多，就比較容易發現。

課程希望你先把計畫變成看得見的頁面，在 build 之前好好檢查。審閱通過後，這份計畫才算是 approved plan。接著，agent 才會把它做成真正的前端：一個可以運作、準備套用 design system 的頁面。

記住順序：`/html` 是讓你「先看」，不是讓你「先做 design system」。先確認區塊安排，再討論外觀。

## 在自己的電腦上跑一次

這一輪可以拆成三個動作：

1. 使用課程附的 section-planning prompt，研究網站需要哪些區塊。
2. 看著清單做取捨，只留下第一版需要的內容。
3. 呼叫 `/html`，把清單渲染成頁面。先看過，再繼續。

如果你跟我一樣，平常寫 React 或 Express，可能會很想直接開專案、建立 component。先忍一下。Create 這一步要先回答「網站有哪些區塊」，後面所有的設計決定都建立在這份清單上。
