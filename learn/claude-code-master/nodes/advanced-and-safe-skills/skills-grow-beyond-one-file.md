# Skill 其實不只是一份 markdown 檔

你手上可能有幾個 skill，每個只有兩三行。它們有用，也跑得動。課程裡也提過這種 skill：只有兩三行長，效果卻相當好。

但任務一變複雜，一份 SKILL.md 就不夠用了。你要它去八個來源抓資料、照固定格式產出，還要它維持一套視覺風格。這些事全寫在純文字裡，只會讓檔案越來越長，而且每次觸發都要整個載入。

真正要判斷的是：什麼時候該讓一個 skill 從單一 markdown 檔，長出 scripts、references 或 HTML 範本。

## 先看一個真的長這樣的 skill

課程作者有一個常用 skill，叫 `/last30days`。它做的事是：從八個不同的來源，抓過去 30 天的資訊。

這種 skill，不會只是一份文字檔。

進到 workspace 的 skills 資料夾看，`last30days` 底下有四類東西：

- 一份 markdown 檔，寫給 agent 的指示。課程裡叫它 recipe card，也就是操作說明卡。
- scripts，也就是程式碼，用來幫你抓那些來源。
- references，說明產出的 brief 應該長什麼樣。
- 還有幾個其他檔案，幫它完成目標。

四類東西各司其職。markdown 檔說清楚做什麼、怎麼做，scripts 真的去執行，references 定義做好是什麼樣子。全部塞進一份 markdown 檔，agent 每次觸發都要讀完，還沒開始做事就先吃掉一堆 context。

## 三種會長出來的東西

課程的兩個例子裡，長出三種常見的附加檔案，各自解決不同的問題。

**scripts**：這個 skill 得真的跑一段程式時。`/last30days` 要從八個來源抓資料，用文字描述沒有用，得有一段程式碼去執行。判準很簡單：指示裡出現抓取、計算、轉檔這類動作，而且每次做法都一樣，那就寫成 script。

**references**：產出有固定長相時。`/last30days` 要產出一份 brief，references 就定義 brief 該長什麼樣。你要的是一個可以對照的標準，不用每次重新描述一次格式。

**HTML 範本**：產出有視覺標準時。作者的 Robo skill 底下有一個 `brandbook.html`。用瀏覽器打開它，就是一份品牌手冊，定義這個 skill 產出的簡報與網頁設計該用什麼風格。

這三種檔案的共同點：它們都是「可以被指向的東西」。SKILL.md 只要寫一行，叫 agent 照這個檔案做。agent 需要時再去讀，不需要時就不佔空間。

## 不要預先設計，讓它自然長出來

作者的建議很直接：讓這些資產與 artifact 自然發生。

他的做法不是先規劃一個 skill 要有幾個資料夾。他在建置的過程裡，需要一份品牌手冊，就做一份品牌手冊。當他請 Claude Code 更新這個 skill 時，Claude Code 自己加了一行，指向那份 brandbook，讓它成為這個 skill 的視覺風格參考。

同樣地，如果 Claude Code 在建立 skill 的過程中建議你產生某個 artifact，你可以直接順著它做。

這裡有一個心態要放掉：skill 不需要從頭讀到尾。作者說得很清楚，這些 skill 你其實不需要一行一行讀完。他把 agent 當成一個話比你預期多的員工。員工會把思考過程講出來，但你是管理者，你只在意最後交付的東西。

對應到檔案上，SKILL.md 就是一份可以跳讀的索引。你不需要把它當教科書，從頭背下來。

## Skill 也可以呼叫 skill

還有一種長法：檔案沒變多，多出來的是一個步驟。這裡先看它長什麼樣，下一段再拆開來做。

作者示範了怎麼改 Robo skill。他希望每次呼叫 Robo 時，Claude Code 都先用 align skill，讓它先問幾個釐清問題。

理由很實際。這類設計與簡報工作很吃 token。先跟 agent 對齊，再讓它動手，比做完才發現方向錯了便宜。

他送出那段指示後，Claude Code 自己想過這個問題，然後去改對應的檔案，也就是 `robo` 的 SKILL.md，加上那一行。結果是加了一個 step zero：在做任何 Robo 工作之前，永遠先直接呼叫 align skill。

<!--image:3-->

每次呼叫這個 skill，那段指示就進到當下的 session，它會自己去找 align skill 來讀。

## 回到你的判斷

所以什麼時候該長？看三個訊號。

第一，指示裡出現重複的執行動作。每次都要做同一件事，而且這件事有明確的輸入與輸出，就抽成 script。

第二，產出有固定格式或固定長相。你每次都要花篇幅描述同一個標準，就抽成 reference 或 HTML 範本。

第三，某個前置動作每次都得先做。像是先釐清需求、先對齊方向，就寫成 step zero，去呼叫另一個 skill。

反過來說，如果一個 skill 兩三行就講得完，而且效果不錯，就讓它保持兩三行。課程一開始就說了，這種 skill 存在，而且有效。

長的時機不是「這個 skill 感覺很高級」，而是「這份 SKILL.md 開始重複自己」。
