# 多少 skill 才算太多？

審過、裝進來之後，下一個問題是總量。

你不會一次裝到 180 個 skill。通常是一週一個：遇到一件重複的工作，就叫 Claude 把它存成 skill，下次直接用。存到某一天，新開的 session 連一句話都還沒打，context 已經先被扣掉一截。這時要問的不是「我還能不能再加」，而是「我加的這些值不值得」。

課程對「多少 skill 才算太多」的回答很簡單：只要不搞混你、也不搞混 Claude，大概就沒問題。

<!--image:1-->

## 先承認它容易被查

skill 庫不用靠感覺管理。skill 全是純文字檔，就 code 和 assets 兩類，Claude Code 自己就能快速讀過一輪。

所以審計可以只用一段 prompt：請它列出彼此重疊、可以合併的 skill，並建議哪些該留、哪些該砍、哪幾個該併。課程說，這樣清一次不到 30 分鐘。

## 用 `/context` 量單次預載

真正要動手前，先量。開一個全新、乾淨的 session，打 `/context`。這頁會顯示每個 session 預載多少 token。

<!--image:2-->

課程的示範：在那個 session 隨手打一句話，馬上就用掉大約 27,000 token。其中一部分來自 skill descriptions：當下 180 個 skill，吃掉大概 13,700 token。

27,000 聽起來不少，但要放回比例來看。示範用的模型有 100 萬 token 的 context window，13,700 只佔很小一塊。所以這兩個數字只是分子，還談不上判決。

## 用 `/usage` 看它有沒有咬到額度

第二個數字在 account and usage，或直接打 `/usage`。課程說，多數人卡住的是每週 rate limit。示範時帳號在 6%。

<!--image:3-->

接著送一句測試訊息。這一下不只是你打的那幾個字，還會載入這個 session 裡約 27,000 的預載 system prompt，整場合計大約 28,000 token。回答完，回到 account and usage，看指針有沒有動。

指針沒動，代表 skill 還沒大到會實質吃掉你這個方案的用量上限。示範裡指針幾乎沒反應，因為 27,000 放進整體並不大。但課程也提醒，額度比較緊的 Pro 方案另當別論。如果你想把 token 花在真正的工作上，清理 skill 就值得做。

## 讀完兩個數字，只剩三種處置

量完之後，每個 skill 的命運只有三種。

<!--image:4-->

**合併**：兩個 skill 在搶同一種觸發，平常只會用到其中一個。

**砍掉**：留著但很少被觸發，或內容已經被別的 skill 蓋掉。

**留著**：它確實會被用到，成本又在你的額度裡可以忽略。

判斷的順序不要顛倒。先用 `/context` 拿到成本，再用 `/usage` 看它在你方案裡佔多少份量，最後才決定留、砍、併。分母不同，結論就不同；同一個 13,700，在 100 萬 token 的視窗裡和在吃緊的週額度裡，重量完全不一樣。

課程最後留給你的挑戰很簡單：今天存一個 skill，再自己做幾個。工作流程本來就能靠對話自動化，缺的只是讓它下次還記得。
