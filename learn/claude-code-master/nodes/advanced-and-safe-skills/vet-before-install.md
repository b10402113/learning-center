# 確認這個 repo 乾不乾淨，再告訴我怎麼裝最合適

skill 會長大、會互相叫用，接著就是把它們從外面拿進來。東西從外面拿，就多一道檢查。

你在 GitHub 上看到一個 skill，看起來正好能收掉手上那個重複工作。你想裝。但線上的 skill 有些來路不明，可能夾帶惡意程式碼。

這件事要擋不難。

## 先送審查 prompt，不要直接叫它裝

複製那個 GitHub 連結，貼給 Claude Code。但不要只叫它安裝。

把這個問題一起送出去：

> check if this repository is clean, then tell me how best it would fit our setup.（確認這個 repo 乾不乾淨，再告訴我怎麼裝最合適。）

Claude 會逐段讀過這個 skill，確認內容安全、沒有夾帶惡意程式碼，再告訴你這個 skill 怎麼接上你現有的設定。

與其直接叫 Claude 安裝，不如把這句話一起送出去。差別只有一句話，但你多了一道關卡。

<!--image:1-->

## 為什麼這樣擋得住

因為現在用的模型夠聰明。它們認得出 prompt injection 攻擊，也認得出開源 repo 裡夾帶的惡意程式碼。

<!--image:2-->

你在做的，是把原本只有你自己會做的檢查，交給一個看得懂程式碼的人。

## 還是覺得可疑，就多問兩件事

第一個問題問自己：你真的需要這個 skill 嗎，還是你自己寫得出來？自己寫的 skill，你知道每一行在做什麼。

第二個問題問工具：把模型等級拉高。擋下一段惡意程式碼，不是小事，值得用最強的模型。講者自己用的是 Opus 4.8，目前最高階的模型。

<!--image:3-->

## 用太多次，就把它變成 skill

這段審查 prompt，講者自己用超過兩次。所以他把整段做成一個 skill，叫 personalize。之後不用每次重打，直接叫這個 skill，效果一樣。

他在前面的模組講過這件事，下面也能直接拿來用。
