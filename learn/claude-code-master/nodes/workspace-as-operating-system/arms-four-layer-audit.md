# ARMS 四層框架：像替新員工布置 workspace

你打開 Claude Code，模型是最新的那一代，harness 也是大家在用的同一套。但隔天早上新開一個 session，它對你的專案、你的習慣、上週做到哪裡，一概不知道。問題通常不是模型不夠聰明，是 workspace 是空的。

## 當 workspace 變成作業系統

課程裡先講了一件不太直觀的事：不論你用 Claude Code、OpenClaw、Hermes、Codex 還是 Anti-Gravity，每個 agent 平台其實都只有三個基本元素。一個是 model，扮演引擎或大腦；一個是 harness，也就是 Claude Code 本身，一組 system prompt 和檔案，把模型包起來，讓它能使用工具、操作你的電腦、替你改檔案。第三個是 context。

關鍵在於，model 和 harness，所有人用的都是同一份。真正的差異化因子是 context，而 context 就是你的 workspace，本質上只是電腦裡的一個資料夾。作者的做法是把事業相關的所有 context、程式碼、自動化，甚至圖片和影片，都放在同一個資料夾裡。當你把 context 布置到這個程度，它就開始變成你的作業系統，也就是所有事情跑在上面的那一層底。他的說法是，現在打開裝置第一件事就是開 Claude Code，那是他每天、每小時講話的 all-in-one 軟體與隊友，個人和事業的工作都跑在上面。

把這句話記住：前兩層所有人都一樣，你能動的只有第三層。

## ARMS：給 agent 一雙手臂

要走到那一步，作者給了一個分類框架，叫 ARMS。取這個名字有兩個理由：一是縮寫好記；二是它像是替 agent 裝上一雙手臂（arms），讓它伸進你的 workspace、你的聯絡人，去把你要它做的事完成。

這個框架的重點不是四個名詞，是四個條件同時成立。當 Claude Code 能存取並連接你的 applications，有在背景自己跑的 routines 或排程任務，有你個人與事業的 memory 和全部 context，最後還有齊全的 skills，讓它用符合你期待的方式完成你交辦的任務，到這裡它才算一個真的會幫你自動化工作的隊友。

## 新員工第一天，你會給他四樣東西

作者請你把 agent 想成你雇來的數位員工。報到的時候，它自帶引擎（model），也自帶車身（harness），就像一台車來的時候已經有引擎和車殼。你能替它準備的只有 workspace。而如果你真的在替一個新員工設定 workspace，你大概會給他四樣東西，這四樣就是 ARMS 的四層。

### Apps：讓他碰得到工具

第一件事是給他裝置上各個 application 的存取權。你的工作發生在那些工具裡，agent 沒接上，就只能在旁邊看。接上之後，那些「跟我們用的工具或 app 有關」的工作才輪得到它做，也才可能做到 24/7。這裡還有個容易漏掉的反向好處：因為這些 agent 夠強，你也可以自己做 application。

### Routines：給他一份會重複發生的行事曆

第二件事是 routines，也就是排程。新員工到的時候，你會跟他說哪些任務每天、每週固定會發生，他的行事曆上就該有這些事，行事曆本身也該放在 workspace 裡。對 agent 來說，routines 就是即使你不在、也會在背景跑完的排程任務。這是四層裡的分水嶺：前面幾層是你推它才動，從這一層開始，它自己會動。

### Memory：給他一個檔案櫃

第三件是 memory。本質上就是一個檔案櫃，裡面放你們一起做過的所有對話和所有專案，需要的時候可以拿出來。重點在「拿得出來」：memory 的價值不在存得多，在相關的時候檢索得到。

### Skills：給他一本寫著作法的食譜卡

第四件是 skills，像一本筆記本，插著一張張 recipe card、instruction card。卡片上寫的不是背景知識，是某個任務具體怎麼做，讓它在接到同一個任務時不必從頭推導，產出也會對齊你期待的樣子和格式。

把這四層對到新員工身上該有的東西，這套框架幾乎就不需要背了。

<!--image:2-->

| 層 | 新員工身上是什麼 | 你的 workspace 裡是什麼 |
| --- | --- | --- |
| Apps | 裝置上各個工具的存取權 | 接上你每天在用的服務，讓 agent 碰得到 |
| Routines | 行事曆上固定重複的事 | 不用你在場、照時間在背景跑的排程 |
| Memory | 一個檔案櫃 | 對話與專案的紀錄，需要時檢索得到 |
| Skills | 一本寫著作法的食譜卡 | 讓它記得某個任務該怎麼做的指示 |

## 拿這四層盤點你自己的 workspace

現在換成盤點你自己。不需要工具，四個問題就夠。

<!--image:3-->

一，Apps：你每天真正在用的那三五個服務，agent 碰得到幾個？如果答案是「每次都要手動複製貼上」，這一層對你來說是空的。

二，Routines：有沒有一件事，是在你沒開 session 的時候自己跑完的？沒有的話，你擁有的是「可以排程」這個能力，不是一條 routine。

三，Memory：上個月的專案，它今天自己找得回來嗎？找不回來的記憶，等於沒有記憶。

四，Skills：你上週重複解釋過三次的同一件事，有沒有變成一張卡？還是每次都在對話裡重講一遍？

四個問題裡答不出「有」的那一層，就是接下來要補的地方。多數人盤完會發現，缺的不是最上面那層，是最下面那層。

## 為什麼是由下往上補

作者建議的順序是由下往上：skills → memory → routines → apps。理由不難懂。skills 是所有東西的基礎，skill 站穩了，agent 才開始累積 memory，長出關於你事業與工作的知識庫；有了可靠的 skills 和 memory，你排出來的 routine 才可能產出你期待的品質。最後才是 apps，因為大部分工作都跟我們用的工具相關，接上去才可能 24/7 運作。

<!--image:4-->

翻成盤點的語言：skills 和 memory 不穩，routine 只會把不穩定的東西放大成每天出錯。所以別急著排第一條 routine。

ARMS 不是四個要學會的功能，是四樣你會替新員工準備的東西。下次開新的 session 覺得它變笨，先問是哪一層沒布置。

盤完之後，多數人會發現缺的是最下面那一層。下一篇就把「從哪裡補起」的順序講清楚。
