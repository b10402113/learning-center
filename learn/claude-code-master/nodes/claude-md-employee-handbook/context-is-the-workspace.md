# Context 就是 workspace 裡的那些檔案

你用了 Claude Code 一陣子，開始覺得不對勁。它變慢，答案變淺，用量額度掉得比你做的事還快。

你沒做錯什麼，你只是一直在工作。工作的每一段都會在 workspace 資料夾裡留下檔案，那些檔案就是 context。

## 先看它壞掉的樣子

這個問題不會一次爆掉。它是慢慢來的。

你加一個 skill，好用，再加一個。你請 agent 寫一份筆記，明天再寫一份。資料夾一天比一天厚。等到某一天你開新的 session，發現它讀東西變慢、花掉的 token 變多，你才會回頭去看那個資料夾。

那時候你通常會嚇一跳。裡面有一半的檔案，你早就忘了為什麼存在。

## Context 不是抽象名詞

課程對 context 的定義很樸素：凡是放進 workspace 資料夾、或在裡面長出來的檔案，都算。

不是「模型的記憶」，不是「對話的歷史」，就是你 `ls` 得到的那一串東西。你放進去的算，agent 自己建的也算。

<!--image:1-->

所以在 Claude Code 裡顧 context，其實就是顧一個資料夾。這件事一講清楚，後面的判斷就有了依據：某個檔案該不該留、該不該拆、該不該讓 agent 每次都讀。

## 把它想成一個檔案櫃

課程用一個畫面解釋 memory：它是一個檔案櫃，你的數位員工（在這裡就是 AI agent）有權打開它。

你為 agent 建的東西、你和 agent 一起處理過的 context，都收進這個櫃子。櫃子整理得好，Claude Code 就能在需要的那一刻，抽出正確的那一格。整理不好，它就只能在一個塞滿東西的抽屜裡翻。

<!--image:2-->

## 兩層 memory，兩個檔案

櫃子裡真正要記住的只有兩個檔案。

第一個是 `CLAUDE.md`，課程叫它員工手冊。手冊講的是這個工作區怎麼做事，是給新進員工看的那種文件。

第二個是 `MEMORY.md`，它是比較大的那個抽屜，agent 的長期記憶，也是類比裡檔案櫃剩下的部分。

課程的說法是「兩個重要檔案、兩層 memory」。接下來它會依序講這兩個檔案，把 memory 怎麼運作、怎麼套進你的設定說清楚。

<!--image:3-->

## 成本是怎麼累積的

回到最前面那個現象。課程講得很直接：這堆檔案會隨著你工作越久越大，然後緩慢但確定地吃掉你的 token 和用量上限，除非你知道怎麼管 memory。

關鍵在「緩慢但確定」。它不是一個爆點，是一條斜率很小的線。所以你感覺不到它，直到額度不夠用。

<!--image:4-->

也因此，管 memory 是每次往資料夾裡放東西時順手做的一個判斷，不用等出問題才回頭清。

## 現在可以做的第一件事

打開你的 workspace 資料夾，把檔案列出來。一個一個問：這個檔案還在幫我做事嗎？還是它只是因為我當時懶得刪？

你不需要一次整理完。你只需要開始把「資料夾裡有什麼」和「我付了多少 token」連在一起。這條線一接上，後面兩個檔案的用法就接得住了。
