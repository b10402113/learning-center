# 你的裝置裡有兩份 CLAUDE.md

上一段那四根柱子，預設都寫在同一份檔案裡。問題是，你其實有兩份可以寫。

你一直在改專案裡那份 CLAUDE.md，改到後來才發現，Claude Code 其實還會讀另一份，而且那一份對你所有的專案都生效。兩份一直都在，只是你只認識其中一份。

先把兩份都找出來，再決定哪一份值得你花時間。

## 問它路徑，比翻資料夾快

問 Claude Code 本身最快：請它給你 root CLAUDE.md 和 project CLAUDE.md 的路徑。它會把兩條路徑列出來，順著看下去，兩份員工手冊各寫了什麼就清楚了。

<!--image:1-->

問一句，兩個位置一次出來，省掉猜路徑和在硬碟裡翻找的功夫。

## 專案那份：你打開的那個資料夾

前面幾個模組提到的那一份，屬於這個專案。位置就是你用 VS Code 打開、Claude Code 在裡面工作的那個資料夾。

那份檔案裡放的是操作指令：規則、目標、身分，以及整個 workspace 的地圖。你每天在調的，其實就是它。

<!--image:2-->

## 全域那份：使用者資料夾裡

另一份適用於你所有的專案，通常放在你的使用者資料夾裡。它管的是跨專案都成立的事，也就是作者說的「整棟房子」的規則。

他自己那份幾乎沒有內容。不是忘了寫，而是他不需要。

## 只有一個 workspace 的人，通常不用維護全域那份

他的觀察是，多數進階使用者，包括他自己，都只在一個專案裡工作，把 second brain 或整個作業系統收在同一個資料夾。這比開一堆專案、每個專案各養一份 CLAUDE.md 更有效。

當你只需要管一個專案、一個 workspace 時，global CLAUDE.md 根本不是必需品。知道有這個東西就好，它只是幫你把 Claude Code 的全貌補齊。

<!--image:3-->

## 所以，先顧專案那份

兩份的分工講白了就是：一份管整棟房子，是全域規則；另一份是他建議你放重心的地方，也就是專案規則。

先問出路徑，看清楚兩份各寫了什麼。力氣放在專案那份就好，全域那份等你真的需要跨專案共用規則時再回來處理。
