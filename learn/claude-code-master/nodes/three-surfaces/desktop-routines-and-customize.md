# Routines 是排程任務，Customize 是一份會失效的清單

你把 desktop app 當成一個比較好開的聊天視窗用了幾天，可能會覺得它跟 claude.ai 沒什麼兩樣。但它有兩個其他介面沒有的頁面：Routines 和 Customize。

這兩個頁面，一個管理「會自動執行的事」，一個管理「agent 能使用的能力」。它們也正是 desktop app 最早顯得不敷使用的地方。

先來定義名詞。Routine 就是排程任務（scheduled tasks）：設定一次，之後就會按時間自動執行，不必每次都重新下指令。後面的課程會專門介紹它；這篇只談它在 desktop app 裡的樣子，以及這個介面什麼時候會不夠用。

## 點進 Routines，你會看到三樣東西

打開 Routines 頁面，Claude 會先列出一份清單，讓你知道可以設定哪些 routine。

清單上的每一條都可以暫停（pause）或恢復（resume）。右上角還能切換到日曆檢視，查看每一天有哪些 routine 會執行。

<!--image:1-->

如果你只有一兩條 routine，這樣就夠用了。你只需要確認它們還在運作，以及這週會不會執行。

## 但 routine 一多，這個介面反而會礙事

課程裡說得很直接：當你累積了好幾條 routine，用這種介面管理，通常反而更麻煩。而且你越常在日常工作中使用 Claude Code，這個問題就越明顯。

原因不難理解。清單擅長陳列，不擅長比較。兩條 routine 的執行時間有沒有重疊、哪一條上週失敗過、哪一條其實已經三個月沒有產出——這些問題都得靠你自己從一張張卡片裡拼湊答案。

所以，desktop app 的 Routines 是一個入口，不是一個控制台。routine 不多時，它能降低使用門檻；數量一多，它就無法提供你需要的資訊。

## Customize：把 agent 的能力都列在同一頁

切換到 Customize，你會看到 Claude Code 目前能使用的所有 skills。

畫面會標示每個 skill 對應的 surface，例如有一個 skill creator 是提供給 Claude desktop 使用的。頁面旁邊也有手動新增 skill 的入口。

往下看，同一頁還會列出 connectors，也就是 MCP connectors。Claude Code 透過它們連接其他工具。把 skills 和 connectors 放在一起其實很合理：一個代表「它會做什麼」，另一個代表「它能存取什麼」。

<!--image:3-->

如果你只是想知道自己裝了哪些東西，這一頁是三個 surface 裡唯一能一次列出全部項目的地方。

## 手動新增 skill 的按鈕，通常是最後手段

課程作者說得很明白：他自己從來不用這種方式新增 skill。

原因是，他把 Claude Code 當成住在電腦裡的數位員工。你會用說的交代事情，不會翻開技能手冊，手動補上一條。一般來說，你只要用自然語言告訴 Claude Code 想做什麼，讓它去建立、修改；至於底層檔案長什麼樣子，就交給它處理。

這背後反映的是一個更大的轉變：自己動手編輯檔案的時代過去了，把資料夾整理得井井有條的時代也過去了。那是上一代軟體的工作方式。現在，你負責說清楚需求，agent 負責處理那些檔案。

因此，Customize 的定位是「檢視」，不是「編輯」。這個差別聽起來很小，卻決定了這個頁面會在什麼時候不敷使用。

## 80 條之後，清單只剩下「知道有這件事」

課程提供了一個具體的參考：在某些設定下，skills 累積到 90 條以上並不奇怪，作者自己大約有 80 條。

到了這個數量，讓 skills 列在這裡幾乎沒有意義。你打開清單，通常是為了修改某一條；但要改 skill，直接叫 Claude Code 開啟並照你的意思修改，會比在清單裡找到它、點進去再自己動手快得多。

<!--image:4-->

VS Code extension 也有相同的情況。那裡根本沒有 skills 清單，只能輸入斜線查看 slash commands，數量同樣有 80 多條。作者說，他從來不需要真的去整理；如果有需要，就會叫 Claude Code 建議哪些可以停用、刪除或精簡。

換句話說，清單好不好用，不是由數量決定，而是由「你想拿它做什麼」決定。想確認某項目是否存在，80 條也還算可以；想動手修改，從第 5 條開始就不划算了。

## 什麼時候該打開頁面，什麼時候該直接開口

- 想知道某個 skill 在不在、對應哪個 surface：打開 Customize 看一眼。
- 想修改某個 skill 的內容或觸發條件：不用打開頁面，直接告訴 Claude Code。
- routine 只有一兩條：Routines 頁面很好用，暫停、恢復和日曆檢視都夠用。
- routine 多到開始互相影響：這個頁面只能幫你查看，不能幫你分析。

## 順帶一提：desktop app 本身的限制

作者不把 desktop app 當成日常使用的主要介面，原因之一就在這裡。分割畫面最多可以並排四個 session，但只能調整寬度，不能把視窗拖出來，也不能按照自己的方式重新排列。

他對 desktop app 的評價很乾脆：它是三個 surface 裡最弱的，但也最不嚇人。Routines 和 Customize 這兩個頁面，正好說明了這一點。它們把原本需要輸入指令的操作，變成容易理解的畫面；代價則是，你只能用介面提供的方式檢視資訊。

所以，這兩個頁面的正確用法是「進門時看一眼」，而不是「每天在裡面工作」。等到 routine 多得一張卡片清單放不下，或 skills 多得一頁列不完，就代表這個介面能幫上忙的部分已經用盡了。
