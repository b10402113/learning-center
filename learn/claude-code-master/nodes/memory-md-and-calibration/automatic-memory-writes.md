# memory.md 是怎麼自己填滿的？

上一段講的是你自己留記憶時的樣子。但有些記憶不是你留的，它會自己寫。

你打開 memory.md，發現裡面多了幾段話，但你確定自己沒寫過。這不是哪裡壞了。最新版的 Claude Code 會自己把 memory.md 填起來。

<!--image:1-->

## 它自己判斷，也自己寫

機制很單純：你跟 Claude Code 對話，只要它認為這段對話值得留在記憶裡，它就會寫進去。

所以會遇到這種情況：你什麼都沒要求，它還是自己把內容寫回 memory.md。沒有一個「存檔」按鈕要你按，判準在它那一邊。

這裡面有兩件事。記憶長得比你預期快；值不值得記，是它當下的判斷，不是你的。你要調的是它判斷出來的結果，而不是自己去改檔案。

## 想叫它記住，用講的

除了它自己寫，你也可以直接下指令：把你要它記住的那一小段資訊講出來，可能關於你的一件事、一個偏好、一個 nugget，它就會照這個自然語言指令寫進 memory.md。

<!--image:2-->

關鍵是：不用自己翻檔案、找位置、改 Markdown。你只要把「記住這件事」講清楚，寫入的動作交給它。

## 那可以自己手改嗎

可以，檔案就是 Markdown，你打得開也改得動。但講者不建議這樣做：在大多數 agentic 平台上，讓 agent 幫你檢視、編輯這些 Markdown 檔，效率高得多。

差別在於你有沒有那個上下文。你自己改，得先知道該動哪一行，還得擔心等一下它自己寫入時跟你打架。讓它改，它讀得到前後文，也看得到自己剛才寫了什麼。

## 確認開關：/memory

自動記憶寫入（auto memory logging）在最新版的 Claude Code 是預設開啟的。要確認，在 VS Code 裡輸入 `/memory`。

它會提示你到 terminal 繼續。點下去，它會幫你開好 terminal 視窗，並從那個 terminal 啟動 Claude Code。

<!--image:3-->

進去之後往上找，你會看到 auto memory 的開關。按 Enter 可以把它切成關閉；預設應該是開著的。

## 什麼時候該你開口

自動記憶處理的是「它自己覺得重要」的那一半。你要處理的是另一半：它還不知道、但你需要它記住的東西。

那一半不用動檔案。一句話就好。
