# MEMORY.md 就是一份索引

上個禮拜你已經跟 Claude Code 一起做完一份東西，決策、偏好、被退回的寫法都講過了。這禮拜開一個新 session，它又從零開始，於是你把同一段背景再貼一次。你會直覺想：那就把所有東西都寫進一個大檔，讓它每次讀完就好了。

問題是，那個「大檔」會越長越可怕。真正的做法是分成兩層，而且要分清楚哪一層負責記住、哪一層負責找到。

## 兩層記憶，兩種讀法

Claude Code 預設給你的記憶，大致是兩層。

一層是 `CLAUDE.md`。它像員工手冊：每次 session 一開始，Claude Code 就把整份從頭讀到尾，一次讀完。它不需要你提醒，也不需要判斷現在該不該看。

<!--image:1-->

另一層是 `MEMORY.md`。它也會被讀，但讀的是很短的一份東西。課程裡示範的那份 `MEMORY.md` 並不長，大概只有 75 行。

長度只是表面。這兩份檔案做的工作不一樣：手冊要你照著做，索引只告訴你東西在哪。

## 短，是因為它只放指標

`MEMORY.md` 本質上就是一份短清單。它的內容是一份 reference file，指向你平常跟 Claude Code 對話時累積下來的各種 artifact——那些被存成記憶的東西。

這裡最容易誤會的是：`MEMORY.md` 不是儲存內容的地方，它是一份索引。它把記憶拆到不同的 markdown 檔，自己只留指向；每一個 markdown 檔裡面，才是真正的記憶內容。

所以在 `MEMORY.md` 裡，你看到的是「這種偏好的記憶放在哪個檔案」，看不到「我不喜歡太技術的範例」。真正的句子在後面那個檔案裡，索引只負責讓你找得到。

## 往下一層：一個實際的例子

課程裡拿 `memory-feedback.md` 當例子。它本身也是指標，指向好幾個記錄「我給過 Claude Code 什麼回饋」的 markdown 檔。

其中一則回饋是：一起協作內容時，所有的內容範例都要盡量不那麼技術，讓一般人也看得懂。

那則記憶落在一個叫 `feedback_audience_non-technical.md` 的檔案裡。打開來看，它不是一句話，而是一個有名字、有描述、也有正文的 text 檔。

<!--image:2-->

關鍵在正文什麼時候被讀。它不會在每個 session 都被載入，Claude Code 覺得需要的時候才讀。以上面這個例子來說，它會在你們一起做某一份內容的時候去讀，因為它判斷這個記憶 artifact 跟眼前的任務有關。

索引幫你的就是這件事：先把目錄看一遍，再進去拿那一份，不會把全部記憶倒進 context。

## 索引的價值在「翻得到」

換個說法。`MEMORY.md` 給 Claude Code 的能力，是讓它可以翻那個檔案櫃，然後真的找到相關的 artifacts、找到你過去那些相關的對話，於是比較能幫上你的忙。

這裡有個順序上的差別。如果記憶全部放在一份長檔，那就是每次都被完整載入，不管今天做的是內容還是程式。如果記憶是一份索引，載入的是目錄，正文等到被判定相關才進來。

## 弄壞它的方式

最好記住這個失敗長相：`MEMORY.md` 越寫越厚，每一則記憶的正文都被你抄進去。

那一刻它就不再是索引了，它變成了一份很長的手冊，只是名字還叫索引。你會同時失去兩個好處——每次 session 都要付整份的載入成本，而它也不再需要判斷哪一則相關，因為全部都已經在眼前了。

判斷的方法很簡單：打開 `MEMORY.md`，如果你看到的是「哪裡有什麼」，它還是索引；如果你看到的是「全部內容」，它已經被當成儲存用了。

真要把偏好、回饋、決策留下來，就往下寫一個有名字、有描述、有正文的 markdown 檔，然後在 `MEMORY.md` 留一行指向它。索引要短，內容要深。
