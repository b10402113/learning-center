# memory.md 其實只是一份短清單

上一段停在一個動作上：往下寫一個有名字、有描述、有正文的 markdown 檔，再回索引留一行。那個檔案就是這裡要拆的 memory artifact。

Claude Code 有長期記憶，聽起來像一個很大的東西，但它的入口檔很小。你打開 `memory.md`，看到的是一份名單：它只列出「有哪些記憶存在」，沒把記憶本身塞進來，也不是一整櫃的偏好與規則。

這個差別很關鍵。Claude Code 每次開 session 讀的東西，跟它當下真正需要知道的東西，可以不是同一批。

## 兩份檔案，兩種讀法

Claude Code 預設有兩層記憶。

一層是 CLAUDE.md，課程裡把它比喻成員工手冊：每次 session 一開始，整本從頭到尾讀完，沒有例外。

另一層是 memory.md。它的角色跟員工手冊不同，是參考檔（reference file），指向你和 Claude Code 對話裡累積下來的各個 memory artifact。

所以這兩份檔案的份量差很多。手冊是「你必須知道的全部」，索引是「有哪些東西你可以去查」。

## 75 行的索引

課程示範的那份 memory.md 只有 75 行左右。以一份長期記憶來說，這短得有點反常。

理由很直接：它的工作是索引，不是倉庫。它不把所有 memory artifact 塞進同一個長檔，只指向不同的 markdown 檔；對話中存下來的記憶，放在那些檔案裡。

<!--image:1-->

打開它就會懂這個設計的好處。你看到的就是一份目錄。要判斷「這件事以前記過嗎」，翻目錄就夠了。

## 指標底下還有指標

索引不只一層。

課程的例子是：memory.md 指向 memory feedback.md，而那份檔案本身也是指標，再指向一堆 markdown 檔，記的是「我給過 Claude Code 什麼回饋」。

換句話說，你有一條指標鏈：入口檔指向分類檔，分類檔指向具體的記憶。中間每一層都只是一個名字加上去向，真正的內容都放在最底層。

<!--image:2-->

其中一條具體的回饋是這樣：與 Claude Code 一起共創內容時，所有的內容範例要盡可能不技術，讓一般人都看得懂。這條回饋放在它指向的其中一個檔案裡，檔名是 `feedback audience non-technical.md`，memory.md 本身沒有。

## 一個 artifact 長什麼形狀

走到最底層，你會看到一個文字檔，形狀固定：它有 name、有 description，還有一個 body。

<!--image:3-->

name 是它的身分，description 說明它管什麼，body 才是真正的內容。Claude Code 不會每次都讀 body，只在它認為必要的時候讀。

「必要」的判斷基準是相關性。課程的例子是：當你們正在一起做某一篇內容，Claude Code 會認出這個 memory artifact 跟眼前這件事有關，於是才去讀它。平常沒碰上相關任務，body 就留在檔案裡。

這也是索引要分層的原因。如果 body 全部塞進 memory.md，每一個 session 都得付這筆成本；分成指標之後，只有被判定相關的那幾份會被載入。

## 它給的是翻櫃子的能力

回到檔案櫃的比喻。memory.md 讓 Claude Code 能翻整個櫃子，找到相關的 artifact、找到你過去相關的對話，做出來的東西才更貼近你。

所以要養的習慣很簡單：把抽屜分好。每份記憶有自己的名字、描述和 body，入口檔只負責讓人找到它。
