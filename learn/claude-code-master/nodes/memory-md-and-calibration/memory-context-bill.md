# 超過五萬 token，就該審記憶檔了

記憶開始自己長之後，下一個問題是：這些記憶檔每次開新對話要你付多少。

你開一個新的 session，還沒打半個字，context 已經少了一塊。那一塊是兩份記憶檔。它們不用等你用到，一開場就整份推進去了。

課程講得很直白：CLAUDE.md 和 MEMORY.md 這兩層記憶，每個 session 都會載入。你每次開一個 session，或開一個 Claude Code 的對話視窗，它們都已經在那裡。你一送出第一個 prompt，它們就是 pre-inject 好的。

<!--image:1-->

所以這是一筆固定成本。專案再小，你一樣要付。

## 先量，不要猜

要知道這筆錢有多少，打 `/context`。做法跟之前看 skills 一樣。

輸出裡有一個 memory files 區塊，課程稱它是綠色那一層。它會明確告訴你，你的 CLAUDE.md 加 MEMORY.md 現在佔多少 token。

<!--image:2-->

課程示範的時候是 8,100 token。他的評語是：這算相當健康。

這裡要停一下。8,100 不是目標值。課程明說，沒有任何規則規定記憶檔該大該小，因為每個人的工作不一樣。這句話不是「隨便多大都行」，是「沒有通用門檻」。

但也不是完全沒有數字。

## 50,000 是課程給的那條線

如果光是 memory 和 CLAUDE.md 加起來就超過 50,000 token，值得審一次你的檔案。

審的目的很具體：確認它們沒有在吃掉你的 token。課程補了一句，如果你用的是 Pro Plan，這件事更要看。

重點在「光是」這兩個字。50,000 算的是這兩份檔案的合計，整個 context 的上限另計。你的程式碼、你的對話、你的工具輸出，都還沒算進去。

## 有一半你改不動

`/context` 會把 token 分門別類。課程點名其中兩類：system prompt 和 system tools。

這兩類是 Anthropic 在 Claude Code 的 harness 裡寫死的。課程的原話是：那裡我們沒什麼能做的，也改不了。

所以看到總數偏高，先別急著刪東西。你要看的是你動得了的那部分。

<!--image:3-->

課程說，動得了的是兩類：memory files，以及 skill descriptions。這兩樣使用者可以改。

50,000 這條線如果被踩到，能動的就只有這兩樣。system prompt 和 system tools 你只能接受。

## 那先砍哪一份

`/context` 給的是 CLAUDE.md 加 MEMORY.md 的合計。它不會告訴你哪一份比較胖。

所以「先砍哪一個」不是從 `/context` 讀出來的答案，是你打開兩個檔案比出來的。課程對這件事的用詞是「審你的檔案」，要做的是改檔案內容，不是調某個設定。

<!--image:4-->

課程沒有給公式。你可以先從一個問題問起：這一段，每個 session 都非知道不可嗎？不是的話，它就是候選。兩份都問過一輪，你才知道該先動哪一份。

## 弄壞它一次

想親眼看到這筆帳，就把 MEMORY.md 塞爆。

貼一段很長的內容進去，開一個新 session，再打一次 `/context`，看 memory files 那一層的數字跳多少。看完再刪掉。

你會看到一件事：那個數字每開一次 session 就重付一次。這就是 50,000 這條線存在的理由。
