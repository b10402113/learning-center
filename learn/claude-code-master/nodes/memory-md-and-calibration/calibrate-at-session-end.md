# 每次結束 session，都用一次叫 calibrate 的 skill

記憶怎麼存、怎麼量，前面都走過了。最後一段講收尾：怎麼讓每一場 session 的修正留下來。

一個 session 裡，你大概會糾正 Claude Code 好幾次。它把摘要寫成三點，你說不要三點；它用了一個你不喜歡的檔名，你說改成另一個；它先解釋再動手，你說直接動手。你當場修好了，對話看起來很順。

然後你關掉 session。下一次開新的，它又回到出廠預設。

課程作者自己每天都在跑這個收尾動作：他有一個叫 calibrate 的 skill，幾乎每個 session 結束都會跑一次。

## calibrate 不做事，它回頭看

calibrate 的功能只有一個：把剛剛那個 session 重看一遍。

它會找出你在對話裡糾正過它的地方，也會找出你中途給回饋的地方，像是「不對，改成這樣」「不要那樣寫」「先別動這個檔案」。找到之後，它做兩件事：把這些教訓寫進它的 memory，再針對該更新的 skill 給出建議。

差了這一步，你花的力氣只留在那一個 session 裡。跑了 calibrate，同樣的修正才有機會變成下一次的預設。

## 你對它說話的方式，本來就該有回饋

作者用一個很日常的比喻：你跟 Claude Code 講話，其實很像在跟隊員講話。

你不會跟隊員講完一次就結束。一次指導結束時，你會期待對方從剛剛那段對話裡學到東西，調整自己的做法，也調整配合你的方式。calibrate 就是把「教練結束時會做的事」寫成一個 skill。

這也是它跟一般聊天機器人最大的差別。你對 ChatGPT 講完一段，那段就過去了；你把同樣的力氣放在 Claude Code 上，它應該留下來。

## 一個真實的例子：recording

作者示範他自己的一個 session。他先跑了一個叫 recording 的 skill，這個 skill 會處理他的一支 YouTube 影片：拿到逐字稿，替那場一小時的社群 live session（Agents of Our Coffee）自動標出時間戳，把整段流程自動化。

這個 session 結束時，他跑 calibrate。

結果是：calibrate 直接更新了 recording 這個 skill，也更新了 memory。它把作者想要的變更直接套進去，不是列成一張待辦清單丟給他。他說，這是因為他的 Claude Code 已經知道 calibrate 這個關鍵字在指什麼，所以能立刻動手，而不是先問一輪。

下一次他用同一個主題跟它對話，它已經帶著那份知識進來，可以直接做得更好。

## 會滾雪球的那件事

把鏡頭拉遠，這就是課程一直在講的 Agentic Operating System 長出來的方式。

起點是一批初始的 skill，加上一份慢慢累積的 memory。然後你持續跟 Claude Code 工作，每個 session 結束跑一次 calibrate。一次一次下來，它越來越貼合你實際需要的樣子，像滾雪球一樣，長成一套只適合你這套工作方式的東西。

<!--image:3-->

作者說得很直接：這樣它就越來越像一個隊員，而不是你以前用 ChatGPT 時習慣的那種聊天機器人。

## 先跑起來，再改成你的

課程把這個 skill 放在資源區，作者的建議是拿去試，再改成自己的。

先看它在你的 session 上抓到什麼、建議改哪些 skill，再判斷哪些建議你買單。不合用的地方就改掉它，讓它更貼合你自己的設定。calibrate 本身就是一個 skill，它也可以被 calibrate。
