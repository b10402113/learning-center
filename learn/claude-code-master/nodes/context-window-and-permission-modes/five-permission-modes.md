# 權限模式：每一次都用 auto mode

你大概遇過這兩種狀況。一種是同一個指令已經按了第十次「允許」，手比腦快，一段本來要做的事被切成十幾個確認。另一種剛好相反：它在改一個你其實不想被動的檔案，你盯著畫面，不確定它下一步要幹嘛。

這兩件事其實是同一個開關造成的。Claude Code 聊天視窗旁邊有一個小切換鈕，就是 permission mode（權限模式）。它只決定一件事：在它動手碰你的檔案之前，要先問你多少。

控制給得越多，它每一步都停下來等你，速度就慢；控制給得越少，它自己往下跑，速度快了，代價是你比較晚才知道它做了什麼。所以這五個模式不是五種功能，是一條線上的五個位置。

## 五個模式，排成一條控制與速度的線

從上到下的順序是：ask before edits、edit automatically、plan mode、auto mode、bypass permissions。

上面的給你控制，下面的給你速度。最上面的 ask before edits 是當中最嚴的：每一次編輯之前，它都要先跟你拿批准。越往下，你按的次數越少，它自己處理的比例越高，出錯時你要回頭追的範圍也越大。

## 第一次打開，只會看到三個

如果你才剛開始用，切換鈕裡大概只有三種模式。另外兩個不是不存在，是預設沒開。

<!--image:2-->

要把它們打開，只需要做一次：左下角的齒輪圖示點進 settings，搜尋 Claude code，會找到一個可以允許 bypass permission mode 的勾選框，它就是大家口中的 dangerously skip permissions。同一個地方也能把 auto mode 打開，它是這五個模式裡最新的一個。勾好、跳出設定，五個模式就全部可以選了。

## ask before edits 和 edit automatically：差在「改」和「跑」

這兩個是最嚴的兩個，但界線比名字看起來細。

edit automatically 並不是全部放行。假設你有一個 demo.md，裡面寫著「Dates added by Claude will appear below.」，你叫它把今天的日期加進去，然後用記事本打開。它會讀檔、把日期加上去，這兩步直接做完，不問你；但要用記事本開啟時，它會停下來，請求你允許這個 bash 指令。

<!--image:3-->

bash 就是終端機指令，讓 Claude Code 代替你在電腦上操作應用程式。請求旁邊會有一句白話說明它到底要做什麼：只是要在記事本打開 demo.md。你可以選只做這一次、只允許這個 session，或者從現在起允許這個專案。確認安全的話，選專案層級，之後就不會再問同一件事。

換句話說，edit automatically 只管「改檔案」這一段，「跑指令」還是會攔。

## plan mode：先給你計畫，再動手

選了 plan mode，打開一篇比較長的文章，請它「改善這篇文章」，它不會直接改，而是先給你一份需要你批准的計畫。

計畫會開在側邊面板，你可以直接 auto accept、自己手動調整，或者叫它繼續規劃。按下接受之後，它才照自己判斷的方式把改動套上去。

這個模式不太受歡迎，原因很單純：這件事用講的就行。你直接叫它「先幫我規劃一下」，不需要切到 plan mode，它也會先給你計畫再動手。作者自己的習慣是維持在 auto mode，然後說「改這篇，先給我計畫」，效果差不多，但計畫直接出現在對話裡，比側邊面板乾淨，也更好回饋意見。

## auto mode：讓它自己挑當下該問不該問

auto mode 做的事，是讓 Claude 針對每一個任務自己選最適合的權限模式。它判斷接下來要做的事有破壞性，就停下來問你；判斷沒有，就直接做。

差別在判斷的顆粒度。你叫它「把我整個 workspace 刪掉」，它不會動手，而是先回你一句：先等一下，這件事是破壞性且不可逆的，我想先確認一下。然後它會跟你核對，確認你的指令是不是真的這個意思。

這就是 auto mode 和 bypass permissions 的分野：不是「一律問」，也不是「一律不問」。

## bypass permissions：真的全開，但沒那麼可怕

bypass permissions 又叫 dangerously skip permissions，名字聽起來像在玩命。

但在 auto mode 出現之前，這其實是很多人的預設，包括作者自己。原因有兩個。第一，Anthropic 這幾代的模型夠聰明，即使開了 bypass，遇到它認為有破壞性的指令，通常還是會問；它也知道哪些檔案不需要碰，哪些東西刪了對使用者不好。第二，跟 agent 工作了幾百小時之後，你會開始優化速度，bypass 就是最快的那個。

不過 bypass 有前置成本：你得先在工作區裡把某些破壞性指令擋掉，這件事可以叫 Claude Code 幫你設定。既然 auto mode 已經有了，作者的建議就變成直接用它。

## 所以選哪一個

五個模式都值得知道它們各自讓 agent 動到哪一步，但多數人只需要記住一個結論：auto mode 是速度與控制之間比較平衡的位置。

ask before edits 留給你在動正式環境、或第一次碰一個 repo 的時候；bypass 留給你已經把破壞性指令擋好、而且真的在意那幾秒的時候。

其餘時間，每一次都用 auto mode。
