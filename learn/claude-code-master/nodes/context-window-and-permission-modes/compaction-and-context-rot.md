# Context Rot：session 越跑越笨

你有過這種 session：前二十分鐘它很準，改什麼中什麼；一個多小時後，你問的還是同一個問題，它卻像第一次聽到，翻出你早就放棄的做法，或指著一個已經修掉的錯誤。

它的能力沒有變。變的是那張桌子。

## 桌子會滿

把 agent 當成你請來的員工，context window 就是他的桌子。你跟他講話，桌上的紙就多一張，一路堆到沒有位置放新東西。

<!--image:1-->

在 Claude Code 裡切到 Opus，這張桌子是 100 萬個 token。你丟一句大概五個 token 的 prompt，它回一段大約兩百 token 的答案，一直聊下去，總有一天桌面會滿。

滿了以後總得讓出空間。Claude Code 的做法是把比較舊的內容摘要掉，這個動作叫 compaction。

## Context rot：不是滿了才變笨

比「滿」更早出現的是 context rot。簡單說：session 跑得越久，它就越明顯地變笨。

原因不是模型退化，是桌上開始混進別的東西。走過的死路、過期的細節、早就修掉的錯誤訊息，這些不會自己下桌。東西一多，模型就慢慢失去主線，在你真正想要的那個答案旁邊繞。

打個比方。你在找一本書裡的某一段話，但如果這本書有一百萬 token，長度差不多是七本《哈利波特》並排。書本身沒問題，模型也夠聰明，只是你問第十章的主題，它可能在第二章就找到一個很像的段落，然後停在那裡。

<!--image:2-->

所以判斷的訊號不是「快滿了」，而是「它開始找錯地方」。

## 先量，再決定

動手之前先看 `/context`。它會告訴你這個窗口已經用掉多少。

有個地方很容易誤會：session 裡你看得到的那些訊息，只佔用量圖上的一小塊。影片裡那一次只花了 7,000 token。剩下的去哪裡了？

在你還沒開口之前就花掉了。每個 Claude Code session 都預先帶著 Anthropic 寫死在 harness 裡的 system prompt，也預先帶著那組叫 system tools 的工具，這兩個你都改不了；再加上你的 memory 檔和 skills。加起來通常是兩萬到兩萬五千 token，workspace 越大還會更多。

<!--image:3-->

換句話說，桌子在你們開始對話之前就已經擺了東西。這也是為什麼「重開一個乾淨的 session」不會真的回到零。

## `/compact` 換到什麼，付掉什麼

`/compact` 會把整個 session 摘要一遍。做法是讓 AI 自己讀完整段文字，再給自己一個 prompt 去濃縮它。你看到的是同一段對話被擠乾，同一個窗口於是裝得下更多後續。

它不是隨時都能用。訊息太少時它會直接拒絕，因為沒有東西可壓。前面那個幫你做完 landing page 的 session 就壓得動，因為裡面真的累積了東西。

代價有三個，都跟「摘要」這件事有關。

第一，留下什麼由模型決定。它讀完整段對話，自己判斷哪些重要。你當時覺得關鍵、它覺得次要的那一句，可能就進不了摘要。

第二，逐字的東西沒了。摘要之後，你不能再回頭引用當時那句錯誤訊息、那段原始回覆。要對照，只能靠摘要裡的轉述。

第三，它壓的是對話，不是那兩萬多 token 的固定開銷。桌面上原本就固定擺著的那疊紙還在。

## 重開換到什麼

重開一個 session，等於把這段歷史整段丟掉。你帶得回來的只有 memory 檔和 skills，那些本來就會在開場被載入。

所以它不是「比較乾淨的 compact」，是另一種取捨：你換到一張沒有死路、沒有過期細節的桌面，代價是前面所有推導、所有試錯的脈絡一起歸零。

## 什麼時候用哪個

看到 rot 的症狀，先問一句：這段歷史裡還有你要的東西嗎？

<!--image:4-->

有，就 `/compact`。走過的路和最後定下來的做法還有用，只是體積太大，壓一壓繼續用。

沒有，就重開。如果大半內容是死路、舊錯誤、已經放棄的方案，摘要只會把這些東西的殘影留在桌上，不如帶上 memory 檔從頭開始。

還有一個選項是什麼都不做。多數時候模型夠好，而且一天比一天好，你可以讓 session 一路跑到肉眼看到 rot 為止。真的跑到一百萬 token，它也會自己 compaction。

## 該防的是 rot，不是滿

影片最後給的判斷值得記著：這個窗口現在相當大，而且大概會越來越大。對大多數人來說，context window 不是最大的阻礙。

真正會咬你的是 rot。桌子還空著，它已經開始找不到路了。

要判斷自己離滿還有多遠，得先把桌面量出來。下一篇就從那個什麼都還沒做的空 session 開始，看 `/context` 上的第一個數字。
