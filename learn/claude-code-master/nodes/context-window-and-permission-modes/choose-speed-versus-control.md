# 速度與控制的平衡

你正在改一份檔案。Claude Code 讀完了，開始動手。然後跳出一個視窗：「允許這個 bash 指令嗎？」你按下允許。過三行，又一個。十分鐘之後，你覺得自己不是在寫程式，是在按按鈕。

Permission mode 要解決的就是這件事。它不是安全設定裡一個無關緊要的開關，而是你每次跟 Claude Code 合作時，速度與控制之間的取捨。

## 一個開關，五個刻度

Permission mode 是聊天視窗旁邊的一個切換器。點開，你會看到五個選項：ask before edits、edit automatically、plan mode、auto mode、bypass permissions。

它們做的事只有一件：決定你給 Claude Code 多少權限去看和改你的檔案。這個決定直接影響它跑得多快。

把這五個想成一條線。上面的模式給你更多控制，因為幾乎每一個動作你都要先核准；代價是速度。下面的模式給你更多速度，因為需要你點頭的地方變少了；代價是控制變少。

第一次打開 Claude Code 的人，通常只看得到其中三個。另外兩個要自己打開。

## 先把看不見的兩個打開

點左下角的齒輪圖示，進到 settings，搜尋 Claude Code。你會找到一個核取方塊，允許 bypass permission mode——它的另一個名字是 dangerously skip permissions。同一個地方也能打開 auto mode，它是這五個模式裡最新的一個。

勾選，離開，五個模式就都在了。這一步只做一次。

## Ask before edits：每一刀都問

這是最嚴格的一個。Claude 每次修改之前都會問你。控制力最高，速度最慢。

## Edit automatically：改檔案放手，跑指令仍然會攔

選這個模式，Claude 會自動修改你選取的文字，或整個檔案。聽起來寬鬆很多。但實際跑一次，你就會看到界線在哪裡。

假設你有一個示範用的文字檔，裡面寫著「Dates added by Claude will appear below.」。你給的指令是：把今天的日期加進這個檔案，然後用記事本打開它。

Claude 讀了檔案，把日期加進去，這一步沒有問你。接著它要開記事本。這裡跳出核准，因為那是一個 bash 指令。

<!--image:2-->

Bash 就是終端機指令，它讓 Claude Code 代替你操作電腦上的應用程式。視窗上會有一段白話說明：即將在記事本中開啟這個檔案。你的選項有三種：只允許這一次；對這個專案往後都允許；或是切成只對目前這個 session 有效。

如果你判斷這個指令安全，就選專案層級，以後不用再點頭。

這一段的重點是：自動編輯不等於自動執行。改檔案內容和動用系統的動作，是兩條不同的線。

## Plan mode：先看計畫，再動手

選 plan mode，然後請它改良一篇長文章。它不會直接改。它會先給你一份計畫，等你核准。

<!--image:3-->

計畫完成之後，右側會開一個面板顯示那份計畫。你可以自動接受這份計畫、手動調整，或讓它繼續規劃。按自動接受，它才照自己的判斷把修改套上去。

這個模式不算流行，原因不是它不好用，而是它有點多餘。你其實可以用自然語言叫它規劃：只要跟 Claude Code 說「先給我計畫」，它就會先規劃再動手，不需要切到 plan mode。

講者的習慣是留在 auto mode，然後說「改良這篇文章，先給我計畫」。計畫直接出現在對話裡，比另外開一個側邊欄乾淨，要給回饋也容易得多。

## Bypass permissions：快，但你要先設防線

在 auto mode 出現之前，bypass permissions 是很多人的預設，講者自己也是。它的名字裡有 dangerously，這點很反直覺。

原因是這些模型夠聰明。即使 bypass 開著，遇到它認為具破壞性的指令，它通常還是會問你。它知道不要去碰不需要碰的檔案，也知道不要刪掉對使用者不好的東西。講者說，他自己的經驗裡，還有他認識的人的經驗裡，都沒看過 auto mode 或 bypass 讓 Claude Code 在沒有使用者同意的情況下跑破壞性指令。

但這不是保證。Bypass 的意思是：一般工作它直接做完，不問你。當你跟這些 agent 相處幾百小時之後，你會開始為速度最佳化，這就是 bypass 變成首選的時候。

代價是要做事前準備。你得先確定這個 workspace 裡有一些破壞性指令是被擋掉的。你可以直接請 Claude Code 幫你設定。

講者現在的建議變了：既然 auto mode 已經有了，就用 auto mode。

## Auto mode：讓它自己判斷風險

Auto mode 做的事，是讓 Claude 針對每個任務自動選擇最合適的權限模式。如果它判斷接下來要做的事有點破壞性，它就會問你。如果不會，它就直接做——這本來就是我們用 agent 的目的。

它怎麼判斷？給它一個極端的指令：刪掉整個 workspace。

它沒有動手。它先回你一段話：先等一下，我要確認，因為這是破壞性且不可逆的操作。接著它跟你對話，確認它有沒有理解錯你的意思。

<!--image:4-->

這就是 auto mode 的價值。它不是把所有核准都關掉，而是把核准留給真正需要的那一次。

## 怎麼選

多數人直接用 auto mode 就好。它給你速度與控制之間正確的平衡。

- 剛開始用，或在不熟悉的 repo 上動東西：ask before edits。
- 要改一批檔案，但不想每次都被問：auto mode。
- 只想要一份計畫，還不要它動手：留在 auto mode，直接叫它先給計畫。
- 已經很清楚這個 workspace 的邊界，也設好了防護：bypass permissions。

最後一件事值得記住：不管選哪一個模式，破壞性且不可逆的指令仍然會被攔下來問你。模式決定的是平常有多順，不是出事時會不會擋。
