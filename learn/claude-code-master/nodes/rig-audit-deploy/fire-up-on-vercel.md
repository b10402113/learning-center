# Fire up：幾秒部署到 Vercel，挑一個自己的網址

上一課的 audit 交出一份問題清單，你也把抓到的問題修完了。網站總算可以交出去了，但在那之前，它還只存在你的電腦裡。

你在本機做好網站，打開瀏覽器看起來一切正常。  
把網址傳給朋友，他卻回你：「打不開。」

問題不在網站，而在網址。

你現在用的是本機位址，它只能連到自己的電腦。要讓別人也能開啟網站，就得把網站放到一台對外開放的機器上。這個動作叫「部署」（deploy）。

CRAFT 把這一步稱為 Fire up：把網站推上網路，讓其他人也打得開你做的東西。

## 本機能打開，不等於別人能打開

先分清楚網站做完後的兩種狀態。

第一種，只有自己的電腦看得到。  
第二種，別人的電腦也看得到。

差別跟程式碼無關，關鍵在網站放在哪裡。本機位址沒有對外開放，網站還留在自己電腦裡，別人就看不到。

想讓別人打得開，就得把網站部署出去。

## 部署交給 agent，你不用學後台

很多人卡在這一步，是以為自己得註冊帳號、操作後台、設定環境變數，還要看懂一堆錯誤訊息。

素材提供的做法簡單得多：交給 agent 部署。它會把網站推上 Vercel，用你選的網址，幾秒鐘就完成。Vercel 提供免費的網站代管服務，agent 負責把網站放上去。

素材裡還有一份 `/vercel` skill，教 agent 部署到 Vercel 的做法。

這就是 skill 的用處。沒有 skill，agent 每次都得重新摸索；有了 skill，它就能依照記錄好的步驟執行。你也不必每開一個新專案，就重新說明一次「上次那種做法是對的」。

## 網址有兩層，先拿第一層就好

部署完成後你會拿到一個網址，這是第一層：Vercel 配給你的位址，馬上就能開，也能直接分享給別人。

第二層是自訂網域（custom domain）。素材提到一份 Custom domain guide，說明如何把自己的 `.com`、`.io` 或 `.ai` 網域指向網站。

兩層要解決的事不一樣：第一層讓別人打得開，第二層讓網站掛在自己的網域上。

先拿到第一層，就有網站可以分享。等你想把網站當成正式門面時，再處理第二層也不遲。

## 上線不算結束：把過程寫回 skill

素材裡有個容易被跳過的提醒：部署之後，要讓 agent 把整個流程連同你的修正，一起寫成 website-creation skill。

「連同你的修正」這句很重要。這次你調了標題大小、移了按鈕、補上頁尾，這些都不是白做的，下一次可以直接沿用。

流程因此變成一個循環：建置、部署、修正，再把修正寫回 skill。下一次做新網站，就不必從零開始。

這也是 CRAFT 在 Fire up 之後安排 Tailor 的原因。Fire up 是把網站推上網路，Tailor 則是把這套做法調整成適合自己的版本。

## 要給客戶看：用 Rubric Flows 展示流程

素材也提到 Rubric Flows。它是一個視覺化工具，能把建置步驟呈現出來，也能模擬給客戶看。

同一套流程，可以調整成不同客戶容易懂的樣子。對接案者來說，這代表不用每次都重畫一份說明，換個說法，就能呈現同一套流程。

## 今天可以做的四步

1. 在本機啟動網站，確認可以正常開啟。
2. 請 agent 使用 `/vercel` skill 部署，並選一個想用的網址。
3. 拿到網址後，換一台機器開啟，確認網站真的公開了。
4. 把這次做過的修改告訴 agent，請它寫進 skill。

做到第 4 步，這次部署的經驗才算真正留下來。
