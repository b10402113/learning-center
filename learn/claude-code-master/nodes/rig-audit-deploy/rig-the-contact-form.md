# Rig：用 Resend 把聯絡表單接成真的會寄信

你的網站版面乾淨、間距舒服，按鈕也有滑鼠移上去時的效果。訪客填好姓名、Email 和訊息，按下「送出」，接著卻什麼也沒發生。沒有錯誤訊息，也沒有收到信，表單就像幾個排在一起的輸入框。

這一課要做的，就是把前端接上真正的寄信服務，讓按下「送出」之後，確實有事情發生。這個步驟叫 **rig**，用餐廳的前場和廚房來想最清楚。

## 前場很亮，廚房還沒開

Module F8 一開始用了餐廳的比喻：前場是客人看得到的地方，像是燈光、桌椅和菜單；廚房則在後面，負責把餐點做出來。

你的網站目前只有前場。表單擺在那裡，但沒有廚房接單。

<!--image:1-->

要補的就是這一段：替前端接上真的能運作的功能。

## Rig：按鈕按下去，真的有事發生

Rig 在這裡的意思是「把線接好」：用 API key 把聯絡表單接到 Resend，有人按下按鈕時，網站真的送出一個寄信請求。

接線之前，送出表單像把訊息塞進沒有出口的瓶子，你沒辦法從網站的反應知道成功沒有。接好之後，就有東西可以查：信到底寄出去了沒。

## Resend 與那組 API key

Resend 是這一課用的寄信服務，網址 resend.com。你要先註冊、拿到一組 API key，才有東西可以接。

API key 就像進廚房的通行證：表單帶著它向 Resend 提出寄信要求，Resend 才會替你把信送出去。寄信的其實不是網站，網站只負責把請求交給專門的服務。

<!--image:2-->

重點是雙方各自負責什麼：網站收集表單內容、送出請求，Resend 負責把信送到收件匣。分工接對了，整條線才算通。

## 怎麼測：按下去，然後去收信

測法很直接：實際送一次表單，然後去信箱看有沒有收到信。不是盯著程式碼猜它寫對了沒。

<!--image:3-->

真的按下去，可能會遇到三種狀況：完全沒反應、有反應但信沒到、信到了內容卻不對。這三種卡在不同環節，修法也不一樣，沒自己測過就分不出來。

## 再來才是 Audit：讓 agent 把整個網站按一遍

接好一個表單只是其中一步。接下來該在上線前，讓 agent 用 Playwright 把整個網站自己檢查一輪。

Playwright 是免費工具，官網是 playwright.dev，能讓 agent 開瀏覽器，一個一個去點按鈕、填表單。目標是把每個按鈕和表單都點過一次，趕在交付前把問題挖出來，而不是等訪客先遇到。

順序要記得：先 rig，再 audit。先把功能接成真的，才有東西可以測；如果順序顛倒，agent 就只能在還沒有後端功能的空殼上點來點去。

<!--image:4-->

## 這個循環可以重複使用

這套做法可以固定下來：先接上功能，再驗證功能。每建一次，都照同樣的順序跑一遍。

這一課要帶走的不只是 Resend 的設定方式，還有順序：接好功能、自己測一次、讓 agent 再檢查一遍，最後才交付。
