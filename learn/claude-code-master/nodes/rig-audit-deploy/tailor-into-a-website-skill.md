# Tailor：把整段建站流程存成可重用的 skill

上一課把網站部署到 Vercel，你手上已經有一個別人打得開的網址。然後呢？

問題往往不是「做不出來」，而是「只有這次做得出來」。你花了不少時間調整間距、改了三次首屏文案，還換掉某個區塊。最後，這些成果只留在一個資料夾和一段對話裡。下次接到新客戶，你又得從空白資料夾開始，上次學到的教訓也跟著忘了。

CRAFT 的最後兩步，就是要解決這件事：Fire up 讓網站真正上線；Tailor 則把整段建站流程整理成可重複使用的 skill。

## 先讓網站上線

Fire up 那一段已經走過一次：agent 把本機網站部署到 Vercel，選好網址，幾秒鐘就能完成。成品離開你的資料夾，成為一個有地址的網站。

<!--image:1-->

這裡只補兩個之後會用到的細節：Vercel 提供免費的 hosting；不確定怎麼部署時，`/vercel` skill 會讓 agent 照正確方式操作，要接自己的 `.com`、`.io` 或 `.ai` 網域，也有專門的 custom domain 指引。

網站上線不難。值得多花時間的是下一步。

## 把流程連同修正寫成 skill

Tailor 要 agent 做的，是把整個建站過程寫成一份 website-creation skill，而不只是把網站成品留下來。

有個容易忽略的細節：要記錄的不只是流程，還有你做過的修正。「用了哪些工具、下了哪些指令」反而是次要的，真正該寫下來的是「哪裡不滿意、後來怎麼改、為什麼這樣改」。

差別在這裡：一般提示詞只留下結果，修正過程留在對話裡。對話一關，這些資訊就不見了。下次接新專案，agent 不知道你上次刪掉了那個 hero 區塊，也不知道你不喜歡某種按鈕陰影，或最後把字級調成多少。於是，它可能又用同樣的方式碰壁。

寫進 skill 的關鍵不是步驟，而是你中途改了什麼。步驟只告訴 agent「照順序做」；修正則提醒它「哪些做法不要再用」。

把修正也記下來，下次建站就能從上次的成果接著做。這也是 skill 和一般筆記的差別：筆記是留給人看的，skill 會在下一次被讀取，然後拿去執行。

## 用 Rubric Flows 對客戶展示

流程整理好之後，還需要一個可以展示給別人看的版本。

Rubric Flows 是一個視覺化介面，可以用來展示和模擬建站的每個步驟。自己看的時候，它讓整段流程更容易檢查；跟客戶談的時候，能把「我們會怎麼做這個網站」變成看得見的內容，不用只靠口頭說明。

同一套流程，可以依不同客戶調整。Tailor 這個名字講的就是這件事：每個客戶都套同一個模板行不通，得先準備一份經過修正的流程，遇到新客戶再從中調整，不必整份重寫。

<!--image:3-->

整個循環是這樣：agent 先部署網站，接著把建站過程和你的修正整理成 skill，最後透過 Rubric Flows 向客戶展示流程，並依客戶需求調整。

## 驗收：你手上應該有什麼

完成這兩步後，你應該能指出三樣成果：

- 一個可公開存取的網址，也就是 agent 部署到 Vercel 的網站。
- 一份 website-creation skill，記錄這次的建站流程和你做過的修正。
- 一份能在 Rubric Flows 上展示，並可依不同客戶調整的流程。

如果你只能指出網址，那這次只是做出一個網站。能拿出那份 skill，並說明裡面記下了哪些修正，才代表這次的經驗下次可以直接拿來用。
