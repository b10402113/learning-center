# 其實有好幾種觸發方式

上一段請你開一個乾淨的 session，數一數自己付了多少預載成本。數完之後，下一個問題就來了：那我要怎麼把其中一個 skill 真正叫起來？

你把一個 skill 放進 workspace，卻發現它沒動。多數時候問題不在 skill 寫壞，而在你有沒有把它叫起來。

這段教學裡示範的 `/robo` 就是例子。同一個 skill，至少有三種叫法。

<!--image:1-->

## 先看清楚，什麼東西已經在對話裡

在講怎麼叫之前，得先弄清楚對話裡已經有什麼。

每個新開的 session 裡，Claude Code 預先載入的不是 skill 的整份內容。它載入的是每個 skill 的 name、description，還有 trigger phrases，其他什麼都沒有。

<!--image:2-->

所以 agent 從第一句話開始，就知道你 workspace 裡有哪些 skill、各自大概管什麼。它不知道的是細節，那些要等 skill 真的被叫起來，才會進來。

這個設計決定了後面三條路為什麼都行得通。

## 第一條路：直接講名字

最省事的一種，是在句子裡直接點名：「run the robo skill」。

因為那份 description 已經預先載入在你的對話裡，agent 聽得出來你在講哪一個 skill。

你不用打任何符號，就照平常講話的方式講。代價是這條路得靠 description 寫得夠清楚。description 含糊，agent 就認不出來。

## 第二條路：打 `/` 加名字

如果你要的是明確指定，就在對話框打 `/`，接著打 skill 的名字。

這樣會直接觸發那個 skill。觸發之後，你照樣可以接上自己的 prompt。教學裡示範的寫法是：先用 `/robo` 叫起 skill，然後補一句「做一張 sample one slider，跟這門課的觀眾打聲招呼」。

指定歸指定，要做什麼還是你當場說。

## 第三條路：讓 Claude 自己選

第三條路反過來。你不指定 skill，只講你要做的工作。

來源的說法是，你只要講清楚要做什麼工作，讓 Claude 幫你挑就好。

這條路適合你其實不在意用哪個 skill、只想把事做完的時候。它把「挑哪一個」的判斷交出去，換來的是你不用先記得每個 skill 叫什麼。

## `/` 選單裡混著兩種東西

打 `/` 會跳出一個清單，但那個清單不是「你的 skill 清單」。

它列的是你在這個環境裡所有的指令，裡面混著兩件事：你自己寫的 skills，還有 Claude Code 預設就帶的那些指令。

<!--image:3-->

你在選單裡看到的項目數量，不等於你擁有的 skill 數量。反過來說，你在選單裡找不到某個東西，也不代表它不存在，它可能只是預設指令之一。

## 被叫起來之後發生什麼

不管走哪一條路，skill 被觸發之後的動作都一樣。

它會去找那個 skill，讀 `SKILL.md`，把整份內容注入這個 session。原本只有 name 和 description 的對話，這時候才拿到完整的操作說明。

<!--image:4-->

`/robo` 的例子裡，注入的是那套為簡報做的 design system。所以產出的那張 slide 會套上指定的字體、dot matrix 的樣式，還有 skill 裡寫好的顏色和視覺。

這也說明 body 為什麼不跟著預先載入。對話裡先放的只有那一小段，真的要用，再把全文補進來。

## 三條路怎麼挑

整理成三條。

想明確指定某個 skill、不靠 agent 判斷，就打 `/` 加名字。

只是描述你手上要做的事，不想管哪個 skill，就讓 Claude 挑。

想指名但又不想打符號，就直接在句子裡講 skill 的名字。

三條路不衝突，同一個 session 裡可以換著用。
