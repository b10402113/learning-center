# 每次 session 都從預先注入 claude.md 開始

你剛跑完 `/init`。左邊的 explorer 多出幾個檔案：一個 `claude.md`、一個 readme、一個 `.gitignore`。看起來像預設樣板，很容易被當成「先放著，之後再填」。

但 `claude.md` 是整個 workspace 裡最特別的那一個。它不是留給你寫備忘的筆記，而是 Claude Code 每次開新 session、開始聊天時，會主動去找的檔案。

## 它每次開場都會被讀進去

先看清楚它的位置。`claude.md` 就放在你選的那個資料夾裡，和 readme、`.gitignore` 並排。Claude Code 認的是這個檔名，也是這個位置。

所以它的作用跟一般檔案不同。你打開一個新的 session，第一句話都還沒打，它已經被處理過了。

這也是為什麼 `/init` 一開始要問你幾個問題：你的事業在做什麼、你想怎麼設定這個專案。它問完，就照你的回答生出這個檔案。你之後看到的預設內容，只是還沒被改過的版本。

## 名字與城市實驗

最直接的驗法，就是自己改一次這個檔案。

打開 `claude.md`，在裡面寫兩句：我的名字是 Jay，我住在 Sydney，然後存檔。接著開一個新的 session，問它一句：「我的名字是什麼，我住哪裡？」

<!--image:1-->

一般的聊天機器人不會知道這件事。它沒有你的名字，也不知道你住哪個城市。

但這裡會直接答出來。答案不是模型猜的，也不是它記住了你。每次 Claude Code 的 session，其實都是從預先注入這整份文字檔開始的。你寫在檔案裡的那兩句，在你打字之前，就已經在那場 session 裡了。

<!--image:2-->

差別就在這裡。「記住」要靠模型記下來，「預先注入」是每場開場都把整份檔案遞進去。前者不一定會發生，後者是每次都發生。

## 這件事的代價與好處

代價是：你寫進 `claude.md` 的內容，每場 session 都會被帶進來一次，不管這場用不用得到。它不挑段落，整份進去。

好處是：你只要改一個檔案，之後每一場都自動套用。不用每次重打一次自我介紹，也不用祈禱模型還記得你上週說過什麼。

這也解釋了為什麼 `/init` 生出來的預設內容不用一次寫到完美。Claude Code 改這些檔案的動作很快，你之後想加什麼、想刪什麼，隨時回頭改就好。

課程後面會再深入這個概念。現在只要先抓住一件事：`claude.md` 不是一個放著不動的說明文件。它是一個每次開場都會被讀到的入口。

所以你真正要設計的，不是每次開場的第一句話，而是那個每次都會被讀到的檔案。這個資料夾會慢慢裝滿你的 context，而 `claude.md` 是第一個被放進去、也是最常被讀到的那一份。
