# 同一個 prompt 打第二次，就存成 skill

你大概有過這種時候：早上打開 Claude Code，貼上一段已經打過的 prompt，下午又貼一次。手指還記得怎麼按，但你還是在重打。真正該問的不是「這段話值不值得變成 skill」，而是「我到底要打幾次才肯存」。

## 門檻很低：第二次就存

課程給的判斷很簡單。同一個 prompt 打兩次或超過兩次，就該把它存成 skill。

<!--image:1-->

這個門檻聽起來很鬆，因為成本真的很低。skill 刪掉不痛，改起來很快，就算放到忘記也損失有限。丟掉的代價這麼小，就不用等到「確定值得」才動手。

還有一個常見的擔心：skill 會不會太多。對重度使用者來說，skill 多反而是好事。多，才代表你平常怎麼工作已經被寫下來了。

## 例子：/align

作者的做法，是在 prompt 裡加一段，讓 agent 先問釐清問題，確認方向一致再開始做。他那時每天打這段超過兩次，於是把它做成一個 skill。

現在要對齊，就打 `/align`，後面接一個數字，代表要它問幾題。

後來他又改了一次。只要情況允許，問題就附上選項，變成選擇題。你直接回題號加答案字母就能往下走。這比純文字來回快得多，也讓你在放手讓它做 deep work 之前，先確認方向是對的。

<!--image:2-->

打開這個 skill 看，裡面沒有魔法。description 寫的是：先問幾個簡短的問題，在花力氣之前把方向講清楚。下面接著使用說明、流程的第一步該做什麼，以及依他個人偏好要求用簡短白話。它就是一張 recipe card，被叫用的時候，agent 照著做。

## 更自然的建法：整段 session 存成 skill

你可以直接在那個 session 裡描述你要的 skill，叫 Claude Code 幫你存。但更有效、也更自然的做法，是在工作收尾時回頭看：如果整段對話都值得留下，就請它把這個 session 做成 skill。

作者的例子是深度研究。那個 session 裡，他已經把這次研究要什麼、不要什麼都講清楚了。到了尾聲，他直接說：根據這個 session，做一個叫 deep research 的 skill。

他通常會再叫一次 `/align`，讓這個新 skill 盡量貼近自己的偏好。它會問幾個關於怎麼建這個 skill 的問題，你答完，skill 就建好。如果已經有同名的 skill，它會直接提醒你撞名，也會問 intake style、要保留哪些 style。

這件事可以練成習慣：工作時留意那種「明天還要再做一次」的 session，或是今天特別順、特別有生產力的 session。遇到就順手叫它存成 skill。

<!--image:3-->

這樣一個一個存下去，你就是在慢慢養出一個懂你怎麼工作的隊友，把原本要自己重複做的工作交出去。最常被拿來當範例的就是 `/align`，下一段把它整張拆給你看。
