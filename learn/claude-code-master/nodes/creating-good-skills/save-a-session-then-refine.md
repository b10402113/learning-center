# 整段對話，可以存成一個 skill

問句設計好之後，下一個問題是：這張卡片從哪裡長出來？從一段已經跑順的 session，不是從一個空白檔案。

你剛和 Claude Code 做完一輪 deep research。規格是你給的，要什麼、不要什麼都講清楚了，最後的產出也真的能用。問題是下禮拜再遇到同樣的任務，你還是得從頭把那些要求再打一次。

所以做法很直接：把一段做得順的 session 直接存成 skill，再用 `/align` 把它問到你滿意。名詞先講清楚。skill 是一份寫給 agent 的指令檔，存在你的工作區裡，被喚起時 agent 就照著它做。`/align` 是其中一種 skill，功能只有一個：先問你幾個問題，確認方向對了，才讓 agent 花力氣去做。

## 同一個 prompt 打兩次，就該存成 skill

課程給的原則很直接：如果你發現自己對 Claude Code 下同一個 prompt 兩次以上，那就把它存成 skill。

<!--image:1-->

理由要反過來想：skill 太好刪了。修一個 skill 很快，刪一個 skill 也很快，忘了它的存在同樣很快。所以數量多不是負擔。對重度使用者來說，有很多 skill 反而是優勢。

這條原則同時回答了「什麼時候該做」：當你發現自己已經在做同一件事的第二次，那就是訊號，不用等 skill 的架構想清楚才動手。

## 最有效的方式，是留下一整段 session

skill 當然可以在對話裡直接描述，叫 Claude Code 幫你存下來。但課程裡作者說，他實際得到的結論是另一種做法：當你有一段和 Claude Code 的工作 session，而且你覺得整段對話可以存成一個 skill，那會是你替自己的工作建 skill 最有效、也最自然的方式。

用 deep research 當例子。那段 session 裡你已經給了明確的規格：這份研究你要什麼、做完時你不要看到什麼。這些東西平常散在對話裡，收尾時只要說一句：根據這次 session，做一個叫 deep research 的 skill。

差別在於，你不是憑空想像一個 skill 該長什麼樣，而是把一段真的跑過、真的產出過東西的流程留下來。規格、順序、你不要的東西，都已經在對話裡了。

## 存完之後，先 invoke 你的 /align

作者的做法還沒結束。skill 剛存好，他會 invoke 自己那個 `/align` skill，讓這個新 skill 盡可能貼合他的偏好。

`/align` 本身也是這樣長出來的。它原本只是一段加在 prompt 裡的文字：請 agent 問幾個澄清問題，確認我們要的是同一件事。作者發現自己每天要打這段超過兩次，於是把它做成 skill。用法是打 `/align`，後面給一個數字，代表要它問幾題。

後來他又改了一次。除了問問題，只要情況允許，它會直接給選擇題。你回題號和選項字母就好，不用每次重新描述一遍想法。這比自由作答快很多，也讓他更快到「我們已經對齊」的那一刻，然後才讓 agent 去做需要深度處理的工作。

## 一個 skill 就是一張食譜卡

看 `/align` 的內容就懂 skill 是什麼了。它的 description 寫的是：問幾個簡短的澄清問題，讓方向在投入力氣之前就清楚。下面有使用方式的說明、有流程（例如第一步該做什麼），還有一條是作者自己的偏好：用簡短的白話講。

這些加起來，就是一張食譜卡。skill 被喚起時，agent 就照這張卡走。

<!--image:4-->

所以用 `/align` 修一個新 skill，修的其實是這張卡。它會問你打算怎麼建這個 skill，你回答，Claude Code 就把它建出來。作者示範的時候，`/align` 還主動指出名稱衝突（他已經有一個同名的 skill），並且問他 intake 要用哪種方式、哪些風格要保留。名稱撞到、風格沒講清楚，這些都是之後才會痛的地方，先問掉。

## 什麼時候值得回頭存

不是每個 session 都要存。作者給的標準有兩種：你覺得明天還會再做一次的事，以及你今天做得特別順、特別有產能的那種 session。

第二種容易被忽略。做得順的時候，你會以為是自己今天狀態好，其實是那段流程剛好對了。把它留下來，下次就少一次重來。

做完可以試一個小動作：找一段你已經做過兩次的任務，收尾時請 Claude Code 照這次 session 建 skill，然後 invoke `/align` 回答它幾個問題。再回頭看它跟你原本手打的方式差在哪裡。
