# Align：動手前先釐清意圖

上一段提到，作者把一段天天在貼的提示詞變成了 `/align`。它在解的是另一種浪費：不是打得太多，是打完才發現方向錯了。

你有過這種時刻：prompt 打得很長，agent 也真的照著做完，回來的東西方向卻是錯的。

不是它不夠聰明，是你們從頭到尾沒對齊。深度工作的成本很高，方向錯了，前面那些 token 和時間全部作廢。課程裡的做法換了個方向：把「先問清楚」這件事本身存成一個 skill，`/align`。

課程對它的說法很直白：它就是**一張 recipe card**（食譜卡）。每當這個 skill 被叫用，agent 就照著卡片上的步驟做。這篇把這張卡片攤開，看它由哪幾塊組成。

## 一張卡片，兩個欄位決定它會不會被叫到

`align` 這個 skill 的檔案開頭只有兩個欄位：`name` 和 `description`。

`name` 是 `align`，也就是你打的那個斜線指令。`description` 才是真正影響觸發的那一行。它的內容大意是：這是一個動工前的對齊檢查，在開始任何任務之前，向使用者提出簡短的編號問題，讓方向在任何力氣花下去之前就清楚；觸發條件是 `/align`、`align`、`/align [task]`、`align [task]`。

換句話說，卡片的第一段在回答「什麼時候該拿出這張卡」。它把觸發詞直接寫進 description，所以你不必另外記住怎麼叫它，打出來就會中。

## 它為什麼會存在：同一個 prompt 打第二次

這個 skill 不是憑空設計的。課程給的原則很務實：當你發現自己跟 agent 工作時，同一個 prompt 一天要打兩次以上，那就該把它存成 skill。

`/align` 就是這樣長出來的。原本只是 prompt 裡隨手加的一句話：「在你開始做之前，先問我幾個問題確認一下」。因為天天在貼，貼到某個程度，直接做成技能比較省事。

存成 skill 的成本很低，這是課程一直強調的：刪掉很容易、改很容易、忘記它也很容易。所以判斷門檻可以放得很寬：打第二次就存。

## 怎麼叫它

三種叫法，對應三種目標：

- 只打 `/align`：對齊對話裡最近一則還沒處理的請求。
- 打 `/align [task]` 或 `align [task]`：對齊那個任務，動工前先問。
- 在一輪回覆的開頭直接打 `align`：效果同上一條。

還有一個實務上的用法：`/align` 後面帶一個數字，就是你希望它問幾題。課程裡作者的習慣就是打 `/align` 加數字，讓問題數量符合當下的情況。

但這裡有一條硬線：它不會自己啟動。卡片裡寫得很清楚，不要憑自己的判斷默默叫用它，只有使用者要求時才觸發。為什麼？因為對齊本身就是一種摩擦，值不值得付這個摩擦，是使用者決定的。

## 四個步驟

卡片的中段是流程，四步。

<!--image:3-->

**第一步，認出目標。** 我們現在要對齊的是哪個請求？帶了 `[task]` 就是那個任務；只打 `/align` 就是最近一則沒處理的請求；如果判斷不出來，就只問一句「align on what?」，然後停住。

**第二步，產生編號問題。** 上限 5 題，挑最關鍵的那幾題，也就是「假設錯了會浪費最多力氣」的那些。至少 1 題，即使任務看起來很清楚，也強迫問一題 sanity check，因為 `/align` 的目的本來就是刻意的摩擦。使用者如果說「再多問一點」，就超過 5 題。題目要短、要白話、不要術語，一題盡量一句話。如果給選項比開放式問法更快，就當場列 A、B、C，但每個選項只有一行；同時要混搭，不要每題都變成選擇題。

**第三步，等答案。** 使用者會在一則訊息裡回完。他可能全答、可能跳過幾題（跳過的就用你的最佳判斷往下走）、可能直接說「你決定就好」、也可能在問題之外補上新的方向，這些都要吃進去。除非使用者明講要更多對齊，否則一輪就結束。

**第四步，複述後開工。** 用一兩行把鎖定的方向講回去，並且點出「他的回答改變了你原本的預設」的地方，那是漏掉風險最高的部分。然後直接開始，不用再確認一次。

## 問句的優先順序

第二步那句「挑最關鍵的」，卡片另外給了一個明確的排序：範圍（scope）優先於格式，格式優先於對象，對象優先於限制條件，最後才是加分項。

這個順序不是隨便排的。範圍錯了，後面全部重做；格式錯了，至少內容還在。五題要放哪裡，就看這個順序。

## 它明確不做的事

卡片的後半段是禁止清單，讀起來比流程還像重點：

- 第一輪不要超過 5 題，除非使用者要求。
- 不要問 context 或 memory 裡已經看得出來的答案。
- 不要用「還有別的想法嗎」這種填充題，每一題都要有承載。
- 複述不要長，一兩行就上路。
- 不要一直問，一輪就夠。
- 不要自作主張叫用它。

還有一條範圍限制：這個 skill 只處理單一任務。叫一次，對齊當前這個任務，然後結束。它不會替你打開一個持續整場 session 的「對齊模式」；要再對齊，就再叫一次。

## 一次實際的長相

卡片最後附了範例，讓你看見問句密度大概長怎樣。使用者打 `/align write a launch email for our new feature`，回來的是一句複述加上五題：這封信寄給誰（現有客戶、試用使用者，還是全名單）；目標是推動升級、預約 demo，還是單純告知；長度要三行短訊、有分段的完整信，還是主旨加預告；語氣照最近的慣例，還是這次更強調急迫性；有沒有哪個具體數字或成果一定要放進去。

使用者回完，agent 複述一兩行，然後開始寫。

## 反過來：把一次 session 變成卡片

課程最後把這個 skill 用在一個更有意思的地方。你做完一場工作 session，如果覺得「這種事我明天還要再做一次」，或者那場 session 特別順，就可以在 session 結束時直接請 Claude Code 把這次的做法存成一個 skill。

這時 `/align` 多了一個用途：拿它去對齊「這個新 skill 該長什麼樣」。你叫用它，它會問你幾個問題（名稱撞到既有的 skill 要不要改、哪種 intake 風格要保留之類），你答完，Claude Code 就把 skill 建出來。

同一張卡片，一次用在任務開始前，一次用在把經驗封裝成下一次的開始。
