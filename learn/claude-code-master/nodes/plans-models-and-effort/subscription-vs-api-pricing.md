# 一旦超額，你付的會是 API 價格

你打開帳號的 usage 頁面，看到這週的額度快滿了。頁面下面有個開關，叫 usage credits。打開它，Claude 就繼續讓你用。

聽起來只是「多付一點」。其實不是。那個開關一開，你用的價目表就換了一套。

這一節講兩件事：訂閱和 API 價格差在哪裡，以及超額之後為什麼會變貴。

## 兩種價格，兩套邏輯

先把兩個東西分開。

**訂閱方案**是你每個月付一筆錢，換到一個用量上限。講者的說法是：訂閱方案相對 token 價格，是「much more subsidized」——補貼很多。

**token 價格**是按用量算的價目表。每一百萬個 token 多少錢，輸入一種價、輸出一種價。這是真的有人在付的錢，例如你自己在開發一個應用、在 Claude Code 之外呼叫這些模型的時候。

所以平常在 Claude Code 裡工作，你不會直接付到 token 的錢。你付的是月費，然後被額度管住。

## 額度是怎麼算的

額度不是「一個月多少 token」。講者說的 rate limits，是 5 小時的 session 有一個上限，每週也有一個上限。

這件事在挑模型的時候馬上就有感。如果你只有 Pro 方案，講者建議預設用 Sonnet。理由很實際：把 Opus 或 Fable 當成每天的主力，額度會很快用完。

反過來，Max 方案可以預設用 Opus。

但講者也補了一句：可惜這題沒有對或錯的答案，取決於你做的是什麼工作。

## 價目表怎麼讀

講者的表上，Fable 是每一百萬個 input token 十美元。

先定義兩個詞：

- **input token**：你送給 agent 的 prompt。
- **output token**：它回你的東西，包括訊息、思考、tool call，也就是它在背後為了回答你做的每一件事。

input 通常比 output 便宜很多。這個方向要記住，因為 agent 動作越多，output 那一邊就越長。

相對關係講者也直接講了：Fable 是 Opus 的兩倍貴；Opus 比 Sonnet 貴將近 60%；Sonnet 是 Haiku 的三倍。

所以從左到右排下來：Haiku 最省，也最弱；越往右能力越強，成本也越高。

## usage credits：方便，但換了價目表

回到那個開關。

額度用完時，你到帳號的 settings，進 usage，就能看到自己的用量上限被填到哪裡。頁面捲到最下面，就是 usage credits 的開關。打開它，就能繼續用 Claude。

代價在下一句：打開之後，你付的價格就是剛才那張表上的 API 價格。

換句話說，你從「月費加額度」切換成「按 token 計價」。前面說過，訂閱方案相對那張表是被補貼的。一旦切過去，補貼就沒了。講者用「much more expensive」形容這個差距。

這就是超額後會突然變貴的原因。不是額度用完要多付一點手續費，而是整個計價基礎換了一套。

## 怎麼選

實務上分三層來看：

1. **平常**：Pro 用 Sonnet，Max 用 Opus。這是講者給的起點。
2. **還是撞牆**：考慮把很簡單的任務降級到 Haiku。講者自己幾乎不把 Haiku 當預設，但他說一直撞到額度時，值得在簡單工作上一試。
3. **真的要繼續用**：打開 usage credits 之前，先知道接下來是按 API 價格算。

講者自己現在預設用 Opus，同時也在試 Fable，想看它跟 Opus 差多少。這個選擇確實沒有標準答案。但計價方式有分——而且那個開關一撥，就換了一套。

價目表管的是「每一個 token 多貴」。還有一個旋鈕管的是一段 prompt 要想多久，它不會直接反映在價目表上，卻會決定你實際燒掉多少 token：那就是 effort。
