## 好點子也可能來自你自己

現在我們來談**內容點子**，以及怎麼想出真正好的內容點子。這些流程我們等一下會大量**自動化**。

但我要先講一件事：當我們談「好點子的來源」，別忘了**點子也可能來自你自己**。我很多最好的內容點子，都是**臨時想到**的，完全沒有靠 AI agent。

所以沒錯，AI 和自動化在找點子這件事上可以幫你很多。但如果你還記得**內容三要素**：你必須找出**你享受的**加上**對你獨特的**，那麼隨之而來的事實就是：**很多好點子會來自你的經驗，也來自你的專業**。

好消息是，因為我們現在要最佳化的是**量**，所以很多 AI agent 和平台，像 **Claude** 和 **Codex**，其實可以幫你**找**好點子。

## 通用來源：知識之井

接下來要講的這個來源，不管你的利基是什麼都能用：你談 AI 也好、談系統工程也好、談**鉤針編織**也好，都套得上。

你要先搞清楚的是：你這個產業的**知識之井**（well of knowledge）在哪裡。

概念很簡單，但非常重要，尤其如果你想做**教育型**內容。因為在任何產業，你要獲得追蹤，就得**展現出你在那個產業的專業**。而最好的方法之一，就是**永遠跟上那個產業最新的知識**。

舉例來說，我很常談 AI。如果我現在還在講 **OpenAI 的 GPT 應用商店**，那是 **2023 年**的事了，那大概會讓人**降低**對我這個利基專家的信心。因為我作為一個做教育內容的人，工作的一部分就是**永遠跟上最新的工具**，這正是人們願意聽我講話的一大原因。

所以我必須辨識出 AI 的知識之井在哪：**全世界關於人工智慧的最新資訊，都落在哪裡？**

這個「井」會隨產業**差很多**。但以 AI 為例，我發現 **X** 是個非常好的來源。原因是：每當有新東西出來，**發一則推文或 X 貼文**容易太多了，因為它全部都是**文字**。

我以前還只是內容**消費者**、不是主動創作知識內容的人時，其實不太活躍於 X。但我發現，**滑它、把覺得有用的東西書籤起來**，就是很好的資訊來源。

X 的好處是，你只要用個**一天**，它大概就會**摸清你的偏好**。而且像 **Anthropic**、**OpenAI** 這些公司的**即時公告**，還有 **Claude 開發者帳號**，其實都相當活躍，包括 Anthropic 團隊的人，例如 **Claude Code 的創辦人 Boris Cherney**。這些我都追得很緊。

任何吸引我注意的東西，我就**書籤**起來。這樣當我需要內容點子時，我可以直接翻我的書籤，或讓 **Claude** 去讀我的書籤，幫我**提議內容點子**。

這是一個很輕鬆的方法，把你**消費內容的時間**轉換成稍微更有生產力的東西，讓它同時變成你的**點子研究階段**。

## GitHub 與 starhistory

**GitHub** 是另一個來源。它有點像開發者界的 **Google Drive**，大量程式碼、外掛、軟體都以**開源**形式發布在那裡。

我至少**每兩週**會去一個網站叫 **starhistory.com**，它會給你一份**熱門清單**：最多人討論、最多 star 的 GitHub repository。

比如這裡這些，如果有看起來有趣的新東西，我以前會直接打開看它在幹嘛。但現在因為 **Claude** 和其他 AI agent 解析資訊的能力太強了，如果裡面有有趣的東西，例如這個 **voice studio**，看起來像我會感興趣的，我就直接把它丟給 Claude，看它**是不是真的可行**、是不是真的值得談。

因為至少現在我看得到它已經有不少**社會認證**（social proof）。但對我個人來說，這又回到「**你作為創作者喜歡什麼**」這件事：它說它是「開源、完全**本地端**的 **11 Labs 替代方案**」。我不覺得這對我會多有用，尤其我做的內容類型並不是專門聚焦在開源本地替代方案上。

## 官方文件：被低估的來源

當然，還有 **Claude 官方文件**和 **OpenAI 官方文件**，這些也都是很好的知識來源。

舉個例子。我兩週前做了一支影片，標題是「**Anthropic 剛公布了 12 條 prompt Opus 5.5 的新規則**」。當時的背景是 **Opus 5.5 剛發布**。

作為我知識之井的一部分，我知道 **Claude 平台的文件**在「怎麼對這些新模型下 prompt」這件事上，有非常好的素材。他們發布了這份「prompting Claude Opus 5.5」的文件，我就把它**餵給 Claude**，開始跟它一起工作，用來草擬那支影片的**段落節奏（beats）**和**重點條列（bullets）**。

那支影片之所以表現很好，你現在看大概有 **40 萬**次觀看，是因為它非常**切中時事**，非常**新**。它站在那個產業知識的**最前緣**，尤其在那個時間點，因為 AI 動得實在太快了。Opus 5.5 才剛發布，而 **Anthropic 官方**出的東西，對很多人來說一定**有用**，因此也就是**高品質**。

這就是知識之井的重點：**為你的利基找到那口井**。

- 也許是一個很多人活躍的**論壇**。
- 如果你是**醫生**，也許有某個群組在討論 AI 領域最新最好的東西。
- 如果你玩**數學**，數學圈有很多內容創作者，也確實有些論壇在談數學的最新發展。

把這些都納入你的知識之井，並且確保我們接下來要談、用來摘要這些點子的那些 **skill**，有把這些來源**包含進去**。

## 讓 agent 幫你盯：即時通知

再給你一個很實用的技巧。如果你已經在用某種 agent，不管是 **Grokbot**，或甚至只是用 **ChatGPT**，它現在已經有辦法在你**不用下 prompt** 的情況下主動通知你。

你可以試試我下面附的那個 prompt，把它丟給你的 agent，不管是 **Grokbot**、**Hermes** 還是 **OpenClaw**，你就可以有一個**持續的通知流**，只要你的利基裡有新東西，它就會通知你。

舉例來說，我有一個 agent，是一個 **Grokbot 帳號**。一開始我只是讓它給我 **Claude 的通知**，後來我擴充它，讓它也談 **GPT-6**、**OpenAI**、**Google 的消息**，然後它一天大概給我**兩到三次**通知。

順帶說，你**不必**一天收三次。我這樣做唯一的原因是：**AI 這個領域動得實在太快了**。

所以，去思考你利基的知識之井在哪。而且盡量選**越即時**的來源越好。

因為如果你對某個產業很有熱情，但你是從 **TikTok、Instagram 或 YouTube** 上看到這些東西，我其實會說那些是**第二手**的知識來源。原因是：拍影片、真的在鏡頭前錄自己、再發到 YouTube，難度高出很多。所以一旦它上了 YouTube 這些平台，知識的傳遞**本來就有延遲**，比不上你直接從**源頭**拿到，例如 Twitter、Claude、官方文件，或依你的產業而定，像 **GitHub** 這樣的地方。

## 你的利基跟我不一樣

但這一點要講清楚：**你的利基跟我不一樣**。

你當然可以談 AI，但你要知道，你可能會**比較辛苦**，尤其在起步的時候，因為我們之前講過的「**紅海**」問題。

反過來說，如果你熱愛**健身器材**，而且你真的想做健身器材的內容，因為那是你有熱情、有興趣的東西，那健身器材的點子來源和最新消息，大概會來自**別的地方**。這就要由你來判斷，或者用 **Claude** 幫你研究一下那些資訊從哪裡來。

要開始的話，下面有一個 prompt，你可以直接丟給你的 agent。

## 最後一個資源：/latest skill

這個模組最後一個資源，是你可以拿走的這個 skill，我用的叫做 **slash latest**（`/latest`）。

它做的事是：去掃**過去七天**的知識，來源涵蓋各種地方，包含**社群媒體**、**Reddit**，當然也包含**網路**。

我的建議是：用這類 skill，你要有辦法**調整它**。現在我設的是**過去七天**，因為我的產業 AI 動得太快。但如果你的產業不是這樣，你可以把它調成**過去 14 天**或**過去 28 天**，特別是當你發現你的產業拿到的點子**不夠水準**、或對你**不夠有用**的時候。

如果你還不會用 skill，我下面也會附上一些基礎資源，帶你把 **Claude Code** 或其他 agentic 平台**設定起來**，大概**15 分鐘**以內就能搞定。

如果你想更深入了解 skill（它是我們這裡所有東西的基礎，而且當你的內容創作越走越進階，它一定會扮演更重要的角色），我們社群裡有很多素材可以讓你之後有時間再深入。但現在，先試試 `/latest`。

比如我在這裡示範，對「AI agents」跑一次 latest，你可以看到它馬上給我**幾個點子**。這裡面每一個，你大概現在就能用手機拍一支影片、講一講、把手機對著螢幕，然後就開始發內容了，如果你做的是 AI 的話。

所以，**針對你自己的產業、你自己的興趣領域做這件事**。如果你今天有時間，**今天就把那則內容發出去**，讓自己開始累積**次數**。
