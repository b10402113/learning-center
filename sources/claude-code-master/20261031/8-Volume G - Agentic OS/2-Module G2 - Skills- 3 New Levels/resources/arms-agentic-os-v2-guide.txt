README

What this is. The guide that goes with the Agentic OS v2 video. It uses the ARMS framework (Apps, Routines,
Memory, Skills), with three up-to-date levels for each part, so twelve in all. Every prompt shown in the video is
here word for word, and each level has at least one prompt you can paste into Claude Code. All text is
selectable.
How to use it. The fastest way: send this whole PDF to your AI agent and ask which three levels would help your
setup most. It can compare each level with your skills, scheduled tasks, CLAUDE.md, memory files and
connected apps, then pick out the prompts you need. To read it yourself, go part by part in the order the video
teaches: Skills, Routines, Memory, then Apps. Each part has a page on what the levels are, then a page of
prompts. Page 3 maps all twelve levels, and the checklist on page 16 lets you tick them off.
Want my exact setup? The RUBRIC Agentic OS template and the micro apps from the video live in the
RoboNuggets community classroom. This guide gives you the ideas and the prompts to build your own.

What's new
Three things changed how I run Claude in the past weeks, and they show up all through this guide:

Claude 5.5

The newest Claude models, a big step up from the last ones. They're smart enough to find their
way around a big workspace with plain text alone, and they have a 1 million token context
window.

Jev

A fast, cheap decision model from TypeSafe, reached through OpenRouter (one account that
reaches many AI models). It sorts things rather than writing them, so it can decide which model
should take each prompt in well under a second.

Mods

Small add-ons that change how the Claude Code desktop app looks and works. Think of them
as Chrome extensions for Claude Code.

S Skills

Skills are saved instructions Claude follows whenever you call them.

L1

Know your skill types

L2

Model routing

The types depend on your work. Here are the three I use most, plus one trap to watch for:
Database skills hold knowledge, not just steps. My /tone skill holds the examples and principles of how I
write, so any chat can draft in my voice. My /thumb skill points to every thumbnail we've shipped. If you
make or reference the same kind of output every week, give it a database skill.
Watch for overfitting. References can lock your agent into copying them, so you stop getting fresh
ideas. Have database skills add wildcards by default: if Claude pitches 10 titles, 8 follow your references
and 2 are wildcards. Add the good wildcards to your references. My /wildcard skill defines what a
wildcard means.
Artifact skills make decks, infographics and PDFs. Agents are great at HTML (the language web pages
are built in), so build in HTML first and export at the end. Tie the skill to a brand book in HTML (your
colours and fonts) to avoid the generic AI look. Then give your artifacts one inbox, so you find old ones
without spending tokens.
Self-triggered skills run outside the chat, from a button. I click /clean-up when my computer slows
down. It runs on claude -p, which sends Claude a prompt in the background without opening a chat.
Pick the model and effort next to the button.

A common mistake is running every skill on a big, pricey model. Skills with clear-cut steps can run on Sonnet
or even Haiku. My /grammar skill only checks spelling, so it has model: haiku at the top of its file. For
everything else, Jev picks the model for each prompt. In the past weeks it made 4,451 routing calls, each
about 0.6 seconds, for 18 cents in total, and about 4 in 10 went to Haiku. I never felt the smaller model.
A skills view that ranks your skills by tokens shows which ones to slim down. Mine is part of RUBRIC Agentic OS.

L3

Self-improving skills

The more you use a skill, the better it should get. When I review a video, I pin comments on the exact
moment, copy them all and send them to Claude. A teach switch adds one line asking Claude to update the
/cut and /animate skills with what it learned. It's a simple version of reinforcement learning, the same idea
AI labs use to improve their models.
The review app with the teach switch is RUBRIC Editor, in the RoboNuggets classroom.

R Routines

Routines are tasks Claude runs on a schedule, without you typing anything.

L1

Active vs passive routines

L2

Capped routines

Active routines hand you an output to review, like my daily inbox digest that lands in Telegram. Passive
routines run in the background and only ping you when they find something worth flagging. My weekly
brand watch checks the web for sites using the RoboNuggets brand without our approval. If it finds none, I
hear nothing.
This matters as you grow. If all 50 of your routines were active, you'd have 50 things to review every week.
Good passive ideas:
A domain scout that pings you when a good name for your business becomes available.
Machine care that clears old files and flags apps slowing your computer down.

Every scheduled task costs you something, either plan usage or API credits. Once you have a lot of them,
it's easy to lose track of the expensive ones. I keep a routines view of the week's tasks, sorted by the tokens
each one uses, so I can spot any that drain usage without adding value.
When one costs too much, ask Claude to optimise it and cap it. A routine burning about 18 million tokens, or
$10 a week in API credits, can often come down to a $4 cap. Claude usually finds a lot of fat to cut.
My routines view is part of RUBRIC Agentic OS, in the RoboNuggets classroom.

L3

Routines that suggest routines

The best routines are jobs you already do by hand, but you often don't notice you repeat them. Every
Friday morning, a scheduled task reads my week of sessions, spots the jobs I keep doing myself and
suggests routines. It puts them in RUBRIC Recos, a small app that runs on my computer. Before my usage
resets, I add the good ones to a cart, copy it and send it to Claude to set up. Every week the system gets a
little better.
RUBRIC Recos is in the RoboNuggets classroom.

M Memory

Memory is everything Claude knows about you and your work, and just as important, how fast and how cheaply
it can find it.

L1

Long-term memory

When people say "second brain" these days, they mean the files in your workspace, which is probably just a
folder on your computer. Mine holds about 420,000 files. A fancy map of them is optional. What matters is
speed and cost: can Claude find your stuff fast, without burning through your usage limits?
My setup is simpler than most: three plain-text layers that give Claude a map of everything.
1. MEMORY.md - Claude Code loads it at the start of every chat. Keep one short line per memory, like a
library's card catalog, so Claude checks the catalog before it walks the shelves.
2. CLAUDE.md as a map - Claude also reads this file at the start of every chat. Instead of a rulebook, I use
mine as a map that sends Claude to each part of my work. Each department then has its own router
file, like content.md, that points to its folders. If you also use Codex, keep shared rules in one
AGENTS.md and point CLAUDE.md to it.
3. Database skills as routers - a skill like /yourbusiness-data that tells Claude where the up-to-date
numbers and dashboards live.
Plain text is enough. I don't use a vector database. Boris Cherny, who created Claude Code, has said early
versions used one, and the team found that letting Claude search the files itself worked better. If it works
for Anthropic, it will likely work for your business too.
Give images a text description. Claude reads text, so searching 1,000 untagged images means looking at
every one. I save the prompt that made each image as its description. For older images, a cheap model like
Gemini 3.5 Flash-Lite can write one. It tagged about 2,400 of mine for about $2.40.

A QUICK TEST

Ask Claude where something lives in your workspace, like last month's numbers or your latest client deck. If it
opens two or three files to answer, your map works. If it searches everywhere, your map needs another layer.

MEMORY - LEVELS 2 AND 3

L2

Short-term memory

This is the context window, Claude's working memory for one chat. The Claude 5.5 models hold 1 million
tokens. It comes with two problems:
The fuller a chat gets, the worse Claude gets at recalling what's in it. Anthropic calls this context rot.
Every message rereads the whole chat, so a bloated chat costs more and drains your usage faster.
Fix 1: compact with a purpose. When a chat fills up, Claude compacts it, which means it writes itself a
summary. Tell it what to keep, like /compact keep the business decisions and the templates, or Claude
decides and might drop the one detail you need. You can also give Claude standing rules for what to always
keep.
Fix 2: watch your cache. The prompt cache lets Claude reread a chat for a small fraction of the normal
price. But leave a chat idle for about an hour and the cache goes cold, so your next message pays to load
the whole chat again. One chat of mine had been idle for 11 and a half hours. My next message would have
reloaded about 600,000 tokens, about $5 at API prices. My usage mod shows the cache state next to my
7-day and 5-hour limits. My chats also send themselves a tiny ping about once an hour to stay warm, for up
to 4 hours. Over the last 30 days, that would have saved me about $437 at API prices.
The usage mod is free: github.com/robonuggets/ribbon

L3

Self-evolving memory

If you have to correct Claude on the same thing twice, your memory system missed something. I use three
things:
A fix backlog. When I notice mid-job that a skill or app should do better, I type /note and my feedback
goes into that skill's own file. Fixing it right then would lose my thread. When I'm ready, or my usage is
about to reset, Claude applies the whole list.
/calibrate for feedback that really matters. Claude Code saves some memories on its own, but you
don't want to leave the important ones to chance. It saves what I taught it, links it to related memories
and fixes the skill it belongs to.
Suggested fixes. RUBRIC Recos also has a memory section, where Claude suggests improvements and I
pick the ones I like.
A free starting point for calibrate: github.com/robonuggets/calibrate

A Apps

Apps are the outside tools Claude can reach from the chat, plus any apps you build yourself.

L1

Connect anything

You can connect Claude to apps that have no official connector, like Adobe Premiere Pro or MyFitnessPal.
Instead of digging through settings, let Claude search for the way in, in this order:
1. The maker's own tools, if they exist.
2. A community CLI (command line interface tool). Claude types one short command and gets back just
the answer, so it's the lightest on your usage.
3. The app's API (application programming interface), usually through an API key. A step heavier, because
answers come back long, with detail Claude doesn't need but still reads.
4. A community MCP (a plugin that lets Claude talk to an app). The heaviest, because Claude loads every
MCP's full tool list at the start of each chat, even if you never use it. Keep your MCPs few.
My /search-connectors skill does this every time. It's in Jay's Resources in the RoboNuggets classroom.

L2

Mods, for Claude Code and your browser

L3

A micro app for every big job

A mod is a small add-on, like a Chrome extension for Claude Code, that changes how it looks and works.
My usage bar shows my weekly and 5-hour limits and my prompt cache, and it costs no tokens. My Claude
Mods video covers more.
Take the idea beyond Claude Code. Your browser already has mods: Chrome extensions. Claude can build
them for the sites you use every day. One of mine grabs the code behind any part of a website I like, so
Claude can rebuild that exact look instead of guessing from a screenshot. Another saves YouTube titles and
thumbnails into my database skills with a right-click, so I never leave YouTube. Extensions run as code, so
they cost no tokens. To load your own, open Chrome extensions, turn on developer mode and click "Load
unpacked".

Once a job is routine, ask whether a chat window is still the best way to do it. A lot of my work has moved
out of the chat into small apps Claude built, running on my computer: RUBRIC Editor to review every cut,
RUBRIC Carousels to approve Instagram carousels, and Generations for every image and video Claude
makes.
Start with a reusable UI parts library, so Claude doesn't rebuild every piece from scratch and every app
your team makes looks the same. Katie Dill, Head of Design at Stripe, says this is why design systems are
having a moment again: Stripe's people and agents now build from the same system.
