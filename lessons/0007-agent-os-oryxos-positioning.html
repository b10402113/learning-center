Agent OS 概念與 OryxOS 定位

本課目標：用一把尺（Agent OS 五項能力）把 AI Agent 產品分成四類，並說出 OryxOS 為什麼選 Java、如何定位。

從一家公司說起

一家公司請了很多員工（Agent）。每個員工都要領電腦、領門禁卡、走報銷流程。如果每個員工都自己搞定這套行政，公司會亂成一團。

行政部門做的事：統一發電腦（模型接入）、發門禁卡（通道與權限）、記考勤（記憶）、審核支出（審計）。業務部門只需要招人（配置 Agent）和安排具體工作（寫 Tool）。

這個「行政部門」，就是 Agent OS。

Agent OS 的五項能力

Agent OS 是裝在用戶或企業自己的機器上、用來運行和管理多個 AI Agent 的基礎系統。它不是 agent runtime（runtime 只管單個 Agent 的執行），而是 N 個 Agent 在企業裡同時運行時的共享基礎設施。

① Agent 配置與生命週期
建 Agent、啟動、停用、管理配置
② 統一外部通道
接 IM、郵件、Web、HTTP 等外部入口
③ 統一內部系統訪問
接 LLM、工具、IT 系統、知識庫
④ 統一記憶
跨會話保留上下文與長期記憶

⑤ Tool 調用與沙箱執行

這就是口號「Agent 是配置出來的，不是寫出來的」的來歷——業務方只做兩件事：寫一個 Tool 和配置一個 Agent 用這個 Tool。所有橫切關注點都是 Agent OS 的事。

一把尺：四類產品的邊界

理解了五項能力，你就能把任何 AI Agent 產品分清楚：

產品類型 產出什麼 代表
Agent OS 配置好的常駐 Agent OryxOS、OpenClaw、Hermes
編排平台 工作流 Dify、Coze、扣子
框架 代碼 LangChain、Spring AI、LangChain4j
大廠 SaaS 綁定雲的完整應用 Glean、Bedrock AgentCore

關鍵區別：編排平台可以跑在 Agent OS 上當後端；框架可以當 Agent OS 的底層元件；大廠 SaaS 不是能私有部署的底座。Agent OS 是開源、可私有部署、不鎖定生態的那一檔。

Java 生態的空白

最有代表性的兩個開源 Agent OS：OpenClaw（Node.js，30 萬星）和 Hermes Agent（Python，15 萬星）。它們共同留下的三塊空白：

  1. 完整企業治理——多租戶 RBAC、SSO、審計架構、合規證據
  2. 與企業 IT 系統的深層整合——ERP、CRM、CMDB、監控
  3. Java 生態缺位——沒有一個 Java 項目把自己定位成 Agent OS

Java 有 Spring AI、Spring AI Alibaba、LangChain4j，但它們全是庫，產出是代碼，開發者要自己處理運行時。一個「裝上就能跑」的 Java Agent OS 底座，業界幾乎是零。

為什麼值得補 健康的技術生態在每個關鍵層都該有自己的實現。Java/Spring 的企業後端棧極其完整（Spring Boot、Nacos、Sentinel、SkyWalking），偏偏缺 Agent 這一層。今天一個 Java 企業想要私有 Agent 底座，只能去用 Node.js 或 Python 的項目，在兩個技術棧的接縫處寫膠水。

OryxOS 的定位

錨定需求，不錨定概念——「Agent OS」這個詞會被換掉或被吸收，但「受監管企業需要一個完全可控、私有、可審計、對齊 Java 的 Agent 底座」這個需求不會變。OryxOS 把腳踩在需求上。

OryxOS 的一句話定義：

企業可控、Java 原生、私有可審計的統一 Agent 底座，裝在企業自己的 K8s/伺服器/物理機上。

四大設計目標，四個字：

目標 承諾
統一 很多業務 Agent 共享一個底座，一份 Profile YAML 拉起新 Agent
私有 數據完全留在企業內；模型用外部或本地 Ollama/vLLM 都可以
易接入 標準 Spring Boot 結構，直連 ERP/CRM/CMDB/SSO，MCP 或 Spring Bean 接工具
可觀測 Prometheus 指標、結構化 JSON 日誌、健康檢查、Web 儀表盤

邊界很明確：OryxOS 做 runtime，不做可視化流程編排。Dify 這類平台可以跑在它上面調用 API，兩者互補不競爭。安全是 day-one 設計，刻意反著 OpenClaw 的弱點來。
