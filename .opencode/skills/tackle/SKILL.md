Verify that one step was actually understood. Invoke as `/tackle <subject>/<step-id>` (use the node-qualified `<subject>/<node-id>/<step-id>` when a step id repeats across nodes). This is the per-step runtime twin of `/probe`: it generates 5–10 multiple-choice questions on the fly from the step's elements, targets the strands the node's probe rated `unknown`/`partial` (anchored to `MEMORY.md`), and adapts to live answers (correct → harder, wrong → easier). A step passes only when the system estimates every element it teaches at `solid`; passing marks the step complete and writes mastery back to `learn/<subject>/mastery.md`. Unlike `/probe` (which measures a node before it is viewed), tackle verifies one step's concepts at learning time and never proposes pruning — it tests one step's concepts and upgrades only the strands those concepts cite to `solid`.

Prereqs: the step exists at `learn/<subject>/nodes/<node-id>/<step-id>.mdx` (run `/nodes` first), `learn/<subject>/MEMORY.md` exists, and `learn/<subject>/digests/` exists. If any is missing, say so and stop.

1. **Resolve the step.** Read `learn/<subject>/MEMORY.md` (for `language` and prior experience), `learn/<subject>/ROADMAP.md`, and the node container `learn/<subject>/nodes/<node-id>.mdx`. Locate the step file — search the subject's `nodes/` directories when given only `<subject>/<step-id>`; if the step id matches steps in more than one node, ask the learner for the node-qualified `<subject>/<node-id>/<step-id>`. Record the step's `teaches` element ids and `sources`.
2. **Read the concepts.** Read the full text of every element the step `teaches` (`learn/<subject>/elements/<element-id>.mdx`) — its Problem Statement, How it works, Practical use, Connections, and Questions — plus the digest L2 sections behind each element's `sources` locator, per `docs/reference/source-reading.md`. Digest only, never raw sources; dispatch a sub-agent to pull section text when the digest lacks detail. These elements are the concepts under test; every question stays grounded in them and their cited sources.
3. **Anchor and target from the node's probe.** From `MEMORY.md`, prior experience and "How to teach me" set where each element's ladder starts, and set the question `language`. Read the step's node entry in `learn/<subject>/mastery.md` (written by `/probe <subject>/<node-id>`) if it exists, and map each element the step teaches to the node's strands via their `sources` locators. The probe's strand rating sets both where an element's ladder starts and how much of the question budget it gets: `unknown` → start shallow (L1/L2), spend the most questions; `partial` → start mid; `solid` → start deep (L3/L4), give a light spot-check or skip. No node entry → fall back to MEMORY only and cover all elements uniformly. This shifts the starting rung and the question mix only — it never skips an element the step actually teaches.
4. **Build a depth ladder per element.** Reuse `/probe`'s four rungs (`.opencode/skills/probe/SKILL.md` step 3), applied to the step's elements rather than source strands:
   - **L1 — recall**: recognize or name the term / basic fact.
   - **L2 — state**: restate the key claim or mechanism.
   - **L3 — apply**: a worked example or "now decide" using the learner's own context.
   - **L4 — judge**: compare, weigh a tradeoff, or handle an edge case across the step's elements.
5. **Generate 5–10 questions adaptively.** Present one MCQ at a time and wait for each answer, grading immediately — correct or not, then a short explanation and the source locator, in the `/quiz` rhythm. Four options, distractors drawn from the subject's real concepts, never invented words, with the correct answer at a random letter and all four options equal in length and completeness. Each question targets one element at its current rung; paraphrase rather than copy an element's `Questions` verbatim. Spend the budget on the `unknown`/`partial` strands the probe flagged — `solid` strands get at most a single spot-check. Correct → move that element one rung deeper; wrong → one rung shallower. Skip a rung the learner has already effectively answered (correct at L3 implies L1–L2 known). Aim 5–10 questions total across the step's elements; ask at least 5 before concluding, and stop early only when every element is already `solid`.
6. **Estimate `solid` — not a score.** An element is `solid` only when the learner answers its deepest rung (L4) correctly **twice consecutively at L4** (N = 2) — one lucky L4 does not count, and a wrong answer resets the element's L4 streak and drops it a rung. Correct at shallow/mid but not confirmed at L4 is `partial`; wrong at the shallowest rung is `unknown`. The step passes only when **every** element it teaches is `solid`. Keep questions deterministic enough that passing means understanding: no best-guess cues in the options, distractors always from real concepts, and the N = 2 L4 gate defeats luck.
7. **On pass — mark complete and write mastery back.** Report the step complete — a machine-graded signal; step completion itself stays client-side UI state (ADR-0005), so never write a `status` into the step or node file. Then update `learn/<subject>/mastery.md`: in the node entry the step belongs to, upgrade the matching strands to `solid` (never downgrade a strand already `solid`), refresh the node `Notes` with `tackled <subject>/<node-id>/<step-id> on <YYYY-MM-DD>`, and bump the frontmatter `updated`. If the node entry does not exist yet, create it with the covered strands `solid` and the rest `unknown`, and note that `/probe` is the fuller first pass.
8. **On fail — summarize and offer retry.** List the elements still `partial`/`unknown`, each with its source locator and the rung reached, and offer a fresh `/tackle` on the same step. Write-back happens only on pass.

Completion: every element the step teaches was walked to its frontier, the verdict followed the `solid` estimate (L4 confirmed by N = 2 consecutive correct, not a score), mastery was written back on pass (or a retry offered on fail), and no completion flag was written into the step or node file.

## Mastery write-back

`tackle` only upgrades toward `solid`; it reuses the report shape `/probe` writes (`learn/<subject>/mastery.md`, per `.opencode/skills/probe/SKILL.md` "Mastery report format", now keyed by node). Map a step to its node through the step's location (`learn/<subject>/nodes/<node-id>/<step-id>.mdx`); an element citing `[[sources/<subject>/<file>#<section>]]` maps to the strands in that node's entry whose `Sources` list the same locator. Mark those strands `solid`; the node's `Status` is the most conservative rating of its strands. A `Notes` line records the frontier reached so a later `/probe` can resume without re-probing from scratch.
