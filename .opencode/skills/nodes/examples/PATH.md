# 理論一：當談論面向對象的時候，我們到底在談論什麼？

**2019-11-11**

考慮到各個水平層次的同學，並且保證專欄內容的系統性、全面性，我會循序漸進地講解跟設計模式相關的所有內容。所以，專欄正文的第一個模塊，我會講一些設計原則、設計思想，比如，面向對象設計思想、經典設計原則以及重構相關的知識，為之後學習設計模式做鋪墊。

在第一個模塊中，我們又首先會講到面向對象相關的理論知識。提到面向對象，我相信很多人都不陌生，隨口都可以說出面向對象的四大特性：封裝、抽象、繼承、多態。實際上，面向對象這個概念包含的內容還不止這些。所以，今天我打算花一節課的時間，先大概跟你聊一下，當我們談論面向對象的時候，經常會談到的一些概念和知識點，為學習後面的幾節更加細化的內容做一個鋪墊。特別說明一下，對於今天講到的概念和知識點，大部分我都是點到為止，並沒有展開詳細講解。如果你看了之後，對某個概念和知識點還不是很清楚，那也沒有關係。在後面的幾節課中，我會花更多的篇幅，對今天講到的每個概念和知識點，結合具體的例子，一一做詳細的講解。

## 什麼是面向對象編程和面向對象編程語言？

面向對象編程的英文縮寫是 OOP，全稱是 Object Oriented Programming。對應地，面向對象編程語言的英文縮寫是 OOPL，全稱是 Object Oriented Programming Language。

面向對象編程中有兩個非常重要、非常基礎的概念，那就是類（class）和對象（object）。這兩個概念最早出現在 1960 年，在 Simula 這種編程語言中第一次使用。而面向對象編程這個概念第一次被使用是在 Smalltalk 這種編程語言中。Smalltalk 被認為是第一個真正意義上的面向對象編程語言。

1980 年左右，C++ 的出現，帶動了面向對象編程的流行，也使得面向對象編程被越來越多的人認可。直到今天，如果不按照嚴格的定義來說，大部分編程語言都是面向對象編程語言，比如 Java、C++、Go、Python、C#、Ruby、JavaScript、Objective-C、Scala、PHP、Perl 等等。除此之外，大部分程序員在開發項目的時候，都是基於面向對象編程語言進行的面向對象編程。

以上是面向對象編程的大概發展歷史。在剛剛的描述中，我着重提到了兩個概念，面向對象編程和面向對象編程語言。那究竟什麼是面向對象編程？什麼語言才算是面向對象編程語言呢？如果非得給出一個定義的話，我覺得可以用下面兩句話來概括。

> **面向對象編程**是一種編程範式或編程風格。它以類或對象作為組織代碼的基本單元，並將封裝、抽象、繼承、多態四個特性，作為代碼設計和實現的基石。

> **面向對象編程語言**是支持類或對象的語法機制，並有現成的語法機制，能方便地實現面向對象編程四大特性（封裝、抽象、繼承、多態）的編程語言。

一般來講，面向對象編程都是通過使用面向對象編程語言來進行的，但是，不用面向對象編程語言，我們照樣可以進行面向對象編程。反過來講，即便我們使用面向對象編程語言，寫出來的代碼也不一定是面向對象編程風格的，也有可能是面向過程編程風格的。這裡聽起來是不是有點繞？不過沒關係，我們在後面的第 7 節課中，會詳細講解這個問題。

除此之外，從定義中，我們還可以發現，理解面向對象編程及面向對象編程語言兩個概念，其中最關鍵的一點就是理解面向對象編程的四大特性。這四大特性分別是：封裝、抽象、繼承、多態。不過，關於面向對象編程的特性，也有另外一種說法，那就是只包含三大特性：封裝、繼承、多態，不包含抽象。為什麼會有這種分歧呢？抽象為什麼可以排除在面向對象編程特性之外呢？關於這個問題，在下一節課詳細講解這四大特性的時候，我還會再拿出來說一下。不過，話說回來，實際上，我們沒必要糾結到底是四大特性還是三大特性，關鍵還是理解每種特性講的是什麼內容、存在的意義以及能解決什麼問題。

而且，在技術圈裡，封裝、抽象、繼承、多態也並不是固定地被叫作“四大特性”（features），也有人稱它們為面向對象編程的四大概念（concepts）、四大基石（cornerstones）、四大基礎（fundamentals）、四大支柱（pillars）等等。你也發現了吧，叫法挺混亂的。不過，叫什麼並不重要。我們只需要知道，這是前人進行面向對象編程過程中總結出來的、能讓我們更容易地實現各種設計思路的幾個編程套路，這就夠了。在之後的課程講解中，我統一把它們叫作“四大特性”。

## 如何判定某編程語言是否是面向對象編程語言？

如果你足夠細心，你可能已經留意到，在我剛剛的講解中，我提到，“如果不按照嚴格的定義來說，大部分編程語言都是面向對象編程語言”。為什麼要加上“如果不按照嚴格的定義”這個前提呢？那是因為，如果按照剛剛我們給出的嚴格的面向對象編程語言的定義，前面提到的有些編程語言，並不是嚴格意義上的面向對象編程語言，比如 JavaScript，它不支持封裝和繼承特性，按照嚴格的定義，它不算是面向對象編程語言，但在某種意義上，它又可以算得上是一種面向對象編程語言。我為什麼這麼說呢？到底該如何判斷一個編程語言是否是面向對象編程語言呢？

還記得我們前面給出的面向對象編程及面向對象編程語言的定義嗎？如果忘記了，你可以先翻到上面回顧一下。不過，我必須坦誠告訴你，那個定義是我自己給出的。實際上，對於什麼是面向對象編程、什麼是面向對象編程語言，並沒有一個官方的、統一的定義。而且，從 1960 年，也就是 60 年前面向對象編程誕生開始，這兩個概念就在不停地演化，所以，也無法給出一個明確的定義，也沒有必要給出一個明確定義。

實際上，面向對象編程從字面上，按照最簡單、最原始的方式來理解，就是將對象或類作為代碼組織的基本單元，來進行編程的一種編程範式或者編程風格，並不一定需要封裝、抽象、繼承、多態這四大特性的支持。但是，在進行面向對象編程的過程中，人們不停地總結發現，有了這四大特性，我們就能更容易地實現各種面向對象的代碼設計思路。

比如，我們在面向對象編程的過程中，經常會遇到 is-a 這種類關係（比如狗是一種動物），而繼承這個特性就能很好地支持這種 is-a 的代碼設計思路，並且解決代碼複用的問題，所以，繼承就成了面向對象編程的四大特性之一。但是隨着編程語言的不斷迭代、演化，人們發現繼承這種特性容易造成層次不清、代碼混亂，所以，很多編程語言在設計的時候就開始摒棄繼承特性，比如 Go 語言。但是，我們並不能因為它摒棄了繼承特性，就一刀切地認為它不是面向對象編程語言了。

實際上，我個人覺得，只要某種編程語言支持類或對象的語法概念，並且以此作為組織代碼的基本單元，那就可以被粗略地認為它就是面向對象編程語言了。至於是否有現成的語法機制，完全地支持了面向對象編程的四大特性、是否對四大特性有所取捨和優化，可以不作為判定的標準。基於此，我們才有了前面的說法，按照嚴格的定義，很多語言都不能算得上面向對象編程語言，但按照不嚴格的定義來講，現在流行的大部分編程語言都是面向對象編程語言。

所以，多說一句，關於這個問題，我們一定不要過於學院派，非要給面向對象編程、面向對象編程語言下個死定義，非得對某種語言是否是面向對象編程語言爭個一清二白，這樣做意義不大。

## 什麼是面向對象分析和面向對象設計？

前面我們講了面向對象編程（OOP），實際上，跟面向對象編程經常放到一塊兒來講的還有另外兩個概念，那就是面向對象分析（OOA）和面向對象設計（OOD）。面向對象分析英文縮寫是 OOA，全稱是 Object Oriented Analysis；面向對象設計的英文縮寫是 OOD，全稱是 Object Oriented Design。OOA、OOD、OOP 三個連在一起就是面向對象分析、設計、編程（實現），正好是面向對象軟件開發要經歷的三個階段。

關於什麼是面向對象編程，我們前面已經講過了。我們現在再來講一下，什麼是面向對象分析和設計。這兩個概念相對來說要簡單一些。面向對象分析與設計中的“分析”和“設計”這兩個詞，我們完全可以從字面上去理解，不需要過度解讀，簡單類比軟件開發中的需求分析、系統設計即可。不過，你可能會說，那為啥前面還加了個修飾詞“面向對象”呢？有什麼特殊的意義嗎？

之所以在前面加“面向對象”這幾個字，是因為我們是圍繞着對象或類來做需求分析和設計的。分析和設計兩個階段最終的產出是類的設計，包括程序被拆解為哪些類，每個類有哪些屬性方法，類與類之間如何交互等等。它們比其他的分析和設計更加具體、更加落地、更加貼近編碼，更能夠順利地過渡到面向對象編程環節。這也是面向對象分析和設計，與其他分析和設計最大的不同點。

看到這裡，你可能會問，那面向對象分析、設計、編程到底都負責做哪些工作呢？簡單點講，面向對象分析就是要搞清楚做什麼，面向對象設計就是要搞清楚怎麼做，面向對象編程就是將分析和設計的結果翻譯成代碼的過程。今天，我們只是簡單介紹一下概念，不展開詳細講解。在後面的面向對象實戰環節中，我會用兩節課的時間，通過一個實際例子，詳細講解如何進行面向對象分析、設計和編程。

## 什麼是 UML？我們是否需要 UML？

講到面向對象分析、設計、編程，我們就不得不提到另外一個概念，那就是 UML（Unified Model Language），統一建模語言。很多講解面向對象或設計模式的书籍，常用它來畫圖表達面向對象或設計模式的設計思路。

實際上，UML 是一種非常複雜的東西。它不僅僅包含我們常提到類圖，還有用例圖、順序圖、活動圖、狀態圖、組件圖等。在我看來，即便僅僅使用類圖，學習成本也是很高的。就單說類之間的關係，UML 就定義了很多種，比如泛化、實現、關聯、聚合、組合、依賴等。

要想完全掌握，並且熟練運用這些類之間的關係，來畫 UML 類圖，肯定要花很多的學習精力。而且，UML 作為一種溝通工具，即便你能完全按照 UML 規範來畫類圖，可對於不熟悉的人來說，看懂的成本也還是很高的。

所以，從我的開發經驗來說，UML 在互聯網公司的項目開發中，用處可能並不大。為了文檔化軟件設計或者方便討論軟件設計，大部分情況下，我們隨手畫個不那麼規範的草圖，能夠達意，方便溝通就夠了，而完全按照 UML 規範來將草圖標準化，所付出的代價是不值得的。

所以，我這裡特別說明一下，專欄中的很多類圖我並沒有完全遵守 UML 的規範標準。為了兼顧圖的表達能力和你的學習成本，我對 UML 類圖規範做了簡化，並配上了詳細的文字解釋，力圖讓你一眼就能看懂，而非適得其反，讓圖加重你的學習成本。畢竟，我們的專欄並不是一個講方法論的教程，專欄中的所有類圖，本質是讓你更清晰地理解設計。

# 重點回顧

今天的內容講完了，我們來一起總結回顧一下，你需要重點掌握的幾個概念和知識點。

1. **什麼是面向對象編程？**
   面向對象編程是一種編程範式或編程風格。它以類或對象作為組織代碼的基本單元，並將封裝、抽象、繼承、多態四個特性，作為代碼設計和實現的基石 。
2. **什麼是面向對象編程語言？**
   面向對象編程語言是支持類或對象的語法機制，並有現成的語法機制，能方便地實現面向對象編程四大特性（封裝、抽象、繼承、多態）的編程語言。
3. **如何判定一個編程語言是否是面向對象編程語言？**
   如果按照嚴格的的定義，需要有現成的語法支持類、對象、四大特性才能叫作面向對象編程語言。如果放寬要求的話，只要某種編程語言支持類、對象語法機制，那基本上就可以說這種編程語言是面向對象編程語言了，不一定非得要求具有所有的四大特性。
4. **面向對象編程和面向對象編程語言之間有何關係？**
   面向對象編程一般使用面向對象編程語言來進行，但是，不用面向對象編程語言，我們照樣可以進行面向對象編程。反過來講，即便我們使用面向對象編程語言，寫出來的代碼也不一定是面向對象編程風格的，也有可能是面向過程編程風格的。
5. **什麼是面向對象分析和面向對象設計？**
   簡單點講，面向對象分析就是要搞清楚做什麼，面向對象設計就是要搞清楚怎麼做。兩個階段最終的產出是類的設計，包括程序被拆解為哪些類，每個類有哪些屬性方法、類與類之間如何交互等等。
