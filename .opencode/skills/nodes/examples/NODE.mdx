# 理論一：當談論面向對象的時候，我們到底在談論什麼？

## Learning goal

理解物件導向編程（OOP）、物件導向編程語言（OOPL）、物件導向分析（OOA）與物件導向設計（OOD）的定義與差異，以及它們在軟體開發流程中的角色。

## Steps

1. [[learn/design-patterns/nodes/oop-foundation/what-is-oop|什麼是 OOP 與 OOPL？]] — 認識 OOP 的四大特性與 OOPL 的定義
2. [[learn/design-patterns/nodes/oop-foundation/judging-an-oopl|如何判定一個語言是不是 OOPL？]] — 用「類／物件」作為粗略判定標準（after step 1）
3. [[learn/design-patterns/nodes/oop-foundation/ooa-ood|OOA、OOD 與 UML 是什麼？]] — 三個開發階段與 UML 的角色（after step 2）

## Lesson

這節課把「面向對象」這個常被掛在嘴邊的詞拆開：OOP 是編程範式，OOPL 是支撐它的語言，OOA 與 OOD 是寫代碼之前的分析與設計階段。三步走完之後，你應該能分辨「用 OOPL 寫的代碼」和「面向對象風格的代碼」是兩回事，也能說出 UML 在團隊開發裡真正的用處。
