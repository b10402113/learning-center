# 什麼是 OOP 與 OOPL？

## Learning goal

能說出 OOP 的四大特性，並分辨「用 OOPL 寫的代碼」和「面向對象風格的代碼」為什麼是兩回事。

## Lesson

提到面向對象，很多人隨口就能說出四大特性：封裝、抽象、繼承、多態。但「面向對象」這個詞其實包了好幾層意思，其中最常被混在一起的，是**編程範式**和**編程語言**這兩件事。

**物件導向編程（OOP，Object-Oriented Programming）** 是一種編程範式——以「類（class）」和「對象（object）」作為組織代碼的基本單元，並用以下四個特性來做設計與實現：

| 特性 | 它解決什麼 | 一句話記法 |
| --- | --- | --- |
| 封裝（Encapsulation） | 防止外部程式隨意改動內部狀態 | 物件自己管自己的抽屜 |
| 繼承（Inheritance） | 相同程式碼重複撰寫 | 藍圖可以沿用再擴充 |
| 多型（Polymorphism） | 相同呼叫方式、不同實作結果 | 同一句話，各說各話 |
| 抽象（Abstraction） | 使用者不必懂底層實作 | 只問能做什麼，不問怎麼做 |

範式是一套想法，不是某一門語言：哪怕不用 OOPL，你照樣可以寫出面向對象風格的代碼。

**物件導向編程語言（OOPL，Object-Oriented Programming Language）** 則是支撐這套範式的語言——它提供了類或對象的語法機制，讓四大特性有現成的落腳處。反過來，就算你拿 OOPL 寫代碼，寫出來的也不一定是面向對象風格，也可能是面向過程的。

這兩個概念在 [[learn/design-patterns/elements/oop-paradigm|物件導向典範 (Object-Oriented Paradigm)]] 裡展開成完整的四大特性；而「類」和「對象」這組概念最早在 1960 年出現於 Simula，Smalltalk 才第一個完整擁抱了這套範式——這段演進在 [[learn/design-patterns/elements/oop-history-video|物件導向發展史 (History of OOP)]] 裡有完整脈絡。

把範式和語言分開看，你才會避開一個常見誤區：把「換了一門 OOPL」當成「寫出了面向對象代碼」。下一課會用這個區分，回答「怎麼判定一門語言算不算 OOPL」。
