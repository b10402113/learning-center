物件是垃圾嗎？可達性分析與四種引用

Step 1/4 · GC、記憶體壓力與線上排查

學習目標

能講清楚 JVM 為什麼用可達性分析而不是引用計數，說出四類 GC Roots，並用四種引用強度解釋「這個物件什麼時候才會被回收」。

前言：記憶體一直漲，重啟就好？

你有沒有遇過這種服務：上線後記憶體慢慢往上爬，撐個三五天就開始卡，重啟一下又恢復正常，過幾天再漲回來。同事問你「到底是哪裡漏了」，你盯著程式碼卻說不出個所以然。

要回答這個問題，得先退一步問一個更基本的問題：JVM 是怎麼知道一個物件「已經沒人用了、可以丟掉」？如果連判斷生死的規則都不清楚，就更不可能說出「為什麼它沒被回收」。這一節就把這條規則講清楚，而它的答案不是「沒人指向我就丟掉」，而是「從幾個固定的根出發，走不到我就丟掉」。

先看一個行不通的做法：引用計數

最直覺的想法是幫每個物件裝一個計數器。有人引用它，計數器加一；引用斷開，計數器減一。計數器歸零，就代表沒人用它了，可以回收。這個方法叫引用計數法，邏輯簡單，聽起來也很合理。

問題出在一個它永遠解不掉的死角：循環引用。假設物件 A 內部持有物件 B，物件 B 內部又持有物件 A，除此之外，外界沒有任何地方引用它們。這種情況下，A 和 B 其實都是垃圾，但因為互相指著對方，兩個計數器永遠是 1，誰也歸不了零，於是永遠收不掉，記憶體就卡在那裡。就因為這個死角，HotSpot 這類工業級 JVM 並不採用引用計數法。

JVM 真正用的方法：可達性分析

JVM 用的是另一種思路，叫可達性分析。它把記憶體裡所有物件看成一大張圖，物件之間的引用就是圖上的線。接著選定幾個固定的起點，稱為 GC Roots，從這些起點沿著線往下走。凡是走得到的物件，就判定為存活；走不到的，就判定為可回收。

你可以把它想成「從家門口出發的地鐵可達圖」。只要有一條路能從家門口走到某個站，那個站就是活的；完全連不上任何路線的站，就當它不存在。這裡的關鍵是：判斷標準不是「有沒有人指向我」，而是「從根能不能走到我」。用這個標準看剛剛的 A 和 B，因為從任何一個 GC Roots 都走不到它們，它們就是垃圾，循環引用再怎麼互相指也沒用。

哪些物件可以當 GC Roots

這是面試最常追問的細節。可以當作根的物件主要有四類：

  1. 虛擬機棧（方法執行時用的那塊記憶體）中，區域變數所引用的物件。例如方法裡寫了 User u = new User();，只要這個方法還沒結束，u 就是根，它指向的 User 物件就不能被回收。
  2. 方法區中靜態屬性（static）所引用的物件。例如 public static User user;，只要類別還被載入著，這個 user 就是根。
  3. 方法區中常數（final）所引用的物件，例如字串常量池裡的引用。
  4. 本地方法棧中，JNI（Java 呼叫 C/C++ 原生方法）所引用的物件。

把這四類記住，你就有了「什麼東西永遠不會被回收」的判準。後面排查記憶體洩漏時，MAT 工具裡的 Path to GC Roots，做的就是反過來沿著這些根找出「是誰還牽著它」。

四種引用強度：決定「什麼時候才收」

可達性分析回答的是「這物件還活著嗎」，但同樣是活的物件，GC 對它們的態度其實不一樣。Java 設計了四種引用強度，讓你可以精細地控制物件的存活時間。它們的差別就在一句話：GC 什麼時候肯收它。

引用寫法GC 的態度典型用途
強引用Object o = new Object()絕不回收，記憶體不足寧願丟 OutOfMemoryError日常最普通的引用
軟引用SoftReference記憶體夠就留著，快不夠時才回收對記憶體敏感的本地快取，例如圖片快取
弱引用WeakReference只要發生 GC，不論記憶體夠不夠都回收ThreadLocal 的 key、WeakHashMap
虛引用PhantomReference無法取回物件，只在回收時發個通知管理堆外記憶體的釋放

強引用就是你平常寫的 new，只要它還指向物件，GC 就不會動它，哪怕快要撐爆記憶體也一樣。軟引用描述的是「有用但不那麼必要」的物件，適合拿來做快取：記憶體充裕時它就跟強引用一樣活著，記憶體吃緊時再清掉它來騰空間，所以不會因為快取把系統撐死。

弱引用更短命，只要 GC 一啟動，不管當下記憶體夠不夠，弱引用綁著的物件都會被回收。這裡最經典的用法是 ThreadLocal 裡的 key，以及 WeakHashMap：當某個 key 不再被外部強引用時，對應的鍵值對就能自動被收掉，避免拖著一堆沒用的資料不放。虛引用則是最弱的一種，你甚至沒辦法用 get() 拿回原物件（永遠回傳 null），它唯一的用處是搭配引用隊列，在物件被回收時收到一個通知，通常用來處理堆外記憶體的清理。

小結

JVM 判斷物件死活靠的是可達性分析，不是引用計數，因為計數器解不掉循環引用。可達性分析從四類 GC Roots 出發，走得到就是活的。至於「什麼時候才被回收」，則由引用強度決定：強引用死不放，軟引用記憶體不足才放，弱引用一 GC 就放，虛引用只負責通知。
