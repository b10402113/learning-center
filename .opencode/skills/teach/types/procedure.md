# 型別：procedure（程序）

**用途**：讓讀者照著做能得到正確結果 —— 「怎麼一步步做」。主角是**程序本身**：核心的程式碼、核心的手法。

**開頭**：先講目標與前置條件 —— 讀者做完會得到什麼、動手前需要先具備什麼。不要先鋪陳原理。

**主體**：以**核心程式碼與核心手法**為骨幹 ——

- 有序動作，每一步講清楚「做了什麼」與「預期看到什麼」。
- 程式碼是主體，不是插圖：關鍵那幾行要逐行說明它在做什麼。
- 有分支就用條件式指令（若 X 則 Y），不要把分支藏進一句話。
- 不可逆或危險的步驟先給警告。
- 只從合理接點開始，不要端到端流水帳。

**結尾**：講清楚「做完長什麼樣」（可驗證的結果），以及為什麼原理交給別處。

**元件偏好**：有序清單、`<pre>` 程式碼區塊、good/bad code 對照。

**不要**：長篇解釋原理（那是 concept 的事）；把關鍵程式碼當附錄塞在最後。
