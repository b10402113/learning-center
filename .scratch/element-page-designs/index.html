Element 頁面設計方案

目標：新的獨立頁面路由 /elements/slug，當用戶點擊 element 內容時自動跳轉。 以下 5 種方案均以真實元素 「目標層級 (Goal Hierarchy)」 為內容，使用現有暗色 developer-docs 設計語彙（近黑中性色 + 品牌粉紅 #ff0071 + 髮絲線邊框 + IBM Plex）。直接點卡片在瀏覽器開啟。

方案 A

文件型 Docs

左側課程導覽 + 中央文章 + 右側錨點目錄，像 React Flow / MDN 文件站。資訊密度高，最接近現有 DetailPane 的閱讀習慣。

sidebar · toc · prev/next
方案 B

編輯器型 Editor

檔案樹 + 檔案路徑麵包屑 + 狀態列，像在 IDE 裡讀 .mdx 原始檔。最貼合「developer-docs」語彙。

file-tree · path · statusbar
方案 C

紙張型 Paper

極簡居中文章 + 襯線標題 + 大留白，像 Notion 文件。閱讀最舒服，適合長文深度閱讀。

centered · serif · calm
方案 D

星雲型 Nebula

滿版星空 + 發光元素節點 + 繞行關係節點，與產品「知識星雲」意象一致。沉浸感最強。

starfield · glass · orbit
方案 E

雜誌型 Editorial

左文章右浮動參考欄的對開排版，參考卡片（先備知識／連結／來源／測驗）固定右側。適合概念間跳轉與比較。

split · sticky-rail · reference
